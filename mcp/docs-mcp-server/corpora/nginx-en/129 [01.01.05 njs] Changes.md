# Changes


## Changes

## Changes with njs 1.0.1

Release Date: 2 September 2026

nginx modules:

-   Security: fixed an access control bypass in [js\_access](<073 [01.01.03 http] Module ngx_http_js_module.md#js_access>) when an asynchronous request body continuation threw an exception or produced an unhandled rejection ([CVE-2026-18329](https://www.cve.org/CVERecord?id=CVE-2026-18329)). Previously, nginx could continue processing the request as though the js\_access check had succeeded. The issue was introduced in [0.9.9](#njs0.9.9). Thanks to Ta Duc Thien.
    
-   Security: fixed a worker process crash when reading [Response.statusText](<137 [01.01.05 njs] Reference.md#response_statustext>) after an upstream server returned a status line with an empty reason phrase ([CVE-2026-78222](https://www.cve.org/CVERecord?id=CVE-2026-78222)). The issue was introduced in [73c75e41](https://github.com/nginx/njs/commit/73c75e41) ([0.5.1](#njs0.5.1)).
    
-   Bugfix: fixed unhandled promise rejection tracking in reused [QuickJS](<132 [01.01.05 njs] JavaScript Engine.md#quickjs_engine>) contexts.
    
-   Bugfix: fixed [SharedDict.pop()](<137 [01.01.05 njs] Reference.md#dict_pop>) returning `undefined` for unexpired entries in [shared dictionaries](<073 [01.01.03 http] Module ngx_http_js_module.md#js_shared_dict_zone>) with a timeout.
    
-   Bugfix: fixed validation and replacement of [Fetch Headers](<137 [01.01.05 njs] Reference.md#headers>) values. This also fixed dangling header names in the QuickJS engine.
    
-   Bugfix: fixed missing validation of [r.headersOut](<137 [01.01.05 njs] Reference.md#r_headers_out>) names and values, and of redirect targets passed to [r.return()](<137 [01.01.05 njs] Reference.md#r_return>).
    
-   Bugfix: fixed use-after-free, worker aborts, and leaks caused by cyclic references involving [Fetch](<137 [01.01.05 njs] Reference.md#ngx_fetch>), HTTP request, and Stream session objects in the QuickJS engine.
    
-   Bugfix: fixed QuickJS context reuse after [internal redirects](<137 [01.01.05 njs] Reference.md#r_internal_redirect>) and when pending jobs remained after request teardown.
    
-   Bugfix: fixed cleanup of partially initialized JavaScript contexts when request setup failed.
    

Core:

-   Security: fixed a heap buffer overflow while parsing namespace prefix lists passed to [xml.exclusiveC14n()](<137 [01.01.05 njs] Reference.md#xml_exclusivec14n>) ([CVE-2026-78689](https://www.cve.org/CVERecord?id=CVE-2026-78689)). The issue was introduced in [9161a840](https://github.com/nginx/njs/commit/9161a840) ([0.7.10](#njs0.7.10)). Thanks to Vladimir Vulnerability Research Tech Lead @ Cyera, evilgensec.
    
-   Feature: added [btoa()](<137 [01.01.05 njs] Reference.md#btoa>) and [atob()](<137 [01.01.05 njs] Reference.md#atob>) global functions to the QuickJS engine and aligned their behavior between both engines.
    
-   Bugfix: fixed a stack buffer overflow when exporting RSA keys larger than 4096 bits to JWK in [crypto.subtle.exportKey()](<137 [01.01.05 njs] Reference.md#crypto_subtle_export_key>). Thanks to Vaibhav Rajput.
    
-   Bugfix: fixed RSA-OAEP [encryption](<137 [01.01.05 njs] Reference.md#crypto_subtle_encrypt>) and [decryption](<137 [01.01.05 njs] Reference.md#crypto_subtle_decrypt>) with SHA-256 and SHA-384 digests in WebCrypto.
    
-   Bugfix: fixed compatibility with quickjs-ng 0.16.0 and later.
    
-   Bugfix: fixed empty stack traces for QuickJS errors created by host callbacks.
    

## Changes with njs 1.0.0

Release Date: 23 June 2026

nginx modules:

-   Improvement: aligned HTTP, Stream, and [Fetch](<137 [01.01.05 njs] Reference.md#ngx_fetch>) exception classes between the njs and QuickJS engines. API misuse is now reported as `TypeError` and status bounds violations as `RangeError`.
    
-   Improvement: rejected unsafe request targets, methods, and header values in [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>) before request serialization.
    
-   Bugfix: fixed a heap use-after-free in [r.subrequest()](<137 [01.01.05 njs] Reference.md#r_subrequest>) when the client closed the connection before the background subrequest completed. The issue was introduced in [75d6b61](https://github.com/nginx/njs/commit/75d6b61) ([0.9.5](#njs0.9.5)).
    
-   Bugfix: fixed a worker segfault while reading a request header that nginx registers without a dedicated slot, such as `Proxy-Connection`, via [r.headersIn](<137 [01.01.05 njs] Reference.md#r_headers_in>).
    
-   Bugfix: excluded unverified-TLS and dynamic-proxy connections from the [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>) [keepalive](<073 [01.01.03 http] Module ngx_http_js_module.md#js_fetch_keepalive>) cache and validated cached connections before reuse.
    
-   Bugfix: fixed Content-Length truncation for very large request bodies and a missing CONNECT terminator for proxies configured without credentials in [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>).
    
-   Bugfix: fixed leaks of promises, events, and init property values on [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>) failure paths in the QuickJS engine.
    
-   Bugfix: fixed missing fetch event cleanup when the resolver failed to start.
    
-   Bugfix: fixed an out-of-bounds read of a short fetch proxy URL.
    
-   Bugfix: fixed request body truncation in [r.readRequestJSON()](<137 [01.01.05 njs] Reference.md#r_read_request_json>) for bodies containing invalid UTF-8 in the QuickJS engine.
    
-   Bugfix: fixed an out-of-bounds read while loading a shared dictionary state file.
    
-   Bugfix: set a pending exception when `sendHeader()`, `send()`, and `finish()` fail in the njs HTTP handlers.
    
-   Bugfix: fixed the variable value state after a stream variable storage allocation failure.
    

Core:

-   Improvement: bounded string-producing chained-buffer growth, so that exceeding the maximum string length raises a catchable `RangeError("invalid string length")` instead of exhausting worker memory.
    
-   Improvement: aligned built-in exception classes (XML, console, TextEncoder, TextDecoder, Buffer, fs.Stats) between the njs and QuickJS engines.
    
-   Bugfix: fixed an infinite loop while inflating a zlib stream that requires a dictionary in the QuickJS engine.
    
-   Bugfix: fixed an infinite loop in `Buffer.prototype.fill()` with a zero-length typed array source.
    
-   Bugfix: fixed a use-after-free in `Array.prototype.sort()` when a getter invoked for a hole grows the array.
    
-   Bugfix: fixed type confusion in `Buffer.concat()` when a list element getter returns a typed array during validation but not during the copy.
    
-   Bugfix: fixed an out-of-bounds access in the variable-length Buffer `readInt`/`writeInt` methods with a zero byteLength.
    
-   Bugfix: fixed an out-of-bounds read in `Buffer.prototype.toString()` when start was greater than end.
    
-   Bugfix: fixed `Array.prototype.slice()` of large arrays returning wrong results in the non-fast keys path.
    
-   Bugfix: fixed the typed array constructor, `slice()`, `toReversed()`, and `toSorted()` ignoring the source view byte offset in the same-type fast path.
    
-   Bugfix: fixed Buffer allocation length checks for lengths greater than or equal to 2^32 on 32-bit platforms.
    
-   Bugfix: fixed the `Buffer.from()` typed-array source offset for multi-byte element types in the QuickJS engine.
    
-   Bugfix: fixed Buffer float access alignment.
    
-   Bugfix: fixed an out-of-bounds read in a parser string escape lookahead.
    

## Changes with njs 0.9.9

Release Date: 19 May 2026

nginx modules:

-   Security: a heap buffer overflow might occur in a worker process when the [js\_fetch\_proxy](<073 [01.01.03 http] Module ngx_http_js_module.md#js_fetch_proxy>) directive value contains nginx variables derived from the client request ( [`$http_*`](<056 [01.01.03 http] Module ngx_http_core_module.md#var_http_>), [`$arg_*`](<056 [01.01.03 http] Module ngx_http_core_module.md#var_arg_>), [`$cookie_*`](<056 [01.01.03 http] Module ngx_http_core_module.md#var_cookie_>), etc.) and the location's JS handler invokes [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>) ([CVE-2026-8711](https://www.cve.org/CVERecord?id=CVE-2026-8711)). The issue was introduced in [dea83189](https://github.com/nginx/njs/commit/dea83189) ([0.9.4](#njs0.9.4)).
    
-   Feature: added [js\_access](<073 [01.01.03 http] Module ngx_http_js_module.md#js_access>) directive.
    
-   Feature: added [r.readRequestText()](<137 [01.01.05 njs] Reference.md#r_read_request_text>), [r.readRequestArrayBuffer()](<137 [01.01.05 njs] Reference.md#r_read_request_array_buffer>), and [r.readRequestJSON()](<137 [01.01.05 njs] Reference.md#r_read_request_json>) async methods that read the request body, available in [js\_access](<073 [01.01.03 http] Module ngx_http_js_module.md#js_access>) and [js\_content](<073 [01.01.03 http] Module ngx_http_js_module.md#js_content>) directives.
    
-   Feature: added [r.readRequestForm()](<137 [01.01.05 njs] Reference.md#r_read_request_form>) async method that parses the request body submitted from an HTML form (`application/x-www-form-urlencoded` and `multipart/form-data`) and returns a structured accessor object. The method is available in [js\_access](<073 [01.01.03 http] Module ngx_http_js_module.md#js_access>) and [js\_content](<073 [01.01.03 http] Module ngx_http_js_module.md#js_content>) directives.
    
-   Feature: added [jsVarNames()](<137 [01.01.05 njs] Reference.md#r_js_var_names>) method. The method returns the names of variables declared with [js\_var](<073 [01.01.03 http] Module ngx_http_js_module.md#js_var>).
    

Core:

-   Bugfix: fixed evaluation order of call arguments with side effects. Previously, an earlier argument could observe a later argument's mutation, e.g. `f(a, a = 2)` passed `2` as both arguments. The issue was introduced in [fd5e523f](https://github.com/nginx/njs/commit/fd5e523f) ([0.9.7](#njs0.9.7)).

## Changes with njs 0.9.6

Release Date: 3 March 2026

nginx modules:

-   Bugfix: fixed expire field truncation in [shared dict](<073 [01.01.03 http] Module ngx_http_js_module.md#js_shared_dict_zone>) state files. Millisecond timestamps were silently truncated to 10 digits, making restored entries appear expired on restart.
    
-   Bugfix: suppressed slab log\_nomem for evict [shared dict](<073 [01.01.03 http] Module ngx_http_js_module.md#js_shared_dict_zone>) zones. When evict is enabled, memory allocation failures are expected and handled by evicting old entries.
    
-   Bugfix: fixed stack trace for [ngx.fetch()](<137 [01.01.05 njs] Reference.md#ngx_fetch>) exceptions for [qjs](<132 [01.01.05 njs] JavaScript Engine.md#quickjs_engine>) engine.
    

Core:

-   Feature: added optional chaining support.
    
-   Feature: added nullish coalescing assignment operator (`??=`).
    
-   Feature: added logical assignment operators (`||=` and `&&=`).
    
-   Improvement: aligned `SyntaxError` reporting with other JS engines. Previously, file name was a part of the error message. Now it is reported as "stack" property.
    
-   Improvement: improved `Error.stack` traces. Stack traces are now attached in error constructors. Performance of `Error.stack` is improved by ~100 times.
    
-   Bugfix: fixed string offset map corruption in scope values hash. The issue caused SEGV/SIGBUS crashes for multi-byte UTF-8 string constants with more than 32 characters when accessing a character at index >= 32 (e.g. via `.replace()` or bracket notation). The issue was introduced in [e7caa46d](https://github.com/nginx/njs/commit/e7caa46d) ([0.9.5](#njs0.9.5)).
    
-   Bugfix: fixed heap-buffer-overflow in atom hash caused by `Symbol()`.
    
-   Bugfix: fixed WebCrypto [importKey()](<137 [01.01.05 njs] Reference.md#crypto_subtle_import_key>) crash with mismatched JWK key type.
    
-   Bugfix: fixed interactive mode detection for piped stdin.
    
-   Bugfix: fixed build on MacOS.
    
-   Bugfix: fixed PTR macro compatibility with newer BFD library.
    
-   Bugfix: auto/cc: use portable `command -v` instead of `which`. Thanks to Zurab Kvachadze.

## Changes with njs 0.8.9

Release Date: 14 January 2025

nginx modules:

-   Bugfix: removed extra VM creation per server. Previously, when `js_import` was declared in [http](<073 [01.01.03 http] Module ngx_http_js_module.md#js_import>) or [stream](<145 [01.01.06 stream] Module ngx_stream_js_module.md#js_import>) blocks, an extra copy of the VM instance was created for each server block. This was not needed and consumed a lot of memory for configurations with many server blocks.
