# 相信

> 章節：[System](<000 目錄.md#c-11>)

在 OPNsense 中，憑證用於確保對等節點之間的信任。為了方便使用，OPNsense 允許從前端建立憑證。此外，它還允許建立用於其他用途的證書，無需使用`openssl`命令列工具。 OPNsense 中的憑證可以透過「系統」‣「信任」‣「憑證」進行管理。

使用憑證的 OPNsense 元件範例：

-   OpenVPN
    
-   IPsec
    
-   強制門戶
    
-   網路代理
    

## 證書類型

OPNsense 可以產生以下類型的憑證：

-   客戶
    
-   伺服器
    
-   客戶端/伺服器組合
    
-   證書頒發機構
    

此外，OPNsense 還可以產生憑證簽署要求 ( CSR )。如果您想建立由外部CA簽署的證書，可以使用此功能。

警告

請務必選擇正確的憑證類型，因為如果使用了錯誤的憑證類型，許多用戶端會拒絕連線（或至少顯示錯誤）。例如，您可以使用伺服器憑證或用戶端/伺服器組合憑證來保護與 Web 介面的連接，但不能使用CA或用戶端憑證。

警告

在我們的設定中，「儲存中間憑證」（系統 ‣ 信任 ‣ 設定）預設為停用狀態，這表示我們的信任儲存區中不會部署任何中間憑證。手動插入需要中間證書進行驗證的新證書時，您必須包含中間證書，以避免在圖形使用者介面中出現驗證問題。

## 設定

在「系統」‣「信任」‣「設定」中，您可以找到一些進階選項來管理系統如何處理信任關係。出於合規性考慮，可以在請求預設 OpenSSL 上下文時實施某些限制。

| **選項**|**描述** |
| --- | --- |
|儲存中間體|允許在本地信任儲存中使用本地定義的中間憑證授權單位。部署中間憑證時要小心，因為交叉簽署的憑證在包含但稍後在鏈中過期時可能會導致損壞。 |
| 儲存CRL | 將所有已配置的CRL儲存在預設信任儲存區。如果用戶端或服務支援CRL ，則部署到預設位置可以簡化維護。 |
| 自動取得CRL | 排程每小時執行一次作業，使用部署在我們信任庫中的 CA 的已定義分發點下載 CRL。 |
| 啟用舊版 | 啟用舊版提供者。 （啟用將在 OpenSSL 的未來版本中移除的密碼套件） |
|配置限制|啟用後，您可以設定一些預設密碼和協議，請小心使用這些選項，因為這些設定將被防火牆的某些應用程式使用（並可能會破壞它們）。 |

注意事項

應用程式並非必須使用標準上下文，根據應用程式的不同，自訂約束可能有效也可能無效。

## 撤銷證書

### 憑證吊銷列表

憑證撤銷清單 ( CRL ) 是憑證授權單位撤銷的憑證清單。 OPNsense 中的某些服務可以使用此清單來驗證憑證是否仍然有效，即使它尚未過期。

在 OPNsense 中定義CRL並不復雜，只需轉到“系統”‣“信任”‣“吊銷”，然後單擊本地證書頒發機構旁邊的 [+] 符號即可創建一個新的CRL 。如果CRL已存在，您可以對其進行編輯，並在其中新增或刪除憑證（使用鉛筆圖示）。

注意事項

如果您想使用CRL作為外部工具，可以使用按鈕下載它。

CRL的一個缺點是其擴充性不佳，清單的每個使用者都必須下載完整的清單才能確定憑證是否仍然可信。此外，由於這些清單通常僅按特定週期生成，因此資訊的準確性往往較低。

當在 OPNsense 上使用CRL作為本地機構時，擴展性通常不是一個大問題，因為證書的數量通常是有限的（例如，受限於您組織中的員工人數）。

若要使用`openssl`指令手動驗證已建立的證書，您需要以下工具：

1.  用於簽署憑證的CA憑證鏈（從「Authorities」選單匯出「cert」）
    
2.  在 OPNsense 中建立的CRL （從「​​撤銷」選單中匯出「crl」）
    
3.  已撤銷的憑證（從「憑證」功能表匯出「憑證」）
    
4.  未過期或未撤銷的證書
    

首先，我們將CA鍊和CRL鏈連接成一個單獨的「鏈」檔案：

```
# cat ca_chain.crt ca_crl.crl > my_chain.pem
```

然後使用以下`openssl`指令驗證已撤銷的憑證：

```
# openssl verify -crl_check -CAfile my_chain.pem revoked_cert.crt
C=NL, CN=my_cert
error 23 at 0 depth lookup: certificate revoked
error ocsp_user_cert2.crt: verification failed
```

以及一份有效的證書：

```yaml
# openssl verify -crl_check -CAfile my_chain.pem ok_cert.crt
ocsp_server_cert.crt: OK
```

### 線上證書狀態協議

線上證書狀態協定 ([OCSP](https://en.wikipedia.org/wiki/Online_Certificate_Status_Protocol) ) 提供與先前描述的CRL類似的功能，但它「線上」驗證證書，並採用白名單而非黑名單機制。憑證會與已知的線上憑證集進行比對，之後伺服器會傳回「有效」、「已撤銷」或「未知」的回應。只有「有效」的回應才被視為有效。

為了向驗證憑證的用戶端解釋在哪裡檢查其有效性，憑證授權單位應提供`AuthorityInfoAccess`擴充（參數`OCSP uri`將其新增至 OPNsense 中的憑證）。

提示

您可以使用該按鈕尋找可用的 ocsp uri。

驗證「 OCSP請求」的OCSP響應者（伺服器）需要一個特殊的簽章證書，該證書可以透過 OPNsense 中的「系統」‣「信任」‣「機構」創建，由創建用戶和/或伺服器證書的同一個CA頒發。

OPNsense 沒有實作OCSP響應器，但為了測試這個概念，我們可以使用 [openssl-ocsp](https://www.openssl.org/docs/man3.0/man1/openssl-ocsp.html)指令。

注意事項

openssl-ocsp 僅供測試和示範之用。

為了驗證這個概念，我們需要以下資料：

1.  用於簽署憑證的CA憑證鏈（從「Authorities」選單匯出「cert」）
    
2.  OCSP簽署者憑證（從「授權機構」選單中匯出簽署者的「憑證」和「金鑰」）
    
3.  openssl-ocsp 的索引檔案（從「撤銷」選單匯出索引），如 [https://pki-tutorial.readthedocs.io/en/latest/cadb.html](https://pki-tutorial.readthedocs.io/en/latest/cadb.html)中所述
    
4.  已撤銷憑證的序號（使用資訊按鈕尋找序號）
    
5.  未過期或未吊銷憑證的序號
    

首先在控制台中啟動伺服器：

```
# openssl ocsp -index index.txt -port 8081 -rsigner ocsp_signer.crt -rkey ocsp_signer.key -CA ca.crt -ignore_err -text
```

然後驗證一個已知有效的憑證（序號為 1）：

```yaml
# openssl ocsp -url http://127.0.0.1:8081 -CAfile ca.crt -issuer ca.crt -serial 1
Response verify OK
1: good
        This Update: Jan  6 13:33:59 2024 GMT
```

已撤銷的：

```yaml
# openssl ocsp -url http://127.0.0.1:8081 -CAfile ca.crt -issuer ca.crt -serial 2
Response verify OK
2: revoked
    This Update: Jan  6 13:34:54 2024 GMT
    Revocation Time: Jan 1 21:31:08 2024 GMT
```

以及一份未知證書

```yaml
# openssl ocsp -url http://127.0.0.1:8081 -CAfile ca.crt -issuer ca.crt -serial 9999
Response verify OK
9999: unknown
    This Update: Jan  6 13:36:51 2024 GMT
```

## 內部組織

本段將解釋內部信任庫的組織結構。現有的憑證和吊銷清單被暫存在系統目錄中，並部署到我們這邊，供名為`certctl.py`的工具使用。

憑證和撤銷清單的來源檔案收集在以下目錄中，這些目錄要麼隨基本系統一起提供，要麼由 OPNsense 管理：

| **路徑**|**主題** |
| --- | --- |
| /usr/share/certs/trusted | 預設系統證書，隨基本系統一起提供 |
| /usr/local/share/certs | 應用程式特定憑證和撤銷清單 |
| /usr/share/certs/untrusted | 不再受信任的憑證 |

`certctl.py`從上面定義的集合中收集所有證書，並在下面指定的目標目錄中建立指向它們的連結。

| **路徑**|**主題** |
| --- | --- |
| /etc/ssl/certs | 包含指向憑證的連結（和檔案）的目錄，憑證依其雜湊值命名。 （例如， `ef954a4e.0`對應的是CRL或`ef954a4e.r0` ）基本系統的主要位置。 |
| /etc/ssl/untrusted | 與上述相同，但設定為 untrusted（忽略） |
| /usr/local/openssl/certs | 與`/etc/ssl/certs`相同，是從「ports」樹建構的應用程式的預設位置 |
| /usr/local/etc/ssl/cert.pem | 適用於只需要單一檔案的應用程式的合併軟體包檔案。 |

每個目標連結（或檔案）都包含一個憑證或撤銷列表，OpenSSL 可以使用憑證主題輕鬆找到它。

注意事項

如果`/etc/ssl/cert.pem`和/或`/usr/local/etc/ssl/cert.pem`存在，則它們優先於目標目錄中的雜湊連結。從 OPNsense 版本25.1開始，這些檔案如果存在將被刪除。

OpenSSL 的預設設定保存在`/usr/local/openssl/openssl.cnf` （連接埠）和`/etc/ssl/openssl.cnf` （基本）中，兩者都由 OPNsense 管理。
