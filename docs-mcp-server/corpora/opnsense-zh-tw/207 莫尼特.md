# 莫尼特

> 章節：[Services](<000 目錄.md#c-40>)

OPNsense 使用 Monit 來監控服務。 Monit 具有相當廣泛的監控功能，這就是為什麼配置選項也很廣泛。本指南將快速瀏覽設置，隨後更詳細地解釋配置選項以及一些注意事項。

## 全域設定

導覽至服務 ‣ 監控 ‣ 設定。在「常規設定」標籤上，開啟 Monit 並填寫 SMTP 伺服器的詳細資料。儲存更改。然後，導航至“警報設定”並為您的電子郵件地址添加一個。如果您的郵件伺服器需要正確設定「寄件者」字段，請在「郵件格式」欄位中輸​​入`From: sender@example.com`。儲存警報並套用變更。

## 添加警報

首先，您必須決定要監視什麼以及什麼構成失敗。如果您了解如何設定 Monit 警報，將會有所幫助。這在[Monit文檔](https://mmonit.com/monit/documentation/monit.html#ALERT-MESSAGES)中有描述。

如果您已這樣做，則必須先新增條件。導覽至「服務測試設定」標籤，查看您要新增的條件是否已存在。如果沒有，請點擊 + 按鈕以新增它。

現在導航到“服務測試”標籤並點擊 + 圖示。在對話方塊中，您現在可以新增服務測試。如果完成，請儲存它，然後套用變更。

本文檔的「設定概述」部分更詳細地描述了對話方塊中的欄位。

## 實施例1

在此範例中，我們將新增一個服務來重新啟動已停止的 FTP 代理程式（在連接埠 8021 上執行）。為了避免出現問題時出現永久循環，我們還將添加一項規定，以便在 FTP 代理必須連續重新啟動五次時停止嘗試。

首先，請確保您已按照「全域設定」下的步驟進行操作。然後，導航至“服務測試設定”標籤。在這裡，您需要添加兩個測試：

|設定|價值|
| --- | --- |
|姓名 | FTPProxy8021 | FTPProxy8021
|狀況 |失敗的主機127.0.0.1埠8021型tcp|
|行動|重新啟動 |

|設定|價值|
| --- | --- |
|名稱 |重啟限制5 |
|狀況 | 5 個週期內重啟 5 次 |
|行動|取消監控 |

現在，導航到“服務設定”標籤。在這裡，添加以下服務：

|設定|價值|
| --- | --- |
|姓名 | FTPProxy8021 | FTPProxy8021
|類型 |流程|
| PID 檔案| /var/run/osftpproxy.127\_0\_0\_1\_8021.pid |
|開始| /usr/local/sbin/configctl ftpproxy 啟動 127\_0\_0\_1\_8021 |
|停止| /usr/local/sbin/configctl ftpproxy 停止 127\_0\_0\_1\_8021 |
|測試 | FTPProxy8021，重啟限制5 |

保存並應用。

## 實施例2

在此範例中，我們要監視 VPN 隧道並對遠端系統執行 ping 操作。如果 ping 不再回應，則應重新啟動 IPsec。

首先，請確保您已按照「全域設定」下的步驟進行操作。然後，導航至“服務測試設定”標籤。在這裡，您需要新增一個測試：

|設定|價值|
| --- | --- |
|名稱 | IPSEC\_重新開始 |
|狀況 | ping4 失敗計數 5 個位址<local IP> |
|行動|重新啟動 |

現在，導航到“服務設定”標籤。在這裡，添加以下服務：

|設定|價值|
| --- | --- |
|名稱 | IPSEC\_監控 |
|類型 |遠端主機|
|地址 | <remote IP> |
|開始| /usr/local/sbin/configctl ipsec 啟動 |
|停止| /usr/local/sbin/configctl ipsec 停止 |
|測試 | IPSEC\_重新開始 |

保存並應用。

## 實施例3

在此範例中，我們要監視 Suricata EVE 日誌以取得警報並發送電子郵件。這非常簡單，請確保誤報率較低，以免收到垃圾郵件警報。

首先，請確保您已按照「全域設定」下的步驟進行操作。然後，導航至“服務測試設定”標籤。在這裡，您需要新增一個測試：

|設定|價值|
| --- | --- |
|名稱 | SURICATA\_EVE |
|狀況 |內容=「被封鎖」|
|行動|警報 |

現在，導航到“服務設定”標籤。在這裡，添加以下服務：

|設定|價值|
| --- | --- |
|名稱 | SURICATA\_警報 |
|類型 |文件|
| 路徑 | /var/log/suricata/eve.json |
|測試 | SURICATA\_EVE |

保存並應用。從現在開始，您將收到每個阻止操作的警報訊息。

## 設定概覽

導覽至服務 ‣ 監控 ‣ 設定。您將看到四個選項卡，我們將在下面更詳細地描述它們

### 常規設定

按一下“進階模式”以查看所有設定。

|設定|描述 |
| --- | --- |
|啟用監控 |開啟或關閉Monit。 |
|輪詢間隔 | Monit 檢查其監視的元件狀態的頻率。 |
|啟動延遲| Monit 啟動時檢查元件之前等待的時間。 |
|郵件伺服器|要傳送通知的郵件伺服器清單（另請參閱此表下方）。 |
|郵件伺服器連接埠 |要使用的郵件伺服器連接埠。 25 和 465 是常見的範例。 |
|使用者名稱 |用於登入 SMTP 伺服器的使用者名稱（如果需要）。通常（但並非總是）與您的電子郵件地址相同。 |
|密碼 |用於登入 SMTP 伺服器的密碼（如果需要）。 |
|安全連線 |連線郵件伺服器時使用TLS。 |
| SSL版本|要使用的TLS版本。 AUTO 將嘗試協商一個工作版本。 |
|驗證SSL證書|檢查TLS證書的有效性。如果您使用自簽名證書，請關閉此選項。 |
|日誌檔 | Monit 程序的日誌檔。這可以是關鍵字 `syslog` 或檔案路徑。 |
|狀態檔| Monit 程序的狀態檔。 |
|事件佇列路徑 | eventqueue 目錄的路徑。 |
|事件佇列插槽 |事件佇列槽的數量。 |
| 啟用 HTTPD | 開啟 Monit Web 介面。 （需要啟用才能查看以下選項。） |
|監控HTTPD埠| Monit Web 介面服務的偵聽埠。 |
|監控HTTPD 存取清單 |用於存取 Monit Web 介面服務的使用者名稱：密碼或主機/網路等。 |
| M/Monit URL | M/Monit URL，例如[https://user:pass@192.168.1.10:8443/collector](https://user:pass@192.168.1.10:8443/collector) |
| M/Monit 逾時 |當向 M/Monit 發出請求時，在此秒數之後逾時。 |
| M/Monit 註冊憑證 |透過傳送 Monit 憑證自動在 M/Monit 中註冊（請參閱上面的 Monit 存取清單）。 |

在「郵件伺服器」設定中，您可以指定多個伺服器。 Monit 將按順序嘗試郵件伺服器，從第一個伺服器開始，如果第一個伺服器不工作，則前進到第二個，依此類推。如果沒有伺服器工作，Monit 將不會再次嘗試發送電子郵件。

**需要記住兩件事**：身份驗證設定在所有伺服器之間共享，並且「寄件者：」地址在「警報設定」中設定。

Monit Web 介面的驗證選項在 [https://mmonit.com/monit/documentation/monit.html#Authentication](https://mmonit.com/monit/documentation/monit.html#Authentication) 中描述。

M/Monit 是一項商業服務，用於從多個 Monit 實例收集資料。若要從 OPNsense 使用它，請填寫相應的欄位並新增相應的防火牆規則。

### 警報設定

這列出了要報告的電子郵件地址。按一下預先存在的條目的「編輯」圖示或「新增」圖示（右下角的加號）以查看下面列出的選項。

|設定|描述 |
| --- | --- |
|啟用警報 |開啟或關閉此警報。 |
|收件者|將此電子郵件傳送到的電子郵件地址。 |
| 未開啟 | 關閉時，將針對下列指定的事件發送通知。開啟時，將針對以下未指定的事件發送通知。 |
|活動 |觸發此通知的事件（或如果選擇「不開啟」則不會觸發此通知）。 |
|郵件格式|可用於控制郵件格式和寄件者地址。請參閱下表。 |
|提醒 |如果經過如此多次檢查後問題仍然存在，請發送提醒。 |
|描述 |此規則的描述，以便在警報設定清單中輕鬆找到它。 |

「郵件格式」是一個以換行符號分隔的屬性列表，用來控制郵件格式。還需要正確設定From 位址。例如：

```yaml
From: sender@example.com
Reply-To: support@example.com
Subject: $SERVICE at $HOST failed
```

|設定|描述 |
| --- | --- |
|啟用服務檢查 |開啟或關閉此服務。 |
|名稱 |該服務的名稱，僅由字母、數字和底線組成。可以在描述欄位中設定更多描述性名稱。 |
|類型 |要檢查的物件類型。 “自訂”允許您使用自訂腳本。 |
|路徑|目錄、檔案或腳本的路徑（如果適用）。 |
|程式逾時|多久執行一次此檢查。 |

|描述 |該服務的描述，以便在服務設定清單中輕鬆找到它。 |

### 服務測試設置

|設定|描述 |
| --- | --- |
|名稱 |測試的名稱。 |
|狀況 |遵守 Monit 語法的條件，請參閱 [Monit 文件](https://mmonit.com/monit/documentation/monit.html#SERVICE-TESTS) |
|行動|當病情發作時該怎麼辦。 |

有一些預先建立的服務測試。其中大多數通常用於一種場景，例如「記憶體使用率 > 75%」測試。然而，有些更通用，可用於測試您自己的腳本的輸出。這些包括：

|服務測試|描述 |
| --- | --- |
| 非零狀態碼 | 傳回的狀態碼不為 0。 （腳本通常在沒有問題時以 0 退出，在出現問題時以非零狀態碼退出。）
|更改狀態 |自上次執行腳本以來，傳回的狀態代碼已發生變更。 |

## 狀態

可透過 Services ‣ Monit ‣ Status 存取 Monit 狀態面板。對於每個活動服務，它將顯示狀態以及額外資訊（如果該服務提供）。

## 進階配置

某些安裝需要在 UI 中無法存取的組態設定。為了支援這些，可以將帶有 `.conf` 副檔名的單獨設定檔放入 `/usr/local/etc/monit.opnsense.d` 目錄中。這些檔案將自動包含在UI產生的設定中。可以在那裡放置多個設定檔。但請注意

-   Monit 中的通配符包含處理基於`glob(7)`。因此文件包含的順序是升序ASCII順序。
    
-   Monit 支援最多 1024 個包含檔案。如果超出此限制，Monit 將報告錯誤。
    
-   檢查設定檔是否有效是有意義的。您可以使用以下命令來執行此操作：
    
    ```
    # Run syntax check for the control file
    configctl monit check
    ```
    

這是一個用於自訂 Monit 守護程式限制的範例設定檔：

```
## Set limits for various tests. The following example shows the default values:
##
set limits {
     programOutput:     5120 B,      # check program's output truncate limit
#     sendExpectBuffer:  256 B,      # limit for send/expect protocol test
     fileContentBuffer: 5120 B,      # limit for file content test
#     httpContentBuffer: 1 MB,       # limit for HTTP content test
#     networkTimeout:    5 seconds   # timeout for network I/O
#     programTimeout:    300 seconds # timeout for check program
#     stopTimeout:       30 seconds  # timeout for service stop
#     startTimeout:      120 seconds  # timeout for service start
#     restartTimeout:    30 seconds  # timeout for service restart
}
```
