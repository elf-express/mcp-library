## [安裝](#id3)

獲得許可證後，您可以切換到包含 OPNcentral 的商業軟體儲存庫。要安裝，只需進入系統->韌體->插件並蒐索`os-OPNcentral`。

## [註冊新主機](#id4)

在新增主機之前，您需要從要授予存取權限的電腦產生 API 金鑰和機密。 API 金鑰在使用者管理員（system\_usermanager.php）中管理，進入使用者管理員頁面並選擇使用者。在頁面下方的某個位置，您會找到該使用者的 API 部分。

點選+號新增密鑰。建立金鑰後，您將收到一份（單一下載），其中包含一個文字檔案（ini 格式）中的憑證。該文件的內容如下所示：

```
key=w86XNZob/8Oq8aC5r0kbNarNtdpoQU781fyoeaOBQsBwkXUt
secret=XeD26XVrJ5ilAc/EmglCRC+0j2e57tRsjHwFepOseySWLM53pJASeTA3
```

接下來前往 Management ‣ Host ‣ Configuration 中管理選單的 Hosts 部分並新增主機，複製機器中的 url 以及上面產生的 API 金鑰和密碼。

注意事項

如果您使用自簽名證書，您可以停用證書驗證，但我們建議為電腦產生正確的證書。

### [中央WebGui憑證管理](#id5)

主機配置提供了將中央憑證連結到託管主機的選項，在這種情況下，憑證將分發到主機（如果正在設定`WebGui`）。

使用此功能，您可以輕鬆地集中管理證書（手動或使用ACME）。

提示

在系統 ‣ 設定 ‣ Cron 中新增 `OPNcentral - provision / reconfigure remote hosts` 以及每日規劃，以每天自動設定所有連接的防火牆。

注意力

請勿同時同步`Certificates`和`WebGUI`。 [設定類別WebGUI](#provisioning-classes-webgui)

## [集中備份](#id7)

當在通用主機設定標籤中選取「啟用備份」時，OPNcentral 將每晚對所有已配置的主機執行備份。主機概述（管理 ‣ 主機 ‣ 設定）顯示每個主機的備份數量及其相關大小和上次修改日期。

注意事項

修改日期定義了遠端主機上次更改的時間，因此如果主機在較長時間內沒有更改，則該值將顯示較舊的日期。

提示

可以從 GUI 手動執行備份。為此，請前往 Management ‣ Host ‣ Configuration 並按 `Execute backup` 按鈕。

提示

如果需要更頻繁的備份，只需在系統‣設定‣Cron 中為任務`OPNcentral - backup remote hosts` 新增一個 cron 作業即可。

## [使用主機群組的多租戶](#id8)

可以使用 Management ‣ Host ‣ Groups 選單選項將主機組織成群組。預設情況下，所有有權存取指定 OPNcentral 選單選項的使用者都可以存取主機。您可以透過將主機連結到一個或多個群組來更改該行為，您可以在其中限制存取。

[![](<../images/13388a63-blockdiag-92b1f550c721b0d0baefd967cdfb81.png>)](https://docs.opnsense.org/_images/blockdiag-92b1f550c721b0d0baefd967cdfb81ac849a4b6e.png)

警告

將主機附加到多個主機群組並想要限制存取時，請確保限制所有主機群組，以避免所有 OPNcentral 使用者意外存取。

在各種管理頁面上，都有可用於登入相關防火牆的直接連結。通常連接的節點會顯示一個鏈接，單擊時會在新選項卡中打開。

下面的範例顯示了韌體狀態頁面中的一個鏈接，該鏈接將打開`https://node1.opnsense.local`。

當允許管理伺服器存取連接節點上的 OPNcentral 元件時，它將在點擊連結後使用分配給 api 令牌使用者的正確憑證自動登入。

如果受管電腦上安裝了最新的商業版，但存取禁止自動登錄，您將被重新導向到登錄頁面。

當連接的機器不是使用商業版時，無法使用該鏈接，將向用戶顯示如下訊息：

可以使用 Management ‣ Status ‣ Firmware 頁面聯繫所有已連接和已啟用的計算機，訪問該頁面時將自動聯繫所有已連接的計算機以報告其狀態和安裝的版本。

[![../../_images/OPNcentral_status_toupdate.png](<../images/bba5741e-OPNcentral_status_toupdate.png>)](https://docs.opnsense.org/_images/OPNcentral_status_toupdate.png)

當有可用更新時，它將顯示在清單中，包括此升級是否需要重新啟動。升級按鈕會啟動升級過程，但如果選取 **啟用重新啟動**，則只會升級需要重新啟動的電腦。

提示

使用刷新按鈕再次請求狀態。

## [配置/共享設定](#id13)

為了配置應共用的設置，您可以在主機設定 Management ‣ Host ‣ Configuration 中配置要同步的「類別」。

[![../../_images/OPNcentral_provisioning_host_classes_setup.png](<../images/9f781828-OPNcentral_provisioning_host_classes_set.png>)](https://docs.opnsense.org/_images/OPNcentral_provisioning_host_classes_setup.png)

警告

**非常**小心地將設定推送到連接的防火牆，這可能會斷開您的會話，例如防火牆和路由相關選項。中央管理主機無法預測您計劃進行的設定是否會導致防火牆無法存取。

## [配置類別](#id14)

預設情況下，合併來自中央防火牆的設定項會覆蓋目標電腦上的設置，但在某些情況下，我們需要更實用的方法來處理本機修改。

在本章中，我們將描述如何在同步時處理具有特殊實作的類別以及如何利用此行為來簡化管理。

### [用戶與群組](#id15)

當使用者和群組同步時，現有的 api key+secret 會合併到同名使用者中，以防止重新配置後出現存取問題。為了避免問題，請在使用同步之前確保有一個具有正確憑證的唯一使用者名稱。

注意事項

儘管相當多的設定可能會使用 OPNsense 中提供的外部身份驗證選項，但有時在不同防火牆之間共用相同的使用者資料庫是實用的。此選項允許共享，無需在所有連接的防火牆上使用相同的密鑰+秘密。

### [別名（防火牆）](#id16)

由於各個防火牆部分依賴別名，因此 OPNcentral 在從遠端防火牆刪除本地別名之前會檢查是否使用了別名。

由於這個強大的功能，在同步中央別名後，您還可以使用巢狀將遠端別名組合到新的本機別名中。

例如，當本機電腦具有 `local_alias_1` 並且中央位置提供 `central_alias_1` 時，當兩者合併為 `local_alias_2` 並且在防火牆/nat 規則中使用 `local_alias_2` 時，它將在從儀表板執行重新配置操作後自動合併中央變更。

![](<../images/cfd7a1a5-blockdiag-7e939dcbc0c5968ff2810b8363f2c8.png>)

注意事項

只要使用`local_alias_2`，`local_alias_1`和`local_alias_2`都會在配置後保留。

### [防火牆規則](#id17)

合併防火牆規則將使中心節點上不存在的介面保持不變，因為這些介面被提供給目標防火牆。如果您想要排除某些介面（對於所有遠端防火牆），您可以在「常規設定」標籤上的「管理」->「主機設定」中輕鬆覆蓋已知介面。

由於處理不同類型的規則有明確的順序，因此您可以根據要使用的「介面」類型來選擇是先符合中心規則還是最後符合中心規則。

![](<../images/21c7e41a-blockdiag-ec0d5aaf9b949b5a5e296533bff3fe.png>)

提示

當強制介面群組到備份節點時，這些將優先於LAN和WAN等介面規則，當僅透過介面群組發送時，遠端防火牆能夠允許否則將被拒絕的流量。

注意事項

當多個介面附加到（浮動）規則時，這些介面將被配置演算法刪除，因為這些問題的意圖並不完全清楚。

筆記

中央節點上適用於所有介面或選擇的介面的規則始終傳送到遠端防火牆。如果這不是故意的，最好不要在「浮動」規則中使用這些選項。

### [NAT（防火牆）](#id18)

合併 nat 規則將使中心節點上不存在的介面保持不變，因為這些介面被提供給目標防火牆。如果您想要排除某些介面（對於所有遠端防火牆），您可以在「常規設定」標籤上的「管理」->「主機設定」中輕鬆覆蓋已知介面。

注意事項

所有 NAT 類型規則 (`Port Forward`, `One-to-One`, `Source NAT (Outbound)`, `NPTv6`) 的處理方式類似。

注意事項

當多個介面附加到一條規則時，可以進行連接埠轉送。這些將被配置演算法刪除。

注意事項

中央節點上適用於所選介面的連接埠轉送規則始終傳送到遠端防火牆。如果這不是故意的，最好阻止使用這些轉發。

### [防火牆類](#id19)

合併類別將保留遠端防火牆上目前使用的類別。

### [WebGui（管理）](#id20)

為了防止同步後損壞，同步後將保留 webgui 使用的憑證（或將發送主機配置中提供的憑證）。

注意

目前無法合併憑證和 webgui 管理設置，因為在這種情況下憑證儲存可能會被覆寫。

## [配置教學](#id21)

在本節中，我們將展示 OPNcentral 中央管理提供的一些功能的範例配置。

### [WebGUI自動登入](#id22)

為了使自動登入功能發揮作用，需要以下基礎設施：

-   一台安裝了 Business Edition 和 OPNcentral 的 OPNsense，將用作配置的中央主機。建議將此 OPNsense 用於配置和管理以外的其他任務。
    
-   安裝了商業版和 OPNcentral 的一個或多個其他 OPNsense，將由中央主機管理。
    
-   您自己的PKI（公鑰基礎設施）或使用系統‣信任中提供的 OPNsense
    
-   管理每個 OPNsense 的 FQDN（完全限定網域名稱）的 DNS 基礎設施或公共 DNS 供應商
    

我們假設我們有這個範例基礎設施：

| FQDN | IP 地址 |任務|
| --- | --- | --- |
| `central-host.opnsense.local` | 203.0.113.1 |中央管理主機 |
| `node-a1.opnsense.local` | 198.51.100.1 |防火牆節點站點 A |
| `node-b1.opnsense.local` | 192.0.2.1 |防火牆節點站點 B |

#### 1\.將防火牆節點新增至中心主機

-   轉至管理 ‣ 主機 ‣ 設定。
    
-   請按照此處所述的步驟[註冊新主機](#register-new-hosts)。
    
-   如果有連線問題，請檢查中央主機是否可以解析防火牆節點的 FQDN。它們必須透過其 FQDN 添加，*不能*透過 IP 位址添加。否則證書的SAN將與FQDN不符。
    

提示

使用自訂 WebGUI 連接埠時，請像這樣指定套接字：`https://node-a1.opnsense.local:8443`

注意事項

僅將防火牆節點新增至中央主機。請勿將中央主機新增至其自身，以防止配置循環。

#### 2\.在中央主機上建立PKI

有關更多信息，請閱讀[設定自簽名憑證鏈](<104 設定自簽名憑證鏈.md>)

-   前往 System ‣ Trust ‣ Authority 並按 *+* 建立內部憑證授權單位。
    
-   將所有填滿欄位保留為預設值。
    
-   新增您自己的州、城市、組織和電子郵件地址。
    
-   作為描述性名稱和通用名稱，請使用 `opncentral-ca`。
    
-   按*儲存*。
    

注意事項

匯出 CA 證書，並將其匯入至應使用自動 WebGUI 登入的每個用戶端的受信任根證書儲存空間。只有當瀏覽器信任該連接時它才會起作用。

#### 3\.為所有主機建立伺服器憑證

-   前往 System ‣ Trust ‣ Certificates 並按 *+* 建立內部憑證。
    
-   將所有填滿欄位保留為預設值。
    
-   作為類型，選擇伺服器憑證。
    
-   作為通用名稱和備用名稱類型DNS (SAN)，選擇防火牆的 FQDN；例如，`central-host.opnsense.local`
    
-   按*儲存*並重複此操作，直到有中央主機和防火牆節點的憑證。
    

#### 4\.更改中央主機的WebGUI證書

-   前往系統 ‣ 設定 ‣ 管理。
    
-   確保協定為HTTPS，並選擇中心主機為FQDN的憑證；例如，`central-host.opnsense.local`
    
-   按*儲存*並按出現的鏈接，這會將會話重定向到新的瀏覽器標籤。
    

注意事項

瀏覽器現在應該會自動信任與中央主機的連線。如果沒有，請確保已依照步驟 2 中所述匯入`opncentral-ca` 憑證。在繼續之前必須建立瀏覽器信任。

#### 5\.向防火牆節點提供憑證和 WebGUI

-   轉至管理 ‣ 主機 ‣ 設定。
    
-   選擇一個防火牆節點，例如`node-a1.opnsense.local`並進行編輯。
    
-   確保現在未選擇驗證SSL。
    
-   在 Push WebUI 證書中選擇正確的證書，本例為`node-a1.opnsense.local`
    
-   在供應類別中，選擇`Web GUI`。注意*不要*選擇`Certificates`，只有`Web GUI`需要作為Provision類別。
    
-   按“儲存”並對所有其他防火牆節點重複相同的操作。
    
-   前往 Management ‣ Provisioning 並選擇所有主機，然後按 Reconfigure。
    
-   配置成功後，返回 Management ‣ Host ‣ Configuration 並為所有防火牆節點啟用 Validate SSL。
    

#### 6\.測試自動登入

-   前往 Management ‣ Provisioning 並點選任意主機連結。將開啟一個附加瀏覽器選項卡，其中包含所選的防火牆節點，並且會話將自動登入。
    

提示

此功能對於集中管理大量 OPNsense 防火牆的網路管理員特別有用。
