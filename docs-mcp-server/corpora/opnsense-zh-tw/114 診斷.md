# 診斷

> 章節：[Interfaces](<000 目錄.md#c-19>)

介面診斷頁麵包含各種工具，可協助調試網路問題。

## ARP表格

[ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol)表模組顯示此防火牆已知的所有MAC位址。

---

|   |   |
| --- | --- |
| IP | IPv4 位址 |
| MAC | [MAC](https://en.wikipedia.org/wiki/MAC_address)地址 |
| 製造商 | 根據上述 MAC 位址尋找製造商 |
| 介面 | 相關介面 |
| 介面名稱 | 如果找到接口，則顯示接口名稱 |
| 主機名稱 | 如果是 DHCPv4 用戶端，則主機名稱取自租約檔案 |

## DNS查找

從防火牆執行快速 DNS 查詢。

| --- | --- |

| 製造商 | 根據上述 MAC 位址尋找製造商 |
| 介面 | 相關介面 |
| 介面名稱 | 如果找到接口，則顯示接口名稱 |

## Netstat

netstat 模組包含一組有用的網路狀態和統計指標，這些指標分為多個主題。

提示

使用標籤頁中的刷新圖示刷新其中的資料（選擇不會改變）。

以下資訊依相關性排序如下：

### 介面

本節包含系統的所有（實體和虛擬）連接接口，其中包含諸如每個（硬體）位址發送和接收的資料包和位元組數等指標。

### 協定

包含每個網路協定的系統級統計資料。例如，此區域可以找到 TCP 監聽連線數、已傳送資料包數、重複資料包數等統計資料。

### 插座

顯示網路和 Unix 網域套接字，基本上將 FreeBSD 上的`netstat`與`sockstat`結合起來，以便提供有關哪個進程正在監聽的見解，並結合系統已知的指標。

### Netisr

顯示內核網路調度服務（稱為`netisr(9)`的統計資訊。

### 記憶

顯示記憶體管理例程（ `mbuf(9)` ）所記錄的統計資料。網路管理著一個私有的記憶體緩衝區池。

### BPF

顯示有​​關`bpf(4)`對等體的統計資訊。這包括bpf設備已匹配、丟棄和接收的資料包數量等信息，以及當前緩衝區大小和設備狀態等資訊。

## 資料包捕獲

封包擷取模組可用於深入分析流經一個或多個網路介面的流量。它提供了一些可選功能，詳情如下。

---

|   |   |
| --- | --- |
|介面|要開始捕獲的介面清單。在每個選定的介面上啟動 tcpdump 進程 |
|亂交|設定後，系統將捕捉介面上存在的所有流量，而不是前往防火牆的流量。 |
| 位址族 | 擷取 IPv4、IPv6 或兩者皆擷取 |
| 反轉協議 | 選擇下方已選協議之外的所有協議 |
| 協定 | 要使用的過濾協定 |
| 主機位址 | 此值可以是來源位址或目標位址IP/MAC ，也可以是子網路位址CIDR ）。封包擷取程式會在來源位址或目標位址欄位中尋找此位址。如果符合失敗，可以在值前加上「 `not` 」。可以使用布林運算式指定多個位址IP或子網路CIDR 。如果將此欄位留空，則會擷取指定介面上的所有資料包。範例： `not 10.0.0.0/24 not and not 11.0.0.1 or 00:0a:01:02:03:04` |
| 反轉連接埠 | 選取下方選取連接埠以外的所有連接埠 |
| 連接埠 | 要過濾的連接埠號碼（例如， `443`表示標準 https， `22`表示 ssh） |
|資料包長度|資料包長度是將捕獲的每個資料包的位元組數。預設值為 0，這將捕獲整個幀，無論其大小如何。 |
|計數|這是封包擷取將抓取的封包數量（每個選定的介面）。預設值為 100。輸入 0（零）表示無計數限制。 |
| 說明 | 將在「職位」標籤中顯示的說明 |

抓包使用[tcpdump](https://www.tcpdump.org/)並在背景運行。執行擷取後，您可以使用作業標籤中的 **檢視擷取** 按鈕檢視它，也可以下載 pcap 檔案以在外部工具（例如 [Wireshark](https://www.wireshark.org/)）中檢查它。

「作業」標籤包含所有正在執行或已執行的擷取任務，每個擷取作業都有以下可用選項：

-   顯示捕獲目前處於活動狀態。
-   移除捕獲（停止目前正在運行的捕獲）
-   停止目前捕獲
-   （重新）啟動目前捕獲，如果之前已執行，則刪除先前的結果。
-   下載包含所有捕獲的 pcap 檔案和帶有所選選項的 json 檔案的 zip 文件
-   以高解析度檢視拍攝畫面
-   以中等細節查看拍攝畫面
-   以標準細節看拍攝效果

提示

當擷取仍在進行時，所有檢視按鈕均可使用，它們只會顯示到目前為止收集到的詳細資訊。

## 平

使用 ping 指令透過ICMP回顯請求來決定是否可以存取遠端主機。它是驗證基本連接性最常用的工具之一。

---

|   |   |
| --- | --- |
| 主機名稱或IP | 發送 ICMP 封包的主機名稱或IP位址 |
|位址家庭|使用 IPv4 或 IPv6 傳送 |
| 來源位址 | 要使用的來源位址，可以是此防火牆上設定的任何位址 |
| 封包大小 | 指定要傳送的資料位元組數。請注意，這是有效載荷大小，也會添加IP和ICMP頭部。 |
| 不要碎片化 | 設定DF位。 |
| 說明 | 將在「職位」標籤中顯示的說明 |

提示

若要尋找MTU （最大傳輸單元）問題，請使用「不分片」選項強制特定大小的封包在網路中傳輸。

提示

當預設 ping 指令無法到達目標位址，但使用預設來源位址的 ping 指令可以到達時，通常需要新增一條靜態路由，強制流量使用正確的來源位址。例如，基於 IPsec 策略的隧道通常會在指定的來源網路上安裝核心陷阱，這種情況很常見。

「作業」標籤包含所有正在執行或已執行的 ping 任務，每個作業都有下列選項和屬性：

-   顯示 ping 操作目前處於活動狀態
-   移除 pi​​ng 功能（目前處於活動狀態時停止捕獲）
-   停止目前ping
-   （重新）啟動目前 ping 任務，如果之前已執行過，則刪除先前的結果。

---

|   |   |
| --- | --- |
| 說明 | 職位說明 |
| 主機名稱 | 目標主機名稱或 IP 位址 |
| source\_address | 來源位址（預設為空） |
| 發送 | 發送的資料包數量 |
| 已接收 | 已接收封包數 |
| 分鐘 | 存活時間（毫秒） |
| 最大 | 最大存活時間（毫秒） |
| 平均值 | 平均存活時間（毫秒） |
|損失|損失百分比|
| last\_error | 上次發現的 ping 錯誤 |

## 端口探針

測試主機是否開啟了某個TCP埠並接受連線。

## 追蹤路線

使用 [traceroute](https://www.freebsd.org/cgi/man.cgi?query=traceroute) / [traceroute6](https://www.freebsd.org/cgi/man.cgi?query=traceroute6)來測量流量嘗試到達特定主機時將遵循的路徑。

---

|   |   |
| --- | --- |
| 主機名稱或IP | 目標主機名稱或IP位址 |
|地址家庭|地址家庭使用 |
| 協議 | 用於追蹤的協議，預設使用UDP ，如果此協議不起作用，則可以使用ICMP作為備選方案 |
| 來源位址 | 來源位址（預設為空） |

提示

結果網格中還包含[自治系統編號](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\) ），如果您想過濾進出特定方的流量，這將非常有用。使用「防火牆」‣「別名」收集關聯的網路並將其新增至規則中。
