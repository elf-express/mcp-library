# 遷移

> 章節：[Development Manual](<000 目錄.md#c-52>) › [Frontend](<000 目錄.md#c-55>) › [Creating Models](<000 目錄.md#c-56>)

在模型 xml 中使用 `<version/>` 標籤時，您會自動允許設定資料升級。如果標籤遺失，它將自動採用您的版本`0.0.0`（初始版本）。

遷移功能提供了一個可插入框架，可在安裝新軟體後提供新的和變更的屬性，因此在執行升級或安裝軟體包時會自動觸發。

提示

您始終可以從控制台執行`/usr/local/opnsense/mvc/script/run_migrations.php`來手動觸發遷移。這將輸出所有已安裝的模組和執行的升級。

如果未提供覆蓋，且執行配置的模組版本與安裝的模組版本不相等，則會自動使用 `BaseModelMigration` 基類建立遷移。這將處理基本更改，例如新增欄位和應用預設值。

注意事項

目前版本將始終儲存為模型 xml 上的屬性（例如 `<Alias version="1.0.0">`）

## 自訂遷移

在某些情況下，人們希望在版本之間升級時執行自訂操作，例如從舊配置設定收集資料。

模型目錄中的目錄`Migrations`用於保存每個版本的遷移程式碼。預設情況下，其中的類別（和檔案）使用以下命名方案：`M1_0_0`，代表\[M\]遷移版本\[1.0.0\]。

注意事項

如果不同的模型共用一個命名空間，您可以變更遷移檔案的前綴，當沒有提供任何內容時預設為**M**，可以使用標籤`<migration_prefix/>`將其變更為其他名稱。 （例如`<migration_prefix>MFP</migration_prefix>`）

模型遷移的樣板如下圖所示（遷移到1.0.0）：

```php
class M1_0_0 extends BaseModelMigration
{
    /**
     * default model migration
     * @param $model
     */
    public function run($model)
    {
        parent::run($model);
    }

    /**
     * post migration action, run after config sync
     * @param $model
     */
    public function post($model)
    {
        return;
    }
}
```

它包含兩個方法，`run()`和`post()`。第一個在記憶體中執行，然後將資料序列化回運行配置並按順序執行所有版本步驟。 （從1.0.0升級到1.0.2可能會執行1.0.1, 1.0.2, 1.0.3）。在這種情況下，配置資料本身將是同步的。

注意事項

除特殊情況外，`run()`方法應始終包含父方法呼叫`parent::run($model);`以執行基本遷移功能。

後操作在正常模型配置之後調用，有時可以實際用於更改原始模型 xml，例如，如果模型版本需要移動資料集，而不實際更改內容。

注意事項

儘管存在切換，但資料遷移很容易導致競爭條件。始終嘗試設計適合更改的軟體，例如添加預設情況下通過驗證的欄位始終優先於預設會失敗的情況。
