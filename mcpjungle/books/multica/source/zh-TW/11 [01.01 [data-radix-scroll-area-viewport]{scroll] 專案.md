# 專案

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

用專案組織相關任務，併為它們提供共同的目標、計劃和執行上下文。

專案用來組織需要多條 [任務](/docs/zh/issues) 一起完成的工作，例如一次產品釋出、一次遷移，或一個分階段推進的功能。

一條任務能說清的工作不需要專案。專案適合有共同目標、需要統一跟進進度，或需要共享倉庫和工作目錄的一組工作。

## 專案的組成

| 內容 | 用途 |
| --- | --- |
| **名稱、圖示和描述** | 目標、範圍和長期有效的要求；描述會進入專案內智慧體的執行上下文。 |
| **狀態** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **優先順序** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **負責人（lead）** | 成員或智慧體，表示誰負責協調專案。 |
| **開始和截止日期** | 專案計劃的時間範圍。 |
| **任務和進度** | 專案中的工作及其完成比例。 |
| **資源** | 關聯的 GitHub 倉庫或指定電腦上的本地目錄。 |

![项目详情：按状态分列的任务、进度与项目描述](/docs/_next/image?url=%2Fdocs%2F_next%2Fstatic%2Fmedia%2Fproject-detail.d958712d.webp&w=3840&q=75)

## 專案和任務的關係

一個專案可以包含多條任務，一條任務最多屬於一個專案。可以在專案中直接建立任務，也可以在任務屬性中選擇或更換專案。

專案進度按關聯任務自動計算：

```
进度 = 状态为 done 或 cancelled 的 issue 数 ÷ 项目中的全部 issue 数
```

`cancelled` 表示這項工作已從專案範圍中結束，因此計入進度。專案狀態與任務狀態彼此獨立：所有任務完成後專案不會自動變為 `completed`，修改專案狀態也不會批次修改其中的任務。

## 專案描述與執行上下文

智慧體執行專案內的任務時，專案名稱和描述會加入本次執行的上下文。描述適合儲存所有相關執行都需要的資訊：目標、技術邊界、交付約定。只與單條任務相關的要求寫在該任務中。

## 新增資源

專案資源告訴智慧體使用哪些程式碼和工作目錄：

-   **GitHub 倉庫**：提供可 checkout 的倉庫和可選 ref。
-   **本地目錄**：讓指定電腦上的執行時在已有目錄中工作，目錄內容會被智慧體直接修改。

具體選擇和安全邊界見[專案資源](/docs/zh/project-resources)。

## 專案負責人

Lead 可以是成員或智慧體，表示誰負責協調專案。它不是許可權設定，不會自動分配專案中的任務；把智慧體設為 lead 也不會自動執行它。啟動執行仍需分配任務、@提及或自動化觸發。

## 固定到側邊欄

固定後，專案出現在你的側邊欄中。固定是個人偏好，不影響其他成員。

## 建立、編輯和刪除

工作區成員都可以建立和編輯專案；只有 `owner` 和 `admin` 可以刪除。

刪除專案不會刪除其中的任務：它們解除關聯後繼續保留在工作區；專案的描述、狀態和資源會被永久刪除。
