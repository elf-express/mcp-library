# 飛書 Bot

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

把智慧體接入飛書，在私聊或群聊中直接交代工作。

把一個 Multica 智慧體連線成飛書 Bot 後，團隊成員可以在飛書裡私聊它、在群裡 @ 它，也可以用 `/issue` 建立任務。對話和執行記錄仍會儲存到 Multica 工作區。

每個 Bot 只對應一個智慧體。需要在飛書中使用多個智慧體時，分別為它們連線 Bot。

## 連線 Bot

智慧體的所有者、工作區 owner 和 admin 可以發起連線：

1.  開啟 **智慧體**，選擇要接入飛書的智慧體。
2.  進入 **整合**，點選 **繫結到飛書**。
3.  用飛書掃描二維碼並確認授權。
4.  回到 Multica。頁面顯示 **已連線到飛書** 後即可使用。

二維碼為一次性憑證，過期後重新生成即可。已經連線的智慧體不會再次顯示掃碼入口；需要改名或調整許可權時，點選 **在飛書中管理**。

目前只開放中國大陸版飛書的新連線入口。已有的國際版 Lark 連線仍可繼續使用和管理。

## 第一次使用

成員第一次給 Bot 發訊息時，會收到一個賬號繫結連結：

1.  開啟連結並登入 Multica。
2.  確認要關聯的工作區賬號。
3.  回到飛書，再發送一次訊息。

繫結後，Multica 才能確認訊息來自哪位工作區成員。非成員無法使用 Bot。

## 在飛書中交代工作

### 私聊

直接給 Bot 發訊息即可。連續訊息保留在同一段 Multica 對話中，智慧體的回覆也發回當前對話。

### 群聊

先把 Bot 加入群聊，再 `@Bot` 並寫下要求。Bot 只會響應明確 @ 它的訊息；執行時會結合當前會話中可讀取的近期上下文。

### 建立任務

傳送：

```
/issue 修复登录后的跳转问题
Safari 登录成功后仍然停留在登录页。
```

第一行作為標題，其餘內容作為描述。只發送 `/issue` 不會建立任務；Bot 會回覆用法提示。

## 管理連線

開啟 **設定 → 訊息渠道 → 飛書** 可以檢視工作區內已連線的 Bot。工作區 owner 和 admin 可以在這裡斷開連線；智慧體所有者也可以回到該智慧體的 **整合** 頁面管理自己的 Bot。

斷開後，Bot 不再接收新訊息，已有的對話和審計記錄不會隨之刪除。

## 自託管配置

Multica Cloud 無需額外配置。自託管部署需要先設定一個用於加密 Bot 憑據的金鑰：

```
MULTICA_LARK_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以這樣生成：

```
openssl rand -base64 32
```

重啟 API 服務後，再從智慧體的 **整合** 頁面連線 Bot。該金鑰需要長期儲存：更換或丟失後，已有憑據無法解密，需要重新連線。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用於代理、測試等特殊部署，正常情況下不需要設定。

## 常見問題

-   **沒有繫結按鈕**：確認當前賬號是智慧體所有者、工作區 owner 或 admin，並檢查自託管金鑰是否已配置。
-   **二維碼失效**：關閉彈窗後重新發起連線。
-   **Bot 要求繫結賬號**：開啟繫結連結並使用該工作區的 Multica 賬號登入。
-   **Bot 不執行**：檢查智慧體是否已歸檔，以及它使用的[執行時](/docs/zh/daemon-runtimes)是否線上。
-   **Bot 完全不回覆**：應用必須通過長連線推送事件，Multica 沒有 webhook 接收地址。開啟飛書開發者後臺的 **事件與回撥 → 事件配置**，確認訂閱方式是使用長連線接收事件而不是請求地址，`im.message.receive_v1` 已訂閱，並且包含該配置的版本已釋出（企業需要稽核時還要通過稽核）。配成請求地址的應用照樣能繫結、照樣顯示「已連線」，但一條訊息都收不到。
