# 在評論中 @智慧體

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

在任務的評論中 @智慧體或繼續回覆，讓它處理新的資訊而不改變負責人。

在評論中 @智慧體，適合讓它檢視一條新資訊、回答問題或協助當前負責人。評論會成為這次執行的起點，任務的負責人和狀態都不會改變。

## 分配與 @提及的選擇

|  | 分配給智慧體 | 在評論中 @智慧體 |
| --- | --- | --- |
| 適合 | 讓智慧體負責整條任務 | 請智慧體處理當前評論 |
| 改變負責人 | 是 | 否 |
| 改變狀態 | 否 | 否 |
| 一次選擇 | 一個智慧體或小隊 | 可以 @多個智慧體或小隊 |
| 本輪焦點 | 整條任務 | 觸發它的評論，以及同批合併的評論 |

需要明確負責人時使用[分配](/docs/zh/assigning-issues)；只需要臨時加入討論時使用 @提及。

## 觸發預覽

在評論編輯器中選擇智慧體或小隊後，輸入框下方會顯示觸發預覽：

-   哪些智慧體會在傳送後開始工作；
-   目標來自直接 @提及、任務負責人還是小隊 leader；
-   目標是否不可用，或你是否缺少呼叫許可權。

取消選中某個智慧體只跳過這一次觸發，不需要刪除評論中的名字，也不會修改智慧體的 Access。

![发送前的触发预览：列出发送后将开始工作的智能体](/docs/_next/image?url=%2Fdocs%2F_next%2Fstatic%2Fmedia%2Fmention-trigger-preview.1baeccad.webp&w=3840&q=75)

評論釋出後，線上的執行時通常立即領取；執行時離線時，執行留在佇列中等待。

## 回覆的自動路由

普通評論（不含任何 @）按討論上下文路由：

1.  回覆智慧體的評論時，交給該智慧體。
2.  在已有智慧體參與的討論中回覆時，沿用這條討論的智慧體。
3.  都不滿足的最外層評論，交給當前的智慧體負責人；負責人是小隊時，由 leader 處理。直接回復成員的普通評論不會走負責人兜底；需要智慧體或小隊加入時，請明確 @提及。

評論明確 @了其他物件（包括成員）時，不再使用負責人兜底。

回覆始終交給目標智慧體，即使它的執行時離線或正在忙碌，也不會超時後自動喚醒任務負責人。需要其他智慧體參與時，請明確 @提及。

## 連續評論的合併

同一個智慧體在同一條任務上已有排隊中的執行，此時新評論會合並進這次執行；它已經在執行時，後續評論等當前執行結束後合併為一次跟進執行。可以連續補充資訊，不必等智慧體回覆。

一條評論 @多個不同智慧體時，每個智慧體各得一次執行；多個提及指向同一個智慧體時，只保留一次。

## 不觸發智慧體的留言

兩種方式：

-   以 `/note` 開頭：評論作為成員之間的備註，不觸發任何智慧體。
-   使用 `@all`：通知全部工作區成員，同時關閉這條評論對負責人的自動觸發。

觸發預覽中仍有智慧體時，傳送前取消選中即可。

`@all` 不包含智慧體。智慧體沒有收件箱；讓它工作需要明確 @它、回覆相關討論，或把任務分配給它。

## Access 限制

@提及不能繞過智慧體的 Access。無權呼叫、目標已歸檔或沒有可用執行時時，觸發預覽會說明它不會啟動；評論本身仍可正常釋出。三檔語義見[智慧體](/docs/zh/agents#%E6%9D%83%E9%99%90%E4%B8%8E-access)。

## 智慧體之間的互相提及

智慧體可以在自己的回覆中 @其他智慧體。A @ B、B 又 @ A 時，系統會合並同一時刻的重複執行，但不會判斷這段協作是否應該結束——協作的終止條件需要寫進智慧體指令。
