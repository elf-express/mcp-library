# 工作區

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

工作區是團隊、工作和智慧體配置彼此隔離的邊界。

工作區是 Multica 的最上層邊界。成員、任務、專案、智慧體、skill 和執行記錄都屬於某一個工作區，彼此完全隔離。

## [工作區的組成](#%E5%B7%A5%E4%BD%9C%E5%8C%BA%E7%9A%84%E7%BB%84%E6%88%90)

| 類別 | 內容 |
| --- | --- |
| **工作** | 任務、專案、評論、附件、執行記錄 |
| **團隊** | 成員、角色、邀請 |
| **智慧體** | 智慧體配置、skill、執行時、自動化 |
| **共享設定** | 上下文、標籤、自定義屬性、整合 |

**上下文**會提供給工作區中的每個智慧體，適合寫團隊背景、產品約定和長期有效的要求。一次性的執行要求寫在對應的任務裡。

## [建立工作區](#%E5%88%9B%E5%BB%BA%E5%B7%A5%E4%BD%9C%E5%8C%BA)

建立時填三項：

-   **名稱**：展示給成員，之後可以修改。
-   **工作區 URL**：地址中的 slug，例如 `multica.ai/my-team` 裡的 `my-team`。只能用小寫字母、數字和連字元，不能與已有工作區或保留地址重複，建立後不可修改。
-   **任務字首**：根據工作區 URL 自動填好，建立前可以改。字首為 `MUL` 時，任務編號顯示為 `MUL-1`、`MUL-2`，在工作區內獨立遞增。只能用大寫字母和數字，最多 10 位，之後也可以在設定裡修改。

建立者自動成為 `owner`。

## [修改設定](#%E4%BF%AE%E6%94%B9%E8%AE%BE%E7%BD%AE)

`owner` 和 `admin` 可以修改名稱、圖示、描述、上下文和任務字首；`member` 只能檢視。

![工作区设置：名称、上下文、slug、任务前缀与危险区](<../images/935e1ccb-image.webp>)

修改任務字首後，所有任務立即換用新編號（`MUL-5` 變為 `NEW-5`），但 PR、分支名和聊天記錄裡的舊編號不會更新。

## [切換和離開](#%E5%88%87%E6%8D%A2%E5%92%8C%E7%A6%BB%E5%BC%80)

一個賬號可以加入多個工作區。切換隻改變當前檢視的範圍，不移動任何資料。

離開工作區後，需要重新接受邀請才能回來。離開會同時停用你擁有的執行時、歸檔繫結在其上的智慧體，並取消它們未結束的執行。

最後一名 `owner` 不能離開，需要先把另一位成員提升為 `owner`。

## [刪除工作區](#%E5%88%A0%E9%99%A4%E5%B7%A5%E4%BD%9C%E5%8C%BA)

只有 `owner` 可以刪除工作區。刪除會永久移除其中的全部工作、成員、智慧體配置和執行記錄，無法恢復。暫時不參與時選擇離開，而不是刪除。
