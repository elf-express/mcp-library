# 钉钉 Bot

> 章節：[Multica Docs](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

把智能体接入钉钉，在私聊或群聊中直接交代工作。

把[智能体](<56 [01.01.01 GitHub] 智能体.md>)接入钉钉后，智能体所在工作区的成员可以私聊 Bot、在群里 @ Bot，或用 `/issue` 指令直接创建 Multica [任务](<53 [01.01.01 GitHub] 任务.md>)。对话和执行记录会保存到 Multica 工作区。

钉钉集成[由社区维护](<86 [01.01.01 GitHub] 社区维护的功能区域.md>)，不提供官方支持 SLA。遇到问题请提交到 [GitHub 任务](https://github.com/multica-ai/multica/issues)。

## [连接 Bot](#%E8%BF%9E%E6%8E%A5-bot)

智能体创建者或工作区 owner/admin 可以将智能体接入钉钉，智能体跟钉钉 Bot 是 1:1 的连接关系。

## [1\. 创建 Stream 模式机器人](#1-%E5%88%9B%E5%BB%BA-stream-%E6%A8%A1%E5%BC%8F%E6%9C%BA%E5%99%A8%E4%BA%BA)

1.  在[钉钉开放平台](https://open-dev.dingtalk.com/)创建一个**企业内部应用**。
2.  开启机器人能力，其中**消息接收模式**设为 **Stream 模式**。

## [2\. 给机器人授权](#2-%E7%BB%99%E6%9C%BA%E5%99%A8%E4%BA%BA%E6%8E%88%E6%9D%83)

默认已添加“机器人发消息权限”（`qyapi_robot_sendmsg`）。如需在 Multica 平台显示 Bot 名称，需手动添加“钉群基础信息管理权限”（`qyapi_chat_manage`）。

## [3\. 获取应用凭证](#3-%E8%8E%B7%E5%8F%96%E5%BA%94%E7%94%A8%E5%87%AD%E8%AF%81)

进入**凭证与基础信息**页面，复制 **Client ID（AppKey）** 和 **Client Secret（AppSecret）**。

## [4\. 把智能体接入钉钉](#4-%E6%8A%8A%E6%99%BA%E8%83%BD%E4%BD%93%E6%8E%A5%E5%85%A5%E9%92%89%E9%92%89)

1.  回到 Multica，打开 **智能体 → *你的智能体* → 能力 → 集成**。
2.  点击**连接钉钉**。
3.  填入 **AppKey** 和 **AppSecret** 后提交。

## [5\. 关联钉钉账号与 Multica 平台账号](#5-%E5%85%B3%E8%81%94%E9%92%89%E9%92%89%E8%B4%A6%E5%8F%B7%E4%B8%8E-multica-%E5%B9%B3%E5%8F%B0%E8%B4%A6%E5%8F%B7)

在钉钉上跟 Bot 私聊，或者在群里 @ Bot，触发一次关联请求，你会在 Bot 私聊对话框中收到一个链接（有效期约 15 分钟），点击链接后看到连接成功的提示即大功告成。

## [在钉钉中给智能体交代工作](#%E5%9C%A8%E9%92%89%E9%92%89%E4%B8%AD%E7%BB%99%E6%99%BA%E8%83%BD%E4%BD%93%E4%BA%A4%E4%BB%A3%E5%B7%A5%E4%BD%9C)

### [私聊](#%E7%A7%81%E8%81%8A)

直接给 Bot 发消息即可。智能体处理完任务后，会将结果回复至私聊对话框中。

### [群聊](#%E7%BE%A4%E8%81%8A)

把 Bot 加入钉群，再发送 `@your-bot <消息>`。每次追问都要重新 @，Bot 只处理 @ 它的消息。

### [发送图片](#%E5%8F%91%E9%80%81%E5%9B%BE%E7%89%87)

私聊和群聊都支持图文混排消息，图片支持 PNG、JPEG、GIF、WebP 和 BMP；每条消息最多 4 张，每张不超过 10 MB。暂不支持文件和语音消息。

注意，群聊中的图文混排消息，@ Bot 产生的内容也会作为消息内容的一部分发送给智能体，如果想精准剔除掉 Bot 名称，需添加“钉群基础信息管理权限”（`qyapi_chat_manage`）。

### [引用消息继续追问](#%E5%BC%95%E7%94%A8%E6%B6%88%E6%81%AF%E7%BB%A7%E7%BB%AD%E8%BF%BD%E9%97%AE)

使用钉钉的引用功能选中一条消息，再输入本轮内容；群聊中仍需 @ Bot。Multica 会把钉钉回调提供的、受支持的引用内容放在本轮消息前，作为智能体的上下文。引用中的 `/issue`、`/new` 或 `/clear` 只是引用内容，不会作为本轮指令执行。

### [消息处理反馈](#%E6%B6%88%E6%81%AF%E5%A4%84%E7%90%86%E5%8F%8D%E9%A6%88)

Multica 收到钉钉消息后，会尝试在用户原消息上添加钉钉的`收到`表情，以表示已将消息交由智能体处理；智能体处理完成、并成功将消息发送到钉钉后，`收到`表情会被替换为`Done`；任务被取消后，会撤回`收到`表情。

表情反馈依赖钉钉接口，不保证即时更新。判断结果时请结合 Bot 回复和 Multica 中的运行记录。

### [使用 `/issue` 创建任务](#%E4%BD%BF%E7%94%A8-issue-%E5%88%9B%E5%BB%BA%E4%BB%BB%E5%8A%A1)

发送 `/issue <标题>` 或者 `/issue <标题>{换行}<详细描述>`，就可以创建一个新 Multica 任务，并自动指派给 Bot 连接着的智能体。同一条消息内的图片也会以附件的形式添加到该任务中。跟普通对话消息不一样的是，`/issue` 指令不会在 Multica 的“[对话](<64 [01.01.01 GitHub] 与智能体对话.md>)”中留下记录。

### [使用 `/new` 新建 Chat](#%E4%BD%BF%E7%94%A8-new-%E6%96%B0%E5%BB%BA-chat)

发送 `/new` 会创建一个新的空 Multica Chat，后续钉钉消息会路由到新 Chat。发送 `/new <消息>` 会创建新 Chat，并把消息作为第一轮。之前的 Chat 仍保存在 Multica 中，可以继续使用。

### [使用 `/clear` 清空当前上下文](#%E4%BD%BF%E7%94%A8-clear-%E6%B8%85%E7%A9%BA%E5%BD%93%E5%89%8D%E4%B8%8A%E4%B8%8B%E6%96%87)

发送 `/clear` 会保留当前 Multica Chat，并把新的智能体可见上下文应用到下一条消息。发送 `/clear <消息>` 会把消息作为边界后的第一轮。完整 Chat 历史仍会显示在 Multica 中。

## [管理连接](#%E7%AE%A1%E7%90%86%E8%BF%9E%E6%8E%A5)

-   在**智能体 → *你的智能体* → 能力 → 集成**页面，智能体创建者、工作区 owner/admin 可以在此连接钉钉，或者断开连接。连接上钉钉后，这里会显示 Bot 名称和已成功处理过消息的钉群，以及 Bot 在钉群内的活跃状态数据，有智能体读权限的工作区成员都能看到这些信息。最近 90 天没有成功处理消息的群会归入**长期未活跃**，展开时再加载。
-   在**设置 → 消息渠道 → 钉钉**页面，显示当前工作区内所有有读权限且连接了钉钉的智能体列表，以及 Bot 在钉群内的活跃状态数据。工作区 owner/admin 还可以在此直接断开列表中任意智能体的钉钉连接。断开后 Bot 停止接收消息，安装记录仍会保留用于审计。工作区 owner/admin 还可以忘记某个群。忘记只会从列表中移除该群，不会删除对话和消息。如果已关联钉钉账号的工作区成员以后在该群再次 @ Bot，且 Multica 成功接收这条消息，群会重新出现。

## [自部署配置](#%E8%87%AA%E9%83%A8%E7%BD%B2%E9%85%8D%E7%BD%AE)

Multica Cloud 用户可跳过本节。自托管部署需要先设置一个用于加密钉钉 `AppSecret` 的密钥：

```
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
```

可以这样生成：

```
openssl rand -base64 32
```

重启 API 服务后，再连接钉钉。该密钥需要长期保存：更换或丢失后，已有 token 无法解密，需要重新连接。

账号绑定链接使用 `MULTICA_APP_URL`，未设置时回退到 `FRONTEND_ORIGIN`；它需要指向成员可以访问的 Multica 地址。
