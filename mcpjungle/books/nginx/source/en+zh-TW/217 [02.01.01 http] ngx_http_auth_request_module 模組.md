# Модуль ngx_http_auth_request_module｜ngx_http_auth_request_module 模組

## Модуль ngx\_http\_auth\_request\_module｜ngx_http_auth_request_module 模組

|   |
| --- |
| [Пример конфигурации](#example)<br>[Директивы](#directives)<br>     [auth\_request](#auth_request)<br>     [auth\_request\_set](#auth_request_set)<br>[設定範例](#example)<br> [指令](#directives)<br> [auth\_request](#auth_request)<br> [auth\_request\_set](#auth_request_set) |

Модуль `ngx_http_auth_request_module` (1.5.4+) предоставляет возможность авторизации клиента, основанной на результате подзапроса. Если подзапрос возвращает код ответа 2xx, доступ разрешается. Если 401 или 403 — доступ запрещается с соответствующим кодом ошибки. Любой другой код ответа, возвращаемый подзапросом, считается ошибкой.

`ngx_http_auth_request_module` ( 1.5.4 +) 模組提供基於子請求結果授權客戶端的功能。如果子請求傳回 2xx 回應代碼，則授予存取權限。如果傳回 401 或 403，則拒絕存取並傳回對應的錯誤代碼。子請求返回的任何其他回應代碼均視為錯誤。

При ошибке 401 клиенту также передаётся заголовок “WWW-Authenticate”（WWW-身份驗證） из ответа подзапроса.

當發生 401 錯誤時，子請求回應中的“WWW-Authenticate”（WWW-身份驗證）標頭也會傳遞給客戶端。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_auth_request_module`.

此模組預設未構建，必須使用`--with-http_auth_request_module`配置參數啟用。

Модуль может быть скомбинирован с другими модулями доступа, такими как [ngx\_http\_access\_module](<213 [02.01.01 http] 模組 ngx_http_access_module.md>), [ngx\_http\_auth\_basic\_module](<215 [02.01.01 http] 模組 ngx_http_auth_basic_module.md>) и [ngx\_http\_auth\_jwt\_module](<216 [02.01.01 http] ngx_http_auth_jwt_module 模組.md>), с помощью директивы [satisfy](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>).

此模組可與其他存取模組（例如 [ngx\_http\_access\_module](<213 [02.01.01 http] 模組 ngx_http_access_module.md>) 、 [ngx\_http\_auth\_basic\_module](<215 [02.01.01 http] 模組 ngx_http_auth_basic_module.md>)和 [ngx\_http\_auth\_jwt\_Hule](<216 [02.01.01 http] ngx_http_auth_jwt_module 模組.md>) ](https://nginx.org/ru/docs/http/ngx_http_core_module.html#satisfy)指令。

> До версии 1.7.3 ответы на авторизационные подзапросы не могли быть закэшированы (с использованием директив [proxy\_cache](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache>), [proxy\_store](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_store>) и т.п.).
>
> 在版本1.7.3無法快取對授權子請求的回應（使用 [proxy\_cache](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache>) 、 [proxy\_store](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_store>)等指令）。

Включает авторизацию, основанную на результате выполнения подзапроса, и задаёт URI, на который будет отправлен подзапрос.

啟用基於子請求結果的授權，並指定要將子請求傳送到的URI 。

|   |   |
| --- | --- |
| Синтаксис:<br>語法： | ``**auth_request_set** `*$переменная*` `*значение*`;``<br>` `**auth_request_set** ` *$變數* ` ` *值* `;` ` |
| Умолчание:<br>預設值： | — |
| Контекст:<br>背景： | `http`, `server`, `location` |

Устанавливает `*переменную*` в запросе в заданное `*значение*` после завершения запроса авторизации. Значение может содержать переменные из запроса авторизации, например, `$upstream_http_*`.

在授權請求完成後，將請求中的`*переменную*`設定為指定的`*значение*` 。該值可以包含來自授權請求的變量，例如`$upstream_http_*` 。
