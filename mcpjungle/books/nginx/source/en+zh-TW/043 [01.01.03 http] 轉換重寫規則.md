#### A redirect to a main site｜重定向到主站點

People who during their shared hosting life used to configure *everything* using *only* Apache’s .htaccess files, usually translate the following rules:

那些在共享主機時代習慣於僅使用 Apache 的 .htaccess 檔案來配置所有設定的人，通常會理解以下規則：

> ```
> RewriteCond  %{HTTP_HOST}  example.org
>
> RewriteCond %{HTTP_HOST} example.org
> RewriteRule  (.*)          http://www.example.org$1
>
> RewriteRule (.*) http://www.example.org$1
> ```

to something like this:

類似這樣：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  www.example.org  example.org;
>
>     伺服器名稱 www.example.org example.org;
>     if ($http_host = example.org) {
>
>     如果 ($http_host = example.org) {
>         rewrite  (.*)  http://www.example.org$1;
>
>         重寫 (.*) http://www.example.org$1;
>     }
>     ...
> }
> ```

This is a wrong, cumbersome, and ineffective way. The right way is to define a separate server for `example.org`:

這是一種錯誤、繁瑣且低效的方法。正確的方法是為`example.org`定義一個單獨的伺服器：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.org;
>
>     伺服器名稱 example.org；
>     return       301 http://www.example.org$request_uri;
>
>     返回 301 http://www.example.org$request_uri;
> }
> 
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  www.example.org;
>
>     伺服器名稱 www.example.org；
>     ...
> }
> ```

> On versions prior to 0.9.1, redirects can be made with:
>
> 在0.9.1之前的版本中，可以使用以下方式進行重定向：
> 
> > ```
> >     rewrite      ^ http://www.example.org$request_uri?;
> >
> >     重寫 ^ http://www.example.org$request_uri?;
> > ```

Another example. Instead of the “upside-down” logic “all that is not `example.com` and is not `www.example.com`”:

另一個例子。與其使用「顛倒」的邏輯「所有不屬於`example.com`且不屬於`www.example.com` 」：

> ```
> RewriteCond  %{HTTP_HOST}  !example.com
>
> RewriteCond %{HTTP_HOST} !example.com
> RewriteCond  %{HTTP_HOST}  !www.example.com
>
> RewriteCond %{HTTP_HOST} !www.example.com
> RewriteRule  (.*)          http://www.example.com$1
>
> RewriteRule (.*) http://www.example.com$1
> ```

one should simply define `example.com`, `www.example.com`, and “everything else”:

只需定義`example.com`, `www.example.com` ，以及「其他所有內容」：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.com www.example.com;
>
>     server_name example.com www.example.com;
>     ...
> }
> 
> server {
>
> 伺服器{
>     listen       80 default_server;
>
>     監聽 80 埠預設伺服器；
>     server_name  _;
>
>     伺服器名稱_;
>     return       301 http://example.com$request_uri;
>
>     返回 301 http://example.com$request_uri;
> }
> ```

> On versions prior to 0.9.1, redirects can be made with:
>
> 在0.9.1之前的版本中，可以使用以下方式進行重定向：
> 
> > ```
> >     rewrite      ^ http://example.com$request_uri?;
> >
> >     重寫 ^ http://example.com$request_uri?;
> > ```

#### Converting Mongrel rules｜轉換雜種規則

Typical Mongrel rules:

典型的雜種犬法則：

> ```
> DocumentRoot /var/www/myapp.com/current/public
> 
> RewriteCond %{DOCUMENT_ROOT}/system/maintenance.html -f
> RewriteCond %{SCRIPT_FILENAME} !maintenance.html
> RewriteRule ^.*$ %{DOCUMENT_ROOT}/system/maintenance.html [L]
> 
> RewriteCond %{REQUEST_FILENAME} -f
> RewriteRule ^(.*)$ $1 [QSA,L]
>
> 重寫規則 ^(.*)$ $1 [ QSA ,L]
> 
> RewriteCond %{REQUEST_FILENAME}/index.html -f
> RewriteRule ^(.*)$ $1/index.html [QSA,L]
>
> RewriteRule ^(.*)$ $1/index.html [ QSA ,L]
> 
> RewriteCond %{REQUEST_FILENAME}.html -f
> RewriteRule ^(.*)$ $1.html [QSA,L]
>
> 重寫規則 ^(.*)$ $1.html [ QSA ,L]
> 
> RewriteRule ^/(.*)$ balancer://mongrel_cluster%{REQUEST_URI} [P,QSA,L]
>
> RewriteRule ^/(.*)$ balancer://mongrel_cluster%{REQUEST_URI} [P, QSA ,L]
> ```

should be converted to

應該轉換為

> ```
> location / {
>
> 地點/{
>     root       /var/www/myapp.com/current/public;
>
>     root /var/www/myapp.com/current/public;
> 
>     try_files  /system/maintenance.html
>
>     嘗試檔案 /system/maintenance.html
>                $uri  $uri/index.html $uri.html
>
>                $url $url/index.html $url.html
>                @mongrel;
>
>                @mongrel；
> }
> 
> location @mongrel {
>
> 位置 @mongrel {
>     proxy_pass  http://mongrel;
>
>     proxy_pass http://mongrel;
> }
> ```
