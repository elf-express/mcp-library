The `ngx_http_scgi_module` module allows passing requests to an SCGI server.

`ngx_http_scgi_module`模組允許向SCGI伺服器傳遞請求。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點 / {
>     include   scgi_params;
>
>     包含 scgi_params；
>     scgi_pass localhost:9000;
> }
> ```

Defines conditions under which access to an SCGI server is allowed or [denied](#denied). If all string parameters are not empty and not equal to “0” then the access is allowed. The conditions are evaluated each time before a connection to an SCGI server is established. Parameter values can contain variables:

定義允許或拒絕存取SCGI伺服器的條件。如果所有字串參數均不為空且不等於“0”，則允許存取。每次建立與SCGI伺服器的連線之前(https://nginx.org/en/docs/http/ngx_http_scgi_module.html#denied)都會評估這些條件。參數值可以包含變數：

> ```
> geo $upstream_last_addr $allow {
>     volatile;
>
>     易揮發的;
>     10.10.0.0/24        1;
> }
> 
> server {
>
> 伺服器 {
>     listen 127.0.0.1:8080;
>
>     聽127.0.0.1:8080 ;
> 
>     location / {
>
>     地點 / {
>         scgi_pass           localhost:9000;
>
>         scgi_pass localhost:9000;
>         scgi_allow_upstream $allow;
>         ...
>     }
> }
> ```

Makes outgoing connections to an SCGI server originate from the specified local IP address with an optional port (1.11.2). Parameter value can contain variables (1.3.12). The special value `off` (1.3.12) cancels the effect of the `scgi_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address and port.

使發送至SCGI伺服器的出站連接源自指定的本地IP位址，並可選擇指定連接埠 ( 1.11.2 )。參數值可以包含變數 ( 1.3.12 )。特殊值`off` ( 1.3.12 ) 會取消從上一配置等級繼承的`scgi_bind`指令的效果，該指令允許系統自動分配本地IP位址和連接埠。

The `transparent` parameter (1.11.0) allows outgoing connections to an SCGI server originate from a non-local IP address, for example, from a real IP address of a client:

`transparent`參數 ( 1.11.0 ) 允許從非本地IP位址（例如，客戶端的真實IP位址）發出到SCGI伺服器的出站連接：

> ```
> scgi_bind $remote_addr transparent;
> ```

In order for this parameter to work, it is usually necessary to run nginx worker processes with the [superuser](<125 [01.01 文件] 核心功能.md#user>) privileges. On Linux it is not required (1.13.8) as if the `transparent` parameter is specified, worker processes inherit the `CAP_NET_RAW` capability from the master process. It is also necessary to configure kernel routing table to intercept network traffic from the SCGI server.

為了使此參數生效，通常需要以 [superuser](<125 [01.01 文件] 核心功能.md#user>)權限執行 nginx 工作進程。在 Linux 系統上則無需此權限 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程會從主進程繼承`CAP_NET_RAW`權限。此外，還需要配置核心路由表以攔截來自SCGI伺服器的網路流量。

Sets the `*size*` of the buffer used for reading the first part of the response received from the SCGI server. This part usually contains a small response header; if it exceeds the buffer size, the response is considered [invalid](#invalid_header). By default, the buffer size is equal to one memory page. This is either 4K or 8K, depending on a platform. It can be made smaller, however.

設定用於讀取從伺服器接收的回應第一部分的緩衝區大小`*size*` SCGI 。這部分通常包含一個較小的響應頭；如果響應頭大小超過緩衝區大小，則該響應被視為無效（ (https://nginx.org/en/docs/http/ngx_http_scgi_module.html#invalid_header) ）。預設情況下，緩衝區大小等於一個記憶體頁。根據平台的不同，該大小為 4K 或 8K。不過，緩衝區大小可以減少。

Enables or disables buffering of responses from the SCGI server.

啟用或停用來自SCGI伺服器的回應緩衝。

When buffering is enabled, nginx receives a response from the SCGI server as soon as possible, saving it into the buffers set by the [scgi\_buffer\_size](#scgi_buffer_size) and [scgi\_buffers](#scgi_buffers) directives. If the whole response does not fit into memory, a part of it can be saved to a [temporary file](#scgi_temp_path) on the disk. Writing to temporary files is controlled by the [scgi\_max\_temp\_file\_size](#scgi_max_temp_file_size) and [scgi\_temp\_file\_write\_size](#scgi_temp_file_write_size) directives.

啟用緩衝後，nginx 會盡快從SCGI接收回應，並將其儲存到由 [scgi\_buffer\_size](#scgi_buffer_size)和 [scgi\_buffers](#scgi_buffers)指令設定的緩衝區中。如果整個回應無法放入內存，則可以將其一部分儲存到磁碟上的暫存檔案 [scgi\_max\_temp\_file\_size](#scgi_temp_path)和 [scgi\_temp\_file\_write\_size](#scgi_max_temp_file_size)指令控制(https://nginx.org/en/docs/http/ngx_http_scgi_module.html#scgi_temp_file_write_size)檔案的寫入。

When buffering is disabled, the response is passed to a client synchronously, immediately as it is received. nginx will not try to read the whole response from the SCGI server. The maximum size of the data that nginx can receive from the server at a time is set by the [scgi\_buffer\_size](#scgi_buffer_size) directive.

停用緩衝後，回應會同步地立即傳遞給客戶端。 nginx 不會嘗試從伺服器讀取整個回應。 nginx 一次可以從伺服器接收的最大資料量由 [scgi\_buffer\ (https://nginx.org/en/docs/http/ngx_http_scgi_module.html#scgi_buffer_size) ]SCGI設定。

Buffering can also be enabled or disabled by passing “`yes`” or “`no`” in the “X-Accel-Buffering” response header field. This capability can be disabled using the [scgi\_ignore\_headers](#scgi_ignore_headers) directive.

也可以透過在“X-Accel-Buffering”響應頭字段中傳遞「 `yes` 」或「 `no` 」來啟用或停用緩衝。可以使用 [scgi\_ignore\_headers](#scgi_ignore_headers)指令停用此功能。

When [buffering](#scgi_buffering) of responses from the SCGI server is enabled, limits the total `*size*` of buffers that can be busy sending a response to the client while the response is not yet fully read. In the meantime, the rest of the buffers can be used for reading the response and, if needed, buffering part of the response to a temporary file. By default, `*size*` is limited by the size of two buffers set by the [scgi\_buffer\_size](#scgi_buffer_size) and [scgi\_buffers](#scgi_buffers) directives.

啟用伺服器回應緩衝功能後，會限制用於向客戶端發送回應的`*size*`總數(https://nginx.org/en/docs/http/ngx_http_scgi_module.html#scgi_buffering) SCGI ，直到客戶端完全讀取回應為止。在此期間，其餘緩衝區可用於讀取回應，並在需要時將部分回應緩衝到暫存檔案。預設情況下，緩衝區大小受限於 [scgi\_buffer\_size] 和 [scgi\_buffers 指令設定的兩個緩衝區的大小](#scgi_buffer_size) `*size*`和(https://nginx.org/en/docs/http/ngx_http_scgi_module.html#scgi_buffers)指令）。

When enabled, only one request at a time will be allowed to populate a new cache element identified according to the [scgi\_cache\_key](#scgi_cache_key) directive by passing a request to an SCGI server. Other requests of the same cache element will either wait for a response to appear in the cache or the cache lock for this element to be released, up to the time set by the [scgi\_cache\_lock\_timeout](#scgi_cache_lock_timeout) directive.

啟用此功能後，每次只允許一個請求透過向SCGI伺服器發送請求來填入根據 [scgi\_cache\_key](#scgi_cache_key)指令標識的新快取元素。對相同快取元素的其他請求將等待快取中出現回應或該元素的快取鎖定被釋放，直到 [scgi\_cache\_lock\_timeout](#scgi_cache_lock_timeout)指令設定的時間結束。
