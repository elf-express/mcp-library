## nginx for Windows｜適用於 Windows 的 nginx

|   |
| --- |
| [Known issues](#known_issues)<br>[Possible future enhancements](#possible_future_enhancements)<br>[已知問題](#known_issues)<br> [未來可能改進之處](#possible_future_enhancements) |

Version of nginx for Windows uses the native Win32 API (not the Cygwin emulation layer). Only the `select()` and `poll()` (1.15.9) connection processing methods are currently used, so high performance and scalability should not be expected. Due to this and some other known issues version of nginx for Windows is considered to be a *beta* version. At this time, it provides almost the same functionality as a UNIX version of nginx except for XSLT filter, image filter, GeoIP module, and embedded Perl language.

Windows 版 nginx 使用原生 Win32 API （而非 Cygwin 模擬層）。目前僅使用`select()`和`poll()` ( 1.15.9 ) 連接處理方法，因此不應期望其具有高效能和可擴展性。由於此原因以及其他一些已知問題，Windows 版 nginx 被視為 *beta* 版本。目前，它提供的功能幾乎與UNIX版 nginx 相同，只是缺少XSLT過濾器、圖像過濾器、GeoIP 模組和嵌入式 Perl 語言。

To install nginx/Windows, [download](<174 [01 在] nginx 下載.md>) the latest mainline version distribution (1.31.6), since the mainline branch of nginx contains all known fixes. Then unpack the distribution, go to the nginx-1.31.6 directory, and run `nginx`. Here is an example for the drive C: root directory:

要安裝 nginx/Windows，請下載最新的主線版本發行版（ (https://nginx.org/en/download.html) ），因為 nginx 的主線分支包含了所有已知的修復。然後解壓縮發行版，進入 nginx- 目錄1.31.6 1.31.6 ，並運行`nginx` 。以下是 C 碟根目錄的範例：

>

>
> CDC：\
> unzip nginx-1.31.6.zip
>
> 解壓縮 nginx- 1.31.6
> cd nginx-1.31.6
>
> cd nginx- 1.31.6
> start nginx
>
> 啟動 nginx
> ```

Run the `tasklist` command-line utility to see nginx processes:

運行`tasklist`命令列實用程式以查看 nginx 進程：

> ```
> C:\nginx-1.31.6>tasklist /fi "imagename eq nginx.exe"
>
> C:\nginx- 1.31.6 >tasklist /fi "imagename eq nginx.exe"

> nginx.exe 652 控制台 0 2 780 K
> nginx.exe           1332 Console                 0      3 112 K
>
> nginx.exe 1332 控制台 0 3 112 K
> ```

One of the processes is the master process and another is the worker process. If nginx does not start, look for the reason in the error log file `logs\error.log`. If the log file has not been created, the reason for this should be reported in the Windows Event Log. If an error page is displayed instead of the expected page, also look for the reason in the `logs\error.log` file.

其中一個進程是主進程，另一個是工作進程。如果 nginx 無法啟動，請在錯誤日誌檔案`logs\error.log`中尋找原因。如果日誌檔案未創建，則應在 Windows 事件日誌中報告原因。如果顯示的是錯誤頁面而不是預期頁面，也請在`logs\error.log`文件中找出原因。

nginx/Windows uses the directory where it has been run as the prefix for relative paths in the configuration. In the example above, the prefix is `C:\nginx-1.31.6\`. Paths in a configuration file must be specified in UNIX-style using forward slashes:

nginx/Windows 使用其運行目錄作為設定檔中相對路徑的前綴。在上面的範例中，前綴為`C:\nginx-1.31.6\` 。設定檔中的路徑必須使用正斜線以UNIX格式指定：

> ```
> access_log   logs/site.log;
>
> 訪問日誌 logs/site.log；
> root         C:/web/html;
>
> 根目錄 C:/web/html;
> ```

nginx/Windows runs as a standard console application (not a service), and it can be managed using the following commands:

nginx/Windows 作為標準控制台應用程式（而非服務）運行，可以使用以下命令進行管理：

> | nginx -s reopen<br>nginx -s 重新開啟 | re-opening log files<br>重新開啟日誌檔案 |

#### Known issues｜已知問題

-   Although several workers can be started, only one of them actually does any work.  
    雖然可以啟動多個工人，但實際上只有一個工人在工作。
-   The UDP (and, inherently, QUIC) functionality is not supported.  
    不支援UDP （以及固有的QUIC ）功能。

#### Possible future enhancements｜未來可能的改進方向

-   Running as a service.  
    以服務形式運作。
-   Using the I/O completion ports as a connection processing method.  
    使用 I/O 完成連接埠作為連接處理方法。
-   Using multiple worker threads inside a single worker process.  
    在單一工作進程中使用多個工作執行緒。
