Модуль `ngx_http_auth_jwt_module` (1.11.3) предоставляет возможность авторизации клиента с проверкой предоставляемого [JSON Web Token](https://datatracker.ietf.org/doc/html/rfc7519) (JWT) при помощи указанных ключей. Модуль поддерживает [JSON Web Signature](https://datatracker.ietf.org/doc/html/rfc7515) (JWS), [JSON Web Encryption](https://datatracker.ietf.org/doc/html/rfc7516) (JWE) (1.19.7) и Nested JWT (1.21.0). Модуль может использоваться для настройки аутентификации [OpenID Connect](http://openid.net/specs/openid-connect-core-1_0.html).

`ngx_http_auth_jwt_module`模組 (1.11.3) 透過使用指定的金鑰驗證提供的 [JSON Web Token](https://datatracker.ietf.org/doc/html/rfc7519) (JWT) 來進行客戶端授權。此模組支援 [JSON Web Signature](https://datatracker.ietf.org/doc/html/rfc7515) (JWS)、[JSON Web Encryption](https://datatracker.ietf.org/doc/html/rfc7516) (JWE) (1.19.7) 和嵌套 JWT (1.21.0)。此模組可用於設定 [OpenID Connect](http://openid.net/specs/openid-connect-core-1_0.html)身份驗證。

Модуль может быть скомбинирован с другими модулями доступа, такими как [ngx\_http\_access\_module](<213 [02.01.01 http] 模組 ngx_http_access_module.md>), [ngx\_http\_auth\_basic\_module](<215 [02.01.01 http] 模組 ngx_http_auth_basic_module.md>) и [ngx\_http\_auth\_request\_module](<217 [02.01.01 http] ngx_http_auth_request_module 模組.md>) с помощью директивы [satisfy](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>).

此模組可與其他存取模組（如 [ngx\_http\_access\_module](<213 [02.01.01 http] 模組 ngx_http_access_module.md>) 、[ngx\_http\_auth\_basic\_module](<215 [02.01.01 http] 模組 ngx_http_auth_basic_module.md>)和 [ngx\_http\_auth\_request\_%a](<217 [02.01.01 http] ngx_http_auth_request_module 模組.md>) [⧟tisP73](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>) ]使用指令

Включает проверку JSON Web Token. Заданная `*строка*` используется в качестве `realm`. В значении параметра допустимо использование переменных.

啟用對JSON Web Token 的驗證。指定的`*строка*`將用作`realm` 。參數值中允許使用變數。

Необязательный параметр `token` задаёт переменную, содержащую JSON Web Token. По умолчанию JWT передаётся в заголовке “Authorization”（授權） в качестве [Bearer Token](https://datatracker.ietf.org/doc/html/rfc6750). JWT может также передаваться как кука или часть строки запроса:

可選參數 `token` 指定包含 JSON Web Token 的變數。預設情況下，JWT作為[Bearer Token]在“Authorization”（授權）標頭中傳遞，(https://datatracker.ietf.org/doc/html/rfc6750). JWT也可以作為cookie或查詢字串的一部分傳遞：

> ```
> auth_jwt "closed site" token=$cookie_auth_token;
> ```

Специальное значение `off` отменяет действие унаследованной с предыдущего уровня конфигурации директивы `auth_jwt`.

特殊值`off`取消從上一個設定等級繼承的`auth_jwt`指令的效果。

Задаёт дополнительные условия для проверки JWT. В качестве значения можно использовать текст, переменные и их комбинации, значение должно начинаться c переменной (1.21.7). Для успешной аутентификации необходимо, чтобы значение всех строковых параметров было непустое или не равно “0”.

指定驗證的附加條件JWT 。該值可以是文字、變數或它們的組合；該值必須以變數開頭 ( 1.21.7 )。為成功進行身份驗證，所有字串參數必須非空或不等於「0」。

> ```
> map $jwt_claim_iss $valid_jwt_iss {
>
> 映射 $jwt_claim_iss $valid_jwt_iss {
>     "good" 1;
>
>     「好」 1；
> }
> ...
> 
> auth_jwt_require $valid_jwt_iss;
> ```

При невыполнении любого из условий возвращается код ответа `401`. Необязательный параметр `error` (1.21.7) позволяет переопределить код ответа на `403`.

如果任何條件不滿足，則回傳回應代碼`401` 。可選參數`error` （ 1.21.7 ）可讓您將回應碼覆寫為`403` 。

Модуль `ngx_http_auth_jwt_module` поддерживает встроенные переменные:

`ngx_http_auth_jwt_module`模組支援內建變數：

`$jwt_header_``*имя*`

возвращает значение указанного [заголовка JOSE](https://datatracker.ietf.org/doc/html/rfc7515#section-4)

傳回指定 [header JOSE](https://datatracker.ietf.org/doc/html/rfc7515#section-4)的值

`$jwt_claim_``*имя*`

возвращает значение указанной [JWT claim](https://datatracker.ietf.org/doc/html/rfc7519#section-4)

傳回指定 [JWT宣告](https://datatracker.ietf.org/doc/html/rfc7519#section-4)的值

Для вложенных claim, а также claim, содержащих точку (“.”), значение переменной вычислить невозможно, следует использовать директиву [auth\_jwt\_claim\_set](#auth_jwt_claim_set).

對於巢狀宣告以及包含句點（“.”）的聲明，無法計算變數值；應使用 [auth\_jwt\_claim\_set](#auth_jwt_claim_set)指令。

Значения переменных для tokens, зашифрованных при помощи JWE, доступны только после дешифрования, которое происходит в [Access](https://nginx.org/ru/docs/dev/development_guide.html#http_phases)\-фазе.

使用JWE加密的令牌的變數值只有在解密後才能訪問，解密發生在 [Access](https://nginx.org/ru/docs/dev/development_guide.html#http_phases)階段。

`$jwt_payload`

возвращает расшифрованную полезную нагрузку (payload) верхнего уровня для `вложенных` или `зашифрованных` токенов (1.21.2). Для вложенных токенов возвращает внутренний JWS токен. Для зашифрованных токенов возвращает JSON с claims.

傳回`вложенных`或`зашифрованных`令牌（ 1.21.2 ）的解密頂層有效載荷。對於嵌套令牌，返回內部的JWS令牌。對於加密令牌，返回帶有宣告的JSON 。
