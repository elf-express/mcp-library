## Module ngx\_http\_hls\_module｜模組 ngx_http_hls_module

Модуль `ngx_http_hls_module` обеспечивает серверную поддержку протокола HTTP Live Streaming (HLS) для медиафайлов в формате MP4 и MOV. Такие файлы обычно имеют расширения `.mp4`, `.m4v`, `.m4a`, `.mov` или `.qt`. Модуль поддерживает видеокодек H.264, а также аудиокодеки AAC и MP3.

`ngx_http_hls_module`模組為HTTP直播串流 ( HLS ) 協定提供伺服器支持，該協定支援MP4和MOV格式的媒體檔案。此類檔案通常具有`.mp4`, `.m4v`, `.m4a`, `.mov`或`.qt`副檔名。此模組支援 H.264 視訊編解碼器以及AAC和MP3音訊編解碼器。

Для каждого медиафайла поддерживается два URI:

每個媒體檔案支援兩個URI ：

-   URI плейлиста, имеющий расширение “`.m3u8`”. URI может принимать необязательные аргументы:  
    URI 副檔名為「`.m3u8`」的播放清單。 URI 可以採用可選參數：
    -   “`start`” и “`end`” задают границы плейлиста в секундах (1.9.0).  
        「 `start` 」和「 `end` 」以秒為單位設定播放清單邊界（ 1.9.0 ）。
    -   “`offset`” сдвигает первоначальную позицию воспроизведения на указанное время в секундах (1.9.0). Положительное значение задаёт временной сдвиг с начала плейлиста. Отрицательное значение задаёт временной сдвиг с конца последнего фрагмента в плейлисте.  
        「 `offset` 」會將初始播放位置移動指定的秒數（ 1.9.0 ）。正值表示從播放清單開頭開始移動的時間。負值表示從播放清單最後一個片段的結尾開始移動的時間。
    -   “`len`” задаёт длину фрагмента в секундах.  
        「 `len` 」設定片段長度（以秒為單位）。
-   URI фрагмента, имеющий расширение “`.ts`”. URI может принимать необязательные аргументы:  
    URI片段，具有副檔名「`.ts`」。 URI 可以採用可選參數：
    -   “`start`” и “`end`” задают границы фрагмента в секундах.  
        「 `start` 」和「 `end` 」以秒為單位設定片段邊界。

> Модуль доступен как часть [коммерческой подписки](https://www.f5.com/products/nginx).
>
> 此模組包含在[商業訂閱](https://www.f5.com/products/nginx)中。

#### Пример конфигурации｜配置範例

> ```
> location / {
>
> 地點 / {
>     hls;
>
>     hls；
>     hls_fragment            5s;
>
>     hls_fragment 5秒；
>     hls_buffers             10 10m;
>
>     hls_buffers 10 10m;
>     hls_mp4_buffer_size     1m;
>
>     hls_mp4_buffer_size 1m;
>     hls_mp4_max_buffer_size 5m;
>     root /var/video/;
>
>     根目錄 /var/video/;
> }
> ```

В такой конфигурации для файла “`/var/video/test.mp4`” будут поддерживаться следующие URI:

在此配置中，「 `/var/video/test.mp4` 」檔案將支援以下URI ：

> ```
> http://hls.example.com/test.mp4.m3u8?offset=1.000&start=1.000&end=2.200
> http://hls.example.com/test.mp4.m3u8?len=8.000
> http://hls.example.com/test.mp4.ts?start=1.000&end=2.200
> ```

該指令出現在版本1.5.12 。

Добавляет аргументы из запроса плейлиста в URI фрагментов. Это может быть необходимо для авторизации клиента во время запроса фрагментов, а также для защиты HLS-потока с помощью модуля [ngx\_http\_secure\_link\_module](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md>).

將播放清單請求中的參數加入URI片段中。這對於片段請求期間的客戶端授權以及使用 [ngx\_http\_secure\_link\_module](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md>)模組保護HLS流可能是必要的。

Например, если клиент запрашивает плейлист `http://example.com/hls/test.mp4.m3u8?a=1&b=2`, то аргументы `a=1` и `b=2` будут добавлены в URI фрагментов после аргументов `start` и `end`:

例如，如果客戶端請求播放清單`http://example.com/hls/test.mp4.m3u8?a=1&b=2` ，則參數`a=1`和`b=2`將在參數`start`和`end`之後加入URI片段中：

> #EXT-X-VERSION:3
> #EXT-X-TARGETDURATION:15
> #EXT-X-PLAYLIST-TYPE:VOD
> 
> #EXTINF:9.333,
> test.mp4.ts?start=0.000&end=9.333&a=1&b=2
>
> test.mp4.ts?start= 0.000 &end= 9.333 &a=1&b=2
> #EXTINF:7.167,
> test.mp4.ts?start=9.333&end=16.500&a=1&b=2
>
> test.mp4.ts?start= 9.333 &end= 16.500 &a=1&b=2
> #EXTINF:5.416,

>
> test.mp4.ts?start= 16.500 &end= 21.916 &a=1&b=2

> test.mp4.ts?start=21.916&end=27.416&a=1&b=2
>
> test.mp4.ts?start= 21.916 &end= 27.416 &a=1&b=2

Если HLS-поток защищён с помощью модуля [ngx\_http\_secure\_link\_module](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md>), переменную `$uri` не следует использовать в выражении [secure\_link\_md5](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md#secure_link_md5>), так как это приведёт к ошибкам при запросах к фрагментам. Вместо `$uri` следует использовать [базовую часть URI](<243 [02.01.01 http] 模組 ngx_http_map_module.md#map>) (`$hls_uri` в примере):

如果使用 [ngx\_http\_secure\_link\_module](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md>)模組對HLS流進行保護，則不應在 [secure\_link\_md5](<255 [02.01.01 http] 模組 ngx_http_secure_link_module.md#secure_link_md5>)表達式中使用`$uri`變數，因為這會在請求片段時導致錯誤。應使用 [URI基本部分](<243 [02.01.01 http] 模組 ngx_http_map_module.md#map>) （例中的`$hls_uri` ）來代替`$uri` ：

> ```
> http {
>     ...
> 
>     map $uri $hls_uri {
>
>     映射 $uri $hls_uri {
>         ~^(?<base_uri>.*).m3u8$ $base_uri;
>
>         ~^(? <base_uri> .*).m3u8$ $base_uri;
>         ~^(?<base_uri>.*).ts$   $base_uri;
>
>         ~^(? <base_uri> .*).ts$ $base_uri;
>         default                 $uri;
>
>         預設值 $uri；
>     }
> 
>     server {
>
>     伺服器 {
>         ...
> 
>         location /hls/ {
>             hls;
>
>             hls；
>             hls_forward_args on;
>
>             hls_forward_args 已開啟；
> 
>             alias /var/videos/;
>
>             別名 /var/videos/;
> 
>             secure_link $arg_md5,$arg_expires;
>             secure_link_md5 "$secure_link_expires$hls_uri$remote_addr secret";
> 
>             if ($secure_link = "") {
>
>             如果 ($secure_link = "") {
>                 return 403;
>
>                 返回 403；
>             }
> 
>             if ($secure_link = "0") {
>
>             如果 ($secure_link = "0") {
>                 return 410;
>
>                 返回 410；
>             }
>         }
>     }
> }
> ```

В ходе обработки метаданных может понадобиться буфер большего размера. Его `*размер*` не может превышать указанного, иначе nginx вернёт серверную ошибку 500 (Internal Server Error) и запишет в лог следующее сообщение:

元資料處理期間可能需要更大的緩衝區。其`*размер*`大小不能超過指定值，否則 nginx 將傳回 500（內部伺服器錯誤）伺服器錯誤並記錄下列訊息：

> ```
> "/some/movie/file.mp4" mp4 moov atom is too large:
>
> "/some/movie/file.mp4" mp4 moov atom 檔案過大：
> 12583268, you may want to increase hls_mp4_max_buffer_size
>
> 12583268，您可能需要增加 hls_mp4_max_buffer_size
> ```
