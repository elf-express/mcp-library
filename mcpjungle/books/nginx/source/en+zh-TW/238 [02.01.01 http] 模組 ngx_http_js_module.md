Модуль `ngx_http_js_module` позволяет задавать обработчики location, переменных и фильтров на JavaScript с помощью [njs](<290 [02.01.03 紐澤西州] 模組 nginx JavaScript.md>).

`ngx_http_js_module`模組可讓您使用 [njs](<290 [02.01.03 紐澤西州] 模組 nginx JavaScript.md>)在 JavaScript 中定義位置、變數和過濾器處理程序。

Инструкция по сборке и установке доступны [здесь](<291 [02.01.03 紐澤西州] 下載和安裝.md>).

組裝和安裝說明可在此處取得(https://nginx.org/ru/docs/njs/install.html) 。

Задаёт функцию njs в качестве фильтра тела ответа. Функция фильтра вызывается для каждого блока данных тела ответа со следующими аргументами:

指定一個 njs 函數作為響應體過濾器。此濾波器函數會針對響應體中的每個資料塊調用，並傳遞以下參數：

`r`

объект [HTTP request](https://nginx.org/ru/docs/njs/reference.html#http)

物件 [HTTP請求](https://nginx.org/ru/docs/njs/reference.html#http)

`data`

входящий блок данных может быть строкой или буфером в зависимости от значения `buffer_type`, по умолчанию является строкой. Начиная с [0.8.5](https://nginx.org/ru/docs/njs/changes.html#njs0.8.5), по умолчанию значение `data` неявно преобразуется в валидную строку UTF-8. Для бинарных данных параметр `buffer_type` необходимо установить в `buffer`.

輸入資料塊可以是字串或緩衝區，取決於`buffer_type`的值，預設為字串。從[0.8.5](https://nginx.org/ru/docs/njs/changes.html#njs0.8.5)開始， `data`的預設值會被隱式轉換為有效字串UTF -8。對於二進位數據， `buffer_type`必須設定為`buffer` 。

`flags`

объект со следующими свойствами:

一個具有以下屬性的物件：

`last`

логическое значение, true, если данные являются последним буфером.

布林值，如果資料是最後一個緩衝區則為真。

Функция фильтра может передавать свою модифицированную версию входящего блока данных следующему фильтру тела ответа при помощи вызова [`r.sendBuffer()`](https://nginx.org/ru/docs/njs/reference.html#r_sendbuffer). Пример преобразования букв в нижний регистр в теле ответа:

過濾函數可以透過呼叫 [`r.sendBuffer()`](https://nginx.org/ru/docs/njs/reference.html#r_sendbuffer)將其修改後的傳入資料塊傳遞給下一個響應體過濾器。以下範例展示如何在響應體中將字母轉換為小寫：

> ```js
> function filter(r, data, flags) {
>
> 函數 filter(r, data, flags) {
>     r.sendBuffer(data.toLowerCase(), flags);
> }
> ```

Если функция фильтра изменяет длину тела ответа, то необходимо очистить заголовок ответа “Content-Length”（內容長度） (если присутствует) в [`js_header_filter`](#js_header_filter), чтобы применить поблочное кодирование:

如果過濾函數改變了響應體的長度，則必須清除 [`js_header_filter`](#js_header_filter)中的響應頭“Content-Length”（內容長度） （如果存在）才能應用分塊編碼：

> example.conf:

>     js_body_filter main.filter;
>  }
> 
> example.js:
>  function clear_content_length(r) {
>
>  函數 clear_content_length(r) {
>      delete r.headersOut['Content-Length'];
>
>      刪除 r.headersOut['Content-Length'];
>  }
> ```

Для отмены фильтра (блоки данных будут передаваться клиенту без вызова `js_body_filter`), можно использовать [`r.done()`](https://nginx.org/ru/docs/njs/reference.html#r_done). Например, чтобы добавить данные в начало тела ответа:

要覆寫過濾器（資料塊將直接傳遞給客戶端，無需呼叫`js_body_filter` ），可以使用 [`r.done()`](https://nginx.org/ru/docs/njs/reference.html#r_done) 。例如，要將資料新增至響應體的開頭：

> ```js
> function prepend(r, data, flags) {
>     r.sendBuffer("XXX");
>
>     r.sendBuffer( "XXX" );
>     r.sendBuffer(data, flags);
>     r.done();
> }
> ```

> Так как обработчик `js_body_filter` должен сразу возвращать результат, то поддерживаются только синхронные операции, Таким образом, асинхронные операции, например [r.subrequest()](https://nginx.org/ru/docs/njs/reference.html#r_subrequest) или [setTimeout()](https://nginx.org/ru/docs/njs/reference.html#settimeout), не поддерживаются.
>
> 由於`js_body_filter`處理程序必須立即傳回結果，因此僅支援同步操作。因此，不支援非同步操作，例如 [r.subrequest()](https://nginx.org/ru/docs/njs/reference.html#r_subrequest)或 [setTimeout()](https://nginx.org/ru/docs/njs/reference.html#settimeout) 。

Эта директива появилась в версии 0.9.9.

該指令是在版本0.9.9中引入的。

Задаёт функцию njs в качестве обработчика [фазы доступа](https://nginx.org/ru/docs/dev/development_guide.html#http_phases). Поддерживаются асинхронные операции, такие как [r.subrequest()](https://nginx.org/ru/docs/njs/reference.html#r_subrequest), [ngx.fetch()](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch) и [setTimeout()](https://nginx.org/ru/docs/njs/reference.html#settimeout).

將 njs 函數設定為 [訪問階段 處理程序](https://nginx.org/ru/docs/dev/development_guide.html#http_phases) 。支援 [r.subrequest()](https://nginx.org/ru/docs/njs/reference.html#r_subrequest) 、[ngx.fetch()](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch)和 [setTimeout()](https://nginx.org/ru/docs/njs/reference.html#settimeout)等非同步操作。

Обработчик, завершившийся без вызова [`r.return()`](https://nginx.org/ru/docs/njs/reference.html#r_return) или [`r.decline()`](https://nginx.org/ru/docs/njs/reference.html#r_decline), разрешает доступ. Чтобы запретить доступ или отправить произвольный ответ (например, перенаправление), обработчик может вызвать [`r.return()`](https://nginx.org/ru/docs/njs/reference.html#r_return). Чтобы обработчик не выражал мнения о доступе, передавая решение другим проверкам доступа при использовании [`satisfy any`](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>), обработчик может вызвать [`r.decline()`](https://nginx.org/ru/docs/njs/reference.html#r_decline).

如果處理程序在未呼叫 [`r.return()`](https://nginx.org/ru/docs/njs/reference.html#r_return)或 [`r.decline()`](https://nginx.org/ru/docs/njs/reference.html#r_decline)的情況下傳回，則表示授予存取權限。若要拒絕存取或傳送任意回應（例如重新導向），處理程序可以呼叫 [`r.return()`](https://nginx.org/ru/docs/njs/reference.html#r_return) 。為了防止處理程序在使用 [`satisfy any`](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>)時透過將決策委託給其他存取檢查來表達對存取權限的意見，處理程序可以呼叫 [`r.decline()`](https://nginx.org/ru/docs/njs/reference.html#r_decline) 。

預設情況下，鍵和值都使用字串。可選參數`type`允許您將值類型變更為數字。

Необязательный параметр `timeout` задаёт время в миллисекундах, по завершении которого все записи в словаре удаляются из зоны. Если для части записей требуется другое время удаления, его можно задать при помощи аргумента `timeout` методов [add](https://nginx.org/ru/docs/njs/reference.html#dict_add), [incr](https://nginx.org/ru/docs/njs/reference.html#dict_incr) и [set](https://nginx.org/ru/docs/njs/reference.html#dict_set) ([0.8.5](https://nginx.org/ru/docs/njs/changes.html#njs0.8.5)).

可選參數`timeout`指定從區域中刪除所有字典條目的時間（以毫秒為單位）。如果某些條目需要不同的刪除時間，可以使用 [add](https://nginx.org/ru/docs/njs/reference.html#dict_add) 、[incr](https://nginx.org/ru/docs/njs/reference.html#dict_incr)和 [set](https://nginx.org/ru/docs/njs/reference.html#dict_set) ([0.8.5](https://nginx.org/ru/docs/njs/changes.html#njs0.8.5) ) 方法來指定的`timeout` 。

Необязательный параметр `evict` удаляет самую старую пару ключ-значение при переполнении зоны.

可選參數`evict`在區域已滿時刪除最舊的鍵值對。

Необязательный параметр `state` задаёт `*файл*`, в котором хранится состояние разделяемого словаря в формате JSON, что позволяет сохранять его между перезапусками nginx ([0.9.1](https://nginx.org/ru/docs/njs/changes.html#njs0.9.1)).

可選的`state`參數指定`*файл*` ，它以JSON格式儲存共享字典的狀態，使其能夠在 nginx 重啟後保留 ([0.9.1](https://nginx.org/ru/docs/njs/changes.html#njs0.9.1) )。

Эта директива появилась в версии 0.5.3.

該指令是在版本0.5.3中引入的。

Объявляет [перезаписываемую](https://nginx.org/ru/docs/njs/reference.html#r_variables) переменную. В качестве значения можно использовать текст, переменные и их комбинации. Переменная не перезаписывается после перенаправления, в отличие от переменных, созданных при помощи директивы [set](<253 [02.01.01 http] ngx_http_rewrite_module 模組.md#set>).

聲明一個(https://nginx.org/ru/docs/njs/reference.html#r_variables)寫的變數。此變數的值可以是文字、變數或二者的組合。與使用 `[set](<253 [02.01.01 http] ngx_http_rewrite_module 模組.md#set>)指令建立的變數不同，重定向後該變數不會被覆寫。

> Директива может быть указана на уровне `server` и `location` начиная с [0.7.7](https://nginx.org/ru/docs/njs/changes.html#njs0.7.7).
>
> 指令可以從 [0.7.7](https://nginx.org/ru/docs/njs/changes.html#njs0.7.7)開始，在`server`和`location`級別指定。
