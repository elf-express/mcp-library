The `ngx_http_dav_module` module is intended for file management automation via the WebDAV protocol. The module processes HTTP and WebDAV methods PUT, DELETE, MKCOL, COPY, and MOVE.

`ngx_http_dav_module`模組旨在透過 WebDAV 協定實現檔案管理自動化。此模組處理HTTP和 WebDAV 方法PUT, DELETE, MKCOL, COPY和MOVE 。

This module is not built by default, it should be enabled with the `--with-http_dav_module` configuration parameter.

此模組預設未構建，應使用`--with-http_dav_module`配置參數啟用。

> WebDAV clients that require additional WebDAV methods to operate will not work with this module.
>
> 需要額外 WebDAV 方法才能運作的 WebDAV 用戶端將無法與此模組一起使用。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點/{
>     root                  /data/www;
>
>     根目錄 /data/www;
> 
>     client_body_temp_path /data/client_temp;
> 
>     dav_methods PUT DELETE MKCOL COPY MOVE;
>
>     dav_methods PUT DELETE MKCOL COPY MOVE ;
> 
>     create_full_put_path  on;
>
>     啟用 create_full_put_path；
>     dav_access            group:rw  all:r;
>
>     dav_access 群組：讀寫所有：讀寫；
> 
>     limit_except GET {
>         allow 192.168.1.0/32;
>
>         允許192.168.1.0/32 ；
>         deny  all;
>
>         全部否認；
>     }
> }
> ```

The WebDAV specification only allows creating files in already existing directories. This directive allows creating all needed intermediate directories.

WebDAV規格僅允許在已存在的目錄中建立檔案。此指令允許建立所有必需的中間目錄。

Sets access permissions for newly created files and directories, e.g.:

設定新檔案和目錄的存取權限，例如：

> ```
> dav_access user:rw group:rw all:r;
>
> dav_access 使用者：讀寫 群組：讀寫 所有：r；
> ```

If any `group` or `all` access permissions are specified then `user` permissions may be omitted:

如果指定了任何`group`或`all`存取權限，則可以省略`user`權限：

> ```
> dav_access group:rw all:r;
>
> dav_access 群組：讀寫所有：讀寫；
> ```

Allows the specified HTTP and WebDAV methods. The parameter `off` denies all methods processed by this module. The following methods are supported: `PUT`, `DELETE`, `MKCOL`, `COPY`, and `MOVE`.

允許指定的HTTP和 WebDAV 方法。參數`off`拒絕此模組處理的所有方法。支援以下方法： `PUT`, `DELETE`, `MKCOL`, `COPY`和`MOVE` 。

A file uploaded with the PUT method is first written to a temporary file, and then the file is renamed. Starting from version 0.8.9, temporary files and the persistent store can be put on different file systems. However, be aware that in this case a file is copied across two file systems instead of the cheap renaming operation. It is thus recommended that for any given location both saved files and a directory holding temporary files, set by the [client\_body\_temp\_path](<056 [01.01.03 http] 模組 ngx_http_core_module.md#client_body_temp_path>) directive, are put on the same file system.

使用PUT方法上傳的文件會先寫入暫存文件，然後再重新命名。從0.8.9版本開始，暫存檔案和持久性儲存可以位於不同的檔案系統上。但是請注意，在這種情況下，檔案會被複製到兩個檔案系統上，而不是進行簡單的重新命名操作。因此，建議對於任何給定的位置，已儲存的檔案和由 [client\_body\_temp\_path](<056 [01.01.03 http] 模組 ngx_http_core_module.md#client_body_temp_path>)指令設定的暫存檔案目錄都位於同一檔案系統上。

When creating a file with the PUT method, it is possible to specify the modification date by passing it in the “Date”（日期） header field.

使用PUT方法建立檔案時，可以透過在“Date”（日期）標頭欄位中傳遞來指定修改日期。

Allows the DELETE method to remove files provided that the number of elements in a request path is not less than the specified number. For example, the directive

允許使用DELETE方法刪除文件，前提是請求路徑中的元素數量不少於指定的數量。例如，指令

> ```
> min_delete_depth 4;
>
> 最小刪除深度 4；
> ```

allows removing files on requests

允許根據請求刪除文件

> ```
> /users/00/00/name
> /users/00/00/name/pic.jpg
> /users/00/00/page.html
> ```

and denies the removal of

並否認移除

> ```
> /users/00/00
> ```
