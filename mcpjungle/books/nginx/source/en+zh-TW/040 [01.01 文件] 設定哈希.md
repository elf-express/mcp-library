## Setting up hashes｜設定哈希

To quickly process static sets of data such as server names, [map](<078 [01.01.03 http] 模組 ngx_http_map_module.md#map>) directive’s values, MIME types, names of request header strings, nginx uses hash tables. During the start and each re-configuration nginx selects the minimum possible sizes of hash tables such that the bucket size that stores keys with identical hash values does not exceed the configured parameter (hash bucket size). The size of a table is expressed in buckets. The adjustment is continued until the table size exceeds the hash max size parameter. Most hashes have the corresponding directives that allow changing these parameters, for example, for the server names hash they are [server\_names\_hash\_max\_size](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>) and [server\_names\_hash\_bucket\_size](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>).

為了快速處理靜態資料集，例如伺服器名稱、[map](<078 [01.01.03 http] 模組 ngx_http_map_module.md#map>)指令值、 MIME類型、請求頭字串名稱等，nginx 使用雜湊表。在啟動和每次重新配置期間，nginx 會選擇雜湊表的最小可能大小，以確保儲存具有相同雜湊值的鍵的桶大小不超過配置的參數（雜湊桶大小）。表的大小以桶為單位。此調整會持續進行，直到表大小超過哈希表的最大大小參數。大多數哈希表都有相應的指令允許更改這些參數，例如，伺服器名稱哈希表的指令是 [server\_names\_hash\_max\_size](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>)和 [server\_names\_hash\_bucket\_size](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>) 。

The hash bucket size parameter is aligned to the size that is a multiple of the processor’s cache line size. This speeds up key search in a hash on modern processors by reducing the number of memory accesses. If hash bucket size is equal to one processor’s cache line size then the number of memory accesses during the key search will be two in the worst case — first to compute the bucket address, and second during the key search inside the bucket. Therefore, if nginx emits the message requesting to increase either hash max size or hash bucket size then the first parameter should first be increased.

哈希桶大小參數設定為處理器快取行大小的倍數。這透過減少記憶體存取次數，加快了現代處理器上哈希表中的鍵查找速度。如果哈希桶大小等於一個處理器的快取行大小，那麼在最壞情況下，鍵查找期間的記憶體存取次數為兩次——第一次用於計算桶位址，第二次用於在桶內尋找鍵。因此，如果 nginx 發出訊息請求增加哈希最大大小或雜湊桶大小，則應先增加第一個參數。
