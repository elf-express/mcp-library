The `ngx_http_tunnel_module` (1.31.0) handles HTTP/1.1 [CONNECT](https://datatracker.ietf.org/doc/html/rfc9110#section-9.3.6) requests and establishes an end-to-end virtual connection.

`ngx_http_tunnel_module` ( 1.31.0 ) 處理HTTP/1.1 [CONNECT](https://datatracker.ietf.org/doc/html/rfc9110#section-9.3.6)請求並建立端對端虛擬連線。

#### Example Configuration｜範例配置

> ```
> http {
> 
>     map $request_port $allow_port {
>
>     映射 $request_port $allow_port {
>         443            1;
>     }
> 
>     map $host $allow_host {
>
>     映射 $host $allow_host {
>         hostnames;
>
>         主機名；
> 
>         example.org    1;
>         *.example.org  1;
>     }
> 
>     server {
>
>     伺服器 {
>         listen 8000;
>
>         聽 8000；
> 
>         resolver dns.example.com;
>
>         解析 dns.example.com；
> 
>         if ($allow_port != 1) {
>
>         如果 ($allow_port != 1) {
>             return 502;
>
>             返回 502；
>         }
> 
>         if ($allow_host != 1) {
>
>         如果 ($allow_host != 1) {
>             return 502;
>
>             返回 502；
>         }
> 
>         tunnel_pass;
>
>         隧道通行；
>     }
> }
> ```

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**tunnel_allow_upstream** `*string*` ...;``<br>` `**tunnel_allow_upstream** ` *字串* ` ...;` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

Defines conditions under which access to the backend server is allowed or [denied](#denied). If all string parameters are not empty and not equal to “0” then the access is allowed. The conditions are evaluated each time before a connection to a backend server is established. Parameter values can contain variables:

定義允許或拒絕存取後端伺服器的條件(https://nginx.org/en/docs/http/ngx_http_tunnel_module.html#denied) 。如果所有字串參數均不為空且不等於“0”，則允許存取。每次建立與後端伺服器的連線之前都會評估這些條件。參數值可以包含變數：

> ```
> geo $upstream_last_addr $allow {
>     volatile;
>
>     易揮發的;
>     10.10.0.0/24        1;
> }
> 
> server {
>
> 伺服器 {
>     listen 127.0.0.1:8080;
>
>     聽127.0.0.1:8080 ;
> 
>     tunnel_pass;
>
>     隧道通行；
>     tunnel_allow_upstream $allow;
> }
> ```

> This directive is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本指令作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**tunnel_bind** `*address*` \| `off`;``<br>` `**tunnel_bind** ` *地址* ` \| `關閉`;` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

Makes outgoing connections to a backend server originate from the specified local IP address with an optional port. Parameter value can contain variables. The special value `off` cancels the effect of the `tunnel_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address and port.

使發送到後端伺服器的出站連線源自指定的本機位址IP連接埠可選。參數值可以包含變數。特殊值`off`會取消從上一配置等級繼承的`tunnel_bind`指令的效果，該指令允許系統自動分配本地位址IP和連接埠。

When enabled, makes the [tunnel\_bind](#tunnel_bind) operation at each connection attempt:

啟用後，每次連線嘗試時都會執行 [tunnel\_bind](#tunnel_bind)操作：

> ```
> geo $upstream_last_addr $bind_addr {
>     volatile;
>
>     易揮發的;
>     10.0.0.0/24    10.0.0.1;
>     192.168.0.0/24  192.168.0.1;
> }
> 
> tunnel_bind         $bind_addr;
>
> tunnel_bind $bind_addr;
> tunnel_bind_dynamic on;
>
> tunnel_bind_dynamic 已啟用；
> ```

Sets the `*size*` of the buffer used for reading data from the backend server. Also sets the `*size*` of the buffer used for reading data from the client.

設定用於從後端伺服器讀取資料的緩衝區的`*size*` 。同時設定用於從客戶端讀取資料的緩衝區的`*size*` 。

Defines a timeout for establishing a connection with a backend server. It should be noted that this timeout cannot usually exceed 75 seconds.

定義與後端伺服器建立連線的逾時時間。需要注意的是，此超時時間通常不能超過 75 秒。

Specifies in which cases a request should be passed to the next server:

指定在哪些情況下應將請求傳遞給下一個伺服器：

`error`

an error occurred while establishing a connection with the server or reading data from the server;

與伺服器建立連線或從伺服器讀取資料時發生錯誤；

`timeout`

a timeout has occurred while establishing a connection with the server, passing a request to it, or reading data from the server;

與伺服器建立連線、向伺服器發送請求或從伺服器讀取資料時發生逾時；

`denied`

the server [denied](#tunnel_allow_upstream) the connection;

伺服器[拒絕](#tunnel_allow_upstream)連線；

> This parameter is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 此參數作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`off`

disables passing a request to the next server.

禁用向下一個伺服器傳遞請求。

One should bear in mind that passing a request to the next server is only possible if nothing has been sent to a client yet. That is, if an error or timeout occurs in the middle of the transferring of a response, fixing this is impossible.

需要注意的是，只有在尚未向客戶端發送任何資料的情況下，才能將請求傳遞給下一個伺服器。也就是說，如果在傳輸回應的過程中發生錯誤或逾時，則無法修復。

The directive also defines what is considered an [unsuccessful attempt](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#max_fails>) of communication with a server. The cases of `error`, `timeout`, and `denied` are always considered unsuccessful attempts, even if they are not specified in the directive.

該指令也定義了與伺服器通訊的[失敗嘗試`denied` (https://nginx.org/en/docs/http/ngx_http_upstream_module.html#max_fails)和`error`, `timeout`的情況始終被視為失敗嘗試，即使指令中未明確規定。

Passing a request to the next server can be limited by [the number of tries](#tunnel_next_upstream_tries) and by [time](#tunnel_next_upstream_timeout).

向下一個伺服器傳遞請求可以受到[嘗試次數](#tunnel_next_upstream_tries)和[時間](#tunnel_next_upstream_timeout)的限制。

限制請求傳遞到[下一個伺服器](#tunnel_next_upstream)的時間。 `0`值關閉此限制。

<table>

Limits the number of possible tries for passing a request to the [next server](#tunnel_next_upstream). The `0` value turns off this limitation.

限制將請求傳遞到[下一個伺服器](#tunnel_next_upstream)的可能嘗試次數。 `0`值關閉此限制。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**tunnel_pass** [`*address*`];``<br>` `**tunnel_pass** [` *地址* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `server`, `location`, `if in location` |

Enables handling of CONNECT requests and sets the address of a backend server. By default, the `address` is `*$host:$request_port*` and is taken from the client request. In most cases, `tunnel_pass` does not require configuring any arguments.

啟用對CONNECT請求的處理，並設定後端伺服器的位址。預設情況下， `address`為`*$host:$request_port*` ，取自客戶端請求。大多數情況下， `tunnel_pass`不需要配置任何參數。

The address can be specified as a domain name or IP address, and a port:

位址可以指定為網域名稱或IP位址，以及連接埠：

> ```
> tunnel_pass localhost:9000;
> ```

or as a UNIX-domain socket path:

或作為UNIX域套接字路徑：

> ```
> tunnel_pass unix:/tmp/backend.socket;
> ```

If a domain name resolves to several addresses, all of them will be used in a round-robin fashion. In addition, an address can be specified as a [server group](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md>).

如果一個網域解析到多個位址，則所有這些位址將以輪詢方式使用。此外，可以將位址指定為 [伺服器群組](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md>) 。

Parameter value can contain variables. In this case, if an address is specified as a domain name, the name is searched among the described [server groups](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md>), and, if not found, is determined using a [resolver](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>).

參數值可以包含變數。在這種情況下，如果將位址指定為域名，則會在所描述的 [伺服器群組](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md>)中搜尋該名稱，如果找不到，則使用 [解析器](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>)進行確定。

Sets the timeout between two successive read or write operations on client or backend server connections. If no data is transmitted within this time, the connection is closed.

設定客戶端或後端伺服器連線上兩次連續讀取或寫入操作之間的逾時時間。如果在此時間內沒有資料傳輸，則連線將關閉。

If the directive is set to a non-zero value, nginx will try to minimize the number of send operations on outgoing connections to a backend server by using either `NOTE_LOWAT` flag of the [kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>) method, or the `SO_SNDLOWAT` socket option, with the specified `*size*`.

如果指令設為非零值，nginx 將嘗試透過使用 [kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>)方法的`NOTE_LOWAT`標誌或`SO_SNDLOWAT`套接字選項，以及指定的`*size*`來最小化到後端伺服器的出站連接的發送操作次數。

This directive is ignored on Linux, Solaris, and Windows.

該指令在 Linux、Solaris 和 Windows 系統上會被忽略。

Sets a timeout for transmitting a request to the backend server. The timeout is set only between two successive write operations, not for the transmission of the whole request. If the backend server does not receive anything within this time, the connection is closed.

設定向後端伺服器發送請求的逾時時間。超時時間僅設定在兩次連續寫入操作之間，而非整個請求的傳輸時間。如果後端伺服器在此時間內未收到任何數據，則連線將關閉。

Configures the “TCP keepalive” behavior for outgoing connections to a backend server. By default, the operating system’s settings are in effect for the socket. If the directive is set to the value “`on`”, the `SO_KEEPALIVE` socket option is turned on for the socket.

配置與後端伺服器建立的出站連線的「 TCP keepalive」行為。預設情況下，套接字採用作業系統的設定。如果指令值設定為“ `on` ”，則會為套接字啟用`SO_KEEPALIVE`選項。

設定與後端伺服器建立出站連線的接收緩衝區大小（ `SO_RCVBUF`選項）。特殊值`0`會取消從上一配置等級繼承的`tunnel_socket_rcvbuf`指令的效果，從而允許作業系統對套接字的設定生效。
