The `ngx_http_oidc_module` module (1.27.4) implements authentication as a Relying Party in OpenID Connect using the [Authorization Code Flow](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowAuth).

`ngx_http_oidc_module`模組 ( 1.27.4 ) 使用 [授權碼流程](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowAuth)在 OpenID Connect 中作為信賴方實作身分驗證。

The module expects the OpenID Provider's configuration to be available via [metadata](https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderConfig) and requires dynamic [resolver](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>).

此模組期望透過 [metadata](https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderConfig)取得 OpenID 提供者的配置，並且需要動態 [resolver](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>) 。

The module can be combined with other access modules via the [satisfy](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>) directive. Note that the module may still block requests even with `satisfy any;` as an OpenID Provider might not redirect the user back to nginx.

此模組可透過 `[satisfy](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>)指令與其他存取模組組合使用。請注意，即使使用`satisfy any;`指令，該模組仍可能阻止請求，因為 OpenID 提供者可能不會將使用者重新導向回 nginx。

> This module is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Example Configuration｜範例配置

> ```
> http {
>     resolver 10.0.0.1;
>
>     解決10.0.0.1 ；
> 
>     oidc_provider my_idp {
>         issuer        "https://provider.domain";
>
>         發行方「 https://provider.domain";
>         client_id     "unique_id";
>
>         client_id "unique_id";
>         client_secret "unique_secret";
>     }
> 
>     server {
>
>     伺服器 {
>         location / {
>
>         地點 / {
>             auth_oidc my_idp;
> 
>             proxy_set_header username $oidc_claim_sub;
>             proxy_pass       http://backend;
>
>             proxy_pass http://backend;
>         }
>     }
> }
> ```

The example assumes that the “`https://<nginx-host>/oidc_callback`” Redirection URI is configured on the OpenID Provider's side. The path can be customized with the [redirect\_uri](#redirect_uri) directive.

此範例假設 OpenID 提供者端已配置「 `https://<nginx-host>/oidc_callback` 」重定向URI 。可以使用 [redirect\_uri](#redirect_uri)指令自訂路徑。

#### Embedded Variables｜嵌入變數

The `ngx_http_oidc_module` module supports embedded variables:

`ngx_http_oidc_module`模組支援嵌入式變數：

`$oidc_id_token`

ID token

ID代幣

`$oidc_access_token`

access token

訪問令牌

`$oidc_claim_``*name*`

top-level ID token or UserInfo claim

頂級ID令牌或 UserInfo 聲明

Nested claims can be fetched with the [auth\_jwt](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>) module:

可以使用 [auth\_jwt](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>)模組取得嵌套宣告：

> ```
> http {
>     auth_jwt_claim_set $postal_code address postal_code;
> 
>     server {
>
>     伺服器 {
>         location / {
>
>         地點 / {
>             auth_oidc my_idp;
>             auth_jwt  off token=$oidc_id_token;
>
>             auth_jwt 關閉 token=$oidc_id_token;
> 
>             proxy_set_header x-postal_code $postal_code;
>             proxy_pass       http://backend;
>
>             proxy_pass http://backend;
>         }
>     }
