Часто разработчику приходится использовать сторонний код и, как правило, такой код доступен в виде библиотеки. В JavaScript концепция модулей является новой и до недавнего времени не была стандартизированa. До сих пор множество платформ или браузеров не поддерживают модули, по этой причине практически невозможно повторно использовать код. В данной статье приводятся способы повторного использования кода в njs при помощи [Node.js](https://nodejs.org/).

開發者經常需要使用第三方程式碼，而這些程式碼通常以程式庫的形式提供。 JavaScript 中的模組概念是近期才出現的，直到最近才被標準化。許多平台和瀏覽器仍然不支援模組，這使得程式碼重用幾乎不可能。本文將介紹如何使用 [Node.js](https://nodejs.org/)在 JavaScript 中重複使用程式碼。

> В примерах статьи используется функциональность [njs](<290 [02.01.03 紐澤西州] 模組 nginx JavaScript.md>) [0.3.8](https://nginx.org/ru/docs/njs/changes.html#njs0.3.8)
>
> 本文中的範例使用了 [njs](<290 [02.01.03 紐澤西州] 模組 nginx JavaScript.md>) [0.3.8](https://nginx.org/ru/docs/njs/changes.html#njs0.3.8)的功能

При добавлении стороннего кода в njs может возникнуть несколько проблем:

在向njs新增第三方程式碼時，可能會出現以下幾個問題：

-   большое количество файлов, ссылающихся друг на друга, и их зависимости  
    大量相互引用的文件及其依賴關係
-   платформозависимые API  
    平台相關API
-   языковые конструкции нового стандарта  
    新標準的語言結構

Однако это не является чем-то новым или специфичным для njs. Разработчикам JavaScript приходится часто иметь дело с подобными случаями, например при поддержке нескольких несхожих платформ с разными свойствами. Данные проблемы можно разрешить при помощи следующих инструментов:

然而，這並非NJS獨有的新問題。 JavaScript開發者經常會遇到類似的情況，例如在支援多個具有不同功能的平台時。這些問題可以使用以下工具解決：

-   Большое количество файлов, ссылающихся друг на друга, и их зависимости  
    大量文件相互引用及其依賴關係
    
    Решение: слияние всего независимого кода в один файл. Для этих целей могут использоваться утилиты [browserify](http://browserify.org/) или [webpack](https://webpack.js.org/), позволяющие преобразовать проект в один файл, содержащий код и все зависимости.

    解決方案：將所有獨立代碼合併到一個檔案中。為此，您可以使用 [browserify](http://browserify.org/)或 [webpack](https://webpack.js.org/)工具，它們可以將項目轉換為包含程式碼及其所有依賴項的單一檔案。
    
-   Платформозависимые API  
    平台相關API
    
    Решение: использование библиотек, реализующих подобные API в платформонезависимом режиме, однако в ущерб производительности. Определённая функциональность может быть также реализована при помощи [polyfill](https://polyfill.io/v3/).

    解決方案：使用以平台無關的方式實現類似API函式庫，但會犧牲效能。某些功能也可以使用(https://polyfill.io/v3/) polyfill 來實現。
    
-   Языковые конструкции нового стандарта  
    新標準的語言結構
    
    Решение: трансплирование кода — ряд преобразований, заменяющих новые функции языка в соответствии со старым стандартом. Для этих целей может использоваться [babel](https://babeljs.io/).

    解決方案：代碼轉譯－一系列轉換，將新語言特性替換為舊標準特性。 [babel](https://babeljs.io/)可用於此目的。

#### Protobufjs

Библиотека предоставляет парсер для определения интерфейса `.proto`, а также генератор кода для парсинга и генерации сообщений.

該函式庫提供了一個用於定義`.proto`介面的解析器，以及一個用於解析和產生訊息的程式碼產生器。

В данном примере используется файл [helloworld.proto](https://github.com/grpc/grpc/blob/master/examples/protos/helloworld.proto) из примеров gRPC. Целью является создание двух сообщений: `HelloRequest` и `HelloResponse`. Также используется [статический](https://github.com/protobufjs/protobuf.js/blob/master/README.md#reflection-vs-static-code) режим protobufjs вместо динамически генерируемых классов, так как njs не поддерживает динамическое добавление новых функций из соображений безопасности.

本範例使用 gRPC 範例中的 [helloworld.proto](https://github.com/grpc/grpc/blob/master/examples/protos/helloworld.proto)檔案。目標是建立兩個訊息： `HelloRequest`和`HelloResponse` 。由於 njs 出於安全考量不支援動態新增功能，因此本範例使用了 Protobufjs 的 [static](https://github.com/protobufjs/protobuf.js/blob/master/README.md#reflection-vs-static-code)模式，而不是動態產生的類別。

Затем устанавливается библиотека, из определения протокола генерируется код JavaScript, реализующий маршалинг сообщений:

然後安裝該庫，並根據協議定義生成 JavaScript 程式碼來實現訊息序列化：

> ```bash
>
> 『`bash
> $ npm install protobufjs
> $ npx pbjs -t static-module helloworld.proto > static.js
> ```

Таким образом файл `static.js` становится новой зависимостью, хранящей необходимый код для реализации обработки сообщений. Функция `set_buffer()` содержит код, использующий библиотеку для создания буфера с сериализованным сообщением `HelloRequest`. Код находится в файле `code.js`:

因此，檔案`static.js`成為一個新的依賴項，其中儲存了實現訊息處理所需的程式碼。函數`set_buffer()`包含使用此函式庫建立包含序列化訊息`HelloRequest`的緩衝區的程式碼。程式碼位於檔案`code.js`中：

> ```js
> var pb = require('./static.js');
> 
> // Пример использования библиотеки protobuf: подготовка буфера к отправке
>
> // 使用 protobuf 函式庫的範例：準備用於傳送的緩衝區
> function set_buffer(pb)
>
> 函式 set_buffer(pb)
> {
>     // назначение полей gRPC payload
>
>     // gRPC 有效載荷欄位賦值
>     var payload = { name: "TestString"（測試字串） };
> 
>     // создание объекта
>
>     // 建立物件
>     var message = pb.helloworld.HelloRequest.create(payload);
> 
>     // сериализация объекта в буфер
>
>     // 將物件序列化到緩衝區
>     var buffer = pb.helloworld.HelloRequest.encode(message).finish();
> 
>     var n = buffer.length;
> 
>     var frame = new Uint8Array(5 + buffer.length);
> 
>     frame[0] = 0;                        // флаг 'compressed'
>
>     frame[0] = 0; // 'compressed' 幀
>     frame[1] = (n & 0xFF000000) >>> 24;  // длина: uint32 в сетевом порядке байт
>
>     frame[1] = (n & 0xFF000000) >>> 24; // 長度：網路位元組序的 uint32
>     frame[2] = (n & 0x00FF0000) >>> 16;
>     frame[3] = (n & 0x0000FF00) >>>  8;
>
>     frame[3] = (n & 0x0000FF00) >>> 8;
>     frame[4] = (n & 0x000000FF) >>>  0;
>
>     frame[4] = (n & 0x000000FF) >>> 0;
> 
>     frame.set(buffer, 5);
> 
>     return frame;
>
>     返回幀；
> }
> 
> var frame = set_buffer(pb);
> ```

嘗試處理`code.js`檔案會產生大量JS程式碼，這些程式碼旨在瀏覽器中運行，即在下載後立即運行。然而，我們需要的是不同的結果——一個可以從 nginx 配置中引用的導出函數。這需要編寫包裝程式碼。
