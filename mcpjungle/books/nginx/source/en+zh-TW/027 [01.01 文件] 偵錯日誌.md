# A debugging log｜偵錯日誌

> 章節：[en｜在](<000 目錄.md#c-1>) › [docs｜文件](<000 目錄.md#c-2>)

## A debugging log｜偵錯日誌

|   |
| --- |
| [Debugging log for selected clients](#clients)<br>[Logging to a cyclic memory buffer](#memory)<br>[選定客戶端的偵錯日誌](#clients)<br>[記錄到循環記憶體緩衝區](#memory) |

To enable a debugging log, nginx needs to be configured to support debugging during the build:

要啟用調試日誌，需要將 nginx 配置為在建置期間支援調試：

> ```
> ./configure --with-debug ...
> ```

Then the `debug` level should be set with the [error\_log](<125 [01.01 文件] 核心功能.md#error_log>) directive:

然後應該使用 [error\_log](<125 [01.01 文件] 核心功能.md#error_log>) 指令設定 `debug` 等級：

> ```
> error_log /path/to/log debug;
>
> error_log /path/to/log 調試；
> ```

To verify that nginx is configured to support debugging, run the `nginx -V` command:

若要驗證 nginx 是否已配置為支援偵錯，請執行 `nginx -V` 命令：

> ```
> configure arguments: --with-debug ...
>
> 配置參數：--with-debug ...
> ```

Pre-built [Linux](<177 [01 在] nginx Linux 軟體套件.md>) packages provide out-of-the-box support for debugging log with the `nginx-debug` binary (1.9.8) which can be run using commands

預先建置的 [Linux](<177 [01 在] nginx Linux 軟體套件.md>) 軟體包透過可使用命令運行的 `nginx-debug` 二進位檔案 (1.9.8) 為偵錯日誌提供開箱即用的支持

> ```
> service nginx stop
>
> 服務 nginx 停止
> service nginx-debug start
>
> 服務 nginx-debug 啟動
> ```

and then set the `debug` level. The nginx binary version for Windows is always built with the debugging log support, so only setting the `debug` level will suffice.

然後設定`debug`級別。 Windows 的 nginx 二進位版本始終建置有偵錯日誌支持，因此只需設定 `debug` 等級就足夠了。

Note that redefining the log without also specifying the `debug` level will disable the debugging log. In the example below, redefining the log on the [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) level disables the debugging log for this server:

請注意，重新定義日誌而不指定 `debug` 等級將停用偵錯日誌。在下面的範例中，在 [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) 層級上重新定義日誌將停用該伺服器的偵錯日誌：

> ```
> error_log /path/to/log debug;
>
> error_log /path/to/log 調試；
> 
> http {
>
> http{
>     server {
>
>     伺服器{
>         error_log /path/to/log;
>
>         error_log /路徑/到/日誌；
>         ...
> ```

To avoid this, either the line redefining the log should be commented out, or the `debug` level specification should also be added:

為了避免這種情況，應該註解掉重新定義日誌的行，或者還應該新增 `debug` 等級規格：

> ```
> error_log /path/to/log debug;
>
> error_log /path/to/log 調試；
> 
> http {
>
> http{
>     server {
>
>     伺服器{
>         error_log /path/to/log debug;
>
>         error_log /path/to/log 調試；
>         ...
> ```

#### Debugging log for selected clients｜選定客戶端的調試日誌

It is also possible to enable the debugging log for [selected client addresses](<125 [01.01 文件] 核心功能.md#debug_connection>) only:

也可以僅啟用[選定的客戶端位址](<125 [01.01 文件] 核心功能.md#debug_connection>)的偵錯日誌：

> ```
> error_log /path/to/log;
>
> error_log /路徑/到/日誌；
> 
> events {
>
> 事件{
>     debug_connection 192.168.1.1;
>
>     調試連接192.168.1.1；
>     debug_connection 192.168.10.0/24;
>
>     調試連接192.168.10.0/24；
> }
> ```

#### Logging to a cyclic memory buffer｜記錄到循環記憶體緩衝區

The debugging log can be written to a cyclic memory buffer:

調試日誌可以寫入循環記憶體緩衝區：

> ```
> error_log memory:32m debug;
>
> error_log記憶體：32m調試；
> ```

Logging to the memory buffer on the `debug` level does not have significant impact on performance even under high load. In this case, the log can be extracted using a `gdb` script like the following one:

即使在高負載下，記錄到`debug`等級的記憶體緩衝區也不會對效能產生重大影響。在這種情況下，可以使用 `gdb` 腳本提取日誌，如下所示：

> ```
> set $log = ngx_cycle->log
>
> 設定 $log = ngx_cycle->log
> 
> while $log->writer != ngx_log_memory_writer
>
> 而 $log->writer != ngx_log_memory_writer
>     set $log = $log->next
>
>     設定 $log = $log->下一個
> end
>
> 結束
> 
> set $buf = (ngx_log_memory_buf_t *) $log->wdata
>
> 設定 $buf = (ngx_log_memory_buf_t *) $log->wdata
> dump binary memory debug_log.txt $buf->start $buf->end
>
> 轉儲二進位記憶體 debug_log.txt $buf->start $buf->end
> ```

Or using an `lldb` script as follows:

或使用 `lldb` 腳本，如下所示：

> ```
> expr ngx_log_t *$log = ngx_cycle->log
> expr while ($log->writer != ngx_log_memory_writer) { $log = $log->next; }
> expr ngx_log_memory_buf_t *$buf = (ngx_log_memory_buf_t *) $log->wdata
> memory read --force --outfile debug_log.txt --binary $buf->start $buf->end
>
> 記憶體讀取 --force --outfile debug_log.txt --binary $buf->start $buf->end
> ```
