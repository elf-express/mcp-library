If `accept_mutex` is enabled, worker processes will accept new connections by turn. Otherwise, all worker processes will be notified about new connections, and if volume of new connections is low, some of the worker processes may just waste system resources.

如果啟用`accept_mutex` ，工作進程將輪流接受新連線。否則，所有工作流程都會收到新連線的通知，如果新連線數量較少，部分工作流程可能會浪費系統資源。

> There is no need to enable `accept_mutex` on systems that support the [EPOLLEXCLUSIVE](<030 [01.01 文件] 連接處理方式.md#epoll>) flag (1.11.3) or when using [reuseport](<056 [01.01.03 http] 模組 ngx_http_core_module.md#reuseport>).
>
> 在支援 [EPOLLEXCLUSIVE](<030 [01.01 文件] 連接處理方式.md#epoll>)標誌 ( 1.11.3 ) 的系統上，或在使用 [reuseport](<056 [01.01.03 http] 模組 ngx_http_core_module.md#reuseport>)時，無需啟用`accept_mutex` 。

> Prior to version 1.11.3, the default value was `on`.
>
> 在版本1.11.3之前，預設值為`on` 。

If [accept\_mutex](#accept_mutex) is enabled, specifies the maximum time during which a worker process will try to restart accepting new connections if another worker process is currently accepting new connections.

如果啟用了 [accept\_mutex](#accept_mutex) ，則指定當另一個工作進程目前正在接受新連線時，工作進程會嘗試重新接受新連線的最大時間。

Determines whether nginx should become a daemon. Mainly used during development.

決定nginx是否應作為守護程式運行。主要用於開發階段。

| Syntax:<br>語法： | ``**debug_connection** `*address*` \| `*CIDR*` \| `unix:`;``<br>` `**debug_connection** ` *地址* ` \| ` * CIDR * ` \| ` unix: `;` ` |

Enables debugging log for selected client connections. Other connections will use logging level set by the [error\_log](#error_log) directive. Debugged connections are specified by IPv4 or IPv6 (1.3.0, 1.2.1) address or network. A connection may also be specified using a hostname. For connections using UNIX-domain sockets (1.3.0, 1.2.1), debugging log is enabled by the “`unix:`” parameter.

啟用選定客戶端連線的偵錯日誌。其他連線將使用 [error\_log](#error_log)指令設定的日誌等級。調試連線透過 IPv4 或 IPv6 ( 1.3.0, 1.2.1 ) 位址或網路指定。也可以使用主機名稱指定連線。對於使用UNIX域套接字 ( 1.3.0, 1.2.1 ) 的連接，偵錯日誌由「 `unix:` 」參數啟用。

> ```
> events {
>
> 事件 {
>     debug_connection 127.0.0.1;
>
>     debug_connection 127.0.0.1 ;
>     debug_connection localhost;
>     debug_connection 192.0.2.0/24;
>
>     debug_connection 192.0.2.0/24 ;
>     debug_connection ::1;
>     debug_connection 2001:0db8::/32;
>
>     debug_connection 2001:0db8::/32 ;
>     debug_connection unix:;
>     ...
> }
> ```

> For this directive to work, nginx needs to be built with `--with-debug`, see “[A debugging log](<027 [01.01 文件] 偵錯日誌.md>)”.
>
> 若要使此指令生效，nginx 需要使用`--with-debug`構建，請參閱「[偵錯日誌](<027 [01.01 文件] 偵錯日誌.md>) 」。

This directive is used for debugging.

此指令用於調試。

When internal error is detected, e.g. the leak of sockets on restart of working processes, enabling `debug_points` leads to a core file creation (`abort`) or to stopping of a process (`stop`) for further analysis using a system debugger.

當偵測到內部錯誤時，例如在工作進程重新啟動時套接字洩漏，啟用`debug_points`會導致建立核心檔案 ( `abort` ) 或停止進程 ( `stop` ) 以便使用系統偵錯器進行進一步分析。

By default, nginx removes all environment variables inherited from its parent process except the TZ variable. This directive allows preserving some of the inherited variables, changing their values, or creating new environment variables. These variables are then:

預設情況下，nginx 會移除從父進程繼承的所有環境變量，但TZ變數除外。此指令允許保留部分繼承的變數、更改其值或建立新的環境變數。這些變數包括：

-   inherited during a [live upgrade](<026 [01.01 文件] 控制 Nginx.md#upgrade>) of an executable file;  
    在可執行檔的 [即時升級](<026 [01.01 文件] 控制 Nginx.md#upgrade>)過程中繼承；
-   used by the [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>) module;  
    由 [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>)模組使用；
-   used by worker processes. One should bear in mind that controlling system libraries in this way is not always possible as it is common for libraries to check variables only during initialization, well before they can be set using this directive. An exception from this is an above mentioned [live upgrade](<026 [01.01 文件] 控制 Nginx.md#upgrade>) of an executable file.  
    供工作進程使用。需要注意的是，並非總是能夠以這種方式控制系統庫，因為庫通常只在初始化期間檢查變量，而此時遠未達到可以通過此指令設置變量的程度。上述可執行檔的 [live upgrade](<026 [01.01 文件] 控制 Nginx.md#upgrade>)是一個例外。

The TZ variable is always inherited and available to the [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>) module, unless it is configured explicitly.

除非明確配置，否則TZ變數總是會被 [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>)模組繼承和使用。

Usage example:

使用範例：

> ```
> env MALLOC_OPTIONS;
> env PERL5LIB=/data/site/modules;
>
> env PERL5LIB =/data/site/modules;
> env OPENSSL_ALLOW_PROXY_CERTS=1;
> ```

> The NGINX environment variable is used internally by nginx and should not be set directly by the user.
>
> NGINX環境變數由 nginx 內部使用，使用者不應直接設定。

</table>

Configures logging. Several logs can be specified on the same configuration level (1.5.2). If on the `main` configuration level writing a log to a file is not explicitly defined, the default file will be used.

配置日誌記錄。可以在相同配置等級（ 1.5.2 ）指定多個日誌。如果在`main`配置層級未明確定義將日誌寫入文件，則將使用預設檔。

The first parameter defines a `*file*` that will store the log. The special value `stderr` selects the standard error file. Logging to [syslog](<169 [01.01 文件] 日誌記錄到系統日誌.md>) can be configured by specifying the “`syslog:`” prefix. Logging to a [cyclic memory buffer](<027 [01.01 文件] 偵錯日誌.md#memory>) can be configured by specifying the “`memory:`” prefix and buffer `*size*`, and is generally used for debugging (1.7.11).

第一個參數定義了一個用於儲存日誌的`*file*` 。特殊值`stderr`選擇標準錯誤檔案。可以透過指定前綴「 `syslog:` 」配置將日誌記錄到 [syslog](<169 [01.01 文件] 日誌記錄到系統日誌.md>) 。可以透過指定前綴「 `memory:` 」和緩衝區(https://nginx.org/en/docs/debugging_log.html#memory)配置將日誌記錄到 [循環記憶體緩衝區]`*size*` ，這通常用於偵錯 ( 1.7.11 )。

The second parameter determines the `*level*` of logging, and can be one of the following: `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`, or `emerg`. Log levels above are listed in the order of increasing severity. Setting a certain log level will cause all messages of the specified and more severe log levels to be logged. For example, the default level `error` will cause `error`, `crit`, `alert`, and `emerg` messages to be logged. If this parameter is omitted then `error` is used.

第二個參數決定日誌等級`*level*` ，可以是下列數值之一： `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`或`emerg` 。以上日誌等級依嚴重程度遞增的順序排列。設定某個日誌等級將導致記錄所有指定等級及更高等級的訊息。例如，預設等級`error`將導致記錄`error`, `crit`, `alert`和`emerg`訊息。如果省略此參數，則使用`error` 。

> For `debug` logging to work, nginx needs to be built with `--with-debug`, see “[A debugging log](<027 [01.01 文件] 偵錯日誌.md>)”.
>
> 若要使`debug`日誌記錄正常運作，需要使用`--with-debug`建置 nginx，請參閱「[偵錯日誌](<027 [01.01 文件] 偵錯日誌.md>) 」。

The `json` parameter (1.29.8) enables writing a log in the JSON format, with support for [context tags](<056 [01.01.03 http] 模組 ngx_http_core_module.md#error_log_tag>):

`json`參數 ( 1.29.8 ) 允許以JSON格式寫入日誌，並支援 [上下文標籤](<056 [01.01.03 http] 模組 ngx_http_core_module.md#error_log_tag>) :

> ```json
> {
>   "level": "error",
>
>   "等級": "錯誤",
>   "timestamp": "2026-05-13T10:30:15.042+00:00",
>
>   "timestamp": "2026-05-13T10:30: 15.042 +00:00",
>   "pid": 12345,  "tid": 12345,  "cnum": 3,
>
>   「pid」：12345，「tid」：12345，「cnum」：3，
>   "msg": "connect() failed",
>
>   "msg": "connect() 失敗",
>   "client": "192.168.1.10",  "server": "example.com",
>
>   "客戶端": " 192.168.1.10 ", "伺服器": "example.com",
>   "request": "GET /api HTTP/1.1",
>
>   "請求": " GET /api HTTP/1.1 ",
>   "upstream": "http://127.0.0.1:8080/api",
>
>   「上游」： http://127.0.0.1:8080/api",
>   "errno": 111,
>   "errtext": "Connection refused"
>
>   "errtext": "連線被拒絕"
> }
> ```

A log entry cannot exceed 2 KB, data beyond this limit is truncated to `“truncated”:1`. Debug logging is not supported for JSON.

日誌條目不能超過 2 KB ，超出此限制的資料將被截斷為`“truncated”:1` 。調試日誌記錄不支援JSON 。

> This parameter is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 此參數作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

> The directive can be specified on the `stream` level starting from version 1.7.11, and on the `mail` level starting from version 1.9.0.
>
> 從版本1.7.11開始，可以在`stream`層級指定該指令；從版本1.9.0開始，可以在`mail`層級指定該指令。

nginx uses the locking mechanism to implement [accept\_mutex](#accept_mutex) and serialize access to shared memory. On most systems the locks are implemented using atomic operations, and this directive is ignored. On other systems the “lock file” mechanism is used. This directive specifies a prefix for the names of lock files.

nginx 使用鎖定機制來實作 [accept\_mutex](#accept_mutex)並且串列化對共享記憶體的存取。在大多數系統中，鎖是透過原子操作實現的，因此該指令會被忽略。在其他系統中，則會使用「鎖定檔案」機制。此指令指定鎖定檔案名稱的前綴。

If `multi_accept` is disabled, a worker process will accept one new connection at a time. Otherwise, a worker process will accept all new connections at a time.

如果`multi_accept`被停用，則工作進程一次只接受一個新連線。否則，工作進程一次接受所有新連線。

> The directive is ignored if [kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>) connection processing method is used, because it reports the number of new connections waiting to be accepted.
>
> 如果使用 [kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>)連接處理方法，則會忽略該指令，因為它會報告等待接受的新連接數。
