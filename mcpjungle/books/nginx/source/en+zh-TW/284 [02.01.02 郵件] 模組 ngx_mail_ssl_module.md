Модуль `ngx_mail_ssl_module` обеспечивает работу почтового прокси-сервера по протоколу SSL/TLS.

`ngx_mail_ssl_module`模組確保使用SSL/TLS協定的郵件代理伺服器正常運作。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-mail_ssl_module`.

此模組預設未構建，必須使用`--with-mail_ssl_module`配置參數啟用。

> Для сборки и работы этого модуля нужна библиотека [OpenSSL](http://www.openssl.org/).
>
> 要建置和運行此模組，您需要 [OpenSSL](http://www.openssl.org/)庫。

Указывает `*файл*` с сертификатом в формате PEM для данного сервера. Если вместе с основным сертификатом нужно указать промежуточные, то они должны находиться в этом же файле в следующем порядке: сначала основной сертификат, а затем промежуточные. В этом же файле может находиться секретный ключ в формате PEM.

指定此伺服器的`*файл*`證書，該證書包含PEM證書。如果除了主證書外還需要中間證書，則必須將它們按以下順序放在同一個文件中：先是主證書，然後是中間證書。此文件中還可以包含PEM格式的私鑰。

Начиная с версии 1.11.0 эта директива может быть указана несколько раз для загрузки сертификатов разных типов, например RSA и ECDSA:

自版本1.11.0起，可以多次指定此指令以載入不同類型的證書，例如RSA和ECDSA ：

> ```
> server {
>
> 伺服器{
>     listen              993 ssl;
>
>     監聽 993 ssl；
> 
>     ssl_certificate     example.com.rsa.crt;
>
>     ssl_certificate example.com.rsa.crt；
>     ssl_certificate_key example.com.rsa.key;
>
>     ssl_certificate_key example.com.rsa.key；
> 
>     ssl_certificate     example.com.ecdsa.crt;
>
>     ssl_certificate example.com.ecdsa.crt；
>     ssl_certificate_key example.com.ecdsa.key;
>
>     ssl_certificate_key example.com.ecdsa.key；
> 
>     ...
> }
> ```

> Возможность задавать отдельные [цепочки сертификатов](<212 [02.01.01 http] 設定HTTPS伺服器.md#chains>) для разных сертификатов есть только в OpenSSL 1.0.2 и выше. Для более старых версий следует указывать только одну цепочку сертификатов.
>
> 僅在 OpenSSL 1.0.2及更高版本中才支援為不同的憑證指定(https://nginx.org/ru/docs/http/configuring_https_servers.html#chains)的憑證鏈。對於舊版本，只能指定一條憑證鏈。

Вместо `*файла*` можно указать значение `data`:`*сертификат*` (1.15.10), при котором сертификат загружается без использования промежуточных файлов. При этом следует учитывать, что ненадлежащее использование подобного синтаксиса может быть небезопасно, например данные секретного ключа могут попасть в [лог ошибок](<285 [02.01 文件] 基本功能.md#error_log>).

您可以指定`data`:`*сертификат*` ( 1.15.10 ) 而不是`*файла*`這樣無需使用中間檔案即可載入憑證。但是，請注意，不當使用此語法可能不安全；例如，私鑰資料最終可能會出現在 [錯誤日誌](<285 [02.01 文件] 基本功能.md#error_log>)中。

> До версии 1.11.0 по умолчанию использовалась кривая `prime256v1`.
>

> При использовании OpenSSL 1.0.2 и выше директива задаёт список кривых, поддерживаемых сервером. Поэтому для работы ECDSA-сертификатов важно, чтобы список включал кривые, используемые в сертификатах.

Задаёт тип и размеры кэшей для хранения параметров сессий. Тип кэша может быть следующим:

指定用於儲存會話參數的快取類型和大小。快取類型可以是以下幾種之一：

`off`

жёсткое запрещение использования кэша сессий: nginx явно сообщает клиенту, что сессии не могут использоваться повторно.

完全禁止使用會話快取：nginx 明確告知客戶端會話不能重複使用。

`none`

мягкое запрещение использования кэша сессий: nginx сообщает клиенту, что сессии могут использоваться повторно, но на самом деле не хранит параметры сессии в кэше.

軟性禁止使用會話快取：nginx 告訴客戶端會話可以重複使用，但實際上並不會將會話參數儲存在快取中。

`builtin`

встроенный в OpenSSL кэш, используется в рамках только одного рабочего процесса. Размер кэша задаётся в сессиях. Если размер не задан, то он равен 20480 сессиям. Использование встроенного кэша может вести к фрагментации памяти.

OpenSSL 的內建快取僅在一個工作進程內使用。快取大小以會話為單位指定。如果未指定大小，則預設為 20480 個會話。使用內建快取可能會導致記憶體碎片。

`shared`

кэш, разделяемый между всеми рабочими процессами. Размер кэша задаётся в байтах, в 1 мегабайт может поместиться около 4000 сессий. У каждого разделяемого кэша должно быть произвольное название. Кэш с одинаковым названием может использоваться в нескольких серверах. Также он используется для автоматического создания, хранения и периодического обновления ключей TLS session tickets (1.23.2), если они не указаны явно с помощью директивы [ssl\_session\_ticket\_key](#ssl_session_ticket_key).

所有工作進程共享的快取。快取大小以位元組為單位指定；1 MB 大約可以容納 4000 個會話。每個共享快取必須具有任意名稱。同名快取可以在多個伺服器上使用。它也用於自動建立、儲存和定期刷新會話票證（ TLS ）（ 1.23.2 ），除非使用 [ssl_session_ticket_key](#ssl_session_ticket_key)指令明確指定。

Можно использовать одновременно оба типа кэша, например:

您可以同時使用這兩種類型的緩存，例如：

> ```
> ssl_session_cache builtin:1000 shared:SSL:10m;
>
> ssl_session_cache builtin:1000 shared: SSL :10m;
> ```

однако использование только разделяемого кэша без встроенного должно быть более эффективным.

但是，僅使用共享快取而不使用內建快取應該會更有效率。
