Модуль `ngx_http_scgi_module` позволяет передавать запросы SCGI-серверу.

`ngx_http_scgi_module`模組可讓您向SCGI伺服器發送請求。

#### Пример конфигурации｜配置範例

> ```
> location / {
>
> 地點 / {
>     include   scgi_params;
>
>     包含 scgi_params；
>     scgi_pass localhost:9000;
> }
> ```

Задаёт условия, при которых доступ к SCGI-серверу будет разрешён или [запрещён](#denied). Если все значения строковых параметров непустые и не равны “0”, то доступ разрешён. Задаёт локальный IP-адрес с необязательным портом (1.11.2), который будет использоваться в исходящих соединениях с SCGI-сервером. В значении параметра допустимо использование переменных (1.3.12). Специальное значение `off` (1.3.12) отменяет действие унаследованной с предыдущего уровня конфигурации директивы `scgi_bind`, позволяя системе самостоятельно выбирать локальный IP-адрес и порт.

指定用於與伺服器建立出SCGI連線的本機位址（ IP ，選用埠號1.11.2 ）。此參數值允許使用變數（ 1.3.12 ）。特殊值`off` （ 1.3.12 ）會覆寫從上一層配置繼承的指令`scgi_bind` ，允許系統獨立選擇本地位址和連接埠IP 。

Параметр `transparent` (1.11.0) позволяет задать нелокальный IP-aдрес, который будет использоваться в исходящих соединениях с SCGI-сервером, например, реальный IP-адрес клиента:

`transparent` ( 1.11.0 ) 參數可讓您指定一個非本地IP位址，該位址將用於與SCGI伺服器建立出站連接，例如，客戶端的真實IP位址：

> ```
> scgi_bind $remote_addr transparent;
> ```

Для работы параметра обычно требуется запустить рабочие процессы nginx с привилегиями [суперпользователя](<285 [02.01 文件] 基本功能.md#user>). В Linux этого не требуется (1.13.8), так как если указан параметр `transparent`, то рабочие процессы наследуют capability `CAP_NET_RAW` из главного процесса. Также необходимо настроить таблицу маршрутизации ядра для перехвата сетевого трафика с SCGI-сервера.

此參數通常要求以 [superuser 權限執行 nginx 工作進程](<285 [02.01 文件] 基本功能.md#user>) )。在 Linux 系統上則無需此操作 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程將從主進程繼承`CAP_NET_RAW`權限。此外，您還需要設定核心路由表以攔截來自SCGI伺服器的網路流量。

Задаёт `*размер*` буфера, в который будет читаться первая часть ответа, получаемого от SCGI-сервера. В этой части ответа находится, как правило, небольшой заголовок ответа; если его размер больше заданного, то такой ответ считается [неверным](#invalid_header). По умолчанию размер одного буфера равен размеру страницы памяти. В зависимости от платформы это или 4K, или 8K, однако его можно сделать меньше.

指定用於讀取從SCGI接收的回應第一部分的`*размер*` 。回應的這一部分通常包含一個較小的回應頭；如果其大小大於指定值，則該回應被視為[不正確(https://nginx.org/ru/docs/http/ngx_http_scgi_module.html#invalid_header) 。預設情況下，一個緩衝區的大小等於一個記憶體頁的大小。根據平台的不同，該大小為 4K 或 8K，但可以減少。

Разрешает или запрещает использовать буферизацию ответов SCGI-сервера.

啟用或停用SCGI伺服器回應緩衝。

Если буферизация включена, то nginx принимает ответ SCGI-сервера как можно быстрее, сохраняя его в буферы, заданные директивами [scgi\_buffer\_size](#scgi_buffer_size) и [scgi\_buffers](#scgi_buffers). Если ответ не вмещается целиком в память, то его часть может быть записана на диск во [временный файл](#scgi_temp_path). Запись во временные файлы контролируется директивами [scgi\_max\_temp\_file\_size](#scgi_max_temp_file_size) и [scgi\_temp\_file\_write\_size](#scgi_temp_file_write_size).

如果啟用了緩衝，nginx 會盡快SCGI伺服器的回應，並將其儲存在 [scgi\_buffer\_size] 和 [scgi\_buffers](#scgi_buffers)指定的(https://nginx.org/ru/docs/http/ngx_http_scgi_module.html#scgi_buffer_size)中。如果整個回應無法放入內存，則可以將其一部分寫入磁碟上的臨時檔案。寫入暫存檔案由 [scgi\_max\_temp\_file\ (https://nginx.org/ru/docs/http/ngx_http_scgi_module.html#scgi_temp_path) ] 和 [scgi\_temp\_file\_write\ (https://nginx.org/ru/docs/http/ngx_http_scgi_module.html#scgi_temp_file_write_size)](#scgi_max_temp_file_size)控制。

Если буферизация выключена, то ответ синхронно передаётся клиенту сразу же по мере его поступления. nginx не пытается считать весь ответ SCGI-сервера. Максимальный размер данных, который nginx может принять от сервера за один раз, задаётся директивой [scgi\_buffer\_size](#scgi_buffer_size).

如果停用緩衝，回應會在到達後立即同步傳輸給用戶端。 NGINX 不會嘗試讀取完整的SCGI回應。 NGINX 一次可以從伺服器接收的最大資料大小由 [scgi\_buffer\_size](#scgi_buffer_size)指定。

Буферизация может быть также включена или выключена путём передачи значения “`yes`” или “`no`” в поле “X-Accel-Buffering”（X-加速緩衝） заголовка ответа. Эту возможность можно запретить с помощью директивы [scgi\_ignore\_headers](#scgi_ignore_headers).

也可以透過在“X-Accel-Buffering”（X-加速緩衝）響應頭字段中傳遞值「 `yes` 」或「 `no` 」來啟用或停用緩衝。可以使用 [scgi\_ignore\_headers](#scgi_ignore_headers)指令停用此功能。

При включённой [буферизации](#scgi_buffering) ответов SCGI-сервера, ограничивает суммарный `*размер*` буферов, которые могут быть заняты для отправки ответа клиенту, пока ответ ещё не прочитан целиком. Оставшиеся буферы тем временем могут использоваться для чтения ответа и, при необходимости, буферизации части ответа во временный файл. По умолчанию `*размер*` ограничен двумя буферами, заданными директивами [scgi\_buffer\_size](#scgi_buffer_size) и [scgi\_buffers](#scgi_buffers).

啟用伺服器回應緩衝（[buffering](#scgi_buffering) SCGI ，在伺服器尚未完全讀取回應之前，可用於向客戶端發送回應的總緩衝區數量`*размер*`將受到限制。剩餘的緩衝區可用於讀取回應，並在必要時將部分回應緩衝到暫存檔案。預設情況下`*размер*`緩衝區數量限制為兩個，分別由 `[scgi\_buffer\_size](#scgi_buffer_size)和 `[scgi\_buffers](#scgi_buffers)指令指定。

Если параметр установлен в значение “`off`”, то временные файлы будут располагаться непосредственно в каталоге кэша.

快取的回應首先寫入一個臨時文件，然後對其進行重新命名。從版本0.8.9臨時檔案和快取可以位於不同的檔案系統上。但是要注意的是，在這種情況下，檔案不是在一個檔案系統內進行簡單的重新命名操作，而是從一個檔案系統複製到另一個檔案系統。因此，最好將快取與包含暫存檔案的目錄放在同一個檔案系統上。暫存檔案所在的目錄由`use_temp_path` （ 1.7.10 ）參數決定。如果未指定此參數或將其設為“ `on` ”，則將使用[scgi\_temp\_path](#scgi_temp_path)指令為給定位置指定的目錄。如果將此參數設為“ `off` ”，則暫存檔案將直接位於快取目錄中。

Например зоны размером в 1 мегабайт достаточно для хранения около 4 тысяч ключей.

如果快取資料在`inactive`指定的時間內未被訪問，則無論其新鮮度如何，資料都將被刪除。預設情況下， `inactive`為 10 分鐘。

Специальный процесс “cache manager” следит за максимальным размером кэша, заданным параметром `max_size`, а также за минимальным объёмом свободного места на файловой системе с кэшем, заданным параметром `min_free` (1.19.1). При превышении максимального размера кэша или недостаточном объёме свободного места процесс удаляет наименее востребованные данные. Удаление данных происходит итерациями, настраиваемыми параметрами (1.11.5) `manager_files`, `manager_threshold` и `manager_sleep`. За одну итерацию загружается не более `manager_files` элементов (по умолчанию 100). Время работы одной итерации ограничено параметром `manager_threshold` (по умолчанию 200 миллисекунд). Между итерациями делается пауза на время, заданное параметром `manager_sleep` (по умолчанию 50 миллисекунд).

一個特殊的「快取管理器」程序會監控由參數`max_size`指定的最大快取大小，以及由參數`min_free` （ 1.19.1 ）指定的檔案系統上包含快取的最小可用空間。如果超過最大快取大小或可用空間不足，則該程序會刪除使用頻率最低的資料。資料刪除操作會依照參數（ 1.11.5 ）、 `manager_files`, `manager_threshold`和`manager_sleep`配置的迭代次數進行。每次迭代最多載入`manager_files`個元素（預設為100個）。單次迭代的持續時間由參數`manager_threshold`限制（預設為200毫秒）。在兩次迭代之間，會暫停一段時間，該時間由參數`manager_sleep`指定（預設為50毫秒）。

Через минуту после старта активируется специальный процесс “cache loader”, который загружает в зону кэша информацию о ранее закэшированных данных, хранящихся на файловой системе. Загрузка также происходит итерациями. За одну итерацию загружается не более `loader_files` элементов (по умолчанию 100). Кроме того, время работы одной итерации ограничено параметром `loader_threshold` (по умолчанию 200 миллисекунд). Между итерациями делается пауза на время, заданное параметром `loader_sleep` (по умолчанию 50 миллисекунд).

啟動一分鐘後，一個名為「快取載入器」的特殊進程會被激活，將檔案系統中先前快取的資料資訊載入到快取區域。載入過程以迭代方式進行，每次迭代最多載入`loader_files`個元素（預設值為100）。此外，單次迭代的運行時間受`loader_threshold`參數的限制（預設值為200毫秒）。迭代之間會暫停一段時間，該時間由`loader_sleep`參數指定（預設值為50毫秒）。

Определяет, в каких случаях запрос будет передан следующему серверу:

`error`

произошла ошибка соединения с сервером, передачи ему запроса или чтения заголовка ответа сервера;

連接伺服器、向伺服器發送請求或讀取伺服器回應頭時發生錯誤；

`timeout`

произошёл таймаут во время соединения с сервером, передачи ему запроса или чтения заголовка ответа сервера;

連接伺服器、向伺服器發送請求或讀取伺服器回應頭時發生逾時；

`denied`

сервер [отклонил](#proxy_allow_upstream) соединение (1.29.3);

`http_503`

сервер вернул ответ с кодом 503;

обычно запросы с [неидемпотентным](https://datatracker.ietf.org/doc/html/rfc7231#section-4.2.2) методом (`POST`, `LOCK`, `PATCH`) не передаются на другой сервер, если запрос серверу группы уже был отправлен (1.9.13); включение параметра явно разрешает повторять подобные запросы;

Необходимо понимать, что передача запроса следующему серверу возможна только при условии, что клиенту ещё ничего не передавалось. То есть, если ошибка или таймаут возникли в середине передачи ответа, то исправить это уже невозможно.

需要注意的是，只有在尚未向客戶端發送任何資料的情況下，才能將請求轉發到下一個伺服器。這意味著，如果在發送回應的過程中發生錯誤或逾時，則無法修復。

Случаи `http_500`, `http_503` и `http_429` считаются неудачными попытками, только если они указаны в директиве. Случаи `http_403` и `http_404` никогда не считаются неудачными попытками.

Разрешает сохранение на диск файлов. Параметр `on` сохраняет файлы в соответствии с путями, указанными в директивах [alias](<221 [02.01.01 http] 模組 ngx_http_core_module.md#alias>) или [root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>). Параметр `off` запрещает сохранение файлов. Кроме того, имя файла можно задать явно с помощью строки с переменными:

啟用檔案儲存到磁碟功能。參數`on`依據 [alias](<221 [02.01.01 http] 模組 ngx_http_core_module.md#alias>)或 [root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>)指令中指定的路徑儲存檔案。參數`off`禁用檔案保存。此外，也可以使用變數字串明確指定檔案名稱：

> ```
> scgi_store /data/www$original_uri;
> ```

Время изменения файлов выставляется согласно полученному полю “Last-Modified”（最後修改日期） в заголовке ответа. Ответ сначала записывается во временный файл, а потом этот файл переименовывается. Начиная с версии 0.8.9 временный файл и постоянное место хранения ответа могут располагаться на разных файловых системах. Однако нужно учитывать, что в этом случае вместо дешёвой операции переименовывания в пределах одной файловой системы файл копируется с одной файловой системы на другую. Поэтому лучше, если сохраняемые файлы будут находиться на той же файловой системе, что и каталог с временными файлами, задаваемый директивой [scgi\_temp\_path](#scgi_temp_path) для данного location.

文件修改時間根據回應頭中接收到的“Last-Modified”（最後修改日期）字段設定。回應首先寫入臨時文件，然後重新命名該文件。從版本0.8.9開始，回應的暫存檔案和永久儲存位置可以位於不同的檔案系統上。但是需要注意的是，在這種情況下，檔案不是在同一個檔案系統內進行簡單的重新命名操作，而是從一個檔案系統複製到另一個檔案系統。因此，最好將已儲存的檔案與 [scgi\_temp\_path](#scgi_temp_path)指令指定的暫存檔案目錄位於相同檔案系統上。
