The `ngx_http_limit_req_module` module (0.7.21) is used to limit the request processing rate per a defined key, in particular, the processing rate of requests coming from a single IP address. The limitation is done using the “leaky bucket” method.

`ngx_http_limit_req_module`模組（ 0.7.21 ）用於限制每個已定義鍵的請求處理速率，特別是來自單一IP位址的請求處理速率。此限制採用「漏桶」方法實作。

#### Example Configuration｜範例配置

> ```
> http {
>     limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
> 
>     ...
> 
>     server {
>
>     伺服器 {
> 
>         ...
> 
>         location /search/ {
>             limit_req zone=one burst=5;
>         }
> ```

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>语法： | ``**limit_req** `zone`=`*name*` [`burst`=`*number*`] [`nodelay` \| `delay`=`*number*`];``<br>``**limit_req** `区域`=`*名称*` [`突发`=`*数量*`] [`nodelay` \| `延迟`=`*数量*`];`` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

Sets the shared memory zone and the maximum burst size of requests. If the requests rate exceeds the rate configured for a zone, their processing is delayed such that requests are processed at a defined rate. Excessive requests are delayed until their number exceeds the maximum burst size in which case the request is terminated with an [error](#limit_req_status). By default, the maximum burst size is equal to zero. For example, the directives

設定共享記憶體區域和請求的最大突發大小。如果請求速率超過為某個區域配置的速率，則請求處理將被延遲，以確保請求以定義的速率處理。過多的請求將被延遲，直到其數量超過最大突發大小，此時請求將被終止並傳回錯誤訊息 [error](#limit_req_status) 。預設情況下，最大突發大小為零。例如，指令

> ```
> limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
> 
> server {
>
> 伺服器 {
>     location /search/ {
>         limit_req zone=one burst=5;
>     }
> ```

allow not more than 1 request per second at an average, with bursts not exceeding 5 requests.

平均每秒請求數不超過 1 個，突發請求數不超過 5 個。

If delaying of excessive requests while requests are being limited is not desired, the parameter `nodelay` should be used:

如果不希望在限制請求的同時延遲過多的請求，則應使用參數`nodelay` ：

> ```
> limit_req zone=one burst=5 nodelay;
> ```

The `delay` parameter (1.15.7) specifies a limit at which excessive requests become delayed. Default value is zero, i.e. all excessive requests are delayed.

`delay`參數（ 1.15.7 ）指定了請求過多時會被延遲處理的閾值。預設值為零，即所有過多的請求都會被延遲處理。

There could be several `limit_req` directives. For example, the following configuration will limit the processing rate of requests coming from a single IP address and, at the same time, the request processing rate by the virtual server:

可能存在多個`limit_req`指令。例如，以下配置將限制來自單一IP位址的請求的處理速率，同時限制虛擬伺服器的請求處理速率：

> ```
> limit_req_zone $binary_remote_addr zone=perip:10m rate=1r/s;
> limit_req_zone $server_name zone=perserver:10m rate=10r/s;
> 
> server {
>
> 伺服器 {
>     ...
>     limit_req zone=perip burst=5 nodelay;
>     limit_req zone=perserver burst=10;
> }
> ```

These directives are inherited from the previous configuration level if and only if there are no `limit_req` directives defined on the current level.

如果目前等級沒有定義`limit_req`指令，則這些指令將從上一個設定等級繼承。

啟用試運轉模式。在此模式下，請求處理速率不受限制，但共享記憶體區域中的超額請求數量仍會像往常一樣進行統計。

該指令出現在版本0.8.18 。

Sets the desired logging level for cases when the server refuses to process requests due to rate exceeding, or delays request processing. Logging level for delays is one point less than for refusals; for example, if “`limit_req_log_level notice`” is specified, delays are logged with the `info` level.

設定伺服器因請求速率過高而拒絕處理請求或延遲處理請求時所需的日誌等級。延遲處理的日誌等級比拒絕處理的日誌等級低一級；例如，如果指定“ `limit_req_log_level notice` ”，則延遲處理的日誌等級為`info` 。

| Syntax:<br>语法： | ``**limit_req_zone** `*key*` `zone`=`*name*`:`*size*` `rate`=`*rate*` [`sync`];``<br>``**limit_req_zone** `*键*` `区域`=`*名称*`:`*大小*` `速率`=`*速率*` [`同步`];`` |

Sets parameters for a shared memory zone that will keep states for various keys. In particular, the state stores the current number of excessive requests. The `*key*` can contain text, variables, and their combination. Requests with an empty key value are not accounted.

设置共享内存区域的参数，该区域将保留各个键的状态。特别是，状态存储当前过量请求的数量。 `*key*` 可以包含文字、變數及其組合。不考慮具有空鍵值的請求。

> Prior to version 1.7.6, a `*key*` could contain exactly one variable.
>
> 在版本1.7.6之前， `*key*`只能包含一個變數。

Usage example:

使用範例：

> ```
> limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
> ```

Here, the states are kept in a 10 megabyte zone “one”, and an average request processing rate for this zone cannot exceed 1 request per second.

在這裡，狀態保存在 10 兆位元組的區域「一」中，該區域的平均請求處理速率不能超過每秒 1 個請求。

A client IP address serves as a key. Note that instead of `$remote_addr`, the `$binary_remote_addr` variable is used here. The `$binary_remote_addr` variable’s size is always 4 bytes for IPv4 addresses or 16 bytes for IPv6 addresses. The stored state always occupies 64 bytes on 32-bit platforms and 128 bytes on 64-bit platforms. One megabyte zone can keep about 16 thousand 64-byte states or about 8 thousand 128-byte states.

客戶端位址IP用作金鑰。請注意，此處使用的是`$binary_remote_addr`變量，而非`$remote_addr`變數的大小對於`$binary_remote_addr`位址始終為4字節，對於IPv6位址始終為16位元組。儲存的狀態在32位元平台上始終佔用64字節，在64位元平台上始終佔用128位元組。一個兆位元組的區域大約可以儲存16000個64位元組的狀態，或大約8000個128位元組的狀態。

If the zone storage is exhausted, the least recently used state is removed. If even after that a new state cannot be created, the request is terminated with an [error](#limit_req_status).

如果區域儲存空間耗盡，則會刪除最近最少使用的狀態。如果即使這樣也無法建立新狀態，則請求將以 [error](#limit_req_status)終止。

The rate is specified in requests per second (r/s). If a rate of less than one request per second is desired, it is specified in request per minute (r/m). For example, half-request per second is 30r/m.

速率以每秒請求數 (r/s) 為單位指定。如果需要的速率低於每秒一次請求，則以每分鐘請求數 (r/m) 為單位指定。例如，每秒半次請求的速率為 30r/m。

Additionally, the following functionality is available as part of our [commercial subscription](https://www.f5.com/products/nginx):

此外，以下功能包含在我們的[商業訂閱](https://www.f5.com/products/nginx)中：

-   The `rate` parameter can contain variables (1.31.3). The rate is evaluated at runtime for each request. Example:  
    `rate`參數可以包含變數 ( 1.31.3 )。速率在運行時針對每個請求進行評估。例如：
    
    > ```
    > map $uri $rate {
    >
    > 映射 $uri $rate {
    >     default       10r/s;
    >
    >     預設值 10 轉/秒；
    >     /api/slow     1r/s;
    >
    >     /api/slow 1r/s;
    >     /api/fast     100r/s;
    >
    >     /api/fast 100r/s;
    > }
    > 
    > limit_req_zone $binary_remote_addr zone=one:10m rate=$rate;
    > ```
    
-   The `sync` parameter (1.15.3) enables [synchronization](<164 [01.01.06 溪流] 模組 ngx_stream_zone_sync_module.md#zone_sync>) of the shared memory zone.  
    `sync`參數 ( 1.15.3 ) 啟用共享記憶體區域的 [同步](<164 [01.01.06 溪流] 模組 ngx_stream_zone_sync_module.md#zone_sync>) 。
    
-   The [status information](<048 [01.01.03 http] 模組 ngx_http_api_module.md#http_limit_reqs_>) for each such shared memory zone can be [obtained](<048 [01.01.03 http] 模組 ngx_http_api_module.md#getHttpLimitReqZone>) or [reset](<048 [01.01.03 http] 模組 ngx_http_api_module.md#deleteHttpLimitReqZoneStat>) with the [API](<048 [01.01.03 http] 模組 ngx_http_api_module.md>) since 1.17.7.  
    對於1.17.7這樣的共享記憶體區域(https://nginx.org/en/docs/http/ngx_http_api_module.html)可以透過 [API](<048 [01.01.03 http] 模組 ngx_http_api_module.md#http_limit_reqs_>)來 [獲取](<048 [01.01.03 http] 模組 ngx_http_api_module.md#getHttpLimitReqZone>)或 [重設](<048 [01.01.03 http] 模組 ngx_http_api_module.md#deleteHttpLimitReqZoneStat>) 。

保留限制請求處理速率的結果（ 1.17.6 ）： `PASSED`, `DELAYED`, `REJECTED`, `DELAYED_DRY_RUN`或`REJECTED_DRY_RUN`
