Имена сервера задаются с помощью директивы [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>) и определяют, в каком блоке [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>) будет обрабатываться тот или иной запрос. См. также “[Как nginx обрабатывает запросы](<272 [02.01.01 http] nginx 如何處理請求.md>)”. Имена могут быть заданы точно, с помощью маски или регулярного выражения:

伺服器名稱使用 `[server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>)指令指定，並決定哪個 `[server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>)程式碼區塊將處理特定請求。另請參閱「[nginx 如何處理請求](<272 [02.01.01 http] nginx 如何處理請求.md>) 」。名稱可以明確指定，也可以使用遮罩或正規表示式指定：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.org  www.example.org;
>
>     伺服器名稱 example.org www.example.org;
>     ...
> }
> 
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  *.example.org;
>
>     伺服器名稱 *.example.org;
>     ...
> }
> 
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  mail.*;
>
>     伺服器名稱 mail.*;
>     ...
> }
> 
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  ~^(?<user>.+)\.example\.net$;
>
>     server_name ~^(? <user> .+)\.example\.net$;
>     ...
> }
> ```

Поиск производится в следующем порядке приоритета и прекращается на первом подходящем варианте:

搜尋按以下優先順序執行，並在找到第一個合適的選項時終止：

1.  точное имя  
    確切姓名
2.  самое длинное имя с маской в начале, например “`*.example.org`”  
    以遮罩開頭的最長名稱，例如“ `*.example.org` ”
3.  самое длинное имя с маской в конце, например “`mail.*`”  
    最長的名稱，末尾帶有掩碼，例如“ `mail.*` ”
4.  первое подходящее регулярное выражение (в порядке следования в конфигурационном файле)  
    第一個符合的正規表示式（按其在設定檔中出現的順序）

#### Имена с масками｜帶面具的名字

Имя с маской может содержать звёздочку (“`*`”) только в начале или в конце имени, и только на границе, определяемой точкой. Имена “`www.*.example.org`” и “`w*.example.org`” являются некорректными, но их можно задать с помощью регулярных выражений, например, “`~^www\..+\.example\.org$`” и “`~^w.*\.example\.org$`”. Звёздочка может соответствовать нескольким частям имени. Имени с маской “`*.example.org`” соответствует не только `www.example.org`, но и `www.sub.example.org`.

通配符名稱只能在名稱的開頭或結尾包含星號（“ `*` ”），且星號必須位於以點號分隔的邊界上。名稱「 `www.*.example.org` 」和「 `w*.example.org` 」無效，但可以使用正規表示式指定，例如「 `~^www\..+\.example\.org$` 」和「 `~^w.*\.example\.org$` 」。一個星號可以匹配名稱的多個部分。通配符名稱「 `*.example.org` 」不僅符合`www.example.org` ，還符合`www.sub.example.org` 。

Специальное имя с маской вида “`.example.org`” соответствует как точному имени “`example.org`”, так и маске “`*.example.org`”.

特殊名稱，其掩碼形式為“ `.example.org` ”，既匹配確切名稱“ `example.org` ”，也匹配掩碼“ `*.example.org` ”。

#### Имена, заданные регулярными выражениями｜透過正規表示式指定的名稱

Регулярные выражения, используемые в nginx, совместимы с используемыми в языке программирования Perl (PCRE). Имя сервера, заданное регулярным выражением, должно начинаться с символа тильды:

nginx 中使用的正規表示式與 Perl 程式語言中使用的正規表示式相容 ( PCRE )。正規表示式指定的伺服器名稱必須以波浪號 (~) 開頭：

> ```
> server_name  ~^www\d+\.example\.net$;
>
> server_name ~^www\d+\.example\.net$;
> ```

в противном случае оно будет рассматриваться как точное, или же, если выражение содержит звёздочку (“`*`”), то как имя с маской (и, скорее всего, некорректное). Не забывайте ставить специальные символы начала (“`^`”) и конца (“`$`”) строки. По синтаксису они не требуются, но логически они могут быть нужны. Также заметьте, что все точки в доменных именах должны быть экранированы символом обратной косой черты. Регулярное выражение, содержащее символы “`{`” и “`}`”, необходимо экранировать:

否則，它將被視為精確匹配；如果表達式包含星號（“ `*` ”），則會被視為通配符名稱（很可能無效）。請務必在字串開頭（“ `^` ”）和結尾（“ `$` ”）添加特殊字元。語法上並非必須，但邏輯上可能需要。另請注意，網域中的所有句點都必須使用反斜線進行轉義。包含字元「 `{` 」和「 `}` 」的正規表示式必須進行轉義。

> ```
> server_name  "~^(?<name>\w\d{1,3}+)\.example\.net$";
>
> server_name "~^(? <name> \w\d{1,3}+)\.example\.net$";
> ```

иначе nginx откажется запускаться и выдаст сообщение об ошибке:

否則，nginx 將拒絕啟動並顯示錯誤訊息：

> ```
> directive "server_name" is not terminated by ";" in ...
>
> 指令“server_name”未以“;”結尾…
> ```

К именованному выделению в регулярном выражении можно впоследствии обратиться через переменную:

正規表示式中指定的命名選擇項之後可以透過變數存取：

> ```
> server {
>
> 伺服器{
>     server_name   ~^(www\.)?(?<domain>.+)$;
>
>     server_name ~^(www\.)?(? <domain> .+)$;
> 
>     location / {
>
>     地點/{
>         root   /sites/$domain;
>
>         根 /sites/$domain;
>     }
> }
> ```

Также можно использовать позиционные выделения:

您也可以使用位置選擇：

> ```
> server {
>
> 伺服器{
>     server_name   ~^(www\.)?(.+)$;
>
>     server_name ~^(www\.)?(.+)$;
> 
>     location / {
>
>     地點/{
>         root   /sites/$2;
>
>         根 /sites/$2;
>     }
> }
> ```

Однако такое использование должно ограничиваться простыми случаями как в примере выше, поскольку позиционные выделения легко перезаписываются другими регулярными выражениями. Синтаксис именованных выделений и подробности о том, как долго доступны выделенные значения, описаны в “[Выделения в регулярных выражениях](https://nginx.org/ru/docs/regex_captures.html)”.

然而，這種用法應僅限於上述範例等簡單情況，因為位置捕獲很容易被其他正規表示式覆蓋。命名捕獲的語法以及捕獲值的有效期限的詳細信息，請參見“正則表達式中的捕獲” (https://nginx.org/ru/docs/regex_captures.html) 。

#### Прочие имена｜其他名稱

Некоторые имена имеют специальное значение.

有些名字有特殊的意義。

Если необходимо обрабатывать запросы без поля “Host”（主持人） в заголовке в блоке [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>), который не является сервером по умолчанию, следует указать пустое имя:

如果要在 [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>)區塊中處理不包含“Host”（主持人）標頭欄位（且該請求不是預設伺服器）的請求，則應指定空名稱：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.org  www.example.org  "";
>
>     server_name example.org www.example.org "";
>     ...
> }
> ```

Если директива [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>) не задана в блоке [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>), то nginx будет использовать пустое имя в качестве имени сервера.

如果 [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>)區塊中未指定 [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>)指令，nginx 將使用空名稱作為伺服器名稱。

> Версии nginx вплоть до 0.8.48 в этом случае использовали имя хоста (hostname) машины в качестве имени сервера.
>
> 在這種情況下，Nginx 版本0.8.48使用機器的主機名稱作為伺服器名稱。

Если имя сервера задано как “`$hostname`” (0.9.4), то используется имя хоста (hostname) машины.

如果伺服器名稱指定為「 `$hostname` 」（ 0.9.4 ），則使用機器的主機名稱。

Если в запросе вместо имени сервера указан IP-адрес, то поле “Host”（主持人） заголовка запроса будет содержать IP-адрес, и запрос можно обработать, используя IP-адрес как имя сервера:

如果請求指定了IP位址而不是伺服器名稱，則“Host”（主持人）請求頭字段將包含IP位址，並且可以使用IP位址作為伺服器名稱來處理請求：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.org
>
>     伺服器名稱 example.org
>                  www.example.org
>                  ""
>                  192.168.1.1
>                  ;
>     ...
> }
> ```

В примерах конфигурации серверов, обрабатывающих все запросы, встречается странное имя “`_`”:

在處理所有請求的伺服器設定範例中，出現了奇怪的名稱「 `_` 」：

> ```
> server {
>
> 伺服器{
>     listen       80  default_server;
>
>     監聽 80 埠預設伺服器；
>     server_name  _;
>
>     伺服器名稱_;
>     return       444;
>
>     返回 444；
> }
> ```

Оно не является каким-то особенным, это просто одно из множества некорректных доменных имён, которые никогда не пересекутся ни с одним из реальных имён. С тем же успехом можно использовать имена типа “`--`” и “`!@#`”.

這沒什麼特別的；它只是眾多無效域名之一，永遠不會與任何真實名稱相交。你完全可以使用類似「 `--` 」和「 `!@#` 」這樣的名稱。

Версии nginx вплоть до 0.6.25 поддерживали специальное имя “`*`”, которое многими неверно воспринималось как имя сервера для обработки всех запросов. Оно никогда так не работало, и не работало как имя с маской. Это имя действовало так же, как сейчас действует директива [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>). Специальное имя “`*`” объявлено устаревшим, а вместо него следует использовать директиву [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>). Заметьте, что с помощью директивы [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>) нельзя задать ни имя сервера для обработки всех запросов, ни сервер по умолчанию. Это является свойством директивы [listen](<221 [02.01.01 http] 模組 ngx_http_core_module.md#listen>), а не [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>). См. также “[Как nginx обрабатывает запросы](<272 [02.01.01 http] nginx 如何處理請求.md>)”. Можно настроить серверы, слушающие на портах \*:80 и \*:8080, и указать, что один из них будет сервером по умолчанию для порта \*:8080, а другой — для порта \*:80:

0.6.25之前的 Nginx 版本支援特殊名稱“ `*` ”，該名稱經常被誤解為處理所有請求的伺服器名稱。它實際上並非如此工作，也不能作為通配符名稱使用。該名稱現在的作用與 [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>)指令相同。特殊名稱「 `*` 」已被棄用，應改用 [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>)指令。請注意，[server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>)指令不能用於設定處理所有請求的伺服器名稱或預設伺服器。這是 [listen](<221 [02.01.01 http] 模組 ngx_http_core_module.md#listen>)指令的屬性，而不是 [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>)指令的屬性。另請參閱「[nginx 如何處理請求](<272 [02.01.01 http] nginx 如何處理請求.md>) 」。您可以設定監聽連接埠 *:80 和 *:8080 的伺服器，並指定其中一個伺服器為連接埠 *:8080 的預設伺服器，另一個伺服器作為連接埠 *:80 的預設伺服器：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     listen       8080  default_server;
>
>     監聽 8080 預設伺服器；
>     server_name  example.net;
>
>     伺服器名稱 example.net；
>     ...
> }
> 
> server {
>
> 伺服器{
>     listen       80  default_server;
>
>     監聽 80 埠預設伺服器；
>     listen       8080;
>
>     聽 8080；
>     server_name  example.org;
>
>     伺服器名稱 example.org；
>     ...
> }
> ```

#### Интернационализованные имена｜國際化名稱

Для указания интернационализированных доменных имён ([IDNs](https://en.wikipedia.org/wiki/Internationalized_domain_name)) в директиве [server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>) следует указывать Punycode-представление имени:

若要指定國際域名（[IDN](https://en.wikipedia.org/wiki/Internationalized_domain_name) ），[server\_name](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name>)指令應指定名稱的 Punycode 表示形式：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  xn--e1afmkfd.xn--80akhbyknj4f;  # пример.испытание
>
>     server_name xn--e1afmkfd.xn--80akhbyknj4f; # example.test
>     ...
> }
> ```

#### Выбор виртуального сервера｜選擇虛擬伺服器

Сначала соединение создаётся в контесте сервера по умолчанию. Затем имя сервера может быть определено на следующих стадиях обработки запроса, каждая из которых участвует в выборе конфигурации:

首先，在預設伺服器上下文中建立連線。然後，可以在請求處理的後續階段確定伺服器名稱，每個階段都涉及設定選擇：

-   предварительно во время операции SSL handshake согласно [SNI](<212 [02.01.01 http] 設定HTTPS伺服器.md#sni>)  
    術前SSL握手，根據 [SNI](<212 [02.01.01 http] 設定HTTPS伺服器.md#sni>)
    
-   после обработки строки запроса  
    處理查詢字串之後
    
-   после обработки поля `Host` заголовка запроса  
    處理完`Host`請求頭字段後
    
-   если после обработки строки запроса или поля `Host` заголовка запроса имя сервера не было выбрано, то nginx будет использовать пустое имя в качестве имени сервера.  
    如果在處理查詢字串或`Host`請求頭字段後仍未選擇伺服器名稱，nginx 將使用空名稱作為伺服器名稱。
    

На каждой из этих стадий могут применяться различные конфигурации сервера. Таким образом, некоторые директивы следует указывать с осторожностью:

在這些階段中，可能需要採用不同的伺服器配置。因此，某些指令應謹慎指定：

-   в случае использования директивы [ssl\_protocols](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_protocols>) список протоколов может применяться из конфигурации виртуального сервера, только если это поддерживается нижележащей библиотекой (OpenSSL 1.1.1 и выше, BoringSSL, AWS-LC). При использовании прочих библиотек список протоколов задаётся перед применением конфигурации сервера согласно SNI, таким образом, протоколы должны быть заданы только для сервера по умолчанию;  
    使用 [ssl\_protocols 指令](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_protocols>)協定清單只能在底層函式庫（OpenSSL 1.1.1及更高版本、BoringSSL AWS-LC ）支援的情況下，才能從虛擬伺服器設定中套用。使用其他程式庫時，協定清單需要在應用程式伺服器配置之前根據SNI指定，因此協定只需為預設伺服器指定即可；
-   в случае использования директив [ssl\_session\_cache](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_session_cache>), [ssl\_session\_tickets](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_session_tickets>), [ssl\_session\_timeout](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_session_timeout>) и, следовательно, [ssl\_early\_data](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_early_data>) восстановление сессии всегда производится из контекста сервера по умолчанию, таким образом, директивы должны быть заданы только для сервера по умолчанию;

-   директивы [client\_header\_buffer\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_header_buffer_size>) и [merge\_slashes](<221 [02.01.01 http] 模組 ngx_http_core_module.md#merge_slashes>) задействуются перед чтением строки запроса, таким образом они используют конфигурацию сервера по умолчанию или конфигурацию сервера, выбранного через SNI;  
    [client\_header\_buffer\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_header_buffer_size>)和 [merge\_slashes](<221 [02.01.01 http] 模組 ngx_http_core_module.md#merge_slashes>)指令在讀取查詢字串之前調用，因此它們使用預設伺服器配置或透過SNI選擇的伺服器配置；
-   в случае использования директив [ignore\_invalid\_headers](<221 [02.01.01 http] 模組 ngx_http_core_module.md#ignore_invalid_headers>), [large\_client\_header\_buffers](<221 [02.01.01 http] 模組 ngx_http_core_module.md#large_client_header_buffers>) и [underscores\_in\_headers](<221 [02.01.01 http] 模組 ngx_http_core_module.md#underscores_in_headers>), которые участвуют в обработке полей заголовка запроса, выбор сервера дополнительно зависит от того, была ли обновлена конфигурация сервера согласно строке запроса или полю заголовка `Host`;

    錯誤回應將使用目前執行請求的伺服器中的 [error\_page](<221 [02.01.01 http] 模組 ngx_http_core_module.md#error_page>)指令進行處理。

#### Оптимизация｜最佳化

Точные имена, имена с масками, начинающиеся со звёздочки, и имена с масками, заканчивающиеся на звёздочку, хранятся в трёх хэш-таблицах, привязанных к слушающим портам. Размеры хэш-таблиц оптимизируются на фазе конфигурации таким образом, что имя может быть найдено с минимальным числом непопаданий в кэш процессора. Подробнее настройка хэш-таблиц обсуждается в отдельном [документе](<211 [02.01 文件] 設定哈希.md>).

精確名稱、以星號開頭的遮罩名稱和以星號結尾的遮罩名稱分別儲存在綁定到監聽埠的三個雜湊表中。哈希表的大小在配置階段進行最佳化，以便以最少的處理器快取未命中次數找到名稱。哈希表配置的更多詳細資訊請參閱單獨的[文件](<211 [02.01 文件] 設定哈希.md>) 。

В первую очередь имя ищется в хэш-таблице точных имён. Если имя не было найдено, то имя ищется в хэш-таблице имён с масками, начинающихся со звёздочки. Если и там поиск не дал результата, то имя ищется в хэш-таблице имён с масками, оканчивающихся на звёздочку.

首先，在包含精確名稱的雜湊表中尋找該名稱。如果找不到，則在包含以星號開頭的通配符名稱的雜湊表中尋找該名稱。如果仍然找不到，則在包含以星號結尾的通配符名稱的雜湊表中尋找該名稱。

Поиск в хэш-таблице имён с масками медленнее, чем поиск в хэш-таблице точных имён, поскольку имена сравниваются по доменным частям. Заметьте, что специальное имя с маской вида “`.example.org`” хранится в хэш-таблице имён с масками, а не в хэш-таблице точных имён.

在通配符名稱雜湊表中搜尋比在精確名稱雜湊表中搜尋要慢，因為名稱是按其網域部分進行比較的。請注意，像「 `.example.org` 」這樣的帶有通配符的特殊名稱儲存在通配符名稱哈希表中，而不是精確名稱哈希表中。

Регулярные выражения проверяются последовательно, а значит являются самым медленным и плохо масштабируемым методом.

正規表示式是按順序檢查的，這意味著它們是最慢、可擴展性最差的方法。

По вышеизложенным причинам предпочтительнее использовать точные имена, где это только возможно. Например, если к серверу наиболее часто обращаются по именам `example.org` и `www.example.org`, то эффективнее будет указать их явно:

鑑於上述原因，最好盡可能使用顯式名稱。例如，如果伺服器最常被名稱`example.org`和`www.example.org`訪問，那麼明確指定這些名稱會更有效率：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  example.org  www.example.org  *.example.org;
>
>     server_name example.org www.example.org *.example.org;
>     ...
> }
> ```

нежели чем использовать упрощённую форму:

而不是使用簡化形式：

> ```
> server {
>
> 伺服器{
>     listen       80;
>
>     聽 80；
>     server_name  .example.org;
>
>     server_name.example.org;
>     ...
> }
> ```

Если задано большое число имён серверов, либо заданы необычно длинные имена, возможно потребуется скорректировать значения директив [server\_names\_hash\_max\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>) и [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>) на уровне *http*. Значение по умолчанию директивы [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>) может быть равно 32, 64, либо другой величине, в зависимости от размера строки кэша процессора. Если значение по умолчанию равно 32 и имя сервера задано как “`too.long.server.name.example.org`”, то nginx откажется запускаться и выдаст сообщение об ошибке:

如果指定了大量伺服器名稱，或指定了異常長的伺服器名稱，則可能需要在 *http* 層級調整 [server\_names\_hash\_max\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>)和 [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>)指令的值。 [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>)指令的預設值可以是 32、64 或其他值，取決於處理器快取行的大小。如果預設值為 32，且伺服器名稱指定為“ `too.long.server.name.example.org` ”，則 nginx 將拒絕啟動並傳回錯誤訊息：

> ```
> could not build the server_names_hash,
>
> 無法建置 server_names_hash，
> you should increase server_names_hash_bucket_size: 32
>
> 您應該將 server_names_hash_bucket_size 的值增加到 32。
> ```

В этом случае следует увеличить значение директивы до следующей степени двойки:

在這種情況下，該指令的值應增加到以下 2 的冪次方：

> ```
> http {
>
> http{
>     server_names_hash_bucket_size  64;
>
>     server_names_hash_bucket_size 64;
>     ...
> ```

Если задано большое число имён серверов, то будет выдано другое сообщение об ошибке:

如果指定了大量伺服器名稱，則會傳回不同的錯誤訊息：

> ```
> could not build the server_names_hash,
>
> 無法建置 server_names_hash，
> you should increase either server_names_hash_max_size: 512
>
> 您應該增加 server_names_hash_max_size: 512
> or server_names_hash_bucket_size: 32
>
> 或 server_names_hash_bucket_size: 32
> ```

В таком случае сначала следует попробовать установить [server\_names\_hash\_max\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>) в величину, близкую к числу имён серверов, и только если это не поможет или время запуска nginx станет неприемлемо большим, следует попытаться увеличить [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>).

在這種情況下，您應該先嘗試設定 [server\_names\_hash\_max\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>) 將其值調整到接近伺服器名稱數量的值，只有當這沒有幫助或 nginx 啟動時間變得無法接受時，才應該嘗試增加 [server\_names\_hash\_bucket\_size]。(https://nginx.org/ru/docs/http/ngx_http_core_module.html#server_names_hash_bucket_size).

Если сервер является единственным сервером для слушающего порта, то nginx не будет проверять имена сервера вообще (а также не будет строить хэш-таблицы для слушающего порта). За одним исключением: если имя сервера задано регулярным выражением с выделениями, то nginx’у придётся выполнить это выражение, чтобы получить значения выделений.

如果某個伺服器是監聽連接埠的唯一伺服器，nginx 將完全不檢查伺服器名稱（也不會為該監聽連接埠建立雜湊表）。但有一種例外：如果伺服器名稱是透過帶有捕獲值的正規表示式指定的，那麼 nginx 必須計算該表達式才能取得捕獲值。

#### Совместимость｜相容性

-   Специальное имя сервера “`$hostname`” поддерживается начиная с версии 0.9.4.  
    自版本0.9.4起，支援特殊伺服器名稱「 `$hostname` 」。
-   Имя сервера по умолчанию является пустой строкой “” начиная с версии 0.8.48.  
    自版本0.8.48起，預設伺服器名稱為空字串「」。
-   Именованные выделения в именах серверов, заданных с помощью регулярных выражений, поддерживаются начиная с версии 0.8.25.  
    支援使用正規表示式指定的伺服器名稱中的命名捕獲，以0.8.25開頭。
-   Выделения в именах серверов, заданных с помощью регулярных выражений, поддерживаются начиная с версии 0.7.40.  
    從版本0.7.40開始，支援使用正規表示式指定的伺服器名稱進行高亮顯示。
-   Пустое имя сервера “” поддерживается начиная с версии 0.7.12.  
    自版本0.7.12起支援空伺服器名稱「」。
-   В качестве первого имени сервера можно задать маску или регулярное выражение начиная с версии 0.6.25.  
    從版本0.6.25開始，第一個伺服器名稱可以指定為遮罩或正規表示式。
-   Регулярные выражения в имени сервера поддерживаются начиная с версии 0.6.7.  
    從版本0.6.7開始支援伺服器名稱中的正規表示式。
-   Имена с маской вида `example.*` поддерживаются начиная с версии 0.6.0.
