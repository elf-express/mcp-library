## Отладочный лог｜偵錯日誌

|   |
| --- |

Для работы отладочного лога nginx должен быть сконфигурирован с поддержкой отладки на этапе сборки:

要使調試日誌正常運作，必須在建置時為 nginx 配置調試支援：

> ```
> ./configure --with-debug ...
> ```

Затем нужно задать уровень `debug` с помощью директивы [error\_log](<285 [02.01 文件] 基本功能.md#error_log>):

然後，您需要使用 [error\_log](<285 [02.01 文件] 基本功能.md#error_log>)指令設定等級`debug` ：

> ```
> error_log /path/to/log debug;
> ```

Чтобы убедиться, что поддержка отладки сконфигурирована, необходимо выполнить команду `nginx -V`:

為確保已配置調試支持，您需要運行`nginx -V`命令：

> ```
> configure arguments: --with-debug ...
>
> 配置參數：--with-debug ...
> ```

Готовые пакеты для [Linux](<327 [02 ru] 適用於 Linux 的 nginx 軟體包.md>) по умолчанию предоставляют поддержку отладочного лога при помощи бинарного файла `nginx-debug` (1.9.8), который можно запустить при помощи команд

[Linux](<327 [02 ru] 適用於 Linux 的 nginx 軟體包.md>)預編譯軟體包預設提供偵錯日誌支持，透過`nginx-debug` ( 1.9.8 ) 二進位檔案運行，該二進位檔案可以使用以下命令運行。

> ```
> service nginx stop
>
> 停止 nginx 服務
> service nginx-debug start
>
> 啟動 nginx-debug 服務
> ```

и затем задать уровень `debug`. Бинарная версия nginx для Windows всегда собирается с поддержкой отладочного лога, поэтому понадобится лишь задать уровень `debug`.

然後將等級設定為`debug`版 nginx 的二進位版本始終建置時帶有偵錯日誌支持，因此您只需將等級設為`debug` 。

Обратите внимание, что переопределение лога без одновременного указания уровня `debug` отключит отладочный лог. В примере ниже, переопределение лога на уровне [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>) отключает отладочный лог для этого сервера:

請注意，如果在未指定`debug`等級的情況下覆寫日誌，則會停用偵錯日誌記錄。在下面的範例中，覆蓋 [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>)等級的日誌會停用此伺服器的偵錯日誌記錄：

> ```
> error_log /path/to/log debug;
> 
> http {
>     server {
>
>     伺服器 {
>         error_log /path/to/log;
>         ...
> ```

Чтобы избежать этого, следует либо закомментировать строку, переопределяющую лог, либо добавить определение уровня `debug`:

為避免這種情況，您應該註解掉覆蓋日誌的行，或新增一個`debug`等級的定義：

> ```
> error_log /path/to/log debug;
> 
> http {
>     server {
>
>     伺服器 {
>         error_log /path/to/log debug;
>         ...
> ```

#### Отладочный лог для определённых клиентов｜特定客戶端的調試日誌

Можно включить отладочный лог только для [определённых клиентских адресов](<285 [02.01 文件] 基本功能.md#debug_connection>):

您可以僅為[特定客戶端位址啟用偵錯日誌記錄](<285 [02.01 文件] 基本功能.md#debug_connection>) ：

> ```
> error_log /path/to/log;
> 
> events {
>
> 事件 {
>     debug_connection 192.168.1.1;
>
>     debug_connection 192.168.1.1 ;
>     debug_connection 192.168.10.0/24;
>
>     debug_connection 192.168.10.0/24 ;
> }
> ```

#### Запись в кольцевой буфер в памяти｜向記憶體中的循環緩衝區寫入數據

Отладочный лог можно записывать в кольцевой буфер в памяти:

偵錯日誌可以寫入記憶體中的環形緩衝區：

> ```
> error_log memory:32m debug;
>
> 錯誤日誌記憶體：32m 調試；
> ```

Запись в буфер в памяти на уровне `debug` не оказывает существенного влияния на производительность даже при высоких нагрузках. В этом случае лог может быть извлечён при помощи `gdb`\-скрипта, подобного следующему:

即使在高負載下，向`debug`級別的記憶體緩衝區寫入資料也不會顯著影響效能。在這種情況下，可以使用類似於以下`gdb`腳本提取日誌：

> ```
> set $log = ngx_cycle->log
>
> 設定 $log = ngx_cycle->log
> 
> while $log->writer != ngx_log_memory_writer
>     set $log = $log->next
>
>     設定 $log = $log->next
> end
>
> 結尾
> 
> set $buf = (ngx_log_memory_buf_t *) $log->wdata
>
> 設定 $buf = (ngx_log_memory_buf_t *) $log->wdata
> dump binary memory debug_log.txt $buf->start $buf->end
>
> 轉儲二進位記憶體 debug_log.txt $buf->start $buf->end
> ```

Или при помощи такого `lldb`\-скрипта:

或使用這個`lldb` \-script：

> ```
> expr ngx_log_t *$log = ngx_cycle->log
> expr while ($log->writer != ngx_log_memory_writer) { $log = $log->next; }
> expr ngx_log_memory_buf_t *$buf = (ngx_log_memory_buf_t *) $log->wdata
> memory read --force --outfile debug_log.txt --binary $buf->start $buf->end
>
> 記憶體讀取 --force --outfile debug_log.txt --binary $buf->start $buf->end
> ```
