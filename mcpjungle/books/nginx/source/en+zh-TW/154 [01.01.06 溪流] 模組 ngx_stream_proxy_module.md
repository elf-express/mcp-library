The `ngx_stream_proxy_module` module (1.9.0) allows proxying data streams over TCP, UDP (1.9.13), and UNIX-domain sockets.

`ngx_stream_proxy_module`模組 ( 1.9.0 ) 允許透過TCP, UDP ( 1.9.13 ) 和UNIX域套接字代理資料流。

#### Example Configuration｜範例配置

> ```
> server {
>
> 伺服器 {
>     listen 127.0.0.1:12345;
>
>     聽127.0.0.1:12345 ;
>     proxy_pass 127.0.0.1:8080;
>
>     proxy_pass 127.0.0.1:8080 ;
> }
> 
> server {
>
> 伺服器 {
>     listen 12345;
>
>     聽 12345；
>     proxy_connect_timeout 1s;
>     proxy_timeout 1m;
>     proxy_pass example.com:12345;
> }
> 
> server {
>
> 伺服器 {
>     listen 53 udp reuseport;
>
>     監聽 53 UDP 重複使用連接埠；
>     proxy_timeout 20s;
>     proxy_pass dns.example.com:53;
> }
> 
> server {
>
> 伺服器 {
>     listen [::1]:12345;
>
>     監聽 [::1]:12345;
>     proxy_pass unix:/tmp/stream.socket;
> }
> ```

該指令出現在版本1.9.2 。

Makes outgoing connections to a proxied server originate from the specified local IP `*address*`. Parameter value can contain variables (1.11.2). The special value `off` cancels the effect of the `proxy_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address.

使發送至代理伺服器的出站連線源自指定的本機位址IP `*address*` 。參數值可以包含變數 ( 1.11.2 )。特殊值`off`會取消從上一配置等級繼承的`proxy_bind`指令的效果，從而允許系統自動分配本地位址IP 。

The `transparent` parameter (1.11.0) allows outgoing connections to a proxied server originate from a non-local IP address, for example, from a real IP address of a client:

`transparent`參數 ( 1.11.0 ) 允許到代理伺服器的出站連線源自非本地IP位址，例如，源自客戶端的真實IP位址：

> ```
> proxy_bind $remote_addr transparent;
> ```

In order for this parameter to work, it is usually necessary to run nginx worker processes with the [superuser](<125 [01.01 文件] 核心功能.md#user>) privileges. On Linux it is not required (1.13.8) as if the `transparent` parameter is specified, worker processes inherit the `CAP_NET_RAW` capability from the master process. It is also necessary to configure kernel routing table to intercept network traffic from the proxied server.

為了使此參數生效，通常需要以 [superuser](<125 [01.01 文件] 核心功能.md#user>)權限執行 nginx 工作進程。在 Linux 系統上則無需此權限 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程會從主進程繼承`CAP_NET_RAW`權限。此外，還需要配置核心路由表以攔截來自代理伺服器的網路流量。

Limits the speed of reading the data from the proxied server. The `*rate*` is specified in bytes per second. The zero value disables rate limiting. The limit is set per a connection, so if nginx simultaneously opens two connections to the proxied server, the overall rate will be twice as much as the specified limit.

限制從代理伺服器讀取資料的速度。 `*rate*` 以每秒位元組數指定。零值禁用速率限制。此限制是針對每個連接設定的，因此如果 nginx 同時開啟兩個到代理伺服器的連接，則總體速率將是指定限制的兩倍。

Parameter value can contain variables (1.17.0). It may be useful in cases where rate should be limited depending on a certain condition:

參數值可以包含變數（ 1.17.0 ）。在需要根據特定條件限制速率的情況下，這可能很有用：

> ```
> map $slow $rate {
>
> 映射 $slow $rate {
>     1     4k;
>     2     8k;
> }
> 
> proxy_download_rate $rate;
> ```

Sets the address of a proxied server. The address can be specified as a domain name or IP address, and a port:

設定代理伺服器的位址。位址可以指定為網域名稱或IP位址，以及連接埠：

> ```
> proxy_pass localhost:12345;
> ```

or as a UNIX-domain socket path:

或作為UNIX域套接字路徑：

> ```
> proxy_pass unix:/tmp/stream.socket;
> ```

If a domain name resolves to several addresses, all of them will be used in a round-robin fashion. In addition, an address can be specified as a [server group](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md>).

如果一個網域解析到多個位址，則所有這些位址將以輪詢方式使用。此外，可以將位址指定為 [伺服器群組](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md>) 。

The address can also be specified using variables (1.11.3):

也可以使用變數指定位址（ 1.11.3 ）：

> ```
> proxy_pass $upstream;
> ```

In this case, the server name is searched among the described [server groups](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md>), and, if not found, is determined using a [resolver](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>).

在這種情況下，會在所描述的 [伺服器群組](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md>)中搜尋伺服器名稱，如果找不到，則使用 [解析器](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>)進行確定。

Sets the number of client datagrams at which binding between a client and existing UDP stream session is dropped. After receiving the specified number of datagrams, next datagram from the same client starts a new session. The session terminates when all client datagrams are transmitted to a proxied server and the expected number of [responses](#proxy_responses) is received, or when it reaches a [timeout](#proxy_timeout).

設定客戶端資料封包的數量，超過該數量後，客戶端與現有UDP流會話之間的綁定將被斷開。收到指定數量的資料封包後，來自同一客戶端的下一個資料封包將啟動一個新的會話。當所有客戶端資料封包都已傳送至代理伺服器並收到預期數量的[回應](#proxy_responses) ，或達到[逾時](#proxy_timeout)時，會話終止。

Sets the number of datagrams expected from the proxied server in response to a client datagram if the [UDP](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#udp>) protocol is used. The number serves as a hint for session termination. By default, the number of datagrams is not limited.

設定使用 [UDP](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#udp>)協定時，代理伺服器回應客戶端資料封包所期望傳回的資料封包數量。此數量用作會話終止的提示。預設情況下，資料報數量沒有限制。

If zero value is specified, no response is expected. However, if a response is received and the session is still not finished, the response will be handled.

如果指定值為零，則不期望收到任何回應。但是，如果收到回應且會話尚未結束，則會處理該回應。

This directive appeared in version 1.15.8.

該指令出現在版本1.15.8中。

Enables terminating all sessions to a proxied server after it was removed from the group or marked as permanently unavailable. This can occur because of [re-resolve](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>) or with the API [`DELETE`](<048 [01.01.03 http] 模組 ngx_http_api_module.md#deleteStreamUpstreamServer>) command. Each session is terminated when the next read or write event is processed for the client or proxied server.
