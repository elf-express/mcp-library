The `ngx_stream_upstream_module` module (1.9.0) is used to define groups of servers that can be referenced by the [proxy\_pass](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_pass>) directive.

`ngx_stream_upstream_module`模組 ( 1.9.0 ) 用於定義可透過 [proxy\_pass](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_pass>)指令引用的伺服器群組。

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>文法： | ``**upstream** `*name*` { ... }``<br>` `**upstream** ` *名稱* ` { ... }` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `stream` |

Defines a group of servers. Servers can listen on different ports. In addition, servers listening on TCP and UNIX-domain sockets can be mixed.

定義一組伺服器。伺服器可以監聽不同的連接埠。此外，監聽TCP和UNIX域套接字的伺服器可以混合使用。

Example:

例子：

> ```
> upstream backend {
>
> 上游後端 {
>     server backend1.example.com:12345 weight=5;
>
>     伺服器 backend1.example.com:12345 weight=5;
>     server 127.0.0.1:12345            max_fails=3 fail_timeout=30s;
>
>     伺服器127.0.0.1:12345 max_fails=3 fail_timeout=30s;
>     server unix:/tmp/backend2;
>
>     伺服器 unix:/tmp/backend2;
>     server backend3.example.com:12345 resolve;
>
>     伺服器 backend3.example.com:12345 解析；
> 
>     server backup1.example.com:12345  backup;
>
>     伺服器 backup1.example.com:12345 備份;
> }
> ```

By default, connections are distributed between the servers using a weighted round-robin balancing method. In the above example, each 7 connections will be distributed as follows: 5 connections go to `backend1.example.com:12345` and one connection to each of the second and third servers. If an error occurs during communication with a server, the connection will be passed to the next server, and so on until all of the functioning servers will be tried. If communication with all servers fails, the connection will be closed.

預設情況下，連線使用加權輪詢負載平衡方法在伺服器之間分配。在上面的範例中，7 個連接將按以下方式分配：5 個連接分配給`backend1.example.com:12345` ，其餘 1 個連接分別分配給第二台和第三台伺服器。如果在與某個伺服器通訊時發生錯誤，則連線將傳遞給下一台伺服器，依此類推，直到嘗試所有可用的伺服器為止。如果與所有伺服器的通訊都失敗，則連線將關閉。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**server** `*address*` [`*parameters*`];``<br>` `**server** ` *地址* ` [` *參數* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `upstream` |

Defines the `*address*` and other `*parameters*` of a server. The address can be specified as a domain name or IP address with an obligatory port, or as a UNIX-domain socket path specified after the “`unix:`” prefix. A domain name that resolves to several IP addresses defines multiple servers at once.

定義伺服器的`*address*`及其他`*parameters*`位址。位址可以指定為網域名稱或IP位址（必須包含連接埠），也可以指定為UNIX網域套接字路徑（位於「 `unix:` 」前綴之後）。一個網域名稱如果解析到多個IP位址，則同時定義多個伺服器。

The following parameters can be defined:

可以定義以下參數：

`weight`\=`*number*`

sets the weight of the server, by default, 1.

設定伺服器權重，預設值為 1。

`max_conns`\=`*number*`

limits the maximum `*number*` of simultaneous connections to the proxied server (1.11.5). Default value is zero, meaning there is no limit. If the server group does not reside in the [shared memory](#zone), the limitation works per each worker process.

限制與1.11.5 `*number*`的並發連線數上限。預設值為零，表示沒有限制。如果伺服器群組不在共享記憶體 ( (https://nginx.org/en/docs/stream/ngx_stream_upstream_module.html#zone) ) 中，則此限制針對每個工作進程生效。

> Prior to version 1.11.5, this parameter was available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.11.5之前，此參數是作為我們的[商業訂閱](https://www.f5.com/products/nginx)的一部分提供的。

`max_fails`\=`*number*`

sets the number of unsuccessful attempts to communicate with the server that should happen in the duration set by the `fail_timeout` parameter to consider the server unavailable for a duration also set by the `fail_timeout` parameter. By default, the number of unsuccessful attempts is set to 1. The zero value disables the accounting of attempts. Here, an unsuccessful attempt is an error or timeout while establishing a connection with the server.

此參數設定了在`fail_timeout`參數設定的時間段內，與伺服器通訊失敗的次數，以此判定伺服器在`fail_timeout`參數設定的時間內不可用。預設情況下，失敗次數為 1。值為 0 則停用失敗次數統計。此處，失敗次數指的是與伺服器建立連線時發生的錯誤或逾時。

`fail_timeout`\=`*time*`

sets

套

-   the time during which the specified number of unsuccessful attempts to communicate with the server should happen to consider the server unavailable;  
    在指定時間內，與伺服器通訊失敗次數達到指定值後，伺服器將被視為不可用；
-   and the period of time the server will be considered unavailable.  
    以及伺服器將被視為不可用的時間段。

By default, the parameter is set to 10 seconds.

預設情況下，此參數設定為 10 秒。

`backup`

marks the server as a backup server. Connections to the backup server will be passed when the primary servers are unavailable.

將伺服器標記為備用伺服器。當主伺服器不可用時，將透過備用伺服器建立連線。

> The parameter cannot be used along with the [hash](#hash) and [random](#random) load balancing methods.
>
> 此參數不能與 [hash](#hash)和 [random](#random)負載平衡方法一起使用。

`down`

marks the server as permanently unavailable.

將伺服器標記為永久不可用。

`resolve`

monitors changes of the IP addresses that correspond to a domain name of the server, and automatically modifies the upstream configuration without the need of restarting nginx. The server group must reside in the [shared memory](#zone).

監控與伺服器網域名稱對應的IP位址的變化，並自動修改上游配置，無需重新啟動nginx。伺服器群組必須位於[共享記憶體](#zone)中。

In order for this parameter to work, the `resolver` directive must be specified in the [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>) block or in the corresponding [upstream](#resolver) block.

為了使此參數生效，必須在 [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>)區塊或對應的 [upstream](#resolver)區塊中指定`resolver`指令。

> Prior to version 1.27.3, this parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.27.3之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`service`\=`*name*`

enables resolving of DNS [SRV](https://datatracker.ietf.org/doc/html/rfc2782) records and sets the service `*name*` (1.9.13). In order for this parameter to work, it is necessary to specify the [resolve](#resolve) parameter for the server and specify a hostname without a port number.

啟用對DNS [SRV](https://datatracker.ietf.org/doc/html/rfc2782)記錄的解析，並設定服務`*name*` ( 1.9.13 )。為了使此參數生效，必須為伺服器指定 [resolve](#resolve)參數，並指定不含連接埠號碼的主機名稱。

If the service name does not contain a dot (“`.`”), then the [RFC](https://datatracker.ietf.org/doc/html/rfc2782)\-compliant name is constructed and the TCP protocol is added to the service prefix. For example, to look up the `_http._tcp.backend.example.com` SRV record, it is necessary to specify the directive:

如果服務名稱不包含點號（「 `.` 」），則建構符合 [RFC](https://datatracker.ietf.org/doc/html/rfc2782)標準的名稱，並將TCP協定新增至服務前綴。例如，要尋找`_http._tcp.backend.example.com` SRV記錄，需要指定以下指令：

> ```
> server backend.example.com service=http resolve;
>
> 伺服器 backend.example.com 服務=http 解析；
> ```

If the service name contains one or more dots, then the name is constructed by joining the service prefix and the server name. For example, to look up the `_http._tcp.backend.example.com` and `server1.backend.example.com` SRV records, it is necessary to specify the directives:

如果服務名稱包含一個或多個點，則名稱由服務前綴和伺服器名稱連接而成。例如，要找`_http._tcp.backend.example.com`和`server1.backend.example.com` SRV記錄，需要指定以下指令：

> ```
> server backend.example.com service=_http._tcp resolve;
> server example.com service=server1.backend resolve;
>
> 伺服器 example.com 服務=server1.backend 解析；
> ```

Highest-priority SRV records (records with the same lowest-number priority value) are resolved as primary servers, the rest of SRV records are resolved as backup servers. If the [backup](#backup) parameter is specified for the server, high-priority SRV records are resolved as backup servers, the rest of SRV records are ignored.

優先順序最高的SRV記錄（優先值最低的記錄）解析為主伺服器，其餘的SRV記錄解析為備份伺服器。如果為伺服器指定了[backup](#backup)參數，則優先順序最高的SRV記錄被解析為備份伺服器，其餘的SRV記錄將被忽略。

> Prior to version 1.27.3, this parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.27.3之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

Additionally, the following parameters are available as part of our [commercial subscription](https://www.f5.com/products/nginx):

此外，以下參數包含在我們的[商業訂閱](https://www.f5.com/products/nginx)中：

`slow_start`\=`*time*`

sets the `*time*` during which the server will recover its weight from zero to a nominal value, when unhealthy server becomes [healthy](<162 [01.01.06 溪流] 模組 ngx_stream_upstream_hc_module.md#health_check>), or when the server becomes available after a period of time it was considered [unavailable](#fail_timeout). Default value is zero, i.e. slow start is disabled.

設定`*time*`在此期間，伺服器的權重將從零恢復到標稱值，當不健康的伺服器變為 [健康](<162 [01.01.06 溪流] 模組 ngx_stream_upstream_hc_module.md#health_check>)時，或當伺服器在被視為 [不可用 一段時間後恢復可用時](#fail_timeout) 。預設值為零，即禁用慢啟動。

> The parameter cannot be used along with the [hash](#hash) and [random](#random) load balancing methods.
>
> 此參數不能與 [hash](#hash)和 [random](#random)負載平衡方法一起使用。

> If there is only a single server in a group, `max_fails`, `fail_timeout` and `slow_start` parameters are ignored, and such a server will never be considered unavailable.
>
> 如果一個群組中只有一個伺服器，則忽略`max_fails`, `fail_timeout`和`slow_start`參數，並且這樣的伺服器永遠不會被視為不可用。

Defines the `*name*` and `*size*` of the shared memory zone that keeps the group’s configuration and run-time state that are shared between worker processes. Several groups may share the same zone. In this case, it is enough to specify the `*size*` only once.

定義共享記憶體區域的`*name*`和`*size*` ，該區域用於保存工作進程間共享的群組配置和運行時狀態。多個群組可以共享同一個區域。在這種情況下，只需指定一次`*size*`即可。

Additionally, as part of our [commercial subscription](https://www.f5.com/products/nginx), such groups allow changing the group membership or modifying the settings of a particular server without the need of restarting nginx. The configuration is accessible via the [API](<048 [01.01.03 http] 模組 ngx_http_api_module.md>) module (1.13.3).

此外，作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分，此類群組允許更改群組成員或修改特定伺服器的設置，而無需重啟nginx。可透過[API](<048 [01.01.03 http] 模組 ngx_http_api_module.md>)模組( 1.13.3 )存取配置。

> Prior to version 1.13.3, the configuration was accessible only via a special location handled by [upstream\_conf](<103 [01.01.03 http] 模組 ngx_http_upstream_conf_module.md#upstream_conf>).
>
> 在版本1.13.3之前，配置只能透過 [upstream\_conf](<103 [01.01.03 http] 模組 ngx_http_upstream_conf_module.md#upstream_conf>)處理的特殊位置存取。

該指令出現在版本1.9.7 。

Specifies a `*file*` that keeps the state of the dynamically configurable group.

指定一個`*file*` ，用於保持動態可設定群組的狀態。

Examples:

例如：

The state is currently limited to the list of servers with their parameters. Changing the file content directly should be avoided. The directive cannot be used along with the [server](#server) directive.

目前狀態僅限於伺服器清單及其參數。解析配置時會讀取該文件，並且每次(https://nginx.org/en/docs/http/ngx_http_api_module.html#stream_upstreams_stream_upstream_name_servers_)配置發生更改時都會更新該文件。應避免直接更改文件內容。該指令不能與 [server](#server)同時使用。

>
> 在 [組態重新載入](<026 [01.01 文件] 控制 Nginx.md#reconfiguration>)或 [二進位升級](<026 [01.01 文件] 控制 Nginx.md#upgrade>)期間所做的變更可能會遺失。

> This directive is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本指令作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**hash** `*key*` [`consistent`];``<br>` `**hash** ` *鍵* ` [`一致性`];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `upstream` |

Specifies a load balancing method for a server group where the client-server mapping is based on the hashed `*key*` value. The `*key*` can contain text, variables, and their combinations (1.11.2). Usage example:

指定伺服器群組的負載平衡方法`*key*`其中客戶端-伺服器映射基於哈希值`*key*`可以包含文字、變數及其組合 ( 1.11.2 )。使用範例：

> ```
> hash $remote_addr;
>
> 哈希 $remote_addr；
> ```

Note that adding or removing a server from the group may result in remapping most of the keys to different servers. The method is compatible with the [Cache::Memcached](https://metacpan.org/pod/Cache::Memcached) Perl library.

請注意，向群組中新增或刪除伺服器可能會導致大部分鍵重新對應到不同的伺服器。此方法與 [Cache::Memcached](https://metacpan.org/pod/Cache::Memcached) Perl 函式庫相容。

If the `consistent` parameter is specified, the [ketama](https://www.metabrew.com/article/libketama-consistent-hashing-algo-memcached-clients) consistent hashing method will be used instead. The method ensures that only a few keys will be remapped to different servers when a server is added to or removed from the group. This helps to achieve a higher cache hit ratio for caching servers. The method is compatible with the [Cache::Memcached::Fast](https://metacpan.org/pod/Cache::Memcached::Fast) Perl library with the `*ketama_points*` parameter set to 160.

如果指定了`consistent`參數，則會使用 [ketama](https://www.metabrew.com/article/libketama-consistent-hashing-algo-memcached-clients)一致性雜湊方法。此方法確保在向群組中新增或從群組中移除伺服器時，只有少數鍵會重新對應到不同的伺服器。這有助於提高快取伺服器的快取命中率。此方法與 [Cache::Memcached::Fast](https://metacpan.org/pod/Cache::Memcached::Fast) Perl 函式庫相容，前提是`*ketama_points*`參數設定為 160。

#### Embedded Variables｜嵌入變數

The `ngx_stream_upstream_module` module supports the following embedded variables:

`ngx_stream_upstream_module`模組支援以下嵌入式變數：

`$upstream_addr`

keeps the IP address and port, or the path to the UNIX-domain socket of the upstream server (1.11.4). If several servers were contacted during proxying, their addresses are separated by commas, e.g. “`192.168.1.1:12345, 192.168.1.2:12345, unix:/tmp/sock`”. If a server cannot be selected, the variable keeps the name of the server group.

保留上游伺服器（ 1.11.4 ）的IP位址和端口，或UNIX域套接字的路徑。如果在代理過程中聯繫了多個伺服器，則它們的位址以逗號分隔，例如「 `192.168.1.1:12345, 192.168.1.2:12345, unix:/tmp/sock` 」。如果無法選擇伺服器，則該變數保留伺服器群組的名稱。

`$upstream_bytes_received`

number of bytes received from an upstream server (1.11.4). Values from several connections are separated by commas like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

從上游伺服器接收的位元組數（ 1.11.4 ）。來自多個連接的值以逗號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_bytes_sent`

number of bytes sent to an upstream server (1.11.4). Values from several connections are separated by commas like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

傳送到上游伺服器的位元組數（ 1.11.4 ）。來自多個連接的值以逗號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_connect_time`

time to connect to the upstream server (1.11.4); the time is kept in seconds with millisecond resolution. Times of several connections are separated by commas like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

連接到上游伺服器所需時間（ 1.11.4 ）；時間以秒為單位，精確到毫秒。多個連接的時間用逗號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_first_byte_time`

time to receive the first byte of data (1.11.4); the time is kept in seconds with millisecond resolution. Times of several connections are separated by commas like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

接收第一個位元組資料的時間（ 1.11.4 ）；時間以秒為單位，精確到毫秒。多個連接的時間用逗號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_last_addr`

keeps the IP address or the path to the UNIX-domain socket of the last selected upstream server (1.29.3).

保留最後選定的上游伺服器（ 1.29.3 ）的IP位址或UNIX域套接字的路徑。

> This variable is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 此變數作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`$upstream_session_time`

session duration in seconds with millisecond resolution (1.11.4). Times of several connections are separated by commas like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

會話持續時間以秒為單位，精確到毫秒（ 1.11.4 ）。多個連接的持續時間用逗號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。
