#### Получение исходного кода｜取得原始碼

Для хранения исходного кода используется [GitHub](https://github.com/). [Репозиторий](https://github.com/nginx/nginx) можно клонировать следующей командой:

原始碼儲存在 [GitHub](https://github.com/)上。 [倉庫](https://github.com/nginx/nginx)可以使用以下指令複製：

> ```bash
>
> 『`bash
> git clone https://github.com/nginx/nginx.git
> ```

#### Оформление изменений｜變更登記

Изменения должны быть оформлены согласно [стилю](https://nginx.org/ru/docs/dev/development_guide.html#code_style), принятому в nginx. В случае возникновения затруднений в оформлении изучите, как оформлен исходный код nginx, и следуйте этому стилю в своём коде. Изменения скорее будут приняты, если их стиль соответствует окружающему коду.

所有變更必須按照 NGINX 風格(https://nginx.org/ru/docs/dev/development_guide.html#code_style)進行格式化。如果遇到任何格式問題，請仔細研究 NGINX 原始碼格式，並在您的程式碼中遵循該風格。如果更改的風格與周圍程式碼一致，則更容易被接受。

[Зафиксируйте](https://docs.github.com/ru/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/about-commits) изменения в вашем ответвлении (fork) проекта. Пожалуйста, убедитесь, что адрес [электронной почты](https://docs.github.com/ru/get-started/getting-started-with-git/setting-your-username-in-git) и настоящее имя автора изменения указаны правильно.

請將變更(https://docs.github.com/ru/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/about-commits)到您 fork 的項目。請確保更改作者的電子郵件地址和真實姓名正確(https://docs.github.com/ru/get-started/getting-started-with-git/setting-your-username-in-git) 。

Сообщение фиксации должно содержать однострочное резюме и подробное описание после пустой строки. Первая строка и остальные строки должны быть не длиннее 72 символов. Итоговый набор изменений может быть получен с помощью команды `git show`:

提交資訊必須包含一行摘要，並在空白行後面添加詳細描述。第一行及後續行長度不得超過 72 個字元。最終的變更集可以使用`git show`指令取得：

> ```

#### Перед отправкой｜發送前

Несколько моментов, на которые следует обратить внимание перед отправкой изменения:

提交更改前，請考慮以下幾點：

-   Предлагаемые изменения должны корректно работать на всех [поддерживаемых платформах](<326 [02 ru] nginx.md#tested_os_and_platforms>).  
    所提出的更改應該在所有[支援的平台](<326 [02 ru] nginx.md#tested_os_and_platforms>)上都能正常運作。
-   Постарайтесь разъяснить, почему предлагаемое изменение нужно, и, если возможно, опишите вариант использования.  
    請嘗試解釋為什麼需要提出這項變更，如果可能，請描述其使用情境。
-   Проверка изменений при помощи специального набора тестов позволит убедиться, что они не вызывают регрессию. [Репозиторий](https://github.com/nginx/nginx-tests) с тестами можно клонировать следующей командой:  
    使用專用測試套件測試您的更改，可以確保它們不會導致回歸。 [倉庫](https://github.com/nginx/nginx-tests)及其測試套件可透過以下命令克隆：
    
    > ```bash
    >
    > 『`bash
    > git clone https://github.com/nginx/nginx-tests.git
    > ```
    

#### Отправка изменений｜提交更改

Предлагаемые изменения следует отправлять из вашего ответвления проекта в исходный [репозиторий](https://github.com/nginx/nginx) как [pull request](https://docs.github.com/ru/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork).

建議的變更應從您的專案分支提交到原始[儲存庫](https://github.com/nginx/nginx)作為[拉取請求](https://docs.github.com/ru/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork) 。

#### Веб-сайт｜網站

Для хранения исходных файлов этого веб-сайта также используется GitHub. [Репозиторий](https://www.github.com/nginx/nginx.org) можно клонировать следующей командой:

GitHub 也用於託管本網站的原始碼檔案。 [倉庫](https://www.github.com/nginx/nginx.org)可以使用以下指令複製：

> ```
> https://github.com/nginx/nginx.org.git
> ```

Предлагаемые изменения следует отправлять из вашего ответвления проекта как pull request.

建議的變更應以拉取請求的形式從您的專案分支提交。

#### Лицензия｜執照

Отправка изменений подразумевает предоставление проекту права на их использование под соответствующей [лицензией](<354 頁.md>).

提交更改意味著授予專案方根據相應的 [許可](<354 頁.md>)使用這些更改的權利。
