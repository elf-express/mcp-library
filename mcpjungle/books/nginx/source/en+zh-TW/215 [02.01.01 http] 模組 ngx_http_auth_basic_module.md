## Модуль ngx\_http\_auth\_basic\_module｜模組 ngx\_http\_auth\_basic\_module

Модуль `ngx_http_auth_basic_module` позволяет ограничить доступ к ресурсам с проверкой имени и пароля пользователя по протоколу “HTTP Basic Authentication”（HTTP 基本驗證）.

`ngx_http_auth_basic_module`模組可讓您透過使用“HTTP Basic Authentication”（HTTP 基本驗證）協定檢查使用者名稱和密碼來限制對資源的存取。

Ограничить доступ можно также по [адресу](<213 [02.01.01 http] 模組 ngx_http_access_module.md>), по [результату подзапроса](<217 [02.01.01 http] ngx_http_auth_request_module 模組.md>) или по [JWT](<216 [02.01.01 http] ngx_http_auth_jwt_module 模組.md>). Одновременное ограничение доступа по адресу и паролю управляется директивой [satisfy](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>).

您也可以透過[地址](<213 [02.01.01 http] 模組 ngx_http_access_module.md>)、[子查詢結果](<217 [02.01.01 http] ngx_http_auth_request_module 模組.md>)或[JWT](<216 [02.01.01 http] ngx_http_auth_jwt_module 模組.md>)來限制存取。透過位址和密碼同時限制存取由 [satisfy](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>) 指令控制。

#### Пример конфигурации｜配置範例

> ```
> location / {
>
> 地點 / {
>     auth_basic           "closed site";
>
>     auth_basic「關閉站點」；
>     auth_basic_user_file conf/htpasswd;
>
>     auth_basic_user_fileconf/htpasswd；
> }
> ```

Включает проверку имени и пароля пользователя по протоколу “HTTP Basic Authentication”（HTTP 基本驗證）. Заданный параметр используется в качестве `*realm*`. В значении параметра допустимо использование переменных (1.3.10, 1.2.7). Специальное значение `off` отменяет действие унаследованной с предыдущего уровня конфигурации директивы `auth_basic`.

使用“HTTP Basic Authentication”（HTTP 基本驗證）協定啟用使用者名稱和密碼驗證。指定的参数用作`*realm*`。参数值中可以使用变量(1.3.10, 1.2.7)。特殊值`off`覆寫從先前配置等級繼承的指令`auth_basic`。

Задаёт файл, в котором хранятся имена и пароли пользователей. Формат файла следующий:

指定存储用户名和密码的文件。文件格式如下：

> ```
> # комментарий｜評論
> имя1:пароль1
>
> 名稱1:密碼1
> имя2:пароль2:комментарий
>
> 名稱2:密碼2:評論
> имя3:пароль3
>
> 名稱3:密碼3
> ```

В имени файла можно использовать переменные.

您可以在文件名中使用变量。

Поддерживаются следующие типы паролей:

支持以下密码类型：

-   зашифрованные функцией `crypt()`; могут быть созданы с помощью утилиты “`htpasswd`” из дистрибутива HTTP-сервера Apache или команды “`openssl passwd`”;  
    使用函數`crypt()`加密；可使用 HTTP Apache 伺服器發行版中的「`htpasswd`」公用程式或「`openssl passwd`」指令建立；
-   хэшированные с помощью алгоритма, основанного на MD5, по версии Apache (apr1); могут быть созданы теми же инструментами;  
    根據 Apache 版本 (apr1)，使用基於 MD5 的演算法進行哈希處理；可以使用相同的工具建立；
-   заданные согласно синтаксису “`{``*схема*``}``*данные*`” (1.0.3+) как описано в [RFC 2307](https://datatracker.ietf.org/doc/html/rfc2307#section-5.3); в настоящий момент реализованы схемы `PLAIN` (в качестве примера, не следует применять), `SHA` (1.3.13) (простое SHA-1 хэширование, не следует применять) и `SSHA` (SHA-1 хэширование с солью, используется в некоторых программах, в частности OpenLDAP и Dovecot).  
    按照語法“`{``*схема*``}``*данные*`” (1.0.3+) 如 [ ] 所述RFC 2307](https://datatracker.ietf.org/doc/html/rfc2307#section-5.3)目前已實施相關方案 `PLAIN` （例如，不應使用） `SHA` (1.3.13） （簡單的 SHA-1 哈希（不應使用）和 `SSHA` (SHA-1 加鹽雜湊（在某些程式中使用，特別是 OpenLDAP 和 Dovecot）。
    
    > Поддержка схемы `SHA` была добавлена лишь для облегчения процесса миграции файлов паролей с других веб-серверов. Её не следует применять для новых паролей, т.к. используемое при этом SHA-1 хэширование без соли уязвимо к взлому при помощи [радужных таблиц](http://en.wikipedia.org/wiki/Rainbow_attack).
    >
    > 新增對 `SHA` 方案的支援只是為了方便從其他 Web 伺服器遷移密碼檔案的過程。它不應該用於新密碼，因為......其中使用的SHA-1無鹽哈希很容易受到使用[彩虹表](http://en.wikipedia.org/wiki/Rainbow_attack)的黑客攻擊。
