> 章節：[en｜在](<000 目錄.md#c-1>) › [docs｜文件](<000 目錄.md#c-2>)

## Support for QUIC and HTTP/3｜支持QUIC和HTTP /3

|   |
| --- |
| [Building from sources](#building)<br>[Configuration tips](#configuration)<br>[Troubleshooting](#troubleshooting)<br>[從原始碼建構](#building)<br> [設定提示](#configuration)<br> [故障排除](#troubleshooting) |

Support for [QUIC](https://datatracker.ietf.org/doc/html/rfc9000) and [HTTP/3](https://datatracker.ietf.org/doc/html/rfc9114) protocols is available since 1.25.0, it is included in Linux [binary packages](<177 [01 在] nginx Linux 軟體套件.md>). Please refer to the [ngx\_http\_v3\_module](<109 [01.01.03 http] 模組 ngx_http_v3_module.md>) documentation.

自 [QUIC](https://datatracker.ietf.org/doc/html/rfc9000)和 [HTTP /3](https://datatracker.ietf.org/doc/html/rfc9114)協議起，已支援1.25.0協議，並包含在 Linux [二進位軟體包](<177 [01 在] nginx Linux 軟體套件.md>)中。請參閱 [ngx\_http\_v3\_module](<109 [01.01.03 http] 模組 ngx_http_v3_module.md>)文件。

#### Building from sources｜從源頭構建

The build is configured using the `configure` command. Please refer to [Building nginx from Sources](<024 [01.01 文件] 從原始碼建構 nginx.md>) for details.

建構配置使用`configure`指令。詳情請參閱 [從原始碼建構 nginx](<024 [01.01 文件] 從原始碼建構 nginx.md>) 。

The [OpenSSL](https://openssl.org/) library version 3.5.1 or higher is recommended to build nginx with QUIC support. Otherwise, the [OpenSSL](https://openssl.org/) compatibility layer will be used that does not support [early data](<098 [01.01.03 http] 模組 ngx_http_ssl_module.md#ssl_early_data>). Alternatively, [BoringSSL](https://boringssl.googlesource.com/boringssl), [LibreSSL](https://www.libressl.org/), or [QuicTLS](https://github.com/quictls/openssl) prebuilt libraries can be used.

建議使用 [OpenSSL](https://openssl.org/)庫版本3.5.1或更高版本來建立支援QUIC的 nginx。否則，將使用不支援 [early data](<098 [01.01.03 http] 模組 ngx_http_ssl_module.md#ssl_early_data>)的 [OpenSSL](https://openssl.org/)相容層。或者，也可以使用 [BoringSSL](https://boringssl.googlesource.com/boringssl) 、[LibreSSL](https://www.libressl.org/)或 [QuicTLS](https://github.com/quictls/openssl)預建置函式庫。

Use the following command to configure nginx with [BoringSSL](https://boringssl.googlesource.com/boringssl):

使用以下命令配置 nginx 以使用 [BoringSSL](https://boringssl.googlesource.com/boringssl) ：

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../boringssl/include"
>     --with-ld-opt="-L../boringssl/build -lstdc++"
> ```

Alternatively, nginx can be configured with [QuicTLS](https://github.com/quictls/openssl):

或者，nginx 可以配置為 [QuicTLS](https://github.com/quictls/openssl) :

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../quictls/build/include"
>     --with-ld-opt="-L../quictls/build/lib"
> ```

Alternatively, nginx can be configured with [LibreSSL](https://www.libressl.org/):

或者，nginx 可以配置為 [LibreSSL](https://www.libressl.org/) :

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../libressl/build/include"
>     --with-ld-opt="-L../libressl/build/lib"
> ```

After configuration, nginx is compiled and installed using `make`.

配置完成後，使用`make`編譯並安裝nginx。

#### Configuration tips｜設定提示

The [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>) directive in [ngx\_http\_core\_module](<056 [01.01.03 http] 模組 ngx_http_core_module.md>) module got a new parameter [quic](<056 [01.01.03 http] 模組 ngx_http_core_module.md#quic>) which enables HTTP/3 over QUIC on the specified port.

[ngx\_http\_core\_module](<056 [01.01.03 http] 模組 ngx_http_core_module.md>)模組中的 [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>)指令獲得了一個新的參數 [quic](<056 [01.01.03 http] 模組 ngx_http_core_module.md#quic>) ，該參數允許在指定的QUIC埠上透過HTTP

Along with the `quic` parameter it is also possible to specify the [reuseport](<056 [01.01.03 http] 模組 ngx_http_core_module.md#reuseport>) parameter to make it work properly with multiple workers.

除了`quic`參數之外，還可以指定 [reuseport](<056 [01.01.03 http] 模組 ngx_http_core_module.md#reuseport>)參數，使其能夠與多個工作進程正常運作。

To [enable](<109 [01.01.03 http] 模組 ngx_http_v3_module.md#quic_retry>) address validation:

啟用(https://nginx.org/en/docs/http/ngx_http_v3_module.html#quic_retry)位址驗證：

> ```
> quic_retry on;
>
> 快速重試已開啟；
> ```

To [enable](<098 [01.01.03 http] 模組 ngx_http_ssl_module.md#ssl_early_data>) 0-RTT:

啟用(https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_early_data) 0- RTT :

> ```
> ssl_early_data on;
>
> 啟用 ssl_early_data；
> ```

To [enable](<109 [01.01.03 http] 模組 ngx_http_v3_module.md#quic_gso>) GSO (Generic Segmentation Offloading):

啟用(https://nginx.org/en/docs/http/ngx_http_v3_module.html#quic_gso) GSO （通用分段卸載）：

> ```
> quic_gso on;
>
> quick_gso 開啟；
> ```

To [set](<109 [01.01.03 http] 模組 ngx_http_v3_module.md#quic_host_key>) host key for various tokens:

設定各種令牌的(https://nginx.org/en/docs/http/ngx_http_v3_module.html#quic_host_key)主機金鑰：

> ```
> quic_host_key <filename>;
>
> quic_host_key <filename> ;
> ```

QUIC requires TLSv1.3 protocol version which is enabled by default in the [ssl\_protocols](<098 [01.01.03 http] 模組 ngx_http_ssl_module.md#ssl_protocols>) directive.

QUIC需要 TLSv1.3 協定版本，該版本在 [ssl\_protocols](<098 [01.01.03 http] 模組 ngx_http_ssl_module.md#ssl_protocols>)指令中預設為啟用。

By default, [GSO Linux-specific optimization](http://vger.kernel.org/lpc_net2018_talks/willemdebruijn-lpc2018-udpgso-paper-DRAFT-1.pdf) is disabled. Enable it in case a corresponding network interface is configured to support GSO.

預設情況下，[GSO Linux 特定最佳化](http://vger.kernel.org/lpc_net2018_talks/willemdebruijn-lpc2018-udpgso-paper-DRAFT-1.pdf)處於停用狀態。如果對應的網路介面配置為支援GSO ，則啟用它。

#### Troubleshooting｜故障排除

Tips that may help to identify problems:

以下提示可能有助於發現問題：

-   Ensure nginx is built with the proper SSL library.  
    確保使用正確的SSL庫建置 nginx。
-   Ensure nginx is using the proper SSL library in runtime (the `nginx -V` shows what it is currently used).  
    確保 nginx 在運行時使用正確的SSL庫（ `nginx -V`顯示目前使用的庫）。
-   Ensure a client is actually sending requests over QUIC. It is recommended to start with a simple console client such as [ngtcp2](https://nghttp2.org/ngtcp2) to ensure the server is configured properly before trying with real browsers that may be quite picky with certificates.  
    確保客戶端確實透過QUIC發送請求。建議先使用簡單的控制台用戶端（例如 [ngtcp2](https://nghttp2.org/ngtcp2)進行測試，以確保伺服器配置正確，然後再嘗試使用對憑證要求較高的真實瀏覽器。
-   Build nginx with [debug support](<027 [01.01 文件] 偵錯日誌.md>) and check the debug log. It should contain all details about the connection and why it failed. All related messages contain the “`quic`” prefix and can be easily filtered out.  
    使用 [debug support](<027 [01.01 文件] 偵錯日誌.md>)建置 nginx，並檢查偵錯日誌。日誌中應該包含連接的所有詳細資訊以及連接失敗的原因。所有相關訊息都包含「 `quic` 」前綴，可以輕鬆過濾掉。
-   For a deeper investigation, additional debugging can be enabled using the following macros: `NGX_QUIC_DEBUG_PACKETS`, `NGX_QUIC_DEBUG_FRAMES`, `NGX_QUIC_DEBUG_ALLOC`, `NGX_QUIC_DEBUG_CRYPTO`.  
    為了進行更深入的調查，可以使用以下巨集啟用額外的偵錯： `NGX_QUIC_DEBUG_PACKETS`, `NGX_QUIC_DEBUG_FRAMES`, `NGX_QUIC_DEBUG_ALLOC`, `NGX_QUIC_DEBUG_CRYPTO` 。
    
    > ```
    > ./configure
    >
    > ./配置
    >     --with-http_v3_module
    >     --with-debug
    >     --with-cc-opt="-DNGX_QUIC_DEBUG_PACKETS -DNGX_QUIC_DEBUG_CRYPTO"
    > ```
