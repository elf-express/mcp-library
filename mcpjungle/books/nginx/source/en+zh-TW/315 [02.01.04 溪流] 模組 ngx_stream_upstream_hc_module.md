# Модуль ngx_stream_upstream_hc_module｜模組 ngx_stream_upstream_hc_module

## Модуль ngx\_stream\_upstream\_hc\_module｜模組 ngx\_stream\_upstream\_hc\_module

|   |
| --- |
| [Пример конфигурации](#example)<br>[Директивы](#directives)<br>     [health\_check](#health_check)<br>     [health\_check\_timeout](#health_check_timeout)<br>     [match](#match)<br>[設定範例](#example)<br> [指令](#directives)<br> [health\_check](#health_check)<br> [health\_check\_timeout](#health_check_timeout)<br> [match](#match) |

Модуль `ngx_stream_upstream_hc_module` (1.9.0) позволяет активировать периодические проверки работоспособности серверов в [группе](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#upstream>). Группа должна находиться в [зоне разделяемой памяти](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>).

`ngx_stream_upstream_hc_module` ( 1.9.0 ) 模組可對 [群組](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#upstream>)中的伺服器進行定期健康檢查。此群組必須位於 [共享記憶體區](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>)中。

Если проверка работоспособности была неуспешной, то сервер признаётся неработоспособным. Если для группы задано несколько проверок, то при любой неуспешной проверке соответствующий сервер будет считаться неработоспособным. На неработоспособные серверы и серверы в состоянии “checking” клиентские соединения передаваться не будут.

如果健康檢查失敗，則伺服器被視為不健康。如果為一組定義了多個健康檢查，則任何失敗的健康檢查都會導致相應的伺服器被視為不健康。客戶端連線將不會被轉送到不健康的伺服器或處於「檢查中」狀態的伺服器。

> Модуль доступен как часть [коммерческой подписки](https://www.f5.com/products/nginx).
>
> 此模組包含在[商業訂閱](https://www.f5.com/products/nginx)中。

#### Пример конфигурации｜配置範例

> ```
> upstream tcp {
>
> 上游 TCP {
>     zone upstream_tcp 64k;
>
>     區域 upstream_tcp 64k；
> 
>     server backend1.example.com:12345 weight=5;
>
>     伺服器 backend1.example.com:12345 權重=5;
>     server backend2.example.com:12345 fail_timeout=5s slow_start=30s;
>     server 192.0.2.1:12345            max_fails=3;
>
>     伺服器192.0.2.1:12345 max_fails=3;
> 
>     server backup1.example.com:12345  backup;
>
>     伺服器 backup1.example.com:12345 備份;
>     server backup2.example.com:12345  backup;
>
>     伺服器 backup2.example.com:12345 備份;
> }
> 
> server {
>
> 伺服器{
>     listen     12346;
>
>     聽 12346；
>     proxy_pass tcp;
>     health_check;
>
>     健康檢查；
> }
> ```

Для каждого сервера группы `tcp` с интервалом в 5 секунд проверяется возможность установки TCP-соединения. Если соединение с сервером не может быть установлено, проверка считается неуспешной и сервер признаётся неработоспособным.

對於`tcp`組中的每個伺服器，每5秒鐘檢查一次其建立TCP連接的能力。如果無法建立與伺服器的連接，則檢查失敗，伺服器被視為不健康。

Проверки работоспособности можно настроить для протокола UDP:

可以對UDP協議配置健康檢查：

> ```
> upstream dns_upstream {
>
> 上游 dns_upstream {
> 
>     zone   dns_zone 64k;
>
>     區域 dns_zone 64k；
> 
>     server dns1.example.com:53;
>
>     伺服器 dns1.example.com:53;
>     server dns2.example.com:53;
>
>     伺服器 dns2.example.com:53;
>     server dns3.example.com:53;
>
>     伺服器 dns3.example.com:53;
> }
> 
> server {
>
> 伺服器{
>     listen       53 udp;
>
>     列表 53 UDP；
>     proxy_pass   dns_upstream;
>
>     proxy_pass dns_upstream;
>     health_check udp;
>
>     健康檢查 UDP；
> }
> ```

В этом случае проверяется отсутствие сообщения ICMP “`Destination Unreachable`” в ответ на отправленную строку “`nginx health check`”.

在這種情況下，檢查是否缺少對發送的字串「 `nginx health check` 」的回應的「 ICMP “ `Destination Unreachable` 」訊息。

Проверки работоспособности могут тестировать данные, полученные от сервера. Тесты настраиваются отдельно при помощи директивы [match](#match) и указываются в параметре `match` директивы [health\_check](#health_check).

健康檢查可以測試從伺服器接收的資料。這些測試使用 [match](#match)指令單獨配置，並在 [health\_check](#health_check)指令的`match`參數中指定。

#### Директивы｜指令

|   |   |
| --- | --- |
| Синтаксис:<br>語法： | ``**health_check** [`*параметры*`];``<br>` `**health_check** [` *參數* `];` ` |
| Умолчание:<br>預設值： | — |
| Контекст:<br>背景： | `server` |

Активирует периодические проверки работоспособности серверов в [группе](#upstream).

啟用對 [群組](#upstream)中的伺服器的定期健康檢查。

Могут быть заданы следующие необязательные параметры:

可指定以下可選參數：

`interval`\=`*время*`

задаёт интервал между двумя последовательными проверками, по умолчанию 5 секунд.

設定兩次連續檢查之間的間隔，預設值為 5 秒。

`jitter`\=`*время*`

задаёт время, в пределах которого случайным образом задерживается каждая проверка, по умолчанию задержки нет.

指定每次檢查隨機延遲的時間；預設情況下，沒有延遲。

`fails`\=`*число*`

задаёт число последовательных неуспешных проверок для определённого сервера, после которых сервер будет считаться неработоспособным, по умолчанию 1.

指定給定伺服器連續檢查失敗的次數，超過該次數後伺服器將被視為不健康，預設值為 1。

`passes`\=`*число*`

задаёт число последовательных успешных проверок для определённого сервера, после которых сервер будет считаться работоспособным, по умолчанию 1.

指定對給定伺服器連續成功檢查的次數，超過該次數後伺服器將被視為健康，預設值為 1。

`mandatory` \[`persistent`\]

устанавливает исходное состояние “checking” для сервера до завершения первой проверки работоспособности (1.11.7). На серверы в состоянии “checking” клиентские соединения передаваться не будут. Если параметр не указан, то исходно сервер будет считаться работоспособным.

將伺服器的初始狀態設定為“檢查中”，直到首次健康檢查 ( 1.11.7 ) 完成。客戶端連線將不會被轉送到處於「檢查中」狀態的伺服器。如果省略此參數，則伺服器初始狀態將被視為健康。

Параметр `persistent` (1.21.1) устанавливает исходное состояние “up” для сервера после перезагрузки nginx в случае, если до перезагрузки сервер считался работоспособным.

如果伺服器在重新啟動前被認為是健康的，則`persistent` ( 1.21.1 ) 參數會在 nginx 重新啟動後設定伺服器的初始「運行」狀態。

`match`\=`*имя*`

указывает на блок `match` с условиями, которым должно удовлетворять соединение, чтобы результат проверки считался успешным. По умолчанию для TCP проверяется лишь возможность установки TCP-соединения с сервером, для [UDP](#health_check_udp) проверяется отсутствие сообщения ICMP “`Destination Unreachable`” в ответ на отправленную строку “`nginx health check`”.

指向`match`程式碼區塊，其中包含連接必須滿足的條件，才能判定檢查成功。預設情況下，對於 TCP，僅檢查能否與伺服器建立 TCP 連線；對於 [UDP](#health_check_udp)則檢查是否收到對發送的「 `nginx health check` 」字串的 ICMP “ `Destination Unreachable` ” 訊息的回應。

> До версии 1.11.7 по умолчанию для UDP требовалось наличие блока [match](#hc_match) с параметрами [send](#match_send) и [expect](#match_expect).
>
> 在1.11.7 UDP的預設行為是具有 [match](#hc_match)塊，以及 [send](#match_send)和 [expect](#match_expect)參數。

`port`\=`*число*`

задаёт порт, используемый при подключении к серверу для проверки его работоспособности (1.9.7). По умолчанию совпадает с портом [сервера](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>).

指定連接到伺服器以檢查其功能時使用的連接埠（ 1.9.7 ）。預設情況下，它與[伺服器連接埠](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)匹配。

`udp`

указывает, что для проверки работоспособности будет использоваться протокол `UDP` вместо протокола `TCP`, используемого по умолчанию (1.9.13).

指定使用`UDP`協議進行健康檢查，而不是預設的`TCP`協議（ 1.9.13 ）。

Переопределяет значение [proxy\_timeout](<307 [02.01.04 溪流] 模組 ngx_stream_proxy_module.md#proxy_timeout>) для проверок работоспособности.

覆蓋健康檢查的 [proxy\_timeout](<307 [02.01.04 溪流] 模組 ngx_stream_proxy_module.md#proxy_timeout>)值。

|   |   |
| --- | --- |
| Синтаксис:<br>文法： | ``**match** `*имя*` { ... }``<br>` `**match** ` *名稱* ` { ... }` ` |
| Умолчание:<br>預設值： | — |
| Контекст:<br>背景： | `stream` |

Задаёт именованный набор тестов для для анализа ответов сервера на запросы проверки работоспособности.

指定一組用於分析伺服器對健康檢查請求的回應的測試案例。

Могут быть заданы следующие параметры:

可設定以下參數：

`send` `*строка*`;

отправляет `*строку*` на сервер;

向伺服器發送`*строку*` ；

`expect` `*стока*` | `~` `*regex*`;

текстовая строка (1.9.12) или регулярное выражение, которым должны соответствовать данные, полученные с сервера. Регулярное выражение задаётся либо с модификатором “`~*`” (для поиска совпадения без учёта регистра символов), либо с модификатором “`~`” (с учётом регистра).

一個文字字串（ 1.9.12 ）或正規表示式，伺服器接收到的資料必須與之相符。正規表示式可以用「 `~*` 」修飾符（用於不區分大小寫的匹配）或「 `~` 」修飾符（用於區分大小寫的匹配）來指定。

Параметры `send` и `expect` могут содержать строки в шестнадцатеричном виде с префиксом “`\x`” и последующими двумя шестнадцатеричными цифрами, например “`\x80`” (1.9.12).

`send`和`expect`參數可以包含十六進位格式的字串，前綴為“ `\x` ”，後面跟著兩個十六進位數字，例如“ `\x80` ”（ 1.9.12 ）。

Проверка работоспособности считается успешной, если

如果滿足以下條件，則功能檢查被視為成功：

-   TCP-соединение успешно установлено;  
    TCP - 連線成功建立；
-   `*строка*` из параметра `send` была отправлена (если была задана);  
    已發送參數`send`中的`*строка*` （如果已設定）；
-   данные, полученные от сервера, совпали со строкой или регулярным выражением из параметра `expect` (если был задан);  
    從伺服器接收的資料與`expect`參數（如果指定）中的字串或正規表示式相符；
-   истёкшее время не превышает значение, указанное в директиве [health\_check\_timeout](#health_check_timeout).  
    經過的時間沒有超過 [health\_check\_timeout](#health_check_timeout)指令中指定的值。

Пример:

例子：

> ```
> upstream backend {
>
> 上游後端{
>     zone     upstream_backend 10m;
>
>     上游後端區域 10 公尺；
>     server   127.0.0.1:12345;
>
>     伺服器127.0.0.1:12345 ;
> }
> 
> match http {
>
> 匹配 http {
>     send     "GET / HTTP/1.0\r\nHost: localhost\r\n\r\n";
>
>     發送“ GET / HTTP/1.0 \r\n主機：localhost\r\n\r\n”；
>     expect ~ "200 OK";
>
>     預計~「200 OK 」；
> }
> 
> server {
>
> 伺服器{
>     listen       12346;
>
>     聽 12346；
>     proxy_pass   backend;
>
>     proxy_pass 後端；
>     health_check match=http;
>
>     健康檢查匹配=http；
> }
> ```

> Проверяются лишь первые байты данных [proxy\_buffer\_size](<307 [02.01.04 溪流] 模組 ngx_stream_proxy_module.md#proxy_buffer_size>), полученные от сервера.
>
> 僅檢查從伺服器接收的前 [proxy\_buffer\_size](<307 [02.01.04 溪流] 模組 ngx_stream_proxy_module.md#proxy_buffer_size>)位元組的資料。
