#### Name-based virtual servers｜基於名稱的虛擬伺服器

nginx first decides which *server* should process the request. Let’s start with a simple configuration where all three virtual servers listen on port \*:80:

nginx 首先決定由哪個伺服器處理請求。我們先來看一個簡單的配置，其中三個虛擬伺服器都監聽 \*:80 連接埠：

> ```
> server {
>
> 伺服器 {
>     listen      80;
>
>     聽 80；
>     server_name example.org www.example.org;
>
>     伺服器名稱 example.org www.example.org;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      80;
>
>     聽 80；
>     server_name example.net www.example.net;
>
>     伺服器名稱 example.net www.example.net;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      80;
>
>     聽 80；
>     server_name example.com www.example.com;
>     ...
> }
> ```

In this configuration nginx tests only the request’s header field “Host”（主持人） to determine which server the request should be routed to. If its value does not match any server name, or the request does not contain this header field at all, then nginx will route the request to the default server for this port. In the configuration above, the default server is the first one — which is nginx’s standard default behaviour. It can also be set explicitly which server should be default, with the `default_server` parameter in the [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>) directive:

在此配置中，nginx 僅檢查請求頭中的“Host”（主持人）欄位來決定請求應路由到哪個伺服器。如果其值與任何伺服器名稱都不匹配，或者請求根本不包含此請求頭字段，則 nginx 會將請求路由到該連接埠的預設伺服器。在上面的設定中，預設伺服器是第一個伺服器——這是 nginx 的標準預設行為。也可以在 [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>)指令中使用`default_server`參數明確設定預設伺服器：

> ```
> server {
>
> 伺服器 {
>     listen      80 default_server;
>
>     監聽 80 埠預設伺服器；
>     server_name example.net www.example.net;
>
>     伺服器名稱 example.net www.example.net;
>     ...
> }
> ```

> The `default_server` parameter has been available since version 0.8.21. In earlier versions the `default` parameter should be used instead.
>
> `default_server`參數自0.8.21版本起可用。在早期版本中，應使用`default`參數。

Note that the default server is a property of the listen port and not of the server name. More about this later.

請注意，預設伺服器是監聽連接埠的屬性，而不是伺服器名稱的屬性。稍後會詳細介紹。

#### How to prevent processing requests with undefined server names｜如何防止處理包含未定義伺服器名稱的請求

If requests without the “Host”（主持人） header field should not be allowed, a server that just drops the requests can be defined:

如果不應該允許缺少“Host”（主持人）標頭欄位的請求，可以定義一個直接丟棄這些請求的伺服器：

> ```
> server {
>
> 伺服器 {
>     listen      80;
>
>     聽 80；
>     server_name "";
>
>     伺服器名稱“”；
>     return      444;
>
>     返回 444；
> }
> ```

Here, the server name is set to an empty string that will match requests without the “Host”（主持人） header field, and a special nginx’s non-standard code 444 is returned that closes the connection.

在這裡，伺服器名稱被設定為空字串，這將匹配沒有“Host”（主持人）標頭欄位的請求，並傳回一個特殊的 nginx 非標準代碼 444，以關閉連線。

> Since version 0.8.48, this is the default setting for the server name, so the `server_name ""` can be omitted. In earlier versions, the machine’s *hostname* was used as a default server name.
>
> 自版本0.8.48起，伺服器名稱的預設設定已啟用，因此可以省略`server_name ""` 。在早期版本中，預設伺服器名稱使用機器的*主機名稱*。

#### Mixed name-based and IP-based virtual servers｜混合基於名稱和IP的虛擬伺服器

Let’s look at a more complex configuration where some virtual servers listen on different addresses:

讓我們來看一個更複雜的配置，其中一些虛擬伺服器監聽不同的位址：

> ```
> server {
>
> 伺服器 {
>     listen      192.168.1.1:80;
>
>     列表192.168.1.1:80 ;
>     server_name example.org www.example.org;
>
>     伺服器名稱 example.org www.example.org;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      192.168.1.1:80;
>
>     聽192.168.1.1:80 ;
>     server_name example.net www.example.net;
>
>     伺服器名稱 example.net www.example.net;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      192.168.1.2:80;
>
>     聽192.168.1.2:80 ;
>     server_name example.com www.example.com;
>     ...
> }
> ```

In this configuration, nginx first tests the IP address and port of the request against the [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>) directives of the [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) blocks. It then tests the “Host”（主持人） header field of the request against the [server\_name](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_name>) entries of the [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) blocks that matched the IP address and port. If the server name is not found, the request will be processed by the default server. For example, a request for `www.example.com` received on the 192.168.1.1:80 port will be handled by the default server of the 192.168.1.1:80 port, i.e., by the first server, since there is no `www.example.com` defined for this port.

在此設定中，nginx 首先IP請求的位址和連接埠與 [server] 區塊中的 [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>)進行比對。然後，它將請求的“Host”（主持人）欄位與 [server] 區塊中匹配IP和連接埠的 [ (https://nginx.org/en/docs/http/ngx_http_core_module.html#server_name)  條目](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>)比對。如果找不到符合的伺服器名稱，則請求將由預設伺服器處理。例如， `www.example.com`收到對192.168.1.1:80的請求(https://nginx.org/en/docs/http/ngx_http_core_module.html#server)則該請求將由連接埠的192.168.1.1:80伺服器（即第一個伺服器）處理，因為該連接埠沒有定義`www.example.com`伺服器。

As already stated, a default server is a property of the listen port, and different default servers may be defined for different ports:

如前所述，預設伺服器是監聽連接埠的一個屬性，不同的連接埠可以定義不同的預設伺服器：

> ```
> server {
>
> 伺服器 {
>     listen      192.168.1.1:80;
>
>     聽192.168.1.1:80 ;
>     server_name example.org www.example.org;
>
>     伺服器名稱 example.org www.example.org;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      192.168.1.1:80 default_server;
>
>     監聽192.168.1.1:80預設伺服器；
>     server_name example.net www.example.net;
>
>     伺服器名稱 example.net www.example.net;
>     ...
> }
> 
> server {
>
> 伺服器 {
>     listen      192.168.1.2:80 default_server;
>
>     監聽192.168.1.2:80預設伺服器；
>     server_name example.com www.example.com;
>     ...
> }
> ```

#### A simple PHP site configuration｜一個簡單的PHP站點配置

Now let’s look at how nginx chooses a *location* to process a request for a typical, simple PHP site:

現在讓我們來看看nginx如何為一個典型的、簡單的PHP網站選擇一個*location*來處理請求：

> ```
> server {
>
> 伺服器 {
>     listen      80;
>
>     聽 80；
>     server_name example.org www.example.org;
>
>     伺服器名稱 example.org www.example.org;
>     root        /data/www;
>
>     根目錄 /data/www;
> 
>     location / {
>
>     地點 / {
>         index   index.html index.php;
>
>         index index.html index.php;
>     }
> 
>     location ~* \.(gif|jpg|png)$ {
>         expires 30d;
>
>         有效期限30天；
>     }
> 
>     location ~ \.php$ {
>         fastcgi_pass  localhost:9000;
>
>         fastcgi_pass localhost:9000;
>         fastcgi_param SCRIPT_FILENAME
>
>         fastcgi_param 腳本檔名
>                       $document_root$fastcgi_script_name;
>         include       fastcgi_params;
>
>         包含 fastcgi_params；
>     }
> }
> ```

nginx first searches for the most specific prefix location given by literal strings regardless of the listed order. In the configuration above the only prefix location is “`/`” and since it matches any request it will be used as a last resort. Then nginx checks locations given by regular expression in the order listed in the configuration file. The first matching expression stops the search and nginx will use this location. If no regular expression matches a request, then nginx uses the most specific prefix location found earlier.

nginx 首先會搜尋由字串字面值指定的最具體的前綴位置，而不管其列出的順序為何。在上面的配置中，唯一的前綴位置是“ `/` ”，由於它匹配任何請求，因此將作為最後的選擇。然後，nginx 會按照設定檔中列出的順序檢查正規表示式指定的位置。第一個匹配的表達式將停止搜索，nginx 將使用該位置。如果沒有正規表示式來符合任何請求，則 nginx 將使用先前找到的最具體的前綴位置。

Note that locations of all types test only a URI part of request line without arguments. This is done because arguments in the query string may be given in several ways, for example:

請注意，所有類型的位置僅測試請求行中不帶參數的部分URI 。這是因為查詢字串中的參數可以透過多種方式提供，例如：

> ```
> /index.php?user=john&page=1
> /index.php?page=1&user=john
> ```

Besides, anyone may request anything in the query string:

此外，任何人都可以在查詢字串中請求任何內容：

> ```
> /index.php?page=1&something+else&user=john
> ```

Now let’s look at how requests would be processed in the configuration above:

現在讓我們來看看在上述配置下請求將如何處理：

-   A request “`/logo.gif`” is matched by the prefix location “`/`” first and then by the regular expression “`\.(gif|jpg|png)$`”, therefore, it is handled by the latter location. Using the directive “`root /data/www`” the request is mapped to the file `/data/www/logo.gif`, and the file is sent to the client.  
    請求“ `/logo.gif` ”首先與前綴位置“ `/` ”匹配，然後與正則表達式“ `\.(gif|jpg|png)$` ”匹配，因此，它由後一個位置處理。使用指令“ `root /data/www` ”，該請求被對應到檔案`/data/www/logo.gif` ”，並將該檔案傳送給客戶端。
-   A request “`/index.php`” is also matched by the prefix location “`/`” first and then by the regular expression “`\.(php)$`”. Therefore, it is handled by the latter location and the request is passed to a FastCGI server listening on localhost:9000. The [fastcgi\_param](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_param>) directive sets the FastCGI parameter `SCRIPT_FILENAME` to “`/data/www/index.php`”, and the FastCGI server executes the file. The variable `$document_root` is equal to the value of the [root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>) directive and the variable `$fastcgi_script_name` is equal to the request URI, i.e. “`/index.php`”.  
    請求“ `/index.php` ”首先匹配前綴位置“ `/` ”，然後匹配正規表示式“ `\.(php)$` ”。因此，它由後一個位置處理，並將請求傳遞給監聽 localhost:9000 的 FastCGI 伺服器。 [fastcgi\_param](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_param>)指令將 FastCGI 參數`SCRIPT_FILENAME`設定為“ `/data/www/index.php` ”，FastCGI 伺服器執行此檔案。變數`$document_root`等於 [root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>)指令的值，變數`$fastcgi_script_name`等於請求URI ，即「 `/index.php` 」。
-   A request “`/about.html`” is matched by the prefix location “`/`” only, therefore, it is handled in this location. Using the directive “`root /data/www`” the request is mapped to the file `/data/www/about.html`, and the file is sent to the client.  
    請求“ `/about.html` ”僅與前綴位置“ `/` ”匹配，因此，它將在該位置處理。使用指令“ `root /data/www` ”，該請求被對應到檔案`/data/www/about.html` ，並將該檔案傳送給客戶端。
-   Handling a request “`/`” is more complex. It is matched by the prefix location “`/`” only, therefore, it is handled by this location. Then the [index](<071 [01.01.03 http] 模組 ngx_http_index_module.md#index>) directive tests for the existence of index files according to its parameters and the “`root /data/www`” directive. If the file `/data/www/index.html` does not exist, and the file `/data/www/index.php` exists, then the directive does an internal redirect to “`/index.php`”, and nginx searches the locations again as if the request had been sent by a client. As we saw before, the redirected request will eventually be handled by the FastCGI server.  
    處理請求「 `/` 」更為複雜。它僅與前綴位置“ `/` ”匹配，因此由該位置處理。然後，[index](<071 [01.01.03 http] 模組 ngx_http_index_module.md#index>)指令會根據其參數和「 `root /data/www` 」指令檢查索引檔案是否存在。如果檔案「 `/data/www/index.html` 」不存在，而檔案`/data/www/index.php` 」存在，則該指令會將請求內部重定向到“ `/index.php` ”，nginx 會再次搜尋這些位置，就好像該請求是由客戶端發送的一樣。如前所述，重定向後的請求最終將由 FastCGI 伺服器處理。
