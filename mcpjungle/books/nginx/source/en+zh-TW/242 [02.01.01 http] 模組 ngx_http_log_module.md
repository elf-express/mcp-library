Модуль `ngx_http_log_module` записывает логи запросов в указанном формате.

`ngx_http_log_module`模組以指定的格式寫入請求日誌。

Логи записываются в контексте location’а, где заканчивается обработка. Это может быть location, отличный от первоначального, если в процессе обработки запроса происходит [внутреннее перенаправление](<221 [02.01.01 http] 模組 ngx_http_core_module.md#internal>).

日誌會寫入處理結束的位置。如果在請求處理過程中發生[內部重定向](<221 [02.01.01 http] 模組 ngx_http_core_module.md#internal>) ，則此位置可能與原始位置不同。

#### Пример конфигурации｜配置範例

> ```
> log_format compression '$remote_addr - $remote_user [$time_local] '
>                        '"$request" $status $bytes_sent '
>                        '"$http_referer" "$http_user_agent" "$gzip_ratio"';
> 
> access_log /spool/logs/nginx-access.log compression buffer=32k;
>
> access_log /spool/logs/nginx-access.log 壓縮緩衝區=32k;
> ```

Задаёт путь, формат и настройки буферизованной записи в лог. На одном уровне конфигурации может использоваться несколько логов. Запись в [syslog](<321 [02.01 文件] 寫入系統日誌.md>) настраивается указанием префикса “`syslog:`” в первом параметре. Специальное значение `off` отменяет все директивы `access_log` для текущего уровня. Если формат не указан, то используется предопределённый формат “`combined`”.

指定緩衝日誌的路徑、格式和設定。單一配置等級可以使用多個日誌。透過在第一個參數中指定「 `syslog:` 」前綴，可以設定日誌記錄到 [syslog](<321 [02.01 文件] 寫入系統日誌.md>) 。特殊值`off`會覆寫目前層級的所有`access_log`指令。如果未指定格式，則使用預先定義的「 `combined` 」格式。

Если задан размер буфера с помощью параметра `buffer` или указан параметр `gzip` (1.3.10, 1.2.7), то запись будет буферизованной.

如果使用`buffer`參數指定緩衝區大小，或指定`gzip` ( 1.3.10, 1.2.7 ) 參數，則錄製內容將會被緩衝。

> Размер буфера должен быть не больше размера атомарной записи в дисковый файл. Для FreeBSD этот размер неограничен.
>
> 緩衝區大小不得大於原子寫入磁碟檔案的大小。在 FreeBSD 系統中，此大小沒有限制。

При включённой буферизации данные записываются в файл:

啟用緩衝後，資料將寫入檔案：

-   если очередная строка лога не помещается в буфер;  
    如果下一行日誌無法放入緩衝區；
-   если данные в буфере находятся дольше интервала времени, заданного параметром `flush` (1.3.10, 1.2.7);  
    若緩衝區中的資料長度超過參數`flush` ( 1.3.10, 1.2.7 ) 指定的時間間隔；
-   при [переоткрытии](<204 [02.01 文件] nginx 管理.md>) лог-файла или завершении рабочего процесса.  
    當[重新開啟](<204 [02.01 文件] nginx 管理.md>)日誌檔案或終止工作流程。

Если задан параметр `gzip`, то буфер будет сжиматься перед записью в файл. Степень сжатия может быть задана в диапазоне от 1 (быстрее, но хуже сжатие) до 9 (медленнее, но лучше сжатие). По умолчанию используются буфер размером 64К байт и степень сжатия 1. Данные сжимаются атомарными блоками, и в любой момент времени лог-файл может быть распакован или прочитан с помощью утилиты “`zcat`”.

如果指定了`gzip`參數，則緩衝區在寫入檔案之前會進行壓縮。壓縮等級可設定為 1（速度較快，但壓縮率較低）到 9（速度較慢，但壓縮率較高）。預設值為 64KB 緩衝區和 1 的壓縮等級。資料以原子塊進行壓縮，可使用「 `zcat` 」公用程式隨時解壓縮或讀取日誌檔。

Пример:

例子：

> ```
> access_log /path/to/log.gz combined gzip flush=5m;
> ```

> Для поддержки gzip-сжатия логов nginx должен быть собран с библиотекой zlib.
>
> 為了支援日誌的 gzip 壓縮，nginx 必須使用 zlib 函式庫進行建置。

В пути файла можно использовать переменные (0.7.6+), но такие логи имеют некоторые ограничения:

您可以在檔案路徑中使用變數（ 0.7.6 +），但此類日誌存在一些限制：

-   [пользователь](<285 [02.01 文件] 基本功能.md#user>), с правами которого работают рабочие процессы, должен иметь права на создание файлов в каталоге с такими логами;  
    [用戶](<285 [02.01 文件] 基本功能.md#user>) ，即工作進程在其權限下運行的用戶，必須擁有在包含此類日誌的目錄中創建文件的權限；
-   не работает буферизация;  
    緩衝功能不起作用；
-   файл открывается для каждой записи в лог и сразу же после записи закрывается. Следует однако иметь в виду, что поскольку дескрипторы часто используемых файлов могут храниться в [кэше](#open_log_file_cache), то при вращении логов в течение времени, заданного параметром `valid` директивы [open\_log\_file\_cache](#open_log_file_cache), запись может продолжаться в старый файл.  
    每次記錄日誌時都會開啟該文件，並在記錄結束後立即關閉。但是，需要注意的是，由於常用的檔案描述子可以儲存在 [cache](#open_log_file_cache)中，因此，當依照 [open\_log\_file\_cache](#open_log_file_cache)指令的`valid`參數指定的時間輪替日誌時，可能會繼續寫入舊檔案。
-   при каждой записи в лог проверяется существование [корневого каталога](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>) для запроса — если этот каталог не существует, то лог не создаётся. Поэтому [root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>) и `access_log` нужно описывать на одном уровне конфигурации:  
    每次寫入日誌條目時，都會檢查請求的 [root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>)是否存在－如果目錄不存在，則不會建立日誌。因此，[root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>)和`access_log`應該在同一配置層級進行描述：
    
    > ```
    > server {
    >
    > 伺服器 {
    >     root       /spool/vhost/data/$host;
    >
    >     root /spool/vhost/data/$host;
    >     access_log /spool/vhost/logs/$host;
    >
    >     存取日誌 /spool/vhost/logs/$host;
    >     ...
    > ```
    

Параметр `if` (1.7.0) включает условную запись в лог. Запрос не будет записываться в лог, если результатом вычисления `*условия*` является “0” или пустая строка. В следующем примере запросы с кодами ответа 2xx и 3xx не будут записываться в лог:

`if` ( 1.7.0 ) 參數啟用條件日誌記錄。如果`*условия*`評估結果為「0」或空字串，則不會記錄該請求。在以下範例中，回應代碼為 2xx 和 3xx 的請求將不會被記錄：

> ```
> map $status $loggable {
>
> 映射 $status $loggable {
>     ~^[23]  0;
>     default 1;
>
>     預設值為 1；
> }
> 
> access_log /path/to/access.log combined if=$loggable;
>
> access_log /path/to/access.log 合併 if=$loggable;
> ```

Задаёт формат лога.

指定日誌格式。

Параметр `escape` (1.11.8) позволяет задать экранирование символов `json` или `default` в переменных, по умолчанию используется `default`. Значение `none` (1.13.10) отключает экранирование символов.

參數`escape` （ 1.11.8 ）可讓您指定變數中字元`json`或`default`的轉義方式；預設使用`default` 。值`none` （ 1.13.10 ）禁用字元轉義。

При использовании `default` символы “`"`”, “`\`”, a также символы со значениями меньше 32 (0.7.0) или больше 126 (1.1.6) экранируются как “`\xXX`”. Если значение переменной не найдено, то в качестве значения в лог будет записываться дефис (“`-`”).

使用`default`字元「 `"` 」、「 `\` 」以及值小於 32 ( 0.7.0 ) 或大於 126 ( 1.1.6 ) 的字元將被轉義為「 `\xXX` 」。如果找不到變數值，則會在日誌中寫入連字符（“ `-` ”）作為該值。

При использовании `json` экранируются все символы, недопустимые в JSON [строках](https://datatracker.ietf.org/doc/html/rfc8259#section-7): символы “`"`” и “`\`” экранируются как “`\"`” и “`\\`”, символы со значениями меньше 32 экранируются как “`\n`”, “`\r`”, “`\t`”, “`\b`”, “`\f`” или “`\u00XX`”.

使用`json`時，所有在JSON [行](https://datatracker.ietf.org/doc/html/rfc8259#section-7)中不允許的字元都會被轉義：字元「 `"` 」和`\\` `\`分別轉義為「 `\"`的字元分別轉義為「 `\n` 」、「 `\r` 」、「 `\t` 」、「 `\b` 」、「 `\f` 」或「 `\u00XX` 」。

Задаёт кэш, в котором хранятся дескрипторы файлов часто используемых логов, имена которых заданы с использованием переменных. Параметры директивы:

指定一個緩存，用於儲存常用日誌的檔案描述符，日誌名稱由變數指定。指令參數：

`max`

задаёт максимальное число дескрипторов в кэше; при переполнении кэша наименее востребованные (LRU) дескрипторы закрываются

設定快取中描述符的最大數量；當快取已滿時，使用最少的（ LRU ）描述符將關閉。

`inactive`

задаёт время, после которого закэшированный дескриптор закрывается, если к нему не было обращений в течение этого времени; по умолчанию 10 секунд

指定快取句柄在多長時間內未被存取後關閉的時間；預設值為 10 秒。

`min_uses`

задаёт минимальное число использований файла в течение времени, заданного параметром `inactive`, после которого дескриптор файла будет оставаться открытым в кэше; по умолчанию 1

設定檔在`inactive`指定的時間內可以最少被使用的次數，超過該次數後，檔案句柄將保持在快取中的開啟狀態；預設值為1。

`valid`

задаёт, через какое время нужно проверять, что файл ещё существует под тем же именем; по умолчанию 60 секунд

指定在檢查同名檔案是否仍存在之前等待的時間；預設值為 60 秒。

`off`

запрещает кэш

禁用快取

Пример использования:

使用範例：

> ```
> open_log_file_cache max=1000 inactive=20s valid=1m min_uses=2;
> ```
