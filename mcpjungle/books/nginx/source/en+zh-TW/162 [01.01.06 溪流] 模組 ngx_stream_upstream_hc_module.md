The `ngx_stream_upstream_hc_module` module (1.9.0) allows enabling periodic health checks of the servers in a [group](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#upstream>). The server group must reside in the [shared memory](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#zone>).

`ngx_stream_upstream_hc_module`模組 ( 1.9.0 ) 允許對 [群組](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#upstream>)中的伺服器進行定期健康檢查。伺服器群組必須位於 [共享記憶體](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#zone>)中。

If a health check fails, the server will be considered unhealthy. If several health checks are defined for the same group of servers, a single failure of any check will make the corresponding server be considered unhealthy. Client connections are not passed to unhealthy servers and servers in the “checking” state.

如果健康檢查失敗，伺服器將被視為不健康。如果為同一組伺服器定義了多個健康檢查，則任何一個檢查失敗都會導致相應的伺服器被視為不健康。客戶端連線不會傳遞給不健康的伺服器和處於「檢查中」狀態的伺服器。

> This module is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Example Configuration｜範例配置

> ```
> upstream tcp {
>
> 上游 TCP {
>     zone upstream_tcp 64k;
>
>     區域 upstream_tcp 64k；
> 
>     server backend1.example.com:12345 weight=5;
>
>     伺服器 backend1.example.com:12345 weight=5;
>     server backend2.example.com:12345 fail_timeout=5s slow_start=30s;
>     server 192.0.2.1:12345            max_fails=3;
>
>     伺服器192.0.2.1:12345 max_fails=3;
> 
>     server backup1.example.com:12345  backup;
>
>     伺服器 backup1.example.com:12345 備份;
>     server backup2.example.com:12345  backup;
>
>     伺服器 backup2.example.com:12345 備份;
> }
> 
> server {
>
> 伺服器 {
>     listen     12346;
>
>     聽 12346；
>     proxy_pass tcp;
>     health_check;
>
>     健康檢查；
> }
> ```

With this configuration, nginx will check the ability to establish a TCP connection to each server in the `tcp` group every five seconds. When a connection to the server cannot be established, the health check will fail, and the server will be considered unhealthy.

在此配置下，nginx 將每五秒鐘檢查一次與`tcp`組中的每個伺服器建立TCP連接的能力。如果無法與伺服器建立連接，則健康檢查失敗，伺服器將被視為不健康。

Health checks can be configured for the UDP protocol:

可以對UDP協議配置健康檢查：

> ```
> upstream dns_upstream {
>
> 上游 dns_upstream {
> 
>     zone   dns_zone 64k;
>
>     區域 dns_zone 64k；
> 
>     server dns1.example.com:53;
>
>     伺服器 dns1.example.com:53;
>     server dns2.example.com:53;
>
>     伺服器 dns2.example.com:53;
>     server dns3.example.com:53;
>
>     伺服器 dns3.example.com:53;
> }
> 
> server {
>
> 伺服器 {
>     listen       53 udp;
>
>     列表 53 UDP；
>     proxy_pass   dns_upstream;
>
>     proxy_pass dns_upstream;
>     health_check udp;
>
>     健康檢查 UDP；
> }
> ```

In this case, the absence of ICMP “`Destination Unreachable`” message is expected in reply to the sent string “`nginx health check`”.

在這種情況下，對於發送的字串“ `nginx health check` ”，預期不會收到“ ICMP “ `Destination Unreachable` ””訊息的回應。

Health checks can also be configured to test data obtained from the server. Tests are configured separately using the [match](#match) directive and referenced in the `match` parameter of the [health\_check](#health_check) directive.

健康檢查還可以配置為測試從伺服器取得的資料。測試使用 [match](#match)指令單獨配置，並在 [health\_check](#health_check)指令的`match`參數中引用。

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**health_check** [`*parameters*`];``<br>` `**health_check** [` *參數* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `server` |

Enables periodic health checks of the servers in a [group](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#upstream>).

啟用對 [群組](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#upstream>)中的伺服器進行定期健康檢查。

The following optional parameters are supported:

支援以下可選參數：

`interval`\=`*time*`

sets the interval between two consecutive health checks, by default, 5 seconds.

設定兩次連續健康檢查之間的間隔，預設值為 5 秒。

`jitter`\=`*time*`

sets the time within which each health check will be randomly delayed, by default, there is no delay.

設定每次健康檢查隨機延遲的時間範圍，預設沒有延遲。

`fails`\=`*number*`

sets the number of consecutive failed health checks of a particular server after which this server will be considered unhealthy, by default, 1.

設定特定伺服器連續健康檢查失敗的次數，超過該次數後，該伺服器將被視為不健康，預設值為 1。

`passes`\=`*number*`

sets the number of consecutive passed health checks of a particular server after which the server will be considered healthy, by default, 1.

設定特定伺服器連續通過健康檢查的次數，超過該次數後，伺服器將被視為健康，預設值為 1。

`mandatory` \[`persistent`\]

sets the initial “checking” state for a server until the first health check is completed (1.11.7). Client connections are not passed to servers in the “checking” state. If the parameter is not specified, the server will be initially considered healthy.

設定伺服器的初始「檢查」狀態，直到首次健康檢查完成（ 1.11.7 ）。客戶端連線不會傳遞給處於「檢查」狀態的伺服器。如果未指定此參數，則伺服器初始狀態將被視為健康。

The `persistent` parameter (1.21.1) sets the initial “up” state for a server after reload if the server was considered healthy before reload.

`persistent`參數 ( 1.21.1 ) 設定伺服器在重新載入後的初始「運行」狀態（如果伺服器在重新載入之前被認為是健康的）。

`match`\=`*name*`

specifies the `match` block configuring the tests that a successful connection should pass in order for a health check to pass. By default, for TCP, only the ability to establish a TCP connection with the server is checked. For [UDP](#health_check_udp), the absence of ICMP “`Destination Unreachable`” message is expected in reply to the sent string “`nginx health check`”.

`match`程式碼區塊用於配置成功連接必須通過的測試，才能通過健康檢查。預設情況下，對於TCP ，僅檢查能否與伺服器建立TCP連線。對於 [UDP](#health_check_udp) ，預期在發送的字符串“ `nginx health check` ”的回復中不存在ICMP “ `Destination Unreachable` ” 訊息。

> Prior to version 1.11.7, by default, UDP health check required a [match](#hc_match) block with the [send](#match_send) and [expect](#match_expect) parameters.
>
> 在版本1.11.7之前，預設情況下， UDP健康檢查需要一個 [match](#hc_match)塊，其中包含 [send](#match_send)和 [expect](#match_expect)參數。

`port`\=`*number*`

defines the port used when connecting to a server to perform a health check (1.9.7). By default, equals the [server](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#server>) port.

定義連接到伺服器執行健康檢查時使用的連接埠（ 1.9.7 ）。預設情況下，等於 [伺服器](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#server>)連接埠。

`udp`

specifies that the `UDP` protocol should be used for health checks instead of the default `TCP` protocol (1.9.13).

指定應使用`UDP`協議進行健康檢查，而不是預設的`TCP`協議（ 1.9.13 ）。

Overrides the [proxy\_timeout](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_timeout>) value for health checks.

覆蓋健康檢查的 [proxy\_timeout](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_timeout>)值。

|   |   |
| --- | --- |
| Syntax:<br>文法： | ``**match** `*name*` { ... }``<br>` `**match** ` *名稱* ` { ... }` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `stream` |

Defines the named test set used to verify server responses to health checks.

定義用於驗證伺服器對健康檢查的回應的命名測試集。

The following parameters can be configured:

可配置以下參數：

`send` `*string*`;

sends a `*string*` to the server;

向伺服器發送`*string*` ；

`expect` `*string*` | `~` `*regex*`;

a literal string (1.9.12) or a regular expression that the data obtained from the server should match. The regular expression is specified with the preceding “`~*`” modifier (for case-insensitive matching), or the “`~`” modifier (for case-sensitive matching).

一個字面字串（ 1.9.12 ）或一個正規表示式，用於匹配從伺服器取得的資料。正規表示式前面有「 `~*` 」修飾符（用於不區分大小寫的匹配），或「 `~` 」修飾符（用於區分大小寫的匹配）。

Both `send` and `expect` parameters can contain hexadecimal literals with the prefix “`\x`” followed by two hex digits, for example, “`\x80`” (1.9.12).

`send`和`expect`參數都可以包含以「 `\x` 」為前綴，後面跟著兩個十六進位數字的十六進位文字，例如「 `\x80` 」（ 1.9.12 ）。

Health check is passed if:

健康檢查合格的標準為：

-   the TCP connection was successfully established;  
    TCP連線已成功建立；
-   the `*string*` from the `send` parameter, if specified, was sent;  
    如果指定了參數`send` ，則發送`*string*` ；
-   the data obtained from the server matched the string or regular expression from the `expect` parameter, if specified;  
    如果指定了`expect`參數，則從伺服器獲得的資料與該參數中的字串或正規表示式相符；
-   the time elapsed does not exceed the value specified in the [health\_check\_timeout](#health_check_timeout) directive.  
    經過的時間不超過 [health\_check\_timeout](#health_check_timeout)指令中指定的值。

Example:

例子：

> ```
> upstream backend {
>
> 上游後端 {
>     zone     upstream_backend 10m;
>
>     上游後端區域 10 公尺；
>     server   127.0.0.1:12345;
>
>     伺服器127.0.0.1:12345 ;
> }
> 
> match http {
>
> 匹配 http {
>     send     "GET / HTTP/1.0\r\nHost: localhost\r\n\r\n";
>
>     發送“ GET / HTTP/1.0 \r\n主機：localhost\r\n\r\n”；
>     expect ~ "200 OK";
>
>     預計~「200 OK 」；
> }
> 
> server {
>
> 伺服器 {
>     listen       12346;
>
>     聽 12346；
>     proxy_pass   backend;
>
>     proxy_pass 後端；
>     health_check match=http;
>
>     健康檢查匹配=http；
> }
> ```

> Only the first [proxy\_buffer\_size](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_buffer_size>) bytes of data obtained from the server are examined.
>
> 僅檢查從伺服器取得的前 [proxy\_buffer\_size](<154 [01.01.06 溪流] 模組 ngx_stream_proxy_module.md#proxy_buffer_size>)位元組的資料。
