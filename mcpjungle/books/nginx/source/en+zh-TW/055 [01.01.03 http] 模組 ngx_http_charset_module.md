## Module ngx\_http\_charset\_module｜模組 ngx_http_charset_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [charset](#charset)<br>     [charset\_map](#charset_map)<br>     [charset\_types](#charset_types)<br>     [override\_charset](#override_charset)<br>     [source\_charset](#source_charset)<br>[範例配置](#example)<br> [指令](#directives)<br> [字符集](#charset)<br> [字符集映射](#charset_types)<br> [字符集(https://nginx.org/en/docs/http/ngx_http_charset_module.html#charset_map)<br> ](#override_charset)<br> [字符集](#source_charset) |

The `ngx_http_charset_module` module adds the specified charset to the “Content-Type”（內容類型） response header field. In addition, the module can convert data from one charset to another, with some limitations:

`ngx_http_charset_module`模組會將指定的字元集加入“Content-Type”（內容類型）響應頭欄位。此外，該模組還可以將資料從一種字元集轉換為另一種字元集，但存在一些限制：

-   conversion is performed one way — from server to client,  
    轉換是單向進行的－從伺服器到客戶端，
-   only single-byte charsets can be converted  
    只能轉換單字節字符集。
-   or single-byte charsets to/from UTF-8.  
    或單字節字元集到/來自UTF -8。

#### Example Configuration｜範例配置

> ```
> include        conf/koi-win;
>
> 包含 conf/koi-win；
> 
> charset        windows-1251;
>
> charset windows-1251;
> source_charset koi8-r;
>
> 來源字元集 koi8-r；
> ```

#### Directives｜指令

<table>
<tr><th>Syntax:<br>語法：</th><td><code><strong>charset<br>字符集</strong> <code><i>charset<br>字符集</i></code> | <code>off<br>關閉</code>;</code></td></tr>
<tr><th>Default:<br>預設值：</th><td>charset off;<br>字元集關閉；</td></tr>
<tr><th>Context:<br>上下文：</th><td><code>http</code>, <code>server<br>伺服器</code>, <code>location<br>位置</code>, <code>if in location<br>如果在位置中</code></td></tr>
</table>

Adds the specified charset to the “Content-Type”（內容類型） response header field. If this charset is different from the charset specified in the [source\_charset](#source_charset) directive, a conversion is performed.

將指定的字元集新增至“Content-Type”（內容類型）響應頭欄位。如果此字元集與 [source\_charset](#source_charset)指令中指定的字元集不同，則會執行轉換。

The parameter `off` cancels the addition of charset to the “Content-Type”（內容類型） response header field.

參數`off`取消將字元集新增至“Content-Type”（內容類型）響應頭字段。

A charset can be defined with a variable:

可以使用變數定義字元集：

> ```
> charset $charset;
>
> 字符集 $charset;
> ```

In such a case, all possible values of a variable need to be present in the configuration at least once in the form of the [charset\_map](#charset_map), [charset](#charset), or [source\_charset](#source_charset) directives. For `utf-8`, `windows-1251`, and `koi8-r` charsets, it is sufficient to include the files `conf/koi-win`, `conf/koi-utf`, and `conf/win-utf` into configuration. For other charsets, simply making a fictitious conversion table works, for example:

在這種情況下，變數的所有可能值都需要在配置中至少出現一次，以 `[charset\_map](#charset_map) 、`[charset](#charset)或 `[source\_charset](#source_charset)指令的形式出現。對於`utf-8`, `windows-1251`和`koi8-r`字元集，只需將檔案`conf/koi-win`, `conf/koi-utf`和`conf/win-utf`包含在設定中即可。對於其他字元集，只需建立一個虛擬的轉換表即可，例如：

> ```
> charset_map iso-8859-5 _ { }
> ```

In addition, a charset can be set in the “X-Accel-Charset”（X-Accel-字元集） response header field. This capability can be disabled using the [proxy\_ignore\_headers](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_ignore_headers>), [fastcgi\_ignore\_headers](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_ignore_headers>), [uwsgi\_ignore\_headers](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_ignore_headers>), [scgi\_ignore\_headers](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_ignore_headers>), and [grpc\_ignore\_headers](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md#grpc_ignore_headers>) directives.

此外，還可以在“X-Accel-Charset”（X-Accel-字元集）響應頭字段中設定字元集。可使用 [proxy\_ignore\_headers](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_ignore_headers>) 、[fastcgi\_ignore\_headers](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_ignore_headers>) 、[uwsgi\_ignore\_headers](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_ignore_headers>) 、[scgi\_ignore\ (https://nginx.org/en/docs/http/ngx_http_scgi_module.html#scgi_ignore_headers) (https://nginx.org/en/docs/http/ngx_http_grpc_module.html#grpc_ignore_headers)指令停用此功能。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**charset_map** `*charset1*` `*charset2*` { ... }``<br>` `**charset_map** ` *字元集1* ` ` *字元集2* ` { ... }` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http` |

Describes the conversion table from one charset to another. A reverse conversion table is built using the same data. Character codes are given in hexadecimal. Missing characters in the range 80-FF are replaced with “`?`”. When converting from UTF-8, characters missing in a one-byte charset are replaced with “`&#XXXX;`”.

描述字符集之間的轉換表。反向轉換表使用相同的資料建構。字元代碼以十六進位表示。 80 到FF範圍內的缺失字元替換為「 `?` 」。從UTF到 8 轉換時，單字節字元集中缺少的字元會替換為「 `&#XXXX;` 」。

Example:

例子：

> ```
> charset_map koi8-r windows-1251 {
>     C0 FE ; # small yu
>
>     C0 FE ; # 小 yu
>     C1 E0 ; # small a
>
>     C1 E0;# 小 a
>     C2 E1 ; # small b
>
>     C2 E1；#小b
>     C3 F6 ; # small ts
>
>     C3 F6；#小ts
>     ...
> }
> ```

When describing a conversion table to UTF-8, codes for the UTF-8 charset should be given in the second column, for example:

在描述到UTF -8的轉換錶時，應在第二列給出UTF -8字元集的代碼，例如：

> ```
> charset_map koi8-r utf-8 {
>     C0 D18E ; # small yu
>
>     C0 D18E ; # 小 yu
>     C1 D0B0 ; # small a
>
>     C1 D0B0 ; # 小 a
>     C2 D0B1 ; # small b
>
>     C2 D0B1 ; # 小 b
>     C3 D186 ; # small ts
>
>     C3 D186；#小ts
>     ...
> }
> ```

Full conversion tables from `koi8-r` to `windows-1251`, and from `koi8-r` and `windows-1251` to `utf-8` are provided in the distribution files `conf/koi-win`, `conf/koi-utf`, and `conf/win-utf`.

分發文件`conf/koi-win`, `conf/koi-utf`和`conf/win-utf`中提供了從`koi8-r`到`windows-1251`以及從`koi8-r`和`windows-1251`到`utf-8`完整轉換錶。

This directive appeared in version 0.7.9.

該指令出現在版本0.7.9 。

Enables module processing in responses with the specified MIME types in addition to “`text/html`”. The special value “`*`” matches any MIME type (0.8.29).

除了「 `text/html` 」類型外，還允許對具有指定MIME類型的回應進行模組處理。特殊值“ `*` ”匹配任何MIME類型（ 0.8.29 ）。

> Until version 1.5.4, “`application/x-javascript`” was used as the default MIME type instead of “`application/javascript`”.
>
> 在版本1.5.4之前，「 `application/x-javascript` 」被用作預設的MIME類型，而不是「 `application/javascript` 」。

<tr><th>Syntax:<br>語法：</th><td><code><strong>override_charset</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:<br>預設值：</th><td>override_charset off;<br>禁用字元集覆蓋；</td></tr>
<tr><th>Context:<br>上下文：</th><td><code>http</code>, <code>server<br>伺服器</code>, <code>location<br>位置</code>, <code>if in location<br>如果在位置中</code></td></tr>
</table>

Determines whether a conversion should be performed for answers received from a proxied or a FastCGI/uwsgi/SCGI/gRPC server when the answers already carry a charset in the “Content-Type”（內容類型） response header field. If conversion is enabled, a charset specified in the received response is used as a source charset.

決定是否要應對從代理伺服器或 FastCGI/uwsgi/ SCGI /gRPC 伺服器收到的回應執行轉換，前提是回應頭欄位“Content-Type”（內容類型）中已包含字元集。如果啟用轉換，則將接收回應中指定的字元集用作來源字元集。

> It should be noted that if a response is received in a subrequest then the conversion from the response charset to the main request charset is always performed, regardless of the `override_charset` directive setting.
>
> 需要注意的是，如果在子請求中收到回應，則無論`override_charset`指令設定如何，都會始終執行從回應字元集到主請求字元集的轉換。

Defines the source charset of a response. If this charset is different from the charset specified in the [charset](#charset) directive, a conversion is performed.

定義回應的來源字元集。如果此字元集與 [charset](#charset)指令中指定的字元集不同，則會執行轉換。
