Модуль `ngx_http_ssl_module` обеспечивает работу по протоколу HTTPS.

Модуль `ngx_http_ssl_module` обеспечивает работу по протоколу HTTPS。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_ssl_module`.

此模組預設未構建，必須使用`--with-http_ssl_module`配置參數啟用。

> Для сборки и работы этого модуля нужна библиотека [OpenSSL](http://www.openssl.org/).

Для уменьшения загрузки процессора рекомендуется

Указывает `*файл*` с сертификатом в формате PEM для данного виртуального сервера. Если вместе с основным сертификатом нужно указать промежуточные, то они должны находиться в этом же файле в следующем порядке: сначала основной сертификат, а затем промежуточные. В этом же файле может находиться секретный ключ в формате PEM.

為此虛擬伺服器指定具有 PEM 格式的憑證的 `*файл*`。如果您需要與主證書一起指定中間證書，則它們必須按以下順序位於同一文件中：首先是主證書，然後是中間證書。同一檔案可能包含格式為 PEM 的金鑰。

Начиная с версии 1.11.0 эта директива может быть указана несколько раз для загрузки сертификатов разных типов, например RSA и ECDSA:

從版本1.11.0開始，可以多次指定該指令來載入不同類型的證書，例如RSA和ECDSA：

> ```
> server {
>
> 伺服器 {
>     listen              443 ssl;
>
>     監聽 443 ssl；
>     server_name         example.com;
>
>     伺服器名稱 example.com；
> 
>     ssl_certificate     example.com.rsa.crt;
>
>     ssl_certificate example.com.rsa.crt；
>     ssl_certificate_key example.com.rsa.key;
>
>     ssl_certificate_key example.com.rsa.key；
> 
>     ssl_certificate     example.com.ecdsa.crt;
>
>     ssl_certificate example.com.ecdsa.crt；
>     ssl_certificate_key example.com.ecdsa.key;
>
>     ssl_certificate_key example.com.ecdsa.key；
> 
>     ...
> }
> ```

> Возможность задавать отдельные [цепочки сертификатов](<212 [02.01.01 http] 設定HTTPS伺服器.md#chains>) для разных сертификатов есть только в OpenSSL 1.0.2 и выше. Для более старых версий следует указывать только одну цепочку сертификатов.
>
> 為不同憑證指定單獨的[憑證鏈](<212 [02.01.01 http] 設定HTTPS伺服器.md#chains>)的功能僅在 OpenSSL 1.0.2 及更高版本中可用。對於舊版本，僅應指定一個憑證鏈。

Начиная с версии 1.15.9 в имени файла можно использовать переменные при использовании OpenSSL 1.0.2 и выше:

從版本 1.15.9 開始，您可以在使用 OpenSSL 1.0.2 及更高版本時在檔案名稱中使用變數：

> ```
> ssl_certificate     $ssl_server_name.crt;
>
> ssl_certificate $ssl_server_name.crt;
> ssl_certificate_key $ssl_server_name.key;
> ```

Однако нужно учитывать, что при использовании переменных сертификат загружается при каждой операции SSL handshake, что может отрицательно влиять на производительность.

但是，請注意，使用變數時，每次SSL握手操作都會載入證書，這可能會對效能產生影響。

Вместо `*файла*` можно указать значение `data`:`*$переменная*` (1.15.10), при котором сертификат загружается из переменной без использования промежуточных файлов. При этом следует учитывать, что ненадлежащее использование подобного синтаксиса может быть небезопасно, например данные секретного ключа могут попасть в [лог ошибок](<285 [02.01 文件] 基本功能.md#error_log>).

您可以指定值 `data`:`*$переменная*` (1.15.10)，而不是`*файла*`，這會從變數載入憑證而不使用中間檔案。但是，應該考慮到，不當使用此類語法可能是不安全的，例如，金鑰資料可能最終出現在[錯誤日誌](<285 [02.01 文件] 基本功能.md#error_log>)中。

Нужно иметь в виду, что из-за ограничения протокола SSL/TLS для максимальной совместимости с клиентами, которые не используют [SNI](http://en.wikipedia.org/wiki/Server_Name_Indication), виртуальные серверы с разными сертификатами должны слушать на [разных IP-адресах](<212 [02.01.01 http] 設定HTTPS伺服器.md#name_based_https_servers>).

請注意，由於 SSL/TLS 協定的限制，為了最大限度地相容於不使用 [SNI](http://en.wikipedia.org/wiki/Server_Name_Indication)的用戶端，具有不同憑證的虛擬伺服器必須監聽 [不同的 IP 位址](<212 [02.01.01 http] 設定HTTPS伺服器.md#name_based_https_servers>) 。

Задаёт кэш, в котором могут храниться [SSL-сертификаты](#ssl_certificate) и [секретные ключи](#ssl_certificate_key), полученные из [переменных](#ssl_certificate_key_variables).

定義一個緩存，其中可以儲存從[變數](#ssl_certificate_key_variables)獲得的[SSL-憑證](#ssl_certificate)和[金鑰](#ssl_certificate_key)。

У директивы есть следующие параметры:

此指令具有以下參數：

`max`

задаёт максимальное число элементов в кэше; при переполнении кэша удаляются наименее востребованные элементы (LRU);

設定快取中元素的最大數量；當快取滿時，刪除最少需要的元素（LRU）；

`inactive`

задаёт время, после которого элемент кэша удаляется, если к нему не было обращений в течение этого времени; по умолчанию 10 секунд;

指定快取項目在多長時間內未被存取後將被刪除；預設值為 10 秒；

`valid`

задает время, в течение которого элемент кэша считается действительным и может быть повторно использован, по умолчанию 60 секунд. По завершении этого времени сертификат будет обновлён или повторно проверен;

指定快取項目被視為有效且可重複使用的時間；預設值為 60 秒。此時間過後，證書將被續訂或重新驗證；

`off`

запрещает кэш.

禁用緩存。

Пример:

例子：

>

>
> ssl_certificate_key $ssl_server_name.key;
> ssl_certificate_cache max=1000 inactive=20s valid=1m;
>
> ssl_certificate_cache max=1000 非活動=20s 有效=1m;
> ```

Вместо `*файла*` можно указать значение `store`:`*схема*`:`*id*` (1.29.0), которое используется для загрузки ключа с указанным `*id*` и зарегистрированной провайдером OpenSSL `*схемой*` URI, такой как [`pkcs11`](https://datatracker.ietf.org/doc/html/rfc7512).

Задаёт тип и размеры кэшей для хранения параметров сессий. Тип кэша может быть следующим:

指定用於儲存會話參數的快取類型和大小。快取類型可以是以下幾種之一：

`off`

жёсткое запрещение использования кэша сессий: nginx явно сообщает клиенту, что сессии не могут использоваться повторно.

完全禁止使用會話快取：nginx 明確告知客戶端會話不能重複使用。

`none`

мягкое запрещение использования кэша сессий: nginx сообщает клиенту, что сессии могут использоваться повторно, но на самом деле не хранит параметры сессии в кэше.

軟性禁止使用會話快取：nginx 告訴客戶端會話可以重複使用，但實際上並不會將會話參數儲存在快取中。

`builtin`

встроенный в OpenSSL кэш, используется в рамках только одного рабочего процесса. Размер кэша задаётся в сессиях. Если размер не задан, то он равен 20480 сессиям. Использование встроенного кэша может вести к фрагментации памяти.

OpenSSL 的內建快取僅在一個工作進程內使用。快取大小以會話為單位指定。如果未指定大小，則預設為 20480 個會話。使用內建快取可能會導致記憶體碎片。

`shared`

кэш, разделяемый между всеми рабочими процессами. Размер кэша задаётся в байтах, в 1 мегабайт может поместиться около 4000 сессий. У каждого разделяемого кэша должно быть произвольное название. Кэш с одинаковым названием может использоваться в нескольких виртуальных серверах. Также он используется для автоматического создания, хранения и периодического обновления ключей TLS session tickets (1.23.2), если они не указаны явно с помощью директивы [ssl\_session\_ticket\_key](#ssl_session_ticket_key).

所有工作進程共享的快取。快取大小以位元組為單位指定；1 MB 大約可以容納 4000 個會話。每個共享快取必須具有任意名稱。名稱相同的快取可以在多個虛擬伺服器上使用。它也用於自動產生、儲存和定期刷新會話票證（ TLS ），除非使用 [1.23.2](#ssl_session_ticket_key)指令明確指定。

Можно использовать одновременно оба типа кэша, например:

Разрешает проверку клиентских сертификатов. Результат проверки доступен через переменную [$ssl\_client\_verify](#var_ssl_client_verify).

啟用客戶端憑證驗證。驗證結果可透過 [$ssl\_client\_verify](#var_ssl_client_verify)變數取得。

Параметр `optional` (0.8.7+) запрашивает клиентский сертификат, и если сертификат был предоставлен, проверяет его.

參數`optional` ( 0.8.7 +) 請求客戶端證書，如果提供了證書，則驗證該證書。

Параметр `optional_no_ca` (1.3.8, 1.2.5) запрашивает сертификат клиента, но не требует, чтобы он был подписан доверенным сертификатом CA. Это предназначено для случаев, когда фактическая проверка сертификата осуществляется внешним по отношению к nginx’у сервисом. Содержимое сертификата доступно через переменную [$ssl\_client\_cert](#var_ssl_client_cert).

`optional_no_ca` ( 1.3.8, 1.2.5 ) 參數請求客戶端證書，但不要求該證書由受信任的CA證書簽署。這適用於實際憑證驗證由 Nginx 外部服務執行的情況。憑證內容可透過 [$ssl\_client\_cert](#var_ssl_client_cert)變數取得。

#### Обработка ошибок｜錯誤處理

Модуль `ngx_http_ssl_module` поддерживает несколько нестандартных кодов ошибок, которые можно использовать для перенаправления с помощью директивы [error\_page](<221 [02.01.01 http] 模組 ngx_http_core_module.md#error_page>):

`ngx_http_ssl_module`模組支援幾個非標準錯誤代碼，可以使用 [error\_page](<221 [02.01.01 http] 模組 ngx_http_core_module.md#error_page>)指令進行重定向：

495

при проверке клиентского сертификата произошла ошибка;

驗證客戶端憑證時發生錯誤；

496

клиент не предоставил требуемый сертификат;

客戶未提供所需證明文件；

497

обычный запрос был послан на порт HTTPS.

向連接埠HTTPS發送了一個正常的請求。

Перенаправление делается после того, как запрос полностью разобран и доступны такие переменные, как `$request_uri`, `$uri`, `$args` и другие переменные.

重定向是在請求完全解析完畢，並且諸如`$request_uri`, `$uri`, `$args`等變數和其他變數可用之後進行的。

#### Встроенные переменные｜內建變數

`ngx_http_ssl_module`模組支援內建變數：

`$ssl_alpn_protocol`

`$ssl_cipher`

傳回用於已建立的SSL連線的密碼的名稱；

`$ssl_ciphers`

возвращает список шифров, поддерживаемых клиентом (1.11.7). Известные шифры указаны по имени, неизвестные указаны в шестнадцатеричном виде, например:

傳回客戶端支援的密碼套件清單（ 1.11.7 ）。已知密碼套件按名稱列出，未知密碼套件以十六進位形式列出，例如：

> ```
> AES128-SHA:AES256-SHA:0x00ff
>
> AES128-SHA:AES256-SHA :0x00ff
> ```

> Переменная полностью поддерживается при использовании OpenSSL версии 1.0.2 и выше. При использовании более старых версий переменная доступна только для новых сессий и может содержать только известные шифры.

`$ssl_client_escaped_cert`

возвращает клиентский сертификат в формате PEM (закодирован в формате urlencode) для установленного SSL-соединения (1.13.5);

`$ssl_client_cert`

возвращает клиентский сертификат в формате PEM для установленного SSL-соединения, перед каждой строкой которого, кроме первой, вставляется символ табуляции; предназначена для использования в директиве [proxy\_set\_header](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_set_header>);

`$ssl_client_fingerprint`

`$ssl_client_raw_cert`

возвращает клиентский сертификат в формате PEM для установленного SSL-соединения;

`$ssl_client_s_dn`

возвращает строку “subject DN” клиентского сертификата для установленного SSL-соединения согласно [RFC 2253](https://datatracker.ietf.org/doc/html/rfc2253) (1.11.6);
