The `ngx_http_memcached_module` module is used to obtain responses from a memcached server. The key is set in the `$memcached_key` variable. A response should be put in memcached in advance by means external to nginx.

`ngx_http_memcached_module`模組用於從 memcached 伺服器取得回應。鍵值設定在`$memcached_key`變數中。回應需要預先透過 nginx 外部的方式放入 memcached 中。

#### Example Configuration｜範例配置

> ```
> server {
>
> 伺服器 {
>     location / {
>
>     地點 / {
>         set            $memcached_key "$uri?$args";
>
>         設定 $memcached_key "$uri?$args";
>         memcached_pass host:11211;
>
>         memcached_pa​​ss host:11211;
>         error_page     404 502 504 = @fallback;
>
>         error_page 404 502 504 = @fallback;
>     }
> 
>     location @fallback {
>         proxy_pass     http://backend;
>
>         proxy_pass http://backend;
>     }
> }
> ```

Defines conditions under which access to a memcached server is allowed or [denied](#denied). If all string parameters are not empty and not equal to “0” then the access is allowed. The conditions are evaluated each time before a connection to a memcached server is established. Parameter values can contain variables:

定義允許或拒絕存取 memcached 伺服器的條件(https://nginx.org/en/docs/http/ngx_http_memcached_module.html#denied) 。如果所有字串參數均不為空且不等於“0”，則允許存取。每次建立與 memcached 伺服器的連線之前都會評估這些條件。參數值可以包含變數：

> ```
> geo $upstream_last_addr $allow {

>
>         memcached_pa​​ss host:11211;
>         memcached_allow_upstream $allow;
>         ...
>     }
> }
> ```

Makes outgoing connections to a memcached server originate from the specified local IP address with an optional port (1.11.2). Parameter value can contain variables (1.3.12). The special value `off` (1.3.12) cancels the effect of the `memcached_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address and port.

使發送至 memcached 伺服器的出站連線源自指定的本機位址IP ，並可選擇指定連接埠 ( 1.11.2 )。參數值可以包含變數 ( 1.3.12 )。特殊值`off` ( 1.3.12 ) 會取消從上一配置等級繼承的`memcached_bind`指令的效果，該指令允許系統自動分配本地位址IP和連接埠。

The `transparent` parameter (1.11.0) allows outgoing connections to a memcached server originate from a non-local IP address, for example, from a real IP address of a client:

`transparent`參數 ( 1.11.0 ) 允許從非本地IP位址（例如，客戶端的真實IP位址）發出到 memcached 伺服器的出站連接：

> ```
> memcached_bind $remote_addr transparent;
>
> memcached_bind $remote_addr 透明;
> ```

In order for this parameter to work, it is usually necessary to run nginx worker processes with the [superuser](<125 [01.01 文件] 核心功能.md#user>) privileges. On Linux it is not required (1.13.8) as if the `transparent` parameter is specified, worker processes inherit the `CAP_NET_RAW` capability from the master process. It is also necessary to configure kernel routing table to intercept network traffic from the memcached server.

為了使此參數生效，通常需要以 [superuser](<125 [01.01 文件] 核心功能.md#user>)權限執行 nginx 工作進程。在 Linux 系統上則無需此權限 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程會從主進程繼承`CAP_NET_RAW`權限。此外，還需要設定核心路由表以攔截來自 memcached 伺服器的網路流量。

Specifies in which cases a request should be passed to the next server:

指定在哪些情況下應將請求傳遞給下一個伺服器：

`error`

an error occurred while establishing a connection with the server, passing a request to it, or reading the response header;

與伺服器建立連線、向伺服器發送請求或讀取回應標頭時發生錯誤；

`timeout`

a timeout has occurred while establishing a connection with the server, passing a request to it, or reading the response header;

與伺服器建立連線、向伺服器發送請求或讀取回應標頭時發生逾時；

`denied`

the server [denied](#memcached_allow_upstream) the connection (1.29.3);

伺服器[拒絕](#memcached_allow_upstream)連線 ( 1.29.3 );

> This parameter is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 此參數作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`invalid_response`

a server returned an empty or invalid response;

伺服器傳回了空響應或無效回應；

`not_found`

a response was not found on the server;

伺服器未找到回應；

`off`

disables passing a request to the next server.

禁用向下一個伺服器傳遞請求。

One should bear in mind that passing a request to the next server is only possible if nothing has been sent to a client yet. That is, if an error or timeout occurs in the middle of the transferring of a response, fixing this is impossible.

需要注意的是，只有在尚未向客戶端發送任何資料的情況下，才能將請求傳遞給下一個伺服器。也就是說，如果在傳輸回應的過程中發生錯誤或逾時，則無法修復。

The directive also defines what is considered an [unsuccessful attempt](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#max_fails>) of communication with a server. The cases of `error`, `timeout`, `denied` and `invalid_response` are always considered unsuccessful attempts, even if they are not specified in the directive. The case of `not_found` is never considered an unsuccessful attempt.

該指令也定義了與伺服器通訊的[不成功嘗試](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#max_fails>)。 `error`, `timeout`, `denied` 和 `invalid_response` 的情況始終被視為不成功的嘗試，即使它們未在指令中指定。 `not_found`的案例絕不被認為是一次不成功的嘗試。

Passing a request to the next server can be limited by [the number of tries](#memcached_next_upstream_tries) and by [time](#memcached_next_upstream_timeout).

向下一個伺服器傳遞請求可以受到 [嘗試次數](#memcached_next_upstream_tries)和 [時間](#memcached_next_upstream_timeout)的限制。

Sets the memcached server address. The address can be specified as a domain name or IP address, and a port:

設定 memcached 伺服器位址。位址可以指定為網域名稱或IP位址，以及連接埠號碼：

或作為UNIX域套接字路徑：

如果一個網域解析到多個位址，則所有這些位址將以輪詢方式使用。此外，可以將位址指定為 [伺服器群組](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md>) 。

Configures the “TCP keepalive” behavior for outgoing connections to a memcached server. By default, the operating system’s settings are in effect for the socket. If the directive is set to the value “`on`”, the `SO_KEEPALIVE` socket option is turned on for the socket.

配置與 memcached 伺服器建立的出站連接的「 TCP keepalive」行為。預設情況下，套接字採用作業系統的設定。如果指令值設定為“ `on` ”，則會為套接字啟用`SO_KEEPALIVE`選項。
