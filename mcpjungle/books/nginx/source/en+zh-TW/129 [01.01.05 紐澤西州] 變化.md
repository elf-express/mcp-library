## Changes｜變化

#### Changes with njs 1.0.1｜與 njs 的變更1.0.1

Release Date: 2 September 2026

發售日期：2026年9月2日

nginx modules:

nginx 模組：

-   Security: fixed an access control bypass in [js\_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_access>) when an asynchronous request body continuation threw an exception or produced an unhandled rejection ([CVE-2026-18329](https://www.cve.org/CVERecord?id=CVE-2026-18329)). Previously, nginx could continue processing the request as though the js\_access check had succeeded. The issue was introduced in [0.9.9](#njs0.9.9). Thanks to Ta Duc Thien.  
    安全性：修正了 [js\_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_access>)中的存取控制繞過問題。當非同步請求體延續拋出異常或產生未處理的拒絕時（[CVE -2026-18329](https://www.cve.org/CVERecord?id=CVE-2026-18329) ），nginx 可以繼續處理請求，就好像 js\_access 檢查已成功一樣。此問題最初由 [0.9.9](#njs0.9.9)引入。感謝 Ta Duc Thien 的貢獻。
    
-   Security: fixed a worker process crash when reading [Response.statusText](<137 [01.01.05 紐澤西州] 參考.md#response_statustext>) after an upstream server returned a status line with an empty reason phrase ([CVE-2026-78222](https://www.cve.org/CVERecord?id=CVE-2026-78222)). The issue was introduced in [73c75e41](https://github.com/nginx/njs/commit/73c75e41) ([0.5.1](#njs0.5.1)).  
    安全性：修正了上游伺服器回傳空原因短語的狀態行後，讀取 [Response.statusText](<137 [01.01.05 紐澤西州] 參考.md#response_statustext>)時工作進程崩潰的問題（[CVE -2026-78222](https://www.cve.org/CVERecord?id=CVE-2026-78222) ）。此問題在 [73c75e41](https://github.com/nginx/njs/commit/73c75e41) ([0.5.1](#njs0.5.1) ) 中引入。
    
-   Bugfix: fixed unhandled promise rejection tracking in reused [QuickJS](<132 [01.01.05 紐澤西州] JavaScript 引擎.md#quickjs_engine>) contexts.  
    Bugfix：修正了重複使用 [QuickJS](<132 [01.01.05 紐澤西州] JavaScript 引擎.md#quickjs_engine>)上下文中未處理的 promise 拒絕追蹤。
    
-   Bugfix: fixed [SharedDict.pop()](<137 [01.01.05 紐澤西州] 參考.md#dict_pop>) returning `undefined` for unexpired entries in [shared dictionaries](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_shared_dict_zone>) with a timeout.  
    Bugfix：修正了 [SharedDict.pop()](<137 [01.01.05 紐澤西州] 參考.md#dict_pop>)在 [shared dictionaries](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_shared_dict_zone>)中未過期條目超時時返回`undefined`的問題。
    
-   Bugfix: fixed validation and replacement of [Fetch Headers](<137 [01.01.05 紐澤西州] 參考.md#headers>) values. This also fixed dangling header names in the QuickJS engine.  
    Bugfix：修正了 [Fetch Headers](<137 [01.01.05 紐澤西州] 參考.md#headers>)值的驗證和替換問題。這也修復了 QuickJS 引擎中懸空的標頭名稱。
    
-   Bugfix: fixed missing validation of [r.headersOut](<137 [01.01.05 紐澤西州] 參考.md#r_headers_out>) names and values, and of redirect targets passed to [r.return()](<137 [01.01.05 紐澤西州] 參考.md#r_return>).  
    Bugfix：修正了 [r.headersOut](<137 [01.01.05 紐澤西州] 參考.md#r_headers_out>)名稱和值以及傳遞給 [r.return()](<137 [01.01.05 紐澤西州] 參考.md#r_return>)的重定向目標的缺失驗證。
    
-   Bugfix: fixed use-after-free, worker aborts, and leaks caused by cyclic references involving [Fetch](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>), HTTP request, and Stream session objects in the QuickJS engine.  
    Bugfix：修正了 QuickJS 引擎中涉及 [Fetch](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>), HTTP請求和 Stream 會話物件的循環引用導致的釋放後使用、工作進程中止和洩漏問題。
    
-   Bugfix: fixed QuickJS context reuse after [internal redirects](<137 [01.01.05 紐澤西州] 參考.md#r_internal_redirect>) and when pending jobs remained after request teardown.  
    Bugfix：修正了 [內部重定向](<137 [01.01.05 紐澤西州] 參考.md#r_internal_redirect>)之後以及請求清理後仍有待處理作業時 QuickJS 上下文重用的問題。
    
-   Bugfix: fixed cleanup of partially initialized JavaScript contexts when request setup failed.  
    Bugfix：修正了請求設定失敗時部分初始化的 JavaScript 上下文的清理問題。
    

Core:

核：

-   Security: fixed a heap buffer overflow while parsing namespace prefix lists passed to [xml.exclusiveC14n()](<137 [01.01.05 紐澤西州] 參考.md#xml_exclusivec14n>) ([CVE-2026-78689](https://www.cve.org/CVERecord?id=CVE-2026-78689)). The issue was introduced in [9161a840](https://github.com/nginx/njs/commit/9161a840) ([0.7.10](#njs0.7.10)). Thanks to Vladimir Vulnerability Research Tech Lead @ Cyera, evilgensec.  
    安全性：修正了解析傳遞給 [xml.exclusiveC14n()] 的命名空間前綴列表時發生的堆緩衝區溢位漏洞(https://nginx.org/en/docs/njs/reference.html#xml_exclusivec14n) ([CVE -2026-78689](https://www.cve.org/CVERecord?id=CVE-2026-78689) )。此問題最初由 [9161a840](https://github.com/nginx/njs/commit/9161a840) ([0.7.10](#njs0.7.10) ) 所引入。感謝 Cyera 和 evilgensec 的漏洞研究技術主管 Vladimir。
    
-   Feature: added [btoa()](<137 [01.01.05 紐澤西州] 參考.md#btoa>) and [atob()](<137 [01.01.05 紐澤西州] 參考.md#atob>) global functions to the QuickJS engine and aligned their behavior between both engines.  
    功能：為 QuickJS 引擎添加了 [btoa()](<137 [01.01.05 紐澤西州] 參考.md#btoa>)和 [atob()](<137 [01.01.05 紐澤西州] 參考.md#atob>)全局函數，並使兩個引擎的行為保持一致。
    
-   Bugfix: fixed a stack buffer overflow when exporting RSA keys larger than 4096 bits to JWK in [crypto.subtle.exportKey()](<137 [01.01.05 紐澤西州] 參考.md#crypto_subtle_export_key>). Thanks to Vaibhav Rajput.  
    Bugfix：修正了在 [ RSA ()] 中將大於 4096 位元的金鑰JWK到 [ (https://nginx.org/en/docs/njs/reference.html#crypto_subtle_export_key) ()] 時發生的堆疊緩衝區溢位問題。感謝 Vaibhav Rajput。
    
-   Bugfix: fixed RSA-OAEP [encryption](<137 [01.01.05 紐澤西州] 參考.md#crypto_subtle_encrypt>) and [decryption](<137 [01.01.05 紐澤西州] 參考.md#crypto_subtle_decrypt>) with SHA-256 and SHA-384 digests in WebCrypto.  
    Bugfix：修正了 WebCrypto 中RSA-OAEP [加密](<137 [01.01.05 紐澤西州] 參考.md#crypto_subtle_encrypt>)和 [解密](<137 [01.01.05 紐澤西州] 參考.md#crypto_subtle_decrypt>)與SHA -256 和SHA -384 摘要的問題。
    
-   Bugfix: fixed compatibility with quickjs-ng 0.16.0 and later.  
    Bugfix：修復了與 quickjs-ng 0.16.0及更高版本的兼容性。
    
-   Bugfix: fixed empty stack traces for QuickJS errors created by host callbacks.  
    Bugfix：修正了主機回呼導致的 QuickJS 錯誤堆疊追蹤為空的問題。
    

#### Changes with njs 1.0.0｜與 njs 的變更1.0.0

Release Date: 23 June 2026

發售日期：2026年6月23日

nginx modules:

nginx 模組：

-   Improvement: aligned HTTP, Stream, and [Fetch](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) exception classes between the njs and QuickJS engines. API misuse is now reported as `TypeError` and status bounds violations as `RangeError`.  
    改進：在 njs 和 QuickJS 引擎之間對齊 HTTP、Stream 和 [Fetch](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) 異常類別。 API 濫用現在報告為 `TypeError`，狀態邊界違規報告為 `RangeError`。
    
-   Improvement: rejected unsafe request targets, methods, and header values in [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) before request serialization.  
    改進：在請求序列化之前，拒絕 [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>)中的不安全請求目標、方法和標頭值。
    
-   Bugfix: fixed a heap use-after-free in [r.subrequest()](<137 [01.01.05 紐澤西州] 參考.md#r_subrequest>) when the client closed the connection before the background subrequest completed. The issue was introduced in [75d6b61](https://github.com/nginx/njs/commit/75d6b61) ([0.9.5](#njs0.9.5)).  
    Bugfix：修正了 [r.subrequest()](<137 [01.01.05 紐澤西州] 參考.md#r_subrequest>)中當客戶端在後台子請求完成之前關閉連接時出現的堆釋放後使用問題。此問題是在 [75d6b61](https://github.com/nginx/njs/commit/75d6b61) ([0.9.5](#njs0.9.5) ) 中引入的。
    
-   Bugfix: fixed a worker segfault while reading a request header that nginx registers without a dedicated slot, such as `Proxy-Connection`, via [r.headersIn](<137 [01.01.05 紐澤西州] 參考.md#r_headers_in>).  
    Bugfix：修正了讀取 nginx 註冊的沒有專用槽的請求頭（例如`Proxy-Connection`時工作進程段錯誤的問題，透過 [r.headersIn](<137 [01.01.05 紐澤西州] 參考.md#r_headers_in>) 。
    
-   Bugfix: excluded unverified-TLS and dynamic-proxy connections from the [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) [keepalive](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_fetch_keepalive>) cache and validated cached connections before reuse.  
    Bugfix：從 [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) [keepalive](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_fetch_keepalive>)快取中排除未驗證的TLS和動態代理連接，並在重複使用之前驗證快取的連接。
    
-   Bugfix: fixed Content-Length truncation for very large request bodies and a missing CONNECT terminator for proxies configured without credentials in [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>).  
    Bugfix：修正了請求體非常大時 Content-Length 截斷的問題，以及 [ngx.fetch()] 中未配置憑證的代理缺少CONNECT (https://nginx.org/en/docs/njs/reference.html#ngx_fetch)符的問題。
    
-   Bugfix: fixed leaks of promises, events, and init property values on [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) failure paths in the QuickJS engine.  
    Bugfix：修正了 QuickJS 引擎中 [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>)失敗路徑上的 promises、事件和 init 屬性值的洩漏。
    
-   Bugfix: fixed missing fetch event cleanup when the resolver failed to start.  
    Bugfix：修正了解析器啟動失敗時缺少 fetch 事件清理的問題。
    
-   Bugfix: fixed an out-of-bounds read of a short fetch proxy URL.  
    Bugfix：修正了對短獲取代理的越界讀取問題URL 。
    
-   Bugfix: fixed request body truncation in [r.readRequestJSON()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_json>) for bodies containing invalid UTF-8 in the QuickJS engine.  
    Bugfix：修正了 QuickJS 引擎中 [r.readRequestJSON()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_json>)包含無效UTF -8 的請求體截斷問題。
    
-   Bugfix: fixed an out-of-bounds read while loading a shared dictionary state file.  
    Bugfix：修正了載入共享字典狀態檔案時發生的越界讀取問題。
    
-   Bugfix: set a pending exception when `sendHeader()`, `send()`, and `finish()` fail in the njs HTTP handlers.  
    Bugfix：當 njs HTTP處理程序中的`sendHeader()`, `send()`和`finish()`失敗時，設定一個待處理的異常。
    
-   Bugfix: fixed the variable value state after a stream variable storage allocation failure.  
    錯誤修復：修復了流變數儲存分配失敗後變數值的狀態。
    

Core:

核：

-   Improvement: bounded string-producing chained-buffer growth, so that exceeding the maximum string length raises a catchable `RangeError("invalid string length")` instead of exhausting worker memory.  
    改進：限製字串產生鍊式緩衝區的成長，使得超過最大字串長度時會引發可捕獲的`RangeError("invalid string length")`異常，而不是耗盡工作記憶體。
    
-   Improvement: aligned built-in exception classes (XML, console, TextEncoder, TextDecoder, Buffer, fs.Stats) between the njs and QuickJS engines.  
    改進：統一了 njs 和 QuickJS 引擎之間的內建異常類別（ XML 、console、TextEncoder、TextDecoder、Buffer、fs.Stats）。
    
-   Bugfix: fixed an infinite loop while inflating a zlib stream that requires a dictionary in the QuickJS engine.  
    Bugfix：修正了在 QuickJS 引擎中載入需要字典的 zlib 流時出現的無限迴圈問題。
    
-   Bugfix: fixed an infinite loop in `Buffer.prototype.fill()` with a zero-length typed array source.  
    Bugfix：修正了`Buffer.prototype.fill()`中長度為零的類型化陣列來源的無限循環。
    
-   Bugfix: fixed a use-after-free in `Array.prototype.sort()` when a getter invoked for a hole grows the array.  
    Bugfix：修正了`Array.prototype.sort()`中當呼叫 getter 處理空洞時數組增大導致的 use-after-free 問題。
    
-   Bugfix: fixed type confusion in `Buffer.concat()` when a list element getter returns a typed array during validation but not during the copy.  
    Bugfix：修正了`Buffer.concat()`中的類型混淆問題，即當列表元素 getter 在驗證期間傳回類型化數組，但在複製期間不傳回類型化數組時。
    
-   Bugfix: fixed an out-of-bounds access in the variable-length Buffer `readInt`/`writeInt` methods with a zero byteLength.  
    Bugfix：修正了可變長度 Buffer `readInt`/`writeInt`方法中位元組長度為零時發生的越界存取問題。
    
-   Bugfix: fixed an out-of-bounds read in `Buffer.prototype.toString()` when start was greater than end.  
    Bugfix：修正了當起始值大於結束值時`Buffer.prototype.toString()`中的越界讀取問題。
    
-   Bugfix: fixed `Array.prototype.slice()` of large arrays returning wrong results in the non-fast keys path.  
    Bugfix：修正了`Array.prototype.slice()`在非快速鍵路徑中大數組傳回錯誤結果的問題。
    
-   Bugfix: fixed the typed array constructor, `slice()`, `toReversed()`, and `toSorted()` ignoring the source view byte offset in the same-type fast path.  
    Bugfix：修正了類型化陣列建構子`slice()`, `toReversed()`和`toSorted()`忽略同類型快速路徑中的來源視圖位元組偏移的問題。
    
-   Bugfix: fixed Buffer allocation length checks for lengths greater than or equal to 2^32 on 32-bit platforms.  
    Bugfix：修正了 32 位元平台上長度大於或等於 2^32 的緩衝區分配長度檢查。
    
-   Bugfix: fixed the `Buffer.from()` typed-array source offset for multi-byte element types in the QuickJS engine.  
    Bugfix：修正了 QuickJS 引擎中多位元組元素類型的`Buffer.from()` typed-array 來源偏移量。
    
-   Bugfix: fixed Buffer float access alignment.  
    Bugfix：修正了緩衝區浮點存取對齊問題。
    
-   Bugfix: fixed an out-of-bounds read in a parser string escape lookahead.  
    Bugfix：修正了解析器字串轉義預讀中的越界讀取問題。
    

#### Changes with njs 0.9.9｜與 njs 的變更0.9.9

Release Date: 19 May 2026

發售日期：2026年5月19日

nginx modules:

nginx 模組：

-   Security: a heap buffer overflow might occur in a worker process when the [js\_fetch\_proxy](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_fetch_proxy>) directive value contains nginx variables derived from the client request ( [`$http_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_http_>), [`$arg_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_arg_>), [`$cookie_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_cookie_>), etc.) and the location's JS handler invokes [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) ([CVE-2026-8711](https://www.cve.org/CVERecord?id=CVE-2026-8711)). The issue was introduced in [dea83189](https://github.com/nginx/njs/commit/dea83189) ([0.9.4](#njs0.9.4)).  
    安全性：當 [js\_fetch\_proxy] 在工作進程中執行時，可能會發生堆疊緩衝區溢位。(https://nginx.org/en/docs/http/ngx_http_js_module.html#js_fetch_proxy) 指令值包含從客戶端請求派生的 nginx 變數（[`$http_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_http_>), [`$arg_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_arg_>), [`$cookie_*`](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_cookie_>)等等）以及位置的 JS 處理程序呼叫 [ngx.fetch()](<137 [01.01.05 紐澤西州] 參考.md#ngx_fetch>) ([CVE-2026-8711](https://www.cve.org/CVERecord?id=CVE-2026-8711)）該問題在[dea83189]中提出。(https://github.com/nginx/njs/commit/dea83189) ([0.9.4](#njs0.9.4)).
    
-   Feature: added [js\_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_access>) directive.  
    功能：新增了 [js\_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_access>)指令。
    
-   Feature: added [r.readRequestText()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_text>), [r.readRequestArrayBuffer()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_array_buffer>), and [r.readRequestJSON()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_json>) async methods that read the request body, available in [js\_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_access>) and [js\_content](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_content>) directives.  
    功能：新增了 [r.readRequestText( (https://nginx.org/en/docs/http/ngx_http_js_module.html#js_access)](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_text>) 、 [r.readRequestArrayBuffer()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_array_buffer>)和 [r.readRequestJSON()](<137 [01.01.05 紐澤西州] 參考.md#r_read_request_json>)異步方法，用於請求體，可在 [jsn_access](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_content>)指令中使用。
