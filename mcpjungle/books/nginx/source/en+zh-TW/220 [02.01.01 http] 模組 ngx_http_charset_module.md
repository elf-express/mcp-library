## Модуль ngx\_http\_charset\_module｜模組 ngx_http_charset_module

Модуль `ngx_http_charset_module` добавляет указанную кодировку в поле “Content-Type”（內容類型） заголовка ответа. Кроме того, модуль может перекодировать данные из одной кодировки в другую с некоторыми ограничениями:

`ngx_http_charset_module`模組會將指定的編碼加入到“Content-Type”（內容類型）響應頭字段中。此外，該模組還可以將資料從一種編碼轉換為另一種編碼，但存在一些限制：

-   перекодирование осуществляется только в одну сторону — от сервера к клиенту,  
    轉碼只能單向進行－從伺服器到客戶端。
-   перекодироваться могут только однобайтные кодировки  
    只有單字節編碼才能被重新編碼。
-   или однобайтные кодировки в UTF-8 и обратно.  
    或UTF -8 及反向的單字節編碼。

#### Пример конфигурации｜配置範例

> ```
> include        conf/koi-win;
>
> 包含 conf/koi-win；
> 
> charset        windows-1251;
>
> charset windows-1251;
> source_charset koi8-r;
>
> 來源字元集 koi8-r；
> ```

Добавляет указанную кодировку в поле “Content-Type”（內容類型） заголовка ответа. Если эта кодировка отличается от указанной в директиве [source\_charset](#source_charset), то выполняется перекодирование.

將指定的編碼新增至“Content-Type”（內容類型）回應頭欄位。如果此編碼與 [source\_charset](#source_charset)指令中指定的編碼不同，則會執行轉換。

Параметр `off` отменяет добавление кодировки в поле “Content-Type”（內容類型） заголовка ответа.

`off`參數禁止在“Content-Type”（內容類型）響應頭字段上新增編碼。

Кодировка может быть задана с помощью переменной:

可以使用變數指定編碼方式：

> ```
> charset $charset;
>
> 字符集 $charset;
> ```

В этом случае необходимо, чтобы все возможные значения переменной присутствовали хотя бы один раз в любом месте конфигурации в виде директив [charset\_map](#charset_map), [charset](#charset) или [source\_charset](#source_charset). Для кодировок `utf-8`, `windows-1251` и `koi8-r` для этого достаточно включить в конфигурацию файлы `conf/koi-win`, `conf/koi-utf` и `conf/win-utf`. Для других кодировок можно просто сделать фиктивную таблицу перекодировки, например:

在這種情況下，變數的所有可能值必須至少在配置中的任何位置出現一次，以 `[charset\_map](#charset_map) 、`[charset](#charset)或 `[source\_charset](#source_charset)指令的形式存在。對於編碼`utf-8`, `windows-1251`和`koi8-r`只需在配置中包含 ` `conf/koi-win`, `conf/koi-utf`和`conf/win-utf`檔案即可。對於其他編碼，您可以簡單地建立一個虛擬轉換表，例如：

> ```
> charset_map iso-8859-5 _ { }
> ```

Кроме того, кодировка может быть задана в поле “X-Accel-Charset”（X-Accel-字元集） заголовка ответа. Эту возможность можно запретить с помощью директив [proxy\_ignore\_headers](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_ignore_headers>), [fastcgi\_ignore\_headers](<225 [02.01.01 http] ngx_http_fastcgi_module 模組.md#fastcgi_ignore_headers>), [uwsgi\_ignore\_headers](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_ignore_headers>), [scgi\_ignore\_headers](<254 [02.01.01 http] 模組 ngx_http_scgi_module.md#scgi_ignore_headers>) и [grpc\_ignore\_headers](<229 [02.01.01 http] 模組 ngx_http_grpc_module.md#grpc_ignore_headers>).

此外，也可以在“X-Accel-Charset”（X-Accel-字元集）響應頭字段中指定編碼。可使用 [proxy\_ignore\_headers](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_ignore_headers>) 、[fastcgi\_ignore\_headers](<225 [02.01.01 http] ngx_http_fastcgi_module 模組.md#fastcgi_ignore_headers>) 、[uwsgi\_ignore\_headers](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_ignore_headers>) 、[scgi\_ignore\ (https://nginx.org/ru/docs/http/ngx_http_scgi_module.html#scgi_ignore_headers) (https://nginx.org/ru/docs/http/ngx_http_grpc_module.html#grpc_ignore_headers) 。

Описывает таблицу перекодирования из одной кодировки в другую. Таблица для обратного перекодирования строится на основании тех же данных. Коды символов задаются в шестнадцатеричном виде. Неописанные символы в пределах 80-FF заменяются на “`?`”. При перекодировании из UTF-8 символы, отсутствующие в однобайтной кодировке, заменяются на “`&#XXXX;`”.

描述一種編碼到另一種編碼的轉換表。反向轉換表使用相同的資料建構。字元代碼以十六進位指定。 80 到FF範圍內的未定義字元被替換為「 `?` 」。從UTF到 8 轉換時，單字節編碼中不存在的字元被替換為「 `&#XXXX;` 」。

Пример:

例子：

> ```
> charset_map koi8-r windows-1251 {
>     C0 FE ; # small yu
>
>     C0 FE ; # 小 yu
>     C1 E0 ; # small a
>
>     C1 E0;# 小 a
>     C2 E1 ; # small b
>
>     C2 E1；#小b
>     C3 F6 ; # small ts
>
>     C3 F6；#小ts
>     ...
> }
> ```

При описании таблицы перекодирования в UTF-8, коды кодировки UTF-8 должны быть указаны во второй колонке, например:

在描述UTF -8中的轉換錶時，應在第二列中註明UTF -8的編碼，例如：

> ```
> charset_map koi8-r utf-8 {
>     C0 D18E ; # small yu
>
>     C0 D18E ; # 小 yu
>     C1 D0B0 ; # small a
>
>     C1 D0B0 ; # 小 a
>     C2 D0B1 ; # small b
>
>     C2 D0B1 ; # 小 b
>     C3 D186 ; # small ts
>
>     C3 D186；#小ts
>     ...
> }
> ```

Полные таблицы преобразования из `koi8-r` в `windows-1251` и из `koi8-r` и `windows-1251` в `utf-8` входят в дистрибутив и находятся в файлах `conf/koi-win`, `conf/koi-utf` и `conf/win-utf`.

發行版中包含從`koi8-r`到`windows-1251`以及從`koi8-r`和`windows-1251`到`utf-8`的完整轉換錶，這些轉換錶位於檔案`conf/koi-win`, `conf/koi-utf`和`conf/win-utf`中。

Эта директива появилась в версии 0.7.9.

該指令是在版本0.7.9中引入的。

Разрешает работу модуля в ответах с указанными MIME-типами в дополнение к “`text/html`”. Специальное значение “`*`” соответствует любому MIME-типу (0.8.29).

使此模組能夠處理除「 `text/html` 」類型之外的指定MIME類型的回應。特殊值“ `*` ”匹配任何MIME類型（ 0.8.29 ）。

> До версии 1.5.4 по умолчанию вместо MIME-типа “`application/javascript`” использовался “`application/x-javascript`”.
>
> 在版本1.5.4預設使用「 `application/x-javascript` 」而不是MIME -type “ `application/javascript` ”。

Определяет, выполнять ли перекодирование для ответов, полученных от проксированного сервера или от FastCGI/uwsgi/SCGI/gRPC-сервера, если в ответах уже указана кодировка в поле “Content-Type”（內容類型） заголовка ответа. Если перекодирование разрешено, то в качестве исходной кодировки используется кодировка, указанная в полученном ответе.

確定是否對從代理伺服器或 FastCGI/uwsgi/ SCGI /gRPC 伺服器接收的回應執行編碼轉碼，前提是回應的“Content-Type”（內容類型）回應頭字段中已指定了編碼。如果啟用編碼，則使用接收到的回應中指定的編碼作為來源編碼。

> Необходимо отметить, что если ответ был получен в подзапросе, то, независимо от значения директивы `override_charset`, всегда выполняется перекодирование из кодировки ответа в кодировку основного запроса.
>
> 需要注意的是，如果在子請求中收到回應，則無論`override_charset`指令的值如何，都會始終執行從回應編碼到主請求編碼的轉換。

Задаёт исходную кодировку ответа. Если эта кодировка отличается от указанной в директиве [charset](#charset), то выполняется перекодирование.

指定回應的初始編碼。如果此編碼與 [charset](#charset)指令中指定的編碼不同，則會執行重新編碼。
