# Запись в syslog｜寫入系統日誌

> 章節：[ru](<000 目錄.md#c-9>) › [docs｜文件](<000 目錄.md#c-10>)

## Запись в syslog｜寫入系統日誌

Директивы [error\_log](<285 [02.01 文件] 基本功能.md#error_log>) и [access\_log](<242 [02.01.01 http] 模組 ngx_http_log_module.md#access_log>) поддерживают запись в syslog. Запись в syslog настраивается при помощи следующих параметров:

[error\_log](<285 [02.01 文件] 基本功能.md#error_log>)和 [access\_log](<242 [02.01.01 http] 模組 ngx_http_log_module.md#access_log>)指令支援將日誌記錄到 syslog。 syslog 日誌記錄使用下列參數進行設定：

`server=``*адрес*`

Задаёт адрес сервера syslog. Адрес может быть указан в виде доменного имени или IP-адреса, и необязательного порта, или в виде пути UNIX-сокета, который указывается после префикса “`unix:`”. Если порт не указан, используется UDP-порт 514. Если доменному имени соответствует несколько IP-адресов, используется только первый адрес.

指定係統日誌伺服器位址。位址可以指定為網域名稱、 IP位址（選用連接埠）或UNIX套接字路徑（位於「 `unix:` 」前綴之後）。如果未指定端口，則使用UDP端口 514。如果網域名稱符合多個IP位址，則僅使用第一個位址。

`facility=``*строка*`

Задаёт категорию сообщений syslog в соответствии с [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1). В качестве категории может быть указано одно из следующих значений: “`kern`”, “`user`”, “`mail`”, “`daemon`”, “`auth`”, “`intern`”, “`lpr`”, “`news`”, “`uucp`”, “`clock`”, “`authpriv`”, “`ftp`”, “`ntp`”, “`audit`”, “`alert`”, “`cron`”, “`local0`”..“`local7`”. По умолчанию используется “`local7`”.

根據 [設定 syslog 訊息類別RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1)該類別可以是以下值之一：“`kern`”, “`user`”, “`mail`”, “`daemon`”, “`auth`”, “`intern`”, “`lpr`”, “`news`”, “`uucp`”, “`clock`”, “`authpriv`”, “`ftp`”, “`ntp`”, “`audit`”, “`alert`”, “`cron`”, “`local0`”..“`local7`預設值為“`local7`”.

`severity=``*строка*`

Задаёт важность сообщений syslog для [access\_log](<242 [02.01.01 http] 模組 ngx_http_log_module.md#access_log>) в соответствии с [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1). Возможны те же самые значения, что и у второго параметра (уровень) директивы [error\_log](<285 [02.01 文件] 基本功能.md#error_log>). По умолчанию используется “`info`”.

根據 [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1)設定 [access\_log](<242 [02.01.01 http] 模組 ngx_http_log_module.md#access_log>)的 syslog 訊息嚴重性等級。其值與 [error\_log](<285 [02.01 文件] 基本功能.md#error_log>)指令的第二個參數（等級）的值相同。預設值為“ `info` ”。

> Важность сообщений об ошибках определяется самим nginx, поэтому в директиве `error_log` параметр игнорируется.
>
> 錯誤訊息的嚴重程度由 nginx 本身決定，因此在`error_log`指令中忽略該參數。

`tag=``*строка*`

Задаёт метку сообщений syslog. По умолчанию используется “`nginx`”.

指定係統日誌訊息標籤。預設值為“ `nginx` ”。

`nohostname`

Запрещает добавление поля “hostname” в заголовок сообщения syslog (1.9.7).

阻止將「hostname」欄位新增至 syslog 訊息標頭（ 1.9.7 ）。

Пример конфигурации syslog:

系統日誌配置範例：

> ```
> error_log syslog:server=192.168.1.1 debug;
>
> error_log syslog:server= 192.168.1.1 debug;
> 
> access_log syslog:server=unix:/var/log/nginx.sock,nohostname;
> access_log syslog:server=[2001:db8::1]:12345,facility=local7,tag=nginx,severity=info combined;
>
> access_log syslog:server=[ 2001:db8::1 ]:12345,facility=local7,tag=nginx,severity=info combined;
> ```

> Запись в syslog доступна начиная с версии 1.7.1. Как часть [коммерческой подписки](https://www.f5.com/products/nginx) запись в syslog доступна начиная с версии 1.5.3.
>
> 從版本1.7.1開始提供系統日誌記錄功能。作為[商業訂閱](https://www.f5.com/products/nginx)從版本1.5.3開始提供系統日誌記錄功能。
