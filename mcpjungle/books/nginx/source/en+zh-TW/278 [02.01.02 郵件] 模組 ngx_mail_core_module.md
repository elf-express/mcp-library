`proxy_protocol` ( 1.19.8 ) 參數指定在此連接埠上接收的所有連接都應使用 [PROXY協定](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt) 。接收到的資訊將傳遞給 [驗證伺服器](<277 [02.01.02 郵件] ngx_mail_auth_http_module 模組.md#proxy_protocol>) ，並可用於 [更改客戶端位址](<282 [02.01.02 郵件] 模組 ngx_mail_realip_module.md>) 。

В директиве `listen` можно также указать несколько дополнительных параметров, специфичных для связанных с сокетами системных вызовов.

`listen`指令也可以指定幾個與套接字相關的系統呼叫特有的其他選項。

`backlog`\=`*число*`

задаёт параметр `backlog` в вызове `listen()`, который ограничивает максимальный размер очереди ожидающих приёма соединений (1.9.2). По умолчанию `backlog` устанавливается равным -1 для FreeBSD, DragonFly BSD и macOS, и 511 для других платформ.

在`listen()`呼叫中設定`backlog`參數，此參數限制待處理連接隊列的最大大小 ( 1.9.2 )。預設情況下，在 FreeBSD、DragonFly BSD和 macOS 上， `backlog`設定為 -1，在其他平台上設定為 511。

`rcvbuf`\=`*размер*`

задаёт размер буфера приёма (параметр `SO_RCVBUF`) для слушающего сокета (1.11.13).

設定監聽套接字（ 1.11.13 ）的接收緩衝區大小（參數`SO_RCVBUF` ）。

`sndbuf`\=`*размер*`

задаёт размер буфера передачи (параметр `SO_SNDBUF`) для слушающего сокета (1.11.13).

設定監聽套接字（ 1.11.13 ）的發送緩衝區大小（參數`SO_SNDBUF` ）。

`bind`

указывает, что для данной пары `*адрес*`:`*порт*` нужно делать `bind()` отдельно. Это нужно потому, что если описаны несколько директив `listen` с одинаковым портом, но разными адресами, и одна из директив `listen` слушает на всех адресах для данного порта (`*:``*порт*`), то nginx сделает `bind()` только на `*:``*порт*`. Необходимо заметить, что в этом случае для определения адреса, на который пришло соединение, делается системный вызов `getsockname()`. Если же используются параметры `backlog`, `rcvbuf`, `sndbuf`, `ipv6only`, `multipath` или `so_keepalive`, то для данной пары `*адрес*`:`*порт*` всегда делается отдельный вызов `bind()`.

表示對於給定的`*адрес*`:`*порт*`對，應單獨執行`bind()`操作。這是必要的，因為如果宣告了多個`listen`指令，且這些指令使用相同的連接埠但不同的位址，並且其中一個`listen`指令監聽給定連接埠的所有位址（ `*:``*порт*` ），則 nginx 只會對`bind()` ），則 nginx 只會對`*:``*порт*`需要注意的是，在這種情況下，會執行`getsockname()`系統呼叫來決定接收到連接的位址。如果使用`backlog`, `rcvbuf`, `sndbuf`, `ipv6only`, `multipath`或`so_keepalive`參數，則始終會針對給定的`*адрес*`:`*порт*`對執行單獨的`bind()`呼叫。

`ipv6only`\=`on`|`off`

этот параметр определяет (через параметр сокета `IPV6_V6ONLY`), будет ли слушающий на wildcard-адресе `[::]` IPv6-сокет принимать только IPv6-соединения, или же одновременно IPv6- и IPv4-соединения. По умолчанию параметр включён. Установить его можно только один раз на старте.

此參數（透過套接字參數`IPV6_V6ONLY` ）決定監聽通配符位址`[::]`的 IPv6 套接字是否僅接受 IPv6 連接，還是同時接受 IPv6 和 IPv4 連接。此參數預設啟用，且只能在啟動時設定一次。

`multipath`

этот параметр (1.29.7) конфигурирует для слушающего сокета протокол [Multipath TCP](https://datatracker.ietf.org/doc/html/rfc8684) (`IPPROTO_MPTCP`). В настоящий момент это работает только на Linux 5.6+.

此參數（ 1.29.7 ）配置監聽套接字的[多路徑TCP](https://datatracker.ietf.org/doc/html/rfc8684) （ `IPPROTO_MPTCP` ）協定。目前，這僅適用於5.6 +。

> Добавление или удаление этого параметра также включает параметр сокета `SO_REUSEPORT`, что может быть [небезопасно](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 新增或刪除此選項也會啟用`SO_REUSEPORT`套接字選項，此選項可能 [不安全](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`so_keepalive`\=`on`|`off`|\[`*keepidle*`\]:\[`*keepintvl*`\]:\[`*keepcnt*`\]

этот параметр конфигурирует для слушающего сокета поведение “TCP keepalive”. Если этот параметр опущен, то для сокета будут действовать настройки операционной системы. Если он установлен в значение “`on`”, то для сокета включается параметр `SO_KEEPALIVE`. Если он установлен в значение “`off`”, то для сокета параметр `SO_KEEPALIVE` выключается. Некоторые операционные системы поддерживают настройку параметров “TCP keepalive” на уровне сокета посредством параметров `TCP_KEEPIDLE`, `TCP_KEEPINTVL` и `TCP_KEEPCNT`. На таких системах (в настоящий момент это Linux, NetBSD, Dragonfly, FreeBSD и macOS) их можно сконфигурировать с помощью параметров `*keepidle*`, `*keepintvl*` и `*keepcnt*`. Один или два параметра могут быть опущены, в таком случае для соответствующего параметра сокета будут действовать стандартные системные настройки. Например,

此參數配置監聽套接字的「 TCP keepalive」行為。如果省略此參數，則使用套接字的作業系統設定。如果設定為“ `on` ”，則為套接字啟用`SO_KEEPALIVE` ”選項。如果設定為“ `off` ”，則為套接字停用`SO_KEEPALIVE` ”選項。某些作業系統支援使用`TCP_KEEPIDLE`, `TCP_KEEPINTVL`和`TCP_KEEPCNT`選項在套接字層級設定「 TCP keepalive」選項。在這些系統（目前包括 Linux、NetBSD、Dragonfly、FreeBSD 和 macOS）上，可以使用`*keepidle*`, `*keepintvl*`和`*keepcnt*`選項進行設定。可以省略一個或兩個參數，在這種情況下，對應的套接字參數將套用系統預設。例如：

> ```
> so_keepalive=30m::10
>
> 所以保持存活=30分鐘::10
> ```

установит таймаут бездействия (`TCP_KEEPIDLE`) в 30 минут, для интервала проб (`TCP_KEEPINTVL`) будет действовать стандартная системная настройка, а счётчик проб (`TCP_KEEPCNT`) будет равен 10.

將不活動逾時（ `TCP_KEEPIDLE` ）設定為 30 分鐘，探測間隔（ `TCP_KEEPINTVL` ）將保持系統預設設置，探測計數（ `TCP_KEEPCNT` ）將為 10。

位址可以指定為網域名稱或IP位址，以及可選連接埠（1.3.1, 1.2.2）。如果未指定端口，則使用端口 53。 DNS 伺服器被循環輪詢。

> До версии 1.1.7 можно было задать лишь один DNS-сервер. Задание DNS-серверов с помощью IPv6-адресов поддерживается начиная с версий 1.3.1 и 1.2.2.
>
> 在版本1.1.7只能指定一個DNS伺服器。從版本1.3.1和1.2.2開始，支援使用IPv6位址指定DNS伺服器。

По умолчанию nginx будет искать как IPv4-, так и IPv6-адреса при преобразовании имён в адреса. Если поиск IPv4- или IPv6-адресов нежелателен, можно указать параметр `ipv4=off` (1.23.1) или `ipv6=off`.

預設情況下，nginx 在將名稱解析為位址時會同時尋找 IPv4 和 IPv6 位址。如果您不想尋找 IPv4 或 IPv6 位址，可以指定`ipv4=off` ( 1.23.1 ) 或`ipv6=off`參數。

> Преобразование имён в IPv6-адреса поддерживается начиная с версии 1.5.8.
>
> 從版本1.5.8開始支援將名稱轉換為 IPv6 位址。

По умолчанию nginx кэширует ответы, используя значение TTL из ответа. Необязательный параметр `valid` позволяет это переопределить:

預設情況下，nginx 使用回應中的TTL值快取回應。可選的`valid`參數可讓您覆寫此設定：

> ```
> resolver 127.0.0.1 [::1]:5353 valid=30s;
>
> 解析器127.0.0.1 [::1]:5353 有效=30秒;
> ```

> До версии 1.1.9 настройка времени кэширования была невозможна и nginx всегда кэшировал ответы на срок в 5 минут.
>
> 在1.1.9無法配置快取時間，nginx 總是快取回應 5 分鐘。

> Для предотвращения DNS-спуфинга рекомендуется использовать DNS-серверы в защищённой доверенной локальной сети.
>
> 為防止DNS欺騙，建議在安全、可信任的本地網路中使用DNS伺服器。

Необязательный параметр `status_zone` (1.17.1) включает [сбор информации](https://nginx.org/ru/docs/http/ngx_http_api_module.html#resolvers_) о запросах и ответах сервера DNS в указанной `*зоне*`. Параметр доступен как часть [коммерческой подписки](https://www.f5.com/products/nginx).

可選參數`status_zone` ( 1.17.1 ) 啟用 [收集資訊](https://nginx.org/ru/docs/http/ngx_http_api_module.html#resolvers_)關於指定`*зоне*`中的伺服器請求和回應DNS 。此參數作為 [商業訂閱](https://www.f5.com/products/nginx)的一部分提供。
