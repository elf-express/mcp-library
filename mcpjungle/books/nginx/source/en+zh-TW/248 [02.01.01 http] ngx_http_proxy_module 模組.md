Модуль `ngx_http_proxy_module` позволяет передавать запросы другому серверу.

`ngx_http_proxy_module`模組允許您將請求轉發到另一個伺服器。

#### Пример конфигурации｜配置範例

> ```
> location / {
>
> 地點 / {
>     proxy_pass       http://localhost:8000;
>
>     proxy_pass http://localhost:8000;
>     proxy_set_header Host      $host;
>
>     proxy_set_header Host $host;
>     proxy_set_header X-Real-IP $remote_addr;
>
>     proxy_set_header X-Real- IP $remote_addr;
> }
> ```

Параметр `transparent` (1.11.0) позволяет задать нелокальный IP-aдрес, который будет использоваться в исходящих соединениях с проксируемым сервером, например, реальный IP-адрес клиента:

`transparent` ( 1.11.0 ) 參數允許您指定一個非本地IP位址，該位址將用於與代理伺服器建立出站連接，例如客戶端的真實IP位址：

> ```
> proxy_bind $remote_addr transparent;
> ```

Для работы параметра обычно требуется запустить рабочие процессы nginx с привилегиями [суперпользователя](<285 [02.01 文件] 基本功能.md#user>). В Linux этого не требуется (1.13.8), так как если указан параметр `transparent`, то рабочие процессы наследуют capability `CAP_NET_RAW` из главного процесса. Также необходимо настроить таблицу маршрутизации ядра для перехвата сетевого трафика с проксируемого сервера.

此參數通常要求以 [superuser 權限](<285 [02.01 文件] 基本功能.md#user>) ) 執行 nginx 工作進程。在 Linux 系統上則無需此操作 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程將從主進程繼承`CAP_NET_RAW`權限。此外，您還需要設定核心路由表以攔截來自代理伺服器的網路流量。

Задаёт `*размер*` буфера, в который будет читаться первая часть ответа, получаемого от проксируемого сервера. В этой части ответа находится, как правило, небольшой заголовок ответа; если его размер больше заданного, то такой ответ считается [неверным](#invalid_header). По умолчанию размер одного буфера равен размеру страницы памяти. В зависимости от платформы это или 4K, или 8K, однако его можно сделать меньше.

指定用於讀取從代理伺服器接收的回應第一部分的緩衝區`*размер*` 。響應的這一部分通常包含一個較小的響應頭；如果其大小大於指定值，則該響應被視為[不正確](#invalid_header) ）。預設情況下，一個緩衝區的大小等於一個記憶體頁的大小。根據平台的不同，該大小為 4K 或 8K，但可以減少。

Разрешает или запрещает использовать буферизацию ответов проксируемого сервера.

啟用或停用代理伺服器回應的緩衝。

Если буферизация включена, то nginx принимает ответ проксируемого сервера как можно быстрее, сохраняя его в буферы, заданные директивами [proxy\_buffer\_size](#proxy_buffer_size) и [proxy\_buffers](#proxy_buffers). Если ответ не вмещается целиком в память, то его часть может быть записана на диск во [временный файл](#proxy_temp_path). Запись во временные файлы контролируется директивами [proxy\_max\_temp\_file\_size](#proxy_max_temp_file_size) и [proxy\_temp\_file\_write\_size](#proxy_temp_file_write_size).

如果啟用了緩衝，nginx 會盡快接收來自代理伺服器的回應，並將其儲存在 [proxy_buffer_size](#proxy_buffer_size)和 [proxy_buffers](#proxy_buffers)指令指定的緩衝區中。如果整個回應無法放入內存，則可以將其一部分寫入磁碟上的 [temporary file](#proxy_temp_path)暫存檔案。寫入暫存檔案由 [proxy_max_temp_file_size](#proxy_max_temp_file_size)和 [proxy_temp_file_write_size](#proxy_temp_file_write_size)指令控制。

Если буферизация выключена, то ответ синхронно передаётся клиенту сразу же по мере его поступления. nginx не пытается считать весь ответ проксируемого сервера. Максимальный размер данных, который nginx может принять от сервера за один раз, задаётся директивой [proxy\_buffer\_size](#proxy_buffer_size).

如果停用緩衝，回應會在到達後立即同步傳輸給用戶端。 NGINX 不會嘗試從代理伺服器讀取整個回應。 NGINX 一次可以從伺服器接收的最大資料大小由 [proxy\_buffer\_size](#proxy_buffer_size)指令指定。

Буферизация может быть также включена или выключена путём передачи значения “`yes`” или “`no`” в поле “X-Accel-Buffering” заголовка ответа. Эту возможность можно запретить с помощью директивы [proxy\_ignore\_headers](#proxy_ignore_headers).

也可以透過在“X-Accel-Buffering”響應頭字段中傳遞值「 `yes` 」或「 `no` 」來啟用或停用緩衝。可以使用 [proxy\_ignore\_headers](#proxy_ignore_headers)指令停用此功能。

Если параметр установлен в значение “`off`”, то временные файлы будут располагаться непосредственно в каталоге кэша.

快取的回應首先寫入一個臨時文件，然後對其進行重新命名。從版本0.8.9臨時檔案和快取可以位於不同的檔案系統上。但是要注意的是，在這種情況下，檔案不是在一個檔案系統內進行簡單的重新命名操作，而是從一個檔案系統複製到另一個檔案系統。因此，最好將快取與包含暫存檔案的目錄放在同一個檔案系統上。暫存檔案所在的目錄由`use_temp_path` （ 1.7.10 ）參數決定。如果未指定此參數或將其設為“ `on` ”，則將使用[proxy\_temp\_path](#proxy_temp_path)指令為給定位置指定的目錄。如果將此參數設為“ `off` ”，則暫存檔案將直接位於快取目錄中。

Кроме того, все активные ключи и информация о данных хранятся в зоне разделяемой памяти, `*имя*` и `*размер*` которой задаются параметром `keys_zone`. Зоны размером в 1 мегабайт достаточно для хранения около 8 тысяч ключей.

此外，所有活動金鑰和資料資訊都儲存在共享記憶體區域`*имя*`和`*размер*`中，該區域由`keys_zone`參數指定。 1兆位元組的區域足以儲存約8000個密鑰。

> Как часть [коммерческой подписки](https://www.f5.com/products/nginx) в зоне разделяемой памяти также хранится расширенная [информация](https://nginx.org/ru/docs/http/ngx_http_api_module.html#http_caches_) о кэше, поэтому для хранения аналогичного количества ключей необходимо указывать больший размер зоны. Например зоны размером в 1 мегабайт достаточно для хранения около 4 тысяч ключей.
>
> 作為[商業訂閱](https://www.f5.com/products/nginx)共享記憶體區域也會儲存關於快取的擴充[資訊](https://nginx.org/ru/docs/http/ngx_http_api_module.html#http_caches_) ，因此，要儲存相同數量的鍵，需要更大的區域大小。例如，1兆位元組的區域足以儲存大約4000個鍵。

Если к данным кэша не обращаются в течение времени, заданного параметром `inactive`, то данные удаляются, независимо от их свежести. По умолчанию `inactive` равен 10 минутам.

如果快取資料在`inactive`指定的時間內未被訪問，則無論其新鮮度如何，資料都將被刪除。預設情況下， `inactive`為 10 分鐘。

Специальный процесс “cache manager” следит за максимальным размером кэша, заданным параметром `max_size`, а также за минимальным объёмом свободного места на файловой системе с кэшем, заданным параметром `min_free` (1.19.1). При превышении максимального размера кэша или недостаточном объёме свободного места процесс удаляет наименее востребованные данные. Удаление данных происходит итерациями, настраиваемыми параметрами (1.11.5) `manager_files`, `manager_threshold` и `manager_sleep`. За одну итерацию загружается не более `manager_files` элементов (по умолчанию 100). Время работы одной итерации ограничено параметром `manager_threshold` (по умолчанию 200 миллисекунд). Между итерациями делается пауза на время, заданное параметром `manager_sleep` (по умолчанию 50 миллисекунд).

一個特殊的「快取管理器」程序會監控由參數`max_size`指定的最大快取大小，以及由參數`min_free` （ 1.19.1 ）指定的檔案系統上包含快取的最小可用空間。如果超過最大快取大小或可用空間不足，則該程序會刪除使用頻率最低的資料。資料刪除操作會依照參數（ 1.11.5 ）、 `manager_files`, `manager_threshold`和`manager_sleep`配置的迭代次數進行。每次迭代最多載入`manager_files`個元素（預設為100個）。單次迭代的持續時間由參數`manager_threshold`限制（預設為200毫秒）。在兩次迭代之間，會暫停一段時間，該時間由參數`manager_sleep`指定（預設為50毫秒）。

Через минуту после старта активируется специальный процесс “cache loader”, который загружает в зону кэша информацию о ранее закэшированных данных, хранящихся на файловой системе. Загрузка также происходит итерациями. За одну итерацию загружается не более `loader_files` элементов (по умолчанию 100). Кроме того, время работы одной итерации ограничено параметром `loader_threshold` (по умолчанию 200 миллисекунд). Между итерациями делается пауза на время, заданное параметром `loader_sleep` (по умолчанию 50 миллисекунд).

啟動一分鐘後，一個特殊的「快取載入器」進程會被激活，將檔案系統中先前快取的資料資訊載入到快取區域。載入過程以迭代方式進行，每次迭代最多載入`loader_files`個元素（預設值為100）。此外，單次迭代的運行時間受`loader_threshold`參數的限制（預設值為200毫秒）。迭代之間會暫停一段時間，該時間由`loader_sleep`參數指定（預設值為50毫秒）。

Значение 0 отключает возможность буферизации ответов во временные файлы.

`error`

произошла ошибка соединения с сервером, передачи ему запроса или чтения заголовка ответа сервера;

連接伺服器、向伺服器發送請求或讀取伺服器回應頭時發生錯誤；

произошёл таймаут во время соединения с сервером, передачи ему запроса или чтения заголовка ответа сервера;

Необходимо понимать, что передача запроса следующему серверу возможна только при условии, что клиенту ещё ничего не передавалось. То есть, если ошибка или таймаут возникли в середине передачи ответа клиенту, то исправить это уже невозможно.

需要注意的是，只有在尚未向客戶端發送任何資料的情況下，才能將請求傳遞給下一個伺服器。這意味著，如果在向客戶端發送回應的過程中發生錯誤或逾時，則無法修復。

    >

    > ```
    
-   Если директива `proxy_pass` указана без URI, то при обработке первоначального запроса на сервер передаётся URI запроса в том же виде, в каком его прислал клиент, а при обработке изменённого URI - нормализованный URI запроса целиком:  
    如果指定了`proxy_pass`指令而URI指定URI指令，則在處理初始請求時， URI請求將以客戶端發送的相同形式傳輸到伺服器；在處理修改後的URI請求時，將完整地傳輸到伺服器。
    
    > ```
    > location /some/path/ {
    >     proxy_pass http://127.0.0.1;
    > }
    > ```
    
    > До версии 1.1.12, если `proxy_pass` указана без URI, в ряде случаев при изменении URI на сервер мог передаваться URI первоначального запроса вместо изменённого URI.
    >
    > 在版本1.1.12之前，如果指定了`proxy_pass`而URI指定URI ，則在某些情況下，當URI更改時，可能會將原始請求的URI發送到伺服器，而不是將更改後的伺服器上。
    

В ряде случаев часть URI запроса, подлежащую замене, выделить невозможно:

在某些情況下，無法選擇需要替換的URI查詢部分：

-   Если location задан регулярным выражением, а также в именованных location’ах.  
    如果位置是透過正規表示式指定的，或在命名位置中指定。
    
    В этих случаях `proxy_pass` следует указывать без URI.

    在這些情況下，應標明`proxy_pass` ，而不用標明URI 。
    
-   Если внутри проксируемого location с помощью директивы [rewrite](<253 [02.01.01 http] ngx_http_rewrite_module 模組.md#rewrite>) изменяется URI, и именно с этой конфигурацией будет обрабатываться запрос (`break`):  
    如果代理位置(https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html#rewrite)內部使用 [rewrite] 指令URI進行了​​更改，並且請求將使用此配置進行處理 ( `break` )：
    
    > ```
    > location /name/ {
    >
    > 位置 /name/ {
    >     rewrite    /name/([^/]+) /users?name=$1 break;
    >
    >     rewrite /name/([^/]+) /users?name=$1 break;
    >     proxy_pass http://127.0.0.1;
    > }
    > ```

    在這種情況下，指令中指定的URI將被忽略，並且整個修改後的URI請求將被傳送到伺服器。
    
-   При использовании переменных в `proxy_pass`:  
    在`proxy_pass`中使用變數時：
    
    > ```
    > location /name/ {
    >
    > 位置 /name/ {
    >     proxy_pass http://127.0.0.1$request_uri;
    > }
    > ```
    
    В этом случае если в директиве указан URI, он передаётся на сервер как есть, заменяя URI первоначального запроса.

    在這種情況下，如果指令中指定了URI ，則會按原樣將其傳遞給伺服器，替換原始請求中的URI 。

Задаёт кэш, в котором могут храниться [SSL-сертификаты](#proxy_ssl_certificate) и [секретные ключи](#proxy_ssl_certificate_key), полученные из [переменных](#proxy_ssl_certificate_key_variables).

У директивы есть следующие параметры:

此指令具有以下參數：

`max`

задаёт максимальное число элементов в кэше; при переполнении кэша удаляются наименее востребованные элементы (LRU);

設定快取中的最大項目數；當快取已滿時，將刪除最不常用的項目（ LRU ）；

`inactive`

задаёт время, после которого элемент кэша удаляется, если к нему не было обращений в течение этого времени; по умолчанию 10 секунд;

指定快取項目在多長時間內未被存取後將被刪除；預設值為 10 秒；

`valid`

задает время, в течение которого элемент кэша считается действительным и может быть повторно использован, по умолчанию 60 секунд. По завершении этого времени сертификат будет обновлён или повторно проверен;

指定快取項目被視為有效且可重複使用的時間；預設值為 60 秒。此時間過後，證書將被續訂或重新驗證；

`off`

запрещает кэш.

禁用緩存。

允許將檔案儲存到磁碟。 `on` 選項根據 [alias](<221 [02.01.01 http] 模組 ngx_http_core_module.md#alias>) 或 [root](<221 [02.01.01 http] 模組 ngx_http_core_module.md#root>) 指令中指定的路徑儲存檔案。設定 `off` 會阻止儲存檔案。此外，可以使用變數行明確設定檔案名稱：

Время изменения файлов выставляется согласно полученному полю “Last-Modified”（最後修改日期） в заголовке ответа. Ответ сначала записывается во временный файл, а потом этот файл переименовывается. Начиная с версии 0.8.9 временный файл и постоянное место хранения ответа могут располагаться на разных файловых системах. Однако нужно учитывать, что в этом случае вместо дешёвой операции переименовывания в пределах одной файловой системы файл копируется с одной файловой системы на другую. Поэтому лучше, если сохраняемые файлы будут находиться на той же файловой системе, что и каталог с временными файлами, задаваемый директивой [proxy\_temp\_path](#proxy_temp_path) для данного location.

文件修改時間根據回應頭中接收到的“Last-Modified”（最後修改日期）字段設定。回應首先寫入臨時文件，然後重新命名該文件。從版本0.8.9開始，回應的暫存檔案和永久儲存位置可以位於不同的檔案系統上。但是需要注意的是，在這種情況下，檔案不是在同一個檔案系統內進行簡單的重新命名操作，而是從一個檔案系統複製到另一個檔案系統。因此，對於給定的位置，最好將已儲存的檔案與 [proxy\_temp\_path](#proxy_temp_path)指令指定的暫存檔案目錄位於相同檔案系統上。

#### Встроенные переменные｜內建變數

В модуле `ngx_http_proxy_module` есть встроенные переменные, которые можно использовать для формирования заголовков с помощью директивы [proxy\_set\_header](#proxy_set_header):

`ngx_http_proxy_module`模組內建了一些變量，可以使用 [proxy\_set\_header](#proxy_set_header)指令產生標頭：

`$proxy_host`

имя и порт проксируемого сервера, как указано в директиве [proxy\_pass](#proxy_pass);

代理伺服器的名稱和端口，如 [proxy\_pass](#proxy_pass)指令中所述；

`$proxy_port`

порт проксируемого сервера, как указано в директиве [proxy\_pass](#proxy_pass), или стандартный порт протокола;

代理伺服器的端口，如 [proxy\_pass](#proxy_pass)指令中所述，或標準協定端口；

`$proxy_add_x_forwarded_for`

поле заголовка запроса клиента “X-Forwarded-For”（X-轉發） и добавленная к нему через запятую переменная `$remote_addr`. Если же поля “X-Forwarded-For”（X-轉發） в заголовке запроса клиента нет, то переменная `$proxy_add_x_forwarded_for` равна переменной `$remote_addr`.

客戶端請求頭字段“X-Forwarded-For”（X-轉發）和附加到其後的變數`$remote_addr` ，用逗號分隔。如果客戶端請求頭字段“X-Forwarded-For”（X-轉發）不存在，則變數`$proxy_add_x_forwarded_for`等於變數`$remote_addr` 。
