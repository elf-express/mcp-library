Модуль `ngx_stream_core_module` доступен начиная с версии 1.9.0. По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-stream`.

從版本1.9.0開始提供`ngx_stream_core_module`模組。此模組預設未建置；必須使用`--with-stream`配置參數啟用其建置。

Задаёт `*адрес*` и `*порт*` для сокета, на котором сервер будет принимать соединения. Можно указать только порт. Кроме того, адрес может быть именем хоста, например:

指定伺服器接受連線的套接字`*адрес*`和`*порт*` 。只能指定連接埠。或者，位址也可以是主機名，例如：

> ```
> listen 127.0.0.1:12345;
>
> 聽127.0.0.1:12345 ;
> listen *:12345;
>
> 監聽 *:12345;
> listen 12345;     # то же, что и *:12345
>
> 監聽 12345；# 等同於 *:12345
> listen localhost:12345;
>
> 監聽 localhost:12345;
> ```

IPv6-адреса задаются в квадратных скобках:

IPv6 位址用方括號括起來：

> ```
> listen [::1]:12345;
>
> 監聽 [::1]:12345;

> ```

UNIX-сокеты задаются префиксом “`unix:`”

UNIX套接字由前綴「 `unix:` 」指定

> ```
> listen unix:/var/run/nginx.sock;

Диапазоны портов (1.15.10) задаются при помощи указания первого и последнего порта через дефис:

端口範圍（ 1.15.10 ）透過指定第一個端口和最後一個端口，並用連字符分隔來指定：

> ```
> listen 127.0.0.1:12345-12399;
>

Если у директивы есть параметр `default_server`, то сервер, в котором описана эта директива, будет сервером по умолчанию для указанной пары `*адрес*`:`*порт*` (1.25.5). Если же директив с параметром `default_server` нет, то сервером по умолчанию будет первый сервер, в котором описана пара `*адрес*`:`*порт*`.

如果指令帶有`default_server`參數，則定義該指令的伺服器將成為指定`*адрес*`:`*порт*` ( 1.25.5 ) 對的預設伺服器。如果沒有帶有`default_server`參數的指令，則預設伺服器將是第一個定義`*адрес*`:`*порт*`對的伺服器。

Параметр `ssl` указывает на то, что все соединения, принимаемые на данном порту, должны работать в режиме SSL.

`ssl`參數指定在此連接埠上接收的所有連接都應以SSL模式運作。

Параметр `udp` конфигурирует слушающий сокет для работы с датаграммами (1.9.13). Для обработки пакетов с одного адреса и порта в рамках одной сессии необходимо также указывать параметр [`reuseport`](#reuseport).

`udp`參數配置用於處理資料封包的監聽套接字 ( 1.9.13 )。要在單一會話中處理來自單一位址和連接埠的封包，也必須指定 [`reuseport`](#reuseport)參數。

Параметр `proxy_protocol` (1.11.4) указывает на то, что все соединения, принимаемые на данном порту, должны использовать [протокол PROXY](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt).

`proxy_protocol` ( 1.11.4 ) 參數指定在此連接埠上接收的所有連接必須使用 [協定PROXY](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt) 。

> Протокол PROXY версии 2 поддерживается начиная с версии 1.13.11.
>
> 從版本1.13.11開始支援PROXY協定版本 2。

В директиве `listen` можно также указать несколько дополнительных параметров, специфичных для связанных с сокетами системных вызовов. Эти параметры можно задать в любой директиве `listen`, но только один раз для указанной пары `*адрес*`:`*порт*`.

`listen`指令也可以指定幾個與套接字相關的系統呼叫特有的附加選項。這些選項可以在任何`listen`指令中指定，但對於給定的`*адрес*`:`*порт*`對只能指定一次。

`setfib`\=`*число*`

этот параметр (1.25.5) задаёт таблицу маршрутизации, FIB (параметр `SO_SETFIB`) для слушающего сокета. В настоящий момент это работает только на FreeBSD.

此參數 ( 1.25.5 ) 指定監聽套接字的路由表 ( FIB ，參數`SO_SETFIB` )。目前，此功能僅適用於 FreeBSD。

`fastopen`\=`*число*`

включает “[TCP Fast Open](http://en.wikipedia.org/wiki/TCP_Fast_Open)” для слушающего сокета (1.21.0) и [ограничивает](https://datatracker.ietf.org/doc/html/rfc7413#section-5.1) максимальную длину очереди соединений, которые ещё не завершили процесс three-way handshake.

為監聽套接字啟用「[TCP快速開啟](http://en.wikipedia.org/wiki/TCP_Fast_Open) 」 ( 1.21.0 )，並[限制](https://datatracker.ietf.org/doc/html/rfc7413#section-5.1)尚未完成三次握手過程的連接的最大隊列長度。

> Не включайте “TCP Fast Open”（TCP快速打開）, не убедившись, что сервер может адекватно обрабатывать многократное получение [одного и того же SYN-пакета с данными](https://datatracker.ietf.org/doc/html/rfc7413#section-6.1).
>
> 請勿啟用“TCP Fast Open”（TCP快速打開）除非確保伺服器能夠充分處理多次接收 [相同的SYN封包](https://datatracker.ietf.org/doc/html/rfc7413#section-6.1) 。

`backlog`\=`*число*`

задаёт параметр `backlog` в вызове `listen()`, который ограничивает максимальный размер очереди ожидающих приёма соединений (1.9.2). По умолчанию `backlog` устанавливается равным -1 для FreeBSD, DragonFly BSD и macOS, и 511 для других платформ.

在`listen()`呼叫中設定`backlog`參數，此參數限制待處理連接佇列的最大大小 (1.9.2)。預設情況下，在 FreeBSD、DragonFly BSD 和 macOS 上， `backlog`設定為 -1，在其他平台上設定為 511。

`rcvbuf`\=`*размер*`

задаёт размер буфера приёма (параметр `SO_RCVBUF`) для слушающего сокета (1.11.13).

設定監聽套接字（ 1.11.13 ）的接收緩衝區大小（參數`SO_RCVBUF` ）。

`sndbuf`\=`*размер*`

задаёт размер буфера передачи (параметр `SO_SNDBUF`) для слушающего сокета (1.11.13).

設定監聽套接字（ 1.11.13 ）的傳送緩衝區大小（參數`SO_SNDBUF` ）。

`accept_filter`\=`*фильтр*`

задаёт название accept-фильтра (параметр `SO_ACCEPTFILTER`) для слушающего сокета, который включается для фильтрации входящих соединений перед передачей их в `accept()` (1.25.5). Работает только на FreeBSD и NetBSD 5.0+. Можно использовать два фильтра: [dataready](http://man.freebsd.org/accf_data) и [httpready](http://man.freebsd.org/accf_http).

指定監聽套接字的接受過濾器（參數`SO_ACCEPTFILTER` ）的名稱，該過濾器用於在將傳入連接傳遞給`accept()` ( 1.25.5 ) 之前對其進行過濾。僅適用於 FreeBSD 和 NetBSD 5.0及更高版本。可以使用兩個過濾器：[dataready](http://man.freebsd.org/accf_data)和 [httpready](http://man.freebsd.org/accf_http) 。

`deferred`

указывает использовать отложенный `accept()` (параметр `TCP_DEFER_ACCEPT` сокета) на Linux (1.25.5).

指定在 Linux 上使用延遲的`accept()` ( `TCP_DEFER_ACCEPT`套接字選項) ( 1.25.5 )。

`bind`

параметр указывает, что для данной пары `*адрес*`:`*порт*` нужно делать `bind()` отдельно. Это нужно потому, что если описаны несколько директив `listen` с одинаковым портом, но разными адресами, и одна из директив `listen` слушает на всех адресах для данного порта (`*:``*порт*`), то nginx сделает `bind()` только на `*:``*порт*`. Необходимо заметить, что в этом случае для определения адреса, на которой пришло соединение, делается системный вызов `getsockname()`. Если же используются параметры `setfib`, `fastopen`, `backlog`, `rcvbuf`, `sndbuf`, `accept_filter`, `deferred`, `ipv6only`, `reuseport`, `multipath` или `so_keepalive`, то для данной пары `*адрес*`:`*порт*` всегда делается отдельный вызов `bind()`.

此參數指定對於給定的`*адрес*`:`*порт*`對，應執行單獨的`bind()` 。這是必要的，因為如果定義了多個`listen`指令，且這些指令使用相同的連接埠但不同的位址，並且其中一個`listen`指令監聽給定連接埠的所有位址（ `*:``*порт*` ），則 nginx 將僅在`bind()` `*:``*порт*`執行需要注意的是，在這種情況下，會發出`getsockname()`系統呼叫來決定接收到連接的位址。如果使用`setfib`, `fastopen`, `backlog`, `rcvbuf`, `sndbuf`, `accept_filter`, `deferred`, `ipv6only`, `reuseport`, `multipath`或`so_keepalive`參數，則對於給定的`*адрес*`:`*порт*`對，始終會發出單獨的`bind()`呼叫。

`ipv6only`\=`on`|`off`

этот параметр определяет (через параметр сокета `IPV6_V6ONLY`), будет ли слушающий на wildcard-адресе `[::]` IPv6-сокет принимать только IPv6-соединения, или же одновременно IPv6- и IPv4-соединения. По умолчанию параметр включён. Установить его можно только один раз на старте.

此參數（透過套接字參數`IPV6_V6ONLY` ）決定監聽通配符位址`[::]`的IPv6套接字是否僅接受IPv6連接，還是同時接受IPv6和IPv4連接。此參數預設啟用，且只能在啟動時設定一次。

`reuseport`

этот параметр (1.9.1) указывает, что нужно создавать отдельный слушающий сокет для каждого рабочего процесса (через параметр сокета `SO_REUSEPORT` для Linux 3.9+ и DragonFly BSD или `SO_REUSEPORT_LB` для FreeBSD 12+), позволяя ядру распределять входящие соединения между рабочими процессами. В настоящий момент это работает только на Linux 3.9+, DragonFly BSD и FreeBSD 12+ (1.15.1).

此選項 ( 1.9.1 ) 指定應為每個工作進程建立一個單獨的監聽套接字（Linux 3.9 + 和 DragonFly BSD `SO_REUSEPORT`套接字選項，或 FreeBSD 12+ `SO_REUSEPORT_LB`的組合進程目前，此選項僅適用於 Linux 3.9 +、DragonFly BSD和 FreeBSD 12+ ( 1.15.1 )。

> Ненадлежащее использование параметра может быть [небезопасно](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 不當使用此參數可能[不安全](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`multipath`

этот параметр (1.29.7) конфигурирует для слушающего сокета протокол [Multipath TCP](https://datatracker.ietf.org/doc/html/rfc8684) (`IPPROTO_MPTCP`). В настоящий момент это работает только на Linux 5.6+.

此參數 ( 1.29.7 ) 配置監聽套接字的 [Multipath TCP](https://datatracker.ietf.org/doc/html/rfc8684) ( `IPPROTO_MPTCP` ) 協定。目前，這僅適用於 Linux 5.6 +。

> Добавление или удаление этого параметра также включает параметр сокета `SO_REUSEPORT`, что может быть [небезопасно](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 新增或刪除此選項也會啟用`SO_REUSEPORT`套接字選項，此選項可能 [不安全](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`so_keepalive`\=`on`|`off`|\[`*keepidle*`\]:\[`*keepintvl*`\]:\[`*keepcnt*`\]

этот параметр конфигурирует для слушающего сокета поведение “TCP keepalive”. Если этот параметр опущен, то для сокета будут действовать настройки операционной системы. Если он установлен в значение “`on`”, то для сокета включается параметр `SO_KEEPALIVE`. Если он установлен в значение “`off`”, то для сокета параметр `SO_KEEPALIVE` выключается. Некоторые операционные системы поддерживают настройку параметров “TCP keepalive” на уровне сокета посредством параметров `TCP_KEEPIDLE`, `TCP_KEEPINTVL` и `TCP_KEEPCNT`. На таких системах (в настоящий момент это Linux, NetBSD, Dragonfly, FreeBSD и macOS) их можно сконфигурировать с помощью параметров `*keepidle*`, `*keepintvl*` и `*keepcnt*`. Один или два параметра могут быть опущены, в таком случае для соответствующего параметра сокета будут действовать стандартные системные настройки. Например,

此選項配置偵聽套接字的「TCP keepalive」行為。如果省略此參數，則將套用套接字的作業系統設定。如果設定為“`on`”，則為套接字啟用`SO_KEEPALIVE`選項。如果設定為“`off`”，則`SO_KEEPALIVE`選項對此套接字停用。某些作業系統支援透過`TCP_KEEPIDLE`, `TCP_KEEPINTVL`和`TCP_KEEPCNT`參數在套接字層級配置「TCPkeepalive」參數。在此類系統（目前為 Linux、NetBSD、Dragonfly、FreeBSD 和 macOS）上，可以使用參數 `*keepidle*`, `*keepintvl*` 和 `*keepcnt*` 進行設定。可以省略一兩個參數，在這種情況下，預設的系統設定將套用於對應的套接字參數。例如，

> ```
> so_keepalive=30m::10
>
> 所以保持存活=30分鐘::10
> ```

`$proxy_protocol_tlv_``*имя*`

TLV, полученный из заголовка протокола PROXY (1.23.2). `Имя` может быть именем типа TLV или его числовым значением. В последнем случае значение задаётся в шестнадцатеричном виде и должно начинаться с `0x`:

TLV，源自協議頭PROXY (1.23.2)。 `Имя` 可以是TLV 之類的名稱或其數值。在後一種情況下，該值以十六進位指定，並且必須以 `0x` 開頭：

> ```
> $proxy_protocol_tlv_alpn
> $proxy_protocol_tlv_0x01
> ```

SSL TLV могут также быть доступны как по имени типа TLV, так и по его числовому значению, оба должны начинаться с `ssl_`:

SSL TLV也可以透過其類型名稱TLV或其數值來訪問，兩者都必須以`ssl_`開頭：

> ```
> $proxy_protocol_tlv_ssl_version
> $proxy_protocol_tlv_ssl_0x21
> ```

Поддерживаются следующие имена типов TLV:

支援以下TLV類型名稱：

-   `alpn` (`0x01`) - протокол более высокого уровня, используемый поверх соединения  
    `alpn` ( `0x01` ) - 連接之上使用的高級協議
-   `authority` (`0x02`) - значение имени хоста, передаваемое клиентом  
    `authority` ( `0x02` ) - 用戶端傳送的主機名稱值
-   `unique_id` (`0x05`) - уникальный идентификатор соединения  
    `unique_id` ( `0x05` ) - 唯一連接標識符
-   `netns` (`0x30`) - имя пространства имён  
    `netns` ( `0x30` ) - 命名空間名稱
-   `ssl` (`0x20`) - структура SSL TLV в бинарном виде  
    `ssl` ( `0x20` ) - SSL TLV的二進位結構

Поддерживаются следующие имена типов SSL TLV:

支援以下SSL TLV類型名稱：

-   `ssl_version` (`0x21`) - версия SSL, используемая в клиентском соединении  
    `ssl_version` ( `0x21` ) - 客戶端連線中使用的SSL版本
-   `ssl_cn` (`0x22`) - Common Name сертификата  
    `ssl_cn` ( `0x22` ) - 證書的通用名稱
-   `ssl_cipher` (`0x23`) - имя используемого шифра  
    `ssl_cipher` ( `0x23` ) - 所用密碼的名稱
-   `ssl_sig_alg` (`0x24`) - алгоритм, используемый для подписи сертификата  
    `ssl_sig_alg` ( `0x24` ) - 用於簽署證書的演算法
-   `ssl_key_alg` (`0x25`) - алгоритм публичного ключа  
    `ssl_key_alg` ( `0x25` ) - 公鑰演算法

Также поддерживается следующее специальное имя типа SSL TLV:

同時支援以下特殊類型名稱SSL TLV ：

-   `ssl_verify` - результат проверки клиентского сертификата: `0`, если клиент предоставил сертификат и он был успешно верифицирован, либо ненулевое значение  
    `ssl_verify` - 用戶端憑證驗證結果： `0`如果用戶端提供了憑證且驗證成功，則為非零值
