The `ngx_stream_ssl_module` module (1.9.0) provides the necessary support for a stream proxy server to work with the SSL/TLS protocol.

`ngx_stream_ssl_module`模組 ( 1.9.0 ) 為流代理伺服器與SSL/TLS協定配合使用提供了必要的支援。

This module is not built by default, it should be enabled with the `--with-stream_ssl_module` configuration parameter.

此模組預設未構建，應使用`--with-stream_ssl_module`配置參數啟用。

> This module requires the [OpenSSL](http://www.openssl.org/) library.
>
> 本模組需要 [OpenSSL](http://www.openssl.org/)函式庫。

#### Example Configuration｜範例配置

To reduce the processor load, it is recommended to

為了降低處理器負載，建議…

-   set the number of [worker processes](<125 [01.01 文件] 核心功能.md#worker_processes>) equal to the number of processors,  
    將[工作進程](<125 [01.01 文件] 核心功能.md#worker_processes>)的數量設定為等於處理器數量，
-   enable the [shared](#ssl_session_cache_shared) session cache,  
    啟用[共享](#ssl_session_cache_shared)會話緩存，
-   disable the [built-in](#ssl_session_cache_builtin) session cache,  
    停用[內建](#ssl_session_cache_builtin)會話緩存，
-   and possibly increase the session [lifetime](#ssl_session_timeout) (by default, 5 minutes):  
    並可能增加會話[生命週期](#ssl_session_timeout) （預設值為 5 分鐘）：

> ```
> worker_processes auto;
>
> worker_processes 自動；
> 
> stream {
>
> 溪流 {
> 
>     ...
> 
>     server {
>
>     伺服器 {
>         listen              12345 ssl;
>
>         監聽 12345 ssl;
> 
>         ssl_protocols       TLSv1.2 TLSv1.3;
>
>         ssl_protocols TLSv1.2 TLSv1.3;
>         ssl_ciphers         AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5;
>
>         ssl_ciphers AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5 ;

>
>         ssl_certificate /usr/local/nginx/conf/cert.pem;
>         ssl_certificate_key /usr/local/nginx/conf/cert.key;
>         ssl_session_cache   shared:SSL:10m;
>
>         ssl_session_cache 共享: SSL :10m;

> 
>         ...
>     }
> ```

Specifies a `*file*` with the certificate in the PEM format for the given virtual server. If intermediate certificates should be specified in addition to a primary certificate, they should be specified in the same file in the following order: the primary certificate comes first, then the intermediate certificates. A secret key in the PEM format may be placed in the same file.

為給定的虛擬伺服器指定一個`*file*`其中包含格式為PEM憑證。如果除了主證書之外還需要指定中間證書，則應將它們按以下順序放在同一個文件中：先是主證書，然後是中間證書。格式為PEM金鑰也可以放在同一個檔案中。

Since version 1.11.0, this directive can be specified multiple times to load certificates of different types, for example, RSA and ECDSA:

自版本1.11.0起，可以多次指定此指令以載入不同類型的證書，例如RSA和ECDSA ：

> ```
> server {
>
> 伺服器 {
>     listen              12345 ssl;
>
>     監聽 12345 ssl;
> 
>     ssl_certificate     example.com.rsa.crt;
>
>     ssl_certificate example.com.rsa.crt;
>     ssl_certificate_key example.com.rsa.key;
> 
>     ssl_certificate     example.com.ecdsa.crt;
>
>     ssl_certificate example.com.ecdsa.crt;
>     ssl_certificate_key example.com.ecdsa.key;
> 
>     ...
> }
> ```

> Only OpenSSL 1.0.2 or higher supports separate [certificate chains](<042 [01.01.03 http] 配置HTTPS伺服器.md#chains>) for different certificates. With older versions, only one certificate chain can be used.
>
> 只有 OpenSSL 1.0.2或更高版本才支援為不同的憑證使用獨立的憑證鏈(https://nginx.org/en/docs/http/configuring_https_servers.html#chains) 。舊版只能使用一條憑證鏈。

Since version 1.15.9, variables can be used in the `*file*` name when using OpenSSL 1.0.2 or higher:

自版本1.15.9起，在使用1.0.2或更高版本時，可以在`*file*`名稱中使用變數：

> ```
> ssl_certificate     $ssl_server_name.crt;
>
> ssl_certificate $ssl_server_name.crt;
> ssl_certificate_key $ssl_server_name.key;
> ```

Note that using variables implies that a certificate will be loaded for each SSL handshake, and this may have a negative impact on performance.

請注意，使用變數意味著每次SSL握手都會載入一個證書，這可能會對效能產生負面影響。

The value `data`:`*$variable*` can be specified instead of the `*file*` (1.15.10), which loads a certificate from a variable without using intermediate files. Note that inappropriate use of this syntax may have its security implications, such as writing secret key data to [error log](<125 [01.01 文件] 核心功能.md#error_log>).

可以使用值`data`:`*$variable*`代替`*file*` ( 1.15.10 )，這樣就可以從變數載入憑證而無需使用中間檔案。請注意，不當使用此語法可能會帶來安全隱患，例如將金鑰資料寫入 [錯誤日誌](<125 [01.01 文件] 核心功能.md#error_log>) 。

It should be kept in mind that due to the SSL/TLS protocol limitations, for maximum interoperability with clients that do not use [SNI](http://en.wikipedia.org/wiki/Server_Name_Indication), virtual servers with different certificates should listen on [different IP addresses](<042 [01.01.03 http] 配置HTTPS伺服器.md#name_based_https_servers>).

需要注意的是，由於SSL/TLS協定的限制，為了與不使用 [SNI](http://en.wikipedia.org/wiki/Server_Name_Indication)的客戶端實現最大程度的互通性，具有不同憑證的虛擬伺服器應該監聽 [不同的IP (https://nginx.org/en/docs/http/configuring_https_servers.html#name_based_https_servers) 。

This directive appeared in version 1.27.4.

該指令出現在版本1.27.4 。

Defines a cache that stores [SSL certificates](#ssl_certificate) and [secret keys](#ssl_certificate_key) specified with [variables](#ssl_certificate_key_variables).

定義一個緩存，用於儲存 [SSL憑證](#ssl_certificate)和 [金鑰](#ssl_certificate_key)金鑰由 [變數](#ssl_certificate_key_variables)指定。

The directive has the following parameters:

此指令具有以下參數：

`max`

sets the maximum number of elements in the cache; on cache overflow the least recently used (LRU) elements are removed;

設定快取中元素的最大數量；當快取溢出時，刪除最近最少使用的（ LRU ）元素；

`inactive`

defines a time after which an element is removed from the cache if it has not been accessed during this time; by default, it is 10 seconds;

定義一個時間段，如果該元素在這段時間內未被訪問，則將其從快取中刪除；預設值為 10 秒；

`valid`

defines a time during which an element in the cache is considered valid and can be reused; by default, it is 60 seconds. Certificates that exceed this time will be reloaded or revalidated;

定義快取中元素被視為有效且可重複使用的時間；預設值為 60 秒。超過此時間的證書將被重新載入或重新驗證；

`off`

disables the cache.

禁用緩存。

Example:

例子：

> ```
> ssl_certificate       $ssl_server_name.crt;
>
> ssl_certificate $ssl_server_name.crt;
> ssl_certificate_key   $ssl_server_name.key;
>
> ssl_certificate_key $ssl_server_name.key;
> ssl_certificate_cache max=1000 inactive=20s valid=1m;
> ```
