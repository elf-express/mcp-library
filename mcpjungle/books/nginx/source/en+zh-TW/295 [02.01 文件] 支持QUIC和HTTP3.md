## Поддержка QUIC и HTTP/3｜支持QUIC和HTTP /3

|   |
| --- |
| [Сборка из исходных файлов](#building)<br>[Советы по настройке](#configuration)<br>[Устранение неполадок](#troubleshooting)<br>[從原始檔建構](#building)<br> [設定提示](#configuration)<br> [故障排除](#troubleshooting) |

Поддержка протоколов [QUIC](https://datatracker.ietf.org/doc/html/rfc9000) и [HTTP/3](https://datatracker.ietf.org/doc/html/rfc9114) доступна начиная с версии 1.25.0, она включена в [бинарных пакетах](<327 [02 ru] 適用於 Linux 的 nginx 軟體包.md>) для Linux. Подробнее см. документацию к модулю [ngx\_http\_v3\_module](<270 [02.01.01 http] ngx_http_v3_module 模組.md>).

從版本1.25.0開始支援 [QUIC](https://datatracker.ietf.org/doc/html/rfc9000)和 [HTTP /3](https://datatracker.ietf.org/doc/html/rfc9114)協議，並包含在 Linux 的 [二進位軟體包](<327 [02 ru] 適用於 Linux 的 nginx 軟體包.md>)中。更多詳情，請參閱 [ngx\_http\_v3\_module](<270 [02.01.01 http] ngx_http_v3_module 模組.md>)模組文件。

#### Сборка из исходных файлов｜從來源檔案構建

Сборка настраивается командой `configure`. Подробнее см. в статье [Сборка nginx из исходных файлов](<202 [02.01 文件] 從原始檔建構 nginx.md>).

建構配置使用`configure`指令。更多詳情，請參閱文章 [從原始檔案建立 nginx](<202 [02.01 文件] 從原始檔建構 nginx.md>) 。

Для сборки nginx с поддержкой QUIC рекомендуется библиотека [OpenSSL](https://openssl.org/) версии 3.5.1 или выше. Иначе будет использоваться OpenSSL compatibility layer без поддержки TLS [early data](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_early_data>). Также возможно использование предварительно собранной библиотеки [BoringSSL](https://boringssl.googlesource.com/boringssl), [LibreSSL](https://www.libressl.org/) или [QuicTLS](https://github.com/quictls/openssl).

要建立支援QUIC的nginx，建議使用3.5.1或更高版本的[OpenSSL](https://openssl.org/)庫。否則，將使用不支援TLS [早期資料](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_early_data>)的OpenSSL相容層。您也可以使用預先建置的[BoringSSL](https://boringssl.googlesource.com/boringssl) 、[LibreSSL](https://www.libressl.org/)或[QuicTLS](https://github.com/quictls/openssl)函式庫。

При конфигурации nginx с [BoringSSL](https://boringssl.googlesource.com/boringssl) используется следующая команда:

使用 [BoringSSL](https://boringssl.googlesource.com/boringssl)請使用下列指令：

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../boringssl/include"
>     --with-ld-opt="-L../boringssl/build -lstdc++"
> ```

Кроме того, можно сконфигурировать nginx с [QuicTLS](https://github.com/quictls/openssl):

或者，您可以使用 [QuicTLS](https://github.com/quictls/openssl)來設定 nginx：

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../quictls/build/include"
>     --with-ld-opt="-L../quictls/build/lib"
> ```

Кроме того, можно сконфигурировать nginx с [LibreSSL](https://www.libressl.org/):

或者，您可以使用 [LibreSSL](https://www.libressl.org/)設定 nginx：

> ```
> ./configure
>
> ./配置
>     --with-debug
>     --with-http_v3_module
>     --with-cc-opt="-I../libressl/build/include"
>     --with-ld-opt="-L../libressl/build/lib"
> ```

После конфигурации nginx компилируется и устанавливается с помощью `make`.

配置完成後，nginx 將使用`make`進行編譯和安裝。

#### Советы по настройке｜設定技巧

В директиве [listen](<221 [02.01.01 http] 模組 ngx_http_core_module.md#listen>) модуля [ngx\_http\_core\_module](<221 [02.01.01 http] 模組 ngx_http_core_module.md>) появился новый параметр [quic](<221 [02.01.01 http] 模組 ngx_http_core_module.md#quic>), который позволяет принимать на указанном порту QUIC-соединения.

[ngx\_http\_core\ (https://nginx.org/ru/docs/http/ngx_http_core_module.html) ] 的 [listen (https://nginx.org/ru/docs/http/ngx_http_core_module.html#listen)指令現在有了一個新的 [quic](<221 [02.01.01 http] 模組 ngx_http_core_module.md#quic>) ，允許在指定的連接埠上接受QUIC 。

Вместе с параметром `quic` можно также указать параметр [reuseport](<221 [02.01.01 http] 模組 ngx_http_core_module.md#reuseport>) для правильной работы с несколькими рабочими процессами.

結合`quic`參數，您也可以指定 [reuseport](<221 [02.01.01 http] 模組 ngx_http_core_module.md#reuseport>)參數，以便與多個工作進程正確配合使用。

Чтобы [разрешить](<270 [02.01.01 http] ngx_http_v3_module 模組.md#quic_retry>) проверку адреса:

啟用(https://nginx.org/ru/docs/http/ngx_http_v3_module.html#quic_retry)位址驗證：

> ```
> quic_retry on;
>
> 快速重試已開啟；
> ```

Чтобы [разрешить](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_early_data>) 0-RTT:

啟用(https://nginx.org/ru/docs/http/ngx_http_ssl_module.html#ssl_early_data) 0- RTT :

> ```
> ssl_early_data on;
>
> 啟用 ssl_early_data；
> ```

Чтобы [разрешить](<270 [02.01.01 http] ngx_http_v3_module 模組.md#quic_gso>) GSO (Generic Segmentation Offloading):

啟用(https://nginx.org/ru/docs/http/ngx_http_v3_module.html#quic_gso) GSO （通用分段卸載）：

> ```
> quic_gso on;
>
> quick_gso 開啟；
> ```

Чтобы [установить](<270 [02.01.01 http] ngx_http_v3_module 模組.md#quic_host_key>) host-ключ для различных токенов:

為不同令牌設定(https://nginx.org/ru/docs/http/ngx_http_v3_module.html#quic_host_key)主機金鑰：

> ```
> quic_host_key <filename>;
>
> quic_host_key <filename> ;
> ```

Для работы QUIC требуется версия протокла TLSv1.3, которая включена по умолчанию в директиве [ssl\_protocols](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_protocols>).

QUIC需要 TLSv1.3 協定版本，該版本在 [ssl\_protocols](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_protocols>)指令中預設為啟用。

По умолчанию [GSO Linux-specific optimization](http://vger.kernel.org/lpc_net2018_talks/willemdebruijn-lpc2018-udpgso-paper-DRAFT-1.pdf) выключена. Включите, если настроен соответствующий сетевой интерфейс, поддерживающий GSO.

預設情況下，[GSO Linux 特定最佳化](http://vger.kernel.org/lpc_net2018_talks/willemdebruijn-lpc2018-udpgso-paper-DRAFT-1.pdf)處於停用狀態。如果配置了支援GSO相應網路接口，則啟用它。

#### Устранение неполадок｜故障排除

Приблизительные шаги при обнаружении проблемы:

偵測到問題時的大致步驟：

-   Убедитесь, что nginx собран с правильной SSL-библиотекой.  
    確保 nginx 建置時使用了正確的SSL函式庫。
-   Убедитесь, что nginx использует правильную SSL-библиотеку в runtime (`nginx -V` покажет что именно используется в данный момент).  
    確保 nginx 在運行時使用正確的SSL庫（ `nginx -V`將顯示目前正在使用的庫）。
-   Убедитесь, что клиент действительно присылает запросы через QUIC. Рекомендуется начать с простого консольного клиента, например [ngtcp2](https://nghttp2.org/ngtcp2), чтобы убедиться, что сервер настроен правильно, и затем попробовать в браузерах, так как браузеры могут быть требовательны к сертификатам.  
    驗證客戶端是否確實透過QUIC發送請求。建議先使用簡單的控制台用戶端，例如 [ngtcp2](https://nghttp2.org/ngtcp2) ，以確保伺服器配置正確，然後再在瀏覽器中進行測試，因為瀏覽器對憑證的要求可能比較嚴格。
-   Соберите nginx с поддержкой [отладочного лога](<205 [02.01 文件] 偵錯日誌.md>) и проверьте отладочный лог. В нём должны содержаться все детали соединения и причины ошибок. Соответствующие сообщения начинаются с префикса “`quic`” и могут быть по нему отфильтрованы.  
    建置支援(https://nginx.org/ru/docs/debugging_log.html)調試日誌的nginx，並檢查偵錯日誌。日誌應包含所有連線詳情和錯誤原因。對應的訊息以「 `quic` 」為前綴，並可依此前綴進行篩選。
-   Для детального исследования можно включить дополнительную отладку при помощи следующих макросов: `NGX_QUIC_DEBUG_PACKETS`, `NGX_QUIC_DEBUG_FRAMES`, `NGX_QUIC_DEBUG_ALLOC`, `NGX_QUIC_DEBUG_CRYPTO`.  
    如需進行詳細調查，您可以使用以下巨集啟用額外的偵錯： `NGX_QUIC_DEBUG_PACKETS`, `NGX_QUIC_DEBUG_FRAMES`, `NGX_QUIC_DEBUG_ALLOC`, `NGX_QUIC_DEBUG_CRYPTO` 。
    
    > ```
    > ./configure
    >
    > ./配置
    >     --with-http_v3_module
    >     --with-debug
    >     --with-cc-opt="-DNGX_QUIC_DEBUG_PACKETS -DNGX_QUIC_DEBUG_CRYPTO"
    > ```
