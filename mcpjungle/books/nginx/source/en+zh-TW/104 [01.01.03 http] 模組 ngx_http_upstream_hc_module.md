# Module ngx_http_upstream_hc_module｜模組 ngx_http_upstream_hc_module

## Module ngx\_http\_upstream\_hc\_module｜模組 ngx\_http\_upstream\_hc\_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [health\_check](#health_check)<br>     [match](#match)<br>[範例設定](#example)<br> [指令](#directives)<br> [健康檢查](#health_check)<br> [符合](#match) |

The `ngx_http_upstream_hc_module` module allows enabling periodic health checks of the servers in a [group](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#upstream>) referenced in the surrounding location. The server group must reside in the [shared memory](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#zone>).

`ngx_http_upstream_hc_module`模組允許對周圍位置引用的 [群組](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#upstream>)中的伺服器進行定期健康檢查。伺服器群組必須位於 [共享記憶體](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#zone>)中。

If a health check fails, the server will be considered unhealthy. If several health checks are defined for the same group of servers, a single failure of any check will make the corresponding server be considered unhealthy. Client requests are not passed to unhealthy servers and servers in the “checking” state.

如果健康檢查失敗，伺服器將被視為不健康。如果為同一組伺服器定義了多個健康檢查，則任何一個檢查失敗都會導致相應的伺服器被視為不健康。客戶端請求不會傳遞給不健康的伺服器和處於「檢查中」狀態的伺服器。

> Please note that most of the variables will have empty values when used with health checks.
>
> 請注意，在進行健康檢查時，大多數變數的值將為空。

> This module is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Example Configuration｜範例配置

> ```
> upstream dynamic {
>
> 上游動態
>     zone upstream_dynamic 64k;
>
>     區域 upstream_dynamic 64k；
> 
>     server backend1.example.com      weight=5;
>
>     伺服器 backend1.example.com 權重=5；
>     server backend2.example.com:8080 fail_timeout=5s slow_start=30s;
>
>     伺服器 backend2.example.com:8080 fail_timeout=5s slow_start=30s;
>     server 192.0.2.1                 max_fails=3;
>
>     伺服器192.0.2.1 max_fails=3;
> 
>     server backup1.example.com:8080  backup;
>
>     伺服器 backup1.example.com:8080 備份;
>     server backup2.example.com:8080  backup;
>
>     伺服器 backup2.example.com:8080 備份;
> }
> 
> server {
>
> 伺服器 {
>     location / {
>
>     地點 / {
>         proxy_pass http://dynamic;
>         health_check;
>
>         健康檢查；
>     }
> }
> ```

With this configuration, nginx will send “`/`” requests to each server in the `backend` group every five seconds. If any communication error or timeout occurs, or a proxied server responds with the status code other than 2xx or 3xx, the health check will fail, and the server will be considered unhealthy.

在此配置下，nginx 將每五秒向`backend`群組中的每個伺服器發送「 `/` 」請求。如果發生任何通訊錯誤或逾時，或代理伺服器傳回的狀態碼不是 2xx 或 3xx，則健康檢查將失敗，伺服器將被視為不健康。

Health checks can be configured to test the status code of a response, presence of certain header fields and their values, and the body contents. Tests are configured separately using the [match](#match) directive and referenced in the `match` parameter of the [health\_check](#health_check) directive:

健康檢查可以配置為測試回應的狀態碼、特定標頭欄位及其值的存在情況以及響應體的內容。測試使用 [match](#match)指令單獨配置，並在 [health\_check](#health_check)指令的`match`參數中引用：

> ```
> http {
>     server {
>
>     伺服器 {
>     ...
>         location / {
>
>         地點 / {
>             proxy_pass http://backend;
>             health_check match=welcome;
>
>             健康檢查匹配=歡迎；
>         }
>     }
> 
>     match welcome {
>
>     比賽歡迎{
>         status 200;
>
>         狀態 200；
>         header Content-Type = text/html;
>         body ~ "Welcome to nginx!";
>
>         正文 ~ "歡迎使用 nginx！";
>     }
> }
> ```

This configuration shows that in order for a health check to pass, the response to a health check request should succeed, have status 200, and contain “`Welcome to nginx!`” in the body.

此配置表明，為了使健康檢查通過，對健康檢查請求的回應應成功，狀態為 200，並且正文中包含「 `Welcome to nginx!` 」。

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**health_check** [`*parameters*`];``<br>` `**health_check** [` *參數* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `location` |

Enables periodic health checks of the servers in a [group](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#upstream>) referenced in the surrounding location.

啟用對周圍位置引用的 [群組](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#upstream>)中的伺服器進行定期健康檢查。

The following optional parameters are supported:

支援以下可選參數：

`interval`\=`*time*`

sets the interval between two consecutive health checks, by default, 5 seconds.

設定兩次連續健康檢查之間的間隔，預設值為 5 秒。

`jitter`\=`*time*`

sets the time within which each health check will be randomly delayed, by default, there is no delay.

設定每次健康檢查隨機延遲的時間範圍，預設沒有延遲。

`fails`\=`*number*`

sets the number of consecutive failed health checks of a particular server after which this server will be considered unhealthy, by default, 1.

設定特定伺服器連續健康檢查失敗的次數，超過該次數後，該伺服器將被視為不健康，預設值為 1。

`passes`\=`*number*`

sets the number of consecutive passed health checks of a particular server after which the server will be considered healthy, by default, 1.

設定特定伺服器連續通過健康檢查的次數，超過該次數後，伺服器將被視為健康，預設值為 1。

`uri`\=`*uri*`

defines the URI used in health check requests, by default, “`/`”.

定義健康檢查請求中使用的URI ，預設為「 `/` 」。

`mandatory` \[`persistent`\]

sets the initial “checking” state for a server until the first health check is completed (1.11.7). Client requests are not passed to servers in the “checking” state. If the parameter is not specified, the server will be initially considered healthy.

設定伺服器的初始「檢查」狀態，直到首次健康檢查完成（ 1.11.7 ）。客戶端請求不會傳遞給處於「檢查」狀態的伺服器。如果未指定此參數，則伺服器初始狀態將被視為健康。

The `persistent` parameter (1.19.7) sets the initial “up” state for a server after reload if the server was considered healthy before reload.

`persistent`參數 ( 1.19.7 ) 設定伺服器在重新載入後的初始「運行」狀態（如果伺服器在重新載入之前被認為是健康的）。

`match`\=`*name*`

specifies the `match` block configuring the tests that a response should pass in order for a health check to pass. By default, the response should have status code 2xx or 3xx.

`match`程式碼區塊用於配置回應必須通過的測試，才能通過健康檢查。預設情況下，回應的狀態碼應為 2xx 或 3xx。

`port`\=`*number*`

defines the port used when connecting to a server to perform a health check (1.9.7). By default, equals the [server](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#server>) port.

定義連接到伺服器執行健康檢查時使用的連接埠（ 1.9.7 ）。預設情況下，等於 [伺服器](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#server>)連接埠。

`type`\=`grpc` \[`grpc_service`\=`*name*`\] \[`grpc_status`\=`*code*`\]

enables periodic [health checks](https://github.com/grpc/grpc/blob/master/doc/health-checking.md#grpc-health-checking-protocol) of a gRPC server or a particular gRPC service specified with the optional `grpc_service` parameter (1.19.5). If the server does not support the gRPC Health Checking Protocol, the optional `grpc_status` parameter can be used to specify non-zero gRPC [status](https://github.com/grpc/grpc/blob/master/doc/statuscodes.md#status-codes-and-their-use-in-grpc) (for example, status code “`12`” / “`UNIMPLEMENTED`”) that will be treated as healthy:

啟用對 gRPC 伺服器或使用可選參數`grpc_service` ( 1.19.5 ) 指定的特定 gRPC 服務的定期健康檢查(https://github.com/grpc/grpc/blob/master/doc/health-checking.md#grpc-health-checking-protocol) 。如果伺服器不支援 gRPC 健康檢查協議，則可以使用可選參數`grpc_status`指定非零 gRPC 狀態(https://github.com/grpc/grpc/blob/master/doc/statuscodes.md#status-codes-and-their-use-in-grpc) （例如，狀態碼“ `12` ” / “ `UNIMPLEMENTED` ”），這些狀態將被視為健康狀態：

> ```
> health_check mandatory type=grpc grpc_status=12;
> ```

The `type`\=`grpc` parameter must be specified after all other directive parameters, `grpc_service` and `grpc_status` must follow `type`\=`grpc`. The parameter is not compatible with [`uri`](#health_check_uri) or [`match`](#health_check_match) parameters.

`type` \= `grpc`參數必須在所有其他指令參數之後指定， `grpc_service`和`grpc_status`必須位於`type` \= `grpc`之後。此參數與 [`uri`](#health_check_uri)或 [`match`](#health_check_match)參數不相容。

`keepalive_time`\=`*time*`

enables [keepalive](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#keepalive>) connections for health checks and specifies the time during which requests can be processed through one keepalive connection (1.21.7). By default keepalive connections are disabled.

啟用用於健康檢查的 [keepalive](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#keepalive>)連接，並指定可透過單一 keepalive 連接 ( 1.21.7 ) 處理請求的時間。預設情況下，keepalive 連線處於停用狀態。

|   |   |
| --- | --- |
| Syntax:<br>文法： | ``**match** `*name*` { ... }``<br>` `**match** ` *名稱* ` { ... }` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http` |

Defines the named test set used to verify responses to health check requests.

定義用於驗證對健康檢查請求的回應的命名測試集。

The following items can be tested in a response:

以下內容可以在答題中測試：

`status 200;`

status is 200

狀態為 200

`status ! 500;`

status is not 500

狀態不是 500

`status 200 204;`

status is 200 or 204

狀態為 200 或 204

`status ! 301 302;`

status is neither 301 nor 302

狀態既不是 301 也不是 302

`status 200-399;`

status is in the range from 200 to 399

狀態值範圍為 200 至 399

`status ! 400-599;`

status is not in the range from 400 to 599

狀態不在 400 到 599 的範圍內

`status 301-303 307;`

status is either 301, 302, 303, or 307

狀態碼為 301、302、303 或 307。

`header Content-Type = text/html;`

header contains “Content-Type”（內容類型） with value `text/html`

標頭包含“Content-Type”（內容類型） ，值為`text/html`

`header Content-Type != text/html;`

header contains “Content-Type”（內容類型） with value other than `text/html`

標頭包含“Content-Type”（內容類型）但其值不等於`text/html`

`header Connection ~ close;`

header contains “Connection”（聯繫） with value matching regular expression `close`

標頭包含“Connection”（聯繫） ，其值與正規表示式`close`匹配

`header Connection !~ close;`

header contains “Connection”（聯繫） with value not matching regular expression `close`

標頭包含“Connection”（聯繫）但其值與正規表示式`close`不符。

`header Host;`

header contains “Host”（主持人）

標題包含“Host”（主持人）

`header ! X-Accel-Redirect;`

header lacks “X-Accel-Redirect”（X-Accel-重定向）

標題缺“X-Accel-Redirect”（X-Accel-重定向）

`body ~ "Welcome to nginx!";`

body matches regular expression “`Welcome to nginx!`”

body 符合正規表示式“ `Welcome to nginx!` ”

`body !~ "Welcome to nginx!";`

body does not match regular expression “`Welcome to nginx!`”

正文與正規表示式「 `Welcome to nginx!` 」不符

`require` `*$variable*` `...;`

all specified variables are not empty and not equal to “0” (1.15.9).

所有指定的變數均不為空且不等於「0」（ 1.15.9 ）。

If several tests are specified, the response matches only if it matches all tests.

如果指定了多個測試，則只有當回應與所有測試都相符時，回應才會相符。

> Only the first 256k of the response body are examined.
>
> 僅檢查回應正文的前 256k。

Examples:

範例：

> ```
> # status is 200, content type is "text/html",｜狀態碼為 200，內容類型為“text/html”，
> # and body contains "Welcome to nginx!"｜正文包含“歡迎使用 nginx！”
> match welcome {
>
> 比賽歡迎{
>     status 200;
>
>     狀態 200；
>     header Content-Type = text/html;
>     body ~ "Welcome to nginx!";
>
>     正文 ~ "歡迎使用 nginx！";
> }
> ```

> ```
> # status is not one of 301, 302, 303, or 307, and header does not have "Refresh:"｜狀態碼不是 301、302、303 或 307，且請求頭中不包含「Refresh:」字樣。
> match not_redirect {
>
> 匹配 not_redirect {
>     status ! 301-303 307;
>
>     狀態！ 301-303 307；
>     header ! Refresh;
>
>     標題！重新整理;
> }
> ```

> ```
> # status ok and not in maintenance mode｜狀態正常，未處於維護模式
> match server_ok {
>
> 匹配 server_ok {
>     status 200-399;
>
>     狀態 200-399；
>     body !~ "maintenance mode";
>
>     身體！ ~「維護模式」；
> }
> ```

> ```
> # status is 200 or 204｜狀態為 200 或 204
> map $upstream_status $good_status {
>
> 映射 $upstream_status $good_status {
>     200 1;
>     204 1;
> }
> 
> match server_ok {
>
> 匹配 server_ok {
>     require $good_status;
>
>     需要 $good_status；
> }
> ```
