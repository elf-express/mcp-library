Модуль `ngx_http_v2_module` (1.9.5) обеспечивает поддержку [HTTP/2](https://datatracker.ietf.org/doc/html/rfc7540).

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_v2_module`.

#### Известные проблемы

До версии 1.9.14 буферизация тела запроса клиента не могла быть запрещена независимо от значения директив [proxy\_request\_buffering](<248 [02.01.01 http] Модуль ngx_http_proxy_module.md#proxy_request_buffering>), [fastcgi\_request\_buffering](<225 [02.01.01 http] Модуль ngx_http_fastcgi_module.md#fastcgi_request_buffering>), [uwsgi\_request\_buffering](<268 [02.01.01 http] Модуль ngx_http_uwsgi_module.md#uwsgi_request_buffering>) и [scgi\_request\_buffering](<254 [02.01.01 http] Модуль ngx_http_scgi_module.md#scgi_request_buffering>).

До версии 1.19.1 механизм [lingering\_close](<221 [02.01.01 http] Модуль ngx_http_core_module.md#lingering_close>) не использовался в управлении закрытием HTTP/2-соединений.

#### Пример конфигурации

> ```
> server {
>     listen 443 ssl;
> 
>     http2 on;
> 
>     ssl_certificate server.crt;
>     ssl_certificate_key server.key;
> }
> ```

Чтобы принимать HTTP/2-соединения по TLS, необходимо наличие поддержки расширения “Application-Layer Protocol Negotiation” (ALPN) протокола TLS, появившейся в [OpenSSL](http://www.openssl.org/) версии 1.0.2.

Если директива [ssl\_prefer\_server\_ciphers](<260 [02.01.01 http] Модуль ngx_http_ssl_module.md#ssl_prefer_server_ciphers>) установлена в значение “`on`”, [шифры](<260 [02.01.01 http] Модуль ngx_http_ssl_module.md#ssl_ciphers>) должны быть настроены таким образом, чтобы соответствовать чёрному списку [RFC 9113, Appendix A](https://datatracker.ietf.org/doc/html/rfc9113#appendix-A), а также поддерживаться клиентами.

<tr><th>Умолчание:</th><td>http2 off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>

Эта директива появилась в версии 1.25.1.

Разрешает протокол [HTTP/2](https://datatracker.ietf.org/doc/html/rfc9113).

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_body_preread_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_body_preread_size 64k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Эта директива появилась в версии 1.11.0.

Задаёт `*размер*` буфера для каждого запроса, в который может сохраняться тело запроса до того, как оно начнёт обрабатываться.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_chunk_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_chunk_size 8k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Задаёт максимальный размер частей, на которое будет разделяться тело ответа. Слишком маленькое значение может привести к росту накладных расходов. Слишком большое значение может негативно сказаться на приоритизации из-за [блокировки очереди](http://en.wikipedia.org/wiki/Head-of-line_blocking).

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_idle_timeout</strong> <code><i>время</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_idle_timeout 3m;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

> Эта директива устарела начиная с версии 1.19.7. Вместо неё следует использовать директиву [keepalive\_timeout](<221 [02.01.01 http] Модуль ngx_http_core_module.md#keepalive_timeout>).

Задаёт таймаут неактивности, после которого соединение закрывается.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_max_concurrent_pushes</strong> <code><i>число</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_max_concurrent_pushes 10;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Эта директива появилась в версии 1.13.9.

> Эта директива устарела начиная с версии 1.25.1.

Ограничивает максимальное число параллельных [push](#http2_push)\-запросов в соединении.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_max_concurrent_streams</strong> <code><i>число</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_max_concurrent_streams 128;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Задаёт максимальное число параллельных HTTP/2-потоков в соединении.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_max_field_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_max_field_size 4k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

> Эта директива устарела начиная с версии 1.19.7. Вместо неё следует использовать директиву [large\_client\_header\_buffers](<221 [02.01.01 http] Модуль ngx_http_core_module.md#large_client_header_buffers>).

Ограничивает максимальный размер заголовка запроса, сжатого при помощи [HPACK](https://datatracker.ietf.org/doc/html/rfc7541). Ограничение применяется в равной степени как к имени, так и к значению. Если применяется кодирование Хаффмана, то фактический размер распакованных строк имени и значения может быть больше. Ограничение по умолчанию подходит для большинства запросов.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_max_header_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_max_header_size 16k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

> Эта директива устарела начиная с версии 1.19.7. Вместо неё следует использовать директиву [large\_client\_header\_buffers](<221 [02.01.01 http] Модуль ngx_http_core_module.md#large_client_header_buffers>).

Ограничивает максимальный размер всего списка заголовков запроса после распаковки [HPACK](https://datatracker.ietf.org/doc/html/rfc7541). Ограничение по умолчанию подходит для большинства запросов.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_max_requests</strong> <code><i>число</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_max_requests 1000;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Эта директива появилась в версии 1.11.6.

> Эта директива устарела начиная с версии 1.19.7. Вместо неё следует использовать директиву [keepalive\_requests](<221 [02.01.01 http] Модуль ngx_http_core_module.md#keepalive_requests>).

Задаёт максимальное число запросов (включая [push](#http2_push)\-запросы), которые можно сделать по одному соединению HTTP/2, после чего очередной клиентский запрос приведёт к закрытию соединения и необходимости установить новое соединение.

Периодическое закрытие соединений необходимо для освобождения памяти, выделенной под конкретные соединения. Поэтому использование слишком большого максимального числа запросов может приводить к чрезмерному потреблению памяти и не рекомендуется.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_push</strong> <code><i>uri</i></code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_push off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Эта директива появилась в версии 1.13.9.

> Эта директива устарела начиная с версии 1.25.1. Вместо неё можно использовать директиву [early\_hints](<221 [02.01.01 http] Модуль ngx_http_core_module.md#early_hints>).

Заблаговременно отправляет ([push](https://datatracker.ietf.org/doc/html/rfc9113#section-8.4)) запрос к заданному `*uri*` вместе с ответом на оригинальный запрос. Будут обработаны только относительные URI с абсолютными путями, например:

> ```
> http2_push /static/css/main.css;
> ```

В значении `*uri*` допустимо использование переменных.

На одном уровне конфигурации можно указать несколько `http2_push` директив. Параметр `off` отменяет действие унаследованных с предыдущего уровня конфигурации директив `http2_push`.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_push_preload</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_push_preload off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Эта директива появилась в версии 1.13.9.

> Эта директива устарела начиная с версии 1.25.1.

Разрешает автоматическое преобразование [preload links](https://www.w3.org/TR/preload/#server-push-http-2), указанных в полях “Link” заголовка ответа, в [push](https://datatracker.ietf.org/doc/html/rfc9113#section-8.4)\-запросы.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_recv_buffer_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_recv_buffer_size 256k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code></td></tr>
</table>

Задаёт размер входного буфера для [рабочего процесса](<285 [02.01 docs] Основная функциональность.md#worker_processes>).

<table>
<tr><th>Синтаксис:</th><td><code><strong>http2_recv_timeout</strong> <code><i>время</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http2_recv_timeout 30s;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

> Эта директива устарела начиная с версии 1.19.7. Вместо неё следует использовать директиву [client\_header\_timeout](<221 [02.01.01 http] Модуль ngx_http_core_module.md#client_header_timeout>).

Задаёт таймаут в случае, когда от клиента ожидаются ещё данные, после которого соединение закрывается.

#### Встроенные переменные

Модуль `ngx_http_v2_module` поддерживает следующие встроенные переменные:

`$http2`

согласованный идентификатор протокола: “`h2`” для HTTP/2 через TLS, “`h2c`” для HTTP/2 через незашифрованный TCP, либо пустая строка.
