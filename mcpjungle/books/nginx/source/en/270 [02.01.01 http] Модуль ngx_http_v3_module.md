## Модуль ngx\_http\_v3\_module

Модуль `ngx_http_v3_module` (1.25.0) обеспечивает экспериментальную поддержку [HTTP/3](https://datatracker.ietf.org/doc/html/rfc9114).

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_v3_module`.

> Для сборки и работы этого модуля нужна библиотека [OpenSSL](http://www.openssl.org/) версии 1.1.1 или выше.

> Для поддержки 0-RTT нужна библиотека [OpenSSL](http://www.openssl.org/) версии 3.5.1 или выше. Также возможно использование библиотек [BoringSSL](https://boringssl.googlesource.com/boringssl), [LibreSSL](https://www.libressl.org/), [QuicTLS](https://github.com/quictls/openssl).

#### Известные проблемы

Модуль экспериментальный, поэтому возможно всё.

До версии 1.29.1 поддержка 0-RTT не могла быть разрешена при использовании OpenSSL независимо от значения директивы [ssl\_early\_data](<260 [02.01.01 http] Модуль ngx_http_ssl_module.md#ssl_early_data>).

Сборка модуля не поддерживается на платформе Win32.

#### Пример конфигурации

> ```
> http {
>     log_format quic '$remote_addr - $remote_user [$time_local] '
>                     '"$request" $status $body_bytes_sent '
>                     '"$http_referer" "$http_user_agent" "$http3"';
> 
>     access_log logs/access.log quic;
> 
>     server {
>         # для лучшей совместимости рекомендуется
>         # использовать одинаковый порт для http/3 и https
>         listen 8443 quic reuseport;
>         listen 8443 ssl;
> 
>         ssl_certificate     certs/example.com.crt;
>         ssl_certificate_key certs/example.com.key;
> 
>         location / {
>             # используется для объявления о поддержке http/3
>             add_header Alt-Svc 'h3=":8443"; ma=86400';
>         }
>     }
> }
> ```

#### Директивы

Разрешает согласование протокола [HTTP/3](https://datatracker.ietf.org/doc/html/rfc9114).

<table>
<tr><th>Синтаксис:</th><td><code><strong>http3_hq</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http3_hq off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>

Разрешает согласование протокола HTTP/0.9, используемого в [функциональных тестах QUIC](https://github.com/marten-seemann/quic-interop-runner).

<table>
<tr><th>Синтаксис:</th><td><code><strong>http3_max_concurrent_streams</strong> <code><i>число</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http3_max_concurrent_streams 128;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Задаёт максимальное число параллельных HTTP/3-потоков в соединении.

<table>
<tr><th>Синтаксис:</th><td><code><strong>http3_stream_buffer_size</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>http3_stream_buffer_size 64k;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Задаёт размер буфера, используемого для чтения и записи QUIC-потоков.

<table>
<tr><th>Синтаксис:</th><td><code><strong>quic_active_connection_id_limit</strong> <code><i>число</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>quic_active_connection_id_limit 2;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Устанавливает значение транспортного параметра QUIC `active_connection_id_limit`. Это максимальное значение ID соединений, возможное для хранения на сервере.

<table>
<tr><th>Синтаксис:</th><td><code><strong>quic_bpf</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>quic_bpf off;</td></tr>
<tr><th>Контекст:</th><td><code>main</code></td></tr>
</table>

Разрешает маршрутизацию пакетов QUIC при помощи [eBPF](https://ebpf.io/). Если маршрутизация включена, то обеспечивается поддержка миграции QUIC-соединений.

> Директива поддерживается только на Linux 5.7+.

<table>
<tr><th>Синтаксис:</th><td><code><strong>quic_gso</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>quic_gso off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Разрешает отправку оптимизированного пакетного режима при помощи segmentation offloading.

> Оптимизированная отправка поддерживается только на Linux с поддержкой `UDP_SEGMENT`.

|   |   |
| --- | --- |
| Синтаксис: | ``**quic_host_key** `*файл*`;`` |
| Умолчание: | — |
| Контекст: | `http`, `server` |

Задаёт `*файл*` с секретным ключом, применяемым при шифровании stateless reset и address validation токенов. По умолчанию создаётся случайный ключ при каждой перезагрузке. Токены, созданные при помощи старых ключей, не принимаются.

<table>
<tr><th>Синтаксис:</th><td><code><strong>quic_retry</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Умолчание:</th><td>quic_retry off;</td></tr>
<tr><th>Контекст:</th><td><code>http</code>, <code>server</code></td></tr>
</table>

Разрешает функциональность [QUIC Address Validation](https://datatracker.ietf.org/doc/html/rfc9000#name-address-validation), в том числе отправку нового токена в `Retry`\-пакете или `NEW_TOKEN` frame и валидацию токена, полученного в `Initial`\-пакете.

#### Встроенные переменные

Модуль `ngx_http_v3_module` поддерживает следующие встроенные переменные:

`$http3`

согласованный идентификатор протокола: “`h3`” для HTTP/3-соединений, “`hq`” для hq-соединений, либо пустая строка.
