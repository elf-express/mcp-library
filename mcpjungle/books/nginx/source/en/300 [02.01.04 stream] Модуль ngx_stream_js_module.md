Модуль `ngx_stream_js_module` позволяет задавать обработчики сессий и переменных на JavaScript с помощью [njs](<290 [02.01.03 njs] Модуль nginx JavaScript.md>).

Инструкция по сборке и установке доступны [здесь](<291 [02.01.03 njs] Загрузка и установка.md>).

#### Пример конфигурации

Пример работает начиная с версии [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0).

> ```
> stream {
>     # начиная с 0.9.1
>     js_engine qjs;
> 
>     js_import stream.js;
> 
>     js_set $bar stream.bar;
>     js_set $req_line stream.req_line;
> 
>     server {
>         listen 12345;
> 
>         js_preread stream.preread;
>         return     $req_line;
>     }
> 
>     server {
>         listen 12346;
> 
>         js_access  stream.access;
>         proxy_pass 127.0.0.1:8000;
>         js_filter  stream.header_inject;
>     }
> }
> 
> http {
>     server {
>         listen 8000;
>         location / {
>             return 200 $http_foo\n;
>         }
>     }
> }
> ```

Файл `stream.js`:

> ```js
> var line = '';
> 
> function bar(s) {
>     var v = s.variables;
>     s.log("hello from bar() handler!");
>     return "bar-var" + v.remote_port + "; pid=" + v.pid;
> }
> 
> function preread(s) {
>     s.on('upload', function (data, flags) {
>         var n = data.indexOf('\n');
>         if (n != -1) {
>             line = data.substr(0, n);
>             s.done();
>         }
>     });
> }
> 
> function req_line(s) {
>     return line;
> }
> 
> // Чтение строки HTTP-запроса.
> // Получение байт в 'req' до того как
> // будет прочитана строка запроса.
> // Добавление HTTP-заголовка в запрос клиента
> 
> var my_header =  'Foo: foo';
> function header_inject(s) {
>     var req = '';
>     s.on('upload', function(data, flags) {
>         req += data;
>         var n = req.search('\n');
>         if (n != -1) {
>             var rest = req.substr(n + 1);
>             req = req.substr(0, n + 1);
>             s.send(req + my_header + '\r\n' + rest, flags);
>             s.off('upload');
>         }
>     });
> }
> 
> function access(s) {
>     if (s.remoteAddress.match('^192.*')) {
>         s.deny();
>         return;
>     }
> 
>     s.allow();
> }
> 
> export default {bar, preread, req_line, header_inject, access};
> ```

Задаёт функцию njs, которая будет вызываться в [access](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md#access_phase>)\-фазе. Начиная с [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0) можно ссылаться на функцию модуля.

В этой фазе может происходить инициализация, также при помощи метода [`s.on()`](https://nginx.org/ru/docs/njs/reference.html#s_on) может регистрироваться вызов для каждого входящего блока данных пока не будет вызван один из методов: [`s.done()`](https://nginx.org/ru/docs/njs/reference.html#s_done) [`s.decline()`](https://nginx.org/ru/docs/njs/reference.html#s_decline), [`s.allow()`](https://nginx.org/ru/docs/njs/reference.html#s_allow). Задаёт URL прямого прокси-сервера при помощи [Fetch API](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch). `*url*` поддерживает только схему HTTP и может содержать необязательные учётные данные пользователя в формате `http://[user:password@]host:port` для базовой аутентификации. Поддерживает как HTTP, так и HTTPS соединения с серверами назначения. Если `*url*` пустой, маршрутизация через прокси отключается. Значение параметра может содержать переменные.

Пример:

> ```
> server {
>     listen 12345;
>     js_fetch_proxy http://user:pass@proxy.example.com:3128;
>     js_preread main.fetch_handler;
> }
> ```

Активирует кэш для соединений с серверами назначения. Если значение больше `0`, включает keepalive-соединения для [Fetch API](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch).

Параметр `*соединения*` задаёт максимальное количество неактивных keepalive-соединений с серверами назначения, которые сохраняются в кэше каждого рабочего процесса. Если это количество превышено, наименее недавно использованные соединения закрываются.

В Stream кэш ведётся отдельно для каждой конфигурации server. Значение, заданное на уровне `stream`, наследуется серверами, но каждый server использует свой кэш. Закэшированные соединения повторно используются для запросов с тем же протоколом, именем узла и портом.

При включении keepalive предполагается, что серверы назначения отправляют корректные HTTP-ответы.

Пример:

> ```
> server {
>     listen 12345;
>     js_fetch_keepalive 32;
>     js_fetch_trusted_certificate /path/to/ISRG_Root_X1.pem;
>     js_preread main.fetch_handler;
> }
> ```

Задаёт фильтр данных. Начиная с [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0) можно ссылаться на функцию модуля. Функция фильтра вызывается однократно при первом достижении сессией [content](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md#content_phase>)\-фазы.

Функция фильтра вызывается со следующими аргументами:

`s`

объект [stream-сессии](https://nginx.org/ru/docs/njs/reference.html#stream)

В этой фазе может происходить инициализация, также при помощи метода [`s.on()`](https://nginx.org/ru/docs/njs/reference.html#s_on) может регистрироваться вызов для каждого входящего блока данных. Для отмены регистрации вызова и отмены фильтра можно использовать метод [`s.off()`](https://nginx.org/ru/docs/njs/reference.html#s_off).

> Так как обработчик `js_filter` должен сразу возвращать результат, то поддерживаются только синхронные операции. Таким образом, асинхронные операции, например [`ngx.fetch()`](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch) или [`setTimeout()`](https://nginx.org/ru/docs/njs/reference.html#settimeout), не поддерживаются.

Эта директива появилась в версии 0.4.0.

Импортирует модуль, позволяющий задавать обработчики сессий и переменных на njs. `Имя_экспорта` является пространством имён при доступе к функциям модуля. Если `имя_экспорта` не задано, то пространством имён будет являться имя модуля.

> ```
> js_import stream.js;
> ```

В примере при доступе к экспорту в качестве пространства имён используется имя модуля `stream`. Если импортируемый модуль экспортирует `foo()`, то для доступа используется `stream.foo`.

Директив `js_import` может быть несколько.

> Директива может быть указана на уровне `server` начиная с [0.7.7](https://nginx.org/ru/docs/njs/changes.html#njs0.7.7).

| Умолчание: | — |
| Контекст: | `stream` |

Задаёт файл, который позволяет задавать обработчики server и переменных на njs:

> ```php
> nginx.conf:
> js_include stream.js;
> js_set     $js_addr address;
> server {
>     listen 127.0.0.1:12345;
>     return $js_addr;
> }
> 
> stream.js:
> function address(s) {
>     return s.remoteAddress;
> }
> ```

Директива устарела в версии [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0) и была удалена в версии [0.7.1](https://nginx.org/ru/docs/njs/changes.html#njs0.7.1). Вместо неё следует использовать директиву [js\_import](#js_import).

| Синтаксис: | ``**js_preload_object** `*имя.json*` \| `*имя*` from `*файл.json*`;`` |
| Умолчание: | — |
| Контекст: | `stream`, `server` |

Эта директива появилась в версии 0.7.8.

Предварительно загружает [неизменяемый объект](<293 [02.01.03 njs] Предзагруженные объекты.md>) во время конфигурации. `Имя` используется в качестве имени глобальной переменной, через которую объект доступен в коде njs. Если `имя` не указано, то будет использоваться имя файла.

> js_preload_object map.json;
> ```

В примере `map` используется в качестве имени во время доступа к предварительно загруженному объекту.

Директив `js_preload_object` может быть несколько.

| --- | --- |
| Синтаксис: | ``**js_preread** `*модуль.функция*`;`` |
| Умолчание: | — |
| Контекст: | `stream`, `server` |

Задаёт функцию njs, которая будет вызываться в [preread](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md#preread_phase>)\-фазе. Начиная с [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0) можно ссылаться на функцию модуля.

Функция вызывается однократно при первом достижении сессией [preread](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md#preread_phase>)\-фазы. Функция вызывается со следующими аргументами:

`s`

объект [stream-сессии](https://nginx.org/ru/docs/njs/reference.html#stream)

В этой фазе может происходить инициализация, также при помощи метода [`s.on()`](https://nginx.org/ru/docs/njs/reference.html#s_on) может регистрироваться вызов для каждого входящего блока данных пока не будет вызван один из методов: [`s.done()`](https://nginx.org/ru/docs/njs/reference.html#s_done) [`s.decline()`](https://nginx.org/ru/docs/njs/reference.html#s_decline), [`s.allow()`](https://nginx.org/ru/docs/njs/reference.html#s_allow). При вызове любого из этих методов обработка сессии переходит на [следующую фазу](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md>) и все текущие вызовы [`s.on()`](https://nginx.org/ru/docs/njs/reference.html#s_on) сбрасываются.

> Так как обработчик `js_preread` должен сразу возвращать результат, то поддерживаются только синхронные операции. Таким образом, асинхронные операции, например [`ngx.fetch()`](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch) или [`setTimeout()`](https://nginx.org/ru/docs/njs/reference.html#settimeout), не поддерживаются. Тем не менее асинхронные операции поддерживаются в вызовах [`s.on()`](https://nginx.org/ru/docs/njs/reference.html#s_on) в [preread](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md#preread_phase>)\-фазе. Подробнее см. [пример](https://github.com/nginx/njs-examples#authorizing-connections-using-ngx-fetch-as-auth-request-stream-auth-request).

|   |   |
| --- | --- |
| Синтаксис: | ``**js_load_stream_native_module** `*путь*` [`as` `*имя*`];`` |
| Умолчание: | — |
| Контекст: | `main` |

Эта директива появилась в версии 0.9.5.

Загружает [нативный модуль](https://nginx.org/ru/docs/njs/native_modules.html) (разделяемую библиотеку) для использования в Stream JavaScript-коде. Директива работает только с движком [QuickJS](<289 [02.01.03 njs] Движок JavaScript.md#quickjs_engine>) и недоступна при использовании встроенного движка njs.

Параметр `*путь*` задаёт абсолютный путь к файлу разделяемой библиотеки. Необязательный параметр `as` `*имя*` задаёт псевдоним для импорта модуля в JavaScript-коде. Если не указан, модуль можно импортировать по имени файла.

Пример:

> ```
> js_load_stream_native_module /path/to/mylib.so;
> js_load_stream_native_module /path/to/other.so as myalias;
> 
> stream {
>     js_import main.js;
>     # ... остальная конфигурация stream
> }
> ```

В JavaScript-коде:

> ```js
> // Импорт по имени файла
> import * as mylib from 'mylib.so';
> 
> // Импорт по псевдониму
> import * as myalias from 'myalias';
> 
> // Использование экспортируемых функций
> let result = mylib.add(5, 10);
> ```

> В целях безопасности директива может использоваться только в контексте `main`. Нативные модули работают с полными привилегиями процесса, необходимо использовать абсолютные пути и проводить проверку кода.

| Умолчание: | — |
| Контекст: | `stream`, `server` |

|   |   |
| --- | --- |
| Синтаксис: | ``**js_periodic** `*модуль.функция*` [`interval`=`*время*`] [`jitter`=`*число*`] [`worker_affinity`=`*маска*`];`` |
| Умолчание: | — |
| Контекст: | `server` |

Эта директива появилась в версии 0.8.1.

Задаёт периодичность запуска обработчика содержимого. В качестве первого аргумента обработчик получает [объект сессии](https://nginx.org/ru/docs/njs/reference.html#periodic_session), также у обработчика есть доступ к глобальным объектам таким как [ngx](https://nginx.org/ru/docs/njs/reference.html#ngx).

Необязательный параметр `interval` задаёт интервал между двумя последовательными запусками, по умолчанию 5 секунд.

Необязательный параметр `jitter` задаёт время, в пределах которого случайным образом задерживается каждый запуск, по умолчанию задержки нет.

По умолчанию обработчик `js_periodic` выполняется для рабочего процесса 0. Необязательный параметр `worker_affinity` позволяет указать рабочий процесс, для которого будет выполняться обработчик содержимого location. Рабочие процессы задаются битовой маской разрешённых к использованию рабочих процессов. Маска `all` позволяет обработчику выполняться для всех рабочих процессов.

Пример:

> ```
> example.conf:
> 
> location @periodics {
>     # интервал выполнения 1 минута для рабочего процесса 0
>     js_periodic main.handler interval=60s;
> 
>     # интервал выполнения 1 минута для всех рабочих процессов
>     js_periodic main.handler interval=60s worker_affinity=all;
> 
>     # интервал выполнения 1 минута для рабочих процессов 1 и 3
>     js_periodic main.handler interval=60s worker_affinity=0101;
> 
>     resolver 10.0.0.1;
>     js_fetch_trusted_certificate /path/to/ISRG_Root_X1.pem;
> }
> 
> example.js:
> 
> async function handler(s) {
>     let reply = await ngx.fetch('https://nginx.org/en/docs/njs/');
>     let body = await reply.text();
> 
>     ngx.log(ngx.INFO, body);
> }
> ```

| Синтаксис: | ``**js_set** `*$переменная*` `*модуль.функция*` [`nocache`];`` |
| Умолчание: | — |
| Контекст: | `stream`, `server` |

Задаёт `функцию` njs для указанной `переменной`. Начиная с [0.4.0](https://nginx.org/ru/docs/njs/changes.html#njs0.4.0) можно ссылаться на функцию модуля.

Функция вызывается в момент первого обращения к переменной для данного запроса. Точный момент вызова функции зависит от [фазы](<317 [02.01.04 stream] Как nginx обрабатывает TCPUDP-сессии.md>), в которой происходит обращение к переменной. Это можно использовать для реализации дополнительной логики, не относящейся к вычислению переменной. Например, если переменная указана в директиве [log\_format](<302 [02.01.04 stream] Модуль ngx_stream_log_module.md#log_format>), то её обработчик не будет выполняться до фазы записи в лог. Этот обработчик также может использоваться для выполнения процедур непосредственно перед освобождением запроса.

Начиная с [0.8.6](https://nginx.org/ru/docs/njs/changes.html#njs0.8.6), если указан необязательный параметр `nocache`, то обработчик выполняется каждый раз при обращении к переменной. Из-за ограничения модуля [ngx\_stream\_set\_module](<311 [02.01.04 stream] Модуль ngx_stream_set_module.md>) при обращении к `nocache`\-переменной при помощи директивы [set](<311 [02.01.04 stream] Модуль ngx_stream_set_module.md#set>), обработчик должен возвращать значение фиксированной длины.

> Так как обработчик `js_set` должен сразу возвращать результат, то поддерживаются только синхронные операции. Таким образом, асинхронные операции, например [`ngx.fetch()`](https://nginx.org/ru/docs/njs/reference.html#ngx_fetch) или [`setTimeout()`](https://nginx.org/ru/docs/njs/reference.html#settimeout), не поддерживаются.

> Директива может быть указана на уровне `server` начиная с [0.7.7](https://nginx.org/ru/docs/njs/changes.html#njs0.7.7).

| Синтаксис: | ``**js_shared_dict_zone** `zone`=`*имя*`:`*размер*` [`timeout`=`*время*`] [`type`=`строка`\|`число`] [`evict`];`` |
| Умолчание: | — |
| Контекст: | `stream` |

Эта директива появилась в версии 0.8.0.

Задаёт `*имя*` и `*размер*` зоны разделяемой памяти, в которой хранится [словарь](https://nginx.org/ru/docs/njs/reference.html#dict) ключей и значений, разделяемый между рабочими процессами.

По умолчанию в качестве ключа и значения используется строка. Необязательный параметр `type` позволяет изменить тип значения на число.

Необязательный параметр `timeout` задаёт время в миллисекундах, по завершении которого все записи в словаре удаляются из зоны. Если для части записей требуется другое время удаления, его можно задать при помощи аргумента `timeout` методов [add](https://nginx.org/ru/docs/njs/reference.html#dict_add), [incr](https://nginx.org/ru/docs/njs/reference.html#dict_incr) и [set](https://nginx.org/ru/docs/njs/reference.html#dict_set) ([0.8.5](https://nginx.org/ru/docs/njs/changes.html#njs0.8.5)).

Необязательный параметр `evict` удаляет самую старую пару ключ-значение при переполнении зоны.

Пример:

> ```
> example.conf:
>     # Создаётся словарь размером 1Мб со строковыми значениями,
>     # пары ключ-значение удаляются при отсутствии активности в течение 60 секунд:
>     js_shared_dict_zone zone=foo:1M timeout=60s;
> 
>     # Создаётся словарь размером 512Кб со строковыми значениями,
>     # удаляется самая старая пара ключ-значение при переполнении зоны:
>     js_shared_dict_zone zone=bar:512K timeout=30s evict;
> 
>     # Создаётся постоянный словарь размером 32Кб с числовыми значениями:
>     js_shared_dict_zone zone=num:32k type=number;
> 
> example.js:
>     function get(r) {
>         r.return(200, ngx.shared.foo.get(r.args.key));
>     }
> 
>     function set(r) {
>         r.return(200, ngx.shared.foo.set(r.args.key, r.args.value));
>     }
> 
>     function del(r) {
>         r.return(200, ngx.shared.bar.delete(r.args.key));
>     }
> 
>     function increment(r) {
>         r.return(200, ngx.shared.num.incr(r.args.key, 2));
>     }
> ```
