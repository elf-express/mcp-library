## Module ngx\_http\_userid\_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [userid](#userid)<br>     [userid\_domain](#userid_domain)<br>     [userid\_expires](#userid_expires)<br>     [userid\_flags](#userid_flags)<br>     [userid\_mark](#userid_mark)<br>     [userid\_name](#userid_name)<br>     [userid\_p3p](#userid_p3p)<br>     [userid\_path](#userid_path)<br>     [userid\_service](#userid_service)<br>[Embedded Variables](#variables) |

The `ngx_http_userid_module` module sets cookies suitable for client identification. Received and set cookies can be logged using the embedded variables [$uid\_got](#var_uid_got) and [$uid\_set](#var_uid_set). This module is compatible with the [mod\_uid](http://www.lexa.ru/programs/mod-uid-eng.html) module for Apache.

#### Example Configuration

> ```
> userid         on;
> userid_name    uid;
> userid_domain  example.com;
> userid_path    /;
> userid_expires 365d;
> userid_p3p     'policyref="/w3c/p3p.xml", CP="CUR ADM OUR NOR STA NID"';
> ```

#### Directives

<table>
<tr><th>Syntax:</th><td><code><strong>userid</strong> <code>on</code> | <code>v1</code> | <code>log</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:</th><td>userid off;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Enables or disables setting cookies and logging the received cookies:

`on`

enables the setting of version 2 cookies and logging of the received cookies;

`v1`

enables the setting of version 1 cookies and logging of the received cookies;

`log`

disables the setting of cookies, but enables logging of the received cookies;

`off`

disables the setting of cookies and logging of the received cookies.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_domain</strong> <code><i>name</i></code> | <code>none</code>;</code></td></tr>
<tr><th>Default:</th><td>userid_domain none;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Defines a domain for which the cookie is set. The `none` parameter disables setting of a domain for the cookie.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_expires</strong> <code><i>time</i></code> | <code>max</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:</th><td>userid_expires off;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Sets a time during which a browser should keep the cookie. The parameter `max` will cause the cookie to expire on “`31 Dec 2037 23:55:55 GMT`”. The parameter `off` will cause the cookie to expire at the end of a browser session.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_flags</strong> <code>off</code> | <code><i>flag</i></code> ...;</code></td></tr>
<tr><th>Default:</th><td>userid_flags off;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

This directive appeared in version 1.19.3.

If the parameter is not `off`, defines one or more additional flags for the cookie: `secure`, `httponly`, `samesite=strict`, `samesite=lax`, `samesite=none`.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_mark</strong> <code><i>letter</i></code> | <code><i>digit</i></code> | <code>=</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:</th><td>userid_mark off;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

If the parameter is not `off`, enables the cookie marking mechanism and sets the character used as a mark. This mechanism is used to add or change [userid\_p3p](#userid_p3p) and/or a cookie expiration time while preserving the client identifier. A mark can be any letter of the English alphabet (case-sensitive), digit, or the “`=`” character.

If the mark is set, it is compared with the first padding symbol in the base64 representation of the client identifier passed in a cookie. If they do not match, the cookie is resent with the specified mark, expiration time, and “P3P” header.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_name</strong> <code><i>name</i></code>;</code></td></tr>
<tr><th>Default:</th><td>userid_name uid;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Sets the cookie name.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_p3p</strong> <code><i>string</i></code> | <code>none</code>;</code></td></tr>
<tr><th>Default:</th><td>userid_p3p none;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Sets a value for the “P3P” header field that will be sent along with the cookie. If the directive is set to the special value `none`, the “P3P” header will not be sent in a response.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_path</strong> <code><i>path</i></code>;</code></td></tr>
<tr><th>Default:</th><td>userid_path /;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Defines a path for which the cookie is set.

<table>
<tr><th>Syntax:</th><td><code><strong>userid_service</strong> <code><i>number</i></code>;</code></td></tr>
<tr><th>Default:</th><td>userid_service IP address of the server;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

If identifiers are issued by multiple servers (services), each service should be assigned its own `*number*` to ensure that client identifiers are unique. For version 1 cookies, the default value is zero. For version 2 cookies, the default value is the number composed from the last four octets of the server’s IP address.

#### Embedded Variables

The `ngx_http_userid_module` module supports the following embedded variables:

`$uid_got`

The cookie name and received client identifier.

`$uid_reset`

If the variable is set to a non-empty string that is not “`0`”, the client identifiers are reset. The special value “`log`” additionally leads to the output of messages about the reset identifiers to the [error\_log](<125 [01.01 docs] Core functionality.md#error_log>).

`$uid_set`

The cookie name and sent client identifier.
