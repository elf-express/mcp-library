# Module ngx_http_sub_module


## Module ngx\_http\_sub\_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [sub\_filter](#sub_filter)<br>     [sub\_filter\_last\_modified](#sub_filter_last_modified)<br>     [sub\_filter\_once](#sub_filter_once)<br>     [sub\_filter\_types](#sub_filter_types) |

The `ngx_http_sub_module` module is a filter that modifies a response by replacing one specified string by another.

This module is not built by default, it should be enabled with the `--with-http_sub_module` configuration parameter.

## Example Configuration

> ```
> location / {
>     sub_filter '<a href="http://127.0.0.1:8080/'  '<a href="https://$host/';
>     sub_filter '<img src="http://127.0.0.1:8080/' '<img src="https://$host/';
>     sub_filter_once on;
> }
> ```

## Directives

### sub_filter

|   |   |
| --- | --- |
| Syntax: | ``**sub_filter** `*string*` `*replacement*`;`` |
| Default: | — |
| Context: | `http`, `server`, `location` |

Sets a string to replace and a replacement string. The string to replace is matched ignoring the case. The string to replace (1.9.4) and replacement string can contain variables. Several `sub_filter` directives can be specified on the same configuration level (1.9.4). These directives are inherited from the previous configuration level if and only if there are no `sub_filter` directives defined on the current level.

### sub_filter_last_modified

<table>
<tr><th>Syntax:</th><td><code><strong>sub_filter_last_modified</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:</th><td>sub_filter_last_modified off;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

This directive appeared in version 1.5.1.

Allows preserving the “Last-Modified” header field from the original response during replacement to facilitate response caching.

By default, the header field is removed as contents of the response are modified during processing.

### sub_filter_once

<table>
<tr><th>Syntax:</th><td><code><strong>sub_filter_once</strong> <code>on</code> | <code>off</code>;</code></td></tr>
<tr><th>Default:</th><td>sub_filter_once on;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Indicates whether to look for each string to replace once or repeatedly.

### sub_filter_types

<table>
<tr><th>Syntax:</th><td><code><strong>sub_filter_types</strong> <code><i>mime-type</i></code> ...;</code></td></tr>
<tr><th>Default:</th><td>sub_filter_types text/html;</td></tr>
<tr><th>Context:</th><td><code>http</code>, <code>server</code>, <code>location</code></td></tr>
</table>

Enables string replacement in responses with the specified MIME types in addition to “`text/html`”. The special value “`*`” matches any MIME type (0.8.29).
