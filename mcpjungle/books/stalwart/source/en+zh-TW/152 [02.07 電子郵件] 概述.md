# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[email｜電子郵件\\\]\\\(&lt;000 目錄.md#c-22&gt;\\\)

Stalwart supports a range of email protocols to accommodate different organisational needs and to ensure compatibility with various email clients and devices. Supported protocols are JMAP, the latest and preceding versions of the Internet Message Access Protocol \(IMAP\), and the Post Office Protocol version 3 \(POP3\).

 Stalwart 支援多種電子郵件協議，以滿足不同的組織需求，並確保與各種電子郵件用戶端和裝置的兼容性。支援的協定包括JMAP 、網際網路訊息存取協定 \( IMAP \) 的最新及更早版本，以及郵局協定版本 3 \( POP3 \)。

 Protocol-level parameters \(limits, timeouts, rate limits, default folders, encryption, compression\) are set on dedicated singletons: Jmap \(found in the WebUI under Settings › Network › JMAP › Limits, Settings › Network › JMAP › Push, Settings › Network › JMAP › WebSocket\), Imap \(found in the WebUI under Settings › Network › IMAP\), and Email \(found in the WebUI under Settings › Email › Defaults, Settings › Email › Encryption, Settings › Email › Limits, Settings › Email › Storage\). Transport-level settings \(bind addresses, ports, TLS\) live on individual NetworkListener objects \(found in the WebUI under Settings › Network › Listeners\).

 協定級參數（限制、逾時、速率限制、預設資料夾、加密、壓縮）在專用單例中設定：Jmap （可在 WebUI 的「設定 › 網路 › JMAP › 限制」、「設定 › 網路 › JMAP › JMAP › WebSocket」中找到），Imap （可在 WebUI 的「設定 › 網路 › IMAP 」中找到），以及 Email （可在 Web › 電子郵件設定 預設值 › 電子郵件設定 」限制」、「設定 › 電子郵件 › 儲存」中找到）。傳輸層設定（綁定位址、連接埠、 TLS ）存在於各個 NetworkListener物件中（可在 WebUI 的「設定 › 網路 › 監聽器」中找到）。

## JMAP for Mail｜JMAP郵件

 JMAP \(JSON Meta Application Protocol\) is a modern, stateful protocol for synchronising mail, calendars, and contacts between a client and a server. It operates over HTTP and uses JSON as its data format. JMAP is designed to handle large amounts of data efficiently, offers a consistent interface for different data types, and provides built-in support for push updates so that changes are reflected on all connected devices.

 JMAP（JSON元應用協定）是一種現代的、有狀態的協議，用於在客戶端和伺服器之間同步郵件、日曆和聯絡人。它在HTTP上運行並使用JSON作為其資料格式。 JMAP 旨在高效處理大量數據，為不同數據類型提供一致的接口，並提供對推送更新的內置支持，以便更改反映在所有連接的設備上。

 To accept JMAP connections, a NetworkListener must be created with protocol set to `"http"`. For example, an implicit-TLS listener on port 8080:

 要接受JMAP連接，必須建立一個 NetworkListener，並將 protocol設定為`"http"` 。例如，在連接埠 8080 上建立一個隱式TLS監聽器：

```json
{
  "name": "jmap",
  "protocol": "http",
  "bind": {"[::]:8080": true},
  "tlsImplicit": true
}
```

## IMAP4

 Stalwart is compatible with the most recent version, [IMAP4rev2 protocol](https://www.rfc-editor.org/rfc/rfc9051.html), as well as the widely used [IMAP4rev1](https://www.rfc-editor.org/rfc/rfc3501). These protocols allow users to access their emails from multiple clients simultaneously and manage their messages directly on the mail server, giving flexibility and real-time synchronisation of email state across devices. In addition to basic IMAP support, Stalwart includes a number of IMAP4 extensions.

 Stalwart 相容於最新版本的 [IMAP4rev2 協定](https://www.rfc-editor.org/rfc/rfc9051.html)以及廣泛使用的 [IMAP4rev1](https://www.rfc-editor.org/rfc/rfc3501)協定。這些協定允許使用者同時從多個客戶端存取電子郵件，並直接在郵件伺服器上管理郵件，從而實現跨裝置的靈活性和郵件狀態的即時同步。除了基本的IMAP支援外，Stalwart 還包含一些 IMAP4擴充 。

 To accept IMAP4 connections, a NetworkListener must be created with protocol set to `"imap"`. For example, a plain-text listener on port 143 and an implicit-TLS listener on port 993:

 要接受IMAP4連接，必須建立一個 NetworkListener，並將 protocol設定為`"imap"` 。例如，在連接埠 143 上建立一個純文字監聽器，在連接埠 993 上建立一個隱式TLS監聽器：

```json
[
  {"name": "imap", "protocol": "imap", "bind": {"[::]:143": true}},
  {"name": "imaptls", "protocol": "imap", "bind": {"[::]:993": true}, "tlsImplicit": true}
]
```

## POP3

 Stalwart also supports POP3, an older email protocol designed for simple, one-way downloading of messages from the server to the email client. Once downloaded, emails are typically deleted from the server unless configured otherwise, making POP3 less flexible than IMAP.

 Stalwart 也支援POP3 ，這是一種較早的電子郵件協議，旨在實現從伺服器到電子郵件用戶端的簡單單向郵件下載。下載完成後，除非另有配置，否則電子郵件通常會從伺服器中刪除，這使得POP3靈活性不如IMAP 。

 While POP3 can be useful for single-device email access or specific legacy applications, it lacks features that many deployments require today, such as multi-device synchronisation and server-side message management. Given its limitations and the security implications of less secure legacy protocols, POP3 should be disabled unless there is a specific need, such as compatibility requirements for legacy devices.

 雖然POP3對於單一裝置電子郵件存取或特定舊版應用程式可能有用，但它缺乏當今許多部署所需的功能，例如多裝置同步和伺服器端訊息管理。鑑於其局限性以及安全性較低的舊版協議帶來的安全隱患，除非有特殊需要（例如滿足舊版設備的兼容性要求），否則應禁用POP3 。

 To accept POP3 connections, a NetworkListener must be created with protocol set to `"pop3"`. For example, a plain-text listener on port 110 and an implicit-TLS listener on port 995:

 要接受POP3連接，必須建立一個 NetworkListener，並將 protocol設為`"pop3"` 。例如，在連接埠 110 上建立一個純文字監聽器，在連接埠 995 上建立一個隱式TLS監聽器：

```json
[
  {"name": "pop3", "protocol": "pop3", "bind": {"[::]:110": true}},
  {"name": "pop3s", "protocol": "pop3", "bind": {"[::]:995": true}, "tlsImplicit": true}
]
```
