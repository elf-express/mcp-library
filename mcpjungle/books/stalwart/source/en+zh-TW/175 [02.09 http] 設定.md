# Settings｜設定

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[http\\\]\\\(&lt;000 目錄.md#c-26&gt;\\\)

Stalwart includes a built-in HTTP server that handles JMAP and WebDAV requests. HTTP server behaviour is configured on the Http singleton \(found in the WebUI under Settings › Network › HTTP › General, Settings › Network › HTTP › Security\).

 Stalwart 包含一個內建的 HTTP 伺服器，用於處理 JMAP 和 WebDAV 請求。 HTTP 伺服器行為在 Http 單例上設定（可在 WebUI 中的設定 › 網路 › HTTP › 常規、設定 › 網路 › HTTP › 安全下找到）。

## Response headers｜回應頭

 Additional HTTP headers returned with every response are configured through responseHeaders, a map of header name to header value. Typical uses include setting security policies, caching behaviour, or adding custom identification headers.

 每個回應傳回的附加HTTP標頭透過 responseHeaders進行配置，該映射將標頭名稱對應到標頭值。典型用途包括設定安全性策略、快取行為或新增自訂識別標頭。

 For example, to advertise a `Server` header and a cache-control policy:

 例如，要通告`Server`標頭和快取控制策略：

```json
{
  "responseHeaders": {
    "Cache-Control": "max-age=3600",
    "Server": "Stalwart"
  }
}
```

Administrators should exercise caution when overriding headers: certain values can affect the behaviour of clients or intermediary systems. Consult the relevant specifications before introducing custom headers.

 管理員在修改請求頭時應格外謹慎：某些值可能會影響客戶端或中間系統的行為。在引入自訂請求頭之前，請務必查閱相關規格。

## Use Forwarded IP｜使用轉發IP

 When Stalwart runs behind a reverse proxy such as Cloudflare or Amazon CloudFront, the client IP address must be read from the `Forwarded` or `X-Forwarded-For` HTTP header rather than from the socket source address, which would otherwise report the proxy’s address. This is controlled by useXForwarded; setting the flag to `true` instructs the server to trust those headers. The flag should not be enabled when the proxy protocol is in use.

 當 Stalwart 運行在 Cloudflare 或 Amazon CloudFront 等反向代理之後時，客戶端的IP位址必須從`Forwarded`或`X-Forwarded-For` HTTP標頭中讀取，而不是從套接字來源位址讀取，否則套接字來源位址會報告代理的位址。這由 useXForwarded控制；將該標誌設為`true`會指示伺服器信任這些標頭。當使用 代理協定時，不應啟用此標誌。

 Care must be taken when enabling this feature. It should only be used when Stalwart is behind a trusted proxy, because untrusted sources can forge these headers and mislead logging or access control decisions. When no proxy is present, useXForwarded must remain `false` to prevent malicious clients from spoofing their source IP address.

 啟用此功能時必須謹慎。只有當 Stalwart 位於受信任代理之後時才應使用此功能，因為不受信任的來源可能會偽造這些標頭，從而誤導日誌記錄或存取控制決策。如果沒有代理，則 useXForwarded必須保持`false`不變，以防止惡意客戶端偽造其來源IP位址。

 The base URL advertised in well-known responses \(for example `/.well-known/jmap` and OAuth discovery metadata\) is derived automatically from the listener address and server hostname; no explicit configuration field is required.

 在眾所周知的回應（例如`/.well-known/jmap`和 OAuth 發現元資料）中公佈的基本URL是從監聽器位址和伺服器主機名稱自動派生出來的；不需要明確配置欄位。
