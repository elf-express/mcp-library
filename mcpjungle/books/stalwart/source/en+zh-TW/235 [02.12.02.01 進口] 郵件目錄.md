# Maildir｜郵件目錄

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[import export｜進出口\\\]\\\(&lt;000 目錄.md#c-40&gt;\\\) › \\\[import｜進口\\\]\\\(&lt;000 目錄.md#c-41&gt;\\\)

The Maildir importer reads a local Maildir++ tree directly from the filesystem into a Vandelay archive. It is a fully offline operation: there is no server URL, no authentication, and no network access of any kind. The source is identified solely by the on-disk path of the Maildir root, which makes this importer the natural choice for migrating from a filesystem backup or from a Dovecot, Courier, or qmail Maildir that has been copied onto the machine running Vandelay.

 Maildir 匯入程式將本機 Maildir++ 樹直接從檔案系統讀取到 Vandelay 檔案中。這是完全離線的操作：沒有伺服器URL，沒有身份驗證，也沒有任何類型的網路存取。來源僅由 Maildir 根的磁碟路徑來標識，這使得此匯入程式成為從檔案系統備份或從已複製到運行 Vandelay 的電腦上的 Dovecot、Courier 或 qmail Maildir 進行遷移的自然選擇。

## Invocation and positional order｜調用和位置順序

 The subcommand takes two positional arguments, and the order matters: the Maildir path comes first, the archive second.

 此子指令採用兩個位置參數，順序很重要：Maildir 路徑排在第一位，存檔路徑排在第二位。

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import maildir <MAILDIR> <ARCHIVE>
```

`<MAILDIR>` is the path to the Maildir root \(the directory that contains the `cur/`, `new/`, and `tmp/` subdirectories\). `<ARCHIVE>` is the local SQLite archive, which is created if it does not already exist. This positional shape is a deliberate departure from the JMAP, IMAP, and DAV importers, which take the archive as their single positional argument and the source on `--url`. A Maildir has no URL; its location is the local path, so the path is expressed positionally rather than behind a flag.

`<MAILDIR>` 是 Maildir 根目錄的路徑（包含 `cur/`, `new/` 和 `tmp/` 子目錄）。 `<ARCHIVE>` 是本機 SQLite 存檔，如果不存在則建立。這種位置形狀是故意背離JMAP, IMAP和DAV導入器的，它們將存檔作為其單一位置參數和`--url`上的來源。 Maildir 沒有 URL；它的位置是本地路徑，因此路徑是按位置而不是在標誌後面表示的。

 The path may be given in any surface form: a relative path, a path containing `..` segments, or a symlink. Vandelay canonicalises it \(following symlinks and resolving `..` to an absolute path\) before recording it, so two different surface forms that resolve to the same directory are treated as the same source.

 路徑可以任何表面形式給出：相對路徑、包含 `..` 段的路徑或符號連結。 Vandelay 在記錄它之前對其進行規範化（遵循符號連結並將 `..` 解析為絕對路徑），因此解析到同一目錄的兩個不同表面形式被視為相同的來源。

## The Maildir++ layout｜Maildir++ 佈局

 A Maildir root is a directory containing exactly the three subdirectories `cur/`, `new/`, and `tmp/`. The root itself holds the INBOX messages. Vandelay reads messages out of `cur/` and `new/` only; `tmp/` is the staging area for delivery agents and is never read.

 Maildir 根目錄是一個包含三個子目錄`cur/`, `new/` 和`tmp/` 的目錄。根本身保存INBOX訊息。 Vandelay 只讀取`cur/` 和`new/` 中的消息； `tmp/` 是送貨代理的中轉區域，永遠不會被讀取。

 Subfolders follow the Maildir++ convention: they are siblings of the root, named with a leading `.`, and the hierarchy is encoded by additional `.` separators inside the directory name. A directory named `.Archive.2025` is therefore the folder `2025` nested under `Archive`.

 子資料夾遵循 Maildir++ 約定：它們是根目錄的同級資料夾，先前導數 `.` 命名，並且層次結構由目錄名稱中附加的 `.` 分隔符號進行編碼。因此，名為 `.Archive.2025` 的目錄是嵌套在 `Archive` 下的資料夾 `2025`。

```xml
<root>/
├── cur/                  (INBOX, read messages)
├── new/                  (INBOX, unread messages)
├── tmp/                  (delivery staging; never read)
├── .Sent/               (folder "Sent")
│   ├── cur/
│   ├── new/
│   └── tmp/
├── .Archive/            (folder "Archive")
│   ├── cur/
│   └── new/
└── .Archive.2025/       (folder "2025" under "Archive")
    ├── cur/
    └── new/
```

The canonical folder name \(used for the mailbox name, for parent/child reconstruction, and for filter matching\) is the literal string `INBOX` for the root, and the Maildir++ name with the leading `.` stripped for every subfolder: `.Sent` becomes `Sent`, `.Archive.2025` becomes `Archive.2025`. The parent/child structure for nested mailboxes is recovered by splitting the canonical name on `.`, so `Archive.2025` is parented under `Archive`.

 規範資料夾名稱（用於郵箱名稱、父/子資料夾重建和過濾器匹配）是字面字串 `INBOX` 根目錄，以及帶有前導符的 Maildir++ 名稱 `.` 已剝離每個子資料夾： `.Sent` 變成 `Sent`, `.Archive.2025` 變成 `Archive.2025`嵌套郵箱的父/子結構是透過拆分規範名稱來恢復的。 `.`， 所以 `Archive.2025` 父級 `Archive`.

 Only the Maildir++ layout is supported. Dovecot’s alternative `LAYOUT=fs` \(subfolders nested as real subdirectories\) is rejected at the discovery step with a clear error.

 僅支援 Maildir++ 佈局。 Dovecot 的替代方案 `LAYOUT=fs`（嵌套為真實子目錄的子資料夾）在發現步驟中被拒絕，並出現明顯錯誤。

## Folder selection｜資料夾選擇

 Folder selection mirrors the IMAP importer. The same three flags apply, matched against the canonical folder name:

 資料夾選擇反映了IMAP導入器。應用相同的三個標誌，與規範資料夾名稱相符：

- `--include <REGEX>` \(repeatable\): keep only folders whose canonical name matches at least one of the supplied patterns. When omitted, every folder is kept.
`--include <REGEX>`（可重複）：僅保留規範名稱至少與所提供的模式之一相符的資料夾。省略時，將保留每個資料夾。
- `--exclude <REGEX>` \(repeatable\): drop folders whose canonical name matches any of the supplied patterns. Exclusion is applied after inclusion.
`--exclude <REGEX>`（可重複）：放置規範名稱與任何提供的模式相符的資料夾。包含後應用排除。
- `--folder <NAME>` \(repeatable\): an exact-match include list. This is mutually exclusive with `--include` and `--exclude`; combining them is a usage error.
`--folder <NAME>`（可重複）：完全符合的包含清單。這與`--include`和`--exclude`互斥；將它們組合起來是一個使用錯誤。
There is no subscription-only filter \(Maildir has no IMAP-style subscription set\) and no special-use exclusion. To skip a folder such as the trash, write an explicit pattern, for example `--exclude '^Trash 沒有僅限訂閱的過濾器（Maildir 沒有IMAP 式的訂閱集），也沒有特殊用途的排除。要跳過垃圾箱等資料夾，請編寫明確的模式，例如 --exclude '^Trash$'`。 ## Role assignment and the name heuristic｜角色分配和名稱啟發式

 Because Maildir carries no SPECIAL-USE metadata, the folder name is the only signal available for assigning a JMAP role. By default Vandelay applies a case-insensitive name heuristic to the leaf component of each canonical folder name:

 由於 Maildir 不攜帶 SPECIAL-USE 元數據，因此資料夾名稱是可用於分配 JMAP 角色的唯一訊號。預設情況下，Vandelay 對每個規範資料夾名稱的葉元件套用不區分大小寫的名稱啟發式：

| Canonical folder name \(leaf, case-insensitive\) 規格資料夾名稱（葉，不區分大小寫） | Role 角色 |
| --- | --- |
| `INBOX` | `inbox` |
| `Sent`, `Sent Items`, `Sent Messages`, `Sent Mail` | `sent` |
| `Drafts`, `Draft` | `drafts` |
| `Trash`, `Deleted`, `Deleted Items`, `Deleted Messages` | `trash` |
| `Junk`, `Spam`, `Junk E-mail` | `junk` |
| `Archive`, `Archives` | `archive` |

The heuristic judges each folder on its own leaf name, so an intermediate Maildir++ level does not inherit a role from its parent. Passing `--noautomap` disables the heuristic entirely; every folder is then imported with no role, except INBOX, which is always the inbox by virtue of being the Maildir root.

 啟發式方法根據每個資料夾自己的葉名稱來判斷，因此中間 Maildir++ 層級不會從其父級繼承角色。透過 `--noautomap` 會完全停用啟發式；然後，除了 INBOX 之外，每個資料夾都會以無角色的方式匯入，由於它是 Maildir 根目錄，所以它總是收件匣。

## Deleted messages｜已刪除的訊息

 Maildir marks a message for deletion with the `T` \(Trashed\) flag in its filename, the local analogue of IMAP’s `\Deleted`. By default Vandelay drops `T`-flagged messages: a freshly trashed message is skipped on import, and a previously imported message that has since gained the `T` flag is removed from the archive on the next run, so the archive converges to “gone” when a message is trashed at the source.

 Maildir 在其檔案名稱中使用 `T`（已刪除）標記標記要刪除的郵件，這是IMAP 的 `\Deleted` 的本地類似物。預設情況下，Vandelay 會丟棄帶有 `T`\\ 標記的訊息：匯入時會跳過新刪除的訊息，而先前匯入的已取得 `T` 標記的訊息會在下次執行時從存檔中刪除，因此當訊息在來源處被刪除時，存檔會收斂為「消失」。

 Passing `--include-deleted` overrides this behaviour. Trashed messages are then imported and tagged with the `$deleted` keyword, and the rows remain stable across re-runs. The remaining Maildir flags map to JMAP keywords directly: `S` to `$seen`, `R` to `$answered`, `P` to `$forwarded`, `D` to `$draft`, and `F` to `$flagged`.

 傳遞 `--include-deleted` 會覆寫此行為。然後匯入已刪除的訊息並使用 `$deleted` 關鍵字進行標記，且行在重新運行後保持穩定。其余 Maildir 标志直接映射到 JMAP 关键字：`S` 至 `$seen`, `R` 至 `$answered`, `P` 至 `$forwarded`, `D` 至 `$draft`，以及 `F` 至 `$flagged`。

## Source-change protection｜來源更改保護

 The archive records the canonical Maildir path of the source it was imported from. If a subsequent `vandelay import maildir` against the same archive supplies a different Maildir path, Vandelay refuses the run, on the assumption that pointing one archive at two distinct Maildirs is almost certainly a mistake. This protection is keyed on the canonical path, so re-running through a different surface form \(a symlink, a relative path\) of the same directory does not trip it.

 存檔記錄了導入來源的規範 Maildir 路徑。如果針對相同檔案的後續 `vandelay import maildir` 提供了不同的 Maildir 路徑，Vandelay 會拒絕運行，因為假設將一個檔案指向兩個不同的 Maildir 幾乎肯定是一個錯誤。此保護以規範路徑為關鍵，因此透過同一目錄的不同表面形式（符號連結、相對路徑）重新運行不會使其失敗。

 When the path genuinely needs to change, pass `--allow-source-change` to permit the import.

 當路徑確實需要改變時，透過`--allow-source-change`允許導入。

## Examples｜範例

 A straightforward import of an entire Maildir tree into a new archive. The Maildir path comes first, the archive second:

 將整個 Maildir 樹直接匯入到新檔案中。 Maildir 路徑排在第一位，存檔路徑排在第二位：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import maildir /home/alice/Maildir alice.sqlite
```

A filtered import that keeps only the archive hierarchy and the sent folder, excludes the trash, and disables role assignment:

 過濾匯入僅保留存檔層次結構和傳送的資料夾，排除垃圾，並停用角色分配：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import maildir \
  --include '^Archive' \
  --include '^Sent$' \
  --exclude '^Trash$' \
  --noautomap \
  /home/alice/Maildir \
  alice.sqlite
```

An import of two named folders only, using the exact-match form \(which cannot be combined with `--include` or `--exclude`\), and including trashed messages:

 僅匯入兩個命名資料夾，使用完全匹配形式（不能與`--include`或`--exclude`組合），並包括已刪除的訊息：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import maildir \
  --folder INBOX \
  --folder Sent \
  --include-deleted \
  /backup/restore/Maildir \
  alice.sqlite
```

## Behaviour and convergence｜行為和收斂

 Vandelay always imports both mailboxes and messages together; there is no way to import only one of the two. The importer is convergent: re-running it against the same Maildir reconciles the archive with the current on-disk state. New messages are inserted, vanished messages are removed, and flag-only changes \(for example a message gaining the `S` flag when it is read\) update the stored keywords in place without re-reading the message body. Message bytes are stored verbatim and content-addressed, so the same message imported from a Maildir, an IMAP server, and a JMAP server lands on a single shared blob.

 Vandelay 始終將郵箱和訊息一起匯入；沒有辦法只匯入兩者之一。導入程序是收斂的：針對相同的 Maildir 重新運行它可以使存檔與當前磁碟狀態保持一致。新訊息被插入，消失的訊息被刪除，並且僅標誌的更改（例如，在讀取訊息時獲得`S`標誌的訊息）會就地更新儲存的關鍵字，而無需重新讀取訊息正文。訊息位元組逐字儲存並按內容尋址，因此從 Maildir、IMAP 伺服器和JMAP 伺服器匯入的相同訊息會落在單一共用 blob 上。

 The global flags behave as they do elsewhere. `--dry-run` computes and prints the per-folder plan \(new, vanished, and present message counts, plus new and vanished folder counts\) without writing to the archive. Verbosity \(`-v`, `-q`\) follows the common convention. The remaining global flags that pertain to networked sources have no effect on a local import: `-j` / `--threads` is accepted but ignored \(the Maildir importer is single-threaded\), `--max-retries` is accepted but ignored \(a filesystem read that fails once will not succeed on retry\), and `--allow-invalid-certs` is accepted but ignored \(there is no TLS\).

 全局標誌的行為與其他地方一樣。 `--dry-run` 計算並列印每個資料夾的計劃（新的、消失的和當前的訊息計數，加上新的和消失的資料夾計數），而不寫入存檔。冗長（`-v`, `-q`）遵循通用約定。与网络源相关的其余全局标志对本地导入没有影响：`-j` / `--threads`被接受但被忽略（Maildir导入器是单线程的），`--max-retries`被接受但被忽略（一次失败的文件系统读取在重试时不会成功），`--allow-invalid-certs`被接受但被忽略（没有TLS）。

Message bytes are stored verbatim and content-addressed, so the same message imported from a Maildir, an IMAP server, and a JMAP server lands on a single shared blob.

 Vandelay 始終將郵箱和訊息一起匯入；沒有辦法只匯入兩者之一。導入程序是收斂的：針對相同的 Maildir 重新運行它可以使存檔與當前磁碟狀態保持一致。新訊息被插入，消失的訊息被刪除，並且僅標誌的更改（例如，在讀取訊息時獲得`S`標誌的訊息）會就地更新儲存的關鍵字，而無需重新讀取訊息正文。訊息位元組逐字儲存並按內容尋址，因此從 Maildir、IMAP 伺服器和JMAP 伺服器匯入的相同訊息會落在單一共用 blob 上。

 The global flags behave as they do elsewhere. `--dry-run` computes and prints the per-folder plan \(new, vanished, and present message counts, plus new and vanished folder counts\) without writing to the archive. Verbosity \(`-v`, `-q`\) follows the common convention. The remaining global flags that pertain to networked sources have no effect on a local import: `-j` / `--threads` is accepted but ignored \(the Maildir importer is single-threaded\), `--max-retries` is accepted but ignored \(a filesystem read that fails once will not succeed on retry\), and `--allow-invalid-certs` is accepted but ignored \(there is no TLS\).

 全局標誌的行為與其他地方一樣。 `--dry-run` 計算並列印每個資料夾的計劃（新的、消失的和當前的訊息計數，加上新的和消失的資料夾計數），而不寫入存檔。冗長（`-v`, `-q`）遵循通用約定。与网络源相关的其余全局标志对本地导入没有影响：`-j` / `--threads`被接受但被忽略（Maildir导入器是单线程的），`--max-retries`被接受但被忽略（一次失败的文件系统读取在重试时不会成功），`--allow-invalid-certs`被接受但被忽略（没有TLS）。
