# Coordination mechanism｜協調機制

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-13&gt;\\\)

Stalwart requires a coordination mechanism to enable communication between nodes in a cluster. Coordination allows nodes to exchange internal updates, detect failures, and remain synchronised during operation. For a full overview of how coordination works and the available options \(peer-to-peer, Kafka, NATS, and Redis\), refer to the Coordination section of this documentation.

 Stalwart 需要一種協調機制來實現叢集中節點間的通訊。協調機制允許節點交換內部更新、檢測故障並在運行期間保持同步。有關協調機制的工作原理和可用選項（點對點、Kafka、 NATS和 Redis）的完整概述，請參閱本文檔的 協調部分。

 Coordination is configured on the Coordinator singleton \(found in the WebUI under Settings › Cluster › Coordinator\). The singleton is a multi-variant object: selecting a variant chooses the backend, and each variant carries its own fields. The supported variants are:

 協調配置在 Coordinator單例物件上進行（可在 WebUI 的「設定」&gt;「叢集」&gt;「協調器」中找到）。這個單例物件是一個多變體物件：選擇一個變體即可選擇後端，每個變體都有其自身的欄位。支持的變體包括：

- `Disabled`: coordination is turned off. Suitable for single-node installations.
`Disabled` ：協調功能已關閉。適用於單節點安裝。
- `Default`: uses the configured in-memory store for coordination \(Redis only\).
`Default` ：使用配置的記憶體儲存進行協調（僅限 Redis）。
- `Zenoh`: peer-to-peer coordination over Eclipse Zenoh.
`Zenoh` ：基於 Eclipse Zenoh 的點對點協調。
- `Kafka`: Apache Kafka or a Kafka-compatible platform such as Redpanda.
`Kafka` ：Apache Kafka 或 Kafka 相容平台，例如 Redpanda。
- `Nats`: NATS messaging.
`Nats`: NATS訊息傳遞。
- `Redis`: a standalone Redis server.
`Redis` ：一個獨立的 Redis 伺服器。
- `RedisCluster`: a Redis Cluster deployment.
`RedisCluster` ：Redis 集群部署。
All nodes in the cluster must use the same coordination backend to function correctly. The backend-specific configuration fields are covered in the dedicated pages for peer-to-peer, Kafka, NATS, and Redis.
 叢集中的所有節點必須使用相同的協調後端才能正常運作。後端特定的設定欄位包含在 peer-to-peer、Kafka、NATS 和 Redis 的專用頁面中。
