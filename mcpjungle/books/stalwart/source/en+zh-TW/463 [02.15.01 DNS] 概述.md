# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\) › \\\[dns｜DNS\\\]\\\(&lt;000 目錄.md#c-63&gt;\\\)

Stalwart can integrate with an external DNS provider and manage the records a mail server needs \(MX, SPF, DKIM, DMARC, TLSA, autoconfig and autodiscover records, and the rest of the set described below\) on the operator’s behalf. When this integration is active, the server publishes and updates the zone directly against the provider’s API, so records stay in sync with the server’s configuration without manual changes in the provider’s control panel.

 Stalwart 可與外部DNS提供者集成，並代表營運商管理郵件伺服器所需的記錄（ MX, SPF, DKIM, DMARC, TLSA 、自動配置和自動發現記錄，以及下文所述的其餘記錄集）。啟用此整合後，伺服器會直接根據提供者的API發布和更新區域，因此記錄無需在提供者的控制面板中手動變更即可與伺服器配置保持同步。

## How records are provisioned｜記錄的提供方式

 Integration is defined by the DnsServer object \(found in the WebUI under Settings › Network › DNS › DNS Providers\), which stores the provider type and the credentials used to authenticate against its API. A single deployment can hold any number of DnsServer entries, for example one per provider or one per tenant.

 整合由 DnsServer物件定義（可在 WebUI 的「設定」&gt;「網路」&gt; DNS &gt; DNS提供者」下找到），該物件儲存提供者類型以及用於對其物件儲存提供者類型以及用於對其進行驗證的憑證API 。單一部署可以包含任意數量的 DnsServer 條目，例如每個提供者一個條目或每個租用戶一個條目。

 A Domain \(found in the WebUI under Management › Domains › Domains\) is wired to a provider through its dnsManagement field. Selecting the `Automatic` variant and setting dnsServerId to the identifier of a DnsServer activates the integration for that domain. When the Domain is first created with an `Automatic` dnsManagement configuration, Stalwart publishes the initial set of records into the target zone. The record types that are published and kept in sync are selected by the `publishRecords` list on the `Automatic` variant, which defaults to DKIM, SPF, MX, DMARC, SRV, MTA-STS, TLS-RPT, CAA, autoconfig, legacy autoconfig, and Microsoft autodiscover. TLSA records can also be added to that list. See DNS record setup for the full wiring.

 網域（可在 WebUI 的「管理」&gt;「網域」&gt;「網域`dnsManagement` \([https://stalw.art/docs/ref/object/domain](https://stalw.art/docs/ref/object/domain)\) \([https://stalw.art/docs/ref/object/domain#dnsmanagement\)欄位連接到提供者。選擇\`Automatic\`變體並將](https://stalw.art/docs/ref/object/domain#dnsmanagement%2529%2525E6%2525AC%252584%2525E4%2525BD%25258D%2525E9%252580%2525A3%2525E6%25258E%2525A5%2525E5%252588%2525B0%2525E6%25258F%252590%2525E4%2525BE%25259B%2525E8%252580%252585%2525E3%252580%252582%2525E9%252581%2525B8%2525E6%252593%252587%252560Automatic%252560%2525E8%2525AE%25258A%2525E9%2525AB%252594%2525E4%2525B8%2525A6%2525E5%2525B0%252587) dnsServerId設定為 DNS 伺服器的標識符，即可啟動該域的整合。首次使用`Automatic` dnsManagement配置建立域時，Stalwart 會將初始記錄集發佈到目標區域。發布並保持同步的記錄類型由`Automatic`變體上的`publishRecords`清單選擇，預設值為DKIM, SPF, MX, DMARC, SRV, MTA-STS, TLS-RPT, CAA 、自動配置、舊版自動配置和 Microsoft 自動發現。 TLSA記錄也可以加入到該清單中。有關完整的接線圖，請參閱DNS記錄設定 。

## Refreshing records｜重新整理記錄

 Records are kept current by the task manager. The Task object exposes a `DnsManagement` variant that targets a specific Domain and optionally narrows the refresh to a subset of record types through its `updateRecords` field. Triggering a task of this variant causes Stalwart to reconcile the domain’s zone with the current configuration, publishing any missing records and replacing any stale ones. The same variant is used internally when DKIM keys are rotated or when the set of managed records changes. See Scheduled tasks for how tasks are scheduled, triggered, and monitored.

 記錄由任務管理器保持最新狀態。 Task物件公開了一個`DnsManagement`變體，該變體針對特定的 Domain ，並可透過其`updateRecords`字段選擇性地將刷新範圍縮小到記錄類型的子集。觸發此變體的任務會導致 Stalwart 將網域的區域與當前配置進行協調，發布任何缺少的記錄並替換任何過時的記錄。當DKIM鍵輪換或受管記錄集發生變更時，內部也會使用相同的變體。有關任務的調度、觸發和監控方式，請參閱 Scheduled tasks 。

 For the list of supported providers and protocols, see Supported providers.

 有關支援的提供者和協議的列表，請參閱支援的提供者 。
