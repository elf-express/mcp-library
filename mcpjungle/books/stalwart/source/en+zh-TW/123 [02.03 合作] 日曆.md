# Calendar｜日曆

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[collaboration｜合作\\\]\\\(&lt;000 目錄.md#c-17&gt;\\\)

Stalwart includes full support for calendar management and scheduling through the JMAP and CalDAV protocols, covering creation, access, and synchronization of calendar data across devices and applications.

 Stalwart 全面支援透過JMAP和 CalDAV 協議進行日曆管理和日程安排，涵蓋跨裝置和應用程式的日曆資料的建立、存取和同步。

## JMAP for Calendars｜JMAP日曆

 JMAP for Calendars is a protocol that provides a JSON-based API for managing calendar data such as events, tasks, and scheduling information. It is designed as a replacement for CalDAV and CalDAV Scheduling, offering the same functionality \(creating, reading, updating, deleting, and sharing calendar data\) but in a simpler and more consistent way.

 JMAP日曆協議提供了一種基於JSON的API來管理日曆數據，例如事件、任務和日程安排資訊。它旨在取代 CalDAV 和 CalDAV Scheduling，以更簡單、更一致的方式提供相同的功能（創建、讀取、更新、刪除和共享日曆資料）。

 Unlike CalDAV, which is built on top of WebDAV and uses XML combined with embedded iCalendar data, JMAP for Calendars is entirely JSON over HTTPS. It uses the same core request/response model as JMAP for Mail, providing a unified protocol for all personal data types.

 與基於 WebDAV 並結合嵌入式 iCalendar 資料的 CalDAV 不同，日曆JMAP XML完全HTTPS JSON 。它使用與郵件協定JMAP相同的核心請求/回應模型，為所有個人資料類型提供統一的協定。

## CalDAV

 CalDAV is a standardized extension of WebDAV that allows clients to interact with calendar data stored on a server. It is supported by calendar applications on desktops and mobile devices, including Apple Calendar, Thunderbird, and Outlook \(with plugins\). CalDAV covers creating events, setting recurring appointments, inviting participants, and viewing shared calendars.

 CalDAV 是 WebDAV 的標準化擴展，它允許客戶端與儲存在伺服器上的日曆資料進行互動。桌面和行動裝置上的日曆應用程式都支援 CalDAV，包括 Apple Calendar、Thunderbird 和 Outlook（需外掛程式）。 CalDAV 的功能涵蓋建立事件、設定重複約會、邀請參與者以及查看共享日曆。

### Accessing calendars｜訪問日曆

 CalDAV clients can access calendar data on Stalwart using standardized URLs. The recommended method for client configuration is through the autodiscovery endpoint located at `/.well-known/caldav`. When a client queries this path, the server redirects the request to the appropriate CalDAV resource associated with the authenticated account. This simplifies setup by allowing most modern clients to automatically locate and configure calendar access without manual URL input.

 CalDAV 用戶端可以使用標準化 URL 存取 Stalwart 上的日曆資料。建議的客戶端設定方法是透過位於`/.well-known/caldav`自動發現端點。當用戶端查詢此路徑時，伺服器會將請求重新導向至與已驗證帳戶關聯的對應 CalDAV 資源。這簡化了設定過程，使大多數現代客戶端能夠自動查找和配置日曆存取權限，而無需手動輸入URL 。

 Alternatively, CalDAV calendars can be accessed directly via the path `/dav/cal/<account_name>`, where `<account_name>` is the username of the account. For example, the calendar for the account `alice` is available at `/dav/cal/alice`. This direct path can be used in clients that support manual CalDAV configuration or when troubleshooting.

 或者，也可以透過路徑`/dav/cal/<account_name>`直接存取 CalDAV 日曆，其中`<account_name>`是帳戶的使用者名稱。例如，帳戶`alice`的日曆位於`/dav/cal/alice` 。此直接路徑可用於支援手動 CalDAV 配置的用戶端或故障排除時。

 Both methods provide access to the same calendar data and are fully compatible with the CalDAV protocol.

 兩種方法均可存取相同的日曆數據，並且與 CalDAV 協定完全相容。

## Limits｜限制

 Calendar-wide limits are configured on the Calendar singleton \(found in the WebUI under Settings › Calendar & Contacts › Calendar\). They protect server resources against clients that attempt to create excessively large or complex calendar entries.

 日曆全域限制在 Calendar單例中設定（可在 WebUI 的「設定」&gt;「行事曆與聯絡人」&gt;「行事曆」中找到）。這些限制可以保護伺服器資源，防止客戶端建立過大或過度複雜的日曆項目。

### Recurrence expansion｜遞迴擴充

 The iCalendar format allows clients to define repeating events using RRULEs \(recurrence rules\). When such an event is created, Stalwart pre-expands the recurrence pattern into individual instances and stores them, avoiding expensive RRULE calculations on every calendar query.

 iCalendar 格式允許客戶端使用 RRULE（重複規則）定義重複事件。在建立此類事件時，Stalwart 會預先將重複模式展開為單一實例並儲存它們，從而避免每次日曆查詢時都進行昂貴的RRULE計算。

 Recurrence expansion is computationally intensive, especially for long-term or infinitely repeating events. The maxRecurrenceExpansions field on the Calendar singleton limits the number of instances generated from a recurrence rule. The default value is `3000`, sufficient for most realistic scheduling needs \(for example, daily events spanning several years\). If a recurrence rule would exceed this limit, the server rejects or truncates the event depending on context. Raising the value may significantly affect server performance.

 循環擴展計算量很大，尤其對於長期或無限重複的事件更是如此。日曆單例中的 maxRecurrenceExpansions欄位限制了循環規則產生的實例數量。預設值為`3000` ，足以滿足大多數實際的調度需求（例如，跨越數年的每日事件）。如果循環規則超出此限制，伺服器將根據上下文拒絕或截斷該事件。提高此值可能會顯著影響伺服器效能。

### iCalendar object size｜iCalendar 物件大小

 maxICalendarSize defines the maximum accepted size of a single iCalendar object \(VEVENT, VTODO, and so on\). The default is `"512kb"`. Lowering or raising the limit protects against unreasonably large calendar entries while accommodating deployment-specific client behaviour.

 maxICalendarSize定義了單一 iCalendar 物件的最大可接受大小（ VEVENT, VTODO以此類推）。預設值為`"512kb"` 。降低或提高此限制可以防止日曆條目過大，同時適應特定部署的用戶端行為。

### Attendee limit｜出席人數限制

 maxAttendees controls the maximum number of attendees allowed in a single iCalendar instance. The default is `20`. Deployments that regularly schedule large meetings may raise this value.

 maxAttendees控制單一 iCalendar 實例中允許的最大與會者人數。預設值為`20` 。經常安排大型會議的部署可以提高此值。

### JMAP parsing limit｜JMAP解析限制

 The JMAP `CalendarEvent/parse` method is bounded by parseLimitEvent on the Jmap singleton \(found in the WebUI under Settings › Network › JMAP › Limits, Settings › Network › JMAP › Push, Settings › Network › JMAP › WebSocket\), which sets the maximum number of iCalendar items that can be parsed in a single request. The default is `10`.

 JMAP `CalendarEvent/parse`方法受 parseLimitEvent的限制，此限制基於 Jmap單例（可在 WebUI 的「設定 › 網路 › JMAP › 網路設定 5」 5 73」 13 7 月 13333 月JMAP月› JMAP › WebSocket」中找到），它設定了單一請求中可以解析的 iCalendar 項的最大數量。預設值為`10` 。

## Default calendar｜預設日曆

 To improve client compatibility and allow calendar operations to proceed without manual setup, Stalwart automatically creates a default calendar when an account is accessed and no calendars currently exist for it. The URL path of the auto-created calendar is controlled by defaultHrefName on the Calendar singleton. The default value is `"default"`, so for an account named `john` the default calendar is created at `/dav/cal/john/default`. CalDAV clients then always see at least one calendar on first connection.

 為了提高客戶端相容性並允許日曆操作無需手動設定即可進行，Stalwart 會在存取帳戶且該帳戶目前不存在任何日曆時自動建立URL日曆。自動建立的日曆的路徑由 Calendar 單例中的 defaultHrefName控制。預設值為`"default"` ，因此對於名為`john`的帳戶，預設日曆會建立在`/dav/cal/john/default` 。這樣，CalDAV 用戶端在首次連線時始終至少可以看到一個日曆。

### Disabling automatic creation｜停用自動建立

 Automatic creation can be suppressed by clearing defaultHrefName \(leaving it unset\). In that case, Stalwart does not create a default calendar and clients that connect to an account with no calendars receive an appropriate error response.

 可以透過清除 defaultHrefName （將其設為未設定）來停用自動建立日曆。在這種情況下，Stalwart 不會建立預設日曆，連接到沒有日曆的帳戶的用戶端會收到相應的錯誤回應。

### Default display name｜預設顯示名稱

 The display name assigned to the auto-created calendar \(as shown in client applications\) is controlled by defaultDisplayName. The default is `"Stalwart Calendar"`; the value can be adjusted to match organisational branding or language preferences.

 自動建立的日曆的顯示名稱（如客戶端應用程式中顯示的名稱）由 defaultDisplayName控制。預設值為`"Stalwart Calendar"` ；該值可以調整以符合組織品牌或語言偏好。

## Per-account limits｜每個帳戶的限額

 The Calendar singleton also sets default caps on per-account calendar resources: maxCalendars caps the number of calendars an account can create \(default `250`\), maxEvents caps the number of events, maxParticipantIdentities caps participant identities \(default `100`\), and maxEventNotifications caps event notifications. These apply unless overridden at the account or tenant level.

 Calendar 單例也設定了每個帳戶行事曆資源的預設上限：maxCalendars 限制一個帳戶可以建立的日曆數量（預設值） `250`\), maxEvents 限制事件數量，maxParticipantIdentities 限制參與者身分（預設） `100`）， 和 maxEventNotifications 限制事件通知次數。除非在帳戶或租戶層級進行更改，否則這些設定將生效。
