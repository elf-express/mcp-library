# Troubleshooting｜故障排除

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-31&gt;\\\)

Stalwart provides a suite of tools to assist administrators in diagnosing and resolving issues related to email delivery, authentication, and compliance with security standards. These tools are integrated into the server’s interface, offering visibility into the email processing pipeline. Below are instructions for using these features.

 Stalwart 提供一套工具，幫助管理員診斷和解決與電子郵件發送、身份驗證和安全標準合規性相關的問題。這些工具整合到伺服器介面中，使用戶能夠了解電子郵件處理流程。以下是使用這些功能的說明。

## Email Delivery Issues｜電子郵件發送問題

 Stalwart includes a dedicated tool for testing email delivery to help administrators identify and resolve potential issues. This tool can be accessed through the Webadmin interface under **Manage -&gt; Troubleshoot -&gt; Email Delivery**. Administrators can use it to simulate the email delivery process without actually sending an email. To initiate the test, an email address or domain name must be provided.

 Stalwart 包含一個用於測試電子郵件傳送的專用工具，以幫助管理員識別和解決潛在問題。可透過 **管理 -&gt; 故障排除 -&gt; 電子郵件傳送**下的 Webadmin 介面存取此工具。管理員可以使用它來模擬電子郵件發送過程，而無需實際發送電子郵件。要啟動測試，必須提供電子郵件地址或網域。

 Once the test begins, the tool displays each step of the delivery process in real-time. It starts by resolving the MX records for the specified domain to identify its mail servers, then retrieves the corresponding IP addresses. It continues by validating the domain’s email security policies, such as MTA-STS and DANE, ensuring compliance and upgrading the connection to TLS for secure transmission. Finally, the tool verifies the recipient’s availability.

 測試開始後，工具會即時顯示郵件投遞流程的每個步驟。首先，它會解析指定網域名稱的MX記錄以識別其郵件伺服器，然後檢索對應的IP位址。接下來，它會驗證該網域的電子郵件安全策略，例如MTA-STS和DANE ，確保其符合相關規定，並將連線升級到TLS以進行安全傳輸。最後，該工具會驗證收件人是否在線上。

 Importantly, this testing tool does not send any email messages. Instead, it verifies the delivery path and the recipient, ensuring no unnecessary or intrusive actions are taken. If any issues arise during the simulation, they are reported on-screen with detailed error messages, allowing administrators to pinpoint the exact step where the process fails.

 重要的是，此測試工具不會發送任何電子郵件。它只會驗證郵件的投遞路徑和收件人，確保不會執行任何不必要或侵入性操作。如果在模擬過程中出現任何問題，螢幕上會顯示詳細的錯誤訊息，方便管理員精確定位流程失敗的特定步驟。

## DMARC

 To verify DMARC compliance, Stalwart provides a specialized tool accessible in the Webadmin interface under **Manage -&gt; Troubleshoot -&gt; DMARC**. This tool allows administrators to assess DMARC settings for both local and remote domains by simulating the server’s message authentication process.

 為了驗證DMARC合規性，Stalwart 提供了一個專用工具，可透過 Webadmin介面中的 **管理 -&gt; 故障排除 -&gt; DMARC** 存取。該工具允許管理員透過模擬伺服器的訊息驗證過程來評估本地和遠端網域的DMARC設定。

 Using the tool requires specific inputs, including the mail from sender address, server IP address, EHLO hostname, and optionally, the message body. The mail from sender address is the email address used during the SMTP “MAIL FROM”（來自） command. The server IP address refers to the server that will send the email. The EHLO hostname is the domain name sent in the EHLO/HELO command to identify the sending server. The message body, while optional, is necessary for verifying DKIM and ARC signatures, but it can be omitted if only SPF compliance is being checked.

 使用此工具需要輸入特定訊息，包括寄件者地址、伺服器位址IP ）、主機名稱EHLO以及可選的郵件正文。寄件者地址是執行SMTP “MAIL FROM”（來自）指令時所使用的電子郵件地址。伺服器位址IP指的是將要傳送電子郵件的伺服器。主機名稱EHLO是執行EHLO/HELO指令時發送的域名，用於標識發送伺服器。郵件正文雖然是可選的，但對於驗證DKIM和ARC簽名是必需的，但如果僅檢查SPF合規性，則可以省略。

 The tool performs checks for SPF, DKIM, ARC, and DMARC compliance. It also verifies that the reverse IP PTR record matches the SPF EHLO hostname. By running the same checks Stalwart performs when receiving a message, this tool analyzes the domain’s email authentication setup and identifies potential issues.

 該工具會檢查是否符合SPF, DKIM, ARC和DMARC規範。它還會驗證反向IP PTR記錄是否與SPF EHLO主機名稱相符。透過執行與Stalwart接收郵件時相同的檢查，該工具可以分析網域的電子郵件身份驗證設定並識別潛在問題。

## Authentication Issues｜身份驗證問題

 For authentication problems, administrators should begin by examining the server logs, where any authentication failures or warnings will be recorded. These logs are located in the system’s designated logging directory for the Stalwart. The logs typically include error messages with specific details about the failed authentication attempts.

 對於身份驗證問題，管理員應先檢查伺服器日誌（ \([https://stalw.art/docs/telemetry/tracing/log](https://stalw.art/docs/telemetry/tracing/log)\) ），其中會記錄所有身份驗證失敗或警告訊息。這些日誌位於 Stalwart 系統指定的日誌目錄中。日誌通常包含錯誤訊息，其中詳細說明了身份驗證失敗的嘗試。

 If the information in the logs is insufficient to diagnose the issue, administrators can increase the log verbosity by setting the log level to `trace`. This detailed logging level provides a granular view of the authentication process, capturing all actions and interactions during the login attempt. With these enhanced logs, administrators can identify configuration errors or issues with credentials, protocols, or communication between the client and server.

 如果日誌中的資訊不足以診斷問題，管理員可以透過將日誌等級設定為`trace`來提高日誌詳細程度。此詳細日誌等級可提供身份驗證過程的精細視圖，擷取登入嘗試期間的所有操作和互動。借助這些增強的日誌，管理員可以識別配置錯誤或憑證、協定或客戶端與伺服器之間通訊方面的問題。
