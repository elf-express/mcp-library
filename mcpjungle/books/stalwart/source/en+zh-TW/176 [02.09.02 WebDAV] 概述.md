# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[http\\\]\\\(&lt;000 目錄.md#c-26&gt;\\\) › \\\[webdav｜WebDAV\\\]\\\(&lt;000 目錄.md#c-28&gt;\\\)

WebDAV \(Web Distributed Authoring and Versioning\) is an extension of the HTTP protocol that allows clients to manage and edit files stored on a remote server. Built on standard web technologies, it exposes files and directories on the server through HTTP verbs for creation, modification, and deletion, so that remote storage can be treated as an extension of the local file system.

 WebDAV（Web分散式創作和版本控制）是HTTP協定的擴展，它允許客戶端管理和編輯儲存在遠端伺服器上的檔案。它基於標準Web技術構建，透過HTTP動詞公開伺服器上的檔案和目錄，用於創建、修改和刪除，從而使遠端儲存可以被視為本地檔案系統的擴展。

 Stalwart includes full support for WebDAV, along with the two related protocols CalDAV and CardDAV. CalDAV covers calendar data, including events and scheduling information; CardDAV covers contact data, keeping address books synchronised across clients. Together these protocols form the basis of Stalwart’s collaboration features and provide broad interoperability with existing client applications.

 Stalwart 完全支援 WebDAV，以及與之相關的 CalDAV 和 CardDAV 協定。 CalDAV 涵蓋日曆數據，包括事件和日程安排資訊；CardDAV 涵蓋聯絡人數據，確保通訊錄在不同客戶端之間同步。這些協定共同構成了 Stalwart 協作功能的基礎，並與現有客戶端應用程式實現了廣泛的互通性。

## Enabling WebDAV｜啟用 WebDAV

 Accepting WebDAV connections requires an HTTP listener defined on the NetworkListener object \(found in the WebUI under Settings › Network › Listeners\) with the protocol set to `http`. In most installations this listener is created automatically during setup, so no further action is required.

 接受 WebDAV 連線需要在 \[NetworkListener\] 物件（可在 WebUI 的「設定」&gt;「網路」&gt;「監聽器」中找到）上定義一個 \[ \(\[[https://stalw.art/docs/ref/object/network-listener\\\)器\\\\\\]HTTP\\]\(https://stalw.art/docs/ref/object/network-listener%29%25E5%2599%25A8%255DHTTP\)](https://stalw.art/docs/ref/object/network-listener%255C%29%25E5%2599%25A8%255C%255C%255DHTTP%255D%28https://stalw.art/docs/ref/object/network-listener%2529%2525E5%252599%2525A8%25255DHTTP%29) \([https://stalw.art/docs/server/listener\)並將](https://stalw.art/docs/server/listener%2529%2525E4%2525B8%2525A6%2525E5%2525B0%252587) protocol `http` 。在大多數安裝過程中，此監聽器會在設定期間自動創建，因此無需執行任何其他操作。

## Accessing WebDAV｜存取 WebDAV

 Stalwart organises its WebDAV resources under a structured path hierarchy so that calendars, contacts, files, and user principals can be located quickly. Each resource type is served under a distinct URL prefix.

 Stalwart 將其 WebDAV 資源組織成結構化的路徑層次結構，以便快速找到日曆、聯絡人、文件和使用者主體。每種資源類型都使用不同的URL前綴提供服務。

 Calendar data managed via CalDAV is available under the `/dav/cal` path. For example, a user named `john` would have their calendar data accessible at `/dav/cal/john`. Contact data managed through CardDAV is located under `/dav/card`, so the address book for user `john` would reside at `/dav/card/john`.

 透過 CalDAV 管理的日曆資料位於`/dav/cal`路徑下。例如，名為`john`的用戶可以透過`/dav/cal/john`存取其日曆資料。透過 CardDAV 管理的聯絡人資料位於`/dav/card`路徑下，因此使用者`john`的通訊錄位於`/dav/card/john`路徑下。

 The general-purpose WebDAV file system is available under `/dav/file`. This path serves as the root directory for users’ personal file storage; for instance, the file storage area for user `jane` is reachable at `/dav/file/jane`, where she can upload, organise, and retrieve documents through any standard WebDAV client.

 通用 WebDAV 檔案系統位於`/dav/file`下。此路徑用作使用者個人文件儲存的根目錄；例如，使用者`jane`的文件儲存區域位於`/dav/file/jane` ，她可以透過任何標準 WebDAV 用戶端上傳、整理和檢索文件。

 Stalwart also supports the WebDAV ACL \(Access Control List\) extensions, and user principals are exposed via `/dav/pal`. Principal resources define and manage access rights across the WebDAV services and are typically consulted by clients to retrieve information about user identities and permissions.

 Stalwart 也支援 WebDAV ACL （存取控制清單）擴展，使用者主體透過`/dav/pal`公開。主體資源定義和管理跨 WebDAV 服務的存取權限，用戶端通常會查詢這些資源以擷取有關使用者身分和權限的資訊。

 For client setup, Stalwart provides autodiscovery endpoints at `/.well-known/caldav` and `/.well-known/carddav`. When queried, they redirect to the appropriate resource location for the authenticated user.

 對於客戶端設置，Stalwart 在`/.well-known/caldav`和`/.well-known/carddav`提供自動發現端點。當進行查詢時，它們會將使用者重新導向到已驗證使用者的對應資源位置。

## Disabling WebDAV｜停用 WebDAV

 By default, WebDAV access is available as soon as an HTTP listener is configured, exposing calendar synchronisation \(CalDAV\), contact management \(CardDAV\), and file storage. Some deployments may need to restrict or disable this entirely for security, compliance, or policy reasons.

 預設情況下，一旦配置了HTTP監聽器，即可使用WebDAV訪問，從而實現日曆同步（CalDAV）、聯絡人管理（CardDAV）和檔案儲存。出於安全、合規性或策略方面的考慮，某些部署可能需要限製或完全停用此功能。

 The most direct way to disable WebDAV access server-wide is to add an HTTP access control rule that blocks any path under `/dav`. This denies access to every WebDAV endpoint, including `/dav/cal`, `/dav/card`, `/dav/file`, and `/dav/pal`, regardless of per-user settings.

 停用伺服器範圍內的 WebDAV 存取的最直接方法是新增一條 HTTP存取控制規則 ，阻止`/dav`下的任何路徑。這將拒絕存取所有 WebDAV 端點，包括`/dav/cal`, `/dav/card`, `/dav/file`和`/dav/pal` ，而不管每個使用者的設定如何。

 For finer control, WebDAV access can be restricted on a per-user, per-group, or per-tenant basis by removing the relevant WebDAV permissions from the account or entity. Revoking the CalDAV, CardDAV, and general WebDAV permissions ensures that only authorised principals can use those services.

 為了更精細地控制，可以透過從帳戶或實體移除相關的 WebDAV 權限按使用者、群組或租用戶限制 WebDAV 存取權限。撤銷 CalDAV、CardDAV 和常規 WebDAV 權限可確保只有授權主體才能使用這些服務。
