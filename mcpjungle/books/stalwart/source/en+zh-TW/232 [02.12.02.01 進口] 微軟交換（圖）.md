# Microsoft Exchange \(Graph\)｜微軟交換（圖）

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[import export｜進出口\\\]\\\(&lt;000 目錄.md#c-40&gt;\\\) › \\\[import｜進口\\\]\\\(&lt;000 目錄.md#c-41&gt;\\\)

The Microsoft Exchange importers are experimental. The flag surface and behaviour may change between releases, and migrations of large or unusual mailboxes should be validated against a test target before committing to them.

 Microsoft Exchange 導入程式是實驗性的。標誌表面和行為可能會在版本之間發生變化，並且大型或不尋常郵箱的遷移應在提交之前針對測試目標進行驗證。

 The Graph importer reads an Exchange Online mailbox into a local archive over the Microsoft Graph v1.0 REST API. It is the preferred path for Exchange Online, because Graph is the interface Microsoft actively develops and because it exposes immutable item identifiers that keep reconciliation stable even when the mailbox owner moves messages between folders between runs. A single invocation produces mail, calendars and contacts: folders and items are enumerated through the Graph collection endpoints, message bodies are fetched as raw MIME, and calendar and contact resources are converted into JSCalendar and JSContact. On-premises Exchange Server, which does not offer Graph, is served by the EWS importer instead.

 Graph 匯入器透過 Microsoft Graph v1.0 REST API 將 Exchange Online 信箱讀取到本機檔案。它是 Exchange Online 的首選路徑，因為 Graph 是 Microsoft 積極開發的介面，並且它公開了不可變的項目標識符，即使郵箱所有者在運行期間在資料夾之間移動郵件，這些標識符也能保持協調穩定。一次呼叫即可產生郵件、日曆和聯絡人：透過 Graph 集合端點枚舉資料夾和項目，以原始 MIME 形式取得訊息正文，並將日曆和聯絡人資源轉換為 JSCalendar 和 JSContact。本機 Exchange Server 不提供 Graph，而是由 EWS 匯入程式 提供服務。

## Immutable identifiers｜不可變的標識符

 Outlook assigns item ids that change when an item moves between folders or mailboxes, which would make a naive importer record every moved message as one deletion plus one new arrival on each run. Vandelay avoids this by requesting immutable ids on every Graph call, so an item keeps the same reconciliation key for the life of the mailbox. This is what makes repeated runs converge cleanly: a re-run after an interruption fetches only the items still missing, and a re-run against a changed mailbox pulls only the delta.

 Outlook 指派的項目 ID 會在專案在資料夾或郵件匣之間移動時發生變化，這會使天真的匯入者在每次執行時將每個移動的郵件記錄為一次刪除和一次新到達。 Vandelay 透過在每個 Graph 呼叫上要求不可變的 id 來避免這種情況，因此專案在郵箱的生命週期內保持相同的協調金鑰。這就是使重複運行完全收斂的原因：中斷後重新運行僅獲取仍然丟失的項目，而針對已更改的郵箱重新運行僅提取增量。

## Authentication｜驗證

 Access to Graph is always through a Microsoft Entra OAuth token, obtained in one of two ways. A pre-acquired token can be supplied with `--access-token`, read inline, from the `VANDELAY_GRAPH_TOKEN` environment variable, or from an interactive prompt; this suits environments that already mint tokens through their own tooling. Otherwise Vandelay runs the interactive device-code flow, which requires the Entra application id in `--client-id` and accepts `--tenant` \(the authority tenant id or short name, defaulting to the multi-tenant `common` authority\). The device-code flow prints a verification URL and code to complete in a browser, after which Vandelay holds the resulting token for the duration of the run.

 對 Graph 的存取始終透過 Microsoft Entra OAuth 令牌進行，可以透過以下兩種方式之一取得。預先取得的令牌可以透過 `--access-token` 提供，從 `VANDELAY_GRAPH_TOKEN` 環境變數或互動式提示中內聯讀取；這適合已經透過自己的工具鑄造代幣的環境。否則，Vandelay 運行互動式裝置程式碼流程，該流程需要`--client-id` 中的 Entra 應用程式 ID 並接受`--tenant`（權限租用戶 ID 或短名稱，預設為多租用戶`common` 權限）。設備程式碼流程會列印驗證URL以及要在瀏覽器中完成的程式碼，之後 Vandelay 在運行期間保留生成的令牌。

## Mailbox selection｜信箱選擇

 By default the importer reads the mailbox of the signed-in identity. A different mailbox that the signed-in account is permitted to read can be targeted with `--user`, naming it by user principal name or object id. The `--mailbox-kind` flag chooses the surface: the default `primary` reads the main mailbox and `archive` reads the In-Place Archive. The public-folders surface is not available over Graph; a request for it is rejected at parse time with a pointer to the EWS importer, which does support public folders.

 預設情況下，導入器會讀取登入身分的郵箱。允許登入帳戶讀取的不同郵箱可以使用 `--user` 進行定位，並透過使用者主體名稱或物件 ID 對其進行命名。 `--mailbox-kind`標誌選擇表面：預設`primary`讀取主信箱，`archive`讀取就地存檔。公共資料夾表面不可透過 Graph 使用；對它的請求在解析時被拒絕，並帶有指向EWS導入器的指針，該導入器確實支援公共資料夾。

## Surface selection｜表面選擇

 The data imported can be narrowed with `--objects`, a comma-separated list drawn from `mail`, `calendar` and `contacts`; the default imports all three. The names are case-insensitive, surrounding whitespace is ignored, and repeating a name has no further effect.

 匯入的資料可以透過`--objects`縮小，這是一個從`mail`, `calendar`和`contacts`提取的逗號分隔清單；預設匯入所有三個。名稱不區分大小寫，周圍的空格將被忽略，重複名稱不會產生進一步的影響。

 These three names are surfaces, not JMAP type names: `mail` covers mail folders and the messages in them, `calendar` covers calendars and their events, and `contacts` covers address books and their cards. A surface is always imported whole, so a single type inside one \(events without their calendars, say\) cannot be selected on its own, and JMAP type names such as `contactcard` or `mailbox` are rejected. Any name outside the three is refused with a usage error that lists the valid ones.

 這三個名稱是表面名稱，而不是 JMAP 類型名稱：`mail` 涵蓋郵件資料夾及其中的消息，`calendar` 涵蓋日曆及其事件，`contacts` 涵蓋地址簿及其卡片。表面始終是整個導入的，因此表面中的單一類型（例如沒有日曆的事件）無法單獨選擇，並且 JMAP 類型名稱（例如 `contactcard` 或 `mailbox`）會被拒絕。這三個名稱之外的任何名稱都會被拒絕，並出現列出有效名稱的使用錯誤。

 With `--mailbox-kind archive` only `mail` is imported: the In-Place Archive holds no calendars or contacts, so those two surfaces are skipped for that run whatever `--objects` asks for.

 對於`--mailbox-kind archive`，僅匯入`mail`：就地存檔不包含日曆或聯絡人，因此無論`--objects`要求什麼，運行時都會跳過這兩個表面。

 The body representation requested for calendar events is controlled by `--event-body-format`, which accepts `text` \(the default\) or `html`.

 日曆事件請求的正文表示由`--event-body-format`控制，它接受`text`（預設）或`html`。

## Throughput tuning｜吞吐量調整

 Items are read over several parallel connections set by `--graph-connections`, defaulting to four with a hard ceiling of sixteen, capped by the worker pool size. The page size of each collection request is set by `--top`, defaulting to one hundred and accepting any value from one to one thousand. Larger pages reduce the number of round trips, while smaller pages can ease pressure against a heavily throttled tenant.

 項目透過 `--graph-connections` 設定的多個平行連接讀取，預設為 4 個，硬性上限為 16 個，受工作池大小限制。每個採集請求的頁面大小由`--top`設置，預設為100，接受1到1000之間的任意值。較大的頁面可以減少往返次數，而較小的頁面可以減輕對嚴重限制的租戶的壓力。

## Source-change protection｜來源更改保護

 The archive records the Graph source and mailbox surface it was first filled from, and a later run against a different one is refused unless `--allow-source-change` is supplied.

 檔案記錄了第一次填充的圖形來源和郵箱表面，並且稍後針對不同的運行將被拒絕，除非提供 `--allow-source-change`。

## Examples｜範例

 Importing an Exchange Online mailbox interactively with the device-code flow:

 與裝置代碼流互動導入 Exchange Online 信箱：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import exchange-graph \
  --client-id 11111111-2222-3333-4444-555555555555 \
  --tenant contoso.onmicrosoft.com \
  alice.sqlite
```

Importing with a token already acquired by external tooling, restricted to mail and calendar data:

 使用外部工具已取得的令牌進行匯入，僅限於郵件和日曆資料：

```bash title=&amp;quot;Terminal window&amp;quot;
export VANDELAY_GRAPH_TOKEN='entra-access-token'
vandelay import exchange-graph \
  --access-token \
  --objects mail,calendar \
  alice.sqlite
```

Reading the In-Place Archive of a delegated mailbox the signed-in administrator can access:

 讀取登入管理員可以存取的委派郵箱的就地存檔：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import exchange-graph \
  --client-id 11111111-2222-3333-4444-555555555555 \
  --tenant contoso.onmicrosoft.com \
  --user [email protected] \
  --mailbox-kind archive \
  alice.sqlite
```

Each run may be repeated to resume or to capture changes since the previous snapshot, and `--dry-run` reports the full plan without writing.

 每次運行都可以重複以恢復或捕獲自上一個快照以來的更改，並且 `--dry-run` 無需寫入即可報告完整計劃。
