# WebDAV

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[collaboration｜合作\\\]\\\(&lt;000 目錄.md#c-17&gt;\\\)

WebDAV \(Web Distributed Authoring and Versioning\) extends the HTTP protocol with operations for remote content management: creating, editing, and deleting files, as well as accessing and synchronising calendars and contacts. WebDAV is widely used in collaborative environments for file sharing, calendar coordination, and contact management.

 WebDAV（Web分散式創作和版本控制）擴展了HTTP協議，增加了遠端內容管理功能，包括建立、編輯和刪除文件，以及存取和同步行事曆和聯絡人。 WebDAV廣泛應用於協作環境中，用於文件共用、行事曆協調和聯絡人管理。

 This page covers WebDAV storage-related settings, such as limits on property length and lock behaviour. All such settings are carried on the WebDav singleton \(found in the WebUI under Settings › Network › WebDAV\). For WebDAV protocol behaviour, including access controls and path routing, see the WebDAV protocol documentation.

 本頁面涵蓋與 WebDAV 儲存相關的設置，例如屬性長度限制和鎖定行為。所有此類設定都保存在 WebDav單例中（可在 WebUI 的「設定」&gt;「網路」&gt;「WebDAV」中找到）。有關 WebDAV 協定行為，包括存取控制和路徑路由，請參閱 WebDAV 協定文件 。

## WebDAV properties｜WebDAV屬性

 WebDAV allows clients to store, retrieve, and manipulate metadata about resources using WebDAV properties. These properties are pieces of information associated with a file, calendar entry, contact, or other resource, accessed through methods such as `PROPFIND` and `PROPPATCH`.

 WebDAV 允許客戶端使用 WebDAV 屬性儲存、檢索和操作有關資源的元資料。這些屬性是與文件、日曆條目、聯絡人或其他資源相關的資訊片段，可透過諸如`PROPFIND`和`PROPPATCH`之類的方法存取。

 WebDAV properties fall into two categories, dead properties and live properties:

 WebDAV 屬性分為兩類：失效屬性與有效屬性：

- **Dead properties** are arbitrary name-value pairs set and maintained by the client. The server stores them without interpreting or enforcing any semantics. For example, a client might add a dead property such as `displayColor` or `clientTag`; the server stores and returns the data as-is. Dead properties are useful for custom metadata, user preferences, and other auxiliary information that does not require server-side processing.
**死屬性**是指客戶端設定和維護的任意名稱-值對。伺服器儲存這些屬性，但不解釋或強制執行任何語義。例如，客戶端可以添加諸如`displayColor`或`clientTag`之類的死屬性；伺服器會按原樣儲存並傳回資料。死屬性適用於自訂元資料、使用者偏好設定以及其他不需要伺服器端處理的輔助資訊。

- **Live properties** are understood and actively managed by the server. They typically represent dynamic or system-managed values such as `getlastmodified`, `resourcetype`, `quota-available-bytes`, or calendar-specific fields defined by the CalDAV or CardDAV standards. The server generates, updates, or restricts modifications to these properties automatically in response to changes in the resource or system state.
**即時屬性**由伺服器識別並主動管理。它們通常表示動態值或系統管理的值，例如`getlastmodified`, `resourcetype`, `quota-available-bytes` ，或由 CalDAV 或 CardDAV 標準定義的日曆特定欄位。伺服器會根據資源或系統狀態的變化自動產生、更新或限制這些屬性的修改。
The difference lies in server awareness: live properties have defined meaning and behaviour enforced by the server; dead properties are stored and returned without interpretation.

 區別在於伺服器感知：活動屬性具有由伺服器強制執行的已定義含義和行為；死屬性被儲存和返回，而不進行任何解釋。

 The maximum size of dead properties is controlled by deadPropertyMaxSize; the default is `1024` bytes per property. The maximum size of live properties is controlled by livePropertyMaxSize; the default is `250` bytes per property. Both limits apply to the total size of each individual property value and can be adjusted to accommodate larger or smaller metadata as required.

 已失效屬性的最大大小由 deadPropertyMaxSize控制；預設值為每個屬性`1024`位元組。有效屬性的最大大小由 livePropertyMaxSize控制；預設值為每個屬性`250`位元組。這兩個限制均適用於每個屬性值的總大小，並且可以根據需要進行調整以適應更大或更小的元資料。

## WebDAV locks｜WebDAV鎖定

 WebDAV includes a locking mechanism that guards against conflicting changes when multiple clients access the same resource concurrently. Locks are particularly important in collaborative environments where shared files or calendar entries may be written by more than one client at once.

 WebDAV 包含一種鎖定機制，可防止多個用戶端同時存取相同資源時發生衝突性變更。在協作環境中，共用檔案或行事曆項目可能同時被多個客戶端寫入，因此鎖定機制尤其重要。

 A WebDAV lock claims temporary exclusive or shared access to a resource. While a lock is held, the operations other clients can perform on the resource are restricted depending on the lock type. Two lock types are defined:

 WebDAV 鎖定聲明對資源的暫時獨佔或共用存取權限。持有鎖期間，其他用戶端對資源執行的操作將受到限制，具體限制取決於鎖的類型。 WebDAV 定義了兩種鎖定類型：

- **Exclusive locks** prevent any other client from modifying the locked resource. Only the lock holder can make changes for the duration of the lock.
**獨佔鎖** 可防止任何其他用戶端修改被鎖定的資源。只有鎖持有者才能在鎖定期間進行更改。
- **Shared locks** allow multiple clients to read and potentially modify a resource concurrently, provided each holds a shared lock and respects the others’ operations.
**共享鎖**允許多個客戶端同時讀取並可能修改資源，前提是每個客戶端都持有共享鎖並尊重其他客戶端的操作。
Locks are typically associated with a lock token, which the client must include in subsequent requests to confirm ownership. Locks may also have an expiration time, after which they are automatically released if not refreshed. Clients use the `LOCK` and `UNLOCK` HTTP methods to acquire and release locks.

 鎖通常與一個鎖定令牌（ \([https://stalw.art/docs/development/urn#resource-types](https://stalw.art/docs/development/urn#resource-types)\) ）關聯，客戶端必須在後續請求中包含該令牌以確認所有權。鎖定也可能有過期時間，過期後若未刷新則會自動釋放。客戶端使用`LOCK`和`UNLOCK` HTTP方法來取得和釋放鎖。

 Two fields bound locking behaviour:

 鎖定行為受兩個欄位約束：

- maxLockTimeout defines the maximum duration a WebDAV lock can remain active. The default is `"1h"`. If a client requests a longer timeout, the server caps it at this value. A reasonable timeout prevents stale locks from blocking shared resources indefinitely.
maxLockTimeout定義了 WebDAV 鎖保持活動狀態的最大持續時間。預設值為`"1h"` 。如果用戶端要求更長的逾時時間，伺服器會將其限制為該值。合理的超時時間可以防止過期的鎖無限期地阻塞共享資源。
- maxLocks limits the total number of active WebDAV locks a single account can hold at once. The default is `10`. The limit guards against clients accumulating excessive locks, whether inadvertently or maliciously.
maxLocks限制單一帳戶同時可持有的活動 WebDAV 鎖的總數。預設值為`10` 。此限制可防止客戶端無意或惡意地累積過多的鎖。
## Request and result limits｜請求和結果限制

 Two further fields bound the scale of a single WebDAV operation. requestMaxSize sets the maximum XML body size the server will accept for a WebDAV request; the default is `"25mb"`. maxResults caps the number of results returned by a WebDAV query; the default is `2000`.

 還有兩個欄位限制了單一 WebDAV 操作的規模。 requestMaxSize設定伺服器可接受的 WebDAV 請求的最大XML大小；預設值為`"25mb"` 。 maxResults限制 WebDAV 查詢傳回的結果數量；預設值為`2000` 。
