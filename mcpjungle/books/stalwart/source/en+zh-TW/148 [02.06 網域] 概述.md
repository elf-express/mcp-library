# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[domains｜網域\\\]\\\(&lt;000 目錄.md#c-21&gt;\\\)

A **Domain** represents a local mail domain that the server recognises as its own. Without a matching Domain object, the server treats messages addressed to that domain as external and refuses delivery for them. The Domain is therefore the anchor for every downstream decision that depends on domain ownership: local-recipient resolution, DKIM signing, TLS certificate issuance, and the publication of DNS policy records.

**網域** 代表伺服器識別為自身所屬的本機郵件網域。如果沒有符合的網域對象，伺服器會將傳送到該網域的郵件視為外部郵件並拒絕投遞。因此，網域是所有依賴網域所有權的下游決策的錨點，包括：本地收件者解析、 DKIM簽章、 TLS憑證頒發以及DNS策略記錄的發布。

 Domains are configured through the Domain object \(found in the WebUI under Management › Domains › Domains\). Each record identifies a primary name and carries the settings that govern how the server handles mail and infrastructure for that name.

 域的配置是透過 Domain物件實現的（可在 WebUI 的「管理」&gt;「域」&gt;「域」下找到）。每筆記錄標識一個主名稱，並包含伺服器如何處理該名稱的郵件和基礎架構的設定。

## Identity and aliases｜身分和別名

 The primary identifier is name, the canonical domain name. Additional names that should be treated as equivalent to the primary name are listed in aliases; these are recognised as local for the purpose of accepting incoming mail and do not require a separate Domain object. Administrators group alias names under the primary record rather than duplicating configuration across multiple Domains, which keeps DKIM, DNS, and TLS settings in a single place.

 主標識符為 name ，即規範網域名稱。其他應視為與主網域等效的名稱列於 aliases中；這些名稱被視為本地名稱，用於接收傳入郵件，無需單獨的域物件。管理員將別名分組到主記錄下，而不是在多個網域中重複配置，這樣可以將DKIM, DNS和TLS設定集中在一個位置。

 A domain can be disabled without deletion by clearing isEnabled; disabled domains are retained in the database but are no longer accepted as local. The description field carries an operator-facing note, and logo holds a branding image used by the WebUI when a user signs in under the domain. In multi-tenant deployments, memberTenantId assigns ownership to a Tenant, and directoryId points to the Directory in which accounts for the domain are looked up. Leaving the directory unset falls back to the internal directory.

 可以透過清除 isEnabled來停用域，而無需刪除該域；停用的域仍保留在資料庫中，但不再被視為本地域。 description欄位包含面向操作員的註釋，logo欄位包含使用者使用該網域登入時 WebUI 使用的品牌圖片。在多租用戶部署中，memberTenantId將所有權分配給 租用戶 ，directoryId指向用於尋找網域帳戶的 目錄 。如果未設定目錄，則會回退到內部目錄。

## Mail handling｜郵件處理

 Recipient resolution for the domain is shaped by three fields. catchAllAddress names a fallback mailbox that receives messages addressed to unknown local recipients; leaving it unset causes unknown recipients to be rejected at SMTP time. subAddressing controls plus-addressing behaviour: the `Enabled` variant accepts `user+tag@domain` and delivers to `user@domain`, the `Disabled` variant turns the feature off, and the `Custom` variant runs an expression against the recipient to decide how the local part is canonicalised. allowRelaying opts the domain into relaying for recipients that are not local, which is required in split-delivery or smart-host setups and should remain disabled otherwise.

 網域的收件者解析由三個欄位決定。 catchAllAddress 指定一個備用郵箱，用於接收發送至未知本機收件者的郵件；如果未設定此項，則未知收件者的郵件將被拒絕。 SMTP 時間。 subAddressing 控制加尋址行為： `Enabled` 變體接受 `user+tag@domain` 並交付至 `user@domain`， 這 `Disabled` 變體將關閉該功能，並且 `Custom` variant 會針對接收者執行表達式，以確定如何規範化本機部分。`allowRelaying`\]\([https://stalw.art/docs/ref/object/domain#allowrelaying](https://stalw.art/docs/ref/object/domain#allowrelaying)\) 選擇將網域轉送至非本機收件人，這在分割投遞或智慧主機設定中是必需的，否則應保持停用狀態。

 The reportAddressUri field sets the mailbox that receives DMARC aggregate, TLS-RPT, and CAA incident reports generated for the domain. The default is `mailto:postmaster`; setting the field to null suppresses report generation for the domain.

 reportAddressUri欄位用於設定接收為該域產生的DMARC聚合報告、 TLS-RPT和CAA事件報告的郵箱。預設值為`mailto:postmaster` ；將該欄位設為空將禁止為該網域產生報表。

## Account provisioning｜帳戶配置

 allowScimProvisioning opens the domain to an external identity provider that provisions accounts over SCIM, and is disabled by default. Enabling it does two things at once: SCIM clients gain permission to create, update, suspend, and delete accounts in the domain, and just-in-time directory synchronisation stops writing to those accounts, so the identity provider becomes the single authority for them. A user who authenticates before being provisioned is refused rather than having an account created for them.

 allowScimProvisioning將網域開放給外部身分提供者，該提供者透過 SCIM配置帳戶，預設為停用。啟用此功能會同時執行兩個動作： SCIM用戶端取得在網域中建立、更新、暫停和刪除帳戶的權限，並且即時目錄同步停止寫入這些帳戶，因此身分提供者成為這些帳戶的唯一權威。在帳戶配置完成之前進行身份驗證的使用者將被拒絕，而不是被建立帳戶。

 The field is per domain, so a server can keep some domains on just-in-time provisioning while others are driven by SCIM. Provisioning models covers the trade in full.

 此欄位按網域劃分，因此伺服器可以對某些網域保持即時配置，而對其他網域則由SCIM驅動。 配置模型完全涵蓋了這種交易。

## Linked infrastructure｜互聯基礎設施

 Three fields on the Domain link it to the objects that manage its externally visible infrastructure:

 域上的三個欄位將其與管理其外部可見基礎架構的物件關聯起來：

- dnsManagement selects manual or automatic DNS record publication. The `Automatic` variant references a DnsServer through dnsServerId and controls which record types the server keeps in sync. See DNS records for the record management workflow.
dnsManagement 選擇手動或自動DNS 記錄發布。 `Automatic` 變體透過 dnsServerId 引用 DnsServer 並控制伺服器保持同步的記錄類型。有關記錄管理工作流程，請參閱DNS記錄。
- certificateManagement selects manual or ACME-driven TLS management. The `Automatic` variant references an AcmeProvider through acmeProviderId; the `Manual` variant relies on Certificate objects supplied by the operator. See TLS certificates for the details.
certificateManagement選擇手動或ACME驅動TLS管理。 `Automatic` 變體透過 acmeProviderId 引用 AcmeProvider; `Manual` 變體依賴於營運商提供的 Certificate 物件。詳情請參閱TLS證書。
- dkimManagement selects manual or automatic DKIM key generation and rotation. The `Automatic` variant drives the creation, publication, and retirement of DkimSignature records for the domain. See DKIM key rotation for the rotation lifecycle.
dkimManagement 選擇手動或自動DKIM 金鑰產生和輪換。 `Automatic` 變體驅動域的 DkimSignature 記錄的建立、發布和停用。請參閱DKIM金鑰輪換了解輪換生命週期。
The read-only dnsZoneFile field exposes the current set of DNS records the server expects to be published for the domain. When DNS management is manual, administrators copy this zone data into the external DNS provider; when DNS management is automatic, the server reconciles the same records against the configured DnsServer.
 只讀欄位 dnsZoneFile公開了伺服器預期為該網域發布的目前DNS記錄集。當DNS管理為手動時，管理員會將此區域資料複製到外部DNS提供者；當DNS管理為自動時，伺服器會將相同的記錄與配置的 DnsServer進行核對。
