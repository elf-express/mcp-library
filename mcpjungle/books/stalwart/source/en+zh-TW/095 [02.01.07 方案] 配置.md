# Configuration｜配置

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[scim｜方案\\\]\\\(&lt;000 目錄.md#c-10&gt;\\\)

Enabling SCIM involves granting authority to the identity provider over a set of domains, creating the account that its SCIM client will authenticate as, and issuing that account a credential. Each step is described below, followed by a verification procedure that confirms the endpoint is reachable before the identity provider is configured.

 啟用SCIM涉及授予身分提供者對一組網域的權限，創建其SCIM客戶端將用於身份驗證的帳戶，並向該帳戶頒發憑證。以下將詳細介紹每個步驟，並在配置身分提供者之前，提供一個驗證程序來確認端點是否可達。

## Prerequisites｜先決條件

 SCIM requires an Enterprise license. On a Community Edition server the `/scim/v2` routes respond with `403 Forbidden` and an explanatory message; no other behaviour changes.

 SCIM需要 企業版授權 。在社群版伺服器上， `/scim/v2`路由會回應`403 Forbidden`和一則解釋性訊息；其他行為不會改變。

 The HTTP service must be reachable by the identity provider over TLS. Hosted identity providers such as Microsoft Entra ID and Okta connect from the public internet and cannot reach an endpoint published only on a private network. Self-hosted providers such as Keycloak may well be able to, in which case restrict the endpoint to the provider’s address; see [Restricting network access](#restricting-network-access).

 HTTP服務必須能夠透過TLS被身分提供者存取。託管身分提供者（例如 Microsoft Entra ID和 Okta）透過公共互聯網連接，無法存取僅在私人網路上發布的終結點。自託管提供者（例如 Keycloak）可能可以訪問，在這種情況下，請將終結點限制為提供者的位址；請參閱 [限制網路存取](#restricting-network-access) 。

 Absolute URLs that Stalwart returns in `meta.location` and `$ref` fields, and in the `Location` header of a creation response, are built from the server’s public URL. If the server sits behind a reverse proxy, set STALWART\_PUBLIC\_URL so that those URLs point at the externally visible name. Some SCIM clients follow `meta.location` on subsequent requests, so an incorrect value here surfaces as intermittent failures.

 Stalwart 在`meta.location`和`$ref`字段以及創建響應的`Location`標頭中返回的絕對 URL，均由伺服器的公共URL構建而成。如果伺服器位於反向代理程式之後，則需要設定 STALWART\_PUBLIC\_URL ，以便這些 URL 指向外部可見的名稱。某些SCIM客戶端會在後續請求中跟隨`meta.location` ，因此此處設定不正確會導致間歇性故障。

## Granting authority over a domain｜授予對域的權限

 SCIM may only write to domains that have been explicitly opened to it. The allowScimProvisioning field on the Domain object \(found in the WebUI under Management › Domains › Domains\) controls this, and it defaults to `false`:

 SCIM只能寫入已明確向其開放的域。 allowScimProvisioning欄位（位於 WebUI 的「管理」&gt;「域\([https://stalw.art/docs/ref/object/domain](https://stalw.art/docs/ref/object/domain)\) &gt;「域」下）控制此行為，其預設值為`false` ：

```json
{
  "name": "example.org",
  "allowScimProvisioning": true
}
```

Enabling the field has a second effect beyond permitting SCIM writes: it makes SCIM authoritative for the domain, which stops just-in-time provisioning from creating or modifying accounts there. That trade is the point of the field, and it is explained in full under Authority when both are configured. Review that section before enabling the field on a domain that currently relies on just-in-time provisioning.

 啟用此欄位除了允許SCIM寫入之外，還會產生第二個影響：它會使SCIM成為該網域的權威，從而阻止即時配置在該網域中建立或修改帳戶。此取捨正是此欄位的作用所在，具體內容在 同時配置時的權威性部分有詳細說明。在目前依賴即時配置的網域上啟用此欄位之前，請務必先閱讀該部分。

 Every address in a request is checked against this field, not merely the primary one. A `POST /Users` whose `userName` is in an enabled domain but which carries an alias in a domain that is not enabled is rejected in full with `400 Bad Request` and a `scimType` of `invalidValue`.

 請求中的每個位址都會與此欄位進行檢查，而不僅僅是主位址。 `POST /Users`的`userName`位於已啟用的域中，但其別名位於未啟用的域中，則會被完全拒絕，並返回`400 Bad Request`和`scimType`為`invalidValue` 。

## Creating the service principal｜建立服務主體

 A SCIM client authenticates as an ordinary Stalwart account, referred to here as the service principal. Create a dedicated account for it; do not reuse an administrator account. Its access can then be revoked independently, and its activity is distinguishable in the logs.

 SCIM客戶端以普通 Stalwart 帳戶（此處稱為服務主體）進行身份驗證。請為其建立一個專用帳戶；不要重複使用管理員帳戶。這樣，其存取權限可以獨立撤銷，並且其活動可以在日誌中區分。

 The account must live in a domain that has `allowScimProvisioning` enabled. This matters beyond tidiness: group accounts created through SCIM are placed in the service principal’s own domain, because a SCIM `Group` carries a display name but no address from which a domain could be derived. A service principal in a domain that is not SCIM-enabled can still manage users, but every attempt to create a group is refused.

 帳戶必須位於已啟用`allowScimProvisioning`的網域中。這不只是為了方便管理：透過SCIM建立的群組帳戶會被放置在服務主體本身的網域中，因為SCIM `Group`只包含顯示名稱，沒有可用於推導網域的位址。位於未啟用SCIM的網域中的服務主體仍然可以管理用戶，但任何建立群組的嘗試都會被拒絕。

 In a multi-tenant deployment, place the service principal inside the tenant it provisions for. Tenant scoping is inherited from the account, so a tenant-scoped service principal sees only that tenant’s accounts and domains, and requests that would cross a tenant boundary are rejected. This is the mechanism by which several identity providers can provision into one server without visibility of each other.

 在多租戶部署中，應將服務主體放置在它所服務的租戶內。租用戶範圍繼承自帳戶，因此租用戶範圍的服務主體只能看到該租用戶的帳戶和網域，任何跨越租用戶邊界的要求都會被拒絕。正是透過這種機制，多個身分提供者可以在同一台伺服器上進行配置，而無需彼此感知。

## Permissions｜權限

 Authorisation happens in two stages. The `scimAccess` permission gates the endpoint as a whole: without it, every SCIM request is refused regardless of what it asks for. Beyond that gate, each operation requires the same account permission that the equivalent administrative operation requires, so a credential can be scoped to exactly the operations the identity provider is expected to perform.

 授權分兩個階段進行。 `scimAccess` 權限將端點作為一個整體來控制：沒有它，每個 SCIM 請求都會被拒絕，無論它要求什麼。除了該門之外，每個操作都需要與等效管理作業所需的相同帳戶權限，因此可以將憑證的範圍限定為身分提供者預期執行的操作。

| Permission 許可 | Required for 必備 |
| --- | --- |
| `authenticate` | Presenting the credential at all 出示證書 |
| `scimAccess` | Every request to `/scim/v2`, other than the discovery endpoints 除發現端點之外，對`/scim/v2`的所有請求 |
| `sysAccountGet` | `GET` on `/Users` and `/Groups`, and every query, including `/.search` `GET`在`/Users`和`/Groups`上，以及每個查詢，包括`/.search` |
| `sysAccountCreate` | `POST /Users` and `POST /Groups` `POST /Users`和`POST /Groups` |
| `sysAccountUpdate` | `PUT` and `PATCH`, and any group creation that carries members `PUT`和`PATCH` ，以及任何包含成員的群組創建 |
| `sysAccountDestroy` | `DELETE` |

Omitting `sysAccountDestroy` is a reasonable precaution where the deprovisioning policy is suspension and not deletion. The identity provider can still send `PATCH` with `{"active": false}`, and its `DELETE` requests are refused with `403 Forbidden` instead of removing mailboxes. Refer to the permissions catalogue for the complete list and to the permissions reference for the SCIM entry.

 如果取消設定策略是暫停而非刪除，則省略`sysAccountDestroy`是合理的預防措施。身分提供者仍然可以發送`PATCH`和`{"active": false}` ，並且其`DELETE`請求將被`403 Forbidden`拒絕，而不是刪除郵箱。有關完整列表，請參閱權限目錄 ，有關SCIM條目，請參閱權限參考 。

## Issuing the credential｜頒發證書

 Requests authenticate with an API key belonging to the service principal, presented as an HTTP bearer token. HTTP Basic authentication is rejected outright, with a message directing the caller to use a bearer token; the published service provider configuration advertises OAuth bearer tokens as the only supported authentication scheme.

 請求使用屬於服務主體的 API 金鑰 進行身份驗證，以 HTTP 不記名令牌的形式呈現。 HTTP 基本身份驗證被徹底拒絕，並顯示一條訊息指示呼叫者使用不記名令牌；已發布的服務提供者配置將 OAuth 承載令牌宣傳為唯一受支援的身份驗證方案。

 Create the key on the ApiKey object \(found in the WebUI under Account › Credentials › API Keys\). Using `Replace` mode instead of `Inherit` confines the credential to the SCIM operations regardless of what the owning account is otherwise permitted to do:

 在 ApiKey物件上建立金鑰（可在 WebUI 的「帳戶」›「憑證」› API鑰」下找到）。使用`Replace`模式而非`Inherit`模式會將憑證限制為SCIM操作，而不管擁有該憑證的帳戶還被允許執行哪些其他操作：

```json
{
  "description": "SCIM provisioning (corporate IdP)",
  "permissions": {
    "@type": "Replace",
    "permissions": {
      "authenticate": true,
      "scimAccess": true,
      "sysAccountGet": true,
      "sysAccountCreate": true,
      "sysAccountUpdate": true,
      "sysAccountDestroy": true
    }
  },
  "allowedIps": {
    "203.0.113.0/24": true
  }
}
```

Values on this page follow the object encoding rules: list and set fields are JSON objects, not arrays, and durations and sizes are integers.

 本頁上的值遵循 對象編碼規則：列表和集合字段是JSON對象，而不是數組，持續時間和大小是整數。

 The secret is generated by the server and displayed once, at creation. It is stored hashed and cannot be recovered afterwards, so it must be transferred to the identity provider’s configuration at that point. Rotation is a matter of issuing a second key, updating the identity provider, and revoking the first.

 該密鑰由伺服器生成，並在創建時顯示一次。它以哈希形式存儲，之後無法恢復，因此必須在創建時將其傳輸到身份提供者的配置中。密鑰輪換是指頒發第二個密鑰、更新身分提供者並撤銷第一個密鑰。

 The optional allowedIps field restricts where the credential may be presented. Identity providers that publish their egress ranges make this a cheap additional control, though those ranges do change and an out-of-date list presents as an authentication failure. An expiresAt value is also available where credential lifetimes are governed by policy; note that provisioning stops when the key expires, so expiry needs to be paired with a rotation procedure.

 可選的 allowedIps欄位限制了憑證的呈現位置。身分提供者如果發布了其出口範圍，則可以利用此欄位進行低成本的額外控制，但這些範圍會發生變化，過期的清單會導致身分驗證失敗。如果憑證的生命週期由策略控制，則也可以使用 expiresAt值；請注意，金鑰過期時，配置將停止，因此過期機制需要與輪調程式搭配使用。

 A SCIM client cannot deprovision itself. Requests that would deactivate or delete the service principal the request authenticated as are refused with `403 Forbidden`, which prevents an identity provider that has been given a mailbox for its own service account from disabling its own access mid-cycle.

 SCIM客戶端無法自行取消配置。任何會停用或刪除請求所驗證的服務主體的請求都會被`403 Forbidden`拒絕，這可以防止已為其服務帳戶分配郵箱的身份提供者在服務週期中途禁用自身的存取權限。

## Restricting network access｜限製網路存取

 The SCIM endpoint accepts requests on the same HTTP listeners as everything else. Where the identity provider connects from known addresses, the allowedEndpoints expression on the Http singleton \(found in the WebUI under Settings › Network › HTTP › General, Settings › Network › HTTP › Security\) can confine `/scim` to those addresses:

 SCIM端點接受與其他所有端點相同的HTTP監聽器上的請求。如果身分提供者從已知位址連接，則 Http單例（可在 WebUI 的「設定」&gt;「網路」&gt; HTTP常規」或「設定」&gt;「網路」&gt;「安全性」中找到）上的`/scim` `allowedEndpoints` HTTP \([https://stalw.art/docs/ref/object/http#allowedendpoints](https://stalw.art/docs/ref/object/http#allowedendpoints)\)

```json
{
  "allowedEndpoints": {
    "match": {
      "0": {"if": "starts_with(url_path, '/scim') && !starts_with(remote_ip, '203.0.113.')", "then": "404"}
    },
    "else": "200"
  }
}
```

Further patterns, including restriction by listener so that SCIM is served only on an internal interface, are covered under Access control.

 其他模式，包括透過監聽器進行限制，以便SCIM僅在內部介面上提供服務，均在 存取控制中有所涵蓋。

 Rate limiting applies as it does to any other authenticated HTTP request; see Rate limiting. When a client exceeds its limit the response is `429 Too Many Requests` with a `Retry-After` header, which well-behaved SCIM clients honour by deferring the remainder of the cycle.

 速率限制適用於任何其他經過驗證的HTTP請求；請參閱 速率限制 。當客戶端超出其限制時，響應為`429 Too Many Requests` ，並帶有`Retry-After`標頭，行為良好的SCIM客戶端會遵守此標頭，延遲剩餘的周期。

## Verifying the endpoint｜驗證端點

 The discovery endpoints are readable without authentication, which makes them the quickest confirmation that routing, TLS, and licensing are in order:

 無需身份驗證即可讀取發現端點，這使得它們成為確認路由、 TLS和許可是否正常的最快方法：

```bash title=&amp;quot;Terminal window&amp;quot;
curl https://mail.example.org/scim/v2/ServiceProviderConfig
```

A working server answers with `application/scim+json` and a document reporting support for patch, bulk, filter, sort, entity tags, and both pagination styles. A `403` response with a message about the Enterprise edition means the license is absent or has not been applied.

 正常運作的伺服器會傳回`application/scim+json`回應，並報告支援修補程式、批次、篩選、排序、實體標籤以及兩種分頁樣式。如果返回`403`回應並包含有關企業版的訊息，則表示許可證缺失或尚未應用。

 Authentication and permissions are confirmed with a request to a resource endpoint:

 透過向資源端點發出請求來確認身份驗證和權限：

```bash title=&amp;quot;Terminal window&amp;quot;
curl -H "Authorization: Bearer $SCIM_TOKEN" \
     "https://mail.example.org/scim/v2/Users?count=1"
```

A `200` response with a `ListResponse` body confirms the credential and the `scimAccess` and `sysAccountGet` permissions. A `401` indicates a missing or invalid token, while a `403` indicates a valid token whose account lacks a required permission; the `detail` field in the error body names which condition failed.

 帶有 `ListResponse` 正文的 `200` 回應確認憑證以及 `scimAccess` 和 `sysAccountGet` 權限。 `401`表示遺失或無效令牌，而`403`表示帳戶缺少所需權限的有效令牌；錯誤主體中的 `detail` 欄位命名了條件失敗的名稱。

 Once these two requests succeed, the identity provider can be configured against the base URL `https://mail.example.org/scim/v2`. Procedures for individual providers are collected under Identity providers.

 一旦這兩個請求成功，就可以針對基本URL `https://mail.example.org/scim/v2`配置身分提供者。各個提供程序的流程收集在 身分提供程序下。
