# Mailing lists｜郵件清單

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[email｜電子郵件\\\]\\\(&lt;000 目錄.md#c-22&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-23&gt;\\\)

A mailing list distributes messages delivered to a single address to a set of recipients. Stalwart treats mailing lists as first-class directory objects rather than as aliases with multiple targets, so each list has its own identity, description, and set of alternate addresses independent of any user account.

 郵件清單將發送到單一位址的郵件分發給一組收件者。 Stalwart 將郵件清單視為一級目錄對象，而不是具有多個目標的別名，因此每個清單都有其自身的識別、描述和一組備用地址，獨立於任何使用者帳戶。

 Mailing lists are defined by the MailingList object \(found in the WebUI under Management › Directory › Mailing Lists\). Each instance represents one distribution address; the object stores the primary local part, the domain it attaches to, an optional description, the set of recipients, and any alternate addresses that should resolve to the same list.

 郵件清單由 MailingList物件定義（可在 WebUI 的「管理」&gt;「目錄」&gt;「郵件清單」下找到）。每個實例代表一個分發位址；該物件儲存主要本機部分、其所屬域、可選描述、收件者集合以及任何應解析到相同清單的備用位址。

## Addressing｜解決

 The primary address of a list is built from the name local part and the domainId reference, joined as `name@domain`. The server exposes the resulting address read-only through emailAddress, so the address updates automatically whenever the local part or the associated domain changes.

 列表的主地址由 name本地部分和 domainId引用構成，連接方式為`name@domain` 。伺服器透過 emailAddress以唯讀方式公開產生的位址，因此，當本地部分或關聯域發生變更時，位址會自動更新。

 Additional addresses that should deliver to the same list are declared through aliases. The field is an ordered list. Each entry is an `EmailAlias` nested object with its own local part, target domain, optional description, and `enabled` flag. Disabling an alias leaves the record in place but stops the address from resolving, which is useful for temporarily parking an old name before removing it.

 透過 aliases宣告應投遞到同一清單的其他位址。該字段是一個有序列表。每個條目都是`EmailAlias`嵌套對象，包含其自身的本地部分、目標域、可選描述和`enabled`標誌。停用別名會保留記錄，但阻止位址解析，這對於在刪除舊名稱之前暫時存放它非常有用。

 Both the primary address and every alias must reference a domain that already exists in the directory. When the list belongs to a tenant, its domain must belong to the same tenant.

 主地址和每個別名都必須引用目錄中已存在的網域名稱。如果清單屬於某個租戶，則其網域必須屬於同一租戶。

## Recipients｜收件者

 The set of destinations for a list is stored in recipients as a set of email addresses. There is no separate membership object and no reference to Account or Group identifiers: local accounts are added to a list by their email address, just like external subscribers. Any valid email address is accepted, so a list can mix internal accounts, nested lists, and external subscribers without extra configuration.

 清單的目標位址集儲存在 recipients中，以電子郵件位址集的形式存在。沒有單獨的成員對象，也不引用帳戶或群組識別碼：本機帳戶和外部訂閱者一樣，都透過電子郵件地址新增到清單中。任何有效的電子郵件地址均被接受，因此清單可以混合使用內部帳戶、巢狀清單和外部訂閱者，而無需額外配置。

## Tenancy｜租約

 In multi-tenant deployments, a list is scoped to a tenant through memberTenantId. Administrators for that tenant can create and manage the list; the global administrator sees lists from every tenant. Leaving the field unset keeps the list outside any tenant boundary, which is the usual case for single-tenant installations.

 在多租用戶部署中，清單透過 memberTenantId限定於特定租用戶。該租用戶的管理員可以建立和管理清單；全域管理員可以看到所有租用戶的清單。如果該欄位未設置，則清單將位於任何租用戶邊界之外，這通常是單一租用戶部署的情況。

## Managing lists｜管理清單

 Lists can be created, updated, and removed through three interfaces that share the same underlying JMAP methods:

 可以透過三個介面建立、更新和刪除列表，這三個介面共享相同的底層JMAP方法：

- **WebUI.** The Directory section of the WebUI offers a dedicated Mailing Lists view where operators fill in the local part, pick a domain, add aliases, and type or paste recipient addresses. The form is backed by the `x:MailingList/set` method and surfaces validation errors returned by the server.
**Web使用者介面。** Web使用者介面的「目錄」部分提供了一個專門的郵件清單視圖，操作員可以在其中填寫本機資訊、選擇網域名稱、新增別名，以及輸入或貼上收件者地址。此表單由`x:MailingList/set`方法提供支持，並會顯示伺服器傳回的驗證錯誤。
- **CLI.** `stalwart-cli` exposes equivalent subcommands, which is convenient for bulk import or for scripting membership changes. For example, `stalwart-cli create mailing-list --field name=announce --field 'domainId=<Domain id>' --field 'recipients={"[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)":true,"[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)":true}'` creates a list in one call, and `stalwart-cli update mailing-list <id> --field 'recipients={...}'` replaces the recipient set. The full command reference lives on the MailingList object page.
**CLI .** `stalwart-cli`公開了等效的子指令，方便批次匯入或編寫成員變更腳本。例如， `stalwart-cli create mailing-list --field name=announce --field 'domainId=<Domain id>' --field 'recipients={"[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)":true,"[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)":true}'`一次呼叫即可建立一個列表，而`stalwart-cli update mailing-list <id> --field 'recipients={...}'`則會取代收件者集。完整的命令參考位於 郵件清單物件頁面 。
- **JMAP API.** Integrations and external provisioning systems can call `x:MailingList/get`, `x:MailingList/query`, and `x:MailingList/set` directly. The methods are standard RFC 8620 shapes advertised under the `urn:stalwart:jmap` capability; each operation requires the matching `sysMailingList*` permission on the calling principal.
**JMAP API .** 整合和外部配置系統可以直接呼叫`x:MailingList/get`, `x:MailingList/query`和`x:MailingList/set` 。這些方法是標準的RFC 8620 格式，在`urn:stalwart:jmap`功能下發布；每次操作都需要呼叫主體擁有對應的`sysMailingList*`權限。
A typical JMAP request creating a list looks like:
 建立清單的典型JMAP請求如下所示：

```json
{
  "methodCalls": [
    [
      "x:MailingList/set",
      {
        "create": {
          "new1": {
            "name": "announce",
            "domainId": "<Domain id>",
            "description": "Company-wide announcements",
            "recipients": {"[email protected]": true, "[email protected]": true},
            "aliases": {
              "0": {"name": "news", "domainId": "<Domain id>", "enabled": true}
            }
          }
        }
      },
      "c1"
    ]
  ],
  "using": ["urn:ietf:params:jmap:core", "urn:stalwart:jmap"]
}
```

Updates and deletions follow the same `x:MailingList/set` pattern with `update` or `destroy` arguments, and existing lists can be enumerated with `x:MailingList/query` filtered by free text or by tenant.

 更新和刪除遵循相同的`x:MailingList/set`模式，帶有`update`或`destroy`參數，現有列表可以透過`x:MailingList/query`按自由文字或租戶進行篩選來枚舉。

## Permissions｜權限

 The `sysMailingListGet`, `sysMailingListQuery`, `sysMailingListCreate`, `sysMailingListUpdate`, and `sysMailingListDestroy` permissions gate each operation independently. Granting read-only visibility to a support role, for example, is done by assigning only `sysMailingListGet` and `sysMailingListQuery`. The same permissions apply regardless of whether the operation is issued from the WebUI, the CLI, or a direct JMAP client, since each surface delegates to the same method handlers.

`sysMailingListGet`, `sysMailingListQuery`, `sysMailingListCreate`, `sysMailingListUpdate`和`sysMailingListDestroy`權限分別控制每個操作。例如，要授予支援角色唯讀權限，只需分配`sysMailingListGet`和`sysMailingListQuery`即可。無論操作是從 WebUI、 CLI或直接客戶端JMAP發出，權限都相同，因為每個介面都委託給相同的方法處理程序。
