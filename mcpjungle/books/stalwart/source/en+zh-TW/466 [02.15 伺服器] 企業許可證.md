# Enterprise License｜企業許可證

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\)

Stalwart is distributed as an open-source mail server. Alongside the open-source core, Stalwart Labs publishes a set of Enterprise features aimed at larger deployments that require additional control, security, and manageability. These features target environments that need tools such as multi-tenancy, dashboards, and AI integrations, and are unlocked by an [Enterprise subscription](https://license.stalw.art/buy).

 Stalwart 以開源郵件伺服器的形式分發。除了開源核心之外，Stalwart Labs 還發布了一系列 企業版功能旨在滿足需要額外控制、安全性和可管理性的大型部署需求。這些功能面向需要多租戶、儀表板和AI整合等工具的環境，可透過 [企業版訂閱](https://license.stalw.art/buy)解鎖。

 Enterprise-exclusive capabilities include multi-tenancy, which allows multiple organizations or domains to be managed within a single server instance, administrative dashboards, and AI-powered models for email processing. For a feature-by-feature comparison between the open-source and Enterprise editions, see the comparison page.

 企業版獨有的功能包括多租戶 ，它允許在單一伺服器實例中管理多個組織或網域；管理儀表板；以及AI支援的模型 ，用於電子郵件處理。有關開源版和企業版的功能對比，請參閱對比頁面 。

## How licenses work｜許可證的工作原理

 Enterprise licenses are issued to a specific **domain name** and carry a mailbox-count limit. A single license can be reused across multiple servers as long as they share the same registered domain. For example, a license issued for `*.example.org` covers `mx1.example.org`, `mx2.example.org`, and any other host under `example.org`, so a distributed deployment does not need separate licenses per node.

 企業版許可證頒發給特定的**網域名稱**，並設有郵箱數量限制。只要多個伺服器共享同一個註冊域名，單一許可證即可重複使用。例如，頒發給`*.example.org`許可證涵蓋`mx1.example.org`, `mx2.example.org`以及`example.org`下的任何其他主機，因此分散式部署無需為每個節點單獨購買許可證。

 The domain constraint applies only to server hostnames. An unlimited number of **client domains** can be hosted on the same infrastructure regardless of the licensed domain: a server licensed for `*.example.org` can provide mail service for `foobar.org`, `test.org`, or any other tenant domain.

 網域限制僅適用於伺服器主機名稱。無論授權網域為何，同一基礎架構上都可以託管無限數量的**客戶端網域名稱**：取得`*.example.org`授權的伺服器可以為`foobar.org`, `test.org`或任何其他租用戶網域提供郵件服務。

## Obtaining a license｜獲得許可證

 Enterprise licenses are distributed as a cryptographically signed string. Stalwart validates each license offline using the embedded signature, so no outbound call to the licensing server is required at validation time. This makes the Enterprise edition suitable for isolated or tightly controlled environments where internet access is limited.

 企業版許可證以加密簽署字串的形式分發。 Stalwart 使用嵌入式簽章離線驗證每個許可證，因此在驗證時無需向許可伺服器發出任何外部呼叫。這使得企業版適用於網路存取受限的隔離或嚴格控制的環境。

### Configuration｜配置

 The license is stored on the Enterprise singleton \(found in the WebUI under Settings › Enterprise\) through licenseKey. The field is a secret: it can hold the literal license string, or point at an environment variable or a file.

 許可證儲存在 Enterprise單例中（可在 WebUI 的「設定 › 企業」下找到），透過 licenseKey進行存取。該欄位是一個秘密欄位：它可以保存許可證字串，也可以指向環境變數或檔案。

```json
{
  "licenseKey": {
    "@type": "Value",
    "secret": "<LICENSE_KEY>"
  }
}
```

### Reload and re-login｜重新載入並重新登入

 After the license key is saved, the server configuration must be reloaded from the CLI. Logging out and back in is required before the Enterprise features become visible in the session.

 儲存許可證金鑰後，必須從 CLI重新載入伺服器設定。需要登出並重新登錄，企業功能才會顯示在會話中。

## Automatic renewals｜自動續訂

 Enterprise licenses expire on a fixed date; once expired, Enterprise features stop working until a new license is installed. Stalwart Labs provides a renewal API that can fetch a fresh license automatically a few days before the current one expires.

 企業版許可證會在固定日期到期；一旦到期，企業版功能將停止運作，直到安裝新許可證為止。 Stalwart Labs 提供續約服務API ，可在目前許可證到期前幾天自動取得新授權。

 Enabling automatic renewal removes the need for manual intervention and reduces the chance of a gap in Enterprise coverage. The renewal process runs in the background and has no impact on day-to-day operations.

 啟用自動續訂功能可免去人工幹預，並降低企業服務中斷的風險。續訂過程在後台運行，不會影響日常運作。

 When an API key is configured, the server begins renewal attempts up to five days before the expiration date. If the first attempt fails, the server retries every twenty-four hours. On the final day of the license, the retry interval shortens to one hour so that transient network issues are less likely to cause an outage.

 配置API金鑰後，伺服器會在到期日前最多五天開始嘗試續訂。如果首次嘗試失敗，伺服器將每24小時重試一次。在許可證到期日當天，重試間隔縮短至一小時，以降低因網路瞬時故障導致服務中斷的可能性。

### Configuration｜配置

 An API key is required to authorise the server to request a new license from the [Stalwart Labs Licensing Portal](https://license.stalw.art/). The key is generated from the subscription details page on the licensing portal.

 要授權伺服器從 [Stalwart Labs 許可入口網站](https://license.stalw.art/)請求新許可證，需要API金鑰。此金鑰由許可入口網站的訂閱詳情頁面產生。

 The key is stored on the Enterprise singleton through apiKey, which accepts a direct value, an environment variable, or a file reference:

 金鑰儲存在 Enterprise單例中，透過 apiKey ，它接受直接值、環境變數或檔案引用：

```json
{
  "apiKey": {
    "@type": "Value",
    "secret": "<API_KEY>"
  }
}
```
