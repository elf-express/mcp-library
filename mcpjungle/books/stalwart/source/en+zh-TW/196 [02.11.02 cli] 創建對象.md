# Creating objects｜創建對象

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-31&gt;\\\) › \\\[cli\\\]\\\(&lt;000 目錄.md#c-33&gt;\\\)

The `create` command creates a single object from one of four input sources. Validation is intentionally minimal \(the server is the source of truth\); the CLI only checks that field names exist on the schema and that values are of the right shape.

`create`指令從四個輸入來源之一建立一個物件。驗證過程刻意簡化（伺服器是權威來源）； CLI僅檢查欄位名稱是否存在於模式中以及值格式是否正確。

## Synopsis｜概要

```
stalwart-cli create <object> ( --field key=value... | --json '<json>' | --file | --stdin )
```

- `<object>`: object type name \(with or without `x:` prefix\). For multi-variant objects, use the `Object/Variant` shorthand to select a variant.
`<object>` ：物件類型名稱（帶或不帶`x:`前綴）。對於多變體對象，請使用`Object/Variant`簡寫形式來選擇變體。
- The four input forms are mutually exclusive \(an error is raised if more than one is supplied\).
這四種輸入形式是互斥的（如果提供了多種輸入形式，則會引發錯誤）。
## Multi-variant objects｜多變體對象

 Multi-variant objects \(such as `Account`, with variants `User` and `Group`\) require an `@type` value. There are two equivalent forms.

 多變體物件（例如`Account` ，其變體為`User`和`Group` ）需要一個`@type`值。有兩種等效形式。

### Slash shorthand｜斜槓速記

 The `Object/Variant` form auto-injects `@type` matching the variant name:

`Object/Variant`表單會自動注入與變體名稱相符的`@type` ：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create account/user \
  --field name=alice \
  --field domainId=b \
  --field 'credentials={"0":{"@type":"Password","secret":"hunter2"}}'
```

### Explicit @type｜顯式 @type

 The same effect can be achieved by supplying `@type` directly:

 直接供應`@type`也能達到相同的效果：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create account \
  --field @type=User \
  --field name=alice \
  --field domainId=b
```

If both the slash form and an explicit `@type` are supplied, the user’s value wins and a warning is printed. To inspect a multi-variant object’s variants and their fields, see Exploring the schema.

 如果同時提供了斜線形式和顯式的`@type` ，則以使用者的值為準，並列印警告。若要檢查多變體物件的變體及其字段，請參閱 探索模式 。

## Input sources｜輸入來源

### `--field key=value`

 Repeatable. Sets one top-level property per flag. Values are coerced based on the schema field’s type:

 可重複。每個標誌設定一個頂級屬性。值根據架構欄位的類型進行強制轉換：

| Field type 欄位類型 | Accepted forms 可接受的表單 |
| --- | --- |
| `boolean` | `true` / `false` \(case-insensitive\) `true` / `false` （不區分大小寫） |
| `number` \(integer\) `number` \(整數\) | a decimal integer literal 十進位整數面量 |
| `number` \(float\) | any float literal 任意浮點數 |
| `string`, `enum`, `objectId`, `blobId`, `datetime` | the literal as written 原文如此 |
| `object`, `objectList`, `set`, `map` | a JSON literal starting with `{` or `[` \(quote it for the shell\) 一個以`{`或`[`開頭的JSON字面量（在 shell 中需要加引號） |

Example:

 例子：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create domain --field name=example.com --field isEnabled=true --field description='Primary domain'
```

For a field whose value is structured \(an object or an array\), supply explicit JSON:

 對於值為結構化物件（物件或陣列）的字段，請提供明確的JSON :

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create dkimsignature \
  --field domainId=b \
  --field '@type=Dkim1Ed25519Sha256' \
  --field 'privateKey={"@type":"Text","secret":"-----BEGIN PRIVATE KEY-----\n..."}' \
  --field selector=2026
```

Repeating the same key in one invocation is an error. To set a JSON sub-key in a `create`, use a structured `--field` value \(JSON pointer paths are an update feature, not a `create` feature\).

 在一次呼叫中重複使用相同的鍵是錯誤的。要在`create`中設定JSON子鍵，請使用結構化的`--field`值（ JSON指標路徑是 update特性，而不是`create`特性）。

#### Quoting field names｜引用欄位名稱

 If a field name itself contains characters that would confuse parsing \(a literal `=`, for example\), wrap it in double or single quotes:

 如果欄位名稱本身包含可能導致解析混亂的字元（例如，字面值`=` ），請將其用雙引號或單引號括起來：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create memorylookupkey \
  --field 'namespace=block-list' \
  --field '"key=foo=bar"=value'
```

Without quotes, the parser splits on the first `=`. With quotes, the whole quoted string is treated as the key and the next `=` is the separator.

 如果沒有引號，解析器會依照第一個`=`進行分割。如果有引號，則整個引號的字串將被視為鍵，下一個`=`是分隔符號。

### `--json '<json>'`

 A complete JSON object passed inline. Useful for one-shot scripts:

 以內聯方式傳遞完整的JSON物件。適用於一次性腳本：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create domain \
  --json '{"name":"example.org","isEnabled":true,"description":"Primary"}'
```

### ` --file  `

 Reads the JSON object from a file. Convenient for templated payloads \(jinja2, jsonnet, …\):

 從檔案中讀取JSON物件。方便使用模板化有效負載（jinja2、jsonnet等）：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create account/user --file users/alice.json
```

### `--stdin`

 Reads the JSON object from standard input. Plays well with pipelines:

 從標準輸入讀取JSON物件。與管道配合良好：

```bash title=&amp;quot;Terminal window&amp;quot;
jq -n '{name: "ops-team", description: "Ops"}' \
  | stalwart-cli create account/group --stdin
```

`--json` / `--file` / `--stdin` accept arbitrarily nested JSON; the slash-in-key restriction only applies to `--field`.

`--json` / `--file` / `--stdin`接受任意嵌套的JSON ；鍵中的斜杠限制僅適用於`--field` 。

## Output｜輸出

 By default, the CLI prints a one-line confirmation including the new server-assigned id:

 預設情況下， CLI會列印一行確認訊息，其中包括伺服器指派的新 ID：

```
Created Domain xyz789
```

If the server returns additional properties \(for example, a generated API key, app password, or DKIM keypair\), those are rendered below the confirmation using the same form-driven view as get. This matters in cases where the value is shown only once and must be captured immediately. The `ApiKey` and `AppPassword` objects do not take an explicit owner field; the credential is attached to the principal that authenticates the CLI request, so a separate `accountId` is neither supplied nor accepted:

 如果伺服器傳回其他屬性（例如，產生的 API 金鑰、應用程式密碼或 DKIM 金鑰對），這些屬性將使用與 get 相同的表單驅動視圖呈現在確認下方。當該值僅顯示一次且必須立即捕獲時，這一點很重要。 `ApiKey` 和 `AppPassword` 物件不採用顯式所有者欄位；此憑證附加到驗證CLI請求的主體，因此既不提供也不接受單獨的`accountId`：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli create apikey \
  --field description='CI deploy key' \
  --field 'permissions={"@type":"Inherit"}' \
  --field 'allowedIps={}'
```

```
Created ApiKey aaa111

Credential
  Secret: API_AAAAEwAAAAHDN7BtUeZSrGrM9DibqfhzRGD7sw
```

The `Secret` value is returned by the server only on this create response. A subsequent get of the same `ApiKey` returns the server’s masked placeholder \(`****`\) for `Secret`; the original cannot be recovered. Capture and store the value before running anything else.

 伺服器僅在本次建立回應中傳回`Secret`值。後續對同一`ApiKey`的 get會傳回伺服器對`Secret`的遮罩佔位符 \( `****` \)；原始值無法恢復。請在執行任何其他操作之前捕獲並儲存該值。

 Unlike get, `create` does not currently support a JSON output mode \(the input flag `--json` is reserved as an input source\). For machine-readable workflows, use apply, which can emit NDJSON status records.

 與 \[ `get` \] 不同， \([https://stalw.art/docs/management/cli/get](https://stalw.art/docs/management/cli/get)\), `create`目前不支援JSON輸出模式（輸入標誌`--json`保留用作輸入來源）。對於機器可讀的工作流程，請使用 apply ，它可以發出NDJSON狀態記錄。
