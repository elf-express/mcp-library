# Connection｜聯繫

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[outbound｜出站\\\]\\\(&lt;000 目錄.md#c-52&gt;\\\)

A connection strategy defines how Stalwart MTA establishes SMTP connections to remote servers during message delivery. While routing strategies determine *where* messages are delivered, connection strategies control *how* those connections are made. A connection strategy specifies parameters such as the source IP address to bind to, the hostname to advertise in the `EHLO` command, and timeout values for each stage of the SMTP session. This level of control is useful in multi-homed systems, outbound IP rotation setups, or when complying with specific policy or network constraints.

 連線策略定義了 Stalwart MTA在訊息傳遞期間如何與遠端伺服器建立SMTP連線。路由策略\([https://stalw.art/docs/mta/outbound/routing\)決定訊息的傳遞\*位置\*，而連接策略則控制這些連接的\*方式\*。連線策略指定了諸如要綁定的來源IP位址、要在\`EHLO\`指令中通告的主機名稱以及SMTP會話每個階段的逾時值等參數。這種程度的控制在多宿主系統、出站IP輪換設定中非常有用，或者在遵守特定策略或網路約束時也很有用。](https://stalw.art/docs/mta/outbound/routing%2529%2525E6%2525B1%2525BA%2525E5%2525AE%25259A%2525E8%2525A8%25258A%2525E6%252581%2525AF%2525E7%25259A%252584%2525E5%252582%2525B3%2525E9%252581%25259E*%2525E4%2525BD%25258D%2525E7%2525BD%2525AE*%2525EF%2525BC%25258C%2525E8%252580%25258C%2525E9%252580%2525A3%2525E6%25258E%2525A5%2525E7%2525AD%252596%2525E7%252595%2525A5%2525E5%252589%252587%2525E6%25258E%2525A7%2525E5%252588%2525B6%2525E9%252580%252599%2525E4%2525BA%25259B%2525E9%252580%2525A3%2525E6%25258E%2525A5%2525E7%25259A%252584*%2525E6%252596%2525B9%2525E5%2525BC%25258F*%2525E3%252580%252582%2525E9%252580%2525A3%2525E7%2525B7%25259A%2525E7%2525AD%252596%2525E7%252595%2525A5%2525E6%25258C%252587%2525E5%2525AE%25259A%2525E4%2525BA%252586%2525E8%2525AB%2525B8%2525E5%2525A6%252582%2525E8%2525A6%252581%2525E7%2525B6%252581%2525E5%2525AE%25259A%2525E7%25259A%252584%2525E4%2525BE%252586%2525E6%2525BA%252590IP%2525E4%2525BD%25258D%2525E5%25259D%252580%2525E3%252580%252581%2525E8%2525A6%252581%2525E5%25259C%2525A8%252560EHLO%252560%2525E6%25258C%252587%2525E4%2525BB%2525A4%2525E4%2525B8%2525AD%2525E9%252580%25259A%2525E5%252591%25258A%2525E7%25259A%252584%2525E4%2525B8%2525BB%2525E6%2525A9%25259F%2525E5%252590%25258D%2525E7%2525A8%2525B1%2525E4%2525BB%2525A5%2525E5%25258F%25258ASMTP%2525E6%25259C%252583%2525E8%2525A9%2525B1%2525E6%2525AF%25258F%2525E5%252580%25258B%2525E9%25259A%25258E%2525E6%2525AE%2525B5%2525E7%25259A%252584%2525E9%252580%2525BE%2525E6%252599%252582%2525E5%252580%2525BC%2525E7%2525AD%252589%2525E5%25258F%252583%2525E6%252595%2525B8%2525E3%252580%252582%2525E9%252580%252599%2525E7%2525A8%2525AE%2525E7%2525A8%25258B%2525E5%2525BA%2525A6%2525E7%25259A%252584%2525E6%25258E%2525A7%2525E5%252588%2525B6%2525E5%25259C%2525A8%2525E5%2525A4%25259A  Each connection strategy is defined as an MtaConnectionStrategy object \(found in the WebUI under Settings › MTA › Outbound › Connection Strategies\). Strategies are selected dynamically for each recipient via the connection expression on MtaOutboundStrategy; see Strategies for details.

 每個連線策略都定義為一個 MtaConnectionStrategy物件（可在 WebUI 的「設定」› MTA › 出站 › 連接策略」下找到）。策略透過 MtaOutboundStrategy上的連線表達式。 \([https://stalw.art/docs/mta/outbound/strategy](https://stalw.art/docs/mta/outbound/strategy)\) 。

 Each connection strategy operates independently and can be tailored to specific domains, message types, or security requirements. For example, one strategy might use a dedicated IP address and hostname for high-volume transactional mail, while another uses different parameters for low-volume or internal mail.

 每種連線原則都獨立運行，並可根據特定網域、郵件類型或安全性需求進行自訂。例如，一種策略可能使用專用的IP位址和主機名稱來處理高容量事務郵件，而另一種策略則使用不同的參數來處理低容量或內部郵件。

## EHLO hostname｜EHLO主機名

 The ehloHostname field overrides the EHLO hostname used when this strategy is applied. When left empty, the system hostname is used. For example:

 ehloHostname欄位會覆寫應用此策略時所使用的EHLO主機名稱。如果留空，則使用系統主機名稱。例如：

```json
{
  "name": "default",
  "ehloHostname": "mx.example.org"
}
```

## Source IP｜來源IP

 The sourceIps field accepts a list of local IPv4 and IPv6 addresses to use when delivering messages to remote servers. If multiple entries are provided, Stalwart randomly selects one for each new connection. Each entry carries a required `sourceIp` and an optional `ehloHostname` that overrides the strategy-wide EHLO hostname for that source address.

 sourceIps欄位接受一個本機 IPv4 和 IPv6 位址列表，用於傳送訊息給遠端伺服器。如果提供了多個條目，Stalwart 會為每個新連接隨機選擇一個。每個條目都包含一個必需的`sourceIp`和一個可選的`ehloHostname` ，後者會覆寫該來源位址的策略等級EHLO主機名稱。

 Correct configuration of `sourceIps` is important for deliverability on multi-homed systems. If no source address is set and the system has several local IPs, the kernel chooses one arbitrarily, which may hurt reputation or violate policy. Per-source EHLO overrides are useful when different IPs are associated with different domains or services.

 正確配置`sourceIps`對於多宿主系統的郵件送達至關重要。如果未設定來源位址且系統有多個本機IP位址，核心會隨機選擇一個，這可能會損害信譽或違反策略。當不同的IP位址與不同的網域或服務關聯時，針對每個來源的EHLO覆蓋設定非常有用。

 Example strategy with four source addresses, one of which overrides the EHLO hostname:

 範例策略包含四個來源位址，其中一個會覆寫EHLO主機名稱：

```json
{
  "name": "default",
  "ehloHostname": "mx.example.org",
  "sourceIps": {
    "0": {"sourceIp": "192.0.2.10", "ehloHostname": "mx-192-0-2-10.example.org"},
    "1": {"sourceIp": "192.0.2.11"},
    "2": {"sourceIp": "2001:db8::a"},
    "3": {"sourceIp": "2001:db8::b"}
  }
}
```

## Timeouts｜暫停

 Timeouts cap how long Stalwart waits for the remote server to respond at each stage of the SMTP dialogue: connectTimeout \(connection establishment, default 5 minutes\), greetingTimeout \(SMTP greeting, default 5 minutes\), ehloTimeout \(`EHLO` response, default 5 minutes\), mailFromTimeout \(`MAIL FROM` response, default 5 minutes\), rcptToTimeout \(`RCPT TO` response, default 5 minutes\), and dataTimeout \(`DATA` response, default 10 minutes\):

 超時機制限制了 Stalwart 在SMTP對話的每個階段等待遠端伺服器回應的時間：connectTimeout （連線建立，預設 5 分鐘），\[ `greetingTimeout` \]SMTP \([https://stalw.art/docs/ref/object/mta-connection-strategy#greetingtimeout](https://stalw.art/docs/ref/object/mta-connection-strategy#greetingtimeout)\) `ehloTimeout` . \([https://stalw.art/docs/ref/object/mta-connection-strategy#ehlotimeout](https://stalw.art/docs/ref/object/mta-connection-strategy#ehlotimeout)\) （ `EHLO`響應，預設 5 分鐘），mailFromTimeout （ `MAIL FROM`響應，預設 5 分鐘）， `rcptToTimeout` `RCPT TO` \]\([https://stalw.art/docs/ref/object/mta-connection-strategy#rcpttotimeout](https://stalw.art/docs/ref/object/mta-connection-strategy#rcpttotimeout)\) 29⧟ `dataTimeout` \]\([https://stalw.art/docs/ref/object/mta-connection-strategy#datatimeout](https://stalw.art/docs/ref/object/mta-connection-strategy#datatimeout)\) （ `DATA`響應，預設 10 分鐘）：

```json
{
  "connectTimeout": 180000,
  "greetingTimeout": 180000,
  "ehloTimeout": 180000,
  "mailFromTimeout": 180000,
  "rcptToTimeout": 180000,
  "dataTimeout": 600000
}
```

Values on this page follow the object encoding rules: list and set fields are JSON objects rather than arrays, and durations and sizes are integers.

 本頁上的值遵循 物件編碼規則：列表和集合字段是JSON物件而不是數組，持續時間和大小是整數。
