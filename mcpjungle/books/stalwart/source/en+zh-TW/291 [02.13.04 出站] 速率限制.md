# Rate limits｜速率限制

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[outbound｜出站\\\]\\\(&lt;000 目錄.md#c-52&gt;\\\)

Rate limiting controls the flow of connections and messages by restricting the number of operations allowed over a specific time period. In Stalwart, rate limiting ensures that email traffic is managed efficiently, preventing resource overuse and protecting the server from abuse such as spam or denial-of-service attacks.

 速率限制透過限制特定時間內允許的操作次數來控制連線和訊息的流量。在 Stalwart 中，速率限制可確保高效管理電子郵件流量，防止資源過度使用，並保護伺服器免受垃圾郵件或拒絕服務攻擊等濫用行為的侵害。

 Stalwart enforces rate limits on both inbound and outbound connections. Inbound limits apply to connections from remote servers on standard ports \(such as 25 and 465\) and help regulate the flow of incoming messages. Outbound limits apply to connections initiated by the queue when delivering messages to remote hosts, and help manage outgoing traffic volume so that external systems are not overwhelmed.

 Stalwart 對入站和出站連線都實施速率限制。入站限制適用於來自遠端伺服器的標準連接埠（例如 25 和 465）連接，有助於調節傳入訊息的流量。出站限制適用於佇列在向遠端主機傳遞訊息時發起的連接，有助於管理出站流量，避免外部系統過載。

 In distributed environments, rate limiters are shared across the whole cluster and stored in the default in-memory store for low-latency access and efficient synchronisation across nodes.

 在分散式環境中，速率限制器在整個叢集中共享，並儲存在預設的記憶體儲存中，以實現低延遲存取和跨節點的高效同步。

## Inbound limits｜入站限制

 Inbound rate limits regulate the flow of incoming connections and messages from remote servers. They mitigate spam campaigns, denial-of-service attempts, and routing loops.

 入站速率限制用於調節來自遠端伺服器的傳入連線和訊息流量。它們可以緩解垃圾郵件活動、拒絕服務攻擊和路由循環。

 When an inbound rate limit is exceeded, additional messages are rejected with a `451 4.4.5 Rate limit exceeded, try again later.` error. This temporary rejection prevents server overload while signalling the remote sender to retry later. Rejection continues until the rate-limiter window resets.

 當入站速率超過限制時，後續訊息將被拒絕，並回傳`451 4.4.5 Rate limit exceeded, try again later.`錯誤。這種臨時拒絕機制可以防止伺服器過載，同時通知遠端發送方稍後重試。拒絕操作會持續進行，直到速率限制視窗重置。

 Inbound rate limits are defined as MtaInboundThrottle objects \(found in the WebUI under Settings › MTA › Rates & Quotas › Inbound Rate Limits\).

 入站速率限制定義為 MtaInboundThrottle物件（可在 WebUI 的「設定 › MTA › 速率與配額 › 入站速率限制」中找到\)。

## Outbound limits｜出站限額

 Outbound rate limits regulate the flow of connections and messages initiated by Stalwart to deliver mail to remote systems. Unlike inbound rate limits, outbound rate limiting does not reject or discard messages: when the limit is reached, affected messages remain in the queue until the window resets, at which point delivery resumes according to the configured retry schedule.

 出站速率限制用於控制 Stalwart 發起的連線和訊息流，以便將郵件傳送到遠端系統。與入站速率限制不同，出站速率限制不會拒絕或丟棄訊息：當達到限制時，受影響的訊息會保留在佇列中，直到時間視窗重置，屆時將根據配置的重試計畫恢復傳送。

 Outbound rate limits are defined as MtaOutboundThrottle objects \(found in the WebUI under Settings › MTA › Rates & Quotas › Outbound Rate Limits\).

 出站速率限制定義為 MtaOutboundThrottle物件（可在 WebUI 的「設定」› MTA › 速率與配額 › 出站速率限制 中找到）。

## Settings｜設定

 Both MtaInboundThrottle and MtaOutboundThrottle expose the same core fields:

 MtaInboundThrottle 和 MtaOutboundThrottle 都公開相同的核心欄位：

- enable: whether the throttle is active. Default `true`.
enable : 油門是否處於作用中。預設值為`true` 。
- rate: the rate limit itself, a `Rate` object with `count` \(requests allowed\) and `period` \(time window, in milliseconds\).
rate : 速率限製本身，一個`Rate`對象，包含`count` （允許的請求）和`period` （時間窗口，以毫秒為單位）。
- key: optional set of context variables that scope the limit \(see [Groups](#groups) below\).
key : 可選的上下文變數集，用於限定限制範圍（請參閱下方的 [Groups](#groups) ）。
- match: optional expression that determines whether the limit applies in a given context.
match : 可選表達式，用於確定限制是否適用於給定的上下文。
- description: short description used for identification \(required on MtaOutboundThrottle, read-only on MtaInboundThrottle\).
description : 用於識別的簡短描述（MtaOutboundThrottle 上為必填項，MtaInboundThrottle 上為唯讀項）。
A throttle with an empty `key` applies globally. For example, an outbound throttle allowing at most 100 outgoing messages per second across all destinations:
`key`為空的節流閥全域生效。例如，出站節流閥允許每秒最多向所有目標發送 100 個出站訊息：

```json
{
  "enable": true,
  "description": "Global outbound cap",
  "key": {},
  "match": {"else": "true"},
  "rate": {"count": 100, "period": 1000}
}
```

Values on this page follow the object encoding rules: list and set fields are JSON objects rather than arrays, and durations and sizes are integers.

 本頁上的值遵循 物件編碼規則：列表和集合字段是JSON物件而不是數組，持續時間和大小是整數。

### Groups｜團體

 The `key` field scopes a limit to specific combinations of context variables. Available keys differ between inbound and outbound throttles.

`key`字段限制了上下文變數的特定組合。入站和出站限流的可用鍵有所不同。

 For outbound throttles \(MtaOutboundThrottleKey\):

 對於出站限速（MtaOutboundThrottleKey ）：

- `remoteIp`: remote IP address.
`remoteIp` ：遠端IP位址。
- `localIp`: local IP address \(only available when a source IP is configured\).
`localIp` : 本地IP位址（僅當配置了 來源IP時可用）。
- `mx`: remote MX hostname.
`mx` : 遠端MX主機名稱。
- `sender`: return path specified in `MAIL FROM`.
`sender` : 返回`MAIL FROM`中指定的路徑。
- `senderDomain`: domain component of the return path.
`senderDomain` ：返迴路徑的域組件。
- `rcptDomain`: domain component of the recipient address.
`rcptDomain` ：收件人地址的域組成部分。
For inbound throttles \(MtaInboundThrottleKey\):
 對於入站節流閥（MtaInboundThrottleKey ）：

- `listener`: identifier of the listener that received the connection.
`listener` ：接收已連接的監聽器的識別碼。
- `remoteIp`: IP address of the client.
`remoteIp`: IP客戶端位址。
- `localIp`: local IP address.
`localIp` : 本地IP地址。
- `authenticatedAs`: username used for authentication.
`authenticatedAs` ：用於身份驗證的使用者名稱。
- `heloDomain`: domain supplied in the `EHLO` command.
`heloDomain` ： `EHLO`指令中提供的域。
- `sender`: return path specified in `MAIL FROM`.
`sender` : 返回`MAIL FROM`中指定的路徑。
- `senderDomain`: domain component of the return path.
`senderDomain` ：返迴路徑的域分量。
- `rcpt`: recipient address specified in `RCPT TO`.
`rcpt` : `RCPT TO`中指定的收件人地址。
- `rcptDomain`: domain component of the recipient address.
`rcptDomain` ：收件人地址的域組成部分。
For example, an outbound throttle limiting to 25 messages per hour per recipient domain:
 例如，設定出站限流，將每個收件者網域每小時發送的訊息數量限制為 25 條：

```json
{
  "enable": true,
  "description": "Per recipient domain throttle",
  "key": {"rcptDomain": true},
  "match": {"else": "true"},
  "rate": {"count": 25, "period": 3600000}
}
```

And an inbound throttle limiting a single sending domain to 6 messages per minute to any given recipient:

 此外，還設定了入站限流，將單一發送域每分鐘向任何給定收件人發送的訊息數量限制為 6 條：

```json
{
  "enable": true,
  "key": {"senderDomain": true, "rcpt": true},
  "match": {"else": "true"},
  "rate": {"count": 6, "period": 60000}
}
```

### Conditional limits｜條件限制

 The `match` expression can restrict a throttle to specific contexts. For example, an outbound throttle imposing a per-sender-per-recipient-domain limit only when mail is destined for IP `192.0.2.20`:

`match`表達式可以將限流限制在特定上下文中。例如，出站限流僅當郵件發送至IP `192.0.2.20`時才對每個寄件者每個收件者網域施加限制：

```json
{
  "enable": true,
  "description": "Throttle deliveries routed via 192.0.2.20",
  "key": {"sender": true, "rcptDomain": true},
  "match": {"else": "remote_ip == '192.0.2.20'"},
  "rate": {"count": 100, "period": 3600000}
}
```

And an inbound throttle imposing a per-recipient limit only for connections from `192.0.2.25`:

 並且對來自`192.0.2.25`的連接施加入站限流，限制每個接收者的流量：

```json
{
  "enable": true,
  "key": {"rcpt": true},
  "match": {"else": "remote_ip == '192.0.2.25'"},
  "rate": {"count": 5, "period": 3600000}
}
```
