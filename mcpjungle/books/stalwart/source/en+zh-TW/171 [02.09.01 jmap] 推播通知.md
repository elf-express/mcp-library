# Push notifications｜推播通知

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[http\\\]\\\(&lt;000 目錄.md#c-26&gt;\\\) › \\\[jmap\\\]\\\(&lt;000 目錄.md#c-27&gt;\\\)

Push notifications allow JMAP clients to receive updates almost immediately and stay in sync with data changes on the server. Stalwart supports two mechanisms:

 推播通知允許JMAP客戶端幾乎立即接收更新，並與伺服器上的資料變更保持同步。 Stalwart支援兩種機制：

- Event source: clients hold a long-lived HTTP connection open and receive notifications directly from the server over a `text/event-stream` channel.
事件來源：客戶端保持長時間的HTTP連線打開，並透過`text/event-stream`通道直接從伺服器接收通知。
- Push subscriptions: clients register an external push service URL with the server. Each state change produces an HTTP POST to that URL, and the push service is responsible for delivering the notification to the client.
推播訂閱：客戶端向伺服器註冊外部推播服務URL 。每次狀態變更都會向該URL產生一個HTTP POST ，推播服務負責將通知傳遞給客戶端。
Push and event-source settings are carried on the Jmap singleton \(found in the WebUI under Settings › Network › JMAP › Limits, Settings › Network › JMAP › Push, Settings › Network › JMAP › WebSocket\).
 推送與事件來源設定保存在 Jmap單例中（在 WebUI 的「設定 › 網路 › JMAP › 限制」、「設定 › 網路 › JMAP › 推送」與「設定 › 網路 › JMAP Web」 › ›P.

## Push Subscriptions｜推送訂閱

 JMAP clients activate push subscriptions by registering a push service URL with the server. Each notification is sent to that URL over HTTPS. For additional privacy, clients can enable [web push encryption](https://datatracker.ietf.org/doc/html/rfc8291) by supplying Elliptic Curve Diffie-Hellman \(ECDH\) public keys during registration.

 客戶JMAP透過向伺服器註冊URL服務來啟動推播訂閱。每條通知都會透過URL傳送到該HTTPS ECDH \([https://datatracker.ietf.org/doc/html/rfc8291\)公鑰來啟用](https://datatracker.ietf.org/doc/html/rfc8291%2529%2525E5%252585%2525AC%2525E9%252591%2525B0%2525E4%2525BE%252586%2525E5%252595%25259F%2525E7%252594%2525A8) \[Web 推送加密\]。

 The push subsystem is tuned through the following fields:

 推送子系統透過以下欄位進行調整：

- pushThrottle: minimum time to wait between successive requests to the same push service. Default `"1s"`.
pushThrottle : 向同一推送服務發出連續請求之間的最短等待時間。預設值為`"1s"` 。
- pushMaxAttempts: maximum number of delivery attempts before a notification is discarded. Default `3`.
pushMaxAttempts : 通知被丟棄前的最大投遞嘗試次數。預設值為`3` 。
- pushAttemptWait: time to wait between delivery attempts. Default `"1m"`.
pushAttemptWait : 兩次投遞嘗試之間的等待時間。預設值為`"1m"` 。
- pushRetryWait: time to wait between retries. Default `"1s"`.
pushRetryWait : 重試之間的等待時間。預設值為`"1s"` 。
- pushRequestTimeout: time after which a connection to the push service URL is considered timed out. Default `"10s"`.
pushRequestTimeout : 與推播服務URL的連線逾時時間。預設值為`"10s"` 。
- pushVerifyTimeout: time to wait for the push service to verify a new subscription. Default `"1m"`.
pushVerifyTimeout : 等待推播服務驗證新訂閱的時間。預設值為`"1m"` 。
## Event Source｜事件來源

 JMAP clients that can hold transport connections open connect directly to Stalwart and receive push notifications through a `text/event-stream` resource, as described in the [event source specification](https://html.spec.whatwg.org/multipage/server-sent-events.html#server-sent-events). This is a long-running HTTP request during which the server can append data to the response without terminating it.

 能夠保持傳輸連線開啟JMAP用戶端可以直接連線到 Stalwart，並透過 \[事件來源規格\] 中所述的資源接收`text/event-stream`通知。這是一個長時間運行HTTP請求\([https://html.spec.whatwg.org/multipage/server-sent-events.html#server-sent-events\)在此期間伺服器可以向回應追加資料而不終止該請求。](https://html.spec.whatwg.org/multipage/server-sent-events.html#server-sent-events%2529%2525E5%25259C%2525A8%2525E6%2525AD%2525A4%2525E6%25259C%25259F%2525E9%252596%252593%2525E4%2525BC%2525BA%2525E6%25259C%25258D%2525E5%252599%2525A8%2525E5%25258F%2525AF%2525E4%2525BB%2525A5%2525E5%252590%252591%2525E5%25259B%25259E%2525E6%252587%252589%2525E8%2525BF%2525BD%2525E5%25258A%2525A0%2525E8%2525B3%252587%2525E6%252596%252599%2525E8%252580%25258C%2525E4%2525B8%25258D%2525E7%2525B5%252582%2525E6%2525AD%2525A2%2525E8%2525A9%2525B2%2525E8%2525AB%25258B%2525E6%2525B1%252582%2525E3%252580%252582)

 The event source endpoint is listed in the JMAP Session resource object \(`/.well-known/jmap`\) and is available at `/jmap/eventsource/?types={types}&closeafter={closeafter}&ping={ping}`.

 事件來源端點列於JMAP會話資源物件 \( `/.well-known/jmap` \) 中，並可在`/jmap/eventsource/?types={types}&closeafter={closeafter}&ping={ping}`存取。

 To avoid overwhelming the client, the server groups updates and delivers them at a configurable cadence controlled by eventSourceThrottle. Default `"1s"`.

 為了避免客戶端不堪重負，伺服器將更新分組，並以可配置的節奏交付它們，該節奏由 eventSourceThrottle控制。預設`"1s"` 。
