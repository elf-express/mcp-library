# Rate limiting｜限速

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[email｜電子郵件\\\]\\\(&lt;000 目錄.md#c-22&gt;\\\) › \\\[settings｜設定\\\]\\\(&lt;000 目錄.md#c-24&gt;\\\)

Rate limiting is a strategy to limit network traffic by capping how often a given action \(for example, a login attempt\) can be repeated within a time window. Rate limiting helps mitigate abuse such as brute-force attacks and reduces load on the mail server.

 速率限制是一種透過限制特定操作（例如登入嘗試）在一定時間視窗內重複次數來限製網路流量的策略。速率限制有助於減少暴力破解攻擊等濫用行為，並降低郵件伺服器的負載。

## IMAP/POP3

 IMAP and POP3 rate-limit fields live on the Imap singleton \(found in the WebUI under Settings › Network › IMAP\).

 IMAP和POP3速率限製欄位位於 Imap單例中（可在 WebUI 的「設定 › 網路 › IMAP 」下找到）。

### Concurrency｜並發性

 The maximum number of concurrent IMAP and POP3 connections a user may hold is set by maxConcurrent. The default is `16`; lowering it, for example to four connections per user:

 使用者可同時持有的IMAP和POP3連接數的最大值由 maxConcurrent設定。預設值為`16` ；降低此值，例如，每位使用者最多可持有四個連線：

```json
{
  "maxConcurrent": 4
}
```

### Requests｜請求

 The per-minute request cap is set by maxRequestRate, which takes a `Rate` value of `count` and `period`, where `period` is a duration in milliseconds. The default is 2000 requests per minute.

 每分鐘請求上限由 maxRequestRate設定，其`Rate`值取`count`和`period` ，其中`period`是以毫秒為單位的持續時間。預設值為每分鐘 2000 個請求。

 For example, to allow 2000 requests per minute:

 例如，允許每分鐘 2000 次請求：

```json
{
  "maxRequestRate": {"count": 2000, "period": 60000}
}
```

## JMAP

 Refer to the JMAP Protocol limits page for details on how JMAP request limits and concurrency are configured on the Jmap singleton.

 有關如何在 Jmap單例上配置JMAP請求限制和並發的詳細信息，請參閱 JMAP協議限制頁面。
