# Configuration｜配置

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[proxy｜代理人\\\]\\\(&lt;000 目錄.md#c-42&gt;\\\)

The proxy is configured by a single TOML file whose path is given on the command line or in the `PROXY_CONFIG` environment variable. The file is parsed and validated in full at startup, and the proxy will not begin serving if validation fails. Validation is strict by design: it checks that every listener references a protocol the default destination actually offers, that credential-bearing protocols are not exposed over plaintext without an explicit override, that TLS legs to IP-addressed backends carry a server name, and that the selected mapping source has its corresponding configuration section. The intent is that a configuration which passes validation cannot misroute or leak credentials at runtime through a simple omission.

 代理伺服器透過一個單獨的TOML檔案進行配置，該檔案的路徑可透過命令列或`PROXY_CONFIG`環境變數指定。啟動時，系統會完整解析並驗證該文件，如果驗證失敗，代理伺服器將不會開始服務。驗證機制設計得非常嚴格：它會檢查每個監聽器是否引用了預設目標伺服器實際提供的協議，是否在未明確覆蓋的情況下以明文形式暴露包含憑證的協議，是否指向IP地址後端伺服器的TLS鏈路包含伺服器名稱，以及所選映射來源是否具有相應的配置部分。這樣做的目的是確保即使配置通過了驗證，也不會因為簡單的疏忽而在運行時導致憑證錯誤路由或洩漏。

 This page covers the global server options and inbound TLS termination. The remaining areas have dedicated pages: backend destinations, listeners, mappings and routing.

 本頁涵蓋全域伺服器選項和入站TLS終止。其餘區域有專門的頁面：後端目標 、監聽器 、映射和路由 。

## File layout｜文件佈局

 A configuration file is composed of a small number of top-level tables. The `[server]` table holds process-wide tuning, `[tls]` defines inbound certificates and protocol policy, `[listener.*]` tables declare the sockets the proxy accepts on, `[destination.*]` tables describe the backends, `[routing]` and `[mapping]` control how accounts are resolved to destinations, `[capabilities.*]` customize what the proxy advertises to clients, `[http.route]` entries govern HTTP routing, and an optional `[admin]` table enables the management API. A complete annotated example is provided under Examples.

 配置檔案由少量頂級表組成。 `[server]` 表格包含全流程調優訊息， `[tls]` 定義入站憑證和協定策略， `[listener.*]` 表格聲明代理接受的套接字， `[destination.*]` 表格描述了後端， `[routing]` 和 `[mapping]` 控制帳戶如何解析到目標位置， `[capabilities.*]` 自訂代理向客戶端宣傳的內容， `[http.route]` 條目管理 HTTP 路由，以及可選的 `[admin]` 表格支援管理 API\[範例\] 部分提供了一個完整的註釋的範例。\([https://stalw.art/docs/migration/proxy/examples/](https://stalw.art/docs/migration/proxy/examples/)\).

## Server options｜伺服器選項

 The `[server]` table is optional; every key has a default, so an empty table or none at all yields a sensible configuration. The available keys are:

`[server]`表是可選的；每個鍵都有一個預設值，因此空表或不建立表也能得到合理的配置。可用鍵如下：

| Key 鍵 | Default 預設值 | Description 描述 |
| --- | --- | --- |
| `threads` | `0` | Number of worker threads in the async runtime. `0` uses one per available CPU core. 非同步運行時中的工作執行緒數。 `0` 每個可用的 CPU 核心使用一個。 |
| `hostname` | unset 未設定 | Hostname the proxy presents in SMTP greetings and forwarded metadata. When unset, the local socket address is used. 代理在SMTP問候語和轉送的元資料中顯示的主機名稱。如果未設置，則使用本機套接字位址。 |
| `shutdown_grace` | `30s` | Time allowed for active connections to drain after a shutdown signal before the process exits. 進程退出前，在收到關閉訊號後，允許活動連線耗盡的時間。 |
| `bridge_idle` | `1800s` | Maximum idle time on an established bridged session before it is closed. 已建立的橋接會話在關閉前的最大空閒時間。 |
| `backend_timeout` | `10s` | Time limit for establishing and authenticating a backend connection. 建立並驗證後端連線的時限。 |
| `backend_connect_retries` | `1` | Number of additional attempts for a retryable backend connection failure. 可重試後端連線失敗的額外嘗試次數。 |
| `host_down_threshold` | `5` | Consecutive backend failures after which a destination is marked down. `0` disables the circuit breaker. 連續的後端故障，之後目的地被標記為關閉。 `0` 禁用斷路器。 |
| `host_down_min_clients` | `2` | Number of distinct client addresses a failure streak must span before failures that occurred after the backend saw the client can mark a destination down. `0` removes the requirement. 在後端發現客戶端可以將目標標記為關閉後發生故障之前，故障條紋必須跨越的不同客戶端位址的數量。 `0` 刪除了該要求。 |
| `host_down_cooldown` | `30s` | Duration a destination stays marked down before the next connection is allowed to probe it. 目標位址被標記後，下一個連接才能偵測到該位址的持續時間。 |
| `proxy_ttl` | `7` | Initial forwarding time-to-live, decremented at each hop, used to detect proxy loops. 初始轉送存活時間，每次躍點遞減，用於偵測代理迴路。 |
| `log_level` | `info` | Tracing verbosity. Overridden by the `RUST_LOG` environment variable when set. 追蹤詳細程度。當設定了`RUST_LOG`環境變數時，此設定將被覆蓋。 |

Durations are written as a number followed by a unit: `ms`, `s`, `m`, `h` or `d`. For example, `shutdown_grace = "45s"` or `bridge_idle = "1h"`.

 持續時間以數字加單位的形式表示： `ms`, `s`, `m`, `h`或`d` 。例如， `shutdown_grace = "45s"`或`bridge_idle = "1h"` 。

 The `bridge_idle` value applies to the data-transfer phase of a session and should be set high enough to accommodate long-lived IMAP `IDLE` connections. The `backend_timeout`, retry and circuit-breaker settings shape how the proxy reacts when a backend is slow or unavailable; their interaction with backend health is described under Destinations.

`bridge_idle` 值適用於會話的資料傳輸階段，並且應設定得足夠高以容納長期的 IMAP `IDLE` 連接。 `backend_timeout`、重試和斷路器設定決定了代理在後端緩慢或不可用時的反應方式；它們與後端健康狀況的交互在目的地下描述。

## Inbound TLS｜入站TLS

 The proxy terminates TLS for clients on listeners configured with implicit TLS or STARTTLS. Inbound certificates are declared as named entries under `[tls.certificate.*]`, and the cryptographic policy is set under `[tls.protocols]`.

 對於配置了隱式TLS或STARTTLS監聽器上的客戶端，代理程式會終止TLS 。入站證書在`[tls.certificate.*]`下宣告為命名條目，加密策略在`[tls.protocols]`下設定。

### Certificates｜證書

 Each certificate entry names a PEM-encoded certificate chain and private key, and optionally the subject names it should serve and whether it is the default:

 每個憑證條目都指定一個PEM編碼的憑證鍊和私鑰，也可以選擇性地指定它應該服務的主題名稱以及它是否為預設主題：

```toml
[tls.certificate.primary]
cert = "/etc/proxy/tls/fullchain.pem"
key = "/etc/proxy/tls/privkey.pem"
subjects = ["mail.example.com", "*.example.com"]
default = true
```

The `cert` file must contain the leaf certificate followed by any intermediate certificates; the `key` file holds the matching private key. The `subjects` list declares the hostnames the certificate answers for during the TLS handshake. When `subjects` is omitted, the proxy reads the subject alternative names \(or, failing that, the common name\) directly from the certificate, so an explicit list is only needed to override what the certificate itself declares. Setting `default = true` marks the certificate as the catch-all presented when no other entry matches the requested name.

`cert` 檔案必須包含葉證書，後面跟著任何中間證書； `key` 檔案保存相符的私鑰。 `subjects` 清單宣告憑證在 TLS 握手期間應答的主機名稱。當省略 `subjects` 時，代理直接從憑證中讀取主題備用名稱（或者，如果失敗，則讀取公用名稱），因此只需要一個明確清單來覆蓋憑證本身聲明的內容。設定 `default = true` 將憑證標記為當沒有其他條目與請求的名稱相符時呈現的包羅萬象的憑證。

 Multiple certificates may be declared, and the proxy selects one per connection using the Server Name Indication the client sends. Selection proceeds from most to least specific: an exact match on the requested name is preferred, then a match on the parent domain \(so a certificate registered for `example.com` serves `host.example.com`\), then the entry marked `default`. If only a single certificate is configured it is used for every connection regardless of the requested name. When nothing matches and no default is set, the proxy presents an internally generated self-signed certificate, which allows the handshake to complete but will not be trusted by clients; production deployments should always configure a real certificate and a default.

 可以聲明多個證書，代理伺服器會根據客戶端傳送的伺服器名稱指示 \(SNI\) 為每個連線選擇一個證書。選擇順序從最精確到最不精確：首先是請求名稱完全匹配的證書，其次是父域匹配的證書（例如，註冊到`example.com`的證書可用於`host.example.com` ），最後是標記為`default`的證書。如果只配置了一個證書，則無論請求名稱為何，每個連線都會使用該證書。如果沒有匹配項且未設定預設值，代理伺服器會提供一個內部產生的自簽名證書，該證書允許握手完成，但用戶端不會信任該證書；生產環境部署應始終配置一個真實證書和一個預設值。

 A wildcard entry registered under the name `*` \(or a certificate marked `default`\) acts as the fallback for unmatched names.

 以`*`為名註冊的通配符條目（或標記為`default`的證書）用作未匹配名稱的備用方案。

### Protocol policy｜協議政策

 The `[tls.protocols]` table tunes the handshake policy applied to all inbound TLS:

`[tls.protocols]`表調整應用於所有入站TLS握手策略：

```toml
[tls.protocols]
min_version = "1.2"
ignore_client_order = false
disable_cipher_suites = []
```

`min_version` accepts `"1.2"` or `"1.3"`; the default of `"1.2"` enables both TLS 1.2 and 1.3, while `"1.3"` restricts the proxy to TLS 1.3 only. `ignore_client_order`, when set to `true`, makes the server’s cipher-suite preference order take precedence over the client’s. `disable_cipher_suites` is a list of cipher-suite names to remove from the negotiated set, identified by their standard names; removing every available suite is rejected at startup.

`min_version`接受`"1.2"`或`"1.3"`；預設值 `"1.2"` 同時啟用 TLS 1.2 和 1.3，而 `"1.3"` 僅將代理限制為 TLS 1.3。 `ignore_client_order`，當設定為`true`時，使伺服器的密碼套件優先順序優先於客戶端的。 `disable_cipher_suites` 是要從協商集中刪除的密碼套件名稱列表，由其標準名稱標識；啟動時會拒絕刪除所有可用套件。

 TLS on the legs from the proxy to each backend is configured independently, per destination, and is covered under Destinations.

 從代理到每個後端的鏈路上的TLS是按目的地獨立配置的，並在 目的地下涵蓋。

## Environment overrides｜環境變數覆蓋

 A few environment variables influence startup independently of the configuration file. `PROXY_CONFIG` supplies the configuration path when no command-line argument is given. `RUST_LOG` overrides `server.log_level` with a tracing filter expression. `PROXY_ADMIN_TOKEN` supplies the management API bearer token and takes precedence over the token configured in the `[admin]` table. These are described in context under Management.

 一些環境變數獨立於設定檔影響啟動。 `PROXY_CONFIG` 在未給出命令列參數時提供配置路徑。 `RUST_LOG` 使用追蹤過濾器表達式覆寫 `server.log_level`。 `PROXY_ADMIN_TOKEN` 提供管理API 承載令牌，並優先於`[admin]` 表中配置的令牌。這些在管理下的上下文中進行了描述。
