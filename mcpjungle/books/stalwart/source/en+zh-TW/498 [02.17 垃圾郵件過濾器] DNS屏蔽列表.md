# DNS blocklists｜DNS屏蔽列表

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[spamfilter｜垃圾郵件過濾器\\\]\\\(&lt;000 目錄.md#c-69&gt;\\\)

In email security and spam filtering, two widely used tools are DNSBL \(DNS-based Block List\) and DNSWL \(DNS-based Allowlist\). Both are maintained by external organisations and updated continuously to reflect the latest information about spam and malicious activity. The lists are queried over DNS, so lookups are fast and cacheable, and are used to decide whether to accept, reject, or further scrutinise an incoming message.

 在電子郵件安全和垃圾郵件過濾領域，兩種廣泛使用的工具是DNSBL （基於DNS的黑名單）和DNSWL （基於DNS的白名單）。兩者都由外部組織維護，並持續更新以反映最新的垃圾郵件和惡意活動資訊。這些清單透過DNS進行查詢，因此查詢速度快且可緩存，並用於決定是否接受、拒絕或進一步審查收到的郵件。

 A **DNSBL** lists IP addresses or domain names known to be sources of spam, malicious activity, or other undesirable content. When a message is received, the mail server queries the DNSBL to determine whether the sender appears on any of the lists. A positive match can cause the message to be flagged, rejected, or subjected to additional checks, depending on configuration.

**DNSBL** 清單列出了已知是垃圾IP 、惡意活動或其他不良內容來源的地址或網域名稱。當收到郵件時，郵件伺服器會查詢DNSBL以確定寄件者是否出現在任何清單中。如果符合成功，則郵件可能會被標記、拒絕或接受額外的檢查，具體取決於配置。

 A **DNSWL** is the converse: a list of trusted IP addresses or domain names known to send legitimate email. Querying a DNSWL allows the mail server to identify and prioritise messages from reputable senders, reducing false positives.

**DNSWL** 則相反：它是一個可信的IP地址或域名列表，這些地址或域名已知會發送合法的電子郵件。查詢DNSWL可以讓郵件伺服器識別並優先處理來自信譽良好的寄件者的郵件，從而減少誤報。

 The following DNSBL checks are performed by Stalwart:

 Stalwart 執行以下DNSBL檢查：

- **IP address**: the reputation of the remote host, as well as of every IP address found in the `Received` headers of a message, is verified against configured lists. Checking the full received chain improves the accuracy of spam detection and reduces the risk of legitimate messages being misclassified.
**IP位址**：系統會根據配置的清單驗證遠端主機以及郵件`Received`標頭中找到的每個IP位址的信譽度。檢查完整的接收鏈可以提高垃圾郵件偵測的準確性，並降低將合法郵件誤判為垃圾郵件的風險。
- **Domain**: domain names extracted from incoming messages are checked against DNS-based block and allow lists.
**網域**：從傳入訊息中提取的網域名稱將與基於DNS的封鎖清單和允許清單進行檢查。
- **URL**: URLs embedded in messages are checked against URL-oriented blocklists to identify malicious links.
**URL**：訊息中嵌入的 URL 將根據URL方向的阻止清單進行檢查，以識別惡意連結。
- **Hashes**: hashes of specific components of the message are checked against hash-based blocklists, so that threats can be identified even when senders slightly modify their tactics or domain names.
**雜湊值**：將訊息特定組成部分的雜湊值與基於雜湊值的黑名單進行比對，以便即使寄件者稍微修改其策略或域名，也能識別威脅。
## DNSBL checks｜DNSBL檢查

 Each DNSBL check is defined as a SpamDnsblServer object \(found in the WebUI under Settings › Spam Filter › DNSBL › Servers\). This is a multi-variant object: the variant selects which part of the message the DNSBL applies to \(`Ip`, `Domain`, `Url`, `Email`, `Header`, `Body`, or `Any`\).

 每個DNSBL檢查都被定義為一個 SpamDnsblServer物件（可在 WebUI 的「設定」&gt;「垃圾郵件過濾器」&gt; DNSBL &gt;「伺服器」下找到）。這是一個多變體物件：變體選擇DNSBL應用於郵件的哪個部分（ `Ip`, `Domain`, `Url`, `Email`, `Header`, `Body`或`Any` ）。

 Each SpamDnsblServer instance carries:

 每個 SpamDnsblServer 實例都包含：

- enable: whether the server is active.
enable : 伺服器是否處於作用中狀態。
- zone: an Expression that evaluates to the DNS zone to query. If the expression evaluates to `false`, the DNSBL server is skipped for that message.
zone : 一 Expression ，其計算結果為要查詢的DNS區域。如果表達式的計算結果為`false` ，則對於該訊息，將跳過DNSBL伺服器。
- tag: an Expression that evaluates to the tag to apply to the message based on the DNS query result. If the expression evaluates to `false`, no tag is applied.
tag : a Expression ，其計算結果為根據DNS查詢結果應用於訊息的標籤。若表達式的計算結果為`false` ，則不套用任何標籤。
Example reproducing the Mailspike IP DNSBL using the `Ip` variant:
 使用`Ip`變體重現 Mailspike IP DNSBL的範例：

```json
{
  "@type": "Ip",
  "name": "STWT_RBL_MAILSPIKE_IP",
  "enable": true,
  "zone": {
    "match": {"0": {"if": "location == 'tcp'", "then": "ip_reverse + '.rep.mailspike.net'"}},
    "else": "false"
  },
  "tag": {
    "match": {
      "0": {"if": "octets[0] != 127", "then": "false"},
      "1": {"if": "octets[3] == 10", "then": "'RBL_MAILSPIKE_WORST'"},
      "2": {"if": "octets[3] == 11", "then": "'RBL_MAILSPIKE_VERYBAD'"},
      "3": {"if": "octets[3] == 12", "then": "'RBL_MAILSPIKE_BAD'"},
      "4": {"if": "octets[3] >= 13 && octets[3] <= 16", "then": "'RWL_MAILSPIKE_NEUTRAL'"},
      "5": {"if": "octets[3] == 17", "then": "'RWL_MAILSPIKE_POSSIBLE'"},
      "6": {"if": "octets[3] == 18", "then": "'RWL_MAILSPIKE_GOOD'"},
      "7": {"if": "octets[3] == 19", "then": "'RWL_MAILSPIKE_VERYGOOD'"},
      "8": {"if": "octets[3] == 20", "then": "'RWL_MAILSPIKE_EXCELLENT'"}
    },
    "else": "false"
  }
}
```

## Core DNSBL servers｜核心DNSBL伺服器

 Stalwart ships a set of predefined DNSBL server definitions maintained by Stalwart Labs. These are identified by a name starting with `STWT_` and cover Spamhaus, Spamcop, Barracuda, and dozens of other popular providers. Core DNSBL servers are regularly updated to remain effective against the latest threat sources.

 Stalwart 提供一套由 Stalwart Labs 維護的預先定義DNSBL伺服器定義。這些伺服器定義以`STWT_`開頭，涵蓋 Spamhaus、Spamcop、Barracuda 以及數十家其他熱門服務供應商。核心DNSBL伺服器定義會定期更新，以有效抵禦最新的威脅來源。

 The latest version of the core list is maintained in the [Spam Filter repository](https://github.com/stalwartlabs/spam-filter). Stalwart can be configured to download and apply the latest definitions automatically; see updates.

 核心清單的最新版本保存在 [垃圾郵件過濾器儲存庫](https://github.com/stalwartlabs/spam-filter)中。 Stalwart 可以設定為自動下載和​​套用最新定義；請參閱 更新 。

 Core definitions should not be modified directly, because any changes are overwritten on the next update. The only safe in-place modification is toggling enable on a core entry, which is preserved across updates. To apply custom behaviour beyond enabling or disabling a core entry, disable the core server and create a custom SpamDnsblServer with the desired values.

 核心定義不應直接修改，因為任何變更都會在下次更新時被覆寫。唯一安全的就地修改方法是切換核心條目上的 enable ，這樣修改會在更新後保留。若要套用啟用或停用核心條目之外的自訂行為，請停用核心伺服器並建立具有所需值的自訂 SpamDnsblServer。

 For example, to disable a core entry and add a custom server:

 例如，要停用核心條目並新增自訂伺服器：

```json
{
  "@type": "Ip",
  "name": "STWT_DNSBL_SERVER",
  "enable": false
}
```

```json
{
  "@type": "Ip",
  "name": "STWT_MY_DNSBL_SERVER",
  "enable": true,
  "zone": {"else": "zone expression"},
  "tag": {"else": "tag expression"}
}
```

This keeps customisations intact while still benefiting from ongoing updates to the core list.

 這樣既能保持自訂設定不變，又能受益於核心清單的持續更新。

## Limits｜限制

 The maximum number of DNSBL queries that can be performed per message is configured on the SpamDnsblSettings singleton \(found in the WebUI under Settings › Spam Filter › DNSBL › Settings\). The per-message limits are:

 每個郵件可執行的最大DNSBL查詢次數在 SpamDnsblSettings單例中配置（可在 WebUI 的「設定」&gt;「垃圾郵件過濾器」&gt; DNSBL ”&gt;「設定」中找到）。每封郵件的限制如下：

- ipLimit: maximum number of IP address queries.
ipLimit : IP地址查詢的最大次數。
- domainLimit: maximum number of domain name queries.
domainLimit : 網域查詢的最大數量。
- emailLimit: maximum number of email address queries.
emailLimit : 電子郵件地址查詢的最大數量。
- urlLimit: maximum number of URL queries.
urlLimit : URL查詢的最大數量。
All four limits default to 50.
 這四個限制的預設值均為 50。
