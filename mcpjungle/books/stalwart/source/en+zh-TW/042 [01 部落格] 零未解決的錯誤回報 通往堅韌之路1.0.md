## Zero open bug reports: The road to Stalwart 1.0｜零未解決的錯誤回報：通往堅韌之路1.0

 Today we released [Stalwart v0.16.10](https://github.com/stalwartlabs/stalwart/releases), and it comes with a milestone we have been working toward for a while: as of today, there are no open bug reports for Stalwart. This release fixes every reported bug we have on record, both the legacy issues that had accumulated on [GitHub](https://github.com/stalwartlabs/stalwart/issues) and the reports submitted through our new [support portal](https://support.stalw.art/).

 今天我們發布了 [Stalwart v0.16.10](https://github.com/stalwartlabs/stalwart/releases) ，並實現了我們長期以來一直努力的目標：截至今日，Stalwart 已無任何未解決的錯誤報告。此版本修復了我們記錄在案的所有已報告錯誤，包括 [GitHub](https://github.com/stalwartlabs/stalwart/issues)上累積的遺留問題以及透過我們新的 [支援入口網站](https://support.stalw.art/)提交的報告。

 We want to be precise about what this means, because it is easy to misread. It does not mean Stalwart is bug free. No non-trivial piece of software is, and we would not claim otherwise. What it means is narrower: as of today there are no open bug reports awaiting a fix. Every issue that a user took the time to report has been triaged and resolved. New reports will arrive, and we will keep working through them, but for now the queue is empty.

 我們希望明確說明這句話的意思，因為它很容易被誤解。這並不意味著 Stalwart 完全沒有 bug。任何一款像樣的軟體都不可能完美無缺，我們也不會這樣宣稱。這句話的意思更具體一些：截至目前，所有待修復的 bug 報告都已處理完畢。用戶提交的每一個問題都經過了分類和解決。我們會繼續處理新的報告，但目前隊列是空的。

 That leaves 108 issues still open on the [GitHub tracker](https://github.com/stalwartlabs/stalwart/issues). These are not bugs. They are minor feature enhancements and requests: refinements, quality-of-life additions, and ideas worth keeping on the list. We will get to them, but none of them block correct operation today.

 目前在 [GitHub 問題追蹤器](https://github.com/stalwartlabs/stalwart/issues)上仍有 108 個待解決的問題。這些並非 bug，而是一些小的功能改進和請求：包括優化、提升用戶體驗以及值得保留的想法。我們會逐一解決，但目前這些問題都不會影響系統的正常運作。

## Latest fixes｜最新修復

 The headline of this release is RFC conformance. Stalwart v0.16.10 now passes all 309 tests of the [JMAP test suite](https://github.com/jmapio/jmap-test-suite), a shared conformance effort that aims to align the behaviour of Stalwart, Cyrus, and Fastmail so that JMAP clients see consistent semantics regardless of which server they talk to. Reaching full conformance touched many corners of the JMAP implementation.

 此版本的標題是RFC 一致性。 Stalwart v0.16.10 現在通過了 [JMAP 測試套件](https://github.com/jmapio/jmap-test-suite) 的所有 309 項測試，這是一項共享的一致性工作，旨在協調 Stalwart、Cyrus 和 Fastmail 的行為，以便 JMAP 客戶端看到與哪個伺服器端一致的語言通訊一致。達到完全一致性觸及JMAP實施的許多角落。

 Beyond JMAP, this release implements the latest drafts from the IETF [mailmaint](https://datatracker.ietf.org/wg/mailmaint/about/) working group. On the authentication side, Stalwart now supports the [OAuth Profile for Open Public Clients](https://datatracker.ietf.org/doc/draft-ietf-mailmaint-oauth-public/) along with client secret verification for confidential clients. On the IMAP side, it implements the [IMAP Extension for Object Identifiers](https://datatracker.ietf.org/doc/draft-ietf-mailmaint-imap-objectid-bis/) \(OBJECTID+\) and adds the `GETJMAPACCESS` command so clients can discover the JMAP session resource URL directly from an IMAP connection. We are glad to share that Stalwart Labs is coauthoring the `OBJECTID+` extension together with Fastmail.

 除了JMAP之外，此版本還實現了IETF [mailmaint](https://datatracker.ietf.org/wg/mailmaint/about/)工作小組的最新草稿。在驗證方面，Stalwart 現在支援 [開放公共用戶端的 OAuth 設定檔](https://datatracker.ietf.org/doc/draft-ietf-mailmaint-oauth-public/) ，以及針對機密用戶端的用戶端金鑰驗證。在IMAP方面，它實現了 [IMAP物件標識符擴展](https://datatracker.ietf.org/doc/draft-ietf-mailmaint-imap-objectid-bis/) \( OBJECTID +\)，並添加了`GETJMAPACCESS`命令，以便客戶端可以直接從IMAP連接中發現JMAP URL 。我們很高興地宣布，Stalwart Labs 正在與 Fastmail 共同開發`OBJECTID+`擴充。

 For the full list, see the [release notes](https://github.com/stalwartlabs/stalwart/releases). We recommend everyone upgrade.

 完整清單請參閱[發行說明](https://github.com/stalwartlabs/stalwart/releases) 。我們建議所有用戶升級。

## Road to 1.0｜通往1.0

 With the bug queue clear, the path to version 1.0 comes down to two pieces of work: finalizing the database schema and a focused round of performance optimization.

 既然 bug 佇列已清理完畢，那麼版本1.0的實作就只剩下兩項工作了：完成資料庫架構和進行一輪有針對性的效能最佳化。

 The first is the reason 1.0 matters. The goal is to stabilize and finalize the database schema so that it is flexible enough to avoid migrations after the 1.0 release. Stalwart is already running in production across a wide range of deployments, but committing to a stable on-disk format is a promise we only want to make once we are confident it will hold. We are taking the time now to make the schema general enough that future features can be added without forcing operators through a migration. When 1.0 ships, upgrading should stop being something you schedule a maintenance window for.

 第一個是1.0重要的原因。目標是穩定並最終確定資料庫模式，使其足夠靈活，以避免在1.0發布後進行遷移。 Stalwart 已經在廣泛的部署中運行在生產環境中，但是只有當我們確信它能夠實現時，我們才會做出承諾，致力於穩定的磁碟格式。我們現在正在花時間使模式足夠通用，以便可以添加未來的功能，而無需強迫操作員進行遷移。當 1.0 發佈時，升級應該不再是您安排維護時段的事情。

 The second is performance. Stalwart is already fast, and that is not an accident: over the past year we have made substantial improvements driven directly by reports from users running it at scale, including deployments with thousands of accounts and others delivering hundreds of thousands of emails per day. Those real-world workloads have been the best optimization guide we could ask for. For 1.0 we want to push further in two specific areas.

 第二點是性能。 Stalwart 的速度已經很快了，這並非偶然：過去一年，我們根據大規模用戶回饋進行了大幅改進，這些回饋包括部署數千個帳戶以及每天發送數十萬封電子郵件的部署。這些真實世界的工作負載是我們所能獲得的最佳最佳化指南。對於1.0 ，我們希望在兩個特定領域進一步提升效能。

 The first is the internal full-text search engine, which matters most for users who do not run an external Elasticsearch or Meilisearch backend and rely on the built-in indexer instead. We want search to be fast out of the box, without an external dependency. The second is a systematic pass over the hot paths in the codebase: benchmarking the code that runs most often to find concrete optimization opportunities, whether that means vectorizing an inner loop, reworking a data structure, or rewriting a section for better cache behaviour. The point is to let measurements, not guesses, decide where the effort goes.

 首先是內部全文搜尋引擎，這對於那些不使用外部 Elasticsearch 或 Meil​​​​isearch 後端，而是依賴內建索引器的使用者來說至關重要。我們希望搜尋功能開箱即用，無需任何外部依賴。其次是對程式碼庫中的熱點路徑進行系統性檢查：對運行頻率最高的程式碼進行基準測試，以發現具體的最佳化機會，例如向量化內部循環、重構資料結構或重寫程式碼段以優化快取行為。關鍵在於讓實際數據而非猜測來決定優化方向。

## ETA

 We expect to release Stalwart 1.0.0 this year, most likely around October and hopefully sooner. Schema work and performance work are both the kind that reward patience, so we would rather give a realistic window than a date we cannot keep. We will keep you posted as the schema settles and the benchmarks come in.

 我們預計今年發布 Stalwart 1.0.0 ，最有可能在 10 月份左右，希望能夠更早。架構和效能最佳化都需要耐心，因此我們寧願給出一個實際可行的時間範圍，而不是一個無法實現的日期。我們會隨著架構的完善和基準測試結果的出爐及時通知大家。

 In the meantime, v0.16.10 is the most conformant and most thoroughly debugged release we have shipped. Thank you to everyone who filed an issue, opened a ticket on the support portal, or sent us a reproducer. An empty bug queue is your work as much as ours, and it is the best possible foundation to build 1.0 on.

 同時， v0.16.10是我們迄今為止發布的版本中相容性最強、調試最徹底的版本。感謝所有提交問題報告、在支援入口網站開工單或提供復現步驟的使用者。清空問題隊列是大家共同努力的成果，也是我們建構1.0最佳基礎。
