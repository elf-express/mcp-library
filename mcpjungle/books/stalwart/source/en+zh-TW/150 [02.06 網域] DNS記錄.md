# DNS records｜DNS記錄

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[domains｜網域\\\]\\\(&lt;000 目錄.md#c-21&gt;\\\)

Stalwart can publish and maintain a domain’s DNS records directly against a managed zone, removing the need to copy records into a provider web console by hand. The feature is driven by the Domain object and relies on a separately configured DnsServer \(found in the WebUI under Settings › Network › DNS › DNS Providers\) that carries the credentials and transport details for the zone. See DNS providers for the DnsServer setup itself; this page covers the lifecycle once a DnsServer is in place.

 Stalwart 可直接針對託管區域發布和維護網域的DNS記錄，無需手動將記錄複製到提供者 Web 控制台。此功能由 Domain 物件驅動，並依賴單獨配置的 DnsServer （可在 WebUI 的「設定」&gt;「網路」&gt; DNS &gt; DNS提供者”中找到），該伺服器承載著區域的憑證和詳細傳輸資訊。有關 DnsServer 本身的設置，請參閱 DNS提供者 ；此頁面涵蓋了 DnsServer 就位後的生命週期。

## Enabling automatic DNS management｜啟用自動DNS管理

 Automatic management is selected per domain through the dnsManagement field on the Domain object. The `Manual` variant leaves the operator responsible for publishing records from the dnsZoneFile text into the external provider. The `Automatic` variant delegates that work to the server and carries three settings:

 透過 Domain 物件上的 dnsManagement 欄位為每個域選擇自動管理。 `Manual` 變體讓操作員負責將 dnsZoneFile 文本中的記錄發佈到外部提供者。 `Automatic` 變體委託工作於伺服器並帶有三個設定：

- dnsServerId references the DnsServer the domain should publish through.
dnsServerId指的是網域應該透過其發佈內容的 DNS 伺服器。
- origin names the zone apex when it differs from the domain itself. For a mail domain of `sub.example.com` hosted inside the `example.com` zone, the origin is set to `example.com`. Leaving the field unset falls back to the domain name.
origin用於指定區域根目錄，當其與網域本身不同時。例如，對於託管在`example.com`區域內的`sub.example.com`郵件域名，其來源位址設定為`example.com` 。如果該欄位未設置，則預設使用網域名稱。
- publishRecords lists the record types the server is allowed to write. The default covers `dkim`, `spf`, `mx`, `dmarc`, `srv`, `mtaSts`, `tlsRpt`, `caa`, `autoConfig`, `autoConfigLegacy`, and `autoDiscover`. Trimming the list restricts the server to a subset, which is useful when some record types are managed elsewhere.
publishRecords列出了伺服器可以寫入的記錄類型。預設包含`dkim`, `spf`, `mx`, `dmarc`, `srv`, `mtaSts`, `tlsRpt`, `caa`, `autoConfig`, `autoConfigLegacy`和`autoDiscover` 。精簡清單會將伺服器限制為子集，這在某些記錄類型由其他地方管理時非常有用。
## Initial publication｜初版

 Records are written to the zone the first time a Domain is saved with automatic DNS management enabled. Creating a Domain with the `Automatic` variant of dnsManagement triggers a publication pass that adds each record type in publishRecords to the configured zone. Switching an existing Domain from manual to automatic management has the same effect: the next save reconciles the expected record set with what is currently present in the zone and adds anything missing.

 首次啟用自動管理DNS保存域時，記錄會被寫入區域。使用 dnsManagement的`Automatic`變體建立域會觸發發布過程，將 publishRecords中的每種記錄類型新增至已配置的區域。將現有網域從手動管理切換到自動管理具有相同的效果：下次儲存時，系統會將預期記錄集與區域中目前存在的記錄集進行核對，並新增任何缺少的記錄。

 Propagation is driven by the DnsServer’s polling and timeout settings. The server issues the update, waits for the configured propagationDelay, then polls every pollingInterval until the record is observed or propagationTimeout is reached. Records are written with a TTL of ttl.

 傳播由 DNS 伺服器的輪詢和逾時設定驅動。伺服器發出更新，等待配置的 propagationDelay ，然後每隔 pollingInterval輪詢一次，直到觀察到記錄或達到 propagationTimeout為止。記錄以 TTL的 \[ `ttl` \] 寫入。

 Flipping a Domain to automatic DNS management does not block the save: the server schedules a `DnsManagement` Task \(found in the WebUI under Management › Tasks › Scheduled, Management › Tasks › Failed\) that performs the initial publication asynchronously. The task’s progress and outcome are visible on the Task record; if publication fails, the task is marked failed and its failureReason carries the details for diagnosis and retry.

 將網域的管理方式切換為DNS管理不會阻止儲存操作：伺服器會排程一個`DnsManagement` （可在 WebUI 的「管理」&gt;「任務」&gt; \([https://stalw.art/docs/ref/object/task\)已排程」和「管理」&gt;「任務」&gt;「失敗」中找到），非同步\`failureReason\`初始發布。任務的進度和結果會在任務記錄中顯示；如果發布失敗，任務將被標記為失敗，其\(https://stalw.art/docs/ref/object/task#failurereason\)將包含診斷和重試的詳細資訊。](https://stalw.art/docs/ref/object/task%2529%2525E5%2525B7%2525B2%2525E6%25258E%252592%2525E7%2525A8%25258B%2525E3%252580%25258D%2525E5%252592%25258C%2525E3%252580%25258C%2525E7%2525AE%2525A1%2525E7%252590%252586%2525E3%252580%25258D%25253E%2525E3%252580%25258C%2525E4%2525BB%2525BB%2525E5%25258B%252599%2525E3%252580%25258D%25253E%2525E3%252580%25258C%2525E5%2525A4%2525B1%2525E6%252595%252597%2525E3%252580%25258D%2525E4%2525B8%2525AD%2525E6%252589%2525BE%2525E5%252588%2525B0%2525EF%2525BC%252589%2525EF%2525BC%25258C%2525E9%25259D%25259E%2525E5%252590%25258C%2525E6%2525AD%2525A5%252560failureReason%252560%2525E5%252588%25259D%2525E5%2525A7%25258B%2525E7%252599%2525BC%2525E5%2525B8%252583%2525E3%252580%252582%2525E4%2525BB%2525BB%2525E5%25258B%252599%2525E7%25259A%252584%2525E9%252580%2525B2%2525E5%2525BA%2525A6%2525E5%252592%25258C%2525E7%2525B5%252590%2525E6%25259E%25259C%2525E6%25259C%252583%2525E5%25259C%2525A8%2525E4%2525BB%2525BB%2525E5%25258B%252599%2525E8%2525A8%252598%2525E9%25258C%252584%2525E4%2525B8%2525AD%2525E9%2525A1%2525AF%2525E7%2525A4%2525BA%2525EF%2525BC%25259B%2525E5%2525A6%252582%2525E6%25259E%25259C%2525E7%252599%2525BC%2525E5%2525B8%252583%2525E5%2525A4%2525B1%2525E6%252595%252597%2525EF%2525BC%25258C%2525E4%2525BB%2525BB%2525E5%25258B%252599%2525E5%2525B0%252587%2525E8%2525A2%2525AB%2525E6%2525A8%252599%2525E8%2525A8%252598%2525E7%252582%2525BA%2525E5%2525A4%2525B1%2525E6%252595%252597%2525EF%2525BC%25258C%2525E5%252585%2525B6%2528https://stalw.art/docs/ref/object/task#failurereason%2529%2525E5%2525B0%252587%2525E5%25258C%252585%2525E5%252590%2525AB%2525E8%2525A8%2525BA%2525E6%252596%2525B7%2525E5%252592%25258C%2525E9%252587%25258D%2525E8%2525A9%2525A6%2525E7%25259A%252584%2525E8%2525A9%2525B3%2525E7%2525B4%2525B0%2525E8%2525B3%252587%2525E8%25 ## Refreshing records｜重新整理記錄

 After initial publication, the record set is kept in sync by running the DNS management task. The task is a variant of the Task object \(the `DnsManagement` variant\) and can be triggered manually when a refresh is required, for example after editing the domain configuration, changing the report address, or rotating DKIM keys. In the WebUI, tasks are created from **Management &gt; Tasks**via the**New Task** button; from the CLI, the Task object is created with `stalwart-cli` in the same way as any other object. Triggering the task causes the server to rebuild the expected record set for the domain, compare it to the live zone, and issue the required add, update, and delete operations against the DnsServer.

 初始發布後，記錄集透過運行DNS管理任務保持同步。任務是 Task 物件（`DnsManagement` 變體）的變體，可在需要刷新時手動觸發，例如在編輯域配置、更改報告地址或輪換 DKIM 鍵後。在 WebUI 中，任務是透過 **新任務**按鈕從**管理 &gt; 任務** 建立的；從CLI開始，任務物件是用`stalwart-cli`建立的，方式與任何其他物件相同。觸發該任務會導致伺服器重建網域的預期記錄集，將其與活動區域進行比較，並對 DnsServer 發出所需的新增、更新和刪除操作。

 The task carries two fields of operational interest. updateRecords restricts the refresh to a subset of record types, which is useful when only a specific record \(for example, DKIM\) needs to be rewritten. onSuccessRenewCertificate chains an ACME renewal after a successful DNS update, which is relevant when the zone change is a prerequisite for a DNS-01 challenge.

 此任務包含兩個操作相關的欄位。 updateRecords將刷新限制為記錄類型的子集，這在只需要重寫特定記錄（例如DKIM ）時非常有用。 onSuccessRenewCertificate在成功更新DNS後連結ACME續期，這在區域更改是DNS -01挑戰的先決條件時非常重要。

## Record coverage｜記錄報道

 The record types the server can manage are described by the `DnsRecordType` enumeration on the Domain object: `dkim`, `tlsa`, `spf`, `mx`, `dmarc`, `srv`, `mtaSts`, `tlsRpt`, `caa`, `autoConfig`, `autoConfigLegacy`, and `autoDiscover`. The contents of each record are derived from the Domain and from related objects \(for example, DKIM public keys come from the DkimSignature records for the domain\). The current expected zone content is always available on the Domain through the read-only dnsZoneFile field.

 伺服器可以管理的記錄類型由 Domain 物件上的枚舉`DnsRecordType`描述： `dkim`, `tlsa`, `spf`, `mx`, `dmarc`, `srv`, `mtaSts`, `tlsRpt`, `caa`, `autoConfig`, `autoConfigLegacy`和`autoDiscover` 。每筆記錄的內容都源自 Domain 和相關物件（例如， DKIM公鑰來自域的 DkimSignature記錄）。目前預期區域內容始終可透過 Domain 上的唯讀欄位 dnsZoneFile取得。
