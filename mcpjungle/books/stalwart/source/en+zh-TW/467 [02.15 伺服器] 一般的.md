# General｜一般的

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\)

General server settings are grouped on the SystemSettings singleton \(found in the WebUI under Settings › Network › Services, Settings › Network › General\). This page covers the hostname, the CPU thread pool, and IP address allow / block lists. Per-listener concurrency is described on the Listeners page.

 常規伺服器設定集中在 SystemSettings單例中（可在 WebUI 的「設定」&gt;「網路」&gt;「服務」或「設定」&gt;「網路」&gt;「一般」中找到）。此頁面涵蓋主機名稱、 CPU線程池和IP位址允許/封鎖清單。每個監聽器的並發性在 Listeners頁面中描述。

## Server hostname｜伺服器主機名稱

 The default server hostname is used in SMTP `EHLO` commands, in message headers, and in reports. It is configured through defaultHostname on the SystemSettings singleton. If the field is left unset, the server falls back to the hostname reported by the operating system.

 預設伺服器主機名稱用於SMTP `EHLO`指令、訊息頭和報告中。它透過 SystemSettings 單例中的 defaultHostname進行配置。如果該欄位未設置，伺服器將回退到作業系統報告的主機名稱。

## Thread pool size｜執行緒池大小

 Stalwart runs CPU-intensive tasks on a dedicated thread pool. The pool size is controlled by threadPoolSize on the SystemSettings singleton. When left unset, the server allocates one worker per CPU core detected at start-up. Raising the value above the number of available cores does not generally improve throughput.

 Stalwart 在專用執行緒池上執行CPU密集型任務。線程池大小由 SystemSettings 單例中的 threadPoolSize控制。如果未設置，伺服器會在啟動時為每個偵測到的CPU核心分配一個工作執行緒。將該值提高到超過可用核心數通常不會提高吞吐量。

## IP address blocking｜IP地址阻塞

 IP addresses and ranges can be rejected at connection time. Each blocked entry is represented by a BlockedIp record \(found in the WebUI under Settings › Security › Blocked IPs\); the address field accepts a single IP address or a CIDR mask such as `203.0.113.0/24`, and expiresAt can be set to make the block temporary.

 IP位址和範圍可以在連線時被拒絕。每個被封鎖的條目都由一個 BlockedIp記錄表示（可在 WebUI 的CIDR設定」&gt;「安全性」 `203.0.113.0/24` 「被封鎖的 IP」下找到）；address板接受單一IP且可將`expiresAt` \]\([https://stalw.art/docs/ref/object/blocked-ip#expiresat\)設定為暫時阻止。](https://stalw.art/docs/ref/object/blocked-ip#expiresat%2529%2525E8%2525A8%2525AD%2525E5%2525AE%25259A%2525E7%252582%2525BA%2525E6%25259A%2525AB%2525E6%252599%252582%2525E9%252598%2525BB%2525E6%2525AD%2525A2%2525E3%252580%252582)

 When auto-banning is enabled, the server creates BlockedIp records automatically for sources that exceed the configured thresholds. Manual entries can be managed from the WebUI or the CLI.

 啟用 自動封鎖後，伺服器會自動為超過配置閾值的來源建立 BlockedIp 記錄。可透過 WebUI或 CLI管理手動條目。

## IP address allow list｜IP地址允許列表

 IP addresses and ranges that should bypass rate limits and auto-banning are represented by AllowedIp records \(found in the WebUI under Settings › Security › Allowed IPs\). The address field accepts a single IP address or a CIDR mask, and expiresAt can be used for time-bounded allowances. The localhost addresses `127.0.0.1` and `::1` are allowed by default to prevent accidental lockouts.

 IP位址和範圍可以繞過速率限制和自動封禁，由 AllowedIp記錄表示（可在 Web 管理介面「設定」&gt;「安全性」&gt;「允許的 IP」中找到）。 address字段接受單一IP位址或CIDR掩碼，expiresAt可用於限時授權。預設允許本地主機位址`127.0.0.1`和`::1`以防止意外鎖定。

## Run as user｜以使用者身分執行

 On Linux systems, Stalwart requires the `CAP_NET_BIND_SERVICE` capability to bind to privileged ports \(those below 1024\). On older systems that do not support this capability, Stalwart can be started as `root` and then drop privileges to a non-privileged account. The target user and group are selected through the `RUN_AS_USER` and `RUN_AS_GROUP` environment variables.

 在 Linux 系統上，Stalwart 需要`CAP_NET_BIND_SERVICE`權限才能綁定到特權連接埠（1024 以下的連接埠）。在不支援此功能的舊系統上，可以先以`root`啟動 Stalwart，然後將權限降到非特權帳號。目標使用者和群組可以透過`RUN_AS_USER`和`RUN_AS_GROUP`環境變數來選擇。
