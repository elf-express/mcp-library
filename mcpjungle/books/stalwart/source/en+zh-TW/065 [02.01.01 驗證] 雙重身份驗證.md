# Two-Factor Authentication｜雙重身份驗證

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[authentication｜驗證\\\]\\\(&lt;000 目錄.md#c-4&gt;\\\)

Two-Factor Authentication \(2FA\) is an additional layer of security used to ensure that individuals trying to access an account are who they claim to be. It typically combines two credential categories: something known \(an additional password, a PIN, or the answer to a security question\), something possessed \(a phone, security token, or smart card\), or something inherent \(a fingerprint, retina scan, or voice recognition\).

 雙重認證 \(2FA\) 是一種額外的安全措施，用於確保嘗試存取帳戶的個人是其聲稱的身份。它通常結合兩種憑證類別：已知資訊（附加密碼、 PIN或安全問題的答案）、擁有的物品（手機、安全令牌或智慧卡）或固有資訊（指紋、視網膜掃描或語音識別）。

 Stalwart supports Two-Factor Authentication using Time-based One-Time Password \(TOTP\). In this scheme the server and the authenticator app share a secret key, and the app generates a new code every 30 seconds by combining the secret with the current time. After entering their username and password, the user is prompted to enter the current TOTP code; the server verifies the code using the shared secret.

 Stalwart 支援使用基於時間的一次性密碼 \( TOTP \) 的雙重認證。在此方案中，伺服器和身份驗證器應用程式共用一個金鑰，應用程式每 30 秒將金鑰與目前時間結合產生一個新程式碼。使用者輸入使用者名稱和密碼後，系統會提示使用者輸入目前的TOTP代碼；伺服器使用共用金鑰驗證該代碼。

 TOTP is compatible with common authenticator apps such as Google Authenticator and Authy.

 TOTP與 Google Authenticator 和 Authy 等常見身份驗證器應用程式相容。

## Enabling 2FA｜啟用雙重認證

 Users can enable Two-Factor Authentication on their accounts from the self-service portal. Inside the portal, the Two-factor Authentication page presents a TOTP QR code that the user scans with an authenticator app, linking the account to the app.

 使用者可以透過自助服務入口網站在其帳戶上啟用雙重認證。在入口網站中，「雙重認證」頁面會顯示一個TOTP QR程式碼，使用者可以使用身份驗證器應用程式掃描程式碼，從而將帳戶與應用程式關聯起來。

 Administrators can enable 2FA on a user account by configuring an OTP Auth URL on the account. The AccountPassword singleton \(found in the WebUI under Account › Credentials › Password\) holds password and OTP credentials for the signed-in account; the OTP Auth URL is set through the otpAuth field, specifically the otpUrl inside the OtpAuth nested type. For administrator-driven provisioning, the same value can be stored as a `Password` credential on the target Account \(found in the WebUI under Management › Directory › Groups, Management › Directory › Accounts\) using the credentials field, which exposes the `otpAuth` URI on each `Password` credential. The TOTP secret embedded in the URL must then be communicated to the user so the same code is registered in their authenticator app.

 管理員可以透過在使用者帳戶上設定OTP Auth URL來啟用雙重認證 \(2FA\)。 AccountPassword單例（位於 WebUI 的「帳戶」&gt;「憑證」&gt;「密碼」下）儲存已登入帳號的密碼和OTP憑證； OTP Auth URL以嵌套\([https://stalw.art/docs/ref/object/account-password#otpauth](https://stalw.art/docs/ref/object/account-password#otpauth)\) `otpAuth` \[⦧\]`otpUrl` \]\([https://stalw.art/docs/ref/object/account-password#otpauth\)字段。對於管理員驅動的配置，可以使用](https://stalw.art/docs/ref/object/account-password#otpauth%2529%2525E5%2525AD%252597%2525E6%2525AE%2525B5%2525E3%252580%252582%2525E5%2525B0%25258D%2525E6%252596%2525BC%2525E7%2525AE%2525A1%2525E7%252590%252586%2525E5%252593%2525A1%2525E9%2525A9%252585%2525E5%25258B%252595%2525E7%25259A%252584%2525E9%252585%25258D%2525E7%2525BD%2525AE%2525EF%2525BC%25258C%2525E5%25258F%2525AF%2525E4%2525BB%2525A5%2525E4%2525BD%2525BF%2525E7%252594%2525A8) credentials字段，將相同的值儲存為目標 帳戶上的`Password`憑證（可在 WebUI的「管理」&gt;「目錄」&gt;「群組」或「管理」&gt;「目錄」&gt;「帳戶」下找到），該欄位會公開每個`Password`憑證上的`otpAuth` URI 。然後，必須將嵌入在URL中的TOTP金鑰告知用戶，以便在其身份驗證器應用程式中註冊相同的程式碼。

 Both users and administrators should verify that the authenticator app has been configured correctly and that codes validate successfully before relying on 2FA.

 使用者和管理員在啟用雙重認證 \(2FA\) 之前，都應該驗證身份驗證器應用程式是否已正確配置，以及驗證碼是否已成功驗證。

 Two-factor authentication can only be managed from the WebUI when Stalwart is configured to use the internal directory. When the server is configured with an external directory, such as LDAP or SQL, administrators must set the OTP Auth URL as one of the account secrets in the external directory.

 只有當 Stalwart 配置為使用 內部目錄時，才能透過 WebUI 管理雙重認證。當伺服器配置為使用外部目錄（例如LDAP或SQL時，管理員必須將OTP Auth URL設定為外部目錄中的帳戶金鑰之一。

## Using 2FA｜使用雙重認證

 Two-factor authentication can only be used with mail clients that support OAuth and the `OAUTHBEARER` or `XOAUTH2` SASL mechanism. Without OAuth, a new TOTP code would have to be entered every time the client retrieves or sends a message, which is impractical for most workflows.

 雙重認證只能與支援 OAuth 和`OAUTHBEARER`或`XOAUTH2` SASL機制的郵件用戶端一起使用。如果沒有 OAuth，用戶端每次收發郵件時都必須輸入新的TOTP程式碼，這對於大多數工作流程來說都不切實際。

 When using an OAuth flow, the user enters their password and a TOTP code during the initial sign-in. After successful authentication, an OAuth token is issued. The client refreshes the token automatically, so no further TOTP codes are required for the lifetime of the refresh token.

 使用 OAuth 流程時，使用者在首次登入時輸入密碼和TOTP代碼。身份驗證成功後，系統會頒發一個 OAuth 令牌。用戶端會自動刷新令牌，因此在刷新令牌的有效期內無需再輸入TOTP代碼。

### Legacy Applications｜遺留應用程式

#### Application Passwords｜應用程式密碼

 For accounts with 2FA enabled, legacy mail clients that do not support `OAUTHBEARER` or `XOAUTH2` can still authenticate by means of Application Passwords. An Application Password is a unique password that is accepted in place of the account’s regular password, and can be revoked individually.

 對於已啟用雙重認證的帳戶，不支援`OAUTHBEARER`或`XOAUTH2`的舊版郵件用戶端仍可透過 應用程式密碼進行身份驗證。應用程式密碼是一種可以取代帳戶常規密碼的唯一密碼，並且可以單獨撤銷。

## Internal Storage｜內部儲存

 The settings for TOTP-based Two-Factor Authentication are stored on the account as one of its secrets, encoded as an OTP Auth URL. The URL contains all the information an authenticator app needs to generate codes.

 基於TOTP的雙重認證設定作為帳戶的金鑰之一儲存在帳戶中，編碼為OTP Auth URL包含身份驗證URL應用程式產生程式碼所需的所有資訊。

 The OTP Auth URL carries the following components:

 OTP認證URL包含以下組件：

- **Secret Key:** The shared key used to derive one-time passwords.
**私鑰：**用於產生一次性密碼的共享金鑰。

- **Issuer:** The organisation issuing the OTP, typically the mail service or domain.
**發卡機構：** OTP機構，通常是郵件服務機構或網域名稱機構。
- **Account Name:** The account identifier, often the email address.
**帳戶名稱：**帳戶識別符，通常是電子郵件地址。

- **Algorithm:** The HMAC hash algorithm used, normally HMAC-SHA1.
**演算法：** 使用的HMAC哈希演算法，通常為HMAC-SHA1 。
- **Digits:** The number of digits in the generated OTP, normally six.
**位數：** 產生的OTP中的位數，通常為六位數。
- **Period:** The validity period of each code, normally 30 seconds.
**有效期限：**每個代碼的有效期，通常為 30 秒。
The URL follows the form `otpauth://totp/<issuer>:<accountname>?secret=<SECRET>&issuer=<issuer>&algorithm=SHA1&digits=6&period=30`. Storing this URL on the account keeps all information required to generate and validate TOTP codes in a single string.

 URL遵循`otpauth://totp/<issuer>:<accountname>?secret=<SECRET>&issuer=<issuer>&algorithm=SHA1&digits=6&period=30`形式。將此URL儲存在帳戶中，可以將產生和驗證TOTP程式碼所需的所有資訊保存在一個字串中。
