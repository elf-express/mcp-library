# Sharded In-Memory Store｜分片內存存儲

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[storage｜貯存\\\]\\\(&lt;000 目錄.md#c-72&gt;\\\) › \\\[backends｜後端\\\]\\\(&lt;000 目錄.md#c-73&gt;\\\) › \\\[composite｜合成的\\\]\\\(&lt;000 目錄.md#c-74&gt;\\\)

Sharding distributes data across multiple backends to improve throughput and balance load. In the sharded in-memory store, each key is hashed and a modulus operation selects one of the configured backends to hold or serve the associated value. Each backend owns a deterministic subset of keys, which avoids hotspots and allows capacity to scale horizontally.

 分片技術將資料分佈在多個後端伺服器上，以提高吞吐量並平衡負載。在分片記憶體儲存中，每個鍵都會被雜湊處理，然後透過取模運算選擇一個已配置的後端伺服器來儲存或處理關聯的值。每個後端伺服器都擁有一個確定的鍵子集，這避免了熱點問題，並允許容量橫向擴展。

 This feature is available exclusively in the Enterprise Edition of Stalwart and is not included in the Community Edition.

 此功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

## Configuration｜配置

 The sharded in-memory backend is selected by choosing the `Sharded` variant on the InMemoryStore object \(found in the WebUI under Settings › Storage › In-Memory Store\). The variant exposes a single field:

 若要選擇分片記憶體後端，請在 InMemoryStore物件上選擇`Sharded`變體（可在 WebUI 的「設定」&gt;「儲存」&gt;「記憶體儲存」中找到）。該變體僅公開一個字段：

- stores: list of two or more backend in-memory stores that make up the shard. Each entry selects one of the base in-memory variants \(Redis or Redis Cluster\).
stores : 構成分片的兩個或多個後端記憶體儲存的清單。每個條目選擇一個基礎記憶體變體（Redis 或 Redis 叢集）。
**IMPORTANT**: the order and number of backends in stores must remain stable once set. Reordering or adding or removing entries changes the hash-to-store mapping and leaves previously written data unreachable. Plan capacity carefully before configuring a shard.
**重要提示**：stores中的後端順序和數量一旦設定就必須保持不變。重新排序、新增或刪除條目都會改變雜湊到儲存的映射關係，並導致先前寫入的資料無法存取。配置分片前，請仔細規劃容量。
