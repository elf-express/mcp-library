# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[telemetry｜遙測\\\]\\\(&lt;000 目錄.md#c-76&gt;\\\) › \\\[tracing｜追蹤\\\]\\\(&lt;000 目錄.md#c-78&gt;\\\)

Stalwart produces detailed tracing and logging output that can be directed to several destinations in parallel, each with its own severity threshold and event filters. Multiple tracers can be configured side by side; the destination and filter choices determine what each consumer receives.

 Stalwart 可產生詳細的追蹤和日誌輸出，這些輸出可以並行發送到多個目標位置，每個位置都有自己的嚴重性閾值和事件過濾器。可以並排配置多個追蹤器；目標位置和過濾器的選擇決定了每個使用者接收的內容。

 Each tracer is an instance of the Tracer object \(found in the WebUI under Settings › Telemetry › Tracers\). The object is multi-variant: the chosen variant selects the output method and the fields it carries, while a set of common fields \(enable, level, lossy, events, eventsPolicy\) apply to every variant.

 每個追蹤器都是 Tracer物件的實例（可在 WebUI 的「設定」&gt;「遙測」&gt;「追蹤器」中找到）。該物件是多變體的：所選變體決定了輸出方法及其攜帶的字段，而一組`level`字段（\[ `enable` \([https://stalw.art/docs/ref/object/tracer#lossy](https://stalw.art/docs/ref/object/tracer#lossy)\) \([https://stalw.art/docs/ref/object/tracer#enable](https://stalw.art/docs/ref/object/tracer#enable)\) `lossy` \([https://stalw.art/docs/ref/object/tracer#level](https://stalw.art/docs/ref/object/tracer#level)\) `events` \([https://stalw.art/docs/ref/object/tracer#events](https://stalw.art/docs/ref/object/tracer#events)\) , eventsPolicy ）適用於所有變體。

 The supported variants are:

 支持的變體有：

- OpenTelemetry: sends traces and logs to an OpenTelemetry collector over HTTP or gRPC. Two variants, `OtelHttp` and `OtelGrpc`, cover the two transports.
OpenTelemetry：透過 HTTP 或 gRPC 將追蹤和日誌傳送到 OpenTelemetry 收集器。兩個變體，`OtelHttp` 和 `OtelGrpc`，涵蓋了兩種傳輸方式。
- Log file: writes entries to a text file with rotation \(`Log` variant\).
日誌檔案 : 將條目寫入文字檔案並旋轉（ `Log`變體）。
- Journal: forwards entries to the systemd journal \(`Journal` variant\). Linux only.
日誌 ：將條目轉送至 systemd 日誌（ `Journal`變體）。僅限 Linux。
- Console: prints entries to standard error \(`Stdout` variant\).
控制台 : 將條目列印到標準錯誤（ `Stdout`變體）。
## Logging levels｜日誌等級

 The verbosity of a tracer is set through level. The available levels are:

 追蹤器的詳細程度透過 level設定。可用等級有：

- `error`: only critical errors that threaten normal operation.
`error` ：僅指威脅正常運作的嚴重錯誤。
- `warn`: warnings that indicate potential problems.
`warn` ：表示潛在問題的警告。
- `info`: general informational output.
`info` ：一般資訊輸出。
- `debug`: detailed diagnostic information useful when troubleshooting.
`debug` ：詳細的診斷訊息，有助於故障排除。
- `trace`: the most verbose level, logging nearly every internal operation.
`trace` ：最詳細的級別，記錄幾乎所有內部操作。
A tracer can be switched off without deleting it by setting enable to `false`.
 可以透過將 enable設為`false`來關閉追蹤器而不將其刪除。

## Event filters｜事件過濾器

 Each tracer can be narrowed to a specific set of events through events together with eventsPolicy. The policy is either `include` \(only the listed events are emitted\) or `exclude` \(the listed events are suppressed and everything else is emitted\). The list of event identifiers is documented on the Events page.

 每個追蹤器都可以透過 events和 eventsPolicy來限定追蹤器只能追蹤特定事件集。策略可以是`include` （僅發出列出的事件）或`exclude` （抑制列出的事件，發出所有其他事件）。事件標識符清單記錄在 Events頁面上。

## Backpressure｜反壓

 If a tracer cannot keep up with the emitted volume, the default behaviour is to apply backpressure. Setting lossy to `true` lets the server drop entries instead, which is appropriate when loss of detail is preferable to slowing down the main event path.

 如果追蹤器無法跟上發出的資料量，預設行為是施加反壓。將 lossy設定為`true`可以讓伺服器丟棄條目，這在寧願損失一些細節也不願減慢主事件路徑速度的情況下是合適的。
