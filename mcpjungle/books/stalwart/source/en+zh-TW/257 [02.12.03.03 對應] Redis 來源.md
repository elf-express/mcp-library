# Redis source｜Redis 來源

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[proxy｜代理人\\\]\\\(&lt;000 目錄.md#c-42&gt;\\\) › \\\[mappings｜對應\\\]\\\(&lt;000 目錄.md#c-45&gt;\\\)

The Redis source resolves mappings from a Redis database. It suits deployments where mappings change frequently or are shared between several proxy instances, since every proxy reads from the same central store and a change made anywhere is visible everywhere once cache entries expire. Lookups are still served from each proxy’s in-memory cache, so Redis is consulted only on cache misses.

 Redis 來源從 Redis 資料庫解析映射。它適用於映射頻繁更改或在多個代理實例之間共享的部署，因為每個代理都從同一個中央存儲讀取數據，並且一旦緩存條目過期，任何地方的更改都會同步到所有地方。查找仍然從每個代理的記憶體快取中提供服務，因此僅在快取未命中時才查詢 Redis。

```toml
[mapping]
source = "redis"
normalize = "lowercase"

[mapping.redis]
url = "redis://10.0.3.1:6379"
key_prefix = "route:"
pool_size = 16
```

The keys under `[mapping.redis]` are:

`[mapping.redis]`下的按鍵是：

| Key 鍵 | Default 預設值 | Description 描述 |
| --- | --- | --- |
| `url` | required 必需 | Connection URL for the Redis server. Redis 伺服器連線URL 。 |
| `key_prefix` | `route:` | Prefix prepended to each identifier to form the Redis key. 為每個標識符加上前綴以形成 Redis 鍵。 |
| `pool_size` | `16` | Number of connections held open to the server. 與伺服器保持開啟的連線數。 |

The `url` follows the standard Redis URL syntax, including the `rediss://` scheme for TLS and an optional password and database number.

`url`遵循標準的 Redis URL語法，包括TLS的`rediss://`方案以及可選的密碼和資料庫編號。

## Key layout｜關鍵佈局

 Each mapping is stored as a single string value under a key formed by concatenating `key_prefix` with the normalized identifier. With the default prefix, the destination for `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` is read from the key `route:[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`. A lookup is a plain `GET`; a missing key, or a key whose value is empty, is treated as the absence of a mapping and routes the connection to the default destination.

 每個映射都以單一字串值的形式存儲，鍵由`key_prefix`與規範化標識符連接而成。使用預設前綴時， `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`的目標位址從鍵`route:[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`讀取。查找操作為純文字`GET` ；如果鍵缺失或值為空，則視為不存在映射，並將連接路由到預設目標位址。

```
GET route:[email protected]   ->  "legacy"
GET route:[email protected]   ->  "stalwart"
```

Mappings are populated using ordinary Redis commands, so an external tool can manage the table directly:

 映射表是使用普通的 Redis 命令填充的，因此外部工具可以直接管理該表：

```bash title=&amp;quot;Terminal window&amp;quot;
redis-cli SET route:[email protected] stalwart
redis-cli DEL route:[email protected]
```

## Runtime updates｜運行時更新

 The Redis source is writable, so the management API can create, replace and delete mappings, which the proxy performs with `SET` and `DEL` against the prefixed keys. Because the cache sits in front of Redis, a change made directly in Redis by an external tool becomes visible to a proxy once the relevant cache entry expires, or immediately if the entry is invalidated through the management API. The proxy maintains a small pool of `pool_size` connections and distributes requests across them.

 Redis 資料來源是可寫的，因此管理元件 API \] 可以建立、取代和刪除映射，代理使用`SET`和`DEL`對帶有前綴的鍵執行這些操作。由於快取位於 Redis 前端，外部工具直接在 Redis 中所做的更改，一旦相關的快取條目過期，代理就能看到這些更改；如果該條目通過管理元件API失效，則代理會立即看到這些更改。代理維護一個小型連接池`pool_size` ，並將請求分發到這些連接上。
