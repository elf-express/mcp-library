# ManageSieve｜管理篩

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[import export｜進出口\\\]\\\(&lt;000 目錄.md#c-40&gt;\\\) › \\\[import｜進口\\\]\\\(&lt;000 目錄.md#c-41&gt;\\\)

The `vandelay import managesieve` command reads the Sieve scripts of a single account from a ManageSieve server \(RFC 5804\) into a local SQLite archive. It is the narrowest of the import sources: a ManageSieve server exposes nothing but Sieve scripts, so this importer produces exactly one JMAP object type \(`SieveScript`\) and silently skips every other type. Because of that, a ManageSieve import is almost always run alongside an IMAP import of the same account, so that the archive holds the mailbox, the messages, and the filtering rules together before being exported to a JMAP target.

`vandelay import managesieve` 指令將單一帳戶的 Sieve 腳本從 ManageSieve 伺服器 \(RFC 5804\) 讀取到本機 SQLite 檔案中。它是最窄的導入來源：ManageSieve 伺服器隻公開 Sieve 腳本，因此該導入器恰好會產生 JMAP 物件類型 \(`SieveScript`\) 並默默地跳過所有其他類型。因此，ManageSieve 匯入幾乎總是與相同帳戶的 IMAP 匯入一起運行，以便存檔在匯出到 JMAP 目標之前將郵箱、訊息和過濾規則保存在一起。

## Invocation｜祈求

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import managesieve \
  --url sieves://host[:port] \
  (--auth-basic <USER> [--auth-password ] | --auth-bearer [<TOKEN>] --auth-user <USER>) \
  [--allow-cleartext] \
  [--allow-source-change] \
  <ARCHIVE>
```

The archive is the final positional argument and is created if it does not yet exist. Exactly one authentication mode must be supplied: either `--auth-basic` \(SASL PLAIN or LOGIN\) or `--auth-bearer` \(SASL OAUTHBEARER\). Re-running the command against the same archive and the same account is safe and convergent: a partial or interrupted run is continued by simply invoking it again, with no cursor or resume token to manage.

 存檔是最終的位置參數，如果尚不存在則建立它。必須只提供一種驗證模式：`--auth-basic`（SASL PLAIN 或LOGIN）或`--auth-bearer`（SASL OAUTHBEARER）。針對相同存檔和同一帳戶重新運行該命令是安全且收斂的：只需再次呼叫它即可繼續部分或中斷的運行，無需管理遊標或恢復令牌。

## Transport and TLS｜交通和TLS

 The transport is selected from the URL scheme. Both schemes default to the IANA-registered ManageSieve port 4190 when no port is given in the URL.

 傳輸方式選自URL方案。當 URL 中沒有給出連接埠時，兩種方案都預設為 IANA 註冊的 ManageSieve 埠 4190。

| URL scheme URL方案 | Default port 預設埠 | Transport behaviour 運輸行為 |
| --- | --- | --- |
| `sieves://host[:port]` | 4190 | TLS from the first byte \(implicit TLS\). 4190 TLS 從第一個字節開始（隱式TLS）。 |
| `sieve://host[:port]` | 4190 | Connect in cleartext, then upgrade to TLS with `STARTTLS` whenever the server advertises it. 4190以明文方式連接，然後每當伺服器通告時使用 `STARTTLS` 升級到 TLS。 |

The `sieve://` scheme always attempts a `STARTTLS` upgrade when the server advertises the capability, and `--allow-cleartext` does not override that: an advertised STARTTLS is always taken. The flag is the escape hatch for the single case of a server that does not advertise STARTTLS at all. Without `--allow-cleartext`, such a server is refused \(exit code 2\) rather than sending credentials over an unencrypted socket; with `--allow-cleartext`, the importer proceeds on the cleartext connection and authenticates anyway. The `sieves://` scheme is unaffected by the flag, since its socket is encrypted from byte one.

 當伺服器通告該功能時，`sieve://`方案始終嘗試`STARTTLS`升級，並且`--allow-cleartext`不會覆蓋該升級：始終採用通告的STARTTLS。該標誌是服務器根本不宣傳STARTTLS的單一情況的逃生口。如果沒有 `--allow-cleartext`，這樣的伺服器會被拒絕（退出代碼 2），而不是透過未加密的套接字發送憑證；使用`--allow-cleartext`，導入器將繼續進行明文連接並進行身份驗證。 `sieves://` 方案不受該標誌的影響，因為它的套接字是從位元組一開始加密的。

 RFC 5804 discourages a dedicated implicit-TLS port, and most real deployments run STARTTLS on port 4190, so `sieve://` is the common path. The `sieves://` scheme is provided for the less common case of a server reachable on a TLS-from-byte-one socket. Certificate verification can be disabled with the global `--allow-invalid-certs` flag for self-signed or otherwise untrusted certificates.

 RFC 5804 不鼓勵使用專用的隱式TLS 端口，並且大多數實際部署在端口 4190 上運行 STARTTLS，因此 `sieve://` 是通用路徑。 `sieves://` 方案是為在 TLS-from-byte-one 套接字上可存取伺服器的不太常見的情況提供的。對於自簽名或其他不受信任的證書，可以使用全域 `--allow-invalid-certs` 標誌停用證書驗證。

## Authentication｜驗證

 The importer supports three SASL mechanisms, chosen by the authentication flags and the mechanisms the server advertises. The actual mechanism in use is negotiated against the server’s advertised SASL list, with an automatic fallback between candidates rather than a hard capability gate.

 導入器支援三種SASL機制，透過驗證標誌和伺服器通告的機制進行選擇。實際使用的機制是根據伺服器公佈的SASL列表進行協商的，在候選者之間自動回退，而不是硬能力門。

- `--auth-basic <USER>` selects password authentication. The importer prefers `AUTHENTICATE "PLAIN"` and falls back to `AUTHENTICATE "LOGIN"` when only LOGIN is advertised. The accompanying password is supplied separately \(see below\) and is never passed as part of the basic flag.
`--auth-basic <USER>` 選擇密碼驗證。當僅宣傳 LOGIN 時，進口商更喜歡`AUTHENTICATE "PLAIN"`，並回退到`AUTHENTICATE "LOGIN"`。隨附的密碼是單獨提供的（見下文），並且永遠不會作為基本標誌的一部分傳遞。
- `--auth-bearer [<TOKEN>] --auth-user <USER>` selects `AUTHENTICATE "OAUTHBEARER"` \(RFC 7628\) for OAuth-based servers. The bearer token alone is not sufficient: `--auth-user` is mandatory and names the ManageSieve identity the token authorises. Passing `--auth-user` together with `--auth-basic` is rejected, as is `--auth-password` together with `--auth-bearer`.
對於基於 OAuth 的伺服器，`--auth-bearer [<TOKEN>] --auth-user <USER>` 選擇 `AUTHENTICATE "OAUTHBEARER"` \(RFC 7628\)。單獨的不記名令牌是不夠的：`--auth-user`是強制性的，並命名令牌授權的 ManageSieve 身分。將 `--auth-user` 與 `--auth-basic` 一起傳遞將被拒絕，`--auth-password` 與 `--auth-bearer` 一起傳遞也會被拒絕。
Mechanisms outside this set \(CRAM-MD5, DIGEST-MD5, GSSAPI, NTLM, EXTERNAL, XOAUTH2\) are out of scope; a server advertising only those is refused with a clear error.
 此群組以外的機制 \(CRAM-MD5, DIGEST-MD5, GSSAPI, NTLM, EXTERNAL, XOAUTH2\) 超出範圍；僅廣告這些內容的伺服器會被拒絕並出現明顯錯誤。

### Credential resolution｜憑證解析

 Credentials are deliberately not taken from the command line as plain values, so that they do not leak into shell history or the process table. The password for `--auth-basic` and the token for `--auth-bearer` are resolved in this order:

 憑證故意不從命令列作為普通值獲取，這樣它們就不會洩漏到 shell 歷史記錄或進程表中。 `--auth-basic`的密碼和`--auth-bearer`的令牌依以下順序解析：

1. The explicit flag value, when one is given \(` --auth-password  ` or `--auth-bearer <TOKEN>`\).
顯式標誌值，當給定一個時（`--auth-password `或`--auth-bearer <TOKEN>`）。
2. The environment variable: `$VANDELAY_PASSWORD` for the basic password, `$VANDELAY_TOKEN` for the bearer token.
環境變數：`$VANDELAY_PASSWORD`表示基本密碼，`$VANDELAY_TOKEN`表示不記名令牌。
3. An interactive prompt, when neither of the above is present.
當以上都不存在時，互動式提示。
Supplying the secret through the environment variable or the prompt is the recommended practice. Credentials are never written to the archive.
 建議的做法是透過環境變數或提示提供秘密。憑證永遠不會寫入檔案。

## Reconciliation and storage｜核對和存儲

 Import is name-based reconciliation with content re-hashing. ManageSieve exposes no per-script timestamp, ETag, or change feed, so on every run the importer enumerates the account’s scripts with `LISTSCRIPTS`, fetches each one with `GETSCRIPT`, and reconciles by content. Sieve scripts are small and few, which makes fetching every script on every run inexpensive.

 導入是基於名稱的協調和內容重新散列。 ManageSieve 不公開每個腳本的時間戳記、ETag 或變更來源，因此每次執行時匯入器都會使用 `LISTSCRIPTS` 枚舉帳戶的腳本，使用 `GETSCRIPT` 取得每個腳本，並按內容進行協調。 Sieve 腳本又小又少，這使得每次執行時取得每個腳本的成本都很低。

 Each script’s bytes are stored verbatim \(no line-ending or encoding normalisation\) and content-addressed by their BLAKE3 hash in the shared `blobs` table, deduplicated on insert. Because the bytes are byte-exact across every import source, a script imported via ManageSieve lands on the same blob row as the identical script imported via JMAP. The reconciliation acts per script name:

 每個腳本的位元組都逐字儲存（沒有行結束或編碼標準化），並透過共用 `blobs` 表中的 BLAKE3 哈希進行內容尋址，並在插入時進行重複資料刪除。由於每個導入來源中的位元組都是位元組精確的，因此透過 ManageSieve 匯入的腳本與透過 JMAP 匯入的相同腳本位於同一 Blob 行上。根據腳本名稱進行協調操作：

- A name with no local row is inserted.
插入沒有本地行的名稱。
- A name whose local hash matches the freshly fetched bytes is left unchanged, except that the active flag is updated if it has flipped on the server.
本機雜湊與新取得的位元組相符的名稱保持不變，但如果活動標誌在伺服器上翻轉，則會更新活動標誌。
- A name whose hash differs \(the script was edited on the server\) has its blob reference updated in place; the superseded blob is reclaimed by the end-of-run garbage-collection sweep.
雜湊不同的名稱（腳本是在伺服器上編輯的）的 blob 引用已就地更新；被取代的 blob 由運行結束垃圾收集掃描回收。
- A local name no longer listed by the server is deleted from the archive.
伺服器不再列出的本機名稱將從存檔中刪除。
The server’s active script is recorded as well: ManageSieve marks at most one script `ACTIVE`, and the archive tracks that flag so a later JMAP export can re-activate the corresponding script on the target.
 伺服器的活動腳本也會被記錄：ManageSieve 標記最多一個腳本 `ACTIVE`，存檔會追蹤該標記，以便稍後的 JMAP 匯出可以重新啟動目標上的對應腳本。

## Source-change protection｜來源更改保護

 The archive records the source it was imported from \(scheme, host, port, and the authenticated identity\). Pointing an existing archive at a different ManageSieve account is refused to prevent accidentally mixing two accounts into one archive. When changing the recorded source is intentional, pass `--allow-source-change` to permit the import to proceed against the new source.

 存档记录了导入的来源（方案、主机、端口和经过身份验证的身份）。拒絕將現有檔案指向不同的 ManageSieve 帳戶，以防止意外地將兩個帳戶混合到一個檔案中。當有意更改記錄來源時，請傳遞`--allow-source-change`以允許針對新來源繼續匯入。

## Examples｜範例

 Dovecot Pigeonhole over implicit TLS, with the password supplied through the environment:

 隱式 TLS 上的 Dovecot Pigeonhole，透過環境提供密碼：

```bash title=&amp;quot;Terminal window&amp;quot;
VANDELAY_PASSWORD='…' vandelay import managesieve \
  --url sieves://mail.example.com:4190 \
  --auth-basic [email protected] \
  alice.sqlite
```

A generic provider \(for example Fastmail\) reached over `sieve://` with a STARTTLS upgrade, prompting for the password interactively:

 通用提供者（例如 Fastmail）透過 STARTTLS 升級達到`sieve://`，以互動方式提示輸入密碼：

```bash title=&amp;quot;Terminal window&amp;quot;
vandelay import managesieve \
  --url sieve://sieve.example.net \
  --auth-basic [email protected] \
  alice.sqlite
```

An OAuth-capable server authenticated with a bearer token via OAUTHBEARER, the token taken from the environment:

 支持 OAuth 的服务器通过 OAUTHBEARER 使用不记名令牌进行身份验证，该令牌取自环境：

```bash title=&amp;quot;Terminal window&amp;quot;
VANDELAY_TOKEN='…' vandelay import managesieve \
  --url sieves://imap.provider.example \
  --auth-bearer --auth-user [email protected] \
  alice.sqlite
```

Since this importer handles Sieve scripts only, the same account’s mailbox and messages are imported separately with `vandelay import imap` into the same archive, so that the export step carries the filtering rules and the mail together.

 由於此匯入器僅處理 Sieve 腳本，因此相同帳戶的郵箱和訊息會使用 `vandelay import imap` 分別匯入到相同檔案中，以便匯出步驟將過濾規則和郵件一起攜帶。
