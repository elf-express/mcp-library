# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\)

A Message Transfer Agent \(MTA\) is a core component of email infrastructure responsible for transferring email messages from one server to another using the Simple Mail Transfer Protocol \(SMTP\). MTAs handle message routing, queuing, delivery attempts, and message handoff between different servers.

 郵件傳輸代理程式（ MTA ）是電子郵件基礎架構的核心元件，負責使用簡單郵件傳輸協定（ SMTP ）將電子郵件從一個伺服器傳輸到另一個伺服器。郵件傳輸代理程式處理郵件路由、排隊、投遞嘗試以及不同伺服器之間的郵件交接。

 SMTP is the protocol used for the transmission of electronic mail across IP networks. It operates by establishing a connection between servers to transfer messages, handling aspects such as message envelopes, routing paths, and error handling. Modern MTAs also incorporate security, authentication, and policy enforcement mechanisms.

 SMTP協定用於在IP網路上傳輸電子郵件。它透過在伺服器之間建立連線來傳輸郵件，並處理郵件信封、路由路徑和錯誤處理等問題。現代郵件傳輸代理程式 \(MTA\) 還整合了安全性、驗證和策略執行機制。

 Stalwart’s MTA is a standards-compliant SMTP server designed to serve both inbound and outbound email flows. It includes native support for email authentication standards such as DMARC, DKIM, SPF, and ARC. To secure message transport, Stalwart implements DANE, MTA-STS, and SMTP TLS reporting, allowing verifiable transmission over TLS.

 Stalwart 的MTA是一個符合標準的SMTP伺服器，旨在服務入站和出站電子郵件流。它原生支援DMARC, DKIM, SPF和ARC等電子郵件身份驗證標準。為了確保訊息傳輸安全，Stalwart 實現了DANE, MTA-STS和SMTP TLS報告功能，從而允許透過TLS進行可驗證的傳輸。

 Beyond authentication and transport security, Stalwart provides mechanisms for managing incoming traffic: inbound connection throttling, configurable filtering rules, support for Sieve scripting, MTA-level hooks, and milter integration.

 除了驗證和傳輸安全性之外，Stalwart 還提供了管理傳入流量的機制：入站連接限速、可設定的過濾規則、對 Sieve 腳本的支援、 MTA級鉤子和 milter 整合。

 For outbound delivery, Stalwart uses a distributed virtual queue architecture with support for delayed and priority delivery, delivery quotas, routing rules, and sender- or domain-specific throttling. Envelope rewriting and message modification are also supported, so operators can adapt message content and routing to deployment-specific requirements.

 對於出站郵件投遞，Stalwart 採用分散式虛擬佇列架構，支援延遲投遞和優先權投遞、投遞配額、路由規則以及針對寄件者或網域的限流。此外，它還支援信封重寫和訊息修改，因此維運人員可以根據部署的特定需求調整訊息內容和路由。

 This documentation provides a detailed guide to configuring and operating the Stalwart MTA.

 本文檔提供了配置和操作 Stalwart MTA的詳細指南。

## Configuration｜配置

 The SMTP service is enabled by creating one or more listeners on the NetworkListener object \(found in the WebUI under Settings › Network › Listeners\). A listener is an entry point for SMTP or LMTP connections on a specific address and port. Multiple listeners may be created, each serving a different role or catering to different types of connections. There is no built-in limit on the number of listeners.

 若要啟用SMTP服務，需要在 NetworkListener物件上建立一個或多個監聽器（可在 WebUI 的「設定」&gt;「網路」&gt;「監聽器」中找到）。監聽器是特定位址和連接埠上SMTP或LMTP連接的入口點。可以建立多個監聽器，每個監聽器承擔不同的角色或處理不同類型的連線。監聽器的數量沒有內建限制。

 Conventional SMTP configurations associate certain ports with specific types of connections: port 25 for cleartext SMTP between servers, port 587 for SMTP submission, and port 465 for SMTP submission with implicit TLS. Stalwart does not enforce these associations; each listener’s role is defined by its configuration. See the main listeners section for the complete listener configuration.

 傳統的SMTP配置將某些連接埠與特定類型的連接關聯起來：連接埠25用於伺服器之間的明文SMTP通信，連接埠587用於SMTP資料提交，連接埠465用於SMTP資料提交（隱式TLS ）。 Stalwart不強制執行這些關聯；每個監聽器的角色由其配置定義。有關完整的監聽器配置，請參閱主listeners部分。

 A listener is created by setting its bind addresses and selecting the appropriate protocol variant. The relevant protocol variants for MTA use are `smtp` and `lmtp`. Implicit TLS is enabled by setting the tlsImplicit field to `true` on the listener. The SMTP banner shown to connecting clients is not configured on the listener itself; it is defined on the MtaStageConnect singleton via the smtpGreeting expression, which can branch on the listener identifier to serve different banners per listener.

 透過設定其 bind位址並選擇對應的 protocol變體來建立監聽器。 MTA 的相關協定變體為`smtp`和`lmtp` 。透過將監聽器上的 tlsImplicit欄位設為`true`來啟用隱式 TLS。向連接客戶端顯示的 SMTP 橫幅並非在監聽器本身上配置；它是在 MtaStageConnect單例中透過 smtpGreeting表達式定義的，該表達式可以根據監聽器進行分支，從而為每個標準器提供分支，從而為每個橫幅監聽器提供。

### SMTP port｜SMTP端口

 Cleartext SMTP connections between servers are typically received on port 25. A listener configured with bind set to `[::]:25` and the SMTP protocol variant enables this role.

 伺服器之間的明文SMTP連接通常在連接埠 25 上接收。配置了 bind的監聽器設定為`[::]:25`和SMTP protocol變體，即可啟用此角色。

### Submissions port \(TLS\)｜提交埠（ TLS ）

 SMTP submissions with implicit TLS are typically received on port 465. A listener configured with bind set to `[::]:465`, the SMTP protocol variant, and tlsImplicit set to `true` serves this role.

 帶有隱式TLS的SMTP提交通常在 465 連接埠接收。配置了 bind設定為`[::]:465` SMTP協議變體）和 tlsImplicit設定為`true`監聽器可以勝任此角色。

### Submissions port｜提交連接埠

 SMTP submissions without implicit TLS, upgradable via `STARTTLS`, are typically received on port 587. A listener configured with bind set to `[::]:587` and the SMTP protocol variant enables this role.

 SMTP提交，不包含隱式TLS ，可透過`STARTTLS`升級，通常在連接埠 587 上接收。配置了 bind的監聽器設定為`[::]:587`和SMTP protocol變體，即可啟用此角色。

### LMTP port｜LMTP端口

 LMTP is a protocol used to deliver email to a mail server. It is similar to SMTP but designed for local handoff rather than transport between organisations. LMTP is typically received on port 24. A listener configured with bind set to `[::]:24` and the LMTP protocol variant enables this role. LMTP is only required when Stalwart is not acting as the final mail store.

 LMTP 是一種用於將電子郵件傳送到郵件伺服器的協定。它類似於SMTP，但設計用於本地切換而不是組織之間的傳輸。 LMTP 通常在連接埠 24 上接收。配置為 bind 設定為 `[::]:24` 且LMTP protocol 變體的偵聽器可啟用此角色。僅當 Stalwart 不充當最終郵件存儲時才需要 LMTP。
