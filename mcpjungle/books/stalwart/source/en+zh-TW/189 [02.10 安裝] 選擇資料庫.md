# Choosing a database｜選擇資料庫

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[install｜安裝\\\]\\\(&lt;000 目錄.md#c-29&gt;\\\)

Stalwart employs a modular storage architecture that separates different types of data into four distinct stores. This design provides flexibility and allows each storage component to be optimized independently, depending on the scale and needs of the deployment.

 Stalwart 採用模組化儲存架構，將不同類型的資料分離到四個獨立的儲存單元。這種設計提供了靈活性，並允許根據部署規模和需求對每個儲存元件進行獨立最佳化。

- The Data Store is responsible for storing structured metadata such as email headers, folder hierarchies, calendar, contacts, user settings, and other non-binary information. Essentially, it holds everything except large binary objects.
資料儲存負責儲存結構化元數據，例如電子郵件標頭、資料夾層級結構、日曆、聯絡人、使用者設定和其他非二進位資訊。本質上，它儲存除大型二進位物件之外的所有內容。
- The Blob Store is where large binary files \(such as the actual email content, sieve scripts, and attachments\) are stored.
Blob 儲存用於儲存大型二進位檔案（例如實際的電子郵件內容、sieve 腳本和附件）。
- To support efficient search operations, Stalwart also utilizes a Search Store, which maintains indexes to speed up text-based queries across message content.
為了支援高效的搜尋操作，Stalwart 還利用了 搜尋儲存 ，它維護索引以加快跨訊息內容的基於文字的查詢。
- Finally, the In-memory Store handles ephemeral key-value data used by security, clustering, and anti-spam components, including rate limiting, distributed locks and message interaction tracking.
最後，記憶體儲存處理安全、叢集和反垃圾郵件元件使用的臨時鍵值數據，包括速率限制、分散式鎖和訊息交互追蹤。
In simple or single-node setups, it is entirely feasible to consolidate these roles into a single storage backend. For example, databases such as **RocksDB**or**PostgreSQL** can be configured to serve as the data store, blob store, search store, and even in-memory store. It is common to see lightweight deployments where RocksDB is used exclusively for all four functions, simplifying management and reducing infrastructure complexity.
 在簡單或單節點設定中，將這些角色整合到單一儲存後端是完全可行的。例如，**RocksDB**或**PostgreSQL** 等資料庫可以配置為資料儲存、blob 儲存、搜尋存儲，甚至記憶體儲存。在輕量級部署中，RocksDB 專門用於所有四種功能，從而簡化管理並降低基礎設施複雜性，這是很常見的。

 However, for larger deployments \(particularly those running in distributed environments\), it is advisable to assign each storage role to a backend that is specifically designed for that purpose. A more scalable configuration might use **FoundationDB**as the data store, an**S3-compatible service**for blob storage,**Redis**for volatile in-memory data, and a dedicated search engine such as**Elasticsearch**or**Meilisearch** for full-text indexing.

 然而，對於規模較大的部署（尤其是在\([https://stalw.art/docs/cluster/\)環境中運行的部署），建議將每個儲存角色指派給專為此目的設計的後端。更具可擴展性的配置可能使用](https://stalw.art/docs/cluster/%2529%2525E7%252592%2525B0%2525E5%2525A2%252583%2525E4%2525B8%2525AD%2525E9%252581%25258B%2525E8%2525A1%25258C%2525E7%25259A%252584%2525E9%252583%2525A8%2525E7%2525BD%2525B2%2525EF%2525BC%252589%2525EF%2525BC%25258C%2525E5%2525BB%2525BA%2525E8%2525AD%2525B0%2525E5%2525B0%252587%2525E6%2525AF%25258F%2525E5%252580%25258B%2525E5%252584%2525B2%2525E5%2525AD%252598%2525E8%2525A7%252592%2525E8%252589%2525B2%2525E6%25258C%252587%2525E6%2525B4%2525BE%2525E7%2525B5%2525A6%2525E5%2525B0%252588%2525E7%252582%2525BA%2525E6%2525AD%2525A4%2525E7%25259B%2525AE%2525E7%25259A%252584%2525E8%2525A8%2525AD%2525E8%2525A8%252588%2525E7%25259A%252584%2525E5%2525BE%25258C%2525E7%2525AB%2525AF%2525E3%252580%252582%2525E6%25259B%2525B4%2525E5%252585%2525B7%2525E5%25258F%2525AF%2525E6%252593%2525B4%2525E5%2525B1%252595%2525E6%252580%2525A7%2525E7%25259A%252584%2525E9%252585%25258D%2525E7%2525BD%2525AE%2525E5%25258F%2525AF%2525E8%252583%2525BD%2525E4%2525BD%2525BF%2525E7%252594%2525A8) **FoundationDB**作為數據存儲，**S3 兼容服務**用於 blob 存儲，**Redis**用於內存中的易失性數據，以及專用搜索引擎（例如**Elasticsearch**或**Meilisearch**）用於全文索引。

 Selecting the right combination of databases will depend on the performance requirements, fault tolerance expectations, and operational constraints of the deployment. Stalwart’s flexible architecture ensures that it can scale from compact single-server setups to complex multi-node clusters with specialized infrastructure for each storage layer.

 選擇合適的資料庫組合取決於部署的效能要求、容錯預期和維運限制。 Stalwart 的靈活架構確保其能夠從緊湊的單一伺服器配置擴展到具有針對每個儲存層專用基礎架構的複雜多節點叢集。
