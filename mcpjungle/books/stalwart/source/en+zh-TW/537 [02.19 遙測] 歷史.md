# History｜歷史

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[telemetry｜遙測\\\]\\\(&lt;000 目錄.md#c-76&gt;\\\)

Telemetry history retains selected event spans \(for example, incoming messages and completed deliveries\) and periodic metric samples in a dedicated database, so that past activity can be reviewed after the fact. Unlike live telemetry, which streams data to connected clients in real time, history persists the signal to storage for later query.

 遙測歷史記錄會將選定的事件範圍（例如，收到的訊息和已完成的交付）和週期性指標樣本保留在專用資料庫中，以便事後回顧過去的活動。與即時\([https://stalw.art/docs/telemetry/live](https://stalw.art/docs/telemetry/live)\) （將資料即時串流傳輸到連接的用戶端）不同，歷史記錄會將訊號持久化到儲存中以供後續查詢。

 Stored spans and metrics can be retrieved through the JMAP API, which exposes filtering on time range, event type, and other criteria. The same data drives the `Dashboard` and `History` views in the WebUI.

 可透過JMAP API檢索已儲存的跨度和指標，該視圖提供按時間範圍、事件類型和其他條件進行篩選的功能。相同的資料驅動 WebUI中的`Dashboard`和`History`視圖。

 This feature is available exclusively in the Enterprise Edition of Stalwart and is not included in the Community Edition.

 此功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

## Tracing history｜追溯歷史

 Tracing history is controlled through the TracingStore singleton \(found in the WebUI under Settings › Storage › Tracing Store\). The object is multi-variant: the chosen variant selects the backend used to store spans. Selecting `Disabled` turns tracing history off; selecting `Default` reuses the main data store; other variants \(such as `FoundationDb` or `PostgreSql`\) point history at a dedicated backend.

 追蹤歷史記錄由 TracingStore單例物件控制（可在 WebUI 的「設定」&gt;「儲存」&gt;「追蹤儲存」中找到）。該物件具有多個變體：選擇的變體決定了用於儲存跨度的後端。選擇`Disabled`將關閉追蹤歷史記錄；選擇`Default`將重複使用主 資料儲存 ；其他變體（例如`FoundationDb`或`PostgreSql` ）則將歷史記錄指向專用後端。

 Retention is controlled by holdTracesFor on the DataRetention object \(found in the WebUI under Settings › Storage › Data Retention › Archiving, Settings › Storage › Data Retention › Data Cleanup, Settings › Storage › Data Retention › Auto-Expunge, Settings › Storage › Data Retention › Telemetry\). The value is a duration, for example `"7d"`, `"12h"`, or `"30m"`. The default is `"30d"`.

 資料保留由 \[DataRetention\] 物件上的 holdTracesFor控制（可在 WebUI 的“設定”&gt;“儲存”&gt;“資料保留\([https://stalw.art/docs/ref/object/data-retention](https://stalw.art/docs/ref/object/data-retention)\) &gt;「歸檔」、「設定」&gt;「儲存」&gt;「資料保留」&gt;「資料清理」、「設定」&gt;「儲存」&gt;「資料保留」&gt;「自動清除」和「設定」&gt;「儲存」&gt;「資料保留」&gt;「遙測」中找到）。該值表示持續時間，例如`"7d"`, `"12h"`或`"30m"` 。預設值為`"30d"` 。

 For example, to retain delivery traces in the main data store for thirty days, set the `TracingStore` singleton to `{"@type": "Default"}` and leave holdTracesFor at its default.

 例如，要在主資料儲存中保留交付追蹤 30 天，請將`TracingStore`單例設為`{"@type": "Default"}` ，並將 holdTracesFor保留為預設值。

## Metrics history｜指標歷史記錄

 Metrics history is controlled through the MetricsStore singleton \(found in the WebUI under Settings › Storage › Metrics Store\). The object is multi-variant in the same way as `TracingStore`: `Disabled` turns metrics history off, `Default` reuses the main data store, and the backend-specific variants point history at a dedicated store.

 指標歷史記錄由 MetricsStore單例物件控制（可在 WebUI 的「設定」&gt;「儲存」&gt;「指標儲存」中找到）。該物件具有多種變體，例如`TracingStore`: `Disabled`關閉指標歷史記錄， `Default`重用主資料存儲，而後端特定的變體則將歷史記錄指向專用儲存。

 Retention and sampling frequency are set on the DataRetention object:

 保留時間和取樣頻率在 DataRetention物件上設定：

- holdMetricsFor: duration for which metrics are retained. Default `"90d"`.
holdMetricsFor : 指標保留的持續時間。預設值為`"90d"` 。
- metricsCollectionInterval: how often metrics are sampled. Specified as a cron expression. The default samples once per hour at minute zero.
metricsCollectionInterval ：指標取樣頻率。可透過 cron 表達式指定。預設值為每小時 0 分鐘採樣一次。
