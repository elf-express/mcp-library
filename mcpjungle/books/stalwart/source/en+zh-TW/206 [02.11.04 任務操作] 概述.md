# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-31&gt;\\\) › \\\[tasks actions｜任務操作\\\]\\\(&lt;000 目錄.md#c-35&gt;\\\)

Stalwart performs two kinds of server management operation beyond the regular request path: Actions, which run immediately on demand, and Tasks, which run in the background according to a schedule. Both are invoked through the same JMAP API exposed by the WebUI, the CLI, and direct HTTP calls, and each is recorded so its outcome can be inspected afterwards.

 除了常規請求路徑之外，Stalwart 還執行兩種伺服器管理操作：Actions ，按需立即運行；以及 Tasks ，根據計劃在後台運行。兩者都透過 WebUI 、CLI和直接調用HTTP公開的同一個JMAP API來調用，並且每個操作都會被記錄，以便後續檢查其結果。

## Actions｜行動

 An Action is a management operation triggered on demand and executed immediately. Reloading settings or TLS certificates, invalidating caches, pausing and resuming the outbound queue, running a DMARC troubleshooting probe, and classifying a message through the spam filter are all Actions. Each invocation is stored as an Action object so that any result it produces, such as a spam score or a troubleshooting report, can be retrieved later.

 操作是按需觸發並立即執行的管理操作。重新加載設定或TLS證書、使快取失效、暫停和恢復出站隊列、運行DMARC故障排除探測以及透過垃圾郵件過濾器對郵件進行分類，這些都是操作。每次呼叫都會儲存為一個 操作對象，以便稍後檢索其產生的任何結果，例如垃圾郵件評分或故障排除報告。

## Tasks｜任務

 A Task is a background job scheduled for execution at a point in time. Search indexing, calendar alarm dispatch, outbound DMARC and TLS reports, account destruction, store and spam filter maintenance, ACME renewal, DKIM key rotation, and DNS record updates are all Tasks. Each scheduled job is stored as a Task object whose status records whether it is pending, awaiting retry, or has failed permanently, and the TaskManager singleton governs how failed tasks are retried.

 Task是規劃在特定時間點執行的後台作業。搜尋索引、行事曆提醒發送、出站報告DMARC和TLS 、帳戶銷毀、商店和垃圾郵件過濾器維護、續訂ACME ）、金鑰輪換（ DKIM ）以及記錄更新DNS都屬於任務。每個計劃作業都儲存為一個 Task對象，其狀態記錄了作業是處於掛起狀態、等待重試還是永久失敗。 TaskManager單例物件控制失敗任務的重試機制。

## How they differ｜它們有何不同

 Actions and Tasks both represent server operations driven through the management API, but they differ in when and how they run:

 操作和任務都代表透過管理程式API驅動的伺服器操作，但它們的運行時間和方式有所不同：

- **Timing**: an Action runs immediately in response to an administrator request; a Task runs in the background at its scheduled due time, whether deferred once or repeated on a recurring basis.
**時間**：操作會立即回應管理員請求而運行；任務會在後台按其預定的 due時間運行，無論延遲一次還是定期重複。
- **Execution model**: an Action completes synchronously and returns its result on the same request; a Task is queued and processed asynchronously by the task manager.
**執行模型**：Action 同步完成，並在同一請求中傳回其結果；Task 排隊，並由任務管理器非同步處理。
- **Failure handling**: an Action either succeeds or fails on the spot; a Task carries a retry budget and is retried according to the TaskManager strategy until it succeeds or is marked as permanently failed.
**失敗處理**：操作要麼立即成功，要麼立即失敗；任務具有重試預算，並根據 TaskManager策略進行重試，直到成功或被標記為永久失敗。
- **Typical use**: Actions cover interactive operations such as reloading configuration or probing message handling; Tasks cover recurring or deferred maintenance such as indexing, reporting, and certificate renewal.
**典型用途**：操作涵蓋互動式操作，例如重新載入設定或偵測訊息處理；任務涵蓋定期或延遲維護，例如索引、報告和憑證續約。
