# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-13&gt;\\\)

Running Stalwart in a clustered environment is flexible. The server was built from the start for distributed deployments, so horizontal scaling and high availability require little extra configuration.

 在叢集環境中運行 Stalwart 非常靈活。伺服器從一開始就為分散式部署而設計，因此橫向擴展和高可用性幾乎不需要額外的配置。

 Three elements must be configured to bring a Stalwart cluster online:

 若要讓 Stalwart 叢集上線，必須配置以下三個要素：

- A unique node identifier per cluster member, so each instance can be individually addressed for coordination and logging.
每個群集成員都有一個唯一的 節點標識符 ，因此可以單獨尋址每個實例以進行協調和日誌記錄。
- A coordination mechanism, allowing nodes to communicate, share internal state, and remain synchronised. Stalwart supports peer-to-peer, Apache Kafka, NATS, and Redis.
Stalwart 提供了一種協調機制（ \([https://stalw.art/docs/cluster/coordination/](https://stalw.art/docs/cluster/coordination/)\) ），讓節點之間進行通訊、共享內部狀態並保持同步。 Stalwart 支援點對點通訊、Apache Kafka、 NATS和 Redis。
- The roles of each node, defining which maintenance tasks and listeners each instance runs.
每個節點的 角色 ，定義每個執行個體執行哪些維護任務和監聽器。
Each of these topics is covered in the following subsections, with examples and guidance, whether the deployment is a lightweight three-node setup or a large-scale distributed system.
 以下各小節將涵蓋這些主題，並提供範例和指導，無論部署是輕量級的三節點設定還是大規模分散式系統。
