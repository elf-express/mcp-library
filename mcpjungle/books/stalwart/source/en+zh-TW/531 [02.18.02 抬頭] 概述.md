# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[storage｜貯存\\\]\\\(&lt;000 目錄.md#c-72&gt;\\\) › \\\[lookup｜抬頭\\\]\\\(&lt;000 目錄.md#c-75&gt;\\\)

Lookup lists serve a similar role to in-memory stores such as Redis, but with one key distinction: they are read-only at runtime. They hold key-value pairs that remain unchanged during server operation and are well suited to cases where a fixed set of values is consulted from configuration expressions or scripts.

 查找清單的作用與 Redis 等記憶體儲存類似，但有一個關鍵區別：它們在運行時是唯讀的。它們儲存的鍵值對在伺服器運行期間保持不變，非常適合從配置表達式或腳本中查詢一組固定值的情況。

 The primary way to interact with lookup lists is through expressions, using specialised functions such as `key_get`, `counter_get`, and others. These functions allow administrators to query values from the lists and evaluate configuration dynamically based on predefined key-value pairs.

 與查找列表互動的主要方式是透過表達式\([https://stalw.art/docs/configuration/expressions/](https://stalw.art/docs/configuration/expressions/)\) ，使用諸如`key_get`, `counter_get`等專用函數。這些函數允許管理員查詢清單中的值，並根據預先定義的鍵值對動態評估配置。

 Stalwart supports both local and remote lookup lists:

 Stalwart 同時支援本地和遠端查找清單：

- Local lookup lists are held as records managed through the MemoryLookupKey and MemoryLookupKeyValue objects. They are suitable for cases where all key-value pairs are known in advance and managed directly by the administrator.
本地查找清單作為記錄保存，並透過 MemoryLookupKey和 MemoryLookupKeyValue物件進行管理。它們適用於所有鍵值對都預先已知且由管理員直接管理的情況。
- Remote lookup lists are fetched over HTTP and defined through the HttpLookup object. They are useful in dynamic environments where configuration is managed centrally or updated independently of the server.
遠端查找清單透過HTTP獲取，並透過 HttpLookup物件定義。它們在配置集中管理或獨立於伺服器更新的動態環境中非常有用。
Additionally, the StoreLookup object exposes an external data store as a lookup namespace, which is convenient when an existing database already holds the data the server should consult.
 此外，StoreLookup物件將外部資料儲存公開為查找命名空間，當現有資料庫已保存伺服器應查詢的資料時，這將非常方便。
