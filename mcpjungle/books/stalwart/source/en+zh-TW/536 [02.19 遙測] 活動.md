# Events｜活動

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[telemetry｜遙測\\\]\\\(&lt;000 目錄.md#c-76&gt;\\\)

Events are specific occurrences within the server that are recorded for monitoring, auditing, and troubleshooting. They cover every aspect of operation, from authentication attempts to message delivery. Stalwart emits hundreds of distinct events, each identified by a hierarchical name such as `auth.success` or `delivery.delivered`.

 事件是指伺服器內部發生的特定事件，這些事件會被記錄下來用於監控、稽核和故障排除。它們涵蓋操作的各個方面，從身份驗證嘗試到訊息傳遞。 Stalwart 會發出數百個不同的事件，每個事件都由一個層級名稱標識，例如`auth.success`或`delivery.delivered` 。

 Each event carries a default logging level that reflects its severity. Tracers use that level to decide whether an event is recorded, so the verbosity of each output can be tuned independently through its level field.

 每個事件都帶有反映其嚴重性的預設日誌等級。追蹤器使用該等級來決定是否記錄事件，因此可以透過其 level欄位獨立調整每個輸出的詳細程度。

 Multiple tracers can run in parallel, each with its own level and event filter, so different consumers can receive different slices of the event stream. For example, a file-based tracer might record at `debug`, while a journal tracer captures only `error` and `warn` events.

 多個 追蹤器可以並行運行，每個追蹤器都有自己的等級和事件過濾器，因此不同的使用者可以接收到事件流的不同切片。例如，基於檔案的追蹤器可能會記錄`debug`等級的事件，而日誌追蹤器則只捕獲`error`和`warn`事件。

 Webhooks work differently. They do not filter by severity level; instead, each WebHook object lists the events that should trigger it through events and eventsPolicy. A webhook delivers notifications regardless of an event’s default level.

 Webhook的工作方式不同。它們不以嚴重程度進行篩選；相反，每個 WebHook物件都會列出應透過 events和 eventsPolicy觸發它的事件。無論事件的預設等級為何，Webhook 都會發送通知。

## Event levels｜事件層級

 Event levels describe severity. The available values are:

 事件等級描述嚴重程度。可用值包括：

- `info`: normal operations and significant milestones.
`info` ：正常營運與重要里程碑。
- `warn`: unusual situations that may indicate a problem.
`warn` ：可能表示有問題的異常情況。
- `error`: failures that typically require attention.
`error` ：通常需要注意的故障。
- `debug`: detailed diagnostic information for troubleshooting.
`debug` ：詳細的故障診斷資訊。
- `trace`: the most verbose level, recording nearly every internal operation.
`trace` ：最詳細的級別，幾乎記錄每一個內部操作。
A tracer with level set to one of the above values records every event whose default level is at that value or more severe. To disable a tracer without removing it, set enable to `false`.
 將 level設為上述值之一的追蹤器會記錄預設等級為該值或更高層級的每個事件。若要停用追蹤器而不將其刪除，請將 enable設為`false` 。

### Overriding the level of an event｜覆蓋事件級別

 The default level of any event can be overridden through the EventTracingLevel object \(found in the WebUI under Settings › Telemetry › Event Levels\). Each instance targets a single event, identified by event, and sets its effective severity through level.

 任何事件的預設等級都可以透過 EventTracingLevel物件（在 WebUI 的「設定 › 遙測 › 事件層級」下找到）來覆寫。每個實例都針對一個由 event標識的事件，並透過 level設定其有效嚴重性。

 For example, to raise `auth.success` from its default `info` to `debug`:

 例如，要將`auth.success`從其預設值`info`提升到`debug` ：

```json
{
  "event": "auth.success",
  "level": "debug"
}
```

Overriding levels is useful when a particular event needs closer monitoring or, conversely, when a noisy event should be suppressed.

 當需要更密切地監控某個特定事件時，或相反，當需要抑制雜訊的事件時，覆蓋層級就很有用。
