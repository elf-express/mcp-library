# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[openid｜OpenID\\\]\\\(&lt;000 目錄.md#c-8&gt;\\\)

OpenID Connect \(OIDC\) is an identity layer built on top of the OAuth 2.0 protocol. Where OAuth 2.0 is concerned with authorization \(granting applications access to resources\), OpenID Connect adds authentication: clients can verify the identity of the user who signed in. This supports single sign-on, in which a user authenticates once and uses the resulting identity across several services.

 OpenID Connect \( OIDC \) 是一個基於 OAuth 2.0協定所建構的身份層。 OAuth 2.0主要專注於授權（授予應用程式存取資源的權限），而 OpenID Connect 則增加了身分驗證功能：用戶端可以驗證登入使用者的身分。這支援單一登錄，用戶只需進行一次身份驗證，即可在多個服務中使用相同的身份。

 In an OIDC flow the user authenticates with an identity provider \(the OIDC server\) and the client receives an ID token in addition to the usual OAuth access token. The ID token carries information about the authenticated user, such as a unique subject identifier, name, email, and other claims, and lets the client confirm the user’s identity without handling passwords directly.

 在 OIDC 流程中，使用者透過身分識別提供者（OIDC 伺服器）進行身份驗證，除了通常的 OAuth 存取權杖之外，用戶端還會收到 ID 令牌。 ID令牌攜帶有關經過驗證的使用者的訊息，例如唯一的主體識別碼、姓名、電子郵件和其他聲明，並讓用戶端無需直接處理密碼即可確認使用者的身分。

## OAuth

 OIDC extends OAuth 2.0 by introducing the ID token: a JSON Web Token \(JWT\) that carries user identity information. OIDC reuses existing OAuth flows \(such as the Authorization Code Flow\) but adds endpoints and token types that support authentication. Together, OAuth 2.0 and OIDC cover both authorization and authentication in a single protocol family.

 OIDC透過引入ID令牌擴展了OAuth2.0：攜帶用戶識別資訊的JSONWeb令牌（JWT）。 OIDC 重複使用現有的 OAuth 流（例如授權代碼流），但新增支援驗證的端點和令牌類型。 OAuth 2.0 和 OIDC 一起涵蓋單一協議系列中的授權和身份驗證。

## Provider vs Client｜提供者與客戶

 Stalwart supports OpenID Connect in two directions. It can act as an OpenID Connect provider or it can authenticate users against a third-party provider. This lets administrators either use Stalwart as the central identity provider or delegate authentication to an existing identity system.

 Stalwart 支援雙向 OpenID Connect。它既可以作為 OpenID Connect 提供程序，也可以透過第三方提供程序對使用者進行身份驗證。這使得管理員既可以將 Stalwart 用作中央身份提供程序，也可以將身份驗證委託給現有的身份系統。

- OIDC Provider: Stalwart acts as the OpenID Connect provider. Clients \(web applications, email clients, or other services\) authenticate users against Stalwart and receive ID tokens that confirm their identity. This mode is useful when Stalwart is the identity provider for other services.
OIDC提供者 ：Stalwart 作為 OpenID Connect 供應商。用戶端（Web 應用程式、電子郵件用戶端或其他服務）透過 Stalwart 對使用者進行身份驗證，並接收ID用於確認其身分的令牌。當 Stalwart 為其他服務提供身分時，此模式非常有用。
- OIDC Client: Stalwart delegates authentication to a third-party OpenID Connect provider. This mode is useful when identity is centrally managed elsewhere \(for example by Google, Microsoft Entra ID, or Keycloak\) and the same accounts should authenticate to the mail server.
OIDC客戶端 ：Stalwart 將身分驗證委託給第三方 OpenID Connect 供應商。當身分由其他地方集中管理（例如 Google、Microsoft Entra ID或 Keycloak）並且相同的帳戶需要向郵件伺服器進行身份驗證時，此模式非常有用。
Both directions share the same OAuth foundation, and the same OidcProvider singleton controls token lifetimes and related policy when Stalwart acts as the provider.
 兩個方向共享相同的 OAuth 基礎，並且當 Stalwart 充當提供者時，相同的 OidcProvider單例控制令牌生命週期和相關策略。
