# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[backend｜後端\\\]\\\(&lt;000 目錄.md#c-6&gt;\\\)

Directories are the central repository for user account information. They hold the accounts, passwords, email addresses, and settings used to authenticate users and validate message recipients. Their primary functions are:

 目錄是使用者帳戶資訊的中央儲存庫。它們保存帳戶、密碼、電子郵件地址以及用於驗證使用者身分和確認郵件接收者的設定。其主要功能包括：

- **Authentication**: verifying account credentials so that only authorised users can access their mailboxes.
**身份驗證**：驗證帳戶憑證，以便只有授權使用者才能存取其郵箱。
- **Email and domain validation**: confirming that a recipient address exists on the server.
**電子郵件和網域驗證**：確認收件者位址存在於伺服器上。
- **Account information**: storing account metadata such as the account name, disk quota, and group memberships.
**帳戶資訊**：儲存帳戶元數據，例如帳戶名稱、磁碟配額和群組成員身分。
## Directory types｜目錄類型

 Stalwart can either use its own internal directory or delegate authentication and account lookup to an external directory service. The choice depends on the environment and on any existing identity infrastructure.

 Stalwart既可以使用其內部目錄，也可以將身份驗證和帳戶查找委託給外部目錄服務。具體選擇取決於環境和現有的身分基礎架構。

### Internal directory｜內部目錄

 The internal directory stores account information inside Stalwart itself. It is intended for deployments where Stalwart is the primary system managing email users and no external identity system is in place. All account management tasks \(creating accounts, updating passwords, setting quotas\) are carried out directly on the server.

 內部目錄將帳戶資訊儲存在 Stalwart 系統內部。它適用於 Stalwart 作為主要電子郵件使用者管理系統且未使用外部身分驗證系統的部署環境。所有帳戶管理任務（建立帳戶、更新密碼、設定配額）均直接在伺服器上執行。

### External directory｜外部目錄

 Stalwart can also be configured against an external directory such as LDAP or an SQL database. This mode is useful when user accounts are already managed by another system and those accounts should be reused by the mail server. Account changes are made in the external directory; Stalwart queries the directory to authenticate users and to resolve email addresses. The external directory must be kept consistent to avoid stale or inconsistent state.

 Stalwart 也可以配置為使用外部目錄，例如LDAP或SQL資料庫。當使用者帳戶已由其他系統管理，且郵件伺服器需要重複使用這些帳戶時，此模式非常有用。帳戶變更在外部目錄中進行；Stalwart 會查詢該目錄以驗證使用者身分並解析電子郵件地址。必須保持外部目錄的一致性，以避免過時或不一致的狀態。

 Local accounts are created from the external directory on demand rather than being copied in advance, and they are never removed automatically. Where the identity provider should own the whole account lifecycle, including suspension and deletion, SCIM provisioning can be enabled per domain; Provisioning models sets out how the two approaches differ and how authority is assigned between them.

 本機帳戶按需從外部目錄創建，而非預先複製，並且永遠不會自動刪除。身分提供者應負責整個帳戶生命週期，包括暫停和刪除，SCIM配置可以按域啟用；配置模型闡述了這兩種方法的區別以及它們之間的權限分配方式。

## Configuration｜配置

 External directories are represented by the Directory object \(found in the WebUI under Settings › Authentication › Directories\). The object is multi-variant, with one variant per backend kind. The variants supported are the LDAP variant, the SQL variant, and the OIDC variant.

 外部目錄由 Directory物件表示（可在 WebUI 的「設定」&gt;「驗證」&gt;「目錄」中找到）。該物件是多變體的，每個後端類型對應一個變體。支持的變體包括LDAP變體、 SQL變體和OIDC變體。

 Use of the internal directory is indicated by leaving the directoryId field unset on the Authentication singleton \(found in the WebUI under Settings › Authentication › General\). To delegate authentication to an external directory, set `directoryId` to the id of the desired Directory object.

 如果使用內部目錄，則在 Authentication單例（位於 WebUI 的「設定」&gt;「驗證」&gt;「常規」下）中，將 directoryId欄位設為未設定。若要將身分驗證委託給外部目錄，請將`directoryId`設定為所需 Directory 物件的 ID。

### Connection pool｜連接池

 The LDAP variant of the Directory object maintains its own connection pool. The pool is configured through poolMaxConnections, poolTimeoutCreate, poolTimeoutRecycle, and poolTimeoutWait on the object. `poolMaxConnections` caps the number of simultaneous connections, while the three timeout fields cap how long the pool waits to create, recycle, and hand out a connection, respectively.

 這 LDAP Directory 物件的變體維護自己的連線池。此連接池透過 poolMaxConnections, poolTimeoutCreate, poolTimeoutRecycle， 和 poolTimeoutWait 在物體上。 `poolMaxConnections` 限制並發連線數，而三個逾時欄位分別限制連線池等待建立、回收和分配連線的時間。

### Default directory｜預設目錄

 The default external directory used for authentication is selected by setting directoryId on the Authentication singleton to the id of the relevant Directory object.

 透過將 directoryId在 Authentication單例中設定為相關 Directory 物件的 id 來選擇用於驗證的預設外部目錄。
