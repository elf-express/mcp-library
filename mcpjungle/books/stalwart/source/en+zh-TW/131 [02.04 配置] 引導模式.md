# Bootstrap mode｜引導模式

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-18&gt;\\\)

The first time Stalwart is started without a `config.json`, it enters bootstrap mode. No mail services are started. The server listens on HTTP port `8080` \(configurable with `STALWART_RECOVERY_MODE_PORT`\) and serves only the WebUI and the management API, with the JMAP API restricted to a single object type: Bootstrap.

 首次啟動 Stalwart 時，如果沒有`config.json` ，它將進入引導模式。不會啟動任何郵件服務。伺服器監聽HTTP埠`8080` （可透過`STALWART_RECOVERY_MODE_PORT`設定），且僅提供 WebUI和管理API服務，其中JMAP API僅限於單一物件類型：Bstraootp 。

 To enable the initial sign-in, Stalwart generates a temporary administrator account and prints the credentials to standard output:

 為了啟用初始登錄，Stalwart 會產生一個臨時管理員帳戶，並將憑證列印到標準輸出：

```
════════════════════════════════════════════════════════════
🔑 Stalwart bootstrap mode - temporary administrator account

   username: admin
   password: iX8pG2uYq3vR7kNc

Use these credentials to complete the initial setup at the
/admin web UI. Once setup is done, Stalwart will provision a
permanent administrator and this temporary account will no
longer apply.

This password is shown only once. To pin a credential
instead, set STALWART_RECOVERY_ADMIN=admin:in the
env file.
════════════════════════════════════════════════════════════
```

The password is regenerated on every bootstrap start and is only printed once. It must be captured from the console before it scrolls out of view, or a credential can be pinned in advance through the STALWART\_RECOVERY\_ADMIN environment variable. When `STALWART_RECOVERY_ADMIN` is set, no temporary password is generated and the provided value is used instead.

 每次啟動引導程式時都會重新產生密碼，並且只列印一次。必須在控制台滾動出螢幕之前將其捕獲，或者可以透過 STALWART\_RECOVERY\_ADMIN環境變數預先設定憑證。如果設定了`STALWART_RECOVERY_ADMIN` ，則不會產生臨時密碼，而是使用提供的值。

 With those credentials, `http://<host>:8080/admin` can be opened in a browser. The WebUI presents a setup wizard backed by the `Bootstrap` object, which collects the server hostname, the default domain, the storage backends, the directory used to authenticate users, and a handful of related settings. On completion of the wizard, Stalwart writes `config.json`, creates the permanent administrator account, provisions the remainder of the configuration, and restarts into normal operation. The temporary bootstrap account no longer applies after that point.

 使用這些訊息，即可在瀏覽器中開啟`http://<host>:8080/admin`會顯示一個由`Bootstrap`物件支援的設定精靈，該精靈會收集伺服器主機名稱、預設網域、儲存後端、用於使用者驗證的目錄以及一些相關設定。精靈完成後，Stalwart 會寫入`config.json` ，建立永久管理員帳戶，配置剩餘部分，然後重新啟動並正常運作。此後，臨時引導帳戶將不再生效。

 After the restart, the WebUI is reached at `https://<hostname>/admin` on the configured server hostname, and HTTP access on port `8080` is no longer available for administration. The change of protocol is required because OAuth sign-in is now bound to the configured hostname over HTTPS; the path-relative issuer served during bootstrap is no longer in use. When HTTPS on the configured hostname is not yet reachable \(for example while DNS is still being set up, or before a TLS certificate has been issued\), the server can be restarted in recovery mode to keep the WebUI available over HTTP until the TLS side of the deployment is ready.

 重新啟動後，可透過設定的伺服器主機名稱上的連接埠`https://<hostname>/admin`存取 WebUI，而連接埠`8080`上的HTTP存取將不再可用於管理。由於 OAuth 登入現在綁定到配置的主機名，並透過連接埠HTTPS進行訪問，因此需要更改協定；引導期間使用的路徑相對頒發者已不再使用。如果配置的主機名稱上的連接埠HTTPS尚無法存取（例如，在DNS仍在設定中，或在TLS證書頒發之前），則可以將伺服器重啟到恢復模式\([https://stalw.art/docs/configuration/recovery-mode](https://stalw.art/docs/configuration/recovery-mode)\) ，以保持 WebUI 可透過連接埠HTTP TLS 。

 The setup wizard is the recommended path for new deployments because it validates every choice interactively and supplies sensible defaults. For deployments that must avoid the wizard, for example when installation is automated across many hosts, `config.json` can be written manually with the required datastore settings, and Stalwart can then be started in recovery mode to provision the remaining configuration through the CLI. The declarative deployments page describes this workflow in more detail.

 對於新部署，建議使用設定精靈，因為它能夠互動式地驗證每個選擇並提供合理的預設值。對於必須避免使用精靈的部署（例如，在多台主機上自動安裝時），可以手動寫入`config.json`以設定所需的資料存儲，然後以 恢復模式啟動 Stalwart，並透過CLI完成剩餘配置。 宣告式部署頁面更詳細地描述了此工作流程。
