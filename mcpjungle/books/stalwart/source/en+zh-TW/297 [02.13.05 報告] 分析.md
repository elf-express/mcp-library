# Analysis｜分析

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[reports｜報告\\\]\\\(&lt;000 目錄.md#c-53&gt;\\\)

Stalwart automatically analyses incoming DMARC, DKIM, SPF, and TLS reports sent by other domains, removing the need for manual intervention and saving time for administrators. If TLS or message-authentication issues are detected, an event is recorded in the log file or sent to OpenTelemetry. Turning reports into actionable events allows administrators to detect and respond to configuration errors and abuse \(such as spam or phishing\), helping maintain the integrity of the email system.

 Stalwart 會自動分析其他網域發送的DMARC, DKIM, SPF和TLS報告，無需人工幹預，從而節省管理員的時間。如果偵測到TLS或郵件驗證問題，則會在日誌檔案中記錄事件或將其傳送至 OpenTelemetry 。將報告轉換為可操作的事件，使管理員能夠偵測並回應配置錯誤和濫用行為（例如垃圾郵件或網路釣魚），從而有助於維護電子郵件系統的完整性。

## Settings｜設定

 Inbound analysis is configured on the ReportSettings singleton \(found in the WebUI under Settings › MTA › Reports › General\):

 入站分析配置在 ReportSettings單例中（位於 WebUI 的「設定」› MTA › 報表 › 常規下）：

- inboundReportAddresses: set of addresses \(with optional wildcards\) from which reports are intercepted and analysed. These addresses must be routable. Default `{"postmaster@*": true}`.
inboundReportAddresses : 用於攔截和分析報告的位址集（可選通配符）。這些位址必須可路由。預設值為`{"postmaster@*": true}` 。
- inboundReportForwarding: whether reports are forwarded to their final recipient after analysis. Default `true`.
inboundReportForwarding : 分析後是否將報告轉發給最終接收者。預設值為`true` 。
Example intercepting `dmarc@*` and `abuse@*` while still forwarding the report to the original recipient:
 例如，攔截`dmarc@*`和`abuse@*` ，同時仍將報告轉發給原始收件人：

```json
{
  "inboundReportAddresses": {"dmarc@*": true, "abuse@*": true},
  "inboundReportForwarding": true
}
```

Values on this page follow the object encoding rules: list and set fields are JSON objects rather than arrays, and durations and sizes are integers.

 本頁上的值遵循 物件編碼規則：列表和集合字段是JSON物件而不是數組，持續時間和大小是整數。

## Retention｜保留

 How long intercepted reports are kept is controlled globally by the DataRetention singleton \(found in the WebUI under Settings › Storage › Data Retention › Archiving, Settings › Storage › Data Retention › Data Cleanup, Settings › Storage › Data Retention › Auto-Expunge, Settings › Storage › Data Retention › Telemetry\) through the holdMtaReportsFor field, which accepts a duration in milliseconds or `null` to disable storage. The default is 30 days \(`2592000000`\).

 攔截報告的保留時間由 DataRetention單例全域控制（可在 WebUI 的「設定 › 儲存 › 資料保留 › 歸檔」、「設定 › 儲存 › 資料保留 › 資料清理」、「設定 › 儲存 › 資料保留 › 儲存 › 資料保留 › 資料清理」、「設定 › 儲存 › 儲存資料保留 尋找儲存 › 資料保留 › 資料清理」、「設定 › 儲存 › 資料保留 找到資料`holdMtaReportsFor` \]\([https://stalw.art/docs/ref/object/data-retention#holdmtareportsfor\)字段進行設置，該字段接受以毫秒為單位的持續時間，或\`null\`以禁用存儲。預設值為](https://stalw.art/docs/ref/object/data-retention#holdmtareportsfor%2529%2525E5%2525AD%252597%2525E6%2525AE%2525B5%2525E9%252580%2525B2%2525E8%2525A1%25258C%2525E8%2525A8%2525AD%2525E7%2525BD%2525AE%2525EF%2525BC%25258C%2525E8%2525A9%2525B2%2525E5%2525AD%252597%2525E6%2525AE%2525B5%2525E6%25258E%2525A5%2525E5%25258F%252597%2525E4%2525BB%2525A5%2525E6%2525AF%2525AB%2525E7%2525A7%252592%2525E7%252582%2525BA%2525E5%252596%2525AE%2525E4%2525BD%25258D%2525E7%25259A%252584%2525E6%25258C%252581%2525E7%2525BA%25258C%2525E6%252599%252582%2525E9%252596%252593%2525EF%2525BC%25258C%2525E6%252588%252596%252560null%252560%2525E4%2525BB%2525A5%2525E7%2525A6%252581%2525E7%252594%2525A8%2525E5%2525AD%252598%2525E5%252584%2525B2%2525E3%252580%252582%2525E9%2525A0%252590%2525E8%2525A8%2525AD%2525E5%252580%2525BC%2525E7%252582%2525BA) 30 天 \( `2592000000` \)。
