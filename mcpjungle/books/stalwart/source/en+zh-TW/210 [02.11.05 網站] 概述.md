# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-31&gt;\\\) › \\\[webui｜網站\\\]\\\(&lt;000 目錄.md#c-36&gt;\\\)

The WebUI is the browser-based front end for managing a Stalwart server and for giving end users control over their own account. It is delivered as a single-page application packaged as an Application \(found in the WebUI under Settings › Web Applications\) and mounted at two URL prefixes on any HTTP listener the server exposes:

 WebUI 是基於瀏覽器的前端，用於管理 Stalwart 伺服器並讓最終使用者控制自己的帳戶。它以單頁應用程式的形式提供，包裝為 Application （可在 WebUI 的「設定」&gt;「Web 應用程式」下找到），並以兩個URL前綴掛載到伺服器公開的任何HTTP監聽器上：

- `/admin`, the administrator console used to configure the server, manage directories and policy, and investigate the running system.
`/admin` ，管理員控制台，用於配置伺服器、管理目錄和策略以及調查正在運行的系統。
- `/account`, the Account Manager used by end users to manage their own credentials and settings.
`/account` ，最終使用者使用帳戶管理器來管理自己的憑證和設定。
Both surfaces are served by the same Application bundle; the prefix determines which entry point the browser lands on and which views are available after sign-in. Installation, download location, update cadence, unpack directory, and on-demand refreshes are not configured on the WebUI itself: the WebUI is a hosted application like any other, and those topics are covered under Applications.
 這兩個介面都由同一個應用程式套件提供服務；前綴決定了瀏覽器進入哪個入口點以及登入後可以使用哪些視圖。 WebUI 本身不配置安裝、下載位置、更新頻率、解壓縮目錄和按需刷新：WebUI 與其他任何託管應用程式一樣，這些主題在 應用程式中涵蓋。

## Administrator console｜管理員控制台

 The `/admin` mount is the administration surface. After signing in with an account that holds the required permissions, operators configure and operate the server from a single interface. The console covers the configuration objects that make up the running system and the operational views that report on its behaviour.

`/admin`掛載點是管理介面。操作員使用具有所需權限的帳戶登入後，即可透過單一介面設定和操作伺服器。控制台涵蓋構成運行系統的配置物件以及報告系統行為的操作視圖。

 Configuration screens are organised around the same object model exposed over the JMAP API and the CLI: every configurable object edited in the WebUI corresponds to a singleton or collection on the server, and every form submission is translated into a `set` call on that object. The breadcrumb notations used throughout the rest of the documentation \(for example, Management › Directory › Groups, Management › Directory › Accounts\) name the exact location under which an object is edited.

 配置介面基於同一個物件模型組織，該模型透過JMAP API和 CLI公開：在 WebUI 中編輯的每個可配置物件都對應於伺服器上的一個單例或集合，並且每個表單提交都會轉換為對該物件的`set` 。文件其餘部分所使用的麵包屑導覽標記（例如，「管理 › 目錄 › 群組」、「管理 › 目錄 › 帳號」）指明了編輯物件的特定位置。

 The console groups the available views into the following broad areas:

 控制台將可用視圖分為以下幾個大類：

- **Directory management.** Accounts, groups, roles, permissions, tenants, and domains, together with the authentication backends that resolve them. Operators create and edit principals, assign roles, and manage credentials from these screens.
**目錄管理。** 帳戶、群組、角色、權限、租用戶和網域，以及解析它們的身份驗證後端。操作員可以從這些畫面建立和編輯主體、指派角色並管理憑證。
- **Server configuration.** Listeners, TLS, storage backends, transport pipelines, filtering rules, and the general server objects. The breadcrumbs on each reference page point to the corresponding location in the tree.
**伺服器配置。** 監聽器、TLS、儲存後端、傳輸管道、過濾規則和通用伺服器物件。每個參考頁面上的麵包屑都指向樹中的對應位置。
- **Operational tooling.** Live sessions, queued messages, retry logic, scheduled tasks, and manually triggered Actions. This is where administrators start, stop, or reload subsystems without leaving the browser.
**維運工具。**即時會話、排隊訊息、重試邏輯、排程任務和手動觸發的操作 。管理員可以在這裡啟動、停止或重新載入子系統，而無需離開瀏覽器。

- **Reports.** DMARC, TLS, and ARF reports delivered to the server are browsable from the console, alongside telemetry dashboards covering metrics, traces, and event history.
**報告。** DMARC, TLS和ARF發送到伺服器的報告可以從控制台瀏覽，以及涵蓋指標、追蹤和事件歷史記錄的 遙測儀表板。
- **Backup and recovery.** Archived items recovery, snapshots, and the maintenance workflows that read from the data retention schedule.
**備份和還原。** 歸檔專案復原、快照以及從 資料保留計畫讀取的維護工作流程。
A global search at the top of the console locates settings by name; the search index is derived from the same object schema that drives the configuration screens, so results point directly at the field being looked for.
 控制台頂部的全域搜尋功能可以按名稱查找設定；搜尋索引源自驅動配置畫面的相同物件架構，因此搜尋結果直接指向正在尋找的欄位。

## Account Manager｜客戶經理

 The `/account` mount is the Account Manager. End users sign in with their mailbox credentials and manage their own password, application passwords, two-factor authentication, email aliases, and, under the Enterprise Edition, masked email addresses. The Account Manager intentionally exposes a small subset of the object model: users see only the objects that belong to their own account and only the fields they are permitted to edit.

`/account`掛載點是 帳戶管理器 。最終使用者使用郵件匣憑證登入並管理自己的密碼、應用程式密碼 、雙重認證 、電子郵件別名，以及（在企業版中）遮罩電子郵件地址 。帳戶管理器有意公開物件模型的一小部分：使用者只能看到屬於自己帳戶的對象，以及他們有權編輯的欄位。

 When an account without administrator permissions signs in at `/admin`, the console redirects to the Account Manager rather than rejecting the request outright.

 當沒有管理員權限的帳號登入`/admin`時，控制台會重新導向至帳號管理員，而不是直接拒絕該要求。

## Access and routing｜訪問和路由

 The WebUI is served over HTTP and so depends on a NetworkListener \(found in the WebUI under Settings › Network › Listeners\) whose protocol is set to `http`. Because the `/admin` and `/account` prefixes are matched against the same HTTP surface that carries JMAP, WebDAV, and the `.well-known` endpoints, operators can restrict exposure of the administrator console to a private listener while keeping the rest of the HTTP traffic on a public one. The mechanics of scoping mount paths to specific listeners are covered under HTTP access control.

 WebUI 透過HTTP提供服務，因此依賴 NetworkListener （可在 WebUI 的「設定」&gt;「網路」&gt;「監聽器`http`中找到），該監聽器的 protocol 。由於`/admin`和`/account`前綴與承載JMAP 、WebDAV 和`.well-known`端點的同一HTTP介面匹配，因此運維人員可以將主機的存取權限制在私有監聽器上，同時將其餘HTTP將掛載路徑限定到特定監聽器的機制在 HTTP存取控制中進行了介紹。

 Authentication at both mounts uses the server’s standard authentication stack, so operators can protect access with two-factor authentication and app-scoped credentials just like any other client.

 兩個掛載點的身份驗證都使用伺服器的標準身份驗證堆疊 ，因此操作員可以像任何其他用戶端一樣，使用雙重認證和應用程式範圍的憑證來保護存取。

## Relationship to the CLI and the JMAP API｜與CLI和JMAP API的關係

 Every action taken in the WebUI is backed by a JMAP method call on a documented object. The same calls are available through `stalwart-cli` \(see the CLI reference\) and directly over the JMAP API, so automated provisioning and interactive administration share the same surface. Administrators who prefer a terminal workflow, or who need to script bulk operations, can reach for the CLI without losing parity with what the WebUI offers.

 WebUI 中的每個操作都由已記錄物件的JMAP方法呼叫支援。這些呼叫也可透過`stalwart-cli` （參見 CLI參考 ）以及直接透過 JMAP API訪問，因此自動化配置和互動式管理共享相同介面。偏好終端工作流程或需要編寫批次操作腳本的管理員可以使用CLI而不會損失與 WebUI 相同的功能。

## Outbound network requirement｜出站網路需求

 The WebUI bundle is not bundled with the server binary. It is fetched on demand from `https://github.com/stalwartlabs/webui/releases/latest/` \(the resourceUrl of the built-in Application record\) the first time the server starts, then cached and reused until the retention period set by autoUpdateFrequency expires or an `UpdateApps` Action forces a fresh download. The Stalwart host therefore needs outbound HTTPS access to GitHub’s release storage, which is served from `github.com` and `objects.githubusercontent.com`.

 WebUI軟體包並未與伺服器二進位檔案打包在一起，而是按需取得。 `https://github.com/stalwartlabs/webui/releases/latest/` （這 resourceUrl 內建應用程式 記錄）伺服器首次啟動時，然後快取並重複使用，直到\[設定的保留期\]`autoUpdateFrequency`\]\([https://stalw.art/docs/ref/object/application#autoupdatefrequency](https://stalw.art/docs/ref/object/application#autoupdatefrequency)\) 過期或 `UpdateApps` 操作會強制重新下載。因此，Stalwart 主機需要出站連線。 HTTPS 存取 GitHub 的發布存儲，該存儲由以下地址提供服務： `github.com` 和 `objects.githubusercontent.com`.

 When the very first download fails, no bundle has been unpacked locally yet and **both `/admin` and `/account` return `404 Not Found`** until a download succeeds. This is a frequent symptom on freshly installed and freshly migrated servers that sit behind a restrictive egress firewall: the rest of the server starts cleanly, the HTTP listener answers, but the WebUI mount paths reply with 404 because there is no bundle to serve. Once a successful download has happened, subsequent failed refreshes are non-fatal: the previously unpacked bundle stays mounted and the WebUI keeps responding until a refresh succeeds.

 當首次下載失敗時，本地尚未解壓任何軟體包，**`/admin`和`/account`都會返回`404 Not Found`**，直到下載成功為止。這在位於嚴格出站防火牆後的新安裝或新遷移的伺服器上很常見：伺服器的其他部分啟動正常， HTTP監聽器回應正常，但 WebUI 掛載路徑返回 404 錯誤，因為沒有軟體包可供提供。一旦下載成功，後續的刷新失敗就不會造成致命後果：先前解壓縮的軟體包會保持掛載狀態，WebUI 也會繼續回應，直到刷新成功為止。

 A WebUI that loads its login page but reports a failure to import or fetch a module after sign-in is a different fault, and it is almost always the unpack directory being swept out from under the server.

 WebUI 載入了登入頁面，但在登入後報告匯入或取得模組失敗，這是另一個故障，而且幾乎總是伺服器端的 unpack 目錄被清除。

 For deployments where outbound HTTPS to GitHub is not permitted, the WebUI bundle can be downloaded out-of-band, staged on an internal HTTPS server, and the resourceUrl on the WebUI’s Application record updated to point at the internal location. The general outbound network requirement for hosted Applications applies to the WebUI in exactly the same way; it is documented separately here only because misconfiguring it on a fresh install produces the WebUI-shaped 404 most operators encounter first.

 對於不允許向 GitHub 發送出HTTPS的部署，WebUI 套件可以帶外下載，暫存在內部HTTPS上，並\([https://stalw.art/docs/ref/object/application#resourceurl](https://stalw.art/docs/ref/object/application#resourceurl)\) WebUI 的 \[Application\] 記錄`resourceUrl`使其指向內部位置。託管應用程式的通用 \[出\([https://stalw.art/docs/management/applications/#outbound-network-requirement](https://stalw.art/docs/management/applications/#outbound-network-requirement)\) \(\[[https://stalw.art/docs/ref/object/application\\\)需求\\\\\\]\\]\(https://stalw.art/docs/ref/object/application%29%25E9%259C%2580%25E6%25B1%2582%255D\)](https://stalw.art/docs/ref/object/application%255C%29%25E9%259C%2580%25E6%25B1%2582%255C%255C%255D%255D%28https://stalw.art/docs/ref/object/application%2529%2525E9%25259C%252580%2525E6%2525B1%252582%25255D%29) 也同樣適用於 WebUI；此處單獨記錄是因為在全新安裝時配置錯誤會導致大多數維運人員首先遇到的 WebUI 404 錯誤。
