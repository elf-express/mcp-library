# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[management｜管理\\\]\\\(&lt;000 目錄.md#c-31&gt;\\\) › \\\[cli\\\]\\\(&lt;000 目錄.md#c-33&gt;\\\)

`stalwart-cli` is a small, schema-driven command line tool for administering a Stalwart Mail and Collaboration server. It speaks exclusively to the JMAP API and operates on the management/configuration objects \(those whose JMAP type names are prefixed with `x:`\) exposed via the `urn:stalwart:jmap` capability.

`stalwart-cli`是一個小型、基於模式的命令列工具，用於管理 Stalwart 郵件和協作伺服器。它專門與JMAP API通信，並對透過`urn:stalwart:jmap`功能公開的管理/配置物件（ JMAP類型名稱以`x:`為前綴的物件）進行操作。

 The tool is **schema-driven**: on first use it downloads \(and caches\) a JSON schema from the server that describes every object, its fields, the forms used to render it, and the lists used to render queries. All command behaviour, validation, and human-readable output is derived from that schema, so the same binary works against any compatible Stalwart deployment without recompilation.

 該工具採用**模式驅動**：首次使用時，它會從伺服器下載（並快取）一個JSON模式，該模式描述了每個物件、其欄位、用於渲染物件的表單以及用於渲染查詢的清單。所有命令行為、驗證和人類可讀的輸出都源自於該模式，因此同一個二進位檔案無需重新編譯即可在任何相容的 Stalwart 部署中運行。

## Capabilities at a glance｜功能概覽

| Task 任務 | Command 指令 | Title 標題 |
| --- | --- | --- |
| Inspect what objects and enums the server exposes 檢查伺服器公開的物件與枚舉 | `describe` | Exploring the schema 探索模式 |
| Read a single object by id \(or a singleton\) 透過 ID 讀取單一物件（或單例） | `get` | Fetching a single object 取得單一物件 |
| List or filter objects of a given type 列出或篩選給定類型的物件 | `query` | Searching and listing 搜尋與清單 |
| Create one or more objects 建立一個或多個物件 | `create` | Creating objects 建立物件 |
| Modify an existing object \(or singleton\) 修改現有物件（或單例） | `update` | Updating objects 更新物件 |
| Destroy one or more objects 摧毀一個或多個物體 | `delete` | Removing objects 移除物體 |
| Apply a bulk plan from a JSON file 從JSON檔案應用批次計畫 | `apply` | Declarative bulk operations 宣告式批次操作 |
| Export live server state as an apply plan 將即時伺服器狀態匯出為應用程式計劃 | `snapshot` | Exporting server state 匯出伺服器狀態 |

## Installation｜安裝

 Pre-built binaries are produced for macOS \(Intel and Apple Silicon\), Linux \(x86\_64 and aarch64, glibc and musl\), and Windows \(x86\_64 and aarch64\), alongside a multi-architecture Docker image. Pick the installer that matches the platform.

 我們為 macOS（Intel 和 Apple Silicon）、Linux（x86\_64 和 aarch64，glibc 和 musl）以及 Windows（x86\_64 和 aarch64）產生了預編譯的二進位文件，同時也提供一個多架構的 Docker 映像。請選擇與您的平台相符的安裝程式。

### macOS / Linux \(shell installer\)｜macOS / Linux（shell 安裝程式）

```bash title=&amp;quot;Terminal window&amp;quot;
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/stalwartlabs/cli/releases/latest/download/stalwart-cli-installer.sh | sh
```

### Windows \(PowerShell installer\)｜Windows（PowerShell 安裝程式）

```powershell title=&amp;quot;Terminal window&amp;quot;
powershell -ExecutionPolicy Bypass -c "irm https://github.com/stalwartlabs/cli/releases/latest/download/stalwart-cli-installer.ps1 | iex"
```

### Homebrew \(macOS / Linux\)｜Homebrew（macOS / Linux）

```bash title=&amp;quot;Terminal window&amp;quot;
brew install stalwartlabs/tap/stalwart-cli
```

### npm \(Node.js, all platforms\)｜npm（Node.js，所有平台）

```bash title=&amp;quot;Terminal window&amp;quot;
npm install -g @stalwartlabs/cli
```

### Docker \(all platforms\)｜Docker（所有平台）

 A multi-architecture image \(`linux/amd64` and `linux/arm64`\) is published with every release to both GitHub Container Registry and Docker Hub:

 每次發布都會向 GitHub Container Registry 和 Docker Hub 發布一個​​多架構映像（ `linux/amd64`和`linux/arm64` ）：

```bash title=&amp;quot;Terminal window&amp;quot;
docker run --rm ghcr.io/stalwartlabs/cli --version
docker run --rm stalwartlabs/cli --version
```

Image tags track releases: a full version \(`:1.2.3`\), the minor series \(`:1.2`\), and `:latest`. Images are signed with [cosign](https://docs.sigstore.dev/cosign/overview/) and carry build-provenance attestations.

 圖片標籤追蹤版本：完整版（ `:1.2.3` ）、次要係列（ `:1.2` ）和`:latest` 。圖片附有[cosign](https://docs.sigstore.dev/cosign/overview/)簽名，並附有建構來源證明。

 Pass connection settings through the environment, and bind-mount a working directory for commands that read or write files \(`apply --file`, `snapshot --output`\):

 透過環境傳遞連接設置，並為讀取或寫入檔案的命令綁定掛載工作目錄（ `apply --file`, `snapshot --output` ）：

```bash title=&amp;quot;Terminal window&amp;quot;
docker run --rm \
  -e STALWART_URL=https://mail.example.com \
  -e STALWART_TOKEN \
  ghcr.io/stalwartlabs/cli query Account --fields id,name

docker run --rm \
  -v "$PWD:/work" -w /work \
  -e STALWART_URL -e STALWART_TOKEN \
  ghcr.io/stalwartlabs/cli apply --file plan.json
```

The container runs as a non-root user whose home is `/home/nonroot`. To persist the [schema cache](#schema-cache) across runs \(and avoid a re-fetch each invocation\), mount a volume at `/home/nonroot/.cache`:

 容器以非 root 使用者身分執行，其主目錄為`/home/nonroot` 。為了在運行之間持久化 [模式快取](#schema-cache) （並避免每次呼叫都重新取得），請在`/home/nonroot/.cache`掛載一個磁碟區：

```bash title=&amp;quot;Terminal window&amp;quot;
docker run --rm \
  -v stalwart-cli-cache:/home/nonroot/.cache \
  -e STALWART_URL -e STALWART_TOKEN \
  ghcr.io/stalwartlabs/cli describe
```

## Connecting to a server｜正在連接到伺服器

 Every invocation needs a server URL and a credential. The same flags are global and may appear before or after the subcommand.

 每次呼叫都需要伺服器URL和憑證。這些標誌是全域的，可以出現在子命令之前或之後。

| Flag 標誌 | Environment variable 環境變數 | Purpose 用途 |
| --- | --- | --- |
| `--url <URL>` | `STALWART_URL` | The Stalwart server endpoint \(required\). Stalwart 伺服器端點（必需）。 |
| `--user <USER>` | `STALWART_USER` | Basic-auth username. 基本驗證使用者名稱。 |
| `--password <PASS>` | `STALWART_PASSWORD` | Basic-auth password. Prompted interactively if absent and stdin is a TTY. 基本驗證密碼。如果未輸入密碼且標準輸入為TTY ，則會以互動方式提示輸入。 |
| `--api-key <TOKEN>` | `STALWART_TOKEN` | Bearer token. Mutually exclusive with `--user`. 持有者代幣。與`--user`互斥。 |
| `--insecure` / `-k` | \(none\) （無） | Skip TLS certificate verification \(matches `curl -k`\). 跳過TLS證書驗證（與`curl -k`匹配）。 |
| `--no-color` | \(none\) （無） | Disable ANSI color output. The `NO_COLOR` environment variable also disables colors. 禁用ANSI彩色輸出。 `NO_COLOR` 環境變數也會停用顏色。 |

A typical invocation against a local development server:

 針對本機開發伺服器的典型呼叫：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli --url http://localhost:8080 --user admin --password admin describe
```

Equivalent with environment variables \(recommended for scripts and CI\):

 與環境變數等效（推薦用於腳本和CI ）：

```bash title=&amp;quot;Terminal window&amp;quot;
export STALWART_URL=https://mail.example.com
export STALWART_USER=admin
export STALWART_PASSWORD='changeme'
stalwart-cli describe
```

For unattended use, prefer an API token:

 對於無人值守使用的情況，建議使用API令牌：

```bash title=&amp;quot;Terminal window&amp;quot;
export STALWART_URL=https://mail.example.com
export STALWART_TOKEN='eyJhbGciOi...'
stalwart-cli describe
```

## Object naming｜對象命名

 The CLI accepts object names with or without the `x:` prefix and is case-insensitive. The following are all equivalent:

 CLI接受帶或不帶`x:`前綴的物件名稱，且不區分大小寫。以下所有形式均等效：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli get Domain abc123
stalwart-cli get domain abc123
stalwart-cli get x:Domain abc123
stalwart-cli get X:DOMAIN abc123
```

Internally, names are normalised to the canonical form before any JMAP request leaves the client. In all human-readable output, the `x:` prefix is stripped \(so `x:Domain` is shown as `Domain`\).

 在內部，任何JMAP請求離開客戶端之前，名稱都會被規範化為規範形式。在所有人類可讀的輸出中， `x:`前綴都會被移除（因此`x:Domain`顯示為`Domain` ）。

## Singletons｜單例

 Some configuration objects are *singletons*: there is exactly one instance per server. Singletons accept \(or default to\) the literal id `singleton`. For example, the JMAP limits singleton can be fetched with either of these:

 某些配置物件是*單例*：每個伺服器只有一個實例。單例接受（或預設接受）字面值 ID `singleton` 。例如，可以使用下列任一方法取得限制單例JMAP ：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli get jmap
stalwart-cli get jmap singleton
```

Singletons cannot be created or destroyed, only updated. The Updating objects and Fetching a single object pages cover the specifics.

 單例物件不能創建或銷毀，只能更新。 更新物件和 取得單一物件頁面詳細介紹了具體操作。

## Multi-variant objects｜多變體對象

 Some objects \(for example `Account`\) have multiple variants discriminated by an `@type` field \(`User`, `Group`, etc.\). When creating such an object, two equivalent forms are accepted:

 某些物件（例如`Account` ）有多個變體，由`@type`字段區分（例如`User`, `Group`等）。建立\([https://stalw.art/docs/management/cli/create\)此類物件時，接受兩種等效形式：](https://stalw.art/docs/management/cli/create%2529%2525E6%2525AD%2525A4%2525E9%2525A1%25259E%2525E7%252589%2525A9%2525E4%2525BB%2525B6%2525E6%252599%252582%2525EF%2525BC%25258C%2525E6%25258E%2525A5%2525E5%25258F%252597%2525E5%252585%2525A9%2525E7%2525A8%2525AE%2525E7%2525AD%252589%2525E6%252595%252588%2525E5%2525BD%2525A2%2525E5%2525BC%25258F%2525EF%2525BC%25259A)

- The shorthand `Object/Variant` syntax \(`stalwart-cli create account/user ...`\), which auto-injects `@type`.
簡寫`Object/Variant`語法 \( `stalwart-cli create account/user ...` \) 會自動注入`@type` 。
- Passing `@type` explicitly via `--field` or as part of a `--json` payload.
透過 `--field` 明確傳遞 `@type` 或作為 `--json` 有效負載的一部分。
For get, query, update, and delete, only the bare object name is accepted \(the slash form is rejected\).
 為了 get, query, update， 和 delete只接受裸物件名稱（拒絕斜線形式）。

## Output formats｜輸出格式

 Read commands support `--json` for machine-readable output. Each output record is a single compact JSON line. Commands that produce a single record \(`get --json`\) emit one line. Commands that produce a stream \(`query --json`, `apply --json`, `snapshot`\) emit **NDJSON** \(newline-delimited JSON\): one complete record per line, no enclosing array. This format streams \(constant memory regardless of result-set size\) and pipes naturally into `jq`, `mlr`, `awk`, and similar tools. To consume an NDJSON stream as a single JSON array, pipe through `jq -s '.'`.

 讀取命令支援`--json`以進行機器可讀輸出。每個輸出記錄都是一個緊湊的JSON行。產生單一記錄的命令 \( `get --json` \) 輸出一行。產生資料流的命令 \( `query --json`, `apply --json`, `snapshot` \) 輸出 **NDJSON**（換行符分隔的JSON ）：每行一個完整的記錄，沒有封閉的陣列。這種格式可以串流（無論結果集大小，記憶體佔用都恆定），並且可以自然地透過管道傳遞給`jq`, `mlr`, `awk`和類似的工具。若要將NDJSON資料流作為單一JSON數組使用，請透過管道傳遞給`jq -s '.'` 。

 Without `--json`, the CLI renders a human-friendly view driven by the schema’s form definitions, with ANSI color when stdout is a TTY.

 如果沒有`--json` ， CLI會根據模式的形式定義呈現一個對人類友好的視圖，當 stdout 為TTY時， ANSI會使用顏色。

 Color is automatically disabled when:

 以下情況會自動停用顏色：

- stdout is not a TTY \(for example, when piping to `head`, `less`, or a file\).
stdout 不是TTY （例如，當透過管道輸出到`head`, `less`或檔案時）。
- The `NO_COLOR` environment variable is set.
`NO_COLOR`環境變數已設定。
- `--no-color` is passed explicitly.
`--no-color`被顯式傳遞。
## Schema cache｜模式快取

 The schema is fetched from `/api/schema` and cached locally under the standard XDG cache directory:

 此模式從`/api/schema`獲取，並緩存在本地標準的XDG快取目錄中：

- Linux: `~/.cache/stalwart-cli/<server-hash>/`
Linux： `~/.cache/stalwart-cli/<server-hash>/`
- macOS: `~/Library/Caches/stalwart-cli/<server-hash>/`
macOS： `~/Library/Caches/stalwart-cli/<server-hash>/`
- Windows: `%LOCALAPPDATA%\stalwart-cli\<server-hash>\`
Windows： `%LOCALAPPDATA%\stalwart-cli\<server-hash>\`
`<server-hash>` is a URL-safe base64 of the SHA-256 of the normalised server URL, so multiple Stalwart deployments coexist in the cache without collision. The cache is consulted before each command. If the server hash hasn’t changed, no schema download is issued. If the network is unreachable but a cached copy exists, the CLI emits a warning and proceeds with the cached schema.
`<server-hash>`是URL安全的 base64 編碼，其URL SHA 256 編碼，因此快取中可以同時存在多個 Stalwart 部署而不會發生衝突。每次執行命令前都會查詢快取。如果伺服器雜湊值沒有改變，則不會下載模式。如果網路不可達但快取中存在副本， CLI會發出警告並使用快取的模式繼續執行。

## Errors｜錯誤

 All errors are written to stderr in the form `error: <message>` and the process exits with a non-zero status. JMAP-level errors are surfaced with their `type` and `description`. Per-object set errors \(validation failures, primary key violations, dependent-object protection, etc.\) include the affected properties and any linked-object information returned by the server.

 所有錯誤都以`error: <message>`的形式寫入stderr，並且進程以非零狀態退出。 JMAP 級錯誤透過其 `type` 和 `description` 出現。每個物件設定的錯誤（驗證失敗、主鍵違規、依賴物件保護等）包括受影響的屬性和伺服器傳回的任何連結物件資訊。

 Piping output to a short-lived consumer such as `head` or `less` is handled cleanly: a broken pipe is treated as a normal end of output, not as an error.

 將輸出透過管道傳遞給`head`或`less`等短生命週期消費者時，處理方式很乾淨：管道破裂被視為正常的輸出結束，而不是錯誤。

## Getting help｜尋求協助

 Standard help is available for every subcommand:

 每個子命令都有標準幫助文件：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli --help
stalwart-cli get --help
stalwart-cli apply --help
```

For schema-driven help \(descriptions of objects, fields, enums, filters, and sort options\), use the describe command.

 對於模式驅動的幫助（物件、欄位、枚舉、過濾器和排序選項的描述），請使用 describe命令。
