# API Endpoints｜API端點

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[development｜發展\\\]\\\(&lt;000 目錄.md#c-20&gt;\\\)

The Stalwart API is deliberately small. The bulk of server configuration and mailbox data is accessed through JMAP \(under `/jmap`\), which is a separate API with its own documentation; the endpoints below are helpers for authentication, account introspection, configuration schema retrieval and live \(Server-Sent Events\) telemetry.

 Stalwart API特意設計得比較小。大部分伺服器配置和郵箱資料都透過JMAP （在`/jmap`下）訪問，這是一個獨立的API有自己的文檔；下面的端點是用於身份驗證、帳戶自省、配置架構檢索和實時（伺服器發送事件）遙測的輔助函數。

 All paths are relative to the server’s base URL, e.g. `https://mail.example.com`.

 所有路徑均相對於伺服器的基址URL ，例如`https://mail.example.com` 。

## Authentication｜驗證

 Requests to the Management API are authenticated with one of:

 管理請求API身份驗證方式如下：

| Scheme 方案 | How to send 如何發送 | When to use 何時使用 |
| --- | --- | --- |
| **Bearer**持有者 | `Authorization: Bearer <access_token>` | Normal programmatic access with an OAuth2 access token. 使用 OAuth2 存取權杖進行常規程式存取。 |
| **Basic**基礎版 | `Authorization: Basic <base64(user:secret)>` | Simple scripts or initial bootstrap. 簡單的腳本或初始引導程式。 |
| **Live token**即時令牌 | `?token=<short_lived_token>` in the URL query `?token=<short_lived_token>`在URL查詢中 | Server-Sent Events streams from browsers where an `Authorization` header cannot be set on `EventSource`. The token is obtained from `/api/token/{kind}` and expires after 60 seconds. 來自瀏覽器的伺服器發送事件流，其中`Authorization`標頭無法在`EventSource`上設定。令牌從`/api/token/{kind}`獲取，並在 60 秒後過期。 |

Anonymous endpoints \(`/api/auth`, `/api/discover/{email}`\) are rate-limited.

 匿名端點（ `/api/auth`, `/api/discover/{email}` ）受到速率限制。

 Failed authentication returns `401 Unauthorized` with a `WWW-Authenticate: Bearer realm="Stalwart Server"` header and an `application/problem+json` body \(RFC 7807\).

 驗證失敗回傳`401 Unauthorized`帶有`WWW-Authenticate: Bearer realm="Stalwart Server"`標頭和`application/problem+json`正文（ RFC 7807）。

## POST /api/auth

 Authenticate a user and obtain an OAuth authorization code. Used by the web UI and by device-flow clients to complete login. Anonymous, rate-limited.

 驗證使用者身分並取得 OAuth 授權碼。供 Web UI和裝置流用戶端用於完成登入。匿名，限速。

**Request body** — tagged union discriminated by `type`:

**請求正文** — 被`type`歧視的工會：

### `authCode` — authorization-code flow \(optionally with PKCE\)｜`authCode` — 授權碼流程（選配PKCE ）

```json
{
  "type": "authCode",
  "accountName": "[email protected]",
  "accountSecret": "s3cret",
  "mfaToken": null,
  "clientId": "stalwart-webui",
  "redirectUri": "https://mail.example.com/admin/oauth/callback",
  "nonce": null,
  "scope": null,
  "codeChallenge": "E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM",
  "codeChallengeMethod": "S256",
  "state": null
}
```

| Field 欄位 | Type 類型 | Required 必填 | Notes 備註 |
| --- | --- | --- | --- |
| `accountName` | string 字串 | yes 是 | Account name or email. 帳號名稱或信箱。 |
| `accountSecret` | string 字串 | yes 是 | Account password. 帳戶密碼。 |
| `mfaToken` | string 字串 | no 否 | Provided on a retry after a previous `mfaRequired` response. 在先前的`mfaRequired`回應後重試時提供。 |
| `clientId` | string 字串 | yes 是 | OAuth client identifier. OAuth 用戶端標識符。 |
| `redirectUri` | string \(URI\) 字串 \( URI \) | no 否 | Must use `https://` unless the server is in recovery or dev mode. 除非伺服器處於復原模式或開發模式，否則必須使用`https://` 。 |
| `nonce` | string 字串 | no 否 | OpenID Connect nonce. OpenID Connect nonce。 |
| `scope` | string 字串 | no 否 | Requested OAuth scope. 請求的 OAuth 範圍。 |
| `codeChallenge` | string 字串 | no 否 | PKCE code challenge \(RFC 7636\). PKCE程式碼挑戰 \( RFC 7636\)。 |
| `codeChallengeMethod` | string 字串 | no 否 | `plain` or `S256`. Defaults to `plain` when a challenge is present. `plain`或`S256` 。當有挑戰時，預設為`plain` 。 |
| `state` | string 字串 | no 否 | Opaque value echoed back to the client. 不透明值已回顯給客戶端。 |

### `authDevice` — device-flow completion｜`authDevice` — 設備流完成

```json
{
  "type": "authDevice",
  "accountName": "[email protected]",
  "accountSecret": "s3cret",
  "code": "BDWP-HQPK"
}
```

| Field 欄位 | Type 類型 | Required 必填 | Notes 備註 |
| --- | --- | --- | --- |
| `accountName` | string 字串 | yes 是 |  |
| `accountSecret` | string 字串 | yes 是 |  |
| `mfaToken` | string 字串 | no 否 |  |
| `code` | string 字串 | yes 是 | User-facing device code issued by `POST /auth/device`. 由`POST /auth/device`頒發的用戶設備代碼。 |

**Response body** — tagged union discriminated by `type`:

**回應正文** — 被`type`標記的工會歧視：

| `type` | Extra fields 附加欄位 | Meaning 意義 |
| --- | --- | --- |
| `authenticated` | `clientCode` \(string\) `clientCode` \(字串\) | Credentials accepted. Exchange `clientCode` at `POST /auth/token`. 憑證已接受。請在`POST /auth/token`處交換`clientCode` 。 |
| `verified` | – | Device-flow verification succeeded. 設備流驗證成功。 |
| `mfaRequired` | – | Multi-factor is required; retry with a valid `mfaToken`. 需要多因素認證；請使用有效的`mfaToken`重試。 |
| `failure` | – | Credentials rejected. 憑證被拒絕。 |

Example success:

 成功案例：

```json
{ "type": "authenticated", "clientCode": "3F7A9C1E4B2D8E6F" }
```

## GET /api/discover/{email}

 Return the OpenID Connect discovery document for the directory that owns the domain of `email`. If the domain is not bound to an external OIDC directory, the server’s own discovery document \(equivalent to `/.well-known/openid-configuration`\) is returned.

 傳回擁有網域`email`的目錄的 OpenID Connect 發現文件。如果該網域未綁定到外部OIDC目錄，則傳回伺服器本身的發現文件（相當於`/.well-known/openid-configuration` ）。

 Anonymous, rate-limited.

 匿名，限速。

**Path parameters**

**路徑參數**

| Name 名稱 | In 在 | Type 類型 | Description 描述 |
| --- | --- | --- | --- |
| `email` | path 路徑 | string 字串 | Email address or account name. 電子郵件地址或帳號名稱。 |

**Response** — `200 OK`, `application/json`. Standard OIDC discovery metadata \(issuer, `authorization_endpoint`, `token_endpoint`, etc. per RFC 8414\).

**回應** — `200 OK`, `application/json` . 標準OIDC發現元資料（頒發者、 `authorization_endpoint`, `token_endpoint`等，請參閱RFC 8414）。

## GET /api/account

 Return the authenticated account’s effective permissions, server edition and preferred locale. Used by the web UI to tailor the interface.

 傳回已驗證帳戶的有效權限、伺服器版本和首選語言環境。供 Web UI用於客製化介面。

**Response** — `200 OK`, `application/json`:

**回覆** — `200 OK`, `application/json` :

```json
{
  "permissions": [
    "authenticate",
    "jmap-email-get",
    "sys-account-settings-get"
  ],
  "edition": "oss",
  "locale": "en-US"
}
```

| Field 字段 | Type 類型 | Notes 備註 |
| --- | --- | --- |
| `permissions` | string\[\] | Effective permissions, filtered to exclude internal/system-only entries. In bootstrap mode, limited to `sys-bootstrap-get`/`-update`. 有效權限，已過濾，排除僅限內部/系統權限的條目。在引導模式下，僅限`sys-bootstrap-get`/`-update` 。 |
| `edition` | string 字串 | One of `oss`, `community`, `enterprise`. `oss`, `community`, `enterprise`之一。 |
| `locale` | string 字串 | BCP 47–style language tag. BCP 47 樣式語言標籤。 |

## GET /api/schema

 Redirect \(`302`\) to `/api/schema/{hash}`, where `{hash}` is the SHA-256 hex digest of the current configuration schema. Callers that do not already know the current hash should follow this redirect; callers that have cached a schema at a specific hash can fetch it directly — that URL is immutable.

 將 \( `302` \) 重新導向到`/api/schema/{hash}` ，其中`{hash}`是目前設定模式的SHA -256 十六進位摘要。不知道目前雜湊值的呼叫者應遵循此重定向；已快取特定雜湊值的模式的呼叫者可以直接取得該模式－該URL是不可變的。

 ---

## GET /api/schema/{hash}

 Return the JSON Schema describing the full Stalwart configuration tree. The response is always `Content-Encoding: gzip` and is served with an immutable cache policy: the schema at a given hash never changes. If the supplied hash does not match the server’s current schema, the server redirects to the correct URL.

 傳回描述完整 Stalwart 配置樹的JSON模式。回應始終為`Content-Encoding: gzip` ，並採用不可變快取策略：給定哈希值的模式永遠不會改變。如果提供的雜湊值與伺服器的目前模式不匹配，伺服器將重定向到正確的URL 。

**Path parameters**

**路徑參數**

| Name 名稱 | In 在 | Type 類型 | Description 描述 |
| --- | --- | --- | --- |
| `hash` | path 路徑 | string 字串 | SHA-256 hex digest of the schema document. SHA -256 是模式文件的十六進位摘要。 |

**Response** — `200 OK`, `application/json` \(gzip-encoded\) containing a JSON Schema document.

**回應** — `200 OK`, `application/json` （gzip 編碼）包含JSON Schema 文件。

## GET /api/token/{kind}

 Issue a short-lived \(60 second\) bearer token for a specific Server-Sent Events stream. The returned token is used as the `?token=` query parameter on the matching `/api/live/...` endpoint, which lets browsers authenticate an `EventSource` connection without being able to set request headers.

 為特定的伺服器傳送事件流頒發一個有效期較短（60 秒）的持有者令牌。傳回`?token=`令牌將用作匹配的`/api/live/...`查詢參數，以便瀏覽器無需設定`EventSource`頭即可驗證連線。

**Path parameters**

**路徑參數**

| `kind` | Permission required 需要權限 | Enterprise only 僅限企業用戶 |
| --- | --- | --- |
| `delivery` | `LiveDeliveryTest` | no 沒有 |
| `tracing` | `LiveTracing` | yes 是 |
| `metrics` | `LiveMetrics` | yes 是 |

**Response** — `200 OK`, `text/plain` — the opaque token string, valid for 60 seconds and bound to the matching `/api/live/{kind}` path.

**回應** — `200 OK`, `text/plain` — 不透明的令牌字串，有效期為 60 秒，並綁定到匹配的`/api/live/{kind}`路徑。

 Requesting `tracing` or `metrics` on a non-Enterprise build returns `404 Not Found`.

 在非企業版構建中請求`tracing`或`metrics`將返回`404 Not Found` 。

## GET /api/live/delivery/{target}

 Stream outbound-delivery diagnostics as Server-Sent Events. Opens a long-running `text/event-stream` that reports each stage of an outbound delivery attempt to `target` \(MX lookup, MTA-STS fetch, DANE/TLSA validation, SMTP conversation, etc.\) and ends with a `completed` event.

 將出站交付診斷資訊作為伺服器發送事件進行串流傳輸。開啟一個長時間運行的`text/event-stream`該進程會將出站交付嘗試的每個階段報告給`target` （ MX查找、 MTA-STS獲取、 DANE/TLSA發現、 SMTP獲取、 `completed`

 Requires the `LiveDeliveryTest` permission. May be authenticated via a normal `Authorization` header **or** via `?token=` using a token from `/api/token/delivery`.

 需要`LiveDeliveryTest`權限。可以透過普通的`Authorization`標頭進行身份驗證 **或** 透過使用`/api/token/delivery`中的令牌透過`?token=`進行身份驗證。

**Path parameters**

**路徑參數**

| Name 名稱 | In 在 | Type 類型 | Description 描述 |
| --- | --- | --- | --- |
| `target` | path 路徑 | string 字串 | Domain or email address to diagnose. 用於診斷的網域名稱或電子郵件地址。 |

**Query parameters**

**查詢參數**

| Name 名稱 | Type 類型 | Default 預設值 | Description 描述 |
| --- | --- | --- | --- |
| `timeout` | integer 整數 | `30` | Maximum stream lifetime in seconds \(≥ 1\). 流的最大生命週期（秒）（≥ 1）。 |
| `token` | string 字串 | – | Short-lived token from `/api/token/delivery`. 來自`/api/token/delivery`的短生命週期標記。 |

**Response** — `200 OK`, `Content-Type: text/event-stream`. Each frame has the form:

**回覆** — `200 OK`, `Content-Type: text/event-stream` 。每個幀的形式如下：

```yaml
event: event
data: [<DeliveryStage JSON>]
```

…where `<DeliveryStage JSON>` is an object tagged by `type` — for example `{"type":"mxLookupStart","domain":"example.com"}`, `{"type":"mxLookupSuccess","mxs":[...],"elapsed":42}`, and so on. The final frame is always `{"type":"completed"}`.

 …其中`<DeliveryStage JSON>`是`type`標記的物件－例如`{"type":"mxLookupStart","domain":"example.com"}`, `{"type":"mxLookupSuccess","mxs":[...],"elapsed":42}` ，依此類推。最後一幀始終是`{"type":"completed"}` 。

## GET /api/live/tracing *\(Enterprise\)*｜GET /api/live/tracing *\(企業版\)*

**Response** — `200 OK`, `Content-Type: text/event-stream`.

**回應** — `200 OK`, `Content-Type: text/event-stream` 。

## Error responses｜錯誤回應

 All error responses use [RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) `application/problem+json`:

 所有錯誤回應均使用 [RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) `application/problem+json` :

```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Invalid or missing credentials."
}
```

| Status 狀態 | Meaning 意義 |
| --- | --- |
| `400` | Malformed request body or invalid parameters. 請求體格式錯誤或參數無效。 |
| `401` | Missing or invalid credentials. Response includes `WWW-Authenticate`. 憑證缺失或無效。響應包含`WWW-Authenticate` 。 |
| `403` | Authenticated, but lacking the required permission. 已通過身份驗證，但缺少所需權限。 |
| `404` | Resource not found, or Enterprise-only endpoint on an OSS build. 資源未找到，或OSS版本中僅包含企業版端點。 |
| `429` | Anonymous-request rate limit exceeded. 匿名請求速率已超出限制。 |
