# SQL Read Replicas｜SQL讀取副本

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[storage｜貯存\\\]\\\(&lt;000 目錄.md#c-72&gt;\\\) › \\\[backends｜後端\\\]\\\(&lt;000 目錄.md#c-73&gt;\\\) › \\\[composite｜合成的\\\]\\\(&lt;000 目錄.md#c-74&gt;\\\)

SQL read replicas are a well-known database architecture pattern for separating read and write traffic. A primary database handles all write operations, ensuring consistent updates; one or more read replicas, synchronised from the primary, handle read traffic. This separation reduces load on the primary and allows the read path to scale horizontally.

 SQL只讀副本是一種眾所周知的資料庫架構模式，用來分離讀寫流量。主資料庫處理所有寫入操作，確保更新的一致性；一個或多個從主資料庫同步的唯讀副本處理讀取流量。這種分離方式降低了主資料庫的負載，並允許讀取路徑進行水平擴展。

 Stalwart supports this pattern for any SQL backend that itself supports read replicas \(PostgreSQL, MySQL, MariaDB, Galera, AlloyDB, and similar\). Using read replicas improves throughput in read-heavy environments while preserving write consistency.

 Stalwart 支援任何支援只讀副本的SQL後端（例如 PostgreSQL、MySQL、MariaDB、Galera、AlloyDB 等）。使用唯讀副本可以在讀取密集型環境中提高吞吐量，同時保持寫入一致性。

 This feature is available exclusively in the Enterprise Edition of Stalwart and is not included in the Community Edition.

 此功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

## Configuration｜配置

 Read replicas are configured directly on the PostgreSQL or MySQL / MariaDB store; there is no standalone SQL-replica variant at the top level of DataStore, BlobStore, or SearchStore. See the backend-specific pages for the exact field list and examples.

 只讀副本直接在 PostgreSQL 或 MySQL / MariaDB 儲存上配置； DataStore、BlobStore 或 SearchStore 頂層變體沒有獨立的 SQL 頂層變體。有關確切的欄位清單和範例，請參閱後端特定頁面。
