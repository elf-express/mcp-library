# App Passwords｜應用密碼

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[authentication｜驗證\\\]\\\(&lt;000 目錄.md#c-4&gt;\\\)

Application Passwords are unique passwords that allow users to access their email accounts from devices or applications that do not support Two-Factor Authentication. They provide a way to use legacy mail clients or tools that do not support the `OAUTHBEARER` or `XOAUTH2` SASL mechanisms while preserving the benefits of 2FA on the primary account password.

 應用程式密碼是唯一的密碼，允許使用者從不支援雙重認證 \( \([https://stalw.art/docs/auth/authentication/2fa](https://stalw.art/docs/auth/authentication/2fa)\) \) 的裝置或應用程式存取其電子郵件帳戶。它們提供了一種使用不支援雙重認證 \( `OAUTHBEARER` `XOAUTH2` SASL機制的舊版郵件用戶端或工具的方法，同時保留了主帳戶密碼的 2FA 優勢。

 Application Passwords are most useful in a few scenarios. Older email clients that do not support OAuth cannot prompt for a TOTP code, so standard 2FA is impractical with them; an Application Password allows these clients to authenticate securely. Third-party applications and services that have not adopted modern authentication mechanisms can also connect using an Application Password rather than the main account password. Finally, automated scripts and tools that need non-interactive access to a mailbox can authenticate with an Application Password scoped to the required permissions.

 應用程式密碼在以下幾種情況下最為有用。不支援 OAuth 的舊版電子郵件用戶端無法提示輸入TOTP代碼，因此標準的雙重認證 \(2FA\) 對它們來說並不實用；應用程式密碼允許這些用戶端安全地進行身份驗證。尚未採用現代身份驗證機制的第三方應用程式和服務也可以使用應用程式密碼而非主帳戶密碼進行連接。最後，需要以非互動式方式存取郵箱的自動化腳本和工具可以使用權限範圍限定的應用程式密碼進行身份驗證。

 Each Application Password is managed as a distinct credential, so it can be named, inspected, and revoked without affecting other sessions.

 每個應用程式密碼都以單獨的憑證進行管理，因此可以對其進行命名、檢查和撤銷，而不會影響其他會話。

## Managing App Passwords｜管理應用程式密碼

 Users create and remove Application Passwords from the self-service portal, under the App Passwords menu option. The portal lists existing Application Passwords and allows individual entries to be revoked.

 使用者可透過自助服務入口網站\([https://stalw.art/docs/management/webui/\)的「應用密碼」選單選項建立和刪除應用程式密碼。此入口網站會列出現有的應用程式密碼，並允許使用者撤銷單一密碼條目。](https://stalw.art/docs/management/webui/%2529%2525E7%25259A%252584%2525E3%252580%25258C%2525E6%252587%252589%2525E7%252594%2525A8%2525E5%2525AF%252586%2525E7%2525A2%2525BC%2525E3%252580%25258D%2525E9%252581%2525B8%2525E5%252596%2525AE%2525E9%252581%2525B8%2525E9%2525A0%252585%2525E5%2525BB%2525BA%2525E7%2525AB%25258B%2525E5%252592%25258C%2525E5%252588%2525AA%2525E9%252599%2525A4%2525E6%252587%252589%2525E7%252594%2525A8%2525E7%2525A8%25258B%2525E5%2525BC%25258F%2525E5%2525AF%252586%2525E7%2525A2%2525BC%2525E3%252580%252582%2525E6%2525AD%2525A4%2525E5%252585%2525A5%2525E5%25258F%2525A3%2525E7%2525B6%2525B2%2525E7%2525AB%252599%2525E6%25259C%252583%2525E5%252588%252597%2525E5%252587%2525BA%2525E7%25258F%2525BE%2525E6%25259C%252589%2525E7%25259A%252584%2525E6%252587%252589%2525E7%252594%2525A8%2525E7%2525A8%25258B%2525E5%2525BC%25258F%2525E5%2525AF%252586%2525E7%2525A2%2525BC%2525EF%2525BC%25258C%2525E4%2525B8%2525A6%2525E5%252585%252581%2525E8%2525A8%2525B1%2525E4%2525BD%2525BF%2525E7%252594%2525A8%2525E8%252580%252585%2525E6%252592%2525A4%2525E9%25258A%2525B7%2525E5%252596%2525AE%2525E4%2525B8%252580%2525E5%2525AF%252586%2525E7%2525A2%2525BC%2525E6%2525A2%25259D%2525E7%25259B%2525AE%2525E3%252580%252582)

 Each Application Password is represented by an AppPassword object \(found in the WebUI under Account › Credentials › App Passwords\). The credential carries a description, an optional expiresAt, an optional list of allowedIps that restrict where the credential may be used, and a permissions mode controlling whether the credential inherits, restricts, or replaces the account’s permissions. The secret itself is server-set and returned only on creation.

 每個應用程式密碼都由一個 AppPassword物件表示（可在 WebUI 的「帳戶」&gt;「憑證」&gt;「應用程式密碼」下找到）。憑證包含一個 description ，一個可選的 expiresAt ，一個可選的 allowedIps列表（用於限制憑據的使用範圍），以及一個 \[ `permissions` \([https://stalw.art/docs/ref/object/app-password#permissions\)模式（用於控制憑證是繼承、限制還是替換帳戶的權限）。密鑰本身由伺服器設置，僅在創建時返回。](https://stalw.art/docs/ref/object/app-password#permissions%2529%2525E6%2525A8%2525A1%2525E5%2525BC%25258F%2525EF%2525BC%252588%2525E7%252594%2525A8%2525E6%252596%2525BC%2525E6%25258E%2525A7%2525E5%252588%2525B6%2525E6%252586%252591%2525E8%2525AD%252589%2525E6%252598%2525AF%2525E7%2525B9%2525BC%2525E6%252589%2525BF%2525E3%252580%252581%2525E9%252599%252590%2525E5%252588%2525B6%2525E9%252582%252584%2525E6%252598%2525AF%2525E6%25259B%2525BF%2525E6%25258F%25259B%2525E5%2525B8%2525B3%2525E6%252588%2525B6%2525E7%25259A%252584%2525E6%2525AC%25258A%2525E9%252599%252590%2525EF%2525BC%252589%2525E3%252580%252582%2525E5%2525AF%252586%2525E9%252591%2525B0%2525E6%25259C%2525AC%2525E8%2525BA%2525AB%2525E7%252594%2525B1%2525E4%2525BC%2525BA%2525E6%25259C%25258D%2525E5%252599%2525A8%2525E8%2525A8%2525AD%2525E7%2525BD%2525AE%2525EF%2525BC%25258C%2525E5%252583%252585%2525E5%25259C%2525A8%2525E5%252589%2525B5%2525E5%2525BB%2525BA%2525E6%252599%252582%2525E8%2525BF%252594%2525E5%25259B%25259E%2525E3%252580%252582)

 Administrators have limited control over Application Passwords. They can view and revoke a user’s Application Passwords but cannot create new ones on a user’s behalf.

 管理員對應用程式密碼的控制權限有限。他們可以查看和撤銷使用者的應用程式密碼，但不能代表使用者建立新密碼。

## Internal Storage｜內部儲存

 Each Application Password is stored on the account as one of its secrets, in the form `$app$name$password`, where `$app$` marks the secret as an Application Password, `name` is the unique identifier for the credential, and `password` is the hashed secret. The `$app$` prefix keeps Application Passwords distinguishable from other credential kinds, and storing only the hash of the generated secret prevents the raw password from being recovered from the directory.

 每個應用程式密碼都作為其機密之一儲存在帳戶中，格式為 `$app$name$password`，其中 `$app$` 將機密標記為應用程式密碼，`name` 是憑證的唯一識別符，`password` 是雜湊機密。 `$app$` 前綴使應用程式密碼與其他憑證類型區分開來，並且僅儲存產生的秘密的雜湊值可防止從目錄中恢復原始密碼。
