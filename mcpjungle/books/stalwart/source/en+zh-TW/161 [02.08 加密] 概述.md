# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[encryption｜加密\\\]\\\(&lt;000 目錄.md#c-25&gt;\\\)

Encryption at rest is a term used to describe the process of encrypting data while it is stored, or “at rest”, on persistent media such as hard drives, solid-state drives, or other forms of digital storage. The purpose of encryption at rest is to ensure that data stored on these media is not readable or accessible without the necessary decryption keys. The process usually involves taking clear-text data and converting it into cipher-text using an encryption algorithm and an encryption key. The key is a secret string of bits used by the encryption algorithm to scramble the data in a specific way. Without the key, or without a way to derive it, the scrambled data remains unintelligible and secure.

 靜態加密是指在資料儲存在硬碟、固態硬碟或其他數位儲存媒體等持久媒體上時對其進行加密的過程。靜態加密的目的是確保儲存在這些媒體上的資料在沒有解密金鑰的情況下無法讀取或存取。這個過程通常涉及使用加密演算法和加密金鑰將明文資料轉換為密文。金鑰是一串秘密的比特，加密演算法使用該比特以特定方式對資料進行加密。如果沒有金鑰或無法推導出金鑰的方法，加密後的資料將保持不可理解且安全。

 Stalwart applies a user-centric encryption strategy where each user’s plain-text messages are automatically encrypted using their provided OpenPGP \(Pretty Good Privacy\) public key or S/MIME \(Secure/Multipurpose Internet Mail Extensions\) certificate before the messages are written to disk. Only the intended recipient, who holds the corresponding private key, can decrypt and access the message contents. As a result, system administrators with access to the server’s data cannot decrypt and read the messages. Even if unauthorized access occurs, the stored messages appear as unintelligible ciphertext without the corresponding private key. This design protects each user’s messages against external compromise as well as internal threats.

 Stalwart 採用以使用者為中心的加密策略，在將訊息寫入磁碟之前，每個使用者的純文字訊息都會使用其提供的 OpenPGP（相當好的隱私）公鑰或 S/MIME（安全/多用途 Internet 擴充工具）憑證自動加密。只有持有相應私鑰的預期接收者才能解密並存取訊息內容。因此，有權存取伺服器資料的系統管理員無法解密和讀取訊息。即使發生未經授權的訪問，儲存的訊息也會顯示為難以理解的密文，而沒有相應的私鑰。這種設計可以保護每個用戶的消息免受外部損害以及內部威脅。

## Configuration｜配置

 Server-wide encryption-at-rest behaviour is configured on the Email singleton \(found in the WebUI under Settings › Email › Defaults, Settings › Email › Encryption, Settings › Email › Limits, Settings › Email › Storage\). Two fields govern the behaviour:

 伺服器級靜態資料加密行為在 Email單例中配置（可在 WebUI 的「設定」&gt;「電子郵件」&gt;「預設值」、「設定」&gt;「電子郵件」&gt;「加密」、「設定」&gt;「電子郵件」&gt;「限制」和「設定」&gt;「電子郵件」&gt;「儲存」中找到）。該行為由兩個字段控制：

- encryptAtRest: when `true` \(the default\), messages delivered via SMTP or LMTP are automatically encrypted before being written to disk, provided the recipient has registered an S/MIME certificate or OpenPGP public key. Setting this field to `false` disables the feature for all accounts.
encryptAtRest ：當`true`為預設值時，透過SMTP或LMTP發送的訊息在寫入磁碟之前會自動加密，前提是收件者已註冊 S/ MIME鑰或 OpenPGP 公鑰。將此欄位設為`false`將停用所有帳戶的此功能。
- encryptOnAppend: when `true`, messages manually appended by a client over JMAP or IMAP are also encrypted. The default is `false`, which leaves appended messages untouched so that clients retain full control over the contents they store.
encryptOnAppend ：當`true`為真時，客戶端透過JMAP或IMAP手動附加的訊息也會加密。預設值為`false` ，此時附加的訊息保持不變，客戶端可以完全控制其儲存的內容。
The server-wide encryptOnAppend value is an override: when set to `true`, it applies to every account regardless of the per-account `encryptOnAppend` carried inside encryptionAtRest. When the server-wide flag is `false`, the per-account setting applies.
 伺服器範圍的 encryptOnAppend值是一個覆蓋值：當設定為`true`時，它將應用於所有帳戶，而不管`encryptionAtRest` \]\([https://stalw.art/docs/ref/object/account-settings#encryptionatrest\)中包含的帳戶等級\`encryptOnAppend\`值如何。當伺服器範圍的標誌為\`false\`時，將會套用帳戶級設定。](https://stalw.art/docs/ref/object/account-settings#encryptionatrest%2529%2525E4%2525B8%2525AD%2525E5%25258C%252585%2525E5%252590%2525AB%2525E7%25259A%252584%2525E5%2525B8%2525B3%2525E6%252588%2525B6%2525E7%2525AD%252589%2525E7%2525B4%25259A%252560encryptOnAppend%252560%2525E5%252580%2525BC%2525E5%2525A6%252582%2525E4%2525BD%252595%2525E3%252580%252582%2525E7%252595%2525B6%2525E4%2525BC%2525BA%2525E6%25259C%25258D%2525E5%252599%2525A8%2525E7%2525AF%252584%2525E5%25259C%25258D%2525E7%25259A%252584%2525E6%2525A8%252599%2525E8%2525AA%25258C%2525E7%252582%2525BA%252560false%252560%2525E6%252599%252582%2525EF%2525BC%25258C%2525E5%2525B0%252587%2525E6%25259C%252583%2525E5%2525A5%252597%2525E7%252594%2525A8%2525E5%2525B8%2525B3%2525E6%252588%2525B6%2525E7%2525B4%25259A%2525E8%2525A8%2525AD%2525E5%2525AE%25259A%2525E3%252580%252582)

 For example:

 例如：

```json
{
  "encryptAtRest": true,
  "encryptOnAppend": false
}
```

Per-account encryption settings, including the selection of a specific public key and the symmetric algorithm, are carried on the AccountSettings singleton \(found in the WebUI under Account › Settings\) through the encryptionAtRest field. Public keys themselves are stored as PublicKey objects \(found in the WebUI under Account › Public Keys\); see OpenPGP and S/MIME for the accepted key formats, and Management for how end users manage their own settings.

 每個帳戶的加密設置，包括特定公鑰和對稱加密演算法的選擇，都儲存在 AccountSettings單例物件（位於 WebUI 的「帳戶」&gt;「設定」下）中，並透過 encryptionAtRest欄位進行管理。公鑰本身儲存為 PublicKey物件（位於 WebUI 的「帳戶」&gt;「公鑰」下）；有關可接受的金鑰格式，請參閱 OpenPGP和 S/ MIME ：有關最終使用者如何管理\([https://stalw.art/docs/encryption/manage](https://stalw.art/docs/encryption/manage)\) 。
