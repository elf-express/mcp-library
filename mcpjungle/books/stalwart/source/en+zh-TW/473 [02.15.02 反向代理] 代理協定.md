# Proxy Protocol｜代理協定

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\) › \\\[reverse proxy｜反向代理\\\]\\\(&lt;000 目錄.md#c-64&gt;\\\)

The Proxy Protocol \(also known as the HAProxy protocol\) extends a TCP connection with metadata describing the original client. Without it, a server behind a proxy sees only the proxy’s IP address, which breaks IP-based access controls, sender authentication, and accurate logging. The Proxy Protocol prepends each forwarded connection with a small header that the back-end server parses to recover the original client IP and the TLS status of the original connection.

 代理協定（也稱為 HAProxy 協定）會為TCP連線新增描述原始客戶端的元資料。如果沒有它，代理伺服器後面的伺服器只能看到代理程式的IP位址，這會破壞基於IP的存取控制、傳送方身份驗證和準確的日誌記錄。代理協定會在每個轉送的連線前新增一個簡短的頭部，後端伺服器會解析該頭部以恢復原始客戶端IP和原始連線的TLS狀態。

 When Stalwart runs behind HAProxy, Caddy, NGINX, or Traefik, enabling the Proxy Protocol preserves every signal the server needs. The client’s remote IP is required for SPF and DMARC checks; per-IP rate limiting and auto-banning need the real source address; and whether the incoming connection was protected by TLS is a policy input on several code paths.

 當 Stalwart 運行在 HAProxy、Caddy、 NGINX或 Traefik 之後時，啟用代理協定可以保留伺服器所需的所有訊號。客戶端的遠端IP用於SPF和DMARC檢查；每個IP的速率限制和自動封禁需要真實的來源位址；而傳入連線是否受TLS保護則是多個程式碼路徑的策略輸入。

## Configuration｜配置

 Stalwart supports both version 1 and version 2 of the Proxy Protocol, including the version-2 TLV extensions. The Proxy Protocol is enabled by declaring the set of trusted IP addresses or CIDR ranges from which Proxy Protocol headers will be accepted. Connections from other addresses are rejected if they carry a Proxy Protocol header and processed without it otherwise.

 Stalwart 同時支援代理協定的版本 1 和版本 2，包含版本 2 的TLV擴充。啟用代理協定需要宣告一組受信任的IP位址或CIDR位址範圍，系統將接受來自這些位址的代理協定標頭。來自其他地址的連接如果攜帶代理協議標頭將被拒絕，否則將被處理。

 Server-wide trusted networks are set through proxyTrustedNetworks on the SystemSettings singleton \(found in the WebUI under Settings › Network › Services, Settings › Network › General\). Each entry is an IP address or a CIDR mask, for example `127.0.0.0/8`, `::1`, or `10.0.0.0/8`.

 伺服器範圍的受信任網路透過 proxyTrustedNetworks在 SystemSettings單例中進行設定（可在 WebUI 的「設定」›「網路」›「服務」或「設定」›「網路」›「常規」中找到）。每個條目都是一個IP位址或一個CIDR掩碼，例如`127.0.0.0/8`, `::1`或`10.0.0.0/8` 。

 The same list can also be set on an individual NetworkListener through overrideProxyTrustedNetworks. The per-listener value replaces the server-wide list for that listener, so different listeners can trust different proxies.

 也可以在單一 NetworkListener到 overrideProxyTrustedNetworks上設定相同的清單。每個監聽器的值會取代該監聽器的伺服器範圍列表，因此不同的監聽器可以信任不同的代理。

- Configure the Proxy Protocol on both the proxy and Stalwart. A mismatch \(only one side sending or accepting the header\) will break connections silently or expose the proxy’s address instead of the client’s.
在代理伺服器和 Stalwart 伺服器上都設定代理協定。如果設定不符（只有一方發送或接收標頭），連線將靜默斷開，或暴露代理伺服器的位址而不是客戶端的位址。
- Not every proxy supports the Proxy Protocol; confirm compatibility before wiring it into a production path.
並非所有代理程式都支援代理協議；在將其連接到生產環境之前，請確認相容性。
- The exact syntax for enabling the Proxy Protocol varies between proxies. See the Stalwart pages for HAProxy, Caddy, NGINX, and Traefik for product-specific examples.
啟用代理協議的具體語法因代理而異。有關特定產品的範例，請參閱 Stalwart 網站上的 HAProxy 、Caddy 、NGINX和 Traefik頁。
