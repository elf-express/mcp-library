# Contacts｜聯絡方式

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[collaboration｜合作\\\]\\\(&lt;000 目錄.md#c-17&gt;\\\)

Stalwart includes built-in support for contact management and synchronization through JMAP for Contacts and CardDAV, covering storage, access, and maintenance of address book data across devices and applications.

 Stalwart 內建了對聯絡人管理和同步的支持，透過JMAP for Contacts 和 CardDAV，涵蓋了跨裝置和應用程式的通訊錄資料的儲存、存取和維護。

## JMAP for Contacts｜JMAP聯絡人

 JMAP for Contacts is a modern alternative to CardDAV, built on the same JSON-based foundation as other JMAP specifications. It allows clients to manage address books and contact data through a schema-defined JSON representation known as JSContact.

 JMAP聯絡人是 CardDAV 的現代替代方案，它與其他JMAP規範一樣，都基於JSON基礎。它允許客戶端透過稱為 JSContact 的模式定義的JSON表示來管理通訊錄和聯絡人資料。

 Where CardDAV relies on XML-based WebDAV extensions and the vCard format, JMAP for Contacts replaces both layers with JSON objects and operations.

 CardDAV 依賴於基於XML的 WebDAV 擴充和 vCard 格式，而JMAP聯絡人則以JSON物件和操作取代了這兩層。

## CardDAV

 CardDAV is a standardized extension of WebDAV that allows clients to interact with contact data stored on a server. It provides an interoperable way to manage personal and shared address books, and is supported by contact applications on desktop and mobile platforms including Apple Contacts and Thunderbird.

 CardDAV 是 WebDAV 的標準化擴展，可讓客戶端與伺服器上儲存的聯絡人資料進行互動。它提供了一種可互通的方式來管理個人和共享地址簿，並受到桌面和行動平台上的聯絡人應用程式的支持，包括 Apple Contacts 和 Thunderbird。

 Through CardDAV, contacts can be created and edited, organised into address books, and synchronised across devices. Stalwart’s CardDAV implementation integrates with the rest of the collaboration stack so that the same underlying data is available to JMAP clients.

 透過 CardDAV，可以建立和編輯聯絡人，將其整理到通訊錄中，並在不同裝置間同步。 Stalwart 的 CardDAV 實作與協作堆疊的其他部分集成，因此JMAP客戶端可以使用相同的底層資料。

### Accessing contacts｜訪問聯絡人

 CardDAV clients can access address book data on Stalwart using standardized URLs. The recommended method for client configuration is through the autodiscovery endpoint located at `/.well-known/carddav`. When a client queries this path, the server redirects the request to the appropriate CardDAV resource associated with the authenticated account.

 CardDAV 用戶端可以使用標準化的 URL 存取 Stalwart 上的通訊錄資料。建議的客戶端設定方法是透過位於`/.well-known/carddav`自動發現端點。當用戶端查詢此路徑時，伺服器會將請求重新導向至與已驗證帳戶關聯的對應 CardDAV 資源。

 Alternatively, CardDAV address books can be accessed directly via the path `/dav/card/<account_name>`, where `<account_name>` is the username of the account. For example, the address book for the account `alice` is available at `/dav/card/alice`.

 或者，也可以透過路徑`/dav/card/<account_name>`直接存取CardDAV地址簿，其中`<account_name>`是帳戶的使用者名稱。例如，帳戶`alice`的地址簿位於`/dav/card/alice` 。

 Both methods provide access to the same contact data and are fully compatible with the CardDAV protocol.

 兩種方法均可存取相同的聯絡人數據，並且與 CardDAV 協定完全相容。

## Limits｜限制

 Address-book-wide limits are configured on the AddressBook singleton \(found in the WebUI under Settings › Calendar & Contacts › Address Book\).

 通訊錄範圍的限制是在 通訊錄單例中配置的（在 WebUI 的「設定 › 行事曆和聯絡人 › 通訊錄」下可以找到）。

### vCard object size｜vCard 物件大小

 maxVCardSize defines the maximum accepted size of a single vCard object submitted to the server. The default is `524288` \(512 KB\). Raise or lower the limit to suit expected client behaviour.

 maxVCardSize定義了提交到伺服器的單一 vCard 物件的最大可接受大小。預設值為`524288` \(512 KB \)。根據預期的客戶端行為提高或降低此限制。

### JMAP parsing limit｜JMAP解析限制

 The JMAP `ContactCard/parse` method is bounded by parseLimitContact on the Jmap singleton \(found in the WebUI under Settings › Network › JMAP › Limits, Settings › Network › JMAP › Push, Settings › Network › JMAP › WebSocket\), which sets the maximum number of vCard items that can be parsed in a single request. The default is `10`.

 JMAP `ContactCard/parse`方法受 parseLimitContact的限制，此限制是基於 Jmap單例（可在 WebUI 的「設定 › 網路 › JMAP › JMAP ,「「」 › JMAP › WebSocket」中找到），它設定了單一請求中可以解析的最大 vCard 項數。預設值為`10` 。

## Default address book｜預設地址簿

 To improve client compatibility and allow contact operations to proceed without manual setup, Stalwart automatically creates a default address book when an account is accessed and no address books currently exist for it. The URL path of the auto-created address book is controlled by defaultHrefName on the AddressBook singleton. The default value is `"default"`, so for an account named `john` the default address book is created at `/dav/card/john/default`.

 為了提高用戶端相容性並允許聯絡人操作無需手動設定即可進行，Stalwart 會在存取帳戶且該帳戶目前不存在通訊錄時自動建立URL通訊錄。自動建立的地址簿的路徑由 AddressBook 單例中的 defaultHrefName控制。預設值為`"default"` ，因此對於名為`john`的帳戶，預設通訊錄建立在`/dav/card/john/default` 。

### Disabling automatic creation｜停用自動建立

 Automatic creation can be suppressed by clearing defaultHrefName \(leaving it unset\). In that case, Stalwart does not create a default address book and clients that connect to an account with no address books receive an appropriate error response.

 可以透過清除 defaultHrefName （將其設為未設定）來禁止自動建立地址簿。在這種情況下，Stalwart 不會建立預設通訊錄，連接到沒有通訊錄的帳戶的用戶端會收到相應的錯誤回應。

### Default display name｜預設顯示名稱

 The display name assigned to the auto-created address book is controlled by defaultDisplayName. The default is `"Stalwart Address Book"`; the value can be adjusted to match organisational branding or language preferences.

 自動建立的通訊錄的顯示名稱由 defaultDisplayName控制。預設值為`"Stalwart Address Book"` ；該值可以調整以符合組織品牌或語言偏好。

## Per-account limits｜每個帳戶的限額

 The AddressBook singleton also sets default caps on per-account address-book resources: maxAddressBooks caps the number of address books an account can create \(default `250`\), and maxContacts caps the number of contact cards. These apply unless overridden at the account or tenant level.

 AddressBook 單例也設定了每個帳戶通訊錄資源的預設上限：maxAddressBooks限制帳戶可以建立的通訊錄數量（預設值為`250` ），maxContacts卡的卡片數量。除非在帳戶或租用戶層級進行覆蓋，否則這些設定將生效。

## Spam filter integration｜垃圾郵件過濾器集成

 Stalwart’s contact management system is integrated with the built-in spam filter to improve filtering accuracy and reduce false positives. When enabled, the spam filter references an account’s address book to identify trusted senders so that their messages are not marked as spam.

 Stalwart 的聯絡人管理系統與內建垃圾郵件過濾器\([https://stalw.art/docs/spamfilter/\)集成，以提高過濾準確率並減少誤報。啟用後，垃圾郵件過濾器會參考帳戶的通訊錄來識別可信任寄件者，從而避免將其郵件標記為垃圾郵件。](https://stalw.art/docs/spamfilter/%2529%2525E9%25259B%252586%2525E6%252588%252590%2525EF%2525BC%25258C%2525E4%2525BB%2525A5%2525E6%25258F%252590%2525E9%2525AB%252598%2525E9%252581%25258E%2525E6%2525BF%2525BE%2525E6%2525BA%252596%2525E7%2525A2%2525BA%2525E7%25258E%252587%2525E4%2525B8%2525A6%2525E6%2525B8%25259B%2525E5%2525B0%252591%2525E8%2525AA%2525A4%2525E5%2525A0%2525B1%2525E3%252580%252582%2525E5%252595%25259F%2525E7%252594%2525A8%2525E5%2525BE%25258C%2525EF%2525BC%25258C%2525E5%25259E%252583%2525E5%25259C%2525BE%2525E9%252583%2525B5%2525E4%2525BB%2525B6%2525E9%252581%25258E%2525E6%2525BF%2525BE%2525E5%252599%2525A8%2525E6%25259C%252583%2525E5%25258F%252583%2525E8%252580%252583%2525E5%2525B8%2525B3%2525E6%252588%2525B6%2525E7%25259A%252584%2525E9%252580%25259A%2525E8%2525A8%25258A%2525E9%25258C%252584%2525E4%2525BE%252586%2525E8%2525AD%252598%2525E5%252588%2525A5%2525E5%25258F%2525AF%2525E4%2525BF%2525A1%2525E4%2525BB%2525BB%2525E5%2525AF%252584%2525E4%2525BB%2525B6%2525E8%252580%252585%2525EF%2525BC%25258C%2525E5%2525BE%25259E%2525E8%252580%25258C%2525E9%252581%2525BF%2525E5%252585%25258D%2525E5%2525B0%252587%2525E5%252585%2525B6%2525E9%252583%2525B5%2525E4%2525BB%2525B6%2525E6%2525A8%252599%2525E8%2525A8%252598%2525E7%252582%2525BA%2525E5%25259E%252583%2525E5%25259C%2525BE%2525E9%252583%2525B5%2525E4%2525BB%2525B6%2525E3%252580%252582)

 In addition to bypassing spam classification for known contacts, the address book can be used to improve the spam classifier. When a message from a known contact is incorrectly flagged as spam, the classifier can learn from the mistake and recognise similar messages in future.

 除了對已知聯絡人繞過垃圾郵件分類之外，通訊錄還可以用於改進垃圾郵件分類器 。當來自已知聯絡人的消息被錯誤地標記為垃圾郵件時，分類器可以從錯誤中學習，並將來識別類似的訊息。

 For details on configuring these features, see the spam filter documentation.

 有關配置這些功能的詳細信息，請參閱垃圾郵件過濾器文件 。
