# Load balancing｜負載平衡

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-13&gt;\\\)

By default, Stalwart derives the server hostname from the underlying system hostname during installation. The hostname appears in protocol responses, logs, and internal identification. When Stalwart is deployed behind a load balancer, all backend nodes should use a consistent hostname that matches the public-facing identity of the service. This keeps client communications and protocol-level interactions uniform, particularly for protocols such as SMTP that expose the server hostname during the handshake.

 預設情況下，Stalwart 在安裝過程中會從底層系統主機名稱派生伺服器主機名稱。該主機名稱會出現在協定回應、日誌和內部識別中。當 Stalwart 部署在負載平衡器之後時，所有後端節點都應使用與服務公開識別一致的主機名稱。這可以確保客戶端通訊和協定級互動的一致性，尤其對於像SMTP這樣的協定而言，它們會在握手過程中暴露伺服器主機名稱。

 The hostname is set on the SystemSettings singleton \(found in the WebUI under Settings › Network › Services, Settings › Network › General\) through the defaultHostname field.

 主機名稱在 SystemSettings單例（在 WebUI 的「設定 › 網路 › 服務」、「設定 › 網路 › 常規」下找到）中透過 defaultHostname欄位設定。

 For example, with three Stalwart nodes \(`mx1.example.org`, `mx2.example.org`, and `mx3.example.org`\) behind a load balancer that publicly serves mail as `mx.example.org`, each node sets `defaultHostname` to the public identity:

 例如，在負載平衡器後面有三個 Stalwart 節點（ `mx1.example.org`, `mx2.example.org`和`mx3.example.org` ），該負載平衡器公開提供郵件服務，即`mx.example.org` ，每個節點將`defaultHostname`設定為公共身分：

```json
{
  "defaultHostname": "mx.example.org"
}
```

All nodes then respond with the same hostname \(`mx.example.org`\), keeping clients consistent and avoiding confusion or misidentification.

 然後所有節點都以相同的主機名稱（ `mx.example.org` ）回應，從而保持客戶端的一致性，避免混淆或誤認。

 Failing to align this setting leads to inconsistent SMTP banners, TLS certificates, and protocol-level responses, especially when multiple backend nodes serve the same clients in a round-robin or failover configuration.

 如果未能正確設定此參數，則會導致SMTP橫幅、 TLS憑證和協定級回應不一致，尤其是在輪詢或故障轉移配置中多個後端節點為相同用戶端提供服務時。

 Setting defaultHostname once on the singleton is the correct approach in a load-balanced cluster. There is no per-node hostname override: the value supplied on the singleton applies across the cluster and is used in SMTP banners, authentication reports, and other protocol-level responses. Each node also has an operating-system hostname, but that value is read only to acquire a node-id lease and is not exposed to clients.

 在負載平衡叢集中，只需在單例節點上設定一次 defaultHostname即可。不存在每個節點的主機名覆蓋：單例節點上提供的值適用於整個集群，並用於SMTP橫幅、身份驗證報告和其他協定級回應。每個節點也有一個作業系統主機名，但該值僅用於取得 node-id lease ，不會暴露給客戶端。
