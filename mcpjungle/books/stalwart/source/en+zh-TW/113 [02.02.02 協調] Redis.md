# Redis

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[coordination｜協調\\\]\\\(&lt;000 目錄.md#c-14&gt;\\\)

Redis is an in-memory data structure store commonly used for caching, session storage, and ephemeral key-value data. Alongside its role as a high-speed cache, Redis provides native publish/subscribe \(pub/sub\) messaging, which can be used for lightweight inter-process or inter-node communication.

 Redis 是一種記憶體資料結構儲存系統，常用於快取、會話儲存和暫時鍵值資料。除了作為高速緩存之外，Redis 還提供原生發布/訂閱 \(pub/sub\) 訊息功能，可用於輕量級進程間或節點間通訊。

 In a Stalwart cluster, Redis can serve as a coordination backend using pub/sub to propagate internal updates between nodes. These include mailbox changes, IMAP IDLE and push notification triggers, blocked IP alerts, and ACME certificate availability. Each node subscribes to the relevant Redis channels and publishes updates as needed, keeping the cluster synchronised in real time.

 在 Stalwart 叢集中，Redis 可作為協調後端，利用發布/訂閱機制在節點間傳播內部更新。這些更新包括郵箱變更、 IMAP IDLE和推播通知觸發、 IP阻塞警報以及ACME證書可用性。每個節點訂閱相關的 Redis 通道，並根據需要發布更新，從而保持叢集的即時同步。

 Redis is useful in small to medium deployments where Kafka or NATS may be too heavy, or where Redis is already in use for transient or ephemeral data. Using Redis for both coordination and ephemeral storage consolidates services and avoids an additional piece of infrastructure.

 Redis 適用於中小型部署，在這些部署中，Kafka 或NATS可能過於臃腫，或 Redis 已被用於儲存瞬態或暫存資料。使用 Redis 同時進行協調和臨時儲存可以整合服務，避免增加額外的基礎設施。

 Redis pub/sub is designed for transient messaging and does not persist messages or guarantee delivery to offline subscribers. For most real-time coordination tasks in modestly sized mail infrastructures this is acceptable, but Redis is not suitable for high-throughput or high-reliability scenarios where message loss is unacceptable.

 Redis 發布/訂閱機制專為瞬態訊息傳遞而設計，它不會持久化訊息，也無法保證離線訂閱者也能收到訊息。對於大多數規模適中的郵件基礎設施中的即時協調任務而言，這尚可接受，但 Redis 不適用於高吞吐量或高可靠性的場景，因為在這些場景中，訊息遺失是不可接受的。

## Configuration｜配置

 Redis coordination is configured through the Coordinator singleton \(found in the WebUI under Settings › Cluster › Coordinator\). Two variants are available:

 Redis 協調是透過 Coordinator單例配置的（可在 WebUI 的「設定」&gt;「叢集」&gt;「協調器」中找到）。有兩種變體可用：

- `Redis`: a standalone Redis server. The variant carries url, timeout, and connection-pool fields poolMaxConnections, poolTimeoutCreate, poolTimeoutWait, and poolTimeoutRecycle.
`Redis` ：一個獨立的 Redis 伺服器。此變體包含 url , timeout , \([https://stalw.art/docs/ref/object/coordinator#poolmaxconnections\)池字段\`poolTimeoutWait\`](https://stalw.art/docs/ref/object/coordinator#poolmaxconnections%2529%2525E6%2525B1%2525A0%2525E5%2525AD%252597%2525E6%2525AE%2525B5%252560poolTimeoutWait%252560) `poolMaxConnections` \]`poolTimeoutCreate` , \[ \([https://stalw.art/docs/ref/object/coordinator#pooltimeoutcreate](https://stalw.art/docs/ref/object/coordinator#pooltimeoutcreate)\) \([https://stalw.art/docs/ref/object/coordinator#pooltimeoutwait](https://stalw.art/docs/ref/object/coordinator#pooltimeoutwait)\) , 和 poolTimeoutRecycle 。
- `RedisCluster`: a Redis Cluster deployment. The variant carries urls, authentication through authUsername and authSecret, retry settings maxRetries, minRetryWait, and maxRetryWait, readFromReplicas, protocolVersion \(`resp2` or `resp3`\), and the same connection-pool fields as the standalone variant.
`RedisCluster` ：Redis 集群部署。此變體包含 urls ，透過 authUsername和 authSecret \([https://stalw.art/docs/ref/object/coordinator#authsecret\)身份驗證，重試設定](https://stalw.art/docs/ref/object/coordinator#authsecret%2529%2525E8%2525BA%2525AB%2525E4%2525BB%2525BD%2525E9%2525A9%252597%2525E8%2525AD%252589%2525EF%2525BC%25258C%2525E9%252587%25258D%2525E8%2525A9%2525A6%2525E8%2525A8%2525AD%2525E5%2525AE%25259A) maxRetries minRetryWait , 和 maxRetryWait , readFromReplicas , protocolVersion `resp3` `resp2` ，以及與獨立變體相同的連接池字段。
The `Default` variant of Coordinator reuses the Redis connection already configured on the in-memory store, avoiding the need to maintain a second connection when Redis is already used for ephemeral data. For detailed connection parameters, authentication options, TLS support, and tuning, refer to the Redis in-memory store page.
`Default`版本的協調器會重複使用已在 記憶體儲存中配置的 Redis 連接，從而避免在 Redis 已用於臨時資料時維護第二個連接。有關詳細的連線參數、驗證選項、 TLS支援和調優，請參閱 Redis 記憶體儲存頁面。

 For example, a standalone Redis coordinator:

 例如，一個獨立的 Redis 協調器：

```json
{
  "@type": "Redis",
  "url": "redis://redis.example.com:6379",
  "timeout": 10000,
  "poolMaxConnections": 10
}
```

A Redis Cluster coordinator with authentication and retry tuning:

 具有身份驗證和重試調優功能的 Redis 集群協調器：

```json
{
  "@type": "RedisCluster",
  "urls": {
    "redis://redis-1.example.com:6379": true,
    "redis://redis-2.example.com:6379": true,
    "redis://redis-3.example.com:6379": true
  },
  "timeout": 10000,
  "authUsername": "stalwart",
  "authSecret": {
    "@type": "Value",
    "secret": "redis-password"
  },
  "readFromReplicas": true,
  "protocolVersion": "resp3"
}
```
