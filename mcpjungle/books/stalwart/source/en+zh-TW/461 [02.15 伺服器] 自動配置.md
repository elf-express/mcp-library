# Autoconfig｜自動配置

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\)

Autoconfig and autodiscover are discovery protocols that allow mail clients to retrieve server settings from the mail domain without requiring manual configuration. They reduce setup errors and shorten the time needed to add an account to a client. Stalwart implements three such protocols: PACC, the legacy Mozilla Autoconfig, and Microsoft Autodiscover.

 自動設定和自動發現是郵件用戶端無需手動設定即可從郵件網域擷取伺服器設定的一種發現協定。它們可以減少設定錯誤，並縮短向客戶端新增帳戶所需的時間。 Stalwart 實作了三種此類協定： PACC 、傳統的 Mozilla 自動設定和 Microsoft 自動發現。

### PACC

 PACC is the short name for “Automatic Configuration of Email, Calendar, and Contact Server Settings”, specified by the IETF draft [draft-ietf-mailmaint-pacc-02](https://datatracker.ietf.org/doc/html/draft-ietf-mailmaint-pacc-02). It is the modern standardised successor to the earlier vendor formats, with a single discovery document that covers mail, calendar, and contact services together.

 PACC是「電子郵件、行事曆和聯絡人伺服器設定的自動設定」的簡稱，由IETF草案 [draft-ietf-mailmaint-pacc-02](https://datatracker.ietf.org/doc/html/draft-ietf-mailmaint-pacc-02)規定。它是早期供應商格式的現代標準化繼承者，使用一份涵蓋郵件、日曆和聯絡人服務的單一發現文件。

 After prompting the user for an email address \(and, where needed, an account password\), a PACC-aware client uses the domain part of the address to fetch the configuration from the well-known URI defined by [RFC 8615](https://www.rfc-editor.org/rfc/rfc8615), using the suffix `user-agent-configuration`. A client signing in as `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` therefore retrieves `https://example.com/.well-known/user-agent-configuration.json` and parses the JSON response. The document advertises human-readable metadata about the provider, the protocols offered for the domain, the server endpoints for each one, and whether the provider supports the OAuth Profile for Open Public Clients; a client that speaks the listed protocols can complete the setup without further input. Combining mail \(JMAP, IMAP, POP, SMTP submission\), calendar \(CalDAV\), and contact \(CardDAV\) services under a single discovery lookup avoids the per-service fallbacks required by the legacy formats and gives IETF-standardised semantics to fields that were previously vendor-defined.

 在提示使用者輸入電子郵件地址（以及在需要時輸入帳戶密碼）後，支援PACC的客戶端會使用地址的網域部分，從 [RFC 8615](https://www.rfc-editor.org/rfc/rfc8615)定義的知名URI獲取設定資訊，並使用後綴`user-agent-configuration`因此，以`[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`身分登入的客戶端會擷取`https://example.com/.well-known/user-agent-configuration.json`並解析JSON回應。該文件以易於理解的方式發布了關於提供者、網域提供的協定、每個協定的伺服器端點以及提供者是否支援面向開放公共客戶端的 OAuth 設定檔的元資料；支援所列協定的用戶端無需進一步輸入即可完成設定。將郵件（ JMAP, IMAP, POP, SMTP提交）、日曆（CalDAV）和聯絡人（CardDAV）服務合併到單一發現查找中，避免了舊格式所需的每個服務的回退，並為先前由供應商定義的欄位提供了IETF標準化語義。

### Autoconfig｜自動配置

 Autoconfig is the legacy format originally defined by Mozilla and now described in an IETF draft. The client fetches a standardised XML document at a URL derived from the user’s domain. A client starting from the address `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` retrieves `http://autoconfig.example.com/mail/config-v1.1.xml` and parses the server addresses, port numbers, and encryption mechanisms from the response. The format is limited to mail services \(IMAP, POP, SMTP\).

 自動配置是 Mozilla 最初定義的傳統格式，現在已在IETF草案中進行了描述。用戶端從用戶域派生的URL位址取得標準化的XML文件。客戶端從位址`[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`開始檢索`http://autoconfig.example.com/mail/config-v1.1.xml`並從回應中解析伺服器位址、連接埠號碼和加密機制。此格式僅限於郵件服務 \( IMAP, POP, SMTP \)。

### Microsoft Autodiscover｜微軟自動發現

 Autodiscover is the format originally introduced by Microsoft for Exchange and Outlook clients. The client issues a request to a URL derived from the user’s domain \(for example `https://autodiscover.example.com/autodiscover/autodiscover.xml`\) and parses the XML response to configure the protocol, server URLs, and related parameters. Two revisions of the protocol exist: v1, which returns the configuration directly from the domain’s autodiscover endpoint, and v2, which first returns a redirect to the endpoint that serves the configuration for the requested service. Stalwart supports both.

 自動發現是微軟最初為 Exchange 和 Outlook 用戶端引入的格式。客戶端向源自使用者網域的URL （例如`https://autodiscover.example.com/autodiscover/autodiscover.xml` ）發出請求，並解析XML回應以設定協定、伺服器 URL 和相關參數。此協定有兩個版本：v1 直接從網域的自動發現終點傳回設定；v2 首先傳回一個重新導向，指向提供所要求服務設定的終點。 Stalwart 同時支援這兩個版本。

## Configuration｜配置

 No protocol-specific configuration is required beyond the standard mail services. Clients that reach the server over HTTPS \(port 443\) receive the generated PACC, autoconfig, and autodiscover documents automatically.

 除了標準郵件服務之外，無需進行任何特定協定的配置。透過HTTPS （連接埠443）連接到伺服器的用戶端會自動收到產生的PACC 、自動設定和自動發現文件。

 The information advertised in those documents is driven by the SystemSettings singleton \(found in the WebUI under Settings › Network › Services, Settings › Network › General\). Per-protocol hostnames and whether a protocol is offered in cleartext or TLS-only mode are controlled through services; provider metadata advertised to mail clients \(name, documentation URLs, logo, contact URI\) is set through providerInfo.
