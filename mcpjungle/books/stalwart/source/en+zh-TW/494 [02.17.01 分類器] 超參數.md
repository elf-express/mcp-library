# Hyperparameters｜超參數

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[spamfilter｜垃圾郵件過濾器\\\]\\\(&lt;000 目錄.md#c-69&gt;\\\) › \\\[classifier｜分類器\\\]\\\(&lt;000 目錄.md#c-70&gt;\\\)

Hyperparameters are configuration values that control how the classifier model is structured and how learning is performed. Unlike model parameters, which are learned from data during training, hyperparameters are fixed in advance and determine properties such as the size of the feature space, the behaviour of the optimiser, and how input features are scaled. Correct hyperparameter choices are essential for stable training and reliable classification.

 超參數是控制分類器模型結構和學習方式的配置值。與在訓練過程中從資料中學習得到的模型參數不同，超參數是預先設定的，它們決定了諸如特徵空間的大小、優化器的行為以及輸入特徵的縮放方式等屬性。正確的超參數選擇對於穩定的訓練和可靠的分類至關重要。

 Hyperparameters live on the SpamClassifier singleton \(found in the WebUI under Settings › Spam Filter › Classifier\), inside the selected model variant. The `FtrlFh` variant uses feature hashing; the `FtrlCcfh` variant uses cuckoo feature hashing and carries a second, dedicated hyperparameter set for the cuckoo indicator.

 超參數位於所選模型變體內的 SpamClassifier 單例（可在 WebUI 的「設定 &gt; 垃圾郵件過濾器 &gt; 分類器」下找到）。 `FtrlFh`變體使用特徵雜湊； `FtrlCcfh` 變體使用布穀鳥特徵散列，並為布穀鳥指標攜帶第二個專用超參數集。

## Feature space size｜特徵空間大小

 By default the classifier uses a feature space of size 2²⁰. The feature space defines the number of distinct weight slots available to the model after feature hashing has been applied. Each extracted feature is mapped, via hashing, to one of these slots, and the corresponding weight contributes to the final classification score. A larger feature space reduces the probability of collisions between unrelated features, improving accuracy at the cost of increased memory usage. A smaller feature space conserves memory but increases collision rates. The default represents a balance that works well for most deployments.

 預設情況下，分類器使用大小為 2²⁰ 的特徵空間。特徵空間定義了應用特徵雜湊後模型可用的不同權重槽的數量。每個提取的特徵都透過哈希映射到這些槽中的一個，相應的權重會影響最終的分類得分。更大的特徵空間可以降低不相關特徵之間發生衝突的機率，從而提高準確率，但會增加記憶體使用量。更小的特徵空間可以節省內存，但會增加衝突率。預設值代表了一種平衡，適用於大多數部署場景。

 The feature-space size is set through numFeatures on the parameters object, expressed as the exponent of 2 \(so `"20"` corresponds to 2²⁰\).

 特徵空間大小透過 numFeatures物件上的 parameters設置，表示為 2 的指數（因此`"20"`對應於 2²⁰）。

## Feature normalisation｜特徵歸一化

 Before features are presented to the classifier, Stalwart applies feature normalisation to improve numerical stability and learning efficiency. By default, sublinear term-frequency scaling is used, implemented as a `log1p` transformation. This reduces the influence of very frequent features by compressing their magnitude, while still preserving relative differences. In practice, this prevents repeated tokens or patterns from dominating the model purely because of frequency.

 在將特徵輸入分類器之前，Stalwart 會應用特徵歸一化來提高數值穩定性和學習效率。預設情況下，它使用亞線性詞頻縮放，並透過`log1p`變換實現。這透過壓縮高頻特徵的振幅來降低其影響，同時保留相對差異。實際上，這可以防止重複的詞元或模式僅僅因為頻率高而主導模型。

 After scaling, features are L2-normalised using the Euclidean norm. This step ensures that the overall feature vector has unit length, making predictions less sensitive to variations in message length and feature count. L2 normalisation also improves the behaviour of gradient-based optimisation methods such as FTRL by keeping updates well-conditioned.

 縮放後，使用歐氏範數對特徵進行 L2 歸一化。此步驟確保整體特徵向量長度為 1，從而降低預測結果對訊息長度和特徵數量變化的敏感度。 L2 歸一化還能維持更新的良好條件性，進而改善基於梯度的最佳化方法（例如FTRL的效能。

 Sublinear term-frequency scaling and L2 normalisation are both enabled by default and are suitable for most environments. They can be disabled when integrating externally normalised features or for experimental purposes, though doing so may affect training stability and classification quality. The corresponding fields on each model variant are featureLogScale and featureL2Normalize.

 預設情況下，亞線性詞頻縮放和 L2 歸一化均已啟用，適用於大多數環境。當整合外部歸一化特徵或用於實驗目的時，可以停用它們，但這樣做可能會影響訓練穩定性和分類品質。每個模型變體的對應欄位為 featureLogScale和 featureL2Normalize 。

## FTRL optimiser settings｜FTRL優化設定

 The classifier is trained using the FTRL-Proximal optimiser, which exposes several hyperparameters that influence learning dynamics. The parameter α controls the base learning rate and determines how aggressively the model updates its weights in response to new samples. The parameter β stabilises learning by smoothing adaptive learning rates over time. The L1 ratio and L2 ratio control the strength of L1 and L2 regularisation respectively, influencing sparsity and weight magnitude.

 此分類器使用FTRL近端優化器進行訓練，該優化器暴露出多個影響學習動態的超參數。參數α控制基礎學習率，決定模型回應新樣本更新權重的正面程度。參數β透過平滑自適應學習率隨時間的變化來穩定學習過程。 L1比率和L2比率分別控制L1和L2正規化的強度，進而影響稀疏性和權重大小。

 These settings interact in subtle ways and have a significant impact on convergence, stability, and generalisation. The default values have been chosen to provide stable behaviour across a wide range of workloads, and modifying them is not recommended without a solid background in machine learning and a clear understanding of the trade-offs involved.

 這些設定以微妙的方式相互作用，對收斂性、穩定性和泛化能力有顯著影響。預設值旨在確保在各種工作負載下都能保持穩定的效能，因此，如果沒有紮實的機器學習基礎和對相關權衡的清晰理解，不建議修改這些設定。

 The optimiser parameters live on the `FtrlParameters` nested type at parameters.alpha, parameters.beta, parameters.l1Ratio, and parameters.l2Ratio, alongside parameters.numFeatures.

 優化器參數儲存在 `FtrlParameters` 嵌套類型位於parameters.alpha, parameters.beta, parameters.l1Ratio， 和 parameters.l2Ratio與parameters.numFeatures.

## Configuration｜配置

 Configure the model variant and its hyperparameters through the model field on SpamClassifier. For the default `FtrlFh` variant, the fields are:

 透過 SpamClassifier 中的 model字段配置模型變體及其超參數。對於預設的`FtrlFh`變體，這些欄位如下：

- featureLogScale: when `true`, enables sublinear term-frequency scaling. Default `true`.
featureLogScale : 當`true`時，啟用亞線性項頻率縮放。預設值為`true` 。
- featureL2Normalize: when `true`, enables L2 normalisation of feature vectors. Default `true`.
featureL2Normalize : 當`true`時，啟用特徵向量的 L2 歸一化。預設值為`true` 。
- parameters.numFeatures: feature-space size as a power of two. Default `"20"` \(2²⁰ = 1,048,576\).
parameters.numFeatures : 特徵空間大小為 2 的冪。預設值為`"20"` \(2²⁰ = 1,048,576\)。
- parameters.alpha: FTRL learning rate. Default `2.0`.
parameters.alpha: FTRL學習率。預設值`2.0` 。
- parameters.beta: FTRL smoothing parameter. Default `1.0`.
parameters.beta: FTRL平滑參數。預設值`1.0` 。
- parameters.l1Ratio: FTRL L1 regularisation strength. Default `0.001`.
parameters.l1Ratio: FTRL L1 正規化強度。預設值`0.001` 。
- parameters.l2Ratio: FTRL L2 regularisation strength. Default `0.0001`.
parameters.l2Ratio: FTRL L2 正規化強度。預設值`0.0001` 。
Example showing the defaults explicitly:
 範例明確展示了預設值：

```json
{
  "model": {
    "@type": "FtrlFh",
    "featureLogScale": true,
    "featureL2Normalize": true,
    "parameters": {
      "numFeatures": "20",
      "alpha": 2.0,
      "beta": 1.0,
      "l1Ratio": 0.001,
      "l2Ratio": 0.0001
    }
  }
}
```

When cuckoo feature hashing is in use \(the `FtrlCcfh` variant\), a second set of hyperparameters applies specifically to the cuckoo indicator training process. These are carried on indicatorParameters and have the same meaning as the primary `parameters` object. By default the indicator uses a feature-space size of 2¹⁸ \(262,144\). Example:

 當使用布穀鳥特徵哈希（ `FtrlCcfh`變體）時，第二組超參數專門用於布穀鳥指標的訓練過程。這些超參數位於 indicatorParameters中，其意義與主`parameters`物件相同。預設情況下，此指標所使用的特徵空間大小為 2¹⁸ \(262,144\)。範例：

```json
{
  "model": {
    "@type": "FtrlCcfh",
    "featureLogScale": true,
    "featureL2Normalize": true,
    "parameters": {
      "numFeatures": "20",
      "alpha": 2.0,
      "beta": 1.0,
      "l1Ratio": 0.001,
      "l2Ratio": 0.0001
    },
    "indicatorParameters": {
      "numFeatures": "18",
      "alpha": 2.0,
      "beta": 1.0,
      "l1Ratio": 0.001,
      "l2Ratio": 0.0001
    }
  }
}
```
