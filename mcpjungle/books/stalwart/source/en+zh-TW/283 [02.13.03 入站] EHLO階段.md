# EHLO stage｜EHLO階段

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[inbound｜入站\\\]\\\(&lt;000 目錄.md#c-51&gt;\\\)

The `EHLO` \(Extended Hello\) command is sent by an email client to the server to initiate an SMTP session and negotiate the features and extensions that will be used during the session. The `EHLO` command provides a way for the email client to identify itself, and for the server to advertise the capabilities and extensions it supports, such as authentication mechanisms, message size limits, and others. The response to the `EHLO` command provides information to the client about the server’s capabilities, which the client can then use to determine the best way to send the email.

`EHLO`（擴展 Hello）命令由電子郵件用戶端發送到伺服器，以啟動 SMTP 會話並協商會話期間將使用的功能和擴展。 `EHLO` 指令為電子郵件用戶端提供了一種識別自身身分的方法，並為伺服器提供了一種通告其支援的功能和擴充的方法，例如驗證機制、訊息大小限制等。對 `EHLO` 命令的回應向客戶端提供有關伺服器功能的信息，然後客戶端可以使用這些資訊來確定發送電子郵件的最佳方式。

## Settings｜設定

 EHLO-stage behaviour is configured on the MtaStageEhlo singleton \(found in the WebUI under Settings › MTA › Session › EHLO Stage\). The relevant fields are require \(whether the remote client must send an `EHLO`, `HELO`, or `LHLO` command before starting an SMTP transaction; enabling this lets Stalwart verify the SPF EHLO identity of the client, default `true`\), rejectNonFqdn \(whether to reject `EHLO` commands that do not include a fully-qualified domain name as a parameter; the default enables the check only on `local_port == 25`, so that submission listeners accept client hostnames that may not be fully qualified\), and script \(the Sieve script to run after a successful `EHLO` command; a typical use is to block specific HELO domains by matching the `helo_domain` variable against an in-memory list\).

 EHLO-stage 行為在 MtaStageEhlo 上配置 單例（在 WebUI 的「設定」下找到） MTA &gt; 會議 &gt; EHLO 階段）。相關字段為require （遠端客戶端是否必鬚髮送一個 `EHLO`, `HELO`， 或者 `LHLO` 在開始之前執行命令 SMTP 交易；啟用此功能後，Stalwart 可以驗證 SPF EHLO 客戶端身份，預設值 `true`\), rejectNonFqdn （是否拒絕） `EHLO` 不包含完全限定網域名稱作為參數的命令；預設僅啟用此檢查 `local_port == 25`以便提交監聽器接受可能不完全限定的客戶端主機名稱），以及script （篩網腳本 追逐成功 `EHLO` 命令；典型用途是阻止特定操作 HELO 透過匹配域 `helo_domain` 變數與記憶體清單中的變數進行比較）。

 Example configuration setting all three fields together, including a per-listener override for `rejectNonFqdn` and a Sieve script selector:

 範例配置將所有三個欄位設定在一起，包括針對`rejectNonFqdn`的每個監聽器的覆蓋設定以及Sieve腳本選擇器：

```json
{
  "require": {"else": "true"},
  "rejectNonFqdn": {
    "match": {"0": {"if": "listener == 'smtp'", "then": "true"}},
    "else": "false"
  },
  "script": {"else": "'ehlo'"}
}
```

A companion Sieve script `ehlo` rejects HELO domains present in a blocked-domain list:

 配套的 Sieve 腳本`ehlo`會拒絕HELO存在於被封鎖網域清單中的網域：

```sieve
require ["variables", "extlists", "reject"];

if string :list "${env.helo_domain}" "blocked-domain" {
    reject "551 5.1.1 Sending domain '${env.helo_domain}' has been blocklisted.";
}
```

 The `blocked-domain` list used by the `:list` match is backed by entries on the MemoryLookupKey object \(found in the WebUI under Settings › Lookups › In-Memory Keys, Settings › Spam Filter › Lists › Blocked Domains, Settings › Spam Filter › Lists › Spam Traps, Settings › Spam Filter › Lists › Trusted Domains, Settings › Spam Filter › Lists › URL Redirectors\). Each blocked domain is a separate key created under the `blocked-domain` namespace, with the domain name itself as the key:

`:list`符合使用的`blocked-domain`清單由 MemoryLookupKey物件中的條目支援（可在 WebUI的「設定」&gt;「尋找」&gt;「記憶鍵」、「設定」&gt;「垃圾郵件過濾器」&gt;「清單」&gt;「已封鎖的網域名稱」、「設定」&gt;「垃圾郵件過濾器」&gt;「清單」&gt;「垃圾郵件陷阱」、「設定」&gt;「垃圾郵件過濾器」&gt;「清單」&gt;「受信任的網域名稱」和URL設定檔&gt;」「每個被阻止的網域都是在`blocked-domain` namespace下創建的單獨鍵，網域本身作為 key :

```json
{
  "namespace": "blocked-domain",
  "key": "spammer.example",
  "isGlobPattern": false
}
```

Additional entries use the same namespace with different key values, and glob patterns such as `*.spammer.example` can be enabled by setting isGlobPattern to `true`.

 其他條目使用相同的命名空間，但鍵值不同，可以透過將 isGlobPattern設定為`true`來啟用`*.spammer.example`等 glob 模式。

## SMTP extensions｜SMTP擴展

 Stalwart supports a range of SMTP extensions, configured on the MtaExtensions singleton \(found in the WebUI under Settings › MTA › Session › Extensions\). Each field accepts an expression that returns either a boolean, a duration, or the extension-specific value described below.

 Stalwart 支援一系列 SMTP擴充 ，這些擴充功能在 MtaExtensions單例中設定（可在 WebUI 的「設定」 › MTA › 會話 會話擴展」下找到）。每個欄位都接受一個表達式，該表達式傳回布林值、持續時間或下文所述的特定於擴展的值。

- pipelining: SMTP pipelining \(RFC 2920\). Multiple commands can be sent in a single request.
pipelining: SMTP流水線（ RFC 2920）。可以在單一請求中發送多個命令。
- chunking: chunking \(RFC 3030\). Large messages can be transferred in chunks.
chunking : 分塊傳輸 \( RFC 3030\)。大型訊息可以分塊傳送。
- requireTls: REQUIRETLS \(RFC 8689\). Clients can require TLS encryption for the SMTP session.
requireTls : REQUIRETLS \( RFC 8689\)。客戶端可以要求對TLS會話SMTP加密。
- noSoliciting: text advertised via `NOSOLICITING` \(RFC 3865\), indicating the server does not accept unsolicited commercial email.
noSoliciting : 透過`NOSOLICITING` \( RFC 3865 \) 發布的文本，表明伺服器不接受未經請求的商業電子郵件。
- dsn: delivery status notifications \(RFC 3461\). Senders can request a DSN from the recipient’s mail server.
dsn : 投遞狀態通知 \( RFC 3461\)。寄件者可以向收件者的郵件伺服器請求DSN 。
- futureRelease: maximum time a message can be held for delivery via the `FUTURERELEASE` \(RFC 4865\) extension. Returning `false` disables the extension.
futureRelease ：訊息可透過`FUTURERELEASE` \( RFC 4865\) 分機保留的最長時間。返回`false`將禁用該分機。
- deliverBy: maximum delivery time allowed by the `DELIVERBY` \(RFC 2852\) extension. Returning `false` disables the extension.
deliverBy : `DELIVERBY` \( RFC 2852\) 分機允許的最長配送時間。返回`false`將禁用該分機。
- mtPriority: priority-assignment policy advertised on the `MT-PRIORITY` \(RFC 6710\) extension. Accepted values are `mixer`, `stanag4406`, and `nsep`, or `false` to disable the extension.
mtPriority : 在`MT-PRIORITY` \( RFC 6710\) 分機上通告的優先分配策略。可接受的值為`mixer`, `stanag4406`和`nsep` ，或`false`以停用該分機。
- vrfy: whether to advertise the `VRFY` command, used by senders to verify the existence of a mailbox. Disabling it by default prevents address harvesting; the default policy only enables it for authenticated sessions.
vrfy ：是否通告`VRFY`命令，該命令供寄件人驗證郵箱是否存在。預設情況下停用此功能可防止位址收集；預設原則僅對已認證的會話啟用此功能。
- expn: whether to advertise the `EXPN` command, used to request the membership of a mailing list. The default policy mirrors `vrfy`.
expn : 是否發布`EXPN`指令，該指令用於請求加入郵件清單。預設策略與`vrfy`類似。
The `SIZE`, `ENHANCEDSTATUSCODES`, `8BITMIME`, and `SMTPUTF8` extensions are always advertised and are not configurable. The `AUTH` extension is governed by the AUTH stage.
`SIZE`, `ENHANCEDSTATUSCODES`, `8BITMIME`和`SMTPUTF8`擴充始終會通告AUTH `AUTH` \]\([https://stalw.art/docs/mta/inbound/auth\)控制。](https://stalw.art/docs/mta/inbound/auth%2529%2525E6%25258E%2525A7%2525E5%252588%2525B6%2525E3%252580%252582)

 Example configuration restricting advanced extensions to authenticated sessions:

 範例配置，將高級擴充功能限制為僅對已認證會話開放：

```json
{
  "pipelining": {"else": "true"},
  "chunking": {"else": "true"},
  "requireTls": {"else": "true"},
  "noSoliciting": {"else": "''"},
  "dsn": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "true"}},
    "else": "false"
  },
  "futureRelease": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "7d"}},
    "else": "false"
  },
  "deliverBy": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "15d"}},
    "else": "false"
  },
  "mtPriority": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "mixer"}},
    "else": "false"
  },
  "vrfy": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "true"}},
    "else": "false"
  },
  "expn": {
    "match": {"0": {"if": "!is_empty(authenticated_as)", "then": "true"}},
    "else": "false"
  }
}
```
