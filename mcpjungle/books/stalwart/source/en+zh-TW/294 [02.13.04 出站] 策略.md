# Strategies｜策略

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[outbound｜出站\\\]\\\(&lt;000 目錄.md#c-52&gt;\\\)

Delivery strategies define the behaviour and policies used when Stalwart MTA delivers email messages, whether to local recipients or remote systems. Strategies allow dynamic delivery logic driven by runtime conditions: expressions are evaluated for each recipient and message, so routing, scheduling, connection parameters, and transport security can all adapt to the context of each delivery.

 投遞策略定義了 Stalwart MTA向本地收件人或遠端系統投遞電子郵件時的行為和策略。策略允許根據運行時條件動態調整投遞邏輯：表達式會針對每個收件人和每封郵件進行評估，因此路由、調度、連接參數和傳輸安全都可以根據每次投遞的上下文進行調整。

 Each message processed by the MTA is evaluated against four strategy expressions to determine how it should be handled. The expressions inspect attributes such as sender, recipient, message headers, IP address, or other metadata, and return the name of a named strategy \(defined by the appropriate reference object\) that should be applied.

 MTA處理的每個訊息都會根據四個策略表達式進行評估，以確定其處理方式。這些表達式會檢查寄件者、收件者、訊息頭、 IP位址或其他元資料等屬性，並傳回應套用的命名策略的名稱（由對應的參考物件定義）。

 There are four types of strategies:

 策略分為四種類型：

- Routing strategy: determines the delivery target. A recipient may be routed for local delivery, to a remote host via MX resolution, or through a predefined relay host.
路由策略 ：確定投遞目標。收件者可以被路由到本地投遞，透過MX解析到遠端主機，或透過預先定義的中繼主機投遞。
- Scheduling strategy: governs how messages are queued and retried. It determines which virtual queue should be used, how frequently delivery attempts are made, how messages are prioritised, and when undeliverable messages expire.
調度策略 ：控制訊息的排隊和重試方式。它決定應該使用哪個虛擬佇列、投遞嘗試的頻率、訊息的優先權以及無法投遞的訊息何時過期。
- Connection strategy: defines how outbound connections to remote mail servers are established, including source IP address, connection timeouts, and custom EHLO domains.
連接策略 ：定義如何建立與遠端郵件伺服器的出站連接，包括來源IP位址、連接逾時和自訂EHLO域。
- TLS strategy: determines the transport-layer security settings applied to the connection, including DANE, MTA-STS, STARTTLS, and certificate-validation policy.
TLS策略 : 確定應用於連接的傳輸層安全設置，包括DANE, MTA-STS, STARTTLS和憑證驗證策略。
Each strategy type is evaluated independently, but together they define a complete delivery policy.
 每種策略類型都是獨立評估的，但它們共同構成了一個完整的交付策略。

## Configuration｜配置

 Delivery behaviour is governed by four fields on the MtaOutboundStrategy singleton \(found in the WebUI under Settings › MTA › Outbound › Strategy\):

 交付行為由 MtaOutboundStrategy單例中的四個欄位控制（可在 WebUI 的「設定」› MTA › 出站 › 策略」下找到）：

- route: expression selecting the route name, resolved to an MtaRoute object.
route : 選擇路由名稱的表達式，解析為 MtaRoute物件。
- schedule: expression selecting the scheduling strategy name, resolved to an MtaDeliverySchedule object.
schedule : 選擇調度策略名稱的表達式，解析為 MtaDeliverySchedule物件。
- connection: expression selecting the connection strategy name, resolved to an MtaConnectionStrategy object.
connection : 選擇連接策略名稱的表達式，解析為 MtaConnectionStrategy物件。
- tls: expression selecting the TLS strategy name, resolved to an MtaTlsStrategy object.
tls : 選取TLS策略名稱的表達式，解析為 MtaTlsStrategy物件。
Each expression is evaluated for every recipient in a message. They have access to a wide set of variables describing the message, its origin, recipients, delivery status, and more, so expressions can match against domain names, message metadata, delivery conditions, or error states. A named strategy object with the returned name must exist. If it does not, delivery does not fail: Stalwart logs an `smtp.id-not-found` warning and falls back to a built-in default \(route `mx`, a 2 minute to 2 hour retry schedule expiring after 5 days on the `default` virtual queue, optional TLS, and default connection timeouts\). Since that fallback silently replaces the policy you configured, treat these warnings as configuration errors rather than informational messages.
 每個表達式都會針對郵件中的每個收件者進行評估。它們可以存取描述郵件、其來源、收件人、投遞狀態等的大量變量，因此表達式可以匹配網域名稱、郵件元資料、投遞條件或錯誤狀態。必須存在一個\([https://stalw.art/docs/configuration/variables#mta-variables\)傳回名稱的命名策略物件。如果不存在，投遞不會失敗：Stalwart](https://stalw.art/docs/configuration/variables#mta-variables%2529%2525E5%252582%2525B3%2525E5%25259B%25259E%2525E5%252590%25258D%2525E7%2525A8%2525B1%2525E7%25259A%252584%2525E5%252591%2525BD%2525E5%252590%25258D%2525E7%2525AD%252596%2525E7%252595%2525A5%2525E7%252589%2525A9%2525E4%2525BB%2525B6%2525E3%252580%252582%2525E5%2525A6%252582%2525E6%25259E%25259C%2525E4%2525B8%25258D%2525E5%2525AD%252598%2525E5%25259C%2525A8%2525EF%2525BC%25258C%2525E6%25258A%252595%2525E9%252581%25259E%2525E4%2525B8%25258D%2525E6%25259C%252583%2525E5%2525A4%2525B1%2525E6%252595%252597%2525EF%2525BC%25259AStalwart) 會記錄一條警告信息，並回退到內置的默認策略（路由為`smtp.id-not-found` ，在`mx`虛擬隊列上設置 2 分鐘到 2 小時的重試間隔，並在 5 天后過期，可選的`default`以及默認連接超時）。由於此回退策略會靜默地替換您配置的策略，因此請將這些警告視為配置錯誤TLS而不是資訊性訊息。

## Example｜例子

 A typical configuration sets each expression to pick a different strategy name based on context: `route` returns `'local'` when the recipient domain is local \(`is_local_domain(rcpt_domain)`\) and `'mx'` otherwise; `schedule` returns `'local'` for local recipients, `'dsn'` for delivery-status notifications, `'report'` for aggregate reports, and `'remote'` otherwise; `connection` returns `'long-timeout'` when a previous attempt failed with a connection error and `'default'` otherwise; and `tls` returns `'invalid-tls'` when a previous attempt failed due to a TLS error and `'default'` otherwise. Corresponding MtaRoute, MtaDeliverySchedule, MtaConnectionStrategy, and MtaTlsStrategy objects must be defined with the names referenced by the expressions.

 典型的配置會根據上下文為每個表達式選擇不同的策略名稱： `route`當收件人域為本地域時返回`'local'` \( `is_local_domain(rcpt_domain)` \)，否則返回`'mx'` `'local'` `schedule`對於本地傳`'dsn'` ，對於匯總報告回傳`'report'` ，否則回傳`'remote'` ； `connection`當先前嘗試因連接錯誤而失敗時返回`'long-timeout'` ，否則返回`'default'` TLS `tls` `'invalid-tls'` ，否則回傳`'default'` 。對應的 MtaRoute 、MtaDeliverySchedule 、MtaConnectionStrategy和 MtaTlsStrategy必須使用表達式中所引用的名稱進行定義。

```json
{
  "route": {
    "match": {
      "0": {"if": "is_local_domain(rcpt_domain)", "then": "'local'"}
    },
    "else": "'mx'"
  },
  "schedule": {
    "match": {
      "0": {"if": "is_local_domain(rcpt_domain)", "then": "'local'"},
      "1": {"if": "source == 'dsn'", "then": "'dsn'"},
      "2": {"if": "source == 'report'", "then": "'report'"}
    },
    "else": "'remote'"
  },
  "connection": {
    "match": {
      "0": {"if": "retry_num > 0 && last_error == 'connection'", "then": "'long-timeout'"}
    },
    "else": "'default'"
  },
  "tls": {
    "match": {
      "0": {"if": "retry_num > 0 && last_error == 'tls'", "then": "'invalid-tls'"}
    },
    "else": "'default'"
  }
}
```

Values on this page follow the object encoding rules: list and set fields are JSON objects rather than arrays, and durations and sizes are integers.

 本頁上的值遵循 物件編碼規則：列表和集合字段是JSON物件而不是數組，持續時間和大小是整數。
