# SQL Database｜SQL資料庫

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[backend｜後端\\\]\\\(&lt;000 目錄.md#c-6&gt;\\\)

Stalwart can authenticate users and look up account metadata against an SQL database such as PostgreSQL, MySQL, or SQLite. This makes it possible to reuse an existing SQL-backed user directory, or to manage accounts in a relational schema that other applications already share.

 Stalwart 可以驗證使用者身份，並根據 PostgreSQL、MySQL 或 SQLite 等資料庫尋找SQL元資料。這使得重複使用現有的、由SQL 、MySQL 或 SQLite 支援的使用者目錄，或在其他應用程式已共用的關係模式中管理帳戶成為可能。

 An SQL directory is configured through the SQL variant of the Directory object \(found in the WebUI under Settings › Authentication › Directories\).

 SQL目錄是透過 Directory物件的SQL變體進行配置的（可在 WebUI 的「設定 › 驗證 › 目錄」下找到）。

## Account provisioning｜帳戶配置

 Accounts are not copied from the database in advance. Stalwart materialises a local account the first time it needs one, either when the user authenticates or when a message arrives for their address and queryRecipient confirms it as a valid recipient. Because that query can be run at any time, an account that has never signed in can still receive mail.

 帳戶不會預先從資料庫複製。 Stalwart 會在首次需要時建立本機帳戶，例如使用者驗證時，或有郵件寄到該位址且 queryRecipient確認其為有效收件者時。由於該查詢可以隨時運行，因此從未登入的帳戶仍然可以接收郵件。

 Removal is the case this does not cover. Just-in-time provisioning never deletes anything: a row removed from the `accounts` table stops matching queries, but the mailbox Stalwart created from it remains, keeps accepting mail, and keeps counting against licensed mailbox limits.

 本文不涵蓋刪除操作。即時設定不會刪除任何內容：從`accounts`表中刪除的行將不再符合查詢，但Stalwart由此建立的郵箱仍然存在，繼續接收郵件，並繼續計入許可的郵箱數量限制。

 Where that matters, SCIM provisioning can be enabled per domain so that the identity provider suspends and deletes accounts explicitly. Doing so makes SCIM authoritative for the accounts in that domain and stops just-in-time synchronisation from writing to them. Provisioning models compares the two and covers how authority is assigned.

 在需要時，可以針對每個網域啟用 SCIM配置 ，以便身分提供者明確暫停和刪除帳戶。這樣做會使SCIM成為該網域中帳戶的權威機構，並阻止即時同步寫入這些帳戶。 配置模型對兩者進行了比較，並介紹如何分配權限。

## Configuration｜配置

 The main fields on the SQL variant of the Directory object are:

 Directory 物件SQL變體的主要欄位有：

- description: a human-readable description of this directory.
description : 此目錄的人類可讀描述。
- store: the backend where the account tables live. The `SqlAuthStore` variant selects between `Default` \(the server’s data store, when that is itself SQL\), `PostgreSql`, `MySql`, and `Sqlite`. Each backend variant carries its own connection parameters \(host, port, database, username, and secret\) detailed on the Directory reference page.
store：帳戶表所在的後端。 `SqlAuthStore` 變體在`Default`（伺服器的資料存儲，當它本身是SQL）、`PostgreSql`, `MySql` 和`Sqlite` 之間進行選擇。每個後端變體都帶有自己的連接參數（主機、連接埠、資料庫、使用者名稱和密碼），詳細資訊請參閱目錄參考頁。
### Directory queries｜目錄查詢

 The SQL variant runs the following queries against the configured store; all of them use positional parameters \(`$1`, `$2`, …\) and sensible defaults that can be overridden per deployment:

 SQL變體針對已配置的儲存執行以下查詢；所有查詢均使用位置參數（ `$1`, `$2` ，…）和合理的預設值，這些預設值可以針對每個部署進行覆蓋：

- queryLogin: resolves account details by login value. Default `"SELECT name, secret, description, type FROM accounts WHERE name = $1"`.
queryLogin : 透過登入值解析帳戶詳細資料。預設值為`"SELECT name, secret, description, type FROM accounts WHERE name = $1"` 。
- queryRecipient: resolves account details by recipient email address or alias. Default `"SELECT name, secret, description, type FROM accounts WHERE name = $1 AND active = true"`.
queryRecipient : 透過收件者電子郵件地址或別名解析帳號詳細資料。預設值為`"SELECT name, secret, description, type FROM accounts WHERE name = $1 AND active = true"` 。
- queryMemberOf: returns the groups an account is a member of. Default `"SELECT member_of FROM group_members WHERE name = $1"`.
queryMemberOf : 傳回帳戶所屬的群組。預設值為`"SELECT member_of FROM group_members WHERE name = $1"` 。
- queryEmailAliases: returns the email aliases of an account. Default `"SELECT address FROM emails WHERE name = $1"`.
queryEmailAliases : 傳回帳號的電子郵件別名。預設值為`"SELECT address FROM emails WHERE name = $1"` 。
### Column mappings｜列映射

 Column names in the database are mapped to account fields through the following fields on the SQL variant:

 資料庫中的列名透過SQL變體上的以下欄位對應到帳戶欄位：

- columnEmail: column holding the account login / primary address. Default `"name"`.
columnEmail : 包含帳號登入名稱/主地址的欄位。預設值為`"name"` 。
- columnSecret: column holding the password hash. Default `"secret"`. Hashes must be in a supported format; plain text is possible but not recommended.
columnSecret ：儲存密碼雜湊值的欄位。預設值為`"secret"` 。哈希值必須採用 支援的格式 ；可以使用純文本，但不建議使用。
- columnClass: column holding the account kind \(`individual`, `person`, or `group`\). Default `"type"`.
columnClass : 儲存帳戶類型的欄位（ `individual`, `person`或`group` ）。預設值為`"type"` 。
- columnDescription: column holding the account’s full name or description. Default `"description"`.
columnDescription : 包含帳戶全名或描述的欄位。預設值為`"description"` 。
There is no column mapping for a per-account disk quota: quotas are held on the Account and Tenant objects rather than read from the SQL directory \(see Quotas\).
 每個帳戶的磁碟配額沒有列映射：配額保存在 Account和 Tenant物件中，而不是從SQL目錄讀取（請參閱 Quotas ）。

 For example:

 例如：

```json
{
  "@type": "Sql",
  "description": "External SQL directory",
  "store": {
    "@type": "Default"
  },
  "columnEmail": "name",
  "columnSecret": "secret",
  "columnDescription": "description",
  "columnClass": "type"
}
```

## Sample directory schema｜範例目錄結構

 The following schema is a reference example for an SQL-backed directory. It may need to be adapted for specific deployments; it is not intended to be used as-is.

 以下架構是基於SQL的目錄的參考範例。它可能需要根據具體部署進行調整；不建議直接使用。

### Table schema｜表結構

#### SQLite

```sql
CREATE TABLE accounts (name TEXT PRIMARY KEY, secret TEXT, description TEXT, type TEXT NOT NULL, active BOOLEAN DEFAULT 1)
CREATE TABLE group_members (name TEXT NOT NULL, member_of TEXT NOT NULL, PRIMARY KEY (name, member_of))
CREATE TABLE emails (name TEXT NOT NULL, address TEXT NOT NULL, type TEXT, PRIMARY KEY (name, address))
```

#### PostgreSQL

```sql
CREATE TABLE accounts (name TEXT PRIMARY KEY, secret TEXT, description TEXT, type TEXT NOT NULL, active BOOLEAN DEFAULT true);
CREATE TABLE group_members (name TEXT NOT NULL, member_of TEXT NOT NULL, PRIMARY KEY (name, member_of));
CREATE TABLE emails (name TEXT NOT NULL, address TEXT NOT NULL, type TEXT, PRIMARY KEY (name, address));
```

#### MySQL

```sql
CREATE TABLE accounts (name VARCHAR(32) PRIMARY KEY, secret VARCHAR(1024), description VARCHAR(1024), type VARCHAR(32) NOT NULL, active BOOLEAN DEFAULT 1);
CREATE TABLE group_members (name VARCHAR(32) NOT NULL, member_of VARCHAR(32) NOT NULL, PRIMARY KEY (name, member_of));
CREATE TABLE emails (name VARCHAR(32) NOT NULL, address VARCHAR(128) NOT NULL, type VARCHAR(32), PRIMARY KEY (name, address));
```

### Creating user accounts｜建立使用者帳戶

 Before inserting an account, hash the password. One way is via `openssl`, for example to produce a SHA-512 crypt hash:

 在插入帳戶之前，請對密碼進行雜湊處理。例如，可以使用`openssl`產生SHA -512 加密哈希值：

```bash title=&amp;quot;Terminal window&amp;quot;
$ openssl passwd -6
```

Once the hashed secret is available, insert the account and its primary address:

 取得雜湊金鑰後，插入帳戶及其主位址：

```sql
INSERT INTO accounts (name, secret, description, type) VALUES ('<ACCOUNT_NAME>', '<HASHED_SECRET>', '<ACCOUNT_FULL_NAME>', 'individual')
INSERT INTO emails (name, address, type) VALUES ('<ACCOUNT_NAME>', '', 'primary')
```

Replace:

 代替：

- `<ACCOUNT_NAME>` with the account login name, for example `john`.
`<ACCOUNT_NAME>`加上帳戶登入名，例如`john` 。
- `<HASHED_SECRET>` with the hashed password produced above.
`<HASHED_SECRET>`使用上面產生的哈希密碼。
- `<ACCOUNT_FULL_NAME>` with the account’s full name, for example `John Doe`.
`<ACCOUNT_FULL_NAME>`加上帳戶的全名，例如`John Doe` 。
- \`\` with the primary address, for example `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`.
``帶有主地址，例如`[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` 。
### Adding an email alias｜新增電子郵件別名

 To add an alias to an existing account:

 在現有帳戶中新增別名：

```sql
INSERT INTO emails (name, address, type) VALUES ('<ACCOUNT_NAME>', '<EMAIL_ALIAS>', 'alias')
```

For example, to add the aliases `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` and `[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)` to the account `john`:

 例如，要將別名`[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`和`[[email protected]](https://stalw.art/cdn-cgi/l/email-protection)`新增至帳戶`john` ：

```sql
INSERT INTO emails (name, address, type) VALUES ('john', '[email protected]', 'alias')
INSERT INTO emails (name, address, type) VALUES ('john', '[email protected]', 'alias')
```

Alternatively, the `postmaster` account can be configured as the catch-all recipient for `example.org` by adding `@example.org` as an alias:

 或者，可以將`postmaster`帳戶配置為\([https://stalw.art/docs/mta/inbound/rcpt#catch-all-addresses\)的](https://stalw.art/docs/mta/inbound/rcpt#catch-all-addresses%2529%2525E7%25259A%252584) \[通用收件人\]`@example.org` `example.org`為別名：

```sql
INSERT INTO emails (name, address, type) VALUES ('postmaster', '@example.org', 'alias')
```

### Creating group accounts｜建立群組帳戶

```sql
INSERT INTO accounts (name, description, type) VALUES ('<GROUP_NAME>', '<GROUP_DESCRIPTION>', 'group')
```

Replace `<GROUP_NAME>` with the group name and `<GROUP_DESCRIPTION>` with a human-readable description.

 將`<GROUP_NAME>`替換為組名， `<GROUP_DESCRIPTION>`替換為易於理解的描述。

### Adding members to a group｜在群組中新增成員

```sql
INSERT INTO group_members (name, member_of) VALUES ('<ACCOUNT_NAME>', '<GROUP_NAME>')
```
