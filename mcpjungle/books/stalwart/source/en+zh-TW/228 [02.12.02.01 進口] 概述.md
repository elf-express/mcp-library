# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[migration｜遷移\\\]\\\(&lt;000 目錄.md#c-37&gt;\\\) › \\\[import export｜進出口\\\]\\\(&lt;000 目錄.md#c-40&gt;\\\) › \\\[import｜進口\\\]\\\(&lt;000 目錄.md#c-41&gt;\\\)

Importing is the first half of a Vandelay migration: it reads a source account, over whichever protocol that source speaks, and records its contents in a local SQLite archive. The archive is a complete, self-contained description of one account that a later export reproduces on a JMAP target. Import and export never communicate directly; the archive is the only thing that passes between them, which is what lets a capture and a restore happen at different times, on different machines, and against different servers.

 導入是 Vandelay 遷移的前半部分：它透過來源使用的任何協定讀取來源帳戶，並將其內容記錄在本機 SQLite 檔案中。該存檔是一個帳戶的完整、獨立的描述，稍後導出會在 JMAP 目標上重現。匯入和匯出從不直接通訊；存檔是它們之間傳遞的唯一東西，這使得捕獲和恢復可以在不同的時間、不同的機器上、針對不同的伺服器進行。

## Supported sources｜支持的來源

 Vandelay imports from a wide range of protocols so that an account can be migrated regardless of what the originating system exposes. Each source has its own page with detailed, validated examples:

 Vandelay 從多種協定中匯入，因此無論原始系統暴露什麼，都可以移轉帳戶。每個來源都有自己的頁面，其中包含詳細的、經過驗證的範例：

- [JMAP](https://stalw.art/docs/migration/import-export/jmap) reads a full account from another JMAP server, the most faithful path because no intermediate representation is involved.
[JMAP](https://stalw.art/docs/migration/import-export/jmap)從另一個JMAP伺服器讀取完整帳戶，這是最可靠的路徑，因為不涉及中間表示。
- [IMAP](https://stalw.art/docs/migration/import-export/imap) reads mail from any IMAP server, with folder filtering, role mapping and keyword translation.
[IMAP](https://stalw.art/docs/migration/import-export/imap)從任何IMAP伺服器讀取郵件，具有資料夾過濾、角色映射和關鍵字翻譯。
- [CalDAV](https://stalw.art/docs/migration/import-export/caldav) reads calendars and events; [CardDAV](https://stalw.art/docs/migration/import-export/carddav) reads address books and contacts; [WebDAV](https://stalw.art/docs/migration/import-export/webdav) reads a plain file collection as a file-storage tree.
[CalDAV](https://stalw.art/docs/migration/import-export/caldav)讀取日曆與事件；[CardDAV](https://stalw.art/docs/migration/import-export/carddav)讀取通訊錄與聯絡人; [WebDAV](https://stalw.art/docs/migration/import-export/webdav) 將純檔案集合讀取為檔案儲存樹。
- [ManageSieve](https://stalw.art/docs/migration/import-export/managesieve) reads Sieve scripts.
[ManageSieve](https://stalw.art/docs/migration/import-export/managesieve) 讀取 Sieve 腳本。
- [Maildir](https://stalw.art/docs/migration/import-export/maildir) reads a local Maildir++ tree with no network access, and [Google Takeout](https://stalw.art/docs/migration/import-export/takeout) reads an exported directory tree of mbox, iCalendar and vCard files.
[Maildir](https://stalw.art/docs/migration/import-export/maildir) 讀取沒有網路存取權限的本機 Maildir++ 樹，[Google Takeout](https://stalw.art/docs/migration/import-export/takeout) 讀取 mbox、iCalendar 和 vCard 檔案的匯出目錄樹。
- [Microsoft Exchange via EWS](https://stalw.art/docs/migration/import-export/exchange-ews) and [Microsoft Exchange Online via Graph](https://stalw.art/docs/migration/import-export/exchange-graph) read Exchange mailboxes, producing mail, calendars and contacts in a single run.
[Microsoft Exchange via EWS](https://stalw.art/docs/migration/import-export/exchange-ews) 和 [Microsoft Exchange Online via Graph](https://stalw.art/docs/migration/import-export/exchange-graph) 讀取 Exchange 郵箱，在一次運行中產生郵件、日曆和聯絡人。
Several of these importers carry only one kind of data, so a complete account migration often combines a few of them against the same archive: an IMAP import for mail, a CalDAV and CardDAV import for scheduling and contacts, and a ManageSieve import for filters, for example. The Exchange importers and the JMAP importer are the exceptions, each producing several data types at once.
 其中幾個導入器僅攜帶一種數據，因此完整的帳戶遷移通常會將其中的幾個導入到同一存檔：例如，用於郵件的 IMAP 導入、用於日程安排和聯絡人的 CalDAV 和 CardDAV 導入以及用於過濾器的 ManageSieve 導入。 Exchange 導入器和 JMAP 導入器是例外，每個導入器同時產生多種資料類型。

## Reconciliation model｜調節模型

 Every importer works by id-based reconciliation rather than by maintaining a running synchronisation cursor. For each data type Vandelay enumerates the identifiers the source currently holds, compares that set against the identifiers already stored in the archive, and then fetches and inserts the objects that are new while removing the records whose identifiers have disappeared from the source. Container types such as mailboxes, calendars and address books are always reconciled before the items that belong to them, so the structure an item depends on is present before the item itself.

 每個導入器都透過基於 id 的協調來運作，而不是透過維護正在運行的同步遊標。對於每種資料類型，Vandelay 枚舉來源目前保存的標識符，將該集合與已儲存在存檔中的標識符進行比較，然後取得並插入新的對象，同時刪除標識符已從來源中消失的記錄。郵箱、日曆和地址簿等容器類型始終在屬於它們的項目之前進行協調，因此項目所依賴的結構先於項目本身出現。

 This model has a useful consequence: an import is convergent. A run that is interrupted by a network failure or a signal can simply be started again, and it resumes by recomputing the difference between source and archive. A run repeated days later against the same account captures whatever has changed in the meantime. There is no bookkeeping flag to clear and no partial state to repair.

 這個模型有一個有用的結果：導入是收斂的。由於網路故障或訊號而中斷的運行可以簡單地重新啟動，並透過重新計算來源和存檔之間的差異來恢復。幾天後對同一帳戶重複運行可以捕獲在此期間發生的任何變化。沒有需要清除的簿記標誌，也沒有需要修復的部分狀態。

## Common behaviour across importers｜進口商的共同行為

 Although the connection and selection flags differ from protocol to protocol, several behaviours are shared by every import path.

 儘管連接和選擇標誌因協定而異，但每個導入路徑都共享一些行為。

 The destination archive is always the final positional argument and is created automatically if it does not yet exist. Credentials, where a source requires them, should be supplied through the `VANDELAY_PASSWORD`, `VANDELAY_TOKEN` or provider-specific environment variables, or through the interactive prompt, rather than written on the command line. Every importer records the identity of the source it was first run against and refuses to import from a different source into the same archive unless `--allow-source-change` is given, which prevents two unrelated accounts from being merged by accident. Items that cannot be parsed, such as a malformed calendar entry, are skipped with a warning and counted toward the partial-failure exit code rather than aborting the whole run. The global `--dry-run` flag computes and reports the full plan, including how many objects would be created or removed, without writing anything.

 目標存檔始終是最終位置參數，如果尚不存在，則會自動建立。如果來源需要憑證，則應透過 `VANDELAY_PASSWORD`, `VANDELAY_TOKEN` 或特定於提供者的環境變數或透過互動式提示提供，而不是在命令列上編寫。每個導入器都會記錄其首次運行的來源的身份，並拒絕從不同的來源匯入到同一存檔中，除非給予`--allow-source-change`，這可以防止兩個不相關的帳戶被意外合併。無法解析的項目（例如格式錯誤的日曆條目）將被跳過並發出警告，併計入部分失敗退出代碼，而不是中止整個運行。全域 `--dry-run` 標誌計算並報告完整計劃，包括將建立或刪除多少對象，而無需編寫任何內容。

 The flags common to every command, including verbosity, worker-pool sizing, retry policy and TLS handling, are described on the [Usage](https://stalw.art/docs/migration/usage) page.

 每個指令通用的標誌，包括詳細程度、工作池大小、重試策略和TLS處理，在[用法](https://stalw.art/docs/migration/usage)頁面上進行了描述。
