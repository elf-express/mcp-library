# Routing｜路由

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[outbound｜出站\\\]\\\(&lt;000 目錄.md#c-52&gt;\\\)

Message routing determines the final destination host for a message. When a message is processed for delivery, the selected routing strategy defines whether it should be delivered locally, resolved through DNS, or sent through an intermediate relay.

 訊息路由決定訊息的最終目的地主機。當處理訊息以進行投遞時，所選的路由策略決定訊息是否應該在本地投遞、透過DNS解析，還是透過中間中繼發送。

 Three routing variants are supported:

 支援三種路由方式：

- **Local**: delivers the message to the local message store, typically for users hosted on the same system or domain.
**本機**：將訊息傳遞到本機訊息存儲，通常適用於託管在同一系統或網域中的使用者。
- **MX**: uses DNS MX-record resolution to determine the destination server for remote delivery.
**MX**: 使用DNS MX記錄解析來決定遠端交付的目標伺服器。
- **Relay**: forwards the message to a predefined relay host, regardless of recipient domain.
**中繼**：將訊息轉送到預先定義的中繼主機，而不管收件者網域為何。
Each message recipient can be routed independently under a different strategy. This allows, for example, some messages to be delivered locally while others are relayed or sent via MX resolution based on domain, authentication status, or other delivery context.
 每個訊息接收者都可以根據不同的策略獨立路由。例如，這使得某些訊息可以在本地傳遞，而其他訊息則可以根據網域、身份驗證狀態或其他傳遞上下文進行中繼或透過MX解析發送。

 Routing strategies are defined as MtaRoute objects \(found in the WebUI under Settings › MTA › Outbound › Routes\). MtaRoute is a multi-variant object: each instance selects one of the `Local`, `Mx`, or `Relay` variants, and the chosen variant determines which fields apply.

 路由策略定義為 MtaRoute物件（可在 WebUI 的「 `Relay` 」› MTA › 出站 › 路由」中找到）。MtaRoute 是一個多變體物件：每個實例選擇`Local`, `Mx`

 Once defined, routes are selected dynamically for each recipient via the route expression on MtaOutboundStrategy; see Strategies.

 一旦定義了路由，就會透過 MtaOutboundStrategy上的路由表達式為每個接收者動態選擇路由；請參閱 Strategies 。

## Local delivery｜本地配送

 The `Local` variant delivers messages to the server’s internal message store, where they are made available to users through JMAP, IMAP, or POP3. This route is typically used for delivering messages to domains and users hosted on the same Stalwart instance. Messages routed locally are written directly into the mailbox storage backend. The Local variant has no additional delivery parameters beyond the route name:

`Local`變體將郵件投遞到伺服器的內部郵件儲存區，然後透過JMAP, IMAP或POP3提供給使用者。此路由通常用於將郵件投遞到託管在相同 Stalwart 實例上的網域和使用者。本機路由的郵件直接寫入郵箱儲存後端。本地變體除了路由名稱之外，沒有其他投遞參數：

```json
{
  "@type": "Local",
  "name": "local"
}
```

## MX delivery｜MX送貨

 The `Mx` variant delivers messages to remote domains using DNS MX-record resolution. Stalwart queries the MX records for the recipient domain and attempts delivery to the listed hosts in priority order. Each record carries a hostname and priority value; the hosts with the lowest priority are tried first, with subsequent hosts attempted if delivery fails.

`Mx`變體使用DNS MX記錄解析將郵件投遞到遠端域。 Stalwart 會查詢MX記錄以取得收件者網域，並以優先順序嘗試將郵件投遞到列出的主機。每筆記錄都包含主機名稱和優先權值；系統會先嘗試優先權最低的主機，如果投遞失敗，則會嘗試優先權較高的主機。

 The following fields apply to the Mx variant:

 以下欄位適用於 Mx 變體：

- maxMxHosts: maximum number of MX hosts tried per delivery attempt. Default 5.
maxMxHosts : 每次投遞嘗試嘗試的最大主機數MX 。預設值為 5。
- maxMultihomed: for multi-homed MX hosts, maximum number of IP addresses to try per host. Default 2.
maxMultihomed : 對於多MX主機，每個主機嘗試的最大IP數。預設值為 2。
- ipLookupStrategy: IP resolution strategy. Supported values are `v4ThenV6` \(default\), `v6ThenV4`, `v4Only`, and `v6Only`.
ipLookupStrategy: IP解析度策略。支援的值為`v4ThenV6` （預設值）、 `v6ThenV4`, `v4Only`和`v6Only` 。
Setting `maxMxHosts` to 3 means that if a domain has five MX records, only the three with the lowest priority are considered during the attempt. This limits connection time and resource usage when dealing with domains that have many fallback servers. Similarly, `maxMultihomed` capped at 2 avoids long delays when several IP addresses are unreachable.
 將`maxMxHosts`設為 3 表示，如果一個域有五個MX記錄，則在嘗試連線時只會考慮優先順序最低的三個記錄。這可以限制連線時間和資源使用，尤其是在處理具有多個備用伺服器的網域時。類似地，將`maxMultihomed`限制為 2 可以避免在多個IP位址無法存取時出現長時間延遲。

 Example MX route trying IPv4 addresses first:

 範例MX路由先嘗試 IPv4 位址：

```json
{
  "@type": "Mx",
  "name": "mx",
  "maxMxHosts": 3,
  "maxMultihomed": 2,
  "ipLookupStrategy": "v4ThenV6"
}
```

## Relay delivery｜接力配送

 The `Relay` variant delivers messages through a predefined relay host instead of resolving the recipient domain via DNS. A relay host accepts mail from another server and forwards it to its final destination, acting as an intermediate stop. Relays are useful when the originating server should not perform direct delivery \(for example because of firewall constraints or IP-reputation issues\), or when outbound mail should pass through a scanning appliance.

`Relay`變體透過預先定義的中繼主機傳遞郵件，而不是透過DNS解析收件者域。中繼主機接收來自其他伺服器的郵件並將其轉發到最終目的地，充當中間站點。當來源伺服器不應執行直接投遞（例如，由於防火牆限製或IP信譽問題）或當出站郵件需要經過掃描設備時，中繼非常有用。

 The following fields apply to the Relay variant:

 以下欄位適用於 Relay 版本：

- address: fully-qualified hostname or IP address of the remote server.
address : 遠端伺服器的完全限定主機名稱或IP位址。
- port: port on the remote server. Default 25.
port : 遠端伺服器連接埠。預設值為 25。
- protocol: `smtp` or `lmtp`. Default `smtp`.
protocol: `smtp`或`lmtp` 。預設值為`smtp` 。
- implicitTls: whether to establish TLS implicitly on connection, rather than negotiating it with `STARTTLS`. Default `false`.
implicitTls : 是否在連接時隱式建立TLS ，而不是與`STARTTLS`協商。預設值為`false` 。
- allowInvalidCerts: whether self-signed or otherwise invalid certificates are accepted. Default `false`.
allowInvalidCerts : 是否接受自簽名憑證或其他無效憑證。預設值為`false` 。
- authUsername: optional username for SMTP authentication to the relay.
authUsername : SMTP中繼驗證的選用使用者名稱。
- authSecret: authentication secret. A multi-variant field supporting `None` \(no authentication\), `Value` \(secret supplied directly\), `EnvironmentVariable` \(secret read from an environment variable\), and `File` \(secret read from a file\).
authSecret : 驗證金鑰。一個多變體字段，支援`None` \(無身份驗證\)、 `Value` \(直接提供的金鑰\)、 `EnvironmentVariable` \(從環境變數讀取的金鑰\) 和`File` \(從檔案中讀取的金鑰\)。
## Examples｜範例

### Relay host｜中繼主機

 Operators can define a Relay MtaRoute for a specific host and an Mx MtaRoute for general remote delivery, and then select between them through the route expression on MtaOutboundStrategy. A common pattern is to relay everything destined for an internal domain through a specific relay while all other mail takes the standard MX path. The corresponding MtaRoute objects:

 操作員可以為特定主機定義一個中繼 MtaRoute，並為一般遠端投遞定義一個 MX MtaRoute，然後透過 MtaOutboundStrategy上的路由表達式在兩者之間進行選擇。常見的模式是將所有發送到內部網域的郵件透過特定的中繼來轉發，而所有其他郵件則走標準的MX路徑。對應的 MtaRoute 物件如下：

```json
[
  {
    "@type": "Relay",
    "name": "relay",
    "address": "relay.example.org",
    "port": 25,
    "protocol": "smtp",
    "implicitTls": false,
    "allowInvalidCerts": false,
    "authSecret": {"@type": "None"}
  },
  {
    "@type": "Mx",
    "name": "mx",
    "ipLookupStrategy": "v4ThenV6"
  }
]
```

The route expression on MtaOutboundStrategy then branches on `is_local_domain(rcpt_domain)` to pick `'relay'` versus `'mx'`.

 MtaOutboundStrategy 上的路由表達式在`is_local_domain(rcpt_domain)`上分支，以選擇`'relay'`而不是`'mx'` 。

### Failover delivery｜故障轉移交付

 Failover delivery forwards messages to a secondary host after the primary delivery path has failed a given number of times. Two MtaRoute objects are created \(for example an Mx route and a Relay “fallback” route\) and the route expression on MtaOutboundStrategy branches on `retry_num` so that after the second failure the `fallback` route is selected. Local-domain traffic can be routed through a third MtaRoute of the Local variant:

 故障轉移機制會在主傳輸路徑發生指定次數的故障後，將訊息轉送到備用主機。系統會建立兩個 MtaRoute 物件（例如，一個 Mx 路由和一個 Relay「回退」路由），並且 MtaOutboundStrategy 上的路由表達式會根據`retry_num`進行分支，以便在第二次故障後選擇`fallback`路由。本地域流量可以透過第三個本地變體的 MtaRoute 進行路由：

```json
[
  {"@type": "Local", "name": "local"},
  {
    "@type": "Mx",
    "name": "mx",
    "ipLookupStrategy": "v4ThenV6"
  },
  {
    "@type": "Relay",
    "name": "fallback",
    "address": "fallback.example.org",
    "port": 25,
    "protocol": "smtp",
    "authSecret": {"@type": "None"}
  }
]
```

The route expression selects `'local'` for local domains, `'fallback'` when `retry_num > 1`, and `'mx'` otherwise.

 路由表達式對本地域選擇`'local'` ，當`retry_num > 1`時選擇`'fallback'` ，否則選擇`'mx'` 。

### LMTP delivery｜LMTP送貨

 LMTP \(Local Mail Transfer Protocol\) is a derivative of SMTP used for the final delivery of mail to a local recipient’s mailbox. To hand messages to an LMTP server, a Relay MtaRoute is created with protocol set to `lmtp`, port set to 24, `implicitTls` disabled, and optionally `authUsername` and `authSecret` populated. The route expression then selects this route for local domains, using the Mx variant for remote traffic:

 LMTP （本地郵件傳輸協議）是SMTP的衍生協議，用於將郵件最終投遞到本地收件人的郵箱。要將郵件轉寄到LMTP伺服器，需要建立一個中繼 MtaRoute，其中 protocol設定為`lmtp` ，port設定為 24， `implicitTls`禁用，並且可以選擇性地填入`authUsername`和`authSecret` 。然後，路由表達式會為本地域選擇此路由，並為遠端流量使用 Mx 變體：

```json
[
  {
    "@type": "Relay",
    "name": "lmtp",
    "address": "localhost",
    "port": 24,
    "protocol": "lmtp",
    "implicitTls": false,
    "allowInvalidCerts": true,
    "authUsername": "relay_server",
    "authSecret": {"@type": "Value", "secret": "123456"}
  },
  {
    "@type": "Mx",
    "name": "mx",
    "ipLookupStrategy": "v4ThenV6"
  }
]
```
