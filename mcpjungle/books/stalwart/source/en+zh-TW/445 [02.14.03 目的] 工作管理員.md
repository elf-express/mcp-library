# TaskManager｜工作管理員

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[ref｜參考\\\]\\\(&lt;000 目錄.md#c-56&gt;\\\) › \\\[object｜目的\\\]\\\(&lt;000 目錄.md#c-61&gt;\\\)

Configures task execution settings including retry strategies.

 配置任務執行設置，包括重試策略。

 This object can be configured from the WebUI under Settings › Task Manager

 此物件可在 WebUI的「設定」&gt;「工作管理員」中進行設定。

## Fields｜田野

##### `maxAttempts`

> Type: \\\`UnsignedInt\\\` · default: \\\`3\\\` · min: 1

類型： \`UnsignedInt\` · 預設值： \`3\` · 最小值：1

 Maximum number of attempts for retrying a task

 任務重試的最大次數

##### `strategy`

> Type: \\\[\\\`TaskRetryStrategy\\\`\\\]\\\(#taskretrystrategy\\\) · required

類型：\[\`TaskRetryStrategy\`\]\(#taskretrystrategy\) · 必填

 Strategy to use for retrying failed tasks

 用於重試失敗任務的策略

##### `totalDeadline`

> Type: \\\`Duration\\\` · default: \\\`21600000\\\`

類型： \`Duration\` · 預設值： \`21600000\`

 Total deadline for retrying a task before it is marked as failed

 任務被標記為失敗前允許重試的總截止時間

## JMAP API

 The TaskManager singleton is available via the `urn:stalwart:jmap` capability.

 TaskManager 單例可透過`urn:stalwart:jmap`功能取得。

### `x:TaskManager/get`

 This is a standard [Foo/get](https://www.rfc-editor.org/rfc/rfc8620#section-5.1) method as defined in [RFC 8620](https://www.rfc-editor.org/rfc/rfc8620#section-5.1), Section 5.1.

 這是[Foo/get](https://www.rfc-editor.org/rfc/rfc8620#section-5.1)方法，如[RFC](https://www.rfc-editor.org/rfc/rfc8620#section-5.1) ，第5.1節定義。

 For singletons, the `ids` argument should be the literal `singleton` \(or `null` to return the single instance\).

 對於單例， `ids`參數應該是字面值`singleton` （或`null`以傳回單一實例）。

 This method requires the `sysTaskManagerGet` permission.

 此方法需要`sysTaskManagerGet` 權限 。

```bash title=&amp;quot;Terminal window&amp;quot;
curl -X POST https://mail.example.com/api \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
      "methodCalls": [
        [
          "x:TaskManager/get",
          {
            "ids": [
              "singleton"
            ]
          },
          "c1"
        ]
      ],
      "using": [
        "urn:ietf:params:jmap:core",
        "urn:stalwart:jmap"
      ]
    }'
```

### `x:TaskManager/set`

 This is a standard [Foo/set](https://www.rfc-editor.org/rfc/rfc8620#section-5.3) method as defined in [RFC 8620](https://www.rfc-editor.org/rfc/rfc8620#section-5.3), Section 5.3.

 這是 [Foo/set](https://www.rfc-editor.org/rfc/rfc8620#section-5.3)方法，如 [RFC 8620](https://www.rfc-editor.org/rfc/rfc8620#section-5.3)節5.3中定義。

 For singletons, only the `update` argument with id `singleton` is accepted; `create` and `destroy` arguments are rejected.

 對於單例，僅接受 id 為`singleton` `update`參數；拒絕`create`和`destroy`參數。

 This method requires the `sysTaskManagerUpdate` permission.

 此方法需要`sysTaskManagerUpdate` 權限 。

```bash title=&amp;quot;Terminal window&amp;quot;
curl -X POST https://mail.example.com/api \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
      "methodCalls": [
        [
          "x:TaskManager/set",
          {
            "update": {
              "singleton": {
                "maxAttempts": 3
              }
            }
          },
          "c1"
        ]
      ],
      "using": [
        "urn:ietf:params:jmap:core",
        "urn:stalwart:jmap"
      ]
    }'
```

## CLI

`stalwart-cli` wraps the same JMAP calls. See the CLI reference for installation, authentication, and general usage.

`stalwart-cli`封裝了相同的JMAP呼叫。有關安裝、驗證和一般用法，請參閱 CLI參考 。

### Fetch｜拿來

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli get TaskManager
```

### Update｜更新

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli update TaskManager --field maxAttempts=3
```

## Nested types｜巢狀類型

### TaskRetryStrategy｜任務重試策略

 Retry strategy for failed tasks.

 失敗任務的重試策略。

- **`ExponentialBackoff`**: Exponential backoff. Carries the fields of [TaskRetryStrategyBackoff](#taskretrystrategybackoff).
**`ExponentialBackoff`**: 指數退避。承載 [TaskRetryStrategyBackoff](#taskretrystrategybackoff)的場。
- **`FixedDelay`**: Fixed delay. Carries the fields of [TaskRetryStrategyFixed](#taskretrystrategyfixed).
**`FixedDelay`**: 固定延遲。承載 [TaskRetryStrategyFixed](#taskretrystrategyfixed)的場。
#### TaskRetryStrategyBackoff｜任務重試策略退避

 Exponential backoff retry strategy settings.

 指數退避重試策略設定。

##### `factor`

> Type: \\\`Float\\\` · default: \\\`2.0\\\` · min: 1

類型： \`Float\` · 預設值： \`2.0\` · 最小值：1

 Backoff factor for calculating retry delays

 用於計算重試延遲的退避因子

##### `initialDelay`

> Type: \\\`Duration\\\` · default: \\\`60000\\\`

類型： \`Duration\` · 預設值： \`60000\`

 Initial delay before retrying a failed task

 重試失敗任務前的初始延遲

##### `maxDelay`

> Type: \\\`Duration\\\` · default: \\\`1800000\\\`

類型： \`Duration\` · 預設值： \`1800000\`

 Maximum delay between retry attempts

 重試嘗試之間的最大延遲

##### `jitter`

> Type: \\\`Boolean\\\` · default: \\\`true\\\`

類型： \`Boolean\` · 預設值： \`true\`

 Whether to apply jitter to the retry delay to avoid thundering herd problem

 是否對重試延遲應用抖動以避免群體攻擊問題

#### TaskRetryStrategyFixed｜任務重試策略已固定

 Fixed delay retry strategy settings.

 修復了延遲重試策略設定。

##### `delay`

> Type: \\\`Duration\\\` · default: \\\`300000\\\`

類型： \`Duration\` · 預設值： \`300000\`

 Fixed delay before retrying a failed task

 修正了重試失敗任務前的延遲問題
