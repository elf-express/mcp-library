# Attribute mapping｜屬性映射

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[auth｜認證\\\]\\\(&lt;000 目錄.md#c-3&gt;\\\) › \\\[scim｜方案\\\]\\\(&lt;000 目錄.md#c-10&gt;\\\)

Stalwart publishes a deliberately small SCIM schema. Every attribute in it corresponds to something a mail server actually stores, and nothing in RFC 7643 that has no mail-server meaning is published. Attributes outside that set are accepted and discarded, not refused, so an identity provider can send its default mappings without trimming them; see schema handling for where the line falls.

 Stalwart 發布了一個刻意精簡的SCIM模式。其中的每個屬性都對應於郵件伺服器實際儲存的內容，而RFC 7643 中任何對郵件伺服器沒有意義的內容都不會被發布。超出此集合的屬性會被接受並丟棄，而不是被拒絕，因此身分提供者可以發送其預設映射而無需對其進行任何修剪；有關具體細節，請參閱 模式處理 。

 The authoritative list is served by the server itself at `GET /scim/v2/Schemas`. This page explains what each attribute does once it arrives.

 權威列表由伺服器本身在`GET /scim/v2/Schemas`處提供。此頁面解釋了每個屬性到達後的作用。

## User｜使用者

 Users are provisioned under `urn:ietf:params:scim:schemas:core:2.0:User` and map onto individual accounts.

 使用者在`urn:ietf:params:scim:schemas:core:2.0:User`下進行配置，並對應到各個帳戶 。

| SCIM attribute SCIM屬性 | Stalwart field 堅韌領域 | Mutability 可變性 | Notes 註 |
| --- | --- | --- | --- |
| `id` | Account identifier 帳戶標識符 | Read-only 只讀 | Assigned by the server 由伺服器分配 |
| `externalId` | externalId externalId | Read-write 讀寫 | The identity provider’s own identifier; indexed and filterable 身分提供者本身的標識符；可索引與過濾 |
| `userName` | Account name and domain 帳戶名稱和網域名稱 | Read-write, required 讀寫權限，必填 | Must be a full email address 必須是完整的電子郵件地址 |
| `displayName` | description description | Read-write 讀寫 | Takes precedence over `name.formatted` 優先權高於`name.formatted` |
| `name.formatted` | description description | Read-write 讀寫 | Same field as `displayName` 與`displayName`相同欄位 |
| `active` | `authenticate` permission `authenticate`權限 | Read-write 讀寫 | See [Administrative status](#administrative-status) 請參閱 [管理狀態](#administrative-status) |

### The account name｜帳戶名稱

`userName` carries the full email address, and Stalwart splits it into a local part and a domain. The domain must already exist as a Domain object with allowScimProvisioning enabled; a `userName` in an unknown domain, or in one that is not open to SCIM, is refused with `invalidValue`. This means domains are created by an administrator and never by the identity provider.

`userName`包含完整的電子郵件地址，Stalwart 會將其拆分為本地部分和網域部分。該域必須已作為 Domain對象存在，並且 allowScimProvisioning已啟用；位於未知域或未對SCIM開放的域中的`userName`將被拒絕，並返回`invalidValue`這意味著網域由管理員創建，而非由身分提供者創建。

 Identity providers whose user principal names differ from their mail addresses need a mapping expression so that `userName` carries the address Stalwart should use. Provisioning a user whose `userName` is a bare login name fails, because there is no domain to resolve.

 使用者主體名稱與其郵件地址不同的身分提供者需要一個映射表達式，以便`userName`承載 Stalwart 應使用的位址。如果`userName`僅為登入名，則設定使用者會失敗，因為沒有可解析的網域。

### Addresses and aliases｜地址和別名

 The primary address is always derived from `userName`. Within the `emails` collection it appears with `primary` set to `true` and a `type` of `work`, and it cannot be removed, retyped, or made non-primary; those sub-attributes are read-only, and an attempt to change the primary entry through `emails` is refused with a message pointing back at `userName`.

 主地址始終源自於`userName` 。在`emails`集合中，它與`primary`設定為`true`以及`type`為`work`一起出現，並且不能刪除、重新輸入或將其設為非主地址；這些子屬性是只讀的，並且嘗試透過`emails` `userName`

 Every other entry in `emails` becomes an alias on the account. Aliases are replaced as a set on each `PUT` and reconciled individually on a `PATCH`, so an address dropped upstream is dropped locally. Each alias must resolve to a domain that is open to SCIM and, in a multi-tenant deployment, that belongs to the same tenant as the account; an address in another tenant’s domain is refused. Duplicate entries are ignored, and an entry that repeats the primary address is skipped.

`emails`中的每隔一個條目都會成為帳戶的別名。別名會在每個`PUT`中作為一個集合進行替換，並在`PATCH`中逐個進行協調，因此上游刪除的地址也會在本地刪除。每個別名必須解析到對SCIM開放的網域，並且在多租用戶部署中，該網域必須與帳戶屬於同一租用戶；其他租用戶網域中的位址將被拒絕。重複的條目將被忽略，重複主位址的條目將被跳過。

### Administrative status｜行政狀態

`active` is not stored as a field. It is expressed as the account’s `authenticate` permission, which is what actually determines whether the account may sign in, and reading `active` computes the effective permission from the account, its roles, and its tenant.

`active`不作為字段存儲。它表示帳戶的`authenticate`權限，這實際上決定了帳戶是否可以登錄，讀取`active`可以計算出帳戶、其角色及其租用戶的有效權限。

 Setting `active` to `false` disables the permission on the account, overriding whatever its roles would otherwise grant. Setting it back to `true` restores the account to the state it was in before, including any unrelated permission customisation an administrator had applied. Where the account had no customisation at all, deactivating and reactivating leaves it exactly as it started.

 將`active`設定為`false`會停用帳戶的權限，覆寫其角色原本授予的所有權限。將其設定回`true`會將帳戶恢復到先前的狀態，包括管理員套用的任何無關權限自訂設定。如果帳戶沒有任何自訂設置，則停用並重新啟用後，帳戶將恢復到初始狀態。

 A deactivated account keeps its mailbox and continues to receive mail; it simply cannot be authenticated against. Where mail should stop as well, delete the account, not deactivate it. Note that a SCIM client cannot deactivate or delete the account it authenticated as.

 已停用的帳戶仍保留其郵箱並繼續接收郵件；只是無法再透過身份驗證進行登入。如果郵件也應該停止接收，請刪除帳戶，而不是停用帳戶。請注意， SCIM客戶端無法停用或刪除其已通過身份驗證的帳戶。

 Both a JSON boolean and the strings `"true"` and `"false"` are accepted in a `PATCH` operation, since some clients send the latter.

 在`PATCH`操作中， JSON布爾值和字串`"true"`和`"false"`均可被接受，因為有些客戶端會發送後者。

### Locale and time zone｜地區和時區

 SCIM writes locales with a hyphen \(`en-US`\) where Stalwart stores an underscore \(`en_US`\); the translation is automatic in both directions, and case is normalised, so `EN-us` and `ca-ES@valencia` are both accepted. `locale` and `preferredLanguage` are two names for one stored value: whichever is supplied is used, `locale` wins if both are, and the resource returns the same value under both names. A locale the server does not carry a translation for is refused with `invalidValue`.

 SCIM 使用連字號 \(`en-US`\) 寫入語言環境，其中 Stalwart 儲存下劃線 \(`en_US`\)；雙向翻譯是自動的，並且大小寫標準化，因此 `EN-us` 和 `ca-ES@valencia` 都被接受。 `locale` 和 `preferredLanguage` 是一個存儲值的兩個名稱：使用提供的任何一個，如果兩者都是，則 `locale` 獲勝，並且資源在兩個名稱下返回相同的值。伺服器不攜帶翻譯的區域設定將被拒絕，並顯示 `invalidValue`。

`timezone` takes an IANA Time Zone Database identifier. An unrecognised identifier is refused.

`timezone`需要一個IANA時區資料庫標識符。無法識別的標識符將被拒絕。

### Attributes that are not implemented｜未實現的屬性

 These attributes are absent from the published schema, and a request carrying them is accepted with the value discarded. Nothing has to be removed on the identity provider.

 這些屬性在已發佈的架構中不存在，因此，如果請求中包含這些屬性，則會接受請求但丟棄其值。身份提供者無需進行任何操作。

`password` is not implemented, as explained under advertised capabilities: the identity provider holds the credential. A `password` sent on creation or replacement is dropped and never written to the credential store, so an account provisioned over SCIM has no password of its own until one is set through another interface.

 如已公佈的功能中所述， `password`尚未實現：身分提供者持有憑證。創建或替換時發送的`password`將被丟棄，並且永遠不會寫入憑證存儲區，因此透過SCIM創建的帳戶沒有自己的密碼，直到透過其他介面設定密碼為止。

`phoneNumbers`, `addresses`, `photos`, `ims`, `title`, `userType`, `nickName`, `profileUrl`, `entitlements`, `roles`, `x509Certificates`, and the enterprise user extension are dropped in the same way. On a Group, `description` is dropped.

`phoneNumbers`, `addresses`, `photos`, `ims`, `title`, `userType`, `nickName`, `profileUrl`, `entitlements`, `roles`, `x509Certificates`和企業用戶分機號的刪除方式相同。在群組中， `description`將被刪除。

`name` carries only `formatted`, because Stalwart stores a single display name and no structured name parts. `middleName`, `honorificPrefix` and `honorificSuffix` are dropped. `givenName` and `familyName` are the exception to the rule: when neither `displayName` nor `name.formatted` is supplied, they are joined with a space and stored as the display name, so a client that sends only structured names still produces a named account. When either display attribute is supplied it wins, and the resource always returns the stored display name under `displayName` and `name.formatted`, never under the structured parts.

`name`僅包含`formatted` ，因為 Stalwart `honorificSuffix` `middleName`, `honorificPrefix`被丟棄`givenName`和`familyName`是例外：當未提供`displayName`或`name.formatted`時，它們之間會用空格連接並儲存為顯示名稱，因此即使客戶端只發送結構化名稱，仍然可以產生命名帳戶。如果提供了任一顯示屬性，則以提供的屬性為準，資源始終傳回儲存在`displayName`和`name.formatted`下的顯示名稱，而不會傳回結構化名稱部分下的顯示名稱。

 An attribute belonging to no schema Stalwart recognises is a different case and is still refused with `invalidSyntax`. A mapping to `dispalyName` fails loudly, and no value it carries is silently discarded.

 如果屬性不屬於 Stalwart 可識別的任何模式，則情況有所不同，仍然會被拒絕並傳回`invalidSyntax` 。映射到`dispalyName`會發出明顯的錯誤，並且它所攜帶的任何值都會被靜默丟棄。

## Group｜團體

 Groups are provisioned under `urn:ietf:params:scim:schemas:core:2.0:Group` and map onto group accounts, which in Stalwart are mail-enabled: a group has an address and distributes to its members.

 群組在`urn:ietf:params:scim:schemas:core:2.0:Group`下配置，並映射到 群組帳戶 ，在 Stalwart 中，群組帳戶啟用了郵件功能：群組擁有一個地址，並向其成員分發郵件。

| SCIM attribute SCIM屬性 | Stalwart field 堅韌領域 | Mutability 可變性 | Notes 註 |
| --- | --- | --- | --- |
| `id` | Account identifier 帳戶標識符 | Read-only 只讀 | Assigned by the server 由伺服器分配 |
| `externalId` | externalId externalId | Read-write 讀寫 | The identity provider’s own identifier 身分提供者本身的標識符 |
| `displayName` | description description | Read-write, required 讀寫，必需 | Must be unique among groups 組內必須唯一 |
| `members` | Membership 會員資格 | Read-write 讀寫 | Users only 限使用者 |
| `meta` | Creation time and version 建立時間與版本 | Read-only 唯讀 | Version covers the membership 版本涵蓋會員資格 |

### Addresses derived from the display name｜從顯示名稱派生的位址

 A SCIM `Group` carries a display name but no address, while a Stalwart group needs one. Stalwart therefore derives the local part from `displayName`, lowercasing it and replacing runs of non-alphanumeric characters with hyphens, so `Sales EMEA` yields `sales-emea`. If that address is already taken, a numeric suffix is appended until a free one is found, and the result is truncated to 64 characters.

 SCIM `Group`包含顯示名稱但沒有位址，而 Stalwart 群組則需要位址。因此，Stalwart 從`displayName`中提取本地部分，將其轉換為小寫，並將連續的非字母數字字符替換為連字符，因此`Sales EMEA`生成`sales-emea` 。如果該位址已被佔用，則會新增一個數字後綴，直到找到空閒位址為止，並將結果截斷為 64 個字元。

 The domain is the one the authenticated service principal belongs to, since nothing in the request identifies one. A service principal whose own domain is not open to SCIM can manage users but cannot create groups; Configuration covers the placement of that account.

 網域是經過驗證的服務主體所屬的網域，因為請求中沒有任何內容可以標識服務主體。如果服務主體的網域未對SCIM開放，則該服務主體可以管理用戶，但不能建立群組；設定涵蓋了該帳戶的部署。

 Renaming a group through `displayName` does not change the address that was derived at creation. Mail already flowing to the group keeps working, which is usually what an operator wants, but it does mean the address stops resembling the name. Where the address matters, set it directly on the account afterwards.

 透過`displayName`重命名群組不會更改建立時產生的位址。已發送到該群組的郵件仍可正常接收，這通常是運營商所希望的，但這確實意味著地址不再與名稱一致。如果地址至關重要，請在重新命名後直接在帳戶中設定地址。

`displayName` must be unique among groups within the tenant, and a collision is refused with `409 Conflict` and a `scimType` of `uniqueness`. A separate `409` arises when two display names slugify to the same address and no free variant can be derived.

`displayName`在租戶內的各組之間必須是唯一的，並且不會與`409 Conflict`和`scimType`或`uniqueness`發生衝突。當兩個顯示名稱的 slugify 值相同且無法推導出其他可用變體時，會產生一個單獨的`409` 。

### Membership｜會員資格

 Only users may be members. `members.type` publishes `User` as its sole canonical value, and a member entry naming a group is refused with `invalidValue`. Nested groups are not supported in either direction.

 只有使用者才可以是會員。 `members.type` 發布 `User` 作為其唯一的規範值，並使用 `invalidValue` 拒絕命名群組的成員條目。任一方向都不支援嵌套組。

 Membership is stored on the user, so `members` is answered by a reverse lookup and a membership change is a write to each affected user. Adding or removing members therefore requires `sysAccountUpdate`, even when it accompanies a group creation. And reading a group with more than 200 members is refused with `tooMany`; request it with `?excludedAttributes=members` and read the membership from the `groups` attribute of the user resources instead.

 成員資訊儲存在用戶端，因此`members`請求透過反向查找來回應，成員變更會寫入每個受影響的用戶。因此，新增或刪除成員需要`sysAccountUpdate` ，即使同時建立群組也是如此。讀取成員超過 200 的群組會被`tooMany`拒絕；應使用`?excludedAttributes=members`請求，並從使用者資源的`groups`屬性中讀取成員資訊。

 The `members` entries are immutable in the SCIM sense: a member is added or removed, never edited in place. `display` is read-only and reflects the member account’s description.

`members` 條目在 SCIM 意義上是不可變的：新增或刪除成員，永遠不會就地進行編輯。 `display` 是唯讀的，反映會員帳號的描述。

## Replace compared with patch｜與補丁相比，替換

`PATCH` applies the operations it carries and leaves everything else alone. `PUT` replaces the resource, and attributes absent from the body revert to their defaults: aliases are cleared, the locale returns to `en-US`, the time zone is cleared, and `active` returns to `true`. A client that sends a partial resource by `PUT` will therefore erase attributes it never intended to touch.

`PATCH` 應用它所承載的操作，而忽略其他所有操作。 `PUT` 取代資源，正文中缺少的屬性恢復為預設值：別名被清除，區域設定返回到 `en-US`，時區被清除，`active` 返回到 `true`。因此，透過`PUT`發送部分資源的客戶端將刪除它從未打算觸及的屬性。

 The interoperability profile tells clients to use `PATCH`, and every current identity provider does. `PUT` is implemented for completeness and for scripted use, where the caller controls the whole body.

 互通性設定檔告訴客戶端使用`PATCH`，目前的每個身分提供者都這樣做。 `PUT` 的實作是為了完整性和腳本化使用，其中呼叫者控制整個主體。

## Settings that remain under local control｜仍由本地控制的設置

 Provisioning covers identity, not entitlement. Quotas, roles, permissions beyond `active`, mailbox layout, sieve scripts, encryption settings, and every other account setting remain under local control and are unaffected by synchronisation. An administrator can set a quota on a SCIM-provisioned account and it will survive every subsequent cycle.

 配置涵蓋身份，而非權限。配額、角色、 `active`以外的權限、郵箱佈局、篩選腳本、加密設定以及所有其他帳戶設定均由本地控制，不受同步影響。管理員可以為SCIM配置的帳戶設定配額，該配額在每個後續週期中都有效。

 New accounts are created with the standard user role and inherited permissions, which means the defaults configured on the server and, where applicable, on the tenant. Where SCIM-provisioned accounts need different defaults from locally created ones, express the difference through roles applied to the tenant or through the server defaults.

 新建立的帳戶將使用標準使用者角色和繼承的權限，這意味著使用伺服器上的預設配置，以及（如果適用）租用戶上的預設配置。如果透過SCIM配置的帳戶需要與本地建立的帳戶不同的預設設置，則可以透過套用於租用戶的 roles或透過伺服器預設設定來表達差異。

 Deleting a user through SCIM removes the account and schedules the destruction of its data, and revokes any shares other accounts held on it. It is not a suspension, and it is not reversible from the identity provider’s side.

 透過SCIM刪除使用者會移除該帳戶並安排銷毀其數據，同時撤銷其他帳戶在該帳戶下持有的所有共享權限。這並非帳戶暫停，且身分提供者無法撤銷此操作。
