# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[telemetry｜遙測\\\]\\\(&lt;000 目錄.md#c-76&gt;\\\) › \\\[metrics｜指標\\\]\\\(&lt;000 目錄.md#c-77&gt;\\\)

Metrics are quantitative measurements of the server’s operation, resource use, and workload. They let administrators see how the server behaves over time, spot trends, and react to anomalies. Metric collection in Stalwart is controlled by the Metrics singleton \(found in the WebUI under Settings › Telemetry › Metrics › General, Settings › Telemetry › Metrics › OpenTelemetry, Settings › Telemetry › Metrics › Prometheus\).

 指標是對伺服器運作、資源使用和工作負載的定量測量。它們使管理員能夠了解伺服器隨時間推移的運作情況，發現趨勢並對異常情況做出反應。 Stalwart 中的指標收集由 Metrics單例控制（可在 WebUI 的「設定」&gt;「遙測」&gt;「指標」&gt;「常規」、「設定」&gt;「遙測」&gt;「指標」&gt;「OpenTeltry」和「設定」&gt;「遙測」&gt;「遙測」&gt;「指標」&gt;「OpenTeltry」和「設定」&gt;「遙測」&gt;「遙測」&gt;「」指標指標」中找到）。

## Push and pull exporters｜推拉出口商

 Two export models are supported:

 支援兩種出口模式：

- Push: the server actively sends metric samples to a collection system at regular intervals. Push is simple to configure, and metrics arrive at the collector as they are produced.
推播：伺服器會定期主動傳送指標樣本給收集系統。推送配置簡單，指標會在產生後立即到達收集器。
- Pull: the collection system queries an HTTP endpoint on the server at a cadence it controls. Pull lets the collector manage the scraping load and is the model used by tools such as Prometheus.
拉取模式：資料擷取系統會依照其控制的頻率查詢伺服器上的HTTP端點。拉取模式允許採集器管理抓取負載，Prometheus 等工具也採用了這種模式。
## Supported backends｜支援的後端

 Stalwart supports both models through a single configuration surface:

 Stalwart 透過單一配置介面支援這兩種模型：

- OpenTelemetry is used for push. It is configured through openTelemetry on the `Metrics` singleton, which is a nested type with variants `Disabled`, `Http`, and `Grpc`.
OpenTelemetry用於推送。它透過 openTelemetry在`Metrics`單例上進行配置，這是一個嵌套類型，具有變體`Disabled`, `Http`和`Grpc` 。
- Prometheus is used for pull. It is configured through prometheus on the `Metrics` singleton, which is a nested type with variants `Disabled` and `Enabled`.
Prometheus用於拉取。它透過 prometheus在`Metrics`單例上進行配置，這是一個嵌套類型，具有變體`Disabled`和`Enabled` 。
Both exporters can be configured at the same time when two independent collectors need the same signal.
 當兩個獨立的擷取器需要相同的訊號時，可以同時配置兩個輸出器。

## Selecting metrics｜選擇指標

 The set of metrics exported is controlled by metrics and metricsPolicy on the `Metrics` singleton. metrics is a set in which each selected metric is a key mapped to `true`. With metricsPolicy set to `exclude` \(the default\), the selected metrics are suppressed and everything else is emitted; with `include`, only the selected metrics are emitted.

 導出的指標集由單例`Metrics`上的 metrics和 metricsPolicy控制。 metrics是一個集合，其中每個選定的指標都是一個映射到`true`鍵。當 metricsPolicy設定為`exclude` （預設值）時，選定的指標將被抑制，所有其他指標都會被匯出；當設定為`include`時，僅匯出選定的指標。

 For example, to suppress the noise of `auth.error` and `smtp.error` while leaving every other metric enabled:

 例如，要抑制`auth.error`和`smtp.error`的噪聲，同時保持其他所有指標啟用：

```json
{
  "metrics": {"auth.error": true, "smtp.error": true},
  "metricsPolicy": "exclude"
}
```
