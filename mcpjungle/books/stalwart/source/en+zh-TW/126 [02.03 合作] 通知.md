# Notifications｜通知

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[collaboration｜合作\\\]\\\(&lt;000 目錄.md#c-17&gt;\\\)

Calendar email notifications in Stalwart deliver alerts for upcoming events directly to an account’s email inbox. These notifications are triggered by alarms defined within calendar entries using the iCalendar standard.

 Stalwart 的日曆電子郵件通知功能可將即將發生的事件提醒直接傳送至帳戶的電子郵件收件匣。這些通知由日曆條目中定義的、符合 iCalendar 標準的提醒觸發。

 When a calendar event includes a `VALARM` component with the action type set to `EMAIL`, Stalwart processes the alarm and generates an email message to the account at the scheduled time. This provides reminders for upcoming meetings, deadlines, or other events without requiring a calendar application to be actively running.

 當日曆事件包含操作類型設定為`EMAIL` `VALARM`元件時，Stalwart 會處理提醒並在預定時間向帳戶發送電子郵件。這樣，無需日曆應用程式處於活動狀態，即可提醒使用者即將到來的會議、截止日期或其他事件。

 Email notifications include the details of the event, such as the summary, start time, location, and description, and are delivered to the email address associated with the calendar account. Delivery is automatic and follows the iCalendar specification.

 電子郵件通知包含事件詳情，例如摘要、開始時間、地點和描述，並傳送至與日曆帳戶關聯的電子郵件地址。發送過程自動進行，並遵循 iCalendar 規範。

## Client limitations｜客戶限制

 Most mainstream CalDAV clients do not support the `ACTION:EMAIL` alarm type. In many cases, alarms configured with this action are ignored entirely. Some clients, such as Apple Calendar, actively remove `VALARM` components that specify `ACTION:EMAIL`, preventing the alarm from ever reaching the server.

 大多數主流 CalDAV 用戶端不支援`ACTION:EMAIL`警報類型。在許多情況下，使用此操作配置的警報會被完全忽略。某些客戶端（例如 Apple Calendar）會主動移除指定`ACTION:EMAIL`的`VALARM`元件，從而阻止警報到達伺服器。

 To work around these limitations, Stalwart allows any alarm to be marked as an email notification even if the action type is something else \(for example, `DISPLAY`\). The marker is the literal string `@email` placed anywhere in the alarm’s summary or description fields.

 為了克服這些限制，Stalwart 允許將任何警報標記為電子郵件通知，即使操作類型是其他類型（例如， `DISPLAY` ）。標記是字串`@email`可以放置在警報的摘要或描述欄位中的任意位置。

 When Stalwart detects this marker, it treats the alarm as if it were configured with `ACTION:EMAIL` and sends the email notification regardless of the `ACTION` field. Users can therefore continue using their preferred calendar clients while still receiving timely email alerts for important events.

 當 Stalwart 偵測到此標記時，它會將警報視為已配置`ACTION:EMAIL` ，並發送電子郵件通知，而不管`ACTION`欄位的值如何。因此，使用者可以繼續使用他們常用的日曆用戶端，同時也能及時收到重要事件的電子郵件提醒。

## Enabling notifications｜啟用通知

 Calendar alarm email notifications are enabled by default. Configuration is carried on the CalendarAlarm singleton \(found in the WebUI under Settings › Calendar & Contacts › Alarms\). When an event includes a supported alarm \(either a standard `VALARM` with `ACTION:EMAIL` or one marked with the `@email` hint\), Stalwart automatically delivers the corresponding notification.

 日曆鬧鐘郵件通知預設為啟用。配置在 CalendarAlarm單例中（可在 WebUI 的「設定」&gt;「日曆與聯絡人」&gt;「鬧鐘」中找到）。當事件包含支援的鬧鐘（標準鬧鐘`VALARM`帶有`ACTION:EMAIL` ，或帶有`@email`提示的鬧鐘）時，Stalwart 會自動發送相應的通知。

 Global disabling is achieved by setting enable to `false`. With that field disabled, Stalwart ignores all email alarms regardless of their configuration or presence in the calendar data.

 全域禁用可透過將 enable設為`false`來實現。停用該欄位後，Stalwart 將忽略所有電子郵件警報，無論其配置如何或是否存在於日曆資料中。

 For finer control, email notifications can also be disabled on a per-account basis through permissions. Revoking the appropriate permission selectively prevents individual accounts from receiving alarm-triggered emails while leaving the feature enabled for others.

 為了更精細地控制，也可以透過 權限逐一帳戶停用電子郵件通知。撤銷對應的權限可以選擇性地阻止特定帳戶接收警報觸發的電子郵件，同時保持其他帳戶的此功能啟用狀態。

## Limits｜限制

### Notification interval｜通知間隔

 minTriggerInterval specifies the shortest duration allowed between consecutive email notifications for a single account, expressed in milliseconds. The default is `3600000` \(one hour\), meaning no more than one email alarm is sent per account within a one-hour window even if multiple alarms trigger in quick succession. This guards against excessive notification volume caused by misconfigured or malicious calendar entries.

 minTriggerInterval指定單一帳戶連續電子郵件通知之間的最短間隔時間，以毫秒為單位。預設值為`3600000` （一小時），這表示即使多個警報在短時間內連續觸發，每個帳戶在一小時內也最多只會發送一封電子郵件警報。這可以防止因配置錯誤或惡意日曆條目而導致通知量​​過大。

### External recipients｜外部接收方

 By default, Stalwart restricts email alarm delivery to an account’s registered email addresses so that notifications go only to trusted destinations. allowExternalRcpts controls this policy; setting it to `true` permits alarms that deliver notifications to arbitrary email addresses, including those outside the organisation. This can be useful for shared calendars or external participants, but should be enabled with care where tighter control over outbound communication is required.

 預設情況下，Stalwart 會將電子郵件警報的發送限制在帳戶註冊的電子郵件地址，以確保通知僅發送到受信任的目的地。 allowExternalRcpts控制此策略；將其設為`true`允許警報向任意電子郵件地址發送通知，包括組織外部的地址。這對於共享日曆或外部參與者非常有用，但在需要更嚴格控制對外通訊的情況下，應謹慎啟用此功能。

 A representative CalendarAlarm configuration:

 一個典型的 CalendarAlarm 設定範例：

```json
{
  "enable": true,
  "minTriggerInterval": 3600000,
  "allowExternalRcpts": false
}
```

## Sender details｜寄件者詳情

 The sender information used in calendar alarm emails is configurable on the CalendarAlarm singleton. By default, notification emails are sent with the From name set to `"Stalwart Calendar"` and the From address generated as `calendar-notification@<user_domain>`, where `<user_domain>` corresponds to the domain of the account receiving the notification.

 日曆提醒郵件中使用的寄件者資訊可在 CalendarAlarm 單例中設定。預設情況下，通知郵件的「寄件者」名稱設定為`"Stalwart Calendar"` ，「寄件者」地址產生為`calendar-notification@<user_domain>` ，其中`<user_domain>`對應於接收通知的帳戶的網域名稱。

 The display name used in the From field is set through fromName and the sender address is set through fromEmail. A representative override:

 「寄件人」欄位中使用的顯示名稱透過 fromName設置，寄件人地址透過 fromEmail設定。以下是一個範例覆蓋：

```json
{
  "fromName": "My Organization Calendar",
  "fromEmail": "[email protected]"
}
```

## Branding and templating｜品牌和模板

 Stalwart supports custom branding and templating for calendar alarm notifications so that the visual appearance and content of email alerts can be aligned with organisational branding.

 Stalwart 支援日曆提醒通知的自訂品牌和模板，以便電子郵件提醒的視覺外觀和內容可以與組織品牌保持一致。

 This feature is available exclusively in the Enterprise Edition of Stalwart and not included in the Community Edition.

 此功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

### Template｜範本

 Stalwart ships with a built-in default HTML template for alarm email notifications. The template can be overridden by setting template on the CalendarAlarm singleton to a custom HTML string. The template is written in standard HTML and supports dynamic placeholders for event-specific information \(event summary, time, location, alarm details\), styles, logos, and layout adjustments.

 Stalwart 內建了一個預設的HTML模板，用於發送鬧鐘郵件通知。您可以透過將 CalendarAlarm 單例中的 template設定為自訂HTML字串來覆寫此範本。此範本採用標準HTML編寫，並支援動態佔位符，用於設定事件特定資訊（事件摘要、時間、地點、鬧鐘詳情）、樣式、標誌和佈局調整。

### Logo｜標識

 The alarm email template includes a logo, which by default is the system-wide branding logo configured for the server. The logo can be overridden per tenant or per domain so that different user groups, business units, or hosted domains display their own logo in alarm emails. For details, refer to the Branding section.

 警告郵件範本包含一個徽標，預設情況下使用的是伺服器配置的系統級品牌徽標。您可以按租戶或網域覆蓋此徽標，以便不同的使用者群組、業務部門或託管網域在警告郵件中顯示各自的徽標。有關詳細信息，請參閱 品牌部分。
