# FoundationDB

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[storage｜貯存\\\]\\\(&lt;000 目錄.md#c-72&gt;\\\) › \\\[backends｜後端\\\]\\\(&lt;000 目錄.md#c-73&gt;\\\)

FoundationDB is a distributed database designed to handle large volumes of data across multiple machines. It combines ACID transactions with the scalability of NoSQL systems, providing high performance, fault tolerance, and straightforward horizontal scaling. It is the recommended backend for distributed deployments of Stalwart.

 FoundationDB 是一款分散式資料庫，旨在處理跨多台機器的大量資料。它結合了ACID事務和 NoSQL 系統的可擴展性，提供高效能、容錯性和便利的水平擴展。它是 Stalwart 分散式部署的建議後端。

 The FoundationDB client library must be installed on the host before Stalwart can connect to a FoundationDB cluster.

 在 Stalwart 能夠連線到 FoundationDB 叢集之前，必須在主機上安裝 FoundationDB 用戶端程式庫。

## Configuration｜配置

 The FoundationDB backend is selected by choosing the `FoundationDb` variant on the DataStore object \(found in the WebUI under Settings › Storage › Data Store\). The variant exposes the following fields:

 若要選擇 FoundationDB 後端，請在 DataStore物件上選擇`FoundationDb`變體（可在 WebUI 的「設定」&gt;「儲存」&gt;「資料儲存」中找到）。該變體公開以下欄位：

- clusterFile: filesystem path to the FoundationDB cluster configuration file. If unset, the default `/etc/foundationdb/fdb.cluster` is used.
clusterFile : FoundationDB 叢集設定檔的檔案系統路徑。如果未設置，則使用預設值`/etc/foundationdb/fdb.cluster` 。
- transactionTimeout: duration after which a transaction times out if not completed.
transactionTimeout : 若交易未完成，則逾時的時間。
- transactionRetryLimit: maximum number of transaction retries before giving up.
transactionRetryLimit : 放棄前的最大交易重試次數。
- transactionRetryDelay: maximum delay between transaction retries.
transactionRetryDelay : 交易重試之間的最大延遲。
- machineId: optional identifier for the machine, useful for logging and cluster-aware behaviour.
machineId : 機器的可選標識符，用於日誌記錄和集群感知行為。
- datacenterId: optional identifier for the data centre hosting the machine, used when tuning cross-datacentre replication.
datacenterId : 託管機器的資料中心的選用標識符，用於調整跨資料中心複製。
FoundationDB is also available as a backend for the blob store, search store, and in-memory store; the same set of cluster-file and transaction fields is exposed on each of those objects under the `FoundationDb` variant.
 FoundationDB 也可用作 blob 儲存、搜尋儲存和記憶體儲存的後端；在`FoundationDb`變體下，每個物件都公開了相同的叢集檔案和事務欄位集。
