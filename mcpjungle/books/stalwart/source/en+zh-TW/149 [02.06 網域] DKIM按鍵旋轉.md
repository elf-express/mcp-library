# DKIM key rotation｜DKIM按鍵旋轉

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[domains｜網域\\\]\\\(&lt;000 目錄.md#c-21&gt;\\\)

Periodic DKIM key rotation limits the impact of key compromise and is a recommended operational practice for any mail domain that signs outbound messages. When rotation is enabled, the server takes over the full lifecycle of DKIM keys for a domain: generating new keys on schedule, publishing them in DNS ahead of use, switching signing over to the new key, and retiring old keys once they are no longer required for verification of in-flight messages.

 定期輪換金鑰DKIM可以降低金鑰洩漏的影響，是所有對出站郵件進行簽署的郵件域建議的操作規範。啟用輪換後，伺服器將接管網域金鑰的完整生命週期DKIM ）：按計畫產生新金鑰，在使用前將其發佈到DNS中，切換到新金鑰進行簽名，並在舊金鑰不再用於驗證傳輸中的郵件時將其停用。

 Signing of outgoing messages and verification of incoming signatures are not covered on this page. For signing configuration and behaviour see DKIM signing; for verification of inbound messages see DKIM verification. The Domain object owns only the rotation side of the lifecycle described below.

 本頁不涉及外發訊息的簽名和入站簽名的驗證。有關簽名配置和行為，請參閱 DKIM簽名 ；有關入站訊息的驗證，請參閱 DKIM驗證 。域物件僅擁有下文所述生命週期中的輪換部分。

## Enabling automatic rotation｜啟用自動旋轉

 Rotation is controlled by the dkimManagement field on the Domain object. The `Manual` variant leaves DkimSignature \(found in the WebUI under Management › Domains › DKIM Signatures\) objects under the operator’s direct control; new keys are not generated and DNS publication is handled as part of manual DNS management. The `Automatic` variant carries the rotation schedule:

 旋轉由 Domain 物件上的 dkimManagement 欄位控制。 `Manual` 變體將 DkimSignature（可在 WebUI 的「管理」&gt;「網域」&gt;「DKIM 簽章」下找到）物件置於操作員的直接控制之下；不會產生新金鑰，並且 DNS 發布作為手動 DNS 管理的一部分進行處理。 `Automatic` 變體有輪換時間表：

- algorithms lists the signing algorithms to use when generating new keys. The default provisions both `Dkim1Ed25519Sha256` and `Dkim1RsaSha256`, so receiving verifiers that do not yet support Ed25519 still find an RSA key.
algorithms列出了產生新金鑰時要使用的簽章演算法。預設同時提供`Dkim1Ed25519Sha256`和`Dkim1RsaSha256` ，因此即使接收驗證器尚不支援 Ed25519，仍然可以找到RSA金鑰。
- selectorTemplate produces the DNS selector for each new key. The template supports `{algorithm}`, `{hash}`, `{version}`, `{date-<fmt>}` \(with strftime specifiers\), `{epoch}`, and `{random}`; the default `v{version}-{algorithm}-{date-%Y%m%d}` yields selectors such as `v1-ed25519-20260101`.
selectorTemplate為每個新鍵產生DNS選擇器。此範本支援`{algorithm}`, `{hash}`, `{version}`, `{date-<fmt>}` （帶 strftime 說明符）、 `{epoch}`和`{random}` ；預設的`v{version}-{algorithm}-{date-%Y%m%d}`會產生諸如`v1-ed25519-20260101`之類的選擇器。
- rotateAfter sets how often a fresh key is generated, defaulting to `90d`.
rotateAfter設定產生新金鑰的頻率，預設值為`90d` 。
- retireAfter sets how long the superseded key’s DNS record remains published after the cutover, defaulting to `7d`.
retireAfter設定被取代金鑰的DNS記錄在切換後保持發布狀態的時間，預設值為`7d` 。
- deleteAfter sets how long the retired key’s material is retained on the server before permanent deletion, defaulting to `30d`.
deleteAfter設定已退役金鑰的材料在永久刪除之前在伺服器上保留多長時間，預設值為`30d` 。
Automatic rotation requires the Domain to have automatic DNS management enabled, since the rotation logic both writes and later removes DKIM DNS records. See DNS records for the DNS-side setup.
 自動輪換要求域啟用自動DNS管理，因為輪換邏輯既會寫入DKIM DNS記錄，也會在之後刪除這些記錄。有關DNS端的設置，請參閱DNS記錄 。

## Rotation lifecycle｜旋轉生命週期

 Each DkimSignature carries a stage field that tracks its position in the rotation lifecycle, together with a nextTransitionAt timestamp indicating when the next transition is due. The four stages are:

 每個 DkimSignature都包含一個 stage字段，用於追蹤其在輪換生命週期中的位置，以及一個 nextTransitionAt時間，用於指示下一次轉換的時間戳。這四個階段是：

- **pending**: the key has been generated and is scheduled for DNS publication, but is not yet visible to remote verifiers. Signing continues with the current active key.
**待處理**：金鑰已產生並已安排發佈到DNS ，但遠端驗證者尚無法查看。簽名將繼續使用目前活動金鑰。
- **active**: the key is published in DNS and is used to sign outgoing messages. For each algorithm in algorithms, at most one signature is active at a time.
**啟動狀態**：金鑰已發佈在DNS中，並用於簽署外發訊息。對於 algorithms中的每個演算法，同一時間最多只有一個簽名處於啟動狀態。
- **retiring**: a newer key has taken over signing, but the DNS record for this key remains published so that messages signed before the cutover still verify. The retiring key no longer signs new messages.
**已停用**：新金鑰已接管簽署工作，但此金鑰的DNS記錄仍保持發布狀態，因此切換前簽署的訊息仍然有效。停用的金鑰不再對新訊息進行簽署。
- **retired**: the DNS record has been removed. The key material is still retained on the server for diagnostic purposes until it is permanently deleted.
**已停用**： DNS記錄已移除。密鑰材料仍保留在伺服器上用於診斷目的，直到永久刪除。
## Cutover sequence｜切換序列

 When the server determines that a rotation is due for a given algorithm, the sequence is:

 當伺服器確定某個演算法需要輪換時，輪換順序如下：

1. A new DkimSignature is created in the **pending** stage and the corresponding public key is pushed to the DnsServer as part of the domain’s managed records.
在**待處理**階段，會建立一個新的 DkimSignature，並將對應的公鑰作為網域的託管記錄的一部分推送到 DnsServer。
2. The DnsServer polls until propagation of the new selector is confirmed; the transition from **pending**to**active**is driven by that confirmation, not by a fixed wall-clock delay. Once propagation is observed, the new key transitions to**active**and the previous active key transitions to**retiring**. Signing switches to the new selector at this point.
DNS 伺服器會持續輪詢，直到確認新選擇器的傳播；狀態從**待定**到**啟動**的轉換由該確認驅動，而非由固定的時間延遲驅動。一旦觀察到傳播，新金鑰將變為**啟動**狀態，而先前啟動的金鑰將變為**停用**狀態。此時，簽章操作將切換到新的選擇器。
3. After retireAfter elapses, the retiring key transitions to **retired** and the DNS record for its selector is removed.
在 retireAfter結束後，退役鍵的狀態變為 **已退役**，並且其選擇器的DNS記錄被刪除。
4. After deleteAfter further elapses, the retired DkimSignature is deleted from the store.
在 deleteAfter進一步過去之後，已棄用的 DkimSignature 將從儲存中刪除。
The schedule for the next rotation is rearmed from rotateAfter relative to the activation of the new key.
 下一次輪換的計畫根據新金鑰的啟動情況，從 rotateAfter重新制定。

## Triggering a rotation manually｜手動觸發旋轉

 Rotation runs automatically on the schedule above, but it can also be driven on demand. Rotation is performed by the DKIM management task, which is the `DkimManagement` variant of the Task object. Triggering the task for a domain evaluates the current keys against the configured schedule and advances any transition that is due \(generation, cutover, retirement, and deletion\).

 輪換會按照上述計劃自動運行，但也可以按需執行。輪換由管理任務DKIM執行，該任務是 Task物件的`DkimManagement`變體。觸發域的任務會根據配置的計劃評估目前鍵，並推進任何到期的轉換（產生、切換、退役和刪除）。

 Running the task on its own does not force a fresh key to be generated before rotateAfter has elapsed. To force an emergency rotation \(for example, when a key is suspected to be compromised\), first set nextTransitionAt on the DkimSignature to the current time, then trigger the `DkimManagement` task. On that run the task sees that a rotation is due and generates the replacement key immediately.

 單獨執行此任務並不會強制在 rotateAfter時間到期前產生新金鑰。要強制執行緊急輪調（例如，當懷疑金鑰已洩漏時），首先將 DkimSignature 的 nextTransitionAt時間設定為當前時間，然後觸發`DkimManagement`任務。在該次運行中，任務會偵測到需要輪換，並立即產生替換金鑰。
