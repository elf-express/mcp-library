# Caddy｜球童

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[server｜伺服器\\\]\\\(&lt;000 目錄.md#c-62&gt;\\\) › \\\[reverse proxy｜反向代理\\\]\\\(&lt;000 目錄.md#c-64&gt;\\\)

[Caddy](https://caddyserver.com/) is an open-source, HTTP/2-enabled web server with automatic HTTPS. It covers static file serving, simple reverse proxies, and TLS management out of the box, and is often chosen for the conciseness of its Caddyfile syntax.

[Caddy](https://caddyserver.com/)是一個開源的、 HTTP /2 啟用的 Web 伺服器，具有自動HTTPS功能。它涵蓋靜態檔案服務、簡單的反向代理和TLS開箱即用的管理，並且由於其 Caddyfile 語法的簡潔性而經常被選擇。

 Stalwart can sit behind Caddy for HTTP traffic. Caddy handles HTTPS termination and certificate management, then forwards requests to Stalwart.

 Stalwart 可以作為 Caddy 的後備伺服器處理HTTP流量。 Caddy 處理HTTPS終止和憑證管理，然後將請求轉發給 Stalwart。

 The example below forwards to Stalwart’s HTTPS listener with Proxy Protocol v2, but a plain HTTP-upstream pattern \(Caddy forwarding plain HTTP to Stalwart’s port `8080`\) works equally well and produces the same OAuth, OIDC, and JMAP discovery responses. See How discovery URLs are composed for the model that drives those responses, and set the STALWART\_PUBLIC\_URL variable to the URL clients reach Caddy on whenever it differs from `https://<defaultHostname>` on port `443`.

 以下範例使用代理協定 v2 將請求轉送至JMAP的HTTPS監聽器，但普通的HTTP上游模式（Caddy 將普通的HTTP轉送到 Stalwart 的連接埠`8080` ）同樣有效，並產生相同的 33、 OIDC有關驅動這些回應的模型，請參閱 如何組成發現 URL ，並將 STALWART\_PUBLIC\_URL變數設定為客戶端在連接埠`443`上與`https://<defaultHostname>`不同的時連接到 Caddy 的URL 。

## Note on Layer 4 support｜關於第 4 層支援的說明

 Caddy does not natively forward raw TCP streams, so it cannot forward the mail ports \(SMTP, IMAP, POP3, ManageSieve\) or preserve the Proxy Protocol on them. To carry client IPs into Stalwart’s mail listeners, either put HAProxy or NGINX in front of Caddy, or build a Caddy binary that includes the community-maintained `caddy-l4` plugin. The plugin adds layer-4 forwarding and Proxy Protocol emission to Caddy.

 Caddy 本身並不會直接轉送原始的TCP流，因此它無法轉送郵件埠（ SMTP, IMAP, POP3 、ManageSieve）或保留其上的 代理協定 。要將客戶端 IP 傳遞到 Stalwart 的郵件監聽器，可以在 Caddy 前面新增 HAProxy或 NGINX ，或建立一個包含社群維護的`caddy-l4`製插件的 Caddy 二進位外掛程式檔案。該插件為 Caddy 添加了四層轉發和代理協議發射功能。

 For example, using `xcaddy`:

 例如，使用`xcaddy` ：

```
xcaddy build --with github.com/mholt/caddy-l4/modules/l4proxy \
    --with github.com/mholt/caddy-l4/modules/l4tls \
    --with github.com/mholt/caddy-l4/modules/l4proxyprotocol
```

## Configuration｜配置

 The following Caddyfile forwards the mail ports \(25, 465, 993, 4190\) using `caddy-l4` with Proxy Protocol v2 and reverse-proxies HTTPS for `mail.example.com`:

 以下 Caddyfile 使用`caddy-l4`和代理協定 v2 轉送郵件連接埠 \(25, 465, 993, 4190\)，並使用反向代理HTTPS為`mail.example.com`進行轉送：

```
{
    layer4 {
        0.0.0.0:25 {
            route {
                proxy {
                    proxy_protocol v2
                    upstream 127.0.0.1:10025
                }
            }
        }

        0.0.0.0:993 {
            route {
                proxy {
                    proxy_protocol v2
                    upstream 127.0.0.1:10993
                }
            }
        }

        0.0.0.0:465 {
            route {
                proxy {
                    proxy_protocol v2
                    upstream 127.0.0.1:10465
                }
            }
        }

        0.0.0.0:4190 {
            route {
                proxy {
                    proxy_protocol v2
                    upstream 127.0.0.1:14190
                }
            }
        }
    }
}

example.com {
    redir https://www.example.com{uri}
}

www.example.com {
    root * /var/www/imkerei

    file_server
}

mail.example.com {
    reverse_proxy https://127.0.0.1:10443 {
        transport http {
            proxy_protocol v2
            tls_server_name mail.example.com
        }
    }
}
```

## Certificate management｜證書管理

### Crontab｜克朗塔布

 Automate copying Caddy-issued certificates into Stalwart’s certificate directory from cron:

 透過 cron 自動將 Caddy 頒發的憑證複製到 Stalwart 的憑證目錄：

```bash title=&amp;quot;Terminal window&amp;quot;
0 3 * * * cat /var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/example.com/example.com.crt > /opt/stalwart/cert/example.com.pem
0 3 * * * cat /var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/example.com/example.com.key > /opt/stalwart/cert/example.com.priv.pem
```

### Systemd

 As an alternative to cron, a systemd path unit can watch the Caddy certificate file, copy the renewed files into place, and trigger a hot reload on Stalwart:

 除了 cron 之外，systemd 路徑單元還可以監視 Caddy 證書文件，將更新的文件複製到相應位置，並觸發 Stalwart 的熱重載：

*stalwart.path:*

```
[Unit]
Description=import certs from caddy to stalwart

[Path]
PathModified=/var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/mail.example.com/mail.example.com.crt

[Install]
WantedBy=multi-user.target
```

*stalwart.service:*

```
[Unit]
Description=imports certs from caddy to stalwart

[Service]
Type=oneshot
ExecStart=/usr/bin/cp -f /var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/mail.example.com/mail.example.com.pem /opt/stalwart/cert/
ExecStart=/usr/bin/cp -f /var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/mail.example.com/mail.example.com.priv.pem /opt/stalwart/cert/
ExecStart=/usr/local/bin/stalwart-cli --url https://mail.example.com --api-key <TOKEN> create action/ReloadTlsCertificates

[Install]
WantedBy=multi-user.target
```

## Stalwart configuration｜堅固的配置

 Create a Certificate object \(found in the WebUI under Settings › TLS › Certificates\) pointing at the copied certificate and private-key files, and reference it from defaultCertificateId on the SystemSettings singleton \(found in the WebUI under Settings › Network › Services, Settings › Network › General\) so that it is presented when clients do not send SNI. The Certificate fields look like:

 建立證書 物件（可在 WebUI 的「設定」下找到 › TLS › 憑證）指向複製的憑證和私鑰文件，並從 引用它defaultCertificateId 在 系統設定 單例模式（可在 WebUI 的「設定」&gt;「網路」&gt;「服務」和「設定」&gt;「網路」&gt;「一般」中找到），以便在用戶端不傳送資料時顯示。 SNI證書欄位如下所示：

```json
{
  "certificate": {
    "@type": "File",
    "filePath": "/opt/stalwart/cert/example.com.pem"
  },
  "privateKey": {
    "@type": "File",
    "filePath": "/opt/stalwart/cert/example.com.priv.pem"
  }
}
```
