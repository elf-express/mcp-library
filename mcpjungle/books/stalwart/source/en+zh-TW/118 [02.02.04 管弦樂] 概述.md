# Overview｜概述

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[orchestration｜管弦樂\\\]\\\(&lt;000 目錄.md#c-16&gt;\\\)

Orchestration refers to the automated management of service lifecycles in a distributed system: deploying, scaling, monitoring, and recovering application instances. In contrast to coordination, which concerns how nodes within a cluster communicate and stay in sync, orchestration handles the infrastructure-level automation that keeps those nodes running, healthy, and responsive under dynamic conditions.

 編排是指分散式系統中服務生命週期的自動化管理，包括應用程式實例的部署、擴展、監控和復原。與協調（關注叢集內節點如何通訊和保持同步\([https://stalw.art/docs/cluster/coordination/\)不同，編排處理的是基礎設施層面的自動化，以確保這些節點在動態條件下持續運作、保持健康並具有回應能力。](https://stalw.art/docs/cluster/coordination/%2529%2525E4%2525B8%25258D%2525E5%252590%25258C%2525EF%2525BC%25258C%2525E7%2525B7%2525A8%2525E6%25258E%252592%2525E8%252599%252595%2525E7%252590%252586%2525E7%25259A%252584%2525E6%252598%2525AF%2525E5%25259F%2525BA%2525E7%2525A4%25258E%2525E8%2525A8%2525AD%2525E6%252596%2525BD%2525E5%2525B1%2525A4%2525E9%25259D%2525A2%2525E7%25259A%252584%2525E8%252587%2525AA%2525E5%25258B%252595%2525E5%25258C%252596%2525EF%2525BC%25258C%2525E4%2525BB%2525A5%2525E7%2525A2%2525BA%2525E4%2525BF%25259D%2525E9%252580%252599%2525E4%2525BA%25259B%2525E7%2525AF%252580%2525E9%2525BB%25259E%2525E5%25259C%2525A8%2525E5%25258B%252595%2525E6%252585%25258B%2525E6%2525A2%25259D%2525E4%2525BB%2525B6%2525E4%2525B8%25258B%2525E6%25258C%252581%2525E7%2525BA%25258C%2525E9%252581%25258B%2525E4%2525BD%25259C%2525E3%252580%252581%2525E4%2525BF%25259D%2525E6%25258C%252581%2525E5%252581%2525A5%2525E5%2525BA%2525B7%2525E4%2525B8%2525A6%2525E5%252585%2525B7%2525E6%25259C%252589%2525E5%25259B%25259E%2525E6%252587%252589%2525E8%252583%2525BD%2525E5%25258A%25259B%2525E3%252580%252582)

 While coordination allows Stalwart nodes to exchange internal updates and work together as a unified system, orchestration schedules them, restarts them when they fail, and scales them according to demand. It maintains operational continuity and elasticity in changing environments.

 協調機制使 Stalwart 節點能夠交換內部更新並作為一個統一的系統協同工作，而編排機制則負責調度這些節點、在發生故障時重啟它們，並根據需求進行擴展。它確保了在不斷變化的環境中運作的連續性和彈性。

 Stalwart runs on a variety of orchestration platforms, including Kubernetes, Apache Mesos, Docker Swarm, and Consul. These platforms each provide mechanisms for automating deployment, service discovery, health monitoring, and high availability across clusters.

 Stalwart 可在多種編排平台上運行，包括 Kubernetes、Apache Mesos、Docker Swarm 和 Consul。這些平台各自提供自動化部署、服務發現、健康監控和跨叢集高可用性的機制。

- Kubernetes: a container orchestration system that automates the deployment and scaling of containerised applications across clusters of machines.
Kubernetes : 一個容器編排系統，可自動在機器叢集中部署和擴充容器化應用程式。
- Apache Mesos: a distributed systems kernel that abstracts CPU, memory, storage, and other resources, allowing applications such as Stalwart to be run in an elastic environment.
Apache Mesos : 一個分散式系統內核，它抽象化了CPU記憶體、儲存和其他資源，允許 Stalwart 等應用程式在彈性環境中運行。
- Docker Swarm: native clustering for Docker containers, offering orchestration while preserving the Docker CLI experience.
Docker Swarm ：Docker 容器的原生集群，提供編排功能，同時保留 Docker CLI體驗。
Supporting these platforms gives administrators flexibility in how clusters are deployed and managed, so the orchestration tooling can match the operational model already in use.
 支援這些平台可以讓管理員靈活地部署和管理集群，從而使編排工具能夠與已在使用的操作模型相匹配。
