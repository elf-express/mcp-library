# Webhooks｜網路鉤子

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[telemetry｜遙測\\\]\\\(&lt;000 目錄.md#c-76&gt;\\\)

Webhooks deliver real-time notifications about server events by posting to an HTTP endpoint of the operator’s choice. They let external systems react to activity in the server without polling; typical uses include recording deliveries into an analytics pipeline, flagging authentication anomalies to a SIEM, or triggering automated workflows on message ingestion.

 Webhook 透過向營運商選擇的HTTP端點發布訊息，即時通知伺服器事件。它們允許外部系統無需輪詢即可對伺服器中的活動做出反應；典型用途包括將訊息傳遞記錄到分析管道中、將身份驗證異常標記到SIEM或在收到訊息時觸發自動化工作流程。

## Configuration｜配置

 Each webhook is represented by a WebHook object \(found in the WebUI under Settings › Telemetry › Webhooks\). Relevant fields are:

 每個 Webhook 都由一個 WebHook物件表示（可在 WebUI 的「設定」&gt;「遙測」&gt;「Webhook」中找到）。相關欄位包括：

- url: endpoint to which `POST` requests are sent.
url : 發送`POST`請求的端點。
- events and eventsPolicy: set of events and how to interpret it. Each selected event is a key mapped to `true`. With `eventsPolicy` set to `include`, only the selected events trigger the webhook; with `exclude`, all events except the selected ones trigger it. Event identifiers are documented on the Events page.
events 和 eventsPolicy：一组事件以及如何解释它。每个选定的事件都是映射到`true`的键。當`eventsPolicy`設定為`include`時，只有選定的事件才會觸發webhook；使用`exclude`，除了選定的事件之外的所有事件都會觸發它。事件标识符记录在事件页面上。
- timeout: maximum time to wait for a response, in milliseconds. Default `30000` \(30 seconds\).
timeout : 等待回應的最長時間，以毫秒為單位。預設值為`30000` \(30 秒\)。
- throttle: minimum interval between batches, in milliseconds. Events that fall within the same window are grouped. Default `1000` \(one second\).
throttle : 批次之間的最小間隔，以毫秒為單位。落在同一視窗內的事件將被分組。預設值為`1000` （一秒）。
- discardAfter: time in milliseconds after which an undelivered webhook request is discarded. Default `300000` \(five minutes\).
discardAfter : 未送達的 webhook 請求被丟棄的時間（以毫秒為單位）。預設值為`300000` （五分鐘）。
- signatureKey: optional HMAC key used to sign each request body. The signature is base64-encoded and carried in the `X-Signature` header. The field is a `SecretKeyOptional` with variants `None`, `Value`, `EnvironmentVariable`, and `File`.
signatureKey : 可選的HMAC金鑰，用於對每個請求體進行簽章。簽章採用 base64 編碼，並包含在`X-Signature`標頭中。該字段為`SecretKeyOptional` ，其變體為`None`, `Value`, `EnvironmentVariable`和`File` 。
- httpAuth: HTTP authentication used by the request. A nested type with variants `Unauthenticated`, `Basic`, and `Bearer`.
httpAuth: HTTP請求使用的驗證。嵌套類型，具有變體`Unauthenticated`, `Basic`和`Bearer` 。
- httpHeaders: additional HTTP headers to include on each request.
httpHeaders : 附加的HTTP標頭，用於在每個請求中包含。
- allowInvalidCerts: whether to permit requests to endpoints with an invalid TLS certificate. Default `false`.
allowInvalidCerts : 是否允許向具有無效憑證的端點發出請求。 TLS預設值為`false` 。
- lossy: whether to drop events when the endpoint is unreachable or persistently failing. When `false`, events accumulate until delivery succeeds or discardAfter elapses.
lossy : 端點不可達或持續失敗時是否丟棄事件。當`false` ，事件會累積，直到傳遞成功或 discardAfter到期為止。
- enable: whether the webhook is active.
enable : webhook 是否處於活動狀態。
- level: minimum severity of events delivered to this endpoint.
level : 傳遞到此端點的事件的最低嚴重程度。
## API documentation｜API文檔

### Response object｜回應對象

 The main object in the webhook response is `WebhookEvents`, which contains a list of `WebhookEvent` objects:

 webhook 回應中的主要物件是`WebhookEvents` ，其中包含`WebhookEvent`物件的清單：

```json
{
    "events": [
        {
            "id": "12345",
            "createdAt": "2023-06-21T14:55:00Z",
            "type": "auth.success",
            "data": {}
        }
    ]
}
```

Each `WebhookEvent` contains the following fields:

 每個`WebhookEvent`包含以下欄位：

- `id` \(String\): Unique identifier for the event.
`id` （字串）：事件的唯一識別碼。
- `createdAt` \(RFC3339 timestamp\): Timestamp when the event was created.
`createdAt` \( RFC3339時間戳\): 事件建立時的時間戳。
- `type` \(WebhookType\): Type of the event.
`type` （Webhook型）：事件的型別 。
- `data` \(WebhookPayload\): Detailed data associated with the event.
`data` （WebhookPayload）：與事件相關的詳細資料。
### Data payload｜數據有效載荷

 The `data` payload is a nested object that contains additional information about the event. The structure of the `data` object varies depending on the event type and it may contain any of the supported keys.

`data` 有效负载是一个嵌套对象，其中包含有关事件的附加信息。 `data` 对象的结构因事件类型而异，并且它可能包含任何受支持的 keys。

## Example｜例子

 The equivalent of a webhook firing on `auth.success` and `store.ingest`, signed with a shared secret, with a custom header and Basic authentication:

 相當於在`auth.success`和`store.ingest`上觸發 webhook，使用共享金鑰簽名，帶有自訂標頭和基本身份驗證：

```json
{
  "url": "https://example.com/webhook",
  "events": {"auth.success": true, "store.ingest": true},
  "eventsPolicy": "include",
  "timeout": 30000,
  "throttle": 1000,
  "signatureKey": {"@type": "Value", "secret": "my-secret-key"},
  "httpHeaders": {"X-My-Header": "my-value"},
  "httpAuth": {
    "@type": "Basic",
    "username": "account",
    "secret": {"@type": "Value", "secret": "password"}
  },
  "allowInvalidCerts": false,
  "enable": true
}
```

Each key in events selects a single event from the EventType enum; wildcard patterns are not supported, so every event to be delivered must be listed explicitly.

 events中的每個鍵都從 EventType 枚舉中選擇一個事件；不支援通配符模式，因此要傳遞的每個事件都必須明確列出。
