# Apache Kafka Redpanda

## Apache Kafka / Redpanda

 Apache Kafka is a distributed event streaming platform for publishing, subscribing to, storing, and processing large volumes of real-time data. It is widely used in distributed systems to provide reliable communication between services, particularly where durability, scalability, and fault tolerance are critical.

 Apache Kafka 是一個分散式事件流平台，用於發布、訂閱、儲存和處理大量即時資料。它廣泛應用於分散式系統中，為服務之間提供可靠的通信，尤其適用於持久性、可擴展性和容錯性至關重要的場景。

 Redpanda is a Kafka-compatible streaming data platform that acts as a drop-in replacement for Kafka, offering similar semantics and APIs with lower latency and simpler operations. It is written in C++ and removes Kafka’s JVM-based dependencies such as ZooKeeper.

 Redpanda 是一個與 Kafka 相容的串流資料平台，可作為 Kafka 的直接替代方案，提供類似的語義和 API，同時延遲更低，操作更簡單。它使用 C++ 編寫，並移除了 Kafka 基於JVM的依賴項，例如 ZooKeeper。

 When used as a coordination backend in a Stalwart cluster, Kafka or Redpanda acts as the message bus for distributing internal updates between nodes. These updates include mailbox changes for IMAP IDLE, push notification events, IP blocking alerts, TLS certificate distribution, and more. By publishing and subscribing to coordination topics, each Stalwart node stays synchronised with the rest of the cluster.

 在 Stalwart 叢集中，Kafka 或 Redpanda 用作協調後端，充當訊息匯流排，用於在節點間分發內部更新。這些更新包括郵箱變更IMAP IDLE 、推播通知事件、阻塞警報IP 、憑證分發TLS等等。透過發布和訂閱協調主題，每個 Stalwart 節點都能與叢集中的其他節點保持同步。

 Using Kafka or Redpanda provides a durable, centralised coordination layer. Messages are reliably delivered even when a node fails, and recovering nodes can catch up on missed updates by replaying messages from the log. Kafka and Redpanda are a good fit for very large Stalwart deployments that require strict delivery guarantees.

 使用 Kafka 或 Redpanda 可以提供持久的集中式協調層。即使某個節點發生故障，訊息也能可靠地送達，而復原的節點可以透過重播日誌中的訊息來追趕錯過的更新。 Kafka 和 Redpanda 非常適合需要嚴格訊息傳遞保證的大型 Stalwart 部署。

 Kafka adds infrastructure requirements, but its ability to handle millions of events per second, support long-term message retention, and integrate with a wide ecosystem of tools makes it well-suited to enterprises with complex or high-traffic mail infrastructures.

 Kafka 增加了基礎設施需求，但它每秒可處理數百萬個事件，支援長期訊息保留，並可與廣泛的工俱生態系統集成，因此非常適合擁有複雜或高流量郵件基礎設施的企業。

 Apache Kafka is not included in the default Stalwart binary. To enable it, build Stalwart with the `kafka` feature flag.

 Apache Kafka 未包含在預設的 Stalwart 二進位檔案中。要啟用它，請使用`kafka`功能標誌 build Stalwart。

## Configuration｜配置

 Kafka coordination is configured by selecting the `Kafka` variant on the Coordinator singleton \(found in the WebUI under Settings › Cluster › Coordinator\). The variant carries the following fields:

 Kafka 協調配置是透過在 Coordinator單例中選擇`Kafka`變體來實現的（可在 WebUI 的「設定」&gt;「叢集」&gt;「協調器」中找到）。此變體包含以下欄位：

- brokers: set of Kafka broker addresses used to bootstrap the client connection. At least one broker is required; without it the Kafka coordinator fails to initialise.
brokers : 用於引導客戶端連線的 Kafka broker 位址集合。至少需要一個 broker；否則 Kafka 協調器將無法初始化。
- groupId: Kafka consumer group identifier that each Stalwart node joins. It coordinates consumption of coordination events among cluster members.
groupId : Kafka 消費者群組標識符，每個 Stalwart 節點都會加入該標識符。它負責協調集群成員之間協調事件的消費。
- timeoutSession: session timeout for the Kafka consumer, in milliseconds. If the broker receives no heartbeat from a consumer within this window, it treats the consumer as failed and rebalances the group. Default five seconds \(`5000`\).
timeoutSession : Kafka 消費者的會話逾時時間，以毫秒為單位。如果代理商在此視窗內未收到來自消費者的心跳，則將此消費者視為失敗並重新平衡群組。預設值為五秒 \( `5000` \)。
- timeoutMessage: maximum time to wait for a message to be delivered to Kafka, in milliseconds. Exceeding this returns an error. Default five seconds \(`5000`\).
timeoutMessage : 等待訊息傳遞到 Kafka 的最長時間，以毫秒為單位。超過此值將傳回錯誤。預設值為五秒 \( `5000` \)。
For example:
 例如：

```json
{
  "@type": "Kafka",
  "brokers": {"kafka1:9092": true, "kafka2:9092": true},
  "groupId": "stalwart-cluster",
  "timeoutSession": 5000,
  "timeoutMessage": 5000
}
```
