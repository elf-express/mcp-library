# NATS

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[coordination｜協調\\\]\\\(&lt;000 目錄.md#c-14&gt;\\\)

NATS is a lightweight messaging system built for cloud-native and edge environments. It provides a publish/subscribe model for real-time communication with low latency and low overhead. NATS suits distributed systems that need fast, reliable event propagation without the operational complexity of heavier platforms such as Apache Kafka.

 NATS是專為雲端原生和邊緣環境所建構的輕量級訊息系統。它提供了一種低延遲、低開銷的即時通訊的發布/訂閱模型。 NATS 適合需要快速、可靠的事件傳播的分散式系統，而無需像 Apache Kafka 等重型平台那樣操作複雜。

 As a coordination backend in a Stalwart cluster, NATS handles the exchange of internal events between nodes, keeping the cluster synchronised. When a mailbox is updated on one node, a push notification is triggered, or an IP address is blocked for abuse, NATS disseminates the information to the other nodes.

 作為 Stalwart 叢集中的協調後端， NATS負責處理節點間內部事件的交換，以保持叢集同步。當一個節點上的郵箱更新、觸發推播通知，或某個IP位址因濫用而被封禁時， NATS會將訊息傳播到其他節點。

 NATS is well-matched to medium-sized deployments where low-latency communication is essential but Kafka-level durability and persistence are not required. Its compact footprint and straightforward configuration also suit teams that want to minimise operational overhead while retaining reliable coordination.

 NATS非常適合中型部署，在這些部署中，低延遲通訊至關重要，但無需 Kafka 等級的持久性和持久性。其緊湊的佔用空間和簡單的配置也適合那些希望在保持可靠協調的同時最大限度降低運維開銷的團隊。

 NATS does not persist messages in the same way as Kafka \(unless extended via JetStream\), but it excels in real-time scenarios where speed and efficiency matter more than long-term storage. For many organisations, it balances performance, simplicity, and scalability for distributed mail coordination.

 NATS訊息持久化方式與 Kafka 不同（除非透過 JetStream 進行擴充），但它在即時場景中表現出色，速度和效率比長期儲存更為重要。對於許多組織而言，它在分散式郵件協調方面兼顧了效能、簡易性和可擴展性。

## Configuration｜配置

 NATS coordination is configured by selecting the `Nats` variant on the Coordinator singleton \(found in the WebUI under Settings › Cluster › Coordinator\). The variant carries the following fields:

 NATS協調配置是透過在 Coordinator單例中選擇`Nats`變體來實現的（可在 WebUI 的「設定」&gt;「叢集」&gt;「協調器」中找到）。此變體包含以下欄位：

- addresses: set of NATS server addresses. Default `{"127.0.0.1:4444": true}`; at least one address is required.
addresses : NATS伺服器位址集。預設值為`{"127.0.0.1:4444": true}` ；至少需要一個位址。
- authUsername and authSecret: optional basic authentication credentials. `authSecret` is a SecretKeyOptional, which accepts a direct value, an environment-variable reference, or a file reference.
authUsername 和 authSecret：可選的基本驗證憑證。 `authSecret` 是一個 SecretKeyOptional，它接受直接值、環境變數引用或檔案引用。
- credentials: a SecretTextOptional holding a JWT used for authentication; an alternative to the username/password pair.
credentials : 一個 SecretTextOptional包含一個JWT用於驗證；使用者名稱/密碼對的替代方案。
- noEcho: when enabled, prevents clients from receiving messages they publish themselves. Recommended for coordination to avoid redundant updates. Default `true`.
noEcho ：啟用後，阻止客戶端接收自己發布的訊息。建議用於協調以避免重複更新。預設值為`true` 。
- useTls: enables TLS for encrypted communication with NATS servers. Default `false`.
useTls : 啟用TLS與NATS伺服器進行加密通訊。預設值為`false` 。
- timeoutConnection: maximum time to wait when establishing a connection, in milliseconds. Default five seconds \(`5000`\).
timeoutConnection : 建立連線時等待的最大時間，以毫秒為單位。預設值為五秒 \( `5000` \)。
- timeoutRequest: timeout for request/response operations, in milliseconds. Default ten seconds \(`10000`\).
timeoutRequest : 請求/回應操作的超時時間，以毫秒為單位。預設值為十秒 \( `10000` \)。
- pingInterval: interval between pings sent to maintain connection health, in milliseconds. Default 60 seconds \(`60000`\).
pingInterval : 發送 ping 以維持連線健康的間隔，以​​毫秒為單位。預設值為 60 秒 \( `60000` \)。
- maxReconnects: number of reconnection attempts after a connection is lost. When left unset the client reconnects indefinitely.
maxReconnects : 連線中斷後嘗試重新連線的次數。如果未設置，客戶端將無限期地重新連接。
- capacityClient: internal channel size for outgoing client operations. Default `2048`.
capacityClient : 出站客戶端操作的內部頻道大小。預設值為`2048` 。
- capacitySubscription: capacity of the internal channel for message subscriptions. Default `65536`.
capacitySubscription : 訊息訂閱的內部通道容量。預設值為`65536` 。
- capacityReadBuffer: size of the read buffer for incoming messages. Default `65535`.
capacityReadBuffer : 傳入訊息的讀取緩衝區大小。預設值為`65535` 。
For example:
 例如：

```json
{
  "@type": "Nats",
  "addresses": {"nats1:4222": true, "nats2:4222": true},
  "authUsername": "nats-user",
  "authSecret": {
    "@type": "Value",
    "secret": "nats-password"
  },
  "pingInterval": 60000,
  "noEcho": true,
  "useTls": false,
  "timeoutConnection": 5000,
  "timeoutRequest": 10000,
  "capacityClient": 2048,
  "capacitySubscription": 65536,
  "capacityReadBuffer": 65535
}
```
