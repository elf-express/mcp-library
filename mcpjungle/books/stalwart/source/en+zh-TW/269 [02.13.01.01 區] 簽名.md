# Signing｜簽名

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[authentication｜驗證\\\]\\\(&lt;000 目錄.md#c-48&gt;\\\) › \\\[dkim｜區\\\]\\\(&lt;000 目錄.md#c-49&gt;\\\)

Stalwart can automatically sign outgoing messages with one or more DKIM signatures. The following algorithms are supported:

 Stalwart 可以使用一個或多個 DKIM 簽章自動簽署傳出訊息。支援以下演算法：

- `ED25519-SHA256`: the Edwards-Curve Digital Signature Algorithm, known for strong security and efficient processing.
`ED25519-SHA256`：Edwards-Curve數位簽章演算法，以其強大的安全性和高效的處理而聞名。
- `RSA-SHA256`: RSA combined with SHA-256.
`RSA-SHA256`: RSA 與SHA-256 結合。
- `RSA-SHA1`: supported for compatibility with legacy systems only; not recommended for new deployments.
`RSA-SHA1`：僅支援相容舊系統；不建議用於新部署。
When using RSA-based DKIM signatures, the key size should be at least 2048 bits. RSA keys smaller than 1024 bits are vulnerable to cryptographic attacks.
 當使用基於RSA的DKIM簽章時，金鑰大小應至少為2048位元。小於 1024 位元的RSA 金鑰容易受到加密攻擊。

## Selecting signatures per message｜選擇每個訊息的簽名

 Whether to sign a given message \(and with which signature\(s\)\) is controlled by the dkimSignDomain field on the SenderAuth singleton \(found in the WebUI under Settings › MTA › Inbound › Sender Authentication\). The field accepts an expression that returns the domain whose DKIM signatures should be applied, or `false` to skip signing. The default policy returns the sender domain when the message is sent by an authenticated user from a local domain:

 是否對給定訊息進行簽署（以及使用哪個簽章）由 SenderAuth 單例上的 dkimSignDomain 欄位控制（可在 WebUI 的設定 › MTA › 入站 發現下碼驗證）。此欄位接受一個表達式，該表達式傳回應套用其 DKIM 簽章的域，或 `false` 以跳過簽章。當訊息由經過驗證的使用者從本機網域傳送時，預設原則會傳回寄件者網域：

```json
{
  "dkimSignDomain": {
    "match": {
      "0": {"if": "is_local_domain(sender_domain) && !is_empty(authenticated_as)", "then": "sender_domain"}
    },
    "else": "false"
  }
}
```

When a domain is returned, Stalwart selects every DkimSignature associated with that domain and signs the outgoing message with each of them. This allows, for example, an Ed25519 signature and an RSA signature to be applied simultaneously by creating two signatures against the same domain.

 返回域後，Stalwart 會選擇與該域關聯的每個 DkimSignature，並使用它們對傳出訊息進行簽署。例如，這允許透過針對相同網域建立兩個簽章來同時套用 Ed25519 簽章和 RSA 簽章。

## Defining signatures｜定義簽名

 DKIM signatures are DkimSignature objects \(found in the WebUI under Management › Domains › DKIM Signatures\). Each instance is a multi-variant object: the `Dkim1Ed25519Sha256` variant covers Ed25519 signatures and the `Dkim1RsaSha256` variant covers RSA signatures. Both variants share the same configuration fields:

 DKIM 簽章是 DkimSignature 物件（可在 WebUI 的管理 › 網域 › DKIM 簽章下找到）。每個實例都是多變體物件：`Dkim1Ed25519Sha256`變體涵蓋Ed25519簽名，`Dkim1RsaSha256`變體涵蓋RSA簽名。兩種變體共享相同的配置欄位：

- privateKey: the PEM-encoded private key used for signing. Can be supplied directly or read from an environment variable or file.
privateKey：用於簽署的PEM編碼私鑰。可以直接提供或從環境變數或檔案中讀取。
- domainId: the identifier of the Domain this signature belongs to.
domainId：該簽章所屬的域的標識符。
- selector: the selector used to locate the public key in DNS.
selector：用於在DNS中定位公鑰的選擇器。
- headers: the set of headers included in the signature. Defaults to `{"From": true, "To": true, "Date": true, "Subject": true, "Message-ID": true}`.
headers：簽名中包含的標頭集。預設為`{"From": true, "To": true, "Date": true, "Subject": true, "Message-ID": true}`。
- canonicalization: the canonicalization algorithm applied to the headers and body. Defaults to `relaxed/relaxed`.
canonicalization：應用於標頭和正文的規範化演算法。預設為`relaxed/relaxed`。
- expire: optional signature lifetime, in milliseconds.
expire：可選簽章生命週期，單位毫秒。
- thirdParty: optional authorised third-party signature value.
thirdParty：可選授權第三方簽章值。
- thirdPartyHash: optional hashing algorithm \(`sha256` or `sha1`\) used to verify third-party signature DNS records.
thirdPartyHash：可選的哈希演算法（`sha256`或`sha1`）用於驗證第三方簽章DNS記錄。
- auid: optional Agent User Identifier included in the signature header.
auid：簽章標頭中所包含的選用代理使用者識別碼。
- report: whether to request failure reports when signature verification fails on the recipient side. Default `true`.
report：接收方簽章驗證失敗時是否要求失敗報告。預設`true`。
- stage: the rotation stage \(`active`, `pending`, `retiring`, `retired`\). Active keys sign outgoing mail; pending keys are staged for DNS publication; retiring keys have been superseded but still published in DNS; retired keys have been removed from DNS and are pending deletion.
stage：旋轉階段（`active`, `pending`, `retiring`, `retired`）。活動鍵簽署外寄郵件；待定金鑰已準備好用於DNS發布；退役金鑰已被取代，但仍發佈在 DNS 中；已停用的金鑰已從DNS 中刪除，並且正在等待刪除。
- nextTransitionAt: optional date when the key transitions to the next rotation stage.
nextTransitionAt：金鑰轉換到下一個輪換階段的可選日期。
For example, a pair of RSA and Ed25519 signatures for `example.org`, each covering an extended set of headers, looks like this:
 例如，`example.org`的一對RSA和Ed25519簽名，每個簽名都覆蓋一組擴展的標頭，如下所示：

```json
[
  {
    "@type": "Dkim1RsaSha256",
    "domainId": "<Domain id>",
    "selector": "rsa-default",
    "privateKey": {"@type": "File", "filePath": "/opt/stalwart/etc/private/dkim-rsa.key"},
    "headers": {
      "From": true, "To": true, "Cc": true, "Date": true, "Subject": true,
      "Message-ID": true, "Organization": true, "MIME-Version": true,
      "Content-Type": true, "In-Reply-To": true, "References": true,
      "List-Id": true, "User-Agent": true, "Thread-Topic": true, "Thread-Index": true
    },
    "canonicalization": "relaxed/relaxed",
    "expire": 864000000,
    "report": true,
    "stage": "active"
  },
  {
    "@type": "Dkim1Ed25519Sha256",
    "domainId": "<Domain id>",
    "selector": "ed-default",
    "privateKey": {"@type": "File", "filePath": "/opt/stalwart/etc/private/dkim-ed.key"},
    "headers": {
      "From": true, "To": true, "Cc": true, "Date": true, "Subject": true,
      "Message-ID": true, "Organization": true, "MIME-Version": true,
      "Content-Type": true, "In-Reply-To": true, "References": true,
      "List-Id": true, "User-Agent": true, "Thread-Topic": true, "Thread-Index": true
    },
    "canonicalization": "relaxed/relaxed",
    "report": false,
    "stage": "active"
  }
]
```

Values on this page follow the object encoding rules: list and set fields are JSON objects rather than arrays, and durations and sizes are integers.

 此頁面上的值遵循物件編碼規則：列表和集合字段是JSON物件而不是數組，持續時間和大小是整數。

## Multiple domains｜多個域

 Although a single DKIM key may be used across multiple domains with [Authorized Third-Party Signatures](https://www.ietf.org/rfc/rfc6541.html), a separate key per domain is recommended. This gives more granular control and makes issues easier to isolate. Because dkimSignDomain returns a domain name, the correct signatures are selected automatically as long as each domain has its own signature definitions.

 儘管單一 DKIM 金鑰可以透過[授權第三方簽署](https://www.ietf.org/rfc/rfc6541.html)跨多個網域使用，但建議每個網域使用單獨的金鑰。這提供了更精細的控制，並使問題更容易隔離。由於 dkimSignDomain 返回域名，只要每個域都有自己的簽名定義，就會自動選擇正確的簽名。

## Generating keys｜產生金鑰

 The simplest way to generate and publish a DKIM key pair is from the WebUI. Keys may also be generated manually using `openssl`.

 產生和發布 DKIM 金鑰對的最簡單方法是透過 WebUI。金鑰也可以使用`openssl`手動產生。

### RSA

```bash title=&amp;quot;Terminal window&amp;quot;
openssl genrsa -out rsa_private.key 2048
openssl rsa -in rsa_private.key -pubout -out rsa_public.key
```

These commands generate a 2048-bit RSA private key and derive the public key. The private key must be kept secure.

 這些命令會產生 2048 位元 RSA 私鑰並匯出公鑰。私鑰必須妥善保管。

### Edwards-curve Digital Signature Algorithm｜愛德華茲曲線數位簽章演算法

```bash title=&amp;quot;Terminal window&amp;quot;
openssl genpkey -algorithm ed25519 -out ed_private.key
openssl pkey -in ed_private.key -pubout -out ed_public.key
```

## Publishing DKIM keys｜發布 DKIM 金鑰

 Once the public key is available, it is published in DNS as a TXT record. The record name follows the form `selector._domainkey.yourdomain.org`.

 一旦公鑰可用，它就會作為 TXT 記錄發佈在 DNS 中。記錄名稱採`selector._domainkey.yourdomain.org`的形式。

 To obtain an RSA DKIM public key in a format suitable for a DNS TXT record:

 若要取得適合 DNS TXT 記錄格式的 RSA DKIM 公鑰：

```bash title=&amp;quot;Terminal window&amp;quot;
openssl rsa -in private.key -pubout -outform der 2>/dev/null | openssl base64 -A
```

For an Ed25519 DKIM public key:

 對於 Ed25519 DKIM 公鑰：

```bash title=&amp;quot;Terminal window&amp;quot;
openssl asn1parse -in ed_public.key -offset 12 -noout -out /dev/stdout | base64
```

The result is a base64-encoded public key that can be wrapped into a standard DKIM TXT record:

 結果是一個 Base64 編碼的公鑰，可以包裝到標準 DKIM TXT 記錄中：

```
v=DKIM1; k=rsa; p=PUBLIC_KEY
```

For example, with domain `example.org`, selector `default`, and an RSA public key `ABCDEFG`:

 例如，對於域 `example.org`、選擇器 `default` 和 RSA 公鑰 `ABCDEFG`：

```
default._domainkey.example.org. IN TXT "v=DKIM1; k=rsa; p=ABCDEFG"
```

The signature must use the matching selector and domain.

 簽章必須使用符合的選擇器和網域。
