# Recovery mode｜恢復模式

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-18&gt;\\\)

Recovery mode is intended for situations where a running deployment requires maintenance and the normal services must not be active. Typical reasons include a misconfigured external directory that is preventing any administrator from signing in, a faulty setting that is causing the MTA to loop, a pre-deployment provisioning step where a large batch of objects must be loaded before any mail traffic reaches the server, or a freshly bootstrapped installation where HTTPS on the configured hostname is not yet reachable and the WebUI must remain available over HTTP to finish the setup.

 復原模式適用於運作中的部署需要維護且正常服務無法運作的情況。常見原因包括：外部目錄配置錯誤導致管理員無法登入；設定錯誤導致MTA循環；部署前設定步驟中，必須在郵件流量到達伺服器之前載入大量物件；或新安裝的\([https://stalw.art/docs/configuration/bootstrap-mode\)中，設定主機名稱上的HTTPS尚無法存取，而](https://stalw.art/docs/configuration/bootstrap-mode%2529%2525E4%2525B8%2525AD%2525EF%2525BC%25258C%2525E8%2525A8%2525AD%2525E5%2525AE%25259A%2525E4%2525B8%2525BB%2525E6%2525A9%25259F%2525E5%252590%25258D%2525E7%2525A8%2525B1%2525E4%2525B8%25258A%2525E7%25259A%252584HTTPS%2525E5%2525B0%25259A%2525E7%252584%2525A1%2525E6%2525B3%252595%2525E5%2525AD%252598%2525E5%25258F%252596%2525EF%2525BC%25258C%2525E8%252580%25258C) WebUI 必須透過HTTP才能完成設定。

 In this mode Stalwart starts with every background service disabled. The MTA does not accept or process messages, task workers do not run, cluster services do not join the coordinator, and scheduled jobs remain paused. The only active listener is the HTTP management endpoint on port `8080` \(configurable with `STALWART_RECOVERY_MODE_PORT`\), which serves the WebUI and the full JMAP management API. From there, administrators can use the WebUI or the CLI to inspect the configuration, correct the problem, and then restart the server without the recovery flag to return it to normal operation.

 在此模式下，Stalwart 啟動時會停用所有背景服務。 MTA 不接受或處理訊息，任務工作執行緒不執行，叢集服務不加入協調器，計畫作業保持暫停狀態。唯一活動的偵聽器是連接埠 `8080` 上的HTTP 管理端點（可使用 `STALWART_RECOVERY_MODE_PORT` 配置），它為 WebUI 和完整的 JMAP 管理 API 提供服務。從那裡，管理員可以使用 WebUI 或 CLI 檢查配置、糾正問題，然後在沒有恢復標誌的情況下重新啟動伺服器以將其恢復到正常操作。

 Stalwart never enters recovery mode automatically. It is activated by setting the environment variable `STALWART_RECOVERY_MODE` to `1` or `true` before starting the server. When the variable is unset, or set to any other value, Stalwart starts normally.

 Stalwart 不會自動進入恢復模式。它需要透過在啟動伺服器之前將環境變數`STALWART_RECOVERY_MODE`設定為`1`或`true`來啟動。如果取消設定該變量，或將其設為任何其他值，Stalwart 將正常啟動。

## Recovery administrator｜復原管理員

 Recovery mode still requires a valid sign-in. If the regular administrator account is locked out, or if the external directory that normally handles authentication is unreachable, the ordinary credentials will not work. The recovery administrator is a built-in account that bypasses the directory. It is honoured whenever `STALWART_RECOVERY_ADMIN` is set in the environment, including while the server is running normally, so emergency tasks such as promoting a directory account to administrator can be performed without taking services offline; bootstrap and recovery mode also rely on the same variable when the directory is not reachable.

 恢復模式仍然需要有效的登入憑證。如果常規管理員帳戶被鎖定，或者通常處理身份驗證的外部目錄無法訪問，則普通憑證將無法使用。恢復管理員是一個內建帳戶，它繞過了該目錄。只要環境中設定了`STALWART_RECOVERY_ADMIN` ，該帳戶就會生效，即使伺服器正常運作時也是如此。因此，可以在不中斷服務的情況下執行諸如將目錄帳戶提升為管理員之類的緊急任務；當目錄無法存取時，bootstrap和恢復模式也依賴相同的變數。

 The recovery administrator is configured with the `STALWART_RECOVERY_ADMIN` environment variable, in the form `username:password`. For example:

 恢復管理員透過環境變數`STALWART_RECOVERY_ADMIN`進行配置，格式為`username:password` 。例如：

```bash title=&amp;quot;Terminal window&amp;quot;
STALWART_RECOVERY_ADMIN=admin:correcthorsebatterystaple
```

The same variable is used during bootstrap to pin a credential instead of relying on the randomly generated one, and it serves as the mechanism for regaining access after an incident.

 在引導過程中使用相同的變數來固定憑證，而不是依賴隨機產生的憑證，並且它作為在事件發生後重新獲得存取權限的機制。

`STALWART_RECOVERY_ADMIN` must not be left permanently set on a production deployment. It is a backdoor credential intended to rescue a server that has lost normal access, not a primary login. It should be set only for the duration of the work that requires it, then removed from the environment before the server is restarted. For day-to-day administration, create regular administrator accounts with appropriately scoped roles.

`STALWART_RECOVERY_ADMIN`不應在生產環境中永久設定。它是一個後門憑證，用於在伺服器失去正常存取權限時進行恢復，並非主登入憑證。它應該僅在需要時設置，並在伺服器重新啟動之前從環境中移除。對於日常管理，請建立具有適當權限範圍的常規管理員帳戶。
