## MySQL / MariaDB

 MySQL is a widely used open-source relational database management system, known for its reliability, simplicity, and broad platform compatibility. It handles large volumes of data efficiently and is a popular choice for web applications and online transaction processing. MariaDB is a drop-in compatible fork of MySQL and is supported through the same variant.

 MySQL 是一款廣泛使用的開源關聯式資料庫管理系統，以其可靠性、易用性和廣泛的平台相容性而聞名。它能夠有效率地處理大量數據，是 Web 應用和線上交易處理的熱門選擇。 MariaDB 是 MySQL 的相容分支，並透過相同的版本提供支援。

## Configuration｜配置

 The MySQL backend is selected by choosing the `MySql` variant on the DataStore object \(found in the WebUI under Settings › Storage › Data Store\). The variant exposes the following fields:

 MySQL 後端可透過選擇 DataStore物件上的`MySql`變體來選擇（可在 WebUI 的「設定」&gt;「儲存」&gt;「資料儲存」中找到）。該變體公開以下欄位：

- host: hostname or IP address of the MySQL server \(required\).
host : MySQL 伺服器的主機名稱或IP位址（必需）。
- port: TCP port. Default: `3306`.
port: TCP端口。預設值： `3306` 。
- database: name of the database. Default: `"stalwart"`.
database : 資料庫名稱。預設值： `"stalwart"` 。
- authUsername: username used to authenticate. Default: `"stalwart"`.
authUsername : 用於身份驗證的使用者名稱。預設值： `"stalwart"` 。
- authSecret: password or other secret reference used to authenticate \(required\).
authSecret : 用於身份驗證的密碼或其他秘密參考資訊（必填）。
- timeout: maximum time to wait when establishing a connection. Default: `"15s"`.
timeout : 建立連線時等待的最大時間。預設值： `"15s"` 。
- maxAllowedPacket: maximum size of a single network packet sent to or received from the server, in bytes.
maxAllowedPacket : 傳送至伺服器或從伺服器接收的單一網路封包的最大大小，以位元組為單位。
### Connection pool｜連接池

 Pool sizing is controlled through poolMaxConnections \(default `10`\) and poolMinConnections \(default `5`\). The minimum ensures a baseline of ready connections at all times.

 連接池大小透過 poolMaxConnections （預設值`10` ）和 poolMinConnections （預設值`5` ）進行控制。最小值可確保始終保持一定的連線就緒率。

### TLS

 TLS is enabled through useTls. When enabled, allowInvalidCerts determines whether connections with invalid certificates are accepted, which is typically only useful in development or testing.

 TLS透過 useTls啟用。啟用後，allowInvalidCerts確定是否接受具有無效憑證的連接，這通常只在開發或測試中有用。

### Read replicas｜讀取副本

 In Enterprise deployments, write operations target the primary connection and read operations are distributed across one or more replicas. Replicas are configured through the readReplicas field on the same DataStore object, which accepts a list of replica connection settings. Each entry defines a full set of connection parameters \(host, port, database, authUsername, and authSecret\). The same pattern is available on the BlobStore and SearchStore objects when their `MySql` variant is selected.

 在企業部署中，寫入作業針對主連接，而讀取操作則分佈在一個或多個副本上。副本透過同一資料儲存物件上的 readReplicas欄位進行配置，該欄位接受副本連接設定清單。每個條目定義了一整套連接參數`database` host 、port 、authUsername \([https://stalw.art/docs/ref/object/data-store#database](https://stalw.art/docs/ref/object/data-store#database)\) \[ `authSecret` \([https://stalw.art/docs/ref/object/data-store#authsecret](https://stalw.art/docs/ref/object/data-store#authsecret)\) ）。當選擇 BlobStore和 SearchStore物件的`MySql`變體時，也可以使用相同的模式。

 Read replicas are available exclusively in the Enterprise Edition of Stalwart and are not included in the Community Edition.

 讀取副本功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

## Authentication directory｜身份驗證目錄

 When MySQL is used as an authentication directory, the queries that resolve account names, group members, recipients, and email addresses are configured on the Directory object with the SQL variant, which references this store. See the SQL directory page for details.

 當 MySQL 用作身份驗證目錄時，用於解析帳戶名稱、群組成員、收件人和電子郵件地址的查詢配置在 Directory物件上，並使用SQL變體，該變體引用此儲存。有關詳細信息，請參閱 SQL directory頁面。

## FTS Limitations｜FTS局限性

 MySQL’s built-in full-text search is a lightweight feature designed primarily for simple keyword matching. While sufficient for basic search use cases, it has several inherent limitations that are important to understand when using it as a full-text search backend for email.

 MySQL 內建的全文搜尋功能較為輕量級，主要用於簡單的關鍵字配對。雖然足以滿足基本的搜尋需求，但它存在一些固有的局限性，在使用其作為電子郵件全文搜尋後端時，了解這些局限性至關重要。

 One significant limitation is that MySQL full-text search does not support **multiple languages within the same indexed column**. A full-text index is tied to a single parser and language configuration, which means messages containing mixed languages cannot be tokenised or ranked correctly. In mail environments where users regularly exchange messages in different languages, this can lead to inconsistent or incomplete search results.

 一個顯著的限制是，MySQL 全文搜尋不支援**同一索引列中包含多種語言**。全文索引與單一解析器和語言配置綁定，這意味著包含混合語言的郵件無法被正確地分詞或排序。在使用者經常使用不同語言交流的郵件環境中，這會導致搜尋結果不一致或不完整。

 MySQL full-text search also does **not support stemming**. Words are indexed and matched in their exact forms, so different grammatical variants of the same word \(singular versus plural, different verb tenses\) are treated as unrelated terms. As a result, searches are less tolerant of natural-language variation and may miss relevant messages unless the exact word forms present in the message are used.

 MySQL 全文搜尋也不**支援詞幹擷取**。單字會依照其確切形式進行索引和匹配，因此同一個字的不同語法變體（單數與複數、不同的動詞時態）會被視為不相關的詞條。因此，搜尋對自然語言變體的容忍度較低，除非使用郵件中出現的確切詞形，否則可能會遺漏相關的郵件。

 Another important constraint is that **words shorter than three characters are not indexed** by default. Common short words, abbreviations, and identifiers \(many of which appear in email content\) are therefore not searchable at all. This is particularly noticeable when searching for short names, acronyms, or codes.

 另一個重要的限制是，預設情況下，**長度小於三個字元的單字不會被索引**。因此，常見的短詞、縮寫和識別碼（其中許多出現在電子郵件內容中）根本無法搜尋。在搜尋簡稱、首字母縮寫或代碼時，這一點尤其明顯。

 Taken together, these limitations can significantly affect search quality and recall. If accurate, language-aware search behaviour is a priority for the deployment, a different full-text search backend that provides better linguistic support and indexing is strongly recommended.

 綜上所述，這些限制會顯著影響搜尋品質和召回率。如果部署的首要任務是實現準確且語言感知的搜尋行為，則強烈建議使用提供更佳語言支援和索引功能的其他全文搜尋後端（例如\([https://stalw.art/docs/storage/fts](https://stalw.art/docs/storage/fts)\) ）。
