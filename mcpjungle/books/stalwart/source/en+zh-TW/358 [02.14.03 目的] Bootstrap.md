# Bootstrap

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[ref｜參考\\\]\\\(&lt;000 目錄.md#c-56&gt;\\\) › \\\[object｜目的\\\]\\\(&lt;000 目錄.md#c-61&gt;\\\)

Initial setup shown the first time Stalwart starts. Configures the server’s identity, storage, user accounts, logging, and DNS management.

 Stalwart 首次啟動時會顯示初始設定。設定伺服器的身分、儲存、使用者帳戶、日誌記錄和DNS管理。

## Fields｜田野

##### `serverHostname`

> Type: \\\`String\\\` · required

類型： \`String\` · 必填

 The public hostname this server answers to, for example mail.example.com. Used in SMTP greetings, outgoing message headers, and TLS certificate requests.

 此伺服器回應的公共主機名，例如 mail.example.com。用於SMTP問候語、外發郵件頭和TLS證書請求。

##### `defaultDomain`

> Type: \\\`String\\\` · required

類型： \`String\` · 必填

 The primary email domain this installation will serve, for example example.com. Additional domains can be added at any time after setup.

 此安裝將服務於主要的電子郵件域名，例如 example.com。設定完成後，可以隨時新增其他網域。

##### `requestTlsCertificate`

> Type: \\\`Boolean\\\` · default: \\\`true\\\`

類型： \`Boolean\` · 預設值： \`true\`

 Automatically obtain a free TLS certificate for the server hostname from Let’s Encrypt using the ACME protocol, so clients can connect securely out of the box. Turn this off if you plan to install a certificate manually.

 使用ACME協議，從 Let's Encrypt 自動取得伺服器主機名稱的免費TLS證書，以便客戶端開箱即用即可安全連線。如果您打算手動安裝證書，請關閉此功能。

##### `generateDkimKeys`

> Type: \\\`Boolean\\\` · default: \\\`true\\\`

類型： \`Boolean\` · 預設值： \`true\`

 Generate DKIM signing keys for the default domain. DKIM cryptographically signs outgoing mail and significantly improves the chances that messages reach the recipient’s inbox instead of spam. Turn this off only if you plan to manage DKIM keys yourself.

 為預設域產生 DKIM 簽章金鑰。 DKIM 對外發郵件進行加密簽名，顯著提高郵件而不是垃圾郵件到達收件者收件匣的機會。僅當您打算自行管理 DKIM 金鑰時才將其關閉。

##### `dataStore`

> Type: \\\[\\\`DataStore\\\`\\\]\\\(&lt;368 \\\[02.14.03 目的\\\] 資料儲存.md&gt;\\\) · default: \\\`{"@type":"RocksDb","path":"/var/lib/stalwart/"}\\\`

類型：\[\`DataStore\`\]\(&lt;368 \[02.14.03 目的\] 資料儲存.md&gt;\) · 預設值： \`{"@type":"RocksDb","path":"/var/lib/stalwart/"}\`

 Where structured data is kept: email metadata, calendars, contacts, mailbox state, and server settings. RocksDB is recommended for single-node installations; PostgreSQL, MySQL, SQLite, and FoundationDB are also supported.

 結構化資料儲存位置：電子郵件元資料、日曆、聯絡人、郵箱狀態和伺服器設定。 RocksDB 推薦用於單節點部署；同時也支援 PostgreSQL、MySQL、SQLite 和 FoundationDB。

##### `blobStore`

> Type: \\\[\\\`BlobStore\\\`\\\]\\\(&lt;356 \\\[02.14.03 目的\\\] BlobStore.md&gt;\\\) · default: \\\`{"@type":"Default"}\\\`

類型：\[\`BlobStore\`\]\(&lt;356 \[02.14.03 目的\] BlobStore.md&gt;\) · 預設值： \`{"@type":"Default"}\`

 Where the raw content of email messages, attachments, and other large files is stored. Leave as default to reuse the data store, or point to an object storage service such as S3 for larger deployments.

 用於儲存電子郵件、附件和其他大型文件的原始內容。保留預設設定以重複使用資料存儲，或指向物件儲存服務（例如 S3）以進行更大規模的部署。

##### `searchStore`

> Type: \\\[\\\`SearchStore\\\`\\\]\\\(&lt;424 \\\[02.14.03 目的\\\] 搜尋商店.md&gt;\\\) · default: \\\`{"@type":"Default"}\\\`

類型：\[\`SearchStore\`\]\(&lt;424 \[02.14.03 目的\] 搜尋商店.md&gt;\) · 預設值： \`{"@type":"Default"}\`

 Where the full-text search index is kept, so users can search across message bodies and attachments. Leave as default to reuse the data store, or point to a dedicated search backend for larger deployments.

 全文搜尋索引的儲存位置，以便使用者可以搜尋郵件正文和附件。您可以保留預設設定以重複使用資料存儲，或針對更大規模的部署指向專用的搜尋後端。

##### `inMemoryStore`

> Type: \\\[\\\`InMemoryStore\\\`\\\]\\\(&lt;387 \\\[02.14.03 目的\\\] 記憶體儲存.md&gt;\\\) · default: \\\`{"@type":"Default"}\\\`

類型：\[\`InMemoryStore\`\]\(&lt;387 \[02.14.03 目的\] 記憶體儲存.md&gt;\) · 預設值： \`{"@type":"Default"}\`

 Where short-lived data lives: session caches, rate-limit counters, and temporary tokens. Leave as default to reuse the data store, or point to Redis for faster lookups and multi-node deployments.

 用於儲存短期資料的地方：會話快取、速率限制計數器和臨時令牌。保留預設設定以重複使用資料存儲，或指向 Redis 以獲得更快的查找速度和多節點部署。

##### `directory`

> Type: \\\[\\\`DirectoryBootstrap\\\`\\\]\\\(#directorybootstrap\\\) · default: \\\`{"@type":"Internal"}\\\`

類型：\[\`DirectoryBootstrap\`\]\(#directorybootstrap\) · 預設值： \`{"@type":"Internal"}\`

 Where user accounts and credentials come from. The internal directory is recommended for ease of setup and management through the WebUI, but external OIDC or LDAP directories can be used for single sign-on and user provisioning in larger organizations.

 使用者帳戶和憑證的來源。建議使用內部目錄，以便透過 WebUI 輕鬆進行設定和管理；但在大型組織中，可以使用外部OIDC或LDAP目錄來實現單一登入和使用者設定。

##### `tracer`

> Type: \\\[\\\`Tracer\\\`\\\]\\\(&lt;452 \\\[02.14.03 目的\\\] 追蹤器.md&gt;\\\) · default: \\\`{"@type":"Log","path":"/var/log/stalwart/"}\\\`

類型：\[\`Tracer\`\]\(&lt;452 \[02.14.03 目的\] 追蹤器.md&gt;\) · 預設值： \`{"@type":"Log","path":"/var/log/stalwart/"}\`

 Where the server writes log messages, traces, and diagnostic events. Defaults to log files on disk; remote destinations such as OpenTelemetry or webhooks can be added after setup.

 伺服器將日誌訊息、追蹤資訊和診斷事件寫入此位置。預設寫入磁碟上的日誌檔案；設定完成後，可以新增遠端目標位置，例如 OpenTelemetry 或 Webhook。

##### `dnsServer`

> Type: \\\[\\\`DnsServerBootstrap\\\`\\\]\\\(#dnsserverbootstrap\\\) · default: \\\`{"@type":"Manual"}\\\`

類型：\[\`DnsServerBootstrap\`\]\(#dnsserverbootstrap\) · 預設值： \`{"@type":"Manual"}\`

 Optionally automate the DNS records your mail server needs \(SPF, DKIM, DMARC, and more\) by connecting to your DNS provider’s API. Leave as manual unless your DNS is hosted by a supported provider; this can always be enabled later.

 您可以選擇透過連接到您的DNS伺服器提供者的API ，自動DNS郵件伺服器所需的記錄（ SPF, DKIM, DMARC等）。除非您的DNS託管在受支援的提供者處，否則請保持手動設定；此功能可以稍後啟用。

## JMAP API

 The Bootstrap singleton is available via the `urn:stalwart:jmap` capability.

 Bootstrap 單例可透過`urn:stalwart:jmap`功能取得。

### `x:Bootstrap/get`

 This is a standard [Foo/get](https://www.rfc-editor.org/rfc/rfc8620#section-5.1) method as defined in [RFC 8620](https://www.rfc-editor.org/rfc/rfc8620#section-5.1), Section 5.1.

 這是[Foo/get](https://www.rfc-editor.org/rfc/rfc8620#section-5.1)方法，如[RFC](https://www.rfc-editor.org/rfc/rfc8620#section-5.1) ，第5.1節中定義。

 For singletons, the `ids` argument should be the literal `singleton` \(or `null` to return the single instance\).

 對於單例， `ids`參數應該是字面值`singleton` （或`null`以傳回單一實例）。

 This method requires the `sysBootstrapGet` permission.

 此方法需要`sysBootstrapGet` 權限 。

```bash title=&amp;quot;Terminal window&amp;quot;
curl -X POST https://mail.example.com/api \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
      "methodCalls": [
        [
          "x:Bootstrap/get",
          {
            "ids": [
              "singleton"
            ]
          },
          "c1"
        ]
      ],
      "using": [
        "urn:ietf:params:jmap:core",
        "urn:stalwart:jmap"
      ]
    }'
```

### `x:Bootstrap/set`

 This is a standard [Foo/set](https://www.rfc-editor.org/rfc/rfc8620#section-5.3) method as defined in [RFC 8620](https://www.rfc-editor.org/rfc/rfc8620#section-5.3), Section 5.3.

 這是[Foo/set](https://www.rfc-editor.org/rfc/rfc8620#section-5.3)方法，如[RFC](https://www.rfc-editor.org/rfc/rfc8620#section-5.3) ，第5.3節中定義。

 For singletons, only the `update` argument with id `singleton` is accepted; `create` and `destroy` arguments are rejected.

 對於單例，僅接受 id 為`singleton`的`update`參數；拒絕`create`和`destroy`參數。

 This method requires the `sysBootstrapUpdate` permission.

 此方法需要`sysBootstrapUpdate` 權限 。

```bash title=&amp;quot;Terminal window&amp;quot;
curl -X POST https://mail.example.com/api \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
      "methodCalls": [
        [
          "x:Bootstrap/set",
          {
            "update": {
              "singleton": {
                "serverHostname": "updated value"
              }
            }
          },
          "c1"
        ]
      ],
      "using": [
        "urn:ietf:params:jmap:core",
        "urn:stalwart:jmap"
      ]
    }'
```
