# Docker Swarm

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[cluster｜簇\\\]\\\(&lt;000 目錄.md#c-12&gt;\\\) › \\\[orchestration｜管弦樂\\\]\\\(&lt;000 目錄.md#c-16&gt;\\\)

Docker Swarm is the native clustering and orchestration solution from Docker. It deploys and manages containers across a group of machines as a single cluster, providing built-in features for service discovery, load balancing, scaling, and fault tolerance while preserving the familiar Docker CLI and Compose workflow.

 Docker Swarm 是 Docker 的原生叢集和編排解決方案。它將容器部署和管理到一組機器上，形成一個單一的集群，提供服務發現、負載平衡、擴展和容錯等內建功能，同時保留了熟悉的 Docker CLI和 Compose 工作流程。

 With Docker Swarm, multi-container services are defined once, and Docker handles the scheduling, replication, and failover of containers across swarm nodes. This makes Swarm an accessible orchestration option for environments that already rely on Docker for containerisation.

 透過 Docker Swarm，只需定義一次多容器服務，Docker 即可處理跨叢集節點的容器調度、複製和故障轉移。這使得 Swarm 成為已依賴 Docker 進行容器化的環境的理想編排方案。

 Stalwart can be deployed on Docker Swarm as a set of replicated or distributed services, each running one or more components of the mail and collaboration stack. Swarm handles container placement, restarts failed containers, and keeps services available, including in the event of hardware or node failure.

 Stalwart 可以部署在 Docker Swarm 上，作為一組複製或分散式服務，每個服務運行郵件和協作堆疊中的一個或多個元件。 Swarm 負責容器部署、重新啟動故障容器，並確保服務可用，即使在硬體或節點發生故障的情況下也能正常運作。

 For teams that want a straightforward orchestration layer without the complexity of Kubernetes or the scale of Mesos, Docker Swarm is a practical option for managing Stalwart clusters in small to medium environments.

 對於想要一個簡單的編排層，而不需要 Kubernetes 的複雜性或 Mesos 的規模的團隊來說，Docker Swarm 是在中小型環境中管理 Stalwart 叢集的一個實用選擇。

## Deployment｜部署

 Set up the necessary node labels to control placement of the mail server:

 設定必要的節點標籤以控制郵件伺服器的放置位置：

```bash title=&amp;quot;Terminal window&amp;quot;
$ docker node update --label-add mail=true <NODE-ID>
```

Deploy the stack to the swarm:

 將堆疊部署到叢集：

```bash title=&amp;quot;Terminal window&amp;quot;
$ docker stack deploy -c stalwart-mail-stack.yml stalwart-mail
```

Check deployment status:

 檢查部署狀態：

```bash title=&amp;quot;Terminal window&amp;quot;
$ docker stack ps stalwart-mail
```

Below is an example Docker Compose file for deploying Stalwart on Docker Swarm. Hostnames, domains, and storage backends are configured through the bootstrap flow on first start rather than through dedicated environment variables; the container only needs the clustering variables to select the right role, and optionally STALWART\_RECOVERY\_ADMIN to pin a known administrator credential:

 以下是用於在 Docker Swarm 上部署 Stalwart 的範例 Docker Compose 檔案。主機名稱、網域和儲存後端在首次啟動時透過開機流程進行配置，而不是透過專用環境變數；容器只需要叢集變數來選擇正確的角色，並且可以選擇STALWART\_RECOVERY\_ADMIN來固定已知的管理員憑證來固定已知的管理員憑證：

```yaml
version: '3.8'

services:
  stalwart:
    image: stalwartlabs/stalwart:latest
    ports:
      - "25:25"      # SMTP
      - "465:465"    # SMTPS
      - "587:587"    # Submission
      - "143:143"    # IMAP
      - "993:993"    # IMAPS
      - "443:443"    # HTTPS
    environment:
      - STALWART_ROLE=frontend
      - STALWART_RECOVERY_ADMIN=admin:YOUR_SECURE_PASSWORD
    volumes:
      - mail_data:/var/lib/stalwart
      - mail_etc:/etc/stalwart
    deploy:
      replicas: 1
      placement:
        constraints:
          - node.role == manager
          - node.labels.mail == true
      resources:
        limits:
          cpus: "1"
          memory: 2G
        reservations:
          cpus: "0.5"
          memory: 1G
      restart_policy:
        condition: on-failure
        delay: 5s
        max_attempts: 3
        window: 120s
      update_config:
        parallelism: 1
        delay: 10s
        order: start-first
      labels:
        - "traefik.enable=true"
        - "traefik.http.routers.stalwart-admin.rule=Host(`mail-admin.example.com`)"
        - "traefik.http.routers.stalwart-admin.service=stalwart-admin"
        - "traefik.http.services.stalwart-admin.loadbalancer.server.port=8080"
        - "traefik.http.routers.stalwart-jmap.rule=Host(`mail.example.com`) && PathPrefix(`/jmap`)"
        - "traefik.http.routers.stalwart-jmap.service=stalwart-jmap"
        - "traefik.http.services.stalwart-jmap.loadbalancer.server.port=8000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 1m
      timeout: 10s
      retries: 3
      start_period: 40s
    networks:
      - mail_network

volumes:
  mail_data:
    driver: local
    driver_opts:
      type: "nfs"
      o: "addr=nfs-server,nolock,soft,rw"
      device: ":/path/to/mail/data"
  mail_etc:
    driver: local

networks:
  mail_network:
    driver: overlay
    attachable: true
    driver_opts:
      encrypted: "true"
```

`STALWART_ROLE` names the ClusterRole the instance adopts. On first start the container enters bootstrap mode on port `8080`; domains, storage backend, and the remaining system settings are supplied through the WebUI or a declarative deployment and persisted to the shared data store, so subsequent replicas pick the same configuration up automatically. Pin a push-notification shard with STALWART\_PUSH\_SHARD when the role performs push delivery.

`STALWART_ROLE`指定實例所採用的 ClusterRole 。首次啟動時，容器在連接埠`8080`上進入開機模式；網域、儲存後端和其餘系統設定透過 WebUI 或 聲明式部署提供，並持久化到共用資料存儲，以便後續副本自動取得相同的配置。當角色執行推播通知時，使用 STALWART\_PUSH\_SHARD固定推播通知分片。
