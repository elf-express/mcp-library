# Azure Blob Storage｜Azure Blob 儲存

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[storage｜貯存\\\]\\\(&lt;000 目錄.md#c-72&gt;\\\) › \\\[backends｜後端\\\]\\\(&lt;000 目錄.md#c-73&gt;\\\)

For distributed and larger-scale deployments, Stalwart supports Azure Blob Storage as a blob store. Azure Blob Storage is a cloud-based object storage service designed for scalable storage of unstructured data, and is well suited to large-scale storage management, replication, and backup of email bodies, Sieve scripts, and other blobs.

 對於分散式和大規模部署，Stalwart 支援使用 Azure Blob 儲存體作為 Blob 儲存體。 Azure Blob 儲存體是一種基於雲端的物件儲存服務，專為可擴充地儲存非結構化資料而設計，非常適合大規模儲存管理、複製和備份電子郵件正文、Sieve 腳本和其他 Blob 資料。

## Configuration｜配置

 The Azure backend is selected by choosing the `Azure` variant on the BlobStore object \(found in the WebUI under Settings › Storage › Blob Store\). The variant exposes the following fields:

 透過在 BlobStore物件上選擇`Azure`變體（可在 WebUI 的「設定」&gt;「儲存」&gt;「Blob 儲存體」下找到）來選擇 Azure 後端。該變體公開以下欄位：

- storageAccount: the Azure Storage Account used to hold blobs \(required\).
storageAccount : 用於保存 Blob 的 Azure 儲存帳戶（必要）。
- container: the container within the Storage Account where blobs are stored \(required\).
container : 儲存帳戶中儲存 blob 的容器（必需）。
- accessKey: the access key for the Storage Account \(required\). The secret may be supplied inline, read from an environment variable, or loaded from a file.
accessKey : 儲存帳戶的存取金鑰（必需）。密鑰可以內聯提供、從環境變數讀取或從檔案載入。
- sasToken: shared access signature token, used instead of an access key for SAS-based authentication.
sasToken : 共用存取簽章令牌，用於取代基於SAS驗證的存取金鑰。
- timeout: maximum time to wait for a response from the Azure service. Default: `"30s"`.
timeout : 等待 Azure 服務回應的最長時間。預設值： `"30s"` 。
- maxRetries: maximum number of retries for a failed operation. Default: `3`.
maxRetries : 失敗操作的最大重試次數。預設值： `3` 。
- keyPrefix: optional prefix prepended to every object key, useful for organising or segregating data within a container.
keyPrefix : 可選前綴，在加入每個物件鍵之前，用於組織或隔離容器內的資料。
