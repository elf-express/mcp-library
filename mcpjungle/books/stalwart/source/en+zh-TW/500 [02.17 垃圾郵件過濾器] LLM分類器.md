# LLM classifier｜LLM分類器

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[spamfilter｜垃圾郵件過濾器\\\]\\\(&lt;000 目錄.md#c-69&gt;\\\)

The LLM classifier extends Stalwart’s spam filtering by using a large language model to detect unsolicited, commercial, or harmful messages. It integrates with any configured AI model and analyses message subjects and bodies through natural language processing, complementing the statistical classifier with higher-level semantic reasoning.

 LLM分類器透過使用大型語言模型來偵測未經請求的、商業性的或有害的訊息，從而擴展了 Stalwart 的垃圾郵件過濾功能。它可以與任何已配置的 AI模型集成，並透過自然語言處理分析訊息主題和正文，以更高層次的語義推理來補充統計分類器。

 The LLM classifier sends a customisable prompt to the AI model, along with the subject and body of the message. The default prompt asks the model to assign one of four categories \(Unsolicited, Commercial, Harmful, or Legitimate\) and a confidence level \(High, Medium, or Low\). The returned category and confidence are combined into a tag, which is assigned to the message and contributes to the overall spam score through the Scores configuration. For example, `LLM_UNSOLICITED_HIGH` carries a default score of 3.0, while `LLM_LEGITIMATE_HIGH` carries −3.0.

 LLM分類器會向AI模型發送一個可自訂的提示訊息，以及郵件的主題和正文。預設提示訊息要求模型將郵件歸類為四個類別之一（垃圾郵件、商業郵件、有害郵件或合法郵件），並指定一個置信度等級（高、中或低）。傳回的類別和置信度會被組合成一個標籤，該標籤會被指派給郵件，並透過 Scores項目計入郵件的整體垃圾郵件評分。例如， `LLM_UNSOLICITED_HIGH`預設評分為3.0 ，而`LLM_LEGITIMATE_HIGH`預設評分為 − 3.0 。

 This feature is available exclusively in the Enterprise Edition of Stalwart and is not included in the Community Edition.

 此功能僅在 Stalwart 的 企業版中提供，社群版不包含此功能。

## Caveats｜注意事項

 Integrating an LLM into spam filtering has performance and cost implications, especially under high message volumes.

 將LLM整合到垃圾郵件過濾中會對效能和成本產生影響，尤其是在郵件量較大的情況下。

### Performance considerations｜性能考量

 When self-hosting AI models, throughput depends heavily on the hardware. Without dedicated hardware \(in particular GPUs designed for machine-learning workloads\), classifying every message with the LLM can introduce significant latency, because each call runs a substantial inference workload. CPU-only deployments in particular may see email intake slow down noticeably. Sites that self-host should ensure they have hardware headroom, preferably with GPU acceleration, before enabling the LLM classifier in production.

 自託管AI模型時，吞吐量很大程度取決於硬體。如果沒有專用硬體（特別是專為機器學習工作負載設計的 GPU），使用LLM對每封郵件進行分類可能會引入顯著的延遲，因為每次呼叫都會運行大量的推理工作負載。特別是僅部署CPU的場景，郵件接收速度可能會明顯下降。自託管的網站應確保其硬體資源充足，最好配備GPU加速器，然後再在生產環境中啟用LLM分類器。

### Cost implications｜成本影響

 For cloud-hosted AI models \(such as those offered by OpenAI or Anthropic\), the primary concern is cost rather than latency. Providers typically charge per token processed. Each message submitted to the model consumes tokens in proportion to the subject, body, and returned response, so costs scale with message volume. Sites using cloud-based models should estimate usage against the provider’s pricing before enabling the LLM classifier on high-traffic servers.

 對於雲端託管的AI模型（例如OpenAI或Anthropic提供的模型），主要考慮因素是成本而非延遲。服務提供者通常按處理的令牌數量收費。提交給模型的每個訊息都會消耗令牌，令牌數量與主題、正文和傳回的回應成正比，因此成本會隨著訊息量的增加而增加。使用雲端模型的網站在啟用高流量伺服器上的LLM分類器之前，應根據服務供應商的定價估算使用量。

 In either case there is a trade-off between performance, cost, and the incremental accuracy the LLM adds over the statistical classifier.

 無論哪種情況，性能、成本和LLM相對於統計分類器增加的增量準確度之間都存在權衡。

## Configuration｜配置

 The LLM classifier is configured on the SpamLlm singleton \(found in the WebUI under Settings › Spam Filter › LLM Classifier\). SpamLlm is a multi-variant object: the `Disable` variant turns the classifier off \(the default\), and the `Enable` variant activates it and carries the configuration fields.

 LLM分類器配置在 SpamLlm單例物件上（可在 WebUI 的「設定」&gt;「垃圾郵件過濾器」&gt; LLM分類器」中找到）。 SpamLlm 是一個多變體物件： `Disable`變體關閉分類器（預設設定）， `Enable`變體啟動分類器並包含配置欄位。

### Model｜模型

 The `Enable` variant requires an modelId field referring to an AiModel object. For example, to use an AI model with id `chat`:

`Enable`變體需要一個 modelId字段，該字段指向一個 AiModel物件。例如，要使用 id 為`chat`的AI模型：

```json
{
  "@type": "Enable",
  "modelId": "chat"
}
```

### Prompt｜迅速的

 The prompt field carries the instructions sent to the AI model alongside each message. Administrators can rewrite the prompt to match local classification needs, for example:

 prompt欄位包含隨每個訊息一起傳送給AI模型的指令。管理員可以根據本機分類需求重寫提示，例如：

```json
{
  "@type": "Enable",
  "modelId": "chat",
  "prompt": "You are an AI assistant specialized in analyzing email content to detect unsolicited, commercial, or harmful messages. Your task is to examine the provided email, including its subject line, and determine if it falls into any of these categories. Please follow these steps:\n\n- Carefully read the entire email content, including the subject line.\n- Look for indicators of unsolicited messages, such as:\n   * Lack of prior relationship or consent\n   * Mass-mailing characteristics\n   * Vague or misleading sender information\n- Identify commercial content by checking for:\n   * Promotional language\n   * Product or service offerings\n   * Call-to-action for purchases\n- Detect potentially harmful content by searching for:\n   * Phishing attempts (requests for personal information, suspicious links)\n   * Malware indicators (suspicious attachments, urgent calls to action)\n   * Scams or fraudulent schemes\n- Analyze the overall tone, intent, and legitimacy of the email.\n- Determine the most appropriate single category for the email: Unsolicited, Commercial, Harmful, or Legitimate.\n- Assess your confidence level in this determination: High, Medium, or Low.\n- Provide a brief explanation for your determination.\n- Format your response as follows, separated by commas: Category,Confidence,Explanation\n  * Example: Unsolicited,High,The email contains mass-mailing characteristics without any prior relationship context.\n\nHere's the email to analyze, please provide your analysis based on the above instructions, ensuring your response is in the specified comma-separated format:"
}
```

### Temperature｜溫度

 The temperature field sets the sampling temperature used by the AI model. Lower values produce more deterministic responses, higher values introduce more variation. The default is `0.5`, which balances diversity and coherence.

 temperature字段設定AI模型使用的取樣溫度。較低的值會產生更確定性的反應，較高的值會引入更多變化。預設值為`0.5` ，它平衡了多樣性和一致性。

### Responses｜回覆

 Response parsing extracts the category, confidence level, and explanation from the AI model’s output. The category and confidence are concatenated with an underscore to form the tag assigned to the message; for example, an Unsolicited classification with High confidence produces the tag `LLM_UNSOLICITED_HIGH`.

 響應解析從AI模型的輸出中提取類別、置信度和解釋。類別和置信度用下劃線連接起來，形成分配給訊息的標籤；例如，置信度為高的非請求分類會產生標籤`LLM_UNSOLICITED_HIGH` 。

 The relevant fields are:

 相關欄位包括：

- separator: the character used to split the AI model’s response into fields. Default `,`.
separator : 用於將AI模型的回應拆分為字段的字元。預設值為`,` 。
- responsePosCategory: zero-based index of the category in the response. Default `0`.
responsePosCategory : 回應中類別的從零開始的索引。預設值為`0` 。
- responsePosConfidence: zero-based index of the confidence in the response. Default `1`.
responsePosConfidence : 響應置信度的從零開始的索引。預設值為`1` 。
- responsePosExplanation: zero-based index of the explanation in the response. Default `2`.
responsePosExplanation : 回應中解釋的從零開始的指標。預設值為`2` 。
- categories: accepted category labels. Responses outside this set are ignored. Default `{"Unsolicited": true, "Commercial": true, "Harmful": true, "Legitimate": true}`.
categories : 已接受的類別標籤。此集合之外的回應將被忽略。預設值為`{"Unsolicited": true, "Commercial": true, "Harmful": true, "Legitimate": true}` 。
- confidence: accepted confidence labels. Responses outside this set are ignored. Default `{"High": true, "Medium": true, "Low": true}`.
confidence : 已接受的置信度標籤。此集合之外的回應將被忽略。預設值為`{"High": true, "Medium": true, "Low": true}` 。
Example showing the defaults explicitly:
 範例明確展示了預設值：

```json
{
  "@type": "Enable",
  "modelId": "chat",
  "separator": ",",
  "categories": {"Unsolicited": true, "Commercial": true, "Harmful": true, "Legitimate": true},
  "confidence": {"High": true, "Medium": true, "Low": true},
  "responsePosCategory": 0,
  "responsePosConfidence": 1,
  "responsePosExplanation": 2
}
```

### Headers｜標題

 When the LLM classifier is enabled, the `X-Spam-LLM` header is added to each analysed message and reports the category, confidence, and explanation returned by the AI model. The header is added unconditionally under its fixed name.

 啟用LLM分類器後， `X-Spam-LLM`標頭會加入到每個分析的訊息中，並報告AI模型傳回的類別、置信度和解釋。此標頭會以其固定名稱無條件添加。
