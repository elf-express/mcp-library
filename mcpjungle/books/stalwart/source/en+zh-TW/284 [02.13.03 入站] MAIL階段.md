# MAIL stage｜MAIL階段

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[mta｜捷運\\\]\\\(&lt;000 目錄.md#c-47&gt;\\\) › \\\[inbound｜入站\\\]\\\(&lt;000 目錄.md#c-51&gt;\\\)

The `MAIL FROM` command initiates an SMTP message transfer by identifying the sender of the message. After the command is issued, the receiving mail server validates the sender address and checks whether the sender is authorised to send messages on behalf of that domain. If valid, the transaction proceeds to the `RCPT TO` stage.

`MAIL FROM`指令透過識別郵件發送者來啟動SMTP郵件傳輸。發出該命令後，接收郵件伺服器會驗證發送者位址，並檢查發送者是否被授權代表該網域發送郵件。如果有效，則事務進入`RCPT TO`階段。

 MAIL-stage behaviour is configured on the MtaStageMail singleton \(found in the WebUI under Settings › MTA › Session › MAIL FROM Stage\).

 MAIL -階段行為在 MtaStageMail單例上配置（在 WebUI 的設定 › MTA › 會話 › MAIL FROM階段下找到）。

## Address rewriting｜地址重寫

 The rewrite field accepts an expression that can modify the sender address. This is useful for obfuscating the sender for privacy, or for changing the domain to match organisational branding. For background on the expression-based rewrite model see the address rewriting documentation.

 rewrite欄位接受一個可以修改寄件者地址的表達式。這對於出於隱私目的混淆發件人身份，或更改網域名稱以匹配組織品牌標識非常有用。有關基於表達式的重寫模型的背景信息，請參閱 地址重寫文檔。

 For example, the following configuration removes any subdomain from the sender address on non-SMTP listeners:

 例如，下列設定會從非SMTP監聽器的寄件者位址中刪除所有子網域：

```json
{
  "rewrite": {
    "match": {"0": {"if": "listener != 'smtp' & matches('^([^.]+)@([^.]+)\\.(.+)$', rcpt)", "then": "$1 + '@' + $3"}},
    "else": "false"
  }
}
```

The backslash in the regex is doubled because the expression is shown inside a JSON document; in an expression field in the WebUI it is written once, as `\.`. See escaping backslashes.

 正規表示式中的反斜線被重複出現，因為該表達式顯示在JSON文件中；在 WebUI 的表達式欄位中，它只寫一次，即`\.` 。參見 轉義反斜線 。

## Allowed senders｜允許的寄件者

 The isSenderAllowed field accepts an expression that determines whether the sender is accepted. If the expression evaluates to `false`, the sender is rejected. The default policy allows the sender when authenticated or when the sender domain is not present in the `spam-block` list.

 isSenderAllowed欄位接受一個表達式，用於確定是否接受寄件者。若表達式的計算結果為`false` ，則拒絕寄件者。預設策略允許已通過身份驗證的寄件人，或當寄件人網域不在`spam-block`清單中時，允許寄件者通過身分驗證。

 For example, to block domains present in the `spam-block` list:

 例如，要封鎖`spam-block`清單中的網域：

```json
{
  "isSenderAllowed": {"else": "!key_exists('spam-block', sender_domain)"}
}
```

## Sieve script｜篩選腳本

 The script field selects a Sieve script to run after a successful `MAIL FROM` command. Typical uses include rejecting specific senders or rewriting the sender address using the `envelope` Sieve extension.

 script欄位用於選擇在`MAIL FROM`指令成功執行後要執行的 Sieve 腳本 。典型用途包括拒絕特定寄件者或使用`envelope` Sieve 擴充重寫寄件者地址。

 For example, setting script to the expression `"'return_path_filter'"` runs a Sieve script named `return_path_filter` which can reject messages whose return path matches a known-bad local part:

 例如，將 script設定為表達式`"'return_path_filter'"`會執行一個名為`return_path_filter`的 Sieve 腳本，該腳本可以拒絕返迴路徑與已知錯誤本地部分相符的訊息：

```sieve
require ["variables", "envelope", "reject"];

if envelope :localpart :is "from" "known_spammer" {
    reject "Messages from this sender are not accepted.";
}
```
