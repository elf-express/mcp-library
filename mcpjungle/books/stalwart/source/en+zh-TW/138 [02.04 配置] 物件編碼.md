# Object encoding｜物件編碼

> 章節：\\\[docs｜文件\\\]\\\(&lt;000 目錄.md#c-2&gt;\\\) › \\\[configuration｜配置\\\]\\\(&lt;000 目錄.md#c-18&gt;\\\)

Configuration objects are stored in the database and written through the JMAP API, either by the WebUI, by the CLI, or by a direct API call. The schema reference documents the fields of every object; this page describes how their values are encoded as JSON.

 配置物件儲存在資料庫中，並透過JMAP API寫入，可以透過 WebUI 、CLI或直接呼叫API來實現。 模式參考記錄了每個物件的欄位；本頁描述了它們的值是如何編碼的，如JSON所示。

 Operators using the WebUI never encounter this: the forms produce the correct payload. It matters when writing a plan for stalwart-cli apply or calling a `Foo/set` method directly, because the encoding differs from ordinary JSON conventions in three respects. A payload that gets any of them wrong is rejected with an error naming the offending property:

 使用 WebUI 的操作人員永遠不會遇到這種情況：表單會產生正確的有效負載。這在編寫 stalwart-cli apply的計劃或直接呼叫`Foo/set`方法時至關重要，因為其編碼與普通的JSON約定在三個方面有所不同。如果有效負載中任何一個方面出錯，都會被拒絕，並傳回一個錯誤訊息，指出出錯的屬性：

```
invalidPatch | Invalid value for object property | Properties: retry/intervals
```

## Lists｜清單

 An ordered list is a JSON object whose keys are the stringified position, starting at `"0"`, rather than a JSON array. The retry intervals of an MtaDeliverySchedule are written as:

 有序列表是一個JSON對象，其鍵是字串化的位置，從`"0"`開始，而不是一個JSON數組。 MtaDeliverySchedule的重試間隔寫法如下：

```json
{
  "intervals": {
    "0": {"duration": 120000},
    "1": {"duration": 300000}
  }
}
```

The keys determine the order in which entries are evaluated. Fields of this kind appear as `List<T>` on the object reference pages.

 鍵決定了條目的評估順序。此類欄位在物件參考頁面上顯示為`List<T>` 。

## Sets｜套

 A set is a JSON object mapping each member to `true`, again not a JSON array. The listen addresses of a NetworkListener are written as:

 集合是一個JSON對象，它將每個成員映射到`true` ，而不是JSON數組。 NetworkListener的監聽位址寫法如下：

```json
{
  "bind": {"[::]:993": true, "127.0.0.1:993": true}
}
```

An empty set is `{}`. Fields of this kind appear as `Set<T>` on the object reference pages.

 空集為`{}` 。此類欄位在物件參考頁面上顯示為`Set<T>` 。

 Genuine key-value maps, which appear as `Map<K, V>`, keep their natural JSON object form and are unaffected. The `httpHeaders` field of an AiModel, for example, maps a header name to its value.

 真正的鍵值映射（顯示為`Map<K, V>` ）保持其自然的JSON物件形式，不受影響。例如，AiModel的`httpHeaders`欄位將標頭名稱對應到其值。

## Durations and sizes｜持續時間和大小

 A duration is an integer count of milliseconds, and a size is an integer count of bytes. Neither accepts a string:

 持續時間以毫秒為單位，大小以位元組為單位。兩者都不接受字串：

```json
{
  "maxAge": 604800000,
  "maxSize": 104857600
}
```

The values above are seven days and 100 MB. Reference pages show the type as `Duration` or `Size` and give defaults in the same integer form.

 上述數值為七天和 100 MB 。參考頁面顯示類型為`Duration`或`Size` ，並以相同的整數形式給出預設值。

 The stalwart-cli get command renders durations in a readable two-unit form \(`2 m`, `1 h 30 m`\) when printing an object for a human reader. That formatting applies to output only; the stored value, and the value accepted on input, is the integer.

 stalwart-cli get指令在為人類讀者列印物件時，會將持續時間以易於閱讀的雙單位形式 \( `2 m`, `1 h 30 m` \) 呈現。此格式僅適用於輸出；儲存的值以及輸入的值均為整數。

## Confirming the encoding｜確認編碼

 The most reliable way to see the canonical encoding of an object is to take a snapshot of a configured system, which prints exactly what the server itself produces:

 查看物件規範編碼最可靠的方法是對已配置的系統進行快照，快照會列印出伺服器本身產生的內容：

```bash title=&amp;quot;Terminal window&amp;quot;
stalwart-cli snapshot MtaDeliverySchedule
```

The example plan linked from the apply documentation shows the same encoding across several object types.

 從 apply文件連結的範例計畫顯示，幾種物件類型採用相同的編碼。
