# Add a login provider

> 章節：[data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-1>) › [portabase/portabase1.8K120](<000 目錄.md#c-2>) › [CLI](<000 目錄.md#c-29>) › [Introduction](<000 目錄.md#c-30>) › [Guides](<000 目錄.md#c-31>)

CLIGuides


Enable single sign-on (OIDC or OAuth) on a dashboard with the CLI.

At the end of this guide, users can log in to your dashboard with your identity provider.

**Prerequisites:** a [dashboard](<092 [01.01.04.01.01 Guides] Set up a dashboard.md>) served on a public URL (not `localhost`), and a client ID / secret from your provider — see [OIDC setup](<015 [01.01.02.01.01.01.01.01.01.01 OIDC Configuration] OIDC Configuration.md>) or [OAuth2 setup](<019 [01.01.02.01.01.01.01.01.02.01 OAuth2 Configuration] OAuth2 Configuration.md>).

### [Set the public URL](#set-the-public-url)

```
portabase dashboard set ./my-dashboard url https://backup.example.com
```

### [Add the provider](#add-the-provider)

```
printf '%s\n' "$KEYCLOAK_SECRET" | portabase dashboard auth add ./my-dashboard oidc keycloak \
  --issuer https://sso.example.com/realms/main \
  --client portabase --secret-stdin \
  --title "Company SSO" --scopes "openid profile email" --pkce
```

For OAuth (Google, GitHub…), use `oauth <provider>` and drop `--issuer`.

### [Register the callback URL](#register-the-callback-url)

The CLI prints the callback URL. Add it to your provider's allowed redirect URIs.

### [Restart and test](#restart-and-test)

```
portabase restart ./my-dashboard
```

The login page now shows a **Company SSO** button.
