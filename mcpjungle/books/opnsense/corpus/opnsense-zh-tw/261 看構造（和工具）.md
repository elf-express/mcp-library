# 看構造（和工具）

儘管我們的大部分程式碼庫都是在伺服器端處理的，但有些事情只需要在客戶端電腦上進行互動即可獲得流暢的使用者體驗。

在本章中，我們將嘗試解釋設計頁面時使用的一些元件以及頁面通常是如何建構的。

## 佈局

為了方便閱讀伏特模板，我們建議在建立模板時使用固定佈局。我們渲染頁面的基礎始終包含標準[佈局](https://github.com/opnsense/core/blob/master/src/opnsense/mvc/app/views/layouts/default.volt)，它透過我們的標準前端控制器掛鉤。

您將在下面找到這些部分及其順序，我們將對其進行簡要描述。

```
{#
  {1} Copyright notice
#}
<script>
$( document ).ready(function() {
  {2} UI code
});
</script>
{3} page html
{{ partial("layout_partials/base_dialog",...)}}  {4} dialog forms (see getForm())
```

1.  版權所有塊，第 2 條BSD，作者位於頂部
    
2.  屬於該頁面的Javascript程式碼
    
3.  HTML 程式碼，通常以一些 `<div>` 容器開始，並使用標準 Bootstrap 3 佈局
    
4.  當使用表單時，它們被放在最後，這些將作為標準html程式碼產生給客戶端
    

## ajax調用

`ajaxCall(url, sendData, callback)` 是 jQuery 的 `$.ajax` 呼叫的包裝器，預設為 `POST` 類型請求，並將 sendData 包裝到 json 物件中。將使用從端點接收到的資料和狀態來呼叫`callback`函數。

用法範例

```
ajaxCall('/api/monit/status/get/xml', {}, function(data, status) {
    console.log(data)
});
```

## ajax獲取

`ajaxGet(url,sendData,callback)` 也是 jQuery 的 `$.ajax` 呼叫的包裝器，但用於 `GET` 類型請求。

用法範例

```
ajaxGet('/api/diagnostics/interface/getInterfaceNames', {}, function(data, status) {
    console.log(data);
});
```

## 將資料映射到FormUI

`mapDataToFormUI(data_get_map, server_params)` 可用於將從控制器擷取的資料對應到瀏覽器中的表單。

函數接受兩個參數，data\_get\_map 包含表單 id 和伺服器端點之間的映射，server\_params 是可選的，可用於在 `GET` 類型請求中設定選項。

當端點被成功呼叫時，它應該會傳回一個包含專案路徑的 json 類型結構，例如使用 `data_get_map = {'myform': '/api/path/to/formdata'};`：

```
{
  "netflow": {
    "capture": {
      "interfaces": {
        "lan": {
          "value": "LAN",
          "selected": 1
        },
        "wan": {
          "value": "WAN",
          "selected": 0
        }
      },
    },
    "collect": {
      "enable": "1"
    }
  }
}
```

它映射到這個簡化結構中的字段（通常透過我們的 volt 模板呈現）：

```xml
<form id="myform">
    <select multiple="multiple" id="netflow.capture.interfaces">
    </select>
    <input type="checkbox" id="netflow.collect.enable">
</form>
```

該函數傳回一個`$.Deferred()`，當所有端點被呼叫時，它將被解析。

## 儲存表單到端點

`saveFormToEndpoint(url, formid, callback_ok, disable_dialog, callback_fail)` 與 `mapDataToFormUI()` 相反，從表單中檢索資料並將其作為 json 結構發送到配置的 (url) 端點。此函數底層使用 opnsense.js 中定義的 `getFormData(parent)` ，它負責從不同的表單類型（例如 `<input>` 和 `<select>` 類型）中提取值。當屬性應該是型別安全的時（例如，json 格式的 *integer* 應表示為 `1` 而不是 `"1"`），可以先使用過濾器「清理」資料。在本例中，在輸入標記上定義一個名為 `type_formatter` 的屬性，其中包含要呼叫的函數。

```xml
<input type="text" type_formatter="my_convert_to_int_function" id="myform.myintval">
```

可以用 javascript 的形式實現：

```js
function my_convert_to_int_function(payload)
{
    if (/^[+-]?[0-9]*$/.test(payload)) {
        return  parseInt(payload);
    } else {
        return payload;
    }
}
```

回應資料看起來與 mapDataToFormUI 中的範例資料類似，但更簡潔，因為選擇將作為單一（分隔）值傳回，例如 `lan,wan`（如果設定了兩個選項）。

使用上面函數的範例，一個有效的整數將提供類似於`{"myform": {"myintval": 1}}`的json對象，不可解析的數據將類似於`{"myform": {"myintval": "1x"}}`，在這種情況下後端驗證能夠反饋驗證結果。

## 更新服務控制UI

`updateServiceControlUI(serviceName)` 函數將服務控制項掛接到標準範本之上，您可以在其中找到服務的\[重新\]啟動、停止和狀態。

它假設模組存在以下端點：

-   /api/{{serviceName}}/service/status
    
    -   在名為「status」的欄位中傳回服務的狀態（正在執行、已停止）
        
    
-   /api/{{serviceName}}/service/start
    
    -   啟動服務
        
    
-   /api/{{serviceName}}/service/restart
    
    -   重新啟動服務
        
    
-   /api/{{serviceName}}/service/stop
    
    -   停止服務
        
    

## 對話框包裝器

我們使用 [BootstrapDialog](https://nakupanda.github.io/bootstrap3-dialog/) 來顯示標準對話框，為了限制顯示這些對話框所需的樣板，我們加入了以下包裝函數：

### stdDialogInform(標題、訊息、關閉、回呼、類型、cssClass)

帶有單一關閉按鈕的資訊對話框，使用以下參數：

-   title: `string` 對話框標題
    
-   訊息：`string`對話訊息
    
-   關閉：`string`關閉按鈕文字
    
-   回調：關閉後呼叫`function()`
    
-   類型：`string`對話框類型。以下之一：危險、預設、訊息、主要、成功、警告
    
-   cssClass：要使用的`string` css 類
    

### stdDialogConfirm(標題、訊息、接受、拒絕、回呼、類型)

使用以下參數的確定/取消對話框類型：

-   title: `string` 對話框標題
    
-   訊息：`string`對話訊息
    
-   接受：`string`接受按鈕文字
    
-   拒絕：`string`拒絕按鈕文字
    
-   回呼：關閉後呼叫`function()`
    
-   類型：`string`對話框類型。以下之一：危險、預設、訊息、主要、成功、警告
    

### stdDialogRemoveItem（訊息，回呼）

簡單的刪除項目（警告）對話框，使用訊息和可選的回呼。

## $.SimpleActionButton

使用 jQuery 擴充功能`SimpleActionButton`，可以在元件點擊事件上註冊簡單的 ajax 調用，這將調用選定的端點並向使用者顯示進度動畫（旋轉器）。

可以提供以下參數作為目標物件的資料屬性：

-   端點：要呼叫的端點（例如`/api/my/action`）
    
-   label：按鈕標籤文字
    
-   service-widget：執行後刷新的服務widget，請參閱`updateServiceControlUI()`
    
-   error-title: 錯誤對話框標題
    

此方法本身可以提供回調，以便在執行之前 (`onPreAction()`) 和執行之後 (`onAction()`) 呼叫。

按鈕的範例如下所示：

```xml
<button class="btn btn-primary" id="reconfigureAct"
        data-endpoint='/api/component/service/reconfigure'
        data-label="{{ lang._('Apply') }}"
        data-service-widget="component"
        data-error-title="{{ lang._('Error reconfiguring component') }}"
        type="button"
></button>
```

要利用回調，可以使用：

```
$('#btnTest').SimpleActionButton({
    onPreAction: function() {
        const dfObj = new $.Deferred();
        console.log("called before endpoint execution, returning a promise.");
        return dfObj;
    },
    onAction: function(data, status){
        console.log("action has been executed.");
    }
});
```

如果出現提示，`SimpleActionButton`也會提醒使用者儲存設定。為此，只需撥打`$(document).trigger("settings-changed");`即可。

## $.SimpleFileUploadDlg

簡單的檔案上傳對話方塊可用於選擇檔案並將其上傳到指定的端點。

若要定義將資料傳送至 /api/path/to/import\_controller 的按鈕，可以使用下列程式碼：

```html
<button
    id="upload"
    type="button"
    data-title="Import"
    data-endpoint='/api/path/to/import_controller'
    class="btn btn-xs"
><span class="fa fa-fw fa-table"></span></button>
```

注意事項

這個`POST`的結構包含一個`payload`和一個`filename`屬性。

可以使用以下命令來初始化此按鈕：

```
$("#upload").SimpleFileUploadDlg();
```

提示

`SimpleFileUploadDlg` 操作支援類似於 `$.SimpleActionButton` 中所述的 `onAction` 處理程序
