# 故障排除




有時，即使您已做好充分的準備工作，仍會出現問題。通常，檢查日誌（系統 ‣ 日誌檔案或您嘗試設定的模組中的日誌檔案）總是有益的，但有時還需要更多幫助。

## 一般問題工作流程

在報告問題之前，請確保您的問題在最新版本中仍然存在。我們通常建議您在報告新問題之前，先查看現有的問題清單（ (https://github.com/opnsense/core/issues) ）和我們的論壇（ (https://forum.opnsense.org/) ）。

如果您的問題是在（小）升級後引入的，您可以使用 [opnsense-revert](<75 OPNsense 工具.md#opnsense-revert>)降級系統上安裝的特定軟體包。

使用韌體部分（系統 ‣ 韌體 ‣ 狀態），您可以對系統執行運行狀況檢查，狀態概述的底部是一個名為 **運行審核**的按鈕，可以將其展開以提供**運行狀況** 選擇。

點擊後會輸出類似以下內容：

```yaml
***GOT REQUEST TO AUDIT HEALTH***
>>> Check installed kernel version
Version 19.7.3 is correct.
>>> Check for missing or altered kernel files
No problems detected.
>>> Check installed base version
Version 19.7.3 is correct.
>>> Check for missing or altered base files
No problems detected.
>>> Check for and install missing package dependencies
Checking all packages: .......... done
>>> Check for missing or altered package files
Checking all packages: ....
opnsense-19.7.4_1: checksum mismatch for /usr/local/etc/inc/auth.inc
Checking all packages...
Checking all packages......... done
***DONE***
```

當報告不符時，您可以在韌體螢幕的 **Packages** 部分重新安裝受影響的軟體包。在上述情況下，您需要重新安裝 opnsense，因為 `auth.inc` 看起來已被污染。

注意事項

如果健康檢查似乎報告了問題，我們建議在 GitHub 上建立錯誤報告時，附上健康檢查的輸出結果。

提示

在提交問題報告時，無論是關於疑似 bug 或功能請求，務必盡量做到精準，清晰地表達意圖至關重要。我們的 GitHub 程式碼庫使用範本來引導您完成提交，請您務必使用這些範本（未使用範本提交的問題將被視為低優先級問題）。
