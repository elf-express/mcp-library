# 15.7 “勇敢的獾”系列

雖然盛夏酷暑，我們依然奮力前行，最終呈現出了現在呈現在您眼前的15.7暱稱“勇敢的獾”。過去六個月裡，我們為這個計畫投入了大量心血，我們敢說，一切付出都是值得的。我們衷心感謝所有追蹤者、朋友、回饋者、論壇潛水員、貢獻者、質疑者和支持者，是你們的幫助成就了今天的15.7 。沒有你們，就沒有今天的我們。謝謝！

就其本身而言，15.7是我們推薦給大家的15.1.12的簡單升級。變化在於，開發將轉移到不同的分支，因此從現在開始回歸的可能性較小，因此穩定性將進一步提高。所提供的圖像也可能是未來 6 個月內唯一的圖像，因為我們對其壽命和線上升級路徑充滿信心。我們還將 LibreSSL 風格提升至生產就緒狀態，並鼓勵每個人都嘗試一下。安裝程式的導入配置工具加上快速簡便的安裝可以幫助您無縫地從 OpenSSL 遷移到 LibreSSL 並返回。

此次更新最大的新增功能是入侵偵測整合（Suricata）以及代理伺服器（Squid）新增的本地和遠端黑名單選項。安全性方面，此次更新相對平靜，僅在第三方工具中發現了少量 CVE 漏洞。詳情及參考資料請參閱完整的更新日誌：

-   核心：從 m0n0wall 借用了一個虛擬網路/ipnat 補丁，以便在涉及NAT時啟用對稱流量整形。
    
-   核心：修復 tmpfs 與 unionfs 結合使用時出現的遞迴鎖恐慌問題
    
-   內核：應用了兩個穩定補丁，防止 Squid 崩潰 [\[1\]]( https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=195802 )
    
-   內核：已棄用ALTQ支持
    
-   基礎：sendmail TLS/DH互通性改進 [\[2\]]( https://www.freebsd.org/security/advisories/FreeBSD-EN-15:08.sendmail.asc )
    
-   基礎：改良的 iconv(3) UTF -7 支援 [\[3\]]( https://www.freebsd.org/security/advisories/FreeBSD-EN-15:10.iconv.asc )
    
-   基礎：區域設定和符文區域設定狀態不一致 [\[4\]]( https://www.freebsd.org/security/advisories/FreeBSD-EN-15:09.xlocale.asc )
    
-   值得關注的連接埠更新：phalcon 2.0.3 [\[5\]]( https://github.com/phalcon/cphalcon/releases/tag/phalcon-v2.0.3 ) , curl 7.43.0 \_2 [\[6\]]( https://curl.haxx.se/changes.html ) , openssh 2.7.10 [\[7\]]( https://hg.python.org/cpython/raw-file/15c95b7d81dc/Misc/NEWS ) , perl 5.20.2 \_5 [\[8\]]( https://perldoc.perl.org/5.20.2/perldelta ) , ntp 4.2 2.9.2 [\[9\lib http://www.eecis.udel.edu/~ntp/ntp_spool/ntp4/ChangeLog-stable [\[10\]]( https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2015-1819 ) , openldap 2.4.41 [\[11\]]( https://www.openldap.org/software/release/changes_lts.html )
    
-   opnsense-update：全新安裝後將不再嘗試重新安裝已安裝的版本
    
-   bsdinstaller：恢復 cpdup 在記憶體不足時報錯的安裝方式（你需要 1 個GB或RAM ，或使用 nano 鏡像進行安裝）
    
-   流量整形器：已移除對舊式佇列的支持，轉而使用新的流量整形器功能。
    
-   流量整形器：允許直接啟用/停用切換
    
-   代理：修復啟動時初始守護程式啟動問題
    
-   代理：已新增LAN作為預設介面配置
    
-   代理：支援正規表示式的本地和遠端黑名單
    
-   入侵偵測：我們基於 Suricata 的IDS GUI的初始版本發布
    
-   網關：監控模式新增 IPv6 支持
    
-   強制門戶：修復空閒逾時錯誤
    
-   強制門戶：存在多個配置時，請勿刪除錯誤的區域
    
-   強制入口網站：已從公開的 Web 目錄中移除包含文件
    
-   後端：始終重新產生使用者和群組，以避免在非正常關機後出現資料損壞。
    
-   後端：等待 configd 套接字啟動，解決啟動競爭問題
    
-   後端：退出時清理 configd 套接字
    
-   後端：修正了阻止使用者腳本透過 /etc/rc.conf 啟動的回歸問題。
    
-   網關：僅當為網關啟用監控時，才會在服務中顯示 apinger
    
-   語言：簡體中文完成度達 49%，德文完成度達 30%。
    
-   通用即插即用：將頁面呼叫設為靜態，以消除舊版軟體包框架的漏洞。
    
-   崩潰報告器：終於啟用了發送按鈕，並提供易於理解的回饋，告知提交是否完成。
    
-   shell：為無頭部署新增了非互動式介面分配
    
-   SSH：恢復出廠設定時停用密碼驗證，以與標準設定保持一致。
    
-   診斷：避免在NDP表格檢視中重複呼叫 gethostbyaddr()
    
-   使用者：更改密碼時提示輸入舊密碼，以防止帳號被盜用
    
-   使用者：由於該實用程式從未成為我們生態系統的一部分，因此已剝奪了不可能的 scponly 使用者權限。

## 15.7.22 （2015年12月9日）

OpenSSL 1.0 .2e 和 LibreSSL 2.2.5終於發布了！ 15.7.22本身只是一些調整和小修復。過去一周沒有收到「菜單怎麼了」之類的抱怨，這真是個好兆頭。也沒人懷念RRD圖表。你們真是太棒了！

之前在15.7.19中提到的過濾器重載逾時問題的根本原因終於找到了。函數 `filter_generate_optcfg_array()` 在一次過濾器重載過程中可能會被呼叫數百次，而它只向呼叫者提供靜態介面數據，這些數據在重載運行時不會發生變化。在某個時間點，該函數的運行速度可能變得非常緩慢，因此在函數周圍添加了快取機制，導致函數的輸出卡住，從而引發了最初的錯誤報告。現在，該函數的運行速度已經恢復正常，並且沒有任何故障。
