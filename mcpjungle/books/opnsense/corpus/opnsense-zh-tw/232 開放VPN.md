# 開放VPN

## 分配的介面

雖然不是絕對必要，但可以為 OpenVPN 伺服器和用戶端分配單獨的介面。然而，這樣做可能會產生防火牆規則的意外行為。最值得注意的是，預設情況下，在 OpenVPN Roadwarrior 伺服器的指定介面上建立的規則是使用 `reply-to` 指令建立的，這會中斷客戶端連線。

提示

在上述情況下，可以觀察到傳入流量匹配並通過相應的防火牆規則，但回覆流量永遠不會發送回連接的客戶端。這可以透過 Web GUI 進行驗證，方法是前往防火牆 -> 日誌檔案 -> 即時視圖，也可以選擇在受影響的介面上執行封包擷取。

有多種方法可以解決此問題。對於大多數設置，在系統 -> 網關 -> 配置下禁用自動建立的 IPv4 和 IPv6 網關就足夠了。這樣做也會停用將 `reply-to` 指令自動新增到介面上建立的規則中，並且客戶端連線將恢復。

另一種選擇是在指定介面上產生的每個防火牆規則上手動選擇「停用回覆」選項。詳情請參閱[規則](<137 規則.md>)。

第三個選項是完全禁用`reply-to`的生成，如[（進階）設定](<146 （進階）設定.md>)中所述。然而，此方法可能會破壞 Multi-WAN 設定。
