# 裝置

除了有線、無線和VPN介面之外，還有一些其他的虛擬介面以及一些其他的介面相關選項。這些選項位於「介面」‣「設備」下。本文檔將簡要介紹這些選項。

## 橋

橋接允許在不同的網路連接之間建立連接，允許網路 A 上發送到網路 B（兩個網路都連接到您的 OPNsense 設備）的流量通過此橋接到達網路 B。請注意，這不包括DHCP服務－這需要使用 [DHCP中繼](<192 DHCP.md#dhcrelay>)進行設定。

網橋的工作原理類似（二層）交換機，將流量從一個介面轉送到另一個介面。群播和廣播資料包總是會轉送到網橋中的所有介面。對於單播流量，網橋會學習哪些MAC位址與哪些介面關聯，並選擇性地轉送流量。

網橋可以設定為支援快速生成樹協定 (RPTP) (https://en.wikipedia.org/wiki/Spanning_Tree_Protocol) ( RSTP/RTP )，以防止網路拓撲中出現環路。這些選項位於配置的「進階」部分，包括以下設定：

|選項|說明 |
| --- | --- |
| 啟用 | 啟用（快速）生成樹協定 |
| 協議 | 要使用的協議，快速生成樹或常規生成樹 |
| STP介面 | 已啟用的介面 tith \[R\]STP ，來自橋接器中的介面 |
| 有效時間（最大期限）| 設定生成樹協定配置的有效時間。預設值為 20 秒。 |
| 轉送延遲 (fwddelay) | 設定啟用生成樹協定後，介面開始轉送封包之前必須經過的延遲時間。預設值為 15 秒。 |
| 保持計數 (holdcnt) | 設定生成樹協定的傳送保持計數。這是在速率受到限制之前可以發送的資料包數量。預設值為 6。最小值為 1，最大值為 10。

螢幕底部還提供其他進階選項，包括以下設定：

|選項|說明 |
| --- | --- |
| 快取大小（maxaddr）| 設定橋接位址快取的大小。預設值為 2000 筆記錄。 |
|快取條目過期時間（逾時）|將位址快取條目的逾時設定為此秒數。如果秒數為零，則位址快取條目不會過期。預設值為 1200 秒。 |
|跨距連接埠| Span 連接埠傳輸網橋收到的每個訊框的副本。這對於在連接到網橋跨連接埠之一的另一台主機上被動監聽橋接網路非常有用。 |
|邊緣連接埠 |將介面設定為邊緣連接埠。邊緣連接埠直接連接到終端站，不能在網路中建立橋接環路；這允許它直接過渡到轉送。 |
|自動邊緣連接埠 |允許介面自動偵測邊緣狀態。這是新增到網橋的所有介面的預設設置，選擇介面將停用自動模式。 |
| PTP埠 | 將介面設定為點對點連結。這是直接過渡到轉送所必需的，並且應該在連接到另一個支援RSTP的交換器的直接鏈路上啟用。 |
| 自動PTP埠 | 透過檢查全雙工連結狀態，自動偵測介面上的點對點狀態。這是添加到網橋的接口的預設設置，選擇接口將禁用自動模式。 |
|黏性連接埠 |將介面標記為「黏性」介面。動態學習的位址條目一旦進入快取就被視為靜態位址條目。即使在不同的介面上看到該位址，黏性條目也不會從快取中老化或被替換。 |
|私人港口|將介面標記為「私有」介面。專用介面不會將任何流量轉送到也是專用介面的任何其他連接埠。 |

## GIF

GIF （ `gif(4)` ，通用隧道介面）可用於透過 IPv4 連接建立 IPv6 隧道。一個常見的應用是 Hurricane Electric (he.net) 的 IPv6 隧道。

注意事項

在 [IPv6 隧道代理](<124 IPv6 隧道代理.md>)中，您可以找到有關如何使用 Hurricane Electric 設定隧道的資訊。

與所有隧道設備一樣，最重要的設定涉及兩端的連接方式以及用於透過隧道路由流量的位址。其餘設定通常最好保留預設值。

|選項|說明 |
| --- | --- |
| 父介面 | 其實是指隧道連線時所使用的來源位址。 |
| GIF遠端位址 | 封裝後的 GIF 封包將會傳送到的對等位址。 |
| GIF隧道本地位址 | 將在介面上設定的隧道本機位址。 |
| GIF隧道遠端位址 | 將在介面上設定的隧道遠端位址。 |
|停用入口過濾 |外部隧道來源上的入口過濾可能會破壞非對稱路由網路中的隧道操作，在這種情況下，可以透過標記此選項來停用此功能。 |
| ECN友善行為 | 請注意， ECN友善行為違反了RFC2893 。這應與對等方達成共識後使用。 |
| 描述 | 此隧道的使用者友善描述 |

## GRE

GRE （ `gre(4)` ，通用路由封裝）用於建立虛擬的點對點連接，封裝的資料包可以透過此連接傳送。這可用於在通常不支援這些協定的連線上使用（ OSI第 3 層）協定。

由於GRE協定是由思科設計的，因此在使用思科解決方案時，它通常被用作預設隧道技術。

GRE的一個常見用例也是轉送（不可路由的）群播流量，儘管這需要額外的軟體，例如IGMP -proxy 或PIMD ，這些軟體在 OPNsense 上不太常用。

可用的設定與GIF隧道類型的設定類似：

|選項|說明 |
| --- | --- |
| 父介面 | 其實是指隧道連線時所使用的來源位址。 |
| GRE遠端位址 | 封裝後的 GIF 封包將會傳送到的對等位址。 |
| GRE隧道本地位址 | 將在介面上設定的隧道本機位址。 |
| GRE隧道遠端位址 | 將在介面上設定的隧道遠端位址。 |
| 描述 | 此隧道的使用者友善描述 |

## LAGG

LAGG ( `lagg(4)` ) 允許鏈路聚合、綁定和容錯。如果您的網路交換器支援此功能，則效果最佳。只有未指派的介面才能加入到LAGG 。

使用者介面支援以下選項：

|選項|說明 |
| --- | --- |
| 父介面 | 連結聚合成員 |
|滯後原型 |用於聚合的協定、可用選項如下表所述。 LACP 最常用。 |
| 描述 | 此介面的使用者友善描述 |
| 快速逾時 | 在介面上啟用 LACP 快速逾時。 |
| 使用 flowid | 如果可用，則使用網卡的RSS哈希值；否則，將在本地計算哈希值。預設值取決於系統在 net.link.lagg.default\_use\_flowid 中的設定。 |
| 哈希層 | 將封包層設定為哈希模式，以用於負載平衡的聚合協定。 |
| 使用嚴格模式 | 在介面上啟用 LACP 嚴格模式。預設值取決於系統，可在 net.link.lagg.lacp.default\_strict\_mode 中進行調整。 |
| MTU | MTU大小，取消設定時將使用LAGG子節點中最小的 MTU。 |

注意事項

哈希層指定設備如何在LAGG鏈路聚合組中的物理鏈路之間進行流量負載平衡。若LACP設備實作允許，則依照五元組進行負載平衡。兩個連接設備之間的哈希層不必相同，雖然這可以被視為最佳實踐，但並非強制要求。

**可用協定**

|名稱 |描述 |
| --- | --- |
|故障轉移|僅透過主連接埠傳送和接收流量。如果主連接埠不可用，則使用下一個活動連接埠。第一個新增的介面為主連接埠；此後新增的任何介面都用作故障轉移設備。 |
|鐵電公司 |支援思科 EtherChannel。這是靜態設置，不會與對等方協商聚合或交換幀來監控鏈路。 |
|拉普|支援 IEEE 802.3ad 鏈路聚合控制協定 (LACP) 和標記協定。 LACP 將與對等方協商一組聚合鏈路到一個或多個鏈路聚合組。每個LAG由相同速度的連接埠組成，設定為全雙工操作。流量將在總速度最大的LAG中的連接埠之間進行均衡，大多數情況下只有一個LAG包含所有連接埠。如果物理連接發生變化，鏈路聚合將快速收斂到新的配置。 |
|負載平衡|根據哈希協定標頭資訊平衡活動連接埠之間的傳出流量，並接受來自任何活動連接埠的傳入流量。這是靜態設置，不會與對等方協商聚合或交換幀來監控鏈路。哈希值包括乙太網路來源位址和目標位址，以及VLAN標籤（如果有）以及IP來源位址和目標位址。 |
| 輪詢 | 使用輪詢調度器將出站流量分配到所有活動端口，並接受來自任何活動端口的入站流量。 |
| 無 | 此協定旨在不執行任何操作：它會停用所有流量，但不會停用 lagg 介面本身。 |

注意

LAGG協定應與您的交換器支援的協定相符。最佳實務是盡可能使用LACP 。透過LAGG連接的設備需要使用相同的協定。

**LACP超時**

LACP超時有兩種模式：慢速/正常模式和快速模式。它控制鏈路故障時重新收斂的速度。這指定了兩個LAGG連接設備之間發送心跳的頻率。

| LACP模式 | 心跳/超時間隔 | 啟用 |
| --- | --- | --- |
| 慢速/正常 | 30秒 | 快速逾時已關閉 |
| 快速 | 1秒 | 快速逾時已開啟 |

在大多數情況下，慢速/正常超時應該是預設值。由於可能有供應商實施問題，最好將 LACP 逾時保持為慢速/正常。在某些情況下，快速逾時可能會導致連線中斷。 LACP 超時要求透過LAGG 連接的兩個設備具有相同的值。否則，可能會失去心跳，導致連線中斷。

請閱讀 [LAGG設定](<115 VLAN和LAGG設置.md>)取得設定範例。

## 環回

環回接口是模擬真實接口的邏輯虛擬接口，可用於需要始終保持連接的各種部署場景。以下列舉了一些此類設備的應用場景。

-   對您的機器上的服務擁有管理權限，這些服務可以綁定到在環回位址之上配置的位址。
    
-   使用環回位址作為OSPF或BGP路由器ID，有助於識別您的節點並簡化管理。
    

## VLAN

VLAN（虛擬區域網路）可用於將單一實體網路劃分為多個虛擬網路。這樣做可以用於服務品質 (QoS) 等目的。因此，大多數通過ISP認證IPTV設備都使用 VLAN。

以下設定適用於這些設備：

|名稱 |描述 |
| --- | --- |
| 裝置 | 此虛擬介面的裝置名稱，通常以 **vlan**或**qinq** 開頭，視類型 |
| 父接口 | 用作父接口的接口，VLAN 標記流量將透過該接口發送/接收 |
| VLAN標籤 | 802.1Q VLAN標籤（介於 1 和 4094 之間） |
| VLAN優先權 | 802.1Q VLAN PCP （優先權碼點） |
| 描述 | 此介面的使用者友善描述 |

注意事項

[802.1ad](https://en.wikipedia.org/wiki/IEEE_802.1ad) ，也稱為 QinQ，可透過VLAN配置進行支援，在這種情況下，您可以將`vlan`堆疊在`vlan`之上，在這種情況下，裝置名稱應以 qinq 開頭。

請閱讀 [VLAN設定](<115 VLAN和LAGG設置.md>)以取得設定範例。

## VXLAN

虛擬可擴充區域網路 ( VXLAN ) 用於將虛擬化的 2 層網路覆寫到 3 層網路上，如 [rfc7348](https://tools.ietf.org/html/rfc7348)所述。

隧道可以設定為點對點模式（參數`Remote address` ）或組播模式（參數`Multicast group`和`Device` ）。來源位址必須是此防火牆上已存在的（靜態分配的）位址，該位址將用作封裝 IPv4/IPv6 標頭中的來源位址。

注意事項

由於 VXLAN 介面使用IP, UDP和 VXLAN 頭部封裝乙太網路幀，因此產生的幀可能大於實體網路的MTU規格建議將實體網路的MTU配置為使用巨型幀來容納封裝後的幀大小。或者，也可以減少 VXLAN 介面的MTU大小，以使封裝後的訊框能夠適應目前實體網路的MTU 。

閱讀 [VXLAN Bridge](<117 VXLAN橋.md>)以取得常見設定的範例設定。

## 點對點

點對點 ( PP ) 介面提供兩個端點之間的直接連接，無需任何中間設備。這些介面通常用於WAN連接、隧道或直接鏈路建立，在這些情況下不需要廣播和多路存取。

以下連結類型可用於這些介面：

**PPP （點對點協定）**

一種廣泛用於透過串行鏈路建立直接連接的協議，常用於撥號和DSL連接。支援身份驗證（ PAP/CHAP ）、壓縮和錯誤檢測。

| **選項**|**描述** |
| --- | --- |
| **鏈路接口** | 普通鏈路（ PPP ）連接選擇一個接口，多鏈路（ MLPPP ）連接至少需要兩個接口。 |
| **描述** |您可以在此輸入描述以供參考。說明將出現在「介面分配」選擇清單中 |
| **服務提供者** | 請選擇PPP連接的國家/地區、服務提供者和套餐。 |
| **使用者名稱** | 請輸入您的使用者名稱以進行CHAP身份驗證。 |
| **密碼** | 請輸入您的密碼以進行CHAP身份驗證。 |
| **電話號碼** | 通常情況下， GSM `*99#` CDMA網路為`#777` |
| **存取點名稱 ( APN )** | 輸入您的服務供應商對應的存取點名稱APN )。例如，T-Mobile 的接入點名稱為`internet.t-d1.de` 。 |

| **進階選項**|**說明** |
| --- | --- |
| **APN編號（可選）** | 如果在上方設定了APN ，則預設為 1。若在上方未設定APN ，則忽略此項。 |
| **SIM PIN** | 如果您的服務提供者要求，請輸入SIM PIN 。如果不需要，請留空。 |
| **SIM PIN等待** | SIM PIN ，等待SIM發現網路所需的時間（秒）。 |
| **初始化字串** | 在此輸入調變解調器初始化字串。請勿在指令開頭包含「 AT 」字串。許多現代的USB 3G調變解調器不需要初始化字串。 |
| **連線逾時** | 輸入建立連線的逾時時間（秒）。預設值為 45 秒。 |
| **正常運作時間日誌記錄** | 此選項會將累積正常運作時間記錄並顯示在「狀態介面」頁面上。 |
| **按需撥號** |此選項可讓介面在按需撥號模式下運作。如果您希望連結始終有效，請不要啟用。介面已配置，但連結的實際連接會延遲，直到偵測到合格的傳出流量。 |
| **空閒逾時** | （秒）預設值為 0，即停用逾時功能。如果在輸入的秒數內沒有傳輸傳入或傳出資料包，則連線將會中斷。當發生空閒逾時時，如果啟用了按需撥號選項，mpd 將傳回按需撥號模式。否則，介面將被關閉並刪除所有關聯的路由。 |
| **壓縮** | 此選項啟用 Van Jacobson TCP頭部壓縮，可為每個TCP封包節省幾個位元組。您幾乎總是需要此選項。對於啟用了時間戳等現代擴展的TCP連接，此壓縮無效，因為這些擴展會修改TCP SACK 。 |
| **TCPmss修復** |此選項使 mpd 調整傳入和傳出的 TCP SYN 段，以便請求的最大段大小不大於介面 MTU 允許的量。這在許多設定中是必要的，以避免丟棄 ICMP 資料封包太大訊息的路由器所引起的問題。如果沒有這些訊息，原始電腦將發送數據，它會通過惡意路由器，然後到達 MTU 不足以容納數據的電腦。由於設定了 IP 不分段選項，因此該電腦將 ICMP 資料封包太大訊息傳送回起始者並丟棄該封包。惡意路由器會丟棄 ICMP 訊息，而發起者永遠不會發現它必須減小分段大小或從其傳出資料中丟棄 IP 不分段選項。 |
| **短序列** |僅當協商多鏈路PPP時，此選項才有意義。它禁止使用較短的多鏈路片段標頭，從而在每個幀上節省兩個位元組。對於非多鏈路連接，無需停用此功能。 |
| **ACFComp** | 位址與控製字段壓縮。此選項僅適用於非同步連結類型。每幀可節省兩個位元組。 |
| **原型Comp** |協定欄位壓縮。對於大多數幀，此選項每幀節省一個位元組。 |

**PPPoE（乙太網路點對點協定）**

將PPP幀封裝在乙太網路幀內，從而實現寬頻連接（如DSL上的身份驗證和連接管理。通常與網際網路服務供應商 (ISP) 一起使用，用於使用者身份驗證。

| **選項**|**描述** |
| --- | --- |
| **連結介面** | 為PPP封裝選擇一個父介面。 |
| **描述** |您可以在此輸入描述以供參考。說明將出現在「介面分配」選擇清單中 |
| **使用者名稱** | 請輸入您的使用者名稱以進行CHAP身份驗證。 |
| **密碼** | 請輸入您的密碼以進行CHAP身份驗證。 |
| **服務名稱** | 此欄位通常可以留空，除非服務提供者另有規定。 |
| **主機唯一性** | 除非提供者另有規定，否則此欄位通常可以留空。 |

注意事項

**PPTP （點對點隧道協定）**

VPN協定使用PPP協定封裝網路資料包，以確保資料傳輸安全。儘管PPTP得到廣泛支持，但由於其加密機制薄弱，因此被認為不安全。

| **選項**|**描述** |
| --- | --- |
| **連結介面** | 為PPP封裝選擇一個父介面。 |
| **描述** |您可以在此輸入描述以供參考。說明將出現在「介面分配」選擇清單中 |
| **使用者名稱** | 請輸入您的使用者名稱以進行CHAP身份驗證。 |
| **密碼** | 請輸入您的密碼以進行CHAP身份驗證。 |

注意事項

查看PPP選項卡以取得所有進階選項。

**L2TP （二層隧道協定）**

PPTP的一個擴展，它本身不提供加密功能，但通常與 IPsec 配合使用以實現安全隧道。用於VPN連接和遠端存取設定。

注意事項

查看PPTP和PPP選項卡以取得所有選項。

注意事項

`ppp`日誌檔案位於「系統」‣「日誌檔案」‣「常規」中。

閱讀 [PPPoE ISP設定](https://docs.opnsense.org/manual/how-tos/pppoe_isp_setup.html) ，了解帶有VLAN標籤的 PPPoE 配置範例，以建立ISP連接。

提示

使用`PPPoE`時，現在很多網路服務供應商都支援[RFC 4638](https://datatracker.ietf.org/doc/html/rfc4638) ，在這種情況下，網路服務供應商期望MTU連線本身的PPP值為1500位元組所需要的隧道位元組。要使用此功能，您的裝置需要在一定程度上支援“巨型幀”，以便與下一個對等體通訊。

要在`PPPoE`中使用 1500 位元組的MTU ，請將介面（通常是 Interfaces ‣ \[ WAN \]）設為MTU的值，在這種情況下`1508`隧道本身將使用全部 1500 位元組。
