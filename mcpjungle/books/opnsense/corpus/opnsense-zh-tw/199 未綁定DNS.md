# 未綁定DNS

Unbound 是驗證、遞迴、快取 DNS 解析器。它的設計目標是快速、精簡，並結合了基於開放標準的現代功能。

自 OPNsense 17.7 以來，它一直是我們的標準 DNS 服務，在新安裝時預設啟用該服務。

## 常規設定

警告

下表包含手動設定**偵聽**和**出站**介面的選項，出於充分的理由，建議對這兩個介面設定為`"All"`。除非您絕對知道自己在做什麼，否則最好將這些設定保留為預設值，因為誤用通常會導致啟動問題。

您可以在下面的**常規**選單部分找到最相關的設定。

---

|   |   |
| --- | --- |
|啟用 |啟用我們的DNS解析器 |
|監聽埠|要偵聽的端口，如果為空，則使用預設值 (53)。 |
|網路介面|介面IP位址，用於回應客戶端的查詢。如果介面同時具有 IPv4 和 IPv6 IP，則同時使用兩者。對未選擇的其他介面 IP 的查詢將被丟棄。預設行為是回應每個可用 IPv4 和 IPv6 位址的查詢。 |

| DNS64 |啟用 [DNS64](https://en.wikipedia.org/wiki/IPv6_transition_mechanism#DNS64)，以便純 IPv6 用戶端可以存取純 IPv4 伺服器。如果啟用，Unbound 會為僅具有 A 記錄的域合成 AAAA 記錄。 DNS64 需要 NAT64 才有用，例如。 g。 Tayga 外掛程式或第三方 NAT64 服務。 DNS64 前綴必須與NAT64 使用的 IPv6 前綴相符。 |

|註冊DHCP靜態映射|註冊靜態 dhcpd 條目，以便客戶端可以解析它們。 IPv4 和 IPv6 支援。 |
|沒有 IPv6 連結本地地址 |不要註冊 IPv6 的鏈路本地地址。當配置多個偵聽介面時，這將防止返回無法到達的位址。 |

| TXT 評論支援 |將描述註冊為 dhcp 靜態主機條目的註解。 |
|強制安全搜尋 |強制在 Google、DuckDuckGo、Bing、Qwant、PixaBay 和 YouTube 上使用安全搜尋。 |
|傳出網路介面 |利用 Unbound 將使用的不同網路介面向權威伺服器發送查詢並接收其回應。預設情況下使用所有介面。請注意，設定明確傳出介面僅在靜態配置時才有效。 |
|本地區域類型 |用於系統域的本機區域類型。類型描述可在 [unbound.conf(5)](https://nlnetlabs.nl/documentation/unbound/unbound.conf/) 手冊頁的「local-zone:」下找到。預設為“透明”。 |

注意事項

為了讓客戶端查詢未綁定，需要在服務‣未綁定DNS‣存取清單中分配ACL。配置的介面應自動獲得ACL。如果用戶端位址不在任何預先定義網路中，請手動新增一個。

## 覆蓋

在覆蓋部分中，您可以建立單獨的主機定義項目並指定是否應將特定網域的查詢轉送至預定義伺服器。

### **主機覆蓋設定**

主機覆蓋可用於變更客戶端查詢的 DNS 結果或新增自訂 DNS 記錄。也會在背景產生PTR記錄以支援反向DNS查找。它們是透過以下方式產生的：

-   如果[常規設定](#general)中的**系統A/AAAA記錄**未勾選，則為主介面建立一條PTR記錄。
    
-   每個主機覆蓋條目**不包含主機通配符**，都會被分配一個 PTR 記錄。
    
-   如果主機覆蓋條目**包含主機通配符**，則為第一個定義的別名分配一個PTR記錄。
    
-   所有其他別名都不會獲得 PTR 記錄。
    

|   |   |
| --- | --- |
|主持人|主機名稱，不含網域部分。使用“\*”建立通配符條目。 |
|網域 |主機的網域名稱（例如 example.com） |
|類型 |記錄類型、A 或AAA（IPv4 或 IPv6 位址）、MX 定義郵件交換 |
| IP |主機位址 |
|描述 |使用者可讀的描述，僅供參考 |
|別名 |不同主機的上述資料副本|

**別名**

您可以為主機建立替代名稱。例如。當 Web 伺服器具有多個虛擬主機時，您可以使用 IP 和 Web 伺服器的名稱以及該 Web 伺服器上每個虛擬主機的別名建立一個主機覆蓋項目。

您必須在頂部清單中選擇主機，它將在底部清單中顯示已指派的別名。

### **域覆蓋設定**

重要

域覆蓋已被[查詢轉送](#forwarding) 取代。查詢轉發還允許您轉發每個請求。

## 進階

儘管預設設定對於大多數設定來說應該是合理的，但有些設定需要更多調整或需要設定特定選項。其中一些設定已啟用並由 Unbound 指定預設值，請參閱 [unbound.conf(5)](https://nlnetlabs.nl/documentation/unbound/unbound.conf/) 以了解預設值。

---

|   |   |
| --- | --- |
|隱藏身分 |如果啟用，則會拒絕 id.server 和 hostname.bind 查詢。 |
|隱藏版本 |如果啟用 version.server 和 version.bind 查詢將被拒絕。 |
|預取支援 |訊息快取元素在過期之前被預取，以幫助保持快取最新。啟用後，此選項可能會導致 DNS 流量和伺服器負載增加約 10%，但頻繁請求的項目不會從快取中過期。 |
|預取 DNS 金鑰支援 |當遇到委託簽署者時，會在驗證過程的早期取得DNSKEY。這有助於降低請求的延遲，但確實會使用更多的CPU。 |
|哈登DNSSEC資料|信任錨定區域需要DNSSEC資料。如果缺少此類數據，該區域就會變成偽造的。如果停用此功能且未收到DNSSEC數據，則該區域將變得不安全。 |
|提供過期回覆 |使用 TTL 0 來提供來自快取的過期回應，而無需等待實際解析完成。選取後，將出現多個選項來自訂有關過期回應的行為。 |
|過期記錄回覆TTL值| TTL 回覆過期資料時所使用的值。如果也使用“客戶端過期回應逾時”，則建議按照RFC 8767 使用 30 作為預設值。僅在選取「提供過期回應」時適用。 |
| TTL 過期回覆 |將過期回應的服務限制為過期後配置的秒數。值為 0 會停用該限制。根據 RFC 8767，建議值介於 86400（1 天）和 259200（3 天）之間。僅在選取「提供過期回應」時適用。 |
|重設過期記錄TTL |嘗試從上游伺服器擷取記錄失敗後，將過期記錄的 TTL 設定為「過期回應的TTL」值。這可以確保只要有查詢，就會提供過期記錄。僅在選取「提供過期回應」時適用。 |
|客戶端回應逾時 |使用過期資料回覆客戶端之前的時間（以毫秒為單位）。這本質上實現了 RFC 8767 中指定的服務穩定行為，該行為在立即響應過期數據之前首先嘗試解決。每個 RF 8767 的建議值為 1800。將其設為 0 將停用此行為。僅在選取「提供過期回應」時適用。 |
|嚴格QNAME最小化|向上游伺服器發送最少量的資訊以增強隱私性。不要退回到將完整的QNAME傳送到可能損壞的網域名稱伺服器。啟用此選項後，許多網域將無法解析。僅當您知道自己在做什麼時才使用。 |
|擴充統計 |如果啟用，擴充統計資料將會列印到系統日誌。 |
|日誌查詢 |如果啟用，則將每個查詢列印一行到日誌，其中包含日誌時間戳記和 IP 位址、名稱、類型和類別。請注意，列印這些行需要時間，這會使伺服器（顯著）變慢。名稱中的奇數（不可列印）字元將列印為“?”。 |
|記錄回覆 |如果啟用，則將每個回應列印一行到日誌，其中包含日誌時間戳記和IP位址、名稱、類型、類別、回傳代碼、解析時間、回覆是否來自快取以及回應大小。請注意，列印這些行需要時間，這會使伺服器（顯著）變慢。名稱中的奇數（不可列印）字元將列印為“?”。 |
|標籤查詢和回覆 |如果啟用，將列印單字「query:」和「reply:」以及記錄的查詢和回覆。這使得過濾日誌變得更容易。 |
|日誌等級詳細程度 |選擇日誌詳細程度。 0 級意味著沒有冗長，只有錯誤。 1 級提供操作資訊。 2 級提供詳細的操作資訊。等級 3 提供查詢等級資訊、每個查詢的輸出。級別 4 提供演算法級別資訊。等級 5 記錄快取未命中的客戶端標識。預設為等級 1。
|私人網域名稱 |要標記為私有的網域清單。這些域及其所有子域都允許包含私有位址。 |
|重新綁定保護網路|這些是您的專用網路上的位址，不允許傳回公共網際網路名稱。任何此類地址的出現都會從DNS答案中刪除。此外，DNSSEC驗證器可能會將答案標記為虛假。這可以防止所謂的 DNS 重新綁定。 (僅適用於[管理](<98 設定.md#administration>)啟用DNS重新綁定檢查) |
|不安全的網域 |要標記為不安全的網域清單。 DNSSEC 網域的信任鏈被忽略。 |
|訊息快取大小 |訊息快取的大小。訊息快取儲存DNS rcodes和驗證狀態。 RRSet 快取（包含實際的RR 資料）將自動設定為此數量的兩倍。有效輸入是純字節，可選擇附加“k”、“m”或“g”，分別表示千字節、兆字節或千兆位元組。 |
| RRset 快取大小 | RRset 快取的大小。包含實際的RR資料。有效輸入是純字節，可選擇附加“k”、“m”或“g”，分別表示千字節、兆字節或千兆位元組。空時自動設定為訊息快取大小的兩倍，但可以手動修改。 |
|傳出 TCP 緩衝區 |每個執行緒分配的傳出 TCP 緩衝區的數量。如果選擇 0，則不會對權威伺服器進行TCP 查詢。 |
|傳入TCP緩衝區|每個執行緒分配的傳入TCP緩衝區的數量。如果選擇 0，則不接受來自客戶端的TCP查詢。 |
|每個執行緒的查詢數量 |每個執行緒將同時服務的查詢數量。如果有更多需要服務的查詢到達，並且沒有查詢可以被推擠（請參閱“推擠超時”），那麼這些查詢將被丟棄。這會強制客戶端在逾時後重新發送，使伺服器有時間處理現有查詢。 |
|傳出範圍 |要開啟的連接埠數。每個線程可以打開這個數量的檔案描述符。較大的數字需要作業系統提供額外的資源。對於性能來說，非常大的值是最好的。作為參考，通常使用每個執行緒的查詢量的兩倍。 |
|推擠逾時 |此逾時用於伺服器非常繁忙時。設定為通常會導致與授權伺服器進行一次往返的值。如果到達的查詢過多，則允許 50% 的查詢運行完成，而另外 50% 的查詢將被新傳入的查詢取代（如果它們已經花費了超過允許的時間）。這可以防止因慢速查詢或高查詢率而導致拒絕服務。 |
| RRsets 和訊息的最大TTL |配置快取中 RRset 和訊息的最大生存時間（以秒為單位）。當內部TTL過期時，快取項目也過期。可以將其配置為強制解析器更頻繁地查詢資料並且不信任（非常大的）TTL值。 |
| RRsets 和訊息的最低TTL |配置快取中 RRset 和訊息的最短生存時間（以秒為單位）。如果啟用最小值，則資料的快取時間將比網域擁有者預期的時間長，因此查找資料的查詢次數會減少。 0 值確保快取中的資料符合網域擁有者的預期。高值可能會導致麻煩，因為快取中的資料可能不再與實際資料相符。 |
| TTL 用於主機快取條目 |主機快取中條目的生存時間（以秒為單位）。主機快取包含往返時序、跛行和EDNS支援資訊。 |
|繼續探測主機 |繼續探測基礎架構主機快取中已關閉的主機。大約每 120 秒就會以指數退避方式對已關閉的主機進行一次偵測。如果主機在此時間段內沒有回應，它們將在主機快取TTL的持續時間內被標記為關閉。此設定可與「TTL用於主機快取條目」結合使用，以在網路連線頻繁發生跳動時提高回應速度。 |
|要快取的主機數量 |快取資訊的主機數量。 |
|不需要的回覆閾值 |如果啟用，則會在每個執行緒中追蹤不需要的回覆總數。當達到閾值時，將採取防禦操作並將警告列印到日誌檔案中。此防禦操作是清除 RRSet 和訊息緩存，希望清除任何有毒物質。 |

## 訪問列表

存取清單定義哪些客戶端可以查詢我們的 DNS 解析器。指派的介面的記錄將自動建立並顯示在概覽中。您還可以定義自訂策略，將操作套用至預先定義的網路。

注意事項

該操作可以如下面的列表中所定義。如果沒有使用任何匹配拒絕，則使用最具體的網路塊匹配。因此，存取控制語句的順序並不重要。

### **行動**

|   |   |
| --- | --- |
|否認|此操作會停止來自訂網路內的主機的查詢。 |
|拒絕|此操作也會停止來自已定義網路內的主機的查詢，但會將DNS rcode REFUSED 錯誤訊息傳回客戶端。 |
|允許 |此操作允許來自訂網路內的主機的查詢。 |
|允許窺探 |此操作允許從定義的網路內的主機進行遞歸和非遞歸存取。用於快取監聽，理想情況下應該只為您的管理主機進行配置。 |
|拒絕非本地 |僅允許來自訂網路內的主機的權威本地資料查詢。不允許的訊息將被丟棄。 |
|拒絕外地 |僅允許來自訂網路內的主機的權威本地資料查詢。對於不允許的訊息，將 DNS rcode REFUSED 錯誤訊息傳回客戶端。 |

## 黑名單

使用預定義來源或自訂位置之一啟用整合 DNS 封鎖清單。

可以定義多個策略，每個策略由一個或多個來源網路分隔。這表示您可以在特定網路上使用封鎖清單或特定（通配符）網域，從而對您的設定進行更細粒度的控制。當域在子網路大小之間重疊時，演算法會選擇最具體的子網路。您可以按照如下所述使用測試儀來查找此類重疊，但是，作為最佳實踐，建議將來源網路分開。

---

|   |   |
| --- | --- |
|啟用 |啟用封鎖清單 |
| DNSBL類型|預先定義的外部來源 |
|封鎖清單的 URL |用於下載封鎖清單的其他 http\[s\] 位置，僅支援包含 FQDN（例如 `my.evil.domain.com`）OR 通配符域（例如 `*.my.evil.domain.com`）清單的純文字檔案。 |
|允許清單域 |當阻止清單項目包含此清單中定義的模式時，它將從結果中省略。例如`.*.nl` 將排除所有 .nl 域。使用 [報告：未綁定DNS](<82 報告 Unbound DNS.md>) 頁面明確列入白名單的封鎖網域將顯示在此清單中。 |
|封鎖清單域 |要明確封鎖的網域清單。不支援正規表示式。使用[報告：未綁定DNS](<82 報告 Unbound DNS.md>)頁面明確阻止的已通過域將顯示在此列表中。 |
|通配符網域 |要封鎖清單的通配符域清單。給定域的所有子域都將被阻止。不支援阻止一級網域名稱（例如“com”）。 |
|來源網路 |要應用策略的來源網路。例如 192.168.1.0/24 或 192.168.1.1。留空以應用於所有內容。所有指定的網路應使用相同的協定族並具有相同的大小，以避免優先順序問題。 |
|快取TTL | TTL 用於阻止清單快取。遠端黑名單的更新頻率通常不會超過一天一次。因此，當下載封鎖清單時，它們會在本地緩存，以防止透過網路進行不必要的獲取。如果您知道遠端檔案旋轉速度比此速度快，則可以在此處變更此行為。 |
|目的地位址 |指定當 DNS 記錄被封鎖時要回傳的 IP 位址。可用於將此類網域重新導向至單獨的網路伺服器，通知使用者內容已被封鎖。預設為0.0.0.0。如果選取“Return NXDOMAIN”，則會跳過此欄位中的任何值。 |
|返回NXDOMAIN|不回傳“目標位址”，而是回傳DNS回傳代碼“NXDOMAIN”。這在裝置無法處理0.0.0.0目標位址的情況下非常有用，例如某些Apple裝置。 |

注意事項

應用程式封鎖清單設定不會重新啟動 Unbound，而是會向 Unbound 發出訊號，讓其在下載封鎖清單後立即進行動態處理。 Unbound 在加載所有內容之前可能會有長達一分鐘的延遲。在此期間，Unbound 仍將保持相同的回應能力。

### *阻止清單測試器*

封鎖清單功能包含測試程序，可讓您檢查給定網域是否與您在「封鎖清單」標籤中定義的策略相符。該測試器完全是本地的，因此該測試器無法匹配解析為 CNAME 的域，這些 CNAME 可能位於或不位於您定義的封鎖清單中。在這種情況下，您可以使用介面 -> 診斷 -> DNS 查找，或從命令列使用以下命令：

> ```
> 鑽-b<source ip> <domain> <record type>
> ```

在上面的範例中，來源IP位址必須存在於防火牆上。

## 查詢轉發

查詢轉送部分允許輸入任意名稱伺服器以將查詢轉送至。假設此處輸入的名稱伺服器能夠處理任何查詢的進一步遞歸。在本部分中，您可以指定要轉送至用戶端查詢的特定網域的名稱伺服器、擷取所有網域並指定非預設連接埠。

---

|   |   |
| --- | --- |
|使用系統名稱伺服器 |配置的系統名稱伺服器將用於將查詢轉送至。這將覆蓋自訂轉送網格中所做的任何條目，但針對特定網域的條目除外。如果沒有系統名稱伺服器，系統會提示您在[常規](<98 設定.md#general>)新增一個。如果您期望從 WAN 獲得 DNS 伺服器，但它未列出，請確保您也在那裡設定「允許DNS 伺服器清單被 WAN 上的 DHCP/PPP 覆蓋」。 |

警告

如果您有多個 WAN 設置，並且 Unbound 與在 [常規](<98 設定.md#general>) 中配置的多個 DNS 伺服器一起運行，並為其分配了單獨的網關，請勿使用系統名稱伺服器選項。 Unbound 將使用本地建立的路由來到達系統名稱伺服器，當網關關閉時，這將無法運作。

注意事項

請記住，如果選中“使用系統名稱伺服器”複選框，則系統名稱伺服器將優先於**查詢轉發和**中的任何**包羅萬象的條目** DNS-超過-TLS，這意味著具有特定網域的條目仍將被轉送到指定的名稱伺服器。

|   |   |
| --- | --- |
|已啟用 |啟用該網域的查詢轉送。 |
|網域 |主機的網域。該網域的所有查詢都將轉送到「伺服器IP」中指定的名稱伺服器。留空以捕獲所有查詢並將其轉發到名稱伺服器。 |
|伺服器IP|用於遞迴解析的DNS伺服器的位址。 |
|港口|指定DNS伺服器使用的連接埠。預設為連接埠 53。在配置時很有用，例如[DNSCrypt-代理](<215 DNSCrypt代理.md>) |

警告

請小心啟用「DNS查詢轉送」與**DNSSEC**，對於特定網域的轉送不會執行DNSSEC驗證，因為上游伺服器可能是本機控制器。如果轉發所有內容且上游伺服器不支援DNSSEC，則其答案將無法到達客戶端，因為無法執行DNSSEC驗證。

## DNS超過TLS

DNS over TLS 使用與查詢轉送相同的邏輯，只是它使用 TLS 進行傳輸。

---

注意事項

請注意查詢轉發與 DNS 透過 TLS 之間的交互作用。由於應用與查詢轉送相同的原理，因此在兩個部分中指定的 **catch-all 條目** 將被視為重複區域。在我們的例子中，DNS優於TLS。

|   |   |
| --- | --- |
|已啟用 |為此域啟用 DNS 而非 TLS。 |
|網域 |主機的網域。該網域的所有查詢都將轉送到「伺服器IP」中指定的名稱伺服器。留空以捕獲所有查詢並將其轉發到名稱伺服器。 |
|伺服器IP|用於遞歸解析的DNS伺服器的位址。 |
|港口|指定DNS伺服器使用的連接埠。請務必在此輸入連接埠 853，除非有充分的理由不這樣做，例如使用 SSH 隧道時。 |
|驗證CN |用於憑證驗證的名稱，例如「445b9e.dns.nextdns.io」。 Unbound 用於檢查TLS 驗證憑證。強烈建議不要忽略此字段，因為中間人攻擊仍然是可能的。 |

提示

為了確保環境經過驗證，在通過 TLS 使用 DNS 時，最好使用防火牆規則阻止連接埠 53 上的所有出站 DNS 流量。如果客戶端直接自己查詢其他名稱伺服器，則可以使用NAT重定向規則到127.0.0.1:53（本地未綁定服務）來強制這些請求通過TLS。

## 進階配置

某些安裝需要在 UI 中無法存取的組態設定。為了支援這些，可以將帶有 `.conf` 副檔名的單獨設定檔放入 `/usr/local/etc/unbound.opnsense.d` 目錄中。這些檔案將自動包含在UI產生的設定中。可以在那裡放置多個設定檔。但請注意

-   由於無法預測目前配置在哪個子句中進行，因此您必須在配置前新增 required 子句。有關「子句」的概念，請參閱`unbound.conf(5)`文件。
    
-   Unbound 中的通配符包含處理是基於`glob(7)`。因此，文件包含的順序是升序ASCII順序。
    
-   與使用此擴充點的插件程式碼的名稱衝突 e。 g。 `dnsbl.conf`，可能會發生。因此請務必使用唯一的檔案名稱。
    
-   最好透過以下方式檢查完整配置：
    
    ```
    # check if the resulting configuration is valid
    configctl unbound check
    ```
    
    這將報告阻止 Unbound 啟動的錯誤，並列出警告，這些警告可能會提示特定配置為何不起作用或如何改進。
    

這是一個在伺服器子句中新增選項的範例設定檔：

```yaml
server:
  private-domain: xip.io
```

注意事項

作為更永久的解決方案，範本系統（「[使用範本](<249 使用模板.md>)」）可用於自動產生這些檔案。

若要獲得與將文件直接放置在`/usr/local/etc/unbound.opnsense.d`中相同的效果，請按照以下步驟操作：

1.  在`/usr/local/opnsense/service/templates/sampleuser/Unbound`中建立`+TARGETS`檔案：
    
    ```
    sampleuser_additional_options.conf:/usr/local/etc/unbound.opnsense.d/sampleuser_additional_options.conf
    ```
    
2.  將範本檔案`sampleuser_additional_options.conf`放在同一目錄中：
    
    ```yaml
    server:
      private-domain: xip.io
    ```
    
3.  透過發出以下命令來測試模板產生：
    
    ```
    # generate template
    configctl template reload sampleuser/Unbound
    ```
    
4.  檢查目標目錄中的輸出：
    
    ```
    # show generated file
    cat /usr/local/etc/unbound.opnsense.d/sampleuser_additional_options.conf
    # check if configuration is valid
    configctl unbound check
    ```
    

警告

管理員有責任將文件放置在擴充目錄中以確保配置有效。

注意事項

此方法取代了未綁定配置的常規頁面中的`Custom options`設置，該設置已在版本21.7中刪除。
