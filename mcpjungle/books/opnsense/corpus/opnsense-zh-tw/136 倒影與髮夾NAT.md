|介面| IPv4 子網路 |主持人 |網關|
| --- | --- | --- | --- |

| DMZ | `172.16.1.0/24` | `172.16.1.1` - 網路伺服器 | `172.16.1.254` - OPNsense |
| LAN | `192.168.1.0/24` | `192.168.1.1` - 客戶| `192.168.1.254` - OPNsense |

## [NAT - 快速概述](#id4)

由於沒有足夠的可用 IPv4 位址，因此 IPv4 標準中實作了一種名為 *NAT*（網路位址轉換）的解決方法。它基本上使 OPNsense 等路由器能夠將 IPv4 位址轉換為其他 IPv4 位址。大多數時候，它用於將有限的外部 IPv4 位址空間轉換為共享的內部 IPv4 位址空間（RFC 1918、`192.168.0.0/16` - `172.16.0.0/12` - `10.0.0.0/8`），反之亦然。

注意事項

SNAT - 來源網路位址轉換

-   更改資料包的來源IP
    
-   防火牆 –> NAT –> 來源 NAT（出站），使用規則中的選項 *翻譯來源 IP*
    

DNAT - 目標網路位址轉換

-   更改資料包的目的地IP
    
-   防火牆 –> NAT –> 目標 NAT（連接埠轉送），使用規則中的選項 *重定向目標 IP*
    

PAT - 埠位址轉換

-   更改資料包的目標端口
    
-   防火牆 –> NAT –> 目標 NAT（連接埠轉送）使用規則中的選項 *重定向目標連接埠*
    

如果您建立 DNAT 規則，則允許 WAN 中的所有用戶端存取內部 IPv4 位址。 OPNsense 的作用就像一個轉換器，在客戶端和伺服器之間轉換 IPv4 位址。 OPNsense 將所有翻譯寫入名為 NAT 表的檔案中。它確切地知道流量應如何在翻譯到位後來回流動。

警告

NAT 不是安全功能。它僅充當翻譯器。如果你想要安全，你還需要防火牆規則。

## [倒影與髮夾簡介NAT](#id5)

例如，您有一個 Web 伺服器 `example.com`，其內部 IP `172.16.1.1` 位於您的 DMZ 中。它有一個公開的DNS記錄`example.com in A 203.0.113.1`。

您的內部客戶 `192.168.1.1` 如果解決了則無法存取網路伺服器 DNS A記錄 `203.0.113.1`。當 OPNsense 收到客戶端寄來的資料包時 `192.168.1.1` 與目的地 IP `203.0.113.1`，它選擇**自己**作為目標，並且**不** `172.16.1.1`。這是因為外部 IPv4 位址 `203.0.113.1` 被映射到 WAN OPNsense 的介面。

這就是反射NAT發揮作用的地方。它創建 NAT 規則，透過使用 OPNsense 作為實際目的地 `172.16.1.1` 的“轉換器”，幫助您的內部客戶端 `192.168.1.1` 與您的網頁伺服器 `203.0.113.1` 進行通訊。

注意

您應該從此處提供的三種可能的選擇中選擇您首選的 Reflection NAT 方法。它們是互斥的，選擇一種方法並堅持下去可以防止錯誤。

-   [方法 1](#nat-method1) - 建立**手動**連接埠轉送NAT（DNAT）、**手動**來源NAT（SNAT）和**自動**防火牆規則
    
-   [方法 2](#nat-method2) - 建立**自動**連接埠轉送NAT（DNAT）、**手動**來源NAT（SNAT）和**手動**防火牆規則
    
-   [方法 3](#nat-method3) - 建立**自動**連接埠轉送NAT (DNAT)、**自動**來源NAT (SNAT) 和**手動**防火牆規則
    

注意事項

-   **反思NAT：** 用戶端和伺服器位於不同的子網路（第 2 層廣播域）中，OPNsense 在它們之間路由流量。他們無法透過解析 ARP 請求直接進行通訊。你只需要DNAT。
    
-   **髮夾NAT：**客戶端和伺服器在同一子網路（二層廣播網域）。他們可以透過解析 ARP 請求直接相互通訊。您需要SNAT和DNAT。
    

注意事項

使用 IPsec 時，預設情況下 NAT 僅與基於策略的 VPN. NAT 匹配，VTI（虛擬隧道介面）不會匹配，除非設定了一些可調參數。這些可調參數變更 if\_enc 和 if\_ipsec 介面上防火牆過濾器和 NAT 的行為。您可以在 [IPsec VTI - 基於路由的設定](<154 虛擬私人網路.md#route-based-vti>) 中閱讀有關可調參數的更多信息

## [最佳實踐](#id6)

在 OPNsense 中進行反射 NAT 的最佳方法是 **不** 使用 [（進階）設定](<146 （進階）設定.md>) 中的舊反射選項。使用[方法 1](#nat-method1) 手動建立NAT規則可防止不需要的流量並使審核變得容易。不會有任何潛規則。所有規則都將在 GUI 和 .xml 配置導出中完全可見。

## [操作方法部分開始：](#id7)

目標是從 WAN, LAN 和 DMZ 中的客戶端透過外部 IP `203.0.113.1` 存取連接埠 `443` 上的 Web 伺服器 `172.16.1.1`。

### [方法 1 - 建立手動連接埠轉送 NAT (DNAT)、手動來源 NAT (SNAT) 和自動防火牆規則](#id8)

前往防火牆 ‣ 設定 ‣ 進階

停用*目的地反射NAT（連接埠轉送）*、*1:1 反射*和*自動來源NAT（出站）反射*

前往防火牆 ‣ NAT ‣ 目標NAT（連接埠轉送）

選擇 **++** 建立新的目標 NAT（連接埠轉送）規則。

|   |   |
| --- | --- |
|介面： |選擇 `WAN`, `DMZ` 和 `LAN` - 選擇客戶端應存取 Web 伺服器的所有介面。這將在 Firewall ‣ Rules ‣ Floating 中建立允許流量的連結防火牆規則。 |
|協議： |選擇`TCP`|
|來源：|選擇`Any`|
|來源埠範圍： |選擇`Any`|
|目的地: |輸入 `203.0.113.1` - 這是網路伺服器的外部 IPv4 位址。 |
|目的連接埠範圍：|輸入`443` - 或選擇別名`HTTPS` |
|重定向目標IP：|輸入`172.16.1.1` - 這是DMZ中Web伺服器的內部IPv4位址。 |
|重定向目標埠：|輸入`443` - 或選擇別名`HTTPS` |
|描述： |輸入 `Reflection NAT Rule Webserver 443` - 新增描述，因為連結的 *過濾器規則關聯* 將使用它作為其名稱，而防火牆 ‣ 規則 ‣ 浮動規則將在描述中包含它。 |
| NAT 反思：|使用系統預設 |
|過濾規則關聯： |新增關聯過濾規則|

提示

像句子一樣閱讀DNAT規則會比較清楚：

如果 OPNsense 在任何介面上收到封包 `WAN`, `DMZ` 和 `LAN` 有協議 `TCP` 從源頭 IP `ANY` 和來源連接埠範圍 `ANY` 到目的地 IP `203.0.113.1` 和目的港 `443` –> 重寫目的地 IP 到 `172.16.1.1` 以及目的港 `443`.

注意事項

由於“新增關聯的過濾規則”，在防火牆‣規則‣浮動中新增的連結防火牆規則將允許流量到達目的地IP `172.16.1.1`，因為NAT規則在防火牆規則之前符合。這意味著防火牆接收資料包，並且NAT規則首先將目標從`203.0.113.1`轉換為`172.16.1.1`，然後再將資料包傳遞到防火牆過濾器。您也可以設定“過濾規則關聯：通過”，但產生的防火牆規則將不可見。

注意事項

在某些設定中（例如，外部IP位址綁定在附加VPN介面上），您需要設定「過濾規則關聯：無」並建立您自己的防火牆規則。這些防火牆規則之一應該僅在VPN接口上匹配，並且在該規則的“高級功能”中，“回复”應該是您的VPN接口。其他防火牆規則（不含「回覆」）應與其餘介面相符。

注意

現在你有反射了NAT。來自內部LAN客戶端`192.168.1.1`和任何WAN客戶端的流量到達Web伺服器。但有一個警告 - 任何 DMZ 用戶端和 Web 伺服器本身仍然無法到達外部 IP `203.0.113.1`。為此，您需要髮夾NAT，其中涉及額外的SNAT規則。

前往防火牆 ‣ NAT ‣ 源 NAT（出站）

選擇*混合來源NAT規則產生*並儲存。這樣，您就可以將手動來源 NAT 規則與自動 IP 偽裝規則結合。您也可以選擇*手動來源NAT規則產生*。請確保您建立自己的IP-偽裝規則並啟用手動來源NAT。

選擇 **++** 建立新的來源 NAT 規則。

|   |   |
| --- | --- |
|介面： |選擇 `DMZ` - 它是網路伺服器所在子網路的介面。
|協議： |選擇`TCP`|
|原始碼位址： |選擇`DMZ net` - 這是DMZ網路`172.16.1.0/24`的別名 |
|來源埠： |選擇`Any`|
|目的地位址：|輸入`172.16.1.1` - 這是DMZ中Web伺服器的內部IPv4位址。 |
|目的港：|輸入`443` - 或選擇別名`HTTPS` |
|翻譯/目標：|選擇 `DMZ address` - 它是 DMZ 網路中 OPNsense 介面 IPv4 位址 `172.16.1.254` 的別名。 |
|描述： |輸入`Hairpin NAT Rule Webserver 443`|

提示

像句子一樣閱讀SNAT規則會比較清楚：

如果介面上的 OPNsense 收到封包 `DMZ` 有協議 `TCP` 來自來源網 `172.16.1.0/24` 和來源埠 `ANY` 到目的地 IP `172.16.1.1` 和目的港 `443` –> 將來源ip重寫為 `172.16.1.254` 以及 OPNsense 的回答 `DMZ` 介面。

注意事項

現在，所有DMZ客戶端（以及Web伺服器本身）都可以透過其外部IP到達Web伺服器。

-   您需要此額外的 SNAT 規則來避免同一第 2 層廣播網域中的用戶端和伺服器之間的不對稱流量。 TCP 否則交通將無法運作。
    

重複[方法1](#nat-method1)，直到所有其他伺服器均可存取。

如果您遇到任何問題，請查看[疑難排解NAT規則](#troubleshooting-nat-rules)以獲得一些提示。

不建議使用以下方法，但仍會進行解釋，以防止配置錯誤。更多資訊請參閱[（進階）設定](<146 （進階）設定.md>)。

## [一對一NAT反思](#id11)

當防火牆 ‣ 設定 ‣ 進階 *1:1 反射* 啟動時，會產生所有一對一 NAT 規則的自動反射 NAT 規則。

如果您想建立手動反射和髮夾NAT規則，請停用*Reflection for 1:1*並依照[方法1](#nat-method1)中的步驟操作。唯一的變更是未將 WAN 介面新增至您建立的目標 NAT（連接埠轉送）規則。產生的目標NAT（連接埠轉送）和來源NAT規則是現有一對一NAT規則的**補充**。

如果您的目標NAT（連接埠轉送）規則選擇了 1 個介面（例如LAN），則產生的*過濾器規則關聯：新增關聯的過濾器規則*將出現在防火牆‣規則‣LAN中。如果您選擇了 1 個以上的接口，它將出現在防火牆 –> 規則 –> 浮動中。

## [疑難排解NAT規則](#id12)

提示

-   打開SSH殼：
    
-   顯示所有已載入和活動的NAT規則：
    
-   `pfctl -s nat`
    
-   「rdr」 表示防火牆 ‣ NAT ‣ 目標NAT（連接埠轉送）規則。
    
-   「nat」 表示防火牆 ‣ NAT ‣ 來源 NAT（出站）規則。
    
-   您也可以在防火牆‣診斷‣統計中GUI查看規則
    

提示

-   顯示 OPNsense 偵錯中的所有 NAT 規則：
    
-   `cat /tmp/rules.debug | grep -i nat`
    
-   如果這裡的規則比`pfctl -s nat`中的規則多，則表示您忘記在某個地方點擊「套用」。
    

提示

-   在 Firewall ‣ Log Files ‣ Live View 中查看防火牆即時日誌的預設丟棄情況
    
-   開啟您建立的 NAT 和防火牆規則的日誌記錄，並在防火牆 ‣ 日誌檔案 ‣ 即時檢視中檢查它們是否符合。 NAT 規則具有標籤「NAT」或「RDR」。防火牆規則的描述為標籤。
    
-   在「防火牆 ‣ 診斷 ‣ 會話」中，您可以檢查內部用戶端和內部伺服器之間是否存在會話，以及與該會話相符的規則。
    
-   在客戶端、opnsense、服務端使用tcpdump，測試設備之間流量來回是否無誤。尋找 TCP SYN 和 SYN ACK。如果只有SYN，則連線未建立，且您的規則有錯誤。
