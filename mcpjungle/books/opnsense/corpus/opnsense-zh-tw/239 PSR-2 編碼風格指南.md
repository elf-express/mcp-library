# PSR-2 編碼風格指南

注意事項

PSR1 和 PSR2 編碼標準由 FIG 根據 MIT 許可證提供。

查看許可證詳細資訊：[http://www.php-fig.org/bylaws/licensing-policies/](http://www.php-fig.org/bylaws/licensing-policies/)

本頁原文內容可在[php-fig](http://www.php-fig.org/psr/psr-2/)找到

本指南對基本編碼標準 [PSR-1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md) 進行了擴展和擴展。

本指南的目的是減少掃描不同作者的程式碼時的認知摩擦。它透過列舉一組關於如何格式化 PHP 程式碼的共用規則和期望來實現這一點。

本文的風格規則源自於各成員項目之間的共通性。當不同的作者在多個專案中進行協作時，擁有一套可在所有這些專案中使用的指南會有所幫助。因此，本指南的好處不在於規則本身，而在於分享這些規則。

關鍵字「MUST」、「MUST NOT」、「REQUIRED」、「SHALL」、「SHALL NOT」、「SHOULD」、「SHOULD NOT」、「推薦」、「MAY」及本文件中的「OPTIONAL」應按[RFC 2119](http://www.ietf.org/rfc/rfc2119.txt)中的描述進行解釋。

## 1\.概述

-   代碼MUST遵循「編碼風格指南」PSR\[[PSR-1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md)\]。
    
-   代碼MUST使用4個空格進行縮進，而不是製表符。
    
-   MUST NOT 對線路長度有硬性限制；軟限制MUST為120個字元；行 SHOULD 不超過 80 個字元。
    
-   `namespace`宣告後有MUST1個空行，MUST在`use`宣告區塊後面有1個空白行。
    
-   類別 MUST 的左大括號位於下一行，右大括號 MUST 位於正文之後的下一行。
    
-   方法 MUST 的左大括號位於下一行，右大括號 MUST 位於主體之後的下一行。
    
-   在所有屬性和方法上聲明可見性MUST； `abstract`和`final` MUST在可見性之前聲明； `static` MUST 在可見性之後聲明。
    
-   控制結構關鍵字MUST後面有一個空格；方法與函數呼叫MUST NOT。
    
-   控制結構 MUST 的左大括號位於同一行，右大括號 MUST 位於主體之後的下一行。
    
-   控制結構MUST NOT的左括號後面有一個空格，控制結構MUST NOT的右括號前面有一個空格。
    

### 1.1。範例

此範例包含以下一些規則作為快速概述：

```php
<?php
namespace Vendor\Package;

use FooInterface;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class Foo extends Bar implements FooInterface
{
    public function sampleFunction($a, $b = null)
    {
        if ($a === $b) {
            bar();
        } elseif ($a > $b) {
            $foo->bar($arg1);
        } else {
            BazClass::bar($arg2, $arg3);
        }
    }

    final public static function bar()
    {
        // method body
    }
}
```

## 2\.一般

### 2.1 基本編碼標準

代碼MUST遵循[PSR-1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md)中概述的所有規則。

### 2.2 文件

所有 PHP 檔案 MUST 使用 Unix LF（換行）行結尾。所有 PHP 檔案 MUST 以單一空白行結尾。

僅包含 PHP 的文件中省略結束 `?>` 標籤 MUST。

### 2.3。線路

MUST NOT 對線路長度有硬性限制。

行長度MUST的軟限制為120個字元；自動樣式檢查器MUST發出警告，但MUST NOT在軟限制處出錯。

行 SHOULD NOT 長度超過 80 個字元；長度超過 SHOULD 的行將被分成多個後續行，每行不超過 80 個字元。

非空白行末尾有 MUST NOT 尾隨空格。

新增空白行MAY以提高可讀性並指示相關的程式碼區塊。

每行有 MUST NOT 多個語句。

### 2.4。縮排

代碼MUST使用4個空格的縮排，MUST NOT使用製表符縮排。

注意事項

注意：僅使用空格，而不是將空格與製表符混合使用，有助於避免差異、補丁、歷史記錄和註釋的問題。使用空格還可以輕鬆插入細粒度的子縮排以進行行間對齊。

### 2.5。關鍵字和 True/False/Null

PHP [關鍵字](http://php.net/manual/en/reserved.keywords.php) MUST 小寫。

PHP 常數 `true`, `false` 和 `null` MUST 為小寫。

## 3\.命名空間和使用聲明

如果存在，則在 `namespace` 宣告之後有一個空白行 MUST。

當存在時，所有`use`聲明MUST都在`namespace`聲明之後。

那裡 MUST 成為一體 `use` 每個聲明的關鍵字。

`use` 塊後有MUST 一個空行。

例如：

```php
<?php
namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

// ... additional PHP code ...
```

## 4\.類別、屬性和方法

術語「類別」是指所有類別、介面和特徵。

### 4.1。擴展和實現

`extends` 和 `implements` 關鍵字 MUST 與類別名稱宣告在同一行。

類別 MUST 的左大括號獨佔一行；類別 MUST 的右大括號位於正文之後的下一行。

```php
<?php
namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements \ArrayAccess, \Countable
{
    // constants, properties, methods
}
```

`implements` MAY 的清單被分成多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個介面。

```php
<?php
namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements
    \ArrayAccess,
    \Countable,
    \Serializable
{
    // constants, properties, methods
}
```

### 4.2。屬性

所有房產均需聲明可見性MUST。

`var` 關鍵字 MUST NOT 用於宣告屬性。

每個語句宣告 MUST NOT 多個屬性。

屬性名稱 SHOULD NOT 以單一底線為前綴，以指示受保護或私有可見性。

屬性聲明如下所示。

```php
<?php
namespace Vendor\Package;

class ClassName
{
    public $foo = null;
}
```

### 4.3。方法

在所有方法上都宣告可見性MUST。

方法名稱 SHOULD NOT 以單一底線為前綴，以指示受保護或私有可見性。

方法名稱 MUST NOT 宣告時在方法名稱後面加上一個空格。左大括號 MUST 獨佔一行，右大括號 MUST 位於主體後方的下一行。左括號後面有 MUST NOT ，右括號前有 MUST NOT 。

方法聲明如下圖所示。注意括號、逗號、空格和大括號的位置：

```php
<?php
namespace Vendor\Package;

class ClassName
{
    public function fooBarBaz($arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

### 4.4。方法參數

在參數清單中，MUST NOT 每個逗號之前都有一個空格，MUST 每個逗號之後有一個空格。

具有預設值 MUST 的方法參數位於參數清單的末端。

```php
<?php
namespace Vendor\Package;

class ClassName
{
    public function foo($arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

參數清單 MAY 分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數。

當參數清單分成多行時，右括號和左大括號 MUST 一起放在自己的行上，中間有一個空格。

```php
<?php
namespace Vendor\Package;

class ClassName
{
    public function aVeryLongMethodName(
        ClassTypeHint $arg1,
        &$arg2,
        array $arg3 = []
    ) {
        // method body
    }
}
```

### 4.5. `abstract`, `final`、`static`

當存在時，`abstract`和`final`聲明MUST位於可見性聲明之前。

當存在時，`static`聲明MUST位於可見性聲明之後。

```php
<?php
namespace Vendor\Package;

abstract class ClassName
{
    protected static $foo;

    abstract protected function zim();

    final public static function bar()
    {
        // method body
    }
}
```

### 4.6。方法和函數調用

呼叫方法或函數時，方法或函數名稱與左括號之間有 MUST NOT 空格，左括號後有 MUST NOT 空格，右括號前有 MUST NOT 空格。在參數清單中，MUST NOT 每個逗號之前都有一個空格，MUST 每個逗號之後有一個空格。

```php
<?php
bar();
$foo->bar($arg1);
Foo::bar($arg2, $arg3);
```

參數清單 MAY 分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數。

```php
<?php
$foo->bar(
    $longArgument,
    $longerArgument,
    $muchLongerArgument
);
```

## 5\.控制結構

控制結構的一般樣式規則如下：

-   控制結構關鍵字後面有MUST一個空格
    
-   左括號後面有MUST NOT空格
    
-   右括號前有 MUST NOT 空格
    
-   右括號和左大括號之間有 MUST 一個空格
    
-   結構體MUST縮排一次
    
-   右大括號 MUST 位於正文之後的下一行
    

每個結構體MUST都用大括號括起來。這標準化了結構的外觀，並減少了在將新線條添加到主體時引入錯誤的可能性。

### 5.1. `if`, `elseif`, `else`

`if` 結構如下圖所示。注意括號、空格和大括號的位置；並且 `else` 和 `elseif` 與先前主體的右大括號在同一行。

```php
<?php
if ($expr1) {
    // if body
} elseif ($expr2) {
    // elseif body
} else {
    // else body;
}
```

使用關鍵字`elseif` SHOULD代替`else if`，以便所有控製關鍵字看起來像單字。

### 5.2. `switch`, `case`

`switch` 結構如下圖所示。請注意括號、空格和大括號的位置。 `case`語句MUST從`switch`縮排一次，`break`關鍵字（或其他終止關鍵字）MUST與`case`主體縮排相同的層級。當在非空 `case` 主體中故意發生失敗時，會有 MUST 註釋，例如 `// no break` 。

```php
<?php
switch ($expr) {
    case 0:
        echo 'First case, with a break';
        break;
    case 1:
        echo 'Second case, which falls through';
        // no break
    case 2:
    case 3:
    case 4:
        echo 'Third case, return instead of break';
        return;
    default:
        echo 'Default case';
        break;
}
```

### 5.3. `while`, `do while`

`while` 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php
while ($expr) {
    // structure body
}
```

同樣，`do while` 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php
do {
    // structure body;
} while ($expr);
```

### 5.4. `for`

`for` 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php
for ($i = 0; $i < 10; $i++) {
    // for body
}
```

### 5.5. `foreach`

`foreach` 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php
foreach ($iterable as $key => $value) {
    // foreach body
}
```

### 5.6. `try`, `catch`

`try catch` 塊如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php
try {
    // try body
} catch (FirstExceptionType $e) {
    // catch body
} catch (OtherExceptionType $e) {
    // catch body
}
```

## 6\.閉包

宣告閉包 MUST 時，在 `function` 關鍵字後面加一個空格，在 `use` 關鍵字前後加一個空格。

左大括號 MUST 位於同一行，右大括號 MUST 位於主體後方的下一行。

參數列表或變數列表的左括號後面有 MUST NOT ，參數列表或變數列表的右括號前有 MUST NOT 。

在參數清單和變數清單中，每個逗號前面都有一個空格MUST NOT，每個逗號後面有一個空格MUST。

具有預設值 MUST 的閉包參數位於參數清單的末端。

關閉聲明如下圖所示。注意括號、逗號、空格和大括號的位置：

```php
<?php
$closureWithArgs = function ($arg1, $arg2) {
    // body
};

$closureWithArgsAndVars = function ($arg1, $arg2) use ($var1, $var2) {
    // body
};
```

參數列表和變數列表MAY分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數或變數。

當結束清單（無論是參數或變數）被分成多行時，右括號和左大括號 MUST 一起放在自己的行上，中間有一個空格。

以下是帶有和不帶有參數列表以及跨多行的變數列表的閉包範例。

```php
<?php
$longArgs_noVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) {
   // body
};

$noArgs_longVars = function () use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_longVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_shortVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use ($var1) {
   // body
};

$shortArgs_longVars = function ($arg) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};
```

請注意，當閉包直接在函數或方法呼叫中用作參數時，格式化規則也適用。

```php
<?php
$foo->bar(
    $arg1,
    function ($arg2) use ($var1) {
        // body
    },
    $arg3
);
```

## 7\.結論

本指南有意省略了許多風格和實踐元素。這些包括但不限於：

-   全域變數和全域常數的聲明
    
-   函數聲明
    
-   運算符和賦值
    
-   行間對齊
    
-   評論和文件區塊
    
-   類別名稱前綴和後綴
    
-   最佳實踐
    

未來的建議MAY修改和擴展本指南以解決風格和實踐的這些或其他要素。
