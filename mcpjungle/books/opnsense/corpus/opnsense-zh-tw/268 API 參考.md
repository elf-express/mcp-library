# API 參考

## 介紹

OPNsense API 呼叫的結構如下：

```
https://opnsense.local/api/<module>/<controller>/<command>/[<param1>/[<param2>/...]]
```

OPNsense API 中使用了兩個 HTTP 動詞：

> -   `GET` 從 OPNsense 檢索數據
>     
> -   `POST` 建立新資料、更新現有資料或執行操作
>     

HTTP POST請求和回應的主體是一個「application/json」物件。

$key 和 $secret 參數用於使用curl 傳遞API 憑證。在範例中使用這些參數之前，您需要使用自己的 API 憑證設定這些參數：

```
key=w86XNZob/8Oq8aC5r0kbNarNtdpoQU781fyoeaOBQsBwkXUt
secret=XeD26XVrJ5ilAc/EmglCRC+0j2e57tRsjHwFepOseySWLM53pJASeTA3
```

注意事項

使用 Postman 測試 API 呼叫時，請使用「基本驗證」授權類型。 $key 和 $secret 參數分別進入使用者名稱/密碼。

注意事項

請務必確保金鑰的擁有者有權存取相關資源，使用者設定的「有效權限」顯示哪些資源可以存取。 （編輯顯示分配給每個資源的端點）。

ACL 在 [development/components/acl](<266 存取控制列表.md>) 中進行了解釋。

## 所需參數和預期響應

我們自動產生的 api 文件只能收集端點及其最有可能的呼叫方法（`GET`, `POST`），由於幾乎 99% 的端點實際上都被 gui 使用，因此查找它們的參數並不復雜，您只需要一個瀏覽器並開啟一個檢查窗格即可。透過過濾以 `/api/` 開頭的請求，可以輕鬆找到從 gui 執行的呼叫。

例如，當查看 System ‣ Diagnostics ‣ Services 中的搜尋網格時，按下重新載入按鈕將執行包含以下原始 json 資料的 `POST` 到 `https://my.firewall/api/core/service/search`：

```json
{"current":1,"rowCount":7,"sort":{},"searchPhrase":""}
```

並返回類似以下的結構：

```
{
    "total": 10,
    "rowCount": 7,
    "current": 1,
    "rows": [
        {
        "id": "configd",
        "locked": 1,
        "running": 1,
        "description": "System Configuration Daemon",
        "name": "configd"
        },
        ....
    ]
}
```

許多端點在下面使用相同的共享模型類，因此看起來非常相似。如果類別綁定到模型，則文件將指向它。在這裡您可以找到所需的標準類型，無需特定應用程式的驗證。

當需要更詳細的資訊時，最好閱讀[架構](<242 大樓.md>)文件以了解系統的不同區域如何互動。
