# 開發流程



接近一個你從未使用過的更大的儲存庫是相當困難的。最大的問題是，很少有專案為新貢獻者定義了開發（如實際編碼）工作流程，因此人們只能在黑暗中摸索幾天或幾週，直到事情開始有意義。說到 *sense*，讓我們解釋一下我們如何設計 [OPNsense](https://opnsense.org/developers-invitation/) 的開發體驗，以及如何立即開始貢獻程式碼。

## 結構

來源、連接埠、核心、工具

結構與 FreeBSD 非常相似：我們有一個 [原始碼](https://github.com/opnsense/src) 儲存庫和一個 [連接埠樹](https://github.com/opnsense/ports)。從歷史上看，我們還有[核心程式碼](https://github.com/opnsense/core)和[工具儲存庫](https://github.com/opnsense/tools)。工具儲存庫是將所有儲存庫黏合在一起的專案外殼程式碼，產生最終影像，而核心是重要的GUI和系統配置位元。

注意事項

從 16.1 開始，還有插件支持，來源儲存庫是 [plugins tree](https://github.com/opnsense/plugins) 。插件是一種輕鬆擴展現有系統的模組化方式。

為什麼 core 不是原始碼的一部分

首先有趣的是，核心不是來源儲存庫的一部分，因為它依賴連接埠中找到的第三方軟體。我們不能將核心固定在原始碼中，因為連接埠是不適合基本系統的東西。它還有助於將來源儲存庫的變更保持在最低限度，以便將來更輕鬆地進行主要的 FreeBSD 升級。

為什麼核心也不屬於連接埠的一部分

為什麼核心儲存庫不在連接埠中？好吧，我們在端口樹中有幾個自訂端口，但這些端口都很小。核心儲存庫以及 ports 樹本身都非常大，因此將它們分開是有意義的。另一個原因是核心儲存庫僅包含 Shell、Python 和PHP 中的腳本。因此，工具儲存庫實際上將核心儲存庫視為一個依賴它所需的所有連接埠的套件。這樣，在圖像上，核心程式碼看起來就像是另一個套件。 **這使得升級核心程式碼變得非常容易和快速，而無需修改基礎。**我們甚至可以升級到更新的連接埠頁面，並在前進時新增和刪除它們。

## 套餐

它變得更好

一旦有了正在運行的實例，如何產生和推送程式碼？那麼，有幾個可選的軟體包可以幫助您提高工作效率：

```
# pkg install vim-console emacs-nox joe nano gnu-watch git tmux screen
```

最重要的一個是用於獲取程式碼的 *git*，如果您需要，其餘的都是可選的 - 主要是編輯器和終端包裝器。如果您想在自己的系統中使用圖形編輯器，也可以安裝 sshfs 或執行 sftp 來同步儲存庫中的檔案。以 root 使用者身分執行以下操作：

```
# cd
# git clone https://github.com/opnsense/core
```

擁有儲存庫後，您可以使用以下命令即時切換它：

```
# cd core
# make mount
```

是的，您在儲存庫中所做的更改現在將直接顯示在GUI中！不幸的是，這會將儲存庫掛載到 */usr/local* 上，因此如果您修改軟體包，變更將在 git 中亮起。當心。為了防止這種情況發生，您可以使用以下方法暫時卸載：

```
# make umount
```

為了完成啟動序列，將儘早掛載在 */root/core* 中設定的核心儲存庫（如果可用），並將使用其修改進行啟動（/usr/local/etc/rc 本身除外）。這使得可以在不同步系統檔案和儲存庫的情況下進行後端配置和啟動順序改進。

## 總結

輕鬆存取是協作的關鍵

雖然這只是 OPNsense 開發工作流程的一瞥，但它引起了人們對一個關鍵方面的關注：消除障礙，使盡可能多的人能夠快速產生結果。是的，有像 [git](http://git-scm.com/book/en/v2/Git-Basics-Getting-a-Git-Repository) 和 [GitHub](https://guides.github.com/activities/contributing-to-open-source/) 這樣的障礙需要處理，甚至可能需要學習 FreeBSD 的複雜性，但是一旦你的程式碼在 GUI 中並且工作正常，你就會感到自豪，能夠忍受確保你的奉獻在我們的上游儲存庫中佔有補丁。
