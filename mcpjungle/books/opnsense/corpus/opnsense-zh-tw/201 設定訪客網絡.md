# 設定訪客網絡

本指南將解釋如何使用強制門戶設定訪客網路。訪客網路廣泛用於允許客人控製酒店、RV 公園或企業的網路存取。

[圖](https://docs.opnsense.org/_images/opnsense_hotspot_controller.png)

注意事項

對於範例，我們期望 GUESTNET 介面與您實際的訪客網路交換器或存取點連接。本教學不解釋如何設定無線網路。

安全考慮

強制門戶功能完全基於網路中可用的資訊運作。 ARP或NDP等協定不提供任何固有的所有權證明。由於入口網站無法控制客戶端，因此不可能以加密方式證明身分和裝置之間的關係。因此，為了提高安全性，附加到入口網站的第 2 層網路必須在存取點/交換器層級進行適當隔離。

這些功能通常被稱為存取點的“第 2 層隔離”或交換器的“連接埠隔離”，可防止客戶端到客戶端的直接通訊。這些功能不能防止欺騙，但會降低網路中的可見性。

如果需要更強的身份，強制門戶可能不適合您。考慮改用由 RADIUS/ 策略伺服器支援的 802.1X 網路存取控制。

請注意，如果您使用 WireGuard 等第 3 層網絡，則這一點不太相關。

## 企業

企業通常希望與客人分享網路存取權限，並向他們展示包含歡迎訊息和一些使用指南（政策）的登陸頁面。同時，確保客人無法存取公司的本地網路並限制網路的最大使用量也很重要。

## 飯店和RV公園

酒店和RV公園通常利用強制門戶允許客人（付費）在有限的時間內訪問互聯網。客人需要使用可以在前台購買或免費取得的優惠券登入。 OPNsense 內建了對優惠券的支持，可以輕鬆地動態創建它們。透過此範例，我們將向您展示如何為此目的設定訪客網路並設定接收帳戶以建立新憑證。

## 先決條件

我們將從全新的 OPNsense 安裝開始設定。對於本教學課程，您將需要一個至少具有 3 個連接埠 (LAN/WAN/GUESTNET) 的系統。

## 第 6 步 - 限制訪客頻寬

對於我們的範例，我們將為訪客網路的 Internet 存取保留 10 Mbps 的下行速率和 1 Mbps 的上行速率。此頻寬將在連線的用戶端之間平均共用。

注意事項

平均共享的意思是，如果 10 個用戶同時嘗試使用盡可能多的頻寬，那麼每個人都獲得 1/10。因此，在我們的範例中，下行速率為 1 Mbps（下載）。還可以限制每個用戶的流量，另請參閱[設定流量調整](https://docs.opnsense.org/manual/how-tos/shaper.html)

轉到：防火牆 ‣ Shaper ‣ 管道。

按表單右下角的 **+** 建立下載管道，然後輸入以下詳細資訊：

|   |   |
| --- | --- |
| **啟用** |已檢查 |
| **頻寬** | 10 | 10
| **頻寬指標** |兆位元/秒 |
| **面具** |目的地 |
| **描述** |管道\_10Mbps\_down |

點選**儲存變更**。並為上傳流量添加另一個管道。

|   |   |
| --- | --- |
| **啟用** |已檢查 |
| **頻寬** | 1 |
| **頻寬指標** |兆位元/秒 |
| **面具** |目的地 |
| **描述** |管道\_1Mbps\_up |

按一下“**儲存變更**”。

建立流量整形器規則。按一下「**規則**」選項卡，然後按**+** 執行此操作。

首先切換進階模式（表單左上角），然後填寫以下詳細資料（保留所有未指定的預設值）：

|   |   |
| --- | --- |
| **序列** | （保留預設值）|
| **介面** | WAN |
| **接口2** | GUESTNET |
| **方向** |在 |
| **目標** |管道\_10Mbps\_down |
| **描述** |將訪客下載限制為 10 Mbps |

點選**儲存變更**。

|   |   |
| --- | --- |
| **序列** | （保留預設值）|
| **介面** | WAN |
| **接口2** | GUESTNET |
| **方向** |出 |
| **目標** |管道\_1Mbps\_up |
| **描述** |將訪客上傳限制為 1 Mbps |

點選**儲存變更**。

現在點擊“**應用**”以應用更改。

將您的PC或筆記型電腦連接到訪客網路並啟動您最喜歡的瀏覽器。輸入要瀏覽的位址，您將看到我們在上一個步驟中使用範本建立的登入表單。點擊登入並開始瀏覽。

要測試您的流量整形器，請造訪速度測試站點，例如 [http://www.speedtest.net/](http://www.speedtest.net/) 測試後，您的結果應該與此類似（如果您的網路連線有足夠的頻寬）。

注意事項

請記住，在此測試中我們只有一個連接的客戶端，因此所有保留的頻寬都將可供我們的客戶端使用。
