本操作指南描述了使用 OPNsense 作為PKI （公鑰基礎設施）建立**自簽名憑證鏈**的過程。

以下部分首先簡要概述PKI 、數位憑證和信任。

## [公鑰基礎設施簡介 ( PKI )](#id1)

**公鑰基礎設施 (PKI)**是用於管理數位金鑰和憑證的框架。 PKI 支援**非對稱加密**，其中兩個相關金鑰（公鑰和私鑰）一起使用來保護通訊和驗證使用者身分。

OPNsense 在系統 ‣ 信任中提供自己的PKI 。

### [PKI的組成部分](#id2)

-   **憑證授權單位（CA）**：核發和驗證數位憑證的受信任實體。
    
-   **註冊機構（RA）**：在頒發證書之前透過驗證實體來協助CA。
    
-   **數位憑證**：將公鑰綁定到個人或實體，以確認身分。
    
-   **憑證撤銷列表 ( CRL )**：已撤銷的憑證列表，用於管理信任。
    

創建和使用您自己的PKI時，上述組件取決於合規性。如果您是家庭用戶或管理小型公司網絡，這些都可以由一個人或一個小團隊完成。在大型基礎設施中， PKI管理需要仔細考慮。

### [PKI工作原理](#id3)

1.  CA頒發包含實體公鑰的數位憑證。
    
2.  發送方使用公鑰對傳送給憑證持有者的資訊進行加密。
    
3.  憑證持有者使用其私鑰解密資訊。
    
4.  數位簽名也可以使用私鑰創建，並由其他人使用公鑰進行驗證。
    

PKI共同實現了安全的資料交換、身份驗證和數位身份驗證。

### [公鑰與私鑰](#id4)

在PKI中，每個實體都有一對唯一的加密金鑰：

-   **公鑰**：公鑰是公開分享的。它用於加密數據，只有匹配的私鑰才能解密這些數據。它也用於驗證由私鑰創建的數位簽章。公鑰包含在數位憑證中，以實現安全的資料交換。
    
-   **私鑰**：私鑰由所有者妥善保管。它用於解密使用匹配的公鑰加密的數據，並產生可使用公鑰驗證的數位簽章。保護私鑰至關重要。
    

### [理解信任](#id5)

憑證信任是指對憑證頒發者的身分和真實性的確信。這並非一個技術術語，而是證書頒發和驗證機構（無論是個人還是組織）之間的信任。信任的實際操作是將CA憑證安裝到作業系統的信任儲存區。如果CA憑證是由第三方機構預先安裝的，則將其保留在信任儲存區中即表示您信任該機構。

**信任CA - 已頒發的證書**

使用CA頒發的證書時，信任是基於身份驗證，因為CA驗證證書請求者的身份；合規性，因為CA遵循行業標準並定期接受審計；以及廣泛的認可，因為CA根證書在大多數系統中都預先受到信任。

**信任自簽名憑證**

對於自簽名證書，信任取決於頒發者的安全措施，以及您是否信任其自簽名CA 。使用者必須在作業系統信任儲存區中接受或安裝該憑證。自簽名憑證被盜用的風險更高，因為通常沒有自動吊銷機制。由於缺乏第三方驗證和自動信任機制，將其用於公共服務會帶來許多限制。

### [證書鏈](#id6)

證書鏈能夠驗證多個層級的證書，而不是依賴驗證單一孤立的證書。

當可以輕易獲得免費且廣受認可的憑證時，是否應該考慮使用自簽名憑證鏈？

-   自簽名憑證與公開信任的憑證一樣安全。
    
-   他們建立了一條信任鏈，其中每一方都廣為人知並受到直接控制。
    
-   您對PKI及其每張證書的有效性擁有完全控制權。任何外部方都無法使憑證失效。
    

對於功能性憑證鏈，您至少需要一個根CA和一個葉憑證（最終實體憑證）。中間CA不是必需的，但增加了一層安全性：如果受到威脅，只有中間CA受到影響，從而保護根CA金鑰。

注意

為了加強安全性：

-   將根私鑰CA離線存儲，例如存儲在USB或安全驅動器上，並保存在安全位置，防止潛在的惡意軟體或未經授權的存取。
    
-   將私鑰的多份副本保存在不同的地方。
    
-   中間體CA通常生命週期較短，可以儲存在防火牆主機上。
    

## [建立憑證鏈](#id7)

我們將使用以下元件建立憑證鏈：

-   **根證書CA**：自簽名 → 簽署中間證書
    
-   **中級CA**：由根部簽名CA → 簽署葉片證書
    
-   **葉級憑證**：由中間憑證CA簽署 → 伺服器或使用者憑證

### [步驟 1：建立根目錄CA](#id8)

注意事項

私鑰無需儲存。為了提高安全性，只需將私鑰位置設為備用選項即可下載私鑰。這樣，私鑰就可以安裝在所需的伺服器上，而無需在 OPNsense 信任庫中保留副本。要頒發葉證書，只有中間 CA 需要將其私鑰儲存在信任庫中。

提示

可以使用同一個中間證書頒發機構CA頒發額外的葉子證書。鏈中的每一層都是一對多的關係。一個根證書頒發機構CA可以頒發多個中間證書頒發機構，一個中間證書頒發機構CA可以頒發多個葉子證書。

下一步是匯出憑證鏈，並在外部 Web 伺服器上使用葉子憑證。

### [步驟 4：匯出憑證鏈](#id11)

現在我們有了完整的憑證鏈，我們為通用的 Linux Apache Web 伺服器建立一個憑證包。

為此，我們需要兩個檔案：

-   以PEM格式依正確順序填入的憑證包：
    
    > 1.  根CA
    >     
    > 2.  中級CA
    >     
    > 3.  葉子證書
    >     
    
-   葉子憑證的私鑰
    

1.  匯出根目錄CA公鑰：
    
    > -   轉到“系統”‣“信任”‣“權限”
    >     
    > -   按下`Root CA`行「命令」列中的下載按鈕
    >     
    > -   選擇文件類型：證書，然後點擊下載
    >     
    
2.  導出中間體CA公鑰：
    
    > -   轉到“系統”‣“信任”‣“權限”
    >     
    > -   按下`Intermediate CA`行「命令」列中的下載按鈕
    >     
    > -   選擇文件類型：證書，然後點擊下載
    >     
    
3.  匯出 Leaf 憑證公鑰：
    
    > -   轉到“系統”‣“信任”‣“證書”
    >     
    > -   按下`Leaf Certificate`行「命令」列中的下載按鈕
    >     
    > -   選擇文件類型：證書，然後點擊下載
    >     
    
4.  匯出 Leaf 憑證私鑰：
    
    > -   轉到“系統”‣“信任”‣“證書”
    >     
    > -   按下`Leaf Certificate`行「命令」列中的下載按鈕
    >     
    > -   選擇檔案類型：私鑰，然後點擊下載
    >     
    

開啟文字編輯器，建立一個包含所有 3 個公鑰的檔案：

`certificate-bundle.pem`

```
-----BEGIN CERTIFICATE-----
Root CA public key data
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
Intermediate CA public key data
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
Leaf Certificate public key data
-----END CERTIFICATE-----
```

憑證包的關鍵僅在於葉子憑證的私鑰。根憑證授權單位和中間憑證授權單位的私鑰**並非**必需。

`certificate-bundle.key`

```
-----BEGIN PRIVATE KEY-----
Leaf Certificate private key data
-----END PRIVATE KEY-----
```

將這些憑證整合到您的 Web 伺服器中，即可使用此憑證包保護網站安全。若要實現自動信任，您必須將中間憑證和/或根憑證CA ）的公鑰安裝到連接到 Web 伺服器的任何用戶端。由於 Web 伺服器會向連接的用戶端提供完整的憑證鏈，因此如果使用者決定自行安裝公鑰，也可以手動建立信任。
