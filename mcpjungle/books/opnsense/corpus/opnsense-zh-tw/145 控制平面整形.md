# 控制平面整形

操作平面是描述和劃分網路設備功能的概念。

本質上，這個概念創建了邏輯層，其中資料包根據其用途和類型進行分類。

有 3 個平面：

1.  **控制平面**
    
    影響網路的可操作性。
    
    控制平面是路由器的大腦。它由動態IP路由協定（即OSPF, IS-IS, BGP等）、RIB、路由更新以及其他協定如PIM, IGMP, ICMP, ARP, BFD, LACP等組成。簡而言之，控制平面負責維護網路拓撲並與其他路由器或網路設備交換協定資訊。
    
2.  **管理平面**
    
    影響網路的可管理性。
    
    管理平面用於透過設備與網路的連接來管理設備。在管理平面中處理的協定範例包括簡單網路管理協定（SNMP）、Telnet、檔案傳輸協定（FTP）、安全性FTP和安全Shell（SSH）。這些管理協定用於監控和命令列介面 (CLI) 存取。
    
3.  **數據平面**
    
    影響用戶的應用程式。
    
    資料平面是轉送平面，負責透過路由器進行封包的交換。
    

## 控制平面整形的必要性

控制平面是網路正常運作的必要組件。如果控制平面管理不當，網路擁塞狀態將導致網路中斷。為了確保運作並避免此類事件造成中斷，我們可以利用流量整形。

**透過Shaping，我們可以為控制平面預留專用頻寬**

注意

控制平面不應與任何其他流量類型共用類別（管道或佇列）。

## 為 OPNsense 配置控制平面

配置將考慮已配置的整形器的存在，依照 [Fighting Bufferbloat with FQ\_CoDel](<144 使用 FQ_CoDel 對抗緩衝區膨脹.md>)

在下面的配置步驟中，假設這些調整速度：

| |下載 |上傳 |
| --- | --- | --- |
|兆位元/秒 | 495 | 495 30|

控制平面的頻寬分配要求：

| BW 的 1% |下載 |上傳 |
| --- | --- | --- |
|兆位元/秒 | 5 | 1 |

1% 是預設的最低值，BW 至少應設定為 1Mbit/s。如果需要的話可以增加。

注意

給予不同管道的BW需要從現有的管道中減去。

可用來控制平面整形的調度程序：

|調度程序|可用|注意|
| --- | --- | --- |
| FIFO | NO |沒有體重優勢|
| WFQ | YES |體重優點|
| DRR | NO |導致延遲 |
| QFQ | YES |體重優點|
| FQ\_CoDel | NO | AQM 背壓 |
| FQ\_PIE | NO | AQM 背壓 |

在此範例中，我們將為 IPv6 控制平面建立一個 Shaper。

首先，前往 Firewall ‣ Shaper ‣ Pipes。選擇*進階模式*

### 步驟 1a - 建立下載管道

在 **管道**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯管道**螢幕。

#### 建立控制平面管道以供下載

|設定|預設|描述 |
| --- | --- | --- |
| **啟用** |已檢查 | *檢查以啟用管道* |
| **頻寬** | 5 | *初始設定為調諧BW的 1%，若需要則增加* |
| **頻寬指標** |兆位元/秒 | *與頻寬相關的指標* |
| **佇列** | （空）| *留空：佇列單獨配置* |
| **面具** | （無）| *留空* |
| **調度程序類型** | WFQ | *預設或QFQ，允許使用每個佇列的權重* |
| **啟用 CoDel** | （空白）| *留空* |
| **(FQ-)CoDel 目標** | （空）| *留空* |
| **(FQ-)CoDel 間隔** | （空）| *留空* |
| **(FQ-)CoDel ECN** | （空）| *留空* |
| **FQ-CoDel 量子** | （空）| *留空* |
| **FQ-CoDel 限制** | （空）| *留空* |
| **FQ-CoDel 流程** | （空）| *留空* |
| **描述** |控制平面管道下載 | *自由字段，輸入描述性內容* |

### 步驟 1b - 建立上傳管道

在 **管道**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯管道**螢幕。

依照下載管道相同的流程，輸入 1% 的調整頻寬值，並輸入「Control-plane-Pipe-Upload」作為**說明**。

### 步驟 2a - 建立下載佇列

在 **佇列**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯佇列**螢幕。

#### 建立控制平面 IPv6 佇列以供下載

|   |   |   |
| --- | --- | --- |
| **啟用** |已檢查 | *檢查以啟用佇列* |
| **管道** |控制平面管道下載 | *選擇我們的管道* |
| **重量** | 100 | 100 *權重越高，隊列獲得BW的比例就越高* |
| **面具** | （無）| *為佇列留空* |
| **啟用 CoDel** | （空）| *為佇列留空* |
| **(FQ-)CoDel 目標** | （空）| *為佇列留空* |
| **(FQ-)CoDel 間隔** | （空）| *為佇列留空* |
| **(FQ-)CoDel ECN** | （空）| *為佇列留空* |
| **描述** |控制平面 IPv6 佇列下載 | *自由字段，輸入描述性內容* |

注意事項

使用WFQ或QFQ和權重，我們可以知道每個協議控制平面將獲得多少BW。

### 步驟 2b - 建立上傳佇列

在 **佇列**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯佇列**螢幕。

依照下載佇列相同的過程，選擇**“Control-plane-Pipe-Upload”**，並輸入“Control-plane-IPv6-Queue-Upload”作為**描述**。

### 步驟 3a - 建立下載規則

在 **規則**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯規則**畫面。

#### 建立用於下載的控制平面 IPv6 規則

|   |   |   |
| --- | --- | --- |
| **啟用** |已檢查 | *檢查以啟用規則* |
| **序列** | 1 | *自動產生編號，僅在需要時覆蓋* |
| **介面** | WAN | *選擇連接到網際網路的介面* |
| **原型** | ipv6 icmp | *在我們的範例中選擇協定 ipv6-icmp* |
| **來源** |任何| *要整形的來源位址，保留任意* |
| **來源端口** |任何| *要塑造的來源端口，保留任何* |
| **目的地** |任何| *目的地IP塑造，留下任意*|
| **目標端口** |任何| *目的港自行塑造，任意留任*|
| **方向** |在 | *符合傳入或傳出資料包或兩者（預設）。我們想要塑造下載，例如 WAN* 上的入口 |
| **目標** |控制平面 IPv6 佇列下載 | *選擇下載佇列* |
| **描述** |控制平面 IPv6 規則下載 | *輸入描述性名稱* |

### 步驟 3b - 建立上傳規則

在 **規則**標籤上，按一下右下角的**+**按鈕。彈出一個空的**編輯規則**畫面。

按照與下載規則相同的過程，使用相同的值，但以下情況除外：

-   **序列**（設定為2）；
    
-   **方向**（設定為“出”）
    
-   **目標**（設定為「控制平面-IPv6-佇列-上傳」）；
    
-   **描述**（設定為「控制平面-IPv6-規則-上傳」）
    

注意

這些序列需要比預設的任何規則或捕獲此流量類型的規則至少少 1，並且您可能需要相應地調整其他規則序列值。

### 第 4 步 - 完成配置

現在按 **應用** 啟動流量整形規則。

## 每個協定的附加控制平面

如果我們需要建立額外協定的控制平面，例如BGP, PIM等，我們可以使用已經建立的「Control-plane-Pipe」。簡單地將具有適當權重和規則的佇列新增至與流量相符的特定管道中。
