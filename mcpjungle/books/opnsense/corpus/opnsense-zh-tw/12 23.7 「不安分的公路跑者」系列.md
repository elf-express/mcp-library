# 23.7 「不安分的公路跑者」系列

八年半以來，OPNsense 透過模組化和強化開源防火牆，推動創新，提供簡單可靠的韌體升級、多語言支援、快速採用上游軟體更新以及清晰穩定的 2 條款BSD許可。

23.7 ，綽號“不安分的走鵑”，具有眾多MVC/API轉換，包括新的 OpenVPN“實例”配置選項、OpenVPN 組別名支持、OpenVPN 的延遲身份驗證、FreeBSD 13.2, PHP 8.2等等。

## 23.7.12 （2024年1月16日）

這確實是另一個版本。我們添加了大量的後端工作來提高安全性，並添加串流功能以避免資料密集型資料交換的記憶體耗盡。請注意，這是為24.1準備，其中將使用這些，但避免在23.7中直接使用，以降低迴歸的可能性。

24.1的發布日期是 1 月 30 日，這次我們採取了不同的方法，候選版本僅從開發版本提供，這意味著在最終版本發布之前不會有安裝媒體。

雖然RC1基本上已準備就緒，但由於正在排查內核崩潰問題，發布工作目前暫停。請留意RC1的發布說明。該版本預計將於本週發布，後續版本RC2將於下週發布。

以下是完整的更新說明：

-   系統：更改ZFS事務組預設值以避免過度磁碟磨損 [\[1\]]( https://github.com/opnsense/core/commit/269b9fbaf )
    
-   防火牆：在假定時間戳記正確之前，請先驗證 GeoIP 和BGP ASN目標是否包含至少 1 KB 的資料。
    
-   韌體：在大版本升級前啟用 Web 代理程式時，自動安裝 os-squid 插件
    
-   韌體：在大升級前重構導出並清理 Unbound DNS資料庫
    
-   韌體：禁止商業鏡像上的TLS低於1.3
    
-   openvpn：新增大於 29 的子網路遮罩的驗證，完全按照 OpenVPN 原始碼中的定義進行操作。
    
-   後端：支援使用“stream\_output”處理程序進行串流輸出
    
-   後端：實作可選的信任模型並新增擴充日誌記錄
    
-   後端：支援可選的 configd 設定檔
    
-   mvc：新增 IPPortField 類型
    
-   MVC：拆分 configdRun() 函數，以便傳回控制器可以以最小記憶體消耗進行串流傳輸的資源。
    
-   使用者介面：修正某些模態方塊中對話方塊缺少內邊距的問題
    
-   ui：設定預設資料大小，以提高選擇器的可讀性
    
-   使用者介面：當網格 td 內容超出範圍時顯示工具提示
    
-   插件：os-bind 1.29 [\[2\]]( https://github.com/opnsense/plugins/blob/stable/23.7/dns/bind/pkg-descr )
    
-   插件：os-ddclient 1.20 [\[3\]]( https://github.com/opnsense/plugins/blob/stable/23.7/dns/ddclient/pkg-descr )

## 23.7.9 （2023 年 11 月 23 日）

## 23.7.8 （2023年11月9日）

由於最近的需求，配置恢復GUI在許多方面都得到了改進，Squid 也更新到了新的主要版本 6。

WireGuard 核心外掛也新增了多項可靠性改進，我們認為它現在已經可以合併到核心核心中了。相關文件正在更新，但還需要一些時間才能確保與GUI中的變更保持一致。

本次更新還包含 FreeBSD 安全公告和各種修復。我們已註意到 OpenSSL 1.1.1 CVE -2023-5678，並且正在測試基於 OpenSSL 3 的構建版本，該版本將在24.1中發布，前提是不會對整體運行造成負面影響。我們也預期版本 1 的修復程序會更快發布，但由於 OpenSSL 不直接提供此類修復程序，因此修復程式的回應時間可能會增加。

-   系統：配置恢復時提供不符的介面邏輯，無需重啟
    
-   系統：允許新的備份API透過 /api/core/backup/download/this 直接下載最新配置
    
-   系統：擴充復原功能，以便能夠乾淨地遷移舊配置
    
-   系統：使信任庫重新載入成為條件性操作
    
-   接口：各種橋樑操控改進
    
-   介面：忽略主 IPv6 偵測的 ULA
    
-   介面：改進無線通道解析
    
-   防火牆：在即時日誌中保留過濾後的項目更長時間
    
-   防火牆：遷移別名時，請確保巢狀不會失敗

## 23.7.7 （2023年10月25日）

多個頁面的使用者體驗已提升。此外，本次更新還包含多項基於 FreeBSD 的更改，旨在進一步提高系統穩定性，並修復和改進了過去幾週在 GitHub 或論壇上提出的核心問題。

提醒第三方軟體倉庫使用者註意：FreeBSD 目前對其生態系統進行了一些更改。首先，由於「openssl」軟體套件現在基於 OpenSSL 3 版本，因此已將其遷移至「openssl111」。這可能會影響尚未更新的第三方軟體包的更新。雖然我們最終希望使用 OpenSSL 3，但在穩定版系統運行期間進行此操作並不合適。其次，FreeBSD 的連接埠不再依賴 Mozilla 提供的 ca_root_nss 軟體包信任函式庫，這為我們整合自己的信任庫帶來了技術障礙。此次更新使 curl 不再使用舊的 bundle 文件，但同時也確保基礎系統能夠註冊我們信任庫中引入的所有CA證書。目前最大的問題是，此過程比以前更慢，如果使用者的 CA 恰好在 FreeBSD 提供的不受信任清單中，則可能會導致這些 CA 不受信任。升級過程中，您將看到它何時寫入信任檔案和捆綁包，以及是否發生任何錯誤。

我們認為，在這兩種情況下，推遲這些變更都沒有任何好處，因此，在確保這些變更對我們的使用者群體有利，並在重要的地方表達我們的保留意見之後，我們將迅速實施這些變更。

遷移說明、已知問題與限制：

-   Unbound ACL現在預設接受所有流量，不再自動產生條目。這樣做是為了避免動態位址配置（尤其是VPN介面）出現連線問題。如果您不希望這樣，可以將其預設為阻止，並手動新增允許的條目。
    
-   Dpinger 不再自行觸發警報，因為它的機制太簡單，無法像 Apinger 那樣偵測丟包和延遲。延遲和丟包觸發機制已修復，日誌記錄也得到了改進。 rc.syshook 中的「monitor」功能仍然存在，但僅出於與現有使用者腳本的兼容性考慮而提供。
    
-   IPsec「隧道設定」 GUI現已棄用，建議手動遷移至「連線」 GUI 。相關終止支援公告將於明年發布。
    
-   新的 OpenVPN 實例頁面和API創建了一組獨立的實例，這些實例更嚴格地遵循 OpenVPN 的上游文件。舊版客戶端/伺服器設定無法透過API進行管理，也不會被遷移，但將繼續獨立運作。
    
-   舊的 DynDNS 插件已被移除，取而代之的是適用於 ddclient 的更新的MVC/API插件。我們已知悉 ddclient 已停止維護，遺憾的是，在我們開始開發新外掛程式僅一年後，ddclient 便宣布停止維護。我們將嘗試添加尚未發布的上游修復程序，並在同一插件中提供我們自己的、不依賴 ddclient 的 Python 後端作為替代方案。

-   Unbound ACL現在預設接受所有流量，不再自動產生條目。這樣做是為了避免動態位址配置（尤其是VPN介面）出現連線問題。如果您不希望這樣，可以將其預設為阻止，並手動新增允許的條目。
    
-   Dpinger 不再自行觸發警報，因為它的機制太簡單，無法像 Apinger 那樣偵測丟包和延遲。延遲和丟包觸發機制已修復，日誌記錄也得到了改進。 rc.syshook 中的「monitor」功能仍然存在，但僅出於與現有使用者腳本的兼容性考慮而提供。
    
-   IPsec「隧道設定」 GUI現已棄用，建議手動遷移至「連線」 GUI 。相關終止支援公告將於明年發布。
    
-   新的 OpenVPN 實例頁面和API創建了一組獨立的實例，這些實例更嚴格地遵循 OpenVPN 的上游文件。舊版客戶端/伺服器設定無法透過API進行管理，也不會被遷移，但將繼續獨立運作。
    
-   舊的 DynDNS 插件已被移除，取而代之的是適用於 ddclient 的更新的MVC/API插件。我們已知悉 ddclient 已停止維護，遺憾的是，該消息在我們開始開發新插件僅一年後才公佈。我們將嘗試添加尚未發布的上游修復程序，並在同一插件中提供我們自己的、不依賴 ddclient 的 Python 後端作為替代方案。
