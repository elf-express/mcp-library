Kea 是下一代 DHCP 軟體，由互聯網系統聯盟 (ISC) 開發。

它被認為是較大的HA啟用設定中ISC-DHCP的替代品，並且與radvd很好地協同作用，以實現HA啟用的路由器通告。

目前無法在 KEA 和 Unbound 之間動態註冊主機名，只有靜態預留才會在 Unbound 服務重新啟動時同步。

## [控制劑](#id2)

Kea 控制代理程式 (CA) 是一個守護進程，它公開用於管理 Kea 伺服器的 RESTful 控制介面。在建置高可用 dhcp 設定時，此類設定需要控制代理程式。

| **選項**|**描述** |
| --- | --- |
|已啟用 |啟用控制代理|
|綁定位址 | RESTful 介面應該可用的位址，通常是 localhost (127.0.0.1) |
|綁定連接埠 |在此選擇一個未使用的連接埠進行通訊。 |

注意事項

儘管控制代理需要使用高可用性對等點，但它不必偵聽非環回位址。預設情況下，對等配置使用所謂的“多執行緒配置 (HA+MT)”，在這種情況下，它會為 HA 通訊啟動一個單獨的偵聽器。

## [DDNS代理](#id3)

Kea DHCP DDNS (D2) 伺服器是 DHCP 伺服器與權威 DNS 伺服器之間的中間件。如果在設定的子網路中為用戶端指派了 IP 位址時應傳送動態 DNS 更新 (RFC2136)，則啟用它是一項要求。

| **選項**|**描述** |
| --- | --- |
|已啟用 |啟用DDNS伺服器。若要將更新傳送至權威名稱伺服器，請在 DHCPv4 和 DHCPv6 子網路內設定動態 DNS。 |
|手動設定 |停用設定檔產生並手動管理檔案 (/usr/local/etc/kea/kea-dhcp-ddns.conf)。 |
|綁定位址 | DHCP DDNS 伺服器介面可用的位址；通常這是本機主機（127.0.0.1）。 |
|綁定連接埠 |用於的連接埠號 DHCP DDNS 伺服器介面；預設值為 53001。

## [設定範例](#id5)

### [適用於中/大型HA設定的DHCPv4](#id6)

KEA DHCP 的主要優勢是能夠在多個伺服器之間同步租約，這使其成為無法使用 Dnsmasq DHCP 的中型到大型 HA 設定（超過 1000 個唯一客戶端）的理想選擇。

例如，我們在主 OPNsense 和備份 OPNsense 上配置具有兩個 KEA DHCP 實例的網路。

若要使用 `192.168.1.0/24` 網路對 LAN 進行最小的 HA 設定來設定 KEA，請依照下列步驟操作：

LAN 網路：

-   CARP IPv4 位址：`192.168.1.1/24`
    
-   主 IPv4 位址：`192.168.1.2/24`
    
-   備份 IPv4 位址：`192.168.1.3/24`
    

注意

所有設定必須在主機上完成，然後透過系統同步到備份： ‣ High Availability ‣ Status

-   轉到服務 ‣ KEA DHCP ‣ 控制代理：
    

| **選項**|**價值** |
| --- | --- |
| 已啟用 | `X` |
|綁定位址 | `127.0.0.1` |
|綁定埠 | `8000` |

### [DHCP選項](#id7)

### [動態DNS(RFC2136)](#id8)

KEA 允許透過動態 DNS (RFC2136) 將客戶端 FQDN 註冊到權威 DNS 伺服器。

這樣的權威 DNS 伺服器將是 ISC BIND 或 PowerDNS 等替代品。像 Dnsmasq 或 Unbound 這樣的遞歸 DNS 伺服器無法履行此角色。

提示

OPNsense 商業版包括 [權威 DNS](<48 權威DNS.md>) 以及 RFC2136 支援。

當客戶端註冊其 IP 位址時，DHCP 伺服器將收到包含客戶端主機名稱或 FQDN 的客戶端 FQDN（DHCP 選項 81）。如果客戶端僅傳送主機名，則使用 DNS 限定後綴將建構 FQDN 並強制更新。

注意

客戶端負責透過DHCP選項81發送動態DNS更新請求。只有使用此有效負載，主機名稱才會在轉送區域中註冊。不傳送任何主機名稱的用戶端無法註冊，管理員必須確保其所有裝置都配置了唯一的主機名稱。

作為範例設置，我們在ISC BIND中配置了這樣的區域。範例取自[KEA DDNS](https://kea.readthedocs.io/en/latest/arm/ddns.html)文件：

```
:
key "key.four.example.com." {
    algorithm hmac-sha224;
    secret "bZEG7Ow8OgAUPfLWV3aAUQ==";
};
:
```

若要設定 DHCPv4 範圍的轉送區域，請前往服務 ‣ KEA DHCP ‣ KEA DHCPv4 並選擇子網路：

| **選項**|**價值** |
| --- | --- |
|子網| `192.168.1.0/24` |
|泳池 | `192.168.1.100 - 192.168.1.199` |
| **DHCP 選項資料** | |
| 自動收集選項資料 |（必須取消選取此項目）|
|路由器（網關）| `192.168.1.1` |
| DNS 伺服器 | `192.168.1.1` |
|網域| `four.example.com` |
| **動態DNS** | |
| DNS 前進區 | `four.example.com.` |
| DNS 資格後綴 | `four.example.com.`（可選，如果您的客戶不通過 DHCP 選項 81 發送FQDN，請使用）|
| DNS 伺服器 | `203.0.113.1`|
| TSIG 按鍵名稱 | `key.four.example.com.` |
| TSIG 關鍵秘密 | `bZEG7Ow8OgAUPfLWV3aAUQ==` |
| TSIG關鍵演算法 | `hmac-sha224` |

接下來，啟用KEA DDNS代理。前往服務 ‣ KEA DHCP ‣ DDNS 代理：

| **選項**|**價值** |
| --- | --- |
|已啟用 | `X` |
|綁定位址 | `127.0.0.1`|
|綁定埠 | `53001` |

套用設定後，DHCP 伺服器根據 DHCP 租約更改事件建構 DDNS 更新請求，稱為 NameChangeRequest (NCR)，然後將其發佈到 DDNS 代理。 DDNS代理嘗試將每個請求與適當的DNS伺服器相匹配，並與這些伺服器進行必要的對話以更新DNS資料。

注意事項

每個 DNS 前向區域的 TSIG 鍵名稱必須是唯一的。如果您配置多個子網路具有相同的 DNS 轉送區域，但 TSIG 金鑰名稱和 TSIG 金鑰秘密，則僅考慮第一個。最佳實踐是為每個子網路創建一個唯一的DNS轉發區域，每個區域都有一個唯一的TSIG金鑰名稱。

注意

只有配置了 DNS 伺服器的子網路才會發送 DDNS 更新。

對於反向區域更新，請在子網路內啟用進階模式。將您的 DNS 反向區域新增至現有的正向配置。請注意，反向區域更新將與正向區域更新傳送到同一台 DNS 伺服器。

某些客戶端可能會傳送客戶端特定標誌以避免反向區域更新。您可以使用「覆蓋無更新」和「覆蓋用戶端更新」來覆寫該行為。

### [前綴委託(IA\_PD)](#id9)

Kea 支援具有靜態或動態前綴的前綴委託。前綴委託最常用於路由器設定後面的路由器，但也用於運行自己的虛擬機器的客戶端實作。

#### [路線安裝](#id10)

每當 `IA_PD` 租約被確認時，就會自動安裝一條針對請求 DHCPv6 用戶端的鏈路本地位址的路由。

由於租約檔案在高可用性模式下同步，因此路由也將在兩個對等方上安裝和清理。

注意事項

如果未找到用戶端路由安裝的 MAC 位址，請查看常規 DHCPv6 設定中的 *MAC 來源* 選項。它會影響預設情況下客戶端MAC位址的建置方式。目前預設的 `ipv6-link-local` 將從 EUI-64 鏈路本地地址建構 MAC。這應該適用於大多數客戶端，但如果他們使用隨機連結本地地址，`duid`將是下一個最佳選擇。
