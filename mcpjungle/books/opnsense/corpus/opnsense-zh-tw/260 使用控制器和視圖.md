# 使用控制器和視圖


## 一般

執行路由後，控制器負責處理為請求執行的實際程式碼。因為我們希望為每個處理的請求實現一些基礎知識，所以您應該從我們的基類繼承，以確保授權和CSRF保護等基本功能。

控制器放置在目錄 /usr/local/opnsense/mvc/app/controllers/<Vendor\_name>/<Module\_name>/ 中，並應使用以下命名約定，在每個類別檔案上新增後綴 Controller.php，在所有操作方法上新增後綴 Action。

## 類別結構

大多數元件繼承自一組標準控制器，這些控制器在下圖中指定，包括它們的主要使用範圍（/ui 或 /api）

[圖：../../_images/Controller_class_hierarchy.svg](https://docs.opnsense.org/_images/Controller_class_hierarchy.svg)

## 基於視圖的控制器

對於渲染標準頁面，我們選擇使用 Volt 模板，在本例中繼承的基本控制器是 OPNsense\\Base\\ControllerBase，並且應該負責將模板綁定到控制器。每個範本都會自動接收標準功能（例如選單系統）。

實現單一操作的線框應如下所示：

```php
<?php
    public function indexAction()
    {
       // address some variables to pass through the view
        $this->view->my_variable1 = 'test 1';
        $this->view->my_variable2 = 'test 2';
       // pick a template
        $this->view->pick('SampleVendor/Sample/index');
    }
```

伏特模板 SampleVendor/Sample/index.volt 可能包含類似以下內容：

```
the contents of my_variable1 => <b> {{ my_variable1 }} </b> <br>
the contents of my_variable2 => <b> {{ my_variable2 }} </b> <br>
```

完整的範例可以在 OPNsense\\Sample 控制器目錄中找到。

有關如何編寫 Volt 頁面的更多資訊可以在這裡找到：[https://docs.phalcon.io/latest/volt/](https://docs.phalcon.io/latest/volt/)

## 使用者表格

當設計者需要表單供使用者輸入資料時，他們可以使用我們標準控制器上的`getForm()`方法來提供一個簡單的xml檔案作為模板引擎使用的定義。範例部分包含如何使用這些的逐步指南。

`getForm()` 方法本身僅將結構傳遞給視圖，視圖可以使用此資訊在頁面載入時呈現表單（靜態）。在我們的標準佈局 [partials](https://github.com/opnsense/core/blob/master/src/opnsense/mvc/app/views/layout_partials/form_input_tr.volt) 中，我們提供了一些不同的記錄類型，我們將在下面詳細介紹：

**屬性**

|名稱 |描述 |
| --- | --- |
|編號 |屬性的唯一 ID |
|類型 |輸入或欄位的類型。有關有效類型的列表，請使用下面的類型表 |
|標籤|屬性標籤（可見文字）|
|尺寸|大小（字元寬度）屬性（如果適用） |
|高度|高度（字元長度）屬性（如果適用）|
|幫助 |幫助文字|
|先進|屬性“is Advanced”，僅在進階模式下顯示 |
|提示|輸入控制提示|
|風格|新增 css 類，有助於使用 jQuery 選擇器更輕鬆地識別項目 |
|寬度|寬度（以像素為單位）（如果適用）|
|允許新建 |如果適用，允許新項目（用於清單）|
|唯讀 |如果為 true，輸入欄位將為唯讀 |

**類型**

|名稱 |描述 |
| --- | --- |
|標題|標題行 |
|文字|單行文字|
|密碼 |用於敏感輸入的密碼欄位。內容將不會顯示。 |
|文字方塊 |多行文字方塊|
|複選框 |複選框|
|下拉式選單 |從下拉清單中選擇單一項目 |
|選擇\_多個 |從下拉清單中選擇多個項目 |
|隱藏 |不適合使用者互動的隱藏欄位 |
|資訊 |靜態文字（幫助圖標，無需輸入或編輯）|
|訊息\_link |靜態文字作為連結（轉換為可點擊連結）|

## 基於API的控制器

對於 API 調用，使用派生一個單獨的類，該類別實作一個簡單的介面來處理調用。與視圖控制器的主要區別在於，操作應該會傳回包含回應資料的命名數組，而不是選擇模板。

用於回顯請求的簡單索引控制器如下所示：

```php
class TestController extends ApiControllerBase
{
    /**
     * @return array
     */
    public function echoAction()
    {
        if ($this->request->hasPost("message")) {
            $message = $this->request->getPost("message");
        } else {
            $message = " " ;
        }

        return ["message" => $message];
    }
}
```

當放置在 Vendor/Sample 的 API 目錄中時，可以透過使用 jQuery 向 /api/sample/test/echo 發送 post 請求來呼叫：

```
$.ajax({
    type: "POST",
    url: "/api/sample/test/echo",
    success: function(data){
        alert(data.message) ;
    },
    data:{message:"test message"}
});
```

提示

OPNsense 隨附兩個標準控制器，用於合併預設操作場景，例如變更模型和重新啟動服務。這些可以在我們的存儲庫中找到[此處](https://github.com/opnsense/core/blob/master/src/opnsense/mvc/app/controllers/OPNsense/Base/)，並命名為`ApiMutableModelControllerBase`, `ApiMutableServiceControllerBase`。兩者都擴展了`ApiControllerBase`，如本章所述。可變模型控制器在[使用網格](<367 使用網格模組和插件.md>)中有更詳細的解釋，服務控制器在[api啟用服務](<368 API啟用標準服務.md>)中有解釋

## 可搜尋的記錄集

上一章的技巧描述了在使用模型時如何使用網格，但在某些情況下存在未綁定到模型的資料集。例如，在遍歷遺留資料或收集系統統計資料時。

為此我們在`ApiControllerBase`中加入了方法`searchRecordsetBase()`。使用此方法可以將記錄集掛鉤到模型網格中可用的相同搜尋功能中。

提供以下參數：

|名稱 |描述 |
| --- | --- |
| $記錄|陣列作為記錄集，例如\[ \[‘id’ => ‘1’\], \[‘id’ => ‘2’\], … \] |
| $欄位|不應傳回所有資料時的選用欄位清單 |
| $預設排序|可選的預設排序順序（記錄集中的欄位名稱）|
| $filter_funct | $filter\_funct |可選的可插入過濾器函數，使用有問題的記錄進行呼叫 |
| $sort\_flags |預設為 `SORT_NATURAL \| SORT_FLAG_CASE` |

注意事項

為了過濾字段集，請確保所有記錄都包含請求的欄位。目前排序時無法省略字段。

將其實現到您自己的控制器中應該非常簡單：

```php
class TestController extends ApiControllerBase
{
    /**
     * @return array
     */
    public function searchAction()
    {
        $records = [];
        $records[] = ['id' => '1', 'description' => 'test 1'];
        $records[] = ['id' => '2', 'description' => 'test 2'];
        $records[] = ['id' => '3', 'description' => 'test 3'];
        return $this->searchRecordsetBase($records);
    }
}
```

## 簡單的 csv 匯出/匯入助手

為了匯出或匯入 csv 結構化數據，可以使用一些助手來簡化這些操作。 `ApiControllerBase`新增了一個簡單的記錄集導出方法（`exportCsv()`），`ApiMutableModelControllerBase`包含了一個匯入資料的方法（`importCsv()`）。

當使用`ArrayField`類型從模型匯出資料時，可以使用`asRecordSet()`方法輕鬆擷取資料。

從使用 `ApiMutableModelControllerBase` 實現的控制器下載檔案的最小功能範例如下所示：

```php
public function downloadAction()
{
    $this->exportCsv($this->getModel()->path->to->items->asRecordSet());
}
```

將數據回饋回模型：

```php
public function uploadReservationsAction()
{
    if ($this->request->isPost() && $this->request->hasPost('payload')) {
        return $this->importCsv(
            'path.to.items',
            $this->request->getPost('payload'),
            ['my_key']
        );
    }
}
```
