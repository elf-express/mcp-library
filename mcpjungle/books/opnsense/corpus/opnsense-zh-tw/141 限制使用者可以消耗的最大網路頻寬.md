# 限制使用者可以消耗的最大網路頻寬


在此範例中，我們將在連線的使用者之間指派網路下載流量，使每個使用者最多接收 1 Mbps。

[圖](https://docs.opnsense.org/_images/nwdiag-3a3b295df95f5f47b05bd5247ff3374f6471bbc9.png)

簡單網路圖

首先前往 Firewall ‣ Shaper ‣ Pipes。

## 步驟 1 - 建立下載和上傳管道

在 **管道**標籤上，按一下右下角的**+**按鈕。將彈出一個空的**編輯管道**螢幕。

建立下載管道

|   |   |   |
| --- | --- | --- |
| **啟用** |已檢查 | *檢查以啟用管道* |
| **頻寬** | 1 | *所需頻寬的數值* |
| **頻寬指標** |兆位元/秒 | *與數值一起使用的量測* |
| **面具** |目的地 | *每個下載客戶端的動態管道* |
| **描述** | PipeDown-1Mbps | *自由字段，輸入描述性內容* |

建立上傳管道

|   |   |   |
| --- | --- | --- |
| **啟用** |已檢查 | *檢查以啟用管道* |
| **頻寬** | 1 | *所需頻寬的數值* |
| **頻寬指標** |兆位元/秒 | *與數值一起使用的量測* |
| **面具** |來源 | *每個上傳客戶端的動態管道* |
| **描述** | PipeUp-1Mbps | *自由字段，輸入描述性內容* |

注意事項

始終為下載和上傳限制建立單獨的管道，以避免在單一管道中混合雙向流量時出現未定義的行為。

在 **規則**標籤上，按一下右下角的**+**按鈕。將彈出一個空的**編輯規則**螢幕。

為來自互聯網的流量建立規則（下載）。

|   |   |   |
| --- | --- | --- |

| **介面** | WAN | *選擇連接到網際網路的介面* |
| **原型** | ip | *選擇協議，在我們的範例中為IP* |
| **來源** |任何| *來源位址，任意留*|
| **來源端口** |任何| *要塑造的來源端口，保留任何* |
| **目的地** | 192.168.1.0/24 | *要塑造的目的地IP，選擇LAN網絡* |
| **目標端口** |任何| *目的港自行塑造，任意留任*|
| **目標** | PipeDown-1Mbps | *選擇 1 Mbps 下載管道* |
| **描述** |形狀下載 | *輸入描述性名稱* |

### 優先使用隊列

透過利用佇列，我們可以影響管道內的頻寬，並根據加權演算法為某些應用程式提供比其他應用程式更多的頻寬。

這個想法很簡單：假設我們有一個 10 Mbps 的管道和 2 個應用程序，例如 smtp（電子郵件）和 http(s)。 http(s) 流量的權重為 1，smtp 流量的權重為 9，然後當管道的所有容量都使用時，電子郵件流量將獲得比 http(s) 流量多 9 倍的頻寬，從而導致 http(s) 流量為 1 Mbps，smtp 流量為 9 Mbps。

對於我們的範例，我們僅查看下載流量，但可以對上傳流量執行完全相同的操作。

## 第 3 步 - 建立規則

在 **規則**標籤上，按一下右下角的**+**按鈕。將彈出一個空的**編輯規則**螢幕。

為 smtp 下載流量（電子郵件）建立規則

|   |   |   |
| --- | --- | --- |
| **序列** | 11 | 11 *自動產生編號，僅在需要時覆寫* |
| **介面** | WAN | *選擇連接到網際網路的介面* |
| **原型** | ip | *選擇協議，在我們的範例中為IP* |
| **來源** |任何| *來源位址，任意留*|
| **來源端口** |郵件傳輸協定 | *形狀的來源端口，smtp 或 25* |
| **目的地** |任何| *目的地IP塑造，留下任意*|

|   |   |   |
| --- | --- | --- |
| **序列** | 21 | 21 *自動產生編號，僅在需要時覆寫* |

|   |   |   |
| --- | --- | --- |
| **序列** | 31 | *自動產生編號，僅在需要時覆寫* |
| **介面** | WAN | *選擇連接到網際網路的介面* |
| **原型** | ip | *選擇協議，在我們的範例中為IP* |
