## [引言](#id2)

透明防火牆無需建立不同的子網路即可過濾流量。此防火牆將同一個二層廣播域橋接到兩個或多個連接埠。如果連接了VLAN中繼鏈路，則所有VLAN標記的幀都將被透明地橋接。

可以使用此設定透過防火牆規則進行過濾，並使用IDS/IPS透過 netmap 驅動程式檢查所有封包。

有關 FreeBSD 上橋接過濾的更多信息，請參閱 [filtering-bridges](https://www.freebsd.org/doc/en/articles/filtering-bridges/article.html)

注意

此橋樑與交通整形方案不相容。

注意

當需要轉送 VLAN 標記訊框時，請勿在網橋的成員連接埠上建立任何 VLAN。否則，VLAN 標記訊框將被過濾，網橋將不再透明。

### [要求](#id3)

為了獲得最佳相容性和效能，建議使用至少配備 3 個實體連接埠的裸機設備。虛擬化設備也可以使用，但可能會出現一些難以察覺的二層問題，例如橋接或 VLAN 配置方面的問題。

注意

如果使用 VLAN 中繼，則應始終使用裸機設備，最好是 Intel 網路卡。用於IDS/IPS的原生 netmap 驅動程式與 VLAN 結合使用時，並非總是能與其他廠商或虛擬化網路卡正常運作。另請確保僅透過此中繼發送帶有標籤的訊框。

## [配置](#id4)

我們的範例設備有 3 個可用的網路連接埠：

-   igc0: LAN （橋接）
    
-   igc1: WAN （橋接）
    
-   igc2：管理
    

```
         +-----------------+                 +-----------------+
Internet |                 |      WAN (igc1) |     (Bridge)    | LAN (igc0)
-------->|    ISP Router   |---------------->|     OPNsense    |----------> Switch
         |                 |      trunk port |  Firewall, IPS  | trunk port
         +-----------------+                 +-----------------+
                                                      | Management (igc2)
                                                      |-------------------> Switch
                                                        access port
```

提示

管理接口可以直接連接到ISP路由器的單獨端口，也可以連接到VLAN的內部交換機，並透過橋接器返回。

### [1. 分配管理介面](#id5)

管理介面將用於存取防火牆 WebGUI，並啟用對網際網路的存取以進行韌體更新。

-   轉到“介面”‣“分配”，然後分配一個新介面。選擇一個可用的空閒連接埠（例如 igc2）並進行分配，將描述設定為「管理」。
    
-   然後轉到“介面”‣“管理”，根據您的使用情況，將 IPv4 配置類型設定為DHCP或“靜態 IPv4”。
    

接下來，我們新增一條防火牆規則，允許透過此管理介面存取 WebGUI：

-   轉到防火牆‣規則‣管理，並新增規則，允許HTTPS存取目標「此防火牆」。
    

套用所有這些設定後，透過管理連接埠連接到您的裝置以進行下一步操作。

### [2. 更改系統可調參數](#id6)

這裡我們修改了防火牆規則，使其在網橋上匹配，而不是在網橋成員上匹配。

-   前往“系統”‣“設定”‣“系統可調選項”，並進行設定：
    
    > -   `net.link.bridge.pfil_bridge` - `1`
    >     
    > -   `net.link.bridge.pfil_member` - `0`
    >     
    

### [3. 建立橋樑](#id7)

-   轉到“接口” WAN和“接口” LAN ：
    
    > -   將 IPv4 設定類型和 IPv6 設定類型設定為`None`
    >     
    > -   停用 Block 私有網路和 Block bogon 網路
    >     
    

注意

停用所有綁定到LAN介面的DHCP伺服器。

-   轉到“接口”‣“設備”‣“橋接器”：
    
    > -   新增橋接器，並選擇WAN和LAN作為成員接口
    >     
    

注意

不要選擇“啟用鏈路本地位址”，在此配置中，橋接介面應保持未編號狀態（不分配IP位址或任何VLAN到該介面或其成員介面）。

-   轉到“接口”‣“分配”：
    
    > -   指派新的橋接接口，並將描述設定為「橋接」。
    >     
    
-   轉到“接口”‣“橋接”：
    
    > -   在介面設定中啟用橋接介面
    >     
    > -   在`None`上設定IPv4配置類型和IPv6配置類型
    >     
    

### [4. 新增防火牆規則](#id8)

-   轉到“防火牆”‣“規則”‣“橋接”：
    
    > -   在橋接介面上新增防火牆規則，允許所有流量（進出方向）。
    >     
    

提示

如有需要，您可以建立更嚴格的規則。如果只需使用IDS/IPS ，則允許任何流量的規則就足夠了。由於該網橋完全透明且無編號，因此任何用戶端都無法直接與防火牆通訊。

### [5. 啟用IDS/IPS](#id9)

為了檢查所有橋樑交通狀況，我們可以啟用入侵偵測服務。

前往“服務”‣“入侵檢測”‣“管理”‣“常規設定”

|選項|說明 |
| --- | --- |
| 已啟用 | `X` |
| IPS模式 | `X` |
| 混雜模式 | `X` （如果橋接成員接收到 VLAN 標記訊框） |
| 接口 | `WAN` |

之後下載並啟動所需的規則，並套用配置。

注意

不要選擇橋接接口，務必選擇WAN接口。模擬的netmap驅動程式無法處理橋接介面上的VLAN，它必須以本機模式連接到實體介面。

### [6. 將介面連接到現有基礎設施](#id10)

現在您可以將橋接成員介面連接到各自的交換器或路由器。

WAN應連接到面向WAN側的中繼端口， LAN應連接到內部保護側的中繼端口。

防火牆將能夠透過管理連接埠連接到互聯網，以獲取最新更新。
