# 路線

路由是防火牆的核心功能之一，它負責根據（預先定義的）路徑在網路上轉送封包。

在防火牆的路由部分，您可以追蹤已設定的路由，並自行定義靜態路由，以告訴防火牆在將封包轉送到特定網路時應該走哪條路徑。



當客戶端向防火牆發送封包，目標網路並非直接連接到該防火牆時，防火牆通常會檢查其路由表，以確定應該將封包傳送至哪個網關（請參閱[網關](<93 閘道.md>) ）。

提示

使用 traceroute（介面 ‣ 診斷 ‣ 路由追蹤）來驗證流量到達目的地所遵循的路徑。

## 配置

在這裡你可以設定靜態路由，參考上一章的圖表，在這裡你可以定義`[1]`如何使用路由器`[3]`訪問`[2]` 。

設定項的數量顯然是有限的，我們需要知道網關和目標網路。

---

|   |   |
| --- | --- |
| 已停用 | （暫時）停用此項目 |
| 網路位址 | 要到達的目標網路 |
| 網關 | 要使用的網關。 |
| 描述 | 此物品的可選描述 |

注意事項

已知有些服務會自行更新路由表，在這種情況下，您不應該手動新增靜態路由（例如，OpenVPN 會管理自己的路由）。

## 地位

狀態頁面顯示路由表的目前活動內容。

---

|   |   |
| --- | --- |
|原型 |協定（IPv4 或 IPv6）|
|目的地 |目的地網路|
| 閘道 | 傳送至此目標網路的封包的位址 |
|旗幟|路由具有關聯的標誌，這些標誌在發送到與路由匹配的目的地時影響協定的操作。有關詳細信息，請參閱下面的 **標誌** 表。 |
| 用途 | 統計透過此路由傳送的資料包數量 |
| MTU | 此路線的MTU設定 |
| Netif | 此路由使用的介面 |
| Netif（名稱）| 如果找到接口，則填寫接口名稱 |
|過期|此路由應過期的時間，若永不過期則為零。各個協定套件有責任確保路由在過期後被實際刪除。 |

### 旗幟

內核支援以下標誌。

| 字母/旗幟 | 說明 |
| --- | --- |
| 1 \[ RTF \_PROTO1\] | 協定特定路由標誌 |
| 2 \[ RTF \_PROTO2\] | 協定特定路由標誌 |
| 3 \[ RTF \_PROTO3\] | 協定特定路由標誌 |
| B \[ RTF \_BLACKHOLE\] | （更新期間）丟棄封包 |
| b \[ RTF \_BROADCAST\] | 此路由表示廣播位址 |
| C \[ RTF \_克隆\] | 使用時產生新路由 |
| c \[ RTF \_PRCLONING\] | 協定指定的在使用時產生新路由 |
| D \[ RTF \_DYNAMIC\] | 動態建立（透過重定向） |
| d \[ RTF \_完成\] | 訊息已確認 |
| G \[ RTF \_GATEWAY\] | 目的地是個網關 |
| H \[ RTF \_HOST\] | 主機條目（否則為網路） |
| L \[ RTF \_LLINFO\] | 有效的協定到連結位址轉換 |
| M \[ RTF \_MODIFIED\] | 動態修改（透過重定向） |
| R \[ RTF \_REJECT\] | 主機或網路不可達 |
| S \[ RTF \_STATIC\] | 手動新增 |
| U \[ RTF \_UP\] | 可用路線 |
| X \[ RTF \_XRESOLVE\] | 外部守護程式解析名稱 |

## 紀錄

路由相關的日誌記錄，例如 IPv6 的`radvd`和`rtsold`會將訊息寫入此日誌部分，這些訊息可用於偵錯目的。
