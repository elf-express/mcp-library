radvd（負責此功能的服務）是 IPv6 的路由器通告守護程式。它監聽路由器請求並發送路由器通告，如「IP版本 6 (IPv6) 的鄰居發現」([RFC 4861](https://tools.ietf.org/html/rfc4861))中所述。透過這些通告，主機可以自動配置其位址和一些其他參數。它也定義了「基於低功耗無線個域網路 (6LoWPAN) 的 IPv6 鄰居發現最佳化」([RFC6775](https://tools.ietf.org/html/rfc6775))。他們也可以根據這些通告選擇預設路由器。

注意

[Dnsmasq](<194 Dnsmasq DNS & DHCP.md>)是新安裝中的預設RA守護進程，如果您想使用radvd，請停用其*路由器廣告*設定。

## [常規設定](#id2)

此服務可以在服務‣路由器通告中設定。

**常規設定**

| **選項**|**描述** |
| --- | --- |
| **啟用** |啟用或停用此條目。如果使用“追蹤介面（舊版）”，則現有的停用條目也會停用該介面上的廣告。或者，如果需要，請切換到“身份關聯”以進行完整的手動配置。 |
| **介面** |選擇應傳送路由器通告的介面。前綴將從該介面的主IP構建，該前綴由所述介面的「身份關聯」或「追蹤介面（傳統）」IPv6模式分配。如果此介面上存在其他虛擬IP位址，則它們的前綴也將被通告。 |
| **模式** |選擇要在從此介面傳送的路由器通告中設定哪些標誌。 |
| **最小間隔** |從介面發送主動多重播送路由器通告之間所允許的最短時間（以秒為單位）。 |
| **最大間隔** |從介面發送主動多重播送路由器通告之間所允許的最大時間（以秒為單位）。 |
| **遞歸 DNS 伺服器 (RDNSS)** |預設情況下，將此介面 IP 位址與啟用的 DNS 服務或設定的全域 DNS 伺服器一起使用。您可以在此指定最多三個顯式伺服器。 |
| **DNS 搜尋清單 (DNSSL)** |預設使用本系統的網域名稱作為DNSSL選項。您可以在此指定顯式域。 |
| **路線** |路線以CIDR格式指定。路由定義的前綴應該是網路前綴；它可用來向主機通告更具體的路由。 |

**進階設定**

| **選項**|**描述** |
| --- | --- |
| **建構子** |預設情況下，使用「常規設定」中給定「介面」的主要前綴。設定構造函數時，a 的主前綴 WAN 可以使用接口代替。一個[NDP 代理](<212 ndp-proxy-go（鄰居發現代理）.md>) 如果相同則需要 WAN 前綴被多個共享 LAN 接口。 |
| **偏好** |選擇路由器通告 (RA) 守護程序的優先權。 |
| **棄用前綴** |透過宣布零首選生命週期來棄用關閉時通告的前綴。 |
| **關機廣告** |關閉後，發送路由器生命週期為零的最終通告。 |
| **預設生命週期** |此路由器被視為有效預設路由器的生命週期（以秒為單位）。 |
| **首選一生** |生命週期（以秒為單位）地址仍然是新連接的首選。 |
| **有效期限** |地址在變得不可用之前保持有效（以秒為單位）。 |
| **來源位址** |選擇RA訊息中嵌入的來源位址。如果使用CARP位址，DeprecatePrefix 和RemoveRoute 都預設為「off」。 |
| **NAT64前綴** |路由器通告中包含的NAT64前綴。為此服務保留的「眾所周知的前綴」是64:ff9b::/96。 |
| **連結MTU** |向顧客宣傳特定的MTU。必須等於或大於 1280 並且對連結有效。 |
| **啟用DNS** |控制嵌入式DNS配置（RFC8106）的發送。 |
| **遞歸 DNS 伺服器生命週期** |廣告遞歸 DNS 伺服器的生命週期（以秒為單位）。 |
| **DNS 搜尋清單生命週期** |已公佈的 DNS 搜尋域的生命週期（以秒為單位）。 |
| **路由生命週期** |通告路由的生命週期（以秒為單位）。 |
| **刪除路線** |透過發送零生命週期來在關閉時撤回通告的路由。 |

## [路由器廣告（模式）](#id3)

模式選擇包含 radvd 的一些預定義設置，這些設置影響一組配置選項並適用於特定的實現場景。它們定義網路中使用的用戶端部署類型。

---

|   |   |
| --- | --- |
|僅路由器|僅通告此路由器，用戶端使用靜態 IPv6 位址 |
|非託管|客戶端將使用無狀態位址自動配置（SLAAC），而不提供其他（非位址）資訊。 |
|管理 | DHCPv6提供的狀態設定、位址設定|
|協助|有狀態配置，由 DHCPv6 提供的位址配置，儘管通告的路由也可以用於無狀態位址自動配置設定 (SLAAC)。 |
|無國籍|客戶端將使用無狀態位址自動設定（SLAAC）|

## [設定範例](#id4)

### [在LAN上發布前綴](#id5)

最常見的設定是 WAN 介面上的 DHCPv6，並透過 DHCPv6-PD 接收路由前綴。將 LAN IPv6 設定設定為具有唯一前綴 ID 的「追蹤介面（傳統）」或「身分關聯」時，路由器通告可以將該前綴和預設路由傳送至用戶端。

前往 Services ‣ Router Advertising 並新增一個條目：

| **選項**|**描述** |
| --- | --- |
| **啟用** | X |
| **介面** | LAN |

按**儲存**並**應用**

預設情況下，RDNSS和DNSSL選項將傳送至客戶端，其中包含LAN介面的IPv6位址和預設系統域。

### [在LAN上發布多個前綴](#id6)

如果除了 GUA（全球單播位址）前綴之外還應發送 ULA（唯一本地位址）前綴，請在介面 ‣ 虛擬 IP 中建立虛擬 IPv6 位址。在LAN介面上配置，確保前綴長度為/64。

然後，應用服務 ‣ 路由器通告中的設定將設定附加前綴。

### [DHCPv6](#id7)

路由器通告足以讓客戶端自動產生SLAAC位址、接收預設閘道和DNS伺服器。這些是 IPv6 連線的基本要求。

可能存在主機名稱註冊、靜態保留和 DHCPv6 選項等進階要求。

對於這些情況，有兩個 DHCPv6 伺服器可用：[KEA](<196 KEA DHCP.md>) 和 [Dnsmasq](<194 Dnsmasq DNS & DHCP.md>)。由於 Dnsmasq 最適合與其自己的路由器通告功能一起使用，因此KEA 是與 radvd 配對的最合理選擇。對於 HA 設定尤其如此，因為 KEA 可以同步 IPv6 租約。

注意

KEA 和 radvd 的組合需要靜態 WAN 前綴，因為 KEA 無法動態追蹤前綴。

若要將 DHCPv6 伺服器通告給客戶端，請根據您的要求設定可用的 [模式](#radvd-mode)。
