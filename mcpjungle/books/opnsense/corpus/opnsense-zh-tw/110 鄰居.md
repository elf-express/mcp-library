## [概述](#id2)

鄰居是指具有硬體位址且連接到相同OSI層 2 廣播域的主機。

主機維護自己的本機鄰居表，與其他廣播域中的主機無關。

當主機向IP位址發送封包時，它首先嘗試解析目標位址是否位於同一廣播域內。如果目標位址不在同一連結上，則封包將傳送到預設閘道。

像防火牆這樣的中心主機會自動學習大多數鄰居的訊息，因為它會變成預設網關。

## [自動發現](#id3)

主機發現服務提供了一種透過ARP和NDP訊息發現網路上大多數鄰居的方法。當守護程式啟動時，它會建立一個已知鄰居的資料庫，並記錄IP位址到MAC映射何時發生變化。

這可以用來了解網路的不穩定程度以及是否出現未知的新主機。

運行守護程序可以改進一些目前直接使用ARP和NDP表的服務。該資料庫具有持久狀態，查詢速度更快，並且對於IPv6，能夠更好地了解RFC 4941位址。

### [設定](#id4)

設定選項位於「介面」‣「鄰居」‣「自動發現」。

---

|   |   |
| --- | --- |
| **啟用** | 啟用「hostwatch」服務以發現網站主機。 |
| **介面** | 將主機發現限制為此處選擇的介面。 |
| **混雜模式** | 監聽並非直接寄往我們的網路封包。 |
| **詳細日誌記錄** | 啟用詳細模式，將更詳細的資訊記錄到日誌中。 |
| **忽略網路** | 忽略選定的網路。 |

注意

此服務僅監聽乙太網路介面。隧道、環回和類似介面將被跳過，因為沒有ARP/NDP流量。

提示

混雜模式很少需要。防火牆位於中心位置，負責在網路之間路由流量。這種設定適用於防火牆僅作為觀察者的網路環境。

### [已發現主機](#id5)

如果主機發現服務已啟用，則可以在此表中看到資料庫的內容。否則，將顯示內核ARP和NDP表的目前內容。

「最後上線時間」欄位是一個有趣的指標，它顯示了最近加入或一段時間未出現的主機。

### [探索日誌](#id6)

在發現日誌中，您可以找到有關新網站（主機）和移動的條目。

這些日誌結構簡單，可以被外部 syslog 伺服器用於進一步處理（例如，新網站的警報）。

如果日誌中充斥著大量類似抖動的流量，則您的網路可能有問題。最常見的情況是MAC位址重複，或是多台主機爭用同一個IP位址。

## [靜態分配](#id7)

本節可讓您在網路上定義靜態 IPv4/IPv6 到MAC位址的對應。

IPv4 條目將會儲存到ARP表中，IPv6 條目將會儲存到NDP表中。

這些表格定義了哪個硬體位址與哪一個IP位址關聯。當無法接收ARP/NDP訊息，或我們希望強制特定客戶端使用IP/MAC組合時，這會非常有用。

開啟頁面後，將顯示一個包含所有已定義靜態條目的網格：

---

|   |   |
| --- | --- |
| **乙太網路位址** | 用戶端硬體MAC位址（格式為 xx:xx:xx:xx:xx:xx） |
| **IP位址** | 要指派給提供的MAC位址的IP位址，該位址最終將位於ARP (IPv4) 或NDP (IPv6) 表中 |
| **描述** | 僅供內部使用 |

注意

有些條目可能來自其他來源，例如DHCP ，並且無法編輯。

提示

若要分析ARP或NDP表的目前內容，請使用 [diagnostics](<114 診斷.md>)文件中詳細介紹的介面診斷選單。
