# 使用配置


## 一般

若要新增可從前端系統或命令列使用的新服務和系統調用，您可以建立 configd 操作。

所有可用範本應安裝在 OPNsense 系統上的以下位置：

```
/usr/local/opnsense/service/conf/actions.d/
```

*請注意，應從前端存取的所有操作都應具有已註冊的 configd 操作，如果可能，請使用標準 rc(8) 腳本來啟動/停止服務。 *

## 命名約定

服務模板應使用獨特的名稱來識別您的服務並包含簡單/清晰的操作。

例如，我們將描述預設安裝的 ssh 模板。

**檔名：**

```
/usr/local/opnsense/service/conf/actions.d/actions_sshd.conf
```

我們的 ssh 服務有兩個可用操作：

-   重新啟動
    
    -   啟動/重新啟動 ssh 服務
        
    
-   停止
    
    -   停止/殺死所有 ssh 守護進程
        
    

```
[restart]
command:/usr/local/etc/rc.sshd
parameters:
type:script
message:starting sshd

[stop]
command:/bin/pkill -TERM sshd; exit 0
parameters:
type:script
message:stop sshd
```

在括號 \[\] 之間可以找到操作的名稱，實際呼叫的定義在下列參數：值對中定義。當服務或模組提供大量操作時，有時添加另一個操作等級是實用的。

例如，此服務的重新啟動服務呼叫將轉換為：**sshd restart**

如果我們有像 **filter diag info** 這樣的操作，您可以建立一個 actions\_filter.conf，其中包含 \[diag.info\] 部分。

## 動作屬性

|物業 |文法 |描述 |
| --- | --- | --- |
|命令 |文字|要執行的 shell 命令字串 |
|參數|每個參數 %s |要使用的參數列表，例如：/i %s |
|類型 |腳本\|腳本\_輸出 |呼叫類型：<br>• script（僅返回退出狀態）<br>• script\_output（傳回結果）<br>• Stream\_output（串流傳回結果）|
|錯誤|文字\[否\]| `errors:no` 忽略腳本退出程式碼 |
|允許的\_組 |文字|允許執行此操作的群組清單（例如wheel） |
|留言 |文字|要傳送到系統日誌的訊息（您可以使用 %s 參數）|
|描述 |文字|人性化的描述，也允許GUI使用 |

## 測試動作

若要測試新的 configd 操作，請先使用下列命令重新啟動 configd 服務：

```
service configd restart
```

接下來使用提供的幫助命令來執行我們的操作：

```
configctl sshd restart
```

## 擴展環境

Configd自己的設定可以在[configd.conf](https://github.com/opnsense/core/blob/master/src/opnsense/service/conf/configd.conf)檔案中找到。在某些情況下，使用 configd 操作所使用的附加設定來擴展環境是可行的。

若要新增環境變量，請使用包含 `[environment]` 部分的 `.conf` 副檔名在 `conf/configd.conf.d/` 目錄中建立新的設定檔。例如，若要新增代理伺服器（用於韌體更新程式），請使用下列設定：

/usr/local/opnsense/service/conf/configd.conf.d/proxy.conf

```
[environment]
HTTP_PROXY=http://proxy-adddress:8080
HTTPS_PROXY=http://proxy-adddress:8080
NO_PROXY=192.168.1.2
```

注意事項

更改 configd 設定後，不要忘記透過 gui 或 service configd restart （以 root 身分）重新啟動 configd 服務。

警告

當使用與基本配置中已指定的相同設定時，這些設定將被覆蓋。設定檔的解析順序是先讀取所有供應商提供的屬性，然後再讀取其他檔案。找到的最後一個屬性是正在使用的屬性（例如，在環境中指定新的`PATH`，將覆蓋我們的`configd.conf`中提供的屬性。）

注意事項

`NO_PROXY` 設定可用來排除主機使用代理，這對於 xmlrpc 同步通常很實用
