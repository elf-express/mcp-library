# 新增約束


約束可以在上一章中描述的基本欄位提供的類型驗證之上使用。基底類別 BaseConstraint 用作基底類型並包含共享功能。

由於欄位通常僅在偵測到變更時才進行驗證，因此通常需要新增對鏈驗證的反向引用。

## 依賴約束

當選擇相互依賴時，您可以使用 DependConstraint 類型。以下範例使 sslur 僅依賴 sslbump 選項，因為需要 <reference> 標籤來確保當其中一項設定變更時，另一個設定也會再次驗證。

```xml
<sslbump type="BooleanField">
    <Constraints>
        <check001>
            <type>DependConstraint</type>
            <addFields>
                <field1>sslurlonly</field1>
            </addFields>
        </check001>
    </Constraints>
</sslbump>
<sslurlonly type="BooleanField">
    <Constraints>
        <check001>
            <reference>sslbump.check001</reference>
        </check001>
    </Constraints>
</sslurlonly>
```

## 全或無約束

確保選項僅在組合選擇時才有效。

## 單選約束

當選項組合無效時，您可以將選項掛鉤在一起，這樣同一時間只能選擇其中一個選項。

## 唯一約束

此限制有助於確保 ArrayField 中的所有項目都是唯一的，例如以下範例，它確保該集合中的所有「檔案名稱」都是唯一的。

```xml
<filename type="TextField">
    <Constraints>
        <check001>
            <type>UniqueConstraint</type>
        </check001>
    </Constraints>
</filename>
```

## 與字段約束比較

CompareToFieldConstraint 將目前欄位的值與相同層級（例如在同一 ArrayField 中）引用欄位的值進行比較。例如，它用於 [rspamd](https://github.com/opnsense/plugins/blob/master/mail/rspamd/src/opnsense/mvc/app/models/OPNsense/Rspamd/RSpamd.xml) 插件，以確保某些值的順序正確。此約束可用於比較數值。

範例：

```xml
<check003>
  <ValidationMessage>This field must be bigger than the greylist score.</ValidationMessage>
  <type>ComparedToFieldConstraint</type>
  <field>greylistscore</field>
  <operator>gt</operator>
</check003>
```

在此範例中，目前欄位的值必須大於欄位「greylistscore」的值。

欄位值：

|   |   |
| --- | --- |
|驗證訊息 |驗證訊息（可翻譯），驗證失敗時會顯示。 |
|類型 |與字段比較約束 |
|領域 |我們引用的另一個字段|
|運算子|操作員檢查該值。有效的運算子有 gt、gte、lt、lte、eq、neq |

運營商：

|   |   |
| --- | --- |
| gt |大於 |
| gte |大於或等於|
| LT |小於|
| LTE |小於或等於 |
|情緒智商|等於|
|內克 |不等於|

## 設定約束條件

SetIfConstraint 用於使某些欄位有條件強制。主要用於[nginx](https://github.com/opnsense/plugins/blob/master/www/nginx/src/opnsense/mvc/app/models/OPNsense/Nginx/Nginx.xml)插件中，例如選擇實作類型。一般來說，其他欄位應該是 OptionField，但並不需要如此。一般來說，隱藏或顯示前端實作所需（不需要）的欄位以及簡化 Web 介面是一個好主意。請注意：選取的欄位應位於相同層級（例如 ArrayField）。

範例：

```xml
<check001>
  <ValidationMessage>This field must be set.</ValidationMessage>
  <type>SetIfConstraint</type>
  <field>match_type</field>
  <check>id</check>
</check001>
```

在此範例中，如果欄位“match\_type”的值為“id”，則該值將是強制的。

欄位值：

|   |   |
| --- | --- |
|驗證訊息 |驗證訊息（可翻譯），驗證失敗時會顯示。 |
|類型 |設定約束 |
|領域 |我們引用的另一個字段|
|檢查 |使該欄位成為必需的其他欄位的值 |
