網路位址轉換（縮寫為NAT）是一種分離外部和內部網路（WAN 和 LAN）並在內部網路上的用戶端之間共用外部IP的方法。 NAT 可用於 IPv4 和 IPv6。

下面的大多數選項使用三個不同的位址：來源位址、目標位址和重定向位址。這些地址用於以下用途：

|   |   |
| --- | --- |
|來源 |流量從哪裡來。這通常可以保留在“any”上。 |
|目的地 |交通流向何處。對於來自外部的傳入流量，這通常是您的外部 IP 位址。 |
|重定向 |流量應該重定向到哪裡。 |

警告

-   不應依賴網路位址轉換作為安全措施。
    
-   禁用 pf 也會停用 NAT。
    

## [部分術語解釋](#id2)

**BINAT**：NAT一般作用於一個方向。但是，如果您的網路大小相同，您也可以使用BINAT，它是雙向的。這可以簡化您的設定。如果你沒有同等規模的網絡，你只能使用常規的NAT。

**NAT反射**：當內部網路上的客戶端嘗試存取另一個客戶端，但使用*外部*IP而不是內部（這是最合乎邏輯的）時，NAT反射可以重寫此請求，以便它使用內部IP，以避免繞道並應用針對實際外部流量的規則。

提示

有一個操作方法部分詳細解釋了[NAT反射](<136 倒影與髮夾NAT.md>)。

注意事項

啟用 **NAT 反射** 產生的 NAT 規則僅包含直接連接到您的防火牆的網路。這意味著，如果您有一個與 LAN 分離的專用網絡，則需要使用手動來源 NAT（出站）規則來新增此網路。

**池選項**：當有多個 IP 可供選擇時，此選項將允許調整使用哪一個 IP。預設情況下，循環法將簡單地將資料包分發到一台伺服器到另一台伺服器。如果您只有一個外部IP，則此選項無效。

## [目的地NAT（港口轉送）](#id3)

當多個內部用戶端共用一個外部IP位址時，任何針對外部IP位址的入站連線都不會成功，因為防火牆不知道將流量傳送到哪裡。這可以透過建立連接埠轉送規則來解決。例如，要存取防火牆後面的 Web 伺服器，需要將連接埠 80 和 443 重新導向到該伺服器。

可以透過導覽到防火牆‣NAT‣目標NAT（連接埠轉送）來設定目標NAT（連接埠轉送）。在這裡，您將看到目的地NAT（連接埠轉送）規則的概述。

新增規則時，以下欄位可用：

**組織**

| **選項**|**描述** |
| --- | --- |
| **已停用** |停用此規則，使其不會被使用。 |
| **順序** |規則依序進行評估。 |
| **類別** |為規則組織指派類別。 |
| **描述** |輸入描述以標識此規則。 |

**介面**

| **選項**|**描述** |
| --- | --- |
| **介面** |選擇流量源自的介面。 |
| **版本** |選擇 IPv4、IPv6 或兩者。 |
| **協議** |為規則組織分配類別。 |
| **描述** |選擇此規則應符合的協定。 |

**來源**

| **選項**|**描述** |
| --- | --- |
| **反轉來源** |符合指定來源以外的所有內容。 |
| **來源位址** |指定要符合的來源網路或別名。 |
| **來源連接埠** |來源連接埠或連接埠範圍。 |

**目的地**

| **選項**|**描述** |
| --- | --- |
| **反轉目的地** |符合指定目的地以外的所有內容。 |
| **目的地位址** |要符合的目標位址或別名。 |
| **目的港** |目標端口或端口範圍。 |

**翻譯**

提示

這會將原始目的地（例如，防火牆的外部IP位址）轉換為新目標（例如，內部主機）。

| **選項**|**描述** |
| --- | --- |
| **重定向目標IP** |將流量轉送到的內部IP位址。 |
| **重定向目標連接埠** |內部主機上要將流量轉送至的連接埠。 |
| **池選項** |選擇使用多個目標 IP 時如何指派流量。 |

**選項**

| **選項**|**描述** |
| --- | --- |
| **無 XMLRPC 同步** |將此規則排除在與HA 對等點的同步之外。 |
| **NAT 反思** |控制此規則的NAT反射。 |
| **設定標籤** |為符合此規則的封包指派標籤。 |
| **符合標籤** |僅符合具有此標記的資料包。 |
| **防火牆規則** |預設情況下，需要手動建立防火牆規則，這也是建議的選項。或者，您可以使用 Pass，它會在 nat 規則上傳遞流量（在規則標籤中不可見）或產生可以透過具有更高優先權的規則推翻的介面規則。請記住，規則的目標應與此 NAT 規則中定義的目標相符。 |

注意事項

此功能也用於實現透明代理。連線可以轉送到守護程式（在本機上偵聽），然後守護程式嘗試從 /dev/pf 裝置取得原始目的地IP。

例如，處理 HTTP 流量的透明代理需要一條規則，將流量從 TCP 連接埠 80、IPv4 轉送到 127.0.0.1:3128（在預設設定中）。

注意

您不能 NAT 到 \[::1\] （IPv6 本機）或任何其他連結本機位址。 IPv6 需要NAT 可路由位址，至少需要一個ULA（唯一本地位址）作為目標。

### [過濾規則關聯](#id4)

此選項控制在 Firewall ‣ Rules \[new\] 中連結過濾規則的建立。

**手冊**

如果您想手動建立自己的防火牆‣規則\[新\]，請選擇此選項。未建立連結的過濾規則。

注意事項

建議更複雜的設定使用此選項，例如 VPN 介面上的目標 NAT（連接埠轉送）規則。可以編輯過濾規則並停用回復等功能。

**透過**

過濾規則將自動新增和更新。在 Firewall ‣ Rules \[new\] 中無法檢視或編輯此規則。

注意事項

大多數設定的推薦選擇。

**註冊規則**

在 Firewall ‣ Rules \[new\] 中新增連結的過濾規則，該規則會在 NAT 規則更新時自動更新。建立的過濾規則無法手動編輯。

## [一對一](#id5)

一對一 NAT 會將兩個 IP 一對一轉換，而不是像其他 NAT 類型中最常見的一對多轉換。在這方面，它類似於NPT對IPv6的作用。

一對一 NAT 可以透過導航至防火牆 ‣ NAT ‣ 一對一進行設定。

新增規則時，以下欄位可用：

**組織**

| **選項**|**描述** |
| --- | --- |
| **啟用** |啟用此規則 |
| **順序** |規則依序進行評估。 |
| **類別** |為規則組織指派類別。 |
| **描述** |輸入描述以標識此規則。 |

**介面**

| **選項**|**描述** |
| --- | --- |
| **介面** |選擇流量源自的介面。 |

**映射**

| **選項**|**描述** |
| --- | --- |
| **類型** |在這裡選擇BINAT（預設）或NAT，當網路大小相等時，binat通常是最佳選擇。使用NAT我們還可以映射不等大小的網路。 BINAT規則指定外部網路和內部網路之間的雙向映射，並且可以從兩端使用，nat僅適用於一個方向。 |
| **外部網路** |輸入 1:1 映射或網路的外部子網路的起始位址。這是流量將轉換至/來自的位址或網路。 |
| **反轉來源** |使用此選項可以反轉符合的意義。 |
| **來源** |輸入 1:1 映射的內部子網路。 |

**目的地**

| **選項**|**描述** |
| --- | --- |
| **反轉目的地** |符合指定目的地以外的所有內容。 |
| **目的地位址** |要符合的目標位址或別名。 1-1 映射僅用於往返指定目的地的連線。提示：這通常是“任何”。 |

**選項**

| **選項**|**描述** |
| --- | --- |
| **日誌** |記錄此規則處理的資料包。 |
| **NAT反射** |選擇自動NAT反射模式。 |

## [來源NAT（出站）](#id6)

當內部網路上的用戶端發出出站請求時，網關必須將來源IP更改為網關的外部IP，因為否則外部伺服器將無法發送回應。

源NAT（出站），縮寫為SNAT，可在防火牆‣NAT‣源NAT（出站）下設定。

如果您只有一台外接IP，大多數情況下自動模式就適合。對於多個外部位址，您可能需要使用混合或手動模式並新增自訂規則。

|   |   |
| --- | --- |
|自動源NAT規則產生|預設。遵循上述行為，適用於大多數場景。 |
|手動源NAT規則生成|不產生自動規則。它們可以手動添加。 |
|混合源NAT規則產生|自動產生規則，並且可以新增其他手動規則。 |
|禁用來源NAT規則產生|禁用來源NAT。例如，這用於[透明橋](<118 透明過濾橋.md>)。 |

新增規則時，以下欄位可用：

**組織**

| **選項**|**描述** |
| --- | --- |
| **啟用** |啟用此規則 |
| **順序** |規則依序進行評估。 |
| **類別** |為規則組織指派類別。 |
| **沒有 XMLRPC 同步** |從 HA 同步中排除此規則。 |
| **描述** |輸入描述以標識此規則。 |

**介面**

| **選項**|**描述** |
| --- | --- |
| **介面** |選擇流量源自的介面。 |
| **版本** |選擇 IPv4、IPv6 或兩者。 |
| **協議** |為規則組織分配類別。 |
| **描述** |選擇此規則應符合的協定。 |

**來源**

| **選項**|**描述** |
| --- | --- |
| **反轉來源** |符合指定來源以外的所有內容。 |
| **來源位址** |指定要符合的來源網路或別名。 |
| **來源連接埠** |來源連接埠或連接埠範圍。 |

**目的地**

| **選項**|**描述** |
| --- | --- |
| **反轉目的地** |符合指定目的地以外的所有內容。 |
| **目的地位址** |要符合的目標位址或別名。 |
| **目的港** |目標端口或端口範圍。 |

**翻譯**

提示

這會將原始來源（例如，內部主機）轉換為新來源（例如，防火牆的外部IP位址）。

| **選項**|**描述** |
| --- | --- |
| **翻譯來源IP** |符合此規則的封包將被對應到此處給出的IP位址。 |
| **翻譯來源連接埠** |來源連接埠號碼或眾所周知的名稱。 |
| **池選項** |選擇如何在多個轉換位址之間指派流量。 |
| **來源雜湊金鑰** |在規則集重新載入過程中保持來源雜湊映射穩定。 |
| **靜態連接埠** |防止TCP和UDP封包的來源埠發生變化。 |
| **端點獨立** |為 UDP 流量啟用端點獨立映射。 |

**選項**

| --- | --- |

| **符合本機標籤** |用於指定封包必須已帶有給定標記才能符合規則。 |

## [NPTv6](#id7)

網路前綴轉換，縮寫為 NPTv6，用於轉換 IPv6 位址。常見用法是將全域（“WAN”）IP 轉換為本機 IP。在這方面，它與NAT類似，儘管NPTv6只能用於一對一映射地址，而不像NAT通常將一個外部IP轉換為多個內部地址。

NPTv6 路由在防火牆 ‣ NAT ‣ NPTv6 中列出。

新增規則時，以下欄位可用：

**組織**

| **選項**|**描述** |
| --- | --- |
| **啟用** |啟用此規則 |
| **順序** |規則依序進行評估。 |
| **類別** |為規則組織指派類別。 |
| **描述** |輸入描述以標識此規則。 |

**介面**

| **選項**|**描述** |
| --- | --- |
| **介面** |選擇此規則適用於哪個介面。 |

**映射**

| **選項**|**描述** |
| --- | --- |
| **內部 IPv6 前綴** |輸入此網路前綴轉換的內部 IPv6 前綴（來源）。 |
| **外部 IPv6 前綴** |輸入此網路前綴轉換的外部 IPv6 前綴（目標）。留空以使用指定的追蹤介面自動偵測前綴位址。為內部前綴指定的前綴大小也將套用於外部前綴。 |
| **軌跡介面** |當未提供目標前綴時，請使用在所選介面上定義的前綴，而不是套用此規則的介面。 |

**選項**

| --- | --- |
| **日誌** |記錄此規則處理的資料包。 |
