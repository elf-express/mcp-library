# 儀表板小工具

## 一般

OPNsense 提供了一個簡單的框架，用於在簡單的抽象層中開發儀表板小部件。每個小部件都是一個獨立的 Javascript 模組，從基本小部件類別擴展而來。每個小部件都會公開一組由儀表板框架邏輯呼叫的函數。每個小部件類別也公開其用於獲取資料的 API 端點，以便儀表板控制器可以應用每個小部件的 ACL 檢查。

此框架提供以下功能：

-   響應式動態網格，允許使用者建立自訂佈局。
    
-   可以為每個登入使用者儲存佈局。
    
-   限制特定使用者存取特定頁面的管理員將自動限制對也使用相同資料來源的小部件的存取。
    
-   小部件是完全非同步的，這意味著它們完全彼此獨立，確保資源密集型小部件不會佔用其他小部件。
    

此框架使用 [GridStack](https://gridstackjs.com/) 建立儀表板網格。

小部件放置在`src/opnsense/www/js/widgets/`目錄中。

## 範例

在討論任何細節之前，提供一個包含大部分核心邏輯的範例通常是最有用的：[介面概述](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/Interfaces.js)小部件。

## 功能

[BaseWidget](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/BaseWidget.js) 顯示了 widget Javascript 模組的骨架。小部件擴展此類以向框架提供預設值。為了使常見模式的生活變得更容易，其他基本小部件也可能會被公開。目前這些是：

-   [BaseTableWidget](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/BaseTableWidget.js)：公開一個可以在多個方向上設定且只需要資料饋送的動態表格。
    
-   [BaseGaugeWidget](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/BaseGaugeWidget.js)：公開一個 Gauge 小部件，允許使用多個鉤子呈現簡單的當前/總計值來自訂小部件。
    

當從 BaseWidget 擴充時，以下函數可被小工具覆蓋：

### *建構函式*

```
constructor(config) {}
```

為了向框架提供合理的預設值，派生的 javascript 類別應始終在建構函數中首先呼叫 `super()`。之後，可以覆蓋預設值。屬性是：

-   `this.title`。設定標題中小部件的標題。
    
-   `this.tickTimeout`。設定呼叫`onWidgetTick()`函數的時間間隔（以秒為單位）。預設值為 10 秒。
    

如果小部件已被持久化（使用者按下「儲存」），則載入的小部件配置將傳遞到建構函數中。可以使用 `await this.getWidgetConfig()` 函數取得小部件正確重新載入自身所需的任何自訂資料。請參閱[可設定小工具](#configurable-widget)部分。

### *取得網格選項*

```
getGridOptions() {}
```

為了提供靈活性，小部件可以選擇覆寫此函數並傳回將合併並載入到 GridStack API 中的物件。在小部件渲染到DOM之前呼叫此函數。例如，以下程式碼：

```
getGridOptions() {
    return {
        // trigger overflow-y:scroll after 650px height
        sizeToContent: 650
    }
}
```

會將 `sizeToContent: 650` 鍵值對插入到 GridStack 選項中，確保在插入捲軸之前小部件的高度不超過最大 650 像素。 GridStack API 參考可以在[此處](https://github.com/gridstack/gridstack.js/blob/master/doc/README.md) 找到。

儲存儀表板後，該物件也會保留，這表示這些屬性也會在小部件重新載入時傳遞到建構函數中。

這些屬性不必與 GridStack API 相對應，任何自訂資料都可以推送到這裡。

### *取得標記*

```
getMarkup() {}
```

該函數必須傳回一個 jQuery 對象，其中包含建立小部件佈局所需的靜態標記。此函數通常只會傳回容器（附加樣式），其中將使用 onMarkupRendered() 載入動態內容

### *ajax呼叫*

```
ajaxCall(url, data, method='GET') {}
```

此函數是 jQuery AJAX 函數的包裝器。它用於對後端進行API調用。此函數內部綁定了重試機制，因此如果API呼叫失敗，它將在很短的時間間隔後重試。預設情況下，呼叫將在三次嘗試後失敗，之後小工具將顯示一般錯誤訊息。

某些呼叫需要使用 POST HTTP 動詞才能將資料傳送到後端。此時，可以將`method`參數改為`POST`，並將`data`參數填入要傳送的資料。

### *onMarkupRendered*

```
async onMarkupRendered() {}
```

一旦儀表板加載完畢，並且所有小部件標記都已渲染到DOM，就可以透過定義此函數來提供動態內容來填充小部件。由於這是一個 `async` 函數，因此必須等待該函數內的任何 API 呼叫。例如：

```
async onMarkupRendered() {
    await this.ajaxCall('/api/interfaces/overview/interfacesInfo', {}, (data, status) => {
        // do something with the data
    });
}
```

這將確保所有其他小部件保持響應，並且在載入資料時會出現一個微調器。使用 jQuery 更新 `getMarkup()` 準備的標記。

### *onWidgetResize*

```
onWidgetResize(elem, width, height) {}
```

如果使用者調整了小部件的大小，或者由於佈局限制/瀏覽器調整大小而調整了小部件的大小，則將使用更新的寬度和高度呼叫此函數。小部件元素也被傳遞到函數中。

使用此功能可使小部件保持響應並使不同尺寸的佈局保持一致。例如：

```
onWidgetResize(elem, width, height) {
    if (width > 500) {
        $('.interface-info-detail').parent().show();
        $('.interface-info').css('justify-content', 'initial');
        $('.interface-info').css('text-align', 'left');
    } else {
        $('.interface-info-detail').parent().hide();
        $('.interface-info').css('justify-content', 'center');
        $('.interface-info').css('text-align', 'center');
    }
}
```

上面的程式碼將確保如果小部件的寬度小於 500px 寬，則刪除不太重要的資訊。根據需要調整樣式。

警告

雖然此函數已進行去抖動（限制以防止過多呼叫），但在調整大小期間仍會經常執行。如果此函數執行大量繁重工作，請確保實作狀態概念，以防止相同邏輯執行不必要的次數。可以在 [BaseTableWidget](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/BaseTableWidget.js) 中找到這樣的範例。

如果從此函數傳回 true，網格將被強制更新以適應新的佈局。

### *onWidgetTick*

```
onWidgetTick() {}
```

此函數每`this.tickTimeout`秒呼叫一次。當儀表板開啟時，此功能用於更新儀表板上顯示的資料。

### *onWidget關閉*

```
onWidgetClose() {}
```

當小部件從網格中刪除時執行。確保清理此小部件正在使用的所有資源。並不總是需要重寫此函數，但您可能正在使用第三方庫，該庫需要在刪除小部件時採取操作。一個例子是渲染圖表的清理。

注意

如果您使用 BaseWidget EventSource 機制，請確保呼叫 `super.onWidgetClose()` 來清理與伺服器的持久連線。

### *可見性改變*

```
onVisibilityChanged(visible) {}
```

當頁面的可見性發生變化（選項卡或實例切換）時執行。您很可能不需要此功能，但如果您需要，請務必呼叫`super.onVisibilityChanged(visible)`。

### *開啟事件來源*

```
openEventSource(url, onMesage);
```

當您的小部件需要持久連接來流資料時，請使用 `super.openEventSource()` 函數以及 API 端點和回調函數。 `onMessage`回呼函數接受單一`event`參數，其中`data`屬性包含事件資料。

此函數與`ajaxCall()`函數綁定相同的重試機制。

### *關閉事件來源*

```
closeEventSource();
```

關閉當前活動`EventSource`。如果小工具關閉且您沒有覆寫 `onWidgetClose` 函數，則會自動呼叫此函數。如果您這樣做，請務必致電`super.onWidgetClose()`。

## 基表控件

BaseTableWidget 公開了一組函數，可以輕鬆建立具有一些基本 CRUD 功能的響應式表格。要利用它，只需從 BaseTableWidget 進行擴展，它也會自動公開 BaseWidget 函數。例如：

```js
import BaseTableWidget from "./BaseTableWidget.js";

export default class YourWidget extends BaseTableWidget {}
```

### *建立表格*

```
super.createTable(id, options);
```

建立並傳回一個 jQuery 對象，並將 id 屬性設定為該函數的 id 參數。 `options`參數是一個具有以下結構的物件：

```js
let options = {
    headerPosition: 'top'|'left'|'none',
}
```

如果`headerPosition`是`top`，則定義一些額外的選項：

```js
let options = {
    headerPosition: 'top',
    rotation: <number>,
    headers: [],
    sortIndex: <number>,
    sortOrder: 'asc'|'desc'
}
```

-   `rotation` 會將表格條目的數量限制為此值，並將新資料「捲動」到檢視中。
    
-   `headers` 定義包含表頭的靜態字串陣列。數組中的位置也隱式定義了列的索引。
    
-   `sortIndex` 指定要排序的標頭數組的索引
    
-   `sortOrder` 如果指定了 sortIndex，則排序順序將為升序或降序。
    

`headerPosition` `left`是一個鍵值結構，而`headerPosition` `none`允許任意行沒有狀態的資料。

### *更新表格*

```
super.updateTable(id, data = [], rowIdentifier = null);
```

使用 id 參數`id` 將一行或多行插入表中。如果指定了 rowIdentifier，則僅更新插入表的一行。

`headerPosition` `top`和`none`的資料佈局如下：

```
[
    ['x', 'y', 'z'],
    ['x', 'y', 'z']
]
```

`headerPosition` `left` 的資料佈局也允許嵌套列：

```
[
    ['x', 'x1'],
    ['y', 'y1'],
    ['z', ['z1', 'z2']]
]
```

## 造型

任何樣式都可以加入[儀表板CSS檔案](https://github.com/opnsense/core/blob/master/src/opnsense/www/css/dashboard.css)或該檔案的主題版本。

由於許多圖表都採用程式方法來處理顏色，因此特殊的

```
:root {
    --chart-js-background-color: #f7e2d6;
    --chart-js-border-color: #d94f00;
    --chart-js-font-color: #d94f00;
}
```

定義了 CSS 選擇器，以便您可以覆寫自訂主題的這些顏色。

## 可配置的小部件

要使小部件可配置，請確保在構造函數中傳入 `config` 對象，並按照 [函數 - 構造函數](#functions) 部分中所述調用 `super(config)`。還在建構函式中設定`this.configurable = true`。

[CPU 圖形小工具](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/Cpu.js) 是可設定小工具的範例。

必須重寫兩個函數才能使小部件可配置：

### *取得小工具選項*

```
async getWidgetOptions();
```

函數必須傳回具有以下結構的物件：

```
{
    option_name: {
        title: <translated string>,
        type: 'select_multiple',
        options: [
            {
                value: 'value',
                label: <translated string>
            },
            {
                value: 'value',
                label: <translated string>
            }
        ],
        default: ['value', 'value']
    }
}
```

此函數是異步的，因為它可能需要呼叫 API 來取得可用選項。

### *onWidgetOptionsChanged*

```
async onWidgetOptionsChanged(options);
```

當使用者更改小部件的選項時呼叫的回調函數。 options 參數是與`getWidgetOptions()`傳回的物件具有相同結構的對象，但會對應到選定的值。

### *取得Widget配置*

```
async getWidgetConfig();
```

取得目前持久的小工具配置。此函數隱式呼叫 `getWidgetOptions()` 函數來考慮選項預設值。

## ACL 和翻譯

每個小工具都必須向框架公開它正在使用的端點，以便控制器可以確定目前登入使用者是否可以存取該小工具。為此，您必須在 `src/opnsense/www/js/widgets/Metadata/<Core|Plugin-specific>.xml` 檔案中建立一個部分。 [核心XML檔](https://github.com/opnsense/core/blob/master/src/opnsense/www/js/widgets/Metadata/Core.xml)顯示了小部件元資料的結構。

如果任何定義的端點不可訪問，則使用者將無法使用該小工具。請注意，與任何其他 [ACL](<366 Hello world 模組和插件.md#plugin-to-access-control-acl>) 相同的規則適用於此。

翻譯在同一個XML檔案中提供，您可以透過使用小部件類別中的`this.translations.<key>`變數來存取這些值，鍵的值由開始/結束XML標籤定義。
