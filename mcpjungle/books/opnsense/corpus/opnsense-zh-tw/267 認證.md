# 認證


存取控制列表



## 概念

OPNsense 中的身份驗證由三個基本概念組成，這些概念在整個系統中都可用：

-   驗證器
    
    -   這些實作了使用的方法，例如 Radius、Ldap、本地身份驗證等
        
-   連接
    
    -   連線使用身份驗證器並定義所需的屬性，例如使用特定設定在我們的網域中可用的 Radius 伺服器。
        
-   服務
    
    -   某些服務需要或支援身份驗證，例如 Web 介面、OpenVPN 等。這些服務可能允許一個或多個連接器。
        

## 身份驗證器和連接

OPNsense 中的服務可以使用不同的驗證方法，可以在 System ‣ Access ‣ Servers 中設定連線（例如，方法可以是 **radius**，透過某個位置的伺服器提供）。所有這些方法都使用`OPNSenseAuthIAuthConnector`中定義的相同API，它附帶了一些簡單易用的句柄。

如果`OPNSenseAuth`中的類別實作了`IAuthConnector`，則它被認為是名為`AuthenticationFactory`的驗證器工廠的可行身份驗證選項。

工廠圍繞著不同的身份驗證概念提供了一個抽象層，例如，可以使用簡單的 `(new AuthenticationFactory())->get('name');` 來請求 System ‣ Access ‣ Servers 中定義的伺服器，這將身份驗證器連接到已配置的伺服器，並且響應對像已準備好處理身份驗證請求。

## 服務

我們努力使用`PAM`來定義我們的服務，在這種情況下，我們採用現有標準。 OPNsense 附帶一個 PAM 模組，它將我們的服務定義與使用 PAM 定義的服務連接起來。

名為 **opnsense-login** 的服務的簡單範例在名為 `/usr/local/etc/pam.d/opnsense-login` 的檔案中定義如下

```
auth                sufficient      pam_opnsense.so
account             sufficient      pam_opnsense.so
```

若要測試身份驗證，您可以對任何已設定的服務使用 opnsense-login。以下範例嘗試對服務 *opnsense-login* 的使用者 *root* 進行驗證（未指定選項時的預設值）。

```
/usr/local/sbin/opnsense-login
```

有關可用命令列選項的列表，請參閱`man opnsense-login`。

注意事項

**opnsense-login** 繼承自用於控制台和 Web GUI 登入的標準系統驗證，除非另有說明。

在內部，PAM 呼叫`/usr/local/libexec/opnsense-pam`，它充當`/usr/local/libexec/opnsense-auth` 所服務的身份驗證序列的墊腳石。由於 `opnsense-auth` 是用 php 編寫的，並且需要提升權限來執行此任務，因此墊腳石確保在使用 *setuid* 位元執行之前已授予這些權限。

[圖](https://docs.opnsense.org/_images/blockdiag-81e9000faecd1ba6324fa1e29324b01913fa3c11.png)

驗證腳本`opnsense_auth`利用我們的工廠類別使用服務中定義的連線執行實際驗證。

為此，我們在 `OPNSenseAuthServices` 中公開一個 *services* 命名空間，可以從 OPNsense 配置中讀取所需的選項。

對於PAM中定義的每個服務，工廠方法`getService()`需要一個實作`OPNsenseAuthIService`的類別。如果需要的話，使用`aliases()`靜態方法服務類別可以一次支援多個PAM服務（例如，系統也可以用於ssh）。

注意事項

並非每個服務都已使用PAM，在這種情況下，它被定義為處理身份驗證的腳本。

介面`IService`非常容易閱讀，而且應該是不言自明的。

## 單一登入流程

當實作基於身份驗證器的單一登入時，事件順序與通常的「提供使用者和密碼，驗證存取」不同。由於防火牆不知道憑證，因此驗證應由處理單一登入的元件來處理，這通常是基於 Web 的驗證序列。

因此，我們使用名為 `listSSOproviders()` 的方法擴充了`AuthenticationFactory`，該方法傳回`/usr/local/opnsense/mvc/app/library/OPNsense/Auth/SSOProviders` 中可用的SSO 驗證器以取得所要求的服務。

每個提供者都應該實作`OPNsenseAuthSSOProvidersISSOContainer`，它傳回提供者所屬的服務。一個提供者可以產生多個服務端點。類別 `Provider` 應該用於產生 `listProviders()` 中的提供者。這只是指向服務的包裝器。

服務需要實現自己的邏輯來處理登入序列，並在適用時在成功登入時建立會話。
