# 診斷

## 別名

詳細了解載入的別名及其內容。當別名啟用**統計**時，它也會顯示這些。

也可以使用**快速新增地址**或刪除按鈕手動調整內容。

注意事項

刪除項目時，請記住，常規更新過程可能會將位址（或網路）放回原處，因為刪除不是持久的。

提示

使用「查找引用」來檢查位址是否與任何配置的別名匹配，這對於偵錯目的非常實用，因為它也會檢查位址是否適合網路（例如10.0.0.2適合10.0.0.0/24）。

## 會議

利用 [pftop](https://www.freebsd.org/cgi/man.cgi?query=pftop) 提供活動會話及其流量計數器的詳細視圖。

網格中提供以下欄位：

---

|   |   |
| --- | --- |
|目錄 |方向（入`->`或出`<-`）|
|原型 |有問題的協定|
|來源 |來源位址與連接埠|
|網關|此會話的位址和連接埠也正在使用 NAT 進行轉換 |
|目的地 |目的位址和連接埠|
|狀態|來源處的狀態：目的地，請參閱「狀態」區段中的表格 |
|年齡（秒）|自狀態創建以來的秒數 |
|過期（秒）|狀態到期前剩餘的秒數。 |
|包裹 |狀態處理的資料包數量 |
|位元組|狀態處理的位元組數|
|規則|規則此狀態（最有可能）屬於 |

## 州

深入了解狀態表 (pf)，提供搜尋特定狀態和刪除的能力。也可以從這裡重置所有狀態和/或來源追蹤表，尤其是狀態表重置應小心使用，因為它會刪除所有活動連線。

如果您使用網格搜尋輸入來尋找狀態，或使用防火牆規則頁面上的 **檢查** 按鈕並開啟狀態視圖，您將看到一個按鈕，讓您終止與條件相符的所有狀態。

注意事項

狀態表嘗試將狀態連接到規則，但由於這些是透過 `pf(4)` 中的規則編號（序列）引用的，因此在規則變更後，這些規則並不總是準確的。

網格中提供以下欄位：

---

|   |   |
| --- | --- |
|州 ID |描述狀態和起源（創建者）的唯一內部識別碼 |
|國際 |綁定到哪個接口，預設情況下都是這樣，除非在防火牆->設定->高級中設定了「將狀態綁定到接口」|
|目錄 |方向（入`->`或出`<-`）|
|原型 |有問題的協定|
|來源 |來源位址與連接埠|
|納特 |此會話的位址和連接埠也正在使用 NAT 進行轉換 |
|目的地 |目的位址和連接埠|
|狀態|來源處的狀態：目的地，請參閱下表以取得狀態清單及其可用說明 |
|規則|規則此狀態（最有可能）屬於 |
|指令 |用於刪除特定狀態（狀態 ID）的按鈕 |

### 可用 TCP 狀態清單（由 [RFC 793](https://www.rfc-editor.org/rfc/rfc793) 定義）

<table>
<tr><td>LISTEN</td><td>表示等待來自任意遠端TCP和連接埠的連線請求。 </td></tr>
<tr><td>SYN_SENT</td><td>表示發送連線請求後等待符合的連線請求。 </td></tr>
<tr><td>SYN_RCVD</td><td>表示在接收和發送連線請求後等待確認連線請求確認。 </td></tr>
<tr><td>ESTABLISHED</td><td>代表開啟連接，接收到的資料可以傳遞給使用者。連接資料傳輸階段的正常狀態。 </td></tr>
<tr><td>FIN_WAIT_1</td><td>表示等待來自遠端的連線終止請求TCP，或對先前發送的連線終止請求的確認。 </td></tr>
<tr><td>FIN_WAIT_2</td><td>表示等待來自遠端的連線終止請求TCP.</td></tr>
<tr><td>CLOSE_WAIT</td><td>表示等待本地用戶的連線終止請求。 </td></tr>
<tr><td>CLOSING</td><td>表示等待來自遠端的連線終止請求確認TCP.</td></tr>
<tr><td>LAST_ACK</td><td>表示等待先前發送到遠端的連線終止請求的確認TCP（其中包括對其連線終止請求的確認）。 </td></tr>
<tr><td>TIME_WAIT</td><td>表示等待足夠的時間以確保遠端TCP收到其連線終止請求的確認。 </td></tr>
<tr><td colspan="2">CLOSED 代表完全沒有連線狀態</td></tr>
</table>

### 可用的UDP/其他狀態列表 (man [pf.conf(5)](https://www.freebsd.org/cgi/man.cgi?pf.conf\(5\)))

|   |   |
| --- | --- |
| NO\_交通 |此方向無交通 |
| SINGLE |來源主機傳送多個封包但目標主機從未傳回封包時的狀態。 |
| MULTIPLE |兩台主機皆已傳送封包的狀態。 |

## 統計數據

從 [pfctl](https://www.freebsd.org/cgi/man.cgi?query=pfctl) 收集的各種詳細統計數據，例如每個介面的資料包計數器、記憶體限制、配置的逾時和詳細的活動規則。
