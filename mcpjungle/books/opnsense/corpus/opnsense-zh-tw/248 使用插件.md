# 使用插件

## 一般

插件位於以下位置：

```
/usr/local/etc/inc/plugins.inc.d/
```

並包含副檔名為“.inc”的檔案。

所有自動註冊的函數都以檔案名稱（不含副檔名）開頭，然後是用途。例如，*vpn\_configure* 將是插件檔案名稱 vpn.inc 中的 *configure* 句柄。

透過使用這些插件，您可以連接到系統的不同區域，例如註冊新的介面類型並確保服務顯示在常規服務概述中。

注意事項

當插件失敗並導致PHP錯誤時，這些錯誤將被收集在`/tmp/PHP_errors.log`中，這些插件在發出此類錯誤時不會註冊和執行

## 服務

要註冊服務，`<plugin>_services()`函數應傳回一個包含其名稱、描述和操作屬性的結構。

```php
function myplugin_services()
{
    $service = array();
    $service['name'] = 'myservice';
    $service['description'] = gettext('My service');
    $service['configd']['restart'] = array('myservice restart');
    $service['configd']['start'] = array('myservice start');
    $service['configd']['stop'] = array('myservice stop');
    $services[] = $pconfig;
    return $services;
}
```

| **選項**|**描述** |
| --- | --- |
|名稱 |服務識別碼 |
|編號 |服務後綴的可選標識符，僅在特定情況下使用，其中一個「服務」實際上可以是它們的列表（例如`openvpn`）|
|描述 |使用者友善的描述 |
| pid 檔案 |根據指定的 pid 檔案（而不是「名稱」）驗證運行 |
|沒有檢查| \[boolean\] 忽略 pid 或進程名稱並且始終報告正在運行 |
| {類型} |類型可以是 `configd`, `php`, `mwexec` | 之一
| {類型}.start |啟動服務時呼叫的操作 |
| {類型}.stop |停止服務時呼叫的操作 |
| {類型}.重新啟動 |重新啟動服務時呼叫的操作 |

若要從命令列列出所有可用服務，您可以使用pluginctl（與我們的核心系統捆綁在一起）。

```
pluginctl -s
```

相同的工具也可用於執行\[重新\]啟動/停止操作，對於上面的範例，重新啟動將如下所示：

```
pluginctl -s myservice restart
```

## 配置

配置插件可用於捕捉某些事件，例如`bootup`, `newwanip`等。

下面顯示了一個註冊的小範例，它註冊了函數 `myplugin_configure()` 啟動時和 `myplugin_configure_vpn()` 在 VPN 狀態變更時，後者最多接受兩個 (:2) 個參數。請注意，傳遞給偵聽器的預設參數數量為 1 (:1)，即 `$verbose` 參數控制是否允許該函數列印進度。傳遞的參數的最大數量取決於特定的事件提供者。如欲了解更多詳情，請參閱下文。

```js
function myplugin_configure()
{
    return [
        'bootup' => ['myplugin_configure'],
        'vpn' => ['myplugin_configure_vpn:2'],
    ];
}
```

要列出所有可用的鉤子，您可以使用不含參數的`pluginctl`：

```
pluginctl -c
```

您將在下面找到當前處理的最常用事件的不完整清單：

| **活動**|**何時** |
| --- | --- |
|早|在啟動過程的早期，在正常服務啟動之前（例如 ssh 和 webconfigurator 使用此點）|
|啟動 |啟動，正常的舊版服務配置，不使用`rc(8)`系統時（例如：unbound、ntpd）|
|紐瓦尼普 |配置動態介面位址後觸發，最多需要三個位置參數（`$verbose`、`$interfaces` 和`$family`）。 `$interfaces` 是一個數組，所有需要重新載入的相關介面或全部為空。 $:code:family 是觸發事件的位址族類型，對於 IPv4 為`inet`，對於 IPv6 為`inet6`。 |
| VPN |在需要重新載入基於VPN的子系統的多個位置觸發，最多需要兩個參數（`$verbose`和`$interfaces`）。 `$interfaces` 是所有需要重新載入的相關介面的數組，或全部為 null。 |

`pluginctl`還可以用來觸發特定事件，例如：

```
pluginctl -c monitor
```

## 防火牆

若要註冊防火牆規則，請建立一個名為 `<plugin>_firewall()` 的函數，這將傳遞一個可用於產生新防火牆規則的插件物件。

以下是此類規則的一個非常簡單的範例：

```php
function myplugin_firewall(\OPNsense\Firewall\Plugin $fw) {
    $fw->registerFilterRule(500000, array("direction" => "in", "protocol" => "udp", "to_port" => 9999));
}
```

`configctl` 可用於重新載入防火牆並測試您的外掛程式：

```
configctl filter reload
```

這將產生一個類似的規則（在 /tmp/rules.debug 中）：

```
pass in quick proto udp from {any} to {any} port {9999}
```

## 介面

若要註冊新（虛擬）接口，請建立名為 `<plugin>_interfaces()` 的函數，該函數應傳回命名數組，其中包含唯一介面名稱作為鍵（例如 ipsec 的 enc0）。

每個項目應包含以下屬性：

| **財產**|**文法**|**描述** |
| --- | --- | --- |
|啟用 |布林 |介面已啟用，如果啟用，它將保存在配置中 |
|描述 |文字|使用者可讀的描述 |
|網絡|數組，\[網絡，掩碼\] |包含遠端網絡的命名數組列表
|類型 |文字| “無” |
|如果|文字|實體介面（例如 enc0）|
|虛擬|布爾 |虛擬接口，真/假|

範例：

```php
function myplugin_interfaces()
{
    global $config;

    $interfaces = array();
    if (isset($config['myplugin']['enable'])) {
        $oic = array("enable" => true);
        $oic['if'] = 'tun0';
        $oic['descr'] = 'myplugin';
        $oic['type'] = "none";
        $oic['virtual'] = true;
        $oic['networks'] = array();
        $interfaces['tun0'] = $oic;
    }

    return $interfaces;
}
```

## 裝置

若要註冊可以逐字使用或手動指派給介面的虛擬網路設備類型，`<plugin>_devices()`函數應傳回包含此類設備和附加定義的結構。

設備註冊涵蓋多個方面，例如介面分配頁面呈現、外部（重新）配置功能、分配設備的自動配置以及匹配設備名稱模式等。可用設定如下所述：

| **財產**|**文法**|**描述** |
| --- | --- | --- |
|功能|文字|以裝置名稱為參數呼叫該名稱的函數 |
|揮發性 |布林 |此介面可能會消失，因此請勿嘗試啟動恢復 |
|可設定|布林 |若為真或缺失，指派的介面可以設定 IPv4/IPv6 模式 |
|圖案|文字|正規表示式批次辨識設備名稱 |
|類型 |文字|作業頁面需要獨特的類型設定 |
|名稱 |陣列 \[ 見下 \] |以單獨名稱作為關聯鍵的設備清單 |
| …描述|文字|設備的描述性文本，例如作業頁面 |
| …ifdescr |文字|逐字描述，例如儲存在 config.xml 中 |
| …姓名|文字|裝置名稱與陣列鍵相同，方便存取 |

範例：

```php
function myplugin_devices()
{
    $devices = [];

    $devices[] = [
        'function' => 'function_name_to_configure',
        'names' => ['dev0' => [
            'descr' => 'descriptive text',
            'ifdescr' => 'verbatim description',
            'name' => 'dev0',
        ]],
        'pattern' => '^dev',
        'volatile' => true,
        'type' => 'bridge',
    ];

    return $devices;
}
```

## 系統日誌

若要註冊系統日誌目標，`<plugin>_syslog()`函數應傳回包含目標和定義的結構。

```php
function myplugin_syslog()
{
    $logfacilities = array();
    $logfacilities['myplugin'] = array(
        'facility' => array('myplugin'),
    );
    return $logfacilities;
}
```

注意事項

從 OPNsense 19.7 Syslog-NG 開始，這些檔案將僅用於在系統 -> 設定 -> 日誌記錄/目標中識別自訂系統日誌遠端目標的應用程式。

要測試服務註冊是否正常運行，只需重新啟動系統日誌工具即可：

```
pluginctl -s syslogd restart
```

注意事項

為了定義 Syslog-NG 的本地目標，您只需新增 **本機** 過濾器（例如，透過建立 `src/opnsense/service/templates/OPNsense/Syslog/local/helloworld.conf`），這些過濾器將被收集到一個大型系統日誌配置中。 [GitHub](https://github.com/opnsense/core/blob/master/src/opnsense/service/templates/OPNsense/Syslog/local/README) 上的自述文件描述了這個過程。當遇到問題時，請務必先手動重新啟動 syslog-ng (`service syslog-ng restart`)，定義錯誤不會寫入任何日誌。您還必須重新啟動插件（`pluginctl -s syslog-ng restart`）才能重新產生 syslog-ng 設定檔。

注意事項

如果 Syslog-NG 應使用其他來源套接字，您可以在 `/usr/local/opnsense/service/templates/OPNsense/Syslog/sources/` 中新增包含定義的檔案。 [001-local.conf](https://github.com/opnsense/core/blob/22.1.7/src/opnsense/service/templates/OPNsense/Syslog/sources/001-local.conf#L5) 檔案包含來自被監禁的核心服務的範例。

## XMLRPC (HA) 同步

當設定部分應公開給高可用性同步時，您可以使用 xmlrpc 外掛程式掛鉤。

如果外掛程式將配置部分公開給 hasync，則可以在同步設定「系統」->「高可用性」->「設定」中單獨啟用它。

在 OPNsense xml 路徑中公開配置部分 Myplugin 的簡單範例如下所示：

```php
function myplugin_xmlrpc_sync()
{
    $result = array();
    $result[] = array(
        'description' => gettext('My Plugin'),
        'section' => 'OPNsense.Myplugin',
        'id' => 'myplugin',
        'services' => 'myplugin', // optional, in case a service with the same name exists
    );
    return $result;
}
```

注意事項

如果您的外掛程式依賴系統中的其他元件，請確保也為這些元件啟用同步。
