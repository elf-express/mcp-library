# 遠端調試內核


FreeBSD 支援使用串列埠進行遠端偵錯。由於大多數虛擬機器解決方案都支援串列埠，因此在另一台機器上部署核心並啟動偵錯工作階段會非常方便。

此設定假設有兩台（虛擬）機器，它們之間透過串行（rs232）連接。

[圖](https://docs.opnsense.org/_images/blockdiag-51ee775ab4d0b0956e2879627609bee55b87586f.png)

## 配置並建構內核

使用我們[此處](https://github.com/opnsense/tools)詳細描述的工具鏈，並將以下選項新增至`/usr/tools/config/[VERSION]/SMP`中的`SMP`檔案。

```
#nomakeoptions DEBUG
options        GDB                     # Support remote GDB.
makeoptions    DEBUG=-g
```

接下來清理並建立內核

```
make clean-obj,kernel kernel
```

## 在測試虛擬機器上安裝內核

建置完成後，建置機器上的核心軟體包應該位於以下位置：

> `/usr/local/opnsense/build/[Version]/[Architecture]/sets/kernel*.txz`

將此軟體包複製到測試虛擬機，並使用我們的`opnsense-update`命令進行安裝：

```
opnsense-update -ikfr [version] -l /location/from/
```

其中 \[version\] 是內核包的版本訊息，例如`19.1.2`

## 配置測試虛擬機

要使用`kgdb`連接到測試機器，您需要確保已設定一些設定。

編輯`/boot/device.hints` ，並更改或新增`hint.uart.0.flags`至以下內容：

```
hint.uart.0.flags="0xc0"
```

此外，/boot/loader.conf.local 檔案中應該配置串列裝置的波特率：

```
comconsole_speed="115200"
```

## 測試您的設置

登入測試機器，並使用以下命令強制在 gdb 中啟動偵錯會話：

```
# sysctl debug.kdb.current=gdb
# sysctl debug.kdb.enter=1
db> gdb
Step to enter the remote GDB backend.
db> c (continue)
```
