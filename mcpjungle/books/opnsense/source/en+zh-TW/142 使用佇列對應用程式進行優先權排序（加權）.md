# Prioritize Applications (Weighted) using Queues｜使用佇列對應用程式進行優先權排序（加權）

> 章節：[Firewall](<000 目錄.md#c-26>) › [Traffic Shaping](<000 目錄.md#c-29>) › [Configuration / How-tos](<000 目錄.md#c-30>)

By utilizing queues we can influence the bandwidth within a pipe and give certain applications more bandwidth than others based on a weighted algorithm.

透過利用佇列，我們可以影響管道內的頻寬，並根據加權演算法為某些應用程式提供比其他應用程式更多的頻寬。

The idea is simple: Let presume we have a pipe of 10 Mbps and 2 applications for instance smtp (email) and http(s). The http(s) traffic will get a weight of 1 and the smtp traffic a weight of 9, then when all capacity of our pipe is in use the email traffic will get 9x more bandwidth than our http(s) traffic, resulting in 1 Mbps for http(s) and 9 Mbps for smtp.

這個想法很簡單：假設我們有一個 10 Mbps 的管道和 2 個應用程序，例如 smtp（電子郵件）和 http(s)。 http(s) 流量的權重為 1，smtp 流量的權重為 9，然後當管道的所有容量都使用時，電子郵件流量將獲得比 http(s) 流量多 9 倍的頻寬，從而導致 http(s) 流量為 1 Mbps，smtp 流量為 9 Mbps。

For our example we only look at download traffic, but the exact same can be done for the upload traffic.

對於我們的範例，我們僅查看下載流量，但可以對上傳流量執行完全相同的操作。

To start go to Firewall ‣ Shaper ‣ Pipes.

首先前往 Firewall ‣ Shaper ‣ Pipes。

## Step 1 - Create Download Pipe｜步驟 1 - 建立下載管道

On the **Pipes** tab click the **+** button in the lower right corner. An empty **Edit Pipe** screen will popup.

在 **管道**標籤上，按一下右下角的**+**按鈕。將彈出一個空的**編輯管道**螢幕。

Create Pipe For Download (10 Mbps)

建立下載管道 (10 Mbps)

|   |   |   |
| --- | --- | --- |
| **enabled**<br>**啟用** | Checked<br>已檢查 | *Check to enable the pipe*<br>*檢查以啟用管道* |
| **bandwidth**<br>**頻寬** | 10 | *Numeric value of the desired bandwidth*<br>10 *所需頻寬的數值* |
| **bandwidth Metric**<br>**頻寬指標** | Mbit/s<br>兆位元/秒 | *Metric to use with the numeric value*<br>*與數值一起使用的量測* |
| **mask**<br>**面具** | (empty)<br>（空） | *Leave empty*<br>*留空* |
| **description**<br>**描述** | PipeDown-10Mbps | *Free field, enter something descriptive*<br>*自由字段，輸入描述性內容* |

Adding an extra rule for HTTPS traffic is simple as we can use the same HTTP queue if we like:

為 HTTPS 流量新增額外規則很簡單，因為如果我們願意，我們可以使用相同的 HTTP 佇列：

|   |   |   |
| --- | --- | --- |
| **sequence**<br>**序列** | 31 | *Auto generated number, overwrite only when needed*<br>*自動產生編號，僅在需要時覆寫* |
| **interface**<br>**介面** | WAN | *Select the interface connected to the internet*<br>*選擇連接到網際網路的介面* |
| **proto**<br>**原型** | ip | *Select the protocol, IP in our example*<br>*選擇協議，在我們的範例中為IP* |
| **source**<br>**來源** | any<br>任何 | *The source address, leave on any*<br>*來源位址，任意留* |
| **src-port**<br>**來源端口** | https | *The source port to shape, https or 443*<br>*要塑造的來源端口，https 或 443* |
| **destination**<br>**目的地** | any<br>任何 | *The destination IP to shape, leave on any*<br>*目的地IP塑造，留下任意* |
| **dst-port**<br>**目標端口** | any<br>任何 | *The destination port to shape, leave on any*<br>*目的港自行塑造，任意留任* |
| **target**<br>**目標** | Queue-HTTP<br>隊列-HTTP | *Select the HTTP queue*<br>*選擇HTTP隊列* |
| **description**<br>**描述** | ShapeHTTPSDownload<br>ShapeHTTPS下載 | *Enter a descriptive name*<br>*輸入描述性名稱* |

This way HTTP and HTTPS traffic will be treated the same (total max of 1 Mbps).

這樣，HTTP 和 HTTPS 流量將被同等對待（總計最大 1 Mbps）。
