# Devices｜裝置

> 章節：[Interfaces](<000 目錄.md#c-19>)

Besides wired, wireless and VPN interfaces, there are also some other, virtual interfaces, as well as some miscellaneous interface-related. These options can be found under Interfaces ‣ Devices. This document briefly explains these options.

除了有線、無線和VPN介面之外，還有一些其他的虛擬介面以及一些其他的介面相關選項。這些選項位於「介面」‣「設備」下。本文檔將簡要介紹這些選項。

## Bridge｜橋

Bridging allows to create a connection between separate networks, allow traffic on network A destined for network B (where both networks are connected to your OPNsense device) to reach it via this bridge. Note that this does not include DHCP services—this needs to set using [DHCP relaying](<192 DHCP.md#dhcrelay>).

橋接允許在不同的網路連接之間建立連接，允許網路 A 上發送到網路 B（兩個網路都連接到您的 OPNsense 設備）的流量通過此橋接到達網路 B。請注意，這不包括DHCP服務－這需要使用 [DHCP中繼](<192 DHCP.md#dhcrelay>)進行設定。

A bridge works like a (layer-2) switch, forwarding traffic from one interface to another. Multicast and broadcast packets are always forwarded to all interfaces that are part of the bridge. For unicast traffic, the bridge learns which MAC addresses are associated with which interfaces and will forward the traffic selectively.

網橋的工作原理類似（二層）交換機，將流量從一個介面轉送到另一個介面。群播和廣播資料包總是會轉送到網橋中的所有介面。對於單播流量，網橋會學習哪些MAC位址與哪些介面關聯，並選擇性地轉送流量。

Optionally a bridge can be configured to support [(Rapid) Spanning Tree Protocol](https://en.wikipedia.org/wiki/Spanning_Tree_Protocol) (RSTP/RTP) to prevent loops in the network topology. These options are provided in the “advanced” section of the configuration and include the following settings:

網橋可以設定為支援快速生成樹協定 (RPTP) (https://en.wikipedia.org/wiki/Spanning_Tree_Protocol) ( RSTP/RTP )，以防止網路拓撲中出現環路。這些選項位於配置的「進階」部分，包括以下設定：

| Protocol<br>協議 | Protocol to use, rapid or regular spanning tree<br>要使用的協議，快速生成樹或常規生成樹 |

| Valid time (maxage)<br>有效時間（最大期限） | Set the time that a Spanning Tree Protocol configuration is valid. The default is 20 seconds.<br>設定生成樹協定配置的有效時間。預設值為 20 秒。 |
| Forward time (fwddelay)<br>轉送延遲 (fwddelay) | Set the time that must pass before an interface begins forwarding packets when Spanning Tree is enabled. The default is 15 seconds.<br>設定啟用生成樹協定後，介面開始轉送封包之前必須經過的延遲時間。預設值為 15 秒。 |

GIF （ `gif(4)` ，通用隧道介面）可用於透過 IPv4 連接建立 IPv6 隧道。一個常見的應用是 Hurricane Electric (he.net) 的 IPv6 隧道。

## GRE

GRE (`gre(4)`, Generic Routing Encapsulation) is used to create a virtual point-to-point connection, through which encapsulated packages can be sent. This can be used to utilize (OSI-layer 3) protocols between devices over a connection that does not normally support these protocols.

GRE （ `gre(4)` ，通用路由封裝）用於建立虛擬的點對點連接，封裝的資料包可以透過此連接傳送。這可用於在通常不支援這些協定的連線上使用（ OSI第 3 層）協定。

Since the GRE protocol was designed by Cisco, it is often used as default tunnel technology when using their solutions.

由於GRE協定是由思科設計的，因此在使用思科解決方案時，它通常被用作預設隧道技術。

A common use-case of GRE is also to forward (no routable) multicast traffic, although this will need additional software such as IGMP-proxy or PIMD, which are less commonly used on OPNsense.

GRE的一個常見用例也是轉送（不可路由的）群播流量，儘管這需要額外的軟體，例如IGMP -proxy 或PIMD ，這些軟體在 OPNsense 上不太常用。

## LAGG

LAGG (`lagg(4)`) allows for link aggregation, bonding and fault tolerance. This works best if your network switches support. Only unassigned interfaces can be added to LAGG.

LAGG ( `lagg(4)` ) 允許鏈路聚合、綁定和容錯。如果您的網路交換器支援此功能，則效果最佳。只有未分配的介面才能加到LAGG 。

The userinterface supports the following options:

使用者介面支援以下選項：

| Option<br>選項 | Description<br>說明 |
| --- | --- |
| Parent interface<br>父介面 | Members of the link aggregation<br>連結聚合成員 |
| Lag proto<br>滯後原型 | Protocol to use for aggregation, available options are described in the next table. LACP is most commonly used.<br>用於聚合的協定、可用選項如下表所述。 LACP最常用。 |
| Description<br>描述 | User friendly description for this interface<br>此介面的使用者友善描述 |
| Fast timeout<br>快速逾時 | Enable lacp fast-timeout on the interface.<br>在介面上啟用 LACP 快速逾時。 |
| Use flowid<br>使用 flowid | Use the RSS hash from the network card if available, otherwise a hash is locally calculated. The default depends on the system tunable in net.link.lagg.default\_use\_flowid.<br>如果可用，則使用網卡的RSS哈希值；否則，將在本地計算哈希值。預設值取決於系統在 net.link.lagg.default\_use\_flowid 中的設定。 |
| Hash Layers<br>哈希層 | Set the packet layers to hash for aggregation protocols which load balance.<br>將封包層設定為哈希模式，以用於負載平衡的聚合協定。 |
| Use strict<br>使用嚴格模式 | Enable lacp strict compliance on the interface. The default depends on the system tunable in net.link.lagg.lacp.default\_strict\_mode.<br>在介面上啟用 LACP 嚴格模式。預設值取決於系統，可在 net.link.lagg.lacp.default\_strict\_mode 中進行調整。 |
| MTU | MTU size, when unset the smallest mtu of the LAGG children will be used.<br>MTU大小，取消設定時將使用LAGG子節點中最小的 MTU。 |

Note

注意事項

Hash Layers, specifies how the device will loadbalance the traffic across physical links in the LAGG bundle. This is done per the 5-tuple if the LACP device implementation allows it. Hash Layers, do not need to be the same between two connecting devices, it can be considered as a best practice but its not a rule of must be.

哈希層指定設備如何在LAGG鏈路聚合組中的物理鏈路之間進行流量負載平衡。若LACP設備實作允許，則依照五元組進行負載平衡。兩個連接設備之間的哈希層不必相同，雖然這可以被視為最佳實踐，但並非強制要求。

**LACP timeout**

**LACP超時**

LACP timeout has two modes; Slow/normal and Fast. It handles how fast the re-convergence occurs in case of link failure. This specifies how often the heartbeats are sent between the two LAGG connected devices.

LACP超時有兩種模式：慢速/正常模式和快速模式。它控制鏈路故障時重新收斂的速度。這指定了兩個LAGG連接設備之間發送心跳的頻率。

| LACP mode<br>LACP模式 | Heartbeat/Timeout interval<br>心跳/超時間隔 | Enable<br>啟用 |
| --- | --- | --- |
| Slow/Normal<br>慢速/正常 | 30s<br>30秒 | Fast timeout turned off<br>快速逾時已關閉 |
| Fast<br>快速 | 1s<br>1秒 | Fast timeout turned on<br>快速逾時已開啟 |

The Slow/normal timeout should be the default in most cases. Due to possible vendor implementation issues, keeping the LACP timeout on Slow/normal is preferable. Fast timeout can cause connectivity disruption in some cases. LACP timeout requires the same value on both devices connected via LAGG. If not, heartbeats can be missed which will cause connectivity disruption.

在大多數情況下，慢速/正常超時應該是預設值。由於可能有供應商實施問題，最好將 LACP 逾時保持為慢速/正常。在某些情況下，快速逾時可能會導致連線中斷。 LACP 超時要求透過LAGG 連接的兩個設備具有相同的值。否則，可能會失去心跳，導致連線中斷。

請閱讀 [LAGG設定](<115 VLAN和LAGG設置.md>)以取得設定範例。

## Loopback｜環回

Loopbacks are logical virtual interfaces which emulate real interfaces and can be used for different setup scenarios, which require always-on interfaces. Below you will find some scenario’s for which these devices are used.

環回接口是模擬真實接口的邏輯虛擬接口，可用於需要始終保持連接的各種部署場景。以下列舉了一些此類設備的應用場景。

-   Administrative access to services on your machine, which can bind to an address configured on top of the loopback.  
    對您的機器上的服務擁有管理權限，這些服務可以綁定到在環回位址之上配置的位址。
    
-   Using loopback addresses as router IDs for OSPF or BGP, which helps to identify your nodes and eases administration  
    使用環回位址作為OSPF或BGP路由器ID，有助於識別您的節點並簡化管理。
    

## VLAN

VLANs (Virtual LANs) can be used to segment a single physical network into multiple virtual networks. This can be done for QoS purposes, among other things. For this reason, most ISP-issued IPTV devices utilize VLANs.

VLAN（虛擬區域網路）可用於將單一實體網路劃分為多個虛擬網路。這樣做可以用於服務品質 (QoS) 等目的。因此，大多數通過ISP認證IPTV設備都使用 VLAN。

The following settings are available for these devices:

| Parent interface<br>父接口 | The interface to use as parent which it will send/receive vlan tagged traffic on<br>用作父接口的接口，VLAN 標記流量將透過該接口發送/接收 |
| VLAN tag<br>VLAN標籤 | 802.1Q VLAN tag (between 1 and 4094)<br>802.1Q VLAN標籤（介於 1 和 4094 之間） |
| VLAN priority<br>VLAN優先權 | 802.1Q VLAN PCP (priority code point)<br>802.1Q VLAN PCP （優先權代碼點） |
| Description<br>描述 | User friendly description for this interface<br>此介面的使用者友善描述 |

[802.1ad](https://en.wikipedia.org/wiki/IEEE_802.1ad) ，也稱為 QinQ，可透過VLAN配置獲得支援，在這種情況下，您可以將`vlan`堆疊在`vlan`之上，在這種情況下，裝置名稱應以 qinq 開頭。

Read [VLAN Setup](<115 VLAN和LAGG設置.md>) for an example configuration.

請閱讀 [VLAN設定](<115 VLAN和LAGG設置.md>)以取得設定範例。

## VXLAN

Virtual eXtensible Local Area Networks (VXLAN) are used to overlay virtualized layer 2 networks over layer 3 networks as described by [rfc7348](https://tools.ietf.org/html/rfc7348).

虛擬可擴充區域網路 ( VXLAN ) 用於將虛擬化的 2 層網路覆寫到 3 層網路上，如 [rfc7348](https://tools.ietf.org/html/rfc7348)所述。

Tunnels can be setup in point to point (parameter `Remote address`) or multicast (parameters `Multicast group` and `Device`). The Source address must be an existing (statically assigned) address assigned at this firewall, which will be used as source in the encapsulating IPv4/IPv6 header.

隧道可以設定為點對點模式（參數`Remote address` ）或組播模式（參數`Multicast group`和`Device` ）。來源位址必須是此防火牆上已存在的（靜態分配的）位址，該位址將用作封裝 IPv4/IPv6 標頭中的來源位址。

Note

注意事項

Since the vxlan interface encapsulates the Ethernet frame with an IP, UDP, and vxlan header, the resulting frame may be larger than the MTU of the physical network. The vxlan specification recommends the physical network MTU be configured to use jumbo frames to accommodate the encapsulated frame size. Alternatively, the MTU size on the vxlan interface might be reduced to allow the encapsulated frame to fit in the current MTU of the physical network.

由於 VXLAN 介面使用IP, UDP和 VXLAN 頭部封裝乙太網路幀，因此產生的幀可能大於實體網路的MTU規格建議將實體網路的MTU配置為使用巨型幀來容納封裝後的幀大小。或者，也可以減少 VXLAN 介面的MTU大小，以使封裝後的訊框能夠適應目前實體網路的MTU 。

Read [VXLAN Bridge](<117 VXLAN橋.md>) for an example configuration with a common setup.

閱讀 [VXLAN Bridge](<117 VXLAN橋.md>)以取得常見設定的範例設定。

## Point-to-Point｜點對點

Point-to-Point (PP) interfaces provide direct connectivity between two endpoints without any intermediary devices. These interfaces are commonly used for WAN connections, tunneling, or direct link setups where broadcast and multiple access are not needed.

點對點 ( PP ) 介面提供兩個端點之間的直接連接，無需任何中間設備。這些介面通常用於WAN連接、隧道或直接鏈路設置，在這些情況下不需要廣播和多路存取。

**PPP （點對點協定）**

A widely used protocol for establishing direct connections over serial links, often utilized for dial-up and DSL connections. Supports authentication (PAP/CHAP), compression, and error detection.

一種廣泛用於透過串行鏈路建立直接連接的協議，常用於撥號和DSL連接。支援身份驗證（ PAP/CHAP ）、壓縮和錯誤檢測。

Tip

When using `PPPoE`, a lot of providers these days support [RFC 4638](https://datatracker.ietf.org/doc/html/rfc4638), in which case the internet provider expects the MTU value for the PPP connection itself to be 1500 bytes, which usually means the parent interface should add the 8 byte tunnel overhead. To use a 1500 byte MTU on `PPPoE` in OPNsense, set the interface (usually Interfaces ‣ \[WAN\]) to an MTU value of `1508`, in which case the tunnel itself will use the full 1500 bytes.
