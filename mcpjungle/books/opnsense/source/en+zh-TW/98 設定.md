# Settings｜設定

> 章節：[System](<000 目錄.md#c-11>)

Besides the configuration options that every component has, OPNsense also contains a lot of general settings that you can tweak. This page contains an overview of them.

除了每個組件都具備的配置選項外，OPNsense 還包含許多可調整的通用設定。本頁面概述了這些設定。

## Administration｜行政

The settings on this page concerns logging into OPNsense. The “Secure Shell”（安全外殼） settings are described under [Creating Users & Groups](<86 本地用戶和群組.md>).

此頁面上的設定涉及登入 OPNsense。 “Secure Shell”（安全外殼） 設定在[建立使用者和群組](<86 本地用戶和群組.md>) 下描述。

### Listen interfaces｜監聽介面

Warning

警告

Before considering the use of manual selected interfaces, make sure to read this chapter so you are aware of the pitfalls upfront. Misconfigurations likely lead to a non-accessible web interface and/or missing ssh access.

在考慮使用手動選擇的介面之前，請務必閱讀本章，以便提前了解可能的問題。設定錯誤很可能導致 Web 介面無法存取和/或 SSH 存取失敗。

Both the WebUI and the Secure Shell server support the option to only listen on specific interfaces, the use of this option however comes with clear warnings which you do need to be aware of before deciding to use this option.

WebUI 和 Secure Shell 伺服器都支援僅監聽特定介面的選項，但是使用此選項會有一些明顯的警告，您在決定使用此選項之前需要了解這些警告。

By default (our recommended settings), these services listen on all addresses (interfaces).

預設情況下（我們建議的設定），這些服務監聽所有位址（介面）。

If for whatever reason, you do need to listen only on specific interfaces, the following rules apply:

如果出於某種原因，您確實需要僅監聽特定接口，則適用以下規則：

-   The interface must always be available, so do not try to bind to vpn instances of any kind (OpenVPN, Wireguard, …)  
    介面必須始終可用，因此請勿嘗試綁定到任何類型的 VPN 實例（OpenVPN、Wireguard 等）。
    
-   The addressing must be fully static, so no IPv6 tracking configured for example  
    位址必須完全靜態，例如，不能配置 IPv6 追蹤。
    

As the webgui is not able to predict with 100% certainty that these rules do apply, it is possible to select interfaces that don’t support binding for these services.

由於 Web 管理介面無法 100% 確定這些規則是否適用，因此可以選擇不支援這些服務綁定的介面。

Note

注意事項

When facing issues with the webgui (and/or ssh) and the above rules are not met, please do not bother to open a ticket as these are unsupported scenario’s.

如果在使用 webgui（和/或 ssh）時遇到問題，且不符合上述規則，請不要費心提交工單，因為這些是不受支援的情況。

Tip

提示

In case (**for any service**) one would like to prevent binding on all interfaces, it is possible to add a loopback interface (Interfaces ‣ Devices ‣ Loopback), assign an ip address and bind to that.

如果（**對於任何服務**）想要阻止在所有介面上進行綁定，可以新增一個環回介面（介面 ‣ 設備 ‣ 環回），請指派一個 IP 位址並綁定到該介面。

When traffic is routed through the firewall, the “loopback ip” (some private address, not in the loopback range) should be directly accessible from the network behind it. For example use an address like `192.168.130.1/32` to access the web interface while your own network is using `192.168.1.0/24`.

當流量通過防火牆路由時，「環回 IP」（某個私人位址，不在環回位址範圍內）應該能夠從其後面的網路直接存取。例如，可以使用類似`192.168.130.1/32`的位址存取 Web 介面，而您自己的網路則使用`192.168.1.0/24` 。

Technologies like Network Address Translation (NAT) can also be combined if the other end is not aware of the route to this single address.

如果另一端不知道到達該單一位址的路由，也可以結合使用網路位址轉換（ NAT ）等技術。

### Secure Shell - Advanced Settings｜安全殼 - 進階設置

To configure options that are not available in the GUI one can add custom configuration files on the firewall itself. Files can be added in `/usr/local/etc/ssh/sshd_config.d/` using the `.conf` file extension. When more files are placed inside the directory, they will be included in alphabetical order. The custom configuration files are included first to provide proper overrides to options normally set by the system.

若要設定GUI中未提供的選項，可以在防火牆本身上新增自訂設定檔。可以使用`.conf`檔案副檔名在`/usr/local/etc/ssh/sshd_config.d/`中新增檔案。目錄中放置多個檔案時，它們將按字母順序排列。自訂設定檔會優先包含，以便對系統預設設定的選項進行適當的覆寫。

Warning

警告

It is the responsibility of the administrator to ensure that the configuration is valid. No configuration checks will be performed and any errors may prevent you being able to login to the firewall remotely!

管理員有責任確保配置有效。系統不會執行任何設定檢查，任何錯誤都可能導致您無法遠端登入防火牆！

## Cron｜克朗

[Cron](https://en.wikipedia.org/wiki/Cron) is a service that is used to execute jobs periodically. Cron jobs can be viewed by navigating to System ‣ Settings ‣ Cron. New jobs can be added by click the `+` button in the lower right corner.

[Cron](https://en.wikipedia.org/wiki/Cron)是一項用來定期執行任務的服務。您可以透過導覽至「系統」‣「設定」‣「Cron」來查看 Cron 任務。您可以透過點擊右下角的`+`按鈕來新增任務。

When adding a new job or modifying an existing one, you will be presented with fields that directly reflect the cron file syntax and that mostly speak for themselves. A job needs a name, a command, command parameters (if applicable), a description (optional, but recommend) and most importantly, a schedule. All time-related fields share the same syntax:

當您新增任務或修改現有任務時，您會看到一些字段，這些字段直接反映了 cron 檔案的語法，而且大多含義顯而易見。一個任務需要包含名稱、命令、命令參數（如果適用）、描述（可選，但建議填寫）以及最重要的規劃任務。所有與時間相關的欄位都使用相同的語法：

-   An asterisk (\*) can be used to mean “any”  
    星號（*）可以用來表示“任意”
    
-   Specifying multiple values is possible using the comma: `1,4,9`  
    可以使用逗號指定多個值： `1,4,9`
    
-   Ranges can be specified using a dash: `4-9`  
    可使用短橫線指定範圍： `4-9`
    

Available cron jobs are registered in the backend to prevent command injection and privilege escalation. These can be found under Command and may use optional Parameters. Restart and reload actions are self-explanatory. They tend to take no parameters and will restart (usually slower stop and start of a process) or reload (usually a faster SIGHUP) the respective service. The availability of restart and reload is subject to their respective services as not all software will support a reload for implementational reasons.

可用的定時任務已在後端註冊，以防止命令注入和權限提升。這些任務可以在“命令”下找到，並可能使用可選參數。重啟和重新載入操作顧名思義，它們通常不接受任何參數，會重啟（通常是進程的停止和啟動，速度較慢）或重新加載（通常是速度較快的SIGHUP ）相應的服務。重新啟動和重新載入的可用性取決於各自的服務，因為出於實現方面的原因，並非所有軟體都支援重新載入。

## Tunables｜可調參數

Tunables are the settings that go into the `loader.conf` and `sysctl.conf` files, which allows tweaking of low-level system settings. They can be set by going to System ‣ Settings ‣ Tunables.

可調參數是指寫入`loader.conf`和`sysctl.conf`檔案的設置，用於調整底層系統設定。可透過「系統」‣「設定」‣「可調參數」進行設定。

Here, the currently active settings can be viewed and new ones can be created. A list of possible values can be obtained by issuing `sysctl -a` on an OPNsense shell. Additional tunables may exist depending on boot loader capabilities and kernel module support.

在這裡，您可以查看當前啟動的設定並建立新的設定。在 OPNsense shell 中執行`sysctl -a`指令可以取得可用值清單。根據引導程式的功能和核心模組支援情況，可能還有其他可調參數。

## Logging｜日誌記錄

Local log settings can be found at System ‣ Settings ‣ Logging, tab “Local”（當地的）.

本機日誌設定可在「系統」‣「設定」‣「日誌記錄」標籤“Local”（當地的）中找到。

The regular log files will use the following standard pattern on disk `/var/log/<application>/<application>_[YYYYMMDD].log` (one file per day). Our user interface provides an integrated view stitching all collected files together. Available settings may change the appearance on disk depending on space and time constraints for log rotation.

常規日誌檔案將使用以下標準模式儲存在磁碟上`/var/log/<application>/<application>_[YYYYMMDD].log` （每天一個檔案）。我們的使用者介面提供了一個整合視圖，將所有收集的文件拼接在一起。根據空間和日誌輪換的時間限制，可用的設定可能會改變磁碟上的顯示方式。

Many plugins have their own logs. In the UI, they are grouped with the settings of that plugin. They mostly log to /var/log/ in text format, so you can view or follow them with *tail*.

許多插件都有自己的日誌。在UI中，這些日誌與插件的設定一起分組。它們大多以文字格式記錄到 /var/log/ 目錄下，因此您可以使用 *tail* 命令查看或追蹤這些日誌。
