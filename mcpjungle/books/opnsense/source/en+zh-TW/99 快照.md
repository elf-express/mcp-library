## [Quick Overview](#id2)｜[快速概覽](#id2)

*Snapshots* capture the base system at a given moment. They’re useful for administration, as they introduce a fallback boot option when more risky operations like major upgrades or experimental configurations fail. If something goes wrong, it is quite simple to roll back to the previous working state.

*快照* 會捕捉系統在特定時刻的基礎狀態。它們對系統管理非常有用，因為當諸如重大升級或實驗性配置等風險較高的操作失敗時，快照可以提供備用啟動選項。如果出現問題，回滾到之前的正常狀態非常簡單。

These *Snapshots* leverage ZFS features, making them space-efficient and easy to manage. During the boot process, the latest and previous saved *Snapshots* can be chosen with *Option 8*, effectively switching between different system states.

這些*快照*利用了ZFS特性，使其既節省空間又易於管理。在啟動過程中，可以使用*選項8*選擇最新和先前儲存的*快照*，從而有效地在不同的系統狀態之間切換。

Attention

注意

**Snapshots require ZFS as filesystem**. UFS will not work since it does not support file system level snapshots.

**快照需要使用ZFS作為檔案系統**。 UFS無法使用，因為它不支援檔案系統層級的快照。

The *Snapshots* are differential. A new *Snapshot* is always the latest current running state. This means, there are no incremental *Snapshot* chains, as seen in other implementations such as Hypervisors.

*快照*是差分式的。新的*快照*始終代表最新的目前運行狀態。這意味著，不存在像其他實作方式（例如虛擬機器管理程式）中那樣的增量式*快照*鏈。

Note

注意事項

Each *Snapshot* can be created and deleted as its own self contained entity with no other dependencies. The size of each *Snapshot* will grow over time as the distance in bytes between the current *active Snapshot* and all stored *non-active Snapshots* grow.

每個快照都可以作為一個獨立的實體建立和刪除，不依賴任何其他元件。隨著目前活動快照與所有已儲存的非活動快照之間的位元組數差距增大，每個快照的大小也會隨之增長。

## [Recommended Workflow](#id3)｜[推薦工作流程](#id3)

1.  Create a new Snapshot with the name `known-good`  
    建立一個名為`known-good`的新快照
    
2.  Do administrative changes (e.g. firmware upgrade)  
    執行管理變更（例如韌體升級）
    
3.  Reboot and test the changes:  
    重新啟動並測試變更：
    

-   OPNsense works as expected:  
    OPNsense 運作正常：
    
    -   Remove the **known-good** *Snapshot* and keep using the **default** *Snapshot*  
        刪除 **已知良好** *快照* 並繼續使用 **預設** *快照*
        
    
-   OPNsense has issues:  
    OPNsense存在一些問題：
    
    -   Activate the **known-good** *Snapshot* either in the WebGUI or the Boot Menu  
        在 Web 圖形使用者介面或啟動選單中啟動**已知良好**的*快照*
        
    -   After rebooting, remove the bad **default** *Snapshot*  
        重新啟動後，刪除壞的**預設** *快照*
        
    -   Rename the **known-good** *Snapshot* back to **default**  
        將**已知良好**的*快照*重新命名回**預設**。
        
    

Tip

提示

*Snapshots* can also be used to safeguard against regressions introduced in configuration changes. Creating a new snapshot and activating it immediately, will make the system roll back automatically to the *last known good configuration* on reboot or power cycle.

*快照*也可以用於防止配置變更引入回歸問題。建立新快照並立即啟動後，系統會在重新啟動或斷電後自動回滾到*上次已知的良好配置*。

## [Tutorial](#id4)｜[教學](#id4)

As an example, there is a major upgrade to a new OPNsense version. To have the option of a quick rollback when things do not turn out as expected, creating a *Snapshot* before doing the changes is the best choice.

例如，OPNsense 進行了一次重大升級，升級到新版本後，為了能夠在出現意外情況時快速回滾，最佳做法是在進行更改之前創建*快照*。

Note

注意事項

This is useful for *Hardware Appliances*. A virtualized OPNsense will have other recovery options that leverage the features of the Hypervisor itself, like creating VM level snapshots.

這對於*硬體設備*非常有用。虛擬化的 OPNsense 將提供其他復原選項，利用虛擬機器管理程式本身的功能，例如建立VM層級的快照。

Snapshots can have the following states:

快照可以有以下幾個狀態：

| Active<br>目前 | Description<br>描述 |
| --- | --- |
| **N** | *Snapshot* is active right now<br>*快照* 目前處於活動狀態 |
| **R** | *Snapshot* will be active after reboot<br>*快照* 將在重新啟動後生效 |
| **NR** | *Snapshot* is active and will be used on reboots<br>*快照* 已啟用，將在重新啟動時使用 |
| **\-** | *Snapshot* is not active<br>*快照* 未啟動 |

### [Creating a Snapshot](#id5)｜[創建快照](#id5)

-   Go to System ‣ Snapshots  
    轉到系統‣快照
    
-   Select **+** to create a new *Snapshot*, use `known-good` as name  
    選擇 **+** 建立新的*快照*，使用`known-good`作為名稱
    

At this point, upgrade the OPNsense to a new version. These changes will all happen in the current active **default** Snapshot, leaving the **known-good** Snapshot as *last known good configuration*.

此時，請將 OPNsense 升級到新版本。所有這些變更都將在目前活動的**預設**快照中進行，而**已知良好**快照將保留為*最後已知的良好配置*。

### [Booting a Snapshot](#id6)｜[啟動快照](#id6)

If the upgrade introduced some issues, the **known-good** *Snapshot* can be activated from the WebGUI.

如果升級引入了一些問題，可以從 WebGUI 啟動**已知良好** *快照*。

-   If the WebGUI is available:  
    如果 WebGUI 可用：
    
    > -   Go to System ‣ Snapshots  
          轉到系統‣快照
    >     
    > -   Select **✓** to activate the **known-good** *Snapshot*  
          選擇 **✓**以啟動**已知良好** *快照*
    >     
    > -   Reboot the OPNsense to roll back to the **known-good** *Snapshot*  
          重新啟動 OPNsense 以回滾到**已知良好**的*快照*。
    >     
    

Note

注意事項

In some cases, if the OPNsense does not boot to the WebGUI due to a software error, the *Boot Menu* can be used to roll back. If a *Hardware Appliance* does not have VGA, using the serial console is the best alternative.

在某些情況下，如果 OPNsense 由於軟體錯誤而無法啟動到 WebGUI，則可以使用*啟動選單*進行回溯。如果*硬體設備*沒有VGA，使用序列控制台是最好的選擇。

-   If the WebGUI is unavailable:  
    如果 WebGUI 不可用：
    
    > -   Boot the OPNsense, at the start of the boot sequence the *Boot Menu* will show up  
          啟動 OPNsense，在啟動順序開始時，將顯示 *啟動選單*
    >     
    > -   Press the *Space Bar* to pause it  
          按*空白鍵*暫停
    >     
    > -   Press `8` to choose `8. Boot Environments` which displays the current *Snapshots*  
          按下`8`選擇`8. Boot Environments` ，即可顯示目前的*快照*
    >     
    > -   Press `2` to select a different *active Snapshot*, it should now display `zfs:zroot/ROOT/known-good`  
          按下`2`選擇另一個*活動快照*，現在應該顯示`zfs:zroot/ROOT/known-good`
    >     
    > -   Press `1` to go back to the *main menu*  
          按`1`返回*主選單*
    >     
    > -   Press `ENTER` to select `1. Boot Multi user [ENTER]`  
          按`ENTER`選擇`1. Boot Multi user [ENTER]`
    >     
    

Tip

提示

If there are more Snapshots, press `2` repeatedly to cycle through them.

如果還有更多快照，請重複按`2`循環瀏覽。

### [Deleting a Snapshot](#id7)｜[刪除快照](#id7)

Now that the OPNsense has booted either the **known-good** *Snapshot* or the **default** *Snapshot*, it is time to clean up to ensure a clear current system state.

現在 OPNsense 已啟動 **已知良好** *快照* 或 **預設** *快照*，是時候進行清理以確保清晰的當前系統狀態了。

-   If the upgrade succeeded and **default** has been booted:  
    如果升級成功且已啟動**預設**系統：
    
    > -   Go to System ‣ Snapshots  
          轉到系統‣快照
    >     
    > -   Check that the **default** *Snapshot* is *Active NR*  
          檢查**預設** *快照* 是否為*活動 NR*
    >     
    > -   Press **🗑** to delete the **known-good** *Snapshot*  
          按 **🗑**刪除**已知良好** *快照*
    >     
    
-   If the upgrade failed and **known-good** has been booted:  
    如果升級失敗且**已知良好**的系統已啟動：
    
    > -   Go to System ‣ Snapshots  
          轉到系統‣快照
    >     
    > -   Check that the **known-good** *Snapshot* is *Active NR*  
          檢查**已知良好**的*快照*是否處於*活動狀態NR *
    >     
    > -   Press **🗑** to delete the **default** *Snapshot*  
          按 **🗑**刪除**預設** *快照*
    >     
    > -   Press **✎** to rename the **known-good** *Snapshot* to **default**  
          按 **✎**將**known-good** *Snapshot* 重新命名為 **default**
    >     
    

At this point, the OPNsense is correctly configured at the *last known good configuration* state.

此時，OPNsense 已正確配置為*最後已知的良好配置*狀態。

Tip

提示

Snapshots can be kept for a while after an upgrade, to have the option to roll back after a few days of testing in production. Please note that all configuration changes in that time will be lost when rolling back, so creating a configuration backup and importing it into the old system state can become a necessity.

升級後可以保留快照一段時間，以便在生產環境測試幾天後選擇回滾。請注意，回滾時這段時間內的所有組態變更都會遺失，因此建立組態備份並將其匯入至舊系統狀態可能成為必要之舉。

Note

注意事項

[Creating a Snapshot](#snapshot-creating) can be repeated to retry the major upgrade. Refer to the [Recommended Workflow](#snapshot-recommended-workflow) for a quick overview.

[建立快照](#snapshot-creating)可以重複執行以重試主要升級。有關快速概覽，請參閱[推薦工作流程](#snapshot-recommended-workflow) 。
