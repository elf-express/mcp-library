## 1\. Overview｜1. 概述

This specification extends, expands and replaces [PSR-2](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-2-coding-style-guide.md), the coding style guide and requires adherence to [PSR-1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md), the basic coding standard.

本規範擴展、擴充並取代了編碼風格指南 [PSR -2](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-2-coding-style-guide.md) ，並要求遵守基本編碼標準 [PSR -1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md) 。

Like PSR-2, the intent of this specification is to reduce cognitive friction when scanning code from different authors. It does so by enumerating a shared set of rules and expectations about how to format PHP code. This PSR seeks to provide a set way that coding style tools can implement, projects can declare adherence to and developers can easily relate to between different projects. When various authors collaborate across multiple projects, it helps to have one set of guidelines to be used among all those projects. Thus, the benefit of this guide is not in the rules themselves but the sharing of those rules.

與PSR-2一樣，此規範的目的是減少掃描不同作者的代碼時的認知摩擦。它透過列舉一組關於如何格式化 PHP 程式碼的共用規則和期望來實現這一點。這個PSR旨在提供一種編碼風格工具可以實現的固定方式，專案可以聲明遵守並且開發人員可以輕鬆地在不同專案之間進行關聯。當不同的作者在多個專案中進行協作時，擁有一套可在所有這些專案中使用的指南會有所幫助。因此，本指南的好處不在於規則本身，而在於這些規則的共享。

PSR-2 was accepted in 2012 and since then a number of changes have been made to PHP which has implications for coding style guidelines. Whilst PSR-2 is very comprehensive of PHP functionality that existed at the time of writing, new functionality is very open to interpretation. This PSR, therefore, seeks to clarify the content of PSR-2 in a more modern context with new functionality available, and make the errata to PSR-2 binding.

PSR -2 於 2012 年被採納，此後PHP進行了一系列修改，這對編碼風格指南產生了影響。雖然PSR -2 非常全面地涵蓋了編寫時已有的PHP功能，但新增功能仍有很大的解釋空間。因此，本PSR旨在結合新增功能，在更現代的背景下闡明PSR -2 的內容，並使PSR -2 的勘誤表具有約束力。

### Previous language versions｜先前語言版本

Throughout this document, any instructions MAY be ignored if they do not exist in versions of PHP supported by your project.

在本文檔中，如果您的專案支援的PHP版本中不存在任何MAY指令，則應忽略這些指令。

### Example｜例子

This example encompasses some of the rules below as a quick overview:

以下範例簡要概述了部分規則：

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

use Vendor\Package\{ClassA as A, ClassB, ClassC as C};
use Vendor\Package\SomeNamespace\ClassD as D;

use function Vendor\Package\{functionA, functionB, functionC};

use const Vendor\Package\{ConstantA, ConstantB, ConstantC};

class Foo extends Bar implements FooInterface
{
    public function sampleFunction(int $a, int $b = null): array
    {
        if ($a === $b) {
            bar();
        } elseif ($a > $b) {
            $foo->bar($arg1);
        } else {
            BazClass::bar($arg2, $arg3);
        }
    }

    final public static function bar()
    {
        // method body
    }
}
```

## 2\. General｜2. 總則

### 2.1 Basic Coding Standard｜2.1基本編碼標準

Code MUST follow all rules outlined in PSR-1.

代碼MUST遵循PSR -1 中概述的所有規則。

The term ‘StudlyCaps’ in PSR-1 MUST be interpreted as PascalCase where the first letter of each word is capitalized including the very first letter.

PSR -1 MUST中的術語「StudlyCaps」應解釋為 PascalCase，其中每個單字的首字母（包括第一個字母）都大寫。

### 2.2 Files｜2.2文件

All PHP files MUST use the Unix LF (linefeed) line ending. All PHP files MUST end with a single blank line.

所有PHP檔案MUST均使用LF （換行符）行尾符。所有PHP文件MUST均以一個空白行結尾。

The closing `?>` tag MUST be omitted from files containing only PHP.

僅包含PHP的檔案應省略結束標籤`?>` MUST 。

### 2.3 Lines｜2.3線

There MUST NOT be a hard limit on line length.

MUST NOT對線路長度有硬性限制。

The soft limit on line length MUST be 120 characters.

行長度的軟限制為 120 個字元MUST 。

Lines SHOULD NOT be longer than 80 characters; lines longer than that SHOULD be split into multiple subsequent lines of no more than 80 characters each.

行SHOULD NOT長度超過80個字元；超過80個字元的行SHOULD將被拆分為多個連續的行，每個行不超過80個字元。

There MUST NOT be trailing whitespace at the end of lines.

MUST NOT行尾會有空格。

Blank lines MAY be added to improve readability and to indicate related blocks of code except where explicitly forbidden.

除明確禁止的情況外，應新增空白行MAY以提高可讀性並指示相關的程式碼區塊。

There MUST NOT be more than one statement per line.

每行可以有多個MUST NOT 。

### 2.4 Indenting｜2.4縮進

Code MUST use an indent of 4 spaces for each indent level, and MUST NOT use tabs for indenting.

代碼MUST每個縮排等級使用 4 個空格，而MUST NOT使用製表符進行縮排。

### 2.5 Keywords and Types｜2.5關鍵字與類型

All PHP reserved [keywords](http://php.net/manual/en/reserved.keywords.php) and [types](http://php.net/manual/en/reserved.types.php) MUST be in lower case.

所有PHP保留 [關鍵字](http://php.net/manual/en/reserved.keywords.php)和 [類型](http://php.net/manual/en/reserved.types.php) MUST均應為小寫。

Any new types and keywords added to future PHP versions MUST be in lower case.

未來版本PHP中新增的任何新類型和關鍵字MUST將採用小寫字母。

Short form of type keywords MUST be used i.e. bool instead of boolean, int instead of integer etc.

類型關鍵字的縮寫形式MUST可以使用，例如 bool 代替 boolean，int 代替 integer 等。

## 3\. Declare Statements, Namespace, and Import Statements｜3.宣告語句、命名空間和導入語句

The header of a PHP file may consist of a number of different blocks. If present, each of the blocks below MUST be separated by a single blank line, and MUST NOT contain a blank line. Each block MUST be in the order listed below, although blocks that are not relevant may be omitted.

PHP 檔案的標頭可能由許多不同的區塊組成。如果存在，MUST 下面的每個區塊都由一個空白行分隔，並且 MUST NOT 包含一個空行。每個區塊MUST按照下面列出的順序排列，儘管可以省略不相關的區塊。

-   Opening `<?php` tag.  
    打開`<?php`標籤。
    
-   File-level docblock.  
    文件級文檔區塊。
    
-   One or more declare statements.  
    一個或多個聲明語句。
    
-   The namespace declaration of the file.  
    檔案命名空間聲明。
    
-   One or more class-based use import statements.  
    一個或多個基於類別的導入語句。
    
-   One or more function-based use import statements.  
    一個或多個基於函數的導入語句。
    
-   One or more constant-based use import statements.  
    使用一個或多個基於常數導入語句。
    
-   The remainder of the code in the file.  
    文件中的剩餘代碼。
    

When a file contains a mix of HTML and PHP, any of the above sections may still be used. If so, they MUST be present at the top of the file, even if the remainder of the code consists of a closing PHP tag and then a mixture of HTML and PHP.

當一個檔案包含HTML和PHP的混合時，上述任何部分仍然可以使用。如果是這樣，它們MUST應該出現在文件頂部，即使程式碼的其餘部分由一個結束的PHP標籤以及HTML和PHP的混合組成。

When the opening <?php tag is on the first line of the file, it MUST be on its own line with no other statements unless it is a file containing markup outside of PHP opening and closing tags.

當 <?php 開始標籤位於檔案的第一行時，它必須單獨MUST一行，且不能包含其他語句，除非該檔案包含位於PHP和結束標籤之外的標記。

Import statements MUST never begin with a leading backslash as they must always be fully qualified.

導入語句MUST永遠不要以反斜線開頭，因為它們必須永遠是完全限定的。

The following example illustrates a complete list of all blocks:

以下範例展示了所有程式碼區塊的完整清單：

```php
<?php

/**
 * This file contains an example of coding styles.
 */

declare(strict_types=1);

namespace Vendor\Package;

use Vendor\Package\{ClassA as A, ClassB, ClassC as C};
use Vendor\Package\SomeNamespace\ClassD as D;
use Vendor\Package\AnotherNamespace\ClassE as E;

use function Vendor\Package\{functionA, functionB, functionC};
use function Another\Vendor\functionD;

use const Vendor\Package\{CONSTANT_A, CONSTANT_B, CONSTANT_C};
use const Another\Vendor\CONSTANT_D;

/**
 * FooBar is an example class.
 */
class FooBar
{
    // ... additional PHP code ...
}
```

Compound namespaces with a depth of more than two MUST NOT be used. Therefore the following is the maximum compounding depth allowed:

複合命名空間的深度不能超過兩層MUST NOT 。因此，允許的最大複合深度如下：

```php
<?php

use Vendor\Package\SomeNamespace\{
  SubnamespaceOne\ClassA,
  SubnamespaceOne\ClassB,
  SubnamespaceTwo\ClassY,
  ClassZ,
};
```

And the following would not be allowed:

以下行為是不被允許的：

```php
<?php

use Vendor\Package\SomeNamespace\{
    SubnamespaceOne\AnotherNamespace\ClassA,
    SubnamespaceOne\ClassB,
    ClassZ,
};
```

When wishing to declare strict types in files containing markup outside PHP opening and closing tags, the declaration MUST be on the first line of the file and include an opening PHP tag, the strict types declaration and closing tag.

當希望在包含PHP開始和結束標籤之外的標記的文件中聲明嚴格類型時， MUST聲明應位於文件的第一行，並包含一個開始PHP標籤、嚴格類型聲明和結束標籤。

For example:

例如：

```php
<?php declare(strict_types=1) ?>
<html>
<body>
    <?php
        // ... additional PHP code ...
    ?>
</body>
</html>
```

Declare statements MUST contain no spaces and MUST be exactly declare(strict\_types=1) (with an optional semi-colon terminator).

宣告語句MUST不包含空格，且MUST必須完全是 declare(strict\_types=1)（有可選的分號終止符）。

Block declare statements are allowed and MUST be formatted as below. Note position of braces and spacing:

允許使用區塊宣告語句， MUST格式如下。注意大括號的位置和間距：

```sql
declare(ticks=1) {
    // some code
}
```

## 4\. Classes, Properties, and Methods｜4. 類別、屬性和方法

The term “class” refers to all classes, interfaces, and traits.

術語「類別」指的是所有類別、介面和特性。

Any closing brace MUST NOT be followed by any comment or statement on the same line.

任何右大括號MUST NOT後面都可以跟同一行的任何註解或宣告。

When instantiating a new class, parentheses MUST always be present even when there are no arguments passed to the constructor.

實例化新類別時，即使沒有向建構子傳遞任何參數，括號MUST也總是存在的。

```
new Foo();
```

### 4.1 Extends and Implements｜4.1擴展與實現

The extends and implements keywords MUST be declared on the same line as the class name.

extends 和 implements 關鍵字MUST必須與類別名稱在同一行宣告。

The opening brace for the class MUST go on its own line; the closing brace for the class MUST go on the next line after the body.

類別名稱MUST的左大括號單獨佔一行；類別名稱MUST的右大括號在正文之後的下一行。

Opening braces MUST be on their own line and MUST NOT be preceded or followed by a blank line.

左大括號MUST應單獨佔一行， MUST NOT前面或後面應有一行。

Closing braces MUST be on their own line and MUST NOT be preceded by a blank line.

右大括號MUST應單獨佔一行， MUST NOT前面應空一行。

```php
<?php

namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements \ArrayAccess, \Countable
{
    // constants, properties, methods
}
```

Lists of implements and, in the case of interfaces, extends MAY be split across multiple lines, where each subsequent line is indented once. When doing so, the first item in the list MUST be on the next line, and there MUST be only one interface per line.

實作清單（以及介面的擴充列表） MAY應跨多行顯示，每行縮排一次。這樣，清單中的第一個元素MUST應位於下一行，且MUST每行只能包含一個介面。

```php
<?php

namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements
    \ArrayAccess,
    \Countable,
    \Serializable
{
    // constants, properties, methods
}
```

### 4.2 Using traits｜4.2使用特徵

The use keyword used inside the classes to implement traits MUST be declared on the next line after the opening brace.

在類別中用於實作特性的 use 關鍵字MUST必須在左大括號後的下一行宣告。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;
}
```

Each individual trait that is imported into a class MUST be included one-per-line and each inclusion MUST have its own use import statement.

導入到類別中的每個單獨的特徵MUST都應逐行包含，並且每個包含項MUST都有自己的 use import 語句。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;
use Vendor\Package\SecondTrait;
use Vendor\Package\ThirdTrait;

class ClassName
{
    use FirstTrait;
    use SecondTrait;
    use ThirdTrait;
}
```

When the class has nothing after the use import statement, the class closing brace MUST be on the next line after the use import statement.

當類別在 use import 語句之後沒有任何內容時，類別的右大括號MUST應位於 use import 語句之後的下一行。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;
}
```

Otherwise, it MUST have a blank line after the use import statement.

否則， MUST use import 語句後面會有一個空白行。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;

    private $property;
}
```

When using the insteadof and as operators they must be used as follows taking note of indentation, spacing, and new lines.

使用 insteadof 和 as 運算子時，必須如下使用，並注意縮排、間距和換行符。

```php
<?php

class Talker
{
    use A;
    use B {
        A::smallTalk insteadof B;
    }
    use C {
        B::bigTalk insteadof C;
        C::mediumTalk as FooBar;
    }
}
```

### 4.3 Properties and Constants｜4.3性質和常數

Visibility MUST be declared on all properties.

可見性MUST應在所有屬性上聲明。

Visibility MUST be declared on all constants if your project PHP minimum version supports constant visibilities (PHP 7.1 or later).

如果您的專案MUST最低版本支援常數可見性（ PHP 7.1或更高版本）， PHP必須在所有常數上宣告可見性。

The var keyword MUST NOT be used to declare a property.

var 關鍵字MUST NOT可用來宣告屬性。

There MUST NOT be more than one property declared per statement.

每份聲明中可以申報MUST NOT房產。

Property names MUST NOT be prefixed with a single underscore to indicate protected or private visibility. That is, an underscore prefix explicitly has no meaning.

屬性名稱MUST NOT可以以單一底線作為前綴，表示受保護或私有可見性。也就是說，下劃線前綴本身並無特定意義。

There MUST be a space between type declaration and property name.

MUST類型宣告和屬性名稱之間應該有一個空格。

A property declaration looks like the following:

屬性聲明如下圖所示：

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public $foo = null;
    public static int $bar = 0;
}
```

### 4.4 Methods and Functions｜4.4方法和函數

Visibility MUST be declared on all methods.

在所有方法上都宣告可見性MUST 。

Method names MUST NOT be prefixed with a single underscore to indicate protected or private visibility. That is, an underscore prefix explicitly has no meaning.

方法名稱MUST NOT應以單一底線作為前綴，以表示受保護或私有可見性。也就是說，下劃線前綴本身並無特殊意義。

Method and function names MUST NOT be declared with space after the method name. The opening brace MUST go on its own line, and the closing brace MUST go on the next line following the body. There MUST NOT be a space after the opening parenthesis, and there MUST NOT be a space before the closing parenthesis.

方法和函數名稱MUST NOT 在方法名稱後宣告時留有空格。左大括號 MUST 獨佔一行，右大括號 MUST 位於主體後方的下一行。左括號後面有 MUST NOT ，右括號前有 MUST NOT 。

A method declaration looks like the following. Note the placement of parentheses, commas, spaces, and braces:

方法聲明如下圖所示。請注意圓括號、逗號、空格和花括號的位置：

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function fooBarBaz($arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

A function declaration looks like the following. Note the placement of parentheses, commas, spaces, and braces:

函數聲明如下所示。請注意圓括號、逗號、空格和花括號的位置：

```php
<?php

function fooBarBaz($arg1, &$arg2, $arg3 = [])
{
    // function body
}
```

### 4.5 Method and Function Arguments｜4.5方法和函數參數

In the argument list, there MUST NOT be a space before each comma, and there MUST be one space after each comma.

在參數清單中，每個逗號前有一個MUST NOT ，每個逗號後面有一個MUST 。

Method and function arguments with default values MUST go at the end of the argument list.

具有預設值的方法和函數參數MUST放在參數列表的末端。

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function foo(int $arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

Argument lists MAY be split across multiple lines, where each subsequent line is indented once. When doing so, the first item in the list MUST be on the next line, and there MUST be only one argument per line.

論證列表MAY可以拆分成多行，每行縮排一次。拆分後，列表中的第一個項目MUST位於下一行，並且MUST每行只能有一個論證。

When the argument list is split across multiple lines, the closing parenthesis and opening brace MUST be placed together on their own line with one space between them.

當參數清單跨越多行時，右括號和左大括號MUST應放在單獨的一行上，並在它們之間留一個空格。

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function aVeryLongMethodName(
        ClassTypeHint $arg1,
        &$arg2,
        array $arg3 = []
    ) {
        // method body
    }
}
```

When you have a return type declaration present, there MUST be one space after the colon followed by the type declaration. The colon and declaration MUST be on the same line as the argument list closing parenthesis with no spaces between the two characters.

當存在回傳類型聲明時， MUST冒號後應有一個空格，然後才是型別宣告。冒號與宣告MUST必須與參數清單的右括號位於同一行，且兩者之間不能有空格。

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

class ReturnTypeVariations
{
    public function functionName(int $arg1, $arg2): string
    {
        return 'foo';
    }

    public function anotherFunction(
        string $foo,
        string $bar,
        int $baz
    ): string {
        return 'foo';
    }
}
```

In nullable type declarations, there MUST NOT be a space between the question mark and the type.

在可空型別聲明中， MUST NOT問號與型別之間要有一個空格。

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

class ReturnTypeVariations
{
    public function functionName(?string $arg1, ?int &$arg2): ?string
    {
        return 'foo';
    }
}
```

When using the reference operator & before an argument, there MUST NOT be a space after it, like in the previous example.

當在參數前使用引用運算子 & 時，其後MUST NOT一個空格，就像前面的範例一樣。

There MUST NOT be a space between the variadic three dot operator and the argument name:

MUST NOT可變參數三點運算子與參數名稱之間必須有一個空格：

```php
public function process(string $algorithm, ...$parts)
{
    // processing
}
```

When combining both the reference operator and the variadic three dot operator, there MUST NOT be any space between the two of them:

當同時使用參考運算子和可變三點運算MUST NOT ，兩者之間可以有空格：

```php
public function process(string $algorithm, &...$parts)
{
    // processing
}
```

### 4.6 abstract, final, and static｜4.6摘要、最終版和靜態版

When present, the abstract and final declarations MUST precede the visibility declaration.

如果存在，則摘要和最終聲明MUST位於可見性聲明之前。

When present, the static declaration MUST come after the visibility declaration.

如果存在，靜態宣告MUST位於可見性宣告之後。

```php
<?php

namespace Vendor\Package;

abstract class ClassName
{
    protected static $foo;

    abstract protected function zim();

    final public static function bar()
    {
        // method body
    }
}
```

### 4.7 Method and Function Calls｜4.7方法和函數調用

When making a method or function call, there MUST NOT be a space between the method or function name and the opening parenthesis, there MUST NOT be a space after the opening parenthesis, and there MUST NOT be a space before the closing parenthesis. In the argument list, there MUST NOT be a space before each comma, and there MUST be one space after each comma.

呼叫方法或函數時，方法或函數名稱與左括號之間必須有一個MUST NOT ，左括號後面必須有一個空格，右括號前MUST NOT有一個空格。在參數清單中，每個逗號前方必須有一個MUST NOT ，每個MUST NOT後面MUST有一個空格。

```php
<?php

bar();
$foo->bar($arg1);
Foo::bar($arg2, $arg3);
```

Argument lists MAY be split across multiple lines, where each subsequent line is indented once. When doing so, the first item in the list MUST be on the next line, and there MUST be only one argument per line. A single argument being split across multiple lines (as might be the case with an anonymous function or array) does not constitute splitting the argument list itself.

參數列表MAY可以跨多行顯示，每行縮排一次。這樣，列表中的第一個元素MUST位於下一行，且MUST每行只能有一個參數。單一參數跨多行顯示（例如匿名函數或陣列的情況）並不等同於參數清單本身的拆分。

```php
<?php

$foo->bar(
    $longArgument,
    $longerArgument,
    $muchLongerArgument
);
```

```php
<?php

somefunction($foo, $bar, [
  // ...
], $baz);

$app->get('/hello/{name}', function ($name) use ($app) {
    return 'Hello ' . $app->escape($name);
});
```

## 5\. Control Structures｜5. 控制結構

The general style rules for control structures are as follows:

控制結構的一般風格規則如下：

-   There MUST be one space after the control structure keyword  
    MUST控制結構關鍵字後面有一個空格
    
-   There MUST NOT be a space after the opening parenthesis  
    MUST NOT左括號後面應有一個空格
    
-   There MUST NOT be a space before the closing parenthesis  
    MUST NOT右括號前應有一個空格
    
-   There MUST be one space between the closing parenthesis and the opening brace  
    MUST右括號和左大括號之間應有一個空格
    
-   The structure body MUST be indented once  
    結構體MUST縮排一次
    
-   The body MUST be on the next line after the opening brace  
    正文MUST應位於左大括號後的下一行
    
-   The closing brace MUST be on the next line after the body  
    右大括號MUST應位於正文之後的下一行。
    

The body of each structure MUST be enclosed by braces. This standardizes how the structures look and reduces the likelihood of introducing errors as new lines get added to the body.

每個結構體MUST的主體部分都應使用大括號括起來。這樣可以規範結構體的外觀，並降低在向主體部分添加新行時引入錯誤的可能性。

### 5.1 if, elseif, else｜5.1如果，否則如果，否則

An if structure looks like the following. Note the placement of parentheses, spaces, and braces; and that else and elseif are on the same line as the closing brace from the earlier body.

一個 if 語句的結構如下圖所示。請注意括號、空格和花括號的位置；以及 else 和 elseif 與前面語句體的右花括號位於同一行。

```php
<?php

if ($expr1) {
    // if body
} elseif ($expr2) {
    // elseif body
} else {
    // else body;
}
```

The keyword elseif SHOULD be used instead of else if so that all control keywords look like single words.

使用關鍵字 elseif SHOULD取代 else if，以便所有控製關鍵字看起來像單字。

Expressions in parentheses MAY be split across multiple lines, where each subsequent line is indented at least once. When doing so, the first condition MUST be on the next line. The closing parenthesis and opening brace MUST be placed together on their own line with one space between them. Boolean operators between conditions MUST always be at the beginning or at the end of the line, not a mix of both.

括號內的表達式MAY應跨行顯示，每行至少縮排一次。這樣，第一個條件MUST應位於下一行。右括號和左大括號MUST應放在同一行，中間留一個空格。條件之間的布林運算子MUST必須位於行首或行尾，不能混用。

```php
<?php

if (
    $expr1
    && $expr2
) {
    // if body
} elseif (
    $expr3
    && $expr4
) {
    // elseif body
}
```

### 5.2 switch, case｜5.2開關，外殼

A switch structure looks like the following. Note the placement of parentheses, spaces, and braces. The case statement MUST be indented once from switch, and the break keyword (or other terminating keywords) MUST be indented at the same level as the case body. There MUST be a comment such as // no break when fall-through is intentional in a non-empty case body.

一個 switch 語句的結構如下所示。請注意括號、空格和花括號的位置。 case 語句MUST應比 switch 語句縮排一次，break 關鍵字（或其他終止關鍵字） MUST應與 case 語句體縮排到相同層級MUST應加入註釋，例如 // 當 case 語句體非空且有意使用 fall-through 時，無需 break。

```php
<?php

switch ($expr) {
    case 0:
        echo 'First case, with a break';
        break;
    case 1:
        echo 'Second case, which falls through';
        // no break
    case 2:
    case 3:
    case 4:
        echo 'Third case, return instead of break';
        return;
    default:
        echo 'Default case';
        break;
}
```

Expressions in parentheses MAY be split across multiple lines, where each subsequent line is indented at least once. When doing so, the first condition MUST be on the next line. The closing parenthesis and opening brace MUST be placed together on their own line with one space between them. Boolean operators between conditions MUST always be at the beginning or at the end of the line, not a mix of both.

括號內的表達式MAY應跨行顯示，每行至少縮排一次。這樣，第一個條件MUST應位於下一行。右括號和左大括號MUST應放在同一行，中間留一個空格。條件之間的布林運算子MUST必須位於行首或行尾，不能混用。

```php
<?php

switch (
    $expr1
    && $expr2
) {
    // structure body
}
```

### 5.3 while, do while

A while statement looks like the following. Note the placement of parentheses, spaces, and braces.

一個 while 迴圈語句看起來像這樣。請注意圓括號、空格和花括號的位置。

```php
<?php

while ($expr) {
    // structure body
}
```

Expressions in parentheses MAY be split across multiple lines, where each subsequent line is indented at least once. When doing so, the first condition MUST be on the next line. The closing parenthesis and opening brace MUST be placed together on their own line with one space between them. Boolean operators between conditions MUST always be at the beginning or at the end of the line, not a mix of both.

括號內的表達式MAY應跨行顯示，每行至少縮排一次。這樣，第一個條件MUST應位於下一行。右括號和左大括號MUST應放在同一行，中間留一個空格。條件之間的布林運算子MUST必須位於行首或行尾，不能混用。

```php
<?php

while (
    $expr1
    && $expr2
) {
    // structure body
}
```

Similarly, a do while statement looks like the following. Note the placement of parentheses, spaces, and braces.

同樣，do while 語句看起來像這樣。請注意圓括號、空格和花括號的位置。

```php
<?php

do {
    // structure body;
} while ($expr);
```

Expressions in parentheses MAY be split across multiple lines, where each subsequent line is indented at least once. When doing so, the first condition MUST be on the next line. Boolean operators between conditions MUST always be at the beginning or at the end of the line, not a mix of both.

括號內的表達式MAY應跨行顯示，且每行至少縮排一次。這樣，第一個條件MUST應位於下一行。條件之間的布林運算子MUST必須位於行首或行尾，不能混用。

```php
<?php

do {
    // structure body;
} while (
    $expr1
    && $expr2
);
```

### 5.4 for｜5.4用於

A for statement looks like the following. Note the placement of parentheses, spaces, and braces.

一個 for 迴圈語句如下所示。請注意圓括號、空格和花括號的位置。

```php
<?php

for ($i = 0; $i < 10; $i++) {
    // for body
}
```

Expressions in parentheses MAY be split across multiple lines, where each subsequent line is indented at least once. When doing so, the first expression MUST be on the next line. The closing parenthesis and opening brace MUST be placed together on their own line with one space between them.

括號內的表達式MAY應跨行顯示，每行至少縮排一次。這樣，第一個表達式MUST應位於下一行。右括號和左大括號MUST應放在同一行，中間留一個空格。

```php
<?php

for (
    $i = 0;
    $i < 10;
    $i++
) {
    // for body
}
```

### 5.5 foreach

A foreach statement looks like the following. Note the placement of parentheses, spaces, and braces.

一個 foreach 語句看起來像這樣。請注意圓括號、空格和花括號的位置。

```php
<?php

foreach ($iterable as $key => $value) {
    // foreach body
}
```

### 5.6 try, catch, finally｜5.6嘗試，捕捉，最終

A try-catch-finally block looks like the following. Note the placement of parentheses, spaces, and braces.

一個 try-catch-finally 程式碼區塊如下所示。請注意圓括號、空格和花括號的位置。

```php
<?php

try {
    // try body
} catch (FirstThrowableType $e) {
    // catch body
} catch (OtherThrowableType | AnotherThrowableType $e) {
    // catch body
} finally {
    // finally body
}
```

## 6\. Operators｜6. 操作員

Style rules for operators are grouped by arity (the number of operands they take).

運算符的樣式規則以元數（運算子接受的操作數的數量）分組。

When space is permitted around an operator, multiple spaces MAY be used for readability purposes.

當運算符周圍允許留有空格時，為了方便閱讀，可以使用多個空格MAY 。

All operators not described here are left undefined.

此處未描述的所有運算子均未定義。

### 6.1. Unary operators｜6.1 . 一元運算符

The increment/decrement operators MUST NOT have any space between the operator and operand.

增/減運算子MUST NOT運算子和運算元之間可以有空格。

```
$i++;
++$j;
```

Type casting operators MUST NOT have any space within the parentheses:

類型轉換運算子MUST NOT括號內可以有空格：

```
$intValue = (int) $input;
```

### 6.2. Binary operators｜6.2 . 二元運算符

All binary \[arithmetic\]\[\], \[comparison\]\[\], \[assignment\]\[\], \[bitwise\]\[\], \[logical\]\[\], \[string\]\[\], and \[type\]\[\] operators MUST be preceded and followed by at least one space:

所有二進位算術運算子、比較運算子、賦值運算子、位元運算運算子、邏輯運算子、字串運算子和型別運算子MUST前後都必須至少有一個空格：

```
if ($a === $b) {
    $foo = $bar ?? $a ?? $b;
} elseif ($a > $b) {
    $foo = $a + $b * $c;
}
```

### 6.3. Ternary operators｜6.3 。三元運算符

The conditional operator, also known simply as the ternary operator, MUST be preceded and followed by at least one space around both the ? and : characters:

條件運算子（也稱為三元運算子） MUST前後必須至少各有一個空格，且 ? 和 : 字元之間必須有空格：

```
$variable = $foo ? 'foo' : 'bar';
```

When the middle operand of the conditional operator is omitted, the operator MUST follow the same style rules as other binary \[comparison\]\[\] operators:

當條件運算子的中間運算元被省略時，運算子MUST遵循與其他二元比較運算子相同的樣式規則：

```
$variable = $foo ?: 'bar';
```

## 7\. Closures｜7. 閉口

Closures MUST be declared with a space after the function keyword, and a space before and after the use keyword.

閉包MUST宣告時，function 關鍵字後面要加一個空格，use 關鍵字前後也要加一個空格。

The opening brace MUST go on the same line, and the closing brace MUST go on the next line following the body.

左大括號 MUST 位於同一行，右大括號 MUST 位於主體後方的下一行。

There MUST NOT be a space after the opening parenthesis of the argument list or variable list, and there MUST NOT be a space before the closing parenthesis of the argument list or variable list.

MUST NOT參數列表或變數列表的左括號後面要有一個空格， MUST NOT參數列表或變數列表的右括號前要有一個空格。

In the argument list and variable list, there MUST NOT be a space before each comma, and there MUST be one space after each comma.

在參數清單和變數清單中， MUST NOT每個逗號前有一個空格， MUST每個逗號後有一個空格。

Closure arguments with default values MUST go at the end of the argument list.

具有預設值的閉包參數MUST放在參數清單的末端。

If a return type is present, it MUST follow the same rules as with normal functions and methods; if the use keyword is present, the colon MUST follow the use list closing parentheses with no spaces between the two characters.

如果存在回傳類型，則它遵循與普通函數和方法相同的規則；如果存在 use 關鍵字， MUST MUST在 use 列表的右括號後面，兩個字元之間沒有空格。

A closure declaration looks like the following. Note the placement of parentheses, commas, spaces, and braces:

閉包聲明如下圖所示。請注意圓括號、逗號、空格和花括號的位置：

```php
<?php

$closureWithArgs = function ($arg1, $arg2) {
    // body
};

$closureWithArgsAndVars = function ($arg1, $arg2) use ($var1, $var2) {
    // body
};

$closureWithArgsVarsAndReturn = function ($arg1, $arg2) use ($var1, $var2): bool {
    // body
};
```

Argument lists and variable lists MAY be split across multiple lines, where each subsequent line is indented once. When doing so, the first item in the list MUST be on the next line, and there MUST be only one argument or variable per line.

參數列表和變數列表MAY應跨多行顯示，每行縮排一次。這樣，列表中的第一個元素MUST應位於下一行，且MUST每行只能有一個參數或變數。

When the ending list (whether of arguments or variables) is split across multiple lines, the closing parenthesis and opening brace MUST be placed together on their own line with one space between them.

當結束清單（無論是參數還是變數）跨越多行時，右括號和左大括號MUST應放在單獨的一行上，並在它們之間留一個空格。

The following are examples of closures with and without argument lists and variable lists split across multiple lines.

以下是帶有參數列表和不帶有參數列表的閉包以及跨多行的變數列表的範例。

```php
<?php

$longArgs_noVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) {
   // body
};

$noArgs_longVars = function () use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_longVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_shortVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use ($var1) {
   // body
};

$shortArgs_longVars = function ($arg) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};
```

Note that the formatting rules also apply when the closure is used directly in a function or method call as an argument.

請注意，當閉包直接用作函數或方法呼叫中的參數時，格式化規則也適用。

```php
<?php

$foo->bar(
    $arg1,
    function ($arg2) use ($var1) {
        // body
    },
    $arg3
);
```

## 8\. Anonymous Classes｜8. 匿名類

Anonymous Classes MUST follow the same guidelines and principles as closures in the above section.

匿名類MUST遵循與上述章節中的封閉類相同的指導原則和原則。

```php
<?php

$instance = new class {};
```

The opening brace MAY be on the same line as the class keyword so long as the list of implements interfaces does not wrap. If the list of interfaces wraps, the brace MUST be placed on the line immediately following the last interface.

只要實作介面的清單不換行，左大括號MAY就應該與class關鍵字在同一行。如果介面清單換行，則大括號MUST應該放在最後一個介面之後的下一行。

```php
<?php

// Brace on the same line
$instance = new class extends \Foo implements \HandleableInterface {
    // Class content
};

// Brace on the next line
$instance = new class extends \Foo implements
    \ArrayAccess,
    \Countable,
    \Serializable
{
    // Class content
};
```
