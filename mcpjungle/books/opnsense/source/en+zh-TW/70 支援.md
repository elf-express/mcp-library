# Support｜支援

> 章節：[Official hardware](<000 目錄.md#c-7>)

Firewalls can be complex devices, in which case it helps to have some pointers when running into issues. When official hardware is used, a free year of OPNsense Business Edition is offered with the product.

防火牆可能非常複雜，因此遇到問題時，掌握一些指導原則會很有幫助。使用官方硬體時，產品會附贈一年的 OPNsense 商業版軟體。

In case a problem emerges, we need to establish if this is related to either hardware or software. Over the years we have seen quite some different challenges people run into, which we would like to highlight in this chapter, including feedback our engineers need to assess if an issue is hardware related. To assist with installation and/or configuration challenges, we can always offer support when subscribed to our business support service.

如果出現問題，我們需要確定問題出在硬體還是軟體上。多年來，我們遇到過各種各樣的挑戰，本章將重點介紹這些挑戰，以及我們的工程師需要哪些回饋來評估問題是否與硬體相關。如果您訂閱了我們的企業支援服務，我們將隨時為您提供安裝和/或設定方面的協助。

Tip

提示

Always make sure to backup your configuration before doing any debugging.

在進行任何調試之前，請務必備份您的配置。

Note

注意事項

To start an RMA procedure, always contact our sales team (sales at opnsense dot com) first, make sure to let us know which device serial number it relates to.

要啟動RMA程序，請務必先聯絡我們的銷售團隊（sales at opnsense dot com），並確保告知我們它與哪個設備序號相關。

Note

注意事項

When redacting output for security reasons, always make sure networks are replaced with similar numbers (specifically using the same subnets), for example when using `192.168.1.1/24` on the firewall and not wanting to share that information, just replace it with something like `x1.x1.x1.1/24` so we know there is a `/24` network for which we use the .1 address.

出於安全原因編輯輸出時，務必確保網路被替換為類似的數字（特別是使用相同的子網），例如，當在防火牆上使用`192.168.1.1/24`並且不想共享該資訊時，只需將其替換為類似`x1.x1.x1.1/24`的內容，這樣我們就知道存在一個`/24`網絡，我們為其使用 .1 位址。

When sharing information with our team, you often need to collect some data from the machine, you can either arrange that via [serial connectivity](<67 串行控制台連接.md>) or a [secure shell](<98 設定.md#secure-shell>).

在與我們的團隊共享資訊時，您經常需要從機器收集一些數據，您可以透過 [串行連接](<67 串行控制台連接.md>)或 [安全外殼](<98 設定.md#secure-shell>)來安排。

## Network connectivity issues｜網路連線問題

When there’s no or limited network connectivity, we need to establish if there is a physical connectivity issue first. Always make sure to use well shielded network cables and check connectivity on the same switch port using a laptop or other device to rule out issues with the other end of the connection.

當網路連線中斷或受限時，我們需要先確定是否有實體連線問題。務必使用屏蔽良好的網路線，並使用筆記型電腦或其他裝置連接到同一交換器連接埠進行連接測試，以排除連接另一端的問題。

Knowing both cable and switch (or modem) connectivity is fine, we can start investigating if the issue is caused by a specific port or if its a more generic issue. We can use Interfaces ‣ Assignments to switch ports around, so for example if `igc0` is having issues, try to move the function to another port and see if the issue persists after a clean reboot.

確認網路線和交換器（或數據機）連接正常後，我們可以開始調查問題是出在特定連接埠還是更普遍的問題上。我們可以使用「接口」‣「分配」來切換端口，例如，如果`igc0`出現問題，可以嘗試將其功能移至另一個端口，然後重啟系統，看看問題是否仍然存在。

If the issue seems to be isolated to a single (specific) port, when contacting our office, please share the status of the lights for both working and non working ports and via a console collect the output of the following commands after a clean reboot:

如果問題似乎僅限於單一（特定）端口，請在聯繫我們辦公室時，提供正常工作端口和不正常工作端口的指示燈狀態，並在乾淨重啟後透過控制台收集以下命令的輸出：

```
dmesg
ifconfig -m -v
ifinfo
```

In cases where the issue seems to persist when chosing another port, the easiest option to rule out hardware issues is to reinstall the device and retest with our default settings.

如果選擇其他連接埠後問題仍然存在，排除硬體問題的最簡單方法是重新安裝設備並使用預設設定重新測試。

## Boot issues / drive issues｜啟動問題/驅動器問題

In order to debug, we need to establish console connectivity first using the (serial) console port. When powering up the machine, after a while, there’s usually some output from the bios of the machine.

為了進行調試，我們需要先透過（串列埠）控制台連接埠建立連線。機器啟動後，過一段時間，通常會從機器的BIOS輸出一些資訊。

You can use the `<ESC>` key to select a boot device, with this you can boot from a usb stick to reinstall if you’re not able to boot into OPNsense at all.

您可以使用`<ESC>`鍵選擇啟動設備，這樣您就可以從 USB 隨身碟啟動以重新安裝，如果您完全無法啟動到 OPNsense。

In some cases, even with a zfs filesystem, it happens that the filesystem gets corrupted, if that’s the case, it’s usually best to reinstall the device (see reinstalling).

在某些情況下，即使使用 zfs 檔案系統，檔案系統也可能損壞。如果發生這種情況，通常最好重新安裝設備（請參閱重新安裝）。

Most of our devices use NVME storage, if your device contains one and you wish to reinstall as clean as possible (which is advisable in some situations), boot into the installer, login using `root` with the password `opnsense` next choose 8 for console and execute the following command:

我們的大多數設備都使用NVME存儲，如果您的設備包含一個存儲並且您希望盡可能乾淨地重新安裝（在某些情況下建議這樣做），請啟動安裝程序，使用`root`和密碼`opnsense`登錄，然後選擇8作為控制台並執行以下命令：

```
nvmecontrol format nvme0
```

Then exit to login prompt (type exit and select 0) And try re-installing (using `installer` with password `opnsense`).

然後退出到登入提示字元（輸入 exit 並選擇 0），然後嘗試重新安裝（使用`installer`和密碼`opnsense` ）。

## Random crashes or reboots｜隨機崩潰或重啟

When the machine crashes with a “kernel” crash, there’s often a crash report in System ‣ Firmware ‣ Reporter, you can upload that via the reporter to us adding your email address (to help us find it) or you can copy any relevant information that is reported there and send it to our team.

當機器發生「核心」崩潰時，通常會在「系統」‣「韌體」‣「報告器」中產生崩潰報告。您可以透過報告器上傳該報告，並附上您的電子郵件地址（以便我們可以找到），或者您可以複製其中報告的任何相關資訊並將其發送給我們的團隊。

In most cases, to exclude hardware issues, it’s best to reinstall the machine and test it without any additional plugins installed. If the machine remains unstable in that case, please share the crash reporter output and the output of the following commands so we can assess next steps on our end:

大多數情況下，為了排除硬體問題，最好重新安裝系統並在不安裝任何額外插件的情況下進行測試。如果系統仍然不穩定，請提供崩潰報告的輸出以及以下命令的輸出，以便我們評估後續步驟：

```
dmesg
cat /var/log/system/latest.log
```

## Reinstalling the Business Edition｜重新安裝商業版

Using your license number, you can always download the latest software installers from our servers, these are located at [https://opnsense-update.deciso.com/\[license\_number\]/Installers](https://opnsense-update.deciso.com/).

使用您的許可證號，您可以隨時從我們的伺服器下載最新的軟體安裝程序，這些程序位於 [ https://opnsense-update.deciso.com/\[license\_number\ ]/Installers]( https://opnsense-update.deciso.com/ )。

The filenames are similar to the ones used for the community edition, these are explained [here](<55 初始安裝和配置.md#image-filename-composition>), just continue reading in that section of the manual to learn how to verify the files, create a bootable usb stick and run the installer. Both versions are similar when it comes to installation.

檔案名稱與社群版使用的檔案名稱類似，具體說明請參閱[此處](<55 初始安裝和配置.md#image-filename-composition>) ，請繼續閱讀手冊的相應章節，以了解如何驗證檔案、建立啟動USB以及運行安裝程式。兩個版本的安裝過程基本上相同。

Note

注意事項

For installs on our hardware, you will need the `serial` type.

要在我們的硬體上進行安裝，您需要`serial`類型。
