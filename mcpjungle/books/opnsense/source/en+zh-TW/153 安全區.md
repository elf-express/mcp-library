## [Introduction](#id1)｜[簡介](#id1)

Firewalls manage traffic between network segments. Utilizing **zones** simplifies configurations by grouping interfaces with similar security trust levels. This approach is beneficial when managing numerous interfaces that require a consistent and unified ruleset.

防火牆管理網段之間的流量。利用 **區域** 透過將具有相似安全信任等級的介面分組來簡化設定。當管理需要一致且統一的規則集的大量介面時，這種方法非常有用。

Zones allow administrators to define policies based on trust levels rather than individual interfaces. Common examples include:

區域允許管理員根據信任等級而不是單一介面來定義策略。常見的例子包括：

-   **Trust**: Secure internal networks  
    **信任**：安全的內部網絡
    
-   **Untrust**: External networks, such as the Internet  
    **不信任**：外部網絡，例如互聯網
    
-   **DMZ**: Public-facing services  
    **DMZ**：面向大眾的服務
    
-   **Guest**: Limited access for guest users  
    **訪客**：訪客使用者的存取權限有限
    

Tip

提示

For more details about constraints, refer to the [Firewall Groups](<134 [介面] 群組.md>) and [Processing Order](<137 規則.md#processing-order>) sections of the documentation.

有關約束的更多詳細信息，請參閱文檔的[防火牆組](<134 [介面] 群組.md>)和[處理順序](<137 規則.md#processing-order>)部分。

When a packet arrives at a firewall interface, it is assigned to a zone based on the inbound interface. This **packet tagging** process involves:

當封包到達防火牆介面時，它會根據入站介面被指派到一個區域。這個**資料包標記**過程涉及：

1.  Determining the receiving interface  
    確定接收介面
    
2.  Assigning the packet to the interface’s configured zone  
    將資料包指派到介面的配置區域
    
3.  Applying security policies between the source and destination zones  
    在來源區域和目標區域之間套用安全策略
    

| Zone (Interface Group)<br>區域（介面組） | Interfaces<br>介面 |
| --- | --- |
| **Trust**<br>**信任** | igc0, igc1, igc2<br>igc0、igc1、igc2 |
| **Untrust**<br>**不信任** | igc3, igc4<br>IGC3、IGC4 |

A packet arriving on igc0, igc1, or igc2 is tagged as **Trust**. If it needs to traverse to igc3 or igc4, tagged as **Untrust**, the firewall applies the relevant policies.

到達 igc0、igc1 或 igc2 的封包被標記為 **Trust**。如果需要遍歷到igc3或igc4，標記為**Untrust**，則防火牆套用相關策略。

Note

注意事項

-   Intrazone rules handle similar trust levels collectively, e.g., from Trust to Trust  
    區域內規則共同處理類似的信任級別，例如從信任到信任
    
-   Interzone rules define boundaries between areas with different trust levels, e.g., from Trust to Untrust  
    域間規則定義了不同信任等級的區域之間的邊界，例如從信任到不信任
    

## [Benefit of Zones](#id2)｜[專區福利](#id2)

Defining uniform policies between zones reduces the number of rules and the complexity of the ruleset. For example, allowing all networks in **Trust** to access HTTPS services in **Untrust** can be achieved with a single rule.

在區域之間定義統一的策略可以減少規則的數量和規則集的複雜性。例如，允許**Trust**中的所有網路存取**Untrust**中的HTTPS服務，可以透過單一規則來實現。

Without Zones (6 Rules):

無區域（6 條規則）：

-   Allow HTTPS from igc0 to igc3  
    允許 HTTPS 從 igc0 到 igc3
    
-   Allow HTTPS from igc0 to igc4  
    允許 HTTPS 從 igc0 到 igc4
    
-   Allow HTTPS from igc1 to igc3  
    允許 HTTPS 從 igc1 到 igc3
    
-   Allow HTTPS from igc1 to igc4  
    允許 HTTPS 從 igc1 到 igc4
    
-   Allow HTTPS from igc2 to igc3  
    允許 HTTPS 從 igc2 到 igc3
    
-   Allow HTTPS from igc2 to igc4  
    允許 HTTPS 從 igc2 到 igc4
    

With Zones (1 Rule):

有區域（1 條規則）：

-   Allow HTTPS from **Trust** to **Untrust**  
    允許HTTPS從**信任**到**不信任**
    

Additionally, a zone-based ruleset allows new interfaces to be added without requiring additional rules, reducing administrative overhead. This approach also enhances configuration clarity, simplifies troubleshooting, and streamlines audits.

此外，基於區域的規則集允許添加新接口，而無需額外的規則，從而減少了管理開銷。此方法還提高了配置清晰度、簡化故障排除並簡化審核。

Note

注意事項

Constraints may arise when using Multi-WAN configurations because the reply-to option does not apply to rules within interface groups.

使用 Multi-WAN 配置時可能會出現限制，因為回覆選項不適用於介面組內的規則。

## [Setup Overview](#id3)｜[設定概覽](#id3)

In our example setup, we will create a unified ruleset, leveraging interface groups as security trust zones.

在我們的範例設定中，我們將建立一個統一的規則集，並利用介面群組作為安全信任區域。

Our goals are the following zones:

我們的目標是以下區域：

| Zone<br>專區 | Interface<br>介面 | Description<br>描述 |
| --- | --- | --- |
| **TRUST** | igc0\_vlan1 to igc0\_vlan9<br>igc0\_vlan1 到 igc0\_vlan9 | Trusted internal networks like LAN<br>受信任的內部網絡，如 LAN |
| **UNTRUST** | igc0\_vlan10 to igc0\_vlan19<br>igc0\_vlan10 到 igc0\_vlan19 | Untrusted external networks like VPN, WAN, GUEST<br>VPN, WAN, GUEST 等不受信任的外部網路 |
| **WIFI** | igc0\_vlan20 to igc0\_vlan29<br>igc0\_vlan20 到 igc0\_vlan29 | Wireless networks with limited trust like WIFI<br>WIFI 等信任度有限的無線網路 |

Note

注意事項

When interfaces are assigned to devices, their default technical identifier is optX. For clarity, the description of each interface was changed to reflect their interface+vlan name. E.g., if the interface identifier is opt19, and the device is vlan0.19 with parent igc0, the description is igc0\_vlan19.

當介面分配給設備時，其預設技術標識符是 optX。為了清楚起見，每個介面的描述已更改以反映其介面+vlan 名稱。例如，如果介面識別碼為 opt19，且裝置為 vlan0.19，父級為 igc0，則描述為 igc0\_vlan19。

第一步是建立包含 VLAN 的介面組。這會將它們分組到相同的安全信任區域。

Tip

提示

Do not create too many zones, they should be defined as broadly as possible as they are the highest level of hierarchy.

不要創建太多區域，應盡可能廣泛地定義它們，因為它們是層次結構的最高層級。

The interfaces will be grouped together in Firewall ‣ Rules and Interfaces. When configuring the zone based ruleset, keep the firewall rule precedence in mind.

這些介面將在 Firewall ‣ Rules and Interfaces 中分組在一起。配置基於區域的規則集時，請記住防火牆規則的優先順序。

### [Verify Aliases](#id5)｜[驗證別名](#id5)

After creating the interface groups, we can check if the automatic aliases contain the expected content.

建立介面組後，我們可以檢查自動別名是否包含預期的內容。

-   Go to Firewall ‣ Diagnostics ‣ Aliases  
    轉到防火牆 ‣ 診斷 ‣ 別名
    

In the dropdown, choose TRUST net, UNTRUST net and WIFI net. Their corresponding IP networks will be displayed as they are automatically gathered from the configured interface IP addresses.

在下拉清單中，選擇TRUST網路、UNTRUST網路和WIFI網路。它們對應的IP網路將顯示，因為它們是從配置的介面IP位址自動收集的。

When using these aliases, all of these networks are automatically part of the firewall rule.

使用這些別名時，所有這些網路都會自動成為防火牆規則的一部分。

### [Create Security Zone Policies](#id6)｜[創建安全區策略](#id6)

Our ruleset will create a baseline that will always match on top-level. Afterwards, we can create more selective allow rules in the individual interface groups. The following policies give a short overview about zone based rules and their results.

我們的規則集將建立一個始終與頂層相符的基線。之後，我們可以在各個介面組中建立更具選擇性的允許規則。以下策略簡要概述了基於區域的規則及其結果。

Go to Firewall ‣ Rules, create these rules with any interface as selection.

前往 Firewall ‣ Rules，建立這些規則並選擇任何介面。

Tip

提示

With the multiselect feature in source and destination you can select multiple aliases per rule. Each alias represents the interface group created before. Each interface group represent a zone.

透過來源和目標中的多選功能，您可以為每個規則選擇多個別名。每個別名代表先前建立的介面組。每個介面組代表一個區域。

**Rule 1**

**規則 1**

-   Allow Trust, Untrust and Wifi to use ICMP between and inside all networks in their zones  
    允許 Trust、Untrust 和 Wifi 在其區域內的所有網路之間和內部使用 ICMP
    

|   |   |
| --- | --- |
| **Action**<br>**行動** | Pass<br>通行證 |
| **Quick**<br>**快** | `X` |
| **Interface**<br>**介面** | any<br>任何 |
| **Direction**<br>**方向** | in<br>在 |
| **TCP/IP Version**<br>**TCP/IP版本** | IPv4 |
| **Protocol**<br>**協議** | ICMP |
| **Source**<br>**來源** | `TRUST net, UNTRUST net, WIFI net` |
| **Source port**<br>**來源連接埠** | any<br>任何 |
| **Destination**<br>**目的地** | `TRUST net, UNTRUST net, WIFI net` |
| **Destination port**<br>**目的港** | any<br>任何 |
| **Description**<br>**描述** | Allow ICMP between TRUST, UNTRUST, WIFI<br>允許 ICMP 介於 TRUST, UNTRUST, WIFI |

Note

筆記

This single GUI rule will create a Cartesian product and result in nine firewall rules in pf(4). Be mindful using inversions in rules or inverted aliases, since they can be generated in an order that creates an unexpected result.

這個單一的 GUI 規則將創建笛卡爾積並導致 pf(4) 中的九個防火牆規則。請注意在規則中使用反轉或反轉別名，因為它們的生成順序可能會產生意外結果。

Attention

注意

This rule will also allow ICMP between all networks inside a zone, that means it is a mixed interzone and intrazone rule. Use these sparingly for broad diagnostic or administrative rules, as they overrule more selective policies that come later in the same ruleset.

此規則還允許區域內所有網路之間使用ICMP，這意味著它是混合的區域間和區域內規則。謹慎地將這些規則用於廣泛的診斷或管理規則，因為它們會否決同一規則集中稍後出現的更具選擇性的策略。

**Rule 2**

**規則2**

-   Allow Trust to access the other zones; excluding its own zone  
    允許 Trust 存取其他區域；不包括自己的區域
    

|   |   |
| --- | --- |
| **Action**<br>**行動** | Pass<br>通行證 |
| **Quick**<br>**快** | `X` |
| **Interface**<br>**介面** | any<br>任何 |
| **Direction**<br>**方向** | in<br>在 |
| **TCP/IP Version**<br>**TCP/IP版本** | IPv4 |
| **Protocol**<br>**協議** | any<br>任何 |
| **Source**<br>**來源** | `TRUST net` |
| **Source port**<br>**來源連接埠** | any<br>任何 |
| **Destination**<br>**目的地** | `UNTRUST net, WIFI net` |
| **Destination port**<br>**目的港** | any<br>任何 |
| **Description**<br>**描述** | Allow any from TRUST to UNTRUST, WIFI<br>允許從 TRUST 到 UNTRUST, WIFI |

Note

注意事項

This single GUI rule will result in two firewall rules in pf(4). It is a clean interzone rule, allowing Trust to Untrust and Wifi, but not the other way around.

這個 GUI 規則將導致 pf(4) 中出現兩條防火牆規則。這是一個乾淨的域間規則，允許信任到不信任和 Wifi，但反之則不然。

**Rule 3**

**規則3**

-   Allow Wifi to access Untrust  
    允許 Wifi 存取 Untrust
    

|   |   |
| --- | --- |
| **Action**<br>**行動** | Pass<br>通行證 |
| **Quick**<br>**快** | `X` |
| **Interface**<br>**介面** | any<br>任何 |
| **Direction**<br>**方向** | in<br>在 |
| **TCP/IP Version**<br>**TCP/IP版本** | IPv4 |
| **Protocol**<br>**協議** | any<br>任何 |
| **Source**<br>**來源** | `WIFI net` |
| **Source port**<br>**來源連接埠** | any<br>任何 |

| **Destination port**<br>**目的港** | any<br>任何 |
| **Description**<br>**描述** | Allow any from WIFI to UNTRUST<br>允許從 WIFI 到 UNTRUST |

### [Adding Additional Interfaces](#id7)｜[新增附加介面](#id7)

Now that the unified ruleset is established, new interfaces can be added without the need of duplicating firewall rules.

既然建立了統一的規則集，就可以新增新的接口，而無需重複防火牆規則。

If we expand the LAN network with more vlans that are on the same level of trust as the existing ones, we simply add the new interfaces to the TRUST interface group. All existing rules will automatically apply to any new member interfaces.

如果我們使用更多與現有 VLAN 具有相同信任等級的 VLAN 來擴展 LAN 網絡，我們只需將新介面新增至 TRUST 介面組即可。所有現有規則將自動套用於任何新成員介面。

Vice versa, if a network should become untrusted, we remove it from TRUST and add it to UNTRUST.

反之亦然，如果網路變得不可信，我們將其從 TRUST 中刪除並將其新增至 UNTRUST 中。

This makes administration and auditing the ruleset more efficient. Deployment of new firewalls or via central management is simplified.

這使得規則集的管理和審核更有效率。新防火牆的部署或透過中央管理的部署得到簡化。
