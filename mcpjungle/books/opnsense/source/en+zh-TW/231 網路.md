## Netmap (IPS, Sensei, …)｜Netmap（ IPS ，Sensei，…）

**General**

**一般的**

Netmap is a technology which enables fast packet processing while minimizing overhead, there are however some pitfalls which may turn your network interface unreachable.

Netmap 是一種能夠快速處理封包並最大限度地減少開銷的技術，但是它也存在一些缺陷，可能會導致您的網路介面無法存取。

Before using this technology, always make sure you have access via another interface (or console) to your firewall in case connectivity is dropped.

在使用此技術之前，請務必確保您可以透過另一個介面（或控制台）存取防火牆，以防連線中斷。

In order for netmap to function properly it is imperative that all sorts of driver / hardware acceleration is disabled (Interfaces -> Settings), this include `VLAN Hardware Filtering` as well (which wasn’t disabled pre 20.7).

為了使 netmap 正常運作，必須停用所有類型的驅動程式/硬體加速（介面 -> 設定），這包括`VLAN Hardware Filtering` （在20.7之前未停用）。

Some drivers have may have additional tunables, which enable hardware acceleration, make sure to disable them as well (.e.g intel ixl has `hw.ixl.enable_head_writeback`, which we disable by default)

某些驅動程式可能具有額外的可調參數，可以啟用硬體加速，請務必將其停用（例如，Intel IXL 有`hw.ixl.enable_head_writeback` ，我們預設為停用它）。

Below you will find a list of tunables which are know to be (partial) incompatible with netmap.

下面列出了已知與 netmap 部分不相容的可調參數。

| Tunable<br>可調 | Description<br>說明 |
| --- | --- |
| hw.ixl.enable\_head\_writeback | Intel `ixl(4)` tunable for increased tx performance, OPNsense standard value is disabled.<br>Intel `ixl(4)`可調參數以提高發送效能，OPNsense 標準值已停用。 |
| dev.ax.<interface number>.sph\_enable<br>dev.ax. <interface number> .sph\_enable | AMD tunable to split header and payload into a separate buffer respectively, Netmap requires a uniform view of a packet. Disabled by default on OPNsense.<br>AMD可調參數，用於將頭部和有效載荷分別拆分到單獨的緩衝區中。 Netmap 要求對封包具有統一的視圖。在 OPNsense 中預設為停用。 |

**Decoupling Netmap from an application**

**將 Netmap 與應用程式解耦**

It can be useful to split the functionality of Netmap and the application using it in order to determine whether it’s Netmap or the application at fault for connectivity issues. To aid in this, Netmap’s `bridge` utility has been added to our pkg repository for easy installation and use. To avoid ambiguity, it has been renamed to `netmap-bridge`.

將 Netmap 的功能與使用它的應用程式的功能分開，有助於確定連接問題是由 Netmap 本身還是應用程式引起的。為了方便使用者進行此操作，我們已將 Netmap 的`bridge`工具新增到我們的軟體套件倉庫中，以便於安裝和使用。為避免歧義，該工具已重新命名為`netmap-bridge` 。

You can install it by running `pkg install netmap-bridge` (`man netmap-bridge`).

您可以透過運行`pkg install netmap-bridge` ( `man netmap-bridge` ) 來安裝它。

`netmap-bridge` provides a L2 software bridge between two interfaces, but can also be used to bridge an interface and the host network stack like Suricata does. To replicate the behaviour of Suricata without actually running Suricata, run `netmap-bridge -i netmap:igb1`. Replace the interface as appropriate. While it is running, pass traffic as normal to determine if an original issue persists.

`netmap-bridge`提供兩個介面之間的二層軟體橋接，但也可以像 Suricata 一樣，用於橋接介面和主機網路協定棧。若要在不實際運行 Suricata 的情況下復現其行為，請運行`netmap-bridge -i netmap:igb1` 。根據需要替換接口。運行期間，正常傳輸流量以確定原始問題是否仍然存在。

## Common error codes｜常見錯誤代碼

Any piece of software that uses system calls to communicate over sockets use the standard interface [errno.h](https://github.com/opnsense/src/blob/master/sys/sys/errno.h) (`man errno`). If an error is logged, a return code is associated to a specific reason of failure. Some common ones are explained below:

任何使用系統呼叫透過套接字進行通訊的軟體都使用標準介面 [errno.h](https://github.com/opnsense/src/blob/master/sys/sys/errno.h) ( `man errno` )。如果記錄了錯誤，則會將回傳碼與特定的故障原因關聯起來。以下解釋了一些常見的故障原因：

| XX | Name<br>名稱 | Description<br>描述 |
| --- | --- | --- |
| 55 | ENOBUFS<br>55 ENOBUFS | No buffer space available. An operation on a socket or pipe was not performed because the system lacked sufficient buffer space or because a queue was full. **Check connectivity from the machine itself using** `ping`, most common mistakes are misconfigured routes, interface issues (disconnected) and policy based routing issues forcing traffic to the wrong target (using `reply-to`)<br>沒有可用的緩衝空間。由於系統缺乏足夠的緩衝區空間或佇列已滿，因此未執行套接字或管道上的操作。 **使用** `ping`檢查機器本身的連接，最常見的錯誤是路由配置錯誤、接口問題（斷開連接）和基於策略的路由問題迫使流量流向錯誤的目標（使用`reply-to`） |
| 64 | EHOSTDOWN | Host is down. A socket operation failed because the destination host was down. **Expecting an (layer 2) ARP response but none was returned, often misconfigured subnets or hosts are actually not accessible over L2**<br>主機已關閉。套接字操作失敗，因為目標主機已關閉。 **預期收到（二層） ARP回應，但未收到任何回應，通常是由於子網路設定錯誤或主機實際上無法透過二層存取。** |
| 65 | EHOSTUNREACH | No route to host. A socket operation was attempted to an unreachable host **The routing table is a good place to look** (System ‣ Routes ‣ Status)<br>無法連接到主機。嘗試對無法存取的主機執行套接字操作。 **路由表是一個很好的查找位置**（系統 ‣ 路由 ‣ 狀態） |
