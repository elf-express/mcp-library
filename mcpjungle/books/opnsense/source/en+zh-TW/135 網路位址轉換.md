Network Address Translation (abbreviated to NAT) is a way to separate external and internal networks (WANs and LANs), and to share an external IP between clients on the internal network. NAT can be used on IPv4 and IPv6.

網路位址轉換（縮寫為NAT）是一種分離外部和內部網路（WAN 和 LAN）並在內部網路上的用戶端之間共用外部IP的方法。 NAT 可在 IPv4 和 IPv6 上使用。

Most of the options below use three different addresses: the source, destination and redirect address. These addresses are used for the following:

下面的大多數選項使用三個不同的位址：來源位址、目標位址和重定向位址。這些地址用於以下用途：

|   |   |
| --- | --- |
| Source<br>來源 | Where the traffic comes from. This can often be left on “any”.<br>流量從哪裡來。這通常可以保留在“any”上。 |
| Destination<br>目的地 | Where the traffic is headed. For incoming traffic from outside, this is usually your external IP address.<br>交通流向何處。對於來自外部的傳入流量，這通常是您的外部 IP 位址。 |
| Redirect<br>重定向 | Where the traffic should be redirected.<br>流量應該重定向到哪裡。 |

Warning

警告

-   Network Address Translation should not be relied upon as a security measure.  
    不應依賴網路位址轉換作為安全措施。
    
-   Disabling pf will also disable NAT.  
    禁用 pf 也會停用 NAT。
    

## [Some terms explained](#id2)｜[部分術語解釋](#id2)

**BINAT**: NAT generally works in one direction. However, if you have networks of equal size, you can also use BINAT, which is bidirectional. This can simplify your set-up. If you don’t have networks of equal size, you can only use regular NAT.

**BINAT**：NAT一般作用於一個方向。但是，如果您的網路大小相同，您也可以使用BINAT，它是雙向的。這可以簡化您的設定。如果你沒有同等規模的網絡，你只能使用常規的NAT。

**NAT reflection**: When a client on the internal network tries to access another client, but using the *external* IP instead of the internal one (which would the most logical), NAT reflection can rewrite this request so that it uses the internal IP, in order to avoid taking a detour and applying rules meant for actual outside traffic.

**NAT反射**：當內部網路上的客戶端嘗試存取另一個客戶端，但使用*外部*IP而不是內部（這是最合乎邏輯的）時，NAT反射可以重寫此請求，以便它使用內部IP，以避免繞道並應用針對實際外部流量的規則。

Tip

提示

There is a how-to section explaining [NAT Reflection](<136 倒影與髮夾NAT.md>) in detail.

有一個操作方法部分詳細解釋了[NAT反射](<136 倒影與髮夾NAT.md>)。

Note

注意事項

The NAT rules generated with enabling **NAT reflection** only include networks directly connected to your Firewall. This means if you have a private network separated from your LAN you need to add this with a manual Source NAT (Outbound) rule.

啟用 **NAT 反射** 產生的 NAT 規則僅包含直接連接到您的防火牆的網路。這意味著，如果您有一個與 LAN 分離的專用網絡，則需要使用手動來源 NAT（出站）規則來新增此網路。

**Pool options**: When there are multiple IPs to choose from, this option will allow regulating which IP gets used. The default, Round Robin, will simply distribute packets to one server after the other. If you only have one external IP, this option has no effect.

**池選項**：當有多個 IP 可供選擇時，此選項將允許調整使用哪一個 IP。預設情況下，循環法將簡單地將資料包分發到一台伺服器到另一台伺服器。如果您只有一個外部IP，則此選項無效。

## [Destination NAT (Port Forward)](#id3)｜[目的地NAT（港口轉送）](#id3)

When multiple internal clients share one external IP address, any inbound connection targeting the external IP address will not succeed, since the firewall will not know where to send the traffic. This can be addressed by creating port forwarding rules. For example, for a web server behind the firewall to be accessible, ports 80 and 443 need to be redirected to it.

當多個內部用戶端共用一個外部IP位址時，任何針對外部IP位址的入站連線都不會成功，因為防火牆不知道將流量傳送到哪裡。這可以透過建立連接埠轉送規則來解決。例如，要存取防火牆後面的 Web 伺服器，需要將連接埠 80 和 443 重新導向到該伺服器。

Destination NAT (Port Forward) can be set up by navigating to Firewall ‣ NAT ‣ Destination NAT (Port Forward). Here, you will see an overview of Destination NAT (Port Forward) rules.

可以透過導覽到防火牆‣NAT‣目標NAT（連接埠轉送）來設定目標NAT（連接埠轉送）。在這裡，您將看到目的地NAT（連接埠轉送）規則的概述。

## [One-to-one](#id5)｜[一對一](#id5)

One-to-one NAT will translate two IPs one-to-one, rather than one-to-many as is most common in other NAT types. In this respect, it is similar to what NPT does for IPv6.

一對一 NAT 會將兩個 IP 一對一轉換，而不是像其他 NAT 類型中最常見的一對多轉換。在這方面，它類似於NPT對IPv6的作用。

One-to-one NAT can be set up by navigating to Firewall ‣ NAT ‣ One-to-one.

## [Source NAT (Outbound)](#id6)｜[來源NAT（出站）](#id6)

When a client on an internal network makes an outbound request, the gateway will have to change the source IP to the external IP of the gateway, since the outside server will not be able to send an answer back otherwise.

當內部網路上的用戶端發出出站請求時，網關必須將來源IP更改為網關的外部IP，因為否則外部伺服器將無法發送回應。

Source NAT (Outbound), abbreviated to SNAT, can be configured under Firewall ‣ NAT ‣ Source NAT (Outbound).

源NAT（出站），縮寫為SNAT，可在防火牆‣NAT‣源NAT（出站）下配置。

If you only have one external IP, the automatic mode is suitable in most cases. With multiple external addresses, you may want to use hybrid or manual mode and add custom rules.

如果您只有一台外接IP，大多數情況下自動模式就適合。對於多個外部位址，您可能需要使用混合或手動模式並新增自訂規則。

|   |   |
| --- | --- |
| Automatic Source NAT rule generation<br>自動源NAT規則產生 | The default. Follows the behaviour described above, and is suitable for most scenarios.<br>預設。遵循上述行為，適用於大多數場景。 |
| Manual Source NAT rule generation<br>手動源NAT規則生成 | No automatic rules are generated. They can be added manually.<br>不產生自動規則。它們可以手動添加。 |
| Hybrid Source NAT rule generation<br>混合源NAT規則產生 | Automatic rules are generated, and additional manual rules can be added.<br>自動產生規則，並且可以新增其他手動規則。 |
| Disable Source NAT rule generation<br>禁用來源NAT規則產生 | Disables Source NAT. This is used for [transparent bridges](<118 透明過濾橋.md>), for example.<br>禁用來源NAT。例如，這用於[透明橋](<118 透明過濾橋.md>)。 |

## [NPTv6](#id7)

Network Prefix Translation, shortened to NPTv6, is used to translate IPv6 addresses. A common usage for this is to translate global (“WAN”（VAN）) IPs to local ones. In this regard, it is similar to NAT, although NPTv6 can only be used to map addresses one-to-one, unlike NAT which typically translates one external IP to several internal ones.

網路前綴轉換，縮寫為 NPTv6，用於轉換 IPv6 位址。常見用法是將全域 (“WAN”（VAN）) IP 轉換為本機 IP。在這方面，它與NAT類似，儘管NPTv6只能用於一對一映射地址，而不像NAT通常將一個外部IP轉換為多個內部地址。

NPTv6 routes are listed at Firewall ‣ NAT ‣ NPTv6.

NPTv6 路由在防火牆 ‣ NAT ‣ NPTv6 中列出。
