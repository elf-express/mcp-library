# Monit｜迅速的

> 章節：[Services](<000 目錄.md#c-40>)

OPNsense uses Monit for monitoring services. Monit has quite extensive monitoring capabilities, which is why the configuration options are extensive as well. This guide will do a quick walk through the setup, with the configuration options explained in more detail afterwards, along with some caveats.

OPNsense 使用 Monit 進行服務監控。 Monit 擁有非常強大的監控功能，因此其配置選項也十分豐富。本指南將簡要介紹設定過程，並在之後詳細解釋配置選項以及一些注意事項。

## Global setup｜全域設定

Navigate to Services ‣ Monit ‣ Settings. On the “General Settings”（常規設定） tab, turn on Monit and fill in the details of your SMTP server. Save the changes. Then, navigate to the “Alert settings” and add one for your e-mail address. If your mail server requires the “From”（從） field to be properly set, enter `From: sender@example.com` in the “Mail format” field. Save the alert and apply the changes.

導覽至「服務」‣「監控」‣「設定」。在“General Settings”（常規設定）選項卡中，啟用監控功能並填寫您的SMTP伺服器詳細資料。儲存更改。然後，導航至「警報設定」並新增一個用於您的電子郵件地址的警報。如果您的郵件伺服器要求正確設定“From”（從）字段，請在「郵件格式」欄位中輸​​入`From: sender@example.com` 。儲存警報並套用變更。

## Adding an alert｜添加警報

First, you have to decide what you want to monitor and what constitutes a failure. It helps if you have some knowledge about how Monit alerts are set up. This is described in the [Monit documentation](https://mmonit.com/monit/documentation/monit.html#ALERT-MESSAGES).

首先，您需要確定要監控的內容以及故障的定義。如果您了解 Monit 警報的設定方法，將會很有幫助。這在 [Monit 文件](https://mmonit.com/monit/documentation/monit.html#ALERT-MESSAGES)中有詳細說明。

If you have done that, you have to add the condition first. Navigate to the ‘Service Test Settings’ tab and look if the condition you want to add already exists. If it doesn’t, click the + button to add it.

如果已經完成上述步驟，則必須先新增條件。導覽至「服務測試設定」標籤，查看要新增的條件是否已存在。如果不存在，請按一下“+”按鈕新增。

Now navigate to the ‘Service Test’ tab and click the + icon. In the dialog, you can now add your service test. If you’re done, save it, then apply the changes.

現在導航至“服務測試”選項卡，然後按一下“+”圖示。在彈出的對話方塊中，您現在可以新增服務測試。完成後，儲存並套用變更。

The fields in the dialogs are described in more detail in the “Settings overview” section of this document.

本文檔的「設定概述」部分對對話方塊中的各個欄位進行了更詳細的描述。

## Example 1｜例 1

In this example, we’ll add a service to restart the FTP proxy (running on port 8021) if it has stopped. To avoid an eternal loop in case something is wrong, we’ll also add a provision to stop trying if the FTP proxy has had to be restarted five times in a row.

在這個例子中，我們將添加一項服務，用於在FTP代理（運行在8021端口）停止運行時重啟它。為了避免故障時陷入無限循環，我們還將添加一項機制，如果FTP代理連續重啟了五次，則停止嘗試重啟。

First, make sure you have followed the steps under “Global setup”. Then, navigate to the “Service Tests Settings”（服務測試設置） tab. Here, you need to add two tests:

首先，請確保您已按照「全域設定」下的步驟操作。然後，導覽至“Service Tests Settings”（服務測試設置）選項卡。在這裡，您需要添加兩個測試：

| Setting<br>設定 | Value<br>值 |
| --- | --- |
| Name<br>姓名 | FTPProxy8021 |
| Condition<br>條件 | failed host 127.0.0.1 port 8021 type tcp<br>失敗主機127.0.0.1埠 8021 類型 tcp |
| Action<br>操作 | Restart<br>重啟 |

| Setting<br>設定 | Value<br>值 |
| --- | --- |
| Name<br>名稱 | RestartLimit5<br>重啟限制5 |
| Condition<br>條件 | 5 restarts within 5 cycles<br>5 個週期內重啟 5 次 |
| Action<br>操作 | Unmonitor<br>取消監控 |

Now, navigate to the “Service Settings”（服務設定） tab. Here, add the following service:

現在，導覽至“Service Settings”（服務設定）選項卡。在此處，新增以下服務：

| Setting<br>設定 | Value<br>值 |
| --- | --- |
| Name<br>姓名 | FTPProxy8021 |
| Type<br>類型 | Process<br>流程 |
| PID File<br>PID檔 | /var/run/osftpproxy.127\_0\_0\_1\_8021.pid |
| Start<br>開始 | /usr/local/sbin/configctl ftpproxy start 127\_0\_0\_1\_8021 |
| Stop<br>停止 | /usr/local/sbin/configctl ftpproxy stop 127\_0\_0\_1\_8021 |
| Tests<br>測試 | FTPProxy8021, RestartLimit5<br>FTPProxy8021，RestartLimit5 |

Save and apply.

保存併申請。

## Advanced Configurations｜進階配置

Some installations require configuration settings that are not accessible in the UI. To support these, individual configuration files with a `.conf` extension can be put into the `/usr/local/etc/monit.opnsense.d` directory. These files will be automatically included by the UI generated configuration. Multiple configuration files can be placed there. But note that

某些安裝需要一些在UI目錄下無法存取的設定。為了支援這些設置，可以將擴展名為`.conf`單獨設定檔放入`/usr/local/etc/monit.opnsense.d`目錄。這些檔案將會被UI產生的設定自動包含。可以在此放置多個設定檔。但請注意：

-   The wildcard include processing in Monit is based on `glob(7)`. So the order in which the files are included is in ascending ASCII order.  
    Monit 中的通配符包含處理基於`glob(7)` 。因此，文件的包含順序是按升序ASCII順序排列的。
    
-   Monit supports up to 1024 include files. If this limit is exceeded, Monit will report an error.  
    Monit 最多支援 1024 個包含檔案。如果超過此限制，Monit 將報告錯誤。
    
-   It makes sense to check if the configuration file is valid. You can do so by using the following command:  
    檢查設定檔是否有效是明智之舉。您可以使用以下命令進行檢查：
    
    ```
    # Run syntax check for the control file
    configctl monit check
    ```
    

This is a sample configuration file to customize the limits of the Monit daemon:

這是一個用於自訂 Monit 守護程式限制的範例設定檔：

```
## Set limits for various tests. The following example shows the default values:
##
set limits {
     programOutput:     5120 B,      # check program's output truncate limit
#     sendExpectBuffer:  256 B,      # limit for send/expect protocol test
     fileContentBuffer: 5120 B,      # limit for file content test
#     httpContentBuffer: 1 MB,       # limit for HTTP content test
#     networkTimeout:    5 seconds   # timeout for network I/O
#     programTimeout:    300 seconds # timeout for check program
#     stopTimeout:       30 seconds  # timeout for service stop
#     startTimeout:      120 seconds  # timeout for service start
#     restartTimeout:    30 seconds  # timeout for service restart
}
```

警告

管理員有責任將檔案放置在擴充目錄中，以確保配置有效。
