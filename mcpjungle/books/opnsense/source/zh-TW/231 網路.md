# 網路

> 章節：[Troubleshooting](<000 目錄.md#c-50>) › [Topics](<000 目錄.md#c-51>)

## 網路圖（IPS，老師，...）

**一般**

Netmap 是一種能夠快速處理封包同時最大限度地減少開銷的技術，但是存在一些缺陷，可能會導致您的網路介面無法存取。

在使用此技術之前，請務必確保您可以透過另一個介面（或控制台）存取防火牆，以防連線中斷。

為了使 netmap 正常運作，必須停用所有類型的驅動程式/硬體加速（介面 -> 設定），這也包括 `VLAN Hardware Filtering`（在 20.7 之前未停用）。

某些驅動程式可能有額外的可調參數，可啟用硬體加速，請確保也停用它們（例如 intel ixl 有 `hw.ixl.enable_head_writeback`，我們預設為停用它）

您將在下面找到已知與網路映射（部分）不相容的可調參數清單。

|可調|描述 |
| --- | --- |
| hw.ixl.enable\_head\_writeback | Intel `ixl(4)` 可調式以提高 tx 效能，OPNsense 標準值已停用。 |
| dev.ax.<interface number>.sph\_enable | AMD 可調整以將標頭和有效負載分別分割到單獨的緩衝區中，Netmap 需要封包的統一視圖。 OPNsense 上預設為停用。 |

**將 Netmap 與應用程式解耦**

拆分 Netmap 和使用它的應用程式的功能非常有用，以便確定是 Netmap 還是應用程式出現連接問題。為此，Netmap 的 `bridge` 實用程式已新增至我們的 pkg 儲存庫中，以便於安裝和使用。為了避免歧義，它已重新命名為`netmap-bridge`。

您可以透過運行`pkg install netmap-bridge`（`man netmap-bridge`）來安裝它。

`netmap-bridge` 提供兩個介面之間的 L2 軟體橋接，但也可以像 Suricata 一樣用於橋接介面和主機網路堆疊。要在不實際運行 Suricata 的情況下複製 Suricata 的行為，請運行 `netmap-bridge -i netmap:igb1`。根據需要更換接口。當它運行時，正常傳遞流量以確定原始問題是否仍然存在。

## 常見錯誤代碼

任何使用系統呼叫透過套接字進行通訊的軟體都使用標準介面 [errno.h](https://github.com/opnsense/src/blob/master/sys/sys/errno.h) (`man errno`)。如果記錄了錯誤，則傳回代碼會與特定的失敗原因相關聯。一些常見的解釋如下：

| XX |名稱 |描述 |
| --- | --- | --- |
| 55 | 55 ENOBUFS |沒有可用的緩衝空間。由於系統缺乏足夠的緩衝區空間或佇列已滿，因此未執行套接字或管道上的操作。 **使用** `ping`檢查機器本身的連接，最常見的錯誤是路由配置錯誤、接口問題（斷開連接）和基於策略的路由問題迫使流量流向錯誤的目標（使用`reply-to`）|
| 64 | 64 E主機下載|樓主掛了。由於目標主機已關閉，套接字操作失敗。 **期待（第 2 層）ARP 回應，但沒有返回，通常配置錯誤的子網路或主機實際上無法透過 L2 存取** |
| 65 | 65 EHOSTUNRACH |沒有到主機的路由。嘗試對無法存取的主機進行套接字操作 **路由表是一個很好的查找位置** (系統 ‣ 路由 ‣ 狀態) |
