# 系統強化與性能

> 章節：[Troubleshooting](<000 目錄.md#c-50>) › [Topics](<000 目錄.md#c-51>)

預設情況下，OPNsense 傾向於選擇更嚴格的增強選項，因此在比較上游標準 FreeBSD 之間的性能時，最好了解哪些設定不同並且可能對您的測量產生影響。本文檔旨在描述（部分）差異，因此當您重視效能而不是安全性時，哪些切換可能值得更改會更加明顯。

請記住，大多數設定都需要重新啟動，並且可以使用 System ‣ Settings ‣ Tunables 中的系統可調參數進行變更。

## IPv4 隨機ID的\[net.inet.ip.random\_id\]

控制IP(v4) ID 生成行為。這消除了一個較小的資訊洩漏，允許遠端觀察者透過觀察計數器來確定機器上資料包產生的速率。同時，在高速鏈路上，可以大幅降低ID的複用週期。 IPv6 流 ID 和片段 ID 總是隨機的。 （來源`man -S 4 inet`）

我們的預設值為 1（啟用）。

## 幽靈與崩潰

為了緩解某些推測執行漏洞，FreeBSD 中提供了一些設定。有關各種漏洞和相關補丁的更多資訊可以在[此處](https://wiki.freebsd.org/SpeculativeExecutionVulnerabilities)找到

使用頁表隔離 (PTI) 來緩解崩潰，雖然在 FreeBSD 中也啟用了，但值得一提的是哪個設定負責啟用此功能。若要停用 PTI，請將 `vm.pmap.pti` 設定為 0。並非所有 cpu 都容易受到 Meltdown 的影響，在這種情況下，可以安全地停用 PTI。

Spectre 變體 2，該系統在 Intel CPU 上提供基於 IBRS 的緩解措施。 IBRS 緩解措施的主要缺點是顯著的性能損失。在 OPNsense 中，預設會透過停用 (0) `hw.ibrs_disable` 來啟用IBRS（對於 Intel），上游 FreeBSD 標準被停用 (1)。

## 使用者/群組分離（security.bsd）

Freebsd 提供了一些開關來加強普通用戶的安全性，這些可能不會對效能產生太大影響，但這些包括與我們端不同的描述（來源`sysctl -d security.bsd`）。

|設定|描述 |
| --- | --- |
| security.bsd.hardlink\_check\_gid \[0->1\] |非特權程序無法建立到其他群組擁有的檔案的硬連結 |
| security.bsd.hardlink\_check\_uid \[0->1\] |非特權程序無法建立指向其他使用者擁有的檔案的硬連結 |
| security.bsd.unprivileged\_proc\_debug \[1->0\] |非特權程序可以使用行程偵錯工具 |
| security.bsd.see\_other\_gids \[1->0\] |非特權程序可能會看到具有不同真實 gid 的主體/物件 |
| security.bsd.see\_other\_uids \[1->0\] |非特權程序可能會看到具有不同真實 uid 的主體/物件 |
| security.bsd.unprivileged\_read\_msgbuf \[1->0\] |非特權程序可能會讀取內核訊息緩衝區 |
