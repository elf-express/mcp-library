作為 OPNsense 商業版的一部分，Deciso 提供了一個插件，可以輕鬆保護 Web 服務免受各種注入攻擊，並為進出外部世界的流量提供加密。

我們的 Web 應用程式防火牆插件提供了一些功能，這些功能也可以在可用的社群插件中找到，但以更用戶友好的方式提供。它結合了[反向代理](https://en.wikipedia.org/wiki/Reverse_proxy)中最常用的功能，例如TLS卸載和負載平衡。

為了簡化維護，`OPNWAF`插件提供內部證書的使用或透過[Let’s Encrypt](https://letsencrypt.org/)使用ACME協議新產生的證書，只需單擊即可。

## [前提條件](#id5)

在將此插件與 Let’s Encrypt 結合使用之前，請確保連接埠 443 未用於此防火牆的 Web GUI（系統 -> 設定 -> 管理）。

注意事項

使用 Let’s Encrypt 時，Web 應用程式防火牆使用 tls-alpn-01 質詢類型來輕鬆進行網域驗證，這要求虛擬伺服器偵聽連接埠 443。確保防火牆允許連接埠 443 上的傳入 HTTPS 連線。如果用戶端透過自訂連接埠連接，您可以將這些請求轉送至連接埠 443，並設定虛擬伺服器將這些請求轉送至正確的內部連接埠。

## [安裝](#id6)

要安裝此插件，請前往系統 ‣ 韌體 ‣ 插件並搜尋 **os-OPNWAF**，\[+\] 按鈕下載並安裝軟體。

接下來前往 Firewall ‣ Web Application ‣ Settings 來啟用它。

## [一般](#id7)

在深入研究設定頁面之前，我們將解釋本模組中使用的最重要的術語。

### [虛擬伺服器](#id8)

虛擬伺服器（也稱為虛擬主機）是一個允許使用相同連接埠在單一網路伺服器上使用多個網域的概念。在我們的例子中，它提供了在網路內託管各種網站伺服器並以安全的方式將流量轉發給它們的可能性。

### [地點](#id9)

位置駐留在虛擬伺服器中，並在路徑層級描述如何處理請求，例如，如果只想將子目錄（如`/api`）轉送到網路中的伺服器，則位置是配置它的位置。

### [網頁保護](#id10)

Web 保護選項可以輕鬆存取 [OWASP ModSecurity 規則集](https://owasp.org/www-project-modsecurity-core-rule-set/)，它提供了一組針對廣泛攻擊的通用攻擊偵測規則，包括 [OWASP 十大](https://owasp.org/www-project-top-ten/)。

## [設定](#id11)

在設定虛擬伺服器之前，我們先來看看常規設定頁面（防火牆 ‣ Web 應用程式 ‣ 設定）。安裝後，模組本身應預設為啟用。

為了使用整合的ACME客戶端（用於Let’s Encrypt），需要設定ACME啟用複選框，需要接受憑證協定（下一個複選框）並需要指定聯絡電子郵件。

（可選）可以為所有虛擬伺服器啟用從 HTTP 到 HTTPS 的永久重定向。如有必要，可以透過啟用進階模式來自訂HTTP連接埠。不要忘記建立額外的防火牆規則以允許存取 HTTP 連接埠。當它是非標準時，需要連接埠轉送（例如，偵聽 8080，將 80 轉送到 8080）。

[![../../_images/OPNWAF_settings.png](<../images/5867ae21-OPNWAF_settings.png>)](https://docs.opnsense.org/_images/OPNWAF_settings.png)

預設未啟用 Web 保護，但您可以在「Web 保護」標籤中啟用它。這也是配置適用於所有虛擬主機的模組和設定的地方。

若要選擇配置預設的包羅萬象的虛擬伺服器，請在防火牆 ‣ Web 應用程式 ‣ 設定中選擇嚴格SNI 檢查的憑證。此憑證可以是自簽署的並與預設伺服器名稱的CN相符。現在將向任何無效的SNI提供錯誤文檔。如果為基域定義了通配符 A 記錄（例如，`*.example.com in A 203.0.113.1`），則每個子域都將由第一個配置的虛擬伺服器應答，即使SNI 與其不符。

上面的部分定義了虛擬伺服器將偵聽的連接埠。請記住，為了使用ACME（讓我們加密），這應該是 443，或者流量應從連接埠 443 轉送到此處定義的連接埠。

注意事項

連接埠號碼可以重複使用。多個虛擬伺服器可以共用相同連接埠。主機名稱必須是唯一的。它們用於透過SNI（伺服器名稱指示）來識別虛擬伺服器。

警告

ALPN 協定（Let’s Encrypt 使用的質詢類型）會將虛擬主機條目中指定的 FQDN 解析為防火牆的 IP 位址。如果您的 DNS 記錄同時指向 IPv4 和 IPv6 位址，則挑戰將首選 IPv6，因此如果是這種情況，請確保您的防火牆也可透過 IPv6 存取。

透過系統信任儲存手動提供憑證時，您也可以在此對話方塊中指派它。

### [配置位置](#id15)

除了提供禁止存取的頁面之外，虛擬伺服器本身不會向使用者提供太多內容，因此下一步是將目錄對應到外部位置。這些可以在虛擬伺服器下方的位置網格中定義。

有不同類型的位置：

1.  代理通行證，反向代理HTTP流量
    
2.  代理傳遞匹配，反向代理 HTTP 流量，但具有正規表示式支援
    
3.  重定向，建立 HTTP 重定向
    
4.  重定向匹配，建立 HTTP 重定向，但具有正規表示式支持
    
5.  Exchange Server，Microsoft Exchange 伺服器的模板

#### [代理通行證匹配](#id17)

代理傳遞匹配類型是代理傳遞的高級替代方案。

選擇它將本機路徑欄位轉變為位置匹配，並將新的遠端路徑欄位轉變為代理通道匹配。

這些類型可讓您根據正規表示式模式（而不僅僅是文字路徑）來匹配請求。

匹配被輸入到本機路徑中，並且可以在遠端路徑中設定替換組。

下面是一個範例：

|選項|說明 |
| --- | --- |
|本地路徑| `^/manual/(.*)$` |
|遠端路徑| `/$1` |

提示

-   `^`：匹配URL路徑的開始
    
-   `/manual/`：匹配文字字串/manual/
    
-   `(.*)`：捕捉 /manual/ 之後的任何字元（零個或多個）－這是群組 1
    
-   `$`：匹配字串末尾
    
-   `$1`：從本地路徑引用捕獲的群組。在此範例中，它在內部從 URL 路徑中剝離 /manual/。
    

注意

這是針對邊緣情況的高級功能，例如從請求中剝離路徑以形成新的基本路徑，或精確錨定路徑。它還可用於防止附加尾部斜杠，這會破壞某些 URL 參數方案。在大多數情況下，使用普通的代理通行證將自動為您提供所需的結果。

#### [重定向匹配](#id19)

重定向匹配類型是重定向的高級替代類型。

選擇它將本機路徑欄位轉變為位置匹配，將遠端目標欄位轉變為重定向匹配。

將重定向包裝到某個位置的行為與使用代理傳遞執行的操作略有不同，因為正規表示式群組無法傳遞到該位置。

預期的方法是使用環境變數。請參閱 [mod\_alias](https://httpd.apache.org/docs/current/mod/mod_alias.html) 以了解更多資訊。

下面是一個範例：

|選項|說明 |
| --- | --- |
|本地路徑| `/error/(?<NUMBER>[0-9]+)` |
|遠程目的地 | `http://example.com/errors/%{env:MATCH_NUMBER}.html` |

提示

使用普通重定向時，一個常見的陷阱是由於 apache 尾部斜杠問題而導致無限重定向。這可以透過重定向匹配來解決，方法是將本地路徑設定為`^/?$`，強制從第一個找到的斜杠的開頭進行匹配。

注意

在大多數情況下，使用普通重定向將自動為您提供所需的結果。

##### [前提條件](#id21)

要成功反向代理程式 Exchange Server，必須滿足一些條件：

-   Apache 和 Exchange Server 之間的通訊必須透過 HTTPS 進行。
    
-   Exchange Server 必須正確設定其內部和外部 URL，最好設定為將設定為虛擬伺服器的相同主機名稱。
    

常見的主機名稱/路徑組合有：

|虛擬目錄| Exchange Server 的內部與外部URL |
| --- | --- |
| Owa 虛擬目錄 | `mail.example.com/owa` |
| Ecp 虛擬目錄 | `mail.example.com/ecp` |
| Web 服務虛擬目錄 | `mail.example.com/EWS/Exchange.asmx` |
| ActiveSync 虛擬目錄 | `mail.example.com/Microsoft-Server-ActiveSync` |
| Oab 虛擬目錄 | `mail.example.com/OAB` |
| Mapi虛擬目錄 | `mail.example.com/mapi` |
| OutlookAnywhere | `mail.example.com/rpc` -ExternalClientAuthenticationMethod 設定為「協商」|
|客戶存取服務| `autodiscover.example.com/Autodiscover/Autodiscover.xml` |

使用自簽名憑證時，必須在「系統」->「信任」->「權限」中匯入該憑證的權限。證書的 SAN 中必須包含 `mail.example.com` 和 `autodiscover.example.com`。如果 OPNsense 和 Exchange Server 之間沒有建立信任，連線將會失敗，因為只允許與 Exchange Server 進行加密連線。

注意

Exchange Server 使用稱為「擴充保護」的功能，該功能要求 Web 應用程式防火牆和 Exchange Server 本身使用相同的憑證。

注意

由於 NTML 協定的棄用，透過 RCP/HTTP 或 MAPI/HTTP 的 Outlook 直通變得更具挑戰性。如果出現身份驗證彈出窗口，將「多處理模組」設為「mpm-prefork」會有所幫助。緩解所有身份驗證問題可能不再可能，因為所需的 NTLM 替換協定 OAuth 僅適用於 Exchange Online。

##### [設定](#id22)

### [測試網頁防護](#id23)

啟用網路保護後，我們始終建議測試它是否真正起作用。幸運的是，使用網頁瀏覽器進行測試非常容易。對於這個例子，我們將嘗試在 url 中註入一些 sql 程式碼，正確配置後應該會阻止這些程式碼：

`https://your.example.domain/?id=100 or 'x'='y'`

這應該會顯示類似於以下頁面的頁面：

[![../../_images/OPNWAF_forbidden.png](<../images/cab04b47-OPNWAF_forbidden.png>)](https://docs.opnsense.org/_images/OPNWAF_forbidden.png)

為虛擬伺服器部署 Web 保護時，請從可為每個虛擬伺服器設定的「僅偵測」設定開始。這樣，您可以評估網路安全日誌文件，並尋找符合的規則。

這將揭示 Web 應用程式是否可能已過時並需要修補，因為多個 Web 保護規則匹配並會阻止連線。

如果是誤報，則可以使用ID選項停用安全規則將規則 ID 設定為豁免。在下拉清單中搜尋規則，然後選擇要排除的多個規則。

完成此配置後，將 Web 保護設為開啟（預設）以啟用它。現在應該配置 Web 應用程式以用於生產。如果仍然有錯誤，請重複上述步驟。

### [安全 WebDav 與 HTTP 檔案伺服器](#id24)

這些伺服器有透過WAF工作的特定要求。他們需要一組擴展的 HTTP 動詞，以及更高的請求和回應正文閾值。

WebDAV 伺服器的一個流行範例是 Nextcloud 或 Owncloud。

前往 Web 保護設置，並將允許的 HTTP 動詞設為：

COPY, DELETE, GET, HEAD, LOCK, MKCOL, MOVE, OPTIONS, POST, PROPFIND, PROPPATCH, PUT, TRACE, UNLOCK.

若要允許大檔案上傳，請將請求正文限制操作設定為處理部分。如果要處理盡可能多的文件內容，請啟用進階模式並為請求正文和回應正文限制設定自訂值。

如果檔案大於配置的限制，則只會部分處理。這意味著，整個文件將被上傳，但 Web 應用程式解析器僅分析文件的一部分。拒絕可以提高安全性，但如果大檔案超出配置的硬限制，則會導致大檔案完全失敗。

注意事項

增加 Body 限制會增加日誌檔案大小，最終會在檢查時使用 OPNsense 的磁碟來寫入檔案。為此，記憶體限制中的請求正文可以增加到 1GB，以專注於RAM 使用。如果您想使用最少的資源、日誌記錄和磁碟 I/O，請將所有設定保留為預設值，並將「請求正文限制操作」設為「處理部分」。

提示

如果 WebDAV 伺服器上託管許多不同的檔案副檔名，則預設規則將阻止其中一些檔案副檔名。在這種情況下，禁用規則：`920440 (URL file extension is restricted by policy)`

### [請求標頭](#id25)

### [使用憑證保護本機伺服器](#id26)

在上面的虛擬主機配置中有幾個與客戶端身份驗證相關的參數。使用這些的優點是，您可以使用（本地）憑證授權單位簽署的憑證來防止對服務進行未經授權的存取。

要使用此功能，首先確保您在 System ‣ Trust ‣ Authorities 中定義了一個憑證授權單位，您將使用它為客戶端建立憑證。

下一步是新增一個 VirtualServer，其中至少包含以下資訊：

|選項|說明 |

|港口|綁定的連接埠號碼，需要時可以使用[連接埠轉送](<135 網路位址轉換.md>)將流量從標準連接埠重定向到非標準連接埠 |
|證書/啟用ACME |使用ACME證書或自行定義證書，連接到該主機的瀏覽器應該信任該證書 |
| CA 用於客戶端身份驗證 |選擇先前建立的權限 |

後面是一個位置，可能就像將路徑 `/` 綁定到沒有憑證的本機電腦`http://10.0.0.1` 一樣簡單。

提示

您可以使用撤銷清單來收回所選用戶端的存取權限，只需確保重新啟動服務以使變更生效。

完成此步驟後，用戶端應該無法存取虛擬主機，接下來您可以為用戶端建立憑證並將其匯入信任儲存區。通常，當客戶端允許時，瀏覽器會自動選取這些。

申請後，該位置需要身份驗證（用戶必須登入）。

### [OpenID Connect 聲明](#id28)

聲明是可用於識別使用者身分的一條訊息。這意味著您可以建立更嚴格的使用者有權存取該位置的策略，不僅強制執行身份驗證，還強制執行授權。

例如，我們只想向所有名字為 `John` 的使用者授予對某個位置的存取權。

首先，我們在 Firewall ‣ Web Application ‣ Gateways ‣ OIDC Claims 中新增一個聲明：

|選項|說明 |
| --- | --- |
| **OpenID 連線** | |
|索賠類型 |大多數索賠類型都透過 OIDC 規範進行標準化。也提供了一些提供者特定的選項（群組）。對於我們的範例案例，我們選擇`name`。 |
|索賠價值| `John` |

接下來，我們將聲明新增至 Firewall ‣ Web Application ‣ Gateways ‣ Virtual Servers 中啟用 OpenID Connect 的位置：

|選項|說明 |
| --- | --- |
| **OpenID 連線** | |
| OIDC 需要授權 |選擇使用以下聲明強制執行 OIDC 身份驗證。 |
| OIDC 索賠 | `name John` |

申請後，該位置將需要身份驗證（用戶必須登入）和授權（用戶必須是John）。

注意事項

可以選擇多個索賠，它們將透過`or`運算符合併。

提示

可以使用 `preferred_username` 聲明來授權唯一用戶，這是用戶進行身份驗證時使用的名稱。一些身分提供者可以在其 OIDC 範圍內發送群組（非標準），這可以在您擁有大量使用者時簡化授權。

### [錯誤文檔](#id29)

預設情況下，將為 HTTP 回應狀態代碼提供通用 Apache 文件。最常見的客戶端錯誤回應可以採用 OPNsense 主題樣式，也可以採用您自己的風格進行品牌化。

若要下載預設錯誤文件模板，請前往防火牆 ‣ Web 應用程式 ‣ 錯誤文件。

選擇`Default`行中的下載指令。之後，您可以解壓縮存檔，並更改個別錯誤文件。

完成後，選擇 **++** 開啟上傳對話方塊：

|選項|說明 |
| --- | --- |
|名稱 |該範本的名稱，例如`MyErrorDocuments` |
|烏裡 |用於提供錯誤頁面的 Uri，如果未指定，將使用 /\_\_waf\_errors\_\_/。最好使用提供的預設值。 |
|內容 |選擇包含已變更錯誤文件的 zip 檔案。 |

儲存後，可以在 Firewall ‣ Web Application ‣ Gateways ‣ Virtual Servers 中新增錯誤文件：

|選項|說明 |
| --- | --- |
|錯誤文檔 | `MyErrorDocuments` 將使用您的新範本。 `Default` 將使用 OPNsense 風格的模板。 `None` 將使用未更改的預設 Apache 文件。 |

若要選擇性地僅使用範本提供的錯誤覆蓋任何錯誤，您可以在某個位置設定以下內容：

|選項|說明 |
| --- | --- |
|覆寫錯誤頁面 |將常見錯誤頁面與虛擬伺服器中指定的頁面重疊。這意味著從 `Remote destinations` 收到的所有 HTTP 響應狀態代碼都會被剝離，並且僅提供當前所選錯誤文檔模板中匹配的 HTTP 響應代碼。 |

提示

使用 OpenID Connect 時，最好使用 `Default` 或自訂錯誤文檔，以確保 `Unauthorized` 錯誤頁面具有更具凝聚力和使用者友好的風格。

## [伺服器狀態](#id30)

伺服器公開可在 Firewall ‣ Web Application ‣ Status 中顯示的指標。

您可以找到包含一般資訊、工人、目前請求和ACME證書的選項卡。

如果伺服器表現異常，檢查目前請求和伺服器負載可以揭示潛在問題：

-   **檢測後端連線問題**
    
    請求保持開啟的時間異常長或反覆失敗可能表示上游服務速度緩慢或無法存取。檢查活動請求清單可以幫助確定問題是源自反向代理還是後端應用程式。
    
-   **即時驗證配置變更**
    
    修改配置後，狀態頁面可用於驗證請求是否如預期處理。透過觀察請求路徑和工作執行緒活動，管理員可以確認流量是否到達了預期的後端服務。
    
-   **尋找惡意客戶端**
    
    如果 CPU 負載非常高且並發請求數量超出預期，則惡意用戶端可能會對託管網站進行 DoS。
    

提示

伺服器統計資料已啟用API，這表示您可以將它們匯出到外部監控系統。由於它們不會儲存在磁碟上，因此持久性需要外部輪詢。
