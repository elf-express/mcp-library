# 虛擬IP

> 章節：[Interfaces](<000 目錄.md#c-19>)

當使用其他位址來實現諸如NAT之類的功能或將服務綁定到不同的介面時，可以使用**虛擬 IP**向已定義的介面添加額外的位址。

注意事項

虛擬IP在高可用性(https://docs.opnsense.org/manual/hacarp.html)設定中也發揮著至關重要的作用。

## 類型及其用途

OPNsense 支援不同類型的虛擬位址，每種虛擬位址都有其特定的用途，我們將在下面進行解釋。

### IP別名

一個標準的額外地址，可用於將服務綁定到該地址或在NAT規則中使用。

該位址將像普通的介面位址一樣運行，這表示它將回應ICMP ping 請求並產生ARP流量（ OSI第 2 層）。

此外，您也可以在現有的CARP組中新增別名（透過設定其VHID ）。有關更多信息，請參閱下面的CARP VIP類型。

通常子網路遮罩應該與介面匹配，或定義為單一位址（/32 或 /128）。

### CARP

指定一個用於高可用性叢集的位址，當節點處於MASTER狀態時，該位址的作用與常規位址相同。

必須指定一個VHID組號。 「選擇一個未指派的VHID 」按鈕可自動選擇一個可用的VHID編號。通常的做法是為每個介面使用不同的VHID編號，但這並非硬性要求，因為底層協定僅要求VHID在指定介面的廣播域內是唯一的。但是，為了方便管理和調試，建議每個介面使用單獨的VHID編號。

內部會產生協定所需的自訂 MAC 位址。有關CARP的更多信息，請參閱我們的 [高可用性](<96 高可用性.md>)部分。

注意事項

CARP介面的虛擬MAC位址為`00:00:5e:00:01:XX` ，其中最後兩位數字將由其 vhid 填入。

注意事項

CARP使用IP協議號 112 (0x70) 來偵測優先權，它會使用`224.0.0.18`或`FF02::12`發送通告。從 OPNsense 24.7開始，當中間基礎設施過濾多播封包時，也可以使用單播。

注意事項

CARP封包的來源位址無法由防火牆控制（通常是介面上的第一個位址）。當兩個防火牆之間存在某種過濾機制（例如雲端入口網站）時，請確保允許來自實際發送位址的 CARP 流量。如有疑問，可以使用資料包擷取來確定資料包使用的位址。

提示

雖然我們通常首選組播封包（預設）進行通告，但從 OPNsense 24.7開始，也可以選擇單播。只需確保在兩台機器上都輸入非 CARP 目標位址即可。

提示

如果您正在調試CARP設置，請考慮提高CARP系統日誌詳細程度。這可以透過在“系統”->“設定”->“可調參數”中添加`net.inet.carp.log`並賦予`2`值來實現。日誌可以在“系統”->“日誌檔案”->“常規（內核進程）”中查看，或使用`dmesg`進行查看。

**將CARP虛IP型與IP別名結合使用**

如果需要在單一介面上設定多個IP別名，且該介面應由CARP集群共享， CARP VIP VHID可以將單一CARP VIP分配給特定的VHID ，並結合常規的IP別名稱類型，同時將VHID

-   現在，所有已設定的虛擬IP位址都被視為一個主機（ VHID ）。
    
-   只有這台VHID會發送廣告資料包。
    
-   針對此VHID將IP位址集進行哈希處理，並插入到通告封包中。在接收到CARP通告時，會將此雜湊值與對等節點上相同的VHID雜湊值進行比較。如果兩者不匹配，則由於配置不同步，對等節點將接管主節點角色。
    

注意事項

有關在正在運行CARP叢集中新增IP的詳細資訊和正確步驟，請參閱 [新增多個CARP IP](<148 配置CARP.md#adding-multiple-carp-ips>) 。

警告

雖然從技術上講，可以在同一介面上分配多個 CARP VIP，但對於單獨的 VHID，這沒有任何好處，因此不建議這樣做。用於故障轉移的CARP流量和系統程式將在每個虛擬IP的雜訊中線性增加。由於CARP的主要目的是對鏈路狀態變化做出反應，因此作用於單一介面的單一VHID是使用該協定的最有效方式。

### 代理ARP

它不會向介面新增實際位址，而是使用 [choparp](https://www.freebsd.org/cgi/man.cgi?query=choparp)來回應網路上的 ARP 請求。在某些情況下，當需要讓客戶端誤以為某個位址是本機位址時，這種方法可能很實用。

## 設定

此介面應驗證設定組合的正確性，下面您將找到每項設定的詳細說明。

---

|   |   |
| --- | --- |
| 模式 | 位址類型，定義見[類型](#firewall-vip-types) 。 |
| 介面 | 此位址所屬的介面。 |
| 類型 | 可以是網路位址或單一位址，僅在建立NAT規則時生效，其中 **代理ARP** 與 **擴充** 結合使用，將為子網路遮罩中的所有項目產生單獨的位址。 |
|位址 |要指派的位址和網路遮罩，在同一網路中指派多個位址時，遮罩通常應該符合。 |
| 拒絕服務綁定 | 將服務指派給虛擬介面IP時，會自動包含此位址。選取此項目可阻止綁定到此位址。 |
| 對等方（IPv4、IPv6）|（OPNsense 版本 >= 24.7 ） CARP通告時使用的目標位址，預設為組播，但在無法使用組播時（例如與雲端提供者一起使用時）可以配置為單播位址 |
| 網關 | 僅適用於 **IP別名** 類型，通常此欄位應為空，但某些隧道設備（ppp/pppoe/tun）需要定義網關位址。 |
| 停用擴充 | 停用將此條目擴展到NAT清單中的 IP 位址（例如， 192.168.1.0/24會擴展到 256 個條目）。 |
| 虛擬IP密碼 | 用於加密網路上CARP封包的密碼，在首選主節點和備份節點上應保持一致。 |
| VHID 群組 |虛擬主機ID。這是一個唯一的編號，用於向群組中的其他節點標識冗餘群組，並區分同一網路上的群組。可接受的值是從 1 到 255。該值對於群組的所有成員必須相同。 |
|廣告頻率|定義通告此介面屬於群組的頻率（`Base` 以秒為單位定義）以及發送通告時的 **傾斜** 程度。 `skew` 越高代表越不受歡迎。 |
| 描述 | 對此VIP的使用者友善描述 |

## 地位

狀態頁面顯示所有已設定的 CARP VHID群組及其活動狀態。我們的狀態螢幕也提供了一些按鈕，用於停用 CARP 或強制節點進入維護模式。

所有不同狀態的詳細資訊如下。

### INIT

這通常表示介面存在問題，通常與介面未斷開連接或其他技術問題有關。

### BACKUP

在備份狀態下，此介面是叢集的一部分，並監聽廣播。如果由於某種原因短時間內無法接收廣播，它將切換到主狀態。

### MASTER

標記目前活動節點，同時監聽網路上的廣告。如果發現另一個節點發出更好的廣告，則該節點可能會切換到備份狀態（取決於「系統」‣「高可用性」‣「設定」頁面中的`preempt`設定）。

### DISABLED

在此頁面點選**暫時停用CARP**時顯示。
