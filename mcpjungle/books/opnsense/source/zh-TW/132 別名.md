# 別名

> 章節：[Firewall](<000 目錄.md#c-26>)

別名是網路、主機或連接埠的命名列表，透過在防火牆的各個支援部分中選擇別名，可以將其用作實體。這些別名對於壓縮防火牆規則和最小化變更特別有用。

可以透過 Firewall ‣ Aliases 新增、修改和刪除別名。

## 概述

該頁面開啟後會概述可用的別名，包括已安裝軟體中可用的一些內部別名。在頁面頂部，您可以搜尋別名或預先選擇它們所屬的各種類型或類別。

為了深入了解插件的當前狀態，將顯示兩個附加（元）字段，即：

-   已載入#
    
    -   顯示計劃安裝到表中的條目數量，如果沒有足夠的記憶體來載入相關項目，可以輕鬆找到導致表條目溢出的別名（頁面右上角的欄）
        
-   最後更新
    
    > -   顯示儲存到磁碟的條目的最後一個時間戳。
    >     
    

注意事項

上面的欄位僅用於包含網路或主機的別名，連接埠類型別名是規則的一部分，因此在任何表中都不可見。

## 別名類型

OPNsense 提供以下別名類型：

|類型 |描述 |
| --- | --- |
|主持人 |透過 IP 或完全限定網域名稱或主機排除（以「！」符號開頭）的單一主機 |
|網|全網P.E. 192.168.1.1/24 或網路排除，例如！ 192.168.1.0/24 |
|港口 |連接埠號碼或連接埠範圍，例如 20:30 |
| MAC 位址 | MAC 位址或部分 MAC 位址，例如 `f4:90:ea` |
| URL（IP）|一次取得的IP位址表|
| URL 表 (IP) |定期取得的IP位址表。 |
| URL JSON 格式的表格 (IP) |定期取得的IP位址表。 （使用json結構）|
|地理IP |選擇國家或整個地區 |
|網路群|將不同的網路類型別名合併為一個 |
|動態 IPv6 主機 |會在前綴更改時自動更新的主機條目 |
| BGP ASN |將自治系統 (AS) 編號對應到其負責的網路。 |
| OpenVPN 群組 |將使用者群組對應到登入的 OpenVPN 使用者 |
|內部（自動）|由產品管理的內部別名 |
|外部（高級）|外部管理的別名，這只處理佔位符。內容是從其他來源設定的（插件、API 呼叫等）|

### 主辦單位

主機可以輸入為單一IP位址、範圍（以減號分隔，例如`10.0.0.1-10.0.0.10`）或完全限定的網域名稱。

使用完全限定域名時，將定期解析該名稱（預設為每 300 秒）。

樣本

假設我們要為 **www.youtube.com** 建立一個別名表

[![../_images/aliases_host.png](<../images/8363346d-aliases_host.png>)](https://docs.opnsense.org/_images/aliases_host.png)

**套用變更**並查看我們新建立的 pf 表的內容。

前往 Firewall ‣ Diagnostics ‣ Aliases 並選擇我們新建立的 YouTube 表格。

[![../_images/pftable_youtube.png](<../images/f7b204d8-pftable_youtube.png>)](https://docs.opnsense.org/_images/pftable_youtube.png)

如您所看到的，該網域有多個 IP 位址。

提示

若要變更別名域解析間隔，請前往 Firewall ‣ Settings ‣ Advanced 並將 **Aliases Resolve Interval** 設定為刷新的秒數。

主機類型別名可以包含排除主機。排除位址以「！」開頭符號（例如！192.168.0.1），可用於從網路群組別名中排除主機。

警告

請注意，**Flush** 操作不是持久的！

**「flush」**表示刷新別名的當前內容，當它不是外部類型時將重新填充別名，因此刷新在大多數情況下不是很有用。

相同的行為適用於 API 呼叫 [alias\_utillush](<276 防火牆.md>)

### 網路

網路以無類別域間路由格式 (CIDR) 指定。為每個條目使用正確的 CIDR 遮罩。例如，/32 指定單一 IPv4 主機，或 /128 指定單一 IPv6 主機，而 /24 指定255.255.255.0，而 /64 指定普通 IPv6 網路。網路類型別名可以包含排除主機或網路。排除位址以「！」開頭符號（例如！192.168.0.0/24），可用於從目前別名或網路組別別名排除主機或網路

除了CIDR表示法之外，還可以使用[通配符遮罩](https://en.wikipedia.org/wiki/Wildcard_mask)來匹配主機或網路的範圍。

提示

若要符合 192.168.X.1 網路中以 .1 結尾的所有伺服器，請使用通配符定義，例如 `192.168.0.1/0.0.255.0`

### 港口

連接埠可以指定為單一數字或使用冒號 **:**的範圍。例如，要新增 20 到 25 的範圍，可以在**Port(s)** 部分輸入 20:25。

### MAC 地址

硬體 MAC 位址可以指定為（部分）十六進位值，例如 `F4:90:EA` 符合 Deciso 中的所有位址，或 `f4:90:ea:00:00:01` 符合單一項目（輸入不區分大小寫）。

這些別名的功能與主機類型別名中的主機名稱大致相同，它們是從 `arp` 和 `ndp` 表中定期解析的。

警告

請注意，硬體位址可能會被欺騙（[https://en.wikipedia.org/wiki/MAC\_spoofing](https://en.wikipedia.org/wiki/MAC_spoofing)），這並不會使它們上的過濾器比 IP 位址更安全。

注意事項

由於位址和 MAC 位址之間的對應會定期解析，因此實際情況可能會有所不同，因此您可以隨時檢查防火牆 -> 診斷 -> 別名來檢查別名的當前內容。

### URL 桌子

URL 表可用於從遠端伺服器取得 IP 位址清單。您可以指定 `` Refresh frequency` `` 來決定此資訊的更新頻率。

注意事項

正在取得的檔案內容每行應包含一個 IPv\[4|6\] 位址，以 `whitespace` 、冒號 (`,`)、分號 (`;`)、豎線 (`|`) 或哈希 (`#`) 開頭的行將被忽略。

### URL JSON 格式的表格（IP）

URL 表可用於從遠端伺服器取得 IP 位址列表，並以 [JSON](https://en.wikipedia.org/wiki/JSON) 格式解析其內容，類似於我們的標準（基於文字）url 表。

您可以使用 `Path expression` 從容器中選擇數據，在某些情況下，當內容是「扁平」時，您只需要一個路徑引用。例如，spamhause [drop](https://www.spamhaus.org/drop/drop_v4.json) 清單每行包含一個 json 文件，其中包含一個欄位 `cidr`。

更高級的場景也是可能的，因為我們的解析器支援 [jq](https://jqlang.org/)，一些（簡單的）範例可以在下表中找到。

|內容 |路徑表達式 |主題 |
| --- | --- | --- |
| [https://ip-ranges.amazonaws.com/ip-ranges.json](https://ip-ranges.amazonaws.com/ip-ranges.json) | .前綴\[\]\| 選擇(.region==”us-east-1”) \| 選擇（.服務==”EC2”) \| .ip\_前綴|屬於服務的所有IP位址 EC2 在 us-east-1 地區 |
| [https://api.github.com/meta](https://api.github.com/meta) | .web + .api + .git \| .\[\] |所有 GitHub 的 Web、API 與 git 位址 |
| [https://endpoints.office.com/endpoints/worldwide?clientrequestid=b10c5ed1-bad1-445f-b386-b919946339a7](https://endpoints.office.com/endpoints/worldwide?clientrequestid=b10c5ed1-bad1-445f-b386-b919946339a7) | .\[\]\| select(.serviceArea==”交換”) \| 選擇（“.ips”）\| .ips \| .\[\]？ | Microsoft 的交換網路 |

### 地理IP

使用 GeoIP 別名，您可以選擇一個或多個國家或整個大陸來阻止或允許。使用*切換全部*複選框選擇給定區域內的所有國家。

要使用 GeoIP，當不使用我們的商業版時，您需要在 Firewall ‣ Aliases -> GeoIP settings 標籤中配置來源，我們的軟體支援 IPinfo 和 MaxMind 提供的格式。

注意事項

根據我們的經驗，IPinfo 提供了更大、更詳細的資料集，當使用清單中的不同國家/地區時，請確保將 Firewall ‣ Settings ‣ Advanced : Firewall Maximum Table Entries 增加到更高的數量。截至撰寫本文時，清單的總大小約為 700 萬個條目。

儘管您沒有義務使用其中一項已定義的服務，但以下文件說明如何使用您選擇的選項：

> -   [IPinfo GeoIP的設定](https://docs.opnsense.org/manual/how-tos/ipinfo_geo_ip.html)
>     
> -   [MaxMind GeoIP 的設定](https://docs.opnsense.org/manual/how-tos/maxmind_geo_ip.html)
>     

提示

使用商業版時，您可以將`Url`欄位留空，這樣防火牆就會自動下載我們的鏡像提供的IPinfo資料庫。

下面您將找到我們的軟體可以自動偵測和處理的詳細規格。

**gzip 格式（IP 資訊）**

此格式是一個簡單的逗號分隔文件，依序包含以下元素：

-   網路
    
-   國家
    
-   國家\_代碼
    
-   大陸
    
-   大陸\_代碼
    
-   阿斯尼
    
-   作為\_name
    
-   作為\_domain
    

我們的軟體只使用`network`和`country_code`，這些應該在csv的標題中提及。文件本身應該使用 `gzip` 進行壓縮

**zip 格式 (MaxMind)**

此格式需要包含以下 csv 檔案的 \[zip\] 檔案：

*標題*

|檔名 |目的|格式|範例|
| --- | --- | --- | --- |
| %prefix%-locations-en.csv |將地理位置對應到 ISO 國家 |地理名稱\_id,,,,國家\_iso\_code | 1,,,,NL |
| %前綴%-IPv4.csv | IPv4網路|網路、地理名稱\_id | 2.21.241.0/28,1 |
| %前綴%-IPv6.csv | IPv6網路|網路、地理名稱\_id | 2001:470:1f15:210::/64,1 |

`%prefix%` 可用於識別產品和/或供應商，例如，在 MaxMind 的情況下，這些檔案被命名為 `GeoLite2-Country-Locations-en.csv`, `GeoLite2-Country-Blocks-IPv4.csv`, `GeoLite2-Country-Blocks-IPv6.csv`。

提示

Geo IP 清單可能相當大，特別是使用 IPv6 時。建立規則時，請務必盡量減少選擇中所需的位址數量。例如，通常可以將世界上除荷蘭以外的所有國家/地區的選擇重寫為僅來自荷蘭的地址。

提示

如果項目數量大於分配的別名大小，您可以為別名分配更多記憶體。防火牆 ‣ 設定 ‣ 進階 : 防火牆最大表格條目數

### 網路組

將不同的網路類型別名組合為一個，這種類型的別名會接受其他主機類型別名（網路、主機等）。儘管其他別名類型也可以嵌套，但此類型僅顯示有效的別名以方便管理，從功能上講，`Networks` 類型別名可以執行相同的操作，但使用不同的表示形式。

### 動態 IPv6 主機

當系統在LAN（追蹤介面）上使用動態前綴時，將使用 IPv6 動態主機。當前綴發生變化時，無論是由於ISP隨意更改前綴，還是由於WAN連接重置時前綴發生變化，任何包含客戶端位址（例如LAN上的伺服器）的別名將不再有效。

例如，您獲得前綴 2001:db8:2222:2800::/56。您有 /56 前綴，如果您的 LAN 的追蹤 ID 設定為 0，則您的 LAN 上的位址範圍為 2001:db8:2222:2800:: 到 2001:db8:2222:2800:FFFF:FFFF:FFFF:FFFF。

您希望在 LAN 上執行一個可從 WAN 存取的伺服器，因此您為其指定靜態位址 2001:db8:2222:2800:1000:1000::1 並建立一條允許流量存取該伺服器的規則。

當您的前綴變更時，此靜態位址不再有效，因此您必須使用動態 IPv6 主機為自動追蹤前綴並變更規則的防火牆項目建立別名位址。

動態主機別名將始終在 /64 邊界上拆分，它將從您選擇的介面中取得高 64 位，並從您輸入的位址中取得低 64 位元。您的前綴委託的大小並不重要。

建立一個新的 IPv6 動態主機別名並僅輸入位址的後綴，在本例中，我們將輸入位址的低 64 位，您將輸入 ::1000:1000:0000:1，注意位址開頭的“::”，您MUST始終以“::”開頭位址。您無需在地址後面輸入大小，即 /128，因為這是自動假定的。

選擇您希望用於高 64 位元來源的接口，在本例中我們將選擇LAN 接口。

當前綴更改時，別名位址將在防火牆規則中更新，假設您的前綴更改為2001:db8:2222:3200::/56，規則更新，並且您的伺服器在防火牆中的條目將自動更新為2001:db8:2222:3200:1000:1000::1

我們再舉個例子，您有一個 /48 前綴委託，有兩個 LAN 接口，每個接口上都有一個伺服器。您需要建立兩個單獨的動態 IPv6 主機條目，每個 LAN 一個。為了簡單起見，我們將為每個介面上的每個伺服器使用相同的位址，您將輸入 ::aaaa:bbbb:cccc:0001 作為位址。

### BGP ASN

使用此別名類型，您可以依責任方選擇網路。使用BGP，各方宣布他們彼此負責的地址。例如，Cloudflare 使用 AS 編號 `13335`，已知 Microsoft 使用 `8075`。

更多背景知識以及如何分配地址在 [wikipedia](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\) 上有解釋）

### 外部

外部別名類型的內容不透過我們的普通別名服務進行管理，並且在您想要從外部程式推送新條目的情況下非常實用。例如特定的鎖定功能或向防火牆提供存取控制的外部工具。

在 Firewall ‣ Diagnostics ‣ Aliases 中，您隨時可以檢查外部別名的目前內容並立即新增或刪除條目。

提示

當變更啟用狀態追蹤的防火牆規則上使用的別名內容時，您可能需要在新規則變為活動狀態之前刪除特定狀態。 （請參閱防火牆 ‣ 診斷 ‣ 狀態轉儲）

提示

由於 OPNsense 不會觸及外部別名類型，因此您可以直接在腳本中使用 `pfctl` 來管理其內容。 （例如 `pfctl -t MyAlias -T add 10.0.0.3` 將 **10.0.0.3**加入**MyAlias**）

### OpenVPN群組

此別名類型提供了根據系統 ‣ 存取 ‣ 群組中配置的所屬群組為登入 OpenVPN 使用者建立防火牆策略的可能性。

目前登入 OpenVPN 的使用者可以透過 VPN ‣ OpenVPN ‣ 連線狀態進行檢查，別名只是遵循此資訊並將附加位址刷新到相關項目。

例如，當名為 **fred**的使用者（**remote\_users** 群組的成員）登入 OpenVPN 並收到`10.10.10.2` 的隧道位址時，包含「remote\_users」的別名也會包含此位址。

注意事項

為了使此機制發揮作用，使用者憑證的公用名稱必須與使用者名稱完全匹配，如果憑證是從使用者管理員建立的，則預設情況下就是這種情況。

提示

使用LDAP（Active Directory）時，您可以同步群組成員資格以避免 OPNsense 中的雙重管理。

### 內部（自動）

內部別名以`__`為前綴，因此易於識別，並且不能與任何使用者定義的別名重疊。這些別名可協助您確定某些內部概念（例如「LAN網路」）的內容。使用「防火牆」->「診斷」->「別名」選單項，您可以隨時檢查其內容。

## 在防火牆規則中使用別名

可以在防火牆規則中使用別名來簡化大型清單的管理。例如，我們可能需要一個應該有權存取某些服務的遠端IP地址列表，當發生任何變更時，我們只需要更新該列表。

讓我們建立一個簡單的別名，以允許 3 個遠端 IP 位址存取 ipsec 伺服器以實現網站到網站隧道連接：

-   192.168.100.1
    
-   192.168.200.2
    
-   192.168.202.2
    

[![../_images/alias_remote_ipsec.png](<../images/44736bc4-alias_remote_ipsec.png>)](https://docs.opnsense.org/_images/alias_remote_ipsec.png)

我們將清單稱為“remote\_ipsec”並相應地更新我們的防火牆規則。

[![../_images/alias_firewall_rules.png](<../images/36283e23-alias_firewall_rules.png>)](https://docs.opnsense.org/_images/alias_firewall_rules.png)

注意事項

清單圖示標識帶有別名的規則。

## 出口/進口

別名管理頁面（防火牆 ‣ 別名）在表格的頁腳中包含一個下載和上傳按鈕，透過此功能，您可以將別名合併到設定中，並下載系統中所有別名的 `json` 格式清單。

由於資料在插入之前經過驗證，因此不可能匯入有缺陷的資料（如果匯入失敗，則會顯示錯誤清單）。

提示

執行遷移時，有時在文字編輯器中一次更改多個項目會更容易。此功能可以輕鬆地用於促進這一點，同時限製配置損壞的風險（因為專案的驗證與單一專案輸入的驗證相同）。

## 使用我們的API新增條目

別名\_util 中的端點可輕鬆用於將新條目推送到別名中（或刪除現有條目）。如果使用外部別名，這些項目將不會在重新啟動後保持不變，這在某些用例中非常實用（例如大型頻繁更改的清單）。

文件「[使用API](<370 使用API.md>)」包含建立 api 金鑰和秘密所需的步驟，接下來您可以呼叫使用者介面所需的相同端點。

下面您將看到如何使用主機 **opnsense.firewall**上的不安全連線（自簽名憑證）和 `curl` 將**10.0.0.2**新增至名為**MyAlias** 的別名。 verbose 選項提供有關兩台電腦之間交換的資料的更多詳細資訊。

```bash
curl \
  --header "Content-Type: application/json" \
  --basic \
  --user "key:secret" \
  --request POST \
  --insecure \
  --verbose \
  --data  '{"address":"10.0.0.2"}' \
  https://opnsense.firewall/api/firewall/alias_util/add/MyAlias
```

注意事項

僅主機、網路和外部類型別名支援使用 `/api/firewall/alias_util/add/` 新增別名

## 排除情況

Pf 防火牆表支援位址例外（或排除）。此功能可在一個別名或組合（網路群組類型）別名中使用。請參閱（[https://www.freebsd.org/doc/handbook/firewalls-pf.html](https://www.freebsd.org/doc/handbook/firewalls-pf.html) 30.3.2.4）。

## 嵌套

對於主機和網路別名類型，嵌套是可能的，這可以大大簡化管理，因為可以正確命名單一專案並將其分組到部分中進行管理。

例如，我們使用不同的規則集在 2 個關鍵伺服器中定義 4 個伺服器：

-   伺服器\_a {10.0.1.1}
    
-   伺服器\_b {10.0.1.2}
    
-   伺服器\_c {10.0.1.100}
    
-   伺服器\_d {10.0.1.200}
    
-   關鍵伺服器{伺服器a，伺服器b}
    
-   其他伺服器 {伺服器\_c , 伺服器\_d}
    
-   伺服器{關鍵伺服器，其他伺服器}。
    

配置後，別名`servers`將包含所有4個位址。

也可以將不同的別名與別名組合起來，包括排除。例如，有一個別名“FireHOL”，它使用廣泛的外部下拉列表，還有兩個包含子網路和主機排除的別名。可以建立網路群組（組合）別名（“FireHOL\_with\_exclusions”）：

-   FireHOL {[https://raw.githubusercontent.com/firehol/blocklist-ipsets/master/firehol\_level1.netset](https://raw.githubusercontent.com/firehol/blocklist-ipsets/master/firehol_level1.netset)}
    
-   子網\_排除 {!127.0.0.0/8, !0.0.0.0/8}
    
-   主機\_排除{!8.8.8.8}
    
-   FireHOL\_with\_exclusions {FireHOL、子網路\_exclusions、主機\_exclusions}
    

`FireHOL_with_exclusions` 別名將包含 FireHOL 別名中的所有記錄，不包括排除別名中的位址。

透過 Firewall ‣ Diagnostics ‣ pfTable 檢查地址是否包含在 Alias 中總是好的
