# 路由

> 章節：[Development Manual](<000 目錄.md#c-52>) › [Frontend](<000 目錄.md#c-55>)

## 一般

為了保持與遺留程式碼的向後相容性，我們嘗試將舊頁面保留在其原始位置。對於新程式碼，我們在 url 中定義兩個根資料夾：

-   /ui/ 用於新的使用者介面部分
    
-   /api/ 用於網路服務 (REST)
    

這部分路由由 lighthttpd 使用 mod\_alias 和 mod\_rewrite 處理。

## 使用者介面路由

如果您查看 OPNsense 中的控制器目錄，您會注意到 /usr/local/opnsense/mvc/app/controllers 中的根控制器目錄下有不同的目錄等級。為了最終支援不同的應用程式和供應商，我們已經使用了一個自動用於設定路由的結構。

在第一級，我們使用應用程式的供應商，在我們的例子中始終是 OPNsense。

下一個層級用於命名主題（或應用程式），例如我們使用 Sample 作為範例應用程式。

最後，您可以將控制器的標準 Phalcon 類別放置在該目錄中，因此如果您想要建立頁面 helloworld，它應該會附帶一個控制器 helloworldController.php （以及用於定義該頁面的索引操作的 indexAction ）。

helloworld 頁面的完整路徑最終將是：

```
/usr/local/opnsense/mvc/app/controllers/OPNsense/Sample/helloworldController.php
```

發佈頁面時，映射中不使用控制器的供應商部分，因此在此範例中 helloworld 索引頁面將位於：

```
https://{url}/ui/sample/helloworld/
```

url 的所有部分都會自動轉換為小寫，因此 **S**ample 將會對應到**s**ample。

該路由是透過我們新程式碼庫的索引頁面設定的，並使用 `/usr/local/opnsense/mvc/app/config/services.php` 將其連接在一起。

## API路由

API功能的路由與路由UI元件非常相似，只需在應用程式路徑下建立Api目錄並放置一個控制器類別來處理請求。唯一的主要區別是它是由單獨的 PHP 文件（稱為 api.php）處理，而不是用於配置 ui 部分的 index.php 文件，路由的詳細資訊可以在 /usr/local/opnsense/mvc/app/config/services\_api.php 中找到。

如果我們的範例應用程式需要 API 透過名為「工具」的控制器回顯某些內容，則可以將其放入名為的檔案中：

```
/usr/local/opnsense/mvc/app/controllers/OPNsense/Sample/Api/toolsController.api
```

並透過以下網址呼叫：

```
https://{host}}/api/sample/tools/echo
```

當控制器有一個名為 echoAction 的方法。
