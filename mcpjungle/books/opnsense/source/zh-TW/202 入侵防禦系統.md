OPNsense 的入侵防禦系統（IPS）系統基於[Suricata](https://suricata.io/)，並利用[Netmap](https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.2-RELEASE+and+Ports)來增強性能並最大限度地減少CPU的利用率。這種深度資料包偵測系統非常強大，可用於以線速偵測和減輕安全威脅。

## [IDS 和 IPS](#id3)

定義本文檔中使用的術語非常重要。 *入侵偵測系統* (IDS) 監視網路流量中的可疑模式，並在模式與已知行為資料庫相符時向操作員發出警報。 *入侵防禦系統* (IPS) 更進一步，在每個資料包穿過網路介面時檢查每個資料包，以確定該資料包是否在某種程度上可疑。如果它與已知模式匹配，系統可以丟棄該資料包以嘗試減輕威脅。

[Suricata](https://suricata.io/) 軟體可作為 IDS 和 IPS 系統運作。

## [選擇介面](#id4)

您可以在不同的介面上設定係統。最常見的問題之一是選擇哪個介面。考慮到IPv4的繼續使用，通常與[網路位址轉換](<135 網路位址轉換.md>)結合使用，使用正確的介面非常重要。如果您在WAN介面上擷取流量，您將只能看到位址轉換後的流量。這意味著所有流量都源自於您的防火牆，而不是來自可能觸發警報的防火牆後面的實際電腦。

IDS/IPS系統的規則通常需要對內部網路有清楚的了解；當捕獲NAT後面的封包時，此資訊會遺失。

無需嘗試解釋 IDS 規則的所有細節（Suricata 的人在這方面做得更好）(https://suricata.readthedocs.io/en/suricata-5.0.5/rules/index.html)），ET-開放規則之一的小示例通常有助於理解家庭網絡的重要性。

```
alert tls $HOME_NET any -> $EXTERNAL_NET any (msg:"ET TROJAN Observed Glupteba CnC Domain in TLS SNI"; flow:established,to_server; tls_sni; content:"myinfoart.xyz"; depth:13; isdataat:!1,relative; metadata: former_category MALWARE; reference:md5,4cc43c345aa4d6e8fd2d0b6747c3d996; classtype:trojan-activity; sid:2029751; rev:2; metadata:affected_product Windows_XP_Vista_7_8_10_Server_32_64_Bit, attack_target Client_Endpoint, deployment Perimeter, signature_severity Major, created_at 2020_03_30, updated_at 2020_03_30;)
```

`$HOME_NET`可以配置，但通常是[RFC 1918](https://tools.ietf.org/html/rfc1918)中定義的靜態網路。使用進階模式，您可以選擇外部位址，但請記住，您將不知道哪台電腦真正參與了攻擊，它實際上應該是靜態位址或網路。

`$EXTERNAL_NET` 被定義為不是家庭網絡，這解釋了為什麼您不應該選擇所有流量作為家庭網絡，因為可能沒有任何規則匹配。

由於防火牆預設會丟棄入站封包，因此在 IPS 模式下使用 WAN 介面通常不會提高安全性，因為它會丟棄本來會被防火牆丟棄的封包。

注意事項

IDS 模式適用於幾乎所有（虛擬）網路類型。當您的網卡不受（完全）支援時，您可以將可調參數 `dev.netmap.admode` 設定為值 `2`，在這種情況下，將強制執行模擬模式（可在 System ‣ Settings ‣ Tunables 中設定）。 FreeBSD 手冊頁中提供了本機[支援的實體適配器](https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.1-RELEASE+and+Ports#SUPPORTED_DEVICES) 的清單。

## [一般設定](#id5)

設定頁麵包含用於啟動並運行 IDS/IPS 系統的標準選項。

---

|   |   |
| --- | --- |
|已啟用 |啟用 Suricata |
|拍攝模式|選擇「PCAP即時移動（IDS）」僅用於警報，「Netmap（IPS）」用於警報並透過網路映射驅動程式丟棄，或「轉移（IPS）」以透過防火牆規則重定向封包。規則的操作需要是「丟棄」才能丟棄資料包，這可以按規則或規則集進行配置（使用輸入過濾器）|
|聽眾|當使用「Divert (IPS)」模式時，指定要啟動的偵聽器數量，通常等於系統中的 CPU 數量。 |
|混雜模式|以混雜模式監聽流量。 （所有資料包，而不僅僅是定址到該網路介面的資料包）|
|啟用系統日誌警報 |使用快速日誌格式將警報傳送至系統日誌 |
|啟用 eve syslog 輸出 |使用日誌等級資訊以 [EVE](https://suricata.readthedocs.io/en/suricata-5.0.5/output/eve/eve-json-output.html) 格式將警報傳送至系統日誌。這不會更改產品本身使用的警報日誌記錄。由於 suricata 的限制，刪除日誌只會傳送到內部記錄器。 |
|模式匹配器|控制模式匹配器演算法。 Aho-Corasick 是預設值。在支援的平台上，Hyperscan 是最佳選擇。在商用硬體上，如果 Hyperscan 不可用，建議設定為“Aho–Corasick Ken Steele 變體”，因為它的性能比“Aho–Corasick”更好。 |
|接口|要保護的介面。當處於IPS模式時，這需要是支援netmap的真實介面。 （使用 VLAN 時，在父級上啟用IPS）|
|旋轉日誌|日誌輪替頻率，也用於內部事件日誌記錄（請參閱「警報」標籤）|
|儲存日誌 |要保留的日誌數量 |

注意事項

若要使用「轉移 (IPS)」模式，您必須使用 Firewall ‣ Rules \[new\] 並建立包含「Divert-to」設定的防火牆規則。更多資訊請查看[規則](<137 規則.md>)手冊。

提示

使用外部報告工具時，您可以使用 syslog 輕鬆發送您的 [EVE](https://suricata.readthedocs.io/en/suricata-5.0.5/output/eve/eve-json-output.html) 日誌。只需啟用「啟用EVE系統日誌輸出」並在系統‣設定‣日誌記錄/目標中建立目標。 （過濾應用程式“suricata”和等級“info”）

注意事項

使用 IPS 模式時，請確保在介面設定中停用所有硬體卸載功能（介面 ‣ 設定）。在20.7版本之前，「VLAN硬體過濾」未停用，這可能會導致某些網卡出現問題。

## [進階選項](#id6)

一些不常用的選項隱藏在“高級”切換開關下。

---

|   |   |
| --- | --- |
|家庭網路|定義與 RFC1918 網路不同的自訂家庭網路。在某些情況下，人們傾向於在NAT（網路位址轉換）後面的 wan 介面上啟用IDPS，在這種情況下，Suricata 只能看到轉換後的位址，而不是內部位址。使用此選項，您可以定義 Suricata 應將哪些位址視為本機位址。 |
|預設資料包大小 |使用此選項，您可以設定網路上資料包的大小。有時可能需要處理更大的資料包。引擎仍然可以處理這些較大的資料包，但處理它會降低效能。 |

## [規則集下載](#id7)

首次啟用IDS/IPS時，系統處於活動狀態，沒有任何規則來偵測或阻止惡意流量。下載標籤包含系統上可用的所有規則集（可以使用外掛程式擴充）。

在本節中，您將找到不同方提供的規則集清單以及它們上次在系統上下載的時間（如果已安裝）。在先前的版本中（21.1之前），您可以在此處選擇「過濾器」來將已安裝規則的預設行為從警報更改為阻止。從 21.1 開始，此功能將由 **策略** 涵蓋，這是 IDS/IPS 模組中的一個單獨功能，它提供對規則集更細粒度的控制。

注意事項

從 21.1 之前的版本遷移時，下載規則集頁面中的篩選器會自動遷移到政策。

## [政策](#id8)

**策略**選單項目包含一個網格，您可以在其中定義要套用於已安裝規則的策略。您可以在此處新增、更新或刪除策略以及停用它們。策略有助於控制您想要以何種方式使用哪些規則，並且是改變行為的首選方法。儘管您仍然可以在規則標籤中更新單獨的規則，但添加大量自訂覆蓋對變更更加敏感，並且存在減慢使用者介面速度的風險。

策略條目包含 3 個不同的部分。首先是一些一般訊息，例如描述、規則是否啟用以及優先順序。重疊的策略按順序處理，優先數字最低的第一個匹配是要使用的策略。

其次是符合條件，其中包含應用程式策略的 **規則集**以及在規則上配置的操作（預設為停用、警報或刪除），最後是包含從已安裝規則收集的元資料的**規則** 部分，其中包含受影響產品（Android、Adobe flash 等）和部署（資料中心、週邊）等選項。

最後一個要選擇的選項是要使用的新操作，要么禁用選定的規則，僅對它們發出警報，要么在匹配時丟棄流量。

注意事項

**規則**部分中的選項取決於供應商，當來源規則中沒有提供元資料時，我們端不能使用任何元資料。

## [已設定規則](#id9)

規則標籤提供了一個易於使用的網格來尋找已安裝的規則及其用途，使用頂部的選擇器可以使用策略檢視中可用的相同元資料屬性來篩選規則。

提示

套用規則變更後，將設定規則動作和狀態（啟用/停用），為了輕鬆尋找規則上使用的策略，請檢查篩選器中的 matches\_policy 選項。手動（單一規則）變更被標記為策略 **“\_\_manual\_\_”**

## [使用者自訂規則](#id10)

IDPS 系統上使用的大多數規則將由 Proofpoint 等第三方供應商提供，但在某些情況下，您自己建立一些（有限的）規則可能會很方便。 “用戶定義”選項卡提供此功能。

### [指紋辨識](#id11)

OPNsense 包含一個非常完善的解決方案，可根據 SSL 指紋阻止受保護的網站。您可以在「使用者定義」標籤中手動新增規則。

### [繞過引擎](#id12)

`Bypass` 切換開關提供了跳過流量檢查的功能，我們的「操作方法」部分包含一個很好的範例，可以排除通過網路的本地流量並提高路由效能。

## [提醒](#id13)

在「警報」標籤中，您可以查看IDS/IPS系統觸發的警報。使用此處的資訊按鈕收集有關偵測到的事件或威脅的詳細資訊。

## [高級配置](#id14)

OPNsense 支援 [suricata.yaml](https://suricata.readthedocs.io/en/suricata-6.0.0/configuration/suricata-yaml.html) 格式的自訂 Suricata 配置。為了新增自訂選項，請在`/usr/local/opnsense/service/templates/OPNsense/IDS/`目錄中建立一個名為`custom.yaml`的範本檔案。

由於該檔案是由我們的模板系統解析的，因此您可以使用 [Jinja2](<249 使用模板.md>) 語言來使用模板標籤。

## [可用規則集](#id15)

### [新興威脅](#id16)

新興威脅 (ET) 具有各種 IDS/IPS 規則集。有免費的 BSD 授權版本和付費版本​​。

提示

Proofpoint 提供了一個社群門戶，可以存取有關規則的文件和更新，您可以透過 [https://community.emergingthreats.net/](https://community.emergingthreats.net/) 存取它。 [常見問題](https://community.emergingthreats.net/t/frequently-asked-questions/56)可能是個開始閱讀的好地方。

#### [ET打開](#id17)

ETOpen 規則集「不是」完整涵蓋的規則集，可能不足以滿足許多受監管的環境，因此不應用作獨立的規則集。

OPNsense 整合了對 ETOpen 規則的支援。

#### [ETPro遙測](#id18)

Proofpoint 為眾所周知的 [ET Pro Telemetry 版本](https://docs.opnsense.org/manual/etpro_telemetry.html) 規則集提供免費替代方案。

#### [ETPro（商業）](#id19)

當擁有Proofpoint [ET Pro](https://www.proofpoint.com/us/threat-insight/et-pro-ruleset) oink代碼時，您可以透過系統‣韌體‣插件安裝`os-intrusion-detection-content-et-pro`插件。

安裝外掛程式後，您將在「服務」‣「入侵偵測」‣「管理/下載」的設定下找到選項`etpro.oinkcode`，您可以在其中輸入此程式碼。

### [濫用.ch](#id20)

[Abuse.ch](https://abuse.ch/) 提供多個黑名單以防止詐騙網路。

#### [SSL黑名單](#id21)

*SSL黑名單*（SSLBL）是由abuse.ch維護的項目。目標是提供由abuse.ch 識別出的與惡意軟體或殭屍網路活動相關的「不良」SSL 憑證清單。 SSLBL依賴SHA1惡意SSL證書的指紋並提供各種黑名單。

詳情請見：[https://sslbl.abuse.ch/](https://sslbl.abuse.ch/)

#### [費奧多追蹤器](#id22)

Feodo（也稱為 Cridex 或 Bugat）是一種特洛伊木馬，用於實施電子銀行欺詐並從受害者的計算機竊取敏感信息，例如信用卡詳細信息或憑證。目前，Feodo Tracker 正在追蹤 Feodo 的四個版本，它們被 Feodo Tracker 標記為版本 A、版本 B、版本 C 和版本 D：

-   **版本 A** *託管在受感染的網頁伺服器上，在連接埠 8080 TCP 上執行 nginx 代理，將所有殭屍網路流量轉送到第 2 層代理節點。殭屍網路流量通常不會使用網域名稱直接到達連接埠 8080 TCP 上的這些主機。 *
    
-   **版本 B** *託管在由網路犯罪分子租用和營運的伺服器上，專門用於託管 Feodo 殭屍網路控制器。通常利用 ccTLD .ru 內的網域。殭屍網路流量通常使用連接埠 80 TCP.* 存取這些網域。
    
-   **C 版本** *Feodo 的後繼者，完全不同的程式碼。託管在與版本 A 相同的殭屍網路基礎架構上（受感染的網頁伺服器、連接埠 8080 TCP 或連接埠 7779 TCP 上的 nginx，無網域名稱），但使用不同的 URL 結構。此版本也稱為 Geodo 和 Emotet。 *
    
-   **版本 D** * Cridex 的繼承者。該版本也稱為 Dridex*
    

詳情請見：[https://feodotracker.abuse.ch/](https://feodotracker.abuse.ch/)

#### [URLHaus列表](#id23)

OPNsense 版本18.1.7引入了abuse.ch 中的URLHaus 列表，該列表收集傳播惡意軟體的受感染網站。

詳情請見：[https://urlhaus.abuse.ch/](https://urlhaus.abuse.ch/)

#### [應用檢測規則](#id24)

OPNsense 18.1.11 引入了應用程式偵測規則集。由於大約 80% 的流量是 Web 應用程序，因此這些規則的重點是阻止 Web 服務及其背後的 URL。

如果您想為規則集做出貢獻，請參閱：[https://github.com/opnsense/rules](https://github.com/opnsense/rules)
