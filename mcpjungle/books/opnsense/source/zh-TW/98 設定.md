# 設定

> 章節：[System](<000 目錄.md#c-11>)

除了每個組件都具備的配置選項外，OPNsense 還包含許多可調整的通用設定。本頁面概述了這些設定。

## 行政

本頁的設定與登入 OPNsense 有關。 「安全外殼」設定在 [建立使用者和群組](<86 本地用戶和群組.md>)下有詳細說明。

### 監聽介面

警告

在考慮使用手動選擇的介面之前，請務必閱讀本章，以便提前了解可能的問題。設定錯誤很可能導致 Web 介面無法存取和/或 SSH 存取失敗。

WebUI 和 Secure Shell 伺服器都支援僅監聽特定介面的選項，但是使用此選項會有一些明顯的警告，您在決定使用此選項之前需要了解這些警告。

預設情況下（我們建議的設定），這些服務監聽所有位址（介面）。

如果出於某種原因，您確實需要僅監聽特定接口，則適用以下規則：

-   介面必須始終可用，因此請勿嘗試綁定到任何類型的 VPN 實例（OpenVPN、Wireguard 等）。
    
-   位址必須完全靜態，例如，不能配置 IPv6 追蹤。
    

由於 Web 管理介面無法 100% 確定這些規則是否適用，因此可以選擇不支援這些服務綁定的介面。

注意事項

如果在使用 webgui（和/或 ssh）時遇到問題，且不符合上述規則，請不要費心提交工單，因為這些是不受支援的情況。

提示

如果（**對於任何服務**）想要阻止在所有介面上進行綁定，可以新增一個環回介面（介面 ‣ 設備 ‣ 環回），請指派一個 IP 位址並綁定到該介面。

當流量通過防火牆路由時，「環回 IP」（某個私人位址，不在環回位址範圍內）應該能夠從其後面的網路直接存取。例如，可以使用類似`192.168.130.1/32`的位址存取 Web 介面，而您自己的網路則使用`192.168.1.0/24` 。

如果另一端不知道到達該單一位址的路由，也可以結合使用網路位址轉換（ NAT ）等技術。

### 安全外殼

要透過SSH, SSH存取OPNsense，需要透過「系統」‣「設定」‣「管理」進行配置。在「安全外殼」標題下，可以使用以下選項：

| **選項**|**描述** |

| 允許密碼登入 | 如果停用此功能，則需要為每個已取得安全性外殼存取權限的使用者設定授權金鑰。 |

| 監聽介面 | 僅接受來自選定介面的連線。留空則監聽全域介面。請謹慎使用。 |
|金鑰交換演算法 |用於產生每個連線金鑰的金鑰交換方法 |
| 密碼 | 用於加密連線的密碼 |

|公鑰簽章演算法|用於公鑰認證的簽章演算法|

### 安全殼 - 進階設置

若要設定GUI中未提供的選項，可以在防火牆本身上新增自訂設定檔。可以使用`.conf`檔案副檔名在`/usr/local/etc/ssh/sshd_config.d/`中新增檔案。當目錄中放置多個檔案時，它們將按字母順序排列。自訂設定檔會優先包含，以便對系統通常設定的選項進行適當的覆寫。

警告

管理員有責任確保配置有效。系統不會執行任何設定檢查，任何錯誤都可能導致您無法遠端登入防火牆！

## 克朗

[Cron](https://en.wikipedia.org/wiki/Cron)是一項用來定期執行任務的服務。您可以透過導覽至「系統」‣「設定」‣「Cron」來查看 Cron 任務。您可以透過點擊右下角的`+`按鈕來新增任務。

當您新增任務或修改現有任務時，您會看到一些字段，這些字段直接反映了 cron 檔案的語法，而且大多含義顯而易見。一個任務需要包含名稱、命令、命令參數（如果適用）、描述（可選，但建議填寫）以及最重要的規劃任務。所有與時間相關的欄位都使用相同的語法：

-   星號（*）可以用來表示“任意”
    
-   可以使用逗號指定多個值： `1,4,9`
    
-   可使用短橫線指定範圍： `4-9`
    

可用的定時任務已在後端註冊，以防止命令注入和權限提升。這些任務可以在“命令”下找到，並可能使用可選參數。重啟和重新載入操作顧名思義，它們通常不接受任何參數，會重啟（通常是進程的停止和啟動，速度較慢）或重新加載（通常是速度較快的SIGHUP ）相應的服務。重新啟動和重新載入的可用性取決於各自的服務，因為出於實現方面的原因，並非所有軟體都支援重新載入。

最常用的核心指令如下：

| GUI中的指令 | shell 中的指令 | 支援的參數 | 背景資訊 |
| --- | --- | --- | --- |
| 自動韌體更新 | configctl firmware auto-update | 不適用 | 如有必要，請執行小版更新。 |
| 下載並重新載入外部代理程式 ACL | configctl proxy fetchacls | 不適用 | 取得並啟動已設定黑名單的外部ACL檔。 |
| 韌體變更日誌更新 | configctl firmware changelog cron | 不適用 | 從權威韌體位置重新整理目前變更日誌狀態，以預覽新版本的變更日誌。請注意，此操作使用 25 分鐘的延遲間隔，並且韌體更新檢查也會執行此操作。 |
| 韌體更新檢查 | configctl firmware poll | 不適用 | 從韌體映像刷新目前更新狀態，例如透過API進行遠端狀態檢查。請注意，此操作使用 25 分鐘的延遲間隔。 |
| HA更新並重新配置備份 | configctl system ha\_reconfigure\_backup | N/A | 將設定同步到備份防火牆並重新啟動其服務以套用變更。 |
| 停止並關閉系統電源 | configctl system halt | N/A | 在指定時間執行關機操作。 |
|手動網關開關| configctl 介面路由警報 |不適用 |如果適用，請執行手動網關切換。故障的網關監視器也將重新啟動 |
| 定期重置介面 | configctl interface reconfigure \[標識符] | 識別碼：介面的內部名稱，如分配或概覽頁面中所示，例如「lan」、「wan」、「optX」。 | 循環執行介面重置，該重置會移除所有連接並乾淨地重新啟動介面。 |
| 重新啟動系統 | configctl system reboot | N/A | 在指定時間執行重新啟動。 |
| 遠端備份 | configctl system remote backup | N/A | 在指定時間觸發遠端備份，而不是預設的夜間備份。 |
| 重新啟動 OpenVPN 實例 | configctl openvpn restart | 實例： UUID | 重新啟動指定的 OpenVPN 實例。 |
| 更新並重新載入URL別名 | configctl filter refresh\_aliases | 不適用 | 更新IP條目和DNS位址的別名以及MAC表。 |
| 更新並重新載入入侵偵測規則 | configctl ids update | 不適用 | 取得遠端規則並重新載入IDS實例以使用新取得的規則。 |
| 更新 Unbound DNSBL | configctl unbound dnsbl | N/A | 更新DNS黑名單並將更改套用到 Unbound。 |
| ZFS池修剪 | configctl zfs trim \[pool\] | pool: ZFS要執行操作的池名稱 | 對池中的所有可用空間立即啟動按需TRIM操作。此操作會通知底層儲存設備池中所有不再指派的區塊，並允許精簡配置的設備回收空間。 |
| ZFS池清理 | configctl zfs scrub \[池\] | 池： ZFS要執行操作的池名稱 | 開始清理或恢復已暫停的清理。清理操作會檢查指定池中的所有數據，以驗證其校驗和是否正確。對於複製（鏡像、RAIDZ 或 DRAID）設備， ZFS會自動修復清理過程中發現的任何損壞。 |

## 可調參數

可調參數是指寫入`loader.conf`和`sysctl.conf`檔案的設置，用於調整底層系統設定。可透過「系統」‣「設定」‣「可調參數」進行設定。

在這裡，您可以查看當前啟動的設定並建立新的設定。在 OPNsense shell 中執行`sysctl -a`指令可以取得可用值清單。根據引導程式的功能和核心模組支援情況，可能還有其他可調參數。

## 日誌記錄

本機日誌設定位於「系統」‣「設定」‣「日誌記錄」標籤「本機」。

常規日誌檔案將使用以下標準模式儲存在磁碟上`/var/log/<application>/<application>_[YYYYMMDD].log` （每天一個檔案）。我們的使用者介面提供了一個整合視圖，將所有收集的文件拼接在一起。根據空間和日誌輪換的時間限制，可用的設定可能會改變磁碟上的顯示方式。

許多插件都有自己的日誌。在UI中，這些日誌與插件的設定一起分組。它們大多以文字格式記錄到 /var/log/ 目錄下，因此您可以使用 *tail* 命令查看或追蹤這些日誌。

本地設定概覽：

| **選項**|**描述** |
| --- | --- |
| 啟用本機日誌記錄 | 為避免快閃記憶體損耗，請在適用情況下停用本機日誌記錄，並改用遠端日誌記錄。 |
| 最大保留檔案數 | 設定日誌保留的天數，或如果使用了「最大檔案大小」選項，則設定檔保留數量。 |
| 最大檔案大小 | 限制日誌檔案的大小，而不是每天只保留一個日誌檔案。 |

提示

當使用（非常）小的檔案大小限制時，可以使用 cron（系統 ‣ 設定 ‣ Cron）更頻繁地安排輪換操作。在這種情況下，請在清單中尋找名為`Rotate log files`的操作。

遠端日誌設定位於「系統」‣「設定」‣「日誌記錄」標籤「遠端」。

*新增*新的*目的地*以設定遠端目標目的地。

| **選項**|**描述** |
| --- | --- |
|已啟用 |主開關。 |
|交通 |用於系統日誌的協議。 |
| 應用程式 | 選擇要傳送到遠端系統日誌的應用程式清單。留空則表示發送*所有*應用程式。 |
| 級別 | 選擇要包含的級別，省略則選擇全部級別。 |
| 設施 | 選擇要包含的設施，省略則選擇全部設施。 |
| 主機名稱 | 日誌傳送到的主機名稱或IP位址。 |
| 端口 | 要使用的端口，通常為 514。 |
| 憑證 | 要使用的用戶端憑證（選擇 TLS 傳輸類型時） |
| 描述 | 為您自己新增描述。 |

注意事項

使用TLS介面的 syslog 時，請確保兩端配置正確（憑證和主機名稱），並且憑證錯誤在此類設定中相當常見。在 OPNsense 上，系統日誌通常包含更多詳細資訊。要追蹤 syslog-ng 訊息，[此](https://support.oneidentity.com/kb/263658/common-issues-of-tls-encrypted-message-transfer)通常是一個很好的資源。

重新配置並不總是能立即應用新的 TLS 設置，如果不是這種情況，最好在 OPNsense 中停止並啟動 syslog（使用圖形使用者介面）。

要啟動任何已更改的設置，請使用下面的“應用”按鈕。

若要清除系統上的所有日誌，請使用「重設日誌檔案」按鈕。
