# 使用 Git 追蹤配置更改

> 章節：[System](<000 目錄.md#c-11>) › [Configuration](<000 目錄.md#c-14>) › [Backup](<000 目錄.md#c-15>)

當尋求解決方案以保持（各個）使用者在防火牆上所做的配置變更的完全可追溯性時，git-backup 外掛程式可能是您設定中的一個有用的補充。

為了使用此功能，必須先安裝 git-backup 外掛程式（在「系統」->「韌體」->「外掛程式」中搜尋 os-git-backup）。

## 概念

由於 git backup 與可用的標準備份選項略有不同，我們將使用下圖簡要解釋它的工作原理。

[![](<../images/7f30c196-blockdiag-781a27354f8d416f4a73d6e6f57110.png>)](https://docs.opnsense.org/_images/blockdiag-781a27354f8d416f4a73d6e6f57110c50393f97c.png)

當因使用者或 api 互動而發生 `config.xml` 變更時，會觸發處理程序可以訂閱的事件（使用 [syshook](<245 開機自動運轉選項.md>)）。我們的 git-backup 外掛程式訂閱這些事件，以便新增收到的備份，並使用從收到的 xml 檔案中提取的資訊提交這些備份。為了防止系統在備份過程中鎖定，我們選擇這種鬆散耦合的方法。尚未處理的事件將保留在（現有）備份目錄中。

注意事項

事件從配置初始備份的那一刻起進行處理，停用備份時，（本地）變更日誌本身會保持活動狀態。

Git 備份將每晚將收集的提交推送到上游儲存庫。若要縮短此預設間隔，可以設定自訂 cronjob（請參閱[設定](<98 設定.md>)），選擇遠端備份作為指令。常規備份過程（也使用使用者介面中的測試按鈕觸發）負責初始化空的本機儲存庫並配置上游目標。

注意事項

人們總是可以更改上游目標，只要新配置的目標要么是空的（絕對沒有歷史記錄 - 換句話說，是一個新的，絕對未受影響的），要么具有與此防火牆上使用的歷史記錄完全相同的歷史記錄（否則說，是一個精確的副本，包括 git 歷史記錄）。

## 初始設定

該外掛程式的配置部分非常基礎，提供兩種傳輸模式：使用使用者名稱和密碼組合的 https 或使用公鑰基礎架構的 ssh。

---

|   |   |
| --- | --- |
| 啟用 | 啟用備份到上游目標 |
| URL |目標位置，定義了傳輸協議，此處允許使用 [ssh://server/project.git](ssh://server/project.git) 或 [https://server/project.git](https://server/project.git) 等選項。 |
|分公司|將您的提交推送到配置的 url 上的分支 |
| SSH 私鑰 |使用ssh時，請務必在此處新增私鑰 |
|用戶名 |用戶名，當使用gitlab和ssh時，這裡預設是`git`（這些提供者大多數使用單一用戶並透過其金鑰識別用戶）|
|密碼 |使用 https 驗證時，請在此選擇密碼。 |
|強力推 |啟用強制推送以使用本地狀態覆蓋遠端儲存庫。有關詳細信息，請參閱下面的“衝突解決”。 |

確保推送到空的（例如，新的且從未使用過的）上游儲存庫，當按下「設定/測試 Git」時，初始提交應發送到您的 git 伺服器。

## SSH 設定

如果您使用 GitHub，那麼 git-backup 的唯一選擇是將其配置為 SSH 存取權限，因為 GitHub 已刪除外部應用程式透過您的使用者名稱和密碼登入您的帳戶的功能。

OPNSense 中`System / Configuration / Backups / Git` 下的欄位應包含以下內容：

-   URL絕對MUST使用GitHub和GitLab時請遵循以下格式：`ssh://github.com/user_name/repo_name.git`。任何不遵循此模式的 URL 字串都將無法運作。
    
-   SSH 私鑰（下面討論）
    
-   使用者名稱應ONLY包含單字`git`
    
-   密碼：將此欄位留空
    

您需要建立儲存庫BEFORE，啟用 git-backup。不要將任何文件或自述文件新增至儲存庫。換句話說，建立一個 BLANK 儲存庫。

接下來，[建立一個新的 SSH 金鑰](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent) 專門用於 git-backup（僅根據該文件產生私鑰/公鑰並跳過其餘部分）。 **請勿在金鑰中新增密碼**，否則您的備份將因身份驗證錯誤而失敗。

您應該透過將 SSH 公鑰指派給儲存庫來設定對儲存庫的 SSH 存取權限，而不是將其指派給您的 GitHub / GitLab 帳戶。這樣做可以確保您不會隨意向 OPNSense 暴露過多的 git 資源，而這些資源是 git-backup 正常工作所必需的。

如果您使用 GitHub，則可以透過前往儲存庫來新增您的 SSH 公鑰，然後按一下 `settings`，然後按一下 `Deploy keys`。或者您可以使用以下格式直接轉到URL：`https://github.com/USER_NAME/REPOSITORY_NAME/settings/keys/new`。

-   選取方框`Allow write Access`。
    

確保如上所述填充欄位並選取「啟用」框，然後按一下`Setup / Test Git`，您應該會在頁面頂部看到一條訊息，指示第一次備份已成功。

提示

當選擇一個不存在的遠端分支時，將自動建立一個。現有的儲存庫需要為空才能使用它，這實際上只有在第一次建立儲存庫時才有可能。

## 衝突解決

從使用者介面中不提供衝突解決方案，您需要配置上游儲存庫並在防火牆的生命週期內堅持使用它。當由於某種原因需要恢復備份並且希望堅持使用同一個 git 儲存庫時，手動解決衝突可能是一種選擇。不提供對這些場景的支援。

此儲存庫位於 OPNsense 電腦上的以下目錄`/conf/backup/git` 中。

注意事項

衝突解決可能會使解決方案變得更加複雜（合併、快轉…），因此我們不會接受嘗試推送到現有（已使用）儲存庫的功能請求。

### 使用力推

當本地和遠端儲存庫不同時（例如透過GUI恢復配置後），同步將失敗，並出現 **git out ofsync** 錯誤。強制推送選項可用於透過使用本機儲存庫狀態覆蓋遠端來解決此問題。

警告

強制推送會以本地狀態永久覆蓋遠端儲存庫歷史記錄。任何遠端存在但不在本地的提交都將丟失。

要解決分歧：

1.  導覽至系統 ‣ 設定 ‣ 備份 ‣ Git
    
2.  啟用**強制推送**選項
    
3.  點選 **Setup/Test Git** 推送目前狀態
    
4.  （可選）停用**強制推送**並再次點擊**設定/測試 Git** 以驗證正常操作
    

強制推送選項也可以永久啟用，以確保遠端始終反映本地狀態。

對於手動衝突解決，請存取 `/conf/backup/git` 中的儲存庫並使用標準 git 命令。

## 錯誤處理

發生錯誤時，這些錯誤將寫入正常系統日誌記錄，在常規系統日誌記錄中搜尋`git-backup`（系統 -> 日誌檔案 -> 常規）。

一些標準錯誤可能會透過測試按鈕返回，這應該提供明確的方向，已知的錯誤是：

-   **身份驗證失敗** -> 使用者名稱/密碼組合無效或提供的 ssh 金鑰與預期的不匹配
    
-   **ssh 主機金鑰已更改** -> 看起來像是發生了中間人攻擊，如果情況並非如此，並且遠端標識因正當原因發生更改，則需要手動幹預（從`/root/.ssh/known_hosts` 中刪除攻擊性金鑰）
    
-   **git 不同步** -> 無法同步，請參閱「衝突解決」以取得更多資訊。
    

## 清理

該儲存庫本地保存在`/conf/backup/git`的防火牆上，如果由於某種原因想要刪除收集的歷史記錄並從頭開始，可以安全地刪除此目錄。

使用 (ssh) 控制台登入並刪除 git 目錄(`rm -rf /conf/backup/git`)

注意事項

只要安裝了外掛程式且 /conf/backup/git 包含 git 儲存庫，變更就會被擷取（也沒有上游）。人們還可以利用這項知識，透過建立儲存庫而不分配上游並停用備份選項來保留本機（唯一）儲存庫。

提示

防火牆包含最近變更的本機備份（在「系統」->「配置」->「歷史記錄」中配置），配置變更事件處理程序使用該備份將其提供給使用者。如果在清理之後想要將收集到的變更再次刷新到上游提供程序，則可以刪除 `/conf/event_config_changed.json` 以「忘記」已處理的設定事件（在這種情況下，所有備份將再次向所有配置 syshook 處理程序發出訊號）
