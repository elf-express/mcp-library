Dnsmasq 是一個輕量級且易於設定的 DNS 轉發器和 DHCPv4/DHCPv6 伺服器。

它被認為是中小型設定中 ISC-DHCP 的替代品，並且與我們標準啟用的轉發/解析器服務 Unbound DNS 具有良好的協同作用。

我們的系統設定精靈為 DNS 設定 Unbound DNS，並為 DHCPv4、DHCPv6 和路由器通告設定 Dnsmasq。

## [部署前註意事項](#id2)

### [DNS服務](#id3)

Dnsmasq 可以與 Unbound 結合起來充當“連接器”，在這種情況下，在 Dnsmasq 中註冊主機名的DHCP 租約可以直接由 Unbound 查詢。

由於 Dnsmasq 不會在配置變更時重新啟動，並且不需要自訂腳本來註冊DNS，因此它非常有彈性且易於管理。

注意事項

Unbound是遞迴解析器，Dnsmasq是一個非遞迴轉送DNS伺服器。這意味著 Dnsmasq 始終需要一個可以將查詢轉送到的遞歸 DNS 解析器。這可以是未綁定的，也可以是網路上的其他DNS服務。

在下面的設定範例中，我們始終將 Unbound 與 Dnsmasq 結合。

### [DHCP服務](#id4)

Dnsmasq 是適合中小型設定（少於 1000 個唯一客戶端）的完美 DHCP 伺服器。配置非常簡單，而且由於它可以註冊租約的DNS名稱，因此它可以複製消費者路由器的簡單性。

如果需要 HA for DHCP，則可以為兩個 Dnsmasq 執行個體配置拆分池。透過 dhcp 回復延遲，輔助實例將僅在第一個實例無回應時進行應答。 DHCPv6 和路由器通告也是沒有快速故障轉移要求的小型HA 設定的選項，因為使用可用的設定選項，IPv6 故障轉移可能需要長達 30 秒。

對於大型企業設置，KEA DHCP 可能是可行的替代方案。它支援透過REST API進行租約同步，這意味著兩個DHCP伺服器都會追蹤所有現有租約，並且不需要拆分池。如果有數千個租賃，它的可擴展性也會大大提高。

使用 KEA DHCP 的權衡是一個更複雜的設置，特別是當需要自訂 DHCP 選項時。 DNS 也無法註冊。

考慮到這一點，請為您的設定選擇正確的選擇。如有疑問，我們的建議是使用 Dnsmasq。

注意

有 DHCPv6 和路由器通告支援。請記住，就像 DHCPv4/DHCPv6 伺服器一樣，在同一系統上不應執行多個路由器通告伺服器。現在，服務 ‣ 路由器通告是預設的 RA 守護程式。如果您不確定，請不要在 Dnsmasq 中啟用它們。

## [常規設定](#id5)

當服務啟用時，這裡的大多數設定都非常簡單，它應該在從網路接收到 DNS 請求時開始轉送。 DHCP 需要至少一個 dhcp-range 和匹配的 dhcp-options。

提示

-   若要停用DNS功能，請將監聽埠設定為`0`。
    
-   若要停用 DHCP 功能，請在介面 \[no dhcp\] 中選擇介面。

| **選項**|**描述** |
| --- | --- |
| **啟用** |啟用 Dnsmasq。 |
| **介面** |用於回應客戶端查詢的介面 IP。如果介面同時具有 IPv4 和 IPv6 IP，則同時使用兩者。對下面未選擇的其他介面 IP 的查詢將被丟棄。預設行為是回應每個可用 IPv4 和 IPv6 位址的查詢。 |
| **嚴格的介面綁定** |預設情況下，我們綁定通配符位址，即使在偵聽某些介面時也是如此。不應該處理的請求將被丟棄，這樣做的優點是即使介面來來去去並更改地址也能正常工作。此選項強制僅綁定到我們正在偵聽的接口，這在非靜態環境中不太穩定。 |

| **DNSSEC** |啟用DNSSEC。 |
| **沒有主機尋找** |不要讀取 /etc/hosts 中的主機名稱。 |

**DNS查詢轉發**

| **選項**|**描述** |
| --- | --- |
| **依序查詢DNS伺服器** |如果設定了此選項，我們將按照指定的順序依序查詢DNS伺服器（系統：常規設定：DNS伺服器），而不是一次並行查詢。 |
| **需要網域名稱** |如果設定此選項，我們不會將不帶點或網域部分的普通名稱的 A 或 AAAA 查詢轉送到上游名稱伺服器。如果從 /etc/hosts 或 DHCP 無法獲知該名稱，則傳回「未找到」答案。 |
| **請勿轉寄至系統定義的DNS** |如果設定此選項，DNS 轉送至系統名稱伺服器（在系統：常規設定：DNS 伺服器中定義）將被停用。服務中定義的上游伺服器：Dnsmasq DNS & DHCP：仍將使用網域。當 Unbound 將本地網域查詢轉送至 Dnsmasq 時，建議使用此選項，以便所有查詢在未知時終止，而無需進一步查找。 |
| **不轉送私人反向查找** |如果設定此選項，我們不會將私人位址 (RFC 1918) 的反向 DNS 尋找 (PTR) 轉送到上游名稱伺服器。在網域覆蓋部分中將私有「n.n.n.in-addr.arpa」名稱轉送至特定伺服器的任何項目仍會被轉送。如果從 /etc/hosts、DHCP 或特定網域覆寫中無法得知 IP 名稱，則立即傳回「未找到」答案。 |
| **新增MAC** |將請求者的MAC位址加入到向上游轉送的DNS查詢中。只有當上游 DNS 伺服器與請求者位於同一子網路時，才會新增 MAC 位址。由於這不是標準化的，因此應被視為實驗性的。這對於上游 DNS 伺服器上的選擇性 DNS 過濾非常有用。 |
| **新增子網路** |將真實用戶端 IPv4 和 IPv6 位址 (add-subnet=32,128) 新增至上游轉送的DNS 查詢。請小心設定此選項，因為它可能會破壞隱私。這對於上游 DNS 伺服器上的選擇性 DNS 過濾非常有用。 |
| **剝離子網** |剝離下游DNS伺服器接收到的子網路。如果使用add\_subnet且下游DNS伺服器已經新增了子網，則DNSMasq不會在不設定strip\_subnet的情況下取代它。 |

**DHCP**

| **選項**|**描述** |
| --- | --- |
| **介面\[無 dhcp\]** |不要在指定介面上提供DHCP, TFTP或路由器通告，但提供DNS服務。 |
| **DHCP fqdn** |在預設模式下，我們將DHCP客戶端的非限定名稱插入到DNS中，在這種情況下它們必須是唯一的。使用此選項，非限定名稱不再放入DNS，僅放入限定名稱。 |
| **DHCP 預設網域** |為了確保所有名稱都有網域部分，設定 dhcp-fqdn 時必須指定預設網域。留空以使用系統域。 |
| **DHCP 最大租約** |將 dnsmasq 限制為指定的最大 DHCP 租約數量。此限制是為了防止來自創建數千個租約並在 dnsmasq 進程中使用大量記憶體的主機的 DoS 攻擊。 |
| **DHCP權威** |當 dnsmasq 絕對是網路上唯一的 DHCP 伺服器時應該設定。對於 DHCPv4，它改變了嚴格 RFC 合規性的行為，以便不會忽略來自未知主機的未知租約的 DHCP 請求。 |
| **DHCP 回覆延遲** |延遲發送 DHCPOFFER 和 PROXYDHCP 回覆至少指定的秒數。這對於拆分DHCP解決方案非常實用，以確保輔助伺服器的回應速度比主伺服器慢。 |
| **DHCP 註冊防火牆規則** |自動註冊防火牆規則以允許所有明確選擇的介面的DHCP流量，如果需要，可以停用以進行更細粒度的控制。 |
| **路由器廣告** |設定此項目將為所有配置的 DHCPv6 範圍啟用路由器通告，並設定託管位址位，並使用SLAAC位重設。若要變更此預設值，請在各個 DHCPv6 範圍中選擇可能選項的組合。請記住，這是一個全域選項；如果配置了 DHCPv6 範圍，則將無條件發送 RA，並且無法選擇性停用。如果不啟用此全域選項，在 DHCPv6 範圍中設定路由器通告模式將無法運作。 |
| **停用 HA 同步** |忽略使用 HA 同步更新的 DHCP 常規設定。 |
| **記錄DHCP選項和標籤** | DHCP 的額外日誌記錄，記錄發送到 DHCP 客戶端的所有選項以及用於確定它們的標籤。 |
| **安靜的日誌訊息** |禁止記錄DHCP, RA和TFTP的日常操作。錯誤和問題仍將被記錄。 |

## [DNS設定](#id6)

**主機（主機覆蓋）**

| **選項**|**描述** |
| --- | --- |
| **主持人** |主機名稱，不含網域部分。使用“\*”建立通配符條目。 |
| **域名** |主機的域名，例如範例.com |
| **本地** |將上述網域設定為本機。這會將這個DNS伺服器配置為權威伺服器；它不會將查詢轉送到該網域的任何上游伺服器。 |
| **IP 位址** | IP 主機位址，例如192.168.100.100 或 fd00:abcd::1。可以是用於雙堆疊配置的多個 IPv4 和 IPv6 位址。設定多個位址將根據接收DHCP Discover 的介面的子網路自動分配最佳匹配。 |
| **別名記錄** |為給定的備用名稱 (FQDN) 新增額外的靜態 A、AAAA 和 PTR 記錄。請注意，只有在此主機條目中配置了IP位址時才會建立這些記錄。 |
| **CNAME 記錄** |為給定的備用名稱 (FQDN) 新增額外的 CNAME 記錄。如果此主機條目具有動態 IPv4 和部分 IPv6 位址，則很有用，因為 CNAME 記錄將指向名稱而不是靜態 IP 位址。 |
| **客戶標識符** |符合客戶端的標識符，例如 DHCPv6 的DUID。如果用戶端同時提供兩種選擇，則設定特殊字元「\*」將忽略 DHCPv4 租約的用戶端識別碼。 |
| **硬體位址** |符合客戶端的硬體位址。可以是多個位址，例如，如果客戶端有多個網路卡。但請記住，當多個同時發送DHCP發現時，Dnsmasq 無法假設哪個位址是正確的。 |
| **租賃時間** |定義伺服器所發出的位址（租約）的有效時間（以秒為單位）。將 `0` 設定為無限。 |
| **標籤\[設定\]** |為符合此範圍的請求設定選用標籤，可用於選擇性地比對DHCP選項。 |
| **忽略** |忽略該主機的任何DHCP封包。如果它應該由不同的 DHCP 伺服器提供服務，則很有用。 |
| **描述** |您可以在此輸入描述以供參考（未解析）。 |
| **評論** |您可以在此輸入描述以供參考（未解析）。 |

注意事項

設定域和IP位址後，將建立主機覆蓋。如果設定了客戶端標識符或硬體位址，則會建立額外的靜態DHCP預留。

**域（域覆蓋）**

| **選項**|**描述** |
| --- | --- |
| **順序** |使用序號排序，例如，使用「嚴格順序」選項時嚴格處理順序。 |
| **網域** |要涵蓋的網域（NOTE：這不必是有效的TLD！）。 |
| **IP位址** | IP 該網域的權威DNS 伺服器位址，留空以防止尋找該網域。 |
| **港口** |此處指定非標準連接埠號，預設為空。 |
| **來源IP** |用於查詢覆蓋域的 DNS 伺服器的來源 IP 位址。最好留空。 |
| **防火牆別名** |從「防火牆 - 別名」選擇「外部（進階）」類型別名。每當客戶端成功解析域時，解析的IP位址將自動加入到所選別名中。新增域還將新增已解析子域的所有 IP 位址。請注意DNS記錄TTL不被評估；一旦新增IP位址，它將永久保留，或直到在「防火牆 - 診斷 - 別名」中手動刷新，或直到在別名設定到期時自動刪除。 |
| **描述** |您可以在此輸入描述以供參考（未解析）。 |

注意事項

在 Services ‣ Dnsmasq DNS & DHCP ‣ General 中依序選擇 Query DNS 伺服器將強制執行嚴格的順序。為了使處理順序正常工作，覆蓋必須配置完全相同，例如匹配相同的域和連接埠。 IP 地址可以不同。

## [DHCP設定](#id7)

**DHCP範圍**

| **選項**|**描述** |
| --- | --- |
| **介面** |服務於該範圍的介面。 |
| **標籤\[設定\]** |為符合此範圍的請求設定選用標籤，可用於選擇性地比對DHCP選項。 |
| **起始位址** |範圍的開始，例如192.168.1.100 對於 DHCPv4，2000::1 對於 DHCPv6 或當構造函數使用 ::1 等後綴時。若要顯示 IPv6 相關選項，請輸入 IPv6 位址。使用路由器通告時，可以使用以 :: 作為起始位址且沒有結束位址的建構函式。 |
| **結束位址** |範圍結束。 |
| **子網路遮罩** |留空可從介面或起始位址的網路類別自動計算子網路遮罩。如果DHCP中繼將IPv4DHCP發現轉送到Dnsmasq，大多數情況下需要設定子網路遮罩。 |
| **建構函數** |用於計算正確範圍的接口，選擇後，可以將範圍指定為部分範圍（例如::1、::400）。 |
| **前綴長度 (IPv6)** |提供給客戶端的前綴長度。如果啟用了路由器通告，則此欄位中的自訂值將被忽略，如下所示 SLAAC 僅適用於前綴長度 64。
| **RA 模式** |控制 IPv6 用戶端接收其位址的方式。在常規設定中啟用路由器通告將為所有配置的 DHCPv6 範圍啟用它，並設定託管位址位，並使用 SLAAC 位重置。若要變更此預設值，請在此處選擇可能選項的組合。 「slaac」、「ra-stateless」和「ra-names」可以自由組合，所有其他選項應保持單一選擇。 |
| **RA 優先** | RA公告的優先順序。 |
| **RA MTU** |可選的MTU透過路由器通告傳送給客戶端。如果不確定，請留空。 |
| **RA 間隔** |路由器通告之間的時間（秒）。 |
| **RA 路由器使用壽命** |路由的生命週期可以更改或設定為零，這允許路由器通告前綴，但不能透過自身通告路由。使用HA時，建議在此處設定較短的時間跨度，以實現更快的 IPv6 故障轉移。一個好的組合可以是 10 秒 RA 間隔和 30 秒 RA 路由器生命週期。低於該值可能會在繁忙的網路中造成問題。 |
| **模式** |為此範圍設定的模式標誌，「靜態」表示不會自動指派位址。 |
| **租賃時間** |定義伺服器所發出的位址（租約）的有效時間（以秒為單位）。設定`0`為無窮大；請小心，因為這可能會耗盡池中的水。 |
| **網域類型** |選擇網域是否僅符合此範圍內的用戶端，或所選介面上任何子網路中的所有用戶端。如果您同時建立 IPv4 和 IPv6 範圍，建議在這兩個範圍上將其設定為「介面」。 |
| **網域名稱** |提供此範圍內的電腦指定的網域。 |
| **停用HA同步** | HA 同步傳輸或更新時忽略此範圍。 |
| **描述** |您可以在此輸入描述以供參考（未解析）。 |

**RA 模式**

| **模式**|**M位元**|**O-位元**|**一點**|**預設路線**|**DHCPv6**|**SLAAC** |
| --- | --- | --- | --- | --- | --- | --- |
| **預設** | 1 | 1 | 0 |廣告|有狀態|沒有|
| **僅限 ra** | 0 | 0 | 0 |廣告|沒有|沒有|
| **斯拉克** | 1 | 0 | 1 |廣告|兩者 |是的 |
| **ra-無狀態** | 0 | 1 | 1 |廣告|無國籍|是的 |

這就是 RA 標誌（位）的意思：

-   `M` - 託管位址配置：
    
    用戶端應使用有狀態 DHCPv6 來取得 IPv6 位址（以及隱式的 `O` 資訊）。
    
-   `O` - 其他配置：
    
    客戶端應使用 DHCPv6 來取得其他資訊（例如，DNS 伺服器、網域）。
    
-   `A` - 自主位址配置：
    
    用戶端可以使用SLAAC根據通告的前綴自行分配IPv6位址。
    

提示

## [設定範例](#id9)

### [具有 DNS 註冊的 DHCPv4](#id10)

Dnsmasq 可用作 DNS 轉發器。儘管在我們推薦的設定中，我們不會將其用作預設的DNS伺服器。

我們將使用 Unbound 作為客戶端的主要 DNS 伺服器，並且僅將一些內部區域轉送到管理 DHCP 註冊租約的主機名稱的 Dnsmasq。

這要求 Dnsmasq 使用 53 以外的非標準連接埠運行。

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ General 並設定：
    

|選項|價值|
| --- | --- |
| **啟用** | `X` |
| **監聽埠** | `53053` |

-   按**申請**
    

之後我們可以設定 Unbound 將區域轉送到 Dnsmasq。

-   進入服務‣解除綁定DNS‣常規並設定：
    

|選項|價值|
| --- | --- |
| **啟用** | `X` |
| **監聽埠** | `53` |

-   按**申請**
    
-   前往 Services ‣ Unbound DNS ‣ Query Forwarding 並為您計劃配置的每個 DHCP 範圍建立一個條目。
    

在我們的範例中，我們為 2 個網路設定查詢轉送：

> -   `lan.internal` - `192.168.1.0/24`
>     
> -   `guest.internal` - `192.168.10.0/24`
>     

**區域網路內部**

|選項|價值|
| --- | --- |
| **網域** | `lan.internal` |
| **伺服器IP** | `127.0.0.1` |
| **伺服器連接埠** | `53053` |

-   按**儲存**並新增下一個
    

|選項|價值|
| --- | --- |
| **網域** | `1.168.192.in-addr.arpa` |
| **伺服器IP** | `127.0.0.1` |
| **伺服器連接埠** | `53053` |

-   按**儲存**並**應用**
    

注意事項

第一個條目用於正向查找（A-Record），第二個條目用於反向查找（PTR-Record）。

提示

如果 192.168.0.0/16 的所有 PTR 記錄都應由 Dnsmasq 處理，則使用 `168.192.in-addr.arpa` 建立單一條目就足夠了。

**訪客.內部**

|選項|價值|
| --- | --- |
| **網域** | `guest.internal` |
| **伺服器IP** | `127.0.0.1` |
| **伺服器連接埠** | `53053` |

-   按**儲存**並新增下一個
    

|選項|價值|
| --- | --- |
| **網域** | `10.168.192.in-addr.arpa` |
| **伺服器IP** | `127.0.0.1` |
| **伺服器連接埠** | `53053` |

-   按**儲存**並**應用**
    

注意事項

`.internal`是IANA和ICANN批准的TLD（頂級網域）供內部使用。如果您擁有 TLD，例如 `example.com`，您可以建立一個不在網路上使用的區域，例如 `lan.internal.example.com`。

現在我們已經設定了DNS基礎設施，我們可以設定DHCP。

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ General 並設定：
    

|選項|價值|
| --- | --- |
| **介面** | `LAN, GUEST`（將為DHCP服務的網路接口，這會註冊防火牆規則）|
| **不要轉送到系統定義的DNS伺服器** | `X`（除非在 Dnsmasq: Domains 中指定了 Domains，否則這將停用轉送行為）|
| **DHCP fqdn** | `X` |
| **DHCP 預設域** | `internal`（或留空以使用本系統的域）|
| **DHCP 註冊防火牆規則** | `X` |

注意事項

**DHCP fqdn** 會做兩件事：

-   確保所有設備都在DNS中註冊，並附加配置的域名，例如`smartphone.lan.internal`。這確保了`smartphone`可以同時存在於`lan.internal`和`guest.internal`中。
    
-   將 DHCP 網域註冊為本地，這將使 Dnsmasq 對該網域具有權威性，確保在此本地域內查詢未知主機名的裝置返回 `NXDOMAIN`。
    

-   按**申請**
    

下一步，我們為介面定義 DHCP 範圍。

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ DHCP 範圍並設定：
    

**LAN**

|選項|價值|
| --- | --- |
| **介面** | `LAN` |
| **起始位址** | `192.168.1.100` |
| **結束網址** | `192.168.1.199` |
| **域名** | `lan.internal` |

-   按**儲存**並**應用**
    

注意事項

如果主機從該範圍接收DHCP租約，並且它通告主機名，則它將在所選網域下註冊。例如，名為 `nas01` 的主機將變為 `nas01.lan.internal`。客戶端可以查詢此FQDN以接收目前的IP位址。

注意

如果您打算透過建構函式使用範圍內的部分 IPv6 位址，請啟用進階模式並將 **Domain Type** 設定為 `Interface`。這會將所選介面上的所有子網路註冊到所選域。當 IPv6 前綴是動態時，這是動態 DNS 註冊成功的唯一方法。

**GUEST**

|選項|價值|
| --- | --- |
| **介面** | `GUEST`|
| **起始位址** | `192.168.10.100` |
| **結束網址** | `192.168.10.199` |
| **網域** | `guest.internal` |

-   按**儲存**並**應用**
    

提示

建立DHCP範圍將自動向請求客戶端發送常見的DHCP選項，而無需明確配置它們。

這是一個不完整的概述，重點介紹了一些預設的 DHCP 選項：

| DHCP 選項 |預設|描述 |
| --- | --- | --- |
|路由器\[3\] |接收DHCP請求的介面的IPv4位址。 |客戶端應使用的預設閘道。在本例中為 OPNsense。 |
| dns 伺服器\[6\] |接收DHCP請求的介面的IPv4位址。 |客戶端應使用的DNS伺服器。在這種情況下，在 OPNsense 上未綁定。 |
|網域名稱\[15\] |在 DHCP 範圍內設定的域，如果沒有符合的則使用預設系統域。 |客戶端應使用的域名，用於在 DNS 查找中構造 FQDN 的短名稱 |
|客戶端 FQDN\[81\] |客戶端主機名稱和網域的組合，DDNS 註冊的結果。 |客戶端應使用的完全限定網域名稱。 |

注意事項

只有某些用例需要手動設定這些選項，例如，使用 CARP 進行高可用性設定時路由器和 dns 伺服器的 IPv4 位址。

注意

如果 Dnsmasq 未啟動，請檢查 ISC-DHCP 和 KEA DHCP 是否處於活動狀態，因為它們會阻止此 DHCP 伺服器所需的可綁定連接埠。檢查 Services ‣ Dnsmasq DNS & DHCP ‣ Log 中的錯誤訊息也是一個好主意。

現在設定已完成，DHCP和DNS將發生以下情況。

1.  新設備（例如智慧型手機）加入LAN網路並發送DHCP發現廣播。
    
2.  Dnsmasq 在連接埠 67 上接收此廣播，並以 DHCP 報價進行回應，其中包含可用的 IP 位址以及路由器\[3\] 和 dns-server\[6\] 的 DHCP 選項。
    
3.  裝置發送 DHCP 請求來請求可用的 IP 位址，並可能發送自己的主機名稱。
    
4.  Dnsmasq 確認該要求。
    

我們的智慧型手機現在具有以下IP配置：

-   IP 地址：`192.168.1.100`
    
-   預設網關：`192.168.1.1`
    
-   DNS 伺服器：`192.168.1.1`
    

同時，Dnsmasq 註冊智慧型手機的DNS主機名稱（如果存在）。由於我們在DHCP範圍內配置了FQDN選項和域，因此智慧型手機的名稱將為：`smartphone.lan.internal.`。

當客戶端查詢 Unbound 時 `smartphone.lan.internal.`，配置的查詢轉送將請求傳送到 DNS 伺服器負責 `lan.internal.` 這是我們設定的 Dnsmasq 監聽 `127.0.0.1:53053`. `Dnsmasq` 回應此查詢並將解析目前的 A 記錄 `smartphone.lan.internal.` 到 `192.168.1.100`，將此資訊發送到 Unbound，後者將回應發送回最初查詢的客戶端。

提示

您通常可以透過查詢來解析網路中的主機名，例如`smartphone`。這是有效的，因為客戶端系統認識到未使用FQDN，因此將使用從 Dnsmasq 收到的網域名稱作為請求後綴，將查詢轉換為`smartphone.lan.internal.`。

正如您所看到的，這是一個高度整合且簡單的設置，僅利用可用的 DHCP 和 DNS 標準，不涉及任何技巧。

### [DHCPv6 與路由器通告](#id11)

DHCPv6 和路由器通告可以與 DHCPv4 同時運行，只需指定另一個範圍即可。

注意

DHCPv6 沒有像 DHCPv4 那樣的路由器選項。若要將預設閘道推送到客戶端，您必須使用路由器通告。這可以使用 Dnsmasq 來完成，也可以透過不同的服務來完成，例如 Services ‣ Router Advertising。

在此範例中，我們將 DHCPv6 範圍和路由器通告新增至我們的 LAN 介面。以下配置設定無狀態 DHCPv6 和 SLAAC。這表示客戶端將使用SLAAC位址，但查詢其他 DHCPv6 選項，例如DNS 伺服器。

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ DHCP 範圍並設定：
    

|選項|價值|
| --- | --- |
| **界面** | `LAN` |
| **起始位址** | `::1000` |
| **結束網址** | `::2000` |
| **建構子** | `LAN` |
| **RA模式** | `slaac` |

當模式設定為`slaac`時，客戶端將產生一個SLAAC位址和一個附加的DHCPv6位址（有狀態DHCPv6）。如果用戶端只應產生 SLAAC 位址，請將模式設為 `ra-stateless`（無狀態 DHCPv6）。

注意

如果您對範圍使用建構函式和自訂網域，請啟用進階模式並將 **Domain Type** 設定為 `Interface`。這會將所選介面上的所有子網路註冊到所選域。否則，所有名稱都會回退到預設系統域。

最後一步，前往 Services ‣ Dnsmasq DNS & DHCP ‣ General 並啟用 `Router Advertisements`。

按 **應用** 啟動新配置。

提示

DNS 伺服器將透過 RDNSS 和 DHCPv6 選項自動發送。 IP 位址將是此防火牆。如果您想要變更此行為，請在 Services ‣ Dnsmasq DNS & DHCP ‣ DHCP options 中建立自己的 DHCPv6 選項

### [DHCP預訂](#id12)

DHCP 預留將始終為客戶端指派相同的 IPv4 和 IPv6 位址。

對於 IPv4 預留，應存在 DHCPv4 範圍。如果此 DHCPv4 範圍應僅提供預留服務，請將其設為靜態。

對於 IPv6 預留，必須設定 DHCPv6 範圍，將 `slaac` 設定為路由器通告選項。這會設定 A 位，以便用戶端可以產生SLAAC 位址並接收額外的 DHCPv6 租約。如果使用不同的路由器通告守護程序，請確保其在輔助模式下運作。

提示

預訂將保留某個範圍內的IP地址，這表示保留的IP將不會提供給動態客戶端。

像`192.168.1.100-192.168.1.199`這樣的動態範圍和`192.168.1.101`這樣的保留是有效的，不會有衝突。

預留也可以超出動態範圍，但不建議進行簡單設置，因為使用 dhcp-fqdn 的動態 dns 註冊將無法正常運作。

注意

預留不需要將範圍模式設定為靜態。它適用於特定用例，其中範圍不應為任何未知的動態客戶端提供服務。

注意事項

由於所有客戶端都會自動使用接收介面名稱配置標籤，因此帶有介面標籤的DHCP選項將自動匹配保留。

以下是DHCP預訂的一些範例。這假設我們已經為 `LAN` 和 `GUEST` 創建了範圍，如前面部分所述。

前往服務 ‣ Dnsmasq DNS & DHCP ‣ 主機

**IPv4**

|選項|價值|
| --- | --- |
| **主持人** | `smartphone`|
| **IP 地址** | `192.168.1.150` |
| **硬體位址** | `aa:bb:cc:dd:ee:ff` |

-   按**儲存**並**應用**
    

注意

在保留中設定網域對動態 dns 註冊沒有影響；它只會建立靜態主機覆蓋。

Dnsmasq 始終將主機與在匹配的 dhcp 範圍中配置的域結合。

這對於部分 IPv6 保留尤其重要，因為在動態 DNS 註冊完成之前無法解析它們。

-   按**儲存**並**應用**

硬體位址不適用於 IPv6 預留。它必須是設備唯一識別碼（DUID）。本例使用常見的DUID-LL類型。

提示

| **客戶識別碼** | `00:03:00:01:aa:bb:cc:dd:ee:ff` |
| **硬體位址** | `aa:bb:cc:dd:ee:ff` |

-   按**儲存**並**應用**
    

提示

這將 IPv4 和 IPv6 保留結合在相同設定項中。

### [適用於小型 HA 設定的 DHCPv4](#id15)

除了上述設定之外，Dnsmasq 還可以成為中小型網路環境中HA 設定中的可行選項。

與KEA DHCP相反，它不提供租約同步。每個 Dnsmasq 實例都是一個單獨的實體。

實現這項工作的主要技巧是以下選項：

-   轉到服務 ‣ Dnsmasq DNS & DHCP ‣ 一般：
    

在目前主機上設定：

|選項|價值|
| --- | --- |
| **DHCP回覆延遲** |此處不要設定值，我們希望主機先回應。 |
| **停用 HA 同步** | `X` |

在當前備份上設定：

|選項|價值|
| --- | --- |
| **DHCP回覆延遲** | `10`（10秒是一個很好的起點）|
| **停用 HA 同步** | `X` |

注意事項

這意味著，每一個DHCPDiscover都會得到大師的解答。如果主伺服器10秒內沒有回應，則備份伺服器將回應。選擇足夠高的延遲時間很重要，否則在繁忙的網路中行為可能無法預測。已停用的 HA 同步可確保 DHCP 常規設定不會在主備之間同步。

-   轉到服務 ‣ Dnsmasq DNS & DHCP ‣ DHCP 範圍：
    

以LAN為例，在當前master上設定：

|選項|價值|
| --- | --- |
| **界面** | `LAN` |
| **起始位址** | `192.168.1.100` |
| **結束網址** | `192.168.1.199` |
| **禁用HA同步** | `X` |

在當前備份上設定：

|選項|價值|
| --- | --- |
| **介面** | `LAN` |
| **起始位址** | `192.168.1.200` |
| **結束網址** | `192.168.1.220` |
| **禁用HA同步** | `X` |

注意事項

現在主節點和備份節點在LAN網路中都有自己的池。 master 上的池更大，因為它將響應大多數 DHCP 發現。如果主伺服器沒有回應，備份伺服器將從其可用池中提供IP位址。由於池不重疊，因此客戶端之間不會出現 IP 位址衝突。已停用的 HA 同步可確保這些池不同步。

提示

在服務 ‣ Dnsmasq DNS & DHCP ‣ 主機覆蓋中建立的單一主機的預留仍然可以同步。它們被視為定義的 DHCP 範圍之外的自己的單一 IP 位址池。這表示兩台伺服器在查詢時都會提供主機相同的IP位址。在這種情況下，不可能存在IP位址衝突。在硬體位址欄位中設定主機的MAC位址。

透過此設置，可以實現簡單高效的 HA 設定以及自動 DNS 註冊。然而，對於許多 VLAN 中具有較大 IP 位址範圍的大型可擴展設置，KEA DHCP 可能是更好的選擇，因為它具有強大的 HA 同步選項。

### [小型 HA 設定的 DHCPv6 和路由器通告](#id16)

與 DHCPv4 一樣，只需進行一些細微調整即可對 DHCPv6 進行相同類型的設定。

由於 IPv6 使用DAD（重複位址偵測），因此您無需建立單獨的池。 SLAAC 和 DAD 將避免重複。

必須特別注意路由器通告。由於Master和Backup都會同時發送，因此目前的預設閘道必須由優先權和路由器生存期來決定。

-   轉到服務 ‣ Dnsmasq DNS & DHCP ‣ DHCP 範圍：
    

在目前主機上設定：

|選項|價值|
| --- | --- |
| **介面** | `LAN` |
| **起始位址** | `::` |
| **建構子** | `LAN` |
| **RA模式** | `ra-stateless` |
| **RA 優先** | `High` |
| **RA 間隔** | `10` |
| **RA 路由器使用壽命** | `30` |
| **停用 HA 同步** | `X` |

在當前備份上設定：

|選項|價值|
| --- | --- |
| **介面** | `LAN` |
| **起始位址** | `::` |
| **建構子** | `LAN` |
| **RA模式** | `ra-stateless` |
| **RA 優先** | `Normal` |
| **RA 間隔** | `10` |
| **RA 路由器使用壽命** | `30` |
| **禁用HA同步** | `X` |

最後一步，前往 Services ‣ Dnsmasq DNS & DHCP ‣ General

在主伺服器和備份伺服器上啟用複選框`Router Advertisements`並套用設定。

主設備和備份設備現在都將通告其鏈路本地地址作為預設網關。只要客戶端收到RA優先權`high`封包，就優先選擇Master作為目前的IPv6預設閘道。當 master 離線時，RA 間隔每 10 秒發送一次，但 30 秒後，RA 路由器生命週期將達到，並且 master 將從客戶端路由表中棄用。備份現在將作為新的 IPv6 預設路由安裝。

一旦master重新上線，更高的RA優先權將使客戶端最終轉移回來。

注意事項

整個過程並不是一帆風順的，需要一些時間。至少只要客戶端不棄用失效的 IPv6 路由，IPv6 仍將被路由到離線主設備的不存在的連結本地位址。

注意

不要將RA間隔和RA路由器生命週期設定得太低，因為客戶端可能會在繁忙的網路中遺失其預設路由。 RA 路由器生命週期的最低限度應為 (RA 間隔\*3)。

### [Dnsmasq 為主要 DNS 解析器](#id17)

這是一個小補充部分，介紹如何將 Dnsmasq 配置為網路的主要 DNS 解析器，並結合 Unbound 作為遞歸器。

如果您依賴透過 DHCP 註冊的 PTR 記錄的動態 IPv6 網路等功能，或防火牆別名 (IPset) 功能，則該功能非常有用。

缺點是基於客戶端IP的未綁定統計或阻止清單功能，因為客戶端始終是127.0.0.1。

這樣做的好處是配置不太複雜，並且在引入新網路時對 Unbound 的調整也更少。

-   進入服務‣解除綁定DNS‣常規並設定：
    

|選項|價值|
| --- | --- |
| **啟用** | `X` |
| **監聽埠** | `53053` |

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ General 並設定：
    

|選項|價值|
| --- | --- |
| **啟用** | `X` |
| **監聽埠** | `53` |
| **不要轉送到系統定義的DNS伺服器** | `X`（這將強制 Dnsmasq 僅使用網域標籤中指定的轉送）|
| **不要轉發私人反向查找** | `X` |

-   前往 Services ‣ Dnsmasq DNS & DHCP ‣ Domains 並設定：
    

|選項|價值|
| --- | --- |
| **順序** | `1` |
| **網域** | `*`（這將符合所有網域）|
| **IP位址** | `127.0.0.1`（Unbound 監聽此IP 位址與連接埠）|
| **港口** | `53053` |

應用配置並使用客戶端測試DNS解析度。

### [防火牆別名（IPset）](#id18)

Dnsmasq有一個強大的功能，它可以將解析的IP位址加入防火牆別名中。

這在受限網路或收集統計資料時非常有用。

例如，您提供訪客網絡，但使用者只能存取`example.com`。對於普通的防火牆別名，這可能具有挑戰性，因為網域可能會使用多個提供附加內容的子網域。它還可以使用 CDN 在不同伺服器之間負載平衡內容，並動態更改每個客戶端的 IP 位址。

使用 Dnsmasq 託管別名，這變得相當簡單，因為一旦客戶端要求，它就會自動新增新的 IPv4 和 IPv6 位址。

使用此功能的要求是 Dnsmasq 是所有客戶端的主要 DNS 伺服器，並且阻止對任何其他 DNS 伺服器的存取。另一種方法是對應新增至其託管防火牆別名的網域執行從 Unbound 到 Dnsmasq 的查詢轉發，但需要注意的是，Dnsmasq 必須使用外部解析器來防止查詢循環。

注意事項

此功能對於白名單比黑名單更有用。由於 IPv4 和 IPv6 位址已新增至託管防火牆別名中，因此將其用作封鎖清單可能會無意中終止對共用託管服務的存取。此外，如果瀏覽器配置為在連接埠 443 上使用 DoH（DNS 超過 HTTPS），則可以繞過阻止列表，因為 Dnsmasq 不會回應 DNS 請求 - 不會填入別名。

注意

嘗試對新增至別名的網域進行選擇性。添加像 `com` 這樣的 TLD（頂級網域）可能會使別名膨脹到無法使用的程度。一個好的經驗法則是每個服務域都有一個別名，稍後可以將它們嵌套在父別名下。

在以下範例中，Dnsmasq 是我們的主要 DNS 解析器，它將查詢轉送到 Unbound 偵聽的`127.0.0.1:53053`。

-   前往防火牆 ‣ 別名：
    

|選項|價值|
| --- | --- |
| **姓名** | `dnsmasq_example_com` |
| **類型** | `External (advanced)` |
| **過期** | `86400`（逐漸從別名中刪除未使用的IP位址）|

建立別名後，前往 Services ‣ Dnsmasq DNS & DHCP ‣ Domains：

|選項|價值|
| --- | --- |
| **網域** | `example.com`（這也包括 example.com 下的所有子網域）|
| **IP 位址** | `127.0.0.1`（或者，如果配置了來自 Unbound 的此域的查詢轉發，則為1.1.1.1 等外部解析器）|
| **港口** | `53053`（若解析器偵聽埠 53，則留空）|
| **防火牆別名** | `dnsmasq_example_com` |

最後一步，建立一條以 `dnsmasq_example_com` 別名為目標的防火牆規則。

提示

在防火牆 ‣ 診斷 ‣ 別名中驗證別名的內容：一旦客戶端透過 Dnsmasq 解析 `example.com`，它就應該填入IP 位址。
