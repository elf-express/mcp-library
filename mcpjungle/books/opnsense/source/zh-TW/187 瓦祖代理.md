# 瓦祖代理

> 章節：[Community Plugins](<000 目錄.md#c-36>) › [Other](<000 目錄.md#c-38>)

## 介紹

[Wazuh](https://wazuh.com/)是一個開源統一的XDR（擴展檢測和回應）和SIEM（安全資訊和事件管理）系統，能夠為端點和雲端工作負載提供保護。

Wazuh 架構是基於在受監控端點上執行的代理，這些端點收集資訊並能夠執行管理員指示的主動回應。

該插件的目標是提供一個易於安裝的插件來連接到 Wazuh 管理器。

注意事項

OPNsense 上的 Wazuh 範圍僅提供可設定代理支援。我們不計劃也不建議在 OPNsense 上運行 Wazuh 中央組件。有關如何在支援的平台上安裝這些的詳細資訊可直接從 [Wazuh 網站](https://documentation.wazuh.com/current/installation-guide/index.html) 獲取，或者您可以使用[此處](https://wazuh.com/cloud/) 提供的基於雲端的產品

警告

該插件是「按原樣」提供，並由 OPNsense 團隊提供非常有限的「第 3 層」社群支援。使用SIEM/XDR系統所需的知識通常超出（免費）社群支援範圍。

## 安裝

這個插件的安裝非常簡單，進入 System ‣ Firmware ‣ Plugins 並蒐索 **os-wazuh-agent**，使用 \[+\] 按鈕安裝它。

接下來到 Services ‣ Wazuh Agent ‣ Settings 來設定服務。

提示

當 ossec 日誌在調試問題時提供的見解太有限時，請嘗試提高調試等級。啟用“進階模式”時，您可以在常規設定下找到此設定。

## 連線代理

若要將代理程式連接至管理器，只需在 **常規設定/管理器主機名稱**下填入主機名，請確保代理程式標記為啟用，並可選擇在**驗證/密碼** 下指定連線密碼。

接下來去管理器看看代理程式是否自己註冊了。

## 選擇要攝取的日誌

我們的 Wazuh 代理插件支援 syslog 目標，就像我們在產品的其餘部分中使用的那樣，因此，如果應用程式將其提要發送到 syslog 並按照我們的[開發文件](<248 使用插件.md#syslog>) 中所述註冊應用程式名稱，它也可以選擇發送到 Wazuh。

對於入侵偵測，我們也可以使用 OPNsense 中使用的相同 (eve) 資料來源發送事件，只需在常規設定中標記 **入侵偵測事件** 即可。

注意事項

Wazuh 僅支援 [rfc3164](https://datatracker.ietf.org/doc/html/rfc3164) 格式的系統日誌訊息，因此我們使用該格式將要求事件的副本記錄到名為 `/var/ossec/logs/opnsense_syslog.log` 的檔案中。

## 安裝自訂 ossec.conf 條目

有些 Wazuh 模組可以直接從 GUI 中選擇，但是當需要插件中未提供的功能時，可以手動新增靜態部分。

您可以在 `/usr/local/opnsense/service/templates/OPNsense/WazuhAgent/ossec_config.d/` 中新增這些內容，例如，若要新增自訂 json feed，請在其中新增包含以下內容的檔案：

/usr/local/opnsense/service/templates/OPNsense/WazuhAgent/ossec\_config.d/099-my-feed.conf

```xml
<localfile>
  <log_format>json</log_format>
  <location>/path/to/my/file.json</location>
</localfile>
```

## 使用正面的回應

Wazuh 支援[主動回應](https://documentation.wazuh.com/current/user-manual/capabilities/active-response/index.html)，因此主教練可以在需要時指揮防守行動。該插件附帶一個名為 `opnsense-fw` 的操作，用於丟棄來自指定來源位址的流量。

注意事項

opnsense-fw 操作是有狀態的，可以在防火牆中新增和刪除地址，有關此類操作的更多上下文可以在 [Wazuh](https://documentation.wazuh.com/current/user-manual/capabilities/active-response/custom-active-response-scripts.html) 文件中找到。

要使用此操作，您需要在管理員中添加一些配置，首先是此操作的定義。

/var/ossec/etc/ossec.conf

```xml
<ossec_config>
  <command>
    <name>opnsense-fw</name>
    <executable>opnsense-fw</executable>
    <timeout_allowed>yes</timeout_allowed>
  </command>
</ossec_config>
```

之後，您可以在主動回應規則中使用它，如下所示（調整代理 ID）：

/var/ossec/etc/ossec.conf

```xml
<ossec_config>
  <active-response>
    <disabled>no</disabled>
    <command>opnsense-fw</command>
    <location>defined-agent</location>
    <agent_id>001</agent_id>
    <rules_id>87702</rules_id>
    <timeout>180</timeout>
  </active-response>
</ossec_config>
```

官方[文件](https://documentation.wazuh.com/current/user-manual/capabilities/active-response/how-to-configure.html)包含有關可用選項的更多資訊。

提示

主動回應被記錄到 Services ‣ Wazuh Agent ‣ Logfile / active-responses 中，包括從管理器接收到的訊息。

為了快速測試是否可以在代理上執行主動回應，我們建議使用 Wazuh ‣ Tools ‣ API 控制台下的 API 控制台。可以使用以下指令在代理程式 `001` 上執行位址 `172.16.1.30` 的 `opnsense-fw` 指令：

```
PUT /active-response?agents_list=001
{
  "command": "!opnsense-fw",
  "custom": false,
  "alert": {
    "data": {
      "srcip": "172.16.1.30"
    }
  }
}
```

提示

Wazuh 提供了相當多的[概念證明](https://documentation.wazuh.com/current/proof-of-concept-guide/index.html) 文檔和部落格文章，例如[此](https://wazuh.com/blog/responding-to-network-attacks-with-suricata-and-wazuh-xdr/) 文檔，解釋瞭如何結合 Suricata 和 Wazuh 來回應偵測到的威脅。

## 測試規則檢測

如果在 `/var/ossec/logs/opnsense_syslog.log` 中收集日誌條目，且管理員中沒有收集任何事件，通常最好檢查 Wazuh 如何處理這些行。

管理器中的 Wazuh ‣ Tools ‣ Ruleset test 選單項目提供了一個易於使用的工具來檢查日誌事件。
