# PSR-12 編碼風格指南

## 1\.概述

該規範擴展、擴展和替換了編碼風格指南 [PSR-2](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-2-coding-style-guide.md)，並要求遵守基本編碼標準 [PSR-1](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-1-basic-coding-standard.md)。

與PSR-2一樣，此規範的目的是減少掃描不同作者的代碼時的認知摩擦。它透過列舉一組關於如何格式化 PHP 程式碼的共用規則和期望來實現這一點。這個PSR旨在提供一種編碼風格工具可以實現的固定方式，專案可以聲明遵守並且開發人員可以輕鬆地在不同專案之間進行關聯。當不同的作者在多個專案中進行協作時，擁有一套可在所有這些專案中使用的指南會有所幫助。因此，本指南的好處不在於規則本身，而在於這些規則的共享。

PSR-2 於 2012 年被接受，此後對 PHP 進行了許多更改，這對編碼風格指南產生了影響。雖然 PSR-2 非常全面地涵蓋了撰寫本文時存在的 PHP 功能，但新功能的解釋非常開放。因此，本PSR旨在在更現代的背景下澄清PSR-2的內容，並提供新的功能，並對PSR-2進行勘誤。

### 以前的語言版本

在本文檔中，如果您的專案支援的 PHP 版本中不存在任何指令 MAY，則將忽略它們。

### 範例

此範例包含以下一些規則作為快速概述：

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

use Vendor\Package\{ClassA as A, ClassB, ClassC as C};
use Vendor\Package\SomeNamespace\ClassD as D;

use function Vendor\Package\{functionA, functionB, functionC};

use const Vendor\Package\{ConstantA, ConstantB, ConstantC};

class Foo extends Bar implements FooInterface
{
    public function sampleFunction(int $a, int $b = null): array
    {
        if ($a === $b) {
            bar();
        } elseif ($a > $b) {
            $foo->bar($arg1);
        } else {
            BazClass::bar($arg2, $arg3);
        }
    }

    final public static function bar()
    {
        // method body
    }
}
```

## 2\.一般

### 2.1 基本編碼標準

代碼MUST遵循PSR-1中概述的所有規則。

PSR-1 MUST 中的術語「StudlyCaps」被解釋為 PascalCase，其中每個單字的第一個字母都大寫，包括第一個字母。

### 2.2 文件

所有 PHP 檔案 MUST 使用 Unix LF（換行）行結尾。所有 PHP 檔案 MUST 以單一空白行結尾。

僅包含 PHP 的文件中省略結束 `?>` 標籤 MUST。

### 2.3 線路

MUST NOT 對線路長度有硬性限制。

行長度 MUST 的軟限制為 120 個字元。

行 SHOULD NOT 長度超過 80 個字元；長度超過 SHOULD 的行將被分成多個後續行，每行不超過 80 個字元。

行尾有 MUST NOT 尾隨空格。

新增空白行MAY以提高可讀性並指示相關程式碼區塊，除非明確禁止。

每行有 MUST NOT 多個語句。

### 2.4 縮排

代碼MUST每個縮排等級使用4個空格的縮進，MUST NOT使用製表符進行縮排。

### 2.5 關鍵字與類型

所有PHP保留的[關鍵字](http://php.net/manual/en/reserved.keywords.php)和[類型](http://php.net/manual/en/reserved.types.php) MUST均為小寫。

新增至未來 PHP 版本 MUST 的任何新類型和關鍵字均採用小寫。

使用型別關鍵字MUST的縮寫形式，即用bool取代boolean，用int取代integer等。

## 3\.宣告語句、命名空間和導入語句

PHP 檔案的標頭可能由許多不同的區塊組成。如果存在，MUST 下面的每個區塊都由一個空白行分隔，並且 MUST NOT 包含一個空行。每個區塊MUST按照下面列出的順序排列，儘管可以省略不相關的區塊。

-   打開`<?php`標籤。
    
-   文件級文檔區塊。
    
-   一個或多個聲明語句。
    
-   文件的命名空間聲明。
    
-   一個或多個基於類別的 use import 語句。
    
-   一個或多個基於函數的 use import 語句。
    
-   一個或多個基於常數的 use import 語句。
    
-   文件中的其餘代碼。
    

當文件包含HTML和PHP的混合時，仍可使用上述任何部分。如果是這樣，它們 MUST 將出現在文件頂部，即使程式碼的其餘部分由結束 PHP 標記以及HTML 和 PHP 的混合組成。

當開始 <?php 標記位於檔案的第一行時，它 MUST 會獨佔一行，沒有其他語句，除非它是包含 PHP 開始和結束標記之外的標記的檔案。

導入語句 MUST 切勿以先前導反斜線開頭，因為它們必須永遠是完全限定的。

以下範例說明了所有區塊的完整清單：

```php
<?php

/**
 * This file contains an example of coding styles.
 */

declare(strict_types=1);

namespace Vendor\Package;

use Vendor\Package\{ClassA as A, ClassB, ClassC as C};
use Vendor\Package\SomeNamespace\ClassD as D;
use Vendor\Package\AnotherNamespace\ClassE as E;

use function Vendor\Package\{functionA, functionB, functionC};
use function Another\Vendor\functionD;

use const Vendor\Package\{CONSTANT_A, CONSTANT_B, CONSTANT_C};
use const Another\Vendor\CONSTANT_D;

/**
 * FooBar is an example class.
 */
class FooBar
{
    // ... additional PHP code ...
}
```

使用深度超過兩個MUST NOT的複合命名空間。因此，以下是允許的最大複合深度：

```php
<?php

use Vendor\Package\SomeNamespace\{
  SubnamespaceOne\ClassA,
  SubnamespaceOne\ClassB,
  SubnamespaceTwo\ClassY,
  ClassZ,
};
```

且以下行為是不允許的：

```php
<?php

use Vendor\Package\SomeNamespace\{
    SubnamespaceOne\AnotherNamespace\ClassA,
    SubnamespaceOne\ClassB,
    ClassZ,
};
```

當希望在包含PHP開始和結束標記之外的標記的文件中聲明嚴格類型時，聲明MUST位於文件的第一行，並包含開始PHP標記、嚴格類型聲明和結束標記。

例如：

```php
<?php declare(strict_types=1) ?>
<html>
<body>
    <?php
        // ... additional PHP code ...
    ?>
</body>
</html>
```

宣告語句 MUST 不包含空格，且 MUST 完全宣告（strict\_types=1）（有可選的分號終止符）。

允許使用區塊宣告語句，並且 MUST 的格式如下。注意大括號的位置和間距：

```sql
declare(ticks=1) {
    // some code
}
```

## 4\.類別、屬性和方法

術語「類別」是指所有類別、介面和特徵。

任何右大括號 MUST NOT 後面都跟著同一行上的任何註解或語句。

實例化新類別時，即使沒有參數傳遞給建構函數，括號 MUST 也始終存在。

```
new Foo();
```

### 4.1 擴展與實現

extends 和implements 關鍵字MUST 與類別名稱在同一行宣告。

類別 MUST 的左大括號獨佔一行；類別 MUST 的右大括號位於正文之後的下一行。

左大括號 MUST 獨佔一行，MUST NOT 之前或之後有一個空白行。

右大括號 MUST 獨佔一行，MUST NOT 前面有一個空白行。

```php
<?php

namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements \ArrayAccess, \Countable
{
    // constants, properties, methods
}
```

實作列表以及介面列表，擴展MAY被分成多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個介面。

```php
<?php

namespace Vendor\Package;

use FooClass;
use BarClass as Bar;
use OtherVendor\OtherPackage\BazClass;

class ClassName extends ParentClass implements
    \ArrayAccess,
    \Countable,
    \Serializable
{
    // constants, properties, methods
}
```

### 4.2 使用特質

類別內部用於實現特徵 MUST 的 use 關鍵字在左大括號後的下一行聲明。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;
}
```

導入到類別 MUST 的每個單獨特徵每行包含一個，並且每個包含 MUST 都有自己的 use import 語句。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;
use Vendor\Package\SecondTrait;
use Vendor\Package\ThirdTrait;

class ClassName
{
    use FirstTrait;
    use SecondTrait;
    use ThirdTrait;
}
```

當類別在 use import 語句之後沒有任何內容時，類別右大括號 MUST 位於 use import 語句之後的下一行。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;
}
```

否則，MUST在use import語句之後會有一個空白行。

```php
<?php

namespace Vendor\Package;

use Vendor\Package\FirstTrait;

class ClassName
{
    use FirstTrait;

    private $property;
}
```

使用 otherof 和 as 運算子時，必須如下使用它們，並注意縮排、間距和換行。

```php
<?php

class Talker
{
    use A;
    use B {
        A::smallTalk insteadof B;
    }
    use C {
        B::bigTalk insteadof C;
        C::mediumTalk as FooBar;
    }
}
```

### 4.3 屬性與常數

所有房產均需聲明可見性MUST。

如果您的專案PHP最低版本支援常數可見性（PHP 7.1或更高版本），則在所有常數上聲明可見性MUST。

var 關鍵字MUST NOT 用來宣告屬性。

每個語句宣告 MUST NOT 多個屬性。

屬性名稱 MUST NOT 以單一底線為前綴，以指示受保護或私有可見性。也就是說，底線前綴明確沒有任何意義。

類型聲明和屬性名稱之間有 MUST 空格。

屬性聲明如下圖所示：

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public $foo = null;
    public static int $bar = 0;
}
```

### 4.4 方法與函數

在所有方法上都宣告可見性MUST。

方法名稱 MUST NOT 以單一底線為前綴，以指示受保護或私有可見性。也就是說，底線前綴明確沒有任何意義。

方法和函數名稱MUST NOT 在方法名稱後宣告時留有空格。左大括號 MUST 獨佔一行，右大括號 MUST 位於主體後方的下一行。左括號後面有 MUST NOT ，右括號前有 MUST NOT 。

方法聲明如下圖所示。注意括號、逗號、空格和大括號的位置：

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function fooBarBaz($arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

函數聲明如下所示。注意括號、逗號、空格和大括號的位置：

```php
<?php

function fooBarBaz($arg1, &$arg2, $arg3 = [])
{
    // function body
}
```

### 4.5 方法與函數參數

在參數清單中，每個逗號前有 MUST NOT 一個空格，每個逗號後面有 MUST 一個空格。

具有預設值 MUST 的方法和函數參數位於參數清單的末端。

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function foo(int $arg1, &$arg2, $arg3 = [])
    {
        // method body
    }
}
```

參數清單 MAY 分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數。

當參數清單分成多行時，右括號和左大括號 MUST 一起放在自己的行上，中間有一個空格。

```php
<?php

namespace Vendor\Package;

class ClassName
{
    public function aVeryLongMethodName(
        ClassTypeHint $arg1,
        &$arg2,
        array $arg3 = []
    ) {
        // method body
    }
}
```

當存在返回類型聲明時，MUST 冒號後面有一個空格，後面跟著類型聲明。冒號與宣告 MUST 與參數清單右括號位於同一行，兩個字元之間沒有空格。

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

class ReturnTypeVariations
{
    public function functionName(int $arg1, $arg2): string
    {
        return 'foo';
    }

    public function anotherFunction(
        string $foo,
        string $bar,
        int $baz
    ): string {
        return 'foo';
    }
}
```

在可為 null 的型別宣告中，問號與型別之間存在 MUST NOT 空格。

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

class ReturnTypeVariations
{
    public function functionName(?string $arg1, ?int &$arg2): ?string
    {
        return 'foo';
    }
}
```

當在參數之前使用引用運算子 & 時，後面有 MUST NOT 一個空格，如前面的範例所示。

可變參數三點運算子和參數名稱之間有 MUST NOT 空格：

```php
public function process(string $algorithm, ...$parts)
{
    // processing
}
```

當組合引用運算子和可變三點運算子時，兩者之間有 MUST NOT 任意空格：

```php
public function process(string $algorithm, &...$parts)
{
    // processing
}
```

### 4.6 抽象、最終、靜態

當存在時，抽象和最終聲明MUST位於可見性聲明之前。

如果存在，靜態宣告MUST位於可見性宣告之後。

```php
<?php

namespace Vendor\Package;

abstract class ClassName
{
    protected static $foo;

    abstract protected function zim();

    final public static function bar()
    {
        // method body
    }
}
```

### 4.7 方法與函數調用

呼叫方法或函數時，方法或函數名稱與左括號之間有 MUST NOT 空格，左括號後有 MUST NOT 空格，右括號前有 MUST NOT 空格。在參數清單中，MUST NOT 每個逗號之前都有一個空格，MUST 每個逗號之後有一個空格。

```php
<?php

bar();
$foo->bar($arg1);
Foo::bar($arg2, $arg3);
```

參數列表MAY分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數。單一參數被拆分為多行（匿名函數或陣列可能就是這種情況）並不構成拆分參數清單本身。

```php
<?php

$foo->bar(
    $longArgument,
    $longerArgument,
    $muchLongerArgument
);
```

```php
<?php

somefunction($foo, $bar, [
  // ...
], $baz);

$app->get('/hello/{name}', function ($name) use ($app) {
    return 'Hello ' . $app->escape($name);
});
```

## 5\.控制結構

控制結構的一般樣式規則如下：

-   控制結構關鍵字後面有MUST一個空格
    
-   左括號後面有MUST NOT空格
    
-   右括號前有 MUST NOT 空格
    
-   右括號和左大括號之間有 MUST 一個空格
    
-   結構體MUST縮排一次
    
-   正文 MUST 位於左大括號之後的下一行
    
-   右大括號 MUST 位於正文之後的下一行
    

每個結構體MUST都用大括號括起來。這標準化了結構的外觀，並減少了在將新線條添加到主體時引入錯誤的可能性。

### 5.1 如果，否則，否則

if 結構如下圖所示。注意括號、空格和大括號的位置； else 和 elseif 與前一個主體的右大括號位於同一行。

```php
<?php

if ($expr1) {
    // if body
} elseif ($expr2) {
    // elseif body
} else {
    // else body;
}
```

使用關鍵字 elseif SHOULD 取代 else if ，以便所有控製關鍵字看起來像單字。

括號中的表達式MAY分為多行，其中每個後續行至少縮排一次。這樣做時，第一個條件MUST位於下一行。右括號和左大括號 MUST 單獨放在一行，中間有一個空格。條件MUST之間的布林運算子總是位於行的開頭或結尾，而不是兩者的混合。

```php
<?php

if (
    $expr1
    && $expr2
) {
    // if body
} elseif (
    $expr3
    && $expr4
) {
    // elseif body
}
```

### 5.2 開關、外殼

開關結構如下圖所示。請注意括號、空格和大括號的位置。 case 語句MUST 從 switch 開始縮排一次，break 關鍵字（或其他終止關鍵字）MUST 與 case 主體縮排到相同層級。有 MUST 註釋，例如 // no break when fall-through is故意在非空的 case body 中。

```php
<?php

switch ($expr) {
    case 0:
        echo 'First case, with a break';
        break;
    case 1:
        echo 'Second case, which falls through';
        // no break
    case 2:
    case 3:
    case 4:
        echo 'Third case, return instead of break';
        return;
    default:
        echo 'Default case';
        break;
}
```

括號中的表達式MAY分為多行，其中每個後續行至少縮排一次。這樣做時，第一個條件MUST位於下一行。右括號和左大括號 MUST 單獨放在一行，中間有一個空格。條件MUST之間的布林運算子總是位於行的開頭或結尾，而不是兩者的混合。

```php
<?php

switch (
    $expr1
    && $expr2
) {
    // structure body
}
```

### 5.3 一會兒，一會兒

while 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php

while ($expr) {
    // structure body
}
```

括號中的表達式MAY分為多行，其中每個後續行至少縮排一次。這樣做時，第一個條件MUST位於下一行。右括號和左大括號 MUST 單獨放在一行，中間有一個空格。條件MUST之間的布林運算子總是位於行的開頭或結尾，而不是兩者的混合。

```php
<?php

while (
    $expr1
    && $expr2
) {
    // structure body
}
```

類似地，do while 語句如下圖所示。請注意括號、空格和大括號的位置。

```php
<?php

do {
    // structure body;
} while ($expr);
```

括號中的表達式MAY分為多行，其中每個後續行至少縮排一次。這樣做時，第一個條件MUST位於下一行。條件MUST之間的布林運算子總是位於行的開頭或結尾，而不是兩者的混合。

```php
<?php

do {
    // structure body;
} while (
    $expr1
    && $expr2
);
```

### 5.4 為

for 語句如下所示。請注意括號、空格和大括號的位置。

```php
<?php

for ($i = 0; $i < 10; $i++) {
    // for body
}
```

括號中的表達式MAY分為多行，其中每個後續行至少縮排一次。這樣做時，第一個表達式MUST位於下一行。右括號和左大括號 MUST 單獨放在一行，中間有一個空格。

```php
<?php

for (
    $i = 0;
    $i < 10;
    $i++
) {
    // for body
}
```

### 5.5 foreach

foreach 語句如下所示。請注意括號、空格和大括號的位置。

```php
<?php

foreach ($iterable as $key => $value) {
    // foreach body
}
```

### 5.6 嘗試，抓住，終於

try-catch-finally 區塊如下所示。請注意括號、空格和大括號的位置。

```php
<?php

try {
    // try body
} catch (FirstThrowableType $e) {
    // catch body
} catch (OtherThrowableType | AnotherThrowableType $e) {
    // catch body
} finally {
    // finally body
}
```

## 6\.運營商

運算符的樣式規則按數量（它們採用的操作數的數量）分組。

當運算元周圍允許有空格時，出於可讀性目的，可以使用多個空格MAY。

此處未描述的所有運算子均未定義。

### 6.1。一元運算符

遞增/遞減運算子 MUST NOT 運算子和運算元之間可以有任何空格。

```
$i++;
++$j;
```

類型轉換運算子 MUST NOT 括號內有空格：

```
$intValue = (int) $input;
```

### 6.2。二元運算符

所有二進位\[算術\]\[\]、\[比較\]\[\]、\[賦值\]\[\]、\[位元\]\[\]、\[邏輯\]\[\]、\[字串\]\[\]和\[類型\]\[\]運算子 MUST 前後至少有一個空格：

```
if ($a === $b) {
    $foo = $bar ?? $a ?? $b;
} elseif ($a > $b) {
    $foo = $a + $b * $c;
}
```

### 6.3。三元運算符

條件運算符，也簡稱為三元運算符，MUST 前後至少各有一個空格，且 ? 周圍各有一個空格。和 : 字元：

```
$variable = $foo ? 'foo' : 'bar';
```

當省略條件運算子的中間運算元時，運算子MUST遵循與其他二元\[比較\]\[\]運算子相同的樣式規則：

```
$variable = $foo ?: 'bar';
```

## 7\.閉包

閉包 MUST 在 function 關鍵字之後宣告一個空格，在 use 關鍵字前後各留一個空格。

左大括號 MUST 位於同一行，右大括號 MUST 位於主體後方的下一行。

參數列表或變數列表的左括號後面有 MUST NOT ，參數列表或變數列表的右括號前有 MUST NOT 。

在參數清單和變數清單中，MUST NOT 每個逗號之前都有一個空格，MUST 每個逗號之後有一個空格。

具有預設值 MUST 的閉包參數位於參數清單的末端。

如果存在回傳類型，則MUST遵循與普通函數和方法相同的規則；如果存在 use 關鍵字，則冒號 MUST 位於 use 清單右括號之後，兩個字元之間沒有空格。

關閉聲明如下圖所示。注意括號、逗號、空格和大括號的位置：

```php
<?php

$closureWithArgs = function ($arg1, $arg2) {
    // body
};

$closureWithArgsAndVars = function ($arg1, $arg2) use ($var1, $var2) {
    // body
};

$closureWithArgsVarsAndReturn = function ($arg1, $arg2) use ($var1, $var2): bool {
    // body
};
```

參數列表和變數列表 MAY 分為多行，其中每個後續行縮排一次。這樣做時，清單中的第一項MUST位於下一行，且MUST每行只有一個參數或變數。

當結束清單（無論是參數或變數）被分成多行時，右括號和左大括號 MUST 一起放在自己的行上，中間有一個空格。

以下是帶有和不帶有參數列表以及跨多行的變數列表的閉包範例。

```php
<?php

$longArgs_noVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) {
   // body
};

$noArgs_longVars = function () use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_longVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};

$longArgs_shortVars = function (
    $longArgument,
    $longerArgument,
    $muchLongerArgument
) use ($var1) {
   // body
};

$shortArgs_longVars = function ($arg) use (
    $longVar1,
    $longerVar2,
    $muchLongerVar3
) {
   // body
};
```

請注意，當閉包直接在函數或方法呼叫中用作參數時，格式化規則也適用。

```php
<?php

$foo->bar(
    $arg1,
    function ($arg2) use ($var1) {
        // body
    },
    $arg3
);
```

## 8\.匿名類

匿名類別MUST遵循與上一節中的閉包相同的指導方針和原則。

```php
<?php

$instance = new class {};
```

只要實作介面清單不換行，左大括號 MAY 就與 class 關鍵字在同一行。如果介面清單換行，則將大括號 MUST 放置在緊接最後一個介面之後的行上。

```php
<?php

// Brace on the same line
$instance = new class extends \Foo implements \HandleableInterface {
    // Class content
};

// Brace on the next line
$instance = new class extends \Foo implements
    \ArrayAccess,
    \Countable,
    \Serializable
{
    // Class content
};
```
