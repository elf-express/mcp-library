## Модуль ngx\_mail\_smtp\_module

|   |
| --- |
| [Директивы](#directives)<br>     [smtp\_auth](#smtp_auth)<br>     [smtp\_capabilities](#smtp_capabilities)<br>     [smtp\_client\_buffer](#smtp_client_buffer)<br>     [smtp\_greeting\_delay](#smtp_greeting_delay) |

#### Директивы

<table>
<tr><th>Синтаксис:</th><td><code><strong>smtp_auth</strong> <code><i>метод</i></code> ...;</code></td></tr>
<tr><th>Умолчание:</th><td>smtp_auth plain login;</td></tr>
<tr><th>Контекст:</th><td><code>mail</code>, <code>server</code></td></tr>
</table>

Задаёт разрешённые методы [SASL-аутентификации](https://datatracker.ietf.org/doc/html/rfc2554) SMTP-клиентов. Поддерживаемые методы:

`plain`

[AUTH PLAIN](https://datatracker.ietf.org/doc/html/rfc4616)

`login`

[AUTH LOGIN](https://datatracker.ietf.org/doc/html/draft-murchison-sasl-login-00)

`cram-md5`

[AUTH CRAM-MD5](https://datatracker.ietf.org/doc/html/rfc2195). Для работы этого метода пароль должен храниться в незашифрованном виде.

`external`

[AUTH EXTERNAL](https://datatracker.ietf.org/doc/html/rfc4422) (1.11.6).

`none`

Аутентификация не требуется.

Методы аутентификации с передачей пароля открытым текстом (`AUTH PLAIN` и `AUTH LOGIN`) включены всегда, однако если методы `plain` и `login` не указаны, то `AUTH PLAIN` и `AUTH LOGIN` не будут автоматически добавляться в [smtp\_capabilities](#smtp_capabilities).

|   |   |
| --- | --- |
| Синтаксис: | ``**smtp_capabilities** `*расширение*` ...;`` |
| Умолчание: | — |
| Контекст: | `mail`, `server` |

Позволяет указать список расширений протокола SMTP, выдаваемый клиенту в ответе на команду `EHLO`. В зависимости от значения директивы [starttls](<284 [02.01.02 mail] Модуль ngx_mail_ssl_module.md#starttls>) к этому списку автоматически добавляются методы аутентификации, указанные в директиве [smtp\_auth](#smtp_auth), и [STARTTLS](https://datatracker.ietf.org/doc/html/rfc3207).

В данной директиве имеет смысл указать расширения, поддерживаемые MTA, на который проксируются клиенты (если эти расширения относятся к командам, используемым после аутентификации, когда nginx прозрачно проксирует подключение клиента на бэкенд).

Текущий список стандартизованных расширений опубликован на [www.iana.org](http://www.iana.org/assignments/mail-parameters).

<table>
<tr><th>Синтаксис:</th><td><code><strong>smtp_client_buffer</strong> <code><i>размер</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>smtp_client_buffer 4k|8k;</td></tr>
<tr><th>Контекст:</th><td><code>mail</code>, <code>server</code></td></tr>
</table>

Задаёт `*размер*` буфера для чтения SMTP-команд. По умолчанию размер одного буфера равен размеру страницы. В зависимости от платформы это или 4K, или 8K.

<table>
<tr><th>Синтаксис:</th><td><code><strong>smtp_greeting_delay</strong> <code><i>время</i></code>;</code></td></tr>
<tr><th>Умолчание:</th><td>smtp_greeting_delay 0;</td></tr>
<tr><th>Контекст:</th><td><code>mail</code>, <code>server</code></td></tr>
</table>

Позволяет задать задержку перед отправкой SMTP-приветствия, чтобы отклонить клиентов, не дожидающихся приветствия до начала отправки SMTP-команд.
