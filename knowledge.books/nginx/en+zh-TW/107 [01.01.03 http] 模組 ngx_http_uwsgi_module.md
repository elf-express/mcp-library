The `ngx_http_uwsgi_module` module allows passing requests to a uwsgi server.

`ngx_http_uwsgi_module`模組允許向 uwsgi 伺服器傳遞請求。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點 / {
>     include    uwsgi_params;
>
>     包含 uwsgi_params；
>     uwsgi_pass localhost:9000;
> }
> ```

| Syntax:<br>語法： | ``**uwsgi_allow_upstream** `*string*` ...;``<br>` `**uwsgi_allow_upstream** ` *字串* ` ...;` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

This directive appeared in version 1.29.3.

該指令出現在版本1.29.3 。

Defines conditions under which access to a uwsgi server is allowed or [denied](#denied). If all string parameters are not empty and not equal to “0” then the access is allowed. The conditions are evaluated each time before a connection to a uwsgi server is established. Parameter values can contain variables:

定義允許或拒絕存取 uwsgi 伺服器的條件(https://nginx.org/en/docs/http/ngx_http_uwsgi_module.html#denied) 。如果所有字串參數均不為空且不等於“0”，則允許存取。每次建立與 uwsgi 伺服器的連線之前都會評估這些條件。參數值可以包含變數：

> ```
> geo $upstream_last_addr $allow {
>     volatile;
>
>     易揮發的;
>     10.10.0.0/24        1;
> }
> 
> server {
>
> 伺服器 {
>     listen 127.0.0.1:8080;
>
>     聽127.0.0.1:8080 ;
> 
>     location / {
>
>     地點 / {
>         uwsgi_pass           localhost:9000;
>
>         uwsgi_pass localhost:9000;
>         uwsgi_allow_upstream $allow;
>         ...
>     }
> }
> ```

| Syntax:<br>語法： | ``**uwsgi_bind** `*address*` [`transparent`] \| `off`;``<br>` `**uwsgi_bind** ` *地址* ` [`透明`] \| `關閉`;` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

Makes outgoing connections to a uwsgi server originate from the specified local IP address with an optional port (1.11.2). Parameter value can contain variables (1.3.12). The special value `off` (1.3.12) cancels the effect of the `uwsgi_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address and port.

使發送至 uwsgi 伺服器的出站連線源自指定的本機位址IP ，並可選擇指定連接埠 ( 1.11.2 )。參數值可以包含變數 ( 1.3.12 )。特殊值`off` ( 1.3.12 ) 會取消從上一配置等級繼承的`uwsgi_bind`指令的效果，該指令允許系統自動分配本地位址IP和連接埠。

The `transparent` parameter (1.11.0) allows outgoing connections to a uwsgi server originate from a non-local IP address, for example, from a real IP address of a client:

`transparent`參數 ( 1.11.0 ) 允許從非本地IP位址（例如，客戶端的真實IP位址）發出到 uwsgi 伺服器的出站連接：

> ```
> uwsgi_bind $remote_addr transparent;
> ```

In order for this parameter to work, it is usually necessary to run nginx worker processes with the [superuser](<125 [01.01 文件] 核心功能.md#user>) privileges. On Linux it is not required (1.13.8) as if the `transparent` parameter is specified, worker processes inherit the `CAP_NET_RAW` capability from the master process. It is also necessary to configure kernel routing table to intercept network traffic from the uwsgi server.

為了使此參數生效，通常需要以 [superuser](<125 [01.01 文件] 核心功能.md#user>)權限執行 nginx 工作進程。在 Linux 系統上則無需此權限 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程會從主進程繼承`CAP_NET_RAW`權限。此外，還需要設定核心路由表以攔截來自 uwsgi 伺服器的網路流量。

Sets the `*size*` of the buffer used for reading the first part of the response received from the uwsgi server. This part usually contains a small response header; if it exceeds the buffer size, the response is considered [invalid](#invalid_header). By default, the buffer size is equal to one memory page. This is either 4K or 8K, depending on a platform. It can be made smaller, however.

設定用於讀取從 uwsgi 伺服器收到的回應第一部分的緩衝區大小`*size*` 。這部分通常包含一個較小的響應頭；如果響應頭大小超過緩衝區大小，則該響應被視為無效（ (https://nginx.org/en/docs/http/ngx_http_uwsgi_module.html#invalid_header) ）。預設情況下，緩衝區大小等於一個記憶體頁。根據平台的不同，該大小為 4K 或 8K。不過，可以將其減小。

<tr><th>Syntax:<br>語法：</th><td><code><strong>uwsgi_buffering</strong> <code>on<br>開啟</code> | <code>off<br>關閉</code>;</code></td></tr>
<tr><th>Default:<br>預設值：</th><td>uwsgi_buffering on;<br>uwsgi_buffering 已啟用；</td></tr>
<tr><th>Context:<br>上下文：</th><td><code>http</code>, <code>server<br>伺服器</code>, <code>location<br>位置</code></td></tr>
</table>

Enables or disables buffering of responses from the uwsgi server.

啟用或停用來自 uwsgi 伺服器的回應緩衝。

When buffering is enabled, nginx receives a response from the uwsgi server as soon as possible, saving it into the buffers set by the [uwsgi\_buffer\_size](#uwsgi_buffer_size) and [uwsgi\_buffers](#uwsgi_buffers) directives. If the whole response does not fit into memory, a part of it can be saved to a [temporary file](#uwsgi_temp_path) on the disk. Writing to temporary files is controlled by the [uwsgi\_max\_temp\_file\_size](#uwsgi_max_temp_file_size) and [uwsgi\_temp\_file\_write\_size](#uwsgi_temp_file_write_size) directives.

啟用緩衝後，nginx 會盡快從 uwsgi 伺服器接收回應，並將其儲存到由 `[uwsgi\_buffer\_size](#uwsgi_buffer_size)和 `[uwsgi\_buffers](#uwsgi_buffers)指令設定的緩衝區中。如果整個回應無法放入內存，則可以將其一部分儲存到磁碟上的暫存檔案（`[temporary file](#uwsgi_temp_path) ）。暫存檔案的寫入由 `[uwsgi\_max\_temp\_file\_size](#uwsgi_max_temp_file_size)和 `[uwsgi\_temp\_file\_write\_size](#uwsgi_temp_file_write_size)指令控制。

When buffering is disabled, the response is passed to a client synchronously, immediately as it is received. nginx will not try to read the whole response from the uwsgi server. The maximum size of the data that nginx can receive from the server at a time is set by the [uwsgi\_buffer\_size](#uwsgi_buffer_size) directive.

停用緩衝後，回應會同步地立即傳遞給客戶端。 nginx 不會嘗試從 uwsgi 伺服器讀取整個回應。 nginx 一次可以從伺服器接收的最大資料大小由 [uwsgi\_buffer\_size](#uwsgi_buffer_size)指令設定。

Buffering can also be enabled or disabled by passing “`yes`” or “`no`” in the “X-Accel-Buffering” response header field. This capability can be disabled using the [uwsgi\_ignore\_headers](#uwsgi_ignore_headers) directive.

也可以透過在“X-Accel-Buffering”響應頭字段中傳遞「 `yes` 」或「 `no` 」來啟用或停用緩衝。可以使用 [uwsgi\_ignore\_headers](#uwsgi_ignore_headers)指令停用此功能。

Sets the `*number*` and `*size*` of the buffers used for reading a response from the uwsgi server, for a single connection. By default, the buffer size is equal to one memory page. This is either 4K or 8K, depending on a platform.

設定用於從 uWSGI 伺服器讀取回應的緩衝區`*number*`和`*size*`的值，此設定僅適用於單一連線。預設情況下，緩衝區大小等於一個記憶體頁。根據平台不同，該值可以是 4K 或 8K。

When [buffering](#uwsgi_buffering) of responses from the uwsgi server is enabled, limits the total `*size*` of buffers that can be busy sending a response to the client while the response is not yet fully read. In the meantime, the rest of the buffers can be used for reading the response and, if needed, buffering part of the response to a temporary file. By default, `*size*` is limited by the size of two buffers set by the [uwsgi\_buffer\_size](#uwsgi_buffer_size) and [uwsgi\_buffers](#uwsgi_buffers) directives.

啟用 uwsgi 伺服器回應的 [buffering](#uwsgi_buffering)功能後，會限制用於向客戶端發送回應的緩衝區總數`*size*` ，直到回應完全讀取完畢。在此期間，其餘緩衝區可用於讀取回應，並在需要時將部分回應緩衝到暫存檔案。預設情況下， `*size*`受限於 [uwsgi\_buffer\_size](#uwsgi_buffer_size)和 [uwsgi\_buffers](#uwsgi_buffers)指令設定的兩個緩衝區的大小。

Allows starting a background subrequest to update an expired cache item, while a stale cached response is returned to the client. Note that it is necessary to [allow](#uwsgi_cache_use_stale_updating) the usage of a stale cached response when it is being updated.

允許啟動後台子請求來更新已過期的快取項，同時向客戶端傳回過時的快取回應。請注意，在更新快取項目時，必須允許使用過時的快取回應（請參閱(https://nginx.org/en/docs/http/ngx_http_uwsgi_module.html#uwsgi_cache_use_stale_updating) ）。

定義不從快取中取得回應的條件。如果字串參數中至少有一個值不為空且不等於“0”，則不會從快取中取得回應：

> uwsgi_cache_bypass $http_pragma    $http_authorization;

> ```

Can be used along with the [uwsgi\_no\_cache](#uwsgi_no_cache) directive.

可與 [uwsgi\_no\_cache](#uwsgi_no_cache)指令一起使用。

When enabled, only one request at a time will be allowed to populate a new cache element identified according to the [uwsgi\_cache\_key](#uwsgi_cache_key) directive by passing a request to a uwsgi server. Other requests of the same cache element will either wait for a response to appear in the cache or the cache lock for this element to be released, up to the time set by the [uwsgi\_cache\_lock\_timeout](#uwsgi_cache_lock_timeout) directive.

Enables saving of files to a disk. The `on` parameter saves files with paths corresponding to the directives [alias](<056 [01.01.03 http] 模組 ngx_http_core_module.md#alias>) or [root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>). The `off` parameter disables saving of files. In addition, the file name can be set explicitly using the `*string*` with variables:

允許將檔案儲存到磁碟。 `on`參數保存與指令[alias](<056 [01.01.03 http] 模組 ngx_http_core_module.md#alias>)或[root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>)相對應的路徑的檔案。 `off` 參數禁用檔案保存。此外，可以使用帶有變數的`*string*`明確設定檔名：

> ```
> uwsgi_store /data/www$original_uri;
> ```

The modification time of files is set according to the received “Last-Modified”（最後修改日期） response header field. The response is first written to a temporary file, and then the file is renamed. Starting from version 0.8.9, temporary files and the persistent store can be put on different file systems. However, be aware that in this case a file is copied across two file systems instead of the cheap renaming operation. It is thus recommended that for any given location both saved files and a directory holding temporary files, set by the [uwsgi\_temp\_path](#uwsgi_temp_path) directive, are put on the same file system.

檔案的修改時間根據接收的“Last-Modified”（最後修改日期）回應頭字段設定。回應首先寫入臨時文件，然後重新命名該文件。從0.8.9版本開始，暫存檔案和持久化儲存可以位於不同的檔案系統上。但是請注意，在這種情況下，檔案會複製到兩個檔案系統上，而不是執行簡單的重新命名操作。因此，建議對於任何給定的位置，已儲存的檔案和由 [uwsgi\_temp\_path](#uwsgi_temp_path)指令設定的暫存檔案目錄都位於同一檔案系統上。

>
