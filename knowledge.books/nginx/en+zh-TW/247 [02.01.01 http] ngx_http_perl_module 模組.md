Модуль `ngx_http_perl_module` позволяет писать обработчики location и переменных на Perl, а также вставлять вызовы Perl в SSI.

`ngx_http_perl_module`模組可讓您用 Perl 編寫位置和變數處理程序，並將 Perl 呼叫插入到SSI中。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_perl_module`.

此模組預設未構建，必須使用`--with-http_perl_module`配置參數啟用。

> Для сборки этого модуля необходим [Perl](https://www.perl.org/get.html) версии 5.6.1 и выше. Компилятор C должен быть совместим с тем, которым был собран Perl.
>
> 建置此模組需要 Perl 版本(https://www.perl.org/get.html) 5.6.1或更高版本。 C 編譯器必須與用於建置 Perl 的編譯器相容。

#### Известные проблемы｜已知問題

Модуль экспериментальный, поэтому возможно всё.

本模組尚處於實驗階段，因此一切皆有可能。

Для того чтобы во время переконфигурации Perl перекомпилировал изменённые модули, его нужно собрать с параметрами `-Dusemultiplicity=yes` или `-Dusethreads=yes`. Кроме того, чтобы во время работы Perl терял меньше памяти, его нужно собрать с параметром `-Dusemymalloc=no`. Узнать значения этих параметров у уже собранного Perl можно так (в примере приведены желаемые значения параметров):

為確保 Perl 在重新配置期間重新編譯已修改的模組，必須使用`-Dusemultiplicity=yes`或`-Dusethreads=yes`參數進行建置。此外，為減少執行期間的記憶體損耗，Perl 還必須使用`-Dusemymalloc=no`參數進行建置。您可以如下找到已建置 Perl 的這些參數值（範例顯示了所需的參數值）：

> ```bash
>
> 『`bash
> $ perl -V:usemultiplicity -V:usemymalloc
> usemultiplicity='define';
> usemymalloc='n';
> ```

Необходимо учитывать, что после пересборки Perl с новыми параметрами `-Dusemultiplicity=yes` или `-Dusethreads=yes` придётся также пересобрать и все бинарные модули Perl, так как они просто перестанут работать с новым Perl.

需要注意的是，使用新的`-Dusemultiplicity=yes`或`-Dusethreads=yes`參數重新建構 Perl 後，您還需要重新建構所有 Perl 二進位模組，因為它們將無法與新的 Perl 一起使用。

Возможно, главный процесс, а вслед за ним и рабочие процессы, будут увеличиваться в размерах при каждой переконфигурации. Когда главный процесс вырастет до неприемлемых размеров, можно воспользоваться процедурой [обновления сервера на лету](<204 [02.01 文件] nginx 管理.md#upgrade>), не меняя при этом сам исполняемый файл.

每次重新配置後，主進程以及隨後的工作進程的大小都可能增加。當主進程成長到無法接受的大小時，您可以使用 [即時伺服器更新 程式](<204 [02.01 文件] nginx 管理.md#upgrade>)而無需更改可執行檔本身。

Если модуль Perl выполняет длительную операцию, например, определяет адрес по имени, соединяется с другим сервером, делает запрос к базе данных, то на это время все остальные запросы, обслуживаемые данным рабочим процессом, не будут обрабатываться. Поэтому рекомендуется ограничиться операциями, время исполнения которых короткое и предсказуемое, например, обращение к локальной файловой системе.

如果 Perl 模組執行耗時較長的操作，例如透過名稱解析位址、連接到其他伺服器或查詢資料庫，則工作進程處理的所有其他請求在此期間都將處於空閒狀態。因此，建議將執行時間限制在執行時間短且可預測的操作上，例如存取本機檔案系統。

#### Методы объекта запроса $r｜$r 請求物件的方法

`$r->args`

возвращает аргументы запроса.

傳回查詢參數。

`$r->filename`

возвращает имя файла, соответствующее URI запроса.

傳回與URI查詢對應的檔案名稱。

``$r->has_request_body(`*обработчик*`)``

` `$r->has_request_body(` *處理程序* `)` `

возвращает 0, если в запросе нет тела. Если же в запросе есть тело, то устанавливается указанный обработчик и возвращается 1. По окончании чтения тела запроса nginx вызовет установленный обработчик. Обратите внимание, что нужно передавать ссылку на функцию обработчика. Пример:

如果請求沒有請求體，則傳回 0。如果請求有請求體，則指定的處理程序將被安裝，並傳回 1。 nginx 讀取請求體後，會呼叫已安裝的處理程序。請注意，您必須傳遞對處理程序函數的參考。例如：

> ```
> package hello;
>
> 打包 hello;
> 
> use nginx;
>
> 使用 nginx；
> 
> sub handler {
>
> 子處理程序{
>     my $r = shift;
>
>     我的 $r = shift;
> 
>     if ($r->request_method ne "POST"（郵政）) {
>
>     如果 ($r->request_method 不等於"POST"（郵政） ) {
>         return DECLINED;
>
>         返回DECLINED ；
>     }
> 
>     if ($r->has_request_body(\&post)) {
>         return OK;
>
>         返回OK ；
>     }
> 
>     return HTTP_BAD_REQUEST;
>
>     返回 HTTP_BAD_REQUEST；
> }
> 
> sub post {
>
> 子帖子{
>     my $r = shift;
>
>     我的 $r = shift;
> 
>     $r->send_http_header;
> 
>     $r->print("request_body: \"", $r->request_body, "\"<br/>");
>
>     $r->print("request_body: \"", $r->request_body, "\" <br/> ");
>     $r->print("request_body_file: \"", $r->request_body_file, "\"<br/>\n");
>
>     $r->print("request_body_file: \"", $r->request_body_file, "\" <br/> \n");
> 
>     return OK;
>
>     返回OK ；
> }
> 
> 1;
> 
> __END__
> ```

`$r->allow_ranges`

разрешает использовать диапазоны байт (byte ranges) при передаче ответа.

允許在發送回應時使用位元組範圍。

`$r->discard_request_body`

указывает nginx игнорировать тело запроса.

告訴nginx忽略請求體。

``$r->header_in(`*поле*`)``

` `$r->header_in(` *字段* `)` `

возвращает значение заданного поля в заголовке запроса клиента.

傳回客戶端請求標頭中指定欄位的值。

`$r->header_only`

определяет, нужно ли передавать клиенту только заголовок ответа или весь ответ.

確定是只向客戶端發送回應頭，還是向客戶端發送整個回應。

``$r->header_out(`*поле*`, `*значение*`)``

` `$r->header_out(` *字段* `, ` *值* `)` `

устанавливает значение для заданного поля в заголовке ответа.

設定響應頭中指定欄位的值。

``$r->internal_redirect(`*uri*`)``

` `$r->internal_redirect(` *嘆氣* `)` `

делает внутреннее перенаправление на указанный `*uri*`. Перенаправление происходит уже после завершения обработчика Perl.

執行內部重定向到指定的`*uri*` 。重定向發生在 Perl 處理程序完成後。

> Начиная с версии 1.17.2 метод принимает экранированные URI и поддерживает перенаправления в именованные location.
>
> 從版本1.17.2開始，該方法接受轉義的URI ，並支援重定向到命名位置。

``$r->log_error(`*код_ошибки*`, `*сообщение*`)``

` `$r->log_error(` *錯誤代碼* `, ` *訊息* `)` `

записывает указанное `*сообщение*` в [error\_log](<285 [02.01 文件] 基本功能.md#error_log>). Если `*код_ошибки*` ненулевой, то к сообщению будет добавлен код ошибки и её описание.

將指定的`*сообщение*`寫入 [error\_log](<285 [02.01 文件] 基本功能.md#error_log>) 。如果`*код_ошибки*`非零，則會將錯誤代碼和描述附加到訊息中。

``$r->print(`*текст*`, ...)``

` `$r->print(` *文本* `, ...)` `

метод передаёт клиенту данные.

該方法將資料傳遞給客戶端。

`$r->request_body`

возвращает тело запроса клиента при условии, что тело не записано во временный файл. Для того чтобы тело запроса клиента гарантированно находилось в памяти, нужно ограничить его размер с помощью [client\_max\_body\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_max_body_size>) и задать достаточной размер для буфера [client\_body\_buffer\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_body_buffer_size>).

傳回客戶端請求體，前提是請求體未寫入臨時檔案。為確保客戶端請求體駐留在記憶體中，請使用 [client\_max\_body\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_max_body_size>)限制其大小，並設定足夠的緩衝區大小 [client\_body\_buffer\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_body_buffer_size>) 。

`$r->request_body_file`

возвращает имя файла, в котором хранится тело запроса клиента. По завершению обработки файл необходимо удалить. Для того чтобы тело запроса клиента всегда записывалось в файл, следует включить [client\_body\_in\_file\_only](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_body_in_file_only>).

傳回儲存用戶端請求正文的檔案名稱。處理完成後，該文件應被刪除。為確保客戶端請求正文始終寫入文件，請包含 [client\_body\_in\_file\_only](<221 [02.01.01 http] 模組 ngx_http_core_module.md#client_body_in_file_only>) 。

`$r->request_method`

возвращает HTTP-метод запроса клиента.

返回HTTP客戶端請求方法。

`$r->remote_addr`

возвращает IP-адрес клиента.

返回IP客戶端位址。

`$r->flush`

немедленно передаёт данные клиенту.

立即將資料傳輸給客戶端。

``$r->sendfile(`*имя*`[, `*смещение*`[, `*длина*`]])``

` `$r->sendfile(` *名稱* `[, ` *偏移量* `[, ` *長度* `]])` `

передаёт клиенту содержимое указанного файла. Необязательные параметры задают начальное смещение и длину передаваемых данных. Непосредственно передача данных происходит уже после завершения обработчика Perl.

將指定文件的內容傳輸到客戶端。可選參數指定要傳輸的資料的起始偏移量和長度。實際的資料傳輸在 Perl 處理程序完成後進行。

``$r->send_http_header([`*тип*`])``

` `$r->send_http_header([` *類型* `])` `

передаёт клиенту заголовок ответа. Необязательный параметр `*тип*` устанавливает значение поля “Content-Type”（內容類型） в заголовке ответа. Пустая строка в качестве типа запрещает передачу поля “Content-Type”（內容類型）.

向客戶端傳遞回應頭。可選參數`*тип*`用於設定響應頭中“Content-Type”（內容類型）字段的值。如果類型為空字串，則不會傳遞“Content-Type”（內容類型）欄位。

``$r->status(`*код*`)``

` `$r->status(` *代碼* `)` `

устанавливает код ответа.

設定響應代碼。

``$r->sleep(`*миллисекунды*`, `*обработчик*`)``

` `$r->sleep(` *毫秒* `, ` *處理程序* `)` `

устанавливает указанный обработчик и останавливает обработку запроса на заданное время. nginx в это время продолжает обрабатывать другие запросы. По истечении указанного времени nginx вызовет установленный обработчик. Обратите внимание, что нужно передавать ссылку на функцию обработчика. Для передачи данных между обработчиками следует использовать `$r->variable()`. Пример:

安裝指定的處理程序並暫停請求處理指定時間。在此期間，NGINX 會繼續處理其他請求。指定時間過後，NGINX 將呼叫已安裝的處理程序。請注意，您必須傳遞對處理程序函數的參考。若要在處理程序之間傳遞數據，請使用`$r->variable()` 。範例：

> ```
> package hello;
>
> 打包 hello;
> 
> use nginx;
>
> 使用 nginx；
> 
> sub handler {
>
> 子處理程序{
>     my $r = shift;
>
>     我的 $r = shift;
> 
>     $r->discard_request_body;
>     $r->variable("var", "OK"（好的）);
>
>     $r->variable("var", "OK"（好的） );
>     $r->sleep(1000, \&next);
> 
>     return OK;
>
>     返回OK ；
> }
> 
> sub next {
>
> 子程序下一個{
>     my $r = shift;
>
>     我的 $r = shift;
> 
>     $r->send_http_header;
>     $r->print($r->variable("var"));
> 
>     return OK;
>
>     返回OK ；
> }
> 
> 1;
> 
> __END__
> ```

``$r->unescape(`*текст*`)``

` `$r->unescape(` *文本* `)` `

декодирует текст, заданный в виде “%XX”.

解碼以「% XX 」形式給出的文字。

`$r->uri`

возвращает URI запроса.

返回查詢的URI 。

``$r->variable(`*имя*`[, `*значение*`])``

` `$r->variable(` *名稱* `[, ` *值* `])` `

возвращает или устанавливает значение указанной переменной. Переменные локальны для каждого запроса.
