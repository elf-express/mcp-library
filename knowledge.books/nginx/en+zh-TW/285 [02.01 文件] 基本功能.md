Если `accept_mutex` включён, рабочие процессы будут принимать новые соединения по очереди. В противном случае о новых соединениях будет сообщаться сразу всем рабочим процессам, и при низкой интенсивности поступления новых соединений часть рабочих процессов может работать вхолостую.

如果啟用`accept_mutex` ，工作進程將一次接受一個新連線。否則，所有工作進程將同時收到新連線的通知，如果傳入連線速率較低，則某些工作進程可能會處於空閒狀態。

> Нет необходимости включать `accept_mutex` на системах, поддерживающих флаг [EPOLLEXCLUSIVE](<207 [02.01 文件] 化合物加工方法.md#epoll>) (1.11.3), или при использовании [reuseport](<221 [02.01.01 http] 模組 ngx_http_core_module.md#reuseport>).
>
> 在支援 [EPOLLEXCLUSIVE](<207 [02.01 文件] 化合物加工方法.md#epoll>) ( 1.11.3 ) 標誌的系統上，或在使用 [reuseport](<221 [02.01.01 http] 模組 ngx_http_core_module.md#reuseport>)時，無需啟用`accept_mutex` 。

> До версии 1.11.3 по умолчанию использовалось значение `on`.
>
> 在版本1.11.3預設值為`on` 。

Включает отладочный лог для отдельных клиентских соединений. Для остальных соединений используется уровень лога, заданный директивой [error\_log](#error_log). Отладочный лог для соединений через UNIX-сокеты (1.3.0, 1.2.1) включается параметром “`unix:`”.

啟用單一客戶端連線的調試日誌記錄。對於其他連接，使用 [error\_log](#error_log)指令指定的日誌等級。調試連線可透過 IPv4 或 IPv6 ( 1.3.0, 1.2.1 ) 位址或網路指定。也可以使用主機名稱指定連線。透過UNIX套接字 ( 1.3.0, 1.2.1 ) 連接的偵錯日誌記錄由「 `unix:` 」參數啟用。

Эта директива используется для отладки.

此指令用於調試。

В случае обнаружения внутренней ошибки, например, утечки сокетов в момент перезапуска рабочих процессов, включение `debug_points` приводит к созданию core-файла (`abort`) или остановке процесса (`stop`) с целью последующей диагностики с помощью системного отладчика.

如果偵測到內部錯誤，例如在工作流程重新啟動期間發生套接字洩漏，啟用`debug_points`將建立核心檔案 ( `abort` ) 或停止進程 ( `stop` ) 以便使用系統偵錯器進行後續診斷。

По умолчанию nginx удаляет все переменные окружения, унаследованные от своего родительского процесса, кроме переменной TZ. Эта директива позволяет сохранить часть унаследованных переменных, поменять им значения или же создать новые переменные окружения. Эти переменные затем:

預設情況下，nginx 會移除從其父進程繼承的所有環境變量，但TZ變量除外。此指令可讓您保留部分繼承的變數、變更其值或建立新的環境變數。這些變數包括：

-   наследуются во время [обновления исполняемого файла на лету](<204 [02.01 文件] nginx 管理.md#upgrade>);  
    在 [即時可執行更新 期間繼承](<204 [02.01 文件] nginx 管理.md#upgrade>) ;
-   используются модулем [ngx\_http\_perl\_module](<247 [02.01.01 http] ngx_http_perl_module 模組.md>);  
    由 [ngx\_http\_perl\_module 模組使用](<247 [02.01.01 http] ngx_http_perl_module 模組.md>) ;
-   используются рабочими процессами. Следует иметь в виду, что управление поведением системных библиотек подобным образом возможно не всегда, поскольку зачастую библиотеки используют переменные только во время инициализации, то есть ещё до того, как их можно задать с помощью данной директивы. Исключением из этого является упомянутое выше [обновление исполняемого файла на лету](<204 [02.01 文件] nginx 管理.md#upgrade>).  
    供工作進程使用。需要注意的是，並非總是能夠以這種方式控制系統庫的行為，因為庫通常僅在初始化期間使用變量，也就是說，在可以透過此指令設定變數之前才會使用。上述的[即時可執行檔更新](<204 [02.01 文件] nginx 管理.md#upgrade>)是一個例外。

Если переменная TZ не описана явно, то она всегда наследуется и всегда доступна модулю [ngx\_http\_perl\_module](<247 [02.01.01 http] ngx_http_perl_module 模組.md>).

如果變數TZ沒有明確聲明，則它總是被繼承，並且始終可供[ngx\_http\_perl\_module模組](<247 [02.01.01 http] ngx_http_perl_module 模組.md>)使用。

Конфигурирует запись в лог. На одном уровне конфигурации может использоваться несколько логов (1.5.2). Если на уровне конфигурации `main` запись лога в файл явно не задана, то используется файл по умолчанию.

配置日誌記錄。可以在單一配置等級 ( 1.5.2 ) 使用多個日誌。如果在設定等級`main`未明確設定日誌記錄到文件，則使用預設檔。

Первый параметр задаёт `*файл*`, который будет хранить лог. Специальное значение `stderr` выбирает стандартный файл ошибок. Запись в [syslog](<321 [02.01 文件] 寫入系統日誌.md>) настраивается указанием префикса “`syslog:`”. Запись в [кольцевой буфер в памяти](<205 [02.01 文件] 偵錯日誌.md#memory>) настраивается указанием префикса “`memory:`” и `*размера*` буфера и как правило используется для отладки (1.7.11).

第一個參數指定`*файл*` ，用於儲存日誌。特殊值`stderr`選擇標準錯誤檔案。寫入[syslog](<321 [02.01 文件] 寫入系統日誌.md>)透過指定前綴「 `syslog:` 」進行設定。寫入 [記憶體環形緩衝區](<205 [02.01 文件] 偵錯日誌.md#memory>)透過指定前綴「 `memory:` 」和`*размера*`緩衝區進行配置，通常用於除錯（ 1.7.11 ）。

Второй параметр определяет `*уровень*` лога и может принимать одно из следующих значений: `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert` или `emerg`. Уровни лога, указанные выше, перечислены в порядке возрастания важности. При установке определённого уровня в лог попадают все сообщения указанного уровня и уровней большей важности. Например, при стандартном уровне `error` в лог попадают сообщения уровней `error`, `crit`, `alert` и `emerg`. Если этот параметр не задан, используется `error`.

第二個參數定義日誌等級`*уровень*` ，其值可以是`debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`或`emerg` 。上述日誌等級依嚴重性遞增的順序排列。設定特定等級後，將記錄指定等級及更高等級的所有訊息。例如，預設等級為`error`將記錄等級為`error`, `crit`, `alert`和`emerg`的訊息。如果未指定此參數，則使用`error` 。

> Для работы уровня лога `debug` необходимо сконфигурировать nginx с `--with-debug`, см. “[Отладочный лог](<205 [02.01 文件] 偵錯日誌.md>)”.
>
> 若要讓日誌等級`debug`生效，您需要使用`--with-debug`設定 nginx，請參閱「[偵錯日誌](<205 [02.01 文件] 偵錯日誌.md>) 」。

最佳值取決於多種因素，包括（但不限於）處理器核心數、包含資料的硬碟數量以及工作負載情況。如果您在選擇合適的值時遇到困難，可以先將其設定為等於處理器核心數（「 `auto` 」值會嘗試自動確定此值）。
