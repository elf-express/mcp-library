The `ngx_http_rewrite_module` module is used to change request URI using PCRE regular expressions, return redirects, and conditionally select configurations.

`ngx_http_rewrite_module`模組用於使用PCRE正規表示式變更請求URI ，返回重定向，並有條件地選擇配置。

The [break](#break), [if](#if), [return](#return), [rewrite](#rewrite), and [set](#set) directives are processed in the following order:

[break](#break) 、[if](#if) 、[return](#return) 、[rewrite](#rewrite)和 [set](#set)指令依下列順序處理：

-   the directives of this module specified on the [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) level are executed sequentially;  
    本模組在 [伺服器](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>)層級指定的指令依序執行；
-   repeatedly:  
    反覆：
    -   a [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) is searched based on a request URI;  
        根據請求URI搜尋[位置](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) ；
    -   the directives of this module specified inside the found location are executed sequentially;  
        此模組中指定的指令在找到的位置內依序執行；
    -   the loop is repeated if a request URI was [rewritten](#rewrite), but not more than [10 times](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>).  
        如果請求URI被[重寫](#rewrite) ，則循環重複，但不超過[10次](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>) 。

Regular expressions can contain captures that are made available for later reuse in the `$1`..`$9` variables (see [Regular expression captures](https://nginx.org/en/docs/regex_captures.html)).     使用「 `~` 」（區分大小寫匹配）和「 `~*` 」（不區分大小寫匹配）運算符，可以將變數與正規表示式進行配對。正規表示式可以包含擷取訊息，這些訊息可在`$1`..`$9` 」變數中重複使用（請參閱[正規表示式擷取](https://nginx.org/en/docs/regex_captures.html) ”）。此外，也可以使用否定運算子「 `!~` 」和「 `!~*` 」。如果正規表示式包含「 `}` 」或「 `;` 」字符，則整個表達式應使用單引號或雙引號括起來。
-   checking of a file existence with the “`-f`” and “`!-f`” operators;  
    使用「 `-f` 」和「 `!-f` 」運算子檢查檔案是否存在；

    使用「 `-e` 」和「 `!-e` 」運算子檢查檔案、目錄或符號連結是否存在；
-   checking for an executable file with the “`-x`” and “`!-x`” operators.  
    使用「 `-x` 」和「 `!-x` 」運算子檢查可執行檔。

Stops processing and returns the specified `*code*` to a client. The non-standard code 444 closes a connection without sending a response header.

停止處理並向客戶端傳回指定的`*code*` 。非標準代碼 444 表示關閉連線而不發送回應頭。

Starting from version 0.8.42, it is possible to specify either a redirect URL (for codes 301, 302, 303, 307, and 308) or the response body `*text*` (for other codes). A response body text and redirect URL can contain variables. As a special case, a redirect URL can be specified as a URI local to this server, in which case the full redirect URL is formed according to the request scheme (`$scheme`) and the [server\_name\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) and [port\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#port_in_redirect>) directives.

從版本0.8.42開始，可以指定重定向URL （對應狀態碼301、302、303、307和308）或響應體`*text*` （對應其他狀態碼）。響應體文字和重定向URL可以包含變數。特殊情況下，重定向URL可以指定為本伺服器本地重定向URI ，此時完整的重定向URL將根據請求方案（ `$scheme` ）以及[server\_name\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) ）以及[server\_name\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#port_in_redirect>)

In addition, a `*URL*` for temporary redirect with the code 302 can be specified as the sole parameter. Such a parameter should start with the “`http://`”, “`https://`”, or “`$scheme`” string. A `*URL*` can contain variables.

此外，可以將代碼 302 用於暫時重定向的`*URL*` 指定為唯一參數。此類參數應以「`http://`」、「`https://`」或「`$scheme`」字串開頭。 `*URL*` 可以包含變數。

> Only the following codes could be returned before version 0.7.51: 204, 400, 402 — 406, 408, 410, 411, 413, 416, and 500 — 504.
>
> 在版本0.7.51之前，只能回傳以下程式碼：204、400、402—406、408、410、411、413、416和500—504。

> The code 307 was not treated as a redirect until versions 1.1.16 and 1.0.13.
>
> 在1.1.16和1.0.13版本之前，代碼 307 不被視為重定向。

| Syntax:<br>語法： | ``**rewrite** `*regex*` `*replacement*` [`*flag*`];``<br>` `**rewrite** ` *正規表達式* ` ` *替換* ` [` *標誌* `];` ` |

If the specified regular expression matches a request URI, URI is changed as specified in the `*replacement*` string. The `rewrite` directives are executed sequentially in order of their appearance in the configuration file. It is possible to terminate further processing of the directives using flags. If a replacement string starts with “`http://`”, “`https://`”, or “`$scheme`”, the processing stops and the redirect is returned to a client.

如果指定的正規表示式與請求匹配，則URI, URI將按照`*replacement*`字串中的指定進行更改。 `rewrite`指令依照它們在設定檔中出現的順序依序執行。可以使用標誌終止指令的進一步處理。如果替換字串以「`http://`」、「`https://`」或「`$scheme`」開頭，則處理停止並將重定向傳回給用戶端。

An optional `*flag*` parameter can be one of:

可選參數`*flag*`可以是以下之一：

`last`

stops processing the current set of `ngx_http_rewrite_module` directives and starts a search for a new location matching the changed URI;

停止處理目前`ngx_http_rewrite_module`指令集，並開始搜尋與已更改的URI匹配的新位置；

`break`

stops processing the current set of `ngx_http_rewrite_module` directives as with the [break](#break) directive;

停止處理目前一組`ngx_http_rewrite_module`指令，就像 [break](#break)指令一樣；

`redirect`

returns a temporary redirect with the 302 code; used if a replacement string does not start with “`http://`”, “`https://`”, or “`$scheme`”;

傳回帶有 302 代碼的暫時重定向；如果替換字串不以「 `http://` 」、「 `https://` 」或「 `$scheme` 」開頭，則使用此方法；

`permanent`

returns a permanent redirect with the 301 code.

返回永久重定向，重定向代碼為 301。

The full redirect URL is formed according to the request scheme (`$scheme`) and the [server\_name\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) and [port\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#port_in_redirect>) directives.

完整的重定向URL是根據請求方案 ( `$scheme` ) 和 [server\_name\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server_name_in_redirect>)和 [port\_in\_redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#port_in_redirect>)指令形成的。

Example:

例子：

> ```
> server {
>
> 伺服器 {
>     ...
>     rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 last;
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra  last;
>
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra last;
>     return  403;
>
>     返回 403；
>     ...
> }
> ```

But if these directives are put inside the “`/download/`” location, the `last` flag should be replaced by `break`, or otherwise nginx will make 10 cycles and return the 500 error:

但是，如果將這些指令放在「 `/download/` 」位置內，則應將`last`標誌替換為`break` ，否則nginx將執行10次循環並傳回500錯誤：

> ```
> location /download/ {
>     rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 break;
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra  break;
>
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra break;
>     return  403;
>
>     返回 403；
> }
> ```

If a `*replacement*` string includes the new request arguments, the previous request arguments are appended after them. If this is undesired, putting a question mark at the end of a replacement string avoids having them appended, for example:

如果`*replacement*`字串包含新的請求參數，則先前的請求參數會附加到其後。如果不希望這樣做，可以在替換字串末尾添加問號，例如：

> ```
> rewrite ^/users/(.*)$ /show?user=$1? last;
> ```

If a regular expression includes the “`}`” or “`;`” characters, the whole expressions should be enclosed in single or double quotes.

如果正規表示式包含「 `}` 」或「 `;` 」字符，則整個表達式應放在單引號或雙引號內。

#### Internal Implementation｜內部實施

The `ngx_http_rewrite_module` module directives are compiled at the configuration stage into internal instructions that are interpreted during request processing. An interpreter is a simple virtual stack machine.

`ngx_http_rewrite_module`模組指令在配置階段被編譯成內部指令，並在請求處理期間進行解釋。解釋器是一個簡單的虛擬堆疊機器。
