## Модуль ngx\_http\_upstream\_conf\_module｜模組 ngx\_http\_upstream\_conf\_module

|   |
| --- |
| [Пример конфигурации](#example)<br>[Директивы](#directives)<br>     [upstream\_conf](#upstream_conf)<br>[設定範例](#example)<br> [指令](#directives)<br> [上游設定](#upstream_conf) |

Модуль `ngx_http_upstream_conf_module` позволяет оперативно настраивать группы серверов при помощи простого HTTP-интерфейса без необходимости перезапуска nginx. Группа серверов [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>) должна находиться в разделяемой памяти.

`ngx_http_upstream_conf_module`模組可讓您使用簡單的HTTP介面快速設定伺服器群組，而無需重新啟動 nginx。 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>)伺服器群組必須位於共享記憶體中。

> Этот модуль был доступен как часть [коммерческой подписки](https://www.f5.com/products/nginx) до версии 1.13.10. Модуль был заменён модулем [ngx\_http\_api\_module](https://nginx.org/ru/docs/http/ngx_http_api_module.html) в версии 1.13.3.
>
> 本模組在版本1.13.10之前作為 [商業訂閱](https://www.f5.com/products/nginx)的一部分提供。本模組在版本1.13.3中被 [ngx\_http\_api\_module](https://nginx.org/ru/docs/http/ngx_http_api_module.html)模組取代。

#### Пример конфигурации｜配置範例

> ```
> upstream backend {
>
> 上游後端{
>     zone upstream_backend 64k;
>
>     區域 upstream_backend 64k；
> 
>     ...
> }
> 
> server {
>
> 伺服器{
>     location /upstream_conf {
>
>     位置/upstream_conf {
>         upstream_conf;
>
>         上游_conf；
>         allow 127.0.0.1;
>
>         允許127.0.0.1 ；
>         deny all;
>
>         全部否認；
>     }
> }
> ```

#### Директивы｜指令

|   |   |
| --- | --- |
| Синтаксис:<br>文法： | `**upstream_conf**;` |
| Умолчание:<br>預設值： | — |
| Контекст:<br>背景： | `location` |

Активирует HTTP-интерфейс для настройки групп серверов в содержащем location. Доступ в location следует [ограничить](<221 [02.01.01 http] 模組 ngx_http_core_module.md#satisfy>).

啟用HTTP接口，用於配置包含位置中的伺服器群組。對該位置的存取應受(https://nginx.org/ru/docs/http/ngx_http_core_module.html#satisfy)限制。

С помощью команд настройки можно:

使用設定命令，您可以：

-   просматривать конфигурацию группы;  
    查看組配置；
-   просматривать или изменять конфигурацию, а также удалять серверы;  
    查看或更改配置，或刪除伺服器；
-   добавлять новые серверы.  
    新增伺服器。

> Поскольку адреса в группе не обязаны быть уникальными, обращение к отдельным серверам в группе осуществляется по их идентификаторам. Идентификаторы назначаются автоматически и показываются при добавлении сервера или просмотре конфигурации группы.
>
> 由於群組內位址無需唯一，因此群組內的各個伺服器透過其 ID 進行存取。 ID 會自動分配，並在新增伺服器或查看群組配置時顯示。

Команда настройки состоит из параметров, передаваемых в аргументах запроса, например:

setup 指令由查詢參數中傳遞的參數組成，例如：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend
> ```

Поддерживаются следующие параметры:

支援以下參數：

`stream=`

Выбирает группу серверов [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md>). Если параметр не задан, будет выбрана группа серверов [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>).

選擇 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md>)伺服器群組。如果未指定此參數，則會選擇 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>)伺服器群組。

`upstream=``*имя*`

Выбирает группу серверов для работы. Параметр является обязательным.

選擇要操作的伺服器群組。此參數為必填項。

`id=``*число*`

Выбирает сервер для просмотра, изменения или удаления.

選擇要查看、修改或刪除的伺服器。

`remove=`

Удаляет сервер из группы.

從群組中移除伺服器。

`add=`

Добавляет новый сервер в группу.

在群組中新增一台新伺服器。

`backup=`

Необходим для добавления запасного сервера.

需要新增備份伺服器。

> До версии 1.7.2 параметр `backup=` требовался также для просмотра, изменения или удаления существующих запасных серверов.
>
> 在1.7.2查看、修改或刪除現有備份伺服器還需要`backup=`參數。

`server=``*адрес*`

То же, что и параметр “`адрес`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)群組伺服器的「 `адрес` 」參數相同。

При добавлении сервер можно задать в виде доменного имени. В этом случае любые изменения IP-адресов, соответствующих доменному имени сервера, отслеживаются и автоматически применяются к конфигурации группы без необходимости перезапуска nginx (1.7.2). Для этого в блоке [http](<221 [02.01.01 http] 模組 ngx_http_core_module.md#resolver>) или [stream](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#resolver>) должна быть задана директива “`resolver`”. См. также параметр “`resolve`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#resolve>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#resolve>).

新增伺服器時，您可以將其指定為網域名稱。在這種情況下，與伺服器網域對應的位址IP ）的任何變更都會被追蹤並自動套用到群組設定中，無需重新啟動 nginx（ 1.7.2 ）。為此，必須在 [http](<221 [02.01.01 http] 模組 ngx_http_core_module.md#resolver>)或 [stream](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#resolver>)程式碼區塊中指定「 `resolver` 」指令。另請參閱 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#resolve>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#resolve>)群組伺服器的「 `resolve` 」參數。

`service=``*имя*`

То же, что и параметр “`service`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#service>) (1.9.13).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#service>) ( 1.9.13 ) 群組伺服器的「 `service` 」參數相同。

`weight=``*число*`

То же, что и параметр “`weight`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#weight>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#weight>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#weight>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#weight>)組伺服器的「 `weight` 」參數相同。

`max_conns=``*число*`

То же, что и параметр “`max_conns`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_conns>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_conns>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_conns>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_conns>)群組伺服器的「 `max_conns` 」參數相同。

`max_fails=``*число*`

То же, что и параметр “`max_fails`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_fails>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_fails>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_fails>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_fails>)群組伺服器的「 `max_fails` 」參數相同。

`fail_timeout=``*время*`

То же, что и параметр “`fail_timeout`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#fail_timeout>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#fail_timeout>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#fail_timeout>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#fail_timeout>)群組伺服器的「 `fail_timeout` 」參數相同。

`slow_start=``*время*`

То же, что и параметр “`slow_start`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#slow_start>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#slow_start>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#slow_start>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#slow_start>)群組伺服器的「 `slow_start` 」參數相同。

`down=`

То же, что и параметр “`down`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#down>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#down>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#down>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#down>)群組伺服器的「 `down` 」參數相同。

`drain=`

Переводит сервер группы серверов [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>) в режим “draining” (1.7.5). В этом режиме на сервер будут проксироваться только [привязанные](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#sticky>) к нему запросы.

將 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>)伺服器群組切換到「清空」模式 ( 1.7.5 )。在此模式下，只有綁定到(https://nginx.org/ru/docs/http/ngx_http_upstream_module.html#sticky)的請求才會被代理到該伺服器。

`up=`

Параметр, обратный по значению параметру “`down`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#down>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#down>).

此參數為 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#down>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#down>)組伺服器的「 `down` 」參數的倒數。

`route=``*строка*`

То же, что и параметр “`route`” сервера группы [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#route>).

與 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#route>)組伺服器的「 `route` 」參數相同。

Первые три параметра выбирают объект. Объектом может быть либо группа серверов http или stream, либо отдельный сервер. Если остальные параметры не указаны, то показывается конфигурация выбранной группы или сервера.

前三個參數用於選擇物件。物件可以是 HTTP 伺服器群組或流伺服器群組，也可以是單一伺服器。如果未指定其餘參數，則顯示所選伺服器群組或伺服器的配置。

Например, команда для просмотра конфигурации всей группы выглядит следующим образом:

例如，查看整個群組的配置的命令如下所示：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend
> ```

Для просмотра конфигурации отдельного сервера следует указать его идентификатор:

若要查看單一伺服器的配置，必須指定其 ID：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend&id=42
> ```

Для добавления нового сервера в группу следует указать его адрес в параметре “`server=`”. Если остальные параметры не указаны, то при добавлении сервера их значения будут установлены по умолчанию (см. директиву “`server`” для [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) или [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)).

若要為群組中新增伺服器，請在「 `server=` 」參數中指定其位址。如果未指定其他參數，則在新增伺服器時，它們的值將設定為預設值（請參閱 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>)或 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)的「 `server` 」指令）。

Например, команда для добавления нового основного сервера в группу выглядит следующим образом:

例如，向群組中新增主伺服器的命令如下所示：

> ```
> http://127.0.0.1/upstream_conf?add=&upstream=backend&server=127.0.0.1:8080
> ```

Добавление нового запасного сервера происходит следующим образом:

新增新的備份伺服器的操作步驟如下：

> ```
> http://127.0.0.1/upstream_conf?add=&upstream=backend&backup=&server=127.0.0.1:8080
> ```

Добавление нового основного сервера с нестандартными значениями параметров и с пометкой его как постоянно недоступного (“`down`”) происходит следующим образом:

新增具有非標準參數值的新主伺服器並將其標記為永久不可用（“ `down` ”）的操作如下：

> ```
> http://127.0.0.1/upstream_conf?add=&upstream=backend&server=127.0.0.1:8080&weight=2&down=
> ```

Для удаления сервера следует указать его идентификатор:

若要刪除伺服器，必須指定其 ID：

> ```
> http://127.0.0.1/upstream_conf?remove=&upstream=backend&id=42
> ```

Пометка существующего сервера как постоянно недоступного (“`down`”) происходит следующим образом:

將現有伺服器標記為永久不可用（「 `down` 」）的操作方法如下：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend&id=42&down=
> ```

Изменение адреса существующего сервера происходит следующим образом:

更改現有伺服器的位址依下列步驟操作：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend&id=42&server=192.0.2.3:8123
> ```

Изменение других параметров существующего сервера происходит следующим образом:

更改現有伺服器的其他參數如下操作：

> ```
> http://127.0.0.1/upstream_conf?upstream=backend&id=42&max_fails=3&weight=4
> ```

Вышеприведённые примеры актуальны для группы серверов [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>). Аналогичные примеры для группы серверов [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md>) требуют указания параметра “`stream=`”.

以上範例適用於 [http](<266 [02.01.01 http] ngx_http_upstream_module 模組.md>)伺服器群組。對於 [stream](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md>)伺服器群組，類似範例需要指定「 `stream=` 」參數。
