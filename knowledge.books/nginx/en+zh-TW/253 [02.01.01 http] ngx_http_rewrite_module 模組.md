Модуль `ngx_http_rewrite_module` позволяет изменять URI запроса с помощью регулярных выражений PCRE, делать перенаправления и выбирать конфигурацию по условию.

`ngx_http_rewrite_module`模組可讓您使用正規表示式PCRE修改URI查詢，進行重定向，並有條件地選擇配置。

Директивы [break](#break), [if](#if), [return](#return), [rewrite](#rewrite) и [set](#set) обрабатываются в следующем порядке:

[break](#break) 、[if](#if) 、[return](#return) 、[rewrite](#rewrite)和 [set](#set)指令依下列順序處理：

-   последовательно выполняются директивы этого модуля, описанные на уровне [server](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>);  
    本模組的指令（在 [伺服器 等級](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>)中描述）依序執行；
-   в цикле:  
    在循環中：
    -   ищется [location](<221 [02.01.01 http] 模組 ngx_http_core_module.md#location>) по URI запроса;  
        正在尋找 [位置](<221 [02.01.01 http] 模組 ngx_http_core_module.md#location>)在URI請求中;
    -   последовательно выполняются директивы этого модуля, описанные в найденном location;  
        此模組的指令（在找到的位置有描述）依序執行；
    -   цикл повторяется, если URI запроса [изменялся](#rewrite), но не более [10 раз](<221 [02.01.01 http] 模組 ngx_http_core_module.md#internal>).  
        如果請求的URI發生(https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html#rewrite) ，則重複該循環，但(https://nginx.org/ru/docs/http/ngx_http_core_module.html#internal)次數不得超過 10 次。

Проверяется указанное `*условие*`. Если оно истинно, то выполняются указанные в фигурных скобках директивы этого модуля и запросу назначается конфигурация, указанная внутри директивы `if`. Конфигурации внутри директив `if` наследуются с предыдущего уровня конфигурации.

檢查指定的`*условие*`。如果為真，則執行大括號中指定的該模組的指令，並將請求指派給`if`指令內指定的配置。 `if`指令中的配置繼承自先前的配置等級。

В качестве условия могут быть заданы:

可指定以下條件：

-   имя переменной; ложными значениями переменной являются пустая строка или “`0`”;  
    變數名；變數的 false 值為空字串或「 `0` 」；
    
    > До версии 1.0.1 ложным значением также являлась любая строка, начинающаяся на “`0`”.
    >
    > 在版本1.0.1之前，任何以「 `0` 」開頭的字串也是 false 值。
    
-   сравнение переменной со строкой с помощью операторов “`=`” и “`!=`”;  
    使用「 `=` 」和「 `!=` 」運算子將變數與字串進行比較；
-   соответствие переменной регулярному выражению с учётом регистра символов — “`~`” и без него — “`~*`”. В регулярных выражениях можно использовать выделения, которые затем доступны в виде переменных `$1`..`$9` (см. [Выделения в регулярных выражениях](https://nginx.org/ru/docs/regex_captures.html)). Также можно использовать отрицательные операторы “`!~`” и “`!~*`”. Если в регулярном выражении встречаются символы “`}`” или “`;`”, то всё выражение следует заключить в одинарные или двойные кавычки.  
    將變數與正規表示式配對時區分大小寫——例如“ `~` ”，以及不區分大小寫——例如“ `~*` ”。正規表示式可以使用捕獲，捕獲的字元隨後可作為變數使用，例如`$1`..`$9` ”（請參閱[正規表達式中的捕獲](https://nginx.org/ru/docs/regex_captures.html) ”）。也可以使用否定運算子「 `!~` 」和「 `!~*` 」。如果正規表示式包含字元“ `}` ”或“ `;` ”，則整個表達式應使用單引號或雙引號括起來。
-   проверка существования файла с помощью операторов “`-f`” и “`!-f`”;  
    使用「 `-f` 」和「 `!-f` 」運算子檢查檔案是否存在；
-   проверка существования каталога с помощью операторов “`-d`” и “`!-d`”;  
    使用運算子「 `-d` 」和「 `!-d` 」檢查目錄是否存在；
-   проверка существования файла, каталога или символической ссылки с помощью операторов “`-e`” и “`!-e`”;  
    使用「 `-e` 」和「 `!-e` 」運算子檢查檔案、目錄或符號連結是否存在；
-   проверка исполняемости файла с помощью операторов “`-x`” и “`!-x`”.  
    使用「 `-x` 」和「 `!-x` 」運算子檢查檔案的可執行性。

>

>

>     set $id $1;
>
>     設定 $id $1;
> }
>

>

Завершает обработку и возвращает клиенту указанный `*код*`. Нестандартный код 444 закрывает соединение без передачи заголовка ответа.

處理完成並向客戶端傳回指定的`*код*` 。非標準的444代碼表示關閉連接，而不發送回應頭。

Начиная с версии 0.8.42 можно задать либо URL перенаправления (для кодов 301, 302, 303, 307 и 308) либо `*текст*` тела ответа (для остальных кодов). В тексте тела ответа и URL перенаправления можно использовать переменные. Как частный случай, URL перенаправления может быть задан как URI, локальный для данного сервера, при этом полный URL перенаправления формируется согласно схеме запроса (`$scheme`) и директивам [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) и [port\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#port_in_redirect>).

從版本 0.8.42 開始，您可以指定重新導向 URL（對於程式碼 301、302、303、307 和 308）或回應正文的 `*текст*`（對於其他程式碼）。您可以在回應正文和重定向 URL 中使用變數。作為一種特殊情況，重定向 URL 可以指定為給定伺服器本地的 URI，並根據請求方案 (`$scheme`) 和 [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) 和 [port\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#port_in_redirect>) 指令形成完整的重定向 URL。

Кроме того, в качестве единственного параметра можно указать `*URL*` для временного перенаправления с кодом 302. Такой параметр должен начинаться со строк “`http://`”, “`https://`” или “`$scheme`”. В `*URL*` можно использовать переменные.

您也可以指定 `*URL*` 作為暫存 302 重定向的唯一參數。此參數必須以字串「`http://`」、「`https://`」或「`$scheme`」開頭。變數可以在`*URL*`中使用。

> До версии 0.7.51 можно было возвращать только следующие коды: 204, 400, 402 — 406, 408, 410, 411, 413, 416 и 500 — 504.
>
> 在版本0.7.51只能回傳以下程式碼：204、400、402–406、408、410、411、413、416和500–504。

> До версий 1.1.16 и 1.0.13 код 307 не обрабатывался как перенаправление.
>
> 在1.1.16和1.0.13代碼 307 不被視為重定向。

> До версии 1.13.0 код 308 не обрабатывался как перенаправление.
>
> 在版本1.13.0代碼308不被視為重定向。

Если указанное регулярное выражение соответствует URI запроса, URI изменяется в соответствии со строкой замены. Директивы `rewrite` выполняются последовательно, в порядке их следования в конфигурационном файле. С помощью флагов можно прекратить дальнейшую обработку директив. Если строка замены начинается с “`http://`”, “`https://`” или “`$scheme`”, то обработка завершается и клиенту возвращается перенаправление.

如果指定的正規表示式與查詢的URI匹配，則修改URI以匹配替換字串。 `rewrite`指令依照它們在設定檔中出現的順序順序執行。標誌可用於停止指令的進一步處理。如果替換字串以「`http://`」、「`https://`」或「`$scheme`」開頭，則處理完成並向用戶端傳回重定向。

Необязательный параметр `*флаг*` может быть одним из:

可選參數`*флаг*`可以是下列值之一：

`last`

завершает обработку текущего набора директив модуля `ngx_http_rewrite_module`, после чего ищется новый location, соответствующий изменённому URI;

完成目前模組指令集`ngx_http_rewrite_module`的處理後，搜尋與修改後的URI對應的新位置；

`break`

завершает обработку текущего набора директив модуля `ngx_http_rewrite_module` аналогично директиве [break](#break);

終止目前模組指令集的處理`ngx_http_rewrite_module`類似 [break 指令](#break) ;

`redirect`

возвращает временное перенаправление с кодом 302; используется, если заменяющая строка не начинается с “`http://`”, “`https://`” или “`$scheme`”;

傳回代碼為 302 的暫時重定向；如果替換字串不以「 `http://` 」、「 `https://` 」或「 `$scheme` 」開頭，則使用此重定向；

`permanent`

возвращает постоянное перенаправление с кодом 301.

返回永久重定向，代碼為 301。

Полный URL перенаправлений формируется согласно схеме запроса (`$scheme`) и директив [server\_name\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>) и [port\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#port_in_redirect>).

完整的URL重定向是根據請求方案（ `$scheme` ）和[server\_name\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_name_in_redirect>)和[port\_in\_redirect](<221 [02.01.01 http] 模組 ngx_http_core_module.md#port_in_redirect>)形成的。

Пример:

例子：

> ```
> server {
>
> 伺服器 {
>     ...
>     rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 last;
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra  last;
>
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra last;
>     return  403;
>
>     返回 403；
>     ...
> }
> ```

Если же эти директивы поместить в location “`/download/`”, то нужно заменить флаг `last` на `break`, иначе nginx сделает 10 циклов и вернёт ошибку 500:

如果將這些指令放在「 `/download/` 」位置，則需要將`last`標誌替換為`break` ，否則nginx將執行10次循環並回傳錯誤500：

> ```
> location /download/ {
>     rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 break;
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra  break;
>
>     rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra break;
>     return  403;
>
>     返回 403；
> }
> ```

Если в строке замены указаны новые аргументы запроса, то предыдущие аргументы запроса добавляются после них. Если такое поведение нежелательно, можно отказаться от этого добавления, указав в конце строки замены знак вопроса, например:

如果在替換字串中指定了新的查詢參數，則先前的查詢參數會附加到這些參數之後。如果不希望出現這種行為，可以透過在替換字串末尾添加問號來停用此附加操作，例如：

> ```
> rewrite ^/users/(.*)$ /show?user=$1? last;
> ```

Если в регулярном выражении встречаются символы “`}`” или “`;`”, то всё выражение следует заключить в одинарные или двойные кавычки.

如果正規表示式包含字元“ `}` ”或“ `;` ”，則整個表達式必須用單引號或雙引號括起來。

#### Внутреннее устройство｜內部結構

Директивы модуля `ngx_http_rewrite_module` компилируются на стадии конфигурации во внутренние инструкции, интерпретируемые во время обработки запроса. Интерпретатор представляет из себя простую стековую виртуальную машину.

`ngx_http_rewrite_module`模組的指令在配置時被編譯成內部指令，並在請求處理期間進行解釋。解釋器是一個簡單的基於堆疊的虛擬機器。
