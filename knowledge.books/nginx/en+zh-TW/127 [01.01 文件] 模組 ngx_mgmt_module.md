The `ngx_mgmt_module` module enables NGINX Plus license verification and usage reporting. This is mandatory for each NGINX Plus instance since 1.27.2 ( [NGINX Plus R33](https://docs.nginx.com/nginx/releases/#r33)).

`ngx_mgmt_module`模組啟用NGINX Plus 許可證驗證和使用情況報告。自1.27.2 ( [NGINX Plus R33](https://docs.nginx.com/nginx/releases/#r33) ) 起，每個NGINX Plus 實例都必須啟用此功能。

A JWT license file named `license.jwt` should be located at `/etc/nginx/` for Linux or `/usr/local/etc/nginx/` for FreeBSD or at the path specified by the [license\_token](#license_token) directive. The license file is available from [MyF5](https://my.f5.com/).

名為`license.jwt`的JWT許可證檔案應位於 Linux 的`/etc/nginx/`或 FreeBSD 的`/usr/local/etc/nginx/`處，或位於 [license\_token](#license_token)指令指定的路徑處。許可證文件可向 [MyF5](https://my.f5.com/)取得。

Usage report is sent directly or via [proxy](#proxy) to F5 licensing endpoint [every hour](#usage_report) using the [secure](#ssl_verify) connection. Optionally, in network-restricted environments reporting can be [configured](#usage_report) to [F5 NGINX Instance Manager](https://docs.nginx.com/nginx-management-suite/about/) from which the report can be sent to F5 licensing endpoint.

使用情況報告將透過 [安全性](#ssl_verify)連接，每小時直接或透過 [代理](#proxy)發送至 F5 許可端點(https://nginx.org/en/docs/ngx_mgmt_module.html#usage_report) 。此外，在網路受限的環境中，報表可以 [設定](#usage_report)傳送至 [F5 NGINX實例管理器](https://docs.nginx.com/nginx-management-suite/about/) ，然後從該執行個體管理器傳送至 F5 授權端點。

By default, if the [initial usage report](#enforce_initial_report) is not received by F5 licensing endpoint, nginx will stop processing traffic.

預設情況下，如果 F5 許可端點未收到 [初始使用情況報告](#enforce_initial_report) ，nginx 將停止處理流量。

Automatic license renewal is supported since 1.29.0 ([NGINX Plus R35](https://docs.nginx.com/nginx/releases/#r35)) for instances that report directly to the F5 licensing endpoint. On renewal, NGINX downloads the updated JWT from F5 licensing endpoint and applies it without configuration [reload](<166 [01.01 文件] 命令列參數.md>). The updated license is stored in the [state\_path](#state_path) directory.

自1.29.0 ([NGINX Plus R35](https://docs.nginx.com/nginx/releases/#r35) ) 起，對於直接向 F5 授權端點報告的實例，支援自動許可證續約。續訂時， NGINX會從 F5 授權端點下載更新後的JWT並套用，無需設定 [reload](<166 [01.01 文件] 命令列參數.md>) 。更新後的授權儲存在 [state\_path](#state_path)目錄中。

> This module is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Example Configuration｜範例配置

> ```
> mgmt {
>
> 管理{
>     # in case if custom path is required｜如果需要自訂路徑
>     license_token custom/file/path/license.jwt;
> 
>     # in case of reporting to NGINX Instance Manager｜如果需要向NGINX實例管理器報告，請提供相關資訊。
>     usage_report endpoint=NIM_FQDN;
>
>     使用情況報告端點=NIM_FQDN；
> }
> ```

Enables or disables the 180-day grace period for sending the initial usage report.

啟用或停用發送初始使用情況報告的 180 天寬限期。

The initial usage report is sent immediately upon nginx first start after installation. By default, if the initial report is not received by F5 licensing endpoint, nginx stops processing traffic until the report is successfully delivered. Setting the directive value to `off` enables the 180-day grace period during which the initial usage report must be received by F5 licensing endpoint.

nginx 安裝完成後首次啟動時，會立即發送初始使用報告。預設情況下，如果 F5 許可端點未收到初始報告，nginx 將停止處理流量，直到報告成功送達。將指令值設為`off`可啟用 180 天的寬限期，在此期間 F5 許可端點必須收到初始使用報告。

Controls how a renewed JWT license token is handled after it is received from the F5 licensing endpoint. By default, the renewed token is saved and applied immediately.

控制從 F5 許可端點收到續訂的JWT許可證令牌後如何處理。預設情況下，續訂的令牌會立即儲存並套用。

When set to a `*file*` path, the renewed token is saved to the specified file but not applied. The path is relative to [`state_path`](#state_path). The token can be copied to the active license token file or applied using the `PUT` method of the `/api/10/license` API endpoint.

當設定為`*file*`路徑時，更新後的令牌將儲存到指定文件，但不會套用。此路徑相對於 [`state_path`](#state_path) 。令牌可以複製到活動許可證令牌文件，也可以使用`/api/10/license` API端點的`PUT`方法應用。

When set to `off`, the renewal event is logged but the token is discarded. In this case, JWT license renewal is managed entirely through the `PUT` method of the `/api/10/license` API endpoint.

當設定為`off`時，續訂事件會被記錄，但令牌會被丟棄。在這種情況下， JWT許可證續訂完全透過`/api/10/license` API端點的`PUT`方法進行管理。
