This directive appeared in version 0.8.11.

該指令出現在版本0.8.11 。

Enables or disables the use of asynchronous file I/O (AIO) on FreeBSD and Linux:

啟用或停用 FreeBSD 和 Linux 上的非同步檔案 I/O ( AIO )：

> ```
> location /video/ {
>     aio            on;
>
>     我打算這樣做；
>     output_buffers 1 64k;
>
>     輸出緩衝區 1 64k；
> }
> ```

On FreeBSD, AIO can be used starting from FreeBSD 4.3. Prior to FreeBSD 11.0, AIO can either be linked statically into a kernel:

在 FreeBSD 系統中， AIO可以從 FreeBSD 4.3開始使用。在 FreeBSD 11.0, AIO可以靜態連結到核心中：

> ```
> options VFS_AIO
>
> 選項 VFS_AIO
> ```

or loaded dynamically as a kernel loadable module:

或作為內核可載入模組動態載入：

> ```
> kldload aio
> ```

On Linux, AIO can be used starting from kernel version 2.6.22. Also, it is necessary to enable [directio](#directio), or otherwise reading will be blocking:

在 Linux 系統中，從核心版本2.6.22開始可以使用AIO 。此外，還需要啟用 [directio](#directio) ，否則讀取操作將會阻塞：

> ```
> location /video/ {
>     aio            on;
>
>     我打算這樣做；
>     directio       512;
>
>     方向 512；
>     output_buffers 1 128k;
>
>     輸出緩衝區 1 128k；
> }
> ```

On Linux, [directio](#directio) can only be used for reading blocks that are aligned on 512-byte boundaries (or 4K for XFS). File’s unaligned end is read in blocking mode. The same holds true for byte range requests and for FLV requests not from the beginning of a file: reading of unaligned data at the beginning and end of a file will be blocking.

在 Linux 系統中，[directio](#directio)只能用於讀取以 512 位元組邊界對齊的資料區塊（ XFS則為 4K）。檔案未對齊的末尾部分將以阻塞模式讀取。位元組範圍請求以及非從檔案開頭讀取的FLV請求也遵循相同的規則：讀取檔案開頭和結尾的未對齊資料將以阻塞模式進行。

When both AIO and [sendfile](#sendfile) are enabled on Linux, AIO is used for files that are larger than or equal to the size specified in the [directio](#directio) directive, while [sendfile](#sendfile) is used for files of smaller sizes or when [directio](#directio) is disabled.

當 Linux 上同時啟用AIO和 [sendfile](#sendfile)時， AIO用於大於或等於 [directio](#directio)指令中指定大小的文件，而 [sendfile](#sendfile) (https://nginx.org/en/docs/http/ngx_http_core_module.html#directio)被禁用時。

> ```
> location /video/ {
>     sendfile       on;
>
>     發送文件已開啟；
>     aio            on;
>
>     我打算這樣做；
>     directio       8m;
>
>     方向 8 公尺；
> }
> ```

Finally, files can be read and [sent](#sendfile) using multi-threading (1.7.11), without blocking a worker process:

最後，可以使用多1.7.11 (https://nginx.org/en/docs/http/ngx_http_core_module.html#sendfile)讀取和[傳送]文件，而不會阻塞工作進程：

> ```
> location /video/ {
>     sendfile       on;
>
>     發送文件已開啟；
>     aio            threads;
>
>     aio線程；
> }
> ```

Read and send file operations are offloaded to threads of the specified [pool](<125 [01.01 文件] 核心功能.md#thread_pool>). If the pool name is omitted, the pool with the name “`default`” is used. The pool name can also be set with variables:

檔案讀取和傳送操作會被卸載到指定的執行緒池 [ (https://nginx.org/en/docs/ngx_core_module.html#thread_pool) ] 中。如果省略執行緒池名稱，則使用名為「 `default` 」的執行緒池。線程池名稱也可以透過變數設定：

> ```
> aio threads=pool$disk;
>
> aio 線程=pool$disk;
> ```

By default, multi-threading is disabled, it should be enabled with the `--with-threads` configuration parameter. Currently, multi-threading is compatible only with the [epoll](<030 [01.01 文件] 連接處理方式.md#epoll>), [kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>), and [eventport](<030 [01.01 文件] 連接處理方式.md#eventport>) methods. Multi-threaded sending of files is only supported on Linux.

預設情況下，多執行緒功能處於停用狀態，需要使用`--with-threads`配置參數啟用。目前，多執行緒僅相容於 [epoll](<030 [01.01 文件] 連接處理方式.md#epoll>) 、[kqueue](<030 [01.01 文件] 連接處理方式.md#kqueue>)和 [eventport](<030 [01.01 文件] 連接處理方式.md#eventport>)方法。檔案多執行緒發送僅在 Linux 系統上支援。

See also the [sendfile](#sendfile) directive.

另請參閱 [sendfile](#sendfile)指令。

If [aio](#aio) is enabled, specifies whether it is used for writing files. Currently, this only works when using `aio threads` and is limited to writing temporary files with data received from proxied servers.

如果啟用了 [aio](#aio) ，則指定是否用於寫入檔案。目前，此功能僅在使用`aio threads`時有效，並且僅限於寫入包含從代理伺服器接收的資料的臨時檔案。

Defines a replacement for the specified location. For example, with the following configuration

定義指定位置的替代項。例如，使用以下配置

應「 `/i/top.gif` 」的要求，將發送文件`/data/w3/images/top.gif` 。

The `*path*` value can contain variables, except `$document_root` and `$realpath_root`.

`*path*`值可以包含變量，但`$document_root`和`$realpath_root`除外。

If `alias` is used inside a location defined with a regular expression then its value specifies a complete file path (0.7.40). Such path should typically refer to the captures contained within the regular expression:

如果在正規表示式定義的位置中使用`alias` ，則其值指定完整的檔案路徑 ( 0.7.40 )。此路徑通常應指向正規表示式中包含的捕獲結果：

> ```
> location ~ ^/users/(.+\.(?:gif|jpe?g|png))$ {
>     alias /data/w3/images/$1;
>
>     別名 /data/w3/images/$1;
> }
> ```

If `alias` is used inside a predicate location then its value specifies a complete file path.

如果在謂詞位置中使用`alias` ，則其值指定完整的檔案路徑。

When location matches the last part of the directive’s value:

當位置與指令值的最後一部分相符時：

> ```
> location /images/ {
>

>     alias /data/w3/images/;
>
>     別名 /data/w3/images/;
> }
> ```

it is better to use the [root](#root) directive instead:

最好改用 [root](#root)指令：

> ```
> location /images/ {
>
> 位置/圖像/ {
>     root /data/w3;
>
>     根 /data/w3;
> }
> ```

Delays processing of unauthorized requests with 401 response code to prevent timing attacks when access is limited by [password](<049 [01.01.03 http] 模組 ngx_http_auth_basic_module.md>), by the [result of subrequest](<051 [01.01.03 http] 模組 ngx_http_auth_request_module.md>), or by [JWT](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>).

當存取受到 [密碼](<049 [01.01.03 http] 模組 ngx_http_auth_basic_module.md>) 、[子請求結果](<051 [01.01.03 http] 模組 ngx_http_auth_request_module.md>)或 [JWT](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>)限制時，延遲處理未經授權的請求，並返回 401 回應代碼以防止時間攻擊。

允許在HTTP/1.1中停用分塊傳輸編碼。當使用不支援分塊編碼（即使該標準要求支援）的軟體時，此功能可能很有用。

Sets buffer size for reading client request body. In case the request body is larger than the buffer, the whole body or only its part is written to a [temporary file](#client_body_temp_path). By default, buffer size is equal to two memory pages. This is 8K on x86, other 32-bit platforms, and x86-64. It is usually 16K on other 64-bit platforms.

設定讀取客戶端請求體的緩衝區大小。如果請求體大於緩衝區大小，則整個請求體或其一部分將寫入暫存檔案（ (https://nginx.org/en/docs/http/ngx_http_core_module.html#client_body_temp_path) ）。預設情況下，緩衝區大小等於兩個記憶體頁。在 x86、其他 32 位元平台和 x86-64 平台上，緩衝區大小為 8KB。在其他 64 位元平台上，緩衝區大小通常為 16KB。

Enables reading of the client request body immediately after the request headers are received, using the request body read settings from the `server` block. If at least one value of the string parameters is not empty and is not equal to “0”, then nginx reads the request body early.

啟用此功能後，即可在收到請求頭後立即讀取客戶端請求體，讀取設定來自`server`代碼區塊。如果字串參數中至少有一個值不為空且不等於“0”，則 nginx 會提前讀取請求體。

The directive is incompatible with modules that use unbuffered request body processing, such as the [ngx\_http\_grpc\_module](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md>) module. The directive is also incompatible with modules which write the request body to a file, such as [ngx\_http\_dav\_module](<057 [01.01.03 http] 模組 ngx_http_dav_module.md>) module.

此指令與使用無緩衝請求體處理的模組不相容，例如 [ngx\_http\_grpc\_module](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md>)模組。此指令也與將請求體寫入檔案的模組不相容，例如 [ngx\_http\_dav\_module](<057 [01.01.03 http] 模組 ngx_http_dav_module.md>)模組。

The [client\_body\_in\_file\_only](#client_body_in_file_only) directive is ignored when the request body is read early.

當提前讀取請求體時，[client\_body\_in\_file\_only](#client_body_in_file_only)指令將被忽略。

Example:

例子：

> ```
> map $http_content_type $is_json {
>
> 映射 $http_content_type $is_json {
>     application/json  1;
>
>     application/json 1;
> }
> 
> server {
>
> 伺服器{
>     listen 8000;
>
>     聽 8000；
> 
>     client_body_early_read $is_json;
> 
>     client_max_body_size    256;
>
>     client_max_body_size 256;
>     client_body_buffer_size 256;
> 
>     return 200 $request_body;
>
>     返回 200 $request_body;
> }
> ```

<tr><th>Default:<br>預設值：</th><td>client_body_in_file_only off;<br>client_body_in_file_only 關閉；</td></tr>

Determines whether nginx should save the entire client request body into a file. This directive can be used during debugging, or when using the `$request_body_file` variable, or the [$r->request\_body\_file](<084 [01.01.03 http] 模組 ngx_http_perl_module.md#methods>) method of the module [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>).

確定 nginx 是否應將整個客戶端請求體儲存到檔案中。此指令可在偵錯期間使用，或使用`$request_body_file`變數時使用，或使用模組 [ngx\_http\_perl\_module](<084 [01.01.03 http] 模組 ngx_http_perl_module.md>)的 [$r->request\_body\_file](<084 [01.01.03 http] 模組 ngx_http_perl_module.md#methods>)方法時使用。

When set to the value `on`, temporary files are not removed after request processing.

當設定為值`on`時，請求處理後不會刪除暫存檔案。

The value `clean` will cause the temporary files left after request processing to be removed.

This directive appeared in versions 1.1.0 and 1.0.6.

該指令出現在版本1.1.0和1.0.6中。

Controls how nginx closes client connections.

控制nginx如何關閉客戶端連線。

The default value “`on`” instructs nginx to [wait for](#lingering_timeout) and [process](#lingering_time) additional data from a client before fully closing a connection, but only if heuristics suggests that a client may be sending more data.

預設值「 `on` 」指示nginx在完全關閉連接之前[等待](#lingering_timeout)和[處理](#lingering_time)來自客戶端的額外數據，但僅當啟發式方法表明客戶端可能正在發送更多數據時才這樣做。

The value “`always`” will cause nginx to unconditionally wait for and process additional client data.

值「 `always` 」將導致nginx無條件等待並處理額外的客戶端資料。

The value “`off`” tells nginx to never wait for more data and close the connection immediately. This behavior breaks the protocol and should not be used under normal circumstances.

值「 `off` 」指示nginx不要等待更多數據，並立即關閉連線。這種行為違反了協議，在正常情況下不應使用。

To control closing [HTTP/2](<108 [01.01.03 http] 模組 ngx_http_v2_module.md>) connections, the directive must be specified on the [server](#server) level (1.19.1).

若要控制關閉 [HTTP /2](<108 [01.01.03 http] 模組 ngx_http_v2_module.md>)連接，必須在 [伺服器](#server)等級指定此指令 ( 1.19.1 )。

When [lingering\_close](#lingering_close) is in effect, this directive specifies the maximum waiting time for more client data to arrive. If data are not received during this time, the connection is closed. Otherwise, the data are read and ignored, and nginx starts waiting for more data again. The “wait-read-ignore” cycle is repeated, but no longer than specified by the [lingering\_time](#lingering_time) directive.

當 [lingering\_close](#lingering_close)指令生效時，指令指定等待客戶端資料到達的最大時間。如果在該時間內未收到數據，則連線將關閉。否則，資料將被讀取並忽略，nginx 將再次開始等待更多資料。 「等待-讀取-忽略」迴圈將重複進行，但持續時間不會超過 [lingering\_time](#lingering_time)指令指定的時間。

On such systems (currently, Linux, NetBSD, Dragonfly, FreeBSD, and macOS), they can be configured using the `*keepidle*`, `*keepintvl*`, and `*keepcnt*` parameters. One or two parameters may be omitted, in which case the system default setting for the corresponding socket option will be in effect. For example,

此參數 ( 1.1.11 ) 配置監聽套接字的「 TCP keepalive」行為。如果省略此參數，則套接字將使用作業系統的設定。如果將其設為值“ `on` ”，則套接字的`SO_KEEPALIVE` ”選項將會啟用。如果將其設為值“ `off` ”，則套接字的`SO_KEEPALIVE` ”選項將被停用。某些作業系統支援使用套接字選項`TCP_KEEPIDLE`, `TCP_KEEPINTVL`和`TCP_KEEPCNT`為每個套接字單獨設定TCP keepalive」參數。在這些系統（目前包括 Linux、NetBSD、Dragonfly、FreeBSD 和 macOS）上，可以使用`*keepidle*`, `*keepintvl*`和`*keepcnt*`參數進行設定。可以省略一個或兩個參數，在這種情況下，將使用對應套接字選項的系統預設。例如：

> ```

根據請求URI或變數的值( 1.31.5 )設定配置。

The matching is performed against a normalized URI, after decoding the text encoded in the “`%XX`” form, resolving references to relative path components “`.`” and “`..`”, and possible [compression](#merge_slashes) of two or more adjacent slashes into a single slash.

匹配是針對規範化的URI執行的，在解碼以“ `%XX` ”形式編碼的文本之後，解析對相對路徑組件“ `.` ”和“ `..` ”的引用，以及將兩個斜杠壓縮或多個斜杠 [ (https://nginx.org/en/docs/http/ngx_http_core_module.html#merge_slashes) ] 。

A location can be defined by a prefix string, a regular expression, or a predicate (1.31.5). Regular expressions are specified with the preceding “`~*`” modifier (for case-insensitive matching), or the “`~`” modifier (for case-sensitive matching). A predicate is specified with the preceding “`$`” and contains a variable evaluated during request processing. A predicate location matches if the variable value is not empty and is not equal to “0”.

位置可以透過前綴字串、正規表示式或謂詞 ( 1.31.5 ) 來定義。正規表示式前面有「 `~*` 」修飾符（用於不區分大小寫的匹配），或「 `~` 」修飾符（用於區分大小寫的匹配）。謂詞前面帶有“ `$` ”，其中包含一個在請求處理期間計算的變數。如果該變數的值不為空且不等於“0”，則謂詞位置符合。

To find location matching a given request, nginx first checks locations defined using the prefix strings (prefix locations). Among them, the location with the longest matching prefix is selected and remembered. Then regular expressions are checked, in the order of their appearance in the configuration file. The search of regular expressions terminates on the first match, and the corresponding configuration is used. If no match with a regular expression is found, predicate locations are checked in the order of their appearance in the configuration file. If no predicate location matches, the configuration of the prefix location remembered earlier is used.

為了找到與給定請求相符的位置，nginx 首先檢查使用前綴字串定義的位置（前綴位置）。其中，匹配前綴最長的位置會被選中並記住。然後，它會按照正規表示式在設定檔中出現的順序進行檢查。正規表示式搜尋會在找到第一個符合項目時終止，並使用對應的配置。如果沒有找到符合的正規表示式，則會依照謂詞位置在設定檔中出現的順序進行檢查。如果仍然沒有符合的謂詞位置，則使用先前記住的前綴位置的配置。

`location` blocks can be nested, with some exceptions mentioned below.

`location`模組可以嵌套，但下面會提到一些例外情況。

For case-insensitive operating systems such as macOS and Cygwin, matching with prefix strings ignores a case (0.7.7). However, comparison is limited to one-byte locales.

對於 macOS 和 Cygwin 等不區分大小寫的作業系統，使用前綴字串進行比對時會忽略大小寫（ 0.7.7 ）。但是，比較僅限於單字節區域設定。

Regular expressions can contain captures (0.7.40) that can later be used in other directives, see [Regular expression captures](https://nginx.org/en/docs/regex_captures.html).

正規表示式可以包含捕獲（ 0.7.40 ），這些捕獲稍後可以在其他指令中使用，請參閱[正規表示式捕獲](https://nginx.org/en/docs/regex_captures.html) 。

If the longest matching prefix location has the “`^~`” modifier, then regular expressions and predicate locations are not checked.

如果最長的符合前綴位置具有「 `^~` 」修飾符，則不檢查正規表示式和謂詞位置。

Also, using the “`=`” modifier it is possible to define an exact match of URI and location. If an exact match is found, the search terminates. For example, if a “`/`” request happens frequently, defining “`location = /`” will speed up the processing of these requests, as search terminates right after the first comparison. Such a location cannot obviously contain nested locations.

此外，使用「 `=` 」修飾符可以定義URI與位置的精確匹配。如果找到精確匹配項，搜尋將終止。例如，如果經常出現「 `/` 」請求，定義「 `location = /` 」將加快這些請求的處理速度，因為搜尋會在第一次比較後立即終止。顯然，這樣的位置不能包含嵌套位置。

> In versions from 0.7.1 to 0.8.41, if a request matched the prefix location without the “`=`” and “`^~`” modifiers, the search also terminated and regular expressions were not checked.
>
> 在0.7.1到0.8.41的版本中，如果請求匹配前綴位置，但沒有「 `=` 」和「 `^~` 」修飾符，則搜尋也會終止，並且不會檢查正則表達式。

The `ngx_http_core_module` module supports embedded variables with names matching the Apache Server variables. First of all, these are variables representing client request header fields, such as `$http_user_agent`, `$http_cookie`, and so on. Also there are other variables:

`ngx_http_core_module`模組支援嵌入變量，其名稱與 Apache 伺服器變數的名稱相符。首先，這些變數表示客戶端請求頭字段，例如`$http_user_agent`, `$http_cookie`等。此外，還有其他變數：

`$arg_``*name*`

argument `*name*` in the request line

請求行中的參數`*name*`

arguments in the request line

請求行中的參數

client address in a binary form, value’s length is always 4 bytes for IPv4 addresses or 16 bytes for IPv6 addresses

客戶端位址，以二進位形式表示，IPv4 位址的長度始終為 4 位元組，IPv6 位址的長度始終為 16 位元組。

`$body_bytes_sent`

number of bytes sent to a client, not counting the response header; this variable is compatible with the “`%B`” parameter of the `mod_log_config` Apache module

傳送給客戶端的位元組數，不包括回應頭；此變數與 Apache 模組`mod_log_config`的「 `%B` 」參數相容。

連接序號（ 1.3.8, 1.2.5 ）

`$connection_requests`

目前透過連線發出的請求數 ( 1.3.8, 1.2.5 )

`$connection_time`

連接時間（以秒為單位，精確到毫秒）( 1.19.10 )

`$content_length`

“Content-Length”（內容長度） request header field

“Content-Length”（內容長度）請求頭字段

`$content_type`

“Content-Type”（內容類型） request header field

“Content-Type”（內容類型）請求頭字段

`$cookie_``*name*`

`*name*` cookie

host name

主機名稱

任意請求頭字段；變數名的最後一部分是字段名，轉換為小寫，並將連字符替換為下劃線。

如果連接以SSL模式運行，則為“ `on` ”，否則為空字串。

`$proxy_protocol_tlv_``*name*`

TLV from the PROXY Protocol header (1.23.2). The `name` can be a TLV type name or its numeric value. In the latter case, the value is hexadecimal and should be prefixed with `0x`:

來自 PROXY 協議頭 (1.23.2) 的TLV。 `name` 可以是TLV 型別名稱或其數值。在後一種情況下，該值是十六進制的，並且應以 `0x` 為前綴：

> ```
> $proxy_protocol_tlv_alpn
> $proxy_protocol_tlv_0x01
> ```

SSL TLVs can also be accessed by TLV type name or its numeric value, both prefixed by `ssl_`:

SSL TLV 也可以透過TLV類型名稱或其數值來訪問，兩者都以`ssl_`為前綴：

> ```
> $proxy_protocol_tlv_ssl_version
> $proxy_protocol_tlv_ssl_0x21
> ```

The following TLV type names are supported:

支援以下TLV類型名稱：

-   `alpn` (`0x01`) - upper layer protocol used over the connection  
    `alpn` ( `0x01` ) - 連接上使用的上層協議
-   `authority` (`0x02`) - host name value passed by the client  
    `authority` ( `0x02` ) - 用戶端傳遞的主機名稱值
-   `unique_id` (`0x05`) - unique connection id  
    `unique_id` ( `0x05` ) - 唯一連接 ID
-   `netns` (`0x30`) - name of the namespace  
    `netns` ( `0x30` ) - 命名空間名稱
-   `ssl` (`0x20`) - binary SSL TLV structure  
    `ssl` ( `0x20` ) - 二元SSL TLV結構

The following SSL TLV type names are supported:

支援以下SSL TLV類型名稱：

-   `ssl_version` (`0x21`) - SSL version used in client connection  
    `ssl_version` ( `0x21` ) - SSL版本用於客戶端連接
-   `ssl_cn` (`0x22`) - SSL certificate Common Name  
    `ssl_cn` ( `0x22` ) - SSL證書通用名稱
-   `ssl_cipher` (`0x23`) - name of the used cipher  
    `ssl_cipher` ( `0x23` ) - 所用密碼的名稱
-   `ssl_sig_alg` (`0x24`) - algorithm used to sign the certificate  
    `ssl_sig_alg` ( `0x24` ) - 用於簽署證書的演算法
-   `ssl_key_alg` (`0x25`) - public-key algorithm  
    `ssl_key_alg` ( `0x25` ) - 公鑰演算法

Also, the following special SSL TLV type name is supported:

此外，也支援以下特殊型別名稱SSL TLV ：

-   `ssl_verify` - client SSL certificate verification result, `0` if the client presented a certificate and it was successfully verified, non-zero otherwise.  
    `ssl_verify` - 用戶端SSL憑證驗證結果， `0`如果客戶端提供了憑證並且驗證成功，則為非零值，否則為非零值。

The PROXY protocol must be previously enabled by setting the `proxy_protocol` parameter in the [listen](#listen) directive.

必須先在 [listen](#listen)指令中設定`proxy_protocol`參數來啟用PROXY協定。

When the name of a temporary file is passed in a proxied request or in a request to a FastCGI/uwsgi/SCGI server, passing the request body should be disabled by the [proxy\_pass\_request\_body off](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_pass_request_body>), [fastcgi\_pass\_request\_body off](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_pass_request_body>), [uwsgi\_pass\_request\_body off](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_pass_request_body>), or [scgi\_pass\_request\_body off](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_pass_request_body>) directives, respectively.
