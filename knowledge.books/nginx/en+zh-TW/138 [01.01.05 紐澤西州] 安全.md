## Security｜安全

All nginx security issues should be reported via one of the methods listed [here](https://github.com/nginx/njs/blob/master/SECURITY.md).

所有 nginx 安全性問題都應該透過 [此處](https://github.com/nginx/njs/blob/master/SECURITY.md)列出的方法之一進行報告。

Patches are signed using one of the [PGP public keys](<178 [01 在] PGP公鑰.md>).

補丁使用 [PGP公鑰](<178 [01 在] PGP公鑰.md>)之一進行簽署。

#### Special considerations｜特殊考慮

njs does not evaluate dynamic code, especially code received from the network, in any way. The only way to evaluate that code using njs is to configure the [js\_import](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_import>) directive in nginx. JavaScript code is loaded once during nginx start.

njs 不會以任何方式執行動態程式碼，尤其是從網路接收的程式碼。要使用 njs 執行此類程式碼，唯一的方法是在 nginx 中配置 [js\_import](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_import>)指令。 JavaScript 程式碼在 nginx 啟動時載入一次。

In the nginx/njs threat model, JavaScript code is considered a trusted source in the same way as `nginx.conf` and sites certificates. What this means in practice:

在 nginx/njs 威脅模型中，JavaScript 程式碼被視為與`nginx.conf`和網站憑證同等的可信來源。這在實踐中意味著：

-   memory disclosure and other security issues triggered by JavaScript code modification are not considered security vulnerabilities, but rather ordinary bugs  
    由 JavaScript 程式碼修改引發的記憶體外洩和其他安全問題不被視為安全漏洞，而是普通的錯誤。
-   measures should be taken for protecting JavaScript code used by njs  
    應採取措施保護njs所使用的JavaScript程式碼
-   if no [js\_import](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_import>) directives are present in `nginx.conf`, nginx is safe from JavaScript-related vulnerabilities  
    如果`nginx.conf`中不存在 [js\_import](<073 [01.01.03 http] 模組 ngx_http_js_module.md#js_import>)指令，則 nginx 不會受到 JavaScript 相關漏洞的影響。
