The `ngx_http_api_module` module (1.13.3) provides REST API for accessing various status information, configuring upstream server groups on-the-fly, and managing [key-value pairs](<074 [01.01.03 http] 模組 ngx_http_keyval_module.md>) without the need of reconfiguring nginx.

`ngx_http_api_module`模組 ( 1.13.3 ) 提供REST API用於存取各種狀態資訊、動態配置上游伺服器群組以及管理 [鍵值對](<074 [01.01.03 http] 模組 ngx_http_keyval_module.md>)而無需重新配置 nginx。

> The module supersedes the [ngx\_http\_status\_module](<099 [01.01.03 http] 模組 ngx_http_status_module.md>) and [ngx\_http\_upstream\_conf\_module](<103 [01.01.03 http] 模組 ngx_http_upstream_conf_module.md>) modules.
>
> 此模組取代了 [ngx\_http\_status\_module](<099 [01.01.03 http] 模組 ngx_http_status_module.md>)和 [ngx\_http\_upstream\_conf\_module](<103 [01.01.03 http] 模組 ngx_http_upstream_conf_module.md>)模組。

When using the `PATCH` or `POST` methods, make sure that the payload does not exceed the [buffer size](<056 [01.01.03 http] 模組 ngx_http_core_module.md#client_body_buffer_size>) for reading the client request body, otherwise, the 413 (Request Entity Too Large) error may be returned.

使用`PATCH`或`POST`方法時，請確保有效負載不超過讀取客戶端請求體的 [緩衝區大小](<056 [01.01.03 http] 模組 ngx_http_core_module.md#client_body_buffer_size>) ，否則可能會傳回 413（請求實體過大）錯誤。

>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Directives｜指令

Turns on the REST API interface in the surrounding location. Access to this location should be [limited](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>).

開啟周圍位置的REST API介面。對該位置的存取應受到限制(https://nginx.org/en/docs/http/ngx_http_core_module.html#satisfy) 。

The `write` parameter determines whether the API is read-only or read-write. By default, the API is read-only.

`write`參數決定API是唯讀還是讀寫。預設情況下， API為唯讀。

All API requests should contain a supported API version in the URI. If the request URI equals the location prefix, the list of supported API versions is returned. The current API version is “`10`”.

所有API請求都應包含受支援的API版本。如果請求URI等於位置前綴， URI傳回受支援的API版本清單。目前API版本為「 `10` 」。

The optional “`fields`” argument in the request line specifies which fields of the requested objects will be output:

請求行中的選用參數「 `fields` 」指定要輸出請求物件的哪些欄位：

> ```
> http://127.0.0.1/api/10/nginx?fields=version,build
> ```

| Context:<br>背景： | `server`, `location`, `if in location` |

This directive appeared in version 1.13.12.

該指令出現在版本1.13.12 。

Enables collection of virtual [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) or [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#server>) server status information in the specified `*zone*`. Several servers may share the same zone.

允許在指定的`*zone*`中收集虛擬 [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>)或 [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#server>)伺服器狀態資訊。多個伺服器可以共享同一個區域。

Starting from 1.17.0, status information can be collected per [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>). The special value `off` disables statistics collection in nested location blocks. Note that the statistics is collected in the context of a location where processing ends. It may be different from the original location, if an [internal redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>) happens during request processing.

從1.17.0開始，可以按 [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>)收集狀態資訊。特殊值`off`會停用嵌套 location 區塊中的統計資訊收集。請注意，統計資料是在處理結束的 location 上下文中收集的。如果在請求處理期間發生 [內部重定向](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>) ，則該 location 可能與原始 location 不同。
