## nginx под Windows｜Windows 下的 nginx

Версия nginx под Windows использует “родной” Win32 API (не эмуляцию Cygwin). В настоящий момент в качестве методов обработки соединений используются `select()` и `poll()` (1.15.9), поэтому не стоит ожидать высокой производительности и масштабируемости. В силу этого и ряда других известных проблем версия nginx под Windows рассматривается пока как *бета*\-версия. На данный момент в ней доступна практически вся функциональность, что и в версии nginx под UNIX, за исключением XSLT-фильтра, фильтра изображений, модуля GeoIP и встроенного языка Perl.

Windows 版 nginx 使用原生 Win32 API （而非 Cygwin 模擬）。目前，連接處理方式採用`select()`和`poll()` （ 1.15.9 ），因此不應期望其具有高效能和高可擴展性。由於此原因以及其他一些已知問題，Windows 版 nginx 目前被視為 *beta* 版本。目前，它幾乎具備UNIX版 nginx 的所有功能，但缺少XSLT過濾器、圖像過濾器、GeoIP 模組和嵌入式 Perl 語言。

Чтобы установить nginx/Windows, [скачайте](<324 [02 ru] 下載 nginx.md>) дистрибутив последней основной версии (1.31.6), поскольку основная ветвь nginx содержит все известные исправления. Затем распакуйте дистрибутив, перейдите в каталог nginx-1.31.6 и запустите `nginx`. Вот пример для корневого каталога на диске C:

要在 Windows 上安裝 nginx，請下載最新主版本（ 1.31.6 ）的(https://nginx.org/ru/download.html)發行版，因為 nginx 主分支包含了所有已知的修復。然後解壓縮發行版，切換到 nginx- 1.31.6目錄，並運行`nginx` 。以下是 C 碟根目錄的範例：

> ```bash
>
> 『`bash
> cd c:\
>
> CDC：\
> unzip nginx-1.31.6.zip
>
> 解壓縮 nginx- 1.31.6
> cd nginx-1.31.6
>
> cd nginx- 1.31.6
> start nginx
>
> 啟動 nginx
> ```

Чтобы увидеть процессы nginx, запустите утилиту командной строки `tasklist`:

若要查看 nginx 進程，請執行`tasklist`命令列公用程式：

> ```
> C:\nginx-1.31.6>tasklist /fi "imagename eq nginx.exe"

Один из процессов главный, другой — рабочий. Если nginx не запускается, нужно искать причину в в файле лога ошибок `logs\error.log`. Если же лог-файл не создался, то причину этого следует искать в Windows Event Log. Если вместо ожидаемой страницы выводится страница с ошибкой, нужно также искать причины ошибки в файле `logs\error.log`.

一個進程是主進程，另一個是工作進程。如果 nginx 啟動失敗，您應該在錯誤日誌檔案`logs\error.log`中尋找原因。如果日誌檔案未生成，則應在 Windows 事件日誌中尋找原因。如果顯示的是錯誤頁面而不是預期頁面，您也應該在`logs\error.log`文件中尋找原因。

nginx/Windows использует каталог, в котором он был запущен, в качестве префикса для относительных путей в конфигурации. В вышеприведённом примере префиксом является `C:\nginx-1.31.6\`. Пути в конфигурационном файле должны задаваться в UNIX-стиле с использованием прямых слэшей:

nginx/Windows 使用其啟動目錄作為設定檔中相對路徑的前綴。在上面的範例中，前綴為`C:\nginx-1.31.6\` 。設定檔中的路徑應使用UNIX格式，並使用正斜線：

> ```
> access_log   logs/site.log;
>
> 訪問日誌 logs/site.log；
> root         C:/web/html;
>
> 根目錄 C:/web/html;
> ```

nginx/Windows работает как стандартное консольное приложение (не сервис) и управляется при помощи следующих команд:

nginx/Windows 作為標準控制台應用程式（而非服務）運行，並使用以下命令進行控制：

> |   |   |
> | --- | --- |
> | nginx -s stop<br>nginx -s 停止 | быстрое завершение<br>快速關閉 |
> | nginx -s quit | плавное завершение<br>優雅關閉 |
> | nginx -s reload | изменение конфигурации, запуск новых рабочих процессов с новой конфигурацией, плавное завершение старых рабочих процессов<br>更改配置，使用新配置啟動新的工作進程，優雅地終止舊的工作進程 |
> | nginx -s reopen<br>nginx -s 重新開啟 | переоткрытие лог-файлов<br>重新開啟日誌檔案 |

#### Известные проблемы｜已知問題

-   Хоть и возможен запуск нескольких рабочих процессов, только один из них реально работает.  
    雖然可以運行多個工作進程，但實際上只有一個進程在運行。
-   UDP (и, как следствие, QUIC) не поддерживается.  
    UDP （以及由此擴展的QUIC ）不受支援。

#### Возможные усовершенствования в будущем｜未來可能的改進

-   Запуск в виде сервиса.  
    以服務形式發布。
-   Использование портов завершения ввода-вывода (I/O completion ports) в качестве метода обработки соединений.  
    使用 I/O 完成連接埠作為連接處理方法。
-   Использование нескольких рабочих нитей внутри одного рабочего процесса.  
    在單一工作進程中使用多個工作執行緒。
