The `ngx_mail_ssl_module` module provides the necessary support for a mail proxy server to work with the SSL/TLS protocol.

`ngx_mail_ssl_module`模組為郵件代理伺服器與SSL/TLS協定配合使用提供了必要的支援。

This module is not built by default, it should be enabled with the `--with-mail_ssl_module` configuration parameter.

此模組預設未構建，應使用`--with-mail_ssl_module`配置參數啟用。

> This module requires the [OpenSSL](http://www.openssl.org/) library.
>
> 本模組需要 [OpenSSL](http://www.openssl.org/)函式庫。

#### Example Configuration｜範例配置

To reduce the processor load, it is recommended to

為了降低處理器負載，建議…

-   set the number of [worker processes](<125 [01.01 文件] 核心功能.md#worker_processes>) equal to the number of processors,  
    將[工作進程](<125 [01.01 文件] 核心功能.md#worker_processes>)的數量設定為等於處理器數量，
-   enable the [shared](#ssl_session_cache_shared) session cache,  
    啟用[共享](#ssl_session_cache_shared)會話緩存，
-   disable the [built-in](#ssl_session_cache_builtin) session cache,  
    停用[內建](#ssl_session_cache_builtin)會話緩存，
-   and possibly increase the session [lifetime](#ssl_session_timeout) (by default, 5 minutes):  
    並可能增加會話[生命週期](#ssl_session_timeout) （預設值為 5 分鐘）：

> ```

>

>

> 
>     ...

>

>
>         監聽 993 ssl；
> 
>         ssl_protocols       TLSv1.2 TLSv1.3;
>
>         ssl_protocols TLSv1.2 TLSv1.3;
>         ssl_ciphers         AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5;
>

> 
>         ...
>     }
> ```

Specifies a `*file*` with the certificate in the PEM format for the given server. If intermediate certificates should be specified in addition to a primary certificate, they should be specified in the same file in the following order: the primary certificate comes first, then the intermediate certificates. A secret key in the PEM format may be placed in the same file.

為給定伺服器指定具有 PEM 格式憑證的 `*file*`。如果除了主證書之外還應指定中間證書，則應按以下順序在同一文件中指定它們：首先是主證書，然後是中間證書。 PEM 格式的金鑰可以放置在同一文件中。

Since version 1.11.0, this directive can be specified multiple times to load certificates of different types, for example, RSA and ECDSA:

自版本1.11.0起，可以多次指定此指令以載入不同類型的證書，例如RSA和ECDSA ：

> ```
> server {
>
> 伺服器 {
>     listen              993 ssl;
>
>     監聽 993 ssl；
> 
>     ssl_certificate     example.com.rsa.crt;
>
>     ssl_certificate example.com.rsa.crt;
>     ssl_certificate_key example.com.rsa.key;
> 
>     ssl_certificate     example.com.ecdsa.crt;
>
>     ssl_certificate example.com.ecdsa.crt;
>     ssl_certificate_key example.com.ecdsa.key;
> 
>     ...
> }
> ```

> Only OpenSSL 1.0.2 or higher supports separate [certificate chains](<042 [01.01.03 http] 配置HTTPS伺服器.md#chains>) for different certificates. With older versions, only one certificate chain can be used.
>
> 只有 OpenSSL 1.0.2或更高版本才支援為不同的憑證使用獨立的憑證鏈(https://nginx.org/en/docs/http/configuring_https_servers.html#chains) 。舊版只能使用一條憑證鏈。

The value `data`:`*certificate*` can be specified instead of the `*file*` (1.15.10), which loads a certificate without using intermediate files. Note that inappropriate use of this syntax may have its security implications, such as writing secret key data to [error log](<125 [01.01 文件] 核心功能.md#error_log>).

可以使用值`data`:`*certificate*`代替`*file*` ( 1.15.10 )，這樣無需使用中間文件即可載入證書。請注意，不當使用此語法可能會帶來安全隱患，例如將金鑰資料寫入 [錯誤日誌](<125 [01.01 文件] 核心功能.md#error_log>) 。

Sets the types and sizes of caches that store session parameters. A cache can be of any of the following types:

設定用於儲存會話參數的快取類型和大小。快取可以是以下任何一種類型：

`off`

the use of a session cache is strictly prohibited: nginx explicitly tells a client that sessions may not be reused.

嚴禁使用會話快取：nginx 明確告知客戶端會話不得重複使用。

`none`

the use of a session cache is gently disallowed: nginx tells a client that sessions may be reused, but does not actually store session parameters in the cache.

nginx 會委婉地禁止使用會話快取：nginx 會告訴客戶端會話可以重複使用，但實際上不會將會話參數儲存在快取中。

`builtin`

a cache built in OpenSSL; used by one worker process only. The cache size is specified in sessions. If size is not given, it is equal to 20480 sessions. Use of the built-in cache can cause memory fragmentation.

OpenSSL 內建快取；僅供單一工作進程使用。快取大小以會話數 (session) 為單位指定。如果未指定大小，則預設為 20480 個會話。使用內建快取可能會導致記憶體碎片。

`shared`

a cache shared between all worker processes. The cache size is specified in bytes; one megabyte can store about 4000 sessions. Each shared cache should have an arbitrary name. A cache with the same name can be used in several servers. It is also used to automatically generate, store, and periodically rotate TLS session ticket keys (1.23.2) unless configured explicitly using the [ssl\_session\_ticket\_key](#ssl_session_ticket_key) directive.

一個在所有工作進程之間共享的快取。快取大小以位元組為單位指定；1 MB 大約可以儲存 4000 個會話。每個共享快取都應該有一個任意名稱。同名快取可以在多個伺服器上使用。它也用於自動產生、儲存和定期輪換會話票據金鑰（ TLS ）（ 1.23.2 ），除非使用 [ssl_session_ticket_key](#ssl_session_ticket_key)指令明確配置。

Both cache types can be used simultaneously, for example:

兩種快取類型可以同時使用，例如：

> ```
> ssl_session_cache builtin:1000 shared:SSL:10m;
>
> ssl_session_cache builtin:1000 shared: SSL :10m;
> ```

but using only shared cache without the built-in cache should be more efficient.

但是，如果只使用共享快取而不使用內建緩存，效率應該會更高。

Sets a `*file*` with the secret key used to encrypt and decrypt TLS session tickets. The directive is necessary if the same key has to be shared between multiple servers. By default, a randomly generated key is used.

設定用於加密和解密TLS會話票證的私鑰`*file*` 。如果需要在多個伺服器之間共用相同金鑰，則此指令是必需的。預設情況下，使用隨機產生的密鑰。

If several keys are specified, only the first key is used to encrypt TLS session tickets. This allows configuring key rotation, for example:

如果指定了多個金鑰，則僅使用第一個金鑰來加密TLS會話票證。這樣可以配置金鑰輪換，例如：

> ```
> ssl_session_ticket_key current.key;
> ssl_session_ticket_key previous.key;
> ```

The `*file*` must contain 80 or 48 bytes of random data and can be created using the following command:

`*file*`必須包含 80 或 48 位元組的隨機數據，可以使用以下命令創建：

> ```
> openssl rand 80 > ticket.key
> ```

Depending on the file size either AES256 (for 80-byte keys, 1.11.8) or AES128 (for 48-byte keys) is used for encryption.

根據檔案大小，使用AES256 （80 位元組金鑰）、 1.11.8或AES128 （48 位元組金鑰）進行加密。
