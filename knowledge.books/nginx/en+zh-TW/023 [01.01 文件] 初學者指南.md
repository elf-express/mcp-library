This guide gives a basic introduction to nginx and describes some simple tasks that can be done with it. It is supposed that nginx is already installed on the reader’s machine. If it is not, see the [Installing nginx](<115 [01.01 文件] 安裝 nginx.md>) page. This guide describes how to start and stop nginx, and reload its configuration, explains the structure of the configuration file and describes how to set up nginx to serve out static content, how to configure nginx as a proxy server, and how to connect it with a FastCGI application.

本指南對 nginx 進行了基本介紹，並描述了一些可以用它完成的簡單任務。假設讀者的機器上已經安裝了 nginx。如果不是，請參閱[安裝nginx](<115 [01.01 文件] 安裝 nginx.md>)頁面。本指南介紹如何啟動和停止 nginx、重新載入其配置、解釋設定檔的結構並介紹如何設定 nginx 來提供靜態內容、如何將 nginx 配置為代理伺服器以及如何將其與 FastCGI 應用程式連接。

nginx has one master process and several worker processes. The main purpose of the master process is to read and evaluate configuration, and maintain worker processes. Worker processes do actual processing of requests. nginx employs event-based model and OS-dependent mechanisms to efficiently distribute requests among worker processes. The number of worker processes is defined in the configuration file and may be fixed for a given configuration or automatically adjusted to the number of available CPU cores (see [worker\_processes](<125 [01.01 文件] 核心功能.md#worker_processes>)).

nginx有一個master行程和多個worker行程。主進程的主要目的是讀取和評估配置，以及維護工作進程。工作進程實際處理請求。 nginx 採用基於事件的模型和OS依賴機制在工作進程之間有效地分配請求。工作進程的數量在設定檔中定義，對於給定配置可以是固定的，也可以自動調整為可用 CPU 核心的數量（請參閱 [worker\_processes](<125 [01.01 文件] 核心功能.md#worker_processes>)）。

The way nginx and its modules work is determined in the configuration file. By default, the configuration file is named `nginx.conf` and placed in the directory `/usr/local/nginx/conf`, `/etc/nginx`, or `/usr/local/etc/nginx`.

nginx 及其模組的工作方式是在設定檔中決定的。預設情況下，設定檔名稱為`nginx.conf`，放置在目錄`/usr/local/nginx/conf`, `/etc/nginx`或`/usr/local/etc/nginx`中。

#### Starting, Stopping, and Reloading Configuration｜啟動、停止和重新載入配置

To start nginx, run the executable file. Once nginx is started, it can be controlled by invoking the executable with the `-s` parameter. Use the following syntax:

若要啟動 nginx，請執行可執行檔。一旦 nginx 啟動，就可以透過使用 `-s` 參數呼叫可執行檔來控制它。使用以下語法：

> ```
> nginx -s signal
>
> nginx -s 訊號
> ```

Where *signal* may be one of the following:

其中*訊號*可能是以下之一：

-   `stop` — fast shutdown  
    `stop` — 快速關閉
-   `quit` — graceful shutdown  
    `quit` — 優雅關閉
-   `reload` — reloading the configuration file  
    `reload` — 重新載入設定檔
-   `reopen` — reopening the log files  
    `reopen` — 重新開啟日誌文件

For example, to stop nginx processes with waiting for the worker processes to finish serving current requests, the following command can be executed:

例如，要停止 nginx 進程並等待工作進程完成目前請求的服務，可以執行下列命令：

> ```
> nginx -s quit
>
> nginx -s 退出
> ```

> This command should be executed under the same user that started nginx.
>
> 該指令應在啟動 nginx 的相同使用者下執行。

Changes made in the configuration file will not be applied until the command to reload configuration is sent to nginx or it is restarted. To reload configuration, execute:

在將重新載入設定的命令傳送到 nginx 或重新啟動之前，設定檔中所做的變更將不會套用。若要重新載入配置，請執行：

> ```
> nginx -s reload
>
> nginx -s 重新載入
> ```

Once the master process receives the signal to reload configuration, it checks the syntax validity of the new configuration file and tries to apply the configuration provided in it. If this is a success, the master process starts new worker processes and sends messages to old worker processes, requesting them to shut down. Otherwise, the master process rolls back the changes and continues to work with the old configuration. Old worker processes, receiving a command to shut down, stop accepting new connections and continue to service current requests until all such requests are serviced. After that, the old worker processes exit.

一旦主進程收到重新載入配置的訊號，它就會檢查新設定檔的語法有效性，並嘗試套用其中提供的配置。如果成功，主進程將啟動新的工作進程並向舊工作進程發送訊息，請求它們關閉。否則，主進程將回滾更改並繼續使用舊配置。舊的工作進程收到關閉命令，停止接受新連線並繼續服務當前請求，直到所有此類請求都得到服務。之後，舊的工作進程退出。

A signal may also be sent to nginx processes with the help of Unix tools such as the `kill` utility. In this case a signal is sent directly to a process with a given process ID. The process ID of the nginx master process is written, by default, to the `nginx.pid` in the directory `/usr/local/nginx/logs` or `/var/run`. For example, if the master process ID is 1628, to send the QUIT signal resulting in nginx’s graceful shutdown, execute:

訊號也可以在 Unix 工具（例如 `kill` 實用程式）的幫助下傳送到 nginx 進程。在這種情況下，訊號直接發送到具有給定進程ID的進程。 nginx主進程的進程ID預設寫入`/usr/local/nginx/logs`或`/var/run`目錄下的`nginx.pid`。例如，如果主進程ID是1628，要發送QUIT訊號導致nginx正常關閉，請執行：

> ```
> kill -s QUIT 1628
>
> 殺死 -s QUIT 1628
> ```

For getting the list of all running nginx processes, the `ps` utility may be used, for example, in the following way:

為了獲取所有正在運行的 nginx 進程的列表，可以使用 `ps` 實用程序，例如，透過以下方式：

> ```
> ps -ax | grep nginx
>
> ps-ax | grep nginx
> ```

For more information on sending signals to nginx, see [Controlling nginx](<026 [01.01 文件] 控制 Nginx.md>).

有關向 nginx 發送訊號的更多信息，請參閱[控制 nginx](<026 [01.01 文件] 控制 Nginx.md>)。

#### Configuration File’s Structure｜設定檔的結構

nginx consists of modules which are controlled by directives specified in the configuration file. Directives are divided into simple directives and block directives. A simple directive consists of the name and parameters separated by spaces and ends with a semicolon (`;`). A block directive has the same structure as a simple directive, but instead of the semicolon it ends with a set of additional instructions surrounded by braces (`{` and `}`). If a block directive can have other directives inside braces, it is called a context (examples: [events](<125 [01.01 文件] 核心功能.md#events>), [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#http>), [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>), and [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>)).

nginx 由由設定檔中指定的指令控制的模組組成。指令分為簡單指令和區塊指令。一個簡單的指令由名稱和參數組成，名稱和參數之間用空格分隔，並以分號 (`;`) 結尾。塊指令具有與簡單指令相同的結構，但它不是以分號結尾，而是以一組用大括號括起來的附加指令（`{` 和 `}`）結尾。如果區塊指令可以在大括號內包含其他指令，則稱為上下文（例如：[events](<125 [01.01 文件] 核心功能.md#events>)、[http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#http>)、[server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) 和 [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>)）。

Directives placed in the configuration file outside of any contexts are considered to be in the [main](<125 [01.01 文件] 核心功能.md>) context. The `events` and `http` directives reside in the `main` context, `server` in `http`, and `location` in `server`.

放置在任何上下文之外的設定檔中的指令都被視為位於 [main](<125 [01.01 文件] 核心功能.md>) 上下文中。 `events` 和 `http` 指令位於 `main` 上下文中，`server` 位於`http` 中，`location` 位於`server` 中。

The rest of a line after the `#` sign is considered a comment.

`#` 符號之後的其餘行視為註解。

#### Serving Static Content｜提供靜態內容

An important web server task is serving out files (such as images or static HTML pages). You will implement an example where, depending on the request, files will be served from different local directories: `/data/www` (which may contain HTML files) and `/data/images` (containing images). This will require editing of the configuration file and setting up of a [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) block inside the [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#http>) block with two [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) blocks.

一項重要的 Web 伺服器任務是提供檔案（例如圖片或靜態HTML 頁面）。您將實作一個範例，其中根據請求，將從不同的本機目錄提供檔案：`/data/www`（可能包含HTML檔案）和`/data/images`（包含影像）。這將需要編輯設定檔並在 [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#http>) 區塊內設定一個 [server](<056 [01.01.03 http] 模組 ngx_http_core_module.md#server>) 區塊以及兩個 [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) 區塊。

First, create the `/data/www` directory and put an `index.html` file with any text content into it and create the `/data/images` directory and place some images in it.

首先，建立`/data/www`目錄並放入一個包含任何文字內容的`index.html`文件，然後建立`/data/images`目錄並在其中放置一些圖像。

Next, open the configuration file. The default configuration file already includes several examples of the `server` block, mostly commented out. For now comment out all such blocks and start a new `server` block:

接下來，開啟設定檔。預設設定檔已包含 `server` 區塊的幾個範例，大部分已註解掉。現在註解掉所有此類區塊並開始一個新的 `server` 區塊：

> ```
> http {
>
> http{
>     server {
>
>     伺服器{
>     }
> }
> ```

Generally, the configuration file may include several `server` blocks [distinguished](<111 [01.01.03 http] nginx 如何處理請求.md>) by ports on which they [listen](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>) to and by [server names](<112 [01.01.03 http] 伺服器名稱.md>). Once nginx decides which `server` processes a request, it tests the URI specified in the request’s header against the parameters of the `location` directives defined inside the `server` block.

一般來說，設定檔可能包含多個`server`區塊[區分](<111 [01.01.03 http] nginx 如何處理請求.md>)，按它們[偵聽](<056 [01.01.03 http] 模組 ngx_http_core_module.md#listen>)的連接埠和[伺服器名稱](<112 [01.01.03 http] 伺服器名稱.md>)。一旦 nginx 決定由哪個 `server` 處理請求，它就會根據 `server` 區塊內定義的 `location` 指令的參數來測試請求標頭中指定的 URI。

Add the following `location` block to the `server` block:

將以下`location`塊加到`server`塊：

> ```
> location / {
>
> 地點/{
>     root /data/www;
>
>     根/數據/www；
> }
> ```

This `location` block specifies the “`/`” prefix compared with the URI from the request. For matching requests, the URI will be added to the path specified in the [root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>) directive, that is, to `/data/www`, to form the path to the requested file on the local file system. If there are several matching `location` blocks nginx selects the one with the longest prefix. The `location` block above provides the shortest prefix, of length one, and so only if all other `location` blocks fail to provide a match, this block will be used.

此`location`塊指定與請求中的URI相比的「`/`」前綴。對於符合的請求，URI將會被加入到[root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>)指令中指定的路徑，即`/data/www`，形成請求檔案在本機檔案系統的路徑。如果有多個匹配的`location`塊，nginx會選擇具有最長前綴的那個。上面的`location`塊提供了長度為1的最短前綴，因此只有當所有其他`location`塊無法提供匹配時，才會使用該塊。

Next, add the second `location` block:

接下來，新增第二個`location`塊：

> ```
> location /images/ {
>
> 位置/圖像/ {
>     root /data;
>
>     根/數據；
> }
> ```

It will be a match for requests starting with `/images/` (`location /` also matches such requests, but has shorter prefix).

它將匹配以 `/images/` 開頭的請求（`location /` 也匹配此類請求，但前綴較短）。

The resulting configuration of the `server` block should look like this:

`server` 塊的最終配置應如下所示：

> ```
> server {
>
> 伺服器{
>     location / {
>
>     地點/{
>         root /data/www;
>
>         根/數據/www；
>     }
> 
>     location /images/ {
>
>     位置/圖像/ {
>         root /data;
>
>         根/數據；
>     }
> }
> ```

This is already a working configuration of a server that listens on the standard port 80 and is accessible on the local machine at `http://localhost/`. In response to requests with URIs starting with `/images/`, the server will send files from the `/data/images` directory. For example, in response to the `http://localhost/images/example.png` request nginx will send the `/data/images/example.png` file. If such file does not exist, nginx will send a response indicating the 404 error. Requests with URIs not starting with `/images/` will be mapped onto the `/data/www` directory. For example, in response to the `http://localhost/some/example.html` request nginx will send the `/data/www/some/example.html` file.

這已經是伺服器的工作配置，該伺服器偵聽標準連接埠 80，並且可以在本機電腦上透過`http://localhost/`進行存取。為了回應 URI 以 `/images/` 開頭的請求，伺服器將從 `/data/images` 目錄發送檔案。例如，為了回應 `http://localhost/images/example.png` 請求，nginx 將發送 `/data/images/example.png` 檔案。如果該檔案不存在，nginx將發送404錯誤回應。 URI 不以`/images/` 開頭的請求將會對應到`/data/www` 目錄。例如，為了回應 `http://localhost/some/example.html` 請求，nginx 將發送 `/data/www/some/example.html` 檔案。

To apply the new configuration, start nginx if it is not yet started or send the `reload` signal to the nginx’s master process, by executing:

若要套用新配置，請啟動 nginx（如果尚未啟動）或將 `reload` 訊號傳送到 nginx 的主進程，方法是執行：

> ```
> nginx -s reload
>
> nginx -s 重新載入
> ```

> In case something does not work as expected, you may try to find out the reason in `access.log` and `error.log` files in the directory `/usr/local/nginx/logs` or `/var/log/nginx`.
>
> 如果出現問題，您可以嘗試在`/usr/local/nginx/logs`或`/var/log/nginx`目錄下的`access.log`和`error.log`文件中找出原因。

#### Setting Up a Simple Proxy Server｜設定簡單的代理伺服器

One of the frequent uses of nginx is setting it up as a proxy server, which means a server that receives requests, passes them to the proxied servers, retrieves responses from them, and sends them to the clients.

nginx 的常見用途之一是將其設定為代理伺服器，這意味著伺服器接收請求，將它們傳遞到代理伺服器，檢索它們的回應，然後將它們傳送到客戶端。

We will configure a basic proxy server, which serves requests of images with files from the local directory and sends all other requests to a proxied server. In this example, both servers will be defined on a single nginx instance.

我們將配置一個基本的代理伺服器，它服務於本地目錄中的帶有檔案的映像請求，並將所有其他請求傳送到代理伺服器。在此範例中，兩個伺服器都將在單一 nginx 實例上定義。

First, define the proxied server by adding one more `server` block to the nginx’s configuration file with the following contents:

首先，透過在 nginx 的設定檔中新增一個`server`區塊來定義代理伺服器，其內容如下：

> ```
> server {
>
> 伺服器{
>     listen 8080;
>
>     聽8080；
>     root /data/up1;
>
>     根/數據/up1；
> 
>     location / {
>
>     地點/{
>     }
> }
> ```

This will be a simple server that listens on the port 8080 (previously, the `listen` directive has not been specified since the standard port 80 was used) and maps all requests to the `/data/up1` directory on the local file system. Create this directory and put the `index.html` file into it. Note that the `root` directive is placed in the `server` context. Such `root` directive is used when the `location` block selected for serving a request does not include its own `root` directive.

這將是一個簡單的伺服器，偵聽連接埠 8080（之前，由於使用了標準連接埠 80，因此尚未指定 `listen` 指令）並將所有請求對應到本機檔案系統上的 `/data/up1` 目錄。建立該目錄並將`index.html`檔案放入其中。請注意，`root`指令放置在`server`上下文中。當選擇用於服務請求的`location`塊不包含其自己的`root`指令時，使用此類`root`指令。

Next, use the server configuration from the previous section and modify it to make it a proxy server configuration. In the first `location` block, put the [proxy\_pass](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_pass>) directive with the protocol, name and port of the proxied server specified in the parameter (in our case, it is `http://localhost:8080`):

接下來，使用上一節中的伺服器配置並修改它以使其成為代理伺服器配置。在第一個 `location` 區塊中，放置 [proxy\_pass](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_pass>) 指令，並在參數中指定代理伺服器的協定、名稱和連接埠（在我們的範例中為 `http://localhost:8080`）：

> ```
> server {
>
> 伺服器{
>     location / {
>
>     地點/{
>         proxy_pass http://localhost:8080;
>     }
> 
>     location /images/ {
>
>     位置/圖像/ {
>         root /data;
>
>         根/數據；
>     }
> }
> ```

We will modify the second `location` block, which currently maps requests with the `/images/` prefix to the files under the `/data/images` directory, to make it match the requests of images with typical file extensions. The modified `location` block looks like this:

我們將修改第二個`location`塊，該塊目前將帶有`/images/`前綴的請求映射到`/data/images`目錄下的文件，以使其匹配具有典型文件副檔名的圖像的請求。修改後的`location`塊如下圖所示：

> ```
> location ~ \.(gif|jpg|png)$ {
>
> 位置 ~ \.(gif|jpg|png)$ {
>     root /data/images;
>
>     根/數據/圖像；
> }
> ```

The parameter is a regular expression matching all URIs ending with `.gif`, `.jpg`, or `.png`. A regular expression should be preceded with `~`. The corresponding requests will be mapped to the `/data/images` directory.

參數是符合所有以`.gif`, `.jpg`或`.png`結尾的URI的正規表示式。正規表示式前面應帶有 `~`。相應的請求將被映射到`/data/images`目錄。

When nginx selects a `location` block to serve a request it first checks [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) directives that specify prefixes, remembering `location` with the longest prefix, and then checks regular expressions. If there is a match with a regular expression, nginx picks this `location` or, otherwise, it picks the one remembered earlier.

當 nginx 選擇一個 `location` 區塊來服務請求時，它首先檢查指定前綴的 [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>) 指令，記住具有最長前綴的 `location`，然後檢查正規表示式。如果與正規表示式匹配，nginx 會選擇這個 `location`，否則，它會選擇先前記住的那個。

The resulting configuration of a proxy server will look like this:

代理伺服器的最終配置將如下所示：

> ```
> server {
>
> 伺服器{
>     location / {
>
>     地點/{
>         proxy_pass http://localhost:8080/;
>     }
> 
>     location ~ \.(gif|jpg|png)$ {
>
>     位置 ~ \.(gif|jpg|png)$ {
>         root /data/images;
>
>         根/數據/圖像；
>     }
> }
> ```

This server will filter requests ending with `.gif`, `.jpg`, or `.png` and map them to the `/data/images` directory (by adding URI to the `root` directive’s parameter) and pass all other requests to the proxied server configured above.

該伺服器將過濾以`.gif`, `.jpg`或`.png`結尾的請求，並將它們對應到`/data/images`目錄（透過將URI加到`root`的參數），並將所有其他代理伺服器傳遞到上面配置的伺服器。

To apply new configuration, send the `reload` signal to nginx as described in the previous sections.

若要套用新配置，請按照前面部分所述向 nginx 發送 `reload` 訊號。

There are many [more](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md>) directives that may be used to further configure a proxy connection.

有許多[更多](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md>)指令可用於進一步配置代理連接。

#### Setting Up FastCGI Proxying｜設定 FastCGI 代理

nginx can be used to route requests to FastCGI servers which run applications built with various frameworks and programming languages such as PHP.

nginx 可用於將請求路由到 FastCGI 伺服器，該伺服器運行使用各種框架和程式語言（例如PHP）建構的應用程式。

The most basic nginx configuration to work with a FastCGI server includes using the [fastcgi\_pass](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_pass>) directive instead of the `proxy_pass` directive, and [fastcgi\_param](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_param>) directives to set parameters passed to a FastCGI server. Suppose the FastCGI server is accessible on `localhost:9000`. Taking the proxy configuration from the previous section as a basis, replace the `proxy_pass` directive with the `fastcgi_pass` directive and change the parameter to `localhost:9000`. In PHP, the `SCRIPT_FILENAME` parameter is used for determining the script name, and the `QUERY_STRING` parameter is used to pass request parameters. The resulting configuration would be:

使用 FastCGI 伺服器的最基本的 nginx 配置包括使用 [fastcgi\_pass](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_pass>) 指令而不是 `proxy_pass` 指令，以及 [fastcgi\_param](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_param>) 指令來設定傳送給 FastCGI GI 的參數。假設可以在 `localhost:9000` 上存取 FastCGI 伺服器。以上一節的代理配置為基礎，將`proxy_pass`指令替換為`fastcgi_pass`指令，並將參數改為`localhost:9000`。 PHP中，`SCRIPT_FILENAME`參數用於決定腳本名稱，`QUERY_STRING`參數用於傳遞請求參數。最終的配置將是：

> ```
> server {
>
> 伺服器{
>     location / {
>
>     地點/{
>         fastcgi_pass  localhost:9000;
>
>         fastcgi_pass 本機：9000；
>         fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
>         fastcgi_param QUERY_STRING    $query_string;
>
>         fastcgi_param QUERY_STRING $query_string;
>     }
> 
>     location ~ \.(gif|jpg|png)$ {
>
>     位置 ~ \.(gif|jpg|png)$ {
>         root /data/images;
>
>         根/數據/圖像；
>     }
> }
> ```

This will set up a server that will route all requests except for requests for static images to the proxied server operating on `localhost:9000` through the FastCGI protocol.

這將設定一個伺服器，該伺服器將透過 FastCGI 協定將除靜態映像請求之外的所有請求路由到在 `localhost:9000` 上運行的代理伺服器。
