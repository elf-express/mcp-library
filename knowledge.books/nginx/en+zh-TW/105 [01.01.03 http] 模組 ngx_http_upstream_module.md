The `ngx_http_upstream_module` module is used to define groups of servers that can be referenced by the [proxy\_pass](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_pass>), [fastcgi\_pass](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_pass>), [uwsgi\_pass](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_pass>), [scgi\_pass](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_pass>), [memcached\_pass](<079 [01.01.03 http] 模組 ngx_http_memcached_module.md#memcached_pass>), and [grpc\_pass](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md#grpc_pass>) directives.

`ngx_http_upstream_module`模組用來定義伺服器群組，這些伺服器群組可以被 [proxy\_pass](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_pass>) 、 [fastcgi\_pass](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_pass>) 、 [uwsgi\_pass](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_pass>) 、 [scgi_pass](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_pass>) (https://nginx.org/en/docs/http/ngx_http_memcached_module.html#memcached_pass)和 [grpc\_pass](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md#grpc_pass>)指令引用。

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>文法： | ``**upstream** `*name*` { ... }``<br>` `**upstream** ` *名稱* ` { ... }` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http` |

Defines a group of servers. Servers can listen on different ports. In addition, servers listening on TCP and UNIX-domain sockets can be mixed.

定義一組伺服器。伺服器可以監聽不同的連接埠。此外，監聽TCP和UNIX域套接字的伺服器可以混合使用。

Example:

例子：

> ```
> upstream backend {
>
> 上游後端 {
>     server backend1.example.com weight=5;
>
>     伺服器 backend1.example.com 權重=5；
>     server 127.0.0.1:8080       max_fails=3 fail_timeout=30s;
>
>     伺服器127.0.0.1:8080 max_fails=3 fail_timeout=30s;
>     server unix:/tmp/backend3;
>
>     伺服器 unix:/tmp/backend3;
> 
>     server backup1.example.com  backup;
>
>     伺服器備份1.example.com；
> }
> ```

By default, requests are distributed between the servers using a weighted round-robin balancing method. In the above example, each 7 requests will be distributed as follows: 5 requests go to `backend1.example.com` and one request to each of the second and third servers. If an error occurs during communication with a server, the request will be passed to the next server, and so on until all of the functioning servers will be tried. If a successful response could not be obtained from any of the servers, the client will receive the result of the communication with the last server.

預設情況下，請求會使用加權輪詢負載平衡方法在伺服器之間分配。在上面的範例中，7 個請求將按以下方式分配：5 個請求發送到`backend1.example.com` ，其餘 1 個請求分別發送到第二台和第三台伺服器。如果在與伺服器通訊過程中發生錯誤，則請求將傳遞給下一台伺服器，依此類推，直到嘗試所有可用的伺服器為止。如果無法從任何伺服器獲得成功回應，客戶端將收到與最後一台伺服器通訊的結果。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**server** `*address*` [`*parameters*`];``<br>` `**server** ` *地址* ` [` *參數* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `upstream` |

Defines the `*address*` and other `*parameters*` of a server. The address can be specified as a domain name or IP address, with an optional port, or as a UNIX-domain socket path specified after the “`unix:`” prefix. If a port is not specified, the port 80 is used. A domain name that resolves to several IP addresses defines multiple servers at once.

定義伺服器的`*address*`及其他`*parameters*`位址。位址可以指定為網域名稱或IP位址（選用連接埠），也可以指定為UNIX網域套接字路徑（位於「 `unix:` 」前綴之後）。如果未指定端口，則使用端口80。解析到多個IP位址的網域名稱可以同時定義多個伺服器。

The following parameters can be defined:

可以定義以下參數：

`weight`\=`*number*`

sets the weight of the server, by default, 1.

設定伺服器權重，預設值為 1。

`max_conns`\=`*number*`

limits the maximum `*number*` of simultaneous active connections to the proxied server (1.11.5). Default value is zero, meaning there is no limit. If the server group does not reside in the [shared memory](#zone), the limitation works per each worker process.

限制與代理伺服器 ( 1.11.5 ) 的並發活動連線數的最大值`*number*` 。預設值為零，表示沒有限制。如果伺服器群組不在共享記憶體 ( (https://nginx.org/en/docs/http/ngx_http_upstream_module.html#zone) ) 中，則此限制針對每個工作進程生效。

> If [idle keepalive](#keepalive) connections, multiple [workers](<125 [01.01 文件] 核心功能.md#worker_processes>), and the [shared memory](#zone) are enabled, the total number of active and idle connections to the proxied server may exceed the `max_conns` value.
>
> 如果啟用了 [空閒保持連接](#keepalive)連接、多個 [工作進程](<125 [01.01 文件] 核心功能.md#worker_processes>)和 [共享內存](#zone) ，則代理伺服器的活動連接和空閒連接總數可能超過`max_conns`值。

> Since version 1.5.9 and prior to version 1.11.5, this parameter was available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 從版本1.5.9到版本1.11.5 ，此參數作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`max_fails`\=`*number*`

sets the number of unsuccessful attempts to communicate with the server that should happen in the duration set by the `fail_timeout` parameter to consider the server unavailable for a duration also set by the `fail_timeout` parameter. By default, the number of unsuccessful attempts is set to 1. The zero value disables the accounting of attempts. What is considered an unsuccessful attempt is defined by the [proxy\_next\_upstream](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_next_upstream>), [fastcgi\_next\_upstream](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_next_upstream>), [uwsgi\_next\_upstream](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_next_upstream>), [scgi\_next\_upstream](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_next_upstream>), [memcached\_next\_upstream](<079 [01.01.03 http] 模組 ngx_http_memcached_module.md#memcached_next_upstream>), and [grpc\_next\_upstream](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md#grpc_next_upstream>) directives.

此設定用於指定在`fail_timeout`參數設定的時間段內，與伺服器通訊失敗的次數，超過此次數則視為伺服器在`fail_timeout`參數設定的時間段內不可用。預設情況下，失敗次數為 1。值為零則禁用失敗次數統計。失敗的嘗試由 [proxy\_next\_upstream](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_next_upstream>) 、 [fastcgi\_next\_upstream](<060 [01.01.03 http] 模組 ngx_http_fastcgi_module.md#fastcgi_next_upstream>) 、 [uwsgi\_next\_upstream](<107 [01.01.03 http] 模組 ngx_http_uwsgi_module.md#uwsgi_next_upstream>) 、 [uwsgi\_next\_upstream](<091 [01.01.03 http] 模組 ngx_http_scgi_module.md#scgi_next_upstream>) , [scgi_n; [memcached\_next\_upstream](<079 [01.01.03 http] 模組 ngx_http_memcached_module.md#memcached_next_upstream>)與 [grpc\_next\_upstream](<064 [01.01.03 http] 模組 ngx_http_grpc_module.md#grpc_next_upstream>)指令定義。

`fail_timeout`\=`*time*`

sets

套

-   the time during which the specified number of unsuccessful attempts to communicate with the server should happen to consider the server unavailable;  
    在指定時間內，與伺服器通訊失敗次數達到指定值後，伺服器將被視為不可用；
-   and the period of time the server will be considered unavailable.  
    以及伺服器將被視為不可用的時間段。

By default, the parameter is set to 10 seconds.

預設情況下，此參數設定為 10 秒。

`backup`

marks the server as a backup server. It will be passed requests when the primary servers are unavailable.

將伺服器標記為備用伺服器。當主伺服器不可用時，請求將轉送給該伺服器。

> The parameter cannot be used along with the [hash](#hash), [ip\_hash](#ip_hash), and [random](#random) load balancing methods.
>
> 此參數不能與 [hash](#hash) 、[ip\_hash](#ip_hash)和 [random](#random)負載平衡方法一起使用。

`down`

marks the server as permanently unavailable.

將伺服器標記為永久不可用。

`resolve`

monitors changes of the IP addresses that correspond to a domain name of the server, and automatically modifies the upstream configuration without the need of restarting nginx (1.5.12). The server group must reside in the [shared memory](#zone).

監控與伺服器網域名稱對應的IP位址的變化，並自動修改上游配置，無需重新啟動nginx（ 1.5.12 ）。伺服器群組必須位於[共享記憶體](#zone)中。

In order for this parameter to work, the `resolver` directive must be specified in the [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>) block or in the corresponding [upstream](#resolver) block.

為了使此參數生效，必須在 [http](<056 [01.01.03 http] 模組 ngx_http_core_module.md#resolver>)區塊或對應的 [upstream](#resolver)區塊中指定`resolver`指令。

> Prior to version 1.27.3, this parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.27.3之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`service`\=`*name*`

enables resolving of DNS [SRV](https://datatracker.ietf.org/doc/html/rfc2782) records and sets the service `*name*` (1.9.13). In order for this parameter to work, it is necessary to specify the [resolve](#resolve) parameter for the server and specify a hostname without a port number.

啟用對DNS [SRV](https://datatracker.ietf.org/doc/html/rfc2782)記錄的解析，並設定服務`*name*` ( 1.9.13 )。為了使此參數生效，必須為伺服器指定 [resolve](#resolve)參數，並指定不含連接埠號碼的主機名稱。

If the service name does not contain a dot (“`.`”), then the [RFC](https://datatracker.ietf.org/doc/html/rfc2782)\-compliant name is constructed and the TCP protocol is added to the service prefix. For example, to look up the `_http._tcp.backend.example.com` SRV record, it is necessary to specify the directive:

如果服務名稱不包含點號（「 `.` 」），則建構符合 [RFC](https://datatracker.ietf.org/doc/html/rfc2782)標準的名稱，並將TCP協定新增至服務前綴。例如，要尋找`_http._tcp.backend.example.com` SRV記錄，需要指定以下指令：

> ```
> server backend.example.com service=http resolve;
>
> 伺服器 backend.example.com 服務=http 解析；
> ```

If the service name contains one or more dots, then the name is constructed by joining the service prefix and the server name. For example, to look up the `_http._tcp.backend.example.com` and `server1.backend.example.com` SRV records, it is necessary to specify the directives:

如果服務名稱包含一個或多個點，則名稱由服務前綴和伺服器名稱連接而成。例如，要找`_http._tcp.backend.example.com`和`server1.backend.example.com` SRV記錄，需要指定以下指令：

> ```
> server backend.example.com service=_http._tcp resolve;
> server example.com service=server1.backend resolve;
>
> 伺服器 example.com 服務=server1.backend 解析；
> ```

Highest-priority SRV records (records with the same lowest-number priority value) are resolved as primary servers, the rest of SRV records are resolved as backup servers. If the [backup](#backup) parameter is specified for the server, high-priority SRV records are resolved as backup servers, the rest of SRV records are ignored.

優先權最高的SRV記錄（優先權值最低的記錄）被解析為主伺服器，其餘的SRV記錄被解析為備份伺服器。如果為伺服器指定了[backup](#backup)參數，則優先順序最高的SRV記錄被解析為備份伺服器，其餘的SRV記錄將被忽略。

> Prior to version 1.27.3, this parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.27.3之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`route`\=`*string*`

sets the server route name.

設定伺服器路由名稱。

> Prior to version 1.29.6, this parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.29.6之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

`drain`

puts the server into the “draining” mode (1.13.6). In this mode, only requests [bound](#sticky) to the server will be proxied to it.

將伺服器置於「清空」模式（ 1.13.6 ）。在此模式下，只有綁定到伺服器的請求（ (https://nginx.org/en/docs/http/ngx_http_upstream_module.html#sticky) ）才會被代理到該伺服器。

> Prior to version 1.13.6, the parameter could be changed only with the [API](<048 [01.01.03 http] 模組 ngx_http_api_module.md>) module.
>
> 在版本1.13.6之前，此參數只能透過 [API](<048 [01.01.03 http] 模組 ngx_http_api_module.md>)模組進行變更。

> Prior to version 1.29.6, the parameter was available only as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 在版本1.29.6之前，此參數僅作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

Additionally, the following parameters are available as part of our [commercial subscription](https://www.f5.com/products/nginx):

此外，以下參數包含在我們的[商業訂閱](https://www.f5.com/products/nginx)中：

`slow_start`\=`*time*`

sets the `*time*` during which the server will recover its weight from zero to a nominal value, when unhealthy server becomes [healthy](<104 [01.01.03 http] 模組 ngx_http_upstream_hc_module.md#health_check>), or when the server becomes available after a period of time it was considered [unavailable](#fail_timeout). Default value is zero, i.e. slow start is disabled.

設定`*time*`在此期間，伺服器的權重將從零恢復到標稱值，當不健康的伺服器變為 [健康](<104 [01.01.03 http] 模組 ngx_http_upstream_hc_module.md#health_check>)時，或當伺服器在被視為 [不可用 一段時間後恢復可用時](#fail_timeout) 。預設值為零，即禁用慢啟動。

> The parameter cannot be used along with the [hash](#hash), [ip\_hash](#ip_hash), and [random](#random) load balancing methods.
>
> 此參數不能與 [hash](#hash) 、[ip\_hash](#ip_hash)和 [random](#random)負載平衡方法一起使用。

> If there is only a single server in a group, `max_fails`, `fail_timeout` and `slow_start` parameters are ignored, and such a server will never be considered unavailable.
>
> 如果一個群組中只有一個伺服器，則忽略`max_fails`, `fail_timeout`和`slow_start`參數，並且這樣的伺服器永遠不會被視為不可用。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**zone** `*name*` [`*size*`];``<br>` `**zone** ` *名稱* ` [` *大小* `];` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `upstream` |

This directive appeared in version 1.9.0.

Enables session affinity, which causes requests from the same client to be passed to the same server in a group of servers. Three methods are available:

`cookie`

When the `cookie` method is used, information about the designated server is passed in an HTTP cookie generated by nginx:

來自尚未綁定到特定伺服器的客戶端的請求將被轉送到配置的負載平衡方法所選擇的伺服器。後續帶有此 cookie 的請求將被轉送到指定的伺服器。如果指定的伺服器無法處理請求，則會選擇新的伺服器，如同該用戶端尚未綁定一樣。

>

`$upstream_addr`

keeps the IP address and port, or the path to the UNIX-domain socket of the upstream server. If several servers were contacted during request processing, their addresses are separated by commas, e.g. “`192.168.1.1:80, 192.168.1.2:80, unix:/tmp/sock`”. If an internal redirect from one server group to another happens, initiated by “X-Accel-Redirect”（X-Accel-重定向） or [error\_page](<056 [01.01.03 http] 模組 ngx_http_core_module.md#error_page>), then the server addresses from different groups are separated by colons, e.g. “`192.168.1.1:80, 192.168.1.2:80, unix:/tmp/sock : 192.168.10.1:80, 192.168.10.2:80`”. If a server cannot be selected, the variable keeps the name of the server group.

保留上游伺服器的位址和連接埠IP ，或指向其網域套接字的路徑（ UNIX ）。如果在請求處理期間聯繫了多個伺服器，則它們的位址會以逗號分隔，例如「 `192.168.1.1:80, 192.168.1.2:80, unix:/tmp/sock` 」。如果發生由“X-Accel-Redirect”（X-Accel-重定向）或[error\_page](<056 [01.01.03 http] 模組 ngx_http_core_module.md#error_page>)發起的內部伺服器群組重定向，則不同伺服器群組的位址以冒號分隔，例如「 `192.168.1.1:80, 192.168.1.2:80, unix:/tmp/sock : 192.168.10.1:80, 192.168.10.2:80` 」。如果無法選擇伺服器，則該變數保留伺服器群組的名稱。

`$upstream_bytes_received`

number of bytes received from an upstream server (1.11.4). Values from several connections are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

從上游伺服器接收的位元組數（ 1.11.4 ）。來自多個連接的值以逗號和冒號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_bytes_sent`

number of bytes sent to an upstream server (1.15.8). Values from several connections are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

發送到上游伺服器的位元組數（ 1.15.8 ）。來自多個連接的值以逗號和冒號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_cache_status`

keeps the status of accessing a response cache (0.8.3). The status can be either “`MISS`”, “`BYPASS`”, “`EXPIRED`”, “`STALE`”, “`UPDATING`”, “`REVALIDATED`”, or “`HIT`”.

保持存取回應快取的狀態（ 0.8.3 ）。此狀態可以是「 `MISS` 」、「 `BYPASS` 」、「 `EXPIRED` 」、「 `STALE` 」、「 `UPDATING` 」、「 `REVALIDATED` `HIT` 」。

`$upstream_connect_time`

keeps time spent on establishing a connection with the upstream server (1.9.1); the time is kept in seconds with millisecond resolution. In case of SSL, includes time spent on handshake. Times of several connections are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

記錄與上游伺服器建立連線所花費的時間（ 1.9.1 ）；時間以秒為單位，精確到毫秒。對於SSL ，則包含握手所花費的時間。多個連接的時間用逗號和冒號分隔，就像[$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_cookie_``*name*`

cookie with the specified `*name*` sent by the upstream server in the “Set-Cookie”（設定 Cookie） response header field (1.7.1). Only the cookies from the response of the last server are saved.

上游伺服器在回應頭欄位（ 1.7.1 ） “Set-Cookie”（設定 Cookie）中發送的帶有指定`*name*`的cookie。僅保存來自最後一個伺服器回應的cookie。

`$upstream_header_time`

keeps time spent on receiving the response header from the upstream server (1.7.10); the time is kept in seconds with millisecond resolution. Times of several responses are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

記錄從上游伺服器接收回應頭所花費的時間（ 1.7.10 ）；時間以秒為單位，精確到毫秒。多個回應的時間用逗號和冒號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_http_``*name*`

keep server response header fields. For example, the “Server”（伺服器） response header field is available through the `$upstream_http_server` variable. The rules of converting header field names to variable names are the same as for the variables that start with the “[$http\_](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_http_>)” prefix. Only the header fields from the response of the last server are saved.

保留伺服器響應頭字段。例如， “Server”（伺服器）響應頭字段可透過`$upstream_http_server`變數存取。將回應頭欄位名稱轉換為變數名稱的規則與以「[$http\_](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_http_>) 」為前綴的變數的轉換規則相同。僅保存來自最後一個伺服器回應的回應頭字段。

`$upstream_last_addr`

keeps the IP address or the path to the UNIX-domain socket of the last selected upstream server (1.29.3).

保留最後選定的上游伺服器（ 1.29.3 ）的IP位址或UNIX域套接字的路徑。

`$upstream_last_server_name`

keeps the name of last selected upstream server (1.25.3); allows passing it [through SNI](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_ssl_server_name>):

保留上次選擇的上游伺服器的名稱（ 1.25.3 ）；允許將其傳遞[透過SNI](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_ssl_server_name>) ：

`$upstream_queue_time`

keeps time the request spent in the upstream [queue](#queue) (1.13.9); the time is kept in seconds with millisecond resolution. Times of several responses are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

記錄請求在上游 [隊列](#queue) ( 1.13.9 ) 中花費的時間；時間以秒為單位，精確到毫秒。多個回應的時間用逗號和冒號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_response_length`

keeps the length of the response obtained from the upstream server (0.7.27); the length is kept in bytes. Lengths of several responses are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

保存從上游伺服器獲得的回應長度（ 0.7.27 ）；長度以位元組為單位。多個回應的長度以逗號和冒號分隔，就像位址一樣，在 [$upstream\_addr](#var_upstream_addr)變數中。

`$upstream_response_time`

keeps time spent on receiving the response from the upstream server; the time is kept in seconds with millisecond resolution. Times of several responses are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable.

記錄接收上游伺服器回應所花費的時間；時間以秒為單位，精確到毫秒。多個回應的時間用逗號和冒號分隔，就像 [$upstream\_addr](#var_upstream_addr)變數中的位址一樣。

`$upstream_status`

keeps status code of the response obtained from the upstream server. Status codes of several responses are separated by commas and colons like addresses in the [$upstream\_addr](#var_upstream_addr) variable. If a server cannot be selected, the variable keeps the 502 (Bad Gateway) status code.

保存從上游伺服器取得的回應狀態碼。多個回應的狀態碼用逗號和冒號分隔，就像位址一樣，儲存在 [$upstream\_addr](#var_upstream_addr)變數中。如果無法選擇伺服器，則變數儲存 502（錯誤網關）狀態碼。

`$upstream_trailer_``*name*`

保留從上游伺服器取得的回應末尾的欄位（ 1.13.10 ）。
