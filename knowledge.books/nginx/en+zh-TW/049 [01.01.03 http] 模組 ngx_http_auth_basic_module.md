# Module ngx_http_auth_basic_module｜模組 ngx_http_auth_basic_module

## Module ngx\_http\_auth\_basic\_module｜模組 ngx_http_auth_basic_module

|   |

| [Example Configuration](#example)<br>[Directives](#directives)<br>     [auth\_basic](#auth_basic)<br>     [auth\_basic\_user\_file](#auth_basic_user_file)<br>[範例配置](#example)<br> [指令](#directives)<br> [auth\_basic](#auth_basic)<br> [auth\_basic\_user\_file](#auth_basic_user_file) |

The `ngx_http_auth_basic_module` module allows limiting access to resources by validating the user name and password using the “HTTP Basic Authentication”（HTTP 基本驗證） protocol.

`ngx_http_auth_basic_module`模組允許透過使用“HTTP Basic Authentication”（HTTP 基本驗證）協定驗證使用者名稱和密碼來限制對資源的存取。

Access can also be limited by [address](<045 [01.01.03 http] 模組 ngx_http_access_module.md>), by the [result of subrequest](<051 [01.01.03 http] 模組 ngx_http_auth_request_module.md>), or by [JWT](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>). Simultaneous limitation of access by address and by password is controlled by the [satisfy](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>) directive.

存取也可以透過 [地址](<045 [01.01.03 http] 模組 ngx_http_access_module.md>) 、[子請求結果](<051 [01.01.03 http] 模組 ngx_http_auth_request_module.md>)或 [JWT](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>)來限制。透過位址和密碼同時限制存取由 [滿足](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>)指令控制。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點/{
>     auth_basic           "closed site";
>
>     auth_basic "已關閉站點";
>     auth_basic_user_file conf/htpasswd;
> }
> ```

Enables validation of user name and password using the “HTTP Basic Authentication”（HTTP 基本驗證） protocol. The specified parameter is used as a `*realm*`. Parameter value can contain variables (1.3.10, 1.2.7). The special value `off` cancels the effect of the `auth_basic` directive inherited from the previous configuration level.

啟用使用“HTTP Basic Authentication”（HTTP 基本驗證）協定驗證使用者名稱和密碼。指定的參數用作`*realm*` 。參數值可以包含變數（ 1.3.10, 1.2.7 ）。特殊值`off`會取消從上一層配置繼承的`auth_basic`指令的效果。

Specifies a file that keeps user names and passwords, in the following format:

指定一個用於保存使用者名稱和密碼的文件，格式如下：

> ```
> # comment｜評論
> name1:password1
>
> 使用者名稱1:密碼1
> name2:password2:comment
>
> 使用者名稱2:密碼2:評論
> name3:password3
>
> 使用者名稱3:密碼3
> ```

The `*file*` name can contain variables.

`*file*`名稱可以包含變數。

The following password types are supported:

支援以下幾種密碼類型：

-   encrypted with the `crypt()` function; can be generated using the “`htpasswd`” utility from the Apache HTTP Server distribution or the “`openssl passwd`” command;  
    使用`crypt()`函數加密；可使用 Apache HTTP伺服器發行版中的「 `htpasswd` 」公用程式或「 `openssl passwd` 」指令產生；
-   hashed with the Apache variant of the MD5-based password algorithm (apr1); can be generated with the same tools;  
    使用基於MD5的 Apache 變體密碼演算法 (apr1) 進行哈希處理；可以使用相同的工具產生；
-   specified by the “`{``*scheme*``}``*data*`” syntax (1.0.3+) as described in [RFC 2307](https://datatracker.ietf.org/doc/html/rfc2307#section-5.3); currently implemented schemes include `PLAIN` (an example one, should not be used), `SHA` (1.3.13) (plain SHA-1 hashing, should not be used) and `SSHA` (salted SHA-1 hashing, used by some software packages, notably OpenLDAP and Dovecot).  
    由「 `{``*scheme*``}``*data*` 」語法（ 1.0.3 +）指定，如[RFC 2307](https://datatracker.ietf.org/doc/html/rfc2307#section-5.3)中所述；目前實現的方案包括`PLAIN` （範例，不應使用）、 `SHA` 1.3.13 ）（普通SHA -1 哈希，不應使用）和`SSHA` （加鹽SHA -1 哈希，一些軟體包使用，特別是 OpenLDAP 和 Dovecot）。
    
    > Support for `SHA` scheme was added only to aid in migration from other web servers. It should not be used for new passwords, since unsalted SHA-1 hashing that it employs is vulnerable to [rainbow table](http://en.wikipedia.org/wiki/Rainbow_attack) attacks.
    >
    > 新增對`SHA`方案的支援僅是為了方便從其他 Web 伺服器遷移。它不應用於新密碼，因為它採用的無鹽SHA -1 哈希容易受到 [彩虹表](http://en.wikipedia.org/wiki/Rainbow_attack)攻擊。
