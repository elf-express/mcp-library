## Настройка хэшей｜設定哈希

Для быстрой обработки статических наборов данных, таких как имена серверов, значения директивы [map](<243 [02.01.01 http] 模組 ngx_http_map_module.md#map>), MIME-типы, имена полей заголовков запросов, nginx использует хэш-таблицы. Во время старта и при каждой переконфигурации nginx подбирает минимально возможный размер хэш-таблиц с учётом того, чтобы размер корзины, куда попадают ключи с совпадающими хэш-значениями, не превышал заданного параметра (hash bucket size). Размер таблицы считается в корзинах. Подбор ведётся до тех пор, пока размер таблицы не превысит параметр hash max size. Для большинства хэшей есть директивы, которые позволяют менять эти параметры, например, для хэшей имён серверов директивы называются [server\_names\_hash\_max\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>) и [server\_names\_hash\_bucket\_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>).

為了快速處理靜態資料集，例如伺服器名稱、[map] 指令值（ (https://nginx.org/ru/docs/http/ngx_http_map_module.html#map), MIME類型）和請求頭字段名稱，nginx 使用雜湊表。在啟動和每次重新配置時，nginx 會選擇最小的雜湊表大小，以確保具有匹配雜湊值的鍵的桶大小不超過指定的參數（雜湊桶大小）。表大小以桶為單位計算。選擇過程會持續進行，直到表大小超過哈希表最大大小參數。大多數哈希表都有指令允許您更改這些參數；例如，對於伺服器名稱哈希表，指令分別為 [server_names_hash_max_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_max_size>)和 [server_names_hash_bucket_size](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server_names_hash_bucket_size>) 。

Параметр hash bucket size всегда выравнивается до размера, кратного размеру строки кэша процессора. Это позволяет ускорить поиск ключа в хэше на современных процессорах, уменьшив число обращений к памяти. Если hash bucket size равен размеру одной строки кэша процессора, то во время поиска ключа число обращений к памяти в худшем случае будет равно двум — первый раз для определения адреса корзины, а второй — при поиске ключа внутри корзины. Соответственно, если nginx выдал сообщение о необходимости увеличить hash max size или hash bucket size, то сначала нужно увеличивать первый параметр.

哈希桶大小參數始終與處理器快取行大小的倍數保持一致。這透過減少記憶體存取次數來加快現代處理器上的哈希鍵查找速度。如果哈希桶大小等於一個處理器快取行的大小，那麼在鍵查找過程中，最壞情況下記憶體造訪次數為兩次——第一次用於確定桶位址，第二次用於在桶內尋找鍵。因此，如果 NGINX 報告有關增加雜湊最大大小或雜湊桶大小的訊息，則應先增加前者。
