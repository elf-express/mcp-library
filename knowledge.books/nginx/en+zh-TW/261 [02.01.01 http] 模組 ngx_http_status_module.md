Модуль `ngx_http_status_module` предоставляет доступ к информации о состоянии сервера.

模組`ngx_http_status_module`提供對伺服器狀態資訊的存取。

> Этот модуль был доступен как часть [коммерческой подписки](https://www.f5.com/products/nginx) до версии 1.13.10. Модуль был заменён модулем [ngx\_http\_api\_module](https://nginx.org/ru/docs/http/ngx_http_api_module.html) в версии 1.13.3.
>
> 本模組作為[商業訂閱](https://www.f5.com/products/nginx)到版本1.13.10的一部分提供。本模組已被版本1.13.3中的[ngx\_http\_api\_module](https://nginx.org/ru/docs/http/ngx_http_api_module.html)模組取代。

По умолчанию информация выводится в формате JSON.

預設情況下，訊息以JSON格式輸出。

Также данные могут выводиться в формате JSONP. Параметр `*callback*` задаёт имя callback-функции. В значении параметра можно использовать переменные. Если параметр не задан или вычисленное значение является пустой строкой, используется имя “`ngx_status_jsonp_callback`”.

資料也可以以JSONP格式輸出。 `*callback*`參數指定回呼函數的名稱。您可以在參數值中使用變數。如果未指定參數或計算值為空字串，則使用名稱「`ngx_status_jsonp_callback`」。

Включает сбор информации о состоянии виртуального сервера группы [http](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>) или [stream](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#server>) (1.7.11) в указанной `*зоне*`. В одной и той же зоне может одновременно собираться информация сразу по нескольким серверам.

啟用指定 `*зоне*` 中群組 [http](<221 [02.01.01 http] 模組 ngx_http_core_module.md#server>) 或 [stream](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#server>) (1.7.11) 的虛擬伺服器狀態資訊的收集。在同一區域內，可以同時從多個伺服器收集資訊。

#### Данные｜數據

Доступна следующая информация:

可取得以下資訊：

`version`

Версия предоставляемого набора данных. Текущей является версия 8.

所提供資料集的版本。目前版本是8。

`nginx_version`

Версия nginx.

nginx 版本。

`nginx_build`

Название сборки nginx.

Nginx 建置名稱。

`address`

Адрес сервера, принявшего запрос на получение информации о состоянии.

接受狀態資訊請求的伺服器的位址。

`generation`

Суммарное число [перезагрузок](<204 [02.01 文件] nginx 管理.md#reconfiguration>) конфигурации.

[重啟](<204 [02.01 文件] nginx 管理.md#reconfiguration>) 配置總數。

`load_timestamp`

Время последней перезагрузки конфигурации, в миллисекундах с начала эпохи.

上次配置重新載入的時間（自紀元以來的毫秒數）。

`timestamp`

Текущее время в миллисекундах с начала эпохи.

自紀元開始以來的當前時間（以毫秒為單位）。

`pid`

Идентификатор рабочего процесса, обработавшего запрос на получение информации о состоянии.

處理狀態資訊請求的工作進程的 ID。

`ppid`

Идентификатор главного процесса, запустившего [рабочий процесс](#pid).

啟動[工作進程](#pid)的主進程ID。

`processes`

`respawned`

Суммарное число перезапусков аварийно завершённых дочерних процессов.

異常終止的子程序的重新啟動總數。

`connections`

`accepted`

Суммарное число принятых клиентских соединений.

接受的客戶端連線總數。

`dropped`

Суммарное число отвергнутых клиентских соединений.

被拒絕的客戶端連線總數。

`active`

Текущее число активных клиентских соединений.

當前活動客戶端連線數。

`idle`

Текущее число бездействующих клиентских соединений.

當前空閒客戶端連線數。

`ssl`

`handshakes`

Суммарное число успешных операций SSL handshake.

SSL 握手操作成功總數。

`handshakes_failed`

Суммарное число неуспешных операций SSL handshake.

SSL 握手操作失敗總數。

`session_reuses`

Суммарное число повторных использований SSL-сессий во время операций SSL handshake.

SSL 握手操作期間重複使用SSL 會話的總數。

`requests`

`total`

Суммарное число клиентских запросов.

客戶端請求總數。

`current`

Текущее число клиентских запросов.

當前客戶端請求的數量。

`server_zones`

Для каждой [status\_zone](#status_zone):

對於每個 [status\_zone](#status_zone)：

`processing`

Число обрабатываемых в настоящий момент клиентских запросов.

目前正在處理的客戶端請求數。

`requests`

Суммарное число запросов, полученных от клиентов.

從客戶端收到的請求總數。

`responses`

`total`

Суммарное число ответов, отправленных клиентам.

發送給客戶端的回應總數。

`1xx`, `2xx`, `3xx`, `4xx`, `5xx`

Число ответов со статусами 1xx, 2xx, 3xx, 4xx и 5xx.

狀態為 1xx、2xx、3xx、4xx 和 5xx 的回應數。

`discarded`

Суммарное число запросов, завершившихся без отправки ответа.

已完成但未發送回應的請求總數。

`received`

Суммарное число байт, полученных от клиентов.

從客戶端接收的總位元組數。

`sent`

Суммарное число байт, отправленных клиентам.

發送到客戶端的總位元組數。

`slabs`

Для каждой зоны разделяемой памяти, в которой используется распределение slab:

對於每個使用slab分配的共享記憶體區域：

`pages`

`used`

Текущее число занятых страниц памяти.

目前佔用的記憶體頁數。

`free`

Текущее число свободных страниц памяти.

目前空閒記憶體頁數。

`slots`

Для каждого размера слота памяти (8, 16, 32, 64, 128 и т.д.) доступны следующие данные:

對於每個記憶體插槽大小（8、16、32、64、128 等），可以使用以下資料：

`used`

Текущее число занятых слотов памяти.

目前佔用的記憶體插槽數。

`free`

Текущее число свободных слотов памяти.

目前可用記憶體插槽的數量。

`reqs`

Суммарное число попыток выделения памяти указанного размера.

嘗試分配指定大小的記憶體的總數。

`fails`

Число неудачных попыток выделения памяти указанного размера.

嘗試分配指定大小的記憶體失敗的次數。

`upstreams`

Для каждой [динамически настраиваемой](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>) [группы](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#upstream>) доступны следующие данные:

對於每個[動態配置](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>)[群組](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#upstream>)，以下資料可用：

`peers`

Для каждого [сервера](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) доступны следующие данные:

對於每個[伺服器](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>)，以下資料可用：

`id`

Идентификатор сервера.

伺服器 ID。

`server`

[Адрес](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) сервера.

[地址](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>)伺服器。

`name`

Имя сервера, указанное в директиве [server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>).

[server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>)指令中指定的伺服器名稱。

`service`

Значение параметра [service](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>) директивы [server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>).

[server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) 指令的 [service](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>) 參數的值。

`backup`

Логическое значение, означающее, является ли сервер [запасным](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#backup>).

一個布林值，指示伺服器是否是[備用](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#backup>)。

`weight`

[Вес](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#weight>) сервера.

[重量](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#weight>)伺服器。

`state`

Текущее состояние, которое может быть одним из “`up`”, “`draining`”, “`down`”, “`unavail`”, “`checking`” или “`unhealthy`”.

目前狀態，可以是「`up`」、「`draining`」、「`down`」、「`unavail`」、「`checking`」或「`unhealthy`」之一。

`active`

Текущее число активных соединений.

目前活動連線數。

`max_conns`

Ограничение [max\_conns](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_conns>) для сервера.

伺服器限制 [max\_conns](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_conns>)。

`requests`

Суммарное число клиентских запросов, перенаправленных на этот сервер.

轉送至此伺服器的客戶端請求總數。

`responses`

`total`

Суммарное число ответов, полученных от этого сервера.

從該伺服器收到的回應總數。

`1xx`, `2xx`, `3xx`, `4xx`, `5xx`

Число ответов со статусами 1xx, 2xx, 3xx, 4xx и 5xx.

狀態為 1xx、2xx、3xx、4xx 和 5xx 的回應數。

`sent`

Суммарное число байт, отправленных на этот сервер.

發送到該伺服器的總位元組數。

`received`

Суммарное число байт, полученных с этого сервера.

從該伺服器接收的總位元組數。

`fails`

Суммарное число неудачных попыток работы с этим сервером.

嘗試使用此伺服器失敗的總數。

`unavail`

Количество раз, когда сервер становился недоступным для клиентских запросов (состояние “`unavail`”) из-за достижения порогового числа неудачных попыток [max\_fails](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_fails>).

由於達到 [max\_fails](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#max_fails>) 閾值，伺服器無法處理客戶端請求（狀態「`unavail`」）的次數。

`health_checks`

`checks`

Суммарное число запросов [проверки работоспособности](<265 [02.01.01 http] ngx_http_upstream_hc_module 模組.md#health_check>).

[健康檢查請求總數](<265 [02.01.01 http] ngx_http_upstream_hc_module 模組.md#health_check>)。

`fails`

Число неудачных проверок работоспособности.

失敗的健康檢查數量。

`unhealthy`

Количество раз, когда сервер становился неработоспособным (состояние “`unhealthy`”).

伺服器變成不可用的次數（狀態「`unhealthy`」）。

`last_passed`

Логическое значение, означающее, была ли последняя проверка работоспособности удачной и удовлетворял ли ответ заданным [тестам](<265 [02.01.01 http] ngx_http_upstream_hc_module 模組.md#match>).

一個布林值，指示上次健全性檢查是否成功以及回應是否滿足指定的 [tests](<265 [02.01.01 http] ngx_http_upstream_hc_module 模組.md#match>)。

`downtime`

Суммарное время, когда сервер находился в состояниях “`unavail`”, “`checking`” и “`unhealthy`”.

伺服器處於「`unavail`」、「`checking`」和「`unhealthy`」狀態的總時間。

`downstart`

Время (в миллисекундах с начала эпохи), когда сервер стал “`unavail`”, “`checking`” или “`unhealthy`”.

伺服器變成「`unavail`」、「`checking`」或「`unhealthy`」的時間（自紀元起以毫秒為單位）。

`selected`

Время (в миллисекундах с начала эпохи), когда сервер в последний раз был выбран для обработки запроса (1.7.5).

最後選擇伺服器處理請求的時間（自紀元以來的毫秒數）(1.7.5)。

`header_time`

Среднее время получения [заголовка ответа](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#var_upstream_header_time>) от сервера (1.7.10). До версии 1.11.6 поле было доступно только при использовании метода балансировки [least\_time](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#least_time>).

從伺服器接收[回應標頭](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#var_upstream_header_time>)的平均時間 (1.7.10)。在版本 1.11.6 之前，此欄位僅在使用 [least\_time](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#least_time>) 平衡方法時可用。

`response_time`

Среднее время получения [всего ответа](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#var_upstream_response_time>) от сервера (1.7.10). До версии 1.11.6 поле было доступно только при использовании метода балансировки [least\_time](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#least_time>).

從伺服器接收[總回應](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#var_upstream_response_time>)的平均時間 (1.7.10)。在版本 1.11.6 之前，此欄位僅在使用 [least\_time](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#least_time>) 平衡方法時可用。

`keepalive`

Текущее число бездействующих [keepalive](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#keepalive>)\-соединений.

目前空閒[keepalive](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#keepalive>)\-連接數。

`zombies`

Текущее число серверов, удалённых из группы, но всё ещё обрабатывающих активные клиентские запросы.

目前已從群組中刪除但仍在處理活動用戶端請求的伺服器數量。

`zone`

Имя [зоны](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>) разделяемой памяти, в которой хранятся конфигурация группы и её рабочее состояние.

儲存組配置及其操作狀態的 [zone](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#zone>) 共享記憶體的名稱。

`queue`

Для [очереди](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#queue>) запросов доступны следующие данные:

以下數據可用於 [queue](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#queue>) 請求：

`size`

Текущее число запросов в очереди.

隊列中目前的請求數。

`max_size`

Максимальное число запросов, которые могут одновременно находиться в очереди.

可以同時排隊的最大請求數。

`overflows`

Суммарное число запросов, отклонённых из-за переполнения очереди.

由於佇列溢出而被拒絕的請求總數。

`caches`

Для каждого кэша, сконфигурированного при помощи [proxy\_cache\_path](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_path>) и аналогичных директив:

對於配置了 [proxy\_cache\_path](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_path>) 和類似指令的每個快取：

`size`

Текущий размер кэша.

目前緩存大小。

`max_size`

Ограничение на максимальный размер кэша, заданное в конфигурации.

配置中指定的最大快取大小的限制。

`cold`

Логическое значение, указывающее, продолжается ли загрузка данных процессом “cache loader” с диска в кэш.

一個布林值，指示快取載入器進程是否繼續將資料從磁碟載入到快取中。

`hit`, `stale`, `updating`, `revalidated`

`responses`

Суммарное число ответов, прочитанных из кэша (попадания в кэш или просроченные ответы вследствие [proxy\_cache\_use\_stale](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_use_stale>) и аналогичных директив).

從快取讀取的總回應數（由於 [proxy\_cache\_use\_stale](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_use_stale>) 和類似指令而導致快取命中或過期回應）。

`bytes`

Суммарное число байт, прочитанных из кэша.

從快取中讀取的總位元組數。

`miss`, `expired`, `bypass`

`responses`

Суммарное число ответов, взятых не из кэша (`miss` — отсутствие данных в кэше, `expired` — просроченные ответы, `bypass` — ответ не был взят из кэша вследствие [proxy\_cache\_bypass](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_bypass>) и аналогичных директив).

未從快取中取得的總回應數（`miss` - 快取中沒有數據，`expired` - 過期回應，`bypass` - 由於 [proxy\_cache\_bypass](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_bypass>) 和類似指令而未從快取中取得回應）。

`bytes`

Суммарное число байт, прочитанных с проксируемого сервера.

從代理伺服器讀取的總位元組數。

`responses_written`

Суммарное число ответов, записанных в кэш.

寫入快取的回應總數。

`bytes_written`

Суммарное число байт, записанных в кэш.

寫入快取的總位元組數。

`stream`

`server_zones`

Для каждой [status\_zone](#status_zone):

對於每個 [status\_zone](#status_zone)：

`processing`

Число обрабатываемых в настоящий момент клиентских соединений.

目前正在處理的客戶端連線數。

`connections`

Суммарное число соединений, полученных от клиентов.

從客戶端收到的連線總數。

`sessions`

`total`

Суммарное число завершённых клиентских сессий.

已完成的客戶端會話總數。

`2xx`, `4xx`, `5xx`

Число завершённых сессий со [статусами](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#var_status>) 2xx, 4xx или 5xx.

[狀態](<297 [02.01.04 溪流] ngx_stream_core_module 模組.md#var_status>) 2xx、4xx 或 5xx 的已完成會話數。

`discarded`

Суммарное число соединений, завершённых без создания сессии.

未建立會話時已完成的連線總數。

`received`

Суммарное число байт, полученных от клиентов.

從客戶端接收的總位元組數。

`sent`

Суммарное число байт, отправленных клиентам.

發送到客戶端的總位元組數。

`upstreams`

Для каждого [сервера](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>) в [динамически настраиваемой](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>) [группе](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#upstream>) доступны следующие данные:

對於[動態配置](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>)[群組](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#upstream>)中的每個[伺服器](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)，以下資料可用：

`id`

Идентификатор сервера.

伺服器 ID。

`server`

[Адрес](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>) сервера.

[地址](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)伺服器。

`name`

Имя сервера, указанное в директиве [server](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>).

[server](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#server>)指令中指定的伺服器名稱。

`service`

Значение параметра [service](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>) директивы [server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>).

[server](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#server>) 指令的 [service](<266 [02.01.01 http] ngx_http_upstream_module 模組.md#service>) 參數的值。

`backup`

Логическое значение, означающее, является ли сервер [запасным](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#backup>).

一個布林值，指示伺服器是否是[備用](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#backup>)。

`weight`

[Вес](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#weight>) сервера.

[重量](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#weight>)伺服器。

`state`

Текущее состояние, которое может быть одним из “`up`”, “`down`”, “`unavail`”, “`checking`” или “`unhealthy`”.

當前狀態，可以是「`up`」、「`down`」、「`unavail`」、「`checking`」或「`unhealthy`」之一。

`active`

Текущее число соединений.

目前連接數。

`max_conns`

Ограничение [max\_conns](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_conns>) для сервера.

伺服器限制 [max\_conns](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_conns>)。

`connections`

Суммарное число клиентских соединений, перенаправленных на этот сервер.

重定向到此伺服器的用戶端連線總數。

`connect_time`

Среднее время установки соединения с сервером группы. До версии 1.11.6 поле было доступно только при использовании метода балансировки [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>).

與群組伺服器建立連線的平均時間。在版本 1.11.6 之前，此欄位僅在使用 [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>) 平衡方法時可用。

`first_byte_time`

Среднее время получения первого байта данных. До версии 1.11.6 поле было доступно только при использовании метода балансировки [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>).

接收資料第一個位元組的平均時間。在版本 1.11.6 之前，此欄位僅在使用 [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>) 平衡方法時可用。

`response_time`

Среднее время получения последнего байта данных. До версии 1.11.6 поле было доступно только при использовании метода балансировки [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>).

接收最後一個資料位元組的平均時間。在版本 1.11.6 之前，此欄位僅在使用 [least\_time](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#least_time>) 平衡方法時可用。

`sent`

Суммарное число байт, отправленных на этот сервер.

發送到該伺服器的總位元組數。

`received`

Суммарное число байт, полученных с этого сервера.

從該伺服器接收到的總位元組數。

`fails`

Суммарное число неудачных попыток работы с этим сервером.

連線此伺服器失敗的總次數。

`unavail`

Количество раз, когда сервер становился недоступным для клиентских соединений (состояние “`unavail`”) из-за достижения порогового числа неудачных попыток [max\_fails](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_fails>).

由於達到 [max\_fails 閾值](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#max_fails>)次失敗嘗試，伺服器無法對客戶端連線（狀態「 `unavail` 」）的次數。

`health_checks`

`checks`

Суммарное число запросов [проверки работоспособности](<315 [02.01.04 溪流] 模組 ngx_stream_upstream_hc_module.md#health_check>).

[健康檢查請求總數](<315 [02.01.04 溪流] 模組 ngx_stream_upstream_hc_module.md#health_check>) 。

`fails`

Число неудачных проверок работоспособности.

健康檢查不合格次數。

`unhealthy`

Количество раз, когда сервер становился неработоспособным (состояние “`unhealthy`”).

伺服器不可用（狀態「 `unhealthy` 」）的次數。

`last_passed`

Логическое значение, означающее, была ли последняя проверка работоспособности удачной и удовлетворял ли ответ заданным [тестам](<315 [02.01.04 溪流] 模組 ngx_stream_upstream_hc_module.md#match>).

一個布林值，表示最後一次健全性檢查是否成功，以及回應是否滿足給定的[測試](<315 [02.01.04 溪流] 模組 ngx_stream_upstream_hc_module.md#match>) 。

`downtime`

Суммарное время, когда сервер находился в состояниях “`unavail`”, “`checking`” и “`unhealthy`”.

伺服器處於「 `unavail` 」、「 `checking` 」和「 `unhealthy` 」狀態的總時間。

`downstart`

Время (в миллисекундах с начала эпохи), когда сервер стал “`unavail`”, “`checking`” или “`unhealthy`”.

伺服器變成「 `unavail` 」、「 `checking` 」或「 `unhealthy` 」的時間（自紀元以來的毫秒數）。

`selected`

Время (в миллисекундах с начала эпохи), когда сервер в последний раз был выбран для обработки соединения.

伺服器上次被選中處理連線的時間（自紀元以來的毫秒數）。

`zombies`

Текущее число серверов, удалённых из группы, но всё ещё обрабатывающих активные клиентские соединения.

目前已從群組中移除但仍在處理活躍用戶端連線的伺服器數量。

`zone`

Имя [зоны](<316 [02.01.04 溪流] 模組 ngx_stream_upstream_module.md#zone>) разделяемой памяти, в которой хранятся конфигурация группы и её рабочее состояние.
