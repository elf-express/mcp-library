# Module ngx_http_auth_request_module｜模組 ngx_http_auth_request_module

> 章節：[en｜在](<000 目錄.md#c-1>) › [docs｜文件](<000 目錄.md#c-2>) › [http](<000 目錄.md#c-5>)

## Module ngx\_http\_auth\_request\_module｜模組 ngx_http_auth_request_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [auth\_request](#auth_request)<br>     [auth\_request\_set](#auth_request_set)<br>[範例配置](#example)<br> [指令](#directives)<br> [auth\_request](#auth_request)<br> [auth\_request\_set](#auth_request_set) |

The `ngx_http_auth_request_module` module (1.5.4+) implements client authorization based on the result of a subrequest. If the subrequest returns a 2xx response code, the access is allowed. If it returns 401 or 403, the access is denied with the corresponding error code. Any other response code returned by the subrequest is considered an error.

`ngx_http_auth_request_module`模組（ 1.5.4 +）基於子請求的結果實現客戶端授權。如果子請求傳回 2xx 回應代碼，則允許存取。如果傳回 401 或 403，則拒絕存取並傳回對應的錯誤代碼。子請求返回的任何其他回應代碼均視為錯誤。

For the 401 error, the client also receives the “WWW-Authenticate”（WWW-驗證） header from the subrequest response.

對於 401 錯誤，客戶端也會從子請求回應中收到“WWW-Authenticate”（WWW-驗證）標頭。

This module is not built by default, it should be enabled with the `--with-http_auth_request_module` configuration parameter.

此模組預設未構建，應使用`--with-http_auth_request_module`配置參數啟用。

The module may be combined with other access modules, such as [ngx\_http\_access\_module](<045 [01.01.03 http] 模組 ngx_http_access_module.md>), [ngx\_http\_auth\_basic\_module](<049 [01.01.03 http] 模組 ngx_http_auth_basic_module.md>), and [ngx\_http\_auth\_jwt\_module](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>), via the [satisfy](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>) directive.

此模組可與其他存取模組組合使用，例如 [ngx\_http\_access\_module](<045 [01.01.03 http] 模組 ngx_http_access_module.md>), [ngx\_http\_auth\_basic\_module](<049 [01.01.03 http] 模組 ngx_http_auth_basic_module.md>)以及 [ngx\_http\_auth\_jwt\_module](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md>)透過 [滿足](<056 [01.01.03 http] 模組 ngx_http_core_module.md#satisfy>) 指示。

> Before version 1.7.3, responses to authorization subrequests could not be cached (using [proxy\_cache](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache>), [proxy\_store](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_store>), etc.).
>
> 在版本1.7.3之前，無法快取授權子請求的回應（使用 [proxy\_cache](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache>) 、 [proxy\_store](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_store>)等）。

#### Example Configuration｜範例配置

> ```
> location /private/ {
>     auth_request /auth;
>     ...
> }
> 
> location = /auth {
>     proxy_pass ...
>     proxy_pass_request_body off;
>
>     proxy_pass_request_body 關閉；
>     proxy_set_header Content-Length "";
>     proxy_set_header X-Original-URI $request_uri;
>
>     proxy_set_header X-Original- URI $request_uri;
> }
> ```

Enables authorization based on the result of a subrequest and sets the URI to which the subrequest will be sent.

啟用基於子請求結果的授權，並設定將要傳送子請求的URI 。

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**auth_request_set** `*$variable*` `*value*`;``<br>` `**auth_request_set** ` *$變數* ` ` *值* `;` ` |
| Default:<br>預設值： | — |
| Context:<br>背景： | `http`, `server`, `location` |

Sets the request `*variable*` to the given `*value*` after the authorization request completes. The value may contain variables from the authorization request, such as `$upstream_http_*`.

在授權請求完成後，將請求`*variable*`設定為給定的`*value*` 。該值可能包含來自授權請求的變量，例如`$upstream_http_*` 。
