Модуль `ngx_http_v2_module` (1.9.5) обеспечивает поддержку [HTTP/2](https://datatracker.ietf.org/doc/html/rfc7540).

`ngx_http_v2_module` ( 1.9.5 ) 模組為 [HTTP /2](https://datatracker.ietf.org/doc/html/rfc7540)提供支援。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_v2_module`.

此模組預設未構建，必須使用`--with-http_v2_module`配置參數啟用。

#### Известные проблемы｜已知問題

До версии 1.9.14 буферизация тела запроса клиента не могла быть запрещена независимо от значения директив [proxy\_request\_buffering](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_request_buffering>), [fastcgi\_request\_buffering](<225 [02.01.01 http] ngx_http_fastcgi_module 模組.md#fastcgi_request_buffering>), [uwsgi\_request\_buffering](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_request_buffering>) и [scgi\_request\_buffering](<254 [02.01.01 http] 模組 ngx_http_scgi_module.md#scgi_request_buffering>).

在版本 1.9.14 之前，無論 [proxy\_request\_buffering](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_request_buffering>)、[fastcgi\_request\_buffering](<225 [02.01.01 http] ngx_http_fastcgi_module 模組.md#fastcgi_request_buffering>)、[uwsgi\_request\_buffering](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_request_buffering>)的值如何，都無法停用客戶端請求正文緩衝[scgi\_request\_buffering](<254 [02.01.01 http] 模組 ngx_http_scgi_module.md#scgi_request_buffering>)。

До версии 1.19.1 механизм [lingering\_close](<221 [02.01.01 http] 模組 ngx_http_core_module.md#lingering_close>) не использовался в управлении закрытием HTTP/2-соединений.

在版本1.19.1之前，[lingering\_close 機制](<221 [02.01.01 http] 模組 ngx_http_core_module.md#lingering_close>)未用於HTTP關閉控制。

#### Пример конфигурации｜配置範例

> ```
> server {
>
> 伺服器{
>     listen 443 ssl;
>
>     監聽 443 ssl；
> 
>     http2 on;
>
>     http2 已開啟；
> 
>     ssl_certificate server.crt;
>     ssl_certificate_key server.key;
> }
> ```

Чтобы принимать HTTP/2-соединения по TLS, необходимо наличие поддержки расширения “Application-Layer Protocol Negotiation”（應用層協定協商） (ALPN) протокола TLS, появившейся в [OpenSSL](http://www.openssl.org/) версии 1.0.2.

接受透過 TLS 建立的 HTTP/2 連線需要支援 TLS 協定的“Application-Layer Protocol Negotiation”（應用層協定協商） (ALPN) 擴展，該擴展是在 [OpenSSL](http://www.openssl.org/)版本 1.0.2 中引入的。

Если директива [ssl\_prefer\_server\_ciphers](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_prefer_server_ciphers>) установлена в значение “`on`”, [шифры](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_ciphers>) должны быть настроены таким образом, чтобы соответствовать чёрному списку [RFC 9113, Appendix A](https://datatracker.ietf.org/doc/html/rfc9113#appendix-A), а также поддерживаться клиентами.

如果 [ssl\_prefer\_server\_ciphers](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_prefer_server_ciphers>)指令設定為“ `on` ”，則 [ciphers](<260 [02.01.01 http] 模組 ngx_http_ssl_module.md#ssl_ciphers>)必須配置為符合 [RFC 9113，附錄 A](https://datatracker.ietf.org/doc/html/rfc9113#appendix-A)

指定響應體將被拆分成的最大部分大小。將此值設定得太小可能會導致開銷增加。將此值設定太大可能會因為 [佇列阻塞](http://en.wikipedia.org/wiki/Head-of-line_blocking)而對優先權產生負面影響。

Задаёт максимальное число запросов (включая [push](#http2_push)\-запросы), которые можно сделать по одному соединению HTTP/2, после чего очередной клиентский запрос приведёт к закрытию соединения и необходимости установить новое соединение.

指定單一HTTP /2 連線可以發出的最大請求數（包括 [push](#http2_push)請求），之後下一個客戶端請求將導致連線關閉，並且必須建立新連線。

Периодическое закрытие соединений необходимо для освобождения памяти, выделенной под конкретные соединения. Поэтому использование слишком большого максимального числа запросов может приводить к чрезмерному потреблению памяти и не рекомендуется.

定期關閉連接對於釋放分配給特定連接的記憶體是必要的。因此，將最大請求數設定過高會導致記憶體消耗過大，不建議這樣做。
