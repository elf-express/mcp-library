## Module ngx\_http\_slice\_module｜模組 ngx\_http\_slice\_module

The `ngx_http_slice_module` module (1.9.8) is a filter that splits a request into subrequests, each returning a certain range of response. The filter provides more effective caching of big responses.

`ngx_http_slice_module`模組（ 1.9.8 ）是一個過濾器，它將請求拆分成多個子請求，每個子請求返回特定範圍的回應。此過濾器可以更有效地快取大型響應。

This module is not built by default, it should be enabled with the `--with-http_slice_module` configuration parameter.

此模組預設未構建，應使用`--with-http_slice_module`配置參數啟用。

#### Known Issues｜已知問題

Currently, the module does not work as expected in subrequests such as [background cache update](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache_background_update>). In this case, a request is constructed without byte-range support.

目前，此模組在諸如 [後台快取更新](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache_background_update>)之類的子請求中無法如預期運作。在這種情況下，建置的請求不支援位元組範圍。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點 / {
>     slice             1m;
>
>     切片 1 公尺；
>     proxy_cache       cache;
>
>     proxy_cache 緩存；
>     proxy_cache_key   $uri$is_args$args$slice_range;
>
>     proxy_cache_key $uri$is_args$args$slice_range;
>     proxy_set_header  Range $slice_range;
>
>     proxy_set_header 範圍 $slice_range;
>     proxy_cache_valid 200 206 1h;
>     proxy_pass        http://localhost:8000;
>
>     proxy_pass http://localhost:8000;
> }
> ```

In this example, the response is split into 1-megabyte cacheable slices.

在這個例子中，回應被分成 1 兆位元組的可緩存切片。

Sets the `*size*` of the slice. The zero value disables splitting responses into slices. Note that a too low value may result in excessive memory usage and opening a large number of files.

設定切片的`*size*`值。值為零時禁用將回應拆分為切片。請注意，值過低可能會導致記憶體使用過多並開啟大量檔案。

In order for a subrequest to return the required range, the `$slice_range` variable should be [passed](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_set_header>) to the proxied server as the `Range` request header field. If [caching](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache>) is enabled, `$slice_range` should be added to the [cache key](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache_key>) and caching of responses with 206 status code should be [enabled](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache_valid>).

為了使子請求傳回所需的範圍，應將`$slice_range`變數作為(https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)請求頭字段傳遞給代理伺服器。如果啟用了 [ (https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_cache) `Range`則應將`$slice_range`新增至 [快取鍵](<085 [01.01.03 http] 模組 ngx_http_proxy_module.md#proxy_cache_key>) ，並啟用狀態碼為 206 的回應的(https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_cache_valid) 。

#### Embedded Variables｜嵌入變數

The `ngx_http_slice_module` module supports the following embedded variables:

`ngx_http_slice_module`模組支援以下嵌入式變數：

`$slice_range`

the current slice range in [HTTP byte range](https://datatracker.ietf.org/doc/html/rfc7233#section-2.1) format, for example, `bytes=0-1048575`.

目前切片範圍採用 [HTTP位元組範圍](https://datatracker.ietf.org/doc/html/rfc7233#section-2.1)格式，例如`bytes=0-1048575` 。
