## Модуль ngx\_http\_slice\_module｜模組 ngx\_http\_slice\_module

Модуль `ngx_http_slice_module` (1.9.8) — это фильтр, который разбивает запрос на подзапросы, каждый из которых возвращает определённый диапазон ответа. Фильтр обеспечивает более эффективное кэширование больших ответов.

模組`ngx_http_slice_module`（1.9.8）是一個過濾器，它將請求拆分為子查詢，每個子查詢返回特定的回應範圍。此過濾器可以更有效地快取大型響應。

По умолчанию этот модуль не собирается, его сборку необходимо разрешить с помощью конфигурационного параметра `--with-http_slice_module`.

此模組預設未構建，必須使用`--with-http_slice_module`配置參數啟用。

#### Известные проблемы｜已知問題

В настоящий момент модуль не работает как ожидается с подзапросами, например [фоновым обновлением кэша](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_background_update>). В этом случае построение запроса происходит без указания диапазона байт.

此模組目前無法如預期使用[後台快取刷新](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_background_update>)等子查詢。在這種情況下，建置查詢時沒有指定位元組範圍。

#### Пример конфигурации｜配置範例

> ```
> location / {
>
> 地點 / {
>     slice             1m;
>
>     切片1m；
>     proxy_cache       cache;
>
>     代理緩存；
>     proxy_cache_key   $uri$is_args$args$slice_range;
>
>     proxy_cache_key $uri$is_args$args$slice_range;
>     proxy_set_header  Range $slice_range;
>
>     proxy_set_header 範圍 $slice_range;
>     proxy_cache_valid 200 206 1h;
>
>     proxy_cache_valid 200 206 1h；
>     proxy_pass        http://localhost:8000;
>
>     proxy_pass http://localhost:8000;
> }
> ```

В данном примере ответ разбивается на кэшируемые фрагменты размером в 1 мегабайт.

在此範例中，回應被分成大小為 1 MB 的可快取片段。

Задаёт `*размер*` фрагмента. Нулевое значение запрещает разбиение ответов на фрагменты. Обратите внимание, что слишком низкое значение может привести к излишнему потреблению памяти и открытию большого количества файлов.

設定片段的`*размер*`。值為零會停用將回應拆分為片段。請注意，將該值設定得太低可能會導致不必要的記憶體消耗和開啟大量檔案。

Для того, чтобы подзапрос вернул необходимый диапазон, переменная `$slice_range` должна быть [передана](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_set_header>) на проксируемый сервер в качестве поля `Range` заголовка запроса. Если включено [кэширование](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache>), то необходимо добавить `$slice_range` в [ключ кэширования](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_key>) и [включить](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_valid>) кэширование ответов с кодом 206.

為了讓子查詢回傳所需的範圍，變數`$slice_range`必須作為`Range`請求頭字段[傳遞](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_set_header>)到代理伺服器。如果啟用了[快取](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache>)，則需要將`$slice_range`加入到[快取鍵](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_key>)並使用代碼206新增[啟用](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_cache_valid>)回應快取。

#### Встроенные переменные｜內建變數

Модуль `ngx_http_slice_module` поддерживает следующие встроенные переменные:

`ngx_http_slice_module`模組支援以下內建變數：

`$slice_range`

текущий диапазон фрагмента в формате [HTTP byte range](https://datatracker.ietf.org/doc/html/rfc7233#section-2.1), например `bytes=0-1048575`.

目前片段範圍，格式為[HTTP位元組範圍](https://datatracker.ietf.org/doc/html/rfc7233#section-2.1)，例如`bytes=0-1048575`。
