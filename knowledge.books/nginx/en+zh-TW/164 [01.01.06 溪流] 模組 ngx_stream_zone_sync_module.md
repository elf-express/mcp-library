The `ngx_stream_zone_sync_module` module (1.13.8) provides the necessary support for synchronizing contents of [shared memory zones](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#zone>) between nodes of a cluster. To enable synchronization for a particular zone, a corresponding module must support this feature. Currently, it is possible to synchronize HTTP [sticky](<105 [01.01.03 http] 模組 ngx_http_upstream_module.md#sticky>) sessions, information about [excessive HTTP requests](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>), and key-value pairs both in [http](<074 [01.01.03 http] 模組 ngx_http_keyval_module.md>) and [stream](<146 [01.01.06 溪流] 模組 ngx_stream_keyval_module.md>).

`ngx_stream_zone_sync_module`模組 ( 1.13.8 ) 為群集節點間 [共享記憶體區域](<163 [01.01.06 溪流] 模組 ngx_stream_upstream_module.md#zone>)內容的同步提供了必要的支援。若要啟用特定區域的同步，對應的模組必須支援此功能。目前，可以同步 [ (https://nginx.org/en/docs/http/ngx_http_upstream_module.html#sticky) ]HTTP會話、[過多請求]HTTP資訊以及 [http](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>)和 [串流](<074 [01.01.03 http] 模組 ngx_http_keyval_module.md>)中的鍵值(https://nginx.org/en/docs/stream/ngx_stream_keyval_module.html) 。

> This module is available as part of our [commercial subscription](https://www.f5.com/products/nginx).
>
> 本模組作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分提供。

#### Example Configuration｜範例配置

Minimal configuration:

最低配置：

> ```
> http {
>     ...
> 
>     upstream backend {
>
>     上游後端 {
>        server backend1.example.com:8080;
>
>        伺服器 backend1.example.com:8080;
>        server backend2.example.com:8081;
>
>        伺服器 backend2.example.com:8081;
> 
>        sticky learn
>
>        黏性學習
>               create=$upstream_cookie_examplecookie
>
>               建立=$upstream_cookie_examplecookie
>               lookup=$cookie_examplecookie
>               zone=client_sessions:1m sync;
>
>               zone=client_sessions:1m 同步;
>     }
> 
>     ...
> }
> 
> stream {
>
> 溪流 {
>     ...
> 
> 
>     server {
>
>     伺服器 {
>         zone_sync;
>
>         區域同步；
> 
>         listen 127.0.0.1:12345;
>
>         聽127.0.0.1:12345 ;
> 
>         # cluster of 2 nodes｜由 2 個節點組成的集群
>         zone_sync_server a.example.com:12345;
>         zone_sync_server b.example.com:12345;
> 
>     }
> ```

A more complex configuration with SSL enabled and with cluster members defined by DNS:

啟用SSL並由DNS定義叢集成員的更複雜配置：

> ```
> ...
> 
> stream {
>
> 溪流 {
>     ...
> 
>     resolver 127.0.0.1 valid=10s;
>
>     解析器127.0.0.1有效期=10秒；
> 
>     server {
>
>     伺服器 {
>         zone_sync;
>
>         區域同步；
> 
>         # the name resolves to multiple addresses that correspond to cluster nodes｜此名稱解析為多個位址，這些位址對應於叢集節點。
>         zone_sync_server cluster.example.com:12345 resolve;
>
>         zone_sync_server cluster.example.com:12345 解析;
> 
>         listen 127.0.0.1:4433 ssl;
>
>         監聽127.0.0.1:4433 ssl;
> 
>         ssl_certificate     localhost.crt;
>
>         ssl_certificate localhost.crt;
>         ssl_certificate_key localhost.key;
> 
>         zone_sync_ssl on;
>
>         zone_sync_ssl 已開啟；
> 
>         zone_sync_ssl_certificate     localhost.crt;
>
>         zone_sync_ssl_certificate localhost.crt;
>         zone_sync_ssl_certificate_key localhost.key;
>     }
> }
> ```

Sets the `*number*` and `*size*` of the per-zone buffers used for pushing zone contents. By default, the buffer size is equal to one memory page. This is either 4K or 8K, depending on a platform.

設定用於推送區域內容的每個區域緩衝區的`*number*`和`*size*`值。預設情況下，緩衝區大小等於一個記憶體頁。根據平台的不同，該值可以是 4K 或 8K。

> A single buffer must be large enough to hold any entry of each zone being synchronized.
>
> 單一緩衝區必須足夠大，能夠容納每個同步區域的任何條目。

Sets `*size*` of a per-connection receive buffer used to parse incoming stream of synchronization messages. The buffer size must be equal or greater than one of the [zone\_sync\_buffers](#zone_sync_buffers). By default, the buffer size is equal to [zone\_sync\_buffers](#zone_sync_buffers) `*size*` multiplied by `*number*`.

設定用於解析傳入同步訊息流的每個連線的接收緩衝區`*size*` 。緩衝區大小必須等於或大於 [zone\_sync\_buffers](#zone_sync_buffers)中的一個值。預設情況下，緩衝區大小等於 [zone\_sync\_buffers](#zone_sync_buffers) `*size*`乘以`*number*` 。

Defines the `*address*` of a cluster node. The address can be specified as a domain name or IP address with a mandatory port, or as a UNIX-domain socket path specified after the “`unix:`” prefix. A domain name that resolves to several IP addresses defines multiple nodes at once.

定義叢集節點的`*address*`位址。該位址可以指定為網域名稱或IP位址（必須包含連接埠），也可以指定為UNIX網域套接字路徑（位於「 `unix:` 」前綴之後）。一個網域名稱如果解析為多個IP位址，則同時定義多個節點。

The `resolve` parameter instructs nginx to monitor changes of the IP addresses that correspond to a domain name of the node and automatically modify the configuration without the need of restarting nginx.

`resolve`參數指示 nginx 監視與節點網域對應的IP位址的變化，並自動修改配置，而無需重新啟動 nginx。

Cluster nodes are specified either dynamically as a single `zone_sync_server` directive with the `resolve` parameter, or statically as a series of several directives without the parameter.

叢集節點既可以動態地指定為具有`resolve`參數的單一`zone_sync_server`指令，也可以靜態地指定為一系列不帶參數的指令。

> Each cluster node should be specified only once.
>
> 每個叢集節點只能指定一次。

> All cluster nodes should use the same configuration.
>
> 所有叢集節點應使用相同的配置。

In order for the `resolve` parameter to work, the [resolver](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>) directive must be specified in the [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#stream>) block. Example:

為了使`resolve`參數生效，必須在 [stream](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#stream>)碼區塊中指定 [resolver](<142 [01.01.06 溪流] 模組 ngx_stream_core_module.md#resolver>)指令。例如：

> ```
> stream {
>
> 溪流 {
>     resolver 10.0.0.1;
>
>     解析器10.0.0.1 ;
> 
>     server {
>
>     伺服器 {
>         zone_sync;
>
>         區域同步；
>         zone_sync_server cluster.example.com:12345 resolve;
>
>         zone_sync_server cluster.example.com:12345 解析;
>         ...
>     }
> }
> ```

#### Starting, stopping, removing a cluster node｜啟動、停止、移除叢集節點

To start a new node, update a DNS record of a cluster hostname with the IP address of the new node and start an instance. The new node will discover other nodes from DNS or static configuration and will start sending updates to them. Other nodes will eventually discover the new node using DNS and start pushing updates to it. In case of static configuration, other nodes need to be reloaded in order to send updates to the new node.

若要啟動新節點，請將叢集主機名稱的DNS記錄更新為新節點的IP位址，然後啟動一個執行個體。新節點將透過DNS或靜態配置發現其他節點，並開始向它們發送更新。其他節點最終將透過DNS發現新節點，並開始向其推送更新。如果是靜態配置，則需要重新載入其他節點才能向新節點發送更新。

To stop a node, send the `QUIT` signal to the instance. The node will finish zone synchronization and gracefully close open connections.

若要停止一個節點，請向該實例發送`QUIT`訊號。節點將完成區域同步並優雅地關閉所有打開的連接。

To remove a node, update a DNS record of a cluster hostname and remove the IP address of the node. All other nodes will eventually discover that the node is removed, close connections to the node, and will no longer try to connect to it. After the node is removed, it can be stopped as described above. In case of static configuration, other nodes need to be reloaded in order to stop sending updates to the removed node.

若要移除節點，請更新叢集主機名稱的DNS記錄，並移除該節點的IP位址。所有其他節點最終都會發現該節點已被移除，並關閉與該節點的連接，且不再嘗試與其連接。節點移除後，即可依上述方法停止該節點。如果是靜態配置，則需要重新載入其他節點，才能停止傳送更新至已移除的節點。
