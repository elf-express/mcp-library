The `ngx_http_proxy_module` module allows passing requests to another server.

`ngx_http_proxy_module`模組允許將請求傳遞給另一個伺服器。

#### Example Configuration｜範例配置

> ```
> location / {
>
> 地點 / {
>     proxy_pass       http://localhost:8000;
>
>     proxy_pass http://localhost:8000;
>     proxy_set_header Host      $host;
>
>     proxy_set_header Host $host;
>     proxy_set_header X-Real-IP $remote_addr;
>
>     proxy_set_header X-Real- IP $remote_addr;
> }
> ```

Defines conditions under which access to a proxied server is allowed or [denied](#denied). If all string parameters are not empty and not equal to “0” then the access is allowed. The conditions are evaluated each time before a connection to a proxied server is established. Parameter values can contain variables:

定義允許或拒絕存取代理伺服器的條件(https://nginx.org/en/docs/http/ngx_http_proxy_module.html#denied) 。如果所有字串參數均不為空且不等於“0”，則允許存取。每次建立與代理伺服器的連線之前都會評估這些條件。參數值可以包含變數：

> ```
> geo $upstream_last_addr $allow {
>     volatile;
>
>     易揮發的;
>     10.10.0.0/24        1;
> }
> 
> server {
>
> 伺服器 {
>     listen 127.0.0.1:8080;
>
>     聽127.0.0.1:8080 ;
> 
>     location / {
>
>     地點 / {
>         proxy_pass           localhost:8000;
>
>         proxy_pass localhost:8000;
>         proxy_allow_upstream $allow;
>         ...
>     }
> }
> ```

Makes outgoing connections to a proxied server originate from the specified local IP address with an optional port (1.11.2). Parameter value can contain variables (1.3.12). The special value `off` (1.3.12) cancels the effect of the `proxy_bind` directive inherited from the previous configuration level, which allows the system to auto-assign the local IP address and port.

使發送至代理伺服器的出站連線源自指定的本機位址IP ，並可選擇指定連接埠（ 1.11.2 ）。參數值可以包含變數（ 1.3.12 ）。特殊值`off` （ 1.3.12 ）會取消從上一配置等級繼承的`proxy_bind`指令的效果，該指令允許系統自動分配本地位址IP和連接埠。

The `transparent` parameter (1.11.0) allows outgoing connections to a proxied server originate from a non-local IP address, for example, from a real IP address of a client:

`transparent`參數 ( 1.11.0 ) 允許到代理伺服器的出站連線源自非本地IP位址，例如，源自客戶端的真實IP位址：

> ```
> proxy_bind $remote_addr transparent;
> ```

In order for this parameter to work, it is usually necessary to run nginx worker processes with the [superuser](<125 [01.01 文件] 核心功能.md#user>) privileges. On Linux it is not required (1.13.8) as if the `transparent` parameter is specified, worker processes inherit the `CAP_NET_RAW` capability from the master process. It is also necessary to configure kernel routing table to intercept network traffic from the proxied server.

為了使此參數生效，通常需要以 [superuser](<125 [01.01 文件] 核心功能.md#user>)權限執行 nginx 工作進程。在 Linux 系統上則無需此權限 ( 1.13.8 )，因為如果指定了`transparent`參數，工作進程會從主進程繼承`CAP_NET_RAW`權限。此外，還需要配置核心路由表以攔截來自代理伺服器的網路流量。

Sets the `*size*` of the buffer used for reading the first part of the response received from the proxied server. This part usually contains a small response header; if it exceeds the buffer size, the response is considered [invalid](#invalid_header). By default, the buffer size is equal to one memory page. This is either 4K or 8K, depending on a platform. It can be made smaller, however.

設定用於讀取從代理伺服器收到的回應第一部分的緩衝區大小`*size*` 。這部分通常包含一個較小的響應頭；如果響應頭大小超過緩衝區大小，則該響應被視為無效（ (https://nginx.org/en/docs/http/ngx_http_proxy_module.html#invalid_header) ）。預設情況下，緩衝區大小等於一個記憶體頁。根據平台的不同，該大小為 4K 或 8K。不過，可以將其減小。

Enables or disables buffering of responses from the proxied server.

啟用或停用代理伺服器回應的緩衝。

When buffering is enabled, nginx receives a response from the proxied server as soon as possible, saving it into the buffers set by the [proxy\_buffer\_size](#proxy_buffer_size) and [proxy\_buffers](#proxy_buffers) directives. If the whole response does not fit into memory, a part of it can be saved to a [temporary file](#proxy_temp_path) on the disk. Writing to temporary files is controlled by the [proxy\_max\_temp\_file\_size](#proxy_max_temp_file_size) and [proxy\_temp\_file\_write\_size](#proxy_temp_file_write_size) directives.

啟用緩衝後，nginx 會盡快從代理伺服器接收回應，並將其儲存到由 `[proxy\_buffer\_size](#proxy_buffer_size)和 `[proxy\_buffers](#proxy_buffers)指令設定的緩衝區中。如果整個回應無法放入內存，則可以將其一部分儲存到磁碟上的暫存檔案 `[temporary file](#proxy_temp_path)中。寫入暫存檔案的操作由 `[proxy\_max\_temp\_file\_size](#proxy_max_temp_file_size)和 `[proxy\_temp\_file\_write\_size](#proxy_temp_file_write_size)指令控制。

When buffering is disabled, the response is passed to a client synchronously, immediately as it is received. nginx will not try to read the whole response from the proxied server. The maximum size of the data that nginx can receive from the server at a time is set by the [proxy\_buffer\_size](#proxy_buffer_size) directive.

停用緩衝後，回應會同步地立即傳遞給客戶端。 nginx 不會嘗試從代理伺服器讀取整個回應。 nginx 一次可以從伺服器接收的最大資料大小由 [proxy\_buffer\_size](#proxy_buffer_size)指令設定。

Buffering can also be enabled or disabled by passing “`yes`” or “`no`” in the “X-Accel-Buffering” response header field. This capability can be disabled using the [proxy\_ignore\_headers](#proxy_ignore_headers) directive.

也可以透過在“X-Accel-Buffering”響應頭字段中傳遞「 `yes` 」或「 `no` 」來啟用或停用緩衝。可以使用 [proxy\_ignore\_headers](#proxy_ignore_headers)指令停用此功能。

啟用代理伺服器回應緩衝功能後，會限制用於向客戶端發送回應的`*size*`總數(https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering) ），直到客戶端完全讀取回應為止。在此期間，其餘緩衝區可用於讀取回應，並在需要時將部分回應緩衝到暫存檔案。預設情況下，緩衝區大小(https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffer_size) `*size*` [proxy_buffers](#proxy_buffers)指令設定的兩個緩衝區大小的限制。

The special “cache manager” process monitors the maximum cache size set by the `max_size` parameter, and the minimum amount of free space set by the `min_free` (1.19.1) parameter on the file system with cache. Sets the text that should be changed in the “Location”（地點） and “Refresh”（重新整理） header fields of a proxied server response. Suppose a proxied server returned the header field “`Location: http://localhost:8000/two/some/uri/`”. The directive

設定代理伺服器回應的“Location”（地點）和“Refresh”（重新整理）標頭欄位中應更改的文字。假設代理伺服器回傳了標頭欄位「 `Location: http://localhost:8000/two/some/uri/` 」。該指令

> ```
> proxy_redirect http://localhost:8000/two/ http://frontend/one/;
> ```

will rewrite this string to “`Location: http://frontend/one/some/uri/`”.

將此字串重寫為“ `Location: http://frontend/one/some/uri/` ”。

A server name may be omitted in the `*replacement*` string:

`*replacement*`字串中可以省略伺服器名稱：

> ```
> proxy_redirect http://localhost:8000/two/ /;
> ```

then the primary server’s name and port, if different from 80, will be inserted.

然後，如果主伺服器的名稱和連接埠不是 80，則會插入該主伺服器的名稱和連接埠。

`default`參數指定的預設替換使用 [location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location>)和 [proxy\_pass](#proxy_pass)指令的參數。因此，以下兩種配置是等效的：

> ```
> location /one/ {
>
> 位置 /one/ {
>     proxy_pass     http://upstream:port/two/;
>
>     proxy_pass http://upstream:port/two/;
>     proxy_redirect default;
>
>     proxy_redirect 預設值；
> ```

> ```
> location /one/ {
>
> 位置 /one/ {
>     proxy_pass     http://upstream:port/two/;
>

>     proxy_redirect http://upstream:port/two/ /one/;
> ```

如果使用變數指定了 [proxy\_pass](#proxy_pass)則不允許使用`default`參數。

A `*replacement*` string can contain variables:

`*replacement*`字串可以包含變數：

> ```
> proxy_redirect http://localhost:8000/ http://$host:$server_port/;
> ```

A `*redirect*` can also contain (1.1.11) variables:

`*redirect*`也可以包含 ( 1.1.11 ) 變數：

> ```
> proxy_redirect http://$proxy_host:8000/ /;
> ```

The directive can be specified (1.1.11) using regular expressions. In this case, `*redirect*` should either start with the “`~`” symbol for a case-sensitive matching, or with the “`~*`” symbols for case-insensitive matching. The regular expression can contain named and positional captures, and `*replacement*` can reference them:

可以使用正規表示式指定指令 ( 1.1.11 )。在這種情況下， `*redirect*`應以「 `~` 」符號開頭以區分大小寫進行匹配，或以「 `~*` 」符號開頭以不區分大小寫進行匹配。正規表示式可以包含命名捕獲和位置捕獲， `*replacement*`可以引用它們：

> ```
> proxy_redirect ~^(http://[^:]+):\d+(/.+)$ $1$2;
>
> proxy_redirect ~^( http://[^: ]+):\d+(/.+)$ $1$2;
> proxy_redirect ~*/user/([^/]+)/(.+)$      http://$1.example.com/$2;
>
> proxy_redirect ~*/user/([^/]+)/(.+)$ http://$1.example.com/$2;
> ```

> ```
> proxy_redirect default;
>

> proxy_redirect http://localhost:8000/  /;
>
> proxy_redirect http://localhost:8000/ /;
> proxy_redirect http://www.example.com/ /;
> ```

If several directives can be applied to the header fields of a proxied server response, the first matching directive will be chosen.

如果多個指令可以套用於代理伺服器回應的標頭字段，則會選擇第一個符合的指令。

`off`參數取消從上一個配置等級繼承的`proxy_redirect`指令的效果。

“X-Forwarded-For”（X-轉發）客戶端請求頭字段，並附加`$remote_addr`變量，兩者之間以逗號分隔。如果客戶端請求頭中不存在“X-Forwarded-For”（X-轉發）字段，則`$proxy_add_x_forwarded_for`變數等於`$remote_addr`變數。
