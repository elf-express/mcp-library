Разрешает или запрещает использование файлового асинхронного ввода-вывода (AIO) во FreeBSD и Linux:

啟用或停用 FreeBSD 和 Linux 上的檔案非同步 I/O ( AIO )：

> ```
> location /video/ {
>     aio            on;
>
>     我打算這樣做；
>     output_buffers 1 64k;
>
>     輸出緩衝區 1 64k；
> }
> ```

Во FreeBSD AIO можно использовать, начиная с FreeBSD 4.3. До FreeBSD 11.0 AIO можно либо собрать в ядре статически:

在 FreeBSD AIO上，您可以從 FreeBSD 4.3開始使用它。在 FreeBSD 11.0 AIO您可以將其靜態編譯到核心中：

> ```
> options VFS_AIO
>
> 選項 VFS_AIO
> ```

либо загрузить динамически через загружаемый модуль ядра:

或透過可載入核心模組動態載入：

> ```
> kldload aio
> ```

В Linux AIO можно использовать только начиная с версии ядра 2.6.22. Кроме того, необходимо также дополнительно включить [directio](#directio), иначе чтение будет блокирующимся:

在 Linux 系統中AIO只能從核心版本2.6.22開始使用。此外，也必須啟用 [directio](#directio) ，否則讀取操作將會阻塞：

> ```
> location /video/ {
>     aio            on;
>
>     我打算這樣做；
>     directio       512;
>
>     方向 512；
>     output_buffers 1 128k;
>
>     輸出緩衝區 1 128k；
> }
> ```

В Linux [directio](#directio) можно использовать только для чтения блоков, выравненных на границу 512 байт (или 4К для XFS). Невыравненный конец файла будет читаться блокированно. То же относится к запросам с указанием диапазона запрашиваемых байт (byte-range requests) и к запросам FLV не с начала файла: чтение невыравненных начала и конца ответа будет блокирующимся.

在 Linux 系統中，[directio](#directio)只能用於讀取以 512 位元組為邊界對齊的資料區塊（ XFS則為 4K）。未對齊的檔案結尾讀取操作將會阻塞。位元組範圍請求和FLV請求（如果不是從檔案開頭開始）也存在同樣的問題：讀取回應中未對齊的開頭和結尾部分將會阻塞。

При одновременном включении AIO и [sendfile](#sendfile) в Linux для файлов, размер которых больше либо равен указанному в директиве [directio](#directio), будет использоваться AIO, а для файлов меньшего размера или при выключенном [directio](#directio) — [sendfile](#sendfile):

在 Linux 上啟用AIO和 [sendfile](#sendfile)時，對於大於或等於 [directio](#directio)指令中指定大小的文件， (https://nginx.org/ru/docs/http/ngx_http_core_module.html#directio)使用AIO ；對於小於此大小的文件，或(https://nginx.org/ru/docs/http/ngx_http_core_module.html#sendfile) ：

> ```
> location /video/ {
>     sendfile       on;
>
>     發送文件已開啟；
>     aio            on;
>
>     我打算這樣做；
>     directio       8m;
>
>     方向 8 公尺；
> }
> ```

Кроме того, читать и [отправлять](#sendfile) файлы можно в многопоточном режиме (1.7.11), не блокируя при этом рабочий процесс:

此外，讀取和[發送](#sendfile)檔案可以在多執行緒模式下完成（ 1.7.11 ），而不會阻塞工作流程：

> ```
> location /video/ {
>     sendfile       on;
>
>     發送文件已開啟；
>     aio            threads;
>
>     aio線程；
> }
> ```

Операции чтения или отправки файлов будут обрабатываться потоками из указанного [пула](<285 [02.01 文件] 基本功能.md#thread_pool>). Если пул потоков не задан явно, используется пул с именем “`default`”. Имя пула может быть задано при помощи переменных:

檔案讀取或上傳操作將由指定的執行緒池 [ (https://nginx.org/ru/docs/ngx_core_module.html#thread_pool) ] 中的執行緒處理。如果未明確指定執行緒池，則使用名為「 `default` 」的執行緒池。可以使用變數指定線程池名稱：

> ```
> aio threads=pool$disk;
>
> aio 線程=pool$disk;
> ```

По умолчанию поддержка многопоточности выключена, её сборку следует разрешить с помощью конфигурационного параметра `--with-threads`. В настоящий момент многопоточность совместима только с методами [epoll](<207 [02.01 文件] 化合物加工方法.md#epoll>), [kqueue](<207 [02.01 文件] 化合物加工方法.md#kqueue>) и [eventport](<207 [02.01 文件] 化合物加工方法.md#eventport>). Отправка файлов в многопоточном режиме поддерживается только на Linux.

預設情況下停用多執行緒支援；必須使用`--with-threads`配置參數啟用。目前，多執行緒僅相容 [epoll](<207 [02.01 文件] 化合物加工方法.md#epoll>) 、[kqueue](<207 [02.01 文件] 化合物加工方法.md#kqueue>)和 [eventport](<207 [02.01 文件] 化合物加工方法.md#eventport>)方法。僅在 Linux 系統上支援以多執行緒模式傳送檔案。

См. также директиву [sendfile](#sendfile).

另請參閱 [sendfile 指令](#sendfile) 。

При включённом [aio](#aio) разрешает его использование для записи файлов. В настоящий момент это работает только при использовании `aio threads` и ограничено записью временных файлов с данными, полученными от проксируемых серверов.

啟用 [aio 後](#aio)允許使用它來寫入檔案。目前，此功能僅在使用`aio threads`時有效，並且僅限於寫入包含從代理伺服器接收的資料的臨時檔案。

Задаёт замену для указанного location’а. Например, при такой конфигурации

指定指定位置的替代方案。例如，使用此配置

> ```
> location /i/ {
>
> 位置 /i/ {
>     alias /data/w3/images/;
>
>     別名 /data/w3/images/;
> }
> ```

на запрос “`/i/top.gif`” будет отдан файл `/data/w3/images/top.gif`.

回應請求“ `/i/top.gif` ”，將返回檔案`/data/w3/images/top.gif` 。

В значении параметра `*путь*` можно использовать переменные, кроме `$document_root` и `$realpath_root`.

參數`*путь*`的值可以使用`$document_root`和`$realpath_root`之外的變數。

Если `alias` используется внутри location’а, заданного регулярным выражением, то его значение задаёт полный путь к файлу (0.7.40). Как правило, в таком пути следует использовать выделения, содержащиеся в регулярном выражении:

當`alias`用於正規表示式指定的位置時，其值指定檔案的完整路徑 ( 0.7.40 )。通常，這樣的路徑應該使用正規表示式中包含的捕獲規則：

> ```
> location ~ ^/users/(.+\.(?:gif|jpe?g|png))$ {
>     alias /data/w3/images/$1;
>
>     別名 /data/w3/images/$1;
> }
> ```

Если `alias` используется внутри предикатного location’а, то его значение задаёт полный путь к файлу.

當`alias`在謂詞位置中使用時，其值指定檔案的完整路徑。

Если location и последняя часть значения директивы совпадают:

如果位置和指令值的最後一部分相符：

> ```
> location /images/ {
>     alias /data/w3/images/;
>
>     別名 /data/w3/images/;
> }
> ```

то лучше воспользоваться директивой [root](#root):

那麼最好使用 [root](#root)指令：

> ```
> location /images/ {
>     root /data/w3;
>
>     根 /data/w3;
> }
> ```

`on`

Если любой компонент пути является символической ссылкой, доступ к файлу запрещается.

如果路徑中的任何組成部分是符號鏈接，則拒絕存取該檔案。

`if_not_owner`

Доступ к файлу запрещается, если любой компонент пути является символической ссылкой, а ссылка и объект, на который она ссылается, имеют разных владельцев.

如果路徑中的任何組成部分是符號鏈接，並且該鏈接和它所指向的對象具有不同的所有者，則拒絕訪問該文件。

`from`\=`*часть*`

При проверке символических ссылок (параметры `on` и `if_not_owner`) обычно проверяются все компоненты пути. Можно не проверять символические ссылки в начальной части пути, указав дополнительно параметр `from`\=`*часть*`. В этом случае символические ссылки проверяются лишь начиная с компонента пути, который следует за заданной начальной частью. Если значение не является начальной частью проверяемого пути, путь проверяется целиком, как если бы этот параметр не был указан вовсе. Если значение целиком совпадает с именем файла, символические ссылки не проверяются. В значении параметра можно использовать переменные.

檢查符號連結（參數`on`和`if_not_owner` ）時，通常會檢查所有路徑組件。您可以透過指定附加參數`from` \= `*часть*`來選擇不檢查路徑開頭的符號連結。在這種情況下，只會檢查指定起始部分之後的路徑組件中的符號連結。如果該值不是要檢查的路徑的開頭，則會檢查整個路徑，就像未指定此參數一樣。如果該值與整個檔案名稱匹配，則不會檢查符號連結。參數值中可以使用變數。

> ```

Задаёт максимальное `*число*` и `*размер*` буферов для чтения большого заголовка запроса клиента. Строка запроса не должна превышать размера одного буфера, иначе клиенту возвращается ошибка 414 (Request-URI Too Large). Поле заголовка запроса также не должно превышать размера одного буфера, иначе клиенту возвращается ошибка 400 (Bad Request). Буферы выделяются только по мере необходимости. По умолчанию размер одного буфера равен 8K байт. Если по окончании обработки запроса соединение переходит в состояние keep-alive, эти буферы освобождаются.

設定用於讀取大型客戶端請求頭的最大緩衝區大小`*число*`和`*размер*` 。請求行的大小不得超過一個緩衝區的大小，否則將向客戶端傳回 414（請求過大）錯誤URI ）。請求頭字段的大小也不得超過一個緩衝區的大小，否則將向客戶端傳回 400（錯誤請求）錯誤。緩衝區僅在需要時分配。預設情況下，緩衝區大小為 8KB。如果請求處理完成後連線進入保持活動狀態，則這些緩衝區將會被釋放。

Ограничения схожим образом применяются в соединениях HTTP/2 и HTTP/3. Размер одного буфера ограничивает максимальный размер поля заголовка запроса, сжатого соответственно при помощи [HPACK](https://datatracker.ietf.org/doc/html/rfc7541) или [QPACK](https://datatracker.ietf.org/doc/html/rfc9204). Следует учитывать, что при применении кодирования Хаффмана фактический размер распакованных строк имени и значения может быть больше. Ограничение на максимальный размер всего заголовка запроса применяется после распаковки.

限制同樣適用於HTTP /2 和HTTP /3 連接。單一緩衝區的大小限制了分別使用 [HPACK](https://datatracker.ietf.org/doc/html/rfc7541)或 [QPACK](https://datatracker.ietf.org/doc/html/rfc9204)壓縮的請求頭字段的最大長度。請注意，使用霍夫曼編碼時，解壓縮後的名稱和值字串的實際長度可能會更大。整個請求頭的最大長度限制是在解壓縮後應用的。

Со значением по умолчанию “`on`” nginx будет [ждать](#lingering_timeout) и [обрабатывать](#lingering_time) дополнительные данные, поступающие от клиента, перед полным закрытием соединения, но только если эвристика указывает на то, что клиент может ещё послать данные.

值「 `always` 」表示nginx將始終等待並處理來自客戶端的附加資料。

Со значением “`off`” nginx не будет ждать поступления дополнительных данных и сразу же закроет соединение. Это поведение нарушает протокол и поэтому не должно использоваться без необходимости.

如果值為“ `off` nginx 將不會等待更多數據，而是立即關閉連線。這種行為違反了協議，因此除非絕對必要，否則不應使用。

Если действует [lingering\_close](#lingering_close), эта директива задаёт максимальное время ожидания поступления дополнительных данных от клиента. Если в течение этого времени данные не были получены, соединение закрывается. В противном случае данные читаются и игнорируются, и nginx снова ждёт поступления данных. Цикл “ждать-читать-игнорировать” повторяется, но не дольше чем задано директивой [lingering\_time](#lingering_time).

如果 [lingering\_close](#lingering_close)指令生效，則此指令指定等待用戶端傳回更多資料的最大時間。如果在此時間內未收到任何數據，則關閉連線。否則，讀取並忽略數據，nginx 繼續等待更多數據。等待-讀取-忽略迴圈會重複進行，但持續時間不會超過 [lingering\_time](#lingering_time)指令指定的時間。

Задаёт `*адрес*` и `*порт*` для IP или `*путь*` для UNIX-сокета, на которых сервер будет принимать запросы. Можно указать `*адрес*` и `*порт*`, либо только `*адрес*` или только `*порт*`. Кроме того, `*адрес*` может быть именем хоста, например:

指定伺服器監聽請求的套接字`*адрес*`和`*порт*` （對應IP或`*путь*` （對應UNIX `*адрес*`您可以指定`*адрес*`和`*порт*` ，或僅指定`*адрес*`或`*порт*`也可以是主機名，例如：

> ```
> listen 127.0.0.1:8000;
>
> 聽127.0.0.1:8000 ;
> listen 127.0.0.1;
>
> 聽127.0.0.1 ;
> listen 8000;
>
> 聽 8000；
> listen *:8000;
>
> 監聽 *:8000；
> listen localhost:8000;
>
> 監聽本地主機：8000；
> ```

>

UNIX-сокеты (0.8.21) задаются при помощи префикса “`unix:`”:

UNIX套接字（ 0.8.21 ）使用「 `unix:` 」前綴指定：

> ```
> listen unix:/var/run/nginx.sock;
>
> 監聽unix:/var/run/nginx.sock;
> ```

Если указан только `*адрес*`, то используется порт 80.

如果只指定`*адрес*` ，則使用連接埠80。

Если директива не указана, то используется либо `*:80`, если nginx работает с привилегиями суперпользователя, либо `*:8000`.

如果未指定指令，則當 nginx 以超級使用者權限運行時，將使用`*:80` ，否則使用`*:8000` 。

Если у директивы есть параметр `default_server`, то сервер, в котором описана эта директива, будет сервером по умолчанию для указанной пары `*адрес*`:`*порт*`. Если же директив с параметром `default_server` нет, то сервером по умолчанию будет первый сервер, в котором описана пара `*адрес*`:`*порт*`.

如果指令具有`default_server`參數，則定義該指令的伺服器將成為指定`*адрес*`:`*порт*`對的預設伺服器。如果沒有指令具有`default_server`參數，則預設伺服器將是第一個定義`*адрес*`:`*порт*`對的伺服器。

> До версии 0.8.21 этот параметр назывался просто `default`.
>
> 在版本0.8.21之前，此參數簡稱為`default` 。

Параметр `ssl` (0.7.14) указывает на то, что все соединения, принимаемые на данном порту, должны работать в режиме SSL. Это позволяет задать компактную [конфигурацию](<212 [02.01.01 http] 設定HTTPS伺服器.md#single_http_https_server>) для сервера, работающего сразу в двух режимах — HTTP и HTTPS.

`ssl` ( 0.7.14 ) 參數指定此連接埠接收的所有連接都應以SSL模式運作。這允許您為同時以HTTP和HTTPS模式運行的伺服器設定緊湊的(https://nginx.org/ru/docs/http/configuring_https_servers.html#single_http_https_server)配置。

Параметр `http2` (1.9.5) позволяет принимать на этом порту [HTTP/2](<269 [02.01.01 http] 模組 ngx_http_v2_module.md>)\-соединения. Обычно, чтобы это работало, следует также указать параметр `ssl`, однако nginx можно также настроить и на приём HTTP/2-соединений без SSL.

`http2` ( 1.9.5 ) 參數允許在此連接埠上接受 [HTTP /2](<269 [02.01.01 http] 模組 ngx_http_v2_module.md>)連接。通常，為了使其正常工作，也必須指定`ssl` ，但也可以配置 nginx 以接受HTTP /2 連接而無需SSL 。

> Параметр устарел, вместо него следует использовать директиву [http2](<269 [02.01.01 http] 模組 ngx_http_v2_module.md#http2>).
>
> 此參數已棄用，應改用 [http2](<269 [02.01.01 http] 模組 ngx_http_v2_module.md#http2>)指令。

Параметр `quic` (1.25.0) позволяет принимать на этом порту [QUIC](<270 [02.01.01 http] ngx_http_v3_module 模組.md>)\-соединения.

參數`quic` ( 1.25.0 ) 允許在此連接埠上接收 [QUIC](<270 [02.01.01 http] ngx_http_v3_module 模組.md>) \-連接。

Параметр `proxy_protocol` (1.5.12) указывает на то, что все соединения, принимаемые на данном порту, должны использовать [протокол PROXY](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt).

參數`proxy_protocol` ( 1.5.12 ) 指定在此連接埠上接收的所有連接必須使用 [協定PROXY](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt) 。

> Протокол PROXY версии 2 поддерживается начиная с версии 1.13.11.
>
> 從版本1.13.11開始支援PROXY協定版本 2。

В директиве `listen` можно также указать несколько дополнительных параметров, специфичных для связанных с сокетами системных вызовов. Эти параметры можно задать в любой директиве `listen`, но только один раз для указанной пары `*адрес*`:`*порт*`.

`listen`指令也可以指定幾個與套接字相關的系統呼叫特有的附加選項。這些選項可以在任何`listen`指令中指定，但對於給定的`*адрес*`:`*порт*`對只能指定一次。

> До версии 0.8.21 их можно было указывать лишь в директиве `listen` совместно с параметром `default`.
>
> 在版本0.8.21之前，它們只能在`listen`指令中與`default`參數一起指定。

`setfib`\=`*число*`

этот параметр (0.8.44) задаёт таблицу маршрутизации, FIB (параметр `SO_SETFIB`) для слушающего сокета. В настоящий момент это работает только на FreeBSD.

此參數 ( 0.8.44 ) 指定監聽套接字的路由表 ( FIB ，參數`SO_SETFIB` )。目前，此功能僅適用於 FreeBSD。

`fastopen`\=`*число*`

включает “[TCP Fast Open](http://en.wikipedia.org/wiki/TCP_Fast_Open)” для слушающего сокета (1.5.8) и [ограничивает](https://datatracker.ietf.org/doc/html/rfc7413#section-5.1) максимальную длину очереди соединений, которые ещё не завершили процесс three-way handshake.

為監聽套接字啟用「[TCP快速開啟](http://en.wikipedia.org/wiki/TCP_Fast_Open) 」 ( 1.5.8 )，並[限制](https://datatracker.ietf.org/doc/html/rfc7413#section-5.1)尚未完成三次握手過程的連接的最大隊列長度。

> Не включайте “TCP Fast Open”（TCP快速打開）, не убедившись, что сервер может адекватно обрабатывать многократное получение [одного и того же SYN-пакета с данными](https://datatracker.ietf.org/doc/html/rfc7413#section-6.1).
>
> 請勿啟用“TCP Fast Open”（TCP快速打開）除非確保伺服器能夠充分處理多次接收 [相同的SYN封包](https://datatracker.ietf.org/doc/html/rfc7413#section-6.1) 。

`backlog`\=`*число*`

задаёт параметр `backlog` в вызове `listen()`, который ограничивает максимальный размер очереди ожидающих приёма соединений. По умолчанию `backlog` устанавливается равным -1 для FreeBSD, DragonFly BSD и macOS, и 511 для других платформ.

在`listen()`呼叫中設定`backlog`參數，此參數限制待處理連接隊列的最大大小。預設情況下，在 FreeBSD、DragonFly BSD 和 macOS 上， `backlog`設定為 -1，在其他平台上設定為 511。

`rcvbuf`\=`*размер*`

задаёт размер буфера приёма (параметр `SO_RCVBUF`) для слушающего сокета.

設定監聽套接字的接收緩衝區大小（參數`SO_RCVBUF` ）。

`sndbuf`\=`*размер*`

задаёт размер буфера передачи (параметр `SO_SNDBUF`) для слушающего сокета.

設定監聽套接字的發送緩衝區大小（參數`SO_SNDBUF` ）。

`accept_filter`\=`*фильтр*`

задаёт название accept-фильтра (параметр `SO_ACCEPTFILTER`) для слушающего сокета, который включается для фильтрации входящих соединений перед передачей их в `accept()`. Работает только на FreeBSD и NetBSD 5.0+. Можно использовать два фильтра: [dataready](http://man.freebsd.org/accf_data) и [httpready](http://man.freebsd.org/accf_http).

指定監聽套接字的接受過濾器（參數`SO_ACCEPTFILTER` ）的名稱，該過濾器用於在將傳入連接傳遞給`accept()`之前對其進行過濾。僅適用於 FreeBSD 和 NetBSD 5.0 +。可以使用兩個過濾器：[dataready](http://man.freebsd.org/accf_data)和 [httpready](http://man.freebsd.org/accf_http) 。

`deferred`

указывает использовать отложенный `accept()` (параметр `TCP_DEFER_ACCEPT` сокета) на Linux.

指定在 Linux 上使用延遲的`accept()` （ `TCP_DEFER_ACCEPT`套接字選項）。

`bind`

указывает, что для данной пары `*адрес*`:`*порт*` нужно делать `bind()` отдельно. Это нужно потому, что если описаны несколько директив `listen` с одинаковым портом, но разными адресами, и одна из директив `listen` слушает на всех адресах для данного порта (`*:``*порт*`), то nginx сделает `bind()` только на `*:``*порт*`. Необходимо заметить, что в этом случае для определения адреса, на который пришло соединение, делается системный вызов `getsockname()`. Если же используются параметры `setfib`, `fastopen`, `backlog`, `rcvbuf`, `sndbuf`, `accept_filter`, `deferred`, `ipv6only`, `reuseport`, `multipath` или `so_keepalive`, то для данной пары `*адрес*`:`*порт*` всегда делается отдельный вызов `bind()`.

表示對於給定的`*адрес*`:`*порт*`對，應單獨發出`bind()`指令。這是必要的，因為如果宣告了多個`listen`指令，且這些指令使用相同的`*:``*порт*`埠但不同的位址，並且其中一個`listen`指令監聽給定連接埠的所有位址（ `*:``*порт*` ），則 nginx 只會對`bind()`需要注意的是，在這種情況下，會發出`getsockname()`系統呼叫來確定接收到連接的位址。如果使用`setfib`, `fastopen`, `backlog`, `rcvbuf`, `sndbuf`, `accept_filter`, `deferred`, `ipv6only`, `reuseport`, `multipath`或`so_keepalive`參數，則始終會針對給定的`bind()` `*адрес*`:`*порт*` 。

`ipv6only`\=`on`|`off`

этот параметр (0.7.42) определяет (через параметр сокета `IPV6_V6ONLY`), будет ли слушающий на wildcard-адресе `[::]` IPv6-сокет принимать только IPv6-соединения, или же одновременно IPv6- и IPv4-соединения. По умолчанию параметр включён. Установить его можно только один раз на старте.

此參數 ( 0.7.42 ) 透過套接字參數`IPV6_V6ONLY`決定監聽通配符位址`[::]`的 IPv6 套接字是否僅接受 IPv6 連接，或同時接受 IPv6 和 IPv4 連接。此參數預設啟用，且只能在啟動時設定一次。

> До версии 1.3.4, если этот параметр не был задан явно, то для сокета действовали настройки операционной системы.
>
> 在版本1.3.4之前，如果未明確設定此參數，則套接字將使用作業系統設定。

`reuseport`

этот параметр (1.9.1) указывает, что нужно создавать отдельный слушающий сокет для каждого рабочего процесса (через параметр сокета `SO_REUSEPORT` для Linux 3.9+ и DragonFly BSD или `SO_REUSEPORT_LB` для FreeBSD 12+), позволяя ядру распределять входящие соединения между рабочими процессами. В настоящий момент это работает только на Linux 3.9+, DragonFly BSD и FreeBSD 12+ (1.15.1).

此選項（ 1.9.1 ）指定應為每個工作進程建立一個單獨的監聽套接字（透過 Linux 3.9 + 的`SO_REUSEPORT`套接字選項和 DragonFly BSD或 FreeBSD 12+的`SO_REUSEPORT_LB`套接字選項），從而允許核心將傳入的連線分配給各個工作進程。目前，此功能僅適用於 Linux 3.9 +、DragonFly BSD和 FreeBSD 12+ ( 1.15.1 )。

> Ненадлежащее использование параметра может быть [небезопасно](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 不當使用此參數可能[不安全](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`multipath`

этот параметр (1.29.7) конфигурирует для слушающего сокета протокол [Multipath TCP](https://datatracker.ietf.org/doc/html/rfc8684) (`IPPROTO_MPTCP`). В настоящий момент это работает только на Linux 5.6+.

此參數（ 1.29.7 ）配置監聽套接字的[多路徑TCP](https://datatracker.ietf.org/doc/html/rfc8684) （ `IPPROTO_MPTCP` ）協定。目前，這僅適用於5.6 +。

> Добавление или удаление этого параметра также включает параметр сокета `SO_REUSEPORT`, что может быть [небезопасно](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 新增或刪除此選項也會啟用`SO_REUSEPORT`套接字選項，此選項可能 [不安全](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`so_keepalive`\=`on`|`off`|\[`*keepidle*`\]:\[`*keepintvl*`\]:\[`*keepcnt*`\]

этот параметр (1.1.11) конфигурирует для слушающего сокета поведение “TCP keepalive”. Если этот параметр опущен, то для сокета будут действовать настройки операционной системы. Если он установлен в значение “`on`”, то для сокета включается параметр `SO_KEEPALIVE`. Если он установлен в значение “`off`”, то для сокета параметр `SO_KEEPALIVE` выключается. Некоторые операционные системы поддерживают настройку параметров “TCP keepalive” на уровне сокета посредством параметров `TCP_KEEPIDLE`, `TCP_KEEPINTVL` и `TCP_KEEPCNT`. На таких системах (в настоящий момент это Linux, NetBSD, Dragonfly, FreeBSD и macOS) их можно сконфигурировать с помощью параметров `*keepidle*`, `*keepintvl*` и `*keepcnt*`. Один или два параметра могут быть опущены, в таком случае для соответствующего параметра сокета будут действовать стандартные системные настройки. Например,

此參數 ( 1.1.11 ) 用於配置監聽套接字的「 TCP keepalive」行為。如果省略此參數，則套接字的作業系統設定生效。如果將其設為“ `on` ”，則套接字的`SO_KEEPALIVE` ”參數將會啟用。如果將其設為“ `off` ”，則套接字的`SO_KEEPALIVE` ”參數將被停用。某些作業系統支援使用`TCP_KEEPIDLE`, `TCP_KEEPINTVL`和`TCP_KEEPCNT` 」參數在套接字層級設定「 TCP keepalive」參數。在這些系統（目前包括 Linux、NetBSD、Dragonfly、FreeBSD 和 macOS）上，可以使用`*keepidle*`, `*keepintvl*`和`*keepcnt*`參數進行設定。可以省略一個或兩個參數，在這種情況下，對應的套接字參數將套用系統預設。例如：

> ```
> so_keepalive=30m::10
>
> 所以保持存活=30分鐘::10
> ```

установит таймаут бездействия (`TCP_KEEPIDLE`) в 30 минут, для интервала проб (`TCP_KEEPINTVL`) будет действовать стандартная системная настройка, а счётчик проб (`TCP_KEEPCNT`) будет равен 10.

將不活動逾時（ `TCP_KEEPIDLE` ）設定為 30 分鐘，取樣間隔（ `TCP_KEEPINTVL` ）將保持系統預設設置，取樣計數（ `TCP_KEEPCNT` ）將為 10。

Устанавливает конфигурацию в зависимости от URI запроса или значения переменной (1.31.5).

根據URI請求或變數的值 ( 1.31.5 ) 設定配置。

Для сопоставления используется URI запроса в нормализованном виде, после декодирования текста, заданного в виде “`%XX`”, преобразования относительных элементов пути “`.`” и “`..`” в реальные и возможной [замены](#merge_slashes) двух и более подряд идущих слэшей на один.

location можно задать префиксной строкой, регулярным выражением или предикатом (1.31.5). Регулярные выражения задаются либо с модификатором “`~*`” (для поиска совпадения без учёта регистра символов), либо с модификатором “`~`” (с учётом регистра). Предикат начинается с символа “`$`” и содержит переменную, вычисляемую в процессе обработки запроса. Предикатный location подходит, если значение переменной непустое и не равно “0”.

可以使用前綴字串、正規表示式或謂詞 ( 1.31.5 ) 來指定位置。正規表示式可以使用「 `~*` 」修飾符（用於不區分大小寫的匹配）或「 `~` 」修飾符（用於區分大小寫的匹配）來指定。謂詞以「 `$` 」字元開頭，包含一個在查詢處理期間計算的變數。如果該變數的值非空且不等於“0”，則謂詞位置符合。

Чтобы найти location, соответствующий запросу, вначале проверяются location’ы, заданные префиксными строками (префиксные location’ы). Среди них ищется location с совпадающим префиксом максимальной длины и запоминается. Затем проверяются регулярные выражения, в порядке их следования в конфигурационном файле. Проверка регулярных выражений прекращается после первого же совпадения, и используется соответствующая конфигурация. Если совпадение с регулярным выражением не найдено, проверяются предикатные location’ы, в порядке их следования в конфигурационном файле. Если ни один предикатный location не подошёл, используется конфигурация запомненного ранее префиксного location’а.

為了尋找與查詢相符的位置，首先檢查由前綴字串指定的位置（前綴位置）。系統會搜尋並記住具有最大長度匹配前綴的位置。然後，系統會依照正規表示式在設定檔中的出現順序進行檢查。正規表示式檢查在找到第一個匹配項後停止，並使用相應的配置。如果沒有找到匹配項，則繼續按照謂詞位置在設定檔中的出現順序進行檢查。如果仍然沒有找到匹配的謂詞位置，則使用先前記住的前綴位置的配置。

Блоки `location` могут быть вложенными, с некоторыми исключениями, о которых говорится ниже.

`location`模組可以嵌套，但下面會討論一些例外情況。

Для операционных систем, нечувствительных к регистру символов, таких как macOS и Cygwin, сравнение с префиксными строками производится без учёта регистра (0.7.7). Однако сравнение ограничено только однобайтными locale’ями.

對於 macOS 和 Cygwin 等不區分大小寫的作業系統，與前綴字串的比較將不區分大小寫 ( 0.7.7 )。但是，此比較僅限於單字節區域設定。

Регулярные выражения могут содержать выделения (0.7.40), которые могут затем использоваться в других директивах, см. [Выделения в регулярных выражениях](https://nginx.org/ru/docs/regex_captures.html).

正規表示式可以包含捕獲（ 0.7.40 ），然後可以在其他指令中使用，請參閱[正規表示式中的捕獲](https://nginx.org/ru/docs/regex_captures.html) 。

Если у совпавшего префиксного location’а максимальной длины указан модификатор “`^~`”, то регулярные выражения и предикатные location’ы не проверяются.

如果符合的最大長度前綴位置指定了「 `^~` 」修飾符，則不會檢查正規表示式和謂詞位置。

Кроме того, с помощью модификатора “`=`” можно задать точное совпадение URI и location. При точном совпадении поиск сразу же прекращается. Например, если запрос “`/`” случается часто, то указав “`location = /`”, можно ускорить обработку этих запросов, так как поиск прекратится после первого же сравнения. Очевидно, что такой location не может иметь вложенные location’ы.

此外，您可以使用「 `=` 」修飾符來指定URI與某個位置之間的精確匹配。精確匹配會立即終止搜尋。例如，如果查詢「 `/` 」頻繁出現，則指定「 `location = /` 」可以加快這些查詢的處理速度，因為搜尋會在找到第一個符合項後終止。顯然，這樣的位置不能包含嵌套位置。

> В версиях с 0.7.1 по 0.8.41, если запрос точно совпал с префиксным location’ом без модификаторов “`=`” и “`^~`”, то поиск тоже сразу же прекращается и регулярные выражения также не проверяются.
>
> 在0.7.1到0.8.41版本中，如果查詢與前綴位置完全匹配，而沒有“ `=` ”和“ `^~` ”修飾符，則搜索也會立即停止，並且不會檢查正則表達式。

Разрешает или запрещает сброс соединений по таймауту, а также при [закрытии](<253 [02.01.01 http] ngx_http_rewrite_module 模組.md#return>) соединений с помощью нестандартного кода 444 (1.15.2). Сброс делается следующим образом. Перед закрытием сокета для него задаётся параметр `SO_LINGER` с таймаутом 0. После этого при закрытии сокета клиенту отсылается TCP RST, а вся память, связанная с этим сокетом, освобождается. Это позволяет избежать длительного нахождения уже закрытого сокета в состоянии FIN\_WAIT1 с заполненными буферами.

啟用或停用逾時時的連線重置，以及使用非標準代碼 444 ( 1.15.2 ) 關閉(https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html#return)連線時的連線重設。重設過程如下：在關閉套接字之前，將其`SO_LINGER`參數設定為逾時時間為 0。之後，當套接字關閉時，向客戶端發送TCP RST ，並釋放與該套接字關聯的所有記憶體。這可以防止已關閉的套接字長時間處於FIN \_WAIT1 狀態且緩衝區已滿。

Необходимо отметить, что keep-alive соединения по истечении таймаута закрываются обычным образом.

需要注意的是，保持連線會在逾時後以正常方式關閉。

В такой конфигурации функция `sendfile()` вызывается с флагом `SF_NODISKIO`, в результате чего она не блокируется на диске, а сообщает об отсутствии данных в памяти. После этого nginx инициирует асинхронную подгрузку данных, читая один байт. При этом ядро FreeBSD подгружает в память первые 128K байт файла, однако при последующих чтениях файл подгружается частями только по 16K. Изменить это можно с помощью директивы [read\_ahead](#read_ahead).

在此配置中， `sendfile()`函數會使用`SF_NODISKIO`標誌調用，使其不會阻塞磁碟讀取，而是報告記憶體中沒有資料。然後，Nginx 會啟動非同步資料加載，讀取一個位元組。 FreeBSD 核心會將檔案的前 128KB 位元組載入記憶體中，但後續讀取操作只會以 16KB 為單位載入檔案。可以使用 [read\_ahead](#read_ahead)指令來更改此行為。

> До версии 1.7.11 подгрузка данных включалась с помощью `aio sendfile;`.
>
> 在版本1.7.11資料載入是透過`aio sendfile;`啟用的。

Проверяет существование файлов в заданном порядке и использует для обработки запроса первый найденный файл, причём обработка делается в контексте этого же location’а. > }
> ```

`$proxy_protocol_tlv_``*имя*`

TLV, полученный из заголовка протокола PROXY (1.23.2). `Имя` может быть именем типа TLV или его числовым значением. В последнем случае значение задаётся в шестнадцатеричном виде и должно начинаться с `0x`:

TLV，源自協議頭PROXY (1.23.2)。 `Имя` 可以是TLV 之類的名稱或其數值。在後一種情況下，該值以十六進位指定，並且必須以 `0x` 開頭：

> ```
> $proxy_protocol_tlv_alpn
> $proxy_protocol_tlv_0x01
> ```

SSL TLV могут также быть доступны как по имени типа TLV, так и по его числовому значению, оба должны начинаться с `ssl_`:

SSL TLV也可以透過其型別名稱TLV或其數值來訪問，兩者都必須以`ssl_`開頭：

> ```
> $proxy_protocol_tlv_ssl_version
> $proxy_protocol_tlv_ssl_0x21
> ```

Поддерживаются следующие имена типов TLV:

支援以下TLV類型名稱：

-   `alpn` (`0x01`) - протокол более высокого уровня, используемый поверх соединения  
    `alpn` ( `0x01` ) - 連接之上使用的高級協議
-   `authority` (`0x02`) - значение имени хоста, передаваемое клиентом  
    `authority` ( `0x02` ) - 用戶端傳輸的主機名稱值
-   `unique_id` (`0x05`) - уникальный идентификатор соединения  
    `unique_id` ( `0x05` ) - 唯一連接標識符
-   `netns` (`0x30`) - имя пространства имён  
    `netns` ( `0x30` ) - 命名空間名稱
-   `ssl` (`0x20`) - структура SSL TLV в бинарном виде  
    `ssl` ( `0x20` ) - SSL TLV的二進位結構

Поддерживаются следующие имена типов SSL TLV:

支援以下SSL TLV類型名稱：

-   `ssl_version` (`0x21`) - версия SSL, используемая в клиентском соединении  
    `ssl_version` ( `0x21` ) - 客戶端連線中使用的SSL版本
-   `ssl_cn` (`0x22`) - Common Name сертификата  
    `ssl_cn` ( `0x22` ) - 證書的通用名稱
-   `ssl_cipher` (`0x23`) - имя используемого шифра  
    `ssl_cipher` ( `0x23` ) - 所用密碼的名稱
-   `ssl_sig_alg` (`0x24`) - алгоритм, используемый для подписи сертификата  
    `ssl_sig_alg` ( `0x24` ) - 用於簽署憑證的演算法
-   `ssl_key_alg` (`0x25`) - алгоритм публичного ключа  
    `ssl_key_alg` ( `0x25` ) - 公鑰演算法

Также поддерживается следующее специальное имя типа SSL TLV:

同時支援以下特殊類型名稱SSL TLV ：

-   `ssl_verify` - результат проверки клиентского сертификата: `0`, если клиент предоставил сертификат и он был успешно верифицирован, либо ненулевое значение  
    `ssl_verify` - 用戶端憑證驗證結果： `0`如果用戶端提供了憑證且驗證成功，則為非零值

Протокол PROXY должен быть предварительно включён при помощи установки параметра `proxy_protocol` в директиве [listen](#listen).

首先必須透過在 [listen](#listen)指令中設定`proxy_protocol`參數來啟用PROXY協定。

`$request_body_file`

При передаче имени временного файла в проксированном запросе или в запросе к FastCGI/uwsgi/SCGI-серверу следует запретить передачу самого тела директивами [proxy\_pass\_request\_body off](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_pass_request_body>), [fastcgi\_pass\_request\_body off](<225 [02.01.01 http] ngx_http_fastcgi_module 模組.md#fastcgi_pass_request_body>), [uwsgi\_pass\_request\_body off](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_pass_request_body>) или [scgi\_pass\_request\_body off](<254 [02.01.01 http] 模組 ngx_http_scgi_module.md#scgi_pass_request_body>) соответственно.

處理完成後，應刪除該檔案。為確保請求體始終寫入文件，請啟用 [client\_body\_in\_file\_only](#client_body_in_file_only) 。在代理請求或向 FastCGI/uwsgi/ SCGI伺服器發送請求時，如果傳遞臨時檔案的名稱，則應分別使用指令 [proxy\_pass\_request\_body off](<248 [02.01.01 http] ngx_http_proxy_module 模組.md#proxy_pass_request_body>) 、[fastcgi\_pass\_request\_body (https://nginx.org/ru/docs/http/ngx_http_fastcgi_module.html#fastcgi_pass_request_body) off](<268 [02.01.01 http] 模組 ngx_http_uwsgi_module.md#uwsgi_pass_request_body>)或 [scgi\_pass\_request\_body off](<254 [02.01.01 http] 模組 ngx_http_scgi_module.md#scgi_pass_request_body>)禁止傳送請求體本身。
