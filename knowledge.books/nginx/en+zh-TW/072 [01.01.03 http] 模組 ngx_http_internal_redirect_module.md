# Module ngx_http_internal_redirect_module｜模組 ngx_http_internal_redirect_module

> 章節：[en｜在](<000 目錄.md#c-1>) › [docs｜文件](<000 目錄.md#c-2>) › [http](<000 目錄.md#c-5>)

## Module ngx\_http\_internal\_redirect\_module｜模組 ngx\_http\_internal\_redirect\_module

|   |
| --- |
| [Example Configuration](#example)<br>[Directives](#directives)<br>     [internal\_redirect](#internal_redirect)<br>[範例設定](#example)<br>[指令](#directives)<br>     [內部\_redirect](#internal_redirect) |

The `ngx_http_internal_redirect_module` module (1.23.4) allows making an internal redirect. In contrast to [rewriting URIs](<090 [01.01.03 http] 模組 ngx_http_rewrite_module.md>), the redirection is made after checking [request](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>) and [connection](<075 [01.01.03 http] 模組 ngx_http_limit_conn_module.md>) processing limits, and [access](<045 [01.01.03 http] 模組 ngx_http_access_module.md>) limits.

`ngx_http_internal_redirect_module` 模組 (1.23.4) 允許進行內部重定向。與[重寫URI](<090 [01.01.03 http] 模組 ngx_http_rewrite_module.md>)相反，重定向是在檢查[請求](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>)和[連接](<075 [01.01.03 http] 模組 ngx_http_limit_conn_module.md>)處理限制以及[訪問](<045 [01.01.03 http] 模組 ngx_http_access_module.md>)限制後進行的。

#### Example Configuration｜範例配置

> ```
> limit_req_zone $jwt_claim_sub zone=jwt_sub:10m rate=1r/s;
>
> limit_req_zone $jwt_claim_sub zone=jwt_sub:10m 速率=1r/s;
> 
> server {
>
> 伺服器 {
>     location / {
>
>     地點 / {
>         auth_jwt          "realm";
>
>         auth_jwt「領域」；
>         auth_jwt_key_file key.jwk;
> 
>         internal_redirect @rate_limited;
>
>         內部重定向@rate_limited；
>     }
> 
>     location @rate_limited {
>
>     位置@rate_limited {
>         internal;
>
>         內部的;
> 
>         limit_req  zone=jwt_sub burst=10;
>
>         limit_req區域=jwt_sub突發=10；
>         proxy_pass http://backend;
>     }
> }
> ```

The example implements [per-user](https://datatracker.ietf.org/doc/html/rfc7519#section-4.1.2) [rate limiting](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>). Implementation without [internal\_redirect](#internal_redirect) is vulnerable to DoS attacks by unsigned JWTs, as normally the [limit\_req](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md#limit_req>) check is performed [before](<028 [01.01.01 開發] 開發指南.md#http_phases>) [auth\_jwt](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md#auth_jwt>) check. Using [internal\_redirect](#internal_redirect) allows reordering these checks.

此範例實現了[每位使用者](https://datatracker.ietf.org/doc/html/rfc7519#section-4.1.2)[速率限制](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md>)。沒有 [internal\_redirect](#internal_redirect) 的實現很容易受到未簽名 JWT 的 DoS 攻擊，因為通常 [limit\_req](<076 [01.01.03 http] 模組 ngx_http_limit_req_module.md#limit_req>) 檢查 [before](<028 [01.01.01 開發] 開發指南.md#http_phases>) [auth\_jwt](<050 [01.01.03 http] 模組 ngx_http_auth_jwt_module.md#auth_jwt>) 檢查執行。使用 [internal\_redirect](#internal_redirect) 允許對這些檢查重新排序。

#### Directives｜指令

|   |   |
| --- | --- |
| Syntax:<br>語法： | ``**internal_redirect** `*uri*`;`` |
| Default:<br>預設值： | — |
| Context:<br>上下文： | `server`, `location` |

Sets the URI for internal redirection of the request. It is also possible to use a [named location](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location_named>) instead of the URI. The `*uri*` value can contain variables. If the `*uri*` value is empty, then the redirect will not be made.

設定請求內部重定向的URI。也可以使用[命名位置](<056 [01.01.03 http] 模組 ngx_http_core_module.md#location_named>)代替URI。 `*uri*`值可以包含變數。如果 `*uri*` 值為空，則不會進行重定向。
