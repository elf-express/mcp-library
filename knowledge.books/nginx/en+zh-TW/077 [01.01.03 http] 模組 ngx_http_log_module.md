The `ngx_http_log_module` module writes request logs in the specified format.

`ngx_http_log_module`模組以指定的格式寫入請求日誌。

Requests are logged in the context of a location where processing ends. It may be different from the original location, if an [internal redirect](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>) happens during request processing.

請求日誌會記錄在處理結束的位置。如果在請求處理過程中發生[內部重定向](<056 [01.01.03 http] 模組 ngx_http_core_module.md#internal>) ，則該位置可能與原始位置不同。

#### Example Configuration｜範例配置

> ```
> log_format compression '$remote_addr - $remote_user [$time_local] '
>                        '"$request" $status $bytes_sent '
>
>                        '“$request”$status $bytes_sent'
>                        '"$http_referer" "$http_user_agent" "$gzip_ratio"';
> 
> access_log /spool/logs/nginx-access.log compression buffer=32k;
>
> access_log /spool/logs/nginx-access.log 壓縮緩衝區=32k;
> ```

Sets the path, format, and configuration for a buffered log write. Several logs can be specified on the same configuration level. Logging to [syslog](<169 [01.01 文件] 日誌記錄到系統日誌.md>) can be configured by specifying the “`syslog:`” prefix in the first parameter. The special value `off` cancels all `access_log` directives on the current level. If the format is not specified then the predefined “`combined`” format is used.

設定緩衝日誌寫入的路徑、格式和配置。可以在相同配置等級指定多個日誌。透過在第一個參數中指定「 `syslog:` 」前綴，可以設定日誌寫入 [syslog](<169 [01.01 文件] 日誌記錄到系統日誌.md>) 。特殊值`off`會取消目前層級的所有`access_log`指令。如果未指定格式，則使用預先定義的「 `combined` 」格式。

If either the `buffer` or `gzip` (1.3.10, 1.2.7) parameter is used, writes to log will be buffered.

如果使用`buffer`或`gzip` ( 1.3.10, 1.2.7 ) 參數，則寫入日誌的操作將會被緩衝。

> The buffer size must not exceed the size of an atomic write to a disk file. For FreeBSD this size is unlimited.
>
> 緩衝區大小不得超過原子寫入磁碟檔案的大小。對於 FreeBSD 系統，此大小沒有限制。

When buffering is enabled, the data will be written to the file:

啟用緩衝後，資料將被寫入檔案：

-   if the next log line does not fit into the buffer;  
    如果下一行日誌無法放入緩衝區；
-   if the buffered data is older than specified by the `flush` parameter (1.3.10, 1.2.7);  
    若緩衝的資料早於`flush`參數 ( 1.3.10, 1.2.7 ) 指定的日期；
-   when a worker process is [re-opening](<026 [01.01 文件] 控制 Nginx.md>) log files or is shutting down.  
    當工作進程[重新開啟](<026 [01.01 文件] 控制 Nginx.md>)日誌檔案或關閉時。

If the `gzip` parameter is used, then the buffered data will be compressed before writing to the file. The compression level can be set between 1 (fastest, less compression) and 9 (slowest, best compression). By default, the buffer size is equal to 64K bytes, and the compression level is set to 1. Since the data is compressed in atomic blocks, the log file can be decompressed or read by “`zcat`” at any time.

如果使用`gzip`參數，則緩衝的資料會在寫入檔案之前被壓縮。壓縮等級可以設定為 1（速度最快，壓縮率最低）到 9（速度最慢，壓縮率最高）。預設情況下，緩衝區大小為 64KB，壓縮等級設定為 1。由於資料以原子塊的形式壓縮，因此可以隨時使用`zcat`解壓縮或讀取日誌檔。

Example:

例子：

> ```
> access_log /path/to/log.gz combined gzip flush=5m;
> ```

> For gzip compression to work, nginx must be built with the zlib library.
>
> 要讓 gzip 壓縮正常運作，nginx 必須使用 zlib 函式庫進行建置。

The file path can contain variables (0.7.6+), but such logs have some constraints:

檔案路徑可以包含變數（ 0.7.6 +），但此類日誌有一些限制：

-   the [user](<125 [01.01 文件] 核心功能.md#user>) whose credentials are used by worker processes should have permissions to create files in a directory with such logs;  
    工作進程使用的憑證對應的 [使用者](<125 [01.01 文件] 核心功能.md#user>)應該具有在包含此類日誌的目錄中建立檔案的權限；
-   buffered writes do not work;  
    緩衝寫入不起作用；
-   the file is opened and closed for each log write. However, since the descriptors of frequently used files can be stored in a [cache](#open_log_file_cache), writing to the old file can continue during the time specified by the [open\_log\_file\_cache](#open_log_file_cache) directive’s `valid` parameter  
    每次寫入日誌時，檔案都會被開啟和關閉。但是，由於常用檔案的描述子可以儲存在 [cache](#open_log_file_cache)中，因此在 [open\_log\_file\_cache](#open_log_file_cache)指令的`valid`參數指定的時間內，可以繼續寫入舊檔案。
-   during each log write the existence of the request’s [root directory](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>) is checked, and if it does not exist the log is not created. It is thus a good idea to specify both [root](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>) and `access_log` on the same configuration level:  
    每次寫入日誌時，都會檢查請求的 [根目錄](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>)是否存在，如果不存在，則不會建立日誌。因此，最好在同一配置層級同時指定 [根目錄](<056 [01.01.03 http] 模組 ngx_http_core_module.md#root>)和`access_log` ：
    
    > ```
    > server {
    >
    > 伺服器 {
    >     root       /spool/vhost/data/$host;
    >
    >     root /spool/vhost/data/$host;
    >     access_log /spool/vhost/logs/$host;
    >
    >     存取日誌 /spool/vhost/logs/$host;
    >     ...
    > ```
    

The `if` parameter (1.7.0) enables conditional logging. A request will not be logged if the `*condition*` evaluates to “0” or an empty string. In the following example, the requests with response codes 2xx and 3xx will not be logged:

`if`參數（ 1.7.0 ）啟用條件日誌記錄。如果`*condition*`值為「0」或空字串，則不會記錄該請求。在以下範例中，回應代碼為 2xx 和 3xx 的請求將不會被記錄：

> ```
> map $status $loggable {
>
> 映射 $status $loggable {
>     ~^[23]  0;
>     default 1;
>
>     預設值為 1；
> }
> 
> access_log /path/to/access.log combined if=$loggable;
>
> access_log /path/to/access.log 合併 if=$loggable;
> ```

Specifies log format.

指定日誌格式。

The `escape` parameter (1.11.8) allows setting `json` or `default` characters escaping in variables, by default, `default` escaping is used. The `none` value (1.13.10) disables escaping.

`escape`參數（1.11.8）允許設定變數中的`json`或`default`字元轉義，預設使用`default`轉義。 `none` 值 (1.13.10) 停用轉義。

For `default` escaping, characters “`"`”, “`\`”, and other characters with values less than 32 (0.7.0) or above 126 (1.1.6) are escaped as “`\xXX`”. If the variable value is not found, a hyphen (“`-`”) will be logged.

對於`default`轉義，字元「 `"` 」、「 `\` 」以及值小於32（ 0.7.0 ）或大於126（ 1.1.6 ）的其他字元將被轉義為「 `\xXX` 」。如果未找到變數值，則會記錄一個連字號（“ `-` ”）。

For `json` escaping, all characters not allowed in JSON [strings](https://datatracker.ietf.org/doc/html/rfc8259#section-7) will be escaped: characters “`"`” and “`\`” are escaped as “`\"`” and “`\\`”, characters with values less than 32 are escaped as “`\n`”, “`\r`”, “`\t`”, “`\b`”, “`\f`”, or “`\u00XX`”.

对于`json`转义，JSON[字符串](https://datatracker.ietf.org/doc/html/rfc8259#section-7)中不允许的所有字符都将被转义：字符“`"`”和“`\`”被转义为“`\"`”和“`\\`”，值小于32的字符被转义为“`\n`”、“`\r`”、“`\t`”、“`\b`”、“`\f`”或“`\u00XX`”。

The log format can contain common variables, and variables that exist only at the time of a log write:

日誌格式可以包含通用變量，以及僅在日誌寫入時存在的變數：

`$bytes_sent`

the number of bytes sent to a client

發送給客戶端的位元組數

`$connection`

connection serial number

連接序號

`$connection_requests`

the current number of requests made through a connection (1.1.18)

目前透過連線發出的請求數 ( 1.1.18 )

`$msec`

time in seconds with a milliseconds resolution at the time of the log write

日誌寫入時的時間，以秒為單位，精確度為毫秒。

`$pipe`

“`p`” if request was pipelined, “`.`” otherwise

如果請求已透過管道處理，則為“ `p` ”，否則為“ `.` ”。

`$request_length`

request length (including request line, header, and request body)

請求長度（包括請求行、請求頭和請求體）

`$request_time`

request processing time in seconds with a milliseconds resolution; time elapsed between the first bytes were read from the client and the log write after the last bytes were sent to the client

請求處理時間（以秒為單位，精確到毫秒）；從客戶端讀取第一個位元組到向客戶端發送最後一個位元組後寫入日誌所經過的時間。

`$status`

response status

回應狀態

`$time_iso8601`

local time in the ISO 8601 standard format

ISO 8601 標準格式的本地時間

`$time_local`

local time in the Common Log Format

通用日誌格式中的本機時間

> In the modern nginx versions variables [$status](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_status>) (1.3.2, 1.2.2), [$bytes\_sent](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_bytes_sent>) (1.3.8, 1.2.5), [$connection](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_connection>) (1.3.8, 1.2.5), [$connection\_requests](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_connection_requests>) (1.3.8, 1.2.5), [$msec](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_msec>) (1.3.9, 1.2.6), [$request\_time](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_request_time>) (1.3.9, 1.2.6), [$pipe](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_pipe>) (1.3.12, 1.2.7), [$request\_length](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_request_length>) (1.3.12, 1.2.7), [$time\_iso8601](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_time_iso8601>) (1.3.12, 1.2.7), and [$time\_local](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_time_local>) (1.3.12, 1.2.7) are also available as common variables.
>
> 在現代 nginx 版本中，變數 [$status](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_status>) (1.3.2, 1.2.2), [$bytes\_sent](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_bytes_sent>) (1.3.8, 1.2.5), [$connection](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_connection>) (1.3.8, 1.2.5), [$connection\_requests](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_connection_requests>) (1.3.8, 1.2.5), [$毫秒](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_msec>) (1.3.9, 1.2.6), [$request\_time](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_request_time>) (1.3.9, 1.2.6), [$pipe](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_pipe>) (1.3.12, 1.2.7), [$request\_length](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_request_length>) (1.3.12, 1.2.7), [$time\_iso8601](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_time_iso8601>) (1.3.12, 1.2.7），以及 [$time\_local](<056 [01.01.03 http] 模組 ngx_http_core_module.md#var_time_local>) (1.3.12, 1.2.7）也可作為常用變數使用。

Header lines sent to a client have the prefix “`sent_http_`”, for example, `$sent_http_content_range`.

發送給客戶端的標頭行帶有前綴“ `sent_http_` ”，例如`$sent_http_content_range` 。

The configuration always includes the predefined “`combined`” format:

配置始終包含預先定義的“ `combined` ”格式：

> ```
> log_format combined '$remote_addr - $remote_user [$time_local] '
>                     '"$request" $status $body_bytes_sent '
>                     '"$http_referer" "$http_user_agent"';
> ```

Defines a cache that stores the file descriptors of frequently used logs whose names contain variables. The directive has the following parameters:

定義一個緩存，用於儲存名稱包含變數的常用日誌檔案的檔案描述符。此指令具有以下參數：

`max`

sets the maximum number of descriptors in a cache; if the cache becomes full the least recently used (LRU) descriptors are closed

設定快取中描述符的最大數量；如果快取已滿，則最近最少使用的（ LRU ）描述符將關閉。

`inactive`

sets the time after which the cached descriptor is closed if there were no access during this time; by default, 10 seconds

設定快取描述符在無存取後關閉的時間；預設值為 10 秒。

`min_uses`

sets the minimum number of file uses during the time defined by the `inactive` parameter to let the descriptor stay open in a cache; by default, 1

設定`inactive`參數定義的時間段內，檔案使用次數的最小值，以使描述子在快取中保持開啟；預設值為1。

`valid`

sets the time after which it should be checked that the file still exists with the same name; by default, 60 seconds

設定檢查同名檔案是否存在的時間間隔；預設值為 60 秒。

`off`

disables caching

禁用快取

Usage example:

使用範例：

> ```
> open_log_file_cache max=1000 inactive=20s valid=1m min_uses=2;
> ```
