Sets permitted methods of authentication for POP3 clients. Supported methods are:

設定POP3客戶端允許的身份驗證方法。支援的方法包括：

`plain`

[USER/PASS](https://datatracker.ietf.org/doc/html/rfc1939), [AUTH PLAIN](https://datatracker.ietf.org/doc/html/rfc4616), [AUTH LOGIN](https://datatracker.ietf.org/doc/html/draft-murchison-sasl-login-00)

`apop`

[APOP](https://datatracker.ietf.org/doc/html/rfc1939). In order for this method to work, the password must be stored unencrypted.

[APOP](https://datatracker.ietf.org/doc/html/rfc1939) 。為了使此方法有效，密碼必須以未加密的形式儲存。

`cram-md5`

[AUTH CRAM-MD5](https://datatracker.ietf.org/doc/html/rfc2195). In order for this method to work, the password must be stored unencrypted.

[AUTH CRAM-MD5](https://datatracker.ietf.org/doc/html/rfc2195) 。為了使此方法有效，密碼必須以未加密的形式儲存。

`external`

[AUTH EXTERNAL](https://datatracker.ietf.org/doc/html/rfc4422) (1.11.6).

Plain text authentication methods (`USER/PASS`, `AUTH PLAIN`, and `AUTH LOGIN`) are always enabled, though if the `plain` method is not specified, `AUTH PLAIN` and `AUTH LOGIN` will not be automatically included in [pop3\_capabilities](#pop3_capabilities).

純文字驗證方法（ `USER/PASS`, `AUTH PLAIN`和`AUTH LOGIN` ）始終啟用，但如果未指定`plain`方法，則`AUTH PLAIN`和`AUTH LOGIN`將不會自動包含在 [pop3\_capabilities](#pop3_capabilities)中。

Sets the [POP3 protocol](https://datatracker.ietf.org/doc/html/rfc2449) extensions list that is passed to the client in response to the `CAPA` command. The authentication methods specified in the [pop3\_auth](#pop3_auth) directive ([SASL](https://datatracker.ietf.org/doc/html/rfc2449) extension) and [STLS](https://datatracker.ietf.org/doc/html/rfc2595) are automatically added to this list depending on the [starttls](<123 [01.01.04 郵件] 模組 ngx_mail_ssl_module.md#starttls>) directive value.

設定回應`CAPA`指令而傳遞給客戶端的 [POP3 協定](https://datatracker.ietf.org/doc/html/rfc2449)擴充清單。根據 [starttls (https://nginx.org/en/docs/mail/ngx_mail_pop3_module.html#pop3_auth)指令中指定的(https://nginx.org/en/docs/mail/ngx_mail_ssl_module.html#starttls)方法（[SASL](https://datatracker.ietf.org/doc/html/rfc2449)擴充）和 [STLS](https://datatracker.ietf.org/doc/html/rfc2595)會自動加入此清單。

It makes sense to specify the extensions supported by the POP3 backends to which the clients are proxied (if these extensions are related to commands used after the authentication, when nginx transparently proxies the client connection to the backend).

如果這些擴充與身份驗證後使用的命令相關，那麼指定客戶端代理到的POP3後端支援的擴充就很有意義（當 nginx 透明地將客戶端連接代理到後端時）。

The current list of standardized extensions is published at [www.iana.org](http://www.iana.org/assignments/pop3-extension-mechanism).

目前標準化擴充清單發佈在 [www.iana.org](http://www.iana.org/assignments/pop3-extension-mechanism) 。
