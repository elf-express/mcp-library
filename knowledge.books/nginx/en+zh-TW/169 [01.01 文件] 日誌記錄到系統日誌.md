# Logging to syslog｜日誌記錄到系統日誌

> 章節：[en｜在](<000 目錄.md#c-1>) › [docs｜文件](<000 目錄.md#c-2>)

## Logging to syslog｜日誌記錄到系統日誌

The [error\_log](<125 [01.01 文件] 核心功能.md#error_log>) and [access\_log](<077 [01.01.03 http] 模組 ngx_http_log_module.md#access_log>) directives support logging to syslog. The following parameters configure logging to syslog:

[error\_log](<125 [01.01 文件] 核心功能.md#error_log>)和 [access\_log](<077 [01.01.03 http] 模組 ngx_http_log_module.md#access_log>)指令支援將日誌記錄到 syslog。以下參數用於設定 syslog 日誌記錄：

`server=``*address*`

Defines the address of a syslog server. The address can be specified as a domain name or IP address, with an optional port, or as a UNIX-domain socket path specified after the “`unix:`” prefix. If port is not specified, the UDP port 514 is used. If a domain name resolves to several IP addresses, the first resolved address is used.

定義 syslog 伺服器的位址。位址可以指定為網域名稱或IP位址（選用連接埠），也可以指定為UNIX網域套接字路徑（位於「 `unix:` 」前綴之後）。如果未指定端口，則使用UDP端口 514。如果網域名稱解析到多個IP位址，則使用第一個解析到的位址。

`facility=``*string*`

Sets facility of syslog messages, as defined in [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1). Facility can be one of “`kern`”, “`user`”, “`mail`”, “`daemon`”, “`auth`”, “`intern`”, “`lpr`”, “`news`”, “`uucp`”, “`clock`”, “`authpriv`”, “`ftp`”, “`ntp`”, “`audit`”, “`alert`”, “`cron`”, “`local0`”..“`local7`”. Default is “`local7`”.

設定 syslog 訊息的功能，如 [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1)中定義。設施可以是以下編號之一：“ `kern` ”、“ `user` ”、“ `mail` ”、“ `daemon` ”、“ `auth` ”、“ `intern` ”、“ `lpr` ”、“ `news` ”、“ `uucp` ”、“ `clock` ”、“ `authpriv` ”、“ `ftp` ”、“ `ntp` ”、“ `audit` ”、“ `alert` ”、“ `cron` ”、“ `local0` 」 `local7` `local7` 」。

`severity=``*string*`

Sets severity of syslog messages for [access\_log](<077 [01.01.03 http] 模組 ngx_http_log_module.md#access_log>), as defined in [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1). Possible values are the same as for the second parameter (level) of the [error\_log](<125 [01.01 文件] 核心功能.md#error_log>) directive. Default is “`info`”.

設定 [access\_log](<077 [01.01.03 http] 模組 ngx_http_log_module.md#access_log>)的 syslog 訊息嚴重性，如 [RFC 3164](https://datatracker.ietf.org/doc/html/rfc3164#section-4.1.1)所定義。可選值與 [error\_log](<125 [01.01 文件] 核心功能.md#error_log>)指令的第二個參數（等級）相同。預設值為“ `info` ”。

> Severity of error messages is determined by nginx, thus the parameter is ignored in the `error_log` directive.
>
> 錯誤訊息的嚴重程度由 nginx 決定，因此在`error_log`指令中忽略該參數。

`tag=``*string*`

Sets the tag of syslog messages. Default is “`nginx`”.

設定係統日誌訊息的標籤。預設值為“ `nginx` ”。

`nohostname`

Disables adding the “hostname” field into the syslog message header (1.9.7).

停用將「hostname」欄位新增至 syslog 訊息標頭（ 1.9.7 ）。

Example syslog configuration:

系統日誌配置範例：

> ```
> error_log syslog:server=192.168.1.1 debug;
>
> error_log syslog:server= 192.168.1.1 debug;
> 
> access_log syslog:server=unix:/var/log/nginx.sock,nohostname;
> access_log syslog:server=[2001:db8::1]:12345,facility=local7,tag=nginx,severity=info combined;
>
> access_log syslog:server=[ 2001:db8::1 ]:12345,facility=local7,tag=nginx,severity=info combined;
> ```

> Logging to syslog is available since version 1.7.1. As part of our [commercial subscription](https://www.f5.com/products/nginx) logging to syslog is available since version 1.5.3.
>
> 從版本1.7.1開始，系統日誌記錄功能已可用。作為我們[商業訂閱](https://www.f5.com/products/nginx)的一部分，從版本1.5.3開始，系統日誌記錄功能已可用。
