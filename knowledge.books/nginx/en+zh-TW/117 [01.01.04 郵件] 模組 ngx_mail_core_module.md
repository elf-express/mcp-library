Sets the `*address*` and `*port*` for the socket on which the server will accept requests. It is possible to specify just the port. The address can also be a hostname, for example:

設定伺服器接受請求的套接字的`*address*`和`*port*` 。也可以只指定連接埠。位址也可以是主機名，例如：

> ```
> listen 127.0.0.1:110;

>
> 監聽 *:110;
> listen 110;     # same as *:110
>
> 監聽埠 110；# 等同於 *:110
> listen localhost:110;
>
> 監聽 localhost:110;
> ```

IPv6 addresses (0.7.58) are specified in square brackets:

IPv6 位址（ 0.7.58 ）以方括號指定：

> ```

UNIX-domain sockets (1.3.5) are specified with the “`unix:`” prefix:

UNIX -域套接字（ 1.3.5 ）以「 `unix:` 」前綴指定：

> ```
> listen unix:/var/run/nginx.sock;
>
> 監聽unix:/var/run/nginx.sock;

Different servers must listen on different `*address*`:`*port*` pairs.

不同的伺服器必須監聽不同的`*address*`:`*port*`對。

The `ssl` parameter allows specifying that all connections accepted on this port should work in SSL mode.

`ssl`參數允許指定在此連接埠上接受的所有連接都應以SSL模式工作。

The `proxy_protocol` parameter (1.19.8) allows specifying that all connections accepted on this port should use the [PROXY protocol](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt). Obtained information is passed to the [authentication server](<116 [01.01.04 郵件] 模組 ngx_mail_auth_http_module.md#proxy_protocol>) and can be used to [change the client address](<121 [01.01.04 郵件] 模組 ngx_mail_realip_module.md>).

`proxy_protocol`參數 ( 1.19.8 ) 允許指定在此連接埠上接受的所有連接都應使用 [PROXY協定](http://www.haproxy.org/download/1.8/doc/proxy-protocol.txt) 。所取得的資訊將傳遞給 [驗證伺服器](<116 [01.01.04 郵件] 模組 ngx_mail_auth_http_module.md#proxy_protocol>) ，並可用於 [更改客戶端位址](<121 [01.01.04 郵件] 模組 ngx_mail_realip_module.md>) 。

The `listen` directive can have several additional parameters specific to socket-related system calls.

`listen`指令可以有幾個與套接字相關的系統呼叫特有的附加參數。

`backlog`\=`*number*`

sets the `backlog` parameter in the `listen()` call that limits the maximum length for the queue of pending connections (1.9.2). By default, `backlog` is set to -1 on FreeBSD, DragonFly BSD, and macOS, and to 511 on other platforms.

在限制1.9.2處理連線佇列最大長度的`listen()`呼叫中設定`backlog`參數。預設情況下，在 FreeBSD、DragonFly BSD和 macOS 上， `backlog`設定為 -1，在其他平台上設定為 511。

`rcvbuf`\=`*size*`

sets the receive buffer size (the `SO_RCVBUF` option) for the listening socket (1.11.13).

設定監聽套接字的接收緩衝區大小（ `SO_RCVBUF`選項）（ 1.11.13 ）。

`sndbuf`\=`*size*`

sets the send buffer size (the `SO_SNDBUF` option) for the listening socket (1.11.13).

設定監聽套接字（ 1.11.13 ）的傳送緩衝區大小（ `SO_SNDBUF`選項）。

`bind`

this parameter instructs to make a separate `bind()` call for a given address:port pair. The fact is that if there are several `listen` directives with the same port but different addresses, and one of the `listen` directives listens on all addresses for the given port (`*:``*port*`), nginx will `bind()` only to `*:``*port*`. It should be noted that the `getsockname()` system call will be made in this case to determine the address that accepted the connection. If the `backlog`, `rcvbuf`, `sndbuf`, `ipv6only`, `multipath`, or `so_keepalive` parameters are used then for a given `*address*`:`*port*` pair a separate `bind()` call will always be made.

此參數指示針對給定的位址:埠對分別發起一次`bind()`呼叫。事實上，如果存在多個`listen`指令使用相同的連接埠但不同的位址，並且其中一個`listen`指令監聽給定連接埠的所有位址（ `*:``*port*` ），則 nginx 將僅對`*:``*port*`發起`bind()` 。需要注意的是，在這種情況下，將發起`getsockname()`系統呼叫來確定接受連接的位址。如果使用`backlog`, `rcvbuf`, `sndbuf`, `ipv6only`, `multipath`或`so_keepalive`參數，則對於給定的`*address*`:`*port*`對，將始終發起一次單獨的`bind()`呼叫。

`ipv6only`\=`on`|`off`

this parameter determines (via the `IPV6_V6ONLY` socket option) whether an IPv6 socket listening on a wildcard address `[::]` will accept only IPv6 connections or both IPv6 and IPv4 connections. This parameter is turned on by default. It can only be set once on start.

此參數（透過套接字選項`IPV6_V6ONLY` ）決定監聽通配符位址`[::]`的 IPv6 套接字是否僅接受 IPv6 連接，還是同時接受 IPv6 和 IPv4 連接。此參數預設啟用，且只能在啟動時設定一次。

`multipath`

this parameter (1.29.7) configures the [Multipath TCP](https://datatracker.ietf.org/doc/html/rfc8684) protocol (`IPPROTO_MPTCP`) for the listening socket. This currently works only on Linux 5.6+.

此參數（ 1.29.7 ）配置監聽套接字的[多路徑TCP](https://datatracker.ietf.org/doc/html/rfc8684)協定（ `IPPROTO_MPTCP` ）。目前僅適用於5.6 +。

> Adding or removing this parameter will also enable the `SO_REUSEPORT` socket option, which may have its security [implications](http://man7.org/linux/man-pages/man7/socket.7.html).
>
> 新增或刪除此參數還將啟用`SO_REUSEPORT`套接字選項，這可能會帶來安全方面的[影響](http://man7.org/linux/man-pages/man7/socket.7.html) 。

`so_keepalive`\=`on`|`off`|\[`*keepidle*`\]:\[`*keepintvl*`\]:\[`*keepcnt*`\]

this parameter configures the “TCP keepalive” behavior for the listening socket. If this parameter is omitted then the operating system’s settings will be in effect for the socket. If it is set to the value “`on`”, the `SO_KEEPALIVE` option is turned on for the socket. If it is set to the value “`off`”, the `SO_KEEPALIVE` option is turned off for the socket. Some operating systems support setting of TCP keepalive parameters on a per-socket basis using the `TCP_KEEPIDLE`, `TCP_KEEPINTVL`, and `TCP_KEEPCNT` socket options. On such systems (currently, Linux, NetBSD, Dragonfly, FreeBSD, and macOS), they can be configured using the `*keepidle*`, `*keepintvl*`, and `*keepcnt*` parameters. One or two parameters may be omitted, in which case the system default setting for the corresponding socket option will be in effect. For example,

此參數配置監聽套接字的「 TCP keepalive」行為。如果省略此參數，則套接字將使用作業系統的設定。如果將其設為“ `on` ”，則會為套接字啟用`SO_KEEPALIVE` ”選項。如果將其設為“ `off` ”，則會為套接字停用`SO_KEEPALIVE` ”選項。某些作業系統支援使用套接字選項`TCP_KEEPIDLE`, `TCP_KEEPINTVL`和`TCP_KEEPCNT`為每個套接字單獨設定TCP keepalive」參數。在這些系統（目前包括 Linux、NetBSD、Dragonfly、FreeBSD 和 macOS）上，可以使用`*keepidle*`, `*keepintvl*`和`*keepcnt*`參數進行設定。可以省略一個或兩個參數，在這種情況下，將使用對應套接字選項的系統預設。例如：

> ```
> so_keepalive=30m::10
>
> 所以保持存活=30分鐘::10
> ```

will set the idle timeout (`TCP_KEEPIDLE`) to 30 minutes, leave the probe interval (`TCP_KEEPINTVL`) at its system default, and set the probes count (`TCP_KEEPCNT`) to 10 probes.

將空閒逾時（ `TCP_KEEPIDLE` ）設定為 30 分鐘，將探測間隔（ `TCP_KEEPINTVL` ）保持為系統預設值，並將探測次數（ `TCP_KEEPCNT` ）設為 10 次探測。

Sets the protocol for a proxied server. Supported protocols are [IMAP](<118 [01.01.04 郵件] 模組 ngx_mail_imap_module.md>), [POP3](<119 [01.01.04 郵件] 模組 ngx_mail_pop3_module.md>), and [SMTP](<122 [01.01.04 郵件] 模組 ngx_mail_smtp_module.md>).

設定代理伺服器的協定。支持的協議有 [IMAP](<118 [01.01.04 郵件] 模組 ngx_mail_imap_module.md>) 、 [POP3](<119 [01.01.04 郵件] 模組 ngx_mail_pop3_module.md>)和 [SMTP](<122 [01.01.04 郵件] 模組 ngx_mail_smtp_module.md>) 。

If the directive is not set, the protocol can be detected automatically based on the well-known port specified in the [listen](#listen) directive:

如果未設定指令，則可根據 [listen](#listen)指令中指定的已知連接埠自動偵測協定：

-   `imap`: 143, 993
-   `pop3`: 110, 995
-   `smtp`: 25, 587, 465

Configures name servers used to find the client’s hostname to pass it to the [authentication server](<116 [01.01.04 郵件] 模組 ngx_mail_auth_http_module.md>), and in the [XCLIENT](<120 [01.01.04 郵件] 模組 ngx_mail_proxy_module.md#xclient>) command when proxying SMTP. For example:

配置用於尋找客戶端主機名稱的名稱伺服器，以便將其傳遞給[身份驗證伺服器](<116 [01.01.04 郵件] 模組 ngx_mail_auth_http_module.md>) ，並在代理SMTP時用於[XCLIENT](<120 [01.01.04 郵件] 模組 ngx_mail_proxy_module.md#xclient>)命令。例如：

> ```
> resolver 127.0.0.1 [::1]:5353;
>
> 解析器127.0.0.1 [::1]:5353;
> ```

The address can be specified as a domain name or IP address, with an optional port (1.3.1, 1.2.2). If port is not specified, the port 53 is used. Name servers are queried in a round-robin fashion.

位址可以指定為網域名稱或IP位址，連接埠號碼可選（ 1.3.1, 1.2.2 ）。如果未指定連接埠號，則使用連接埠53。名稱伺服器以輪詢方式進行查詢。

> Before version 1.1.7, only a single name server could be configured. Specifying name servers using IPv6 addresses is supported starting from versions 1.3.1 and 1.2.2.
>
> 在版本1.1.7之前，只能配置單一名稱伺服器。從版本1.3.1和1.2.2開始，支援使用IPv6位址指定名稱伺服器。

By default, nginx will look up both IPv4 and IPv6 addresses while resolving. If looking up of IPv4 or IPv6 addresses is not desired, the `ipv4=off` (1.23.1) or the `ipv6=off` parameter can be specified.

預設情況下，nginx 在解析時會同時尋找 IPv4 和 IPv6 位址。如果不需要尋找 IPv4 或 IPv6 位址，可以指定`ipv4=off` ( 1.23.1 ) 或`ipv6=off`參數。

> Resolving of names into IPv6 addresses is supported starting from version 1.5.8.
>
> 從版本1.5.8開始支援將名稱解析為IPv6位址。

By default, nginx caches answers using the TTL value of a response. An optional `valid` parameter allows overriding it:

預設情況下，nginx 使用回應的TTL值快取答案。可選的`valid`參數允許覆蓋此設定：

> ```
> resolver 127.0.0.1 [::1]:5353 valid=30s;
>
> 解析器127.0.0.1 [::1]:5353 有效=30秒;
> ```

> Before version 1.1.9, tuning of caching time was not possible, and nginx always cached answers for the duration of 5 minutes.
>
> 在版本1.1.9之前，無法調整快取時間，nginx 總是快取答案 5 分鐘。

> To prevent DNS spoofing, it is recommended configuring DNS servers in a properly secured trusted local network.
>
> 為防止DNS欺騙，建議在安全可靠的本地網路中設定DNS伺服器。

The optional `status_zone` parameter (1.17.1) enables [collection](<048 [01.01.03 http] 模組 ngx_http_api_module.md#resolvers_>) of DNS server statistics of requests and responses in the specified `*zone*`. The parameter is available as part of our [commercial subscription](https://www.f5.com/products/nginx).

可選參數`status_zone` ( 1.17.1 ) 啟用 [收集](<048 [01.01.03 http] 模組 ngx_http_api_module.md#resolvers_>)指定`*zone*`中請求和回應的DNS伺服器統計資訊。此參數作為我們 [商業訂閱](https://www.f5.com/products/nginx)的一部分提供。
