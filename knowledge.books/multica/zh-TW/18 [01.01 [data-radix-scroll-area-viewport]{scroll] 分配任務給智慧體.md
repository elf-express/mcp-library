# 分配任務給智慧體

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

讓智慧體負責一條任務，並決定是否立即開始執行。

當一項工作需要由智慧體持續負責時，把任務分配給它。智慧體會讀取任務的說明和討論，使用自己的配置與 skill 完成工作，並把進展和結果寫回原來的任務。

只需要智慧體處理一條具體請求、不改變負責人時，改用[評論中的 @提及](/docs/zh/mentioning-agents)。

## 分配並開始執行

1.  開啟一條任務，點選**負責人**。
2.  選擇一個智慧體或小隊。
3.  在確認視窗中檢查即將啟動的智慧體，然後選擇**開始**。

![分配确认窗：确认分配，或选择暂不开始](/docs/_next/image?url=%2Fdocs%2F_next%2Fstatic%2Fmedia%2Fassign-confirm-dialog.a746af9f.webp&w=3840&q=75)

這次執行需要智慧體知道的資訊，都寫在任務本身——它的說明、討論，或者專案說明與智慧體指令中。

分配給小隊時，任務的負責人是小隊，首先開始執行的是小隊 leader。它會按照小隊的工作方式判斷是否需要交給其他成員。

## 分配後的執行流程

Multica 會為智慧體建立一條[執行](/docs/zh/tasks)。線上執行時領取執行後，會呼叫本機的 AI 程式設計工具；進度、評論和結果隨後顯示在任務中。

執行時暫時離線時，執行留在佇列中等待；執行繫結該執行時，不會轉移到其他電腦執行。

智慧體在執行時可以：

-   讀取任務的描述、屬性和評論；
-   使用繫結的 skill、MCP 和專案上下文；
-   在本地工作目錄中讀取檔案、執行命令和修改內容；
-   發表評論並更新任務狀態。

具體能力仍受智慧體配置、執行時環境和你的呼叫許可權限制。

執行過程中，智慧體根據工作對任務的實際影響管理狀態：開始做任務本身要求的工作時立刻推到 `in_progress`，交付即推到 `in_review`，工作跨輪繼續則保持 `in_progress`，僅答疑或討論則不動狀態——這些動作以智慧體的身份出現在時間線中。執行的生命週期和任務狀態是分開的：執行完成本身不會改變任務狀態。

負責人是[小隊](/docs/zh/squads)時，同樣的規則適用：Multica 入隊的是隊長，派活不等於交付——派活輪結束時父任務處於 `in_progress`，整體目標達成後隊長才推到 `in_review`。

## 只分配，暫時不啟動

確認視窗中的**暫不開始**會儲存負責人，但不建立這一次執行。適合先明確歸屬，等背景或依賴準備好以後再開始。

`backlog` 也不會因為分配智慧體而啟動執行。把任務移出 `backlog`，或者在評論中繼續向負責人提出要求後，才會產生後續執行。

如果任務已經有智慧體或小隊負責人，把它移出 `backlog` 會彈出同一個確認窗：真正啟動執行的正是這次狀態變更，所以同樣有**暫不開始**——只改狀態，不叫醒智慧體。只要目標不是 `backlog` 本身，也不屬於 `done` 或 `closed` 分類，都會彈這個確認窗。

只有固定的 `backlog` 狀態有這個效果。`unstarted` 分類下的[自定義狀態](/docs/zh/issues#%E8%87%AA%E5%AE%9A%E4%B9%89%E7%8A%B6%E6%80%81)**不會**停住工作——把智慧體分配到那裡會立刻啟動執行。已經處於 `done` 或 `cancelled` 的任務，分配或重新分配給智慧體時同樣會立即開始執行。

## 分配許可權

能否分配由智慧體的 Access 決定：

-   **僅自己**：只有智慧體 owner 可以呼叫；
-   **指定成員**：owner 和名單中的成員可以呼叫；
-   **整個工作區**：所有工作區成員都可以呼叫。

工作區 owner 和 admin 可以管理智慧體，但"看得到"不代表"可以執行"。負責人選擇器會停用你無權呼叫的智慧體。完整規則見[智慧體](/docs/zh/agents#%E6%9D%83%E9%99%90%E4%B8%8E-access)。

## 更換或移除負責人

把負責人換成另一個智慧體，會為新負責人啟動一次新的執行；選擇成員只會改變負責人，不會呼叫 AI 程式設計工具。移除負責人也不會建立執行。

更換負責人、取消分配或修改任務狀態，都不會停止已經開始的執行。需要中斷時，在執行日誌中停止對應的執行。

## 使用 CLI

```
multica issue assign MUL-42 --to "Agent name"
multica issue assign MUL-42 --to-id <agent-uuid> --no-start
multica issue status MUL-42 in_progress --no-start
multica issue assign MUL-42 --unassign
```

指令碼中用 `--to-id <uuid>` 可避免同名物件匹配錯誤。UUID 通過 `multica agent list --output json` 或 `multica workspace member list --output json` 檢視。

如果指派只用於記錄負責人、不應建立新執行（例如同一智慧體已在另一次執行中處理該任務），請使用 `--no-start`。`issue update` 和 `issue status` 同樣支援這個 flag。如果只記錄歸屬的流程同時修改負責人和狀態，兩條命令都要傳入該 flag；抑制指派不會自動抑制後續狀態變更觸發的執行。
