# 執行

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

瞭解智慧體的一次執行如何排隊、執行、停止和重試。

每次智慧體開始工作，Multica 都會建立一條**執行記錄**。它記錄這次執行由什麼觸發、交給了哪個智慧體、當前進行到哪裡，以及最後是否成功。

## 任務與執行

任務儲存一項工作的目標、討論、負責人和最終狀態；執行記錄智慧體對這項工作的一次執行。

|  | 任務 | 執行 |
| --- | --- | --- |
| 記錄什麼 | 一項持續推進的工作 | 智慧體的一次執行 |
| 持續多久 | 可以反覆討論、補充和重新分配 | 從觸發開始，到完成、失敗或取消為止 |
| 數量關係 | 一個任務可以包含多次執行 | 每次執行都有獨立記錄 |

因此，同一個任務可以先後交給不同的智慧體，也可以在一次失敗後重新執行。每次都會產生新的執行記錄，之前的記錄不會被覆蓋。

## 觸發來源

以下操作都可能觸發一次執行：

-   把任務分配給智慧體或小隊。
-   在評論中提及智慧體。
-   在對話中向智慧體傳送訊息。
-   由自動化按計劃或外部事件觸發。

不同入口提供的上下文不同，但執行方式相同：Multica 建立執行，執行時領取它，再呼叫智慧體配置的 AI 程式設計工具。

## 執行過程

一次執行通常會經過以下狀態：

| 狀態 | 表示什麼 |
| --- | --- |
| `deferred` | 已安排稍後觸發，到達指定時間後進入佇列 |
| `queued` | 正在等待執行時領取 |
| `dispatched` | 執行時已經領取，正在啟動 AI 程式設計工具 |
| `waiting_local_directory` | 目標本地目錄正被另一條執行佔用，等待目錄鎖釋放 |
| `running` | AI 程式設計工具正在執行 |
| `completed` | 這次執行已正常結束 |
| `failed` | 執行出錯或中斷 |
| `cancelled` | 執行被手動停止 |

執行時線上時，新執行通常會很快開始；如果執行入隊後執行時離線，它會留在佇列中等待恢復。排隊本身不會導致過期——執行時只要還在心跳就說明它是忙，不是沒了，它的積壓可以排多久就排多久。只有**同時**滿足兩個條件，排隊中的執行才會失敗：繫結的執行時心跳缺席超過重連寬限期，**並且**該執行自己也已經排隊滿這麼久。第二個條件針對的是「指派給一臺已經休眠的機器」——這種情況下執行仍然會獲得完整的一個寬限期供你把機器喚醒，而不是立刻失敗。

如果系統在觸發前已經知道目標執行時離線，部分即時操作會直接提示當前無法執行，而不是繼續建立一條無法領取的執行。

心跳正常的執行時可以執行長時間執行，伺服器不會僅因為執行時間較長就強制結束它。執行時會根據實際活動判斷程序是否已經卡住；相關設定見[環境變數](/docs/zh/environment-variables#%E5%AE%88%E6%8A%A4%E8%BF%9B%E7%A8%8B%E9%85%8D%E7%BD%AE)。

## 檢視執行記錄

任務產生的所有執行都列在任務右側欄的 **執行日誌**裡，不需要跳轉到單獨的頁面或標籤頁。這一段預設展開：進行中的執行固定在最上面，已結束的收在 \*\*顯示歷史執行（N）\*\*下面。每一行會顯示觸發來源、執行智慧體、狀態和時間。如果沒看到這一段，用任務頂部的面板按鈕開啟右側欄；視窗較窄時它預設是收起的。

頁面保持開啟時，執行日誌通過即時連線自動更新 —— 新的執行、狀態變化和智慧體的評論都會直接出現，不需要手動重新整理。

智慧體工作期間，任務頂部還會出現一個即時狀態條，例如 "Engineer 在工作"。懸停就能看到同樣的進行中執行，不用離開當前頁面。

你可以在這裡：

-   點選某一行的 **檢視記錄**，檢視智慧體的訊息、工具呼叫和錯誤資訊。執行還在進行時，彈窗開啟期間內容會持續即時追加，也可以用 **最新在前**切換事件順序。
-   停止已安排稍後觸發、排隊、啟動、等待本地目錄或進行中的執行。
-   對失敗或已取消的執行發起重試。

修改任務的負責人或狀態不會停止已經開始的執行。需要中斷時，在執行日誌中停止對應的執行。刪除任務時，關聯的活動執行才會一併取消。

## 失敗與自動重試

執行時短暫離線、守護程序重啟、執行超時或 AI 程式設計工具網路中斷等臨時故障，可以觸發自動重試。普通執行預設最多執行兩次；工具網路中斷最多執行三次。

智慧體自身返回的錯誤通常不會自動重試。例如鑑權失效、額度不足、配置錯誤或模型無法完成請求，都需要先處理原因，再手動重試。

自動化的**僅執行**模式不會自動重試，以免和下一次計劃執行重疊。**建立任務**模式產生的是普通任務執行，基礎設施故障仍按上面的規則重試。兩種模式都可以在自動化執行歷史中檢視最終結果。

當一條任務上沒有其他活動執行，也沒有新的重試等待執行時，失敗會讓處於 `in_progress` 的任務回到 `todo`。

## 失敗原因參考

執行日誌和用量統計中常見的失敗原因分兩類：不帶字首的原因碼由平臺記錄；`agent_error.*` 由 AI 程式設計工具的報錯歸類而來。

**平臺側**

| 原因 | 含義 | 處理 |
| --- | --- | --- |
| `runtime_offline` | 執行期間執行時離線 | 恢復執行時後重試，見[守護程序與執行時](/docs/zh/daemon-runtimes) |
| `queued_expired` | 執行時心跳缺席超過重連寬限期，且該執行也已排隊滿這麼久 | 確認執行時線上後重試 |
| `runtime_recovery` | 守護程序重啟後回收了中斷的執行 | 直接重試 |
| `environment_prepare_failed` | 守護程序沒能準備好本次執行的執行環境——工作目錄，或寫入其中的本地執行時配置 | 先看原始錯誤定位是哪一步失敗，再檢查那臺機器：磁碟空間、許可權、目錄是否仍被佔用，或 AI 程式設計工具的本地配置 |
| `cancelled` | 被手動停止，或隨歸檔、刪除一併取消 | 無需處理 |
| `timeout` | 超過守護程序配置的執行時長上限 | 縮小任務範圍，或調整守護程序的 `agent_timeout` |
| `iteration_limit` | 達到執行輪次上限 | 縮小任務範圍 |
| `agent_blocked` | 智慧體主動報告無法繼續 | 按它在評論中的說明補充資訊 |
| `api_invalid_request` | 平臺 API 拒絕了非法請求 | 重試；反覆出現時報告問題 |
| `codex_semantic_inactivity` | Codex 長時間無有效輸出被判停滯 | 重試，或調整 Codex 停滯超時 |

**工具側（`agent_error.*`，字首省略）**

| 原因 | 含義 | 處理 |
| --- | --- | --- |
| `provider_auth_or_access` | 模型服務認證失敗或無訪問許可權（401/403） | 在該 AI 程式設計工具中重新登入，或檢查 API key |
| `provider_quota_limit` | 配額或餘額用盡（402） | 充值或更換賬號 |
| `provider_capacity_or_rate_limit` | 限流或容量不足（429/529） | 稍後重試 |
| `provider_server_error` | 模型服務端錯誤（5xx） | 稍後重試 |
| `provider_network` | 到模型服務的網路故障 | 會自動重試；持續出現時檢查執行電腦的網路 |
| `model_not_found_or_unavailable` | 模型不存在或當前不可用 | 在智慧體設定中改選可用模型 |
| `context_overflow` | 上下文超出模型視窗 | 縮小任務範圍或減少輸入內容 |
| `missing_config` | 缺少 API key 等必需配置 | 補齊智慧體環境變數或工具配置 |
| `runtime_missing_executable` | 找不到 AI 程式設計工具的執行檔 | 重新安裝該工具，見[安裝 AI 程式設計工具](/docs/zh/install-agent-runtime) |
| `runtime_version_unsupported` | AI 程式設計工具版本過舊 | 升級該工具 |
| `process_failure` | 工具程序異常退出 | 檢視執行日誌定位後重試 |
| `empty_or_unparseable_output` | 工具無輸出或輸出無法解析 | 重試；反覆出現時檢查工具安裝 |
| `agent_timeout` | 工具長時間無響應被終止 | 重試或縮小任務範圍 |
| `unknown` | 未能歸類的失敗 | 檢視執行日誌中的原始報錯 |

## 手動重試

在執行日誌中點選某一行的重試按鈕，會再次呼叫**當時負責這次執行的智慧體**。即使任務後來換了負責人，也不會改用新負責人。

重試會盡量保留上一次已經寫入本地目錄的檔案。如果原會話仍然安全，並且由同一個執行時領取，也會繼續之前的會話。上下文溢位或無效請求等會汙染會話的錯誤，則會在原工作目錄上開啟新會話。原目錄已經不存在時，會改用新的工作目錄。

也可以通過 CLI 重新運行當前任務：

```
multica issue rerun <issue-id>
```

這種方式沒有指定某一條歷史執行，因此會使用任務當前的智慧體負責人，並從新的會話和工作目錄開始。

## 執行完成與任務完成

`completed` 只表示這一次執行正常結束，不代表任務的目標已經得到確認。你仍然可以檢查結果、繼續討論、補充要求或再次觸發智慧體。

任務是否完成，以實際工作進展和它的狀態為準。

## 狀態與超時速查

以下數字對應伺服器的預設配置，供排查時快速對照。

| 狀態 | 含義 | 超時與後果 |
| --- | --- | --- |
| `deferred` | 已安排稍後觸發 | 到達預定時間後進入 `queued`，再按下面的規則計時 |
| `queued` | 等待執行時領取 | 只要執行時還在心跳就一直等待，並且無論如何都會在入隊後至少保留一個重連寬限期；兩個視窗都過去才會失敗，且不會自動重試 |
| `dispatched` | 執行時已領取，正在啟動工具 | 停留超過 **5 分鐘**按失敗處理 |
| `waiting_local_directory` | 等待本地目錄鎖釋放 | 沒有獨立超時；目錄釋放後回到啟動流程 |
| `running` | AI 程式設計工具正在執行 | 不設固定時長上限；以執行時心跳判定存活，心跳每 15 秒一次，失去心跳的執行時最遲約 3 分鐘被判為離線，其上的執行隨之失敗 |

自動重試只覆蓋以下臨時故障，且僅適用於掛在任務或對話上的執行（自動化**僅執行**模式除外）：

| 可自動重試的失敗原因 | 執行次數上限 |
| --- | --- |
| 執行時離線 | 預設 2 次（首次執行 + 1 次重試） |
| 守護程序重啟後回收 | 預設 2 次 |
| 平臺判定執行超時 | 預設 2 次 |
| Codex 長時間無有效輸出 | 預設 2 次 |
| Skill 包下載失敗 | 預設 2 次（此時智慧體程序尚未啟動，已下載的包走本地快取） |
| 工具網路中斷 | 最多 3 次，最後一次延遲約 5 秒發起 |

其餘失敗原因（鑑權、額度、配置、模型等）都不會自動重試，需要先處理原因再手動重試。
