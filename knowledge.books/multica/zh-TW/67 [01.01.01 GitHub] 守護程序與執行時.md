# 守護程序與執行時

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

瞭解 Multica 如何連線電腦、發現 AI 程式設計工具並執行。

Multica 負責記錄和協調工作，連線的電腦負責執行。電腦上的**守護程序**（daemon）領取執行，再呼叫本機安裝的 AI 程式設計工具。

## [概念區分](#%E6%A6%82%E5%BF%B5%E5%8C%BA%E5%88%86)

-   **守護程序**是執行在一臺電腦上的 Multica 後臺程式。它負責連線伺服器、發現本機工具、領取執行和回傳結果。
-   **執行時**代表一個工作區可以使用的具體執行環境。它對應一臺電腦，以及這臺電腦上的一款 AI 程式設計工具或自定義執行時配置。

例如，一臺電腦同時安裝了 Claude Code 和 Codex，並連線兩個工作區。守護程序會分別為兩個工作區註冊 Claude Code 和 Codex 執行時。重啟守護程序會更新原有記錄，不會為同一個組合不斷建立新執行時。

## [執行位置與資料邊界](#%E6%89%A7%E8%A1%8C%E4%BD%8D%E7%BD%AE%E4%B8%8E%E6%95%B0%E6%8D%AE%E8%BE%B9%E7%95%8C)

本地執行時呼叫的 AI 程式設計工具、這些工具自己的登入憑據，以及原生代碼目錄都留在連線的電腦上。Multica 伺服器不會代替本地工具執行命令，也不會自動上傳整個工作目錄。

為了讓團隊能夠協作，伺服器會儲存任務、評論、智慧體配置、執行上下文、執行記錄和智慧體寫回的結果。這些內容可能包含智慧體主動讀取並寫入回覆的程式碼片段或其他專案上下文。

智慧體的自定義環境變數儲存在伺服器側，並在執行時傳送給執行時。不要把"本地執行"理解為所有 secret 都只存在本機；自定義環境變數和 MCP 配置儲存在伺服器側，展示受敏感資訊規則限制。

## [啟動守護程序](#%E5%90%AF%E5%8A%A8%E5%AE%88%E6%8A%A4%E8%BF%9B%E7%A8%8B)

使用 Multica Desktop 時，應用會自動啟動守護程序，不需要額外執行命令。

使用 Web、遠端電腦或無介面環境時，先[安裝 Multica CLI](<84 [01.01.01 GitHub] 使用 CLI.md>)，再執行：

```
multica daemon start
```

守護程序預設在後臺執行。常用命令如下：

| 命令 | 作用 |
| --- | --- |
| `multica daemon status` | 檢視守護程序和連線狀態 |
| `multica daemon logs -f` | 持續檢視日誌 |
| `multica daemon restart` | 重啟守護程序並重新檢測本機工具 |
| `multica daemon stop` | 停止守護程序 |
| `multica daemon start --foreground` | 在當前終端中執行，便於除錯 |

如需把執行工作目錄放到其他磁碟，可用 `multica config set workspaces_root <path>` 為當前 profile 持久化根目錄，也可在 `daemon start` 或 `daemon restart` 中傳入 `--workspaces-root <path>`。flag 的優先順序高於 `MULTICA_WORKSPACES_ROOT`，環境變數又高於 profile 配置。修改根目錄不會遷移已有的執行目錄。

啟動時，守護程序會檢測 `PATH` 中受支援的 AI 程式設計工具，併為你有權連線的工作區註冊執行時。如果一款工具剛剛安裝或登入，重啟守護程序即可重新檢測。

守護程序至少需要檢測到一款內建支援的 AI 程式設計工具才能啟動。安裝方法和執行檔名見[安裝 AI 程式設計工具](<68 [01.01.01 GitHub] 安裝 AI 程式設計工具.md>)。

## [派發與線上狀態](#%E6%B4%BE%E5%8F%91%E4%B8%8E%E5%9C%A8%E7%BA%BF%E7%8A%B6%E6%80%81)

執行時註冊後會持續保持連線。新執行入隊時，伺服器會通知對應守護程序；守護程序也會定期輪詢，作為連線中斷後的補充。因此執行時線上且有空閒容量時，執行通常會立即開始。

守護程序每 15 秒傳送一次心跳。服務端綜合心跳與連線狀態判斷執行時是否線上；守護程序意外退出後，最遲通常會在約 3 分鐘內顯示為離線。

![一台在线电脑的运行时详情：同一守护进程注册了 7 个运行时，每款检测到的 AI 编程工具各占一行，均显示在线状态与 CLI 版本](<../images/1d44a804-image.webp>)

執行時離線時：

-   已經排隊的執行會等待執行時恢復，只有當它心跳缺席超過重連寬限期**且**該執行自己也已排隊滿這麼久時才會失敗；所以執行時只是忙的話積壓會一直保留，指派給已離線執行時的工作也仍然有完整一個寬限期可以等待。
-   正在執行的執行會失敗；符合條件的任務或對話執行可以自動重試。
-   守護程序重新啟動後，會重新註冊執行時，並回收上一次沒有正常結束的執行。
-   離線超過 7 天且沒有任何智慧體（包括已歸檔的）繫結的執行時，會被自動清理。

詳細狀態和重試規則見[執行](<66 [01.01.01 GitHub] 執行.md>)。

## [併發限制](#%E5%B9%B6%E5%8F%91%E9%99%90%E5%88%B6)

一臺守護程序預設最多同時執行 20 次執行；每個智慧體預設最多同時執行 6 次。實際併發取兩者中的較小值。

達到上限後，新執行會繼續排隊。你可以在智慧體設定中調整單個智慧體的併發數，也可以通過 `MULTICA_DAEMON_MAX_CONCURRENT_TASKS` 調整整臺電腦的上限。並行執行會同時佔用機器效能、工具賬號額度和同一工作目錄。

## [私有與公開](#%E7%A7%81%E6%9C%89%E4%B8%8E%E5%85%AC%E5%BC%80)

本地執行時預設是**私有**的：只有執行時所有者可以在它上面建立智慧體。工作區的 owner、admin 也不例外——執行時是別人的電腦，在上面跑智慧體消耗的是對方的機器和工具憑據。

只有執行時所有者可以把它改為**公開**——管理員可以重新命名或刪除執行時，但要不要共享由所有者決定。公開後，工作區中的其他成員也可以選擇這條執行時；這不會分享底層 AI 程式設計工具的登入憑據，只是允許成員把智慧體的執行路由到這臺電腦。

## [自定義執行時配置](#%E8%87%AA%E5%AE%9A%E4%B9%89%E8%BF%90%E8%A1%8C%E6%97%B6%E9%85%8D%E7%BD%AE)

如果團隊使用內部 wrapper、固定版本的執行檔，或需要為一款相容工具追加固定引數，可以建立**自定義執行時配置**。

自定義配置不會增加新的通訊協議。建立時仍需選擇一種 Multica 已支援的協議族（工具的對接協議型別，見 [AI 程式設計工具對照](<69 [01.01.01 GitHub] AI 程式設計工具對照.md>)）；命令本身必須與該協議相容。

### [Task 執行時環境](#task-%E8%BF%90%E8%A1%8C%E6%97%B6%E7%8E%AF%E5%A2%83)

守護程序啟動智慧體 task 時，會把 task 上下文注入執行時程序。這些值由守護程序管理；智慧體的自定義環境無法覆蓋任何 `MULTICA_` 變數或 task 臨時目錄變數。

下表列出自定義執行時目前可以使用的變數。它不是完整清單，也不是有版本保證的 API。整合只能依賴標為**整合契約**的 5 個變數；其餘變數僅供參考，後續可能變化。

| 變數 | task 中的值 | 穩定性 |
| --- | --- | --- |
| `MULTICA_TOKEN` | task 級 `mat_` API 憑據 | **整合契約** |
| `MULTICA_TASK_ID` | 當前 task 的 ID | **整合契約** |
| `MULTICA_AGENT_ID` | 被指派智慧體的 ID | **整合契約** |
| `MULTICA_WORKSPACE_ID` | task 所屬工作區的 ID | **整合契約** |
| `MULTICA_SERVER_URL` | 守護程序選定的 Multica 服務地址 | **整合契約** |
| `MULTICA_TASK_CONFIG_ROOT` | 私有的 task 本地 Multica CLI 配置根目錄 | 僅供參考 |
| `MULTICA_TASK_WORKSPACES_ROOT` | 守護程序管理的 task 工作區根目錄 | 僅供參考 |
| `MULTICA_AGENT_NAME` | 被指派智慧體的顯示名稱 | 僅供參考 |
| `MULTICA_DAEMON_PORT` | 本地守護程序的健康檢查/API 埠，供 `multica repo checkout` 等僅限 task 的命令使用 | 僅供參考 |
| `MULTICA_TASK_SLOT` | 守護程序全域併發池中的槽位，可用於 GPU 等按槽位編號的資源 | 僅供參考 |
| `TMPDIR` | 當前 task 的私有臨時目錄；也會以 `TMP` 和 `TEMP` 提供給跨平臺工具 | 僅供參考 |

使用 `MULTICA_TOKEN` 發起請求時，作者身份由服務端決定；任務評論等寫入操作會歸屬到被指派的智慧體和當前 task。令牌的完整繫結關係、許可權、歸屬方式、最長 24 小時的有效期和清理規則見[智慧體執行的臨時令牌](<85 [01.01.01 GitHub] 認證與令牌.md#%E6%99%BA%E8%83%BD%E4%BD%93%E6%89%A7%E8%A1%8C%E7%9A%84%E4%B8%B4%E6%97%B6%E4%BB%A4%E7%89%8C>)。

這些值存在於執行時程序的實際環境中。執行時啟動的任何子程序預設都會繼承全部變數，包括 `MULTICA_TOKEN`。如果子程序不應持有該憑據，必須顯式移除；不要假定程序之間存在並沒有的隔離。反過來，有些工具會過濾自己的子程序環境，因此可能需要顯式放行變數。例如，Codex 的 shell 工具會丟棄名稱中含有 `TOKEN`、`KEY` 或 `SECRET` 的變數，所以守護程序會安裝託管的 shell 策略，放行所需的 task 變數。令牌只能存在於程序環境中，不得寫入 prompt、日誌、倉庫檔案或持久配置。子程序與父 task 共享身份和許可權，不會獲得新的獨立作用域身份。

### [建立配置](#%E5%88%9B%E5%BB%BA%E9%85%8D%E7%BD%AE)

只有工作區 owner 和 admin 可以建立、修改或刪除自定義執行時配置：

1.  開啟 **執行時**，進入已經安裝該命令的電腦。
2.  點選**新增自定義執行時**。
3.  選擇命令實際相容的協議族。
4.  填寫名稱、命令和固定引數，然後儲存。

配置會在工作區內共享。每臺已連線電腦會自行查詢這個命令；只有能在 `PATH` 中解析到它的電腦才會註冊對應執行時。建立配置不會自動安裝命令，也不會替其他成員完成工具登入。

這裡填寫的是執行檔和引數，不是 shell 指令碼。可以使用普通引數、引號和反斜槓轉義，但不能使用管道、重定向、`&&`、`;`、反引號或環境變數展開。需要這些行為時，把它們放進 wrapper script，再把該指令碼作為命令填寫。

### [引數的排列順序](#%E5%8F%82%E6%95%B0%E7%9A%84%E6%8E%92%E5%88%97%E9%A1%BA%E5%BA%8F)

命令欄位裡填寫的內容會緊跟在執行檔之後，排在 Multica 追加的引數之前：

```
<你的命令> <你的固定参数> <Multica 的协议参数> <Agent 的自定义参数>
```

帶子命令的 wrapper 正是依靠這個順序才能工作。如果命令是 `ccms start q36`，工具會先看到 `start q36`，在 Multica 的 `-p` 等引數到達之前完成子命令選擇——這類 wrapper 只接受這一種順序。

此前這裡填寫的引數是追加在最後的。多數 flag 形式的命令在兩種位置下解析結果相同，但並非全部——如果某個命令區分全域 flag 和子命令 flag，它就會在意 flag 的位置。如果你已經配置了帶固定引數的 profile，升級後請發起一次執行，確認它仍能正常啟動。

另有兩點需要注意：

-   **衝突時以 Multica 的值為準。** 如果固定引數設定了 Multica 也會設定的 flag，Multica 的值排在後面並最終生效。最典型的是：在 Agent 上選擇的模型會覆蓋 profile 裡固定的 `--model`。若要為所有人固定模型，請把 Agent 的模型欄位留空。
-   **協議關鍵 flag 會被忽略。** `-p`、`--output-format`、`--input-format`、`--permission-mode` 以及其他協議族的對應 flag 會從固定引數中被剔除，因為覆蓋它們會切斷 daemon 與工具之間的通訊。子命令和其他位置引數始終原樣傳遞。

如果 Desktop 啟動的守護程序找不到終端裡能夠執行的命令，可以為當前電腦設定絕對路徑：

```
multica runtime profile set-path <profile-id> --path /absolute/path/to/command
```

移除路徑覆蓋：

```
multica runtime profile unset-path <profile-id>
```

修改配置隻影響之後領取的執行。刪除配置前，需要先處理仍繫結在對應執行時上的活動智慧體。只刪除某臺電腦上的執行時例項並不會刪除配置，執行中的守護程序還會重新註冊它。

## [執行時離線的排查](#%E8%BF%90%E8%A1%8C%E6%97%B6%E7%A6%BB%E7%BA%BF%E7%9A%84%E6%8E%92%E6%9F%A5)

按以下順序檢查：

1.  執行 `multica daemon status`，確認守護程序已經啟動。
2.  執行 `multica daemon logs -f`，檢視登入、網路或工具檢測錯誤。
3.  在同一執行環境中執行 `command -v <工具命令>`，確認守護程序能夠找到它。
4.  開啟 Multica 的**執行時**頁面，檢查目標電腦和對應的 AI 程式設計工具是否顯示線上。
5.  工具剛安裝、路徑剛修改或配置剛更新時，執行 `multica daemon restart`。

仍未解決時，參見[故障排查](<83 [01.01.01 GitHub] 故障排查.md>)。
