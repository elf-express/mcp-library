# 建立和配置智慧體

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

選擇起點，定義智慧體的職責、能力、執行方式和 Access。

建立智慧體前，需要先有一個可用的[執行時](<67 [01.01.01 GitHub] 守護程序與執行時.md>)。執行時決定這名智慧體使用哪臺電腦和哪款 AI 程式設計工具；智慧體則儲存它長期使用的身份、指令和能力。

在工作區的 **智慧體** 頁面點 **新建智慧體**。

## [選擇起點](#%E9%80%89%E6%8B%A9%E8%B5%B7%E7%82%B9)

建立頁面提供兩種方式：

| 方式 | 適合什麼情況 |
| --- | --- |
| **從空白開始** | 已經知道智慧體的職責，想自己填寫每項配置。 |
| **通過 AI 建立** | 先描述目標，讓 Agent Builder 追問關鍵資訊並生成草稿。 |

通過 AI 建立需要一個線上執行時來完成 Builder 對話。無論選擇哪種方式，建立前都可以檢查並修改最終配置。

![创建智能体的起点选择页：Start blank 与 Build with AI](<../images/9f208c98-image.webp>)

## [必填項](#%E5%BF%85%E5%A1%AB%E9%A1%B9)

建立智慧體只要求兩項：

-   **名稱**：在當前工作區中必須唯一。
-   **執行時**：選擇實際執行的環境。

其他欄位可以先使用預設值，建立後再調整。新智慧體預設只有建立者可以執行。

## [描述與指令](#%E6%8F%8F%E8%BF%B0%E4%B8%8E%E6%8C%87%E4%BB%A4)

**描述**是寫給團隊看的簡短介紹，只顯示在智慧體列表和詳情中，不會進入 AI 程式設計工具的提示。

**指令**會在每次執行時提供給智慧體，通常包含：

-   它負責什麼、不負責什麼；
-   收到工作後先檢查什麼；
-   允許修改哪些內容；
-   結果的提交方式；
-   什麼時候需要向成員確認。

例如：

```
你负责审查前端 Pull Request。

先阅读改动和相关测试，只检查：
- React 与 TypeScript 的正确性
- 可访问性
- 与现有组件模式是否一致

不要直接修改代码。把问题按严重程度写在 issue 评论中；
没有阻塞问题时，明确说明可以合并。
```

## [新增 skill](#%E6%B7%BB%E5%8A%A0-skill)

建立時可以從工作區選擇一個或多個 [skill](<58 [01.01.01 GitHub] Skills.md>)。

Skill 適合儲存可以跨智慧體複用的方法和資料；只屬於這名智慧體的長期要求寫在指令中。

## [對話開場建議](#%E5%AF%B9%E8%AF%9D%E5%BC%80%E5%9C%BA%E5%BB%BA%E8%AE%AE)

最多新增三條**對話開場建議**，讓使用者在傳送第一條訊息前瞭解這個智慧體擅長什麼。它們出現在別人與該智慧體開始新對話時，位於輸入框上方。每項包含一個簡短標題和一條完整提示詞。選擇後只會填入輸入框，使用者可以先檢查或修改，不會自動開始執行。

編輯器下方會預覽新對話的實際效果；有編輯許可權的人還會在那個空狀態裡看到**自定義開場建議**入口，點選可直接跳回這裡。

留空時，對話頁會顯示本地化的通用預設值。針對智慧體職責和邊界編寫的示例通常更有幫助。

CLI 可用 `agent create` / `agent update` 的 `--conversation-starters` 設定（`{"label","prompt"}` 物件的 JSON 陣列；更新時傳 `'[]'` 清空）。`agent copy` 仍只搬運源值，沒有覆蓋 flag。

## [選擇執行時、模型和思考強度](#%E9%80%89%E6%8B%A9%E8%BF%90%E8%A1%8C%E6%97%B6%E6%A8%A1%E5%9E%8B%E5%92%8C%E6%80%9D%E8%80%83%E5%BC%BA%E5%BA%A6)

執行時已經對應一款 AI 程式設計工具。選擇執行時後，可以繼續選擇該工具支援的模型和思考強度；部分工具（如 Codex）還可選擇速度檔：

-   留空時，使用執行時或本地 CLI 的預設配置。
-   設定模型後，該智慧體之後領取執行時會使用這個覆蓋值。
-   某些執行時自行管理模型，因此不會顯示模型選擇。

不同工具支援的模型、會話恢復、skill 和 MCP 能力不同，見[AI 程式設計工具對照](<69 [01.01.01 GitHub] AI 程式設計工具對照.md>)。

## [設定 Access](#%E8%AE%BE%E7%BD%AE-access)

Access 決定哪些成員可以執行這名智慧體（分配、@提及或對話）：

| Access | 含義 |
| --- | --- |
| **僅自己**（Only me） | 只有你可以執行。預設選項。 |
| **整個工作區**（Entire workspace） | 所有工作區成員都可以執行。 |
| **指定成員**（Specific people） | 只有你和選中的成員可以執行。 |

![Access 设置：仅自己、整个工作区、指定成员三档](<../images/1070d7b7-image.webp>)

只有智慧體 owner 可以修改 Access，工作區管理員也不行。工作區 `owner` 和 `admin` 可以管理其他配置，但不能借管理員身份執行未授權的智慧體。

## [建立後的配置項](#%E5%88%9B%E5%BB%BA%E5%90%8E%E7%9A%84%E9%85%8D%E7%BD%AE%E9%A1%B9)

開啟智慧體詳情頁，可以繼續調整：

| 配置 | 作用 |
| --- | --- |
| **併發上限** | 同一名智慧體最多同時執行多少次執行，預設是 6；達到上限後繼續排隊。 |
| **環境變數** | 在 AI 程式設計工具啟動時注入變數。 |
| **自定義引數** | 逐項追加到 AI 程式設計工具的 CLI 引數中。 |
| **MCP** | 為支援的 AI 程式設計工具提供 MCP server 配置。 |
| **整合** | 連線這名智慧體可以使用的外部服務。 |

執行時所在的守護程序還有一個全域併發上限（預設 20），實際併發取兩者中的較小值。

修改配置不會改變已經開始的執行。後續執行被執行時領取時，會使用當時儲存的智慧體配置。

## [環境變數與憑據](#%E7%8E%AF%E5%A2%83%E5%8F%98%E9%87%8F%E4%B8%8E%E5%87%AD%E6%8D%AE)

環境變數適合放這名智慧體執行時需要的有限許可權憑據，例如只讀 API key 或單一 scope 的 token。

**`custom_env` 的值在 Multica 伺服器的資料庫裡是明文儲存的**，不屬於"只留在本機"的資料。agent list/get 介面不再返回任何 env 值，只返回鍵的數量；只有工作區 `owner`、`admin` 可以解鎖和修改，並且每次讀取或修改都會留下審計記錄。執行中的智慧體不能呼叫管理介面讀取其他智慧體的變數。

不要使用生產資料庫的管理員密碼或其他高價值長期憑據。

`PATH`、`HOME` 和 `MULTICA_*` 等執行環境關鍵變數不能通過這裡覆蓋。

## [自定義引數和 MCP](#%E8%87%AA%E5%AE%9A%E4%B9%89%E5%8F%82%E6%95%B0%E5%92%8C-mcp)

自定義引數按陣列逐項傳給 AI 程式設計工具，不經過 shell 展開。引數名稱是否有效由對應工具決定；已有獨立欄位的模型配置不需要在這裡重複設定。

不要把憑據或其他 secret 放進自定義引數。它們會留在子程序的 argv 中，同機其他程序可能通過 `ps` 或 `/proc` 看到；請改用環境變數（`custom_env`）。守護程序日誌會遮蔽引數值，但無法保護作業系統的程序列表。

MCP 配置可能包含 token，儲存與展示規則和環境變數相同。只有支援託管 MCP 配置的執行時會顯示這一項；不支援的工具不會因為儲存了配置就自動獲得 MCP 能力。

## [複製智慧體](#%E5%A4%8D%E5%88%B6%E6%99%BA%E8%83%BD%E4%BD%93)

複製會帶上名稱之外的大部分工作配置，包括指令、對話開場建議、skill、自定義引數、頭像、併發上限和 Access 設定。模型、思考強度和速度檔也會一併帶走；如果原執行時不可用、複製被迫換到其他執行時，這三項會清空，需要重新選擇。

環境變數的值和 MCP 配置在任何情況下都不會複製，需要在新智慧體中重新設定。複製會保留原智慧體的執行時繫結和 Access 設定。

## [使用 CLI 建立](#%E4%BD%BF%E7%94%A8-cli-%E5%88%9B%E5%BB%BA)

```
multica agent create \
 --name "Frontend Reviewer" \
 --runtime-id <runtime-id> \
 --description "审查前端 Pull Request" \
 --instructions "先阅读改动和测试，只在 issue 评论中提交审查结论。" \
 --conversation-starters '[{"label":"审查 PR","prompt":"审查当前最相关的未合并 Pull Request。"}]'
```

命令列引數中的明文會進入 shell 歷史；stdin 和許可權受限的檔案不會。

已有配置相近的智慧體時，可以直接複製：

```
multica agent copy <agent-id>
```

預設複製到同一執行時；加 `--runtime-id` 換到其他執行時，必須同時指定 `--model`。環境變數、MCP 配置和 `runtime_config` 永不復制；執行時繫結本身會保留。完整引數見[使用 CLI](<84 [01.01.01 GitHub] 使用 CLI.md>)。
