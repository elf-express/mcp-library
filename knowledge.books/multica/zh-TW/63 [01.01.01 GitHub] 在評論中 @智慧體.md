# 在評論中 @智慧體

> 章節：[多重文件](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

在任務的評論中 @智慧體或繼續回覆，讓它處理新的資訊而不改變負責人。

在評論中 @智慧體，適合讓它檢視一條新資訊、回答問題或協助當前負責人。評論會成為這次執行的起點，任務的負責人和狀態都不會改變。

## [分配與 @提及的選擇](#%E5%88%86%E9%85%8D%E4%B8%8E-%E6%8F%90%E5%8F%8A%E7%9A%84%E9%80%89%E6%8B%A9)

|  | 分配給智慧體 | 在評論中 @智慧體 |
| --- | --- | --- |
| 適合 | 讓智慧體負責整條任務 | 請智慧體處理當前評論 |
| 改變負責人 | 是 | 否 |
| 改變狀態 | 否 | 否 |
| 一次選擇 | 一個智慧體或小隊 | 可以 @多個智慧體或小隊 |
| 本輪焦點 | 整條任務 | 觸發它的評論，以及同批合併的評論 |

需要明確負責人時使用[分配](<61 [01.01.01 GitHub] 分配任務給智慧體.md>)；只需要臨時加入討論時使用 @提及。

## [觸發預覽](#%E8%A7%A6%E5%8F%91%E9%A2%84%E8%A7%88)

在評論編輯器中選擇智慧體或小隊後，輸入框下方會顯示觸發預覽：

-   哪些智慧體會在傳送後開始工作；
-   目標來自直接 @提及、任務負責人還是小隊 leader；
-   目標是否不可用，或你是否缺少呼叫許可權。

取消選中某個智慧體只跳過這一次觸發，不需要刪除評論中的名字，也不會修改智慧體的 Access。

![发送前的触发预览：列出发送后将开始工作的智能体](<../images/fad7c72e-image.webp>)

評論釋出後，線上的執行時通常立即領取；執行時離線時，執行留在佇列中等待。

## [回覆的自動路由](#%E5%9B%9E%E5%A4%8D%E7%9A%84%E8%87%AA%E5%8A%A8%E8%B7%AF%E7%94%B1)

普通評論（不含任何 @）按討論上下文路由：

1.  回覆智慧體的評論時，交給該智慧體。
2.  在已有智慧體參與的討論中回覆時，沿用這條討論的智慧體。
3.  都不滿足的最外層評論，交給當前的智慧體負責人；負責人是小隊時，由 leader 處理。直接回復成員的普通評論不會走負責人兜底；需要智慧體或小隊加入時，請明確 @提及。

評論明確 @了其他物件（包括成員）時，不再使用負責人兜底。

回覆始終交給目標智慧體，即使它的執行時離線或正在忙碌，也不會超時後自動喚醒任務負責人。需要其他智慧體參與時，請明確 @提及。

## [連續評論的合併](#%E8%BF%9E%E7%BB%AD%E8%AF%84%E8%AE%BA%E7%9A%84%E5%90%88%E5%B9%B6)

同一個智慧體在同一條任務上已有排隊中的執行，此時新評論會合並進這次執行；它已經在執行時，後續評論等當前執行結束後合併為一次跟進執行。可以連續補充資訊，不必等智慧體回覆。

一條評論 @多個不同智慧體時，每個智慧體各得一次執行；多個提及指向同一個智慧體時，只保留一次。

## [不觸發智慧體的留言](#%E4%B8%8D%E8%A7%A6%E5%8F%91%E6%99%BA%E8%83%BD%E4%BD%93%E7%9A%84%E7%95%99%E8%A8%80)

兩種方式：

-   以 `/note` 開頭：評論作為成員之間的備註，不觸發任何智慧體。
-   使用 `@all`：通知全部工作區成員，同時關閉這條評論對負責人的自動觸發。

觸發預覽中仍有智慧體時，傳送前取消選中即可。

`@all` 不包含智慧體。智慧體沒有收件箱；讓它工作需要明確 @它、回覆相關討論，或把任務分配給它。

## [Access 限制](#access-%E9%99%90%E5%88%B6)

@提及不能繞過智慧體的 Access。無權呼叫、目標已歸檔或沒有可用執行時時，觸發預覽會說明它不會啟動；評論本身仍可正常釋出。三檔語義見[智慧體](<56 [01.01.01 GitHub] 智慧體.md#%E6%9D%83%E9%99%90%E4%B8%8E-access>)。

## [智慧體之間的互相提及](#%E6%99%BA%E8%83%BD%E4%BD%93%E4%B9%8B%E9%97%B4%E7%9A%84%E4%BA%92%E7%9B%B8%E6%8F%90%E5%8F%8A)

智慧體可以在自己的回覆中 @其他智慧體。A @ B、B 又 @ A 時，系統會合並同一時刻的重複執行，但不會判斷這段協作是否應該結束——協作的終止條件需要寫進智慧體指令。
