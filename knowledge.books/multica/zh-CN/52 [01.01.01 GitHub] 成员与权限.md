# 成员与权限

> 章節：[Multica Docs](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

邀请成员，并用 owner、admin 和 member 三种角色管理工作区权限。

加入[工作区](<51 [01.01.01 GitHub] 工作区.md>)的人都是成员，每位成员有一个角色：`owner`、`admin` 或 `member`。角色只控制工作区设置和团队管理；创建任务、发表评论等日常协作对所有成员开放。

## [三种角色](#%E4%B8%89%E7%A7%8D%E8%A7%92%E8%89%B2)

| 操作 | owner | admin | member |
| --- | --- | --- | --- |
| 查看工作区并参与日常协作 | ✓ | ✓ | ✓ |
| 修改工作区设置 | ✓ | ✓ | — |
| 邀请 `admin` 或 `member` | ✓ | ✓ | — |
| 调整或移除 `admin`、`member` | ✓ | ✓ | — |
| 授予、收回或移除 `owner` | ✓ | — | — |
| 删除工作区 | ✓ | — | — |

工作区必须始终保留至少一名 `owner`：最后一名 `owner` 不能被降级、移除或离开。

角色不决定谁能运行智能体。每个智能体有独立的访问范围（Access），`owner` 和 `admin` 也不能绕过它运行未授权的智能体。详见[智能体](<56 [01.01.01 GitHub] 智能体.md#%E6%9D%83%E9%99%90%E4%B8%8E-access>)。

## [邀请成员](#%E9%82%80%E8%AF%B7%E6%88%90%E5%91%98)

`owner` 和 `admin` 在设置 → 成员中输入邮箱、选择角色后发送邀请。邀请只能授予 `admin` 或 `member`；`owner` 需要先加入工作区，再由现有 `owner` 提升。

![成员管理：邀请表单与带角色的成员名册](<../images/8ce6e50d-image.webp>)

受邀者用该邮箱登录即可接受，无需提前注册。邀请有效期 7 天，过期后重新发送。在限制注册的自部署实例中，待接受且未过期的邀请允许该邮箱创建账号，无需另外加入白名单，见[登录与注册](<82 [01.01.01 GitHub] 登录与注册.md#%E9%82%80%E8%AF%B7%E4%B8%8E%E6%B3%A8%E5%86%8C%E9%99%90%E5%88%B6>)。

邀请链接只出现在邮件里，产品界面中没有查看或复制它的入口。邮件发送失败时邀请记录仍然存在，可以撤销后重新发送。

## [调整角色](#%E8%B0%83%E6%95%B4%E8%A7%92%E8%89%B2)

`admin` 可以在 `admin` 和 `member` 之间调整角色，也可以移除这两类成员。涉及 `owner` 的变更——提升、更改或移除——只有 `owner` 能执行。

角色变化立即生效。

## [移除成员](#%E7%A7%BB%E9%99%A4%E6%88%90%E5%91%98)

被移除的成员立即失去工作区访问权限。该成员创建的任务、评论和其他协作记录保留在工作区中。

移除成员会同时停用该成员拥有的运行时、归档绑定在其上的智能体，并取消尚未结束的运行。该成员在智能体访问范围（Access）中获得的授权也会被清除，重新加入后不会自动恢复。
