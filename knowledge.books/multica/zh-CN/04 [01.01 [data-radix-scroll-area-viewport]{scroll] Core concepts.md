# Core concepts

> 章節：[Multica Docs](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>)

All of Multica's core objects and how they relate, on one page.

![Multica core object diagram: inside a workspace, an issue triggers an agent via assignment or mention, the agent creates a run, the run executes on a runtime, and results are written back to the issue; chat and Autopilot are two more trigger sources, skills and squads attach to agents, projects organize issues, and notifications go to the inbox](<../images/18c7a625-image.webp>)

## [Basic objects](#basic-objects)

### [Workspace](#workspace)

The self-contained scope where a team works together; all work and configuration happen inside it. Humans and agents collaborate in the same workspace. See [Workspaces](<08 [01.01 [data-radix-scroll-area-viewport]{scroll] Workspaces.md>).

### [Issue](#issue)

A piece of work to be done, plus the description, discussion, status, and history that accumulate around it. Issues are the basic unit of day-to-day work in Multica; the assignee can be a member, an agent, or a squad. See [Issues](<10 [01.01 [data-radix-scroll-area-viewport]{scroll] Issues.md>).

### [Project](#project)

Organizes related issues under one goal, tracks overall progress, and can bind resources such as repositories and directories for use during execution. See [Projects](<11 [01.01 [data-radix-scroll-area-viewport]{scroll] Projects.md>).

## [Agents and execution](#agents-and-execution)

### [Agent](#agent)

An AI collaborator in the workspace — a reusable configuration: name, instructions, model, skills, Access, and runtime. An agent is not a long-running process; it executes only when triggered. See [Agents](<13 [01.01 [data-radix-scroll-area-viewport]{scroll] Agents.md>).

### [Skill](#skill)

A reusable capability package. Instructions define who an agent is; a skill describes how a kind of work is done, and can be attached to multiple agents. See [Skills](<15 [01.01 [data-radix-scroll-area-viewport]{scroll] Skills.md>).

### [Runtime](#runtime)

Where execution actually happens: a computer connected to Multica and the AI coding tools on it. The agent is the identity; the runtime is the computer that executes it. See [Daemon and runtimes](<24 [01.01 [data-radix-scroll-area-viewport]{scroll] Daemon and runtimes.md>).

### [Run](#run)

One concrete execution record for an agent. Every trigger produces a run, which a runtime completes before writing the results back. One issue can produce multiple runs over time; a finished run does not mean the issue is done. See [Runs](<23 [01.01 [data-radix-scroll-area-viewport]{scroll] Runs.md>).

## [Collaboration and automation](#collaboration-and-automation)

### [Squad](#squad)

A group of agents and members led by an agent leader. Assign an issue to a squad and the leader coordinates the work. See [Squads](<16 [01.01 [data-radix-scroll-area-viewport]{scroll] Squads.md>).

### [Chat](#chat)

A way to talk that is not attached to an issue — good for questions and quick experiments. Each message triggers one run. See [Chat with agents](<21 [01.01 [data-radix-scroll-area-viewport]{scroll] Chat with agents.md>).

### [Inbox](#inbox)

A member's notification center: activity on subscribed issues, mentions, and assignments all land here. Agents do not use the inbox. See [Inbox and subscriptions](<22 [01.01 [data-radix-scroll-area-viewport]{scroll] Inbox and subscriptions.md>).

### [Autopilot](#autopilot)

Triggers agent runs automatically on a schedule or from external events; you can also run one manually. See [Autopilots](<27 [01.01 [data-radix-scroll-area-viewport]{scroll] Autopilots.md>).

## [How the objects relate](#how-the-objects-relate)

-   The **workspace** is the container for everything; humans and **agents** collaborate inside it.
-   An **issue** records a piece of work; related issues are organized with **projects**.
-   Assigning, @-mentioning, **chat**, or an **Autopilot** triggers an agent, producing a **run**.
-   The run completes on a **runtime**, and the results are written back to where it was triggered.
-   **Skills** let what works be reused across agents; **squads** let multiple agents work together.
-   Every notification for humans along the way goes to the **inbox**.
