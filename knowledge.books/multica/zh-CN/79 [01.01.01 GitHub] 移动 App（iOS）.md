# 移动 App（iOS）

> 章節：[Multica Docs](<000 目錄.md#c-1>) › [data-radix-scroll-area-viewport{scrollbar-width:none;-ms-o](<000 目錄.md#c-2>) › [GitHub](<000 目錄.md#c-3>)

从源码把 Multica 安装到 iPhone，并连接 Cloud 或自托管实例。

Multica iOS 客户端目前还没有上架 App Store。你可以在 Mac 上从公开的源码仓库构建 Release 版本，再安装到自己的 iPhone。Android 客户端暂未提供。

安装后的 App 默认连接 Multica Cloud，使用已有账号即可登录。工作区、任务、评论和执行记录都保存在服务端，不需要从 Web 或 Desktop 手动同步。

## [准备工作](#%E5%87%86%E5%A4%87%E5%B7%A5%E4%BD%9C)

你需要：

-   一台安装了 Xcode 的 Mac；
-   已在 **Xcode → Settings → Accounts** 中登录的 Apple ID；
-   一台通过 USB 连接的 iPhone；
-   在 iPhone 的**设置 → 隐私与安全性**中打开开发者模式；
-   Node.js、pnpm 和 Git。

Xcode 或真机开发环境未配置时，先完成 Expo 的 [iOS Device 环境配置](https://docs.expo.dev/get-started/set-up-your-environment/)。

## [安装到 iPhone](#%E5%AE%89%E8%A3%85%E5%88%B0-iphone)

克隆仓库并安装依赖：

```bash
git clone https://github.com/multica-ai/multica.git
cd multica
pnpm install
```

然后从仓库根目录运行：

```bash
pnpm ios:mobile:device:prod:release
```

这会构建一个不依赖 Metro 的 Release 版本，并安装到已连接的 iPhone。第一次构建需要下载 iOS 依赖并编译 React Native，之后会复用 Xcode 缓存。

如果 iPhone 阻止打开应用，到**设置 → 通用 → VPN 与设备管理**中信任对应的开发者证书。

## [免费签名的 7 天限制](#%E5%85%8D%E8%B4%B9%E7%AD%BE%E5%90%8D%E7%9A%84-7-%E5%A4%A9%E9%99%90%E5%88%B6)

免费 Apple ID 签名的 App 只能使用 7 天。到期后，把 iPhone 重新连接到 Mac，并再次运行同一条构建命令即可续签。

Apple Developer Program 账号签名的有效期更长，也可以用于 TestFlight 和正式分发。无论使用哪种签名，服务端数据都不会因为重新安装或续签而丢失。

## [签名失败](#%E7%AD%BE%E5%90%8D%E5%A4%B1%E8%B4%A5)

如果 Xcode 提示 `No matching provisioning profiles found`，默认 bundle identifier 可能不属于你的 Apple ID。换成自己控制的反向域名后重新构建：

```bash
export EXPO_BUNDLE_IDENTIFIER_PROD=com.yourname.multica
pnpm ios:mobile:device:prod:release
```

这个值只需要在你的 Apple Developer team 中可用，不影响 Multica 账号或工作区。

## [更新](#%E6%9B%B4%E6%96%B0)

iOS 自助安装版不会自动更新。拉取最新代码、更新依赖并重新构建：

```bash
git pull --ff-only
pnpm install
pnpm ios:mobile:device:prod:release
```

## [连接自托管实例](#%E8%BF%9E%E6%8E%A5%E8%87%AA%E6%89%98%E7%AE%A1%E5%AE%9E%E4%BE%8B)

Release 构建会把 API 地址写入 App。`apps/mobile/.env.production` 已随仓库提交，默认指向 multica.ai 的公开后端，干净克隆即可构建生产版本。

要连接自托管实例，把 `apps/mobile/.env.production.example` 复制为 `apps/mobile/.env.production.local` 并修改副本：

```
EXPO_PUBLIC_API_URL=https://api.example.com
EXPO_PUBLIC_WEB_URL=https://app.example.com
```

`.local` 文件会按 key 覆盖提交的默认值，且已被 gitignore，个人 API 地址不会进入仓库。`EXPO_PUBLIC_API_URL` 必填；`EXPO_PUBLIC_WEB_URL` 用于 "Copy link"、"Open on web" 等入口。两个都要在副本里设置：没写的 key 会沿用 multica.ai 的默认值，这些入口就会打开 multica.ai，而不是你的实例。

修改后重新运行构建命令。iPhone 必须能访问这个 API 地址；使用局域网地址时，不要写 `localhost`，因为它在 iPhone 上指向手机本身。

直接修改 `.env.production` 会改变当前 checkout 的生产配置。个人配置请放在 gitignore 的 `.env.production.local` 中。

开发移动端、使用 Simulator 或连接 staging 的说明见仓库中的 [`apps/mobile/README.md`](https://github.com/multica-ai/multica/blob/main/apps/mobile/README.md)。
