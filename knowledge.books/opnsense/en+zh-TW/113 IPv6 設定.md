## [Introduction](#id4)｜[引言](#id4)

To this day IPv6 remains an elusive topic. IPv6 has long been shipped as a default option in OPNsense and received gradual improvements over the years, but configuration complexity, ISP problems and sometimes also software bugs can cause connectivity to fail or not establish at all. This guide aims to provide groundwork for how IPv6 can be configured and how to spot known mistakes and troubleshoot connectivity.

時至今日，IPv6 仍然是一個難以捉摸的話題。 OPNsense 早已將 IPv6 作為預設選項，並在這些年中不斷改進，但配置的複雜性、 ISP問題以及有時出現的軟體漏洞都可能導致連線失敗或根本無法建立連線。本指南旨在為如何設定 IPv6、如何發現已知錯誤以及如何排除連線故障提供基礎知識。

When talking about external and internal interfaces this guide uses “WAN”（VAN） and “LAN”（和）, not excluding the possibility for multiple interfaces on each side being used at the same time.

本指南在討論外部和內部介面時使用“WAN”（VAN）和“LAN”（和） ，但不排除同時使用每一邊多個介面的可能性。

Note this guide will not cover NAT on IPv6 for simplicity’s sake.

為了簡單起見，請注意本指南不會涵蓋 IPv6 上的NAT 。

## [Technical background](#id5)｜[技術背景](#id5)

### [Overview](#id6)｜[概述](#id6)

When digging into IPv6, a lot of differences between IPv4 come to light, which is practical to be aware of when debugging issues. In this chapter we want to explain some of the most relevant building blocks in IPv6 networks.

深入研究 IPv6 時，會發現它與 IPv4 有許多不同之處，了解這些差異對於偵錯問題非常實用。本章我們將解釋 IPv6 網路中一些最相關的基本組成部分。

![](<../images/69610cfd-seqdiag-5e7d7575cb746bc602818fdaec96a0d7.png>)

WAN configuration flow (most common)

WAN配置流程（最常見）

*In the sequence diagram above, the client is the OPNsense firewall and the server the ISP, but clients inside the network will act similar to what OPNsense is doing on the WAN interface.*

*在上圖中，客戶端是 OPNsense 防火牆，伺服器是ISP ，但網路內部的客戶端的行為與 OPNsense 在WAN介面上的行為類似。 *

Most concepts explained in this paragraph are part of the [Neighbor Discovery Protocol](https://en.wikipedia.org/wiki/Neighbor_Discovery_Protocol).

本段中解釋的大多數概念都是 [鄰居發現協議](https://en.wikipedia.org/wiki/Neighbor_Discovery_Protocol)的一部分。

### [Finding your neighbors \[NS,NA\]](#id7)｜[尋找你的鄰居 \[ NS,NA \]]( https://docs.opnsense.org/manual/ipv6.html#id7 )

For a machine to know its neighbors, it will use the neighbor discovery protocol (NDP), a bit similar to ARP on IPv4 networks, but using Neighbor Solicitation (`ICMPv6 type 135`) and Neighbor Advertisement `ICMPv6 type 136`) messages.

為了讓機器知道它的鄰居，它將使用鄰居發現協定（ NDP ），這與 IPv4 網路上的ARP有些類似，但使用鄰居請求（ `ICMPv6 type 135` ）和鄰居通告`ICMPv6 type 136` ）訊息。

In order to verify if a neighbor is known, you can use the NDP table in Interfaces ‣ Diagnostics ‣ NDP Table.

為了驗證鄰居是否已知，您可以使用「介面」‣「診斷」‣ NDP表」中的NDP表。

### [Router Solicitation \[RS\]](#id8)｜[路由器請求 \[ RS \]]( https://docs.opnsense.org/manual/ipv6.html#id8 )

Since a lot of home and branch office setups are auto-configured, it does make sense to explain router solicitations (RS) first.

由於許多家庭和分公司的設定都是自動設定的，所以先解釋路由器請求（ RS ）是很有意義的。

Compared to IPv4, dynamic configuration is quite different when it comes to addressing and routes. A dynamically configured host starts with sending a router solicitation message using `ICMPv6 type 133`, after which it expects the other end to answer with a router advertisement (`ICMPv6 type 134`).

與 IPv4 相比，動態配置在尋址和路由方面有很大不同。動態設定的主機首先使用`ICMPv6 type 133`發送路由器請求訊息，然後期望另一端以路由器通告 ( `ICMPv6 type 134` ) 回應。

The address a host will use depends partly on the answer it receives, when a DHCPv6 client configuration is used, similar to IPv4 a dhcp client will be used to retrieve an address. When stateless auto configuration is used, the client calculates an address to use based on its mac address and network received from the advertisement.

主機使用的位址部分取決於它收到的回應。當使用 DHCPv6 用戶端設定時，與 IPv4 類似，需要使用 DHCP 用戶端來取得位址。當使用無狀態自動設定時，用戶端會根據其 MAC 位址和從通告中接收到的網路資訊來計算要使用的位址。

Note

注意事項

For simplicity we’re not going deeper into [stateless auto configuration](https://datatracker.ietf.org/doc/html/rfc2462) including optional features to prevent address duplication ([DAD](https://datatracker.ietf.org/doc/html/rfc4429))

為簡單起見，我們不深入探討[無狀態自動配置](https://datatracker.ietf.org/doc/html/rfc2462) ，包括防止位址重複的選用功能（[DAD](https://datatracker.ietf.org/doc/html/rfc4429) ）。

On OPNsense a service called `rtsold` is used to send out these solicitations and can take some actions on the responses it receives (from the advertisements). Although without explicitly asking for advertisements, you will likely still receive them, but have little control over them. The kernel handles these advertisements when `accept_rtadv` is enabled on the interface anyway.

在 OPNsense 系統中，名為`rtsold`的服務用於發送這些要求，並可根據收到的回應（來自廣告）執行一些操作。即使您沒有明確要求廣告，您仍然可能會收到它們，但對它們幾乎沒有控制權。無論如何，當介面上啟用`accept_rtadv`時，核心都會處理這些廣告。

### [Router Advertisement \[RA\]](#id9)｜[路由器通告 \[ RA \]]( https://docs.opnsense.org/manual/ipv6.html#id9 )

The opposite of the solicitation is the advertisement, which we will also use on our end to inform our clients. A router advertisement contains vital information for the client to exist within the network. Usually a link-local (`FE80::/10`) address is used as source address in the message, which will then be used as (default) gateway by the client.

與請求相反的是通告，我們也會使用通告來通知我們的客戶。路由器通告包含客戶端在網路中存在所必需的重要資訊。通常，訊息中的來源位址使用鏈路本地位址（ `FE80::/10` ），客戶端隨後會將該位址用作（預設）網關。

Certain flags and options are offered to the client, the most prominent flags are the following ones ([rfc4861](https://www.rfc-editor.org/rfc/rfc4861)):

客戶端可以使用某些標誌和選項，其中最突出的標誌如下（[rfc4861](https://www.rfc-editor.org/rfc/rfc4861) ）：

| Code<br>代碼 | Name<br>名稱 | Description<br>描述 |
| --- | --- | --- |
| M | Managed Address Configuration<br>管理位址設定 | When set, it indicates that addresses are available via DHCPv6<br>啟用後，表示可透過 DHCPv6 取得位址 |
| O | Other Configuration Flag<br>其他配置標誌 | This indicates that other information, such as dns related options, are available via DHCPv6<br>這表示可以透過 DHCPv6 獲取其他信息，例如 DNS 相關選項 |

Relevant other information includes:

其他相關資訊包括：

| Purpose<br>用途 | Option type<br>選項類型 | Description<br>說明 |
| --- | --- | --- |
| Prefix information<br>前綴資訊 | 3 | Prefix to use, when flag `A` is set it may be used for stateless autoconfiguration (slaac).<br>設定標誌`A`時，可用於無狀態自動設定 (SLAAC) 的前綴。 |
| Recursive DNS Server<br>遞歸DNS伺服器 | 25 | DNS server information (RDNS)<br>DNS伺服器資訊 ( RDNS ) |
| Route Information<br>路由資訊 | 24 | Routes to install with their priority<br>待安裝路由及其優先權 |

Our clients (usually on LAN) will require a router advertisement daemon on our end, this service can be offered via either [radvd](<197 路由器廣告.md>) or [dnsmasq](<194 Dnsmasq DNS & DHCP.md>) on our end.

我們的客戶（通常在LAN上）需要我們這邊有一個路由器通告守護程序，這項服務可以透過我們這邊的 [radvd](<197 路由器廣告.md>)或 [dnsmasq](<194 Dnsmasq DNS & DHCP.md>)提供。

### [DHCPv6](#id10)｜[DHCPv6](#id10)

Similar to IPv4, there’s also a network configuration protocol for IPv6, but the scope of the service is different. In the sequence diagram above we’ll see that a dhcpv6 client will be executed after the router solicitation process. Since dhcpv6 is not responsible for the routing part and address configuration may depend on routing advertisement reveived, it needs this information first.

與 IPv4 類似，IPv6 也有一個網路配置協議，但其服務範圍有所不同。在上面的時序圖中，我們可以看到 dhcpv6 用戶端會在路由器請求程序之後執行。由於 dhcpv6 不負責路由部分，且位址配置可能取決於接收到的路由通告，因此它需要先取得這些資訊。

When debugging DHCPv6 communication, it’s important to know clients listen on `UDP port 546` and servers receive their messages on `UDP port 547`.

在調試 DHCPv6 通訊時，需要知道客戶端監聽`UDP port 546` ，伺服器在`UDP port 547`上接收訊息。

Depending on their role, clients may receive an address via DHCPv6 (or are auto-configured using [SLAAC](https://en.wikipedia.org/wiki/IPv6#Stateless_address_autoconfiguration_\(SLAAC\))) and information about surrounding servers like the DNS to use.

根據其角色，用戶端可以透過 DHCPv6 接收位址（或使用 [SLAAC](https://en.wikipedia.org/wiki/IPv6#Stateless_address_autoconfiguration_\(SLAAC\)自動設定）以及有關周圍伺服器（如DNS ）的資訊來使用。

The other important aspect of DHCPv6 is the ability to send networks to use for attached routers, this process is called [Prefix Delegation \[PD\]](https://en.wikipedia.org/wiki/Prefix_delegation). In most cases, OPNsense receives a PD from the provider which it can use for the networks attached. Usually these prefixes are larger than the minimal `/64` (e.g. `/48`).

DHCPv6 的另一個重要面向是能夠將網路指派給連接的路由器，這個過程稱為前綴委派https://en.wikipedia.org/wiki/Prefix_delegation PD 。在大多數情況下，OPNsense 會從服務提供者收到一個PD ，並將其用於連接的網路。通常，這些前綴比最小的`/64`更大（例如`/48` ）。

Our DHCP client is also responsible for configuring an address to the lan type interface based on the delegated prefix received. This part of the configuration is specified on the lan interface as “tracking”.

我們的DHCP客戶端也負責根據收到的委派前綴為LAN介面配置位址。這部分配置在LAN介面上被指定為「追蹤」。

Note

注意事項

When your provider or cloud hosting does not offer a PD, routing is not reliably possible. In some cases proxying neighbor discovery packets may be an option as explained in [RFC4389](https://datatracker.ietf.org/doc/html/rfc4389). An implementation is available via [ndp-proxy-go](<212 ndp-proxy-go（鄰居發現代理）.md>).

當您的供應商或雲端託管服務商不提供PD時，路由將無法可靠實作。在某些情況下，代理鄰居發現資料包可能是可行的方案，如 [RFC4389](https://datatracker.ietf.org/doc/html/rfc4389)中所述。可透過 [ndp-proxy-go](<212 ndp-proxy-go（鄰居發現代理）.md>)取得實現。

Note

注意事項

There is some overlap in what DHCPv6 offers and router advertisements bring to the table, but in most auto-configured environments both are being used.

DHCPv6 提供的功能與路由器通告提供的功能有些重疊，但在大多數自動設定的環境中，兩者都在使用。

Multiple options exist which may act as DHCPv6 server on our end, an overview of the options can be found in our [DHCP](<192 DHCP.md>) documentation.

有多種選項可以作為我們這邊的 DHCPv6 伺服器，有關這些選項的概述可以在我們的 [DHCP](<192 DHCP.md>)文件中找到。

Note

注意事項

Although not explained in detail here, when the firewall itself needs to connect to the outside world, it expects a global unicast address configured on the WAN interface. For this reason the dhcp IA\_NA (non-temporary addresses) option is used.

雖然這裡沒有詳細說明，但當防火牆本身需要連接到外部網路時，它會期望在WAN介面上配置一個全域單播位址。因此，會使用 dhcp IA \_NA（非臨時位址）選項。

## [Interface configuration modes](#id12)｜[介面配置模式](#id12)

Depending on the IPv6 mode selected IPv6 behaviour differs in outcome. The matching mode must be selected for your ISP. If in doubt ask for assistance via your ISP or ask on the forum how other users of your ISP configured it successfully.

根據所選的 IPv6 模式，IPv6 的行為會有所不同。必須為您的ISP選擇相符的模式。如有疑問，請透過ISP尋求協助，或在論壇上詢問其他ISP用戶是如何成功配置的。

### [None](#id13)｜[無](#id13)

This mode turns off IPv6 connectivity for this particular interface. Use this mode when the default mode (DHCPv6) does not work or causes broken connectivity with your ISP.

此模式會關閉此特定介面的 IPv6 連線。當預設模式 (DHCPv6) 不起作用或導致與ISP的連線中斷時，請使用此模式。

Note

注意事項

You can use this mode for WAN and LAN connections.

您可以將此模式用於WAN和LAN連接。

### [Static IPv6](#id14)｜[靜態 IPv6](#id14)

When the ISP offers a static address block you can assign one /64 network to your WAN interface and other /64 networks to your LANs. You can even delegate bigger networks within your prefix to downstream routers via DHCPv6 which is generally available in static mode. Note that you need to create and set a gateway address for this mode to connect to your next gateway hop which your ISP should provide to you as well.

當ISP提供靜態位址區塊時，您可以將一個/64網路指派給WAN接口，並將其他/64網路指派給您的區域網路。您甚至可以透過DHCPv6（通常在靜態模式下可用）將前綴內的更大網路委派給下游路由器。請注意，您需要為此模式建立並設定網關位址，以便連接到下一個網關跳， ISP也應該為您提供該位址。

Note

注意事項

You can use this mode for WAN and LAN connections.

您可以將此模式用於WAN和LAN連接。

### [DHCPv6](#id15)｜[DHCPv6](#id15)

For dynamic address offerings (which likely are also shifting the prefix) this mode is the most common configuration and therefore also the default setting for a preset WAN. In this mode a prefix will be acquired if offered, either with or without an additional IP addresses for your WAN. Internally, a single globally unique address is acquired via DHCPv6 and/or SLAAC (not to be confused with SLAAC mode), but for routing an ISP-provided link-local address is automatically used as the next hop gateway. Setting “Request only an IPv6 prefix” may be required in case the ISP refuses to hand out a prefix. Note that the interface will not assign a /64 to itself from the prefix by default in contrast to static IPv6.

對於動態位址分配（可能也會更改前綴），此模式是最常見的配置，因此也是預設WAN的預設設定。在此模式下，如果分配到前綴，則會取得該前綴，無論是否為您的WAN分配額外的IP位址。在內部，透過DHCPv6和/或SLAAC （不要與SLAAC模式混淆）取得一個全域唯一的位址，但對於路由，會自動使用ISP提供的鏈路本地位址作為下一跳網關。如果ISP拒絕指派前綴，則可能需要設定「僅請求IPv6前綴」。請注意，與靜態IPv6不同，預設情況下，介面不會從前綴為自身分配/64位址。

Note

注意事項

You can use this mode for WAN connections only.

此模式僅適用於WAN連接。

### [SLAAC](#id16)

Use “Stateless Address Autoconfiguration”（無狀態位址自動配置） for the IPv6 connectivity only. In cases where Static IPv6 or DHCPv6 not available this mode may still provide ISP connectivity.

“Stateless Address Autoconfiguration”（無狀態位址自動配置）僅用於 IPv6 連線。在靜態 IPv6 或 DHCPv6 不可用的情況下，此模式仍可能提供ISP連線。

Note

注意事項

You can use this mode for WAN connections only.

此模式僅適用於WAN連接。

### [6to4 Tunnel](#id17)｜[6to4隧道](#id17)

This is an IPv6 over IPv4 tunnelling mode as specified in RFC3056 over a fixed IPv4 router address. It does not require any client side configuration, but is not being used much anymore due to 6rd.

這是根據RFC3056中的規定，透過固定IPv4路由器位址實現的IPv6 over IPv4隧道模式。它不需要任何客戶端配置，但由於第六版協定的出現，現在已很少使用。

Note

注意事項

You can use this mode for WAN connections only.

此模式僅適用於WAN連接。

### [6rd Tunnel](#id18)｜[第六隧道](#id18)

6rd means “IPv6 Rapid Deployment”（IPv6快速部署） which is a generalised form of 6to4 connectivity where a variable prefix can be obtained through configuration. Some ISPs may still use this mode although it’s not very popular in general. The configuration for 6rd may be delivered by IPv4 DHCP connectivity, but is currently not being parsed and presented to the user.

6rd 指的是“IPv6 Rapid Deployment”（IPv6快速部署） ，它是 6to4 連接的一種通用形式，可以透過配置獲得可變前綴。一些 ISP 可能仍然在使用這種模式，儘管它總體上並不流行。 6rd 的設定可以透過 IPv4 DHCP連線傳遞，但目前尚未被解析並呈現給使用者。

Note

注意事項

You can use this mode for WAN connections only.

此模式僅適用於WAN連接。

### [Identity Association](#id19)｜[身份關聯](#id19)

This mode uses a WAN DHCPv6 interface to assign a single (/64) network to your LAN interfaces.

此模式使用WAN DHCPv6 介面將單一 (/64) 網路指派給您的LAN介面。

It is similar to Track Interface (legacy), with the important distinction that it does not auto-configure any IPv6 services like `radvd` or `dnsmasq`.

它與 Track Interface（傳統）類似，但重要的區別在於它不會自動配置任何 IPv6 服務，例如`radvd`或`dnsmasq` 。

Configuration of DHCPv6 and Router Advertisements must be done manually via the preferred available services.

DHCPv6 和路由器通告的設定必須透過首選的可用服務手動完成。

Note

注意事項

You can use this mode for LAN connections only.

此模式僅適用於LAN連接。

### [Track Interface (legacy)](#id20)｜[軌道界面（傳統）](#id20)

This mode uses a WAN DHCPv6 interface to assign a single (/64) network to your LAN interfaces. The “Manual configuration” option switches from automatically configuring router advertisements and DHCPv6 (including prefix delegation if the prefix is big enough) to how Static IPv6 configured devices are able to use it from the menu.

此模式使用WAN DHCPv6 介面為您的LAN介面分配一個 /64 網路。 「手動設定」選項可將路由器通告和 DHCPv6（如果前綴足夠大，則包括前綴委派）的自動設定切換為靜態 IPv6 設定設備如何從選單中使用。

The primary function of a “track” interface is to prepare the addressing based on the configured “wan” interface, this is either facilited statically (calculated) for `6to4` , `6rd` or requested via `dhcp6c`.

「track」介面的主要功能是根據配置的「wan」介面準備尋址，這可以透過`6to4` , `6rd`靜態計算，也可以透過`dhcp6c`請求。

Tip

提示

As dhcpv6 is most commonly used, it helps to understand how networks are being distributed using the information received via dhcpv6 on the wan interface. Two properties play an important role here, being *Assign prefix ID* (`sla-id`) , which is the Site-Level Aggregation Identifier and is specified on the LAN type interface, it identifies the network number (each network uses a unique number). The other option is *Prefix delegation size* (`sla-len`), which is specified on the wan type interface and configures the prefix size to use for all attached networks (default `/64`).

由於 dhcpv6 最常用，因此它有助於使用 wan 介面上透過 dhcpv6 接收的資訊來了解網路是如何分佈的。兩個屬性在這裡起著重要作用，*分配前綴ID* (`sla-id`)，它是站點級聚合標識符，在LAN類型介面上指定，它標識網路編號（每個網路使用唯一的編號）。另一個選項是*前綴委託大小* (`sla-len`)，它在 wan 類型介面上指定，並配置用於所有連接網路的前綴大小（預設`/64`）。

As soon as the interface has an address, we can start serving router advertisements using `radvd` or `dnsmasq` and addresses using any of the available dhcpv6 servers.

一旦介面有了位址，我們就可以開始使用`radvd`或`dnsmasq`以及任何可用的dhcpv6伺服器的位址來提供路由器通告。

Note

注意事項

You can use this mode for LAN connections only.

此模式僅適用於LAN連接。

### [Link Local](#id21)｜[本地連結](#id21)

This mode generates an automatic link-local address on the selected interfaces and does not process router advertisements, which means SLAAC is not generated and routes are not installed automatically.

此模式會在選定的介面上自動產生連結本地位址，且不處理路由器通告，這表示不會產生SLAAC ，也不會自動安裝路由。

The usecases for this mode are more advanced, examples are:

此模式的應用場景較為高級，例如：

-   Distribute a larger prefix that is received via a static or dynamic route (BGP). These routes most likely target the link-local address of the WAN interface. To delegate a prefix to customers, set the LAN interface to link-local and use KEA for DHCPv6-PD. KEA will set a route to the next hop link-local address automatically.  
    分發透過靜態或動態路由（ BGP ）接收到的較大前綴。這些路由很可能指向WAN介面的鏈路本地位址。若要將前綴委派給客戶，請將LAN介面設定為連結本地，並使用KEA進行DHCPv6設定PD. KEA將自動設定到下一跳鏈路本地位址的路由。
    
-   NDP proxying, as link-local prevents the same on-link prefix to appear on multiple links which would cause routing issues. Such a scenario requires an additional NDP proxy plugin.  
    NDP代理，因為鏈路本地化會防止相同的鏈路前綴出現在多個鏈路上，從而導致路由問題。這種情況需要額外的NDP代理插件。
    

Note

注意事項

You can use this mode for WAN and LAN connections.

您可以將此模式用於WAN和LAN連接。

## [Basic setup and troubleshooting](#id22)｜[基本設定與故障排除](#id22)

There are two steps for providing IPv6:

提供 IPv6 服務需要兩個步驟：

1.  Provide IPv6 to your WAN and the firewall itself.  
    為您的WAN和防火牆本身提供IPv6。
    
2.  Provide IPv6 to your LAN including the clients behind it.  
    為您的LAN及其背後的客戶端提供 IPv6。
    

For step 1 start with selecting the appropriate IPv6 mode, reconfigure the WAN interface and try to ping an IPv6 address or host from the firewall itself, e.g.:

步驟 1 首先選擇適當的 IPv6 模式，重新配置WAN接口，然後嘗試從防火牆本身 ping 一個 IPv6 位址或主機，例如：

Test if ping over IPv6 to Internet is successful (also possible via Interfaces‣Diagnostics‣Ping).

測試透過 IPv6 ping 網際網路是否成功（也可以透過介面‣診斷‣Ping 進行測試）。

```
# ping -6 heise.de
```

Test if IPv6 default route exists (also possible via System‣Routes‣Status and search for default).

測試 IPv6 預設路由是否存在（也可以透過「系統」‣「路由」‣「狀態」並蒐索「預設路由」來實現）。

```
# netstat -nr6 | grep default
```

Note

注意事項

If one or both of these do not work you are looking at a configuration problem on the WAN side or your ISP does not support IPv6 for you at this point. Do not try to debug step 2 at this point wondering why clients cannot connect.

如果上述方法之一或兩者都無效，則表示WAN端配置存在問題，或者您的ISP目前不支援IPv6。此時請勿嘗試調試步驟2，也不要糾結於客戶端無法連線的原因。

For step 2 static and tracking modes are what can be used on a LAN to provide attached clients with IPV6 connectivity.

對於步驟 2，靜態和追蹤模式可以在LAN上使用，為連接的客戶端提供IPV6連接。

Tracking mode is enabled by default and the DHCPv6 on the WAN automatically sets up both Router Advertisements and DHCPv6 server including the use of prefixes being delegated to clients if the present prefix has enough room left to delegate.

追蹤模式預設為啟用， WAN上的 DHCPv6 會自動設定路由器通告和 DHCPv6 伺服器，包括將前綴委派給客戶端（如果當前前綴有足夠的空間可以委派）。

When using static mode or the “Manual configuration” setting in tracking you can configure both Router Advertisements and DHCPv6 server from the menu, but defaulting to off. Most endpoint devices work fine with only Router Advertisements set, but if you deal with downstream routers it can be beneficial to set up DHCPv6 server as well to delegate part of the prefix.

在靜態模式或追蹤的「手動設定」設定下，您可以從選單中設定路由器通告和 DHCPv6 伺服器，但預設情況下它們處於關閉狀態。大多數終端設備僅啟用路由器通告即可正常運作，但如果您需要處理下游路由器，則設定 DHCPv6 伺服器以分配部分前綴可能更有益。

Note

注意事項

Note that certain network stack implementations such as Android phones only support Router Advertisement configuration via SLAAC and DCHPv6 leases do not work there.

請注意，某些網路協定堆疊實作（例如 Android 手機）僅支援透過SLAAC進行路由器通告配置，而 DHCPv6 租約在這些情況下不起作用。

Make sure to test the following on multiple different clients to see if connectivity can be established at all or not:

請務必在多台不同的用戶端上測試以下操作，以查看是否能夠建立連線：

-   [https://test-ipv6.com/](https://test-ipv6.com/)
    
-   [https://ipv6-test.com/](https://ipv6-test.com/)
    

These two pages can help you diagnose remaining issues as well. Make sure to set up both DHCPv6 server and Router advertisements during testing when debugging IPv6 connectivity. If you eventually do not have any need for one or the other it’s also ok to disable them. A completely static setup is also possible.

這兩個頁面也能幫助您診斷剩餘問題。在偵錯 IPv6 連線時，請務必在測試期間同時設定 DHCPv6 伺服器和路由器通告。如果您最終不需要其中任何一項，也可以將其停用。完全靜態配置也是可行的。

Tip

提示

When you experience issues during setup, consider the sequence of events as explained earlier and use the packet capture to inspect if data is being exchanged using the expected protocols (e.g. `ICMPv6` to find RS, RA traffic)

當您在設定過程中遇到問題時，請考慮前面解釋的事件順序，並使用封包擷取來檢查資料是否正在使用預期的協定進行交換（例如，使用`ICMPv6`來尋找RS, RA流量）。
