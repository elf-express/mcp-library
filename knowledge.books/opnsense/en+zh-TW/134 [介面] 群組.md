# [Interface] Groups｜[介面] 群組

> 章節：[Firewall](<000 目錄.md#c-26>)

## \[Interface\] Groups｜\[介面\]群組

To simplify rulesets, you can combine interfaces into **Interface Groups** and add policies which will be applied to all interfaces in the group.

為了簡化規則集，您可以將介面組合到**介面組**並新增將套用於群組中所有介面的策略。

Since interface groups are processed before normal interfaces, you should not have issues with overlapping rules in the interface tabs itself. More details about processing order can be found [here](<137 規則.md#firewall-rule-processing-order>)

由於介面組是在普通介面之前處理的，因此您不應該遇到介面選項卡本身規則重疊的問題。有關處理訂單的更多詳細信息，請參閱[此處](<137 規則.md#firewall-rule-processing-order>)

Note

注意事項

For multiwan setups be careful with groups. Since groups are not bound to a specific interface, they will use the normal routing system to determine the next hop when applied on WAN type interfaces (`reply-to` is not used here).

對於多WAN 設置，請小心群組。由於群組沒有綁定到特定接口，因此當應用於WAN類型接口（此處不使用`reply-to`）時，它們將使用正常的路由系統來確定下一跳。
