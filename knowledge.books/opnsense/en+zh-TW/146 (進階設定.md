# (Advanced) Settings｜(進階設定

> 章節：[Firewall](<000 目錄.md#c-26>)

In some circumstances people might want to change how our system handles traffic by default, in which case the advanced settings section is a good place to look.

在某些情況下，使用者可能希望更改我們系統預設的流量處理方式，在這種情況下，進階設定部分是一個不錯的查找位置。

## Network Address Translation｜網路位址轉換

Warning

警告

Although the options below might look interesting to ease setup, we do not advise to use them. Since automatic rules always contain assumptions about the situation they try to solve, it’s not guaranteed they will fit your use-case at all times. They merely exist for historical reasons, if possible better add manual nat rules to make sure the intend is very explicit when one inspects your setup.

儘管以下選項看起來似乎可以簡化設置，但我們並不建議使用它們。因為自動規則總是包含它們試圖解決的情況的假設，所以無法保證它們始終適用於您的用例。它們的存在只是出於歷史原因。如果可能，最好手動新增 NAT 規則，以確保在檢查您的設定時，其意圖非常明確。

Tip

提示

There is a how-to section explaining [NAT Reflection](<136 倒影與髮夾NAT.md>) in detail.

有一個操作指南部分詳細解釋了 [NAT反射](<136 倒影與髮夾NAT.md>) 。

Attention

注意

Firewall Rules won’t be automatically generated when using any of the below Reflection options. You have to create them manually or traffic will be blocked by the default deny rule.

使用以下任何反射選項時，防火牆規則都不會自動產生。您必須手動建立規則，否則流量將被預設的拒絕規則阻止。

Note

注意事項

-   Examine the automatic Reflection rules either in the shell with `pfctl -s nat` or in the GUI at Firewall ‣ Diagnostics ‣ Statistics ‣ rules.  
    在 shell 中使用`pfctl -s nat`或在防火牆 ‣ 診斷 ‣ 統計 ‣ 規則 中，使用GUI檢查自動反射規則。
    
-   `rdr` means redirection. Redirection rules are Firewall ‣ NAT ‣ Destination NAT (Port Forward) rules, also known as *Destination NAT*. *Destination NAT* changes the destination IP of a packet.  
    `rdr`表示重定向。重定向規則是防火牆 ‣ NAT ‣ 目標NAT （連接埠轉送）規則，也稱為 *目標NAT *。 *目標NAT * 更改封包的目標IP 。
    
-   `nat` rules are Firewall ‣ NAT ‣ Source NAT (Outbound) rules. *Source NAT* changes the source IP of a packet.  
    `nat`規則是防火牆 ‣ NAT ‣ 源NAT （出站）規則。 *來源NAT * 更改封包的來源IP 。
    
-   *Reflection NAT* is just `rdr`. *Hairpin NAT* is a combination of `rdr` and `nat`.  
    *反射NAT * 就是`rdr` 。 *髮夾NAT * 是`rdr`和`nat`的組合。
    

### Reflection for Destination NAT (Port Forwards)｜目的地NAT （埠轉送）的反射

Disabled by default, when enabled the system will generate `rdr` rules to reflect Destination NAT (Port Forwards) on internal interfaces automatically (interfaces without a gateway set).

預設情況下停用，啟用後，系統將自動產生`rdr`規則，以反映內部介面（未設定網關的介面）上的目標NAT （連接埠轉送）。

If you create a Firewall ‣ NAT ‣ Destination NAT (Port Forward) rule with the interface as `wan`, the automatic `rdr` rules will be created for any of your other connected interfaces (e.g. `lan`, `opt1`, `lo0`).

如果您建立防火牆 ‣ NAT ‣ 目標NAT （連接埠轉送）規則，並將介面設定為`wan` ，則會自動為任何其他連接的介面建立`rdr`規則（例如`lan`, `opt1`, `lo0` ）。

### Reflection for 1:1｜一對一反思

Disabled by default, when enabled the system will generate redirect `rdr` rules for 1to1 nat rules similar to the portforward option.

預設情況下停用，啟用後，系統將產生類似於連接埠轉送選項的 1to1 nat 規則的重定向`rdr`規則。

### Automatic Source NAT (Outbound) for Reflection｜自動反射源NAT （出站）

Disabled by default, when enabled the system will generate `nat` rules in addition to `rdr` rules, effectively turning all Reflection NAT into Hairpin NAT.

預設情況下停用，啟用後，系統除了產生`nat`規則外，還會產生`rdr`規則，從而有效地將所有反射NAT轉換為髮夾NAT 。

Warning

警告

The disadvantage of reflecting traffic back with the firewall’s internal IP address is that the receiving side will see the source IP address of the firewall instead of the source IP address of the client. Some security features on servers like fail2ban can’t properly function like this.

使用防火牆內部的IP位址反射流量的缺點是，接收者看到的將是防火牆的來源IP位址，而不是客戶端的來源IP位址。伺服器上的某些安全功能（例如 fail2ban）在這種情況下無法正常運作。

## Bogon Networks｜博貢網絡

### Update Frequency｜更新頻率

Configure the frequency of updating the lists of IP addresses that are reserved (but not RFC 1918) or not yet assigned by IANA.

配置更新已保留（但不是RFC 1918）或尚未由IANA分配的IP地址清單的頻率。

## Gateway Monitoring｜網關監控

### Skip rules｜跳過規則

By default, when a rule has a specific gateway set, and this gateway is down, rule is created and traffic is sent to default gateway. This option overrides that behavior and the rule is not created when gateway is down

預設情況下，當規則設定了特定網關，而該網關發生故障時，系統會建立規則並將流量傳送到預設網關。此選項會覆寫此預設行為，在網關發生故障時不會建立規則。

## Multi-WAN｜多色- WAN

### Sticky connections｜黏性連接

When using a gateway group the firewall will use the same gateway for the same source address, by default as long as there’s a state active, optionally this can be configured with a different timeout.

使用網關群組時，防火牆預設會對相同來源位址使用相同網關（只要網關群組處於活動狀態），也可以選擇配置不同的逾時時間。

### Shared forwarding｜分享轉發

Using policy routing in the packet filter rules causes packets to skip processing for the traffic shaper and captive portal tasks. Using this option enables the sharing of such forwarding decisions between all components to accommodate complex setups.

在封包過濾規則中使用策略路由，可使封包跳過流量整形器和強制入口網站的處理。啟用此選項後，所有元件之間即可共用此類轉送決策，從而適應複雜的網路環境。

### Disable force gateway｜停用強制網關

By default OPNsense enforces a gateway on “Wan”（範） type interfaces (those with a gateway attached to it), although the default usually is the desired behaviour, it does influence the routing decisions made by the system (local traffic bound to an address will use the associated gateway).

預設情況下，OPNsense 會在“Wan”（範）類型介面（已連接網關的介面）上強制使用網關，雖然預設行為通常是期望的行為，但它確實會影響系統做出的路由決策（綁定到某個位址的本地流量將使用關聯的網關）。

Note

注意事項

This rule is responsible for the `let out anything from firewall host itself (force gw)` rule visible in the floating section, it forces a route to (`route-to`) on all non local traffic for the “Wan”（範） type interface.

此規則負責浮動部分中可見的`let out anything from firewall host itself (force gw)`規則，它強制所有非本地流量通過“Wan”（範）類型介面路由到 ( `route-to` )。

## Schedules｜日程安排

### Schedule States｜附表州

By default schedules clear the states of existing connections when the expiration time has come. This option overrides that behavior by not clearing states for existing connections.

預設情況下，排程任務會在到期時間到達時清除現有連線的狀態。此選項會覆寫此預設行為，不會清除現有連線的狀態。

## Logging｜日誌記錄

Here the logging behaviour of the default block/pass, automatic Source NAT as well as bogon and private network blocks can be adjusted. If disabled, only log directives from your manual rules will be show in the firewall log.

您可以在此處調整預設阻止/允許、自動來源NAT以及 bogon 和私有網路封鎖的日誌記錄行為。如果停用此功能，防火牆日誌中將僅顯示您手動規則中的日誌指令。

## Miscellaneous｜各種各樣的

### Firewall Optimization｜防火牆優化

Firewall state table optimization to use, influences the number of active states in the system, only to be changed in specific implementation scenarios.

防火牆狀態表最佳化的使用會影響系統中的活動狀態數量，僅在特定實施場景中才會變更。

-   \[normal\] (default)As the name says, it is the normal optimization algorithm  
    [normal]（預設）顧名思義，它是普通的最佳化演算法
    
-   \[high-latency\] Used for high latency links, such as satellite links. Expires idle connections later than default  
    [高延遲] 用於高延遲鏈路，例如衛星鏈路。空閒連線的過期時間比預設值晚。
    
-   \[aggressive\] Expires idle connections quicker. More efficient use of CPU and memory but can drop legitimate idle connections  
    [激進型] 更快終止空閒連線。更有效地利用CPU和內存，但可能會丟棄合法的空閒連接。
    
-   \[conservative\] Tries to avoid dropping any legitimate idle connections at the expense of increased memory usage and CPU utilization.  
    [保守型] 盡量避免丟棄任何合法的空閒連接，代價是增加記憶體使用量和CPU利用率。
    

### Bind states to interface｜將狀態綁定到接口

Set behaviour for keeping states, by default states are floating, but when this option is set they should match the interface. The default option (unchecked) matches states regardless of the interface, which is in most setups the best choice.

設定狀態保持行為。預設情況下，狀態是浮動的，但啟用此選項後，狀態應與介面保持一致。預設選項（未選取）會使狀態與介面保持一致，這在大多數情況下是最佳選擇。

### Disable Firewall｜停用防火牆

Disable all firewall (including NAT) features of this machine.

停用此機器的所有防火牆（包括NAT ）功能。

### Firewall Adaptive Timeouts｜防火牆自適應逾時

Timeouts for states can be scaled adaptively as the number of state table entries grows.

狀態逾時時間可以隨著狀態表條目數量的增長而自適應地擴展。

-   \[start\] When the number of state entries exceeds this value, adaptive scaling begins. All timeout values are scaled linearly with factor (adaptive.end - number of states) / (adaptive.end - adaptive.start).  
    [start] 當狀態條目數超過此值時，自適應縮放開始。所有超時值均以因數（adaptive.end - 狀態數）/（adaptive.end - adaptive.start）線性縮放。
    
-   \[end\] When reaching this number of state entries, all timeout values become zero, effectively purging all state entries immediately. This value is used to define the scale factor, it should not actually be reached (set a lower state limit, see below).  
    當狀態條目數達到此值時，所有逾時值將變為零，立即清除所有狀態條目。此值用於定義縮放因子，實際上不應達到此值（請設定更低的狀態限制，詳見下文）。
    

### Firewall Maximum States｜防火牆最大狀態

Maximum number of connections to hold in the firewall state table, usually the default is fine, when serving a lot of connections you may consider increasing the default size which is mentioned in the help text.

防火牆狀態表中要保存的最大連線數，通常預設值就足夠了，當需要處理大量連線時，可以考慮增加幫助文字中提到的預設大小。

### Firewall Maximum Fragments｜防火牆最大碎片

Sets the maximum number of entries in the memory pool used for fragment reassembly.

設定用於片段重組的記憶體池中的最大條目數。

### Firewall Maximum Table Entries｜防火牆最大表項數

Maximum number of table entries for systems such as aliases, sshlockout, bogons, etc, combined. When using a lot of large aliases, you may consider increasing the default. The configured default is mentioned in the help text.

別名、SSH鎖定、Bogon等系統表項的最大總數。使用大量大型別名時，建議增加預設值。說明文字中提供了配置的預設值。

### Static route filtering｜靜態路由過濾

This option only applies if you have defined one or more static routes. If it is enabled, traffic that enters and leaves through the same interface will not be checked by the firewall. This may be desirable in some situations where multiple subnets are connected to the same interface.

此選項僅在您定義了一或多條靜態路由時適用。啟用此選項後，防火牆將不會檢查透過相同介面進出的流量。在某些情況下，例如多個子網路連接到相同介面時，這可能是理想的選擇。

Note

注意事項

Although these rules will be visible in the “automatic” rule section of each interface, we generally advice to add the rules actually recquired on a per net basis manually.

雖然這些規則會在每個介面的「自動」規則部分中顯示，但我們通常建議手動為每個網路新增實際需要的規則。

### Disable reply-to｜禁用回覆

With Multi-WAN you generally want to ensure traffic leaves the same interface it arrives on, hence `reply-to` is added automatically by default. When using bridging, you must disable this behavior if the WAN gateway IP is different from the gateway IP of the hosts behind the bridged interface.

使用多WAN配置時，通常需要確保流量從相同介面發出，因此預設會自動新增`reply-to` 。使用橋接時，如果WAN IP與橋接介面後方主機的網關IP不同，則必須停用此功能。

Warning

警告

Although our default is to enable this rule for historic reasons, there are side-affects when adding `reply-to` to every “wan” type rule. When allowing traffic originating from the same network as the interface is attached to, it will still reply the packet to the configured gateway.

雖然出於歷史原因，我們預設啟用此規則，但將`reply-to`新增到每個「wan」類型規則中會產生一些副作用。當允許來自與介面所連接網路相同的流量時，它仍然會將資料包回復到配置的網關。

To prevent this behavior, you can either disable `reply-to` here and configure the desired behaviour on a per-rule basis or add a rule for local traffic above the one for outbound traffic disabling `reply-to` (in rule advanced).

為防止此行為，您可以停用此處的`reply-to`並逐條規則配置所需的行為，或在出站流量規則之上新增一條本地流量規則，停用`reply-to` （在規則進階設定中）。

### Disable anti-lockout｜停用防鎖定功能

When this is unchecked, access to the web GUI or SSH on the LAN interface is always permitted, regardless of the user-defined firewall rule set. Check this box to disable the automatically added rule, so access is controlled only by the user-defined firewall rules. Ensure you have a firewall rule in place that allows you in, or you will lock yourself out.

如果取消選取此項，則無論使用者定義的防火牆規則集為何，始終允許透過LAN介面存取GUI或SSH 。選取此核取方塊可停用自動新增的規則，以便僅由使用者定義的防火牆規則控制存取權限。請確保您已設定允許您存取的防火牆規則，否則您將被鎖定在外。

### Aliases Resolve Interval｜別名解析區間

Interval, in seconds, that will be used to resolve hostnames configured on aliases.

用於解析別名上配置的主機名稱的間隔時間（以秒為單位）。

### Check certificate of aliases URLs｜檢查別名 URL 的證書

Make sure the certificate is valid for all HTTPS addresses on aliases. If it’s not valid or is revoked, do not download it.

請確保證書對所有別名上的HTTPS地址均有效。如果憑證無效或已被撤銷，請勿下載。

## Anti DDOS｜反DDOS

### Enable syncookies｜啟用同步cookie

This option is quite similar to the [syncookies](https://www.freebsd.org/cgi/man.cgi?syncookies) kernel setting, preventing memory allocation for local services before a proper handshake is made.

此選項與 [syncookies](https://www.freebsd.org/cgi/man.cgi?syncookies)核心設定非常相似，它阻止在進行適當的握手之前為本地服務分配記憶體。

In this case pf will be protected against state table exhaustion.

在這種情況下，pf 將免受狀態表耗盡的影響。

The following modes are available:

提供以下幾種模式：

-   never (default)  
    從不（預設）
    
-   always  
    總是
    
-   adaptive - in which case a lower and upper percentage should be specified referring to the usage of the state table.  
    自適應 - 在這種情況下，應參考狀態表的使用情況指定下限百分比和上限百分比。
