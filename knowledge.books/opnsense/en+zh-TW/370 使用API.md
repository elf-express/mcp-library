## [Overview](#id2)｜[概述](#id2)

All components that are using the full architecture of OPNsense automatically receive API capabilities, for this simple tutorial we use the firmware module but others will function in the same way. API access is part of the local user authentication system, but uses key/secret pairs to separate account information from machine to machine communication. Secrets are not stored on OPNsense and can be downloaded only once, if lost, a new key has to be generated for your application.

使用 OPNsense 完整架構的所有元件都會自動接收 API 功能，在這個簡單的教學中，我們使用韌體模組，但其他元件將以相同的方式運作。 API 存取是本機使用者驗證系統的一部分，但使用金鑰/秘密對將帳戶資訊與機器到機器通訊分開。秘密不會儲存在 OPNsense 上，只能下載一次，如果遺失，則必須為您的應用程式產生新金鑰。

A user can have multiple keys, our advice is to create a unique key for every application in use.

使用者可以擁有多個金鑰，我們的建議是為每個使用的應用程式建立一個唯一的金鑰。

## [Creating keys](#id3)｜[建立金鑰](#id3)

API keys are managed in the user manager (system\_usermanager.php), go to the user manager page and select a user. Somewhere down the page you will find the API section for this user.

API 金鑰在使用者管理員（system\_usermanager.php）中管理，進入使用者管理員頁面並選擇一個使用者。在頁面下方的某個位置，您會找到該使用者的 API 部分。

[![Usermanager add api key.png](<../images/fd0cdef1-Usermanager_add_api_key.png>)](https://docs.opnsense.org/_images/Usermanager_add_api_key.png)

Click on the + sign to add a new key. When the key is created, you will receive a (single download) with the credentials in one text file (ini formatted). The contents of this file look like this:

點選+號新增密鑰。建立金鑰後，您將收到一份（單一下載），其中包含一個文字檔案（ini 格式）中的憑證。該文件的內容如下所示：

```
key=w86XNZob/8Oq8aC5r0kbNarNtdpoQU781fyoeaOBQsBwkXUt
secret=XeD26XVrJ5ilAc/EmglCRC+0j2e57tRsjHwFepOseySWLM53pJASeTA3
```

## [Code sample (python)](#id4)｜[程式碼範例（python）](#id4)

For the python code sample we use the nice “requests” library ([http://docs.python-requests.org/en/latest/](http://docs.python-requests.org/en/latest/)), which makes HTTP calls very easy.

對於Python程式碼範例，我們使用很好的「請求」函式庫（[http://docs.python-requests.org/en/latest/](http://docs.python-requests.org/en/latest/)），這使得HTTP呼叫非常容易。

Before you can start, make sure your OPNsense has a valid SSL certificate (or choose to ignore it for testing purposes by setting verify=False), don’t forget to verify that the selected user may access the firmware page.

在開始之前，請確保您的 OPNsense 具有有效的 SSL 憑證（或透過設定 verify=False 選擇忽略它以進行測試），不要忘記驗證所選用戶是否可以存取韌體頁面。

The web interface uses the same logic that will be available for the api, in this example we will collect some status information from the firmware module and print it out for the user.

Web 介面使用與 api 可用的邏輯相同的邏輯，在本例中，我們將從韌體模組收集一些狀態資訊並將其列印給使用者。

It all starts with creating the request and waiting for the response, all data interaction is using json format, both for the responses as for the request data (when sending POST data).

一切都從創建請求和等待回應開始，所有資料互動都使用 json 格式，無論是回應還是請求資料（發送POST資料時）。

First step of the example is importing the required libraries, then define the endpoint url and credentials to use and finally fire the (get type) request. As soon as we receive the response, we parse the json string back to a dictionary and print some data depending on the response.

此範例的第一步是匯入所需的庫，然後定義要使用的端點 url 和憑證，最後觸發（取得類型）請求。一旦我們收到回應，我們就會將 json 字串解析回字典，並根據回應列印一些資料。

```js
# import libraries
import json
import requests

# define endpoint and credentials
api_key = 'w86XNZob/8Oq8aC5hxh2he+vLN00r0kbNarNtdpoQU781fyoeaOBQsBwkXUt'
api_secret = 'puOyw0Ega3xZXeD26XVrJ5WYFepOseySWLM53pJASeTA3'
url = 'https://192.168.1.1/api/core/firmware/status'

# request data
r = requests.get(url,
                 verify='OPNsense.pem',
                 auth=(api_key, api_secret))

if r.status_code == 200:
    response = json.loads(r.text)

    if response['status'] == 'ok':
        print ('OPNsense can be upgraded')
        print ('download size : %s' % response['download_size'])
        print ('number of packages : %s' % response['updates'])
        if response['upgrade_needs_reboot'] == '1':
            print ('REBOOT REQUIRED')
    elif 'status_msg' in response:
        print (response['status_msg'])
else:
    print ('Connection / Authentication issue, response received:')
    print r.text
```

## [Using cURL](#id5)｜[使用cURL](#id5)

Simple testing with curl is also possible, the sample below uses the same credentials, but ignores the SSL certificate check (-k) for testing.

也可以使用curl進行簡單測試，下面的範例使用相同的憑證，但忽略SSL證書檢查（-k）進行測試。

```bash
curl -k -u "w86XNZob/8Oq8aC5hxh2he+vLN00r0kbNarNtdpoQU781fyoeaOBQsBwkXUt":"puOyw0Ega3xZXeD26XVrJ5WYFepOseySWLM53pJASeTA3" https://192.168.1.1/api/core/firmware/status
```

And schedule the actual update of all packages using:

並使用以下命令安排所有套件的實際更新：

```bash
curl -XPOST -k -u "w86XNZob/8Oq8aC5hxh2he+vLN00r0kbNarNtdpoQU781fyoeaOBQsBwkXUt":"puOyw0Ega3xZXeD26XVrJ5WYFepOseySWLM53pJASeTA3" https://10.211.55.100/api/core/firmware/update
```

## [Using browser console to inspect API](#id6)｜[使用瀏覽器控制台檢查API](#id6)

All API endpoints are used by the WebGUI to interact between view and controller. There are only very few endpoints that are not directly used in the WebGUI. This makes inspecting the API requests and responses in a browser console the best way to inspect the correct usage of the API.

WebGUI 使用所有 API 端點在視圖和控制器之間進行互動。只有極少數端點不直接在 WebGUI 中使用。這使得在瀏覽器控制台中檢查 API 請求和回應成為檢查 API 正確使用的最佳方法。

All API requests can be easily reproduced using command-line tools like cURL.

所有 API 請求都可以使用 cURL 等命令列工具輕鬆重現。

Below is a simple guide using Google Chrome and Firefox:

以下是使用 Google Chrome 和 Firefox 的簡單指南：

### [1\. Open an UI Component](#id7)｜[1\.打開UI組件](#id7)

In our example, we want to inspect how to create a new group in System ‣ Access ‣ Groups.

在我們的範例中，我們想要檢查如何在 System ‣ Access ‣ Groups 中建立新群組。

First we browse to the UI page that offers the option to add a new group. Afterwards we press the **+** button to open the form dialog for input. We will input the following data:

首先，我們瀏覽到 UI 頁面，該頁面提供新增群組的選項。然後我們按下**+**按鈕開啟表單對話框輸入。我們將輸入以下數據：

| Option<br>選項 | Value<br>價值 |
| --- | --- |
| **Group name**<br>**群組名稱** | HelloWorld<br>你好世界 |
| **Description**<br>**描述** | HelloWorld<br>你好世界 |
| **Privileges**<br>**特權** | Lobby: Dashboard<br>大廳：儀表板 |
| **Members**<br>**會員** | root<br>根 |

Before pressing **Save**, we will open the browser developer tools to inspect what happens when we do.

在按**儲存**之前，我們將開啟瀏覽器開發人員工具來檢查執行時會發生什麼。

### [2\. Open Browser Developer Tools](#id8)｜[2\.開啟瀏覽器開發者工具](#id8)

Google Chrome or Firefox:

Google瀏覽器或火狐瀏覽器：

Press F12 or Ctrl+Shift+I (Windows/Linux) or Cmd+Option+I (macOS).

按 F12 或 Ctrl+Shift+I (Windows/Linux) 或 Cmd+Option+I (macOS)。

Navigate to the **Network** tab.

導航至 **網路** 標籤。

Now press the **Save** button in the open form dialog. This will trigger the serialization of the data via API endpoint. You will see the `add/` in the network tab.

現在按下開啟的表單對話方塊中的 **儲存** 按鈕。這將透過API端點觸發資料的序列化。您將在網路標籤中看到`add/`。

### [3\. Inspect the API Call](#id9)｜[3\.檢查API通話](#id9)

Click on the relevant request (e.g., /api/auth/group/add/).

點選相關請求（例如 /api/auth/group/add/）。

Inspect the following details:

檢查以下詳細資訊：

-   Headers: Method (POST, GET), URL, headers (like content-type, accept, authorization, and cookie).  
    標頭：方法 (POST, GET)、URL、標頭（如內容類型、接受、授權和 cookie）。
    
-   Payload: Inspect the request payload in the Payload tab.  
    有效負載：在「有效負載」標籤中檢查請求有效負載。
    
-   Response: View the response data under the Response tab.  
    回應：在「回應」標籤下查看回應資料。
    

In our case it will look like this:

在我們的例子中，它看起來像這樣：

-   Request URL: `https://192.168.1.1/api/auth/group/add/`  
    要求URL: `https://192.168.1.1/api/auth/group/add/`
    
-   Request Method: `POST`  
    請求方式：`POST`
    
-   Request Payload: `group: {name: "HelloWorld", description: "HelloWorld", priv: "page-system-login-logout", member: "0"}`  
    請求負載：`group: {name: "HelloWorld", description: "HelloWorld", priv: "page-system-login-logout", member: "0"}`
    
-   Response: `{"result":"saved","uuid":"569118e0-006b-4a2d-8eb6-332d29300a2a"}`  
    回覆：`{"result":"saved","uuid":"569118e0-006b-4a2d-8eb6-332d29300a2a"}`
    

With this information, you know exactly how to use the group API to add a new group.

有了這些信息，您就可以確切地知道如何使用群組API來新增群組了。

### [4\. Replicate the API Call with cURL](#id10)｜[4\.使用 cURL 複製 API 呼叫](#id10)

In Chrome and Firefox, you can easily generate a cURL command out of the previous API call.

在 Chrome 和 Firefox 中，您可以輕鬆地從先前的 API 呼叫中產生 cURL 命令。

Right-click the request entry (e.g., `add/`), select Copy → Copy as cURL.

右鍵點選請求條目（例如，`add/`），選擇複製 → 複製為 cURL。

This provides a complete cURL command that can be completed with an API token for authorization.

這提供了完整的 cURL 命令，可以使用 API 令牌來完成授權。

```bash
curl -X POST 'https://172.16.0.254:4444/api/auth/group/add/' \
-H 'accept: application/json, text/javascript, */*; q=0.01' \
-H 'content-type: application/json' \
--data-raw '{"group":{"name":"HelloWorld","description":"HelloWorld","priv":"page-system-login-logout","member":"0"}}' \
--insecure
```

This approach allows you to test or automate API interactions outside of the GUI for debugging, automation and scripting.

這種方法允許您在 GUI 之外測試或自動化 API 交互，以進行調試、自動化和腳本編寫。
