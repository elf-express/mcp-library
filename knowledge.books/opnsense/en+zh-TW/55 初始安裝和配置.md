## [Architecture](#id2)｜[建築](#id2)

## [Embedded vs Full](#id3)｜[嵌入式與完整](#id3)

OPNsense offers two Image types with all major releases: embedded and full images. The Embedded Image is intended for environments where preinstalling the storage media is required due to a lack of local resources on the firewall like storage, and/or console access (VGA/Serial). The image is tailored to reduce write cycles as well, but the image can be used anywhere. Another reason for the Embedded Image is to eliminate the need for local console access for installing OPNsense. Installation is managed by prewriting the image to a storage device, installing the storage device, and booting the system.

OPNsense 為所有主要版本提供兩種影像類型：嵌入式影像和完整影像。嵌入式映像適用於由於防火牆上缺乏儲存和/或控制台存取（VGA/序列）等本機資源而需要預先安裝儲存媒體的環境。該映像也經過定制，可以減少寫入週期，但該映像可以在任何地方使用。使用嵌入式映像的另一個原因是無需本地控制台存取即可安裝 OPNsense。透過將映像預先寫入儲存裝置、安裝儲存裝置並引導系統來管理安裝。

Full Images provide installation tools like OPNsense Importer, Live Environment, and Installer. Full Images are released to support different console/hardware installation requirements.

完整映像檔提供 OPNsense Importer、Live Environment 和 Installer 等安裝工具。發布完整映像以支援不同的控制台/硬體安裝要求。

Both image types can be installed and run from virtual disks (VM), [SD memory cards](https://en.wikipedia.org/wiki/Secure_Digital), USB disks, [solid-state disks (SSD)](https://en.wikipedia.org/wiki/Solid-state_drive), or [hard disk drives (HDD)](https://en.wikipedia.org/wiki/Hard_disk_drive).

兩種映像類型都可以從虛擬磁碟 (VM)、[SD 記憶卡](https://en.wikipedia.org/wiki/Secure_Digital), USB 磁碟、[固態磁碟 (SSD)](https://en.wikipedia.org/wiki/Solid-state_drive) 或 [硬碟 (HDD)](https://en.wikipedia.org/wiki/Hard_disk_drive) 安裝和運行。

The main differences between embedded and full images are:

嵌入圖像和完整圖像之間的主要區別是：

| Embedded<br>嵌入式 | Full<br>完整 |
| --- | --- |
| Writes to RAM disk<br>寫入RAM磁碟 | Writes to local disk<br>寫入本機磁碟 |
| No log data retention after reboot<br>重啟後無日誌資料保留 | Log data retention after reboot<br>重啟後日誌資料保留 |
| Not intended for local disk writes<br>不適用於本機磁碟寫入 | Suitable for disk writes.<br>適合磁碟寫入。 |
| Embedded only use, SWAP file is optional<br>僅限嵌入式使用，SWAP 檔案可選 | Can enable RAM disk for embedded mode.<br>可以啟用RAM磁碟為嵌入式模式。 |

The embedded image stores logging and cache data in memory only, while full versions will keep the data stored on the local drive. A full version can mimic the behavior of an embedded version by enabling RAM disks, which is especially useful for SD memory card installations.

嵌入式映像僅將日誌記錄和快取資料儲存在記憶體中，而完整版本會將資料儲存在本機磁碟機上。完整版本可以透過啟用RAM磁碟來模仿嵌入式版本的行為，這對於SD記憶卡安裝特別有用。

Warning

警告

See the chapter [Hardware Sizing & Setup](<54 硬體尺寸和設置.md>) for further information on hardware requirements prior to an install.

有關安裝前硬體要求的更多信息，請參閱[硬體調整和設定](<54 硬體尺寸和設置.md>)一章。

所有完整映像類型都可以在啟動到 Live 環境之前運行 [OPNsense Importer](#opnsense-importer)，並且在啟動到 Live 環境後也可以運行 [Installer](#install-to-target-system)。

Warning

警告

To enable non-embedded versions: Go to System ‣ Settings ‣ Miscellaneous ‣ Disk / Memory Settings, change the setting, then reboot. Consider enabling an external syslog server as well.

若要啟用非嵌入式版本：前往 System ‣ Settings ‣ Miscellaneous ‣ Disk / Memory Settings，變更設置，然後重新啟動。也可以考慮啟用外部系統日誌伺服器。

## [Download and Verification](#id6)｜[下載並驗證](#id6)

The OPNsense distribution can be [downloaded](https://opnsense.org/download) from one of our [mirrors](https://opnsense.org/download).

OPNsense 發行版可以從我們的 [鏡像](https://opnsense.org/download) 之一[下載](https://opnsense.org/download)。

OpenSSL is used for image file verification. 4 files are needed for verification process:

OpenSSL 用於映像檔驗證。驗證過程需要4個文件：

-   The SHA-256 checksum file (<filename>.sha256)  
    SHA-256 校驗與文件 (<filename>.sha256)
    
-   The bzip-compressed image file (<filename>.<image>.bz2)  
    bzip 壓縮的圖片檔案 (<filename>.<image>.bz2)
    
-   The signature file for the uncompressed image file (<filename>.<image>.sig)  
    未壓縮圖片檔案的簽名檔（<filename>.<image>.sig）
    
-   The OpenSSL public key (<filename>.pub)  
    OpenSSL 公鑰 (<filename>.pub)
    

Use one of the OPNsense mirrors to download these files:

使用 OPNsense 鏡像之一下載這些檔案：

1.  Go to the bottom of OPNsense [download](https://opnsense.org/download) page.  
    前往 OPNsense [下載](https://opnsense.org/download) 頁面底部。
    
2.  Click one of the available mirrors closest to your location.  
    點擊距離您所在位置最近的可用鏡子之一。
    
3.  Download one of each file mentioned above for your Image type.  
    根據您的圖像類型下載上述每個檔案之一。
    

The OpenSSL public key (.pub) is required to verify against. Although the file is available on the mirror’s repository, you should not trust the copy there. Download it, open it up, and verify the public key matches the one from other sources. If it does not, the mirror may have been hacked, or you may be the victim of a man-in-the-middle attack. Some other sources to get the public key from include:

需要 OpenSSL 公鑰 (.pub) 進行驗證。儘管該文件在鏡像存儲庫中可用，但您不應信任那裡的副本。下載它，打開它，並驗證公鑰與其他來源的公鑰是否匹配。如果沒有，鏡像可能已被駭客入侵，或者您可能是中間人攻擊的受害者。獲取公鑰的其他一些來源包括：

-   [https://pkg.opnsense.org/releases/mirror/README](https://pkg.opnsense.org/releases/mirror/README)
    
-   [https://forum.opnsense.org/index.php?board=11.0](https://forum.opnsense.org/index.php?board=11.0)
    
-   [https://opnsense.org/blog/](https://opnsense.org/blog/)
    
-   [https://github.com/opnsense/changelog/tree/master/community](https://github.com/opnsense/changelog/tree/master/community)
    
-   [https://pkg.opnsense.org](https://pkg.opnsense.org/) (/<FreeBSD:<version>:<architecture>/<release version>/sets/changelog.txz)
    

Note

注意事項

Only major release announcements for images contain the public key, and update release announcements will not. i.e. 22.1 will have a copy of the public key in the release announcement, but 22.1.9 will not.

只有鏡像的主要發佈公告包含公鑰，更新發佈公告則不會。即22.1將在發佈公告中擁有公鑰副本，但22.1.9不會。

Once you download all the required files and verify that the public key matches the public key found in one of the alternate sources listed above, you can be relatively confident that the key has not been tampered with. To verify the downloaded image, run the following commands (substituting the filenames in brackets for the files you downloaded):

下載所有必需的文件並驗證公鑰是否與上面列出的備用來源之一中找到的公鑰匹配後，您可以相對確信該密鑰沒有被篡改。若要驗證下載的映像，請執行以下命令（用括號中的檔案名稱取代您下載的檔案）：

```
openssl sha256 OPNsense-<filename>.bz2
```

Match the checksum command output with the checksum values in the file `OPNsense-<version>-OpenSSL-checksums-amd64.sha256`. If the checksums don’t match, redownload your image file.

將 checksum 指令輸出與檔案 `OPNsense-<version>-OpenSSL-checksums-amd64.sha256` 中的校驗和值進行比對。如果校驗和不匹配，請重新下載映像檔。

If the checksums match, continue with the verification commands.

如果校驗和匹配，則繼續執行驗證命令。

```
openssl base64 -d -in OPNsense-<filename>.<image>.sig -out /tmp/image.sig
openssl dgst -sha256 -verify OPNsense-<filename>.pub -signature /tmp/image.sig OPNsense-<filename>.<image>
```

Warning

警告

Make sure to unpack the image using `bunzip2` before verifying. Our signatures are generated before compressing them (as of OPNsense version 24.1)

確保在驗證之前使用`bunzip2`解壓鏡像。我們的簽名是在壓縮之前產生的（從 OPNsense 版本 24.1 開始）

If the output of the second command is “**Verified OK**”, your image file was verified successfully, and it is safe to install from it. Any other outputs, and you may need to check your commands for errors, or the image file may have been compromised.

如果第二個指令的輸出是“**Verified OK**”，則您的映像檔已成功驗證，可以安全地從中進行安裝。任何其他輸出，您可能需要檢查命令是否有錯誤，或者圖像檔案可能已洩露。

## [Installation Media](#id7)｜[安裝媒體](#id7)

Now that you have downloaded and verified the installation image from above, you must unpack the image file before you can write the image to disk. For Unix-like OSes use the following command:

現在您已經從上面下載並驗證了安裝映像，您必須先解壓縮映像文件，然後才能將映像寫入磁碟。對於類別 Unix 作業系統，請使用下列命令：

```
bzip2 -d OPNsense-<filename>.bz2
```

For Windows use an application like [7zip](https://www.7-zip.org/download.html). The `.bz2` will be removed from the end of the filename after command/application completes.

對於 Windows，請使用 [7zip](https://www.7-zip.org/download.html) 等應用程式。命令/應用程式完成後，`.bz2`將從檔案名稱末尾刪除。

After unpacking the image you can create the installation media. The easiest method to install OPNsense is to use the USB “[vga](#installation-media)” Image. If your target platform has a serial console interface choose the “[serial](#installation-media)” image. If you need to know more about using the serial console interface, consult the [serial access how-to](<60 序列存取.md>).

解壓縮映像後，您可以建立安裝媒體。安裝 OPNsense 最簡單的方法是使用 USB “[vga](#installation-media)” 映像。如果您的目標平台有序列控制台接口，請選擇「[serial](#installation-media)」映像。如果您需要了解有關使用串行控制台介面的更多信息，請參閱[串行存取操作方法](<60 序列存取.md>)。

Write the image to a USB flash drive (>=1 GB) or hard disk, using either dd for Unix-like OSes or, for Windows, physdiskwrite, [Etcher](https://www.balena.io/etcher#download-etcher), or [Rufus](https://rufus.ie/).

將映像寫入 USB 隨身碟 (>=1 GB) 或硬碟，對於類 Unix 作業系統使用 dd，對於 Windows，使用 physdiskwrite、[Etcher](https://www.balena.io/etcher#download-etcher) 或 [Rufus](https://rufus.ie/)。

**FreeBSD**

**免費BSD**

```
dd if=OPNsense-##.#.##-[Type]-[Architecture].img of=/dev/daX bs=16k
```

Where X = the device number of your USB flash drive (check `dmesg`)

其中 X = USB 快閃磁碟機的裝置編號（檢查`dmesg`）

**OpenBSD**

**開放BSD**

```
dd if=OPNsense-##.#.##-[Type]-[Architecture].img of=/dev/rsd6c bs=16k
```

The device must be the ENTIRE device (in Windows/DOS language: the ‘C’ partition), and a raw I/O device (the ‘r’ in front of the device “sd6”), not a block mode device.

該裝置必須是 ENTIRE 裝置（在 Windows/DOS 語言中：「C」分割區）和原始 I/O 裝置（裝置「sd6」前方的「r」），而不是區塊模式裝置。

**Linux**

```bash
sudo dd if=OPNsense-##.#.##-[Type]-[Architecture].img of=/dev/sdX bs=16k
```

where X = the IDE device name of your USB flash drive (check with hdparm -i /dev/sdX) (ignore the warning about trailing garbage - it’s because of the digital signature)

其中 X = USB 快閃磁碟機的 IDE 裝置名稱（使用 hdparm -i /dev/sdX 檢查）（忽略有關尾隨垃圾的警告 - 這是因為數位簽章）

**macOS**

```bash
sudo dd if=OPNsense-##.#.##-[Type]-[Architecture].img of=/dev/rdiskX bs=64k
```

where r = raw device, and where X = the disk device number of your CF card (check Disk Utility) (ignore the warning about trailing garbage - it’s because of the digital signature)

其中 r = 原始設備，X = CF 卡的磁碟設備號碼（檢查「磁碟工具」）（忽略有關尾隨垃圾的警告 - 這是因為數位簽章）

**Windows**

```
physdiskwrite -u OPNsense-##.#.##-[Type]-[Architecture].img
```

(use v0.3 or later!)

（使用v0.3或更高版本！）

## [System Boot Preparation](#id8)｜[系統啟動準備](#id8)

After preparing the installation media, we need to make sure we can access the console (either via keyboard and \[virtual\]monitor or [serial connectivity](<60 序列存取.md>)). Next we need to know how to access the boot menu or the system BIOS (UEFI) to boot from the installation media. In most cases, it will be a function (F#), Del, or ESC key that needs to pressed immediately after powering on (or rebooting) the system. Usually within the first 2 to 3 seconds from powering up.

準備好安裝媒體後，我們需要確保可以存取控制台（透過鍵盤和\[虛擬\]顯示器或[序列連接](<60 序列存取.md>)）。接下來我們需要知道如何存取啟動選單或系統BIOS（UEFI）以從安裝媒體啟動。在大多數情況下，它是一個功能鍵 (F#)、Del 或 ESC 鍵，需要在開啟（或重新引導）系統後立即按下。通常在通電後的前 2 至 3 秒內。

Tip

提示

OPNsense devices from the [OPNsense shop](https://shop.opnsense.com/) use `<ESC>` to enter the BIOS and boot selection options.

[OPNsense 商店](https://shop.opnsense.com/) 的 OPNsense 設備使用 `<ESC>` 進入BIOS 和啟動選擇選項。

Note

DECXXXX 設備的串列連接設定可以在[此處](<67 串行控制台連接.md>) 找到

## [Installation Instructions](#id9)｜[安裝說明](#id9)

Install Instructions

安裝說明

OPNsense installation boot process allows us to run several optional configuration steps. The boot process was designed to always boot into the live environment, allowing us to access the GUI or even SSH directly. If a timeout was missed, restart the boot procedure.

OPNsense 安裝引導程序可讓我們執行幾個可選的設定步驟。啟動過程被設計為始終啟動到實時環境，允許我們直接訪問GUI甚至SSH。如果逾時，請重新啟動啟動程序。

### [OPNsense Importer](#id10)｜[OPNsense 導入器](#id10)

All Full Images have the OPNsense Importer feature that offers flexibility in recovering failed firewalls, testing new releases without overwriting the current installation by running the new version in memory with the existing configuration or migrating configurations to new hardware installations. Using Importer is slightly different between previous installs with existing configurations on disk vs new installations/migrations.

所有完整映像都具有 OPNsense 導入器功能，可靈活恢復失敗的防火牆、透過在記憶體中使用現有配置運行新版本或將配置遷移到新硬體安裝來測試新版本，而無需覆蓋當前安裝。使用導入器在磁碟上現有配置的先前安裝與新安裝/遷移之間略有不同。

For systems that have OPNsense installed and the configuration intact, here is the process:

對於已安裝 OPNsense 且配置完好的系統，流程如下：

1.  Boot the system with installation media  
    使用安裝媒體引導系統
    
2.  Press any key when you see **“Press any key to start the configuration importer”**.  
    當您看到 **「按任意鍵啟動配置導入程式」** 時，請按任意鍵。
    
    1.  If you see the login prompt, you have passed the importer and will need to reboot.  
        如果您看到登入提示，則表示您已通過匯入程序，需要重新啟動。
        
3.  Type the device name of the existing drive that contains the configuration and press enter.  
    輸入包含配置的現有磁碟機的裝置名稱，然後按 Enter 鍵。
    
4.  If Importer is successful, the boot process will continue into the live environment using the stored configuration on disk.  
    如果導入程式成功，引導程序將使用磁碟上儲存的配置繼續進入即時環境。
    
5.  If Importer was unsuccessful, we will be returned to the device selection prompt. Confirm the device name is correct and try again. Otherwise, there may be possible disk corruption and restoring from backup.  
    如果導入程式不成功，我們將返回到設備選擇提示。確認設備名稱正確並重試。否則，可能會出現磁碟損壞並從備份還原的情況。
    

At this point, the system will boot up with a fully functional firewall in live environment using existing configuration but will not overwrite the previous installation. Use this feature for safely previewing or testing upgrades.

此時，系統將使用現有配置在即時環境中啟動功能齊全的防火牆，但不會覆蓋先前的安裝。使用此功能可以安全地預覽或測試升級。

For new installations or migrations, follow this process:

對於新安裝或遷移，請遵循以下流程：

1.  We must have a 2nd USB drive formatted with FAT or FAT32 File system.  
    我們必須有一個使用 FAT 或 FAT32 檔案系統格式化的第二個 USB 驅動器。
    
    1.  Preferable non-bootable USB drive.  
        首選不可啟動的USB驅動器。
        
2.  Create a **conf** directory on the root of the USB drive  
    在 USB 磁碟機的根目錄下建立 **conf** 目錄
    
3.  Place an *unencrypted* <downloaded backup>.xml into /conf and rename the file to **config.xml** (`/conf/config.xml`)  
    將 *未加密的* <downloaded backup>.xml 放入 /conf 並將檔案重新命名為 **config.xml** (`/conf/config.xml`)
    
4.  Put both the Installation media and the 2nd USB drive into the system and power up / reboot.  
    將安裝媒體和第二個USB驅動器放入系統中並啟動/重新啟動。
    
5.  Boot the system from the OPNsense Installation media via Boot Menu or BIOS (UEFI).  
    透過啟動選單或BIOS (UEFI) 從 OPNsense 安裝媒體啟動系統。
    
6.  Press any key when you see: **“Press any key to start the configuration importer”**  
    當您看到：**「按任一鍵啟動配置導入程式」時，請按任一鍵**
    
7.  Type the device name of the 2nd USB Drive, e.g. da0 or nvd0 , and press Enter.  
    輸入第二個USB驅動器的裝置名稱，例如da0 或 nvd0 ，然後按 Enter。
    
    1.  If Importer is successful, the boot process will continue into the Live environment using the configuration stored on the USB drive.  
        如果導入程式成功，引導程序將使用儲存在USB磁碟機上的設定繼續進入即時環境。
        
    2.  If unsuccessful, the importer will error and return to the device selection prompt. In this case, repeat steps 1-3 again.  
        如果不成功，導入器將出錯並返回到裝置選擇提示。在這種情況下，請再次重複步驟 1-3。
        

### [Live Environment](#id11)｜[生活環境](#id11)

![../_images/opnsense_liveenv.png](<../images/5531e393-opnsense_liveenv.png>)

After booting with an OPNsense Full Image (DVD, VGA, Serial), the firewall will be in the Live environment with and without the use of OPNsense Importer. We can interact with the Live environment via Local Console, GUI (HTTPS), or SSH.

使用 OPNsense 完整映像（DVD, VGA、序列）啟動後，無論是否使用 OPNsense 導入器，防火牆都會處於即時環境中。我們可以透過本地控制台、GUI（HTTPS）或SSH與Live環境互動。

By default, we can log into the shell using the user `root` with the password `opnsense` to operate the live environment via the local console.

預設情況下，我們可以使用使用者`root`和密碼`opnsense`登入shell，透過本機控制台操作即時環境。

The GUI is accessible at [https://192.168.1.1/](https://192.168.1.1/) using Username: `root` Password: `opnsense` by default (unless a previous configuration was imported).

預設情況下，可以使用使用者名稱：`root`密碼：`opnsense`在[https://192.168.1.1/](https://192.168.1.1/)訪問GUI（除非匯入了先前的設定）。

Using SSH we can access the firewall at IP **192.168.1.1** . Both the **root** and **installer** users are available with the password specified above.

使用 SSH 我們可以存取位於 IP **192.168.1.1**的防火牆。**root**和**installer** 使用者都可以使用上面指定的密碼。

Note

注意事項

The installation media is read-only, which means your current live configuration will be lost after reboot.

安裝媒體是唯讀的，這表示您目前的即時配置將在重新啟動後遺失。

Continue to [OPNsense Installer](#opnsense-installer) to install OPNsense to the local storage device.

繼續 [OPNsense 安裝程序](#opnsense-installer) 將 OPNsense 安裝到本機儲存裝置。

### [OPNsense Installer](#id12)｜[OPNsense 安裝程序](#id12)

Note

注意事項

To invoke the installer, log in with user **installer** and password **opnsense**

若要呼叫安裝程序，請使用使用者 **installer**和密碼**opnsense** 登入

After successfully booting up with the OPNsense Full Image (DVD, VGA, Serial), the firewall will be at the Live Environment’s login: prompt. To start the installation process, login with the user `installer` and password `opnsense`. If Importer was used to import an existing configuration, the installer and root user password will be the root password from the imported configuration.

使用 OPNsense 完整映像（DVD, VGA，串列）成功啟動後，防火牆將出現在即時環境的登入：提示字元處。若要開始安裝流程，請使用使用者`installer`和密碼`opnsense`登入。如果使用導入程式導入現有配置，則安裝者和 root 使用者密碼將是導入配置中的 root 密碼。

If the installer user does not work, log in as user root and select: `8) Shell` from the menu and type `opnsense-installer`. The `opnsense-importer` can also be run this way should you need to rerun the import.

如果安裝程式使用者不起作用，請以 root 使用者身分登錄，然後從選單中選擇：`8) Shell`，然後輸入`opnsense-installer`。如果您需要重新執行匯入，也可以透過這種方式執行 `opnsense-importer`。

The installer can always be run to clone an existing system, even for Nano images. This can be useful for creating live backups for later recovery.

始終可以運行安裝程式來克隆現有系統，甚至對於 Nano 映像也是如此。這對於建立即時備份以供以後恢復非常有用。

Tip

提示

The installer can also be started from an internal host using SSH. The default IP address is `192.168.1.1`

也可以使用 SSH 從內部主機啟動安裝程式。預設IP位址為`192.168.1.1`

Attention

注意

When installing an appliance with SD or MMC flash card storage, ensure you select the UFS filesystem and choose `mmcsd0` in the Disk Selection. Do not choose `da0` as that is the USB drive. As an example, this is applicable to the DEC677 Desktop Security Appliance.

安裝具有 SD 或 MMC 快閃記憶體卡儲存的裝置時，請確保選擇 UFS 檔案系統，並在磁碟選擇中選擇 `mmcsd0`。不要選擇`da0`，因為它是USB 驅動器。例如，這適用於DEC677桌面安全設備。

The installation process involves the following steps:

安裝過程包括以下步驟：

1.  Keymap selection - The default configuration should be fine for most occasions.  
    鍵映射選擇 - 預設配置應該適合大多數情況。
    
2.  Install (UFS|ZFS) - Choose UFS or ZFS filesystem. ZFS is in most cases the best option as it is the most reliable option, but it does require enough capacity (a couple of gigabytes at least).  
    安裝 (UFS|ZFS) - 選擇 UFS 或 ZFS 檔案系統。 ZFS 在大多數情況下是最好的選擇，因為它是最可靠的選擇，但它確實需要足夠的容量（至少幾千兆位元組）。
    
3.  Partitioning (ZFS) - Choose a device type. The default option (stripe) is usually acceptable when using a single disk.  
    分區 (ZFS) - 選擇設備類型。使用單一磁碟時，預設選項（條帶）通常是可以接受的。
    
4.  Disk Selection (ZFS) - Select the Storage device e.g. `da0` or `nvd0`  
    磁碟選擇 (ZFS) - 選擇儲存設備，例如`da0` 或 `nvd0`
    
5.  Last Chance! - Select Yes to continue with partitioning and to format the disk. However, doing so will **destroy** the contents of the disk.  
    最後的機會！ - 選擇「是」繼續分割區並格式化磁碟。但是，這樣做會**破壞**磁碟的內容。
    
6.  Continue with recommended swap (UFS) - Yes is usually fine here unless the install target is very small (< 16GB)  
    繼續使用建議的交換 (UFS) - 此處「是」通常沒問題，除非安裝目標非常小（< 16GB）
    
7.  Select Root Password - Change and confirm the new root password  
    選擇 Root 密碼 - 更改並確認新的 root 密碼
    
8.  Select Complete Install - Exits the installer and reboots the machine. The system is now installed and ready for initial configuration.  
    選擇完整安裝 - 退出安裝程式並重新啟動電腦。系統現已安裝並準備好進行初始設定。
    

Warning

警告

You will lose all files on the installation disk. If another disk is to be used then choose a Custom installation instead of the Quick/Easy Install.

您將會遺失安裝盤上的所有檔案。如果要使用另一個磁碟，則選擇自訂安裝而不是快速/輕鬆安裝。

### [Nano Image](#id13)｜[奈米影像](#id13)

To use the nano image follow this process:

要使用奈米圖像，請遵循以下過程：

1.  Create the system disk by using the Nano image. See [Installation Media](#installation-media) how to write the nano image to disk.  
    使用Nano鏡像建立系統磁碟。請參閱[安裝媒體](#installation-media)如何將nano鏡像寫入磁碟。
    
2.  Install the system disk drive into the system.  
    將系統磁碟機安裝到系統中。
    
3.  Configure the system (BIOS) to boot from this disk.  
    將系統 (BIOS) 配置為從此磁碟啟動。
    
4.  After the system boots, the firewall is ready to be configured.  
    系統啟動後，防火牆就可以進行設定了。
    

Using the nano image for embedded systems, your firewall is already up and running. The configuration settings to enable Memory Disks (RAM disks) that minimize write cycles to relevant partitions by mounting these partitions in system memory and reporting features are disabled by default.

使用嵌入式系統的奈米映像，您的防火牆已經啟動並運行。預設情況下，停用記憶體磁碟（RAM 磁碟）的配置設置，透過將這些分割區掛載到系統記憶體中來最小化相關分割區的寫入週期，並且報告功能處於停用狀態。

## [Initial Configuration](#id14)｜[初始配置](#id14)

After installation, the system will prompt you for the interface assignment. If you ignore this, then the default settings will be applied. Installation ends with the login prompt.

安裝完成後，系統會提示您進行介面分配。如果您忽略這一點，則將套用預設設定。安裝以登入提示結束。

By default you have to log in to enter the console.

預設情況下，您必須登入才能進入控制台。

**Welcome message**

**歡迎留言**

```yaml
* * * Welcome to OPNsense [OPNsense 15.7.25 (amd64/OpenSSL) on OPNsense * * *

WAN (em1)     -> v4/DHCP4: 192.168.2.100/24
LAN (em0)     -> v4: 192.168.1.1/24

FreeBSD/10.1 (OPNsense.localdomain) (ttyv0)

login:
```

Tip

提示

A user can login to the console menu with his credentials. The default credentials after a fresh install are username “root” and password “opnsense”.

使用者可以使用其憑證登入控制台選單。全新安裝後的預設憑證是使用者名稱「root」和密碼「opnsense」。

VLANs and assigning interfaces

VLAN 和分配介面

If you choose to do manual interface assignment or when no config file can be found then you are asked to assign Interfaces and VLANs. VLANs are optional. If you do not need VLANs then choose **no**. You can always configure VLANs at a later time.

如果您選擇手動指派介面或找不到設定文件，系統會要求您指派介面和 VLAN。 VLAN 是選購的。如果您不需要 VLAN，則選擇**否**。您始終可以稍後配置 VLAN。

LAN, WAN and optional interfaces

LAN, WAN及可選接口

The first interface is the LAN interface. Type the appropriate interface name, for example “em0”. The second interface is the WAN interface. Type the appropriate interface name, e.g. “em1” . Possible additional interfaces can be assigned as OPT interfaces. If you assigned all your interfaces you can press \[ENTER\] and confirm the settings. OPNsense will configure your system and present the login prompt when finished.

第一個接口是LAN接口。鍵入適當的介面名稱，例如“em0”。第二個接口是WAN接口。輸入適當的介面名稱，例如“em1”。可能的附加介面可指派為OPT 介面。如果您指派了所有接口，您可以按\[ENTER\]並確認設定。 OPNsense 將設定您的系統並在完成後顯示登入提示。

Minimum installation actions

最少的安裝操作

In case of a minimum install setup (i.e. on CF cards), OPNsense can be run with all standard features, except for the ones that require disk writes, e.g. a caching proxy like Squid. Do not create a swap slice, but a RAM Disk instead. In the GUI enable System ‣ Settings ‣ Miscellaneous ‣ RAM Disk Settings and set the size to 100-128 MB or more, depending on your available RAM. Afterwards reboot.

如果是最低安裝設定（即在CF卡上），OPNsense 可以使用所有標準功能運行，但需要磁碟寫入的功能除外，例如像 Squid 這樣的快取代理。不要建立交換片，而是建立 RAM 磁碟。在GUI中啟用系統‣設定‣雜項‣RAM磁碟設定並將大小設為100-128MB或更大，取決於您可用的RAM。之後重新啟動。

**Enable RAM disk manually**

**手動啟用RAM磁碟**

[![../_images/Screenshot_Use_RAMdisks.png](<../images/adf8cae3-Screenshot_Use_RAMdisks.png>)](https://docs.opnsense.org/_images/Screenshot_Use_RAMdisks.png)

Then via console, check your /etc/fstab and make sure your primary partition has **rw,noatime** instead of just **rw**.

然後透過控制台，檢查您的 /etc/fstab 並確保您的主分區有 **rw,noatime**而不是只有**rw**。
