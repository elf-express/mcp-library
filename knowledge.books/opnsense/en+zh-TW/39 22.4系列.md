# 22.4 Series｜22.4系列

> 章節：[Releases](<000 目錄.md#c-1>) › [Business Edition](<000 目錄.md#c-3>)

The OPNsense business edition successfully transitions to this 22.4 release with a new API-capable VLAN interface including QinQ support, FreeBSD 13 and many other improvements. Please make sure to read the migration notes before upgrading.

OPNsense 商業版已成功升級至22.4版本，並新增了相容API VLAN的介面，包括 QinQ 支援、FreeBSD 13 相容性以及其他許多改進。升級前請務必閱讀遷移說明。

Download link is as follows. An installation guide [\[1\]](<55 初始安裝和配置.md>) and the checksums for the images can be found below as well.

下載連結如下。安裝指南 [\[1\]]( https://docs.opnsense.org/manual/install.html ) 和映像校驗和也如下所示。

[https://downloads.opnsense.com/](https://downloads.opnsense.com/)

Known issues and limitations:

已知問題和限制：

-   This release contains a new major operating system version and should be carried out with the necessary care. Despite extended test coverage changes made by FreeBSD may still affect operation without our knowledge. Except for ZFS boot environments rollbacks between major operating system versions are extremely fragile and a reinstall of an older version should be attempted in the worst case. For more information please consult the FreeBSD 13.0 release notes [\[43\]](https://www.freebsd.org/releases/13.0R/relnotes/) .  
    此版本包含一個新的主要作業系統版本，因此應謹慎操作。儘管測試覆蓋範圍已擴大，但 FreeBSD 所做的更改仍可能在我們不知情的情況下影響系統運作。除ZFS啟動環境外，主要作業系統版本之間的回溯極度不穩定，最壞情況下應嘗試重新安裝舊版。更多資訊請參閱 FreeBSD 13.0發行說明 [\[43\]]( https://www.freebsd.org/releases/13.0R/relnotes/ )。
    
-   IPsec hash and cipher removals in FreeBSD 13 can affect existing setups as insecure cryptographic options have been removed upstream. If you are using MD5, Blowfish, DES, 3DES, or CAST128 in your phase 2 please move to more secure settings prior to the upgrade. Note that phase 1 settings are unaffected, but insecure settings should still be avoided. For more information see the FreeBSD commit in question [\[44\]](https://github.com/opnsense/src/commit/16aabb761c0a) .  
    FreeBSD 13 中 IPsec 雜湊和加密演算法的移除可能會影響現有配置，因為上游已移除不安全的加密選項。如果您在第二階段使用了MD5 、Blowfish、 DES 、3DES 或CAST128 ，請在升級前遷移到更安全的設定。請注意，第一階段的設定不受影響，但仍應避免使用不安全的設定。更多資訊請參閱相關的 FreeBSD 提交 [\[44\]]( https://github.com/opnsense/src/commit/16aabb761c0a )。
    
-   The Realtek vendor driver is no longer bundled with the updated FreeBSD kernel. If unsure whether FreeBSD 13 supports your Realtek NIC please install the os-realtek-re plugin prior to upgrading to retain operability of your NICs.  
    更新後的 FreeBSD 核心不再包含 Realtek 廠商驅動程式。如果您不確定 FreeBSD 13 是否支援您的 Realtek NIC網卡，請在升級前安裝 os-realtek-re 插件，以確保網路卡的正常運作。
    
-   MAC spoofing now only pertains to the configured interface and not the VLAN siblings or parent interface. This can introduce unwanted configuration due to previous side effects in the code. Make sure to assign and set the spoofed MAC for all interfaces that require a spoofed MAC or simply spoof the MAC on the parent and leave the VLAN sibling settings empty to let them follow the parent MAC automatically. If in doubt the parent interface can be set into promiscuous mode now to allow for mixed MAC address use across VLANs too.  
    MAC欺騙現在僅適用於已配置的接口，而不適用於VLAN同級接口或父接口。由於先前程式碼中的副作用，這可能會引入不必要的配置。請確保為所有需要欺騙MAC的介面分配並設定欺騙的MAC位址，或直接在父介面上欺騙MAC位址，並將同級介面的VLAN設定留空，使其自動跟隨父介面MAC位址。如有疑問，現在可以將父介面設定為混雜模式，以允許跨 VLAN 混合使用MAC位址。
    
-   Media and hardware offload settings are no longer shown for non-parent interfaces and need to be set individually on the parent interface to take effect. This can introduce unwanted configuration due to previous side effects in the code. If the parent interface was not previously assigned please assign it to reapply the required settings.  
    媒體和硬體卸載設定不再顯示在非父介面上，需要單獨在父介面上設定才能生效。由於先前程式碼中的副作用，這可能會導致不必要的配置。如果之前未指派父接口，請先指派以重新套用所需的設定。
    
-   NTPD defaults changed to exclude the “iburst” option by default. “limited” setting was detached from “kod” option. In both cases configuration adjustments can achieve previous behaviour if required.  
    NTPD預設設定已更改，預設不包含「iburst」選項。 “limited”設定已從“kod”選項中分離。如有需要，可透過配置調整恢復之前的行為。
    
-   Rebind checks through os-dyndns or os-rfc2136 will no longer work due to the deprecation of both plugins. Please add your rebind hosts manually or disable rebind protection prior to the upgrade.  
    由於 os-dyndns 和 os-rfc2136 插件已被棄用，透過這兩個插件進行的重新綁定檢查將不再有效。請手動新增您的重新綁定主機，或在升級前停用重新綁定保護。
    
-   GRE link1 support has been removed and needs a static route to function now.  
    GRE link1 支援已移除，現在需要靜態路由才能正常運作。
    
-   Circular logging support has been removed. No user interaction is required.  
    循環日誌記錄支援已被移除。無需用戶互動。
