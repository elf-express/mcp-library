# Diagnostics｜診斷

> 章節：[Interfaces](<000 目錄.md#c-19>)

The interface diagnostics page contains various tools to help debug network issues.

介面診斷頁麵包含各種工具，可協助調試網路問題。

## ARP Table｜ARP表格

The [ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol) table module shows all MAC addresses known by this firewall.

[ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol)表模組顯示此防火牆已知的所有MAC位址。

|   |   |
| --- | --- |
| IP | IPv4 address<br>IPv4 位址 |
| MAC | [MAC](https://en.wikipedia.org/wiki/MAC_address) address<br>[MAC](https://en.wikipedia.org/wiki/MAC_address)地址 |
| Manufacturer<br>製造商 | Manufacturer looked up with the mac address above<br>根據上述 MAC 位址尋找製造商 |
| Interface<br>介面 | Associated interface<br>相關介面 |
| Interface name<br>介面名稱 | The name of the interface if found<br>如果找到接口，則顯示接口名稱 |
| Hostname<br>主機名稱 | In case of a DHCPv4 client, the hostname when found in the leases file<br>如果是 DHCPv4 用戶端，則主機名稱取自租約檔案 |

## Netstat

The netstat module contains a useful set of network status and statistics metrics, which are split into a number of topics.

netstat 模組包含一組有用的網路狀態和統計指標，這些指標分為多個主題。

Tip

提示

Use the refresh icon in the tab to refresh the data in it (selection won't change).

使用標籤頁中的刷新圖示刷新其中的資料（選擇不會改變）。

In order of relevance you can find the following information here:

以下資訊依相關性排序如下：

### Interfaces｜介面

This section contains all (physical and virtual) attached interfaces to the system containing metrics like the number of packets and bytes send- and received per (hardware) address.

本節包含系統的所有（實體和虛擬）連接接口，其中包含諸如每個（硬體）位址發送和接收的資料包和位元組數等指標。

### Protocol｜協定

Contains system wide statistics for each network protocol. Examples of statistics that can be found in this region are the number of tcp listening connections, sent packets, duplicate packets, etc, etc.

包含每個網路協定的系統級統計資料。例如，此區域可以找到 TCP 監聽連線數、已傳送資料包數、重複資料包數等統計資料。

### Sockets｜插座

Displays network and unix domain sockets, this basically combines `netstat` with `sockstat` on FreeBSD in order to provide insights into which process is listening were combined with metrics known by the system.

顯示網路和 Unix 網域套接字，基本上將 FreeBSD 上的`netstat`與`sockstat`結合起來，以便提供有關哪個進程正在監聽的見解，並結合系統已知的指標。

### Netisr

Show statistics from the kernel network dispatch service, known as `netisr(9)`.

顯示內核網路調度服務（稱為`netisr(9)`的統計資訊。

### Memory｜記憶

Show statistics recorded by the memory management routines (`mbuf(9)`). The network manages a private pool of memory buffers.

顯示記憶體管理例程（ `mbuf(9)` ）所記錄的統計資料。網路管理著一個私有的記憶體緩衝區池。

### Bpf｜BPF

Show statistics about `bpf(4)` peers. This includes information like how many packets have been matched, dropped and received by the bpf device, also information about current buffer sizes and device states.

顯示有​​關`bpf(4)`對等體的統計資訊。這包括bpf設備已匹配、丟棄和接收的資料包數量等信息，以及當前緩衝區大小和設備狀態等資訊。

## Packet capture｜資料包捕獲

The packet capture module can be used to deep dive into traffic passing a (or multiple) network interfaces. It has some options you can choose from, which are detailed below.

封包擷取模組可用於深入分析流經一個或多個網路介面的流量。它提供了一些可選功能，詳情如下。

---

|   |   |
| --- | --- |
| Interface<br>介面 | List of interfaces to start a capture on. A tcpdump process is started on each selected interface<br>要開始捕獲的介面清單。在每個選定的介面上啟動 tcpdump 進程 |
| Promiscuous<br>亂交 | When set, the system will capture all traffic present on the interface instead of the traffic heading to the firewall.<br>設定後，系統將捕捉介面上存在的所有流量，而不是前往防火牆的流量。 |
| Address Family<br>位址族 | Capture IPv4, IPv6 or both<br>擷取 IPv4、IPv6 或兩者皆擷取 |
| Invert Protocol<br>反轉協議 | Select all but the protocol selected below<br>選擇下方已選協議之外的所有協議 |
| Protocol<br>協定 | The protocol to filter on<br>要使用的過濾協定 |
| Host Address<br>主機位址 | This value is either the Source or Destination IP/MAC address or subnet in CIDR notation. The packet capture will look for this address in either field. Matching can be negated by preceding the value with “`not`”. Multiple IP addresses or CIDR subnets may be specified as boolean expression. If you leave this field blank, all packets on the specified interface will be captured. Example: `not 10.0.0.0/24 not and not 11.0.0.1 or 00:0a:01:02:03:04`<br>此值可以是來源位址或目標位址IP/MAC ，也可以是子網路位址CIDR ）。封包擷取程式會在來源位址或目標位址欄位中尋找此位址。如果符合失敗，可以在值前加上「 `not` 」。可以使用布林運算式指定多個位址IP或子網路CIDR 。如果將此欄位留空，則會擷取指定介面上的所有資料包。範例： `not 10.0.0.0/24 not and not 11.0.0.1 or 00:0a:01:02:03:04` |
| Invert Port<br>反轉連接埠 | Select all but the port selected below<br>選取下方選取連接埠以外的所有連接埠 |
| Port<br>連接埠 | Port number to filter on (e.g. `443` for standard https, `22` for ssh)<br>要過濾的連接埠號碼（例如， `443`表示標準 https， `22`表示 ssh） |
| Packet Length<br>資料包長度 | The Packet length is the number of bytes of each packet that will be captured. Default value is 0, which will capture the entire frame regardless of its size.<br>資料包長度是將捕獲的每個資料包的位元組數。預設值為 0，這將捕獲整個幀，無論其大小如何。 |
| Count<br>計數 | This is the number of packets the packet capture will grab (per selected interface). Default value is 100. Enter 0 (zero) for no count limit.<br>這是封包擷取將抓取的封包數量（每個選定的介面）。預設值為 100。輸入 0（零）表示無計數限制。 |
| Description<br>說明 | Description to be displayed in “jobs” tab<br>將在「職位」標籤中顯示的說明 |

Packet capture uses [tcpdump](https://www.tcpdump.org/) and runs in the background. After a capture is performed you can either look into it using the **View capture** button in the jobs tab or download the pcap file(s) to inspect it in an external tool, such as [Wireshark](https://www.wireshark.org/).

抓包使用[tcpdump](https://www.tcpdump.org/)並在背景運行。執行擷取後，您可以使用作業標籤中的 **檢視擷取** 按鈕檢視它，也可以下載 pcap 檔案以在外部工具（例如 [Wireshark](https://www.wireshark.org/)）中檢查它。

The jobs tab contains all running or executed captures, the following options are available per capture job:

「作業」標籤包含所有正在執行或已執行的擷取任務，每個擷取作業都有以下可用選項：

-   Shows the capture is currently active  
    顯示捕獲目前處於活動狀態。
-   Remove capture (stops capture when currently active)  
    移除捕獲（停止目前正在運行的捕獲）
-   Stop the current capture  
    停止目前捕獲
-   (Re)starts the current capture, removes previous results when executed before  
    （重新）啟動目前捕獲，如果之前已執行，則刪除先前的結果。
-   Download a zip file containing all captured pcap files and a json file with selected options  
    下載包含所有捕獲的 pcap 檔案和帶有所選選項的 json 檔案的 zip 文件
-   View capture in high detail  
    以高解析度檢視拍攝畫面
-   View capture in medium detail  
    以中等細節查看拍攝畫面
-   View capture in standard detail  
    以標準細節看拍攝效果

Tip

提示

All view buttons can be used when the capture is still active, they will just show the details collected until now.

當擷取仍在進行時，所有檢視按鈕均可使用，它們只會顯示到目前為止收集到的詳細資訊。

## Ping｜平

Use ping to establish if a remote host can be reached using ICMP echo requests. It’s one of the most used tools to validate basic connectivity.

使用 ping 指令透過ICMP回顯請求來決定是否可以存取遠端主機。它是驗證基本連接性最常用的工具之一。

---

|   |   |
| --- | --- |
| Hostname or IP<br>主機名稱或IP | Hostname or IP address to send the icmp packet too<br>發送 ICMP 封包的主機名稱或IP位址 |
| Address Family<br>位址家庭 | Send using IPv4 or IPv6<br>使用 IPv4 或 IPv6 傳送 |
| Source address<br>來源位址 | Source address to use, can be any address configured on this firewall<br>要使用的來源位址，可以是此防火牆上設定的任何位址 |
| Packet size<br>封包大小 | Specify the number of data bytes to be sent. Keep in mind this is the payload size, an IP and ICMP header are added.<br>指定要傳送的資料位元組數。請注意，這是有效載荷大小，也會添加IP和ICMP頭部。 |
| Do not fragment<br>不要碎片化 | Set DF bit.<br>設定DF位。 |
| Description<br>說明 | Description to be displayed in “jobs” tab<br>將在「職位」標籤中顯示的說明 |

Tip

提示

To locate MTU (Maximum transmission unit) issues, use the “Do not fragment” option to force a packet of certain size to travel the network

若要尋找MTU （最大傳輸單元）問題，請使用「不分片」選項強制特定大小的封包在網路中傳輸。

Tip

提示

When the default ping is not able to reach the target, but one with a preset source address is, one usually needs to add a static route to force traffic using the correct source address. This is for example common for IPsec policy based tunnels which install a kernel trap on the specified source network.

當預設 ping 指令無法到達目標位址，但使用預設來源位址的 ping 指令可以到達時，通常需要新增一條靜態路由，強制流量使用正確的來源位址。例如，基於 IPsec 策略的隧道通常會在指定的來源網路上安裝核心陷阱，這種情況很常見。

The jobs tab contains all running or executed pings, the following options and properties are available per job:

「作業」標籤包含所有正在執行或已執行的 ping 任務，每個作業都有下列選項和屬性：

-   Shows the ping is currently active  
    顯示 ping 操作目前處於活動狀態
-   Remove ping (stops capture when currently active)  
    移除 pi​​ng 功能（目前處於活動狀態時停止捕獲）
-   Stop the current ping  
    停止目前ping
-   (Re)starts the current ping, removes previous results when executed before  
    （重新）啟動目前 ping 任務，如果之前已執行過，則刪除先前的結果。

|   |   |
| --- | --- |
| description<br>說明 | Job description<br>職位說明 |
| hostname<br>主機名稱 | Target hostname or ip address<br>目標主機名稱或 IP 位址 |
| source\_address | Source address (default empty)<br>來源位址（預設為空） |
| send<br>發送 | Number of packets send<br>發送的資料包數量 |
| received<br>已接收 | Number of packets received<br>已接收封包數 |

| max<br>最大 | max time to live (ms)<br>最大存活時間（毫秒） |
| avg<br>平均值 | average time to live (ms)<br>平均存活時間（毫秒） |
| loss<br>損失 | loss percentage<br>損失百分比 |

## Trace Route｜追蹤路線

Use [traceroute](https://www.freebsd.org/cgi/man.cgi?query=traceroute) / [traceroute6](https://www.freebsd.org/cgi/man.cgi?query=traceroute6) to measure the path traffic would follow when trying to reach a specific host.

使用 [traceroute](https://www.freebsd.org/cgi/man.cgi?query=traceroute) / [traceroute6](https://www.freebsd.org/cgi/man.cgi?query=traceroute6)來測量流量嘗試到達特定主機時將遵循的路徑。

---

|   |   |
| --- | --- |
| Hostname or IP<br>主機名稱或IP | Target hostname or ip address<br>目標主機名稱或IP位址 |
| Address Family<br>地址家庭 | Address family to use<br>地址家庭使用 |
| Protocol<br>協議 | Protocol to use for the trace, by default UDP is used, if this doesn’t work, ICMP is available as alternative<br>用於追蹤的協議，預設使用UDP ，如果此協議不起作用，則可以使用ICMP作為備選方案 |
| Source address<br>來源位址 | Source address (default empty)<br>來源位址（預設為空） |

Tip

提示

The result grid also contains the [autonomous system number](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\)) which can be practical if you want to filter traffic to or from a specific party. Use Firewall ‣ Aliases to collect the associated networks and add them in rules.

結果網格中還包含[自治系統編號](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\) ），如果您想過濾進出特定方的流量，這將非常有用。使用「防火牆」‣「別名」收集關聯的網路並將其新增至規則中。
