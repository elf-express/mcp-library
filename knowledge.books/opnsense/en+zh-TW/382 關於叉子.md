# About the Fork｜關於叉子

> 章節：[History](<000 目錄.md#c-65>)

Welcome to about the fork. This page is intended to explain the original motivation for forking, but keep in mind that currently less than 10% of the original legacy code base remains. As it stands today, OPNsense has evolved from being a fork to a whole new security platform with leading innovations such as weekly security updates for all components, a REST API, inline Intrusion Prevention and an intuitive modern user interface.

歡迎來到關於叉子。本頁旨在解釋分叉的原始動機，但請記住，目前原始遺留程式碼庫的剩餘量不足 10%。就目前而言，OPNsense 已從一個分支發展成為一個全新的安全平台，具有領先的創新，例如所有組件的每周安全更新、REST API、內聯入侵防禦和直觀的現代用戶界面。

Let’s fork and lift the project!

讓我們分叉並提升該項目！

![../_images/fork-lift_new.jpg](<../images/d7285c5b-fork-lift_new.jpg>)

## So why did we fork?｜那我們為什麼要分叉呢？

Back in 2014, after having sponsored pfSense® for years, we felt that there was no other option than to fork the project and to keep the spirit of the - original m0n0wall based fork - alive. Below you can read about our original motivations and the birth of OPNsense®.

早在 2014 年，在贊助 pfSense® 多年後，我們覺得除了分叉這個計畫並保持基於 m0n0wall 的原始分叉精神之外，別無選擇。您可以在下面了解我們的初衷和 OPNsense® 的誕生。

### Technical｜科技

We had technical reasons to fork. As much as we love the functionality/feature set of pfSense, we do not enjoy the [code quality](<237 基礎與未來.md>) and dispersed development method. We like structure, achievable goals set forth in a [roadmap](https://opnsense.org/roadmap/) with regular releases and a decent [framework](<242 建築學.md>).

我們出於技術原因進行分叉。儘管我們非常喜歡 pfSense 的功能/特性集，但我們不喜歡[程式碼品質](<237 基礎與未來.md>) 和分散的開發方法。我們喜歡[路線圖](https://opnsense.org/roadmap/)中規定的結構、可實現的目標，定期發布和體面的[框架](<242 建築學.md>)。

### Security｜安全性

On the security part the main issue was the need to separate logic. The GUI should not perform tasks that require root access, and potential security issues should be fixed before they become a real problem.

在安全部分，主要問題是需要分離邏輯。 GUI 不應執行需要 root 存取權的任務，並且應在潛在的安全問題成為真正的問題之前將其修復。

### Quality｜品質

As for quality, all new features will be built using a solid [framework](<242 建築學.md>) with a Model View Controller. For this purpose we choose [Phalcon](https://phalcon.io/) as it is the fastest open source PHP framework available. And we will gradually migrate parts inherited from pfSense to the new framework to avoid a big-bang approach.

至於質量，所有新功能都將使用具有模型視圖控制器的可靠[框架](<242 建築學.md>)來構建。為此，我們選擇[Phalcon](https://phalcon.io/)，因為它是可用的最快的開源PHP框架。我們將逐步將從 pfSense 繼承的部分遷移到新框架，以避免大爆炸。

### Community｜社群

A thriving community can only exist when people are willing to share. We want to make it easier for people to join and help to build the community. With pfSense, this has been rather difficult, as the tools to build it are difficult to use and often do not work in the first few attempts. And since 2014 they are not freely available any more, you need to apply for access with ESF. We believe a good open source project has nothing to hide so access to the sources should be there for all. It will remain a mystery why ESF made that move, as commit rights and read rights are totally different.

只有當人們願意分享時，一個繁榮的社區才能存在。我們希望讓人們更容易加入並幫助建立社區。對於 pfSense，這相當困難，因為建造它的工具很難使用，並且在最初的幾次嘗試中通常不起作用。自 2014 年起，它們不再免費提供，您需要透過 ESF 申請訪問。我們相信一個好的開源專案沒有什麼可隱藏的，因此所有人都應該能夠存取原始碼。 ESF 為何採取這項措施仍是個謎，因為提交權和讀取權完全不同。

Note

筆記

ESF has since changed their policy several times with different license models, including the ESF 6 clause license and the latest being a Apache style license.

此後，ESF 使用不同的授權模型多次更改了其政策，包括 ESF 6 條款授權和最新的 Apache 樣式授權。

### Transparency｜透明度

A real concern with pfSense is transparency. Since Netgate bought the majority share of pfSense and renamed the company to ESF, it has been difficult to understand the direction they want the project to go. Removing the tools from GitHub without prior warning and using the brand name to fence off competitors has scared quite a lot of people. Also the license had changed for no apparent reason…

pfSense 真正關心的是透明度。自從 Netgate 收購了 pfSense 的大部分股份並將公司更名為ESF以來，人們一直很難理解他們希望專案發展的方向。在沒有事先警告的情況下從 GitHub 上刪除這些工具並使用品牌名稱來隔離競爭對手已經讓許多人感到害怕。而且許可證也無緣無故地發生了變化…

### Restore a firm open source project｜恢復一個堅定的開源項目

With OPNsense, we have restored a stable project with clear goals and a very simple license that is suitable for forking and making OEM versions. We think a community project is there for all to use and work with.

透過 OPNsense，我們恢復了一個穩定的項目，具有明確的目標和非常簡​​單的許可證，適合分叉和製作 OEM 版本。我們認為社區計畫可供所有人使用和合作。

## First Release｜首次發布

Much work had already been done before the [first official release](https://web.archive.org/web/20150503182123/https://opnsense.org/opnsense-version-15-1-released/):

在[第一次正式發布](https://web.archive.org/web/20150503182123/https://opnsense.org/opnsense-version-15-1-released/)之前已經做了很多工作：

-   The build-tools had been completely rewritten from the ground up with clear and easy to read build scripts that are portable and small,  
    建置工具已從頭開始完全重寫，具有清晰易讀的建置腳本，這些腳本可移植且小巧，
    
-   OPNsense is now a package that can be installed on top of our custom FreeBSD build (you can literally do pkg remove opnsense and you are left with an almost standard FreeBSD base system),  
    OPNsense 現在是一個可以安裝在我們自訂 FreeBSD 建置之上的軟體套件（您實際上可以執行 pkg remove opnsense ，然後您就剩下一個幾乎標準的 FreeBSD 基本系統），
    
-   The firmware upgrade process is now done with pkgng,  
    韌體升級過程現在透過 pkgng 完成，
    
-   Captive portal has been rewritten and does not make use of kernel patches anymore,  
    強制門戶已重寫，不再使用核心補丁，
    
-   New features (captive portal) have been implemented with a clear structure,  
    新功能（強制門戶）已以清晰的結構實施，
    
-   The check\_reload\_status functionality, effectively the backend daemon starting and stopping components, has been fully rewritten in Python (configd),  
    check\_reload\_status 功能（實際上是後端守護程式啟動和停止元件）已用 Python (configd) 完全重寫，
    
-   Fully reworked the GUI to a modern Bootstrap based one that is also easier to customize if you want to.  
    將 GUI 完全重新設計為基於 Bootstrap 的現代版本，如果您願意，也可以更輕鬆地進行自訂。
    

## Future Development & Focus｜未來發展及重點

Moving forward the focus will remain on code quality and security.

展望未來，重點仍將放在程式碼品質和安全性上。

Note

筆記

A lot of work has been done to improve the code quality and with weekly updates we have proven to be able to act quickly on known security threats. For current status of the project and future development see our [roadmap](https://opnsense.org/roadmap/).

我們已經做了大量工作來提高程式碼質量，並且透過每週更新，我們已經證明能夠對已知的安全威脅快速採取行動。有關專案的當前狀態和未來的發展，請參閱我們的[路線圖](https://opnsense.org/roadmap/)。

### Deciso’s involvement｜Deciso的參與

That being said it is important to know that [Deciso](https://www.deciso.com/) has been a long time sponsor of pfSense and invested a lot of time and money into the project. Deciso helped to make it a success in Europe. Until Netgate bought the company there was room for many others like us, but that has changed unfortunately.

話雖如此，重要的是要知道 [Deciso](https://www.deciso.com/) 一直是 pfSense 的長期贊助商，並為該專案投入了大量時間和金錢。 Deciso 幫助其在歐洲取得了成功。在 Netgate 收購該公司之前，還有許多像我們這樣的其他人的空間，但不幸的是，這種情況已經改變了。

### Closing thoughts｜結束語

In the end it all boils down to the direction we will go both technical as well as community involvement and transparency.

最終，這一切都歸結為我們在技術、社區參與和透明度方面的發展方向。

You are invited! Try OPNsense, be part of the community and help the project move forward. OPNsense is rapidly becoming the number one open source firewall platform!

誠摯邀請您！嘗試 OPNsense，成為社區的一部分並幫助專案向前發展。 OPNsense 正迅速成為排名第一的開源防火牆平台！
