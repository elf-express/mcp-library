The Intrusion Prevention System (IPS) system of OPNsense is based on [Suricata](https://suricata.io/) and utilizes [Netmap](https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.2-RELEASE+and+Ports) to enhance performance and minimize CPU utilization. This deep packet inspection system is very powerful and can be used to detect and mitigate security threats at wire speed.

OPNsense 的入侵防禦系統 ( IPS ) 基於 [Suricata](https://suricata.io/) ，並利用 [Netmap](https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.2-RELEASE+and+Ports)來提升效能並最大限度地減少CPU的資源佔用。此深度套件偵測系統功能強大，能夠以線速偵測和緩解安全威脅。

## [IDS and IPS](#id3)｜[IDS和IPS](#id3)

It is important to define the terms used in this document. An *Intrustion Detection System* (IDS) watches network traffic for suspicious patterns and can alert operators when a pattern matches a database of known behaviors. An *Intrusion Prevention System* (IPS) goes a step further by inspecting each packet as it traverses a network interface to determine if the packet is suspicious in some way. If it matches a known pattern the system can drop the packet in an attempt to mitigate a threat.

明確本文檔中使用的術語至關重要。 *入侵偵測系統* ( IDS ) 監控網路流量中的可疑模式，並在發現與已知行為資料庫相符的模式時向操作員發出警報。 *入侵防禦系統* ( IPS ) 更進一步，它會檢查每個資料包在網路介面上的傳輸過程，以確定該資料包是否有任何可疑之處。如果資料包與已知模式匹配，系統可以丟棄該資料包以降低威脅。

The [Suricata](https://suricata.io/) software can operate as both an IDS and IPS system.

[Suricata](https://suricata.io/)軟體既可以作為IDS系統運行，也可以作為IPS系統運行。

## [Choosing an interface](#id4)｜[選擇界面](#id4)

You can configure the system on different interfaces. One of the most commonly asked questions is which interface to choose. Considering the continued use IPv4, usually combined with [Network Address Translation](<135 網路位址轉換.md>), it is quite important to use the correct interface. If you are capturing traffic on a WAN interface you will see only traffic after address translation. This means all the traffic is originating from your firewall and not from the actual machine behind it that is likely triggering the alert.

您可以在不同的介面上設定係統。最常見的問題之一是應該選擇哪個介面。考慮到 IPv4 的持續使用（通常與網路位址轉換 (NAT) (https://docs.opnsense.org/manual/nat.html)結合使用），使用正確的介面至關重要。如果您在WAN介面上擷取流量，則只會看到經過位址轉換後的流量。這意味著所有流量都來自您的防火牆，而不是來自其後方可能觸發警報的實際電腦。

Rules for an IDS/IPS system usually need to have a clear understanding about the internal network; this information is lost when capturing packets behind NAT.

IDS/IPS系統的規則通常需要對內部網路有清晰的了解；當在NAT後面捕獲封包時，這些資訊會丟失。

Without trying to explain all the details of an IDS rule (the people at Suricata are way better in doing [that](https://suricata.readthedocs.io/en/suricata-5.0.5/rules/index.html)), a small example of one of the ET-Open rules usually helps understanding the importance of your home network.

無需解釋IDS規則的所有細節（Suricata 的人員在這方面做得更好(https://suricata.readthedocs.io/en/suricata-5.0.5/rules/index.html) ），一個ET -Open 規則的小例子通常有助於理解家庭網絡的重要性。

```
alert tls $HOME_NET any -> $EXTERNAL_NET any (msg:"ET TROJAN Observed Glupteba CnC Domain in TLS SNI"; flow:established,to_server; tls_sni; content:"myinfoart.xyz"; depth:13; isdataat:!1,relative; metadata: former_category MALWARE; reference:md5,4cc43c345aa4d6e8fd2d0b6747c3d996; classtype:trojan-activity; sid:2029751; rev:2; metadata:affected_product Windows_XP_Vista_7_8_10_Server_32_64_Bit, attack_target Client_Endpoint, deployment Perimeter, signature_severity Major, created_at 2020_03_30, updated_at 2020_03_30;)
```

The `$HOME_NET` can be configured, but usually it is a static net defined in [RFC 1918](https://tools.ietf.org/html/rfc1918). Using advanced mode you can choose an external address, but bear in mind you will not know which machine was really involved in the attack and it should really be a static address or network.

`$HOME_NET`可以配置，但通常是 [RFC 1918](https://tools.ietf.org/html/rfc1918)中定義的靜態網路。使用高級模式可以選擇外部位址，但請記住，您將無法知道哪台機器真正參與了攻擊，因此它應該是靜態位址或網路。

`$EXTERNAL_NET` is defined as being not the home net, which explains why you should not select all traffic as home since likely none of the rules will match.

`$EXTERNAL_NET`被定義為非歸屬網絡，這解釋了為什麼你不應該將所有流量都選擇為歸屬網絡，因為可能沒有任何規則能夠匹配。

Since the firewall is dropping inbound packets by default it usually does not improve security to use the WAN interface when in IPS mode because it would drop the packet that would have also been dropped by the firewall.

由於防火牆預設會丟棄入站封包，因此在IPS模式下使用WAN介面通常不會提高安全性，因為它會丟棄防火牆也會丟棄的封包。

Note

筆記

IDS mode is available on almost all (virtual) network types. When your network card is not (fully) supported, you can set the tunable `dev.netmap.admode` to the value `2` in which case emulated mode will be enforced (Configurable in System ‣ Settings ‣ Tunables). A list of natively [supported physical adapters](https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.1-RELEASE+and+Ports#SUPPORTED_DEVICES) is available in the FreeBSD man page.

IDS模式幾乎適用於所有（虛擬）網路類型。如果您的網路卡未（完全）支持，您可以將可調參數`dev.netmap.admode`設定為`2` ，此時將強制使用類比模式（可在「系統」‣「設定」‣「可調參數」中設定）。 FreeBSD 手冊頁中提供了原生支援的實體適配器清單(https://www.freebsd.org/cgi/man.cgi?query=netmap&sektion=4&manpath=FreeBSD+12.1-RELEASE+and+Ports#SUPPORTED_DEVICES) 。

## [Download rulesets](#id7)｜[下載規則集](#id7)

When enabling IDS/IPS for the first time the system is active without any rules to detect or block malicious traffic. The download tab contains all rulesets available on the system (which can be expanded using plugins).

首次啟用IDS/IPS時，系統處於啟動狀態，但沒有任何規則來偵測或阻止惡意流量。下載標籤包含系統上所有可用的規則集（可透過外掛程式進行擴充）。

In this section you will find a list of rulesets provided by different parties and when (if installed) they where last downloaded on the system. In previous versions (prior to 21.1) you could select a “filter” here to alter the default behavior of installed rules from alert to block. As of 21.1 this functionality will be covered by **Policies**, a separate function within the IDS/IPS module, which offers more fine grained control over the rulesets.

在本節中，您將找到不同方提供的規則集清單以及它們上次在系統上下載的時間（如果已安裝）。在以前的版本中（21.1之前），您可以在此处选择“过滤器”来将已安装规则的默认行为从警报更改为阻止。从 21.1 开始，此功能将由 **策略** 涵盖，这是 IDS/IPS 模块中的一个单独功能，它提供对规则集更细粒度的控制。

Note

筆記

When migrating from a version before 21.1 the filters from the download rulesets page will automatically be migrated to policies.

從21.1之前的版本遷移時，下載規則集頁面中的篩選器會自動遷移到政策中。

## [Policies](#id8)｜[政策](#id8)

The **policy** menu item contains a grid where you can define policies to apply to installed rules. Here you can add, update or remove policies as well as disabling them. Policies help control which rules you want to use in which manner and are the preferred method to change behaviour. Although you can still update separate rules in the rules tab, adding a lot of custom overwrites there is more sensitive to change and has the risk of slowing down the user-interface.

**策略**選單項目包含一個網格，您可以在其中定義要套用於已安裝規則的策略。您可以在此處新增、更新或刪除策略以及停用它們。策略有助於控制您想要以何種方式使用哪些規則，並且是改變行為的首選方法。儘管您仍然可以在規則標籤中更新單獨的規則，但添加大量自訂覆蓋對變更更加敏感，並且存在減慢使用者介面速度的風險。

A policy entry contains 3 different sections. First some general information, such as the description and if the rule is enabled as well as a priority. Overlapping policies are taken care of in sequence, the first match with the lowest priority number is the one to use.

策略條目包含三個不同的部分。首先是一些常規訊息，例如描述、規則是否啟用以及優先順序。重疊的策略會依序處理，優先順序最低的第一個符合項目將會被使用。

Secondly there are the matching criteria, these contain the **rulesets** a policy applies on as well as the action configured on a rule (disabled by default, alert or drop), finally there is the **rules** section containing the metadata collected from the installed rules, these contain options as affected product (Android, Adobe flash, …) and deployment (datacenter, perimeter).

其次是符合條件，其中包含策略適用的**規則集**以及對規則配置的操作（預設為停用、發出警報或丟棄）；最後是**規則**部分，其中包含從已安裝規則收集的元數據，這些元資料包含受影響的產品（Android、Adobe Flash 等）和部署（資料中心、邊界）等選項。

The last option to select is the new action to use, either disable selected rules, only alert on them or drop traffic when matched.

最後要選擇的選項是要使用的新操作，可以是停用選定的規則、僅對選定的規則發出警報，或在符合時丟棄流量。

Note

筆記

The options in the **rules** section depend on the vendor, when no metadata is provided in the source rule, none can be used at our end.

**規則** 部分中的選項取決於供應商，如果來源規則中沒有提供元數據，則我們這邊無法使用任何元數據。

## [Installed rules](#id9)｜[已安裝規則](#id9)

The rules tab offers an easy to use grid to find the installed rules and their purpose, using the selector on top one can filter rules using the same metadata properties available in the policies view.

規則標籤提供了一個易於使用的網格，用於查找已安裝的規則及其用途；使用頂部的選擇器，可以使用與策略檢視中相同的元資料屬性來篩選規則。

Tip

提示

After applying rule changes, the rule action and status (enabled/disabled) are set, to easily find the policy which was used on the rule, check the matched\_policy option in the filter. Manual (single rule) changes are being marked as policy **“\_\_manual\_\_”**

套用規則變更後，將設定規則動作和狀態（啟用/停用），為了輕鬆尋找規則上使用的策略，請檢查篩選器中的 matches\_policy 選項。手動（單一規則）變更被標記為策略 **“\_\_manual\_\_”**

## [User defined rules](#id10)｜[使用者自訂規則](#id10)

Most of the rules being used on your IDPS system will be supplied by third party vendors like Proofpoint, but in some cases it can be convenient to build some (limited) rules yourself. The “User defined” tab offers this functionality.

您的IDPS系統中使用的大部分規則都由Proofpoint等第三方供應商提供，但在某些情況下，自行建立一些（有限的）規則會很方便。 「使用者自訂」標籤提供了此功能。

### [Fingerprinting](#id11)｜[指紋採集](#id11)

OPNsense includes a very polished solution to block protected sites based on their SSL fingerprint. You can manually add rules in the “User defined” tab.

OPNsense 提供了一個非常完善的解決方案，可以根據網站的SSL指紋來封鎖受保護的網站。您可以在「使用者自訂」標籤中手動新增規則。

### [Bypassing the engine](#id12)｜[繞過引擎](#id12)

The `Bypass` toggle offers the ability to skip traffic inspection, our How-tos section contains a good example to exclude local traffic passing your network and increase routing performance.

`Bypass`開關可以跳過流量檢查，我們的操作指南部分提供了一個很好的範例，可以排除通過您網路的本地流量並提高路由效能。

## [Alerts](#id13)｜[警報](#id13)

In the “Alerts”（警報） tab you can view the alerts triggered by the IDS/IPS system. Use the info button here to collect details about the detected event or threat.

在“Alerts”（警報）選項卡中，您可以查看由IDS/IPS系統觸發的警報。使用此處的「資訊」按鈕可以收集有關偵測到的事件或威脅的詳細資訊。

## [Advanced configuration](#id14)｜[進階配置](#id14)

OPNsense supports custom Suricata configurations in [suricata.yaml](https://suricata.readthedocs.io/en/suricata-6.0.0/configuration/suricata-yaml.html) format. In order to add custom options, create a template file named `custom.yaml` in the `/usr/local/opnsense/service/templates/OPNsense/IDS/` directory.

OPNsense 支援 [suricata.yaml](https://suricata.readthedocs.io/en/suricata-6.0.0/configuration/suricata-yaml.html)格式的自訂 Suricata 配置。若要新增自訂選項，請在`/usr/local/opnsense/service/templates/OPNsense/IDS/`目錄中建立名為`custom.yaml`的範本檔案。

Since this file is parsed by our template system, you are able to use template tags using the [Jinja2](<249 使用模板.md>) language.

由於此文件由我們的模板系統解析，因此您可以使用 [Jinja2](<249 使用模板.md>)語言的模板標籤。

#### [SSL Blacklist](#id21)｜[SSL黑名單](#id21)

*SSL Blacklist* (SSLBL) is a project maintained by abuse.ch. The goal is to provide a list of “bad” SSL certificates identified by abuse.ch to be associated with malware or botnet activities. SSLBL relies on SHA1 fingerprints of malicious SSL certificates and offers various blacklists.

*SSL黑名單*（SSLBL）是由abuse.ch維護的項目。目標是提供由abuse.ch 識別出的與惡意軟體或殭屍網路活動相關的「不良」SSL 憑證清單。 SSLBL依賴SHA1惡意SSL證書的指紋並提供各種黑名單。

See for details: [https://sslbl.abuse.ch/](https://sslbl.abuse.ch/)

詳情請見：[https://sslbl.abuse.ch/](https://sslbl.abuse.ch/)

#### [Feodo Tracker](#id22)｜[Feed Tracker](#id22)

Feodo (also known as Cridex or Bugat) is a Trojan used to commit ebanking fraud and steal sensitive information from the victim’s computer, such as credit card details or credentials. At the moment, Feodo Tracker is tracking four versions of Feodo, and they are labeled by Feodo Tracker as version A, version B, version C and version D:

Feodo（又稱 Cridex 或 Bugat）是一種木馬程序，用於實施網上銀行詐騙，竊取受害者電腦中的敏感信息，例如信用卡詳細信息或憑證。目前，Feodo Tracker 正在追蹤四個版本的 Feodo，並將其標記為 A 版、B 版、C 版和 D 版。

-   **Version A** *Hosted on compromised webservers running an nginx proxy on port 8080 TCP forwarding all botnet traffic to a tier 2 proxy node. Botnet traffic usually directly hits these hosts on port 8080 TCP without using a domain name.*  
    **版本 A** *託管於已入侵的 Web 伺服器上，這些伺服器運行著 nginx 代理，連接埠為 8080 TCP並將所有殭屍網路流量轉送到二級代理節點。殭屍網路流量通常直接透過連接埠 8080 TCP存取這些主機，而無需使用網域名稱。 *
    
-   **Version B** *Hosted on servers rented and operated by cybercriminals for the exclusive purpose of hosting a Feodo botnet controller. Usually taking advantage of a domain name within ccTLD .ru. Botnet traffic usually hits these domain names using port 80 TCP.*  
    **版本 B** *託管於網路犯罪分子租用和營運的伺服器上，其唯一目的是託管 Feodo 殭屍網路控制器。通常利用 .ru 頂級域名下的域名。殭屍網路流量通常使用 80 連接埠TCP ）攻擊這些網域。 *
    
-   **Version C** *Successor of Feodo, completely different code. Hosted on the same botnet infrastructure as Version A (compromised webservers, nginx on port 8080 TCP or port 7779 TCP, no domain names) but using a different URL structure. This Version is also known as Geodo and Emotet.*  
    **C 版本** *Feodo 的後續版本，程式碼完全不同。託管在與 A 版本相同的殭屍網路基礎架構上（被入侵的 Web 伺服器，nginx 運行在 8080 連接埠TCP或 7779 連接埠TCP ，無網域名稱），但使用不同的URL結構。此版本也稱為 Geodo 和 Emotet。 *
    
-   **Version D** *Successor of Cridex. This version is also known as Dridex*  
    **D版** *Cridex的後續版本。此版本也稱為Dridex*
    

See for details: [https://feodotracker.abuse.ch/](https://feodotracker.abuse.ch/)

詳情請見：[https://feodotracker.abuse.ch/](https://feodotracker.abuse.ch/)
