# Aliases｜別名

> 章節：[Firewall](<000 目錄.md#c-26>)

Aliases are named lists of networks, hosts or ports that can be used as one entity by selecting the alias name in the various supported sections of the firewall. These aliases are particularly useful to condense firewall rules and minimize changes.

別名是網路、主機或連接埠的命名列表，透過在防火牆的各個支援部分中選擇別名，可以將其用作實體。這些別名對於壓縮防火牆規則和最小化變更特別有用。

Aliases can be added, modified and removed via Firewall ‣ Aliases.

可以透過 Firewall ‣ Aliases 新增、修改和刪除別名。

## Overview｜概述

The page opens with an overview of the aliases available, including some internal ones available from installed software. At the top of the page you can search for aliases or preselect various types or categories to which they belong.

該頁面開啟後會概述可用的別名，包括已安裝軟體中可用的一些內部別名。在頁面頂部，您可以搜尋別名或預先選擇它們所屬的各種類型或類別。

In order to gain some insights into the current status of the plugins, two additional (meta) fields are being displayed, being:

為了深入了解插件的當前狀態，將顯示兩個附加（元）字段，即：

-   Last updated

    > -   Shows the last timestamp from the entries saved to disk.  
          顯示儲存到磁碟的條目的最後一個時間戳。

注意事項

The fields above are only used for aliases that contain either networks or hosts, port type aliases are part of the rule and thus not visible in any table.

上面的欄位僅用於包含網路或主機的別名，連接埠類型別名是規則的一部分，因此在任何表中都不可見。

### Hosts｜主辦單位

Hosts can be entered as a single IP address, a range (separated with a minus sign, e.g. `10.0.0.1-10.0.0.10`) or a fully qualified domain name.

主機可以輸入為單一IP位址、範圍（以減號分隔，例如`10.0.0.1-10.0.0.10`）或完全限定的網域名稱。

When using a fully qualified domain name, the name will be resolved periodically (default is each 300 seconds).

使用完全限定域名時，將定期解析該名稱（預設為每 300 秒）。

Hosts type Aliases can contain exclusion hosts. Exclusion addresses starts with “!” sign (eg !192.168.0.1) and can be used to exclude hosts from Network Group Aliases.

主機類型別名可以包含排除主機。排除位址以「！」開頭符號（例如！192.168.0.1），可用於從網路群組別名中排除主機。

Warning

警告

Please note that the **Flush** action is not persistent!

請注意，**Flush** 操作不是持久的！

**“flush”** means flush the current contents of the alias, which will be repopulated when it’s not an external type, so flush in most cases isn’t very useful.

**「flush」**表示刷新別名的當前內容，當它不是外部類型時將重新填充別名，因此刷新在大多數情況下不是很有用。

Same behaviour applies to the API call [alias\_util flush](<276 防火牆.md>)

相同的行為適用於 API 呼叫 [alias\_utillush](<276 防火牆.md>)

### Networks｜網路

Networks are specified in Classless Inter-Domain Routing format (CIDR). Use the the correct CIDR mask for each entry. For instance a /32 specifies a single IPv4 host, or /128 specifies a single IPv6 host, whereas /24 specifies 255.255.255.0 and /64 specifies a normal IPv6 network. Network type Aliases can contain exclusion hosts or networks. Exclusion addresses starts with “!” sign (eg !192.168.0.0/24) and can be used to exclude hosts or networks from current Alias or Network Group Alias

網路以無類別域間路由格式 (CIDR) 指定。為每個條目使用正確的 CIDR 遮罩。例如，/32 指定單一 IPv4 主機，或 /128 指定單一 IPv6 主機，而 /24 指定 255.255.255.0，而 /64 指定普通 IPv6 網路。網路類型別名可以包含排除主機或網路。排除位址以「！」開頭符號（例如！192.168.0.0/24），可用於從目前別名或網路組別別名排除主機或網路

Apart from the CIDR notation, one could also use a [wildcard mask](https://en.wikipedia.org/wiki/Wildcard_mask) to match ranges of hosts or networks.

除了CIDR表示法之外，還可以使用[通配符遮罩](https://en.wikipedia.org/wiki/Wildcard_mask)來匹配主機或網路的範圍。

Tip

提示

To match all servers ending at .1 in the 192.168.X.1 networks, use a wildcard definition like `192.168.0.1/0.0.255.0`

若要符合 192.168.X.1 網路中以 .1 結尾的所有伺服器，請使用通配符定義，例如 `192.168.0.1/0.0.255.0`

### Ports｜港口

Ports can be specified as a single number or a range using a colon **:**. For instance to add a range of 20 to 25 one would enter 20:25 in the **Port(s)** section.

連接埠可以指定為單一數字或使用冒號 **:**的範圍。例如，要新增 20 到 25 的範圍，可以在**Port(s)** 部分輸入 20:25。

### MAC addresses｜MAC 地址

Hardware mac addresses can be specified as a (partial) hex value, such as `F4:90:EA` to match all addresses from Deciso or `f4:90:ea:00:00:01` to match a single item (the input is case insensitive).

硬體 MAC 位址可以指定為（部分）十六進位值，例如 `F4:90:EA` 符合 Deciso 中的所有位址，或 `f4:90:ea:00:00:01` 符合單一項目（輸入不區分大小寫）。

The way these aliases function is approximately the same as hostnames in host type aliases, they are resolved on periodic intervals from the `arp` and `ndp` tables.

這些別名的功能與主機類型別名中的主機名稱大致相同，它們是從 `arp` 和 `ndp` 表中定期解析的。

Warning

警告

Please be aware that hardware addresses can be spoofed ([https://en.wikipedia.org/wiki/MAC\_spoofing](https://en.wikipedia.org/wiki/MAC_spoofing)), which doesn’t make filters on them more secure than ip addresses in any way.

請注意，硬體位址可能會被欺騙（[https://en.wikipedia.org/wiki/MAC\_spoofing](https://en.wikipedia.org/wiki/MAC_spoofing)），這並不會使它們上的過濾器比 IP 位址更安全。

Note

注意事項

Since mappings between addresses and mac addresses are resolved periodically the actual situation can differ, you can always check Firewall -> Diagnostics -> Aliases to inspect the current contents of the alias.

由於位址和 MAC 位址之間的對應會定期解析，因此實際情況可能會有所不同，因此您可以隨時檢查防火牆 -> 診斷 -> 別名來檢查別名的當前內容。

### URL Tables｜URL 桌子

URL tables can be used to fetch a list of IP addresses from a remote server. You can specify a `` Refresh frequency` `` to determine how often this information should be updated.

URL 表可用於從遠端伺服器取得 IP 位址清單。您可以指定 `` Refresh frequency` `` 來決定此資訊的更新頻率。

Note

注意事項

The content of the file being fetched should contain one IPv\[4|6\] address per line, lines that start with a `whitespace` , colon (`,`), semicolon (`;`), pipe (`|`) or hash (`#`) will be ignored.

正在取得的檔案內容每行應包含一個 IPv\[4|6\] 位址，以 `whitespace` 、冒號 (`,`)、分號 (`;`)、豎線 (`|`) 或哈希 (`#`) 開頭的行將被忽略。

### URL Table in JSON format (IPs)｜URL JSON 格式的表格（IP）

URL tables can be used to fetch a list of IP addresses from a remote server and parse their contents when in [JSON](https://en.wikipedia.org/wiki/JSON) format, similar to our standard (text based) url table.

URL 表可用於從遠端伺服器取得 IP 位址列表，並以 [JSON](https://en.wikipedia.org/wiki/JSON) 格式解析其內容，類似於我們的標準（基於文字）url 表。

You can use a `Path expression` to select data from the container, in some cases, when content is “flat” you just need a single path reference. For example the spamhause [drop](https://www.spamhaus.org/drop/drop_v4.json) list contains a json file per row with a field `cidr`.

您可以使用 `Path expression` 從容器中選擇數據，在某些情況下，當內容是「扁平」時，您只需要一個路徑引用。例如，spamhause [drop](https://www.spamhaus.org/drop/drop_v4.json) 清單每行包含一個 json 文件，其中包含一個欄位 `cidr`。

More advanced scenarios are also possible as our parser supports [jq](https://jqlang.org/), some (simple) examples can be found below in the table below.

更高級的場景也是可能的，因為我們的解析器支援 [jq](https://jqlang.org/)，一些（簡單的）範例可以在下表中找到。

使用 GeoIP 別名，您可以選擇一個或多個國家或整個大陸來阻止或允許。使用*切換全部*複選框選擇給定區域內的所有國家。

### Network group｜網路組

Combine different network type aliases into one, this type of alias accepts other host type aliases (networks, hosts, …). Although nesting is possible with other alias types as well, this type only displays valid aliases easing administration, functionally a `Networks` type alias can do the same but uses a different presentation.

將不同的網路類型別名組合為一個，這種類型的別名會接受其他主機類型別名（網路、主機等）。儘管其他別名類型也可以嵌套，但此類型僅顯示有效的別名以方便管理，從功能上講，`Networks` 類型別名可以執行相同的操作，但使用不同的表示形式。

### Dynamic IPv6 Host｜動態 IPv6 主機

An IPv6 Dynamic Host is used where the system is using a dynamic prefix on the LAN, a tracking interface. When the prefix changes, either due to the ISP changing the prefix at will or the prefix changes when the WAN connection is reset, any alias containing an address of a client such as a server on the LAN would no longer be valid.

IPv6 動態主機用於系統在 LAN（追蹤介面）上使用動態前綴的情況。當前綴發生變化時，無論是由於ISP隨意更改前綴，還是由於WAN連接重置時前綴發生變化，任何包含客戶端位址（例如LAN上的伺服器）的別名將不再有效。

For example, you obtain a prefix 2001:db8:2222:2800::/56. You have a /56 prefix and if the tracking id was set to 0 for your LAN, you would have an address range on your LAN of 2001:db8:2222:2800:: to 2001:db8:2222:2800:FFFF:FFFF:FFFF:FFFF.

例如，您獲得前綴 2001:db8:2222:2800::/56。您有 /56 前綴，如果您的 LAN 的追蹤 ID 設定為 0，則您的 LAN 上的位址範圍為 2001:db8:2222:2800:: 到 2001:db8:2222:2800:FFFF:FFFF:FFFF:FFFF。

You want to run a server on your LAN that is accessible from the WAN so you give it a static address of 2001:db8:2222:2800:1000:1000::1 and create a rule allowing traffic to access the server.

您希望在 LAN 上執行一個可從 WAN 存取的伺服器，因此您為其指定靜態位址 2001:db8:2222:2800:1000:1000::1 並建立一條允許流量存取該伺服器的規則。

When your prefix changes, that static address is no longer valid, so you must use the Dynamic IPv6 Host to create an alias address for the firewall entry that automatically tracks the prefix and changes the rule.

當您的前綴變更時，此靜態位址不再有效，因此您必須使用動態 IPv6 主機為自動追蹤前綴並變更規則的防火牆項目建立別名位址。

The Dynamic Host Alias will always split on the /64 boundary, it will take the upper 64 bits from the interface you select and the lower 64 bits from the address you enter. It does not matter what size your prefix delegation is.

動態主機別名將始終在 /64 邊界上拆分，它將從您選擇的介面中取得高 64 位，並從您輸入的位址中取得低 64 位元。您的前綴委託的大小並不重要。

Create a new IPv6 Dynamic Host alias and enter only the suffix of the address, in this example, we will enter the lower 64 bits of the address, you would enter ::1000:1000:0000:1, note the ‘::’ at the start of the address, you MUST always start the address with a ‘::’. You do not need to enter a size after the address i.e. /128 as that is automatically assumed.

建立一個新的 IPv6 動態主機別名並僅輸入位址的後綴，在本例中，我們將輸入位址的低 64 位，您將輸入 ::1000:1000:0000:1，注意位址開頭的“::”，您MUST始終以“::”開頭位址。您無需在地址後面輸入大小，即 /128，因為這是自動假定的。

Select the interface you wish to use for the source of the upper 64 bits, in this case we will select the LAN interface.

選擇您希望用於高 64 位元來源的接口，在本例中我們將選擇LAN 接口。

When the prefix changes, the alias address will then be updated in the firewall rules, let’s say your prefix changes to 2001:db8:2222:3200::/56 the rule updates and the entry for your server in the firewall would update automatically to be 2001:db8:2222:3200:1000:1000::1

當前綴變更時，別名位址將在防火牆規則中更新，假設您的前綴變更為 2001:db8:2222:3200::/56 規則更新，防火牆中伺服器的項目將自動更新為 2001:db8:2222:3200:1000:1000::1

Let’s take another example, you have a /48 prefix delegation, you have two LAN interfaces and a server on each. You would need to create two separate Dynamic IPv6 Host entries, one for each LAN. For simplicities sake we will use the same address for each server on each interface, you would enter ::aaaa:bbbb:cccc:0001 as the address.

我們再舉個例子，您有一個 /48 前綴委託，有兩個 LAN 接口，每個接口上都有一個伺服器。您需要建立兩個單獨的動態 IPv6 主機條目，每個 LAN 一個。為了簡單起見，我們將為每個介面上的每個伺服器使用相同的位址，您將輸入 ::aaaa:bbbb:cccc:0001 作為位址。

### BGP ASN

With this alias type you are able to select networks by their responsible parties. Using BGP parties announce the addresses they are responsible for to each other. For example Cloudflare uses AS number `13335`, Microsoft is known to use `8075`.

使用此別名類型，您可以依責任方選擇網路。使用BGP，各方宣布他們彼此負責的地址。例如，Cloudflare 使用 AS 編號 `13335`，已知 Microsoft 使用 `8075`。

More background and how addresses are assigned is explained on [wikipedia](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\))

更多背景知識以及如何分配地址在 [wikipedia](https://en.wikipedia.org/wiki/Autonomous_system_\(Internet\) 上有解釋）

### External｜外部

The contents for external alias types is not administered via our normal alias service and can be practical in scenarios where you want to push new entries from external programs. Such as specific lockout features or external tools feeding access control to your firewall.

外部別名類型的內容不透過我們的普通別名服務進行管理，並且在您想要從外部程式推送新條目的情況下非常實用。例如特定的鎖定功能或向防火牆提供存取控制的外部工具。

In Firewall ‣ Diagnostics ‣ Aliases you can always inspect the current contents of the external alias and add or remove entries immediately.

在 Firewall ‣ Diagnostics ‣ Aliases 中，您隨時可以檢查外部別名的目前內容並立即新增或刪除條目。

Tip

提示

When changing alias contents which are used on firewall rules with state tracking enabled, you might need to remove the specific state before the new rule turns active. (see Firewall ‣ Diagnostics ‣ States Dump )

當變更啟用狀態追蹤的防火牆規則上使用的別名內容時，您可能需要在新規則變為活動狀態之前刪除特定狀態。 （請參閱防火牆 ‣ 診斷 ‣ 狀態轉儲）

Tip

提示

Since external alias types won’t be touched by OPNsense, you can use `pfctl` directly in scripts to manage its contents. (e.g. `pfctl -t MyAlias -T add 10.0.0.3` to add **10.0.0.3** to **MyAlias**)

由於 OPNsense 不會觸及外部別名類型，因此您可以直接在腳本中使用 `pfctl` 來管理其內容。 （例如 `pfctl -t MyAlias -T add 10.0.0.3` 將 **10.0.0.3**加入到**MyAlias**）

### OpenVPN group｜OpenVPN群組

This alias type offers the possibility to build firewall policies for logged in OpenVPN users by the group they belong to as configured in System ‣ Access ‣ Groups.

此別名類型提供了根據系統 ‣ 存取 ‣ 群組中配置的所屬群組為登入 OpenVPN 使用者建立防火牆策略的可能性。

The current users that are logged into OpenVPN can be inspected via VPN ‣ OpenVPN ‣ Connection Status, the alias just follows this information and flushes the attached addresses to the item in question.

目前登入 OpenVPN 的使用者可以透過 VPN ‣ OpenVPN ‣ 連線狀態進行檢查，別名只是遵循此資訊並將附加位址刷新到相關項目。

For example, when a user named **fred** which is a member of group **remote\_users** logs into OpenVPN and received a tunnel address of `10.10.10.2`, the alias containing “remote\_users” would include this address as well.

例如，當名為 **fred**的使用者（**remote\_users** 群組的成員）登入 OpenVPN 並收到`10.10.10.2` 的隧道位址時，包含「remote\_users」的別名也會包含此位址。

Note

注意事項

For this mechanism to work, the common-name of the user certificate must match the username exactly, which is the case by default if the certificate has been created from the user manager.

為了使此機制發揮作用，使用者憑證的公用名稱必須與使用者名稱完全匹配，如果憑證是從使用者管理員建立的，則預設情況下就是這種情況。

Tip

提示

When using LDAP (Active directory), you can synchronise group membership to avoid double administration in OPNsense.

使用LDAP（Active Directory）時，您可以同步群組成員資格以避免 OPNsense 中的雙重管理。

### Internal (automatic)｜內部（自動）

Internal aliases are prefixed with `__` so they are easy to identify and can’t overlap with any user defined ones. These aliases help you to determine what the content is for some internal concepts such as “LAN network”. Using the Firewall->Diagnostics->Aliases menu item you can inspect their contents at any time.

內部別名以`__`為前綴，因此易於識別，並且不能與任何使用者定義的別名重疊。這些別名可協助您確定某些內部概念（例如「LAN網路」）的內容。使用「防火牆」->「診斷」->「別名」選單項，您可以隨時檢查其內容。

## Export / Import｜出口/進口

The alias admin page (Firewall ‣ Aliases) contains a download and an upload button in the footer of the table, with this feature you can merge aliases into the configuration and download a `json` formatted list of all aliases in the system.

別名管理頁面（防火牆 ‣ 別名）在表格的頁腳中包含一個下載和上傳按鈕，透過此功能，您可以將別名合併到設定中，並下載系統中所有別名的 `json` 格式清單。

Since data is validated before insertion, it shouldn’t be possible to import defective data (if the import fails, a list of errors is presented).

由於資料在插入之前經過驗證，因此不可能匯入有缺陷的資料（如果匯入失敗，則會顯示錯誤清單）。

Tip

提示

When performing migrations, sometimes its easier to change multiple items at once in a text editor. This feature can easily be used to facilitate that, with limiting risk of a broken configuration (since items are validated equally as single item input would do).

執行遷移時，有時在文字編輯器中一次更改多個項目會更容易。此功能可以輕鬆地用於促進這一點，同時限製配置損壞的風險（因為專案的驗證與單一專案輸入的驗證相同）。

## Add new entries using our API｜使用我們的 API 新增條目

The endpoints from the alias\_util can easily be used to push new entries into an alias (or remove existing ones). In case of an external alias these items won’t be persistent over reboots, which can be practical in some use-cases (large frequent changing lists for example).

別名\_util 中的端點可輕鬆用於將新條目推送到別名中（或刪除現有條目）。如果使用外部別名，這些項目將不會在重新啟動後保持不變，這在某些用例中非常實用（例如大型頻繁更改的清單）。

The document “[Use the API](<370 使用API.md>)” contains the steps needed to create an api key and secret, next you can just call the same endpoint the user interface would.

文件「[使用API](<370 使用API.md>)」包含建立 api 金鑰和秘密所需的步驟，接下來您可以呼叫使用者介面所需的相同端點。

Below you see how to add **10.0.0.2** to an alias named **MyAlias** using an insecure connection (self-signed cert) on the host **opnsense.firewall** with `curl`. The verbose option provides more details about the data exchanged between the two machines.

下面您將看到如何在主機 **opnsense.firewall**上使用 `curl` 使用不安全連線（自簽名憑證）將**10.0.0.2**新增至名為**MyAlias** 的別名。 verbose 選項提供有關兩台電腦之間交換的資料的更多詳細資訊。

```bash
curl \
  --header "Content-Type: application/json" \
  --basic \
  --user "key:secret" \
  --request POST \
  --insecure \
  --verbose \
  --data  '{"address":"10.0.0.2"}' \
  https://opnsense.firewall/api/firewall/alias_util/add/MyAlias
```

Note

注意事項

Adding aliases using `/api/firewall/alias_util/add/` is only supported for Host, Network and External type aliases

僅主機、網路和外部類型別名支援使用 `/api/firewall/alias_util/add/` 新增別名

## Exclusions｜排除情況

Pf firewall tables support exceptions (or exclusion) of addresses. This feature can be used in one Alias or in combined (Network group type) Aliases. See ([https://www.freebsd.org/doc/handbook/firewalls-pf.html](https://www.freebsd.org/doc/handbook/firewalls-pf.html) 30.3.2.4).

Pf 防火牆表支援位址例外（或排除）。此功能可在一個別名或組合（網路群組類型）別名中使用。請參閱（[https://www.freebsd.org/doc/handbook/firewalls-pf.html](https://www.freebsd.org/doc/handbook/firewalls-pf.html) 30.3.2.4）。

## Nesting｜嵌套

For host and network alias types nesting is possibility, this can simplify management a lot since single items can be named properly and grouped into sections for administration.

對於主機和網路別名類型，嵌套是可能的，這可以大大簡化管理，因為可以正確命名單一專案並將其分組到部分中進行管理。

For example, we define 4 servers among 2 critical using different rulesets:

例如，我們使用不同的規則集在 2 個關鍵伺服器中定義 4 個伺服器：

-   server\_a {10.0.1.1}  
    伺服器\_a {10.0.1.1}
    
-   server\_b {10.0.1.2}  
    伺服器\_b {10.0.1.2}
    
-   server\_c {10.0.1.100}  
    伺服器\_c {10.0.1.100}
    
-   server\_d {10.0.1.200}  
    伺服器\_d {10.0.1.200}
    
-   critical\_servers {server\_a , server\_b}  
    關鍵伺服器{伺服器a，伺服器b}
    
-   other\_servers {server\_c , server\_d}  
    其他伺服器 {伺服器\_c , 伺服器\_d}
    
-   servers { critical\_servers , other\_servers}.  
    伺服器{關鍵伺服器，其他伺服器}。
    

The alias `servers` will contain all 4 addresses after configuration.

配置後，別名`servers`將包含所有4個位址。

There is also a possibility to combine different Aliases with Aliases, consisting of exclusions. For example, there is Alias “FireHOL”（火熱） that use extensive externl drop-list and two Aliases that contains subnet and hosts exclusions. It is possible to create Network group (combined) Alias (“FireHOL\_with\_exclusions”):

也可以將不同的別名與別名組合起來，包括排除。例如，有一個別名“FireHOL”（火熱），它使用廣泛的外部下拉列表，以及兩個包含子網路和主機排除的別名。可以建立網路群組（組合）別名（“FireHOL\_with\_exclusions”）：

-   FireHOL {[https://raw.githubusercontent.com/firehol/blocklist-ipsets/master/firehol\_level1.netset](https://raw.githubusercontent.com/firehol/blocklist-ipsets/master/firehol_level1.netset)}
    
-   subnets\_exclusions {!127.0.0.0/8, !0.0.0.0/8}  
    子網\_排除 {!127.0.0.0/8, !0.0.0.0/8}
    
-   hosts\_exclusions {!8.8.8.8}  
    主機\_排除{!8.8.8.8}
    
-   FireHOL\_with\_exclusions {FireHOL, subnets\_exclusions, hosts\_exclusions}  
    FireHOL\_with\_exclusions {FireHOL、子網路\_exclusions、主機\_exclusions}
    

`FireHOL_with_exclusions` Alias will contain all records from FireHOL Alias excluding addresses from exclusions Aliases.

`FireHOL_with_exclusions` 別名將包含 FireHOL 別名中的所有記錄，不包括排除別名中的位址。

It’s always good to check if an address is included in the Alias via Firewall ‣ Diagnostics ‣ pfTable

透過 Firewall ‣ Diagnostics ‣ pfTable 檢查地址是否包含在 Alias 中總是好的

## Spamhaus｜斯帕姆豪斯

The Spamhaus Don’t Route Or Peer Lists DROP (Don’t Route Or Peer) and DROPv6 are advisory “drop all traffic” lists, consisting of netblocks that are “hijacked” or leased by professional spam or cyber-crime operations (used for dissemination of malware, trojan downloaders, botnet controllers). The DROP and DROPv6 lists are a tiny subset of the SBL, designed for use by firewalls and routing equipment to filter out the malicious traffic from these netblocks.

Spamhaus 不路由或對等列表DROP（不路由或對等）和 DROPv6 是建議性「丟棄所有流量」列表，由專業垃圾郵件或網路犯罪操作「劫持」或租用的網路區塊（用於傳播惡意軟體、木馬下載器、殭屍網路控制器）組成。 DROP 和 DROPv6 清單是 SBL 的一個小子集，設計用於防火牆和路由設備過濾掉來自這些網路區塊的惡意流量。
