# Access User Management｜存取用戶管理

> 章節：[System](<000 目錄.md#c-11>) › [Access / User Management](<000 目錄.md#c-12>)

## Access / User Management｜存取/用戶管理

[![../_images/user_manager.png](<../images/092435fd-user_manager.png>)](https://docs.opnsense.org/_images/user_manager.png)

The user manager of OPNsense allows for controlling access to the different part (pages) of the configurator as well as controlling access to particular services on a per user bases.

OPNsense 的使用者管理員允許控制對配置器不同部分（頁面）的訪問，以及按使用者控制對特定服務的存取。

## Authentication｜驗證

OPNsense offers integration with external servers for services that require user authentication. These services include:

OPNsense 提供與外部伺服器的集成，以支援需要使用者身份驗證的服務。這些服務包括：

-   IPsec
    
-   OpenVPN
    
-   Captive Portal  
    強制門戶
    
-   Proxy  
    代理人
    

Integrated into OPNsense are the **Local User Database** and **Voucher Server**. The Voucher Server is intended to be used with the Captive portal.

OPNsense 整合了**本地用戶資料庫**和**憑證伺服器**。憑證伺服器旨在與強制門戶配合使用。

External services currently supported are:

目前支援的外部服務包括：

-   LDAP (OpenLDAP, MS Active Directory, Novell eDirectory)  
    LDAP （OpenLDAP， MS Active Directory，Novell eDirectory）
    
-   Radius  
    半徑
    
-   OpenID connect (BE only)  
    OpenID 連線（僅限BE ）
    

## Authorization｜授權

Besides authenticating, user authorization to access parts of the configuration can also be setup with an external server, but in order to grant the appropriate privileges to the users they need to exist in OPNsense’s local user manager. This way one can validate a user against its externally stored password and have a fine grained control over the configuration pages that user may access.

除了身份驗證之外，還可以透過外部伺服器設定使用者存取部分配置的權限，但為了授予使用者相應的權限，這些使用者必須存在於 OPNsense 的本機使用者管理員中。這樣，就可以根據外部儲存的密碼驗證使用者身份，並對使用者可以存取的設定頁面進行精細控制。

Note

注意事項

When creating administration users with a configured shell, their naming scheme’s are more strict (max 33 characters of a limited set). All other usernames are more flexible as no local shell accounts will be created.

建立已配置 shell 的管理員使用者時，其命名規則更為嚴格（最多 33 個字符，且必須使用限定字符集）。所有其他使用者名稱則更為靈活，因為不會建立本機 shell 帳戶。

## Users, Groups & Privileges｜使用者、群組和權限

When using the local user manager, either stand alone or on combination with an external authentication server one can define groups to combine a set of privileges for a specific user group. A user should be an individual, a group needs to be specific in such a way that anyone of that group can be granted the same access rights, called privileges.

使用本機使用者管理員時，無論是單獨使用或與外部身分驗證伺服器結合使用，都可以定義使用者群組，從而為特定使用者群組組合一組權限。使用者必須是個人，而使用者群組則需要足夠具體，以便該群組中的任何成員都可以被授予相同的存取權限，即特權。

Note

注意事項

It’s not always required to have users in your local database, when the remote server should merely answer the question if a user offers a valid user/password combination, most services can just push this question to the authenticating server. Constraints in some cases can be part of the authenticator as well. When the user should login to the firewall (for example to change settings or download a profile), a local user is always required as it serves as a linking pin to the ACL system.

並非總是需要在本地資料庫中儲存使用者。當遠端伺服器只需回答使用者提供的使用者名稱/密碼組合是否有效時，大多數服務都可以將此問題直接傳送給身分驗證伺服器。在某些情況下，驗證器本身也可以包含約束條件。例如，當用戶需要登入防火牆（例如更改設定或下載設定檔）時，始終需要本機用戶，因為它充當了與ACL系統的連接令牌。

## Authentication services｜身份驗證服務

Authentication services can be configured using the settings in System ‣ Access ‣ Servers. This includes both local accounts and remote authentication.

驗證服務可透過「系統」‣「存取」‣「伺服器」中的設定進行設定。這包括本機帳戶和遠端身份驗證。

By default, OPNsense GUI login will use local accounts. This can be changed, however, by going to System ‣ Settings ‣ Administration, scrolling down to the “Authentication”（驗證） group, and changing the ‘Server’ option.

預設情況下，OPNsense GUI登入將使用本機帳戶。但是，可以透過前往“系統”‣“設定”‣“管理”，向下捲動至“Authentication”（驗證）組，然後變更“伺服器”選項來變更此設定。

Tip

提示

The authentication part always uses a local “anchor” (user in the local database) to account for access rights, some remote servers are able to supply the required information by communicating the groups a user is member of after authentication.

身份驗證部分始終使用本機「錨點」（本地資料庫中的使用者）來計算存取權限，而一些遠端伺服器能夠在身份驗證後透過通訊使用者所屬的群組來提供所需資訊。

## Local account configuration｜本機帳戶配置

Settings for handling login via local accounts can be set by going to System ‣ Access ‣ Servers, then clicking the ‘Edit’ icon (a pencil) for ‘Local Database’. Here, you can improve security of local user accounts by setting password length and complexity constraints.

您可以依序點擊“系統”‣“存取”‣“伺服器”，然後點擊“本機資料庫”旁的“編輯”圖示（鉛筆圖示）來設定本機帳號登入的處理方式。在這裡，您可以透過設定密碼長度和複雜度限制來提高本機使用者帳戶的安全性。

An overview of available settings:

可用設定概覽：

|   |   |
| --- | --- |
| **Policy**<br>**政策** | Enable password policy constraints.<br>啟用密碼原則約束。 |
| **Duration**<br>**持續時間** | \[Policy\] Password duration, optionally define how often the user should change his or her password.<br>[策略] 密碼持續時間，可選擇性地定義使用者變更密碼的頻率。 |
| **Length**<br>**長度** | \[Policy\] Minimum password length to require.<br>[策略] 密碼最小長度需求。 |
| **Complexity**<br>**複雜度** | \[Policy\] Enforce password complexity checks.<br>[策略] 強制執行密碼複雜度檢查。 |
| **Compliance**<br>**合規性** | \[Policy\] Require SHA-512 password hashing instead of Blowfish<br>[政策] 要求使用SHA -512 密碼雜湊演算法，而非 Blowfish 演算法 |

Tip

提示

When using One Time Passwords in combination with the local database, the same policy constraints apply as configured in “Local Database”（本地資料庫）.

當將一次性密碼與本機資料庫結合使用時，適用與“Local Database”（本地資料庫）中配置相同的政策約束。

Note

注意事項

Our default Blowfish is not part of AES and is not considered compliant with any Federal Information Processing Standards (FIPS). Although more secure than SHA-512, its use may not be permitted in some environments.

我們的預設 Blowfish 並非AES的一部分，也不符合任何聯邦資訊處理標準 ( FIPS )。雖然它比SHA -512 更安全，但在某些環境下可能不允許使用。

Note

注意事項

When using external authentication services (such as ldap), the firewall needs a route to the configured target machine in order to function properly. Specifically when the server is only reachable over a classic IPsec tunnel (non VTI), a static route might be needed to guide the packets into the right tunnel matching the policy. (for example when a policy for LAN exists, add a gateway pointing to our own address and a static routing pusing traffic to the other end).

使用外部認證服務（例如 LDAP）時，防火牆需要一條通往已設定目標機器的路由才能正常運作。特別是當伺服器只能透過傳統的 IPsec 隧道（非VTI ）存取時，可能需要一條靜態路由來引導封包進入符合策略的正確隧道。 （例如，當存在LAN策略時，需要新增一條指向我們自身位址的網關，以及一條將流量轉送到另一端的靜態路由。）

A quick test if the routes are properly setup can always be performed using ping from the `default` source address.

始終可以使用從`default`來源位址執行 ping 指令來快速測試路由是否已正確設定。
