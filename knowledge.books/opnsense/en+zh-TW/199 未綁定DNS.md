# Unbound DNS｜未綁定DNS

> 章節：[Services](<000 目錄.md#c-40>)

Unbound is a validating, recursive, caching DNS resolver. It is designed to be fast and lean and incorporates modern features based on open standards.

Unbound 是驗證型、遞歸型、快取型的DNS解析器。它的設計目標是快速、精簡，並融合了基於開放標準的現代功能。

Since OPNsense 17.7 it has been our standard DNS service, which on a new install is enabled by default.

自 OPNsense 17.7以來，它一直是我們的標準DNS服務，在新安裝時預設為啟用。

Note

筆記

In order for the client to query unbound, there need to be an ACL assigned in Services ‣ Unbound DNS ‣ Access Lists. The configured interfaces should gain an ACL automatically. If the client address is not in any of the predefined networks, please add one manually.

為了讓客戶端能夠查詢非綁定資源，需要在「服務」‣「非綁定」 DNS 「存取清單」中指派ACL 。已配置的介面應自動獲得ACL 。如果用戶端位址不在任何預先定義網路中，請手動新增一個。

## Overrides｜覆蓋

Within the overrides section you can create separate host definition entries and specify if queries for a specific domain should be forwarded to a predefined server.

在覆蓋部分，您可以建立單獨的主機定義項目，並指定是否應將特定網域的查詢轉送至預先定義的伺服器。

### **Host override settings**｜**主機覆蓋設定**

Host overrides can be used to change DNS results from client queries or to add custom DNS records. PTR records are also generated under the hood to support reverse DNS lookups. These are generated in the following way:

主機覆蓋可用於變更客戶端查詢的 DNS 結果或新增自訂 DNS 記錄。也會在背景產生PTR記錄以支援反向DNS查找。它們是透過以下方式產生的：

-   If **System A/AAAA records** in [General settings](#general) is unchecked, a PTR record is created for the primary interface.  
    如果 [常規設定](#general)中的 **系統 A/ AAAA記錄** 未選中，則會為主介面建立PTR記錄。
    
-   Each host override entry **that does not include a wildcard for a host**, is assigned a PTR record.  
    每個主機覆蓋條目**不包含主機通配符**，都會分配一個PTR記錄。
    
-   If a host override entry **includes a wildcard for a host**, the first defined alias is assigned a PTR record.  
    如果主機覆蓋條目**包含主機的通配符**，則第一個定義的別名將被指派一個PTR記錄。
    
-   Every other alias does not get a PTR record.  
    其他所有別名都不會獲得PTR記錄。
    

|   |   |
| --- | --- |
| Host<br>主機名 | Name of the host, without domain part. Use “\*” to create a wildcard entry.<br>主機名，不包含網域部分。使用“*”建立通配符條目。 |
| Domain<br>網域 | Domain of the host (such as example.com)<br>主機的網域名稱（例如 example.com） |
| Type<br>類型 | Record type, A or AAA (IPv4 or IPv6 address), MX to define a mail exchange<br>記錄類型，A 或AAA （IPv4 或 IPv6 位址）， MX用於定義郵件交換 |
| IP | Address of the host<br>主機位址 |
| Description<br>描述 | User readable description, only for informational purposes<br>使用者可讀的描述，僅供參考 |
| Aliases<br>別名 | Copies of the above data for different hosts<br>上述資料在不同主機上的副本 |

**Aliases**

**別名**

You may create alternative names for a Host. E.g. when having a webserver with several virtual hosts you create a Host override entry with the IP and name for the webserver and an alias name for every virtual host on this webserver.

您可以為主機建立別名。例如，當一個 Web 伺服器有多個虛擬主機時，您可以建立一個主機覆蓋條目，其中包含IP和 Web 伺服器的名稱，以及該 Web 伺服器上每個虛擬主機的別名。

You have to select the host in the top list and it will the show you the assigned aliases in the bottom list.

您需要在頂部清單中選擇主機，然後它會在底部清單中顯示已指派的別名。

### **Domain override settings**｜**域覆蓋設定**

Important

重要

Domain overrides has been superseded by [Query Forwarding](#forwarding). Query forwarding also allows you to forward every single request.

域覆蓋已被 [查詢轉送](#forwarding)取代。查詢轉發還允許您轉發每個請求。

筆記

Keep in mind that if the “Use System Nameservers”（使用系統名稱伺服器） checkbox is checked, the system nameservers will be preferred over any **catch-all entry** in **both** Query Forwarding and DNS-over-TLS, this means that entries with a specific domain will still be forwarded to the specified nameserver.

請記住，如果 “Use System Nameservers”（使用系統名稱伺服器） 如果選取此複選框，系統名稱伺服器將優先於查詢轉發和配置中的任何**通用條目**。 DNS-超過-TLS這意味著具有特定網域名稱的條目仍將轉發到指定的名稱伺服器。

|   |   |
| --- | --- |
| Enabled<br>已啟用 | Enable query forwarding for this domain.<br>為此網域啟用查詢轉送。 |
| Domain<br>網域 | Domain of the host. All queries for this domain will be forwarded to the nameserver specified in “Server IP”（伺服器IP）. Leave empty to catch all queries and forward them to the nameserver.<br>主機的網域名稱。所有針對此網域的查詢都將轉送到“Server IP”（伺服器IP）中指定的名稱伺服器。留空則會捕獲所有查詢並將其轉送到名稱伺服器。 |
| Server IP<br>伺服器IP | Address of the DNS server to be used for recursive resolution.<br>用於遞歸解析的DNS伺服器的位址。 |
| Port<br>連接埠 | Specify the port used by the DNS server. Default is port 53. Useful when configuring e.g. [DNSCrypt-Proxy](<215 DNSCrypt代理.md>)<br>指定DNS伺服器所使用的連接埠。預設連接埠為 53。在配置例如 [DNSCrypt-Proxy](<215 DNSCrypt代理.md>)時非常有用 |

Warning

警告

Be careful enabling “DNS Query Forwarding”（DNS 查詢轉送） in combination with **DNSSEC**, no DNSSEC validation will be performed for forwards with a specific domain, as the upstream server might be a local controller. If forwarding everything and the upstream server doesn’t support DNSSEC, its answers will not reach the client as no DNSSEC validation could be performed.

請謹慎啟用“DNS Query Forwarding”（DNS 查詢轉送）與 **DNSSEC** 的組合，因為上游伺服器可能是本機控制器，所以對於特定網域的轉送要求將不會執行DNSSEC驗證。如果轉送所有請求，而上游伺服器不支援DNSSEC ，則其回應將無法到達客戶端，因為無法執行DNSSEC驗證。

## DNS over TLS｜DNS覆蓋TLS

DNS over TLS uses the same logic as Query Forwarding, except it uses TLS for transport.

DNS over TLS使用與查詢轉送相同的邏輯，只是它使用TLS進行傳輸。

---

Note

筆記

Please be aware of interactions between Query Forwarding and DNS over TLS. Since the same principle as Query Forwarding applies, a **catch-all entry** specified in both sections will be considered a duplicate zone. In our case DNS over TLS will be preferred.

請注意查詢轉發與DNS和TLS之間的交互作用。由於查詢轉發的原則相同，在兩個部分中指定的**兜底條目**將被視為重複區域。在本例中，我們將優先使用DNS而不是TLS 。

|   |   |
| --- | --- |
| Enabled<br>已啟用 | Enable DNS over TLS for this domain.<br>為此域啟用DNS而非TLS 。 |
| Domain<br>網域 | Domain of the host. All queries for this domain will be forwarded to the nameserver specified in “Server IP”（伺服器IP）. Leave empty to catch all queries and forward them to the nameserver.<br>主機的網域名稱。所有針對此網域的查詢都將轉送到“Server IP”（伺服器IP）中指定的名稱伺服器。留空則會捕獲所有查詢並將其轉送到名稱伺服器。 |
| Server IP<br>伺服器IP | Address of the DNS server to be used for recursive resolution.<br>用於遞歸解析的DNS伺服器的位址。 |
| Port<br>連接埠 | Specify the port used by the DNS server. Always enter port 853 here unless there is a good reason not to, such as when using an SSH tunnel.<br>指定DNS伺服器所使用的連接埠。除非有充分的理由（例如使用SSH隧道時），否則請務必在此輸入連接埠 853。 |
| Verify CN<br>驗證CN | The name to use for certificate verification, e.g. “445b9e.dns.nextdns.io”. Used by Unbound to check the TLS authentication certificates. It is strongly discouraged to omit this field since man-in-the-middle attacks will still be possible.<br>用於憑證驗證的名稱，例如「445b9e.dns.nextdns.io」。 Unbound 使用此名稱來檢查TLS身份驗證憑證。強烈建議不要省略此字段，因為仍然可能遭受中間人攻擊。 |

Tip

提示

To ensure a validated environment, it is a good idea to block all outbound DNS traffic on port 53 using a firewall rule when using DNS over TLS. Should clients query other nameservers directly themselves, a NAT redirect rule to 127.0.0.1:53 (the local Unbound service) can be used to force these requests over TLS.

為確保環境經過驗證，建議在使用DNS而非TLS時，使用防火牆規則阻止所有DNS端口 53 上的出站流量。如果用戶端直接查詢其他名稱伺服器，則可以使用NAT重定向規則將這些請求強制透過127.0.0.1:53 （本地TLS服務）進行。

## Advanced Configurations｜進階配置

Some installations require configuration settings that are not accessible in the UI. To support these, individual configuration files with a `.conf` extension can be put into the `/usr/local/etc/unbound.opnsense.d` directory. These files will be automatically included by the UI generated configuration. Multiple configuration files can be placed there. But note that

某些安裝需要一些在UI目錄下無法存取的設定。為了支援這些設置，可以將擴展名為`.conf`單獨設定檔放入`/usr/local/etc/unbound.opnsense.d`目錄。這些檔案將會被UI產生的設定自動包含。可以在此放置多個設定檔。但請注意：

-   As it cannot be predicted in which clause the configuration currently takes place, you must prefix the configuration with the required clause. For the concept of “clause” see the `unbound.conf(5)` documentation.  
    由於無法預測目前配置位於哪個子句中，因此必須在配置前加上所需的子句。有關「子句」的概念，請參閱`unbound.conf(5)`文件。
    
-   The wildcard include processing in Unbound is based on `glob(7)`. So the order in which the files are included is in ascending ASCII order.  
    Unbound 中的通配符包含處理基於`glob(7)` 。因此，文件的包含順序是按升序排列的ASCII順序。
    
-   Name collisions with plugin code, which use this extension point e. g. `dnsbl.conf`, may occur. So be sure to use a unique filename.  
    可能會出現與使用此副檔名（例如`dnsbl.conf` ）的插件程式碼的名稱衝突。因此，請務必使用唯一的檔案名稱。
    
-   It is a good idea to check the complete configuration via:  
    建議透過以下方式檢查完整配置：
    
    ```
    # check if the resulting configuration is valid
    configctl unbound check
    ```
    
    This will report errors that prevent Unbound from starting and also list warnings that may give hints as to why a particular configuration is not working or how it could be improved.

    這將報告封鎖 Unbound 啟動的錯誤，並列出可能提示特定配置為何不起作用或如何改進的警告。
    

This is a sample configuration file to add an option in the server clause:

這是一個用於在伺服器子句中新增選項的範例設定檔：

```yaml
server:
  private-domain: xip.io
```

Note

筆記

As a more permanent solution the template system (“[Using Templates](<249 使用模板.md>)”) can be used to automatically generate these files.

作為一種更持久的解決方案，可以使用範本系統（“[使用範本](<249 使用模板.md>) ”）自動產生這些檔案。

To get the same effect as placing the file in the sample above directly in `/usr/local/etc/unbound.opnsense.d` follow these steps:

若要達到與上述範例中將文件直接放入`/usr/local/etc/unbound.opnsense.d`相同的效果，請依照下列步驟操作：

1.  Create a `+TARGETS` file in `/usr/local/opnsense/service/templates/sampleuser/Unbound`:  
    在`/usr/local/opnsense/service/templates/sampleuser/Unbound`中建立`+TARGETS`檔案：
    
    ```
    sampleuser_additional_options.conf:/usr/local/etc/unbound.opnsense.d/sampleuser_additional_options.conf
    ```
    
2.  Place the template file as `sampleuser_additional_options.conf` in the same directory:  
    將範本檔案`sampleuser_additional_options.conf`放置在同一目錄下：
    
    ```yaml
    server:
      private-domain: xip.io
    ```
    
3.  Test the template generation by issuing the following command:  
    透過執行以下命令測試模板來產生：
    
    ```
    # generate template
    configctl template reload sampleuser/Unbound
    ```
    
4.  Check the output in the target directory:  
    檢查目標目錄中的輸出：
    
    ```
    # show generated file
    cat /usr/local/etc/unbound.opnsense.d/sampleuser_additional_options.conf
    # check if configuration is valid
    configctl unbound check
    ```
    

Warning

警告

It is the sole responsibility of the administrator which places a file in the extension directory to ensure that the configuration is valid.

管理員有責任將檔案放置在擴充目錄中，以確保配置有效。

Note

筆記

This method replaces the `Custom options` settings in the General page of the Unbound configuration, which was removed in version 21.7.

此方法取代了 Unbound 配置的常規頁面中的`Custom options`設置，該設置已在21.7版本中移除。
