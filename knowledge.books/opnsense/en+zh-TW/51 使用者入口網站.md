## [Preparation](#id1)｜[準備](#id1)

In order to effectively use this module, make sure to allow users to login to OPNsense using a username and password when they are on the local network.

為了有效地使用此模組，請確保允許使用者在本地網路上使用使用者名稱和密碼登入 OPNsense。

## [General](#id2)｜[一般](#id2)

[![../../_images/user_portal.png](<../images/4669beee-user_portal.png>)](https://docs.opnsense.org/_images/user_portal.png)

The portal replaces the simple user password menu, which can be found at Lobby ‣ Password and offers additional functionality for self-service support.

此入口網站取代了簡單的使用者密碼選單（可在大廳 ‣ 密碼中找到），並提供自助服務支援的附加功能。

Depending on the configuration users are able to change their password and language here, download and re-generate one time password tokens and access OpenVPN profiles for the instances they have access to.

根據配置，使用者可以在此處更改密碼和語言、下載並重新產生一次性密碼令牌以及存取他們有權存取的實例的 OpenVPN 設定檔。

Note

注意事項

The visible tabs depend on access rights configured in the administration part.

可見選項卡取決於管理部分中配置的存取權限。

在 System ‣ Settings ‣ Portal Admin 下，您將找到入口網站的管理部分，其中包括通用帳戶設定和 OpenVPN 執行個體存取。

### [2\. Configure a user (Onboarding)](#id8)｜[2\.配置用戶（入職）](#id8)

Now we need a user that will become a member of the groups we created.

現在我們需要一個將成為我們創建的群組的成員的使用者。

Go to System ‣ Access ‣ User and add the following user:

前往 System ‣ Access ‣ User 並新增以下使用者：

| **Option**<br>**選項** | **Description**<br>**描述** |
| --- | --- |
| **Username**<br>**使用者名稱** | `john` |
| **Password**<br>**密碼** | Set a password<br>設定密碼 |
| **Group Membership**<br>**團體會員** | `user_default_priv, user_otp_priv, user_ovpn_priv` |

-   Press **Save**  
    按**儲存**
    

Note

注意事項

Creating a user certificate is not necessary, the user portal will automagically create one for the user when they download an OpenVPN configuration. Same goes for the OTP token which the user can create themselves.

不需要建立使用者證書，使用者入口網站將在使用者下載 OpenVPN 設定時自動為使用者建立證書。使用者可以自己建立的OTP令牌也是如此。

Tip

提示

When using an LDAP authentication server, creating users manually is not needed. Go to System ‣ Access ‣ Servers and enable Automatic user creation. For Default groups, choose `user_default_priv`. Add the groups `user_otp_priv` and `user_ovpn_priv` to users on the LDAP server. Please note that all groups must be created manually and share the same name between System ‣ Access ‣ Groups and the LDAP server.

使用LDAP認證伺服器時，不需要手動建立使用者。前往 System ‣ Access ‣ Servers 並啟用自動使用者建立。對於預設組，選擇 `user_default_priv`。將群組`user_otp_priv`和`user_ovpn_priv`加入到LDAP伺服器上的使用者。請注意，所有群組必須手動創建，並在系統 ‣ 存取 ‣ 群組和 LDAP 伺服器之間共用相同的名稱。

### [3\. Configure Authentication Servers](#id9)｜[3\.設定驗證伺服器](#id9)

We require two server types:

我們需要兩種伺服器類型：

> -   The default server `Local Database` will allow users to authenticate with the user portal.  
      預設伺服器`Local Database`將允許使用者透過使用者入口網站進行身份驗證。
>     
> -   The additional server `Local Database + TOTP` will be used for OpenVPN.  
      額外的伺服器`Local Database + TOTP`將用於OpenVPN。
>     

Go to System ‣ Access ‣ Servers and add the following additional server:

前往 System ‣ Access ‣ Servers 並新增以下附加伺服器：

| **Option**<br>**選項** | **Description**<br>**描述** |
| --- | --- |
| **Descriptive name**<br>**描述性名稱** | `Local Database + TOTP` |
| **Type**<br>**類型** | `Local + Timebased One Time Password` |

-   Press **Save**  
    按**儲存**
    

Attention

注意

If you set the authentication server in System ‣ Settings ‣ Administration to the `Local Database + TOTP` option, users cannot manage their own OTP tokens in the user portal without prior help from an administrator; because they need an OTP token for authentication and might not have one yet. Especially if you choose an LDAP variant and have a big userbase, take this into consideration if everything should be fully automated. This is why we suggest using two authentication server types so users will be able to authenticate to the user portal without using TOTP.

如果您在系統 ‣ 設定 ‣ 管理 中將驗證伺服器設定為 `Local Database + TOTP` 選項，則在沒有管理員事先協助的情況下，使用者無法在使用者入口網站中管理自己的 OTP 令牌；因為他們需要一個 OTP 令牌進行驗證，但可能還沒有。特別是如果您選擇 LDAP 變體並擁有龐大的用戶群，如果一切都應該完全自動化，請考慮這一點。這就是為什麼我們建議使用兩種身份驗證伺服器類型，以便使用者能夠在不使用TOTP的情況下向使用者入口網站進行身份驗證。

使用者將能夠更改密碼，產生自己的OTP令牌，並下載OpenVPN設定檔；它也會自動產生他們的使用者憑證。

### [7\. Remove Access (Offboarding)](#id13)｜[7\.刪除存取權限（Offboarding）](#id13)

The prior steps outlined most of the onboarding process. Though, what should happen if the user access must be removed?

前面的步驟概述了大部分入職流程。但是，如果必須刪除使用者存取權限該怎麼辦？

Go to System ‣ Access ‣ User and remove all `Group memberships` and `Privileges`, regenerate the `OTP seed` and set the `Disabled` flag. After saving, the users rights will be nullified, and even if it will be re-enabled, the user will not be able to elevate their rights as they cannot log into the user portal, or use their OTP token to establish an OpenVPN connection.

進入系統‣訪問‣用戶並刪除所有`Group memberships`和`Privileges`，重新產生`OTP seed`並設定`Disabled`標誌。儲存後，使用者權限將被取消，即使重新啟用，使用者也無法提升權限，因為他們無法登入使用者門戶，也無法使用OTP令牌建立OpenVPN連線。

Attention

注意

If you use an LDAP authentication server, you must deactivate the user on that server. Keep the group memberships in mind, also the current default groups you might have set.

如果您使用 LDAP 驗證伺服器，則必須在該伺服器上停用使用者。請記住群組成員身份，以及您可能設定的目前預設群組。

As further step, invalidate the user certificate.

進一步，使用戶證書失效。

Go to System ‣ Trust ‣ Revocation and edit the CA you created for the OpenVPN instance. If there is no CRL yet, create one by setting a Description and pressing **Apply**.

前往 System ‣ Trust ‣ Replication 並編輯您為 OpenVPN 實例建立的 CA。如果還沒有 CRL，請透過設定描述並按 **套用** 來建立一個。

Afterwards, edit the CA again, and select a `Revocation per type`, e.g., `Unspecified` where you choose the created user certificate. After applying, this certificate will no longer be valid.

然後，再編輯CA，選擇一個`Revocation per type`，例如`Unspecified`，在這裡選擇建立的使用者憑證。申請後，該證書將不再有效。

Attention

注意

Deleting a certificate from the GUI will not invalidate it. You must use the revocation component to publish the revocation to the OpenVPN instance.

從GUI刪除憑證不會使其失效。您必須使用吊銷元件將撤銷發佈到 OpenVPN 執行個體。
