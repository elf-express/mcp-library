# 流量整形

> 章節：[Firewall](<000 目錄.md#c-26>) › [Traffic Shaping](<000 目錄.md#c-29>)

流量整形（也稱為「資料包整形」）是對電腦網路流量的控制，以便透過延遲滿足特定標準的資料包來優化或保證效能、降低延遲和/或增加可用頻寬。更具體地說，流量整形是對一組資料包（通常稱為流或流）的任何操作，它對這些資料包施加額外的延遲，以便它們符合某些預定的約束（合約或流量配置檔案）。

![../_images/traffic_shaping.png](<../images/f390d338-traffic_shaping.png>)

## 介紹

OPNsense 內的流量整形非常靈活，並圍繞管道、隊列和相應規則進行組織。管道定義允許的頻寬，佇列可用於設定管道內的權重，最後使用規則將整形應用於特定的包流。除非直接在防火牆規則中指派管道或佇列，否則整形規則的處理獨立於防火牆規則和其他設定。

OPNsense 流量整形是限制頻寬或確定流量優先順序的可靠解決方案，並且可以與強制入口網站或高可用性 (CARP) 等其他功能結合。

頻寬限制可以根據介面、IP來源和目的地、流量方向（輸入/輸出）和連接埠號碼（應用程式）來定義。

可用頻寬可以在所有用戶之間平均共享，這樣可以始終實現最佳效能。

還可以透過新增佇列和定義權重來確定流量的優先權。嚴格來說，流量並沒有真正優先考慮，但當總可用頻寬有限時，權重較高的應用程式可能會比其他應用程式消耗更多的頻寬。

流量整形器實作使用 IPFW 和 dummynet 來提供現代化、可靠且 CPU 佔用空間低的解決方案。

## 虛擬網路和 ipfw

Dummynet 的運作方式是先使用防火牆對封包進行分類並將其劃分為流，並使用可在 ipfw 規則中使用的任何匹配模式。根據本地策略，流可以包含單一TCP連接的資料包，或來自/到給定主機的資料包，或整個子網，或協定類型等。

然後，屬於同一流的資料包被傳遞到兩個不同物件中的任意一個，從而實現流量調節：

管子

管道模擬具有給定頻寬、傳播延遲、佇列大小和丟包率的連結。資料包從分類器出來時在管道前面排隊，然後根據管道的參數傳輸到管道。

佇列

隊列是用於實現WF2Q+（最壞情況公平加權公平排隊）策略的抽象，它是WFQ策略的高效變體。佇列將權重和參考管道與每個流相關聯，然後連結到同一管道的所有積壓（即，資料包排隊）流按與其權重成比例地共享管道的頻寬。請注意，權重不是優先級；而是優先級。即使權重較高的流永久積壓，權重較低的流仍能保證獲得其頻寬的一部分。

實際上，管道可用於對流可以使用的頻寬設定硬限制，而佇列可用於確定不同流如何共享可用頻寬。

整形規則可以在流量整形器的規則部分中定義。

提示

Dummynet 建議將可調的 `kern.hz` 配置為最小值 `1000`，在虛擬機器上使用整形器時，此設定的預設值通常較低。較高的值可提高整形器的反應能力。

您可以在 System ‣ Settings ‣ Tunables 中新增此值

## 狀態/統計數據

若要檢查您的 shaper 是否如預期運作，您可以使用狀態頁面（防火牆 -> Shaper -> 狀態）。

該元件將顯示已配置管道、隊列和規則的詳細信息，顯示自上次服務重新啟動以來通過它的流量，包括發生該事件時的時間戳。

如果流處於活動狀態，您可以使用「顯示活動流」複選框顯示其詳細信息，請記住在更改這些設定後刷新視圖。

預設不顯示規則，您可以使用「顯示規則」複選框來啟用這些規則，此選項可以幫助您更輕鬆地識別錯誤配置，因為底層技術（`ipfw`）會根據每個規則追蹤資料。

提示

確保使用易於查找的描述，當流量未按預期處理時，這些描述將簡化偵錯。
