# 紀錄檔案

> 章節：[Firewall](<000 目錄.md#c-26>)

在排除防火牆問題時，您很可能必須檢查系統上可用的日誌。在OPNsense的UI中，日誌檔案通常會依照其所屬組件的設定進行分組。日誌檔案可以在這裡找到：

|   |   |   |
| --- | --- | --- |
| **即時查看** |防火牆 ‣ 日誌檔案 ‣ 即時視圖 | *即時查看防火牆日誌，可套用智慧過濾* |
| **普通視圖** |防火牆 ‣ 日誌檔案 ‣ 普通視圖 | *只是簡單的內容如何* **pf** *登入* **filter.log** |

## 即時取景

如果匹配啟用了日誌記錄的規則或在以下位置啟用了全域日誌記錄選項之一，則即時視圖會即時更新：系統 ‣ 設定 ‣ 日誌記錄

在頁面的左上角，您可以為檢查流量時匹配的規則建立過濾條件，而在這裡您可以選擇不同的欄位（例如標籤、來源位址、目標位址）以及如何將它們與條件（字串或預選值，取決於類型）相結合（包含、是、否、不包含）。 \[+\] 按鈕將篩選器新增至視圖。

預設情況下，結果應符合所有條件 (AND)，但您可以將其變更為任何條件 (OR)。如果您想追蹤一小部分主機，後者有時很實用。

可以使用每行末尾的資訊按鈕提供特定規則的詳細資訊。

提示

`host` 和 `port` 欄位有點特殊，適用於來源和目標，這確保與特定位址或連接埠相符的流量都相符。

提示

通常，規則包含一個 `rid` 字段，該字段對應於 OPNsense 中負責此匹配的規則或設置，當點擊連結時，系統將嘗試將您重定向到正確的設定（或規則）。

注意事項

即時日誌僅顯示防火牆符合的規則，如果建立了狀態，則會報告第一個資料包的流量，只要該狀態仍然存在，就不會為相同流量報告新的線路。如果您需要檢查原始流量，將即時日誌與選單中介面診斷下的資料包擷取功能結合通常很實用。

注意事項

由於日誌行儲存在系統上，但與相關規則沒有完全匹配，因此我們確實需要將檔案中的序列轉換回系統中儲存的規則定義。因此，如果重新配置防火牆，歷史資訊的準確性會降低。 （查看舊數據時標籤可能不正確）

## 概述

日誌記錄概述頁面顯示防火牆日誌行在一組不同屬性上的分佈，但其評估的規則數量受到限制 (5000)。

儘管它可能有助於從日誌儲存頂部發現一些清晰的模式，但相關用例的數量可能有限。
