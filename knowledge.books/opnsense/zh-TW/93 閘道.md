# 閘道

> 章節：[System](<000 目錄.md#c-11>)

![](<../images/7238aa1d-blockdiag-1ac1ecbed766e9941fcce1f649bea0.png>)

網關定義了可用於存取其他網路（例如網際網路）的可能路徑。您可以在此頁面管理防火牆可用的所有路徑，該頁面位於「系統」->「網關」->「設定」中。

您可以自行定義這些網關，也可以透過動態設定的介面（例如 DHCP）自動提供這些網關，在這種情況下，它們將沒有預先定義的位址。

即使網關是自動產生的，您仍然可以變更其設定。自動產生的網關通常具有類似`WAN_DHCP`的名稱。

在需要將特定網路轉送至特定目標的情況下，可以使用靜態路由，可以在「系統」->「路由」->「配置」中進行配置，並取決於網關頁面中顯示的條目。

一種特殊的路由是`default`路由，當沒有配置其他靜態路由時，所有流量都會傳送到這條路由。系統路由表中每個IP協定（IPv4、IPv6）一次只能有一個預設路由。

## 預設網關

由於只能有一個活動的預設網關，我們需要一種方法來確定要使用哪個網關。對於兩種 IP 協定（IPv4 和 IPv6），確定方法相同。

網關具有優先權，從`1` \[非常重要\]到`255` \[最不重要\]，自動產生的網關預設優先權較低（您可以手動變更）。

接下來是名為`upstream`的設置，它將網關標記為預設網關的優選網關，可以同時配置多個上游網關。

在選擇預設網關時，演算法始終會將`upstream`網關的優先排序更高（更具吸引力），並優先使用優先順序最高的網關。如果沒有明確指定任何網關作為上游網關，則選擇第一個非上游網關。

如果配置了網關監控，選擇網關還涉及測試其當前狀態，並在被監控位址無法存取時採取相應的措施。

預設情況下，系統僅在啟動時或介面連接/斷開連接時選擇（新的）預設閘道。在許多情況下，您可能希望在當前網關無法存取時（透過設定的監控）也更改預設網關，在這種情況下，您可以在「系統」->「設定」->「常規」中啟用「網關切換」。

提示

如果您有多個（動態）網關，並且希望它們在發生故障時按特定順序切換，只需設定**優先**和**上行**標誌即可。 （例如，優先使用光纖而非4G網路）。您的選擇應相應地反映在網關網格中（最重要的網關排在最前面）。

## 概覽頁面

概覽頁面（系統->網關->設定）顯示所有目前已知的網關及其狀態，並依重要性排序（最重要的在最上方）。當某個網關被視為「預設」網關時，其名稱後會顯示**(活動)**。

注意事項

清單中顯示的**(活動)**狀態反映的是目前計算的預設值，如果未啟用網關交換，則該預設值可能與機器路由不同。您隨時可以在「系統」->「路由」->「狀態」中查看目前的活動預設值。

提示

在偵錯動態網關問題時，請務必檢查您期望的網關是否確實在清單中。系統只會考慮清單中顯示的網關。

## 設定

下面列出了網關項目最重要的可用設定。

|   |   |
| --- | --- |
| 已停用 | （暫時）停用此項目 |
| 名稱 | 此網關的唯一名稱 |
| 描述 | 此物品的可選描述 |
| 介面 | 此網關連接的介面 |
| 地址族 | IP系列（v4 或 v6） |
| IP位址 | 我們的閘道位址，動態產生時為空/**動態**。 |
| 上游網關 | 上游網關，請將此網關視為預設網關候選網關 |
| 遠端網關 | 選取此複選框，允許網關存在於介面子網路之外。 |
| 停用網關監控 | 停用監控（考慮**線上**） |
| 停用主機路由 | 請勿為此監視器建立專用主機路由。 |
|故障轉移狀態 |如果此網關發生故障，則透過終止與此網關關聯的狀態來強制客戶端透過不同的線上網關重新連線。此選項需要啟用“預設網關切換”，或將此網關指派為網關群組的一部分才能觸發。 |
|故障復原狀態 |如果另一個網關的優先權高於此網關，則透過終止與此網關關聯的狀態來強制客戶端重新連線。此選項需要啟用“預設網關切換”，或將此網關指派為網關群組的一部分才能觸發。此選項的常見用例是透過 LTE 進行計量連接，僅在沒有其他網關在線時才應使用。 |
| 監控IP | 備用監控位址，請務必確保該位址實際可存取並使用此介面（透過靜態閘道） |
| 將網關標記為已關閉 | 將此網關視為已關閉，因此不能將其視為預設閘道 |
| 優先級 | 對此網關進行優先排序，數值越低表示越重要。 |

## 故障排除

### 缺少動態網關

大多數動態介面類型會將目前網關寫入名為`/tmp/[interface]_router`或`/tmp/[interface]_routerv6`的檔案中。如果頁面中未列出預期的網關，則可能是介面類型有問題（例如，遠端伺服器目前未提供網關）。

注意事項

某些VPN類型支援在不知道中間網關的情況下向介面發送流量，要啟用此功能，請在介面設定中檢查「動態網關策略」。

### 網關已離線

當網關被標記為離線時，請務必先檢查監控位址是否可透過正確的介面存取。您可以使用「介面」->「診斷」->「Ping」來測試連線性。如果監控位址與介面不在同一子網路中，也要檢查是否存在一條靜態路由（「系統」->「路由」->「狀態」），則該路由會將要求的流量傳送到正確的上游網關。

應該始終有一個`dpinger`進程處於活動狀態，您可以在服務頁面（系統->診斷->服務）中檢查它。最後，如果一切似乎都在運行，您可以深入分析離開介面的資料包。如果 dpinger 處於活動狀態，則應該有ICMP封包發送到您的監控位址，您可以使用介面->診斷->封包擷取來檢查它們。
