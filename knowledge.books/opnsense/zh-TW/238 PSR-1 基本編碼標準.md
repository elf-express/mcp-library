# PSR-1 基本編碼標準

> 章節：[Development Manual](<000 目錄.md#c-52>) › [Coding Guidelines](<000 目錄.md#c-53>)

注意事項

PSR1 和 PSR2 編碼標準由 FIG 根據 MIT 許可證提供。

查看許可證詳細資訊：[http://www.php-fig.org/bylaws/licensing-policies/](http://www.php-fig.org/bylaws/licensing-policies/)

本頁原文內容可在[php-fig](http://www.php-fig.org/psr/psr-1/)找到

標準的這一部分包括應被視為確保共享PHP代碼之間高水準技術互通性所需的標準編碼元素。

關鍵字「MUST」、「MUST NOT」、「REQUIRED」、「SHALL」、「SHALL NOT」、「SHOULD」、「SHOULD NOT」、「推薦」、「MAY」及本文件中的「OPTIONAL」應按[RFC 2119](http://www.ietf.org/rfc/rfc2119.txt)中的描述進行解釋。

## 1\.概述

-   檔案MUST僅使用`<?php`和`<?=`標籤。
    
-   檔案MUST僅使用UTF-8，不使用BOM作為PHP程式碼。
    
-   檔案SHOULD*要麼*宣告符號（類別、函數、常數等）*或*導致副作用（例如產生輸出、變更.ini設定等），但SHOULD NOT兩者兼而有之。
    
-   命名空間與類別MUST遵循「自動載入」PSR：\[[PSR-0](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-0.md)，[PSR-4](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-4-autoloader.md)\]。
    
-   類別名稱MUST在`StudlyCaps`中宣告。
    
-   類別常數 MUST 全部大寫並帶有下劃線分隔符號。
    
-   方法名稱MUST在`camelCase`中宣告。
    

## 2\.文件

### 2.1. PHP標籤

PHP代碼MUST使用長`<?php ?>`標籤或短回顯`<?= ?>`標籤；它MUST NOT使用其他標籤變體。

### 2.2。字元編碼

PHP代碼MUST僅使用UTF-8，不使用BOM。

### 2.3。副作用

檔案 SHOULD 宣告新符號（類別、函數、常數等）並且不會引起其他副作用，或者它 SHOULD 執行有副作用的邏輯，但 SHOULD NOT 兩者兼而有之。

短語「副作用」是指執行與聲明類別、函數、常數等不直接相關的邏輯，*僅透過包含檔案*。

「副作用」包括但不限於：產生輸出、明確使用`require`或`include`、連接到外部服務、修改ini設定、發出錯誤或異常、修改全域或靜態變數、讀取或寫入檔案等。

以下是同時具有聲明和副作用的文件範例；即，要避免的範例：

```php
<?php
// side effect: change ini settings
ini_set('error_reporting', E_ALL);

// side effect: loads a file
include "file.php";

// side effect: generates output
echo "<html>\n";

// declaration
function foo()
{
    // function body
}
```

以下範例是一個包含無副作用聲明的檔案；即，要模擬的範例：

```php
<?php
// declaration
function foo()
{
    // function body
}

// conditional declaration is *not* a side effect
if (! function_exists('bar')) {
    function bar()
    {
        // function body
    }
}
```

## 3\.命名空間和類別名

命名空間與類別MUST遵循「自動載入」PSR：\[[PSR-0](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-0.md)，[PSR-4](https://github.com/php-fig/fig-standards/blob/master/accepted/PSR-4-autoloader.md)\]。

這意味著每個類別都單獨位於一個檔案中，並且位於至少一級的命名空間中：頂級供應商名稱。

類別名稱MUST在`StudlyCaps`中宣告。

為PHP 5.3和MUST編寫的程式碼使用正式命名空間。

例如：

```php
<?php
// PHP 5.3 and later:
namespace Vendor\Model;

class Foo
{
}
```

為 5.2.x 和 SHOULD 之前所寫的程式碼在類別名稱上使用 `Vendor_` 前綴的偽命名空間約定。

```php
<?php
// PHP 5.2.x and earlier:
class Vendor_Model_Foo
{
}
```

## 4\.類別常數、屬性與方法

術語「類別」是指所有類別、介面和特徵。

### 4.1。常數

類別常數 MUST 全部大寫並帶有下劃線分隔符號。例如：

```php
<?php
namespace Vendor\Model;

class Foo
{
    const VERSION = '1.0';
    const DATE_APPROVED = '2012-06-01';
}
```

### 4.2。屬性

本指南有意避免任何有關使用 `$StudlyCaps`, `$camelCase` 或 `$under_score` 屬性名稱的建議。

無論使用什麼命名約定SHOULD，都應在合理的範圍內一致應用。此範圍可以是供應商級、包級、類別級或方法級。

### 4.3。方法

方法名稱MUST在`camelCase()`中宣告。
