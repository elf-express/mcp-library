# 斯通內爾

> 章節：[Virtual Private Networking](<000 目錄.md#c-32>) › [Plugin VPN options](<000 目錄.md#c-35>)

OPNsense 中的 Stunnel 可以使用TLS相互認證安全地轉送 TCP 連線。雖然應用程式本身支援基於預先共用金鑰的認證，但我們的外掛程式僅支援基於憑證的認證，這種認證更安全，但會帶來更多的（連線）開銷（[https://www.stunnel.org/perf.html](https://www.stunnel.org/perf.html) ）。

[![](<../images/84d95f2e-blockdiag-e621d010d47a7e47952dc0fbe6812a.png>)](https://docs.opnsense.org/_images/blockdiag-e621d010d47a7e47952dc0fbe6812a8e3dd7836a.png)

上圖顯示了該插件提供的基本功能，客戶端部分（並非由該插件提供）透過預先定義的連接埠連接到伺服器，並開始將本地接收到的封包轉送到隧道的另一端。

保護 HTTP 代理流量是 stunnel 的常見用例之一。

## 先決條件

在建立新的安全隧道之前，我們需要確保我們有憑證授權單位以及可用於隧道兩端的憑證。

創建CA最簡單的方法是使用內部自簽名證書，您可以在「系統」->「信任」->「證書頒發機構」中選擇「建立內部證書頒發機構」作為方法，並填寫所有詳細資訊。

當您擁有可用的CA時，即可為伺服器（即此電腦）和用戶端建立憑證。只需依序點擊“系統”->“信任”->“證書”，建立一個內部證書，選擇正確的類型（隧道此端的伺服器證書），然後選擇上一個步驟建立的CA 。通用名稱用於標識隧道的兩端，您可以在此處為伺服器選擇一個完全限定域名，並為客戶端選擇一個使用者名稱（例如）。

更多資訊請閱讀[設定自簽名憑證鏈](<104 設定自簽名憑證鏈.md>)

注意事項

範例設定假設代理伺服器已配置並正常運作。

注意事項

插件本身可以透過「系統」‣「韌體」‣「插件」選單進行安裝（搜尋`stunnel` ）。

## 設定伺服器

若要新增隧道，請前往VPN -> Stunnel -> 配置，然後按一下 \[+\] 新增記錄。

收聽地址

對於要監聽的地址，我們通常建議在此處使用環回接口，並使用 [Destination NAT (Port Forward)](<135 網路位址轉換.md>)將流量轉送到該位址。在本例中，保留此預設值 ( 127.0.0.1 )。

注意事項

選擇非環回介面時，請務必使用靜態介面。

監聽埠

要監聽的連接埠號碼（stunnel 用戶端連接的連接埠）。在本例中，我們選擇`31280` 。

目標主機名

若要連線的服務的主機名稱或 IP 位址，在本例中為代理伺服器的內部 IP 位址。

目標連接埠

此服務使用的端口，在本例中為`3128` （Squid 代理的預設端口）。

證書

對於此伺服器證書，請選擇先決條件中為伺服器建立的證書。

CA驗證與連接

要使用的憑證授權機構，此 stunnel 只接受使用由同一CA頒發的憑證的連接。

啟用CRL

啟用憑證撤銷清單後，需要在 ( `/var/run/stunnel/certs/` ) 目錄中放置一個格式為XXXXXXXX .r0 的CRL檔案。如果憑證由這台機器管理，所有附加的 CRL 都會自動產生。有關此選項的更多信息，請參閱 stunnels 手冊中的 CRLpath 部分。

警告

如果已設定但有效的CRL憑證不可用，則所有連線都將被拒絕。新增憑證可能需要重新啟動 stunnel 服務（如果該憑證已被使用）。

描述

請在此輸入易於理解的描述，例如「企業代理」。

提示

若要將流量從您的`wan`介面轉送至環回位址，請前往「防火牆」-> NAT 」->「目標NAT 」（連接埠轉送），並新增一條新規則，設定如下`WAN address`介面`WAN` ， `31280` `TCP` ，重定向目標IP `127.0.0.1`和重定向目標埠`31280`

注意事項

為了增強安全性，您可以在VPN -> Stunnel -> 常規」中啟用`chroot`模式」。但是，使用此功能也存在一個缺點。如果系統日誌服務 (syslog) 由於某種原因重啟，stunnel 將失去與該服務的連接，導致之後無法查看日誌。

## 配置客戶端

在設定客戶端之前，請確保為您的平台安裝 [stunnel](https://www.stunnel.org/) ，下載您的CA公鑰和為此客戶端建立的憑證。

```
[proxy]
client = yes
accept = 127.0.0.1:3128
connect = our.opnsense.address:31280
requireCert = yes
verifyChain = yes
cert = /path/to/client.pem
CAfile = /path/to/ca.pem
```

注意事項

client.pem 包含此用戶端憑證的公鑰和私鑰部分。

## 測試

隧道連線建立後，您應該可以使用瀏覽器的代理設定連接到連接機器上的`127.0.0.1:3128` 。

## 啟用 Identd

我們的 stunnel 外掛程式包含一項附加服務，提供 [ident](https://en.wikipedia.org/wiki/Ident_protocol) ( RFC 1413) 協定服務。此服務依賴我們在 stunnel 中提供的自訂 [patch](https://github.com/opnsense/ports/commit/1b9d7b1416046357cd9b2187c038787b19f2a813) ，以確保已認證的TLS會話被正確記錄，以便我們的 ident 服務可以對其進行過濾，從而追蹤屬於 stunnel 會話的使用者。

當TLS會話通過身份驗證後，將向 syslog 發送以下日誌記錄。

```yaml
stunnel: LOG5[xxxxx]: IDENT Service [xx-xx-xx-xx-xx] from 127.0.0.2:11446 --> C=NL, ST=Zuid-Holland, L=Middelharnis, O=OPNsense, emailAddress=contact_at_domain, CN=test_client.opnsense.local
```

我們的 ident 服務將其解釋為`127.0.0.2`使用源端口`11446`連接到`test_client.opnsense.local` （僅返回CN部分）

注意事項

由於我們的標識服務綁定到`0.0.0.0:113`因此它與其他可能使用相同連接埠的識別服務不相容​​，強烈建議禁止除此服務的使用者（通常是防火牆本身）之外的其他主機存取此服務。

此功能可透過兩個 telnet 會話輕鬆驗證：一個會話由 stunnel 用戶端保持開啟狀態，另一個會話使用 ident 連接到相同主機。上面的範例日誌行將產生以下請求/回應場景：

```
# telnet 127.0.0.2 113
Trying 127.0.0.2...
Connected to OPNsense.localdomain.
Escape character is '^]'.
11446,3128
11446, 3128 : USERID : OTHER : test_client.opnsense.local
Connection closed by foreign host.
```

注意事項

請注意， `127.0.0.2`主機與連接該主機的服務運作所在的主機相同，使用連接到相同防火牆的不同位址會導致`NO-USER`錯誤。
